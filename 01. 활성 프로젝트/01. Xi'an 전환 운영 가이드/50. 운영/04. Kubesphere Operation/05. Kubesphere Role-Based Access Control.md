# KubeSphere RBAC

> [!summary] 요약
> KubeSphere는 Platform(Global), Workspace, Project 3단계 역할 계층을 제공한다. DKS는 기본 역할을 커스터마이즈하여 운영한다.

---

## 1. KubeSphere & Kubernetes Role 비교

### Role 계층 구조

| Platform Role (=Global Role) | Cluster Role | Workspace Role | None (Create separately through CRD) | ProjectRole (=Namespace) |
|------------------------------|--------------|----------------|--------------------------------------|--------------------------|
| Role | Role | Role | — | Role |

---

## 2. DKS KubeSphere Role 정의

### Kubesphere Roles

**User Role**

| Role | 설명 |
|------|------|
| **platform-regular** | Workspace에 초대되기 전까지 리소스 관리 권한 없음. 접근 권한은 Platform-admin이 특정 Workspace/Project에서 부여 |

**Admin Role**

| Role | 설명 |
|------|------|
| **platform-admin** | 클러스터의 모든 리소스 관리, 모든 Workspace 생성 및 관리 |

### Workspace Role

| Role | 설명 |
|------|------|
| **ws-viewer** | Workspace 내 모든 리소스를 조회할 수 있는 Viewer. ws-admin으로부터 Workspace 초대받음 |
| **ws-self-provisioner** | Workspace 내에서 Project 및 DevOps Project 생성이 가능한 Self-provisioner 사용자. **미사용** — DevOps 서비스 미지원으로 인해 이 역할을 사용하지 않음 |
| **ws-admin** | 특정 Workspace 하단 모든 리소스 관리 (새 Project 생성, 새 멤버 초대에 사용) |

### ProjectRole (=Namespace)

| Role | 설명 |
|------|------|
| **project-admin** | Project 내 모든 리소스에 대한 완전한 제어권. Workload, Pipeline 등 리소스 생성, Project 멤버 초대 가능 |
| **project-operator** | Project 내 사용자/역할을 제외한 리소스 관리 가능 |
| **project-viewer** | Project 내 모든 리소스 조회 가능. Project-admin으로부터 Project 초대받음 |

> [!note] 권한 매핑 참고
> 신청서 Admin 권한 요청 시 `project-operator`, User 요청 시 `project-viewer` 역할이 부여됩니다. [[50. 운영/04. Kubesphere Operation/03. Assigning project roles to users|Assigning project roles]] 문서 참고.
