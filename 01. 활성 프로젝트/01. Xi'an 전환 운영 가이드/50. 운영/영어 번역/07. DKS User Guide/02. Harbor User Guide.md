> [!summary] Summary
> Use Harbor in the following order: register for the Global AD security group → open the Harbor firewall → access the web console → apply the Docker CA certificate and log in → pull a container image → tag and push the image.

> [!warning] Xi'an Application Status
> The Harbor FQDN `xa.dcr.dks.samsungds.net`, IP address `109.156.22.53`, and ports `80/443` have been verified against the Xi'an cluster catalog and installation guide. The Global AD security group `SG1599` and the DS Pass and GSAMS request paths come from the provided existing guide and have not been finalized as Xi'an operating procedures. Confirm that they are valid with the Xi'an operations team before submitting a request.

> [!note] Command and Log Placement
> The command examples and output logs provided in the source have been included without omission. Only the Taylor registry address was replaced with the Xi'an address, so these are procedural examples rather than actual Xi'an execution evidence. Inconsistencies in tag and repository notation in the source output are preserved and identified below each block.

---

## 1. Register for the Global AD Security Group

Harbor uses Global AD accounts. A user can access Harbor with a Global AD account when the user is a member of the applicable AD security group.

Submit a request for AD security group membership through [DS Pass](https://pass.samsungds.net:8082/).

### Global AD User Group

| AD Security group name | Description | Xi'an Verification Status |
|---|---|---|
| `[SG1599] DKS Prd User Group` | DKS Production environment user group | Existing guide value; final Xi'an confirmation required |

> [!warning] Confirm Before Requesting
> The Xi'an SCS AD domain information and final login integration procedure have not yet been finalized in the reference documents. Before requesting membership in `SG1599`, confirm with the Xi'an operations team that the target security group and DS Pass path still apply.

## 2. Configure the Firewall for Harbor Access

To access Harbor, open the firewall from the source IP of the user's system to the Xi'an Harbor IP. If you have a firewall issue, contact [GSAMS](http://gsams.samsungds.net/).

| Purpose | Source IP | Destination IP | Port | Protocol | Description |
|---|---|---:|---:|---|---|
| To use Harbor | User IP | `109.156.22.53` | `80`, `443` | TCP | Xi'an Harbor |

> [!note] Xi'an Value Change
> Use the Xi'an Harbor backend IP `109.156.22.53` instead of the existing Taylor Harbor IP `105.219.33.203`. Xi'an Harbor connects directly to this IP without a separate load balancer.

## 4. Log In to Harbor

### Prerequisites

- A system on which the user can install Docker is required.
- The firewall from that system to TCP ports `80` and `443` on the Xi'an Harbor IP `109.156.22.53` must be open.
- The approved Xi'an 2-Tier Root CA certificate file must be installed on the system.
- The CA trust path and commands below are for RHEL-based systems and require `sudo` privileges.

Certificate file: `SECDS-2TROOTCA.crt`

> [!warning] 2-Tier Root CA Required
> Xi'an Harbor access requires `SECDS-2TROOTCA.crt`. A standard CA certificate or server certificate file cannot be used as a substitute.

### Log In with a G-AD Account

```console
# Copy CA Certification
[ @ ~]$ sudo cp ./SECDS-2TROOTCA.crt /etc/pki/ca-trust/source/anchors

# CA-Trust Update
[ @ ~]$ sudo update-ca-trust extract

# Docker Service Restart
[ @ ~]$ sudo systemctl restart docker

[ @ ~]$ sudo docker login xa.dcr.dks.samsungds.net
Username:
Password:
Authenticating with existing credentials...
WARNING! Your password will be stored unencrypted in /root/.docker/config.json.
Configure a credential helper to remove this warning. See https://docs.docker.com/engine/reference/commandline/login/#credentials-store

Login Succeeded
```

> [!warning] Docker Credential Storage
> This warning does not indicate a login failure. It warns that the password will be stored unencrypted in `/root/.docker/config.json`. If the organization provides an approved Docker credential helper, configure it according to the applicable policy. Do not record passwords in documents or work logs.

## 5. Pull a Container Image

### 5-1. Pull the Image

Use the following syntax to store an image locally.

```bash
docker pull [DOMAIN_NAME][:PORT]/[REPOSITORY_PATH]/[IMAGE][:TAG]
```

Example:

```console

> [!note] Notation in the Provided Log
> The command specifies `dspaas-testrepo/nginx:latest`, but the first line of the provided log is `v1.0: Pulling from dks-test/nginx`. This line remains unchanged to preserve the source. For an actual execution, verify the result against the repository and tag specified in the command.

### 5-2. Check the Local Image

Check the image stored locally.

```bash
sudo docker image ls
```

Example:

```console

## 6. Push a Container Image

### 6-1. Tag the Image with the Target Address

Change the repository address of the image to the repository address to which it will be pushed.

```bash
docker tag [SOURCE_IMAGE][:TAG] [DOMAIN_NAME][:PORT]/[REPOSITORY_PATH]/[IMAGE][:TAG]
```

Example:

```console
[ @ ~]$ sudo docker image ls
nginx                                                  v1.0     ac13107facae   2 weeks ago    142MB

[ @ ~]$ sudo docker tag nginx:v1.0 xa.dcr.dks.samsungds.net/dspaas-testrepo/nginx:latest

[ @ ~]$ sudo docker image ls
REPOSITORY                                             TAG      IMAGE ID       CREATED        SIZE
xa.dcr.dks.samsungds.net/dspaas-testrepo/nginx        latest   ac13107facae   2 weeks ago    142MB
nginx                                                  v1.0     ac13107facae   2 weeks ago    142MB
```

### 6-2. Push the Image to the Registry

```bash
docker push [DOMAIN_NAME][:PORT]/[REPOSITORY_PATH]/[IMAGE][:TAG]
```

Example:

```console
[ @ ~]$ sudo docker push xa.dcr.dks.samsungds.net/dspaas-testrepo/nginx:latest
The push refers to repository [xa.dcr.dks.samsungds.net/dspaas-testrepo/nginx]

33e3df466e11: Layer already exists
747b7a567071: Layer already exists
57d3fc88cb3f: Layer already exists
53ae81198b64: Layer already exists

For an actual Push, verify success by checking both the tag used in the command and the artifact and digest shown on the Harbor repository page.
