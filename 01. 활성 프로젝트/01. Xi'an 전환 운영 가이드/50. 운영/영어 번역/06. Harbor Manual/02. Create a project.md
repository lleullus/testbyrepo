> [!summary] Summary
> Creating a Harbor project consists of three steps: submit a request to the system administrator → create the project in Harbor (Private + 10GB) → assign member roles.

---

## 1. Request Procedure

When a user requests access to a Harbor project, the system administrator receives and processes the request form.

### Request Form

| Item | Content |
|------|------|
| **DKS Kubesphere Application Form** | Remarks |
| **User Information** | |
| - Department | Cloud Platform Group |
| - Requester | Requester's name |
| - User account | Global AD account |
| **Permission** | |
| - Permission | Admin or User (designate only one Admin) |
| **DKS Information** | |
| - Cluster | Target Cluster (for example, dev-apps-pa01-tas) |
| - Project | Project name |

### Example

| AD Account | Role |
|---------|------|
| dj2.kim | Admin |
| dshl04829.id | User |
| dsml14311.id | User |
| dsml14312.id | User |
| dsml14313.id | User |

## 2. Create a Harbor Project

### 2-1. Log in to Harbor

Log in to the Harbor interface.

### 2-2. Create the Project

1. Go to the **Projects** menu.
2. Click **New Project**.
3. Create the project with the following settings:

| Setting | Value | Notes |
|-----------|------|------|
| Project Name | Project name from the request form | |
| Access Level | **Private** | Do not select Public |
| Storage Quota | **10 GB** | |

### 2-3. Access Level: Private vs Public

| | Private | Public |
|---|---------|--------|
| Image pull access | Project members only | All users |
| Security | High | Low |
| Usage scope | Restricted teams/projects | Public libraries |

**When set to Private**: only users included in the project are granted permission to pull images. If set to Public, all users can pull images without authentication, so it is not recommended for security reasons.
