# KubeSphere RBAC

> [!summary] Summary
> KubeSphere provides a three-level role hierarchy: Platform (Global), Workspace, and Project. DKS operates KubeSphere by customizing the default roles.

---

## 1. KubeSphere & Kubernetes Role Comparison

### Role Hierarchy

| Platform Role (=Global Role) | Cluster Role | Workspace Role | None (Create separately through CRD) | ProjectRole (=Namespace) |
|------------------------------|--------------|----------------|--------------------------------------|--------------------------|
| Role | Role | Role | — | Role |

---

## 2. DKS KubeSphere Role Definitions

### KubeSphere Roles

**User Role**

| Role | Description |
|------|-------------|
| **platform-regular** | Has no resource management permissions until invited to a Workspace. Access permissions are granted by platform-admin in a specific Workspace/Project |

**Admin Role**

| Role | Description |
|------|-------------|
| **platform-admin** | Can manage all resources in the cluster and create and manage all Workspaces |

### Workspace Roles

| Role | Description |
|------|-------------|
| **ws-viewer** | Viewer who can view all resources within a Workspace. Invited to the Workspace by ws-admin |
| **ws-self-provisioner** | Self-provisioner user who can create Projects and DevOps Projects within a Workspace. **Not used** — this role is not used because the DevOps service is not supported |
| **ws-admin** | Can manage all resources within a specific Workspace; used to create new Projects and invite new members |

### ProjectRole (=Namespace)

| Role | Description |
|------|-------------|
| **project-admin** | Has full control over all resources within a Project. Can create resources such as Workloads and Pipelines and invite Project members |
| **project-operator** | Can manage resources within a Project, excluding users and roles |
| **project-viewer** | Can view all resources within a Project. Invited to the Project by project-admin |

> [!note] Permission Mapping Reference
> When Admin permission is requested on the request form, the `project-operator` role is assigned. When User permission is requested, the `project-viewer` role is assigned. See [[50. 운영/영어 번역/04. Kubesphere Operation/03. Assigning project roles to users|Assigning project roles to users]].
