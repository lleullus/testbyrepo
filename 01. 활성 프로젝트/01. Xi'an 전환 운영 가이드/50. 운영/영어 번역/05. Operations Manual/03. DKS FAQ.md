> [!summary] Summary
> Key operational FAQs covering DKS (DS Kubernetes Service) resource requests, Harbor permissions, Namespace management, CLI usage, external access, DevOps, image creation, and login.

---

## 1. How to Use DKS Resources

**Procedure**: Submit a request for a DKS Project -> Create a security group and open the firewall -> Create a Namespace (Workspace -> Project -> Resource Quota) -> Inform the user

| Step | Activity | Notes |
| --- | --- | --- |
| 1 | Submit the DKS Project request form | 1:1 Workspace/Project mapping |
| 2 | Create a security group | Configure firewall rules |
| 3 | Request that the firewall be opened | The DKS operations team does not process this directly |
| 4 | Set the Resource Quota | Three types: CPU/Memory/Storage |
| 5 | Inform the user | Confirm the firewall opening and provide KubeSphere login information |

---

## 2. Obtaining Harbor Permissions

**Procedure**: Confirm SG1599 membership -> Create a project -> Set a 10GB quota -> Add members

| Step | Activity | Notes |
| --- | --- | --- |
| 1 | Confirm that the user belongs to SG1599 | Security group membership is required |
| 2 | Create a Harbor project | Image registry project |
| 3 | Set a 10GB quota | Allocate storage |
| 4 | Add members | Grant project access permissions |

---

## 3. Reducing or Deleting a Namespace

### Reducing Namespace Resources
- Reduce Namespace resources by adjusting the Resource Quota.

### Completely Deleting a Namespace
- Enable the option to delete the Project when deleting the Workspace.
- Delete Namespaces and Projects in bulk at the Workspace level.

---

## 4. Using the CLI (kubectl)

**Procedure**: Create an OS account -> Copy the ConfigMap -> Configure the kubeconfig at `/home/.kube/config`

| Step | Activity | Notes |
|------|------|------|
| 1 | Create an OS account on the Bastion server | Same as the AD account name |
| 2 | Access the Bastion through CyberArk | Permission request required |
| 3 | Copy kubeconfig from the ConfigMap | Path: `/home/.kube/config` |
| 4 | Run kubectl commands | Alternative to the KubeSphere Web UI |

## 5. Accessing Application Services Externally

**Access method**: Use the `[application-name].ingress-cluster` format.

- The cluster Ingress domain must be registered on the DNS server with the VIP-B IP.
- External access is available through the VIP-B domain.

---

## 6. Using DKS DevOps

**Current status**: DKS does not support Docker builds or DevOps features.

**Alternatives**:
- Use the P-DEP system.
- Build and deploy using the user's own system.

---

## 7. Creating Images and Deploying Pods from Binary/Source

**Image creation**: The user is responsible; the DKS operations team does not provide support.

**Supported approaches**:
- Images already deployed on external/internal networks can be used.
- Build directly with Docker, Podman, or another tool, then push to a registry.
- DKS platform standard CRI: **ContainerD** (image building is not supported, but image management and Pull/Push are fully supported).

---

## 8. Login Error ("Wrong username or password")

**Causes and resolutions**:

| Cause | Check |
|------|----------|
| AD user group permissions | Check AD group membership |
| AD password | Password reset required |
| Not a member of the security group | **SG1599 security group membership is required** |
