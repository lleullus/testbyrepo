> [!summary] Summary
> This is a six-step procedure for adding a new worker node to the cluster using Kubespray. Proceed in the following order: preparation, editing the inventory, running scale.yml, checking the status, testing deployment, and organizing the inventory.

---

## Prerequisites

- Verify VM access permissions
- Verify NetApp Storage ACL configuration

---

## 1. Node Preparation

After completing the Bastion node preparation, apply the configuration to all cluster nodes in bulk through Ansible. (※ The `-k` option prompts for the SSH password of the dspaas user on each node when running with root privileges.)

| Phase | No. | Item | Check/Apply | Notes |
|-------|-----|------|-----------|------|
| **1. Node Preparation** | 1 | Verify the `dspaas` user group | ☐ | Manual on Bastion |
| | 2 | Bastion `/etc/hosts` configuration | ☐ | Manual on Bastion |
| | 3 | Verify SSH key pair | ☐ | Manual on Bastion |
| | 4 | sudoers wheel NOPASSWD | ☐ | Ansible |
| | 5 | Copy SSH public key | ☐ | Ansible |
| | 6 | YUM repository (Artifactory) | ☐ | Ansible |
| | 7 | Install required packages | ☐ | Ansible |
| | 8 | Disable SWAP | ☐ | Ansible |
| | 9 | Configure logrotate compress | ☐ | Ansible |
| | 10 | Deploy SECDS-ROOTCA CA Cert | ☐ | Ansible |
| | 11 | Comment out IPv6 in sysctl.conf | ☐ | Ansible |
| | 12 | Verify VM resources | ☐ | Ansible |
| **2. Edit Kubespray Inventory** | 1 | Add new node information to hosts.yaml | ☐ | `inventory/dks/hosts.yaml` |
| **3. Add a Node** | 1 | Run scale.yml | ☐ | `--limit xadkswkmp03,xadkswkmp04` |
| **4. Check Node Status** | 1 | Verify that the node is Ready | ☐ | `kubectl get nodes` |
| | 2 | Verify the containerd/kernel version | ☐ | `kubectl get nodes -o wide` |
| | 3 | Verify system Pod status | ☐ | `kubectl get pod -A -o wide` |
| **5. Deploy Test** | 1 | Deployment test | ☐ | checker pod |
| | 2 | PVC & Pod deployment test | ☐ | netapp SC |
| **6. Organize Inventory** | 1 | Organize the Inventory file | ☐ | XiAn_DKS path |

## 3. Add a Node

### 3-1. Run scale.yml

Run with only the new nodes selected using the `--limit` option (may take more than 30 minutes).

```bash
[dspaas@xadksbtmp01 20.kubespray-release-2.19 (prod-ds-ksp-member-xas:monitoring)]$ ansible-playbook -e @inventory/dks/dks_vars.yml -i inventory/dks/hosts.yaml --become --become-user=root scale.yml --limit "xadkswkmp03,xadkswkmp04"
```

## 5. Deployment Test

### 5-1. Deployment test

**Create the test yaml**:

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: checker-podselctor-test3
  labels:
    app: checker3
spec:
  replicas: 1
  selector:
    matchLabels:
      app: checker3
  template:
    metadata:
      labels:
        app: checker3
    spec:
      containers:
        - image: xa.dcr.dks.samsungds.net/dspaas-testrepo/checker:v5
          name: checker
          command: ['sh', '-c', 'sleep 365d']
      nodeSelector:
        kubernetes.io/os: linux
        kubernetes.io/hostname: xadkswkmp01  # 신규 추가 노드
```

**Apply and verify**:

```bash
[dspaas@xadksbtmp01 ~ (prod-ds-ksp-member-xas:monitoring)]$ kc apply -f ./test_deploy.yaml
deployment.apps/checker-podselctor-test3 created

[dspaas@xadksbtmp01 ~ (prod-ds-ksp-member-xas:monitoring)]$ kc get pods -o wide
NAME                                                READY   STATUS    RESTARTS   AGE   IP           NODE             NOMINATED NODE   READINESS GATES
checker-podselctor-test3-977b76485-97wht            1/1     Running   0          9s    192.211.3.4  xadkswkmp01      <none>           <none>
```

### 5-2. PVC & Pod deployment test

**Check the StorageClass**:

```bash
[dspaas@xadksbtmp01 ~ (prod-ds-ksp-member-xas:monitoring)]$ k get sc
NAME                               PROVISIONER               RECLAIMPOLICY   VOLUMEBINDINGMODE   ALLOWVOLUMEEXPANSION   AGE
xa-netapp-nfs-sc                   csi.trident.netapp.io     Delete          Immediate           true                   106d
```

> In the Xi'an environment, use `xa-netapp-nfs-sc` or `powerflexos-xfs-sc-300t-sp04`.

**Create the PVC yaml**:

```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: test-netapp-deploy
spec:
  accessModes:
    - ReadWriteOnce
  resources:
    requests:
      storage: 16Gi
  storageClassName: xa-netapp-nfs-sc
```

```bash
[dspaas@xadksbtmp01 ~ (prod-ds-ksp-member-xas:monitoring)]$ kc apply -f ./netapp-test.yaml
persistentvolumeclaim/test-netapp-deploy created

[dspaas@xadksbtmp01 ~ (prod-ds-ksp-member-xas:monitoring)]$ kc get pvc
NAME                 STATUS   VOLUME           CAPACITY   ACCESS MODES   STORAGECLASS                       AGE
test-netapp-deploy   Bound    k8s-1dae9701d3   16Gi       RWO            xa-netapp-nfs-sc                  5s
```

**Create the Pod yaml**:

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: test-pvc-app
spec:
  volumes:
    - name: test-pvc
      persistentVolumeClaim:
        claimName: test-netapp-deploy
  containers:
    - image: xa.dcr.dks.samsungds.net/dspaas-testrepo/nginx:latest
      name: test-pvc-app
      volumeMounts:
        - name: test-pvc
          mountPath: "/pvc-test"
  nodeSelector:
    kubernetes.io/os: linux
    kubernetes.io/hostname: xadkswkmp01  # 신규 추가 노드
```

```bash
[dspaas@xadksbtmp01 ~ (prod-ds-ksp-member-xas:monitoring)]$ kc apply -f ./test_pvc_pod.yaml
pod/test-pvc-app created

[dspaas@xadksbtmp01 ~ (prod-ds-ksp-member-xas:monitoring)]$ kc get pods -o wide test-pvc-app
NAME           READY   STATUS    RESTARTS   AGE   IP           NODE             NOMINATED NODE   READINESS GATES
test-pvc-app   1/1     Running   0          15s   192.211.3.5  xadkswkmp01      <none>           <none>
```
