# Harbor 접속, 로그인 및 Image Push/Pull 오류

## Index

Xi'an Harbor는 `xa.dcr.dks.samsungds.net` (`109.156.22.53`, TCP `80/443`)을 사용한다. 웹 접속과 Docker CLI를 분리해서 보고, Docker CLI 문제는 CA 인증서 → 로그인 → Repository/Tag → Push 권한 순서로 확인한다.

## 1. 웹은 열리는데 `docker login`에서 x509가 발생하는 경우

브라우저에서 `https://xa.dcr.dks.samsungds.net/`가 열리는데 Docker만 실패하면 사용자 시스템의 CA trust부터 확인한다.

```console
[root@user-host ~]# sudo docker login xa.dcr.dks.samsungds.net
Username: dsjl32783.id
Password:
Error response from daemon: Get "https://xa.dcr.dks.samsungds.net/v2/": x509: certificate signed by unknown authority

[root@user-host ~]# ls -l /etc/pki/ca-trust/source/anchors/SECDS-2TROOTCA.crt
ls: cannot access '/etc/pki/ca-trust/source/anchors/SECDS-2TROOTCA.crt': No such file or directory

[root@user-host ~]# ls -l ./SECDS-2TROOTCA.crt
-rw-r--r--. 1 dsjl32783.id dsjl32783.id 1984 Aug 12 09:14 ./SECDS-2TROOTCA.crt

[root@user-host ~]# sudo cp ./SECDS-2TROOTCA.crt /etc/pki/ca-trust/source/anchors/
[root@user-host ~]# sudo update-ca-trust extract
[root@user-host ~]# sudo systemctl restart docker
[root@user-host ~]# sudo systemctl is-active docker
active

[root@user-host ~]# sudo docker login xa.dcr.dks.samsungds.net
Username: dsjl32783.id
Password:
Authenticating with existing credentials...
WARNING! Your password will be stored unencrypted in /root/.docker/config.json.
Configure a credential helper to remove this warning. See https://docs.docker.com/engine/reference/commandline/login/#credentials-store

Login Succeeded
```

## 2. 웹과 Docker 모두 로그인되지 않는 경우

인증 자체가 실패하면 웹 로그인과 Docker 로그인을 같은 계정으로 비교한다. `/`가 `200`인 경우 Registry 자체가 응답하고 있다는 뜻이다. 이 경우 계정/비밀번호/Harbor 사용 권한을 확인한다.

```console
[root@user-host ~]# sudo docker login xa.dcr.dks.samsungds.net
Username: dsjl32783.id
Password:
Error response from daemon: Get "https://xa.dcr.dks.samsungds.net/v2/": unauthorized: unauthorized to access repository

[root@user-host ~]# curl -sk -o /dev/null -w '%{http_code}\n' https://xa.dcr.dks.samsungds.net/
200

[root@user-host ~]# curl -sk -o /dev/null -w '%{http_code}\n' https://xa.dcr.dks.samsungds.net/v2/
401
```

## 4. Push가 실패하는 경우

Push는 로컬 Image → Tag → Push → Harbor Artifact 확인 순서로 본다.

```console
[root@user-host ~]# sudo docker image ls nginx
REPOSITORY   TAG    IMAGE ID       CREATED        SIZE
nginx        v1.0   ac13107facae   2 weeks ago    142MB

[root@user-host ~]# sudo docker tag nginx:v1.0 xa.dcr.dks.samsungds.net/dspaas-v1.22.10-a/nginx:1.14.2

[root@user-host ~]# sudo docker image ls
REPOSITORY                                                    TAG      IMAGE ID       CREATED        SIZE
xa.dcr.dks.samsungds.net/dspaas-v1.22.10-a/nginx              latest   ac13107facae   2 weeks ago    142MB

denied: requested access to the resource is denied
```

## 5. 웹 콘솔 자체가 열리지 않는 경우

웹도 Docker도 연결 자체가 안 되면 네트워크를 확인한다.

```console
[root@user-host ~]# getent hosts xa.dcr.dks.samsungds.net
109.156.22.53   xa.dcr.dks.samsungds.net

[root@user-host ~]# nc -vz -w 3 109.156.22.53 443
Ncat: Version 7.92 ( https://nmap.org/ncat )
Ncat: Connected to 109.156.22.53:443.
Ncat: 0 bytes sent, 0 bytes received in 0.02 seconds.

[root@user-host ~]# curl -skI https://xa.dcr.dks.samsungds.net/ | head
HTTP/2 200
server: nginx
date: Wed, 12 Aug 2026 03:22:41 GMT
content-type: text/html
content-length: 785
```

DNS가 `109.156.22.53`으로 해석되고 `443` 연결과 HTTPS 응답까지 나오면 방화벽 구간은 통과한 것이다. `nc` 단계에서 timeout이면 사용자 Source IP → `109.156.22.53:80/443` 경로를 확인한다.

## 6. 정상 확인

```text
웹 HTTPS 응답 정상
→ docker login = Login Succeeded
→ Pull/Push 명령 완료
→ Harbor Repository 화면에서 Artifact/Tag/digest 확인
```
