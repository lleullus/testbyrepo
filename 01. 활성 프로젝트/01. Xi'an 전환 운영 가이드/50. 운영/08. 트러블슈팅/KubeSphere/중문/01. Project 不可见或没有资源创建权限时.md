# Project 不可见或没有资源创建权限时

## Index

用户登录 KubeSphere 后，如果看不到目标 Project，或者虽然能看到 Project，但无法创建 Deployment/PVC/Secret，则按 **Project → Workspace 成员 → Project 成员 → Project Role** 的顺序确认。

## 1. Project 本身不可见时

先确认该 Project 是否以 Kubernetes Namespace 的形式存在。

```console
[dspaas@xadksbtmd01 ~]$ kubectl get namespace hello-kubesphere-dev
NAME                   STATUS   AGE
hello-kubesphere-dev   Active   41d
```

如果 Namespace 为 `Active`，但用户界面中看不到 Project，则不是 Project 创建问题，而是成员关系问题。继续确认 Workspace 和 Project 成员。

如果出现以下结果，则说明申请的 Project 尚未创建，或者 Project 名称错误。先按照 [[50. 운영/04. Kubesphere Operation/01. Creating Workspaces&projects|Creating Workspaces&projects]] 流程创建 Project。

```console
[dspaas@xadksbtmd01 ~]$ kubectl get namespace hello-kubesphere-dev
Error from server (NotFound): namespaces "hello-kubesphere-dev" not found
```

## 2. Workspace 中没有该用户时

在 KubeSphere 中确认目标 Workspace 的成员。

```text
Workbench
→ Workspaces
→ 目标 Workspace
→ Workspace Settings
→ Workspace Members
```

例如，申请单中的两个用户都需要使用服务时，Workspace Members 中应存在 `dj2.kim` 和 `dsjl32783.id`。

如果用户不存在，则按以下方式邀请。

```text
Workspace Settings
→ Workspace Members
→ Invite Member
→ 选择 dj2.kim 或 dsjl32783.id
→ Role: viewer
→ OK
```

邀请后，如果用户已显示在 Workspace Members 中，再确认 Project 成员。

## 3. Workspace 可见但 Project 不可见时

这种情况表示 Workspace 成员注册已经完成，但漏掉了 Project 成员注册。

```text
Workspace: 可见
Project: hello-kubesphere-dev 不可见
```

在目标 Project 中添加用户。

```text
Projects
→ hello-kubesphere-dev
→ Project Settings
→ Project Members
→ Invite
```

根据申请单中的 Permission 选择 Role。

```text
dj2.kim        Admin → project-operator
dsjl32783.id   User  → project-viewer
```

保存后，让用户退出 KubeSphere 并重新登录，此时应能看到 `hello-kubesphere-dev`。

## 4. Project 可见但没有 Create/Edit 菜单时

如果可以进入 Project，也能查看现有 Workload/PVC/Secret，但没有 `Create`、`Edit`、`Delete`，则将当前 Project Role 与申请单进行比较。

### User 申请者

如果 `dsjl32783.id` 在申请单中为 `User`，且 Project Role 为 `project-viewer`，则没有创建菜单是正常的。

```text
申请 Permission = User
Project Role     = project-viewer

Workload 查看    可以
PVC 查看         可以
Secret 查看      可以
Create/Edit      不可以
Delete           不可以
```

不要将此情况视为故障并提升权限。如果需要创建权限，应先变更申请 Permission 或完成单独的审批流程。

### Admin 申请者被分配为 viewer 时

如果 `dj2.kim` 在申请单中为 `Admin`，但被分配为 `project-viewer`，则 Role 配置错误。

```text
Project Settings
→ Project Members
→ dj2.kim
→ Edit Role
→ project-operator
→ OK
```

修改后，让用户退出并重新登录。

正常的 `project-operator` 应能在以下区域使用创建/修改菜单。

```text
Application Workloads → Workloads
Storage → Volumes
Configuration → Secrets
Configuration → ConfigMaps
```

`project-operator` 看不到 Project Member 邀请菜单是正常的。成员管理属于 `project-admin` 范围。

## 5. Role 修改后确认实际创建权限

将 `Admin → project-operator` 修改后，可以在 UI 中创建一个小型测试 Deployment 来确认实际操作是否正常。

```console
[dspaas@xadksbtmd01 ~]$ kubectl get deployment -n hello-kubesphere-dev
NAME         READY   UP-TO-DATE   AVAILABLE   AGE
nginx-test   1/1     1            1           1m

[dspaas@xadksbtmd01 ~]$ kubectl get pod -n hello-kubesphere-dev
NAME                          READY   STATUS    RESTARTS   AGE
nginx-test-6f7c8d9b6d-7k2pm   1/1     Running   0          1m
```
