# When a Project Is Not Visible or You Do Not Have Permission to Create Resources

## Index

If a user can log in to KubeSphere but cannot see the target Project, or can see the Project but cannot create a Deployment/PVC/Secret, check in this order: **Project → Workspace member → Project member → Project Role**.

## 1. When the Project itself is not visible

First, confirm that the Project exists as a Kubernetes Namespace.

```console
[dspaas@xadksbtmd01 ~]$ kubectl get namespace hello-kubesphere-dev
NAME                   STATUS   AGE
hello-kubesphere-dev   Active   41d
```

If it is `Active` but the Project is not visible to the user, this is not a Project creation issue. Check Workspace and Project membership.

If the result is as follows, the requested Project has not been created yet or the Project name is incorrect. Create the Project first by following [[50. 운영/04. Kubesphere Operation/01. Creating Workspaces&projects|Creating Workspaces&projects]].

```console
[dspaas@xadksbtmd01 ~]$ kubectl get namespace hello-kubesphere-dev
Error from server (NotFound): namespaces "hello-kubesphere-dev" not found
```

## 2. When the user is not a Workspace member

Check the members of the target Workspace in KubeSphere.

```text
Workbench
→ Workspaces
→ Target Workspace
→ Workspace Settings
→ Workspace Members
```

For example, if both users in the request form need to use the service, `dj2.kim` and `dsjl32783.id` must appear in Workspace Members.

If a user is missing, invite the user as follows.

```text
Workspace Settings
→ Workspace Members
→ Invite Member
→ Select dj2.kim or dsjl32783.id
→ Role: viewer
→ OK
```

After the user appears in Workspace Members, check Project membership.

## 3. When the Workspace is visible but the Project is not

This means Workspace member registration is complete but Project member registration is missing.

```text
Workspace: visible
Project: hello-kubesphere-dev not visible
```

Add the user to the target Project.

```text
Projects
→ hello-kubesphere-dev
→ Project Settings
→ Project Members
→ Invite
```

Select the Role according to the requested Permission.

```text
dj2.kim        Admin → project-operator
dsjl32783.id   User  → project-viewer
```

After saving, the user must log out of KubeSphere and log back in. `hello-kubesphere-dev` should then be visible.

## 4. When the Project is visible but Create/Edit is not available

If the user can enter the Project and see existing Workloads/PVCs/Secrets but cannot see `Create`, `Edit`, or `Delete`, compare the current Project Role with the request form.

### For a User request

If `dsjl32783.id` requested `User` and the Project Role is `project-viewer`, the absence of create menus is normal.

```text
Requested Permission = User
Project Role          = project-viewer

View Workload         Allowed
View PVC              Allowed
View Secret           Allowed
Create/Edit           Not allowed
Delete                Not allowed
```

Do not treat this as a failure and raise the permission. If create permission is required, change the requested Permission or complete the separate approval process first.

### When an Admin request was assigned viewer

If `dj2.kim` requested `Admin` but was assigned `project-viewer`, the Role is incorrect.

```text
Project Settings
→ Project Members
→ dj2.kim
→ Edit Role
→ project-operator
→ OK
```

After the change, the user logs out and logs back in.

With a normal `project-operator` Role, create/edit menus should be available in the following areas.

```text
Application Workloads → Workloads
Storage → Volumes
Configuration → Secrets
Configuration → ConfigMaps
```

It is normal that `project-operator` cannot see the Project Member invitation menu. Member management is within the `project-admin` scope.

## 5. Verify actual create permission after changing the Role

After changing `Admin → project-operator`, create a small test Deployment in the UI and verify the actual result.

```console
[dspaas@xadksbtmd01 ~]$ kubectl get deployment -n hello-kubesphere-dev
NAME         READY   UP-TO-DATE   AVAILABLE   AGE
nginx-test   1/1     1            1           1m

[dspaas@xadksbtmd01 ~]$ kubectl get pod -n hello-kubesphere-dev
NAME                          READY   STATUS    RESTARTS   AGE
nginx-test-6f7c8d9b6d-7k2pm   1/1     Running   0          1m
```
