# Project가 보이지 않거나 리소스 생성 권한이 없는 경우

## Index

사용자가 KubeSphere에 로그인했는데 대상 Project가 보이지 않거나, Project는 보이지만 Deployment/PVC/Secret을 만들 수 없으면 **Project 확인 → Workspace 멤버 → Project 멤버 → Project Role** 순서로 확인한다.

## 1. Project 자체가 보이지 않는 경우

먼저 Project가 Kubernetes Namespace로 존재하는지 확인한다.

```console
[dspaas@xadksbtmd01 ~]$ kubectl get namespace hello-kubesphere-dev
NAME                   STATUS   AGE
hello-kubesphere-dev   Active   41d
```

`Active`인데 사용자 화면에 Project가 없으면 Project 생성 문제가 아니라 멤버십 문제다. Workspace와 Project 멤버를 확인한다.

반대로 다음처럼 나오면 신청 Project 생성이 완료되지 않았거나 Project 이름이 잘못된 것이다. [[50. 운영/04. Kubesphere Operation/01. Creating Workspaces&projects|Creating Workspaces&projects]] 절차에서 Project를 먼저 생성한다.

```console
[dspaas@xadksbtmd01 ~]$ kubectl get namespace hello-kubesphere-dev
Error from server (NotFound): namespaces "hello-kubesphere-dev" not found
```

## 2. Workspace에 사용자가 없는 경우

KubeSphere에서 대상 Workspace의 멤버를 확인한다.

```text
Workbench
→ Workspaces
→ 대상 Workspace
→ Workspace Settings
→ Workspace Members
```

예를 들어 신청서의 두 사용자가 모두 서비스를 이용해야 하면 Workspace Members에 `dj2.kim`, `dsjl32783.id`가 있어야 한다.

사용자가 없으면 다음처럼 초대한다.

```text
Workspace Settings
→ Workspace Members
→ Invite Member
→ dj2.kim 또는 dsjl32783.id 선택
→ Role: viewer
→ OK
```

초대 후 Workspace Members 목록에 사용자가 표시되면 Project 멤버를 확인한다.

## 3. Workspace는 보이는데 Project만 보이지 않는 경우

Workspace 멤버 등록만 끝나고 Project 멤버 등록이 빠진 경우다.

```text
Workspace: 보임
Project: hello-kubesphere-dev 안 보임
```

대상 Project에서 사용자를 추가한다.

```text
Projects
→ hello-kubesphere-dev
→ Project Settings
→ Project Members
→ Invite
```

신청서 Permission에 맞춰 Role을 선택한다.

```text
dj2.kim        Admin → project-operator
dsjl32783.id   User  → project-viewer
```

저장 후 사용자가 KubeSphere에서 로그아웃했다가 다시 로그인하면 `hello-kubesphere-dev`가 보여야 한다.

## 4. Project는 보이는데 Create/Edit 메뉴가 없는 경우

Project에 들어갈 수 있고 기존 Workload/PVC/Secret은 보이는데 `Create`, `Edit`, `Delete`가 없으면 현재 Project Role을 신청서와 비교한다.

### User 신청자라면

`dsjl32783.id`가 신청서에서 `User`이고 Project Role이 `project-viewer`라면 생성 메뉴가 없는 것이 정상이다.

```text
신청 Permission = User
Project Role     = project-viewer

Workload 조회    가능
PVC 조회         가능
Secret 조회      가능
Create/Edit      불가
Delete           불가
```

이 경우 장애로 보고 권한을 올리지 않는다. 생성 권한이 필요하면 신청 Permission 변경 또는 별도 승인부터 진행한다.

### Admin 신청자인데 viewer라면

`dj2.kim`이 신청서에서 `Admin`인데 `project-viewer`로 들어가 있으면 잘못된 Role이다.

```text
Project Settings
→ Project Members
→ dj2.kim
→ Edit Role
→ project-operator
→ OK
```

수정 후 사용자는 로그아웃했다가 다시 로그인한다.

정상 `project-operator`라면 다음 영역에서 생성/수정 메뉴를 사용할 수 있어야 한다.

```text
Application Workloads → Workloads
Storage → Volumes
Configuration → Secrets
Configuration → ConfigMaps
```

`project-operator`에게 Project Member 초대 메뉴가 보이지 않는 것은 정상이다. 멤버 관리는 `project-admin` 범위다.

## 5. Role 수정 후 실제 생성 권한 확인

`Admin → project-operator` 수정 후에는 UI에서 작은 테스트 Deployment 하나를 생성해 실제 동작을 확인할 수 있다.

```console
[dspaas@xadksbtmd01 ~]$ kubectl get deployment -n hello-kubesphere-dev
NAME         READY   UP-TO-DATE   AVAILABLE   AGE
nginx-test   1/1     1            1           1m

[dspaas@xadksbtmd01 ~]$ kubectl get pod -n hello-kubesphere-dev
NAME                          READY   STATUS    RESTARTS   AGE
nginx-test-6f7c8d9b6d-7k2pm   1/1     Running   0          1m
```
