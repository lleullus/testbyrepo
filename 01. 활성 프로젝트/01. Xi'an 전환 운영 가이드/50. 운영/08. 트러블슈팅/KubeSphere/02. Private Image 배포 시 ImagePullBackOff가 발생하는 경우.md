# Private Image 배포 시 ImagePullBackOff가 발생하는 경우

## Index

KubeSphere에서 Private Harbor Image를 사용한 Deployment의 Pod가 `ErrImagePull` 또는 `ImagePullBackOff` 상태인 경우 **Pod Event → Image 경로 → 같은 Project의 Image Registry Secret → Deployment의 Image Pull Secret → Harbor Tag/권한** 순서로 확인한다.

## 1. Pod Event에서 Pull 실패 원인 확인

먼저 Pod 상태를 확인한다.

```console
[dspaas@xadksbtmd01 ~]$ kubectl get pod -n hello-kubesphere-dev
NAME                          READY   STATUS             RESTARTS   AGE
nginx-test-6f7c8d9b6d-7k2pm   0/1     ImagePullBackOff   0          4m
```

Pod 이름을 그대로 사용해 Event를 확인한다.

```console
[dspaas@xadksbtmd01 ~]$ kubectl describe pod nginx-test-6f7c8d9b6d-7k2pm -n hello-kubesphere-dev
Name:             nginx-test-6f7c8d9b6d-7k2pm
Namespace:        hello-kubesphere-dev
Node:             xadkswkmd01/109.156.22.82
Status:           Pending
Containers:
  nginx:
    Image:          xa.dcr.dks.samsungds.net/dspaas-v1.22.10-a/nginx:1.14.2
    State:          Waiting
      Reason:       ImagePullBackOff
Events:
  Type     Reason     Age               From               Message
  ----     ------     ----              ----               -------
  Normal   Scheduled  4m                default-scheduler  Successfully assigned hello-kubesphere-dev/nginx-test-6f7c8d9b6d-7k2pm to xadkswkmd01
  Normal   Pulling    2m (x4 over 4m)   kubelet            Pulling image "xa.dcr.dks.samsungds.net/dspaas-v1.22.10-a/nginx:1.14.2"
  Warning  Failed     2m (x4 over 4m)   kubelet            Failed to pull image "xa.dcr.dks.samsungds.net/dspaas-v1.22.10-a/nginx:1.14.2": pull access denied, repository does not exist or may require authorization
  Warning  Failed     2m (x4 over 4m)   kubelet            Error: ErrImagePull
  Normal   BackOff    40s (x10 over 4m) kubelet            Back-off pulling image "xa.dcr.dks.samsungds.net/dspaas-v1.22.10-a/nginx:1.14.2"
  Warning  Failed     40s (x10 over 4m) kubelet            Error: ImagePullBackOff
```

## 2. Deployment의 Image 경로 확인

Deployment YAML에서 `image`를 확인한다.

```console
[dspaas@xadksbtmd01 ~]$ kubectl get deployment nginx-test -n hello-kubesphere-dev -o yaml
...
    spec:
      containers:
      - image: xa.dcr.dks.samsungds.net/dspaas-v1.22.10-a/nginx:1.14.2
        name: nginx
...
```

## 3. 같은 Project에 Image Registry Secret이 있는지 확인

Image Secret은 Deployment와 같은 KubeSphere Project, 즉 같은 Namespace에 있어야 한다. Secret type을 확인한다. Secret이 없거나 다른 Project에만 있으면 KubeSphere에서 해당 Project 안에 다시 만든다.

```console
[dspaas@xadksbtmd01 ~]$ kubectl get secret -n hello-kubesphere-dev
NAME                     TYPE                             DATA   AGE
harbor-registry-secret   kubernetes.io/dockerconfigjson   1      18d

[dspaas@xadksbtmd01 ~]$ kubectl describe secret harbor-registry-secret -n hello-kubesphere-dev
Name:         harbor-registry-secret
Namespace:    hello-kubesphere-dev
Type:         kubernetes.io/dockerconfigjson

Data
====
.dockerconfigjson:  248 bytes
```

## 4. Deployment에 Image Pull Secret이 연결됐는지 확인

```console
[dspaas@xadksbtmd01 ~]$ kubectl get deployment nginx-test -n hello-kubesphere-dev -o yaml
...
    spec:
      imagePullSecrets:
      - name: harbor-registry-secret
      containers:
      - image: xa.dcr.dks.samsungds.net/dspaas-v1.22.10-a/nginx:1.14.2
        name: nginx
...
```

## 5. `manifest unknown`이면 Tag를 수정

Pod Event가 다음처럼 나오면 Secret 권한보다 Repository/Tag를 먼저 확인한다.

```console
[dspaas@xadksbtmd01 ~]$ kubectl describe pod nginx-test-6f7c8d9b6d-7k2pm -n hello-kubesphere-dev
...
Warning  Failed  35s  kubelet  Failed to pull image "xa.dcr.dks.samsungds.net/dspaas-v1.22.10-a/nginx:not-exist": manifest unknown: manifest unknown
Warning  Failed  35s  kubelet  Error: ErrImagePull
```

Harbor 가이드에서 실제 확인된 정상 Tag는 `1.14.2`다.

```console
[root@user-host ~]# sudo docker pull xa.dcr.dks.samsungds.net/dspaas-v1.22.10-a/nginx:not-exist
Error response from daemon: manifest for xa.dcr.dks.samsungds.net/dspaas-v1.22.10-a/nginx:not-exist not found: manifest unknown: manifest unknown

[root@user-host ~]# sudo docker pull xa.dcr.dks.samsungds.net/dspaas-v1.22.10-a/nginx:1.14.2
3ce19acfc13c: Pull complete
Digest: sha256:f5578142accc4a354c4759f960645f83328ca602a17083e82c873a070a7fd172
Status: Downloaded newer image for xa.dcr.dks.samsungds.net/dspaas-v1.22.10-a/nginx:1.14.2
```

## 6. `pull access denied`이면 Harbor 계정 권한 확인

Image 경로, Secret, `imagePullSecrets` 연결이 모두 맞는데 다음 메시지가 나오면 Harbor 계정의 Project 권한이나 Secret에 저장된 계정을 확인한다.

```text
pull access denied
repository does not exist or may require authorization
denied: requested access to the resource is denied
```

Harbor에서 같은 계정으로 직접 로그인과 Pull을 확인한다.

```console
[root@user-host ~]# sudo docker login xa.dcr.dks.samsungds.net
Username: dsjl32783.id
Password:
Login Succeeded

[root@user-host ~]# sudo docker pull xa.dcr.dks.samsungds.net/dspaas-v1.22.10-a/nginx:1.14.2
3ce19acfc13c: Pull complete
Digest: sha256:f5578142accc4a354c4759f960645f83328ca602a17083e82c873a070a7fd172
Status: Downloaded newer image for xa.dcr.dks.samsungds.net/dspaas-v1.22.10-a/nginx:1.14.2
```

## 7. 수정 후 새 Pod가 Image를 정상 Pull하는지 확인

Image 또는 Image Pull Secret을 저장하면 Deployment가 새 Pod를 생성한다.

```console
[dspaas@xadksbtmd01 ~]$ kubectl rollout status deployment/nginx-test -n hello-kubesphere-dev
deployment "nginx-test" successfully rolled out

[dspaas@xadksbtmd01 ~]$ kubectl get pod -n hello-kubesphere-dev
NAME                          READY   STATUS    RESTARTS   AGE
nginx-test-75d8c78fbc-r8k4m   1/1     Running   0          42s
```

새 Pod Event도 확인한다.

```console
[dspaas@xadksbtmd01 ~]$ kubectl describe pod nginx-test-75d8c78fbc-r8k4m -n hello-kubesphere-dev
Events:
  Type    Reason     Age   From               Message
  ----    ------     ----  ----               -------
  Normal  Scheduled  43s   default-scheduler  Successfully assigned hello-kubesphere-dev/nginx-test-75d8c78fbc-r8k4m to xadkswkmd01

  Normal  Started    38s   kubelet            Started container nginx
```
