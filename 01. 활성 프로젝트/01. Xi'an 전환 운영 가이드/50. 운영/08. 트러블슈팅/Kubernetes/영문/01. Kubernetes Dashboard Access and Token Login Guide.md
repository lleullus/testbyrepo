# Kubernetes Dashboard Access and Token Login Guide

## Index

The Xi'an Kubernetes Dashboard uses a different access URL for each cluster. Confirm the target cluster and open the corresponding URL.

| Cluster | Dashboard URL |
|---|---|
| `prd-host-pa01-xas` | `https://dashboard.apps.xaprdpa01.mgmt.dks.samsungds.net` |
| `prd-apps-pa01-xas` | `https://dashboard.apps.xaprdpa01.apps.dks.samsungds.net` |
| `dev-apps-pa01-xas` | `https://dashboard.apps.xadevpa01.apps.dks.samsungds.net` |

This guide is based on Kubernetes `v1.22.10` and Kubernetes Dashboard `v2.5.0`. Login uses the Token from the `kubernetes.io/service-account-token` Secret associated with the `admin-user` ServiceAccount.

## 1. Normal Token Login

Check `admin-user` and the current Token Secret.

```console
[dspaas@xadksbthm01 ~]$ kubectl -n kubernetes-dashboard get sa admin-user
NAME         SECRETS   AGE
admin-user   1         ...

[dspaas@xadksbthm01 ~]$ kubectl -n kubernetes-dashboard get secret | grep '^admin-user-token-'
admin-user-token-jsjxf   kubernetes.io/service-account-token   3   ...
```

Use the confirmed Secret name to output the Dashboard Token.

```console
[dspaas@xadksbthm01 ~]$ kubectl -n kubernetes-dashboard describe secret admin-user-token-jsjxf | awk '/^token:/{print $2}'
<token omitted>
[dspaas@xadksbthm01 ~]$
```

Open the Dashboard URL for the target cluster, select `Token`, and paste the entire Token line. The login is normal if Namespace, Node, and Workload resources are displayed.

## 2. Recreate the `admin-user` Token Secret

When replacing the Token Secret, create the new Secret first without deleting the existing Secret. Keep the existing `admin-user` and RBAC unchanged.

```console
[dspaas@xadksbthm01 ~]$ cat <<'EOF' | kubectl apply -f -
apiVersion: v1
kind: Secret
metadata:
  name: admin-user-token-new
  namespace: kubernetes-dashboard
  annotations:
    kubernetes.io/service-account.name: admin-user
type: kubernetes.io/service-account-token
EOF
secret/admin-user-token-new created
```

Verify that the controller has populated the new Secret with Token data.

```console
[dspaas@xadksbthm01 ~]$ kubectl -n kubernetes-dashboard get secret admin-user-token-new
NAME                     TYPE                                  DATA   AGE
admin-user-token-new     kubernetes.io/service-account-token   3      ...
```

When `DATA` is `3`, output the new Token.

```console
[dspaas@xadksbthm01 ~]$ kubectl -n kubernetes-dashboard describe secret admin-user-token-new | awk '/^token:/{print $2}'
<token omitted>
[dspaas@xadksbthm01 ~]$
```

Verify that Dashboard login succeeds with the new Token. After successful login is confirmed, delete only the previous Secret.

```console
[dspaas@xadksbthm01 ~]$ kubectl -n kubernetes-dashboard delete secret admin-user-token-jsjxf
secret "admin-user-token-jsjxf" deleted
```

## 3. Verification

```text
admin-user exists
→ service-account-token Secret confirmed
→ Token output confirmed
→ Dashboard Token login succeeds
```
