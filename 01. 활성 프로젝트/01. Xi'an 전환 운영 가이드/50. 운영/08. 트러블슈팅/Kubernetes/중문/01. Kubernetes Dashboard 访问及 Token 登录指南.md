# Kubernetes Dashboard 访问及 Token 登录指南

## Index

Xi'an Kubernetes Dashboard 的访问地址因集群而异。请先确认目标集群，再使用对应的 URL 访问。

| Cluster | Dashboard URL |
|---|---|
| `prd-host-pa01-xas` | `https://dashboard.apps.xaprdpa01.mgmt.dks.samsungds.net` |
| `prd-apps-pa01-xas` | `https://dashboard.apps.xaprdpa01.apps.dks.samsungds.net` |
| `dev-apps-pa01-xas` | `https://dashboard.apps.xadevpa01.apps.dks.samsungds.net` |

本文以 Kubernetes `v1.22.10`、Kubernetes Dashboard `v2.5.0` 为基准，使用与 `admin-user` ServiceAccount 关联的 `kubernetes.io/service-account-token` Secret 中的 Token 登录。

## 1. 正常 Token 登录

确认 `admin-user` 和当前 Token Secret。

```console
[dspaas@xadksbthm01 ~]$ kubectl -n kubernetes-dashboard get sa admin-user
NAME         SECRETS   AGE
admin-user   1         ...

[dspaas@xadksbthm01 ~]$ kubectl -n kubernetes-dashboard get secret | grep '^admin-user-token-'
admin-user-token-jsjxf   kubernetes.io/service-account-token   3   ...
```

使用确认到的 Secret 名称输出 Dashboard Token。

```console
[dspaas@xadksbthm01 ~]$ kubectl -n kubernetes-dashboard describe secret admin-user-token-jsjxf | awk '/^token:/{print $2}'
<token omitted>
[dspaas@xadksbthm01 ~]$
```

在浏览器中打开目标集群的 Dashboard URL，选择 `Token`，并粘贴输出的完整 Token 行。能够查看 Namespace、Node、Workload 等资源即为正常。

## 2. 重新创建 `admin-user` Token Secret

更换 Token Secret 时，不要先删除现有 Secret，而应先创建新的 Secret。现有 `admin-user` 和 RBAC 保持不变。

```console
[dspaas@xadksbthm01 ~]$ cat <<'EOF' | kubectl apply -f -
apiVersion: v1
kind: Secret
metadata:
  name: admin-user-token-new
  namespace: kubernetes-dashboard
  annotations:
    kubernetes.io/service-account.name: admin-user
type: kubernetes.io/service-account-token
EOF
secret/admin-user-token-new created
```

确认 Controller 已向新的 Secret 填充 Token 数据。

```console
[dspaas@xadksbthm01 ~]$ kubectl -n kubernetes-dashboard get secret admin-user-token-new
NAME                     TYPE                                  DATA   AGE
admin-user-token-new     kubernetes.io/service-account-token   3      ...
```

当 `DATA` 为 `3` 时，输出新的 Token。

```console
[dspaas@xadksbthm01 ~]$ kubectl -n kubernetes-dashboard describe secret admin-user-token-new | awk '/^token:/{print $2}'
<token omitted>
[dspaas@xadksbthm01 ~]$
```

使用新 Token 确认 Dashboard 可以正常登录。确认登录成功后，再删除原有 Secret。

```console
[dspaas@xadksbthm01 ~]$ kubectl -n kubernetes-dashboard delete secret admin-user-token-jsjxf
secret "admin-user-token-jsjxf" deleted
```

## 3. 正常确认

```text
admin-user 存在
→ 已确认 service-account-token Secret
→ 已确认 Token 输出
→ Dashboard Token 登录成功
```
