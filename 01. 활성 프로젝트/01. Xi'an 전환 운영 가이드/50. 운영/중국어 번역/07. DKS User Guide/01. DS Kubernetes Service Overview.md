> [!summary] 摘要
> Xi'an DKS 是一项通过 KubeSphere 运营 Kubernetes 应用资源、通过 Harbor 管理容器镜像的服务。用户在分配的 Project 中进行操作，Project 与 Kubernetes Namespace 相同。

> [!warning] 草案状态
> 本文是以 Xi'an 为基准、替换 Taylor 环境值后的草案。集群和网络值已纳入当前目录，但 SCS AD 集成信息和 KubeSphere Dashboard 的最终 FQDN 尚未确定。

---

## 1. 服务构成

| 组成部分 | Xi'an 基准 | 用户侧的作用 |
|---|---|---|
| KubeSphere Host | `prd-host-pa01-xas` | 用户登录，以及 Workspace、Project 和权限管理 |
| Production Member | `prd-apps-pa01-xas` | 生产应用的部署和运行 |
| Development Member | `dev-apps-pa01-xas` | 开发应用的部署和运行 |
| Harbor | `prd-harbor-xas` | 容器镜像的存储、Push 和 Pull |

KubeSphere 的管理区域与应用运行区域相互分离。用户在 Host 的 Web Console 中选择分配的 Project，实际工作负载则部署到 Production 或 Development Member Cluster。

---

## 2. 域名和访问信息

| 对象 | 域名或模式 | 访问 IP | 端口 | 状态 |
|---|---|---:|---:|---|
| KubeSphere Dashboard | 需要确认最终 FQDN | `109.156.25.46` | 80, 443 | Host Ingress VIP 已确认 |
| Host Ingress | `*.xaprdpa01.mgmt.dks.samsungds.net` | `109.156.25.46` | 80, 443 | 已纳入目录 |
| Production Ingress | `*.xaprdpa01.apps.dks.samsungds.net` | `109.156.25.60` | 80, 443 | 已纳入目录 |
| Development Ingress | `*.xadevpa01.apps.dks.samsungds.net` | `109.156.25.75` | 80, 443 | 已纳入目录 |
| Harbor | `xa.dcr.dks.samsungds.net` | `109.156.22.53` | 80, 443 | FQDN 和证书已完成 |

外部 80/443 请求会从各 Ingress VIP 转发到 Router Node 的 30080/30443 端口。访问前，必须确认防火墙已允许用户 Source IP 访问所需的目标 IP 和端口。

> [!note] 需要确认认证
> 用户申请以 AD 账户为依据处理。但是，当前基准资料仍在请求 SCS AD 域和 KubeSphere 集成信息，因此最终登录方式和账户启用流程需经运营团队确认后确定。

## 3. Workspace、Project、Namespace

- 根据 DKS 政策，**Workspace 和 Project 按 1:1 匹配配置**。
- KubeSphere 的 **Project 与 Kubernetes Namespace 相同**。
- 用户只能在分配的 Project 中查看或管理获准的应用资源。
- CPU 和 Memory 通过 Workspace 与 Project Quota 限制，Storage 则通过整个 Namespace 及各 StorageClass 的 Quota 限制。

申请表中的 `Admin` 请求默认映射到 KubeSphere 的 `project-operator`，`User` 请求映射到 `project-viewer`。`project-operator` 可以管理工作负载和存储等资源，但不能管理 Project 成员和角色。具有成员管理权限的 `project-admin` 按单独的运营政策执行。

---

## 4. 使用流程

1. 请求开放 KubeSphere Dashboard、Harbor 以及所使用的 Member Cluster Ingress 的防火墙。
2. 根据运营团队的说明，首次登录 KubeSphere，生成账户访问记录。
3. 提交使用申请表，填写 Project 名称、目标环境、CPU、Memory、Storage、用户和申请权限。
4. 运营团队创建 Workspace 和 Project，邀请用户，并授予 Project 角色和 Quota。
5. 被添加为 Harbor Project 成员的用户 Push 镜像，然后在 KubeSphere 中使用该镜像部署工作负载。Private 镜像需要 Image Secret。
6. 应用通过目标 Member Cluster 的 Ingress 域名对外提供访问。

`kubectl` 不是默认的用户访问路径。只有在 Bastion 账户、防火墙、CyberArk 权限以及用户专用 kubeconfig 均获批准后，才能按照单独的运营流程使用。
