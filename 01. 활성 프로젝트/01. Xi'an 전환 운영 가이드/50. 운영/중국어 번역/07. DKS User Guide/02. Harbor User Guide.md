> [!summary] 摘要
> 按以下顺序使用 Harbor：加入 Global AD 安全组 → 开通 Harbor 防火墙 → 访问 Web Console → 应用 Docker CA 证书并登录 → Pull 容器镜像 → Tag 并 Push 镜像。

> [!warning] Xi'an 适用状态
> Harbor FQDN `xa.dcr.dks.samsungds.net`、IP 地址 `109.156.22.53`及端口 `80/443`已经通过 Xi'an 集群目录和安装文档确认。Global AD 安全组 `SG1599`以及 DS Pass、GSAMS 申请路径来自所提供的既有指南，尚未确定为 Xi'an 最终运营流程。提交申请前，请向 Xi'an 运营团队确认其有效性。

> [!note] 命令与日志编排原则
> 下文完整保留了源文档提供的命令示例和输出日志，未作省略。仅将 Taylor 镜像仓库地址替换为 Xi'an 地址，因此这些内容属于操作流程示例，并非 Xi'an 环境的实际执行证据。源输出中的 Tag 和 Repository 标记不一致之处予以原样保留，并在各代码块下方单独说明。

## 1. 加入 Global AD 安全组

Harbor 使用 Global AD 账号。用户属于相应 AD 安全组时，可以使用 Global AD 账号访问 Harbor。

通过 [DS Pass](https://pass.samsungds.net:8082/) 提交加入 AD 安全组的申请。

### Global AD User Group

| AD Security group name | Description | Xi'an 确认状态 |
|---|---|---|
| `[SG1599] DKS Prd User Group` | DKS Production environment user group | 既有指南中的值，需要 Xi'an 最终确认 |

> [!warning] 申请前确认
> 当前基准文档尚未确定 Xi'an SCS AD 域信息和最终登录集成流程。申请加入 `SG1599`前，请向 Xi'an 运营团队确认目标安全组和 DS Pass 路径是否仍然适用。

---

## 2. 配置访问 Harbor 所需的防火墙

要访问 Harbor，需要开通从用户系统的 Source IP 到 Xi'an Harbor IP 的防火墙。如遇防火墙问题，请联系 [GSAMS](http://gsams.samsungds.net/)。

| Purpose | Source IP | Destination IP | Port | Protocol | Description |
|---|---|---:|---:|---|---|
| To use Harbor | User IP | `109.156.22.53` | `80`, `443` | TCP | Xi'an Harbor |

> [!note] Xi'an 变更值
> 使用 Xi'an Harbor Backend IP `109.156.22.53`，不再使用原 Taylor Harbor IP `105.219.33.203`。Xi'an Harbor 不经过单独的负载均衡器，直接连接到该 IP。

## 4. 登录 Harbor

### 前置条件

- 需要一台用户可以安装 Docker 的系统。
- 必须开通从该系统到 Xi'an Harbor IP `109.156.22.53`的 TCP `80`、`443`端口。
- 必须在系统中安装经过批准的 Xi'an 2-Tier Root CA 证书文件。
- 以下 CA trust 路径和命令适用于 RHEL 系列系统，并且需要 `sudo`权限。

证书文件：`SECDS-2TROOTCA.crt`

> [!warning] 必须使用 2-Tier Root CA
> 访问 Xi'an Harbor 必须使用 `SECDS-2TROOTCA.crt`。不能使用普通 CA 证书或服务器证书文件代替。

### 使用 G-AD 账号登录

```console
# Copy CA Certification
[ @ ~]$ sudo cp ./SECDS-2TROOTCA.crt /etc/pki/ca-trust/source/anchors

# CA-Trust Update
[ @ ~]$ sudo update-ca-trust extract

# Docker Service Restart
[ @ ~]$ sudo systemctl restart docker

[ @ ~]$ sudo docker login xa.dcr.dks.samsungds.net
Username:
Password:
Authenticating with existing credentials...
WARNING! Your password will be stored unencrypted in /root/.docker/config.json.
Configure a credential helper to remove this warning. See https://docs.docker.com/engine/reference/commandline/login/#credentials-store

Login Succeeded
```

> [!warning] Docker Credential 保存
> 上述警告并不表示登录失败，而是表示密码将以未加密状态保存在 `/root/.docker/config.json`中。如果组织提供了经过批准的 Docker credential helper，请按照相关策略进行配置。不要在文档或工作日志中记录密码。

## 5. Pull 容器镜像

### 5-1. Pull 镜像

使用以下格式将镜像保存到本地。

```bash
docker pull [DOMAIN_NAME][:PORT]/[REPOSITORY_PATH]/[IMAGE][:TAG]
```

示例：

```console

75a963e94de0: Already exists
7b1fab684d70: Already exists
db24d06d5af4: Already exists
3ce19acfc13c: Pull complete
```

> [!note] 所提供日志中的标记
> 命令指定的是 `dspaas-testrepo/nginx:latest`，但所提供日志的第一行记录为 `v1.0: Pulling from dks-test/nginx`。为保留源文档，该行未作修改。实际执行时，应以命令中指定的 Repository 和 Tag 为准确认结果。

### 5-2. 确认本地镜像

确认保存在本地的镜像。

```bash
sudo docker image ls
```

示例：

## 6. Push 容器镜像

### 6-1. 将镜像 Tag 修改为目标地址

将待上传镜像的 Repository 地址修改为目标 Repository 地址。

```bash
docker tag [SOURCE_IMAGE][:TAG] [DOMAIN_NAME][:PORT]/[REPOSITORY_PATH]/[IMAGE][:TAG]
```

示例：

```console
[ @ ~]$ sudo docker image ls
nginx                                                  v1.0     ac13107facae   2 weeks ago    142MB

[ @ ~]$ sudo docker tag nginx:v1.0 xa.dcr.dks.samsungds.net/dspaas-testrepo/nginx:latest

[ @ ~]$ sudo docker image ls
REPOSITORY                                             TAG      IMAGE ID       CREATED        SIZE
xa.dcr.dks.samsungds.net/dspaas-testrepo/nginx        latest   ac13107facae   2 weeks ago    142MB
nginx                                                  v1.0     ac13107facae   2 weeks ago    142MB
```

### 6-2. 将镜像 Push 到 Registry

```bash
docker push [DOMAIN_NAME][:PORT]/[REPOSITORY_PATH]/[IMAGE][:TAG]
```

示例：

```console
[ @ ~]$ sudo docker push xa.dcr.dks.samsungds.net/dspaas-testrepo/nginx:latest
The push refers to repository [xa.dcr.dks.samsungds.net/dspaas-testrepo/nginx]
a3d6c9eec156: Layer already exists
33e3df466e11: Layer already exists
747b7a567071: Layer already exists
57d3fc88cb3f: Layer already exists
53ae81198b64: Layer already exists
58354abe5f0e: Layer already exists
ad6562704f37: Layer already exists
test: digest: sha256:f5578142accc4a354c4759f960645f83328ca602a17083e82c873a070a7fd172 size: 1777
```

> [!note] 所提供日志中的 Tag 标记
> Push 命令使用 `latest` Tag，但所提供日志的最后一行记录为 `test: digest: ...`。为保留源文档，该行未作修改。实际 Push 时，应同时检查命令中使用的 Tag，以及 Harbor Repository 页面中显示的 Artifact 和 Digest，以确认 Push 是否成功。
