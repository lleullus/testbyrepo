> [!summary] 摘要
> KubeSphere 使用流程：确认账户 → 开放防火墙 → 获取 Project 权限 → 部署 PVC/Image Secret/Deployment/Service/Route → 设置 Autoscaling

> [!warning] Xi'an 适用状态
> Cluster、网络、Harbor 和 StorageClass 信息已根据 Xi'an 集群目录更新。SCS AD 集成信息和 KubeSphere Dashboard 最终 FQDN 尚未确认。
> 安装基准为 KubeSphere `v3.2.1`。如果界面名称不同，应以 Xi'an 实际 Console 为准，并在 [[10. 기준 및 설계/클러스터 카탈로그/클러스터 카탈로그|Xi'an Cluster 详细概览]] 中再次确认环境值。

## 1. 注册 AD 账户

KubeSphere 用户申请以 AD 账户为基准处理。SCS AD 域、组路径、安全组及最终登录方式尚未确认，未经运营团队确认不得沿用原 Taylor 环境值。

### AD 安全组信息

| 项目 | 值 |
|------|------|
| 域 | 需要向运营团队确认 |
| 位置 | 需要向运营团队确认 |
| 安全组 | 需要向运营团队确认 |

## 2. 开放防火墙

要访问 KubeSphere Dashboard、Harbor 和所需的 Member Cluster Ingress，必须开放从用户 Source IP 到下列目标 80/443 端口的防火墙访问权限。

### Dashboard IP

| 服务 | IP | 端口 |
|--------|------|------|
| KubeSphere Dashboard | 109.156.25.46 | 80, 443 |

Dashboard 最终 FQDN 仍需确认。上述 IP 是 `prd-host-pa01-xas` 的 Host Ingress VIP。

### Cluster Ingress IP

| Cluster | IP | 端口 | 用途 |
|---------|------|------|------|
| prd-apps-pa01-xas | 109.156.25.60 | 80, 443 | 生产环境 Ingress 访问 |
| dev-apps-pa01-xas | 109.156.25.75 | 80, 443 | 开发环境 Ingress 访问 |

### Harbor IP

| 服务 | IP | 端口 |
|--------|------|------|
| Harbor (Container Image Registry) | 109.156.22.53 | 80, 443 |

Harbor FQDN 为 `xa.dcr.dks.samsungds.net`。

## 3. 权限管理

在与 Namespace 等同的 Project 中为用户分配角色。申请表中的 `Admin` 映射为 `project-operator`，`User` 映射为 `project-viewer`。可管理成员的 `project-admin` 按单独的运营策略授予。

| 角色 | 说明 |
|------|------|
| **project-admin** | 管理项目资源、设置和成员，仅按单独的运营策略授予 |
| **project-operator** | 可创建、修改和删除资源，但不能管理用户、角色或项目设置；对应申请表 `Admin` |
| **project-viewer** | 仅可查看项目资源；对应申请表 `User` |

### 授予 Operator 权限的流程

1. 使用具有 `project-admin` 权限的账户登录
2. **Projects** → 选择项目 → **Project Settings** → **Project Members**
3. 点击 **Invite** 或 **+User** → 添加已邀请到 Workspace 的成员账户
4. 在角色中选择 **project-operator** → **OK**

## 4. 部署 PVC (UI)

### 4-1. 创建 PVC

1. KubeSphere Dashboard → 选择目标项目 → **Storage** → **Volumes** → **Create**

### 4-2. 基本信息

| 项目 | 输入 | 备注 |
|------|------|------|
| Name | `<pvc-name>` | 必填 |
| Alias | — | 可选 |
| Description | — | 可选 |

### 4-3. 设置 PVC 选项

| 项目 | 选择 | 备注 |
|------|------|------|
| Storage Class | `scs-netapp-qtree-nfs-sc-delete` | Xi'an NetApp NFS；通过 UI 列表或 `kubectl get sc` 再次确认 |
| Access Mode | RWX | 仅在需要共享挂载且 StorageClass 支持时选择 |
| Volume Capacity | 输入已批准 Quota 范围内的容量 | — |

### 4-4. 创建

**Advanced Settings** → **Create**

---

## 5. 部署镜像 Secret (UI)

1. 在与 Deployment 相同的项目中点击 **Configuration** → **Secrets** → **Create**
2. 在 **Basic Information** 中输入 Secret Name → Next
3. 在 **Data Settings** 中设置 Secret 选项
4. **Type**：选择 Image registry information
5. **Registry Address**：输入 `xa.dcr.dks.samsungds.net`
6. **Username**：输入镜像仓库账户
7. **Password**：输入镜像仓库密码
8. 点击 **Create**

仅创建 Secret 不会自动生效。必须在 Deployment 的 Image Pull Secret 中明确选择该 Secret，并且不得在文档或 YAML 中记录密码。

## 6. 部署 Deployment (UI)

### 6-1. 创建 Deployment

1. KubeSphere Dashboard → 选择项目 → **Application Workloads** → **Workloads** → **Deployments** → **Create**

### 6-2. 基本信息

| 项目 | 输入 | 备注 |
|------|------|------|
| Name | `<deployment-name>` | 必填 |
| Alias | — | 可选 |
| Description | — | 可选 |

### 6-3. 设置选项

| 项目 | 输入 | 备注 |
|------|------|------|
| Pod Replicas | 输入副本数 | — |
| Container Image | `xa.dcr.dks.samsungds.net/<harbor-project>/<image>:<tag>` | 替换为实际 Harbor Project、Repository 和 Tag |

保持 Pod Label 与 Deployment Selector 一致，并设置容器 CPU/Memory `requests` 和 `limits`。使用私有镜像时，连接同一项目中的 Image Pull Secret。

### 6-4. 挂载 PVC

1. 选择 **Volume Settings** → **Mount Volume** → **Existing Volume**
2. 选择卷 → 选择 PVC 名称
3. 在挂载路径中输入容器内部绝对路径，例如 `/data`

### 6-5. 创建

**Advanced Settings** → **Create**

## 7. 部署 Service

### 7-1. 创建 Service

1. KubeSphere Dashboard → 选择项目 → **Application Workloads** → **Services** → **Create**
2. 选择 **Specify Workloads**

### 7-2. Service 名称

| 项目 | 输入 | 备注 |
|------|------|------|
| Name | `<service-name>` | 必填 |
| Alias | — | 可选 |
| Description | — | 可选 |

### 7-3. 设置选项

| 项目 | 输入 | 备注 |
|------|------|------|
| Label Selector | 输入与 Deployment Pod Template Label 完全相同的值 | 不一致时不会生成 Endpoint |
| Ports | 输入 Protocol、Name、Container Port、Service Port | Container Port 必须与应用实际监听端口一致 |

### 7-4. 创建

**Advanced Settings** → **Create**

## 8. 部署 Route (Ingress)

KubeSphere Route 是 Kubernetes Ingress。HostName 使用目标环境的域名模式：生产环境 `*.xaprdpa01.apps.dks.samsungds.net`，开发环境 `*.xadevpa01.apps.dks.samsungds.net`。

### 8-1. 创建 Route

1. KubeSphere Dashboard → 选择项目 → **Application Workloads** → **Routes** 或 **Routers** → **Create**

### 8-2. Route 名称

| 项目 | 输入 | 备注 |
|------|------|------|
| Name | `<route-name>` | 必填 |
| Alias | — | 可选 |
| Description | — | 可选 |

### 8-3. 设置 Route 选项

| 项目 | 输入 | 备注 |
|------|------|------|
| Add Route Rule | 选择 Specify Domain | — |
| HostName | 输入目标环境已批准的 FQDN | 禁止混用生产与开发域名 |
| Protocol | 选择 HTTP/HTTPS | — |
| Paths | 输入 path、连接服务、端口 | — |

### 8-4. 创建

**Advanced Settings** → **Create**

## 9. 基于 YAML 的部署

### 9-1. PVC YAML

1. KubeSphere Dashboard → **Storage** → **Volumes** → **Create** → **Edit YAML**

将下例中的 `example-project`、资源名称和容量替换为已批准的实际值。

```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  namespace: example-project
  name: nginx-test
spec:
  accessModes:
    - ReadWriteMany
  resources:
    requests:
      storage: 10Gi
  storageClassName: scs-netapp-qtree-nfs-sc-delete
  volumeMode: Filesystem
```

### 9-2. Deployment YAML

1. KubeSphere Dashboard → 选择项目 → **Application Workloads** → **Workloads** → **Deployments** → **Create** → **Edit YAML**

将 `image` 和 `imagePullSecrets.name` 替换为在同一 Project 中确认的实际值。

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  namespace: example-project
  name: nginx-test
  labels:
    app: nginx-test
spec:
  replicas: 1
  selector:
    matchLabels:
      app: nginx-test
  template:
    metadata:
      labels:
        app: nginx-test
    spec:
      imagePullSecrets:
        - name: harbor-registry-secret
      containers:
        - image: xa.dcr.dks.samsungds.net/example-project/nginx:latest
          imagePullPolicy: IfNotPresent
          name: nginx
          ports:
            - containerPort: 80
              name: http-test
              protocol: TCP
          volumeMounts:
            - mountPath: /data
              name: nginx-data
          resources:
            requests:
              cpu: 100m
              memory: 128Mi
            limits:
              cpu: 500m
              memory: 256Mi
      volumes:
        - name: nginx-data
          persistentVolumeClaim:
            claimName: nginx-test
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxUnavailable: 25%
      maxSurge: 25%
```

### 9-3. Service YAML

1. KubeSphere Dashboard → 选择项目 → **Application Workloads** → **Services** → **Create** → **Specify Workload** → **Edit YAML**

```yaml
apiVersion: v1
kind: Service
metadata:
  namespace: example-project
  name: nginx-test
  labels:
    app: nginx-test
spec:
  sessionAffinity: None
  ports:
    - name: http-test
      port: 80
      protocol: TCP
      targetPort: 80
  selector:
    app: nginx-test
```

### 9-4. Route YAML

1. KubeSphere Dashboard → 选择项目 → **Application Workloads** → **Routes** → **Create** → **Edit YAML**

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  namespace: example-project
  name: nginx-test
spec:
  rules:
    - host: nginx-test.xadevpa01.apps.dks.samsungds.net
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: nginx-test
                port:
                  number: 80
```

## 10. 设置 Autoscaling

1. 选择项目 → **Application Workloads** → **Workloads** → 选择 Deployment
2. 点击 **More** → **Edit Autoscaling**
3. 确认 Metrics API 正常，且目标容器已设置 CPU/Memory `requests`，然后设置选项并点击 **OK**

| 项目 | 说明 |
|------|------|
| Target CPU Usage (%) | 容器平均 CPU 使用量占 `resources.requests.cpu` 的百分比 |
| Target Memory Usage (MiB) | 每个 Pod 的平均内存绝对使用量，与相对于内存请求量的百分比不同 |
| Minimum Replicas | 最小 Pod 数量 |
| Maximum Replicas | 最大 Pod 数量，必须大于或等于 Minimum Replicas |

## 11. 使用 Kubectl CLI

`kubectl` 不是默认用户访问路径。仅当目标 Cluster 的 Bastion 账户、防火墙、CyberArk 权限及用户专用 kubeconfig 均获批准后才可使用。

- 需要向 T-DKS 团队申请创建 Bastion 账户（与 AD 账户名相同）
- 收到账户创建通知后，还需要另外申请 **CyberArk 权限**
- kubeconfig 可能包含私钥，应作为敏感信息处理，并将用户文件权限限制为 `0600`
- 在已批准的 Project 中以只读方式验证访问，例如 `kubectl auth can-i get pods -n <project>`

详细流程请参考 [[50. 운영/중국어 번역/04. Kubesphere Operation/06. Enable users using kubectl CLI|使用 kubectl CLI 启用用户]]。
