# 1. Bastion 节点预设置

本文档是 Taylor Bastion 预设置流程在 Xi'an 环境中的转换版本。
Taylor 节点名称、IP 地址、VIP、DNS 值和软件包名称不得复制到 Xi'an 环境。

## 0. 前提条件

Xi'an 环境包含一个 Host 集群和两个 Member 集群。在完成 `/etc/hosts` 和 Ansible 清单之前，必须从 SCS VM 清单中确认 VM 主机名、节点 IP、操作系统和资源信息。

### 0-1. 已确认的 Xi'an 集群配置

| 集群 | 集群名称 | 域名 | Pod 网络 | Service 网络 | VIP-B |
|---|---|---|---|---|---|
| Host | `PRD-HOST-PA01-XAS` | `*.xaprdpa01.mgmt.dks.samsungds.net` | `172.210.0.0/16` | `192.210.0.0/16` | `109.156.25.46` |
| Member - PRD | `PRD-APPS-PA01-XAS` | `*.xaprdpa01.apps.dks.samsungds.net` | `172.211.0.0/16` | `192.211.0.0/16` | `109.156.25.60` |
| Member - DEV | `DEV-APPS-PA01-XAS` | `*.xadevpa01.apps.dks.samsungds.net` | `172.212.0.0/16` | `192.212.0.0/16` | `109.156.25.75` |

集群安装前仍需确认以下值：

| 项目 | 状态 | 必需操作 |
|---|---|---|
| Bastion 运行模式 | 需确认 | 确认使用一台共享 SCS VM，还是每个集群使用一个 Bastion。 |
| 节点主机名/IP 列表 | 需确认 | 获取每个集群的最终 SCS VM 清单。 |
| Kubernetes API 的 VIP-A | 需确认 | 获取 API 负载均衡器虚拟 IP 以及端口 6443 的映射。 |
| 操作系统和 VM 资源 | 需确认 | 确认最终的 CPU、内存、磁盘和挂载点分配。 |
| Xi'an DKS 软件包 URL 和目录名称 | 需确认 | 从 Xi'an 软件包负责人处获取软件包路径。 |

### 0-2. ETCD 文件系统要求

确认安装前 VM 模板的挂载点。根据最终节点角色设计，ETCD 节点需要 `/var/lib/etcd`；工作节点和基础设施节点需要 `/var/lib/containerd`。

```bash
hostnamectl
lsblk -f
df -hT
findmnt /var/lib/containerd /var/lib/etcd
```

在确认 SCS 节点清单和角色分配后记录最终结果。不要将 Taylor 的角色到主机映射应用于 Xi'an 节点。

### 0-3. `dspaas` 账户要求

Bastion 和所有 Kubernetes 节点上必须存在 `dspaas` 账户。该账户必须属于 `wheel` 组，并能在 Kubespray 执行期间使用免密码 sudo。

```bash
id dspaas
getent group wheel
sudo -n true
```

所需结果：

```text
uid=<dspaas-uid>(dspaas) gid=<dspaas-gid>(dspaas) groups=<dspaas-gid>(dspaas),10(wheel)
wheel:x:10:dspaas
```

UID 和主 GID 是环境值，必须保留 SCS VM 中的值。如果账户不在 `wheel` 组中，请按照已批准的 SCS 流程在目标 VM 上添加该账户。


开始测试前通知服务台。未通知的后端变更可能触发负载均衡器服务下线检测。

## 0-5. 验证 VIP-B 路由

Xi'an VIP-B 地址和目标端口已知。确认最终 Router 节点列表后，在每个 Router 节点上启动临时 HTTP 服务器，然后测试每个 VIP。

```bash
python3 -m http.server 18080 --bind 0.0.0.0
curl -i http://109.156.25.46/
curl -i http://109.156.25.60/
curl -i http://109.156.25.75/
```

HTTP 服务器端口仅用于临时后端测试。完成负载均衡器配置验证后，VIP-B 服务端口仍为 `80` 和 `443`。

| VIP-B | 集群 | 服务端口 | 后端角色 | 结果 |
|---|---|---:|---|---|
| `109.156.25.46` | `PRD-HOST-PA01-XAS` | 80, 443 | Router | 待执行 |
| `109.156.25.60` | `PRD-APPS-PA01-XAS` | 80, 443 | Router | 待执行 |
| `109.156.25.75` | `DEV-APPS-PA01-XAS` | 80, 443 | Router | 待执行 |

## 0-6. 验证 VIP-A 路由

当前环境准备文档中尚未记录 Xi'an VIP-A 地址。不要复用其他环境的 VIP-A 值。

SCS 提供 VIP-A 地址后，针对 Master 节点验证端口 `6443`：

```bash
curl -k -i https://<xian-vip-a>:6443/healthz
```

配置 API 负载均衡器后的所需结果：

```text
HTTP/1.1 200 OK
ok
```

## 1. 配置 Bastion 节点

Xi'an 需要一个 Bastion 执行点，用于 Kubespray、Helm 和集群管理。当前资料指出由 SCS VM 执行这些操作，但未确认该 VM 是否由三个集群共享。在创建最终清单文件前，确认此运行模式。

### 1-1. 验证 Nameserver 文件 (`/etc/resolv.conf`)

Xi'an VM 已包含所需的 DNS 配置。因此不需要按照 Taylor 流程替换 DNS。验证当前配置并保留 SCS 提供的值。

```bash
cat /etc/resolv.conf
getent hosts nexus.adpaas.cloud.samsungds.net
getent hosts repo.samsungds.net
```

当前 Xi'an 环境记录表明，由于已部署 VM 上已配置 DNS，无需单独请求 SCS DNS。如果查找失败，请停止操作并请求 SCS DNS/NTP 配置，不要复制 Taylor 的 nameserver 地址。

### 1-2. 配置 Hosts 文件 (`/etc/hosts`)

当前环境准备文档中没有最终 Xi'an 节点主机名/IP 清单。向 SCS 获取并在 Bastion 及所有节点上更新 `/etc/hosts`。

```bash
cp -p /etc/hosts /etc/hosts.$(date +%Y%m%d%H%M%S)
vi /etc/hosts
cat /etc/hosts
getent hosts $(hostname -s)
```

以下条目是已确认的外部端点，不得与 Kubernetes 节点条目混淆：

```text
109.156.22.53 xa.dcr.dks.samsungds.net
109.156.25.46 PRD-HOST-PA01-XAS
109.156.25.60 PRD-APPS-PA01-XAS
109.156.25.75 DEV-APPS-PA01-XAS
```

上述 VIP 条目仅供操作员参考。将其添加到生产 `/etc/hosts` 前，使用 SCS 提供的最终 DNS/L4 命名规范。节点清单确认前不要添加节点条目。

## 2. 用户和权限设置

### 2-1. 确认 `dspaas` 用户组

```bash
cat /etc/group | grep '^wheel:'
id dspaas
```

所需组结果：

```text
wheel:x:10:dspaas
```

### 2-2. 配置 sudoers

使用 `visudo` 为 `wheel` 组启用免密码 sudo。仅通过已批准的 SCS 账户管理流程应用此更改。

```bash
sudo visudo
sudo grep -nE '^#?%wheel' /etc/sudoers
sudo -n true
```

必须启用的条目：

```text
%wheel ALL=(ALL) NOPASSWD: ALL
```

## 3. 安装前置软件依赖

Kubespray 要求 Bastion 具备 Python、Pip、Ansible 和 SSH 访问能力。Xi'an 仅在确认连通性和仓库归属后，才使用与 Taylor 流程相同的内部仓库模式。

### 3-1. 验证仓库连通性

Xi'an 环境准备记录确认可访问以下端点：

| 端点 | 地址 | 用途 | 状态 |
|---|---|---|---|
| HQ Nexus | `10.227.100.42` | Kubespray 和 Helm 软件包传输 | 开放 |
| HQ JFrog | `10.227.253.89` | Python/YUM 软件包访问 | 开放 |
| HQ Harbor | `10.166.111.201` | 集群镜像传输 | 开放 |

修改仓库文件前，从 Bastion 验证访问：

```bash
curl -I --connect-timeout 10 http://10.227.100.42
curl -I --connect-timeout 10 http://10.227.253.89
curl -I --connect-timeout 10 http://10.166.111.201
```

本运行手册未记录确切的 Nexus 仓库路径、JFrog 虚拟仓库路径和凭据。向 Xi'an 软件包负责人获取这些信息。不要记录密码或复制 Taylor 的凭据值。

### 3-2. 配置 `pip.conf`

在仓库负责人确认路径后，使用 Xi'an 批准的 JFrog 端点。下方 Taylor URL 并非 Xi'an 的确认值，未经连通性验证不得应用。

```bash
sudo vi /etc/pip.conf
sudo cat /etc/pip.conf
```

必需的配置格式：

```ini
[global]
index-url=http://<xian-approved-jfrog-pypi-path>/simple
trusted-host=<xian-approved-jfrog-host>
```

### 3-3. 配置 YUM 仓库

在 `/etc/yum.repos.d/` 下创建 Xi'an 批准的仓库文件。最终 base URL 待仓库所有者确认。

```bash
cd /etc/yum.repos.d/
sudo vi Appstream.repo
sudo vi Artifactory-docker.repo
sudo vi BaseOS.repo
sudo vi EPEL.repo
sudo vi kubernetes.repo
sudo dnf repolist
```

所需仓库检查：

```text
repo id                         repo name                         status
appstream                       Xi'an Appstream                   enabled
baseos                          Xi'an BaseOS                      enabled
epel                            Xi'an EPEL                        enabled
kubernetes                      Xi'an Kubernetes                   enabled
```

上述仓库 ID 和名称是验证目标。确认端点后，记录实际的 SCS 仓库值。

### 3-4. 安装 Python 3.8

```bash
python3 -V
cd /usr/bin
test -e python || sudo ln -s python3.8 python
python -V
```

所需 Python 结果：

```text
Python 3.8.x
```

确切的 Xi'an 软件包版本由启用的仓库决定，安装后必须在 Bastion 上记录。

### 3-5. 更新 Pip

```bash
python -m pip install --upgrade pip
pip -V
```

结果必须显示 Pip 运行于 Python 3.8，并使用 Xi'an 批准的内部索引。

## 4. Kubespray 安装准备

### 4-1. 下载 Xi'an DKS 安装包

当前环境材料中未确认 Xi'an 软件包 URL 和目录名称。执行下载步骤前先获取这些信息。

```bash
su - dspaas
wget '<xian-approved-dks-package-url>'
tar -xf '<xian-dks-package-file>.tar'
ls -al
```

在执行日志中记录实际软件包名称和校验和：

```bash
sha256sum '<xian-dks-package-file>.tar'
```

Xi'an 软件包必须包含 Kubespray 文件、Helm 二进制文件、kubectl 二进制文件，以及已批准 DKS 版本所需的任何集群专用部署资产。对于 Xi'an NetApp Trident 存储路径，不需要 PowerFlex 和 ScaleIO 资产。

### 4-2. 安装 Helm

在已确认的 Xi'an 软件包中的 Helm 目录执行此步骤。

```bash
cd <xian-package-directory>/helm-<approved-version>/
ls -al helm
sudo cp -p helm /usr/local/bin/helm
ls -al /usr/local/bin/helm
helm version
```

从 Xi'an 软件包记录已安装的 Helm 版本。除非 Xi'an 软件包负责人确认版本相同，否则不要假定 Taylor 的 `v3.8.2`。

### 4-3. 从 `dks-requirements.txt` 安装 Python 软件包

```bash
cd <xian-package-directory>/DKS-Kubespray-<approved-version>/
pip list
ansible --version
```

所需 Ansible 检查：

```text
ansible [core <approved-version>]
config file = None
executable location = /usr/local/bin/ansible
python version = 3.8.x
```

### 4-4. 生成 SSH 密钥对

在 `dspaas` 账户下生成密钥，并通过已批准的 SCS 流程分发公钥。

```bash
su - dspaas
ssh-keygen -t rsa -b 3072
ls -l ~/.ssh/id_rsa ~/.ssh/id_rsa.pub
```

所需密钥结果：

```text
RSA 3072
```

不要将私钥内容放入本文档或执行证据中。

### 4-5. 安装 `sshpass`

```bash
sudo yum -y install sshpass
rpm -q sshpass
```

所需结果：

```text
sshpass-1.09-*.el8.x86_64
```

### 4-6. 创建 Xi'an Ansible 清单

Xi'an 节点主机名/IP 列表及共享 Bastion 与每集群独立 Bastion 的运行模式尚未确认。不要使用 Taylor 主机名填充 Ansible 清单。仅在 SCS 提供最终节点角色后创建清单。

角色结构保持如下：

```ini
[k8s:children]
master
router
infra
system

[bastion]
# Xi'an Bastion hostname: pending SCS inventory

[master]
# Xi'an Master hostnames: pending SCS inventory

[etcd]
# Xi'an ETCD hostnames: pending SCS inventory

[router]
# Xi'an Router hostnames: pending SCS inventory

[infra]
# Xi'an Infra hostnames: pending SCS inventory

[system]
# Xi'an System hostnames: pending SCS inventory
```

填充最终清单后，在运行 Kubespray 前验证名称解析和 SSH 访问：

```bash
ansible -i inventory all -m ping
ssh <xian-node-hostname> hostnamectl
```

每个节点必须得到以下结果：

```text
SUCCESS => {
    "changed": false,
    "ping": "pong"
}
```

## 5. Xi'an 转换完成状态

| 部分 | 状态 | 原因 |
|---|---|---|
| 集群名称、域名、Pod/SVC 网络 | 完成 | 已在 Xi'an 环境准备记录中确认。 |
| VIP-B 值 | 完成 | Host、PRD 和 DEV 的 VIP-B 值已记录。 |
| VIP-A 值 | 待定 | API 负载均衡器 VIP 尚未记录。 |
| DNS 流程 | 仅验证 | 已在已部署的 Xi'an VM 上配置 DNS。 |
| 节点 `/etc/hosts` 条目 | 待定 | 最终主机名/IP 清单不可用。 |
| 仓库路径 | 待定 | 尚未记录 Xi'an 批准的 JFrog/Nexus 路径。 |
| DKS 软件包下载 | 待定 | 尚未记录 Xi'an 软件包 URL 和目录名称。 |
| Ansible 清单 | 待定 | 最终节点角色和 Bastion 运行模式尚未确认。 |

本文档可通过已确认的部分执行。在向 Xi'an VM 应用更改前，从 SCS 补充待定值。
