# 设置配额

> [!summary] 摘要
> 设置 Workspace Quotas（CPU/Memory）、Project Quotas（CPU/Memory）、Storage Resource Quota 这 3 种配额。在 Xi'an 环境中，存储应以 NetApp Trident StorageClass 为基准进行配置。在 DKS 环境中，Workspace 和 Project 为 1:1 匹配，因此 Workspace Quota 和 Project Quota 设置为相同的值。

> [!note] 申请表关联
> 根据用户提交的申请表中的 **DKS Information** 项目（CPU、Memory、Storage）设置 Quota 值。申请表示例请参考 [[50. 운영/중국어 번역/04. Kubesphere Operation/01. Creating Workspaces&projects|01. 创建 Workspace 和 Project]] 文档。

---

## 1. Workspace Quotas（CPU/Memory）

Workspace Quotas 控制 Workspace 内所有 Project 的总资源使用量。

在 DKS 环境中，由于 Workspace 和 Project 为 1:1 匹配，Workspace Quota 和 Project Quota 设置为相同的值。

Workspace Quotas 包含 CPU 和 Memory 的 **Requests** 和 **Limits**。

- **Requests**：保证并预留 Workspace 内 Project 所需的资源。
- **Limits**：确保 Workspace 内所有 Project 的资源使用量不超过特定值。

### 步骤

1. 点击 **Workbench > Workspaces**
2. 选择要设置 Quotas 的 **Workspace**
3. 点击 **Workspace Settings > Workspace Quotas > Edit Quotas**
4. **设置 Quotas**
   - 默认值：Requests 和 Limits 均未设置
   - 使用滑块移动或直接输入数字
    - **CPU Limit**：应用程序的 CPU 核心数
    - **CPU Request**：应用程序的 CPU 核心数
    - **Memory Limit**：应用程序的内存大小
    - **Memory Request**：应用程序的内存大小
5. 点击 **OK**

---

## 2. Project Quotas（CPU/Memory）

KubeSphere 使用 Kubernetes 的 Requests 和 Limits 控制 Project 内资源（CPU、Memory）的使用量。在 Kubernetes 中，这些称为 **ResourceQuotas**。

- **Requests**：保证并预留 Project 所需的资源。
- **Limits**：确保 Project 使用的资源不超过特定值。

### 步骤

1. 在 **Project Overview** 页面确认 Quotas
   - 新创建的 Project 尚未设置 Quotas
   - 点击 **Edit Quotas** 进行配置
2. **设置 Quotas**
   - 默认值：Requests 和 Limits 均未设置
   - 使用滑块移动或直接输入数字
    - **CPU Limit**：应用程序的 CPU 核心数
    - **CPU Request**：应用程序的 CPU 核心数
    - **Memory Limit**：应用程序的内存大小
    - **Memory Request**：应用程序的内存大小
3. 点击 **OK**
4. 在 **Project Settings > Basic Info** 中确认所有资源 Quotas

## 3. Storage Resource Quota

限制 Namespace（=Project）中可以请求的存储资源总量。此外，还可以按 StorageClass 限制存储消耗。

### 步骤

1. **确认当前 StorageClass 状态**

   ```bash
   $ kubectl get sc
   ```

   | NAME | PROVISIONER | RECLAIMPOLICY | VOLUMEBINDINGMODE | ALLOWVOLUMEEXPANSION | AGE |
   |------|-------------|---------------|-------------------|----------------------|-----|
   | scs-netapp-qtree-nfs-sc-delete | csi.trident.netapp.io | Delete | Immediate | true | 27d |

    **为当前使用的 NetApp StorageClass 设置 Quota。**

    > 请确认实际的 `kubectl get sc` 结果，并使用目标集群对应的 StorageClass 名称。

2. **创建 YAML 文件**

   ```yaml
   # storagequota.yaml
   ---
   apiVersion: v1
   kind: ResourceQuota
   metadata:
     name: (project name)-storage-quota
     namespace: (project name)
   spec:
     hard:
        # 各 StorageClass 的配额
        scs-netapp-qtree-nfs-sc-delete.storageclass.storage.k8s.io/requests.storage: 10Gi
        # PVC 请求总量
        requests.storage: 10Gi
   ```

   #### 字段说明

   | 字段 | 说明 |
   |------|------|
   | `metadata.name` | `(project name)-storage-quota` |
   | `metadata.namespace` | Project 名称 |
   | `requests.storage` | Namespace 中可以请求的存储总量（例如，“100Gi”表示总量不能超过 100Gi） |
   | `<storage-class-name>.storageclass.storage.k8s.io/requests.storage` | 对应 StorageClass 的存储请求总量 |

    **示例**：为 NetApp StorageClass 分配配额时：

   ```yaml
   spec:
     hard:
        scs-netapp-qtree-nfs-sc-delete.storageclass.storage.k8s.io/requests.storage: 50Gi
        requests.storage: 50Gi
   ```

   - `requests.storage`：所有 PersistentVolumeClaim 的存储请求总和不能超过此值
   - `<storage-class-name>.storageclass.storage.k8s.io/requests.storage`：对应 StorageClass 的 PVC 请求总和不能超过此值

3. **应用 ResourceQuota**

   ```bash
   $ kubectl create -f storagequota.yaml
   resourcequota/(project name)-storage-quota created
   ```
