# KubeSphere RBAC

> [!summary] 摘要
> KubeSphere 提供 Platform（Global）、Workspace、Project 三级角色层级。DKS 对默认角色进行自定义后使用。

---

## 1. KubeSphere 与 Kubernetes Role 对比

### Role 层级结构

| Platform Role (=Global Role) | Cluster Role | Workspace Role | None（通过 CRD 单独创建） | ProjectRole (=Namespace) |
|------------------------------|--------------|----------------|----------------------------|--------------------------|
| Role | Role | Role | — | Role |

---

## 2. DKS KubeSphere Role 定义

### KubeSphere Roles

**User Role**

| Role | 说明 |
|------|------|
| **platform-regular** | 在被邀请加入 Workspace 之前没有资源管理权限。访问权限由 platform-admin 在特定 Workspace/Project 中授予 |

**Admin Role**

| Role | 说明 |
|------|------|
| **platform-admin** | 管理 Cluster 的所有资源，并创建和管理所有 Workspace |

### Workspace Role

| Role | 说明 |
|------|------|
| **ws-viewer** | 可以查看 Workspace 内所有资源的 Viewer。由 ws-admin 邀请加入 Workspace |
| **ws-self-provisioner** | 可以在 Workspace 内创建 Project 和 DevOps Project 的 Self-provisioner 用户。**未使用** — 由于不支持 DevOps 服务，不使用此角色 |
| **ws-admin** | 管理特定 Workspace 下的所有资源（用于创建新 Project、邀请新成员） |

### ProjectRole (=Namespace)

| Role | 说明 |
|------|------|
| **project-admin** | 对 Project 内所有资源拥有完全控制权。可以创建 Workload、Pipeline 等资源，并邀请 Project 成员 |
| **project-operator** | 可以管理 Project 内除用户和角色以外的资源 |
| **project-viewer** | 可以查看 Project 内所有资源。由 project-admin 邀请加入 Project |

> [!note] 权限映射参考
> 申请表中请求 Admin 权限时分配 `project-operator` 角色，请求 User 权限时分配 `project-viewer` 角色。请参考 [[50. 운영/중국어 번역/04. Kubesphere Operation/03. Assigning project roles to users|为用户分配 Project 角色]] 文档。
