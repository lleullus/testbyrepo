## 1. Taints & Tolerations 개념

### 구성 요소

Taints와 Tolerations는 Key, Value, Effect 3성분으로 구성된다.

- **Taints** (노드 속성) — 노드가 특정 Pod을 거부하도록 설정
- **Tolerations** (Pod 속성) — Pod이 taint가 있는 노드에 스케줄링되도록 허용

예시: `key1=value1:NoSchedule` — `key1`이 `value1`인 taint가 있는 노드에 매칭되는 toleration이 없는 Pod은 스케줄링 불가

### Effect 3종

| Effect | 동작 |
|--------|------|
| `PreferNoSchedule` | Pod 스케줄링 시도 않음 (권장, 엄격하지 않음) |
| `NoSchedule` | 매칭 toleration 없는 Pod 스케줄링 불가 |
| `NoExecute` | 매칭 toleration 없는 Pod 즉시 격리(Eviction) |

## 3. scale.yml 실행

```bash
[dspaas@xadksbtmp01 20.kubespray-release-2.19 (prod-ds-ksp-member-xas:monitoring)]$ ansible-playbook -e @inventory/dks/dks_vars.yml -i inventory/dks/hosts.yaml --become --become-user=root scale.yml --limit "worker1_node"
```

> [!note] 참고
> 기본 노드 추가(`01. Adding a worker node using kubespray`)와 차이점: `--limit` 대상이 `worker1_node` 그룹이며, taint/label이 자동으로 적용됨

## 5. 노드셀렉터 & 톨레이션 배포

### 5-1. nodeSelector

Pod spec에 `nodeSelector`를 추가하여 대상 노드의 라벨과 매칭:

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: checker-podselector-test3
spec:
  replicas: 1
  selector:
    matchLabels:
      app: checker3
  template:
    metadata:
      labels:
        app: checker3
    spec:
      containers:
        - name: checker
          image: xa.dcr.dks.samsungds.net/dspaas-testrepo/checker:v5
          command: ['s', '-c', 'sleep 365d']
      nodeSelector:
        kubernetes.io/os: linux
        team: dscmp
        node-type: worker
```

### 5-2. tolerations

taint가 있는 노드에 Pod 스케줄링을 허용:

```yaml
spec:
  tolerations:
    - key: team
      value: dscmp
      effect: NoSchedule
```
