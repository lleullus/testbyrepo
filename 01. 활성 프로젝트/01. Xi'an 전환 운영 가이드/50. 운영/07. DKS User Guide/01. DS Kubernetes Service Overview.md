> [!summary] 요약
> Xi'an DKS는 KubeSphere에서 Kubernetes 애플리케이션 리소스를 운영하고 Harbor에서 컨테이너 이미지를 관리하는 서비스다. 사용자는 할당된 Project에서 작업하며, Project는 Kubernetes Namespace와 동일하다.

> [!warning] 시안 상태
> 이 문서는 Xi'an 기준 자료로 Taylor 환경값을 교체한 시안이다. 클러스터와 네트워크 값은 현재 카탈로그를 반영했지만, SCS AD 연동 정보와 KubeSphere Dashboard의 최종 FQDN은 확정 전이다.

---

## 1. 서비스 구성

| 구성 요소 | Xi'an 기준 | 사용자 관점의 역할 |
|---|---|---|
| KubeSphere Host | `prd-host-pa01-xas` | 사용자 로그인, Workspace·Project와 권한 관리 |
| Production Member | `prd-apps-pa01-xas` | 운영 애플리케이션 배포·실행 |
| Development Member | `dev-apps-pa01-xas` | 개발 애플리케이션 배포·실행 |
| Harbor | `prd-harbor-xas` | 컨테이너 이미지 저장·Push·Pull |

KubeSphere의 관리 영역과 애플리케이션 실행 영역은 분리된다. 사용자는 Host의 웹 콘솔에서 할당된 Project를 선택하고, 실제 워크로드는 Production 또는 Development Member Cluster에 배포한다.

---

## 2. 도메인 및 접속 정보

| 대상 | 도메인 또는 패턴 | 접속 IP | 포트 | 상태 |
|---|---|---:|---:|---|
| KubeSphere Dashboard | 최종 FQDN 확인 필요 | `109.156.25.46` | 80, 443 | Host Ingress VIP 확인 |
| Host Ingress | `*.xaprdpa01.mgmt.dks.samsungds.net` | `109.156.25.46` | 80, 443 | 카탈로그 반영 |
| Production Ingress | `*.xaprdpa01.apps.dks.samsungds.net` | `109.156.25.60` | 80, 443 | 카탈로그 반영 |
| Development Ingress | `*.xadevpa01.apps.dks.samsungds.net` | `109.156.25.75` | 80, 443 | 카탈로그 반영 |
| Harbor | `xa.dcr.dks.samsungds.net` | `109.156.22.53` | 80, 443 | FQDN·인증서 완료 |

외부 80/443 요청은 각 Ingress VIP에서 Router Node의 30080/30443 포트로 전달된다. 접속 전 사용자 Source IP에서 필요한 대상 IP와 포트로 방화벽이 개방되어 있어야 한다.

> [!note] 인증 확인 필요
> 사용자 신청은 AD 계정을 기준으로 처리한다. 다만 SCS AD 도메인과 KubeSphere 연동 정보는 현재 기준 자료에서 요청 중이므로, 최종 로그인 방식과 계정 활성화 절차는 운영팀 확인 후 확정한다.

## 3. Workspace, Project, Namespace

- DKS 정책상 **Workspace 1개와 Project 1개를 1:1로 구성**한다.
- KubeSphere의 **Project는 Kubernetes Namespace와 동일**하다.
- 사용자는 할당된 Project 안에서만 허용된 애플리케이션 리소스를 조회하거나 관리한다.
- CPU·Memory는 Workspace와 Project Quota로, Storage는 Namespace 전체 및 StorageClass별 Quota로 제한한다.

신청서의 `Admin` 요청은 기본적으로 KubeSphere `project-operator`에, `User` 요청은 `project-viewer`에 매핑된다. `project-operator`는 워크로드와 스토리지 같은 리소스를 관리할 수 있지만 Project 멤버와 역할은 관리할 수 없다. 멤버 관리 권한이 있는 `project-admin`은 별도 운영 정책에 따른다.

## 4. 이용 흐름

1. KubeSphere Dashboard, Harbor, 사용할 Member Cluster Ingress에 대한 방화벽 개방을 요청한다.
2. 운영팀 안내에 따라 KubeSphere에 최초 로그인하여 계정 접근 이력을 생성한다.
3. Project명, 대상 환경, CPU·Memory·Storage, 사용자와 요청 권한을 기재한 이용 신청서를 제출한다.
4. 운영팀이 Workspace와 Project를 생성하고 사용자를 초대한 뒤 Project 역할과 Quota를 부여한다.
5. Harbor Project 멤버로 추가된 사용자는 이미지를 Push하고, KubeSphere에서 해당 이미지를 사용해 워크로드를 배포한다. Private 이미지는 Image Secret이 필요하다.
6. 애플리케이션은 대상 Member Cluster의 Ingress 도메인으로 노출한다.

`kubectl`은 기본 사용자 접속 경로가 아니다. Bastion 계정, 방화벽, CyberArk 권한과 사용자별 kubeconfig가 승인된 경우에만 별도 운영 절차에 따라 사용한다.
