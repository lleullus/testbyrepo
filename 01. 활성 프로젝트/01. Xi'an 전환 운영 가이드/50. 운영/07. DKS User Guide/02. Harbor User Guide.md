> [!summary] 요약
> Global AD 보안그룹 등록 → Harbor 방화벽 개방 → 웹 콘솔 접속 → Docker CA 인증서 적용 및 로그인 → Container Image Pull → Tag 및 Push 순서로 Harbor를 사용한다.

> [!warning] Xi'an 적용 상태
> Harbor FQDN `xa.dcr.dks.samsungds.net`, IP `109.156.22.53`, 포트 `80/443`은 Xi'an 클러스터 카탈로그와 설치 문서에서 확인했다. Global AD 보안그룹 `SG1599`, DS Pass·GSAMS 신청 경로는 제공된 기존 가이드의 값이며 Xi'an 최종 운영 절차로 확정되지 않았다. 신청 전에 Xi'an 운영팀에 유효성을 확인한다.

> [!note] 명령 및 로그 배치 기준
> 아래 실행 예시는 제공된 명령과 출력 로그를 생략하지 않고 배치했다. Taylor 레지스트리 주소만 Xi'an 주소로 치환했으므로 실제 Xi'an 실행 증적이 아니라 절차 예시다. 원문 출력 안의 태그·repository 표기 불일치는 그대로 보존하고 각 블록 아래에 별도로 표시했다.

## 1. Global AD 보안그룹 등록

Harbor는 Global AD 계정으로 접속한다. 사용자가 해당 AD 보안그룹의 멤버인 경우 Global AD 계정으로 Harbor에 접근할 수 있다.

AD 보안그룹 멤버 등록 요청은 [DS Pass](https://pass.samsungds.net:8082/)를 통해 제출한다.

### Global AD User Group

| AD Security group name | Description | Xi'an 확인 상태 |
|---|---|---|
| `[SG1599] DKS Prd User Group` | DKS Production environment user group | 기존 가이드 값, Xi'an 최종 확인 필요 |

> [!warning] 신청 전 확인
> Xi'an SCS AD 도메인 정보와 최종 로그인 연동 절차는 현재 기준 문서에서 미확정이다. `SG1599` 가입 요청을 제출하기 전에 Xi'an 운영팀에 대상 보안그룹과 DS Pass 경로가 그대로 적용되는지 확인한다.

## 2. Harbor 접속 방화벽 설정

Harbor에 접근하려면 사용자 시스템의 Source IP에서 Xi'an Harbor IP로 향하는 방화벽을 개방해야 한다. 방화벽 문제가 있으면 [GSAMS](http://gsams.samsungds.net/)에 문의한다.

| Purpose | Source IP | Destination IP | Port | Protocol | Description |
|---|---|---:|---:|---|---|
| To use Harbor | User IP | `109.156.22.53` | `80`, `443` | TCP | Xi'an Harbor |

> [!note] Xi'an 변경값
> 기존 Taylor Harbor IP `105.219.33.203` 대신 Xi'an Harbor Backend IP `109.156.22.53`을 사용한다. Xi'an Harbor는 별도 LB 없이 이 IP로 직접 연결한다.

## 4. Harbor 로그인

### 사전 요구사항

- 사용자가 Docker를 설치할 수 있는 시스템이 필요하다.
- 해당 시스템에서 Xi'an Harbor IP `109.156.22.53`의 TCP `80`, `443` 포트로 방화벽이 개방되어 있어야 한다.
- 승인된 Xi'an 2-Tier Root CA 인증서 파일을 시스템에 배치해야 한다.
- 아래 CA trust 경로와 명령은 RHEL 계열 시스템 기준이며 `sudo` 권한이 필요하다.

인증서 파일: `SECDS-2TROOTCA.crt`

> [!warning] 2-Tier Root CA 필수
> Xi'an Harbor 접속에는 `SECDS-2TROOTCA.crt`를 사용해야 한다. 일반 CA 인증서 또는 서버 인증서 파일로 대체할 수 없다.

### G-AD 계정으로 로그인

```console
# Copy CA Certification
[ @ ~]$ sudo cp ./SECDS-2TROOTCA.crt /etc/pki/ca-trust/source/anchors

# CA-Trust Update
[ @ ~]$ sudo update-ca-trust extract

# Docker Service Restart
[ @ ~]$ sudo systemctl restart docker

[ @ ~]$ sudo docker login xa.dcr.dks.samsungds.net
Username:
Password:
Authenticating with existing credentials...
WARNING! Your password will be stored unencrypted in /root/.docker/config.json.
Configure a credential helper to remove this warning. See https://docs.docker.com/engine/reference/commandline/login/#credentials-store

Login Succeeded
```

> [!warning] Docker credential 저장
> 위 경고는 로그인 실패가 아니라 `/root/.docker/config.json`에 비밀번호가 암호화되지 않은 상태로 저장된다는 경고다. 조직에서 승인한 Docker credential helper가 있으면 해당 정책에 따라 구성한다. 비밀번호를 문서나 작업 로그에 기록하지 않는다.

## 5. Container Image Pull

### 5-1. Image Pull

이미지를 로컬에 저장하려면 다음 형식으로 실행한다.

```bash
docker pull [DOMAIN_NAME][:PORT]/[REPOSITORY_PATH]/[IMAGE][:TAG]
```

Example:

```console
[ @ ~]$ sudo docker pull xa.dcr.dks.samsungds.net/dspaas-testrepo/nginx:latest
v1.0: Pulling from dks-test/nginx
42c077c10790: Already exists
62c70f376f6a: Already exists
915cc9bd79c2: Already exists
75a963e94de0: Already exists
7b1fab684d70: Already exists
db24d06d5af4: Already exists
3ce19acfc13c: Pull complete
Digest: sha256:f5578142accc4a354c4759f960645f83328ca602a17083e82c873a070a7fd172
Status: Downloaded newer image for xa.dcr.dks.samsungds.net/dspaas-testrepo/nginx:latest
xa.dcr.dks.samsungds.net/dspaas-testrepo/nginx:latest
```

> [!note] 제공 로그의 표기
> 명령은 `dspaas-testrepo/nginx:latest`이지만 제공 로그의 첫 줄은 `v1.0: Pulling from dks-test/nginx`로 기록되어 있다. 이 줄은 원문 보존을 위해 수정하지 않았다. 실제 실행 시 명령에 지정한 repository와 tag를 기준으로 결과를 확인한다.

### 5-2. 로컬 Image 확인

로컬에 저장된 이미지를 확인한다.

```bash
sudo docker image ls
```

Example:

```console
[ @ ~]$ sudo docker image ls
REPOSITORY                                             TAG      IMAGE ID       CREATED        SIZE
xa.dcr.dks.samsungds.net/dspaas-testrepo/nginx        latest   ac13107facae   2 weeks ago    142MB
```

## 6. Container Image Push

### 6-1. Push 대상 주소로 Image Tag 변경

업로드할 Image의 repository 주소를 Push 대상 repository 주소로 변경한다.

```bash
docker tag [SOURCE_IMAGE][:TAG] [DOMAIN_NAME][:PORT]/[REPOSITORY_PATH]/[IMAGE][:TAG]
```

Example:

```console
[ @ ~]$ sudo docker image ls
nginx                                                  v1.0     ac13107facae   2 weeks ago    142MB

[ @ ~]$ sudo docker tag nginx:v1.0 xa.dcr.dks.samsungds.net/dspaas-testrepo/nginx:latest

[ @ ~]$ sudo docker image ls
REPOSITORY                                             TAG      IMAGE ID       CREATED        SIZE
xa.dcr.dks.samsungds.net/dspaas-testrepo/nginx        latest   ac13107facae   2 weeks ago    142MB
nginx                                                  v1.0     ac13107facae   2 weeks ago    142MB
```

### 6-2. Registry로 Image Push

```bash
docker push [DOMAIN_NAME][:PORT]/[REPOSITORY_PATH]/[IMAGE][:TAG]
```

Example:

```console
[ @ ~]$ sudo docker push xa.dcr.dks.samsungds.net/dspaas-testrepo/nginx:latest
The push refers to repository [xa.dcr.dks.samsungds.net/dspaas-testrepo/nginx]
a3d6c9eec156: Layer already exists
33e3df466e11: Layer already exists
747b7a567071: Layer already exists
57d3fc88cb3f: Layer already exists
53ae81198b64: Layer already exists
58354abe5f0e: Layer already exists
ad6562704f37: Layer already exists
test: digest: sha256:f5578142accc4a354c4759f960645f83328ca602a17083e82c873a070a7fd172 size: 1777
```

> [!note] 제공 로그의 태그 표기
> Push 명령의 tag는 `latest`이지만 제공 로그의 마지막 줄은 `test: digest: ...`로 기록되어 있다. 이 줄은 원문 보존을 위해 수정하지 않았다. 실제 Push 성공 여부는 명령에 사용한 tag와 Harbor repository 화면의 artifact 및 digest를 함께 확인한다.
