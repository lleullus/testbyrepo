# 5-1. KubeSphere Host 클러스터 설치 및 운영 구성

Xi'an KubeSphere Host 클러스터 `prd-host-pa01-xas`를 설치하고, DKS 표준 배치 및 모니터링 운영 구성을 적용하는 절차입니다. Host 클러스터는 member 클러스터를 관리하는 중앙 control plane이며 환경당 하나만 지정합니다.

### 참조 출력 규칙

- `참조 출력: 예상`은 권위 문서의 확정된 리소스명과 환경값을 사용한 예상 형태이며 실제 Xi'an 실행 증적이 아닙니다.
- Pod suffix, Pod IP, AGE, timestamp, UID, resourceVersion, checksum, token, secret 값은 실행 후 실제 출력으로 기록합니다.
- 실제 실행 증적에는 실행 일시, 실행자, 대상 context를 함께 남기고 이 문서의 예상 출력을 덮어쓰지 않습니다.
- password, token, JWT secret, private key와 webhook 인증값은 기록하지 않습니다. 필요한 경우 `<승인된 자격 증명>` 또는 역할이 드러나는 placeholder만 사용합니다.

### 공통 사전 확인

`dspaas` 사용자로 Bastion에서 실행합니다. 현재 context가 대상 Host 클러스터인지 확인하고, Host 인벤토리에 `system` 노드를 추가하지 않습니다.

```bash
kubectl config current-context
kubectl get nodes -o name | sort
kubectl get nodes --show-labels | egrep 'node-type=|node-role.kubernetes.io/'
```

참조 출력: 예상

```text

node/xadksirhm02
node/xadksirhm03
node/xadksmahm01
node/xadksmahm02
node/xadksmahm03
node/xadksrthm01
node/xadksrthm02
node/xadksrthm03
```

다음 조건이 모두 충족되어야 합니다.

- 현재 context가 `prd-host-pa01-xas`용 kubeconfig를 사용한다.
- `xadksirhm01`부터 `xadksirhm03`까지가 `node-type=infra`이고 `node-role.kubernetes.io/infra:NoSchedule` 정책을 수용한다.
- API VIP-A `109.156.25.43:6443`은 Xi'an 노드 인벤토리에 기록되어 있으나, Bastion 사전 설정 문서에서는 확인 필요 상태다. 프로덕션 실행 전 SCS에 실제 L4 매핑을 확인한다.
- `cluster-configure.yaml`과 `kubesphere-installer.yaml`은 같은 Host bundle에서 확보한다.

## 5-1-4. Installer 로그 확인 및 monitoring 재시도

`cluster-configure.yaml` 적용 후 `ks-installer` 로그를 확인합니다. KubeSphere `v3.2.1`에서 ServiceMonitor CRD 준비 전에 node-exporter ServiceMonitor가 적용되면 monitoring task가 첫 시도에 실패할 수 있습니다.

```bash
kubectl logs -n kubesphere-system \
  "$(kubectl get pod -n kubesphere-system -l app=ks-install -o jsonpath='{.items[0].metadata.name}')" -f
```

참조 출력: 예상

```text
Start installing monitoring
Start installing multicluster
Start installing openpitrix
Start installing network
Start installing devops
**************************************************
Waiting for all tasks to be completed ...
```

다음 오류는 알려진 CRD 준비 순서 문제로 분류합니다. 설정값을 임의 변경하지 않습니다.

참조 출력: 예상

```text
task monitoring status is failed
error: unable to recognize "/kubesphere/kubesphere/prometheus/node-exporter/node-exporter-serviceMonitor.yaml": no matches for kind "ServiceMonitor" in version "monitoring.coreos.com/v1"
```


## 5-1-5. DKS 표준 workload 재배치

KubeSphere installer의 nodeSelector/toleration은 설치 후 생성된 모든 workload에 자동 전파되지 않을 수 있습니다. Xi'an Host에는 `system` 노드 타입이 없으므로 아래 대상 workload는 모두 `infra` 노드로 재배치합니다.

| Namespace | 대상 리소스 | 대상 노드 |
|---|---|---|
| `kubesphere-monitoring-system` | `alertmanager/main`, `prometheus/k8s`, `prometheus-operator`, `kube-state-metrics`, `notification-manager`, `notification-manager-operator` | `infra` |
| `kubesphere-controls-system` | `default-http-backend`, `kubectl-admin` | `infra` |
| `kubesphere-devops-system` | `devops-apiserver`, `devops-controller`, `devops-jenkins`, `s2ioperator`, `devops` CronJob | `infra` |
| `kubesphere-system` | `ks-apiserver`, `ks-console`, `ks-controller-manager`, `minio`, `tower`, `redis-ha-haproxy`, `openldap`, `redis-ha-server` | `infra` |

`common.redis.enabled: false` 및 `common.openldap.enabled: false`이므로 `redis-ha-*`와 `openldap`가 없을 수 있습니다. 존재하는 리소스만 patch합니다.

### Monitoring namespace

```bash
kubectl -n kubesphere-monitoring-system patch alertmanager main --type=json \
  -p='[{"op":"add","path":"/spec/nodeSelector","value":{"node-type":"infra","kubernetes.io/os":"linux"}}]'
kubectl -n kubesphere-monitoring-system patch alertmanager main --type=json \
  -p='[{"op":"add","path":"/spec/tolerations/0","value":{"key":"node-role.kubernetes.io/infra","effect":"NoSchedule"}}]'
kubectl -n kubesphere-monitoring-system patch prometheus k8s --type=json \
  -p='[{"op":"add","path":"/spec/nodeSelector","value":{"node-type":"infra","kubernetes.io/os":"linux"}}]'
kubectl -n kubesphere-monitoring-system patch prometheus k8s --type=json \
  -p='[{"op":"add","path":"/spec/tolerations/0","value":{"key":"node-role.kubernetes.io/infra","effect":"NoSchedule"}}]'

for deploy in prometheus-operator kube-state-metrics notification-manager-operator; do
  kubectl -n kubesphere-monitoring-system get deployment "$deploy" >/dev/null 2>&1 || continue
  kubectl -n kubesphere-monitoring-system patch deployment "$deploy" --type merge \
    -p '{"spec":{"template":{"spec":{"nodeSelector":{"kubernetes.io/os":"linux","node-type":"infra"},"tolerations":[{"key":"node-role.kubernetes.io/infra","effect":"NoSchedule"}]}}}}'
done

kubectl -n kubesphere-monitoring-system patch notificationmanagers notification-manager --type=json \
  -p='[{"op":"add","path":"/spec/nodeSelector","value":{"node-type":"infra","kubernetes.io/os":"linux"}}]'
kubectl -n kubesphere-monitoring-system patch notificationmanagers notification-manager --type=json \
  -p='[{"op":"add","path":"/spec/tolerations/0","value":{"key":"node-role.kubernetes.io/infra","effect":"NoSchedule"}}]'
```

### Controls 및 DevOps namespace

```bash
for deploy in default-http-backend kubectl-admin; do
  kubectl -n kubesphere-controls-system get deployment "$deploy" >/dev/null 2>&1 || continue
  kubectl -n kubesphere-controls-system patch deployment "$deploy" --type merge \
    -p '{"spec":{"template":{"spec":{"nodeSelector":{"kubernetes.io/os":"linux","node-type":"infra"},"tolerations":[{"key":"node-role.kubernetes.io/infra","effect":"NoSchedule"}]}}}}'
done

for deploy in devops-apiserver devops-controller devops-jenkins; do
  kubectl -n kubesphere-devops-system get deployment "$deploy" >/dev/null 2>&1 || continue
  kubectl -n kubesphere-devops-system patch deployment "$deploy" --type merge \
    -p '{"spec":{"template":{"spec":{"nodeSelector":{"kubernetes.io/os":"linux","node-type":"infra"},"tolerations":[{"key":"node-role.kubernetes.io/infra","effect":"NoSchedule"}]}}}}'
done

kubectl -n kubesphere-devops-system get statefulset s2ioperator >/dev/null 2>&1 && \
  kubectl -n kubesphere-devops-system patch statefulset s2ioperator --type merge \
    -p '{"spec":{"template":{"spec":{"nodeSelector":{"kubernetes.io/os":"linux","node-type":"infra"},"tolerations":[{"key":"node-role.kubernetes.io/infra","effect":"NoSchedule"}]}}}}'
```

`devops` CronJob Pod가 `Pending`이거나 `JobAlreadyActive`면 현재 상태를 확인한 후 toleration을 추가합니다.

```bash
kubectl -n kubesphere-devops-system describe cronjob devops
kubectl -n kubesphere-devops-system patch cronjob devops --type merge \
  -p '{"spec":{"jobTemplate":{"spec":{"template":{"spec":{"tolerations":[{"key":"node-role.kubernetes.io/infra","effect":"NoSchedule"}]}}}}}}'
```

### KubeSphere system namespace 및 installer 중지

`ks-installer`가 다시 실행되면 설정 일부가 초기 상태 방향으로 돌아갈 수 있으므로 설치 완료 후 replica를 `0`으로 유지합니다.

```bash
for deploy in ks-apiserver ks-console ks-controller-manager minio tower redis-ha-haproxy; do
  kubectl -n kubesphere-system get deployment "$deploy" >/dev/null 2>&1 || continue
  kubectl -n kubesphere-system patch deployment "$deploy" --type merge \
    -p '{"spec":{"template":{"spec":{"nodeSelector":{"kubernetes.io/os":"linux","node-type":"infra"},"tolerations":[{"key":"node-role.kubernetes.io/infra","effect":"NoSchedule"}]}}}}'
done

for sts in openldap redis-ha-server; do
  kubectl -n kubesphere-system get statefulset "$sts" >/dev/null 2>&1 || continue
  kubectl -n kubesphere-system patch statefulset "$sts" --type merge \
    -p '{"spec":{"template":{"spec":{"nodeSelector":{"kubernetes.io/os":"linux","node-type":"infra"},"tolerations":[{"key":"node-role.kubernetes.io/infra","effect":"NoSchedule"}]}}}}'
done

kubectl scale -n kubesphere-system deployment ks-installer --replicas=0
kubectl get deployment -n kubesphere-system ks-installer
```

### 변환 파일 생성

아래 절차는 기존 `Sensor` group을 제거한 뒤 재생성하므로 중복을 만들지 않습니다. 각 기존 group에서는 `record` rule만 유지하고 `alert` rule은 제거합니다.

```bash
cd ~/dks-prom-rules

python3 <<'PY'
import json
import subprocess
import sys

namespace = "kubesphere-monitoring-system"
name = "prometheus-k8s-rules"

raw = subprocess.check_output(
    ["kubectl", "get", "prometheusrule", name, "-n", namespace, "-o", "json"],
    text=True,
)
obj = json.loads(raw)

metadata = obj.setdefault("metadata", {})
for key in [
    "resourceVersion",
    "uid",
    "creationTimestamp",
    "generation",
    "managedFields",
    "selfLink",
]:
    metadata.pop(key, None)

kept_groups = []
for group in obj.get("spec", {}).get("groups") or []:
    if group.get("name") == "Sensor":
        continue
    record_rules = [rule for rule in group.get("rules") or [] if "record" in rule]
    if record_rules:
        kept_group = {
            "name": group.get("name"),
            "interval": group.get("interval"),
            "partial_response_strategy": group.get("partial_response_strategy"),
            "rules": record_rules,
        }
        kept_groups.append({key: value for key, value in kept_group.items() if value is not None})

kept_groups.append(
    {
        "name": "Sensor",
        "rules": [
            {
                "alert": "[Grade I Sensor] Pod Status Issue (Core)",
                "annotations": {
                    "description": "NameSpace: {{ $labels.namespace }} , Pod: {{ $labels.pod }}. Pod status is: {{ $labels.phase }}."
                },
                "expr": 'kube_pod_status_phase{phase!~"Succeeded|Running", namespace=~"kube.*|ingress.*"} != 0',
                "for": "5m",
                "labels": {
                    "cluster": "{{ $externalLabels.cluster }}",
                    "grade": "I",
                    "type": "Status",
                },
            },
            {
                "alert": "[Grade C Sensor] Node Status Issue (NotReady)",
                "annotations": {
                    "description": "Node: {{ $labels.node }} status is NotReady."
                },
                "expr": 'kube_node_status_condition{condition="Ready", status="true"} != 1',
                "for": "5m",
                "labels": {
                    "cluster": "{{ $externalLabels.cluster }}",
                },
            },
        ],
    }
)

obj["spec"]["groups"] = kept_groups
record_count = sum(1 for group in kept_groups for rule in group["rules"] if "record" in rule)
alert_count = sum(1 for group in kept_groups for rule in group["rules"] if "alert" in rule)
print(
    f"groups={len(kept_groups)} record_rules={record_count} alert_rules={alert_count}",
    file=sys.stderr,
)

try:
    import yaml

    with open("prometheus-k8s-rules.dks.yaml", "w", encoding="utf-8") as output:
        yaml.safe_dump(obj, output, sort_keys=False, allow_unicode=True)
    print("wrote prometheus-k8s-rules.dks.yaml")
except Exception:
    with open("prometheus-k8s-rules.dks.json", "w", encoding="utf-8") as output:
        json.dump(obj, output, ensure_ascii=False, indent=2)
    print("wrote prometheus-k8s-rules.dks.json (PyYAML unavailable)")
PY
```

참조 출력: 예상
