### 실제 증적과 예상 출력

- `참조 출력(예상)`은 manifest와 절차에서 확정된 형식만 보인 예시이며, Xi'an 실행 증적이 아니다.
- Pod hash, Pod IP, 생성 시간, UUID, `resourceVersion`, PV 이름, token, Secret 값은 `<실행 후 기록>`으로 남긴다.
- 비밀번호, JWT Secret, token, private key는 출력하거나 문서에 기록하지 않는다. `<HOST_JWT_SECRET>`, `<승인된 자격 증명>`, `<실행 후 생성값>`만 사용한다.
- 명령은 Bastion `xadksbtmd01`에서 `dspaas` 계정으로 실행한다. 다른 context 또는 다른 노드에서 실행해야 하면 해당 명령 앞에 명시한다.

`1.service.yaml`과 `2.endpoints.yaml`은 아래 구조여야 한다.

```yaml
apiVersion: v1
kind: Service
metadata:
  name: etcd-k8s
  namespace: monitoring
  labels:
    k8s-app: etcd-k8s
spec:
  type: ClusterIP
  clusterIP: None
  ports:
    - name: metrics
      port: 2379
      targetPort: 2379
  selector: null
---
apiVersion: v1
kind: Endpoints
metadata:
  name: etcd-k8s
  namespace: monitoring
  labels:
    k8s-app: etcd-k8s
subsets:
  - addresses:
      - ip: 109.156.22.70
      - ip: 109.156.22.71
      - ip: 109.156.22.72
    ports:
      - name: metrics
        port: 2379
        protocol: TCP
```

Secret에서 확인한 실제 key 이름을 넣어 `3.servicemonitor-metrics.yaml`을 완성한다.

```yaml
apiVersion: monitoring.coreos.com/v1
kind: ServiceMonitor
metadata:
  name: etcd-k8s
  namespace: monitoring
  labels:
    k8s-app: etcd-k8s
spec:
  jobLabel: k8s-app
  endpoints:
    - port: metrics
      interval: 30s
      scheme: https
      tlsConfig:
        caFile: /etc/prometheus/secrets/etcd-certs/ca.pem
        certFile: /etc/prometheus/secrets/etcd-certs/<확인한-dev-node-cert>.pem
        keyFile: /etc/prometheus/secrets/etcd-certs/<확인한-dev-node-cert>-key.pem
        serverName: etcd-cluster
        insecureSkipVerify: true
  selector:
    matchLabels:
      k8s-app: etcd-k8s
```

`insecureSkipVerify: true`는 원본 DKS procedure의 값이다. ETCD 인증서 운영 담당자가 SAN 검증 전환을 승인하기 전에는 임의로 변경하지 않는다.

- [ ] `project-admin` RoleBase가 생성됐다.
- [ ] Host Join용 secret 일치 여부와 kubeconfig 전달 준비가 완료됐다. 값은 기록하지 않는다.

## 5-2-3. Member Cluster Host Join

**상태: 과거 참고/미확정.** `Member 클러스터/개요.md`는 5-2-3을 작성 예정으로 정의한다. 현재 작업본에 있는 과거 Join 로그, Pod 이름, 시간, signature 오류 사례는 Xi'an DEV 실행 증적이나 확정된 실행 절차가 아니다.

이 문서에서 확정하는 범위는 5-2-2-6의 Join 준비까지다. Host Console import 절차, Host endpoint, Join 결과 판정, 재시도 절차는 Host/Member Join 권위 문서와 담당자 승인을 받은 뒤 별도 최신화한다.

## 5-2-4. Daily Monitoring Script 배포

**상태: 과거 참고/미확정.** `Member 클러스터/개요.md`는 5-2-4를 작성 예정으로 정의한다. 현재 작업본의 legacy script 경로, ETCD wrapper, Ansible inventory, node 목록, 대화형 출력은 Xi'an DEV에 적용하지 않는다.

향후 실행 문서에 필요한 확정 입력은 다음과 같다.

- Xi'an 승인 script bundle 경로와 version
- DEV Member ETCD hostname 및 certificate path
- script 실행 계정과 sudo 권한
- namespace 수집 범위와 결과 보관 위치
- schedule, alert 전달 담당자, warning 대응 기준

위 입력이 확정되기 전에는 daily monitoring script를 배포하거나 과거 출력으로 정상 여부를 판정하지 않는다.

## 확인 필요

| 항목 | 사유 | 필요한 확인 |
|---|---|---|
| DEV API VIP 및 Console endpoint | 개요와 5-2-2 상세 문서의 표기가 일치하지 않으며, 이 문서의 실행 대상 VIP는 Ingress VIP `109.156.25.75`만 확정됨 | SCS/L4 담당자가 DEV Member API VIP와 NodePort 노출 경로를 승인 |
| External ETCD Secret key 이름 | Secret은 현장 생성값이며 인증서 key 이름을 권위 문서가 고정하지 않음 | `etcd-certs` metadata에서 key 이름만 확인 |
| Custom Prometheus component image/tag 및 imagePullSecret | registry host와 repository 원칙만 확정됨 | 실제 DEV bundle manifest와 Harbor에서 component별 repository/tag 및 pull secret 확인 |
| Ingress TLS Secret | 권위 문서가 80/443 L4 경로만 정의함 | Ingress Controller와 인증서 정책 확인 |
| 5-2-3 Host Join 실행 절차 | 개요가 작성 예정으로 표기 | Host Join 권위 문서, 책임자, 성공 기준 확정 |
| 5-2-4 Daily monitoring script | bundle/경로/운영 정책이 확정되지 않음 | Xi'an 승인 bundle 및 운영 책임자 승인 |

## 실행 증적 수집

민감값을 제외한 증적만 수집한다. 파일명과 보관 위치는 운영 담당자 승인 경로를 사용한다.

```bash
mkdir -p ~/5-2-evidence
kubectl get nodes -o wide > ~/5-2-evidence/01-nodes.txt
kubectl get storageclass > ~/5-2-evidence/02-storageclass.txt
kubectl get pod -n monitoring -o wide > ~/5-2-evidence/03-monitoring-pods.txt
kubectl get pvc -n monitoring -o wide > ~/5-2-evidence/04-monitoring-pvc.txt
kubectl get ingress -n monitoring -o wide > ~/5-2-evidence/05-monitoring-ingress.txt
kubectl get endpoints -n monitoring etcd-k8s > ~/5-2-evidence/06-etcd-endpoints.txt
kubectl get pod -n kubesphere-system -o wide > ~/5-2-evidence/07-kubesphere-system-pods.txt
kubectl get rolebase > ~/5-2-evidence/08-rolebase.txt
kubectl get deploy -n kubesphere-system ks-installer > ~/5-2-evidence/09-ks-installer.txt
```

Secret, kubeconfig, JWT Secret, password, certificate private key, token은 위 증적에 포함하지 않는다.
