# 3. Ansible Playbook 배포 및 클러스터 설정

이 문서는 Xi'an 환경의 Ansible Playbook 배포, 배포 후 설정 및 클러스터 구성 검증 절차를 정리한 문서입니다.

> [!warning] 원문 로그 주의
> 원문 로그에는 Taylor 환경 또는 과거 실행의 호스트명, IP 주소, 도메인, 저장소, 클러스터 값과 자격 증명이 포함될 수 있습니다. Xi'an 확정값으로 간주하거나 현재 환경에 그대로 적용하지 마십시오.

## 3-1. Ansible Playbook 배포 환경 설정

Xi'an 클러스터 정보를 기준으로 Ansible 실행 환경과 Kubespray 설정 파일을 준비합니다.

### 3-1-1. Ansible 설정 파일 준비

`host_key_checking` 값을 `False`로 설정하여 strict host key check를 비활성화합니다. Ansible은 기본적으로 host key checking을 사용합니다. 이는 서버 스푸핑과 man-in-the-middle 공격을 방지하지만, 서버 재설치 후 `known_hosts`의 key가 달라지거나 새 호스트가 등록되지 않은 경우 조치 또는 확인이 필요합니다. 이 동작을 비활성화하려면 `/etc/ansible/ansible.cfg` 또는 `/.ansible/cfg`를 수정합니다.

```bash
cd SCS_DKS_Kubernetes_Stack-v1.0/DKS-Kubespray-v2.19/
cat ansible.cfg | grep host_key
```

```bash
[dspaas@xadksbthm01 ~]$ cd SCS_DKS_Kubernetes_Stack-v1.0/DKS-Kubespray-v2.19/
```

참조 출력:

```text
[dspaas@xadksbthm01 DKS-Kubespray-v2.19]$ ls
```

## 3-2. Ansible Playbook 배포

준비한 인벤토리와 설정을 사용하여 Kubespray Ansible Playbook을 배포합니다.

### 3-2-1. Ansible Playbook 배포

Kubespray를 Ansible Playbook으로 배포합니다. 완료에는 약 20~30분이 소요되며, Playbook을 root로 실행하려면 `--become` 옵션이 필요합니다.

```bash
ansible-playbook -e @inventory/dks/dks_vars.yml -i inventory/dks/hosts.yaml --become --become-user=root cluster.yml
```

```bash
[dspaas@xadksbthm01 DKS-Kubespray-v2.19]$ ansible-playbook -e @inventory/dks/dks_vars.yml -i inventory/dks/hosts.yaml --become --become-user=root cluster.yml
```

설치가 성공하면 Kubernetes 클러스터가 설치되어 실행 중이어야 합니다. master 노드 중 하나에 root로 SSH하여 클러스터 상태를 확인합니다.
