# 4. Kubernetes 스토리지 컴포넌트 구축 및 설치 검증

이 문서는 **Xi'an KubeSphere Host 클러스터 `prd-host-pa01-xas`**의 External Snapshotter와 NetApp Trident 스토리지 컴포넌트 구축·검증 절차를 정리한 운영 가이드입니다.

> [!important] 대상 고정
> 이 문서의 대상은 Xi'an Host Cluster `prd-host-pa01-xas`입니다. Bastion은 `xadksbthm01`, Host Infra 노드는 `xadksirhm01`~`xadksirhm03`입니다. PRD/DEV Member Cluster의 `xadks*mp*`, `xadks*md*` 실행 결과를 Host 실행 증적으로 사용하지 않습니다.

> [!danger] Taylor/TAS 원문 값 사용 금지
> 기존 원문에 있던 `khdks*`, `dtadks*`, Taylor/TAS용 LIF·aggregate·export policy·PowerFlex endpoint·MDM·credential은 Xi'an Host 값이 아닙니다. 이 문서에서는 확인된 Xi'an Host 값만 고정하고, 현재 Obsidian에서 Host 실증적을 찾지 못한 동적 출력은 `<Host 실제 실행 후 기록>`으로 남깁니다. Pod suffix, Pod IP, PVC/PV UID, backend UUID, AGE, timestamp를 임의 생성하지 않습니다.

> [!note] 증적 표기
> - **확인값**: Xi'an Host 카탈로그 또는 Xi'an 실제 소스에서 확인된 값
> - **공통 Xi'an Storage 확인값**: Xi'an SCS Storage 자료에서 확인됐지만 Host live 출력으로 다시 확인할 값
> - **실행 후 기록**: Host에서 명령을 실제 실행한 뒤 출력 원문을 넣을 값
> - **미확인**: 다른 환경 값으로 채우지 않고 담당 자료 또는 live 조회가 필요한 값

## 4-1. 외부 스냅샷터 설치

External Snapshotter는 CSI snapshot API와 snapshot controller를 제공하는 공통 선행 컴포넌트입니다. Host에서는 Trident 설치 전에 snapshot CRD와 controller 상태를 확인합니다.

### 4-1-1. 외부 스냅샷터 설치

#### 1. 설치 파일 확인

```bash
[dspaas@xadksbthm01 ~]$ ls -al /app/dspaas/SCS_DKS_Kubernetes_Stack-v1.0/external-snapshotter/
```

확인 대상:

```text
1.snapshot.storage.k8s.io_volumesnapshotclasses.yaml
2.snapshot.storage.k8s.io_volumesnapshotcontents.yaml
3.snapshot.storage.k8s.io_volumesnapshots.yaml
4.rbac-snapshot-controller.yaml
5.setup-snapshot-controller.yaml
```

실제 Host package 파일 목록:

```text
<Host 실제 실행 후 기록>
```

설치 파일이 없으면 다른 Cluster package에서 복사하지 않습니다. 현재 Host용 승인 package와 기준본을 먼저 확인합니다.

#### 2. Replica 수 확인

Host Infra는 세 노드입니다.

```bash
[dspaas@xadksbthm01 ~]$ grep -n 'replicas:' /app/dspaas/SCS_DKS_Kubernetes_Stack-v1.0/external-snapshotter/5.setup-snapshot-controller.yaml
```

기대 구성:

```text

```

Replica만 보지 말고 배치 조건도 확인합니다.

```bash
[dspaas@xadksbthm01 ~]$ grep -nE 'replicas:|nodeSelector:|node-type|tolerations:|NoSchedule' /app/dspaas/SCS_DKS_Kubernetes_Stack-v1.0/external-snapshotter/5.setup-snapshot-controller.yaml
```

Host 기준 의도:

```text
controller replica = 3
배치 대상 = Host infra 계층
실행 후 NODE = xadksirhm01~03 중 하나
```

#### 3. 적용 전 dry-run

```bash
[dspaas@xadksbthm01 ~]$ kubectl apply --dry-run=client -f /app/dspaas/SCS_DKS_Kubernetes_Stack-v1.0/external-snapshotter/
```

오류가 없을 때만 실제 적용 범위를 확인합니다.

#### 4. 설치

신규 구축 또는 승인된 재구축에서만 수행합니다.

```bash
[dspaas@xadksbthm01 ~]$ kubectl apply -f /app/dspaas/SCS_DKS_Kubernetes_Stack-v1.0/external-snapshotter/
```

실제 Host 적용 출력:

```text

```

기대 리소스 종류:


실제 Host 출력:

```text

```

#### 7. Deployment와 Pod 확인

```bash
[dspaas@xadksbthm01 ~]$ kubectl get deploy -n kube-system snapshot-controller -o wide
```

```text
5. 비정상 restart 또는 Pending 원인이 없음
```

> [!warning] 증적 미확보
> 현재 Obsidian에는 위 Snapshotter의 **Host 실제 Pod suffix/IP/timestamp 출력 원문이 별도로 보존되어 있지 않습니다.** 따라서 과거 Taylor Pod 이름이나 IP를 Xi'an 값으로 치환하지 않습니다.

## 4-2. PowerFlex 스토리지 컴포넌트 설치(필요 시)

> [!important] Xi'an Host 현재 판정: 적용 제외
> `prd-host-pa01-xas`의 KubeSphere Host 설정은 `persistence.storageClass`와 `monitoring.storageClass`에 `scs-netapp-qtree-nfs-sc-delete`를 사용합니다. 기존 원문의 PowerFlex StorageClass를 Host 실제값으로 취급하지 않습니다.

이 절은 원문의 항목 구조를 유지하되 **현재 Host에 PowerFlex를 설치하는 절차로 실행하지 않습니다.** 향후 Host에 PowerFlex 사용이 별도 승인될 때만 Storage 담당자와 신규 기준을 받아 재작성합니다.

### 4-2-1. Master, Infra, Router, Worker 노드 ScaleIO 에이전트 설치

Host에는 현재 Worker role이 별도로 없으며, 현재 스토리지 기준은 NetApp Trident입니다. 따라서 Taylor의 SDC RPM 배포·MDM 등록 절차를 Host 노드에 실행하지 않습니다.

#### 1. 현재 Host StorageClass 확인

```bash
[dspaas@xadksbthm01 ~]$ kubectl get storageclass
```

판정:

```text
scs-netapp-qtree-nfs-sc-delete가 Host에서 사용 중인지 확인
PowerFlex 전용 StorageClass가 보인다면 "설치 필요"로 단정하지 말고 현재 사용 여부/기원을 확인
```

#### 2. CSI Driver 확인

```bash
[dspaas@xadksbthm01 ~]$ kubectl get csidriver
```

Host 기준 필수 확인 대상:

```text
csi.trident.netapp.io
```

PowerFlex CSI가 예상 밖으로 존재하면 아래를 읽기 전용으로 확인합니다.

```bash
[dspaas@xadksbthm01 ~]$ kubectl get ns vxflexos
[dspaas@xadksbthm01 ~]$ kubectl get pod -n vxflexos -o wide
```

실제 Host 출력:

```text
<Host 실제 실행 후 기록 또는 NotFound>
```

#### 3. Host 노드에 SDC를 신규 설치하지 않음

다음 종류의 작업은 현재 Host 절차에서 수행하지 않습니다.

```text
- ScaleIO SDC RPM 배포
- MDM_IP 환경변수로 SDC 등록
- /etc/emc/scaleio/drv_cfg.txt 수정
- scini service 신규 설치/재시작
- PowerFlex systemID/endpoint 입력
```

특히 과거 원문의 MDM, endpoint, systemID, GUID는 Xi'an Host 값이 아닙니다.

#### 4. 향후 PowerFlex 도입 시 필요한 선행 정보

PowerFlex가 정말 Host 요구사항으로 추가되면 아래 항목을 **새로** 확보합니다.

| 항목 | 필요 값 |
|---|---|
| 적용 Cluster | `prd-host-pa01-xas`인지 승인 확인 |
| 대상 Node role | Master/Router/Infra 중 실제 대상 |
| SDC version | Storage Pool과 호환되는 승인 버전 |
| MDM | Xi'an Host용 실제 값 |
| PowerFlex endpoint | Xi'an Host용 실제 값 |
| systemID | Xi'an Host용 실제 값 |
| Storage Pool | Xi'an Host용 실제 값 |
| credential source | Secret/승인 저장소; 문서 평문 금지 |
| StorageClass | 신규 승인 이름 |
| rollback | SDC/CSI/SC 제거 순서와 영향도 |

### 4-2-2. CSI 드라이버 설치

현재 Host에서는 PowerFlex CSI 설치 명령을 실행하지 않습니다.

#### 적용 여부 확인

```bash
[dspaas@xadksbthm01 ~]$ kubectl get storageclass
[dspaas@xadksbthm01 ~]$ kubectl get csidriver
[dspaas@xadksbthm01 ~]$ kubectl get ns | grep -E '^vxflexos\b' || true
```

기록 형식:

```text
Cluster: prd-host-pa01-xas
NetApp StorageClass: <Host 실제 출력>
Trident CSI: <Host 실제 출력>
PowerFlex Namespace: <Host 실제 출력 또는 없음>
PowerFlex CSI Driver: <Host 실제 출력 또는 없음>
판정: 현재 Host PowerFlex 적용 제외 / 별도 확인 필요
```

> [!danger] Secret 원문 출력 금지
> 기존 문서처럼 Storage credential Secret을 base64 decode하여 password, endpoint, systemID를 문서에 출력하지 않습니다. Secret 존재 여부와 metadata까지만 확인합니다.

## 4-3. NetApp Trident 스토리지 컴포넌트 설치

Host의 실제 KubeSphere 설정은 `scs-netapp-qtree-nfs-sc-delete`를 사용하므로 이 절이 Xi'an Host Storage 구축의 주 경로입니다.


Trident bundle 확인:

```bash
[dspaas@xadksbthm01 SCS_DKS_Kubernetes_Stack-v1.0]$ test -d Trident-CSI-Driver-22.07.0 && echo OK
[dspaas@xadksbthm01 SCS_DKS_Kubernetes_Stack-v1.0]$ cd Trident-CSI-Driver-22.07.0/
[dspaas@xadksbthm01 Trident-CSI-Driver-22.07.0]$ ls -al
```

확인 대상:

```text
deploy/
dks-config/
extras/
helm/
sample-input/
setup/
tridentctl
```

실제 Host package 출력:

```text
<Host 실제 실행 후 기록>
```

#### 2. tridentctl 파일 확인

```bash
[dspaas@xadksbthm01 Trident-CSI-Driver-22.07.0]$ ls -l tridentctl

```

Checksum은 실제 Host 파일값을 증적에 기록하며 다른 Cluster 값을 복사하지 않습니다.

### 4-3-2. Namespace 및 CRD 배포

#### 1. 현재 상태 먼저 확인

운영 중인 Host에서 무조건 `apply`부터 하지 않습니다.

```bash
[dspaas@xadksbthm01 Trident-CSI-Driver-22.07.0]$ kubectl get ns trident
[dspaas@xadksbthm01 Trident-CSI-Driver-22.07.0]$ kubectl get crd | grep trident
[dspaas@xadksbthm01 Trident-CSI-Driver-22.07.0]$ kubectl get tridentorchestrator trident -o yaml
```

실제 Host 출력:

```text
<Host 실제 실행 후 기록>
```

이미 정상 설치되어 있으면 신규 구축 명령을 반복하지 않고 현재 상태를 증적으로 수집합니다.

#### 2. Namespace manifest 확인

```bash
[dspaas@xadksbthm01 Trident-CSI-Driver-22.07.0]$ cat deploy/namespace.yaml
```

기준 형태:

```yaml
apiVersion: v1
kind: Namespace
metadata:
  labels:
    pod-security.kubernetes.io/enforce: privileged
  name: trident
```

실제 bundle이 다르면 실제 bundle을 우선하고 차이를 기록합니다.

#### 3. CRD manifest 확인

```bash
[dspaas@xadksbthm01 Trident-CSI-Driver-22.07.0]$ ls -al deploy/crds/
[dspaas@xadksbthm01 Trident-CSI-Driver-22.07.0]$ grep -nE 'name: tridentorchestrators|group: trident.netapp.io|scope:' deploy/crds/trident.netapp.io_tridentorchestrators_crd_post1.16.yaml
```

#### 4. TridentOrchestrator CR 확인

```bash
[dspaas@xadksbthm01 Trident-CSI-Driver-22.07.0]$ cat deploy/crds/tridentorchestrator_cr.yaml
```

Xi'an Host에서 확인할 핵심 값:

```yaml
apiVersion: trident.netapp.io/v1
kind: TridentOrchestrator
metadata:
  name: trident
spec:
  namespace: trident
  imageRegistry: xa.dcr.dks.samsungds.net/dspaas-v1.22.10-a
  controllerPluginNodeSelector:
    node-type: infra
  controllerPluginTolerations:
    - effect: NoSchedule
      key: node-role.kubernetes.io/infra
```

> [!note] Registry
> `xa.dcr.dks.samsungds.net/dspaas-v1.22.10-a`는 Xi'an Kubespray inventory에서 확인되는 registry base입니다. Trident bundle의 실제 repository/tag는 실행 전에 manifest에서 다시 확인합니다.

Host Infra가 맞는지 대조합니다.

```bash
[dspaas@xadksbthm01 Trident-CSI-Driver-22.07.0]$ kubectl get nodes -l node-type=infra -o wide
```

기대 Host node:

```text
xadksirhm01
xadksirhm02
xadksirhm03
```

#### 5. 신규 구축 시 Namespace/CRD/Orchestrator 적용

신규 구축 또는 승인된 재구축일 때만 실행합니다.


### 4-4-2 완료 후 보존할 Host 증적

최소 다음 출력은 같은 실행 시점·같은 Host context로 보존합니다.

```bash
kubectl config current-context
kubectl get nodes -o wide
kubectl get storageclass scs-netapp-qtree-nfs-sc-delete -o yaml
kubectl get pod -n trident -o wide
kubectl get pvc -n xian-host-storage-test -o wide
kubectl get pv <TEST_PV> -o yaml
kubectl get pod -n xian-host-storage-test -l app=host-netapp-test -o wide
kubectl describe pvc host-netapp-pvc -n xian-host-storage-test
kubectl describe pod <TEST_POD> -n xian-host-storage-test
kubectl exec -n xian-host-storage-test <TEST_POD> -- df -h /pvc-test
```

Trident:

```bash
./tridentctl -n trident version
./tridentctl -n trident get backend
./tridentctl -n trident get volume
```

민감정보는 보존하지 않습니다.

```text
Secret data
Storage password
Token
Private key
kubeconfig 원문
Authorization header
```
