# 0. 初始 VM 设置

## 0-1. 前置要求

在构建 Xi'an DKS 集群之前，确认所有 DKS 节点的 VM 配置和所需的负载均衡器路由。对照已批准的 VM 清单，确认主机名、IP 地址、操作系统、CPU、内存、块磁盘及文件系统布局。

| 检查对象 | 检查项目 | 验收标准 |
|---|---|---|
| 所有 DKS 节点 | 主机名、IP 地址、操作系统、资源及文件系统布局 | 与已批准的 VM 清单和角色规格一致 |
| ETCD 节点 | VM 模板文件系统用途 | 已将 `/var/lib/etcd` 分配用于 ETCD 数据 |
| Load Balancer | 到 Master 和 Router 节点的 VIP-A/VIP-B 路由 | 已记录后端连通性及相应协议的确认结果 |
| 所有节点 | DATA 磁盘及 `dspaas` 账户 | 0-2-1 和 0-2-2 章节已完成 |

在所有 Bastion、Master、ETCD、Router、Infra 及 Worker 节点上执行以下检查，然后将结果与清单进行对照。

```bash
hostnamectl
hostname -I
ip addr
cat /etc/os-release
nproc
free -h
lsblk -f
df -hT
findmnt /var/lib/containerd /var/lib/etcd
```

## 0-1-2. VIP-A/B 检查

确认每个 Load Balancer 虚拟 IP 是否路由到正确的后端角色。

- VIP-A 暴露前端端口 `6443`，并路由到 Master 节点。
- VIP-B 暴露前端端口 `80`，并路由到 Router 后端端口 `30080`。
- VIP-B 暴露前端端口 `443`，并路由到 Router 后端端口 `30443`。

可以在 Router 节点上使用临时 Python HTTP 服务器确认从 `80` 到 `30080` 的映射。

```bash
# 在用于 HTTP 映射检查的 Router 后端上
python3 -m http.server 30080 --bind 0.0.0.0

# 通过 VIP-B 前端端口 80
curl -i http://<VIP-B>/
```

`python3 -m http.server` 仅适用于 HTTP 映射确认，不能证明从 `443` 到 `30443` 的映射具备 TLS 行为。在 Router 后端端口 `30443` 上使用适当的 TLS 支持监听器，然后通过 VIP-B 执行具备 TLS 感知能力的连接测试。

```bash
# VIP-B TLS 前端检查
curl -k -i https://<VIP-B>/

# 后端监听器可用时执行适当的 TLS 感知测试
openssl s_client -connect <VIP-B>:443
```

VIP-A 端口 `6443` 是 Kubernetes API/TLS 端点。普通 HTTP 服务器或普通 HTTP 请求不能证明 API 或 TLS 路径正常工作。对于 `6443` 路径，使用适当的 TCP/TLS 监听器或连接测试。

```bash
# 确认 VIP-A TCP 连接可达性
nc -vz <VIP-A> 6443

# 如可用，确认 Kubernetes API/TLS 状态
curl -k -i https://<VIP-A>:6443/healthz
```

对于每次测试执行，记录以下五项。

- 被测试的集群、VIP 地址、前端端口及后端角色。
- 用于确认的后端服务器主机名/IP 及监听器端口。
- 用于确认的命令及执行时间。
- VIP-A `6443` 以及 VIP-B HTTP `80` 到 `30080` 的观察结果。
- VIP-B `443` 到 `30443` 的观察到的 TLS 结果，包括错误或警告消息。

| 前端 | 后端 | 状态检查 |
|---|---|---|
| `109.156.25.43:6443` | Master 节点 | TCP `6443` |
| `109.156.25.46:80` | Router 节点 `:30080` | TCP `30080` |
| `109.156.25.46:443` | Router 节点 `:30443` | TCP `30443` |
| `109.156.25.57:6443` | Master 节点 | TCP `6443` |
| `109.156.25.60:80` | Router 节点 `:30080` | TCP `30080` |
| `109.156.25.60:443` | Router 节点 `:30443` | TCP `30443` |
| `109.156.25.72:6443` | Master 节点 | TCP `6443` |

### 0-2-1. 破坏性磁盘流程

此流程具有破坏性，需要 root 权限。删除已批准 DATA 磁盘的分区表项和文件系统签名，然后创建新的 LVM 及 XFS 结构。一次仅在一个已确认的节点上执行。命令有意使用 `/dev/sdb`。不要仅根据设备名称选择此设备，也不要在未获得针对目标的已批准变更的情况下将其替换为其他磁盘。

> [!warning] 执行破坏性命令前确认目标磁盘和维护批准
> 在确认以下所有门禁之前，不执行 `fdisk /dev/sdb`、`pvcreate` 或 `mkfs.xfs`。
> - 主机名和角色与已批准的清单一致。
> - `/dev/sdb` 是已批准的 DATA 磁盘，大小和序列号与 VM 或存储记录一致。
> - 已批准对磁盘上现有数据的处理方案。
> - 当前块设备、PV/VG/LV、挂载及 `/etc/fstab` 状态已记录在变更证据中。
> - 已批准的维护时间处于有效状态。
> 任何一项未知或不一致时，停止操作。

#### 1. 确认节点并记录当前状态

在更改磁盘之前，在目标节点上执行以下命令。将完整输出保存为变更前证据。不要只短暂检查终端，也不要假定磁盘为空。

```bash
hostnamectl --static
lsblk -o NAME,PATH,SIZE,TYPE,FSTYPE,MOUNTPOINTS,UUID,SERIAL
findmnt -rn
cat /etc/fstab
pvs
vgs
lvs -a -o lv_name,vg_name,lv_size,lv_attr,devices
```

根据记录的输出和已批准的清单，确认 `/dev/sdb` 不是 `/`、`/app`、`/var/lib/containerd`、`/var/lib/etcd` 或其他必须保留的数据的源设备或后备设备。如果文件系统已挂载、PV/VG/LV 已存在、存在文件系统签名，或者设备标识符与已批准的 DATA 磁盘不一致，则停止操作，并在继续之前调整状态。不要使用额外的 `fdisk` 删除命令或强制选项来绕过未预期的状态。

角色决定第二个 DATA 分区及其所使用逻辑卷的必需大小。此流程不更改根文件系统。

| 角色配置 | 块磁盘 | `/dev/sdb1` -> `/app` | `/dev/sdb2` -> 文件系统 | `vg00disk2` 中的逻辑卷 |
|---|---:|---:|---:|---|
| Bastion, Master, Infra, Worker | 315 GB | 50 GB | 100 GB | `containerd_lv` -> `/var/lib/containerd` |
| ETCD | 315 GB | 50 GB | 100 GB | `etcd_lv` -> `/var/lib/etcd` |
| Router | 265 GB | 50 GB | 50 GB | `containerd_lv` -> `/var/lib/containerd` |

ETCD 行是不可变条件。ETCD 节点不是使用 `/var/lib/containerd`，而是使用 `/var/lib/etcd`。[[02. K8S Cluster Nodes Pre-setting]] 中记录了目录清单中 ETCD 文件系统大小尚未解决的不一致。如果尚未确认最终批准的 ETCD 挂载设计，则在 `fdisk` 之前停止操作。不要将目录清单中的 `0 GB` 值或非 ETCD 布局作为默认值。

#### 2. 删除并重新创建 DATA 分区

在 Bastion、Master、ETCD、Infra 及 Worker 节点上使用以下 315 GB 布局。此操作创建一个 50 GB 的第一分区和一个 100 GB 的第二分区。

在 `fdisk` 提示符中一次执行一个以下输入。注释用于说明检查点，不要将其输入 `fdisk`。如果本地 `fdisk` 针对命令、分区编号或类型显示单独的提示，请分别在相应提示中输入相同的值。不要猜测其他值。

```text
# 1. 删除并重新创建分区
fdisk /dev/sdb
d 1
n
(Enter)
(Enter)
+50G
(Enter)
p    # 确认创建的分区
n
(Enter)
(Enter)
+100G
(Enter)
t 1 31
t 2 31
p    # 确认结果与批准的布局一致
w
```

仅在 Router 节点上使用相同的输入流程，但创建 50 GB 的第二分区。不要对 Router 节点应用 100 GB 的第二分区输入。

```text
# 1. Router 的分区删除及重新创建
fdisk /dev/sdb
d 1
n
(Enter)
(Enter)
+50G
(Enter)
p    # 确认创建的分区
n
(Enter)
(Enter)
+50G
(Enter)
t 1 31
t 2 31
p    # 确认结果与批准的布局一致
w
```

交互式输入的含义如下。

- `d 1` 仅删除分区 1。这并不表示已批准删除其他分区或数据。
- 每个 `(Enter)` 接受 `fdisk` 显示的默认分区编号、第一扇区或其他默认值。不要将显示的分区编号或第一扇区替换为猜测的值。
- `+50G` 和 `+100G` 请求上述定义的准确分区容量。第二个值在 Router 上为 `+50G`，在上面列出的其他所有角色配置上为 `+100G`。
- `t 1 31` 和 `t 2 31` 将两个分区设置为类型代码 `31`（已批准布局中的 `Linux LVM`）。
- `p` 输出内存中待处理的分区表。不记录变更，是必需的检查点。
- `w` 写入已检查的分区表。将其视为破坏性分区变更的提交点。
- `q` 在检查结果不正确时不写入并退出。

在任何一次 `p` 检查中，如果 `fdisk` 显示未预期的分区编号、大小、类型、磁盘标签、现有签名、已挂载或正在使用的设备，或显示已批准流程未涵盖的提示，则不要输入 `w`，而应输入 `q`，并停止操作。如果 `d 1` 报告分区 1 不存在，或存在其他现有分区，则停止操作并调整磁盘状态。不要任意创建额外的删除输入。除非特定数据丢失已获批准并属于批准范围，否则绝不要确认要求删除现有签名的提示。

`w` 返回后，等待内核重新读取分区表，并在创建 PV 之前进行验证。

```bash
udevadm settle
lsblk -o NAME,PATH,SIZE,TYPE,FSTYPE,MOUNTPOINTS
fdisk -l /dev/sdb
```

验收标准是：50 GB 且类型代码为 `31`（`Linux LVM`）的 `/dev/sdb1`；在 315 GB 配置中，100 GB 且类型代码为 `31` 的 `/dev/sdb2`；在 Router 上，50 GB 且类型代码为 `31` 的 `/dev/sdb2`。不得存在未预期的分区或挂载。由于磁盘对齐，扇区编号可能不同，但经角色批准的分区编号、容量和类型不得改变。如果结果不正确，在 `pvcreate` 之前停止操作。

#### 3. 创建并验证通用 LVM 及 XFS 结构

仅在分区批准确认通过后执行通用命令。如果 `pvcreate` 报告现有签名或正在使用的设备，`vgcreate` 报告卷组已存在，`mkfs.xfs` 报告现有签名或请求覆盖数据，或者任何命令请求未预期的确认，则停止操作。不要使用 `-f`、`-ff` 或其他设备来绕过条件。

```bash
# 2. 创建通用 LVM 结构
lsblk
pvcreate /dev/sdb1
pvcreate /dev/sdb2
vgcreate vg00disk1 /dev/sdb1
vgcreate vg00disk2 /dev/sdb2
lvcreate -n app_lv -l 100%free vg00disk1

# 3. 创建通用文件系统
mkfs.xfs /dev/vg00disk1/app_lv
```

非 ETCD 角色包括 Bastion、Master、Router、Infra 及 Worker 节点，这些角色需要创建 containerd 逻辑卷和文件系统。`100%free` 分配使用已批准的第二分区大小。315 GB 配置为 100 GB，Router 为 50 GB。

```bash
# 仅在非 ETCD 角色上执行
lvcreate -n containerd_lv -l 100%free vg00disk2
mkfs.xfs /dev/vg00disk2/containerd_lv
```

在 ETCD 节点上，改为创建 ETCD 逻辑卷和文件系统。

```bash
# 仅在 ETCD 角色上执行
lvcreate -n etcd_lv -l 100%free vg00disk2
mkfs.xfs /dev/vg00disk2/etcd_lv
```

非 ETCD 和 ETCD 分支互斥。在 ETCD 节点上完全不创建 `containerd_lv`，也不要先创建 `containerd_lv` 后再在同一卷组中创建 `etcd_lv`。在非 ETCD 节点上，不要用 `etcd_lv` 替代 `containerd_lv`。

在继续挂载或修改 `/etc/fstab` 之前，验证新创建的结构。

```bash
lsblk -f
pvs
vgs
lvs -a -o lv_name,vg_name,lv_size,lv_attr,devices
blkid /dev/vg00disk1/app_lv
```

准确执行以下角色检查中的一个。

```bash
# 仅在非 ETCD 角色上执行
blkid /dev/vg00disk2/containerd_lv
```

```bash
# 仅在 ETCD 角色上执行
blkid /dev/vg00disk2/etcd_lv
```

验证结果必须显示 `app_lv` 和所选第二个 LV 使用 XFS，并显示预期的角色特定大小及 VG/LV 名称。ETCD 节点必须显示 `etcd_lv` 且不得显示 `containerd_lv`；非 ETCD 节点必须显示 `containerd_lv` 且不得显示 `etcd_lv`。将 `blkid` 返回的实际 UUID 记录在变更证据中。不要在本指南中创建或复制 UUID。

本节在 LVM 和 XFS 验证后结束。不要在此处创建挂载点、执行 `mount` 或编辑 `/etc/fstab`。如果检查通过，则使用实际目标节点的 UUID 和符合角色的路径，继续 [[02. K8S Cluster Nodes Pre-setting]] 中的挂载点及 `/etc/fstab` 持久化流程。如果验证失败，则停止操作，不要将其交接给挂载流程。

### 0-2-2. `dspaas` wheel 组成员资格确认

在所有 Bastion 及 DKS 集群节点上执行组成员关系和 sudo 确认。使用 `id` 和 `groups` 两者确认账户。

```bash
id dspaas
groups dspaas
```

如果 `dspaas` 不是 `wheel` 的成员，则添加该组，不替换用户现有的补充组。

```bash
usermod -aG wheel dspaas
```

不要使用具有破坏性的 `usermod -G wheel dspaas` 格式。重新确认组成员关系，并从 `dspaas` 账户确认免密码 sudo。

```bash
id dspaas
groups dspaas
sudo -n true
```
