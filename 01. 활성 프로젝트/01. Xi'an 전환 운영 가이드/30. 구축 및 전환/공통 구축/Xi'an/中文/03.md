### 3-1-1. 准备 Ansible 配置文件

将 `host_key_checking` 值设置为 `False`，以禁用 strict host key check。Ansible 默认使用 host key checking。这可以防止服务器欺骗和 man-in-the-middle 攻击，但服务器重新安装后如果 `known_hosts` 中的 key 发生变化，或者未注册新主机，则需要采取措施或进行确认。要禁用此行为，请修改 `/etc/ansible/ansible.cfg` 或 `/.ansible/cfg`。

```bash
cd SCS_DKS_Kubernetes_Stack-v1.0/DKS-Kubespray-v2.19/
cat ansible.cfg | grep host_key
```

```bash
[dspaas@xadksbthm01 ~]$ cd SCS_DKS_Kubernetes_Stack-v1.0/DKS-Kubespray-v2.19/
```

参考输出：


## 3-2. Ansible Playbook 部署

使用准备好的 inventory 和配置部署 Kubespray Ansible Playbook。

### 3-2-1. Ansible Playbook 部署

使用 Ansible Playbook 部署 Kubespray。完成大约需要 20~30 分钟；如果要以 root 身份运行 Playbook，则需要 `--become` 选项。

```bash
ansible-playbook -e @inventory/dks/dks_vars.yml -i inventory/dks/hosts.yaml --become --become-user=root cluster.yml
```

```bash
[dspaas@xadksbthm01 DKS-Kubespray-v2.19]$ ansible-playbook -e @inventory/dks/dks_vars.yml -i inventory/dks/hosts.yaml --become --become-user=root cluster.yml
```
