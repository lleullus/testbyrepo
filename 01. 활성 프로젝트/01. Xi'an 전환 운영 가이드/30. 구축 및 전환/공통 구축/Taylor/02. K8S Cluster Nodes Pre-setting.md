## Index 2-1. Configure all nodes using Ansible(bastion→all nodes)

After successful completion of presettings for the Bastion Node, it is now possible to utilize Ansible from the Bastion to configure all of the Cluster Node's presetting.

(※ Just a note that the '-k' option at the end of each ansible ad-hoc command that is executed as root user will prompt the SSH password for each node's dspaas user password)

### 2-1-1. Edit the sudoers file

As the 'dspaas' user is added to the 'wheel' group, the user will be able to use the 'sudo' command without a password after the below ansible command.

```bash
ansible k8s,etcd -i inventory -m lineinfile -a 'path=/etc/sudoers regexp="^# %wheel\s+ALL=\(ALL\)\s+NOPASSWD: ALL" line="%wheel ALL=(ALL) NOPASSWD: ALL" state=present' -K -k -b
ansible k8s,etcd -i inventory -m shell -a "cat /etc/sudoers | grep %wheel" -K -k -b
ansible k8s,etcd -i inventory -m lineinfile -a 'path=/etc/sudoers regexp="^%wheel\s+ALL=\(ALL\)\s+ALL" line="#%wheel ALL=(ALL) ALL" state=present' -K -k -b
ansible k8s,etcd -i inventory -m shell -a "cat /etc/sudoers | grep %wheel" -b
```

[dspaas@xadksbthm01 ansible]# ansible k8s,etcd -i inventory -m shell -a "sed -i 's/%wheel/# %wheel/g' /etc/sudoers" -K -k -b

### 2-1-5. Disable SWAP

Kubernetes aims to densely pack instances such that they are as nearly 100% used as feasible. CPU and memory limitations ought to be pegged for every deployment. Therefore, the scheduler should never utilize swap at all if it sends a pod to a machine. Thus swap is turned off before Kubernetes installation.

```bash
ansible all -i inventory -m shell -a "swapoff -a" -b
ansible all -i inventory -m shell -a "cp /etc/fstab /etc/fstab.bak" -b
ansible all -i inventory -m lineinfile -a 'path=/etc/fstab regexp=swap state=absent' -b
```

### 2-1-7. SECDS-ROOTCA CA Cert Download

SECDS-ROOTCA CA CERT is the root certificate authority that is used to verify the authenticity of all other certificates within the cluster. It ensures that all these certificates are trusted, and that any communications happening within the cluster is secure and authenticated. Download/move the root CA Certificate to the '/etc/containerd/certs.d/' directory.

```bash
ansible all -i inventory -m file -a "path=/etc/containerd/certs.d/ state=directory owner=root group=root mode=0755" -b
ansible all -i inventory -m copy -a "src=/app/dspaas/SCS_DKS_Kubernetes_Stack-v1.0/SECDS-ROOTCA.crt dest=/etc/containerd/certs.d/ mode=0644 owner=root group=root" -b
ansible all -i inventory -m copy -a "src=/app/dspaas/SCS_DKS_Kubernetes_Stack-v1.0/SECDS-T2RootCA.crt dest=/etc/containerd/certs.d/ mode=0644 owner=root group=root" -b
ansible all -i inventory -m copy -a "src=/app/dspaas/SCS_DKS_Kubernetes_Stack-v1.0/SECDS-T2IssuingCA.crt dest=/etc/containerd/certs.d/ mode=0644 owner=root group=root" -b
ansible all -i inventory -m copy -a "src=/app/dspaas/SCS_DKS_Kubernetes_Stack-v1.0/SECDS-T2RootCA.crt dest=/etc/pki/ca-trust/source/anchors mode=0644 owner=root group=root" -b
ansible all -i inventory -m copy -a "src=/app/dspaas/SCS_DKS_Kubernetes_Stack-v1.0/SECDS-T2IssuingCA.crt dest=/etc/pki/ca-trust/source/anchors mode=0644 owner=root group=root" -b
ansible all -i inventory -m shell -a "update-ca-trust" -b
```

### 2-1-8. configure sysctl.conf

Since the kernel has already decided not to use ipv6, it annotates the ipv6-related settings in the sysctl.conf file. If that setting remains, kubespray returns an error when installing the cluster.

```bash
ansible all -i inventory -m shell -b -a "sed -i '/ipv6/s/^/#/g' /etc/sysctl.conf"
ansible all -i inventory -m shell -b -a "cat /etc/sysctl.conf"
ansible all -i inventory -m shell -b -a "sysctl -p"
```
