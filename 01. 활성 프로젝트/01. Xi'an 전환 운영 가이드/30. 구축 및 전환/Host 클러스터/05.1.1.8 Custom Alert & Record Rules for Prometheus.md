# 05.1.1.8 Custom Alert & Record Rules for Prometheus

> **실행자**: DSPAAS
>
> **원문 기준**: 기존 Host cluster 설치 절차의 `8) Custom Alert & Record Rules for Prometheus` 를 Xi'an 문서 형식으로 재구성  
> **작업 방식**: 대화형 `kubectl edit` 없이 **backup → 스크립트 변환 → apply/patch** 로 적용

DKS는 KubeSphere 기본 Prometheus alert rule을 쓰지 않는다.  
기본 **alert** 는 제거하고, 필요한 **recording rule** 은 남긴 뒤, DKS **Sensor** alert 를 넣는다.

원문은 `kubectl edit` 로 808번째 줄부터 지우라고 되어 있지만, 줄 번호는 환경마다 달라서 위험하다.  
이 문서는 **같은 결과**를 내는 재현 가능한 방식으로 다시 적는다.

> [!summary] 한 줄 요약
> `prometheus-k8s-rules` 를 백업한 뒤, alert rule만 걷어내고 recording rule은 유지한 다음 Sensor group을 붙여 `kubectl apply` 로 반영한다.

## 0. 이 단계가 하는 일

| 구분 | 처리 |
|------|------|
| 기본 `alert` rule | **삭제** (DKS 미사용) |
| `record` rule (recording) | **유지** |
| DKS `Sensor` alert | **추가** |
| 대상 CR | `prometheusrules/prometheus-k8s-rules` (`kubesphere-monitoring-system`) |

### 왜 edit 를 안 쓰나

- 파일이 매우 길고, “808번째 줄”이 환경마다 다름
- 들여쓰기 한 칸만 틀려도 rule 전체 로딩 실패 가능
- 백업·재적용·검증을 자동화하기 어려움

### 왜 patch/apply 인가

- 결과를 YAML 파일로 남길 수 있음
- 적용 전 diff 확인 가능
- 실패 시 backup 으로 즉시 롤백 가능


## 3. 적용할 Sensor rule (원문 확보분)

지금 문서에 넣는 Sensor 는 전달된 원문 기준 **2개**다.

| Alert 이름 | Grade | 의미 |
|------------|-------|------|
| `[Grade I Sensor] Pod Status Issue (Core)` | I | `kube.*` / `ingress.*` namespace Pod 가 Running/Succeeded 가 아님 (5분) |
| `[Grade C Sensor] Node Status Issue (NotReady)` | C | 노드 Ready 조건 실패 (5분) |

실제 PrometheusRule 에 들어갈 group 내용:

```yaml
- name: Sensor
  rules:
  - alert: '[Grade I Sensor] Pod Status Issue (Core)'
    annotations:
      description: 'NameSpace: {{ $labels.namespace }} , Pod: {{ $labels.pod }}. Pod status is: {{ $labels.phase }}.'
    expr: kube_pod_status_phase{phase!~"Succeeded|Running", namespace=~"kube.*|ingress.*"} != 0
    for: 5m
    labels:
      cluster: '{{ $externalLabels.cluster }}'
      grade: I
      type: Status
  - alert: '[Grade C Sensor] Node Status Issue (NotReady)'
    annotations:
      description: 'Node: {{ $labels.node }} status is NotReady.'
    expr: kube_node_status_condition{condition="Ready", status="true"} != 1
    for: 5m
    labels:
      cluster: '{{ $externalLabels.cluster }}'
```

> [!note]
> 전체 DKS Sensor 세트가 더 있으면 같은 `Sensor` group 의 `rules` 배열에 이어서 넣으면 된다.

## 4. 변환 스크립트로 새 YAML 만들기 (권장 본경로)

아래 스크립트가 하는 일:

1. 현재 `prometheus-k8s-rules` 를 읽음
2. 각 group 안에서 **`alert` rule 은 제거**, **`record` rule 만 유지**
3. 비어 버린 group 은 삭제
4. 기존 `Sensor` group 이 있으면 제거 후 새로 추가 (중복 방지)
5. apply 가능한 clean YAML 을 `prometheus-k8s-rules.dks.yaml` 로 저장

```bash
cd ~/dks-prom-rules

python3 <<'PY'
import json, subprocess, sys

ns = "kubesphere-monitoring-system"
name = "prometheus-k8s-rules"

raw = subprocess.check_output([
    "kubectl", "get", "prometheusrule", name, "-n", ns, "-o", "json"
], text=True)
obj = json.loads(raw)

# cluster-scoped noise 제거 (apply 시 충돌 방지)
md = obj.setdefault("metadata", {})
for k in ["resourceVersion", "uid", "creationTimestamp", "generation",
          "managedFields", "selfLink"]:
    md.pop(k, None)

groups = obj.get("spec", {}).get("groups") or []
kept_groups = []

for g in groups:
    gname = g.get("name")
    # 기존 Sensor 는 아래에서 재생성
    if gname == "Sensor":
        continue
    rules = g.get("rules") or []
    # alert 제거, record 유지
    # (alert+record 혼합 group 이면 record만 남김)
    rec_rules = []
    for r in rules:
        if "record" in r:
            rec_rules.append(r)
        # alert 키 있는 rule 은 버림
    if rec_rules:
        kept_groups.append({
            "name": g.get("name"),
            "interval": g.get("interval"),
            "partial_response_strategy": g.get("partial_response_strategy"),
            "rules": rec_rules,
        })
        # None 필드 제거
        kept_groups[-1] = {k: v for k, v in kept_groups[-1].items() if v is not None}

sensor_group = {
    "name": "Sensor",
    "rules": [
        {
            "alert": "[Grade I Sensor] Pod Status Issue (Core)",
            "annotations": {
                "description": "NameSpace: {{ $labels.namespace }} , Pod: {{ $labels.pod }}. Pod status is: {{ $labels.phase }}."
            },
            "expr": 'kube_pod_status_phase{phase!~"Succeeded|Running", namespace=~"kube.*|ingress.*"} != 0',
            "for": "5m",
            "labels": {
                "cluster": "{{ $externalLabels.cluster }}",
                "grade": "I",
                "type": "Status",
            },
        },
        {
            "alert": "[Grade C Sensor] Node Status Issue (NotReady)",
            "annotations": {
                "description": "Node: {{ $labels.node }} status is NotReady."
            },
            "expr": 'kube_node_status_condition{condition="Ready", status="true"} != 1',
            "for": "5m",
            "labels": {
                "cluster": "{{ $externalLabels.cluster }}",
            },
        },
    ],
}

kept_groups.append(sensor_group)
obj["spec"]["groups"] = kept_groups

# 통계
n_groups = len(kept_groups)
n_records = sum(1 for g in kept_groups for r in g["rules"] if "record" in r)
n_alerts = sum(1 for g in kept_groups for r in g["rules"] if "alert" in r)
print(f"groups={n_groups} record_rules={n_records} alert_rules={n_alerts}", file=sys.stderr)

import yaml
# PyYAML 없으면 json으로 저장 후 kubectl convert 대신 apply -f json 가능
try:
    import yaml
    with open("prometheus-k8s-rules.dks.yaml", "w", encoding="utf-8") as f:
        yaml.safe_dump(obj, f, sort_keys=False, allow_unicode=True)
    print("wrote prometheus-k8s-rules.dks.yaml")
except Exception:
    with open("prometheus-k8s-rules.dks.json", "w", encoding="utf-8") as f:
        json.dump(obj, f, ensure_ascii=False, indent=2)
    print("wrote prometheus-k8s-rules.dks.json (PyYAML 없음)")
PY
```

### 스크립트 결과 확인

```bash
# 파일 존재
ls -l prometheus-k8s-rules.dks.*

# Sensor / Grade 문구 있는지
grep -n "Sensor\|Grade I Sensor\|Grade C Sensor\|record:" prometheus-k8s-rules.dks.yaml | head -40

# group 이름 목록
python3 - <<'PY'
import sys
try:
    import yaml
    obj=yaml.safe_load(open("prometheus-k8s-rules.dks.yaml"))
except Exception:
    import json
    obj=json.load(open("prometheus-k8s-rules.dks.json"))
for g in obj["spec"]["groups"]:
    n_a=sum(1 for r in g["rules"] if "alert" in r)
    n_r=sum(1 for r in g["rules"] if "record" in r)
    print(f"{g['name']}: alert={n_a} record={n_r}")
PY
```

기대:

- 마지막 group 이름 `Sensor`
- `Sensor` 에 alert 2개
- 다른 group 은 `record` 만 (alert=0)
- 원문이 남기라고 한 recording 예시도 유지되는지 확인:

```bash
grep -n 'prometheus:prometheus_tsdb_head_samples_appended:sum_rate' prometheus-k8s-rules.dks.*
```

> [!warning] 원문 “808줄 삭제”와의 관계
> 원문은 긴 파일 끝부분을 수동 삭제한 것이다.  
> 이 스크립트는 **줄 번호 대신 “alert 제거 / record 유지”** 로 같은 의도를 구현한다.  
> 특정 recording rule 이름까지 강제로 맞출 필요는 없고, **alert 가 기본 rule 에서 빠졌는지** 가 핵심이다.

## 5. apply 로 반영 (본적용)

```bash
cd ~/dks-prom-rules
```

```text
prometheusrule.monitoring.coreos.com/prometheus-k8s-rules configured
```

### apply 가 부담되면: 전체 groups 를 merge patch

`spec.groups` 전체를 통째로 바꾸는 merge patch 도 가능하다.  
(내용이 길어서 파일 기반이 더 안전하다.)

```bash
# dks yaml/json 에서 groups 만 추출해 patch
python3 <<'PY'
import json, subprocess
try:
    import yaml
    obj=yaml.safe_load(open("prometheus-k8s-rules.dks.yaml"))
except Exception:
    obj=json.load(open("prometheus-k8s-rules.dks.json"))
patch={"spec":{"groups":obj["spec"]["groups"]}}
open("groups-patch.json","w").write(json.dumps(patch))
print("wrote groups-patch.json")
PY

kubectl patch prometheusrule prometheus-k8s-rules \
  -n kubesphere-monitoring-system \
  --type merge \
  --patch-file groups-patch.json
```

성공 예:

```text
prometheusrule.monitoring.coreos.com/prometheus-k8s-rules patched
```

> [!tip] Sensor 만 추가하고 기본 alert 삭제는 나중에?
> 기본 alert 를 당장 못 지우는 임시 상황이면, **추가만** JSON patch 로 할 수 있다.  
> 다만 DKS 원칙은 기본 alert 미사용이므로, 정상 절차는 **4→5절(제거+추가)** 이다.

```bash
# (임시) Sensor group 만 끝에 추가 — 기본 alert 는 그대로 남음
kubectl patch prometheusrule prometheus-k8s-rules \
  -n kubesphere-monitoring-system \
  --type json \
  -p='[
  {"op":"add","path":"/spec/groups/-","value":{
    "name":"Sensor",
    "rules":[
      {
        "alert":"[Grade I Sensor] Pod Status Issue (Core)",
        "annotations":{"description":"NameSpace: {{ $labels.namespace }} , Pod: {{ $labels.pod }}. Pod status is: {{ $labels.phase }}."},
        "expr":"kube_pod_status_phase{phase!~\"Succeeded|Running\", namespace=~\"kube.*|ingress.*\"} != 0",
        "for":"5m",
        "labels":{"cluster":"{{ $externalLabels.cluster }}","grade":"I","type":"Status"}
      },
      {
        "alert":"[Grade C Sensor] Node Status Issue (NotReady)",
        "annotations":{"description":"Node: {{ $labels.node }} status is NotReady."},
        "expr":"kube_node_status_condition{condition=\"Ready\", status=\"true\"} != 1",
        "for":"5m",
        "labels":{"cluster":"{{ $externalLabels.cluster }}"}
      }
    ]
  }}
]'
```

이미 `Sensor` 가 있으면 이 add 는 중복 group 을 만든다. 그때는 본경로(4→5)로 재생성한다.

## 6. 검증 (반드시)

### 6-1. group / alert 존재

```bash
echo "=== groups ==="
kubectl get prometheusrule prometheus-k8s-rules -n kubesphere-monitoring-system \
  -o jsonpath='{range .spec.groups[*]}{.name}{"\n"}{end}'

echo "=== Sensor alerts ==="
kubectl get prometheusrule prometheus-k8s-rules -n kubesphere-monitoring-system -o yaml \
  | grep -E 'name: Sensor|Grade I Sensor|Grade C Sensor'
```

기대:

- group 목록 끝에 `Sensor`
- Grade I / Grade C 문자열 존재

### 6-2. 기본 alert 가 줄었는지

```bash
python3 <<'PY'
import json, subprocess
raw=subprocess.check_output([
  "kubectl","get","prometheusrule","prometheus-k8s-rules",
  "-n","kubesphere-monitoring-system","-o","json"
], text=True)
obj=json.loads(raw)
alerts=[]; records=[]
for g in obj["spec"]["groups"]:
  for r in g.get("rules",[]):
    if "alert" in r: alerts.append((g["name"], r["alert"]))
    if "record" in r: records.append((g["name"], r["record"]))
print(f"alert_count={len(alerts)} record_count={len(records)}")
print("--- alerts ---")
for g,a in alerts:
  print(f"{g}: {a}")
PY
```

기대:

- alert 는 Sensor 2개 (또는 추후 보강한 Sensor 목록) 위주
- KubeSphere 기본 대량 alert 이름들이 사라져 있음
- record_count 는 0 이 아님

### 6-3. Prometheus 가 rule 을 먹었는지

```bash
kubectl get pod -n kubesphere-monitoring-system -l app.kubernetes.io/name=prometheus
kubectl logs -n kubesphere-monitoring-system -l app.kubernetes.io/name=prometheus --tail=50 \
  | grep -iE 'error|rule|failed' || true
```

rule YAML 이 깨지면 Prometheus log 에 rule 로드 실패가 난다.
