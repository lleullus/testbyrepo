# 05.1.1 Apply the `kubesphere-installer.yaml` file

> **실행자**: DSPAAS
>
> **원문 기준**: 사용자가 전달한 기존 `5-1-1` 문서의 `1) Apply the kubesphere-installer.yaml file` 절차를 Xi'an 문서 형식으로 재구성

Xi'an 환경에서는 DKS 설치 bundle 내부의 Host cluster용 manifest를 사용합니다. 이 단계의 목적은 KubeSphere installer를 위한 CRD, namespace, service account, RBAC, deployment를 먼저 배포하는 것입니다.

## 1-1. 설치 디렉토리 이동 및 파일 확인

```bash

```

## 1-2. Installer manifest 핵심 확인

적용 전 `kubesphere-installer.yaml` 의 주요 설정을 확인합니다. 원본 YAML 전체를 문서에 장문으로 복사하기보다, 운영 시 실제로 확인해야 하는 항목 위주로 정리합니다.

```bash
cat kubesphere-installer.yaml
```

### 주요 확인 포인트

| 항목 | 확인 내용 |
|------|-----------|
| CRD | `clusterconfigurations.installer.kubesphere.io` 생성 |
| Namespace | `kubesphere-system` 생성 |
| ServiceAccount | `ks-installer` 생성 |
| RBAC | `ks-installer`용 `ClusterRole`, `ClusterRoleBinding` 생성 |
| Deployment | `kubesphere-system/ks-installer` 배포 |
| Node 배치 | `nodeSelector: node-type: infra` |
| Toleration | `node-role.kubernetes.io/infra:NoSchedule` |
| Image | `xa.dcr.dks.samsungds.net/dspaas-cloud/kubesphere/ks-installer:v3.2.1` |

Xi'an 표준에서 특히 확인할 부분은 아래와 같습니다.

```yaml
spec:
  serviceAccountName: ks-installer
  nodeSelector:
    kubernetes.io/os: linux
    node-type: infra
  tolerations:
    - effect: NoSchedule
      key: node-role.kubernetes.io/infra
  containers:
    - name: installer
      image: xa.dcr.dks.samsungds.net/dspaas-cloud/kubesphere/ks-installer:v3.2.1
      imagePullPolicy: Always
```

> [!note]
> Xi'an 환경에서는 KubeSphere installer를 `infra` node에 배치하고, 이미지 소스는 `xa.dcr.dks.samsungds.net/dspaas-cloud` registry를 사용합니다. 따라서 node label/toleration과 private registry 경로가 현장 표준과 일치하는지 먼저 확인해야 합니다.

## 1-3. Installer manifest 적용

```bash
kubectl apply -f kubesphere-installer.yaml
```

적용 예시:

```text
customresourcedefinition.apiextensions.k8s.io/clusterconfigurations.installer.kubesphere.io created
namespace/kubesphere-system created
serviceaccount/ks-installer created
clusterrole.rbac.authorization.k8s.io/ks-installer created
clusterrolebinding.rbac.authorization.k8s.io/ks-installer created
deployment.apps/ks-installer created
```

## 1-4. 설치 리소스 검증

k get clusterrole | grep installer
k get clusterrolebinding | grep installer

## 1-5. 완료 기준

- `clusterconfigurations.installer.kubesphere.io` CRD 생성 완료
- `kubesphere-system` namespace 생성 완료
- `ks-installer` Deployment/Pod가 `Running` 상태
- installer pod가 의도한 `infra` node 계열에 배치됨
- private registry 이미지 pull 오류 없음

> [!note]
> `ks-installer` Deployment 자체는 `infra` node 에 배치되더라도, 설치 후 생성되는 KubeSphere workload 전체에 같은 스케줄링 정책이 자동 전파되지 않을 수 있습니다. DKS 표준의 후속 재배치 절차는 [[05.1.1.4 Re-deployment of Pods according to the DKS Standard|05.1.1.4 Re-deployment of Pods according to the DKS Standard]] 를 참고합니다.
