# 05.1.2 Apply the cluster configuration file

> **실행자**: DSPAAS
>
> **원문 기준**: 사용자가 전달한 `cluster-configure.yaml` 기존 원문과 Xi'an 실제 `Kubesphere-v3.2.1/host/cluster-configure.yaml` 파일을 대조해 재구성

설치용 설정 파일을 적용합니다. Host cluster로 사용해야 하므로 `cluster-configure.yaml` 에서 `clusterRole` 값이 `host` 로 설정되어 있어야 합니다.

> [!info] 원본과 Xi'an 커스텀 구분
> 사용자가 전달한 기존 원문에는 HQ/타 환경 기준 값이 포함되어 있었고, 현재 문서 본문은 이를 Xi'an 실제 소스 기준으로 치환한 상태입니다. 특히 `storageClass`, `local_registry`, `etcd.endpointIps`, `cloudCore/edgeWatcher nodeSelector` 는 환경별로 달라집니다.

## 2-1. 설정 파일 확인

```bash
cat cluster-configure.yaml
```

Xi'an Host cluster 기준 핵심 설정은 아래와 같습니다.

| 항목 | Xi'an 설정값 | 비고 |
|------|-------------|------|
| `metadata.labels.version` | `v3.2.1` | DKS 기본 버전 |
| `persistence.storageClass` | `scs-netapp-qtree-nfs-sc-delete` | Cluster별 SC 상이, 적용 전 확인 |
| `authentication.jwtSecret` | `""` | Host cluster는 join 대상이 아니므로 공란 |
| `local_registry` | `xa.dcr.dks.samsungds.net/dspaas-cloud` | Private image registry |
| `etcd.monitoring` | `false` | ETCD는 수동으로 ServiceMonitor 구성 |
| `etcd.endpointIps` | `109.156.22.41,109.156.22.42,109.156.22.43` | External ETCD IP |
| `etcd.port` | `2379` | ETCD port |
| `etcd.tlsEnable` | `true` | External ETCD TLS 사용 |
| `common.core.console.port` | `30880` | Console NodePort |
| `common.core.console.type` | `NodePort` | Console 노출 방식 |
| `common.redis.enabled` | `false` | Embedded Redis 미사용 |
| `common.openldap.enabled` | `false` | Embedded OpenLDAP 미사용 |
| `common.monitoring.endpoint` | `http://prometheus-operated.kubesphere-monitoring-system.svc:9090` | KubeSphere monitoring endpoint |
| `devops.enabled` | `true` | DevOps module 설치 |
| `logging.enabled` | `false` | Logging 미설치 |
| `metrics_server.enabled` | `false` | Metrics Server 미설치 |
| `monitoring.storageClass` | `scs-netapp-qtree-nfs-sc-delete` | Prometheus 저장소 SC |
| `multicluster.clusterRole` | `host` | Host cluster 지정 |
| `openpitrix.store.enabled` | `true` | App Store 설치 |

### 2-1-a. 원본 대비 Xi'an 커스텀 포인트

| 항목 | 기존 원문 값 | Xi'an 반영 값 |
|------|--------------|---------------|
| `persistence.storageClass` | `powerflexos-xfs-sc-300t-sp04` | `scs-netapp-qtree-nfs-sc-delete` |
| `monitoring.storageClass` | `powerflexos-xfs-sc-300t-sp04` | `scs-netapp-qtree-nfs-sc-delete` |
| `local_registry` | `dcr.cloud.samsungds.net/dspaas-cloud` | `xa.dcr.dks.samsungds.net/dspaas-cloud` |
| `etcd.endpointIps` | `10.166.202.74,10.166.202.75,10.166.202.76` | `109.156.22.41,109.156.22.42,109.156.22.43` |
| `cloudCore.nodeSelector` | `node-role.kubernetes.io/worker` | `node-role.kubernetes.io/infra` |
| `edgeWatcher.nodeSelector` | `node-role.kubernetes.io/worker` | `node-role.kubernetes.io/infra` |
| `edgeWatcherAgent.nodeSelector` | `node-role.kubernetes.io/worker` | `node-role.kubernetes.io/infra` |

> [!warning] 적용 전 치환 필수 항목
> `cluster-configure.yaml` 는 다른 지역/클러스터 원본을 그대로 쓰면 안 됩니다. 특히 StorageClass, Registry, External ETCD IP, nodeSelector는 대상 cluster 기준 값으로 치환 후 적용해야 합니다.

## 2-2. 주요 설정 발췌

```yaml
persistence:
  storageClass: "scs-netapp-qtree-nfs-sc-delete"

authentication:
  jwtSecret: ""

local_registry: "xa.dcr.dks.samsungds.net/dspaas-cloud"

etcd:
  monitoring: false
  endpointIps: 109.156.22.41,109.156.22.42,109.156.22.43
  port: 2379
  tlsEnable: true

common:
  core:
    console:
      enableMultiLogin: true
      port: 30880
      type: NodePort
  redis:
    enabled: false
  openldap:
    enabled: false
  monitoring:
    endpoint: http://prometheus-operated.kubesphere-monitoring-system.svc:9090

devops:
  enabled: true

logging:
  enabled: false
  containerruntime: docker
  logsidecar:
    enabled: true
    replicas: 2

metrics_server:
  enabled: false

monitoring:
  storageClass: "scs-netapp-qtree-nfs-sc-delete"

multicluster:
  clusterRole: host

openpitrix:
  store:
    enabled: true
```

## 2-3. 설정 파일 적용

```bash
kubectl apply -f cluster-configure.yaml
```

적용 예시:

```text
clusterconfiguration.installer.kubesphere.io/ks-installer created
```

## 2-4. 설치 상태 점검

```bash
kubectl get cc -n kubesphere-system
kubectl describe cc ks-installer -n kubesphere-system
kubectl get pods -A | grep -E 'ks-|prometheus|alertmanager|grafana'
kubectl logs -n kubesphere-system deploy/ks-apiserver
```

> [!warning] Known issue
> 일부 환경에서는 `ks-apiserver` pod 로그에 monitoring 설치 작업이 `failed` 로 표시될 수 있습니다. `ServiceMonitor` CRD 준비 타이밍 이슈로 1차 시도가 실패하고 `ks-installer` pod 재기동 후 정상화되는 사례가 있으며, 절차는 [[05.1.1.3 Watch logs for the kubesphere installer|05.1.1.3 Watch logs for the kubesphere installer]] 를 참고합니다.

## 2-5. 완료 기준

- `cluster-configure.yaml` 적용 완료
- `multicluster.clusterRole: host` 반영 완료
- Xi'an 대상 값으로 StorageClass / Registry / ETCD IP 치환 완료
- `ClusterConfiguration/ks-installer` 리소스 생성 완료
- `ks-apiserver` 및 monitoring 관련 리소스 상태 점검 완료
