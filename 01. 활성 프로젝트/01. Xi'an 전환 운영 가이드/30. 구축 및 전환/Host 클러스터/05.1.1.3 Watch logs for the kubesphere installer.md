# 05.1.1.3 Watch logs for the `kubesphere` installer

> **실행자**: DSPAAS
>
> **원문 기준**: Host cluster 설치 로그 중 `3) Watch logs for the kubesphere installer` 절차와 monitoring 재시도 사례를 Xi'an 문서 형식으로 재구성

`cluster-configure.yaml` 적용 후에는 `ks-installer` pod 로그를 지속적으로 확인해 설치 task 상태를 점검합니다. KubeSphere `v3.2.1` 에서는 monitoring 단계에서 `ServiceMonitor` CRD 준비 타이밍 때문에 1차 시도가 실패하고, `ks-installer` pod 재기동 후 2차 시도에서 정상 완료되는 사례가 확인되었습니다.

## 1. 설치 로그 확인

```bash
kubectl logs -n kubesphere-system $(kubectl get pod -n kubesphere-system -l app=ks-install -o jsonpath='{.items[0].metadata.name}') -f
```

정상 진행 시 예시:

```text
Start installing monitoring
Start installing multicluster
Start installing openpitrix
Start installing network
Start installing devops
**************************************************
Waiting for all tasks to be completed ...
```

## 2. Known issue: monitoring task failed

다음 오류는 `ServiceMonitor` CRD 가 아직 API server 에 등록되기 전에 node-exporter용 `ServiceMonitor` manifest 가 먼저 적용되면서 발생하는 known issue 입니다.

```text
task monitoring status is failed
error: unable to recognize "/kubesphere/kubesphere/prometheus/node-exporter/node-exporter-serviceMonitor.yaml": no matches for kind "ServiceMonitor" in version "monitoring.coreos.com/v1"
```

운영 해석:

- 설정값 자체가 잘못된 경우라기보다 monitoring CRD 등록 타이밍 이슈로 봄
- 동일 설치를 새로 시작하면 이미 CRD 가 등록된 상태라 2차 시도에서 통과할 수 있음

## 3. 조치 절차

### 3-1. 현재 `ks-installer` pod 확인

```bash
kubectl get pods -n kubesphere-system | grep ks-installer
```

### 3-2. `ks-installer` pod 삭제로 재시도 트리거

```bash
kubectl delete pod -n kubesphere-system <ks-installer-pod-name>
```

예시:

```bash
kubectl delete pod -n kubesphere-system ks-installer-5fbbdb79f4-2bpqc
```

### 3-3. 새 pod 기동 확인

```bash
kubectl get pods -n kubesphere-system | grep ks-installer
```

### 3-4. 새 pod 로그 재확인

```bash
kubectl logs -n kubesphere-system $(kubectl get pod -n kubesphere-system -l app=ks-install -o jsonpath='{.items[0].metadata.name}') -f
```

성공 예시:

```text
task network status is successful (1/5)
task devops status is successful (2/5)
task openpitrix status is successful (3/5)
task multicluster status is successful (4/5)
task monitoring status is successful (5/5)

#####################################################
### Welcome to KubeSphere! ###
#####################################################
```

## 4. 완료 기준

- `ks-installer` 로그에서 `monitoring status is successful` 확인
- 최종적으로 `Welcome to KubeSphere!` 배너 출력 확인
- `multicluster` 와 `monitoring` task 가 모두 `successful` 상태 확인

## 5. 운영 메모

- 이 이슈는 monitoring 설정 전체를 수동 재구성해야 하는 상황으로 보지 않고, installer 재시도로 회복 가능한 일시적 순서 문제로 취급합니다.
- `ks-installer` pod 삭제는 설치 상태를 처음부터 다시 진행시키는 안전한 재시도 방식으로 기록합니다.
- 재시도 후에도 동일 오류가 반복되면 `monitoring.coreos.com` CRD 생성 여부와 Prometheus operator 관련 리소스 상태를 추가 확인합니다.
