# 05.1.1.7 Edit Prometheus Retention & External Labels

> **실행자**: DSPAAS
>
> **원문 기준**: 기존 Host cluster 설치 절차의 `7) Edit Prometheus Retention & External Labels` 를 Xi'an 문서 형식으로 재구성

이 단계는 “YAML 아무 데나 붙이기”가 아니다.  
**편집할 객체 → 현재 값 확인 → `spec` 안 정확한 위치 → 저장 → 검증** 순서로 한다.

> [!summary] 한 줄 요약
> `kubesphere-monitoring-system` namespace의 Prometheus CR `k8s` 에서  
> `spec.retention = 30d`  
> `spec.externalLabels.cluster / stage = 해당 클러스터 값`  
> 으로 맞춘다.

## 0. 왜 하는가 (먼저 이해)

| 항목 | 의미 | DKS 기준 |
|------|------|----------|
| `retention` | Prometheus가 메트릭을 얼마나 오래 보관할지 | **30일** (`30d`) |
| `externalLabels.cluster` | 이 Prometheus가 어느 클러스터인지 표시 | **클러스터 이름** |
| `externalLabels.stage` | 운영/개발 구분 | **Prd** 또는 **Dev** |

- retention을 안 바꾸면 기본값이 짧아 장애 분석에 부족할 수 있다.
- externalLabels를 안 넣으면 이후 Sensor alert에 클러스터명이 안 붙는다. ([[05.1.1.8 Custom Alert & Record Rules for Prometheus|5.1.1.8]] 에서 `{{ $externalLabels.cluster }}` 사용)

## 1. 작업 전에 넣을 값을 종이에 적기

**지금 작업 중인 클러스터 이름**을 먼저 확정한다. Host 문서 기준 예시는 아래.

| 지금 작업 클러스터 | 넣을 `cluster` 값 | 넣을 `stage` 값 |
|--------------------|-------------------|-----------------|
| Xi'an Host `prd-host-pa01-xas` | `prd-host-pa01-xas` | `Prd` |
| Xi'an Apps 운영 `prd-apps-pa01-xas` | `prd-apps-pa01-xas` | `Prd` |
| Xi'an Apps 개발 `dev-apps-pa01-xas` | `dev-apps-pa01-xas` | `Dev` |

> [!danger] 절대 그대로 복사 금지
> 원본 운영 로그 예시 `cluster: dev-ds-kstest` / `stage: Dev` 는 **다른 사이트 값**이다.  
> Xi'an Host 작업 중이면 반드시 `prd-host-pa01-xas` / `Prd` 를 쓴다.

아래부터는 **Host 클러스터** 기준으로 설명한다.  
Apps면 표의 값만 바꿔 같은 순서로 하면 된다.

## 2. context / 대상 객체 확인

```bash
# 지금 어느 클러스터를 보고 있는지
kubectl config current-context

# Prometheus CR이 있는지
kubectl get prometheus -n kubesphere-monitoring-system
```

기대 출력 예:

```text
NAME   VERSION   REPLICAS   AGE
k8s    v2.xx.x   1          xxd
```

- **이름**: `k8s`
- **네임스페이스**: `kubesphere-monitoring-system`
- 이 두 값이 맞아야 다음 명령을 그대로 쓸 수 있다.

없으면 KubeSphere monitoring 설치가 안 끝난 것이다. 이 단계를 진행하지 않는다.

## 3. 현재 값부터 보기 (편집 전 필수)

편집기를 열기 전에 **지금 뭐가 들어 있는지** 본다.

```bash
kubectl get prometheus -n kubesphere-monitoring-system k8s -o yaml | grep -nE '^\s*(retention|externalLabels|cluster|stage):' -A2
```

또는 더 직관적으로:

```bash
echo "=== retention ==="
kubectl get prometheus -n kubesphere-monitoring-system k8s -o jsonpath='{.spec.retention}{"\n"}'

echo "=== externalLabels ==="
kubectl get prometheus -n kubesphere-monitoring-system k8s -o jsonpath='{.spec.externalLabels}{"\n"}'
```

### 해석

| 결과 | 의미 | 다음에 할 일 |
|------|------|--------------|
| `retention` 이 비어 있거나 `15d` 등 | 아직 30일 아님 | `30d` 로 변경 |
| `externalLabels` 가 비어 있음 (`{}` 또는 출력 없음) | 라벨 미설정 | `cluster`/`stage` **새로 추가** |
| `externalLabels` 에 다른 값이 있음 | 잘못된 클러스터명일 수 있음 | Host 값으로 **교체** |
| 이미 `30d` + 올바른 cluster/stage | 작업 완료 상태 | 편집 불필요, 검증만 |

## 4. 어디에 넣는지 — YAML 위치 지도

`kubectl edit` 로 열면 문서가 길다. **맨 위 `metadata` 가 아니라 `spec:` 블록 안**에 넣는다.

구조만 보면 대략 이렇다:

```yaml
apiVersion: monitoring.coreos.com/v1
kind: Prometheus
metadata:
  name: k8s
  namespace: kubesphere-monitoring-system
  # ... 라벨, annotation 많음 — 여기 건드리지 말 것
spec:                          # <<<< 여기부터가 작업 영역
  replicas: 1
  retention: 30d               # <<<< ① 이 줄
  externalLabels:              # <<<< ② 이 블록
    cluster: prd-host-pa01-xas
    stage: Prd
  serviceAccountName: prometheus-k8s
  # ... 아래 scrapeConfig, resources 등은 건드리지 말 것
```

### 넣는 규칙 (중요)

1. **들여쓰기**
   - `retention` 은 `spec:` 보다 **스페이스 2칸** 안쪽
   - `externalLabels:` 도 `spec:` 보다 **스페이스 2칸** 안쪽
   - `cluster` / `stage` 는 `externalLabels:` 보다 **스페이스 2칸 더** (총 4칸)
2. **콜론 뒤 공백 1칸**
   - `retention: 30d` (O)
   - `retention:30d` (X)
3. **따옴표 불필요** (값에 특수문자 없으면)
   - `cluster: prd-host-pa01-xas` (O)
4. **`metadata` / `status` 블록에는 넣지 않는다**
5. **이미 같은 키가 있으면 추가하지 말고 값만 고친다** (키 중복 금지)

### 잘못된 예

```yaml
# ❌ metadata 아래 — 안 됨
metadata:
  retention: 30d

# ❌ spec과 같은 깊이 — 안 됨
spec:
  replicas: 1
retention: 30d

# ❌ externalLabels 들여쓰기 깨짐 — 안 됨
spec:
  externalLabels:
  cluster: prd-host-pa01-xas
```

## 5. 방법 A — `kubectl edit` (원문 방식, 권장 숙지)

### 5-1. 편집기 열기

```bash
kubectl edit prometheus -n kubesphere-monitoring-system k8s
```

기본 편집기는 보통 `vi` / `vim` 이다.  
nano 를 쓰고 싶으면:

```bash
EDITOR=nano kubectl edit prometheus -n kubesphere-monitoring-system k8s
```

### 5-2. vi 기준 찾는 법

1. 열리면 파일이 길다. 당황하지 말고 **검색**한다.
2. `spec:` 찾기: `/^spec:` 입력 후 Enter
3. retention 찾기: `/retention` 입력 후 Enter
4. externalLabels 찾기: `/externalLabels` 입력 후 Enter

### 5-3. 케이스별 수정

#### 케이스 1) `retention` 줄이 이미 있다

예:

```yaml
  retention: 15d
```

- `i` 키로 입력 모드
- `15d` 를 `30d` 로 고침
- Esc

#### 케이스 2) `retention` 줄이 없다

- `spec:` 바로 아래 아무 안전한 위치(예: `replicas:` 근처)에 커서를 둔다
- `o` 로 아래 줄 추가 후 입력:

```yaml
  retention: 30d
```

- Esc

#### 케이스 3) `externalLabels` 가 없다

`spec:` 안, `retention` 근처가 읽기 좋다. 예:

```yaml
  retention: 30d
  externalLabels:
    cluster: prd-host-pa01-xas
    stage: Prd
```

#### 케이스 4) `externalLabels` 는 있는데 값이 틀리다

```yaml
  externalLabels:
    cluster: dev-ds-kstest   # ← 이걸
    stage: Dev               # ← 이것도
```

Host라면:

```yaml
  externalLabels:
    cluster: prd-host-pa01-xas
    stage: Prd
```

### 5-4. 저장하고 나가기 (vi)

| 동작 | 키 |
|------|----|
| 입력 모드 종료 | `Esc` |
| 저장 후 종료 | `:wq` 후 Enter |
| 저장 안 하고 취소 | `:q!` 후 Enter |

### 5-5. 성공 / 실패 메시지

**성공:**

```text
prometheus.monitoring.coreos.com/k8s edited
```

**실패 예:**

```text
error: ... was not valid ...
```

- YAML 들여쓰기 오류, 키 중복, 탭 문자 등이 원인이다.
- 다시 `kubectl edit` 로 열어 수정한다.
- 임시 파일이 남으면 메시지에 경로가 나온다. 당황하지 말고 다시 편집하면 된다.

## 6. 방법 B — `kubectl patch` (edit 가 부담될 때)

한 번에 값을 밀어 넣고 싶으면 patch 를 쓴다.  
Host 예시:

```bash
kubectl patch prometheus k8s -n kubesphere-monitoring-system --type merge -p '{
  "spec": {
    "retention": "30d",
    "externalLabels": {
      "cluster": "prd-host-pa01-xas",
      "stage": "Prd"
    }
  }
}'
```

Apps 개발이면:

```bash
kubectl patch prometheus k8s -n kubesphere-monitoring-system --type merge -p '{
  "spec": {
    "retention": "30d",
    "externalLabels": {
      "cluster": "dev-apps-pa01-xas",
      "stage": "Dev"
    }
  }
}'
```

성공 시:

```text
prometheus.monitoring.coreos.com/k8s patched
```

> [!tip]
> 원문 운영은 `kubectl edit` 다. 현장 숙련/재현을 위해 edit 를 우선 익히고, 실수 위험이 클 때만 patch 를 쓴다.

## 7. 저장 후 반드시 검증

### 7-1. CR 값 확인

```bash
kubectl get prometheus -n kubesphere-monitoring-system k8s -o yaml \
  | grep -Eie 'retention:|^\s+cluster:|^\s+stage:'
```

Host 기대:

```text
  retention: 30d
    cluster: prd-host-pa01-xas
    stage: Prd
```

한 줄로:

```bash
kubectl get prometheus -n kubesphere-monitoring-system k8s \
  -o jsonpath='retention={.spec.retention}{"\n"}cluster={.spec.externalLabels.cluster}{"\n"}stage={.spec.externalLabels.stage}{"\n"}'
```

기대:

```text
retention=30d
cluster=prd-host-pa01-xas
stage=Prd
```

### 7-2. Prometheus Pod 상태

값이 바뀌면 operator 가 Prometheus 를 재구성할 수 있다. Ready 인지 본다.

```bash
kubectl get pod -n kubesphere-monitoring-system -l app.kubernetes.io/name=prometheus -o wide
kubectl get prometheus -n kubesphere-monitoring-system k8s
```

- pod 가 `Running` / Ready
- CR 에 에러 메시지가 반복되지 않음

### 7-3. (선택) 실제 Prometheus 설정 반영 확인

Prometheus UI 또는 API 로 external label 이 보이는지 확인한다.

```bash
# port-forward 예시
kubectl -n kubesphere-monitoring-system port-forward svc/prometheus-k8s 9090:9090
```

브라우저에서 `http://127.0.0.1:9090/config` 또는 Status → Configuration 에서  
`global.external_labels` 에 `cluster`, `stage` 가 있는지 본다.

## 8. 자주 하는 실수

| 실수 | 결과 | 방지 |
|------|------|------|
| 원본 예시 `dev-ds-kstest` 그대로 입력 | 알림에 잘못된 클러스터명 | Xi'an 표 값 사용 |
| `metadata` 에 넣음 | 무시되거나 검증 실패 | 반드시 `spec` 안 |
| 들여쓰기 깨짐 | edit 저장 실패 | 스페이스 2칸 단위 |
| `retention: 30` (단위 없음) | 의도치 않은 값 | 반드시 `30d` |
| `stage: prd` / `PRD` 혼용 | 환경 표기 불일치 | 문서 기준 `Prd` / `Dev` |
| 확인 없이 다음 단계 진행 | 5.1.1.8 alert cluster 비정상 | jsonpath 로 3값 확인 |

## 9. 완료 체크리스트

- [ ] 작업 대상 context 가 맞는 클러스터
- [ ] `prometheus/k8s` 존재 (`kubesphere-monitoring-system`)
- [ ] 편집 전 현재 값 확인함
- [ ] `spec.retention` = `30d`
- [ ] `spec.externalLabels.cluster` = 해당 클러스터명 (Host면 `prd-host-pa01-xas`)
- [ ] `spec.externalLabels.stage` = `Prd` 또는 `Dev`
- [ ] 저장 메시지 `edited` 또는 `patched`
- [ ] jsonpath 로 3값 재확인
- [ ] Prometheus pod Ready
