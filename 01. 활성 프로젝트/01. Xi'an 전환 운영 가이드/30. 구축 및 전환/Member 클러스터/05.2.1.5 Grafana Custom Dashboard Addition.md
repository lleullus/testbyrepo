# 05.2.1.5 Grafana Custom Dashboard Addition

> **실행자**: DSPAAS
>
> **대상 클러스터**: `dev-apps-pa01-xas`
>
> **선행 단계**: [[05.2.1.4 Deploy Ingresses and External ETCD Monitoring|05.2.1.4 Deploy Ingresses and External ETCD Monitoring]]

DKS bundle에 포함된 Dashboard JSON을 Grafana에 import합니다. Dashboard를 import하기 전에 Prometheus datasource 이름과 URL이 custom stack 기준으로 맞는지 확인합니다.

## 1. Dashboard 파일 확인

```bash
cd ~/SCS_DKS_Kubernetes_Stack-v1.0/dks-prometheus-stack_v2.0/2.kube-prometheus-0.11.0/grafana-custom-dashboards
ls -al
```

대상 파일:

| 파일 | 용도 |
|---|---|
| `cluster-status-check-test.json` | Cluster Status Check |
| `DKS-Performance-Report-User.json` | Namespace/Service 사용자 성능 보고서 |
| `DKS-Performance-Report-Admin.json` | Admin 성능 보고서 |
| `DKS-Policy-Dashboard.json` | DKS Underutilized Namespace Collect Policy |

JSON 파일을 임의로 수정하지 않고, import 후 datasource와 panel query 오류를 확인합니다.

## 2. Grafana 접속 정보 확인

```bash
kubectl get pod -n monitoring | grep grafana
kubectl get svc -n monitoring grafana
kubectl get ingress -n monitoring grafana-ingress -o wide
```

dev Grafana Host:

```text
grafana.xadevpa01.apps.dks.samsungds.net
```

Ingress에 TLS와 HTTPS 전달이 확정되지 않은 경우에는 manifest와 LB 정책에 맞는 scheme으로 접속합니다. 브라우저에서 인증서 경고가 발생하면 임의로 TLS Secret을 만들지 말고 현장 인증서 정책을 확인합니다.

## 3. Datasource 확인

Grafana Web UI에서 **Connections/Data sources**로 이동해 datasource를 확인합니다.

| 항목 | 값 |
|---|---|
| Name | `prometheus` |
| Type | `Prometheus` |
| URL | `http://prometheus-k8s.monitoring.svc:9090` |
| Access | `Server`/`proxy` |

`kubesphere-monitoring-system` 또는 다른 클러스터 URL이 들어 있으면 Dashboard import 전에 수정합니다. **Save & test**가 성공해야 합니다.

## 4. Dashboard import

Grafana Web UI에서 다음 순서로 각 JSON을 import합니다.

1. `Dashboards` 이동
2. `New` 또는 `Import` 선택
3. `Upload dashboard JSON file` 선택
4. Dashboard JSON 파일 선택
5. Datasource 선택 화면에서 `prometheus` 지정
6. `Import` 실행
7. Dashboard 제목과 panel query 오류 확인

같은 파일을 반복 import하면 Dashboard가 중복될 수 있으므로 기존 제목을 먼저 확인합니다.

## 5. Dashboard별 검증

| Dashboard | 검증 기준 | 초기 상태 메모 |
|---|---|---|
| Cluster Status Check | Node/Pod/Cluster health panel에 데이터 표시 | backend component가 모두 배포된 뒤 검증 |
| Performance Report - User | Namespace/Service resource query가 오류 없이 실행 | 사용량 데이터가 쌓이기 전에는 비어 있을 수 있음 |
| Performance Report - Admin | 전체 Namespace/Service report query 확인 | 권한/대상 Namespace가 없으면 빈 결과 가능 |
| DKS Policy Dashboard | Underutilized Namespace policy 결과 확인 | ResourceQuota와 사용자 Namespace가 없으면 빈 결과가 정상 |

각 Dashboard에서 `Datasource prometheus was not found`, `No data source`, PromQL parse error가 발생하면 datasource 이름과 JSON의 datasource reference를 대조합니다.

## 6. PNG Export 확인

PNG export 기능은 Grafana 환경에 필요한 plugin 또는 renderer가 설치되어 있어야 합니다. Export 메뉴가 보이지 않거나 실패하면 Dashboard import 실패로 판단하지 말고 plugin/renderer 설치 여부를 별도로 확인합니다.

## 7. 완료 기준

- [ ] dev Grafana Host로 접속 가능
- [ ] `prometheus` datasource의 Test 성공
- [ ] 4개 Dashboard import 완료
- [ ] Dashboard panel에 datasource/PromQL 오류가 없음
- [ ] 초기 데이터 부족으로 빈 panel이 발생하는 경우 원인을 기록함
- [ ] PNG export 필요 여부와 plugin 상태를 확인함

## 증적

비밀번호, Secret, 인증서 원문은 저장하지 않고 아래 정보만 기록합니다.

| 증적 | 기록 내용 |
|---|---|
| Grafana Host | `grafana.xadevpa01.apps.dks.samsungds.net` |
| Datasource | 이름, URL, Test 결과 |
| Dashboard | 파일명, import 시각, 오류 여부 |
| Export | plugin/renderer 상태와 테스트 결과 |
