# 05.2 Member Cluster 설치

Member Cluster는 Host Cluster가 관리하는 사용자 클러스터입니다. Host Cluster와 달리 Member Cluster에서는 **DKS custom Prometheus monitoring stack을 먼저 설치한 뒤 KubeSphere를 설치**해야 합니다.

> [!info] 문서 상태
> 이 문서는 원본 DSPAAS `5-2-1`부터 `5-2-4`까지의 절차를 Xi'an 운영 가이드 형식으로 관리하는 상위 문서입니다. `5-2-1-1~5`는 `dev-apps-pa01-xas` 기준값으로 하위 문서에 분리했습니다. StorageClass와 ETCD 인증서 키 이름처럼 현장 조회가 필요한 값은 확정값으로 추정하지 않습니다.

## 범위

| 단계 | 작업 | 실행자 | 상태 |
|---|---|---|---|
| 5-2-1 | Member Cluster용 DKS Prometheus monitoring stack 설치 | DSPAAS | dev 기준 5개 하위 문서 반영 |
| 5-2-2 | Member Cluster에 KubeSphere 설치 | DSPAAS | 작성 예정 |
| 5-2-3 | Member Cluster를 Host Cluster에 Join | DSPAAS | 작성 예정 |
| 5-2-4 | Host/Member Cluster Daily monitoring script 배포 | DSPAAS | 작성 예정 |

## Host Cluster와의 차이

| 구분 | Host Cluster | Member Cluster |
|---|---|---|
| KubeSphere 설치 순서 | KubeSphere 설치 후 Monitoring 구성 | Prometheus monitoring stack 선행 설치 후 KubeSphere 설치 |
| Monitoring | Host용 Monitoring/KubeSphere stack | DKS custom Prometheus stack을 먼저 배포 |
| 역할 | Member Cluster 관리 및 중앙 Console 제공 | 사용자 workload 실행 및 Host Cluster에 Join |
| Join | 대상이 아님 | 설치 완료 후 Host Cluster Web UI에서 Join |
| 사전 의존성 | Storage/KubeSphere bundle | Storage Class + DKS Prometheus stack |

## 사전 확인

- [ ] 대상이 기존 Host Cluster가 아닌 Member Cluster인지 확인
- [ ] `kubectl` context가 Member Cluster를 가리키는지 확인
- [ ] Storage Class가 생성되어 있고 PVC를 사용할 수 있는지 확인
- [ ] DKS Prometheus stack 설치 bundle 및 image registry 접근 확인
- [ ] Member Cluster용 `kubesphere-installer.yaml` 및 `cluster-configure.yaml` 확보
- [ ] `cluster-configure.yaml`의 Member Cluster 역할 값 확인
- [ ] Host Cluster Web Console 접근 계정 및 Join용 kubeconfig 준비
- [ ] Host/Member Cluster의 cluster name, domain, VIP, CIDR 값 혼동 여부 확인

## 5-2-3. Join Member Cluster to Host Cluster

Member Cluster의 KubeSphere 설치가 완료되면 Host Cluster KubeSphere Web UI에서 Member Cluster를 Import합니다.

### 5-2-3-1. Host Cluster Web UI 절차

1. Host Cluster KubeSphere Web Console에 `admin`으로 로그인
2. 좌측 상단 `Platform` 선택
3. `Cluster Management` 이동
4. `Add Cluster` 선택
5. `Import Cluster`에서 Member Cluster 기본 정보 입력
6. Member Cluster에서 준비한 kubeconfig 입력
7. `Create` 실행
8. Cluster Agent가 `Running`이 된 뒤 Host Cluster에서 Join 결과 확인

### 5-2-3-2. Join 후 검증

```bash
# Member Cluster에서 확인
kubectl get pod -A | grep -E 'cluster-agent|ks-apiserver'

# Host Cluster Web UI에서 Imported Cluster 상태 확인
```

### 5-2-3-3. Join 실패 시 ks-apiserver 로그

```bash
kubectl get pod -n kubesphere-system | grep ks-api
kubectl logs -n kubesphere-system <ks-apiserver-pod>
```

정상 로그에는 `Start listening on :9090`과 같은 기동 메시지가 확인됩니다. 다음 경고는 in-cluster 설정을 사용하는 환경에서 발생할 수 있으므로 단독으로 실패 원인으로 판단하지 않습니다.

```text
Neither --kubeconfig nor --master was specified. Using the inClusterConfig.
```

### 5-2-3-4. `signature is invalid` 발생 시

`ks-apiserver` 로그에 아래 오류가 반복되면 JWT 서명 검증 상태를 우선 확인합니다.

```text
jwt: failed to parse token: signature is invalid
signature is invalid
```

원본 운영 절차의 제한적 조치는 `ks-apiserver` Deployment rollout restart입니다.

```bash
kubectl -n kubesphere-system rollout restart deployment ks-apiserver
kubectl -n kubesphere-system rollout status deployment ks-apiserver
```

재시작 후 Join을 다시 시도하고, 동일 오류가 반복되면 `jwtSecret`, Host/Member 시간 동기화, kubeconfig 및 Join 대상 endpoint를 추가 확인합니다.

### 5-2-3 완료 기준

- [ ] Host Cluster Cluster Management에서 Member Cluster가 표시됨
- [ ] Cluster Agent가 `Running`
- [ ] Member Cluster의 workload/Namespace를 Host Console에서 조회 가능
- [ ] `ks-apiserver` 로그에 새로운 Join 오류가 없음

## 5-2-4. Deploy Mon Script (Daily Monitoring Script)

Host Cluster와 Member Cluster에 Daily monitoring script를 배포합니다.

### 수집 대상

- Node Status
- External ETCD Status
- Pod Status
- Kubernetes Certificate/Key Status

### 배포 전 확인

- [ ] Script 실행 계정과 권한 확인
- [ ] 대상 Context가 Host/Member 중 어느 클러스터인지 명시
- [ ] ETCD endpoint 및 인증서 경로 확인
- [ ] 출력 저장 위치와 보존 기간 확인
- [ ] Cron/Schedule 실행 시간 확인
- [ ] 경고 상태를 담당자에게 전달하는 방법 확인

```bash
# TODO: 실제 Mon script bundle 경로와 설치 명령 추가
kubectl config current-context
kubectl get nodes
```

### 일일 점검 기준

| 점검 항목 | 정상 기준 | Warning 시 조치 |
|---|---|---|
| Node Status | 모든 대상 Node Ready | `kubectl describe node` 및 kubelet 확인 |
| ETCD Status | Target/Endpoint 정상 | endpoint, 인증서, 네트워크 확인 |
| Pod Status | 비정상/재시작 증가 없음 | Namespace별 Pod와 Events 확인 |
| Kubernetes Cert/Key | 만료 임박 또는 만료 없음 | 갱신 일정과 영향 범위 확인 |
