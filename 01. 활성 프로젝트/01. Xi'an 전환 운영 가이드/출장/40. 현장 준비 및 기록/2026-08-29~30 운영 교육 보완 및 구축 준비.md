## 13. Bastion 준비

### 13.1 Bastion 역할

Bastion은 단순 Jump Host가 아니라 설치·검증·운영 명령의 기준점이다.

### 13.2 준비 범주

- `dspaas` 계정
- Group·sudoers
- passwordless sudo
- SSH Key
- Node Host Key
- `/etc/hosts`
- DNS
- Python·Ansible
- Repository
- Kubespray Bundle
- Trident·KubeSphere Bundle
- kubectl·Helm·crictl 등 도구
- CA Trust
- Disk 여유
- 실행 로그 저장 위치

### 13.3 확인 증거

```text
Bastion 로그인
→ 실제 Bundle 경로·Version
→ 대상 Node passwordless SSH
→ sudo -n
→ Ansible Inventory Parse
→ Node Ping
```

### 13.4 다른 Cluster 혼입 방지

- Bastion Prompt의 context
- `/etc/hosts` 대상
- Bundle Directory
- Inventory 이름
- kubeconfig
- Shell History의 과거 명령

다른 Cluster Bastion을 편의상 사용하려면 분리 근거와 대상 검증이 있어야 한다.

## 21. 8/31 Go/No-Go Gate

### GO

- 신규 Member VM과 Role·IP·Disk 자료 확보
- Bastion 접근·Bundle·Tool 준비
- Node SSH·sudo 가능
- VIP·CIDR·Domain·Registry 승인값 확보
- Inventory 기준본과 Backup 준비
- 변경 역할·승인·증적 경로 확인
- 외부 의존성 담당자 연락 가능

### GO WITH CONSTRAINTS

- 일부 실제값은 8/31 현장에서 확인해야 함
- 일부 Network·Storage 항목이 담당자 확인 중
- 대체 진행 순서가 있음
- Kubespray 실행 전까지 해결 가능한 시각·담당자가 명확함

### NO-GO / BLOCKED

- VM·Role·IP 자료 없음
- Bastion 접근 불가
- SSH·sudo 불가
- VIP·CIDR·Domain 중복 여부 미확정
- Inventory 기준본 없음
- Bundle·Registry 접근 불가
- 승인자·복구 기준 없음

BLOCKED 상태에서 Kubespray를 앞당겨 실행하지 않는다.

```text
Host Group·VIP·CIDR·Domain·Registry·Version 전체 검토
→ 값 출처가 없는 필드는 미확정

```

### 사례 4 — StorageClass 이름을 아직 모름

```text
과거 예시로 채우지 않음

```

### 사례 5 — Host Join Port 미확정

```text
9/3 문제로 미루지 않음

→ Network 담당

```
