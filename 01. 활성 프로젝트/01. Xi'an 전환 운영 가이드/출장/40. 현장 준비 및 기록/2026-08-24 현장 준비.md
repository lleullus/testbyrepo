# 2026-08-24 Xi'an 현장 준비

> [!important] 이 문서의 역할
> 8/24는 이동·출입 절차와 현장 운영 조건을 맞추는 준비일이다. **정상적인 기술 교육이나 Cluster 변경을 수행하는 날이 아니며**, 8/25 Kubernetes·DKS 기초 교육을 실제로 시작할 수 있도록 교육 장소·통역·참석자·자료·화면·접근·연락 체계를 사실로 확인하고 미확정 항목을 담당자와 다음 행동으로 연결하는 현장 준비 기준이다.

> [!success] 최신 일정 전제
> 기술 전수 순서는 `8/25 Kubernetes 기초 → 8/26~8/28 운영 Manual → 8/31~9/3 신규 Member 구축 → 9/4 철수`다. 기존 Xi'an Host Cluster는 구축 완료 상태이며 이번 출장에서 재설치하지 않는다. 8/24에는 옛 일정의 “다음날 바로 구축 시작” 전제를 사용하지 않는다.

> [!warning] 준비와 실행의 경계
> 교육장·네트워크·계정·Bastion·Console 접근은 가능 여부를 확인할 수 있지만, 8/24에는 `apply`, `delete`, `patch`, `scale`, `taint`, `rollout restart`, Playbook 실행, 인증서 갱신, Host Join 같은 기술 변경을 하지 않는다. 접근 확인은 조회와 로그인 성공 범위로 제한한다.

## 1. 8/24의 성공 조건

8/24의 목적은 모든 기술 문제를 해결하는 것이 아니라 다음날 교육을 시작할 수 있는지 판단할 수 있는 상태를 만드는 것이다.

```text
현장 도착·출입 가능
+ 교육 장소·장비 사용 가능
+ 참석자·통역 시간 확정
+ 한국어·중국어 최종 교재 준비
+ 화면 공유·Projection 확인
+ 필요한 Web UI·문서 접근 확인
+ 주요 담당자·연락 경로 확인
+ 미확정 항목과 대체 진행안 기록
=
8/25 기초 교육 시작 가능 여부 판정
```

### 1.1 8/24에 완료하지 않아도 되는 것

- 명령어·제품명·Resource Kind는 번역하지 않는다.
- 실제값과 예시값을 명확히 표시한다.
- 질문을 다시 확인한 후 답한다.

- 위험 작업의 승인·중단·복구 용어를 사전에 맞춘다.

3. `Bound`, `Mount`, `Running`, `Ready`를 같은 “정상”으로 번역하지 않는가?

접근 실패를 해결하기 위해 운영 설정을 변경하지 않는다. Source IP·방화벽·계정·URL·시간을 정확히 기록해서 담당자에게 전달한다.

## 13. 8/31 구축 준비의 조기 확인

8/24에 구축을 시작하지 않지만, 이후 일정을 막을 수 있는 외부 의존성의 존재와 담당자만 확인한다.

- Bundle 전달 방식
- Repository 접근

- Pod·Service CIDR 확정 주체
- Domain·DNS 등록 주체
- Host↔Member Join 통신
- Harbor·Repository·Storage 접근

### 13.4 Storage

- SVM·Data LIF·Export policy 담당
- StorageClass 승인값
- Backend 정보 제공 시점
- Node Source IP 허용 방식
