# Workspace Member 운영자 실습 진행안

## 실제 진행 순서

| 순서 | 강사가 시연할 내용 | 교육생이 할 일 | 확인 기준 | 권장 시간 |
|---|---|---|---|---:|
| 1 | 대상 Workspace와 자기 AD 확인 | 01번에서 만든 자기 Workspace 열기 | Workspace 이름 일치 | 2분 |
| 2 | Workspace Member 초대 | 자기 AD 계정 추가, Viewer 선택 | AD + Viewer 일치 | 4~6분 |
| 3 | Workspace Members 확인 | 자기 계정/Role 확인 | 중복 없이 1개, Viewer | 2분 |

정상 진행 기준 약 **10분 내외**로 본다.

## 1. 먼저 한 줄로 연결한다

`일단` 01번에서 Workspace와 Project를 만들어도 실제 사용자는 아직 그 운영 영역에 연결되지 않음 → `그래서` 사용자를 먼저 Workspace Member로 등록해 상위 관리 범위에 포함시킴 → `하지만` Workspace Viewer가 되었다고 Project의 Workload를 생성·변경할 권한까지 생기는 것은 아님 → `따라서` 02번에서는 Workspace Membership만 만들고 → `이후` 03번에서 같은 사용자를 Project Member로 추가하면서 실제 Project Role을 부여함 → `결국` 사용자 접근은 Workspace Membership과 Project Role을 순서대로 연결해야 완성됨

### 이 파트에서 가져가야 할 핵심

```text
Workspace Member
= 사용자를 Workspace 관리 범위에 포함

Workspace Viewer
= Workspace 조회 기반

Project Role
= 실제 Namespace 내부 리소스 권한
```

### 강사 대본

> 1번에서 Workspace하고 Project를 만들었고 실제 Namespace까지 확인했습니다. 그런데 지금 상태는 운영 영역만 만들어진 거고, 실제 사용자는 아직 그 Workspace에 연결되지 않은 상태입니다. 그래서 2번에서는 신청자의 AD 계정을 Workspace Member로 넣는 작업을 합니다. 오늘은 각자 자기 AD를 자기 Workspace에 넣는 방식으로 진행하겠습니다.
>
> 여기서 Workspace Member하고 Project Member를 구분해서 봐야 합니다. Workspace는 Project보다 상위 관리 영역이기 때문에, 먼저 사용자를 Workspace에 포함시켜야 합니다. 그리고 이번에 Workspace에서 주는 Role은 Viewer입니다. Viewer라는 이름 때문에 권한이 너무 약한 것 아닌가 생각할 수 있는데, DKS에서는 일반 사용자를 Workspace 범위에 연결할 때 Viewer를 사용하고 실제 Application 운영 권한은 Project 쪽에서 따로 줍니다.
>
> 그래서 Workspace Viewer를 받았다고 해서 Deployment를 만들거나 PVC, Secret 같은 Project 리소스를 바로 관리할 수 있는 것은 아닙니다. 그건 다음 3번에서 같은 사용자를 Project Member로 추가하고 `project-operator`나 `project-viewer` 같은 Project Role을 줄 때 결정됩니다. Workspace Role하고 Project Role은 범위 자체가 다르다고 보시면 됩니다.
>
> 실제 작업은 간단합니다. `admin`으로 로그인한 상태에서 1번에서 만든 자기 Workspace를 열고, Workspace Members에서 자기 AD를 찾아서 추가한 다음 Viewer를 선택합니다. 여기서 가장 많이 틀릴 수 있는 건 비슷한 AD를 잘못 고르거나 다른 Workspace에 넣는 경우입니다. 그러니까 추가하기 전에 Workspace 이름하고 AD 두 개만 다시 확인하겠습니다.
>
> 완료 기준도 단순합니다. 자기 Workspace의 Workspace Members 목록에 자기 AD가 한 번만 들어가 있고 Role이 Viewer로 보이면 2번은 끝입니다. Project 권한까지 확인하려고 하지 않습니다. 그 상태 그대로 다음 3번으로 넘어가서 같은 사용자를 같은 Project에 연결하겠습니다.

## 2. 실제 진행

### 2.1 대상 확인

`admin`으로 로그인한 상태에서 01번에서 만든 자기 AD 기반 Workspace를 연다.

예시 AD가 `abcd1234.id`라면:

```text
Workspace
ws-dev-apps-pa01-xas-abcd1234-id-dev

추가할 사용자
abcd1234.id
```

주의:
- 로그인 계정은 `admin`이다.
- 추가 대상 사용자는 자기 AD다.
- 다른 교육생 Workspace나 비슷한 계정명을 선택하지 않는다.

---

### 2.2 Workspace Member 추가

```text
Workbench
→ Workspaces
→ 자기 Workspace
→ Workspace Settings
→ Workspace Members
→ Invite Member
→ 자기 AD 계정 선택
→ Viewer 선택
→ OK
```

이번 실습에서 Workspace Role은 **Viewer**를 선택한다.

주의:
- 신청서 Permission이 Admin이어도 여기서 Workspace Admin을 주지 않는다.
- Workspace Viewer는 Project Role과 별도다.

---

### 2.3 바로 확인

Workspace Members 목록에서 다음만 확인한다.

```text
사용자
= 자기 AD 계정

Workspace Role
= Viewer
```

완료 기준:

```text
자기 Workspace
→ 자기 AD Member 존재
→ Viewer 적용
→ 동일 사용자 중복 없음
```

확인 후 같은 사용자와 같은 Project를 사용해 03번 Project Role 실습으로 넘어간다.
