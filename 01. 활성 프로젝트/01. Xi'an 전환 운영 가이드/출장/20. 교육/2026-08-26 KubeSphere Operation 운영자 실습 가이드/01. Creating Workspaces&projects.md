# Creating Workspaces&projects

> [!summary] 요약
> KubeSphere 프로젝트 생성은 신청 접수 → 로그인 확인 → Workspace 생성 → Project 생성의 4단계 절차로 진행된다. DKS 정책상 Workspace와 Project는 1:1 매칭된다.

---

## 1. 신청 접수

시스템 관리자가 사용자로부터 KubeSphere 프로젝트 이용 신청을 수령한다.

KubeSphere에서 **Project**는 Kubernetes의 **Namespace**를 나타낸다. 따라서 사용자는 KubeSphere Project를 통해 DKS Namespace 서비스 이용 신청을 제출해야 한다.

### 방화벽 개방 신청 (사전 필요)

DKS 운영팀은 방화벽 개방을 직접 처리하지 않으므로, 별도의 방화벽 개방 신청이 사전에 필요하다.

| ------- | -------------------- | ------- | ------------- | ------- | ---- | -------------------------------------------------------- |
| All     | KubeSphere Dashboard | User IP | 109.156.25.46 | 80, 443 | TCP  | prd-host VIP-B (Ingress)                                 |
| All     | Harbor               | User IP | 109.156.22.53 | 80, 443 | TCP  | prd-harbor 직접 IP (LB 없음, 도메인 `xa.dcr.dks.samsungds.net`) |

> Xi'an 환경에는 prd-harbor-xas(109.156.22.53) 만 존재하며, dev Harbor는 없습니다.

## 2. 로그인 이력 확인

KubeSphere는 계정 승인 시 사용자의 접근 기록을 요구한다. 따라서 프로젝트 생성 전, 사용자가 KubeSphere 웹 대시보드에 최소 한 번 이상 접속했는지 확인해야 한다.

### 절차

1. Admin 계정으로 KubeSphere 웹 콘솔(Host Cluster)에 로그인
2. 상단 네비게이션바에서 **Workbench > Users** 클릭 → 사용자 관리 페이지 이동
3. 대상 사용자의 로그인 이력 확인
4. 로그인 이력이 없으면 사용자에게 먼저 KubeSphere 웹 접속을 요청

## 3. Workspace 생성

Workspace는 프로젝트의 논리적 단위로, 팀 내에서 리소스에 대한 접근을 제어하고 리소스를 공유하기 위해 사용된다.

DKS 정책상 **Workspace와 Project는 1:1 매칭**된다. 따라서 하나의 Workspace 아래 하나의 Project가 생성된다.

### 교육 전 확인

- 교육생 6명이 사용할 Workspace 이름이 기존 환경에 존재하지 않는지 확인한다.
- 이번 실습 대상 Member Cluster는 `dev-apps-pa01-xas`로 고정한다.
- 각 교육생이 Workspace 생성 작업을 수행할 수 있는 운영 권한이 준비되어 있는지 확인한다. 현재 RBAC 기준상 Workspace 생성은 `platform-admin` 범위에 포함되므로, 실제 교육 환경에서 승인된 교육용 운영 권한을 사용한다.
- 신청서 Permission의 `Admin`과 Workspace 생성 화면의 **Administrator `admin(DKS)`**는 서로 다른 개념이다. 신청서 Admin은 이후 Project Role 매핑 기준이고, `admin(DKS)`는 Workspace 생성 시 지정하는 Administrator이다.

### 절차

1. **Workspace > Create** 클릭
2. **Basic Information** 페이지:
   - **Name**: `ws-[cluster]-[project]-[suffix]`
     - 모든 문자 소문자 사용
     - 예: `ws-prd-apps-pa01-xas-myapp-prd`
   - **Administrator**: 드롭다운에서 `admin(DKS)` 선택
   - **Description**: 신청자 정보 입력 (AD 계정, 부서, 요청일 등)
3. **Cluster Settings** 페이지:
   - 프로젝트명 확인 후 클러스터 할당
   - `prd` 접미사 → `prd-apps-pa01-xas`(production)
   - `dev` 접미사 → `dev-apps-pa01-xas`(development)

   #### Cluster 정보

   | Namespace 접미사 | 용도        | Cluster명          | Ingress 도메인                              |
   | -------------- | --------- | ---------------- | ----------------------------------------- |
   | OOO-prd        | Production | prd-apps-pa01-xas | *.xaprdpa01.apps.dks.samsungds.net        |
   | OOO-dev        | Development | dev-apps-pa01-xas | *.xadevpa01.apps.dks.samsungds.net        |

   > [!note] 권한 매핑 참고
   > 신청서에서 "admin" 권한을 요청하면 KubeSphere에서 `project-operator` 권한이 부여됩니다. "user" 권한을 요청하면 `project-viewer` 권한이 부여됩니다.

4. **Create** 클릭

## 4. Project 생성

KubeSphere의 Project는 Kubernetes의 Namespace와 동일하며, 리소스에 대한 가상 격리를 제공한다.

### 절차

1. Workspace 내에서 **Projects > Create** 클릭
2. Project 이름 입력 후 **OK** 클릭
   - 별칭(Alias) 및 설명(Description) 추가 가능
3. **Projects** 목록에서 생성한 Project 클릭 → 상세 정보 확인

### 완료 확인

Project 생성 직후 화면 확인으로 끝내지 않고, KubeSphere Project와 Kubernetes Namespace가 같은 대상을 가리키는지 확인한다.

```bash
kubectl get namespace <project-name>
```

- Workspace가 생성되어 있다.
- Workspace 아래 Project가 1개 생성되어 있다.
- Project 이름과 Namespace 이름이 동일하다.
- Namespace 상태가 `Active`이다.
- 대상 Member Cluster가 `dev-apps-pa01-xas`와 일치한다.
