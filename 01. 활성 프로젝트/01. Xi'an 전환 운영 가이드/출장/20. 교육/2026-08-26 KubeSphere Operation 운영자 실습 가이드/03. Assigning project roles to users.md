# Assigning project roles to users

> [!summary] 요약
> Workspace에 초대된 멤버에게 Project 레벨에서 역할을 부여하는 절차이다. Role은 project-admin, project-operator, project-viewer 중 선택하며, 사용자의 신청 정보에 따라 할당한다.

---

## Project 멤버 초대

**Workspace에 먼저 초대된 멤버를 Project Member로 추가하고 Project Role을 부여한다.** 따라서 먼저 02. Inviting a new member 절차를 통해 Workspace에 사용자를 초대해야 한다.

### 절차

1. 왼쪽 네비게이션 패널에서 **Projects** 클릭
2. 사용자 권한을 변경할 **Project 이름 클릭**
3. **Project Settings > Project Members > Invite** 클릭
4. **사용자 초대**
   - **이번 6명 교육 실습에서는 모두 `project-operator`를 선택**한다.
   - 실제 운영에서는 사용자 신청서의 Permission 항목(Admin/User) 기준으로 Role을 할당한다. 아래 `[!note]` 권한 매핑을 참고한다.
5. **OK** 클릭

---

## 역할 부여 기준

| Role | 권한 | 신청서 Permission |
|------|------|-------------------|
| **project-admin** | 프로젝트 관리자 — 리소스 생성/수정/삭제, 설정 변경, 멤버 초대 | - |
| **project-operator** | Project Member/Role 관리를 제외한 Project 리소스 생성/수정/삭제 가능 | Admin |
| **project-viewer** | 조회 전용 — 리소스만 확인 가능, 변경 불가 | User |

---

> [!note] 권한 매핑 참고
> 신청서에서 "Admin" 권한을 요청한 사용자는 `project-operator`로, "User" 권한을 요청한 사용자는 `project-viewer`로 역할이 부여됩니다.

### 교육 실습 기준

이번 6명 운영자 실습에서는 교육생별 난이도나 Role을 다르게 나누지 않는다.

- 6명 모두 동일한 절차로 Project Member를 추가한다.
- 6명 모두 동일하게 `project-operator` 지정 작업을 실습한다.
- `project-admin`, `project-viewer`의 차이는 05. RBAC 문서에서 설명한다.

### 완료 확인

- 대상 Project와 AD 계정이 정확하다.
- Project Members 목록에 대상 계정이 등록되어 있다.
- Role이 `project-operator`로 표시된다.
- Workspace Member 등록과 Project Role 부여가 서로 다른 단계임을 확인한다.
