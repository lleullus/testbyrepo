# Enable users using kubectl CLI

> [!summary] 요약
> KubeSphere Web UI 중심 환경에서 kubectl CLI 사용이 필요한 경우 Bastion 접근 → 사용자 kubeconfig 확인/추출 → DEV Member VIP-A 및 context 수정 → 사용자 경로 배치 → 권한 확인 순서로 구성한다.

> [!important] 이번 교육에서의 범위
> 계정 신청·방화벽·CyberArk·VM/Bastion 준비 자체를 수업 중 새로 수행하지 않는다. 교육생 6명은 사전에 준비된 AD 계정과 VM/Bastion 접근을 사용하고, **kubeconfig 구성과 `dev-apps-pa01-xas` context 확인, 자기 Project kubectl 접근 확인**을 직접 수행한다.

---

## 1. 개요

KubeSphere Web UI 기반 운영 환경에서 kubectl CLI는 별도 Bastion 경로를 통해 제공한다.

이번 실습 대상은 `dev-apps-pa01-xas`이며 API Server VIP-A는 `109.156.25.72:6443`이다.

교육에서는 다음 연결을 이해하고 직접 확인하는 것이 목적이다.

```text
사용자 AD 계정
→ Bastion/VM 접속
→ kubeconfig-[AD 계정] ConfigMap
→ dev-apps-pa01-xas / 109.156.25.72:6443
→ 사용자 context
→ 자기 Project RBAC
→ kubectl 명령 결과 확인
```

---

## 2. 사전 요청 절차

원본 운영 절차에서는 T-DKS 팀에 Bastion 계정 생성 및 방화벽 개방을 요청한다. Bastion 계정명은 AD 계정명과 동일하게 구성하며, DKS 운영팀으로부터 계정 생성 통보를 받은 뒤 필요한 CyberArk 권한을 별도로 요청한다.

### 요청 폼 양식

| 항목 | 내용 |
|------|------|
| **DKS kubectl application** | Remarks |
| **User information** | |
| - Requestor Name | 신청자 이름 |
| - User account | Global AD 계정 |
| **DKS information** | |
| - Cluster | `dev-apps-pa01-xas` |
| - Project | 대상 Project |

### 이번 교육 Preflight

수업 시작 전 확인한다.

- [ ] 교육생 6명 모두 VM/Bastion 접속 가능
- [ ] `kubectl` 명령 실행 가능
- [ ] 각 사용자 `kubeconfig-<AD 계정>` ConfigMap 존재
- [ ] 각 사용자 Project 생성 완료
- [ ] 각 사용자에게 `project-operator` Role 부여 완료

## 3. 설정 절차

### 3.1 Bastion/VM 연결

이번 교육에서는 사전에 준비된 VM/Bastion 계정으로 접속한 상태에서 시작한다.

```bash
whoami
kubectl version --client
```

### 3.2 사용자 kubeconfig ConfigMap 확인

ConfigMap 이름:

```text
kubeconfig-[User global AD account]
```

ConfigMap 조회는 해당 Namespace를 조회할 수 있는 기존 운영 context에서 수행한다.

```bash
AD_ACCOUNT=<G-AD-user-account>

kubectl get -n kubesphere-controls-system configmaps | grep -F "$AD_ACCOUNT"
kubectl get -n kubesphere-controls-system configmap "kubeconfig-$AD_ACCOUNT"
```

#### config 파일 추출

원본 가이드는 `kubectl describe ... > config` 후 설명용 라인을 제거하는 방식이다. ConfigMap의 `config` key가 확인되면 해당 데이터만 직접 추출할 수 있다.

```bash
mkdir -p "$HOME/ksop-260826/$AD_ACCOUNT"
cd "$HOME/ksop-260826/$AD_ACCOUNT"

kubectl get configmap "kubeconfig-$AD_ACCOUNT" \
  -n kubesphere-controls-system \
  -o jsonpath='{.data.config}' > config
```

직접 추출이 어려운 경우 원본 방식도 사용할 수 있다.

```bash
kubectl describe configmap \
  -n kubesphere-controls-system \
  "kubeconfig-$AD_ACCOUNT" > config
```

`describe` 출력 방식을 사용한 경우 `#Name`, `#Namespace`, `#Labels`, `#Annotations`, `#Data`, `#config`, `#BinaryData`, `#Events` 등 설명용 라인을 제거하고 kubeconfig YAML만 남긴다.

### 3.3 config 파일 수정

```bash
vi config
```

수정 항목:

| 변경 항목 | 변경값 |
|-----------|-----------|
| `server` | `https://109.156.25.72:6443` |
| `name` (clusters) | `dev-apps-pa01-xas` |
| `cluster` (contexts) | `dev-apps-pa01-xas` |
| `name` (contexts) | `[AD 계정]@dev-apps-pa01-xas` |
| `current-context` | `[AD 계정]@dev-apps-pa01-xas` |

구조 예시:

```yaml
apiVersion: v1
clusters:
- cluster:
    certificate-authority-data: <기존 값 유지>
    server: https://109.156.25.72:6443
  name: dev-apps-pa01-xas
contexts:
- context:
    cluster: dev-apps-pa01-xas
    namespace: default
    user: <AD_ACCOUNT>
  name: <AD_ACCOUNT>@dev-apps-pa01-xas
current-context: <AD_ACCOUNT>@dev-apps-pa01-xas
kind: Config
preferences: {}
users:
- name: <AD_ACCOUNT>
  user:
    client-certificate-data: <기존 값 유지>
    client-key-data: <기존 값 유지>
```

### 3.4 Bastion 사용자 계정 준비 — 운영 절차 참고

원본 운영 절차에서는 필요 시 Bastion 서버에 AD 계정과 동일한 OS 계정을 생성한다.

```bash
sudo useradd [G-AD user account]
sudo passwd [G-AD user account]
```

이번 교육에서는 계정 생성 자체를 반복하지 않고, 사전 준비된 계정/VM을 사용한다.

### 3.5 config 배치

이번 6명 실습에서는 기존 config와 구분되는 교육용 파일을 사용한다.

```bash
mkdir -p "$HOME/.kube"
cp config "$HOME/.kube/config-ksop-260826"
chmod 600 "$HOME/.kube/config-ksop-260826"
export KUBECONFIG="$HOME/.kube/config-ksop-260826"
```

6명이 각자 별도 VM을 사용하므로 같은 파일명을 사용해도 서로 충돌하지 않는다.

### 3.6 config 적용 및 권한 확인

교육생 각자가 자기 Project 이름을 넣고 확인한다.

```bash
PROJECT=<자기-project-name>

kubectl config view --minify -o jsonpath='{.clusters[0].cluster.server}{"\n"}'
kubectl auth can-i get pods -n "$PROJECT"
kubectl auth can-i create deployments.apps -n "$PROJECT"
kubectl get all -n "$PROJECT"
```

확인 기준:

- API Server가 `https://109.156.25.72:6443`를 가리킨다.
- 자기 Project 조회가 가능하다.
- `project-operator` 기준의 리소스 운영 권한이 확인된다.
- `kubectl get all -n <project>` 결과가 비어 있어도 명령 자체가 정상 수행되면 접근 확인은 완료다.

## 5. 교육 종료 후 정리

교육용 별도 config를 만든 경우 실습 종료 후 정리한다. 예를 들어 실습 계정이 `dj2.kim`이라면 다음과 같이 정리한다.

```bash
unset KUBECONFIG
rm -f "$HOME/.kube/config-ksop-260826"
rm -rf "$HOME/ksop-260826/dj2.kim"
```

Bastion/VM에 `dj2.kim` 로컬 OS 계정을 실습 중 직접 생성했다면 계정과 홈 디렉터리도 함께 삭제한다.

```bash
sudo userdel -r dj2.kim
```

삭제 확인:

```bash
getent passwd dj2.kim
```

아무 결과가 나오지 않으면 로컬 OS 계정 삭제가 완료된 것이다. CyberArk/AD 계정 자체를 삭제하는 명령이 아니라 Bastion/VM에 직접 만든 로컬 계정 정리 절차다.
