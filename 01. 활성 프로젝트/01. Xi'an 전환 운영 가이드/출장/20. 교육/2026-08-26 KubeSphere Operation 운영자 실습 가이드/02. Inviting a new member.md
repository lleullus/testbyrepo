# Inviting a new member

> [!summary] 요약
> Workspace에 새 사용자를 초대하고 viewer 역할을 부여하는 절차이다. Workspace Settings에서 멤버를 추가하고, 기존 멤버의 역할 변경 또는 제거도 가능하다.

---

## Workspace 멤버 초대

KubeSphere는 사용자 계정 승인 시 사용자의 접근 기록을 요구한다. **Project Member/Role을 부여하기 전에** 사용자를 Workspace에 먼저 초대해야 한다.

### 절차

1. **Workbench > Workspaces** 클릭
2. 멤버를 추가할 **Workspace 선택**
3. **Workspace Settings > Workspace Members > Invite Member** 클릭
4. **사용자 초대**
   - Role: **viewer** 부여
   - viewer는 Workspace 내 모든 리소스를 조회할 수 있는 역할
5. **OK** 클릭 — Workspace Members 목록에 새로 초대된 멤버 확인

> [!note] Role 표기
> 운영 가이드와 RBAC 문서에서는 `viewer`, `ws-viewer` 표현이 함께 사용된다. 교육에서는 실제 KubeSphere UI에 표시되는 Workspace Viewer 역할을 선택하고, 개념상 `ws-viewer` 역할임을 연결해서 설명한다.

### 완료 확인

- 대상 Workspace가 정확하다.
- 초대한 AD 계정이 신청/교육 대상 계정과 일치한다.
- Workspace Members 목록에 대상 계정이 1개만 등록되어 있다.
- Workspace Viewer 역할이 적용되어 있다.
- Project Role은 아직 별도 단계이며, Workspace Viewer만으로 Project 리소스 운영 권한이 생기는 것은 아니다.

### 기존 멤버 관리

기존 멤버의 역할을 변경하거나 Workspace에서 제거할 수 있다.

- **역할 변경**: Workspace Members에서 대상 멤버 선택 → Edit
- **제거**: Workspace Members에서 대상 멤버 선택 → 제거

---

> [!note] 권한 매핑 참고
> 신청서에서 "admin" 권한을 요청한 사용자는 이후 Project 레벨에서 `project-operator`로, "user" 권한을 요청한 사용자는 `project-viewer`로 역할이 부여됩니다. Workspace 초대는 일단 `viewer`로 진행됩니다.

---

## Role: viewer

| 항목 | 내용 |
|------|------|
| 권한 | Workspace 내 모든 리소스 조회 |
| 제한 | 리소스 생성/수정/삭제 불가 |
| 용도 | 사용자 온보딩, 접근 이력 확인용 |
