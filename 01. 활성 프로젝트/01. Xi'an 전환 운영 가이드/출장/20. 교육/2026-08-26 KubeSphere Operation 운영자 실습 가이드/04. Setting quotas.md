# Setting quotas

> [!summary] 요약
> Workspace Quotas(CPU/Memory), Project Quotas(CPU/Memory), Storage Resource Quota 3가지 할당량을 설정한다. Xi'an 환경의 저장소는 NetApp Trident StorageClass를 기준으로 설정한다. DKS 환경에서 Workspace와 Project는 1:1 매칭되므로 Workspace Quota와 Project Quota는 동일한 값으로 설정한다.

> [!note] 신청서 연동
> Quota 값은 사용자가 제출한 신청서의 **DKS Information** 항목(CPU, Memory, Storage)에 따라 설정합니다. 신청서 Sample은 [[50. 운영/04. Kubesphere Operation/01. Creating Workspaces&projects|01. Creating Workspaces&projects]] 문서를 참고하세요.

> [!important] 교육 실습 기준
> 이번 6명 실습에서는 CPU·Memory·Storage 값을 하나로 정하고 6명 모두 동일하게 적용한다.

---

## 1. Workspace Quotas (CPU/Memory)

Workspace Quotas는 Workspace 내 모든 Project의 총 리소스 사용량을 제어한다.

DKS 환경에서 Workspace와 Project가 1:1 매칭되므로, Workspace Quota와 Project Quota는 동일한 값으로 설정한다.

Workspace Quotas는 CPU와 Memory의 **Requests**와 **Limits**를 포함한다.

- **Requests**: Workspace 내 Project가 필요한 리소스를 보장하고 예약한다.
- **Limits**: Workspace 내 모든 Project의 리소스 사용량이 특정 값을 초과하지 않도록 한다.

### 절차

1. **Workbench > Workspaces** 클릭
2. Quotas를 설정할 **Workspace 선택**
3. **Workspace Settings > Workspace Quotas > Edit Quotas** 클릭
4. **Quotas 설정**
   - 기본값: Requests와 Limits 모두 미설정
   - 슬라이더로 이동하거나 숫자를 직접 입력
   - **CPU Limit**: 애플리케이션의 CPU 코어 값
   - **CPU Request**: 애플리케이션의 CPU 코어 값
   - **Memory Limit**: 애플리케이션의 메모리 값
   - **Memory Request**: 애플리케이션의 메모리 값
5. **OK** 클릭

---

## 2. Project Quotas (CPU/Memory)

KubeSphere는 Kubernetes의 Requests와 Limits를 사용하여 Project 내 리소스(CPU, Memory) 사용량을 제어한다. Kubernetes에서는 이를 **ResourceQuotas**라고 한다.

- **Requests**: Project가 필요한 리소스를 보장하고 예약한다.
- **Limits**: Project가 특정 값을 초과하여 리소스를 사용하지 못하도록 한다.

### 절차

1. **Project Overview** 페이지에서 Quotas 확인
   - 새로 생성된 Project는 Quotas가 미설정되어 있음
   - **Edit Quotas** 클릭하여 구성
2. **Quotas 설정**
   - 기본값: Requests와 Limits 모두 미설정
   - 슬라이더로 이동하거나 숫자를 직접 입력
   - **CPU Limit**: 애플리케이션의 CPU 코어 값
   - **CPU Request**: 애플리케이션의 CPU 코어 값
   - **Memory Limit**: 애플리케이션의 메모리 값
   - **Memory Request**: 애플리케이션의 메모리 값
3. **OK** 클릭
4. **Project Settings > Basic Info**에서 모든 리소스 Quotas 확인

## 3. Storage Resource Quota

Namespace(=Project)에서 요청할 수 있는 저장소 리소스의 총합을 제한한다. 또한, StorageClass별로 저장소 소비를 제한할 수 있다.

### 절차

1. **현재 StorageClass 상태 확인**

   ```bash
   kubectl get sc
   ```

   | NAME | PROVISIONER | RECLAIMPOLICY | VOLUMEBINDINGMODE | ALLOWVOLUMEEXPANSION | AGE |
   |------|-------------|---------------|-------------------|----------------------|-----|
   | scs-netapp-qtree-nfs-sc-delete | csi.trident.netapp.io | Delete | Immediate | true | 27d |

   **현재 사용 중인 NetApp StorageClass에 대해 Quota를 설정한다.**

   > 실제 `kubectl get sc` 결과를 한 번 확인한 뒤 6명 모두 같은 StorageClass를 사용한다.

2. **YAML 파일 생성**

   ```yaml
   # storagequota.yaml
   ---
   apiVersion: v1
   kind: ResourceQuota
   metadata:
     name: <project-name>-storage-quota
     namespace: <project-name>
   spec:
     hard:
       scs-netapp-qtree-nfs-sc-delete.storageclass.storage.k8s.io/requests.storage: 10Gi
       requests.storage: 10Gi
   ```

   `<project-name>`은 각자 자기 Project 이름으로 바꾼다. 교육용 Storage 값이 10Gi가 아닌 경우 두 `10Gi`를 동일한 확정값으로 바꾼다.

   #### 필드 설명

   | 필드 | 설명 |
   |------|------|
   | `metadata.name` | `<project-name>-storage-quota` |
   | `metadata.namespace` | 프로젝트 이름 |
   | `requests.storage` | Namespace에서 요청할 수 있는 저장소의 총합 |
   | `<storage-class-name>.storageclass.storage.k8s.io/requests.storage` | 해당 StorageClass별 저장소 요청 총합 |

3. **적용 전 대상 확인**

   Storage Quota는 CLI로 적용하므로 적용 직전에 대상 Namespace를 확인한다.

   ```bash
   kubectl get namespace <project-name>
   ```

   - `<project-name>`이 자기 AD 기반 Project이고 Namespace 상태가 `Active`인지 확인한다.

4. **ResourceQuota 적용**

   ```bash
   kubectl create -f storagequota.yaml
   ```

5. **적용 결과 확인**

   ```bash
   kubectl get resourcequota -n <project-name>
   kubectl describe resourcequota <project-name>-storage-quota -n <project-name>
   ```

   확인 항목:

   - Namespace가 대상 Project와 일치하는지
   - `requests.storage`가 교육에서 정한 값과 일치하는지
   - StorageClass별 Quota가 현재 사용 중인 StorageClass에 적용됐는지

   > [!note] 기존 ResourceQuota 확인
   > 동일 이름의 ResourceQuota가 이미 존재하면 `create`를 반복하지 않고 기존 상태를 먼저 확인한다.
