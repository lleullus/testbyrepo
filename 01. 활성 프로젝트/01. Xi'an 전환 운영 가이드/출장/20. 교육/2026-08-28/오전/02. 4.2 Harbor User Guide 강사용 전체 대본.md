# 4.2 Harbor User Guide 강사용 전체 대본

> [!important] 사용 방법
> 이 대본은 **사용자가 Xi'an Harbor에서 처음 Image를 Pull하고 Push한다는 전제**로 작성했다. 명령부터 외우게 하지 않는다. 사용자 자격, Network와 HTTPS 신뢰가 먼저 준비돼야 하는 이유를 설명한 뒤 Login·Pull·Tag·Push로 연결한다. 제공된 출력은 실제 Xi'an 실행 증적이 아니므로 핵심 결과만 설명한다.

## 0. 강사가 머릿속에 들고 갈 설명 공식

```text
사용자가 Image로 하려는 일을 먼저 말한다
→ 그 작업의 선행조건을 설명한다
→ Xi'an 실제 주소와 값을 보여준다
→ 명령의 입력과 결과를 연결한다
→ 명령 종료가 아니라 실제 Image 결과를 확인한다
```

## 0-1. 오늘 전체 한 줄

```text
Harbor를 사용할 계정을 준비한다
→ Harbor까지 방화벽을 연다
→ 웹에서 접속을 확인한다
→ Docker가 Xi'an CA를 신뢰하게 한다
→ Docker Login
→ Image Pull과 로컬 확인
→ Source Image에 대상 주소를 Tag
→ Image Push와 Harbor 결과 확인
```

---

# 1. 시작 — docker login부터 실행하지 않는다

> 오늘은 사용자가 Xi'an Harbor에서 Container Image를 가져오고 올리는 방법을 보겠습니다.
>
> Harbor에서 Image를 가져오는 동작은 **Pull**, Harbor에 Image를 올리는 동작은 **Push**입니다.
>
> **하지만**, `docker login` 명령부터 실행하면 계정, Network와 인증서 신뢰 중 어디가 준비되지 않았는지 구분하기 어렵습니다.
>
> **그래서**, 먼저 누가 사용할 수 있는지, 사용자 시스템에서 Harbor까지 갈 수 있는지, Docker가 Harbor 인증서를 신뢰하는지 확인한 뒤 Login과 Image 작업으로 들어갑니다.

```text
사용자 자격
→ Network
→ 웹 접속
→ Docker CA Trust
→ Login
→ Pull
→ Tag
→ Push
```

---

# 2. 누가 Harbor를 사용할 수 있는가

> Xi'an Harbor는 Global AD 계정으로 접속합니다.
>
> 사용자가 Harbor 사용 대상 AD 보안그룹의 Member여야 해당 Global AD 계정으로 접근할 수 있습니다.

## 2.1 AD 보안그룹 신청

> AD 보안그룹 Member 등록 요청은 DS Pass를 통해 제출합니다.

- DS Pass: [https://pass.samsungds.net:8082/](https://pass.samsungds.net:8082/)
- 기존 가이드의 보안그룹: `[SG1599] DKS Prd User Group`
- 설명: `DKS Production environment user group`

> **하지만**, `SG1599`와 DS Pass 신청 경로는 기존 가이드의 값이며 Xi'an 최종 운영 절차로 확정되지 않았습니다.
>
> SCS AD Domain과 최종 로그인 연동 방식도 확인이 필요합니다.
>
> **따라서**, 가입 요청을 제출하기 전에 Xi'an 운영팀에 대상 보안그룹과 신청 경로가 그대로 적용되는지 확인합니다.

## 2.2 계정과 Network는 서로 다른 조건이다

> AD 보안그룹 Member라는 사실은 사용 자격을 준비했다는 뜻입니다.
>
> **하지만**, 사용자 시스템에서 Harbor까지 Network가 막혀 있으면 올바른 계정도 Harbor에 도달할 수 없습니다.

---

# 3. 사용자 시스템에서 Harbor까지 길을 연다

> Harbor에 접근하려면 사용자 시스템의 Source IP에서 Xi'an Harbor IP로 방화벽을 개방해야 합니다.

| 목적 | Source IP | Destination IP | Port | Protocol |
|---|---|---:|---:|---|
| Harbor 사용 | 사용자 시스템 IP | `109.156.22.53` | `80`, `443` | TCP |

> 방화벽 관련 신청과 문의는 GSAMS를 사용합니다.
>
> GSAMS 주소는 [http://gsams.samsungds.net/](http://gsams.samsungds.net/)입니다.

## 3.1 Xi'an 주소를 사용한다

> 기존 Taylor Harbor IP는 `105.219.33.203`입니다.
>
> **하지만**, Xi'an에서는 이 값을 사용하지 않습니다. Xi'an Harbor IP는 `109.156.22.53`입니다.
>
> Xi'an Harbor는 별도 Load Balancer 없이 이 IP로 직접 연결합니다.

```text
사용자 Source IP
→ TCP 80·443
→ 109.156.22.53
→ Xi'an Harbor
```

> Network가 준비되면 브라우저에서 Harbor 웹 콘솔에 접속해 주소와 계정 경로를 확인합니다.

---

# 4. 웹 접속과 Docker Login은 같은 확인이 아니다

## 4.1 Harbor 웹 콘솔 접속

| 항목 | 값 |
|---|---|
| Harbor URL | `https://xa.dcr.dks.samsungds.net/` |
| Username | G-AD Account |
| Password | G-AD Password |

> 브라우저에서 `https://xa.dcr.dks.samsungds.net/`에 접속하고 G-AD 계정으로 로그인합니다.
>
> **하지만**, 브라우저에서 화면이 열린다고 Docker도 같은 인증서를 자동으로 신뢰하는 것은 아닙니다.
>
> Docker가 Harbor Registry와 HTTPS로 통신하려면 사용자 시스템에 Xi'an CA 신뢰를 적용해야 합니다.

## 4.2 Docker Login 전에 필요한 것

> Docker Login을 진행할 시스템에는 다음 조건이 필요합니다.

```text
Docker 설치 가능 시스템
+
109.156.22.53의 TCP 80·443 방화벽
+
승인된 Xi'an 2-Tier Root CA
+
CA Trust 변경과 Docker 재시작을 위한 sudo 권한
```

> 아래 경로와 명령은 RHEL 계열 시스템 기준입니다.

## 4.3 Xi'an 2-Tier Root CA를 적용한다

> 사용할 인증서 파일은 `SECDS-2TROOTCA.crt`입니다.
>
> 일반 CA 인증서나 Harbor Server 인증서로 바꾸지 않습니다.

```bash
sudo cp ./SECDS-2TROOTCA.crt /etc/pki/ca-trust/source/anchors
sudo update-ca-trust extract
sudo systemctl restart docker
```

> 첫 번째 명령은 승인된 2-Tier Root CA를 Trust Anchor 경로에 복사합니다.
>
> 두 번째 명령은 시스템 CA Trust를 갱신합니다.
>
> 세 번째 명령은 Docker가 갱신된 Trust를 사용하도록 Service를 재시작합니다.

## 4.4 Docker Login

```bash
sudo docker login xa.dcr.dks.samsungds.net
```

> Username에는 승인된 G-AD 계정을 입력하고 Password는 화면에서 직접 입력합니다.
>
> 정상 결과는 다음 문장입니다.

```text
Login Succeeded
```

## 4.5 Credential 저장 경고를 실패로 오해하지 않는다

> Login 과정에서 `/root/.docker/config.json`에 Password가 암호화되지 않은 상태로 저장될 수 있다는 경고가 표시될 수 있습니다.
>
> 이 경고 자체는 Login 실패 메시지가 아닙니다.
>
> **하지만**, 보안상 무시할 내용도 아닙니다. 조직에서 승인한 Docker Credential Helper가 있으면 해당 정책을 따르고 Password를 문서나 작업 로그에 기록하지 않습니다.

---

# 5. Harbor에서 Image를 가져온다

> Login이 준비되면 Harbor에 있는 Image를 사용자 시스템으로 가져올 수 있습니다.
>
> Pull 명령을 실행하기 전에 Image 주소를 네 부분으로 나눠 읽겠습니다.

```text
Domain
/
Repository Path
/
Image
:
Tag
```

예시는 다음과 같습니다.

```text
xa.dcr.dks.samsungds.net/dspaas-testrepo/nginx:latest
```

| 부분 | 값 |
|---|---|
| Domain | `xa.dcr.dks.samsungds.net` |
| Repository Path | `dspaas-testrepo` |
| Image | `nginx` |
| Tag | `latest` |

## 5.1 Image Pull

명령 형식:

```bash
docker pull [DOMAIN_NAME][:PORT]/[REPOSITORY_PATH]/[IMAGE][:TAG]
```

Xi'an 예시:

```bash
sudo docker pull xa.dcr.dks.samsungds.net/dspaas-testrepo/nginx:latest
```

> Pull이 완료되면 명령에 지정한 Repository와 Tag가 Download 결과에 표시되는지 확인합니다.
>
> 제공된 Guide 출력에는 명령의 `dspaas-testrepo/nginx:latest`와 첫 출력의 `dks-test/nginx`, `v1.0`이 일치하지 않습니다. 이 출력은 실제 Xi'an 증적이 아닙니다.
>
> **따라서**, 실제 작업에서는 제공 로그를 성공 증거로 사용하지 않고 자신이 실행한 명령의 Repository와 Tag를 기준으로 확인합니다.

## 5.2 로컬 Image 확인

```bash
sudo docker image ls
```

> Pull은 명령 종료만 보는 것이 아니라 로컬 Image 목록에서 결과를 확인합니다.

```text
REPOSITORY
xa.dcr.dks.samsungds.net/dspaas-testrepo/nginx

TAG
latest
```

> Repository와 Tag가 예상한 값과 일치하면 어떤 Image를 로컬로 가져왔는지 확인할 수 있습니다.

---

# 6. 로컬 Image를 Harbor에 올린다

> Push는 사용자 시스템에 있는 Image를 Harbor Repository로 올리는 동작입니다.
>
> **하지만**, 로컬 이름 `nginx:v1.0`만으로는 어느 Harbor와 Repository에 올릴지 알 수 없습니다.
>
> **그래서**, 먼저 Source Image에 Harbor 대상 전체 주소를 새 Tag로 붙입니다.

## 6.1 Source Image를 확인한다

```bash
sudo docker image ls
```

확인할 Source:

```text
nginx:v1.0
```

> Source Repository와 Tag가 실제로 존재하는지 확인한 뒤 대상 Tag를 만듭니다.

## 6.2 Harbor 대상 주소로 Tag한다

명령 형식:

```bash
docker tag [SOURCE_IMAGE][:TAG] [DOMAIN_NAME][:PORT]/[REPOSITORY_PATH]/[IMAGE][:TAG]
```

Xi'an 예시:

```bash
sudo docker tag nginx:v1.0 \
  xa.dcr.dks.samsungds.net/dspaas-testrepo/nginx:latest
```

```text
Source
nginx:v1.0

Target
xa.dcr.dks.samsungds.net/dspaas-testrepo/nginx:latest
```

> Tag는 같은 Image에 Harbor 대상 이름을 추가하는 작업입니다.
>
> Tag를 만들었다고 Harbor에 업로드된 것은 아닙니다.

## 6.3 Tag 결과를 확인한다

```bash
sudo docker image ls
```

> Source와 Target이 같은 Image ID를 가리키는지 확인합니다.
>
> 그다음 Target 전체 주소를 사용해 Push합니다.

## 6.4 Registry로 Push한다

명령 형식:

```bash
docker push [DOMAIN_NAME][:PORT]/[REPOSITORY_PATH]/[IMAGE][:TAG]
```

Xi'an 예시:

```bash
sudo docker push \
  xa.dcr.dks.samsungds.net/dspaas-testrepo/nginx:latest
```

> 제공된 Guide 출력의 마지막 줄에는 Push 명령의 `latest`와 다른 `test` Tag가 기록돼 있습니다. 이 출력도 실제 Xi'an 성공 증거로 사용하지 않습니다.
>
> 실제 Push에서는 자신이 실행한 Target Repository와 Tag를 기준으로 결과를 확인합니다.

## 6.5 Push 결과를 Harbor에서 확인한다

> Push 명령이 끝났으면 Harbor 웹 콘솔에서 대상 Repository를 엽니다.
>
> 실제 Target과 Harbor 화면의 Artifact, Tag와 Digest가 일치하는지 확인합니다.

```text
Push 명령의 Target
=
Harbor Repository의 Artifact·Tag·Digest
```

> **결국**, Tag 생성은 로컬 Image에 대상 이름을 붙이는 단계이고 Push는 그 이름의 Image를 Harbor에 업로드하는 단계입니다.

---

# 7. 처음부터 끝까지 다시 연결한다

> Harbor 사용은 `docker login` 한 줄로 시작하고 끝나는 작업이 아닙니다.
>
> 먼저 사용자가 승인된 AD 보안그룹 Member인지 확인합니다.
>
> 사용자 시스템의 Source IP에서 Xi'an Harbor `109.156.22.53`의 TCP `80`, `443`까지 방화벽을 준비합니다.
>
> 웹에서는 `https://xa.dcr.dks.samsungds.net/`에 G-AD 계정으로 접속합니다.
>
> Docker를 사용하는 RHEL 계열 시스템에는 `SECDS-2TROOTCA.crt`를 적용하고 CA Trust 갱신과 Docker 재시작을 진행합니다.
>
> `Login Succeeded`를 확인한 뒤 정확한 Repository·Image·Tag로 Pull하고 `docker image ls`에서 로컬 결과를 확인합니다.
>
> Push할 때는 Source Image에 Harbor Target 주소를 Tag하고 Push한 뒤 Harbor 화면의 Artifact·Tag·Digest를 확인합니다.

```text
AD 사용자 자격
→ Harbor Network
→ 웹 접속
→ 2-Tier Root CA
→ Docker Login
→ Pull과 로컬 Image
→ Tag
→ Push
→ Harbor Artifact·Tag·Digest
```
