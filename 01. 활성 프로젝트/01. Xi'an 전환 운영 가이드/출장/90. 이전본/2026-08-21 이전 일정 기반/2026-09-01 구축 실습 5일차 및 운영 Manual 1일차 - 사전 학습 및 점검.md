# 2026-09-01 구축 실습 5일차 및 운영 Manual 1일차 - 사전 학습 및 점검

> [!important] 하루 구성
> **오전에는 신규 Member 구축의 최종 완료 조건인 기존 Host Join까지 끝내고**, 구축이 정상 완료된 경우 오후부터 `1. Kubesphere Operation` Manual을 빠르게 가이딩한다.

> [!success] Host 전제
> Join 대상 Host Cluster는 이미 구성 완료된 기존 Host다. Host 자체를 새로 설치하거나 재구성하지 않는다.

## 1. 오전 — Member 최종 검증과 기존 Host Join

### 적용 Manual

- [[30. 구축 및 전환/공통 구축/Xi'an/한국어/05-2|5.5.2 Install kubesphere - member cluster]]

### Join 전 확인

- Member Monitoring Pod·PVC 정상
- Prometheus Target 정상
- Grafana datasource / Dashboard 정상
- Member KubeSphere 주요 workload 정상
- `multicluster.clusterRole=member`
- Member API 접근 가능
- 기존 Host 접근 가능
- Host↔Member 통신·DNS·방화벽 조건 확인

### 수행 흐름

```text
Member 최종 상태 확인
→ 기존 Host Console / Join 대상 확인
→ 승인된 Join 절차 수행
→ Member Agent 상태 확인
→ Host Console에서 신규 Member 확인
→ Multi-Cluster 관리·관측 확인
```

### 구축 5일 완료 기준

- [ ] 신규 Member Kubernetes가 정상이다.
- [ ] Storage가 Mount·Read/Write까지 정상이다.
- [ ] Member Monitoring이 정상이다.
- [ ] Member KubeSphere가 정상이다.
- [ ] 기존 Host에 Join됐다.
- [ ] Host Console에서 Member가 정상 상태로 보인다.
- [ ] Multi-Cluster 관리·관측이 가능하다.

오전 구축이 완료되지 않으면 오후 Manual 가이딩 시간을 압축하거나 뒤로 조정하되 **Member Join 완료가 우선**이다.

## 2. 오후 — 1. Kubesphere Operation

오후의 목적은 모든 UI를 처음부터 끝까지 실습하는 것이 아니라, **배포 Manual의 메뉴 구조와 각 문서의 사용 시점·핵심 절차를 빠르게 인계**하는 것이다.

### 1.1 Creating Workspaces&projects

[[50. 운영/04. Kubesphere Operation/01. Creating Workspaces&projects|1.1 Creating Workspaces&projects]]

확인할 것:

- 어떤 신청을 받을 때 사용하는 문서인가.
- Workspace와 Project의 역할은 무엇인가.
- Project가 Kubernetes Namespace와 어떻게 연결되는가.
- 대상 PRD/DEV Cluster를 어떻게 구분하는가.

### 1.2 Inviting a new member

[[50. 운영/04. Kubesphere Operation/02. Inviting a new member|1.2 Inviting a new member]]

확인할 것:

- Workspace Member 초대 위치
- viewer 역할의 의미
- Workspace 초대와 Project 권한이 같은 것이 아니라는 점

### 1.3 Assigning project roles to users

[[50. 운영/04. Kubesphere Operation/03. Assigning project roles to users|1.3 Assigning project roles to users]]

확인할 것:

- Project Member 초대
- `project-operator` / `project-viewer` 등 역할 구분
- 신청서 권한과 실제 Role 매핑

### 1.4 Setting quotas

[[50. 운영/04. Kubesphere Operation/04. Setting quotas|1.4 Setting quotas]]

확인할 것:

- Workspace / Project CPU·Memory Quota
- Storage ResourceQuota
- 실제 StorageClass 확인 후 적용해야 하는 이유

### 1.5 Kubesphere Role-Based Access Control

[[50. 운영/04. Kubesphere Operation/05. Kubesphere Role-Based Access Control|1.5 Kubesphere Role-Based Access Control]]

확인할 것:

- Platform / Workspace / Project 권한 계층
- 최소 권한 관점에서 각 Role을 어디에 사용하는지

### 1.6 Enable users using kubectl CLI

[[50. 운영/04. Kubesphere Operation/06. Enable users using kubectl CLI|1.6 Enable users using kubectl CLI]]

확인할 것:

- Web UI와 kubectl 접근 경계
- Bastion / kubeconfig / context / VIP-A 관계
- 인증정보 원문을 공유하거나 기록하지 않는 원칙

### 1.7. Kubesphere SECDS-ROOT.crt(CA.crt) ConfigMap Mount

[[50. 운영/04. Kubesphere Operation/07. KubeSphere SECDS-ROOT.crt ConfigMap Mount|1.7. Kubesphere SECDS-ROOT.crt(CA.crt) ConfigMap Mount]]

확인할 것:

- 어떤 상황에서 CA 인증서를 Workload에 제공해야 하는가.
- ConfigMap과 실제 Pod Mount의 관계
- 대상 Namespace·Workload를 확인하는 방법

## 3. 오후 완료 기준

교육생이 세부 화면을 암기할 필요는 없다. 다음이 가능하면 1일차 Manual 가이딩은 완료로 본다.

- [ ] KubeSphere 운영 요청이 들어왔을 때 1.1~1.7 중 어느 문서를 볼지 고를 수 있다.
- [ ] Workspace / Project / Role / Quota 관계를 구분한다.
- [ ] Web UI 접근과 kubectl 접근을 구분한다.

- [ ] 실제값·권한·Secret은 현장에서 다시 확인해야 한다는 원칙을 이해한다.
