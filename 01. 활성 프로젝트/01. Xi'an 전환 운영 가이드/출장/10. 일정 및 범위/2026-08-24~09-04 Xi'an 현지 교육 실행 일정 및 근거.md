# Xi'an DKS Member Cluster 구축 및 운영 기술 전수 계획

> [!important] Source of Truth
> 이 문서는 2026-08-24~09-04 Xi'an 출장의 **일정·날짜별 범위·수행 순서에 대한 최상위 기준**이다. 출장의 다른 현재 문서가 날짜나 범위에서 이 문서와 충돌하면 이 문서를 우선한다. 현장에서 일정이 공식 변경되면 [[출장/40. 현장 준비 및 기록/현장 변경 및 확인사항|현장 변경 및 확인사항]]에 근거를 남긴 뒤 이 문서와 해당 일자 문서를 함께 갱신한다.

> [!important] 일정 운영 원칙
> 교육생의 Kubernetes 사전 지식이 없는 점을 반영하여 **Kubernetes 기초 교육 → 운영 Manual 교육 → 실제 Member Cluster 구축** 순서로 진행한다. 아래 오전·오후 구분은 일정 기준이며, 구축 작업은 실제 진행 상황에 따라 오전 작업이 오후까지 이어질 수 있다.

> [!success] 이번 출장의 구축 범위
> 기존 Xi'an **Host Cluster는 이미 구축 완료된 상태**이며 이번 실습에서 새로 구축하지 않는다. 이번 Cluster Setup의 목표는 **신규 Member Cluster를 구축하고 기존 Host Cluster에 Join하여 Multi-Cluster 상태를 확인하는 것**이다. `5.5.1 Install kubesphere - host cluster`는 배포 Manual에는 존재하지만 이번 출장의 수행 범위에서는 제외한다.

> [!warning] 이전 일정 문서
> `출장/90. 이전본/` 아래의 날짜별 문서와 커리큘럼은 이 일정 확정 전 자료다. 현재 현장 일정 판단에는 사용하지 않는다.

## 3. Cluster Setup 수행 범위

이번 구축은 다음 한 흐름으로 본다.

```text
신규 Member VM 및 실제 환경 확인
→ 5.0 Initial VM setting
→ 5.1 SCS Bastion node pre-setting
→ 5.2 SCS K8S Cluster nodes pre-settings
→ 5.3 SCS Deploy DKS Cluster using Kubespray
→ 5.4 SCS Install storage components
→ 5.5.2 Install kubesphere - member cluster
→ 기존 Host Cluster Join
→ Multi-Cluster 확인
```

### 수행하지 않는 항목

- **5.5.1 Install kubesphere - host cluster**: 기존 Host가 이미 구성되어 있으므로 이번 신규 구축 대상이 아니다.
- 기존 Host의 재설치·재구성: 필요 시 정상 상태와 접근, Join 대상만 확인한다.
- 기존 PRD·DEV Member 재설치: 현재 환경은 정상 비교 및 운영 교육에 사용한다.
- 9/4 신규 기술 작업: 철수일이며 기술 Buffer로 사용하지 않는다.

## 5. 운영 Manual 기술 전수 방식

운영 교육의 목적은 모든 세부 명령과 화면을 암기시키는 것이 아니라 **배포된 Manual의 메뉴 구조, 사용 시점, 대표 절차, 정상 확인 지점, 변경 경계와 장애 첫 분기를 인계하는 것**이다.

- **8/26 오후:** `1. KubeSphere Operation`
- **8/27 오전:** `2. Operations Manual`
- **8/27 오후:** `3. Harbor Manual`
- **8/28 오전:** `4. User Manual`
- **8/28 오후:** `6. Troubleshooting Guide` + 운영 교육 Q&A

각 문서에서는 다음을 확인한다.

1. 이 문서는 어떤 요청·상황에서 사용하는가.
2. 시작 전에 대상과 무엇을 확인해야 하는가.
3. 핵심 절차는 어디에 있는가.
4. 완료 또는 정상 상태를 무엇으로 확인하는가.
5. 한 상태를 전체 성공으로 과잉 판정하지 않는가.
6. 실제값·권한·민감정보는 어디서 다시 확인해야 하는가.
7. 어디에서 작업을 중단하거나 다른 담당 영역으로 넘겨야 하는가.
8. 조치 후 같은 정상 경로를 어떻게 재검증하는가.

## 7. 일정 변동 시 기준

- 구축 단계는 실제 진행 상황에 따라 오전·오후 경계를 유동적으로 사용한다.
- 각 단계의 선행조건과 완료 기준을 충족하지 않은 상태에서 다음 단계로 넘어가지 않는다.
- 단순 시간 지연과 공식 일정 변경을 구분한다.
- 공식 변경은 [[출장/40. 현장 준비 및 기록/현장 변경 및 확인사항|현장 변경 및 확인사항]]에 근거·영향·결정자를 기록한다.
- 기술적인 최종 완료 조건은 **9/3 신규 Member 구축, 기존 Host Join 및 Multi-Cluster 확인**이다.
- **9/4는 철수일이므로 기술 작업 Buffer로 사용하지 않는다.**
- 9/3까지 Blocker가 남으면 실패를 숨기거나 9/4에 강행하지 않고 PASS / PARTIAL / BLOCKED로 판정하여 인계한다.
