# KubeSphere 证书更新时用户 kubectl kubeconfig 处理指南

## 1. 证书更新类型及影响评估

证书更新时对 Bastion 用户账号的 kubeconfig 影响按下表基准进行评估与判断。

| 更新作业类型 | Root CA 变更与否 | 用户环境影响 | 运维团队作业内容 |
|---|:---:|:---:|---|
| **控制平面定期更新** (kubeadm certs renew all) | **无变更** | **无影响** | **无单独作业**。既有配置的用户 kubeconfig 在自身有效期内正常保持可用 |
| **个别用户证书到期** (1年周期到期) | 不适用 | **仅限该账号单件** | **运维团队单件更新**。从 KubeSphere ConfigMap 提取最新配置后重新部署至该用户账号 |
| **Kubernetes Root CA 更换** (10年周期等) | **新颁发更换** | **影响全部账号** | **运维团队统一全量更新**。对 Bastion 内全部用户 kubeconfig 统一批量重新部署 |

---

## 2. 各场景详细处理基准

### 2-1. 常规控制平面证书更新

在 Master 节点执行 kubeadm certs renew all 命令，仅更新 API Server、Controller Manager、Scheduler 等组件证书的情况。

由于集群 Root CA (/etc/kubernetes/ssl/ca.crt) 保持原样不变，运维团队此前在 Bastion 用户账号中配置的既有 Client Certificate 在自身有效期内依然正常可用。

### 2-2. 个别用户证书到期时

特定用户的 Client Certificate 有效期到期的情况。

运维团队在 kubesphere-controls-system 命名空间中确认该用户的 ConfigMap (kubeconfig-<AD账号>)，提取更新后的配置内容，并重新覆盖配置到该用户的 ~/.kube/config 文件中。

### 2-3. Kubernetes Root CA 自行更换时

集群 Root CA 自身到期的情况，必须按照新 Root CA 基准对 Bastion 内所有用户账号的 kubeconfig 重新全量同步并部署。

---

## 3. 正常运行验证要领

控制平面证书更新完成后，如需抽样确认是否对普通用户产生影响，登录任意 1 个用户账号执行基础查询命令确认通信状态即可。

```console
[dsjl32783.id@xadksbtmp01 ~]$ kubectl get pods
NAME                          READY   STATUS    RESTARTS   AGE
nginx-test-6f7c8d9b6d-7k2pm   1/1     Running   0          5d

[dsjl32783.id@xadksbtmp01 ~]$ kubectl auth can-i create deployments
yes
```
