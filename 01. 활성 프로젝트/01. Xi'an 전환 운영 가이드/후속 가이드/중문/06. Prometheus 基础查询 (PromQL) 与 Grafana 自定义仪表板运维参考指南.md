## 1. PromQL 概念及标签过滤

Prometheus 指标根据采集特性分为计数器 (Counter) 与计量器 (Gauge) 两种类型。

| 数据类型 | 运行特性 |
|---|---|
| **Counter** | 持续单调递增的累计数值 (重启时重置为 0) |
| **Gauge** | 当前时刻的增减状态值 (温度、当前内存占用等) |

标签过滤及正则表达式匹配语法：

```promql
# 特定标签完全匹配
up{job="node-exporter"}

# 排除特定字符串
up{job!="node-exporter"}

# 正则表达式包含匹配 (=~)
container_memory_working_set_bytes{namespace=~"default|kube-system"}

# 正则表达式排除匹配 (!~)
node_network_receive_bytes_total{device!~"lo|cali.*|veth.*"}
```

## 2. 按主题划分的基础 PromQL

### 2-1. 目标与节点健康检查 (Target & Node Health)

```promql
# 1. 全部采集目标存活状态 (1: 正常采集, 0: 采集失败)
up

# 2. Node Exporter 采集目标状态确认
up{job="node-exporter"}

# 3. Kube-State-Metrics 采集目标状态确认
up{job="kube-state-metrics"}

# 4. 集群处于正常(Ready)状态的节点列表
kube_node_status_condition{condition="Ready", status="true"} == 1

# 5. 集群处于异常(NotReady)状态的节点列表
kube_node_status_condition{condition="Ready", status!="true"} == 1
```

### 2-2. 节点基础架构 (Node)

```promql
# 1. 节点各模式每秒 CPU 使用时间
rate(node_cpu_seconds_total[5m])

# 2. 节点 CPU 空闲(Idle)状态每秒增长率
rate(node_cpu_seconds_total{mode="idle"}[5m])

# 3. 节点 I/O 等待(iowait)状态每秒增长率
rate(node_cpu_seconds_total{mode="iowait"}[5m])

# 4. 节点实际可用内存 (Bytes)
node_memory_MemAvailable_bytes

# 5. 节点全部物理内存 (Bytes)
node_memory_MemTotal_bytes

# 6. 根目录(/)文件系统剩余磁盘空间 (Bytes)
node_filesystem_free_bytes{mountpoint="/"}

# 7. 根目录(/)文件系统全部磁盘空间 (Bytes)
node_filesystem_size_bytes{mountpoint="/"}

# 8. 节点网络接收(RX)流量 (每秒字节数)
rate(node_network_receive_bytes_total[5m])

# 9. 节点网络发送(TX)流量 (每秒字节数)
rate(node_network_transmit_bytes_total[5m])
```

### 2-3. Pod 与工作负载 (Pod & Container)

```promql
# 1. 各容器每秒 CPU 使用时间 (核心消耗量)
rate(container_cpu_usage_seconds_total{container!=""}[5m])

# 2. 按 Pod 汇总的 CPU 使用时间总和
sum by (namespace, pod) (rate(container_cpu_usage_seconds_total{container!=""}[5m]))

# 3. 容器实际内存占用量 (Working Set, Bytes)
container_memory_working_set_bytes{container!=""}

# 4. 按 Pod 汇总的内存占用量总和
sum by (namespace, pod) (container_memory_working_set_bytes{container!=""})

# 5. Pod 的 CPU Limit 设置值
kube_pod_container_resource_limits{resource="cpu"}

# 6. Pod 的 Memory Limit 设置值
kube_pod_container_resource_limits{resource="memory"}

# 7. Pod 重启(Restart)累计次数
kube_pod_container_status_restarts_total

# 8. Pod 当前运行阶段状态 (Running, Pending, Failed 等)
kube_pod_status_phase == 1
```

### 2-4. Ingress 与网络

```promql
# 1. Ingress NGINX 全部每秒 HTTP 请求处理吞吐量 (RPS)
rate(nginx_ingress_controller_requests[5m])

# 2. 按 Ingress 汇总的每秒 HTTP 请求数总和
sum by (ingress) (rate(nginx_ingress_controller_requests[5m]))

# 3. 按 HTTP 响应状态码汇总的请求数总和
sum by (status) (rate(nginx_ingress_controller_requests[5m]))

# 4. Ingress NGINX 当前活跃连接数
nginx_ingress_controller_nginx_process_connections{state="active"}

# 5. Ingress 响应延迟直方图 Bucket 分布
rate(nginx_ingress_controller_request_duration_seconds_bucket[5m])

# 6. Ingress 响应数据传输流量 (每秒字节数)
rate(nginx_ingress_controller_response_size_bytes_sum[5m])
```

### 2-5. 存储卷 (PVC)

```promql
# 1. 各 PVC 存储卷实际已用空间 (Bytes)
kubelet_volume_stats_used_bytes

# 2. 各 PVC 存储卷总容量 (Bytes)
kubelet_volume_stats_capacity_bytes

# 3. 各 PVC 存储卷剩余可用空间 (Bytes)
kubelet_volume_stats_available_bytes

# 4. PVC 当前绑定状态确认 (Bound, Pending, Lost)
kube_persistentvolumeclaim_status_phase == 1
```

## 3. Grafana 基础配置与访问

### 3-1. 环境访问信息

- **环境 FQDN**: grafana.xaprdpa01.apps.dks.samsungds.net
- **默认管理员 ID**: admin
- 在 Bastion(xadksbtmp01) 节点查询管理员密码：

```bash
kubectl get secret -n monitoring grafana -o jsonpath='{.data.admin-password}' | base64 -d
```

### 3-2. Prometheus 数据源 (Datasource) 连接确认

在 Grafana 左侧导航栏底部 Configuration (齿轮图标) → Data sources 菜单中检查 prometheus 配置：

| 配置项 | 配置值 | 说明 |
|---|---|---|
| **Name** | prometheus | 默认数据源名称 |
| **Type** | Prometheus | 数据源类型 |
| **URL** | http://prometheus-k8s.monitoring.svc:9090 | 集群内部服务域名 |
| **Access** | Server (default) | 后端代理模式 |

点击底部的 **Save & test** 按钮，必须显示 `Data source is working` 正常提示。

## 4. 模板变量 (Variables) 配置

首先在 Dashboards → New Dashboard 中创建新的仪表板。

以下示例已在 https://grafana.xaprdpa01.apps.dks.samsungds.net/dashboards 中作为 test dashboard 预先配置完成。

接着在右上角齿轮图标 (Dashboard settings) 的 Variables 菜单中依次创建命名空间 (namespace) 和容器组 (pod) 变量：

### 步骤 1: $namespace 变量
- Name: namespace
- Type: Query
- Data source: 已连接的 Prometheus
- Refresh: On Dashboard Load
- Selection Options: 勾选 Multi-value, 勾选 Include All option, Custom all value 输入 `.*`
- 变量查询语句 (Query):
```promql
label_values(kube_pod_info, namespace)
```

### 步骤 2: $pod 变量
- Name: pod
- Type: Query
- Data source: 已连接的 Prometheus
- Refresh: On Dashboard Load
- Selection Options: 勾选 Multi-value, 勾选 Include All option, Custom all value 输入 `.*`
- 变量查询语句 (Query):
```promql
label_values(kube_pod_info{namespace=~"${namespace:regex}"}, pod)
```

## 5. 运维面板实现示例

### 采集目标故障监控 (Scrape Targets Down)
- Visualization: Stat
- Query Type: Instant
- Unit: Short
- Thresholds: Base 为绿色 (0), 1 以上设为红色 (Red)
- PromQL 查询式:
```promql
# 采集失败目标数汇总 (正常时返回 0)
sum(up == 0) or vector(0)
```

### 各 Pod 实时 CPU 使用核数 (Pod CPU Usage)
- Visualization: Time series
- Unit: Cores (或 Short)
- Legend: namespace / pod
- 特性: 调整时间范围时使用 $__rate_interval 实现自适应分辨率匹配
- PromQL 查询式:
```promql
# 各 Pod 实时 CPU 核心使用量趋势 ($__rate_interval 自动自适应匹配)
sum by (namespace, pod) (
  rate(container_cpu_usage_seconds_total{
    namespace=~"${namespace:regex}",
    pod=~"${pod:regex}",
    container!="",
    container!="POD"
  }[$__rate_interval])
)
```

### 各 Pod 实际工作集内存占用量 (Pod Working Set Memory)
- Visualization: Time series
- Unit: Data > bytes (IEC) 指定 (自动转换为 KiB, MiB, GiB)
- Legend: namespace / pod
- PromQL 查询式:
```promql
# 各 Pod 工作集内存占用量汇总
sum by (namespace, pod) (
  container_memory_working_set_bytes{
    namespace=~"${namespace:regex}",
    pod=~"${pod:regex}",
    container!="",
    container!="POD"
  }
)
```
