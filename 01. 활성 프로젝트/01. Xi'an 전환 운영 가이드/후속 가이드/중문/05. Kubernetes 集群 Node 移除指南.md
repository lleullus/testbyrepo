# Kubernetes 集群 Node 移除指南

## Index

本流程用于因硬件检修、资源优化或节点更换等原因，从现有 Kubernetes 集群中安全移除特定 Worker 节点（例如：xadkswkmp04）。为确保运行中的工作负载（Pod）不发生中断，需在切断流量并完成驱逐（Drain）后再将节点从集群中分离。

作业按以下顺序进行：

1. **移除节点前工作负载及 NetApp 卷挂载检查**
2. **停止目标节点的新 Pod 调度 (kubectl cordon)**
3. **安全驱逐运行中的 Pod (kubectl drain)**
4. **执行 Kubespray remove-node.yml 及删除集群节点**
5. **清理 Kubespray hosts.yaml Inventory**
6. **移除后集群状态及系统 Pod 正常运行验证**
7. **紧急取消及恢复 (kubectl uncordon)**

---

## 1. 移除节点前工作负载及 NetApp 卷挂载检查

在移除目标节点（例如：xadkswkmp04, 109.156.22.64）前，预先确认正在运行的 Pod、StatefulSet 以及 PVC 连接状态。

在 Bastion (xadksbtmp01) 上执行：

```console
[dspaas@xadksbtmp01 ~]$ kubectl get node xadkswkmp04 -o wide
NAME          STATUS   ROLES   AGE    VERSION    INTERNAL-IP     OS-IMAGE                KERNEL-VERSION           CONTAINER-RUNTIME
xadkswkmp04   Ready    node    60d    v1.22.10   109.156.22.64   CentOS Linux 7 (Core)   3.10.0-1160.el7.x86_64   containerd://1.6.4

[dspaas@xadksbtmp01 ~]$ kubectl get pods -A -o wide --field-selector spec.nodeName=xadkswkmp04
NAMESPACE              NAME                          READY   STATUS    RESTARTS   AGE   IP               NODE
hello-kubesphere-dev   nginx-test-6f7c8d9b6d-7k2pm   1/1     Running   0          4d    10.233.112.45    xadkswkmp04
kube-system            calico-node-8k4px             1/1     Running   0          60d   109.156.22.64    xadkswkmp04
kube-system            nodelocaldns-9z8qw            1/1     Running   0          60d   10.233.112.1     xadkswkmp04
trident                trident-node-linux-v2p4k      2/2     Running   0          60d   109.156.22.64    xadkswkmp04
```

确认除 DaemonSet (calico-node, nodelocaldns, trident-node-linux) 外，还存在普通的 Deployment Pod (nginx-test)。

---

## 2. 停止目标节点的新 Pod 调度 (kubectl cordon)

将目标节点设置为 SchedulingDisabled 状态，阻止新 Pod 被调度至该节点。

```console
[dspaas@xadksbtmp01 ~]$ kubectl cordon xadkswkmp04
node/xadkswkmp04 cordoned

[dspaas@xadksbtmp01 ~]$ kubectl get node xadkswkmp04
NAME          STATUS                     ROLES   AGE   VERSION
xadkswkmp04   Ready,SchedulingDisabled   node    60d   v1.22.10
```

---

## 3. 安全驱逐运行中的 Pod (kubectl drain)

安全终止在该节点上运行的应用程序 Pod，并重新调度至其他正常的 Worker 节点。

### 3-1. 执行 Drain 命令

```console
[dspaas@xadksbtmp01 ~]$ kubectl drain xadkswkmp04 --delete-emptydir-data --ignore-daemonsets --force
node/xadkswkmp04 already cordoned
WARNING: ignoring DaemonSet-managed Pods: kube-system/calico-node-8k4px, kube-system/nodelocaldns-9z8qw, trident/trident-node-linux-v2p4k
evicting pod hello-kubesphere-dev/nginx-test-6f7c8d9b6d-7k2pm
pod/nginx-test-6f7c8d9b6d-7k2pm evicted
node/xadkswkmp04 drained
```

### 3-2. 驱逐结果及工作负载重新分布验证

```console
[dspaas@xadksbtmp01 ~]$ kubectl get pods -A -o wide --field-selector spec.nodeName=xadkswkmp04
NAMESPACE     NAME                       READY   STATUS    RESTARTS   AGE   IP              NODE
kube-system   calico-node-8k4px          1/1     Running   0          60d   109.156.22.64   xadkswkmp04
kube-system   nodelocaldns-9z8qw         1/1     Running   0          60d   10.233.112.1    xadkswkmp04
trident       trident-node-linux-v2p4k   2/2     Running   0          60d   109.156.22.64   xadkswkmp04

[dspaas@xadksbtmp01 ~]$ kubectl get pod -n hello-kubesphere-dev -o wide
NAME                          READY   STATUS    RESTARTS   AGE   IP              NODE
nginx-test-6f7c8d9b6d-m9v4l   1/1     Running   0          45s   10.233.98.112   xadkswkmp03
```

确认应用程序 Pod 已成功迁移至 xadkswkmp03 节点并正常运行。

---

## 4. 执行 Kubespray remove-node.yml 及删除集群节点

执行 Kubespray Playbook 以彻底分离节点，或进行手动删除及重置。

### 4-1. 通过 Kubespray Playbook 移除

```console
[dspaas@xadksbtmp01 ~]$ cd /app/dspaas/SCS_DKS_Kubernetes_Stack-v1.0/20.kubespray-release-2.19
[dspaas@xadksbtmp01 20.kubespray-release-2.19]$ ansible-playbook -e @inventory/dks/dks_vars.yml -i inventory/dks/hosts.yaml --become --become-user=root remove-node.yml -e node=xadkswkmp04

PLAY [Check if target node is valid] ***********************************************************************************
ok: [localhost]

PLAY [Remove node from cluster] ****************************************************************************************
changed: [xadksbtmp01 -> 109.156.22.58]
...
PLAY RECAP *************************************************************************************************************
localhost                  : ok=3    changed=0    unreachable=0    failed=0    skipped=0    rescued=0    ignored=0
xadkswkmp04                : ok=18   changed=5    unreachable=0    failed=0    skipped=7    rescued=0    ignored=0
```

### 4-2. 执行手动删除（未运行 Playbook 时）

若通过手动方式移除节点，执行 kubectl delete node 并在对应 VM 上停止 Kubelet 及容器。

```console
[dspaas@xadksbtmp01 ~]$ kubectl delete node xadkswkmp04
node "xadkswkmp04" deleted

[dspaas@xadksbtmp01 ~]$ ssh xadkswkmp04
[dspaas@xadkswkmp04 ~]$ sudo systemctl stop kubelet
[dspaas@xadkswkmp04 ~]$ sudo systemctl disable kubelet
[dspaas@xadkswkmp04 ~]$ exit
```

---

## 5. 清理 Kubespray hosts.yaml Inventory

为避免在后续集群扩缩容（scale.yml）或升级操作中再次引用已被移除的节点，需从 inventory/dks/hosts.yaml 文件中删除目标节点定义。

```console
[dspaas@xadksbtmp01 20.kubespray-release-2.19]$ cd inventory/dks
[dspaas@xadksbtmp01 dks]$ cp hosts.yaml hosts.yaml.bak_$(date +%Y%m%d)
[dspaas@xadksbtmp01 dks]$ vi hosts.yaml
```

**需删除的项目**：
1. 从 all.hosts 配置块中删除 xadkswkmp04 节点块
2. 从 kube_node.hosts 配置块中删除 xadkswkmp04 行

**修改后确认**：
```console
[dspaas@xadksbtmp01 dks]$ grep xadkswkmp04 hosts.yaml
[dspaas@xadksbtmp01 dks]$ 
```

确认无任何内容输出。

## 7. 紧急取消及恢复 (kubectl uncordon)

在执行 Drain 过程中，若因工作负载驱逐问题导致需要中止节点移除作业并回滚时，解除调度阻止状态。

```console
[dspaas@xadksbtmp01 ~]$ kubectl uncordon xadkswkmp04
node/xadkswkmp04 uncordoned

[dspaas@xadksbtmp01 ~]$ kubectl get node xadkswkmp04
NAME          STATUS   ROLES   AGE   VERSION
xadkswkmp04   Ready    node    60d   v1.22.10
```
