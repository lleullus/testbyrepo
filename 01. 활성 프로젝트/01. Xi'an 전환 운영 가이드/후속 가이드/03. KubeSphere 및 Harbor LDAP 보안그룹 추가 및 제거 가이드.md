# KubeSphere 및 Harbor LDAP 보안그룹 추가 및 제거 가이드

## Index

Xi'an DKS 환경의 KubeSphere와 Harbor는 사내 Global AD(LDAP)와 연동되어 인증을 처리한다. 프로젝트 투입, 조직 변경, 접근 통제 강화 시 두 시스템의 LDAP 로그인 필터에서 보안그룹(Security Group)을 추가하거나 제거하는 절차이다.

1. **KubeSphere LDAP 보안그룹 추가 및 제거 (ConfigMap)**
   - 1-1. kubesphere-config 사전 백업
   - 1-2. userSearchFilter 수정 전 상태 확인
   - 1-3. 보안그룹 추가 (OR 조건 반영)
   - 1-4. 보안그룹 제거 및 단일화 정리
   - 1-5. ks-apiserver 재시작 및 로그인 검증
2. **Harbor 시스템 전체 인증 LDAP 필터 수정 및 검증**
   - 2-1. Harbor 관리자 인증 설정 메뉴 진입
   - 2-2. LDAP User Filter 수정 전 상태 확인
   - 2-3. LDAP User Filter에 보안그룹 추가 (OR 조건 반영)
   - 2-4. LDAP User Filter에서 보안그룹 제거
   - 2-5. 연결 테스트, 저장 및 Docker CLI 로그인 검증
3. **설정 오류 시 복구 절차**

---

## 1. KubeSphere LDAP 보안그룹 추가 및 제거 (ConfigMap)

KubeSphere의 로그인 필터는 kubesphere-system 네임스페이스의 kubesphere-config ConfigMap 내 userSearchFilter 속성에서 관리한다.

### 1-1. kubesphere-config 사전 백업

Bastion(xadksbtmp01)에서 작업 전 설정을 백업한다.

```console
[dspaas@xadksbtmp01 ~]$ mkdir -p /tmp/ldap-backup && cd /tmp/ldap-backup
[dspaas@xadksbtmp01 ldap-backup]$ kubectl get configmap kubesphere-config -n kubesphere-system -o yaml > kubesphere-config-backup-$(date +%Y%m%d).yaml
[dspaas@xadksbtmp01 ldap-backup]$ ls -l
total 16
-rw-r--r--. 1 dspaas dspaas 14210 Sep  7 12:00 kubesphere-config-backup-20260907.yaml
```

### 1-2. userSearchFilter 수정 전 상태 확인

```console
[dspaas@xadksbtmp01 ldap-backup]$ kubectl get configmap kubesphere-config -n kubesphere-system -o jsonpath='{.data.kubesphere\.yaml}' | grep -A 2 "userSearchFilter:"
      userSearchFilter: (&(objectclass=user)(memberOf=CN=SG1599,OU="Security Groups",OU=Groups,OU=KOR,OU=Locations,DC=samsungds,DC=net))
```

### 1-3. 보안그룹 추가 (OR 조건 반영)

새로운 보안그룹(예: SG1600, SG1590, SG1591)을 추가할 때는 반드시 |(OR) 연산자로 묶어야 한다.

```console
[dspaas@xadksbtmp01 ~]$ kubectl edit configmap kubesphere-config -n kubesphere-system
```

**수정 전**:
```yaml
userSearchFilter: (&(objectclass=user)(memberOf=CN=SG1599,OU="Security Groups",OU=Groups,OU=KOR,OU=Locations,DC=samsungds,DC=net))
```

**수정 후 (SG1600, SG1590, SG1591 추가)**:
```yaml
userSearchFilter: (&(objectclass=user)(|(memberOf=CN=SG1599,OU="Security Groups",OU=Groups,OU=KOR,OU=Locations,DC=samsungds,DC=net)(memberOf=CN=SG1600,OU="Security Groups",OU=Groups,OU=KOR,OU=Locations,DC=samsungds,DC=net)(memberOf=CN=SG1590,OU="Security Groups",OU=Groups,OU=KOR,OU=Locations,DC=samsungds,DC=net)(memberOf=CN=SG1591,OU="Security Groups",OU=Groups,OU=KOR,OU=Locations,DC=samsungds,DC=net)))
```

### 1-4. 보안그룹 제거 및 단일화 정리

특정 그룹(예: SG1590)을 제외할 때는 해당 memberOf 라인만 삭제한다. 최종적으로 1개 그룹만 남을 경우 | 연산자를 풀고 단일 조건으로 정리한다.

```yaml
userSearchFilter: (&(objectclass=user)(memberOf=CN=SG1599,OU="Security Groups",OU=Groups,OU=KOR,OU=Locations,DC=samsungds,DC=net))
```

### 1-5. ks-apiserver 재시작 및 로그인 검증

ConfigMap 수정 후 ks-apiserver를 재시작해야 새 필터가 적용된다.

```console
[dspaas@xadksbtmp01 ~]$ kubectl rollout restart deployment ks-apiserver -n kubesphere-system
deployment.apps/ks-apiserver restarted

[dspaas@xadksbtmp01 ~]$ kubectl rollout status deployment ks-apiserver -n kubesphere-system
deployment "ks-apiserver" successfully rolled out
```

- 추가된 그룹 소속 계정: KubeSphere 콘솔(https://xa.ks.dks.samsungds.net/) 로그인 성공
- 제거된 그룹 소속 계정: 로그인 실패 확인

## 2. Harbor 시스템 전체 인증 LDAP 필터 수정 및 검증

Harbor 역시 시스템 전체 로그인 인증(Authentication) 설정에서 **LDAP User Filter**를 수정하여 로그인 가능한 사내 보안그룹을 제어한다.

### 2-1. Harbor 관리자 인증 설정 메뉴 진입

1. Harbor 관리자(admin) 계정으로 웹 콘솔(https://xa.dcr.dks.samsungds.net/)에 로그인한다.
2. 좌측 메뉴에서 **Administration** (관리) -> **Configuration** (설정)을 클릭한다.
3. 상단 탭에서 **Authentication** (인증) 메뉴를 선택한다.
4. Auth Mode가 **LDAP**으로 설정되어 있는지 확인하고, 하단의 **LDAP User Filter** 입력란으로 이동한다.

### 2-2. LDAP User Filter 수정 전 상태 확인

현재 Harbor의 LDAP User Filter 필드에 등록된 기존 필터 문자열을 확인한다.

**수정 전 (기본 상태)**:
```text
(&(objectclass=user)(memberOf=CN=SG1599,OU="Security Groups",OU=Groups,OU=KOR,OU=Locations,DC=samsungds,DC=net))
```

### 2-3. LDAP User Filter에 보안그룹 추가 (OR 조건 반영)

새로운 보안그룹(예: SG1600, SG1590, SG1591)을 추가할 경우, KubeSphere와 동일하게 |(memberOf=...)(memberOf=...) 형태로 OR 묶음을 구성하여 **LDAP User Filter** 입력란에 직접 입력한다.

**수정 후 (SG1600, SG1590, SG1591 추가)**:
```text
(&(objectclass=user)(|(memberOf=CN=SG1599,OU="Security Groups",OU=Groups,OU=KOR,OU=Locations,DC=samsungds,DC=net)(memberOf=CN=SG1600,OU="Security Groups",OU=Groups,OU=KOR,OU=Locations,DC=samsungds,DC=net)(memberOf=CN=SG1590,OU="Security Groups",OU=Groups,OU=KOR,OU=Locations,DC=samsungds,DC=net)(memberOf=CN=SG1591,OU="Security Groups",OU=Groups,OU=KOR,OU=Locations,DC=samsungds,DC=net)))
```

### 2-4. LDAP User Filter에서 보안그룹 제거

보안 통제 또는 프로젝트 종료로 특정 보안그룹(예: SG1590)을 제거할 경우, **LDAP User Filter** 필드에서 해당 그룹 조건만 삭제한다.

**제거 후**:
```text
(&(objectclass=user)(|(memberOf=CN=SG1599,OU="Security Groups",OU=Groups,OU=KOR,OU=Locations,DC=samsungds,DC=net)(memberOf=CN=SG1600,OU="Security Groups",OU=Groups,OU=KOR,OU=Locations,DC=samsungds,DC=net)(memberOf=CN=SG1591,OU="Security Groups",OU=Groups,OU=KOR,OU=Locations,DC=samsungds,DC=net)))
```

### 2-5. 연결 테스트, 저장 및 Docker CLI 로그인 검증

1. 필터 문자열 수정 후, 화면 하단의 **TEST LDAP SERVER** 버튼을 클릭한다.
2. "The connection to the LDAP server is successful." 알림 팝업이 뜨는지 확인한다.
3. 연결 성공 확인 후 하단의 **SAVE** 버튼을 클릭하여 Harbor 시스템에 즉시 반영한다. (Harbor 재시작 불필요, 즉시 적용)

#### 로그인 검증 (Docker CLI 및 Web)

새로 추가된 그룹(SG1600) 소속 계정으로 Docker CLI 로그인을 검증한다.

```console
[root@user-host ~]# sudo docker login xa.dcr.dks.samsungds.net
Username: dsjl32783.id
Password: 
Login Succeeded
```

제거된 그룹(SG1590) 전용 계정 또는 비인가 그룹 계정으로 로그인 시 차단되는지 확인한다.

```console
[root@user-host ~]# sudo docker login xa.dcr.dks.samsungds.net
Username: dshl99999.id
Password: 
Error response from daemon: Get "https://xa.dcr.dks.samsungds.net/v2/": unauthorized: incorrect username or password
```

## 3. 설정 오류 시 복구 절차

### 3-1. KubeSphere 복구

KubeSphere ConfigMap 문법 오류 발생 시 백업본을 다시 적용한다.

```console
[dspaas@xadksbtmp01 ~]$ cd /tmp/ldap-backup
[dspaas@xadksbtmp01 ldap-backup]$ kubectl apply -f kubesphere-config-backup-20260907.yaml
configmap/kubesphere-config configured

[dspaas@xadksbtmp01 ldap-backup]$ kubectl rollout restart deployment ks-apiserver -n kubesphere-system
deployment.apps/ks-apiserver restarted
```

### 3-2. Harbor 복구

Harbor 관리자(admin 로컬 계정)로 웹 콘솔에 접속하여 **Administration -> Configuration -> Authentication** 메뉴의 **LDAP User Filter** 항목에 기존 정상 필터 문자열을 복원 입력한 후 **SAVE**를 클릭한다.
