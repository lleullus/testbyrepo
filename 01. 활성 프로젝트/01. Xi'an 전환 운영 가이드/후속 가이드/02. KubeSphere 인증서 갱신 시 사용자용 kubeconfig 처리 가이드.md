# KubeSphere 인증서 갱신 시 사용자용 kubeconfig 처리 가이드

## 1. 인증서 갱신 유형별 영향도 판정

인증서 갱신 시 Bastion 사용자 계정의 kubeconfig에 미치는 영향은 아래 기준으로 판단한다.

| 갱신 작업 유형 | Root CA 변경 여부 | 사용자 환경 영향 | 운영팀 작업 내용 |
|---|:---:|:---:|---|
| **Control Plane 정기 갱신** (kubeadm certs renew all) | **변경 없음** | **영향 없음** | **별도 작업 없음**. 기존에 세팅된 사용자 kubeconfig는 자체 만료일까지 정상 동작함 |
| **개별 사용자 인증서 만료** (1년 주기 도래) | 해당 없음 | **해당 계정 단건** | **운영팀 단건 갱신**. KubeSphere ConfigMap에서 추출 후 해당 사용자 계정에 재반영 |
| **Kubernetes Root CA 교체** (10년 주기 등) | **신규 교체** | **전체 계정 영향** | **운영팀 전체 일괄 갱신**. Bastion 내 전체 사용자 kubeconfig 일괄 재배포 |

---

## 2. 상황별 세부 처리 기준

### 2-1. 일반 Control Plane 인증서 갱신

Master 노드에서 kubeadm certs renew all을 실행해 API Server, Controller Manager, Scheduler 등의 인증서만 갱신한 경우이다. 

클러스터 Root CA(/etc/kubernetes/ssl/ca.crt)가 그대로 유지되므로, 운영팀이 이전에 Bastion 사용자 계정에 세팅해 둔 기존 Client Certificate도 유효기간 동안 정상 동작한다.

### 2-2. 개별 사용자 인증서 만료 시

운영팀에서 kubesphere-controls-system 네임스페이스의 사용자 ConfigMap(kubeconfig-<AD계정>)을 확인하여 갱신된 설정을 추출한 뒤 해당 사용자의 ~/.kube/config 파일로 재배치한다.

### 2-3. Kubernetes Root CA 자체 교체 시

클러스터 Root CA 자체가 만료되는 경우 Bastion 내 모든 사용자 계정의 kubeconfig를 신규 CA 기준으로 다시 반영해야 한다.

## 3. 정상 동작 검증 요령

Control Plane 인증서 갱신 완료 후 사용자 영향 여부를 확인하려면, 임의의 사용자 계정 1곳에서 기본 조회 명령으로 통신 상태만 확인한다.

```console
[dsjl32783.id@xadksbtmp01 ~]$ kubectl get pods
NAME                          READY   STATUS    RESTARTS   AGE
nginx-test-6f7c8d9b6d-7k2pm   1/1     Running   0          5d

[dsjl32783.id@xadksbtmp01 ~]$ kubectl auth can-i create deployments
yes
```
