# Operations Guide Korean Translation and Repository Modernization Guide

## Index

Early Xi'an DKS infrastructure guides were primarily written in English and Chinese, and internal repository URLs (Nexus → internal Artifactory), Harbor image registry FQDNs, and Kubespray package paths were documented with legacy temporary paths. This document consolidates these into modernized Xi'an standards and provides a Korean operational procedure ready for field execution.

The procedure is performed in the following order:

1. **Verify and modernize internal YUM repository (Artifactory) configurations**
2. **Modernize Harbor image registry repository paths**
3. **Normalize Kubespray and deployment package directory paths**
4. **Validate offline installation binary download paths**
5. **Verify latest repository references during Worker node expansion**

---

## 1. Verifying and Modernizing Internal YUM Repository (Artifactory) Configurations

The legacy temporary Nexus path (`nexus.adpaas.cloud.samsungds.net`) mentioned in older guides has been decommissioned. The environment now uses dedicated internal YUM mirrors or Artifactory.

### 1-1. Checking Bastion and Node YUM Repository Files

Inspect `/etc/yum.repos.d/` directory configurations on the Bastion (`xadksbtmp01`) and Master/Worker nodes.

```console
[dspaas@xadksbtmp01 ~]$ ls -l /etc/yum.repos.d/
total 16
-rw-r--r--. 1 root root  820 Jun 19 04:00 dks-base.repo
-rw-r--r--. 1 root root  910 Jun 19 04:00 dks-docker.repo
-rw-r--r--. 1 root root  780 Jun 19 04:00 dks-kubernetes.repo

[dspaas@xadksbtmp01 ~]$ cat /etc/yum.repos.d/dks-base.repo
[dks-base]
name=DKS Base Repository
baseurl=http://repo.dks.samsungds.net/repository/centos-7-base/
enabled=1
gpgcheck=0
```

## 2. Modernizing Harbor Image Registry Repository Paths

The `dspaas-testrepo` or `dks-test` namespaces used in older guides and early test environments have been updated to official production namespaces.

### 2-1. Harbor Image Path Mapping

| Usage | Legacy Guide Notation | Xi'an Production Standard Path |
|---|---|---|
| **Default Nginx Test Image** | `xa.dcr.dks.samsungds.net/dspaas-testrepo/nginx:latest` | `xa.dcr.dks.samsungds.net/dspaas-v1.22.10-a/nginx:1.14.2` |
| **KubeSphere Installer Image** | `harbor.adpaas.cloud/...` | `xa.dcr.dks.samsungds.net/kubesphere/ks-installer:v3.3.0` |
| **Calico CNI Image** | `calico/cni:v3.21.4` | `xa.dcr.dks.samsungds.net/calico/cni:v3.21.4` |

## 4. Validating Offline Installation Binary Download Paths

Verify that Docker and utility packages required for new Worker node installation in closed-network environments can be downloaded normally from internal mirrors.

```console
[dspaas@xadksbtmp01 ~]$ curl -sk -o /dev/null -w "%{http_code}\n" http://repo.dks.samsungds.net/repository/files/docker-compose
200

[dspaas@xadksbtmp01 ~]$ curl -sk -o /dev/null -w "%{http_code}\n" http://repo.dks.samsungds.net/repository/files/harbor-offline-installer-v2.2.2.tgz
200
```

Confirm that `200 OK` is returned.
