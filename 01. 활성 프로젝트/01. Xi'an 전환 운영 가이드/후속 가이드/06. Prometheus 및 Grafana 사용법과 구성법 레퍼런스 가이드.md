## 1. PromQL 개념 및 라벨 필터링

Prometheus 메트릭은 수집 특성에 따라 카운터(Counter)와 게이지(Gauge) 두 가지로 나뉩니다.

| 데이터 타입 | 동작 특성 |
|---|---|
| **Counter** | 지속해서 증가하는 누적 수치 (재기동 시 0으로 리셋) |
| **Gauge** | 현재 시점의 증감 상태값 (온도, 현재 메모리 등) |

라벨 필터링 및 정규식 매칭 문법:

```promql
# 특정 라벨 완전 일치
up{job="node-exporter"}

# 특정 문자열 제외
up{job!="node-exporter"}

# 정규식 일치 매칭 (=~)
container_memory_working_set_bytes{namespace=~"default|kube-system"}

# 정규식 제외 매칭 (!~)
node_network_receive_bytes_total{device!~"lo|cali.*|veth.*"}
```

## 2. 주제별 기본 PromQL

### 2-1. 타깃 및 노드 헬스체크 (Target & Node Health)

```promql
# 1. 전체 수집 타깃 생존 여부 (1: 정상, 0: 수집 실패)
up

# 2. Node Exporter 수집 타깃 상태 확인
up{job="node-exporter"}

# 3. Kube-State-Metrics 수집 타깃 상태 확인
up{job="kube-state-metrics"}

# 4. 클러스터 정상(Ready) 상태인 노드 목록
kube_node_status_condition{condition="Ready", status="true"} == 1

# 5. 클러스터 비정상(NotReady) 상태인 노드 목록
kube_node_status_condition{condition="Ready", status!="true"} == 1
```

### 2-2. 노드(Node) 인프라

```promql
# 1. 노드 모드별 초당 CPU 사용 시간
rate(node_cpu_seconds_total[5m])

# 2. 노드별 CPU 유휴(Idle) 상태 초당 증가율
rate(node_cpu_seconds_total{mode="idle"}[5m])

# 3. 노드별 I/O 대기(iowait) 상태 초당 증가율
rate(node_cpu_seconds_total{mode="iowait"}[5m])

# 4. 노드 실제 가용 메모리 (Bytes)
node_memory_MemAvailable_bytes

# 5. 노드 전체 물리 메모리 (Bytes)
node_memory_MemTotal_bytes

# 6. 루트(/) 파일시스템 남은 디스크 용량 (Bytes)
node_filesystem_free_bytes{mountpoint="/"}

# 7. 루트(/) 파일시스템 전체 디스크 용량 (Bytes)
node_filesystem_size_bytes{mountpoint="/"}

# 8. 노드 네트워크 수신(RX) 트래픽 (초당 바이트)
rate(node_network_receive_bytes_total[5m])

# 9. 노드 네트워크 송신(TX) 트래픽 (초당 바이트)
rate(node_network_transmit_bytes_total[5m])
```

### 2-3. 파드 및 워크로드(Pod & Container)

```promql
# 1. 컨테이너별 초당 CPU 사용 시간 (코어 사용량)
rate(container_cpu_usage_seconds_total{container!=""}[5m])

# 2. 파드별 CPU 사용 시간 합산
sum by (namespace, pod) (rate(container_cpu_usage_seconds_total{container!=""}[5m]))

# 3. 컨테이너 실제 메모리 점유량 (Working Set, Bytes)
container_memory_working_set_bytes{container!=""}

# 4. 파드별 메모리 점유량 합산
sum by (namespace, pod) (container_memory_working_set_bytes{container!=""})

# 5. 파드별 CPU Limit 설정값
kube_pod_container_resource_limits{resource="cpu"}

# 6. 파드별 Memory Limit 설정값
kube_pod_container_resource_limits{resource="memory"}

# 7. 파드 재기동(Restart) 누적 횟수
kube_pod_container_status_restarts_total

# 8. 파드 현재 상태(Phase) 확인 (Running, Pending, Failed 등)
kube_pod_status_phase == 1
```

### 2-4. 인그레스(Ingress) 및 네트워크

```promql
# 1. Ingress NGINX 전체 초당 HTTP 요청 처리량 (RPS)
rate(nginx_ingress_controller_requests[5m])

# 2. 인그레스별 초당 HTTP 요청 수 합산
sum by (ingress) (rate(nginx_ingress_controller_requests[5m]))

# 3. HTTP 응답 상태 코드별 요청 수 합산
sum by (status) (rate(nginx_ingress_controller_requests[5m]))

# 4. Ingress NGINX 현재 활성 커넥션 수
nginx_ingress_controller_nginx_process_connections{state="active"}

# 5. 인그레스 응답 지연시간 히스토그램 버킷
rate(nginx_ingress_controller_request_duration_seconds_bucket[5m])

# 6. 인그레스 응답 데이터 전송량 (초당 바이트)
rate(nginx_ingress_controller_response_size_bytes_sum[5m])
```

### 2-5. 스토리지(PVC)

```promql
# 1. PVC 볼륨별 실제 사용 공간 (Bytes)
kubelet_volume_stats_used_bytes

# 2. PVC 볼륨별 전체 용량 (Bytes)
kubelet_volume_stats_capacity_bytes

# 3. PVC 볼륨별 잔여 가용 공간 (Bytes)
kubelet_volume_stats_available_bytes

# 4. PVC 현재 바인딩 상태 확인 (Bound, Pending, Lost)
kube_persistentvolumeclaim_status_phase == 1
```

## 3. Grafana 기본 구성 및 접속

### 3-1. 환경 접속 정보

- **환경 FQDN**: grafana.xaprdpa01.apps.dks.samsungds.net
- **기본 관리자 ID**: admin
- Bastion(xadksbtmp01)에서 관리자 비밀번호를 조회한다:

```bash
kubectl get secret -n monitoring grafana -o jsonpath='{.data.admin-password}' | base64 -d
```

### 3-2. Prometheus Datasource 연결 확인

Grafana 좌측 사이드바 하단 Configuration(톱니바퀴 아이콘) → Data sources 메뉴에서 prometheus 설정을 확인한다.

| 항목 | 설정값 | 비고 |
|---|---|---|
| **Name** | prometheus | 기본 데이터소스 |
| **Type** | Prometheus | 프로메테우스 타입 |
| **URL** | http://prometheus-k8s.monitoring.svc:9090 | 클러스터 내부 도메인 |
| **Access** | Server (default) | 백엔드 프록시 모드 |

하단의 **Save & test** 버튼을 클릭하여 Data source is working 정상 알림이 출력되어야 합니다.

## 4. 템플릿 변수(Variables) 구성

먼저 Dashboards → New Dashboard에서 새로운 대시보드를 생성합니다.

아래 예시는 https://grafana.xaprdpa01.apps.dks.samsungds.net/dashboards에서 test dashboard로 사전 구성 되어있습니다.

그리고 우측 상단의 톱니바퀴(Dashboard settings)의 Variables 메뉴에서 순서대로 네임스페이스와 파드 변수를 생성합니다.

### 단계 1: $namespace 변수
- Name: namespace
- Type: Query
- Data source: 연결된 Prometheus
- Refresh: On Dashboard Load
- Selection Options: Multi-value 체크, Include All option 체크, Custom all value에 .* 입력
- 변수 쿼리(Query):
```promql
label_values(kube_pod_info, namespace)
```

### 단계 2: $pod 변수
- Name: pod
- Type: Query
- Data source: 연결된 Prometheus
- Refresh: On Dashboard Load
- Selection Options: Multi-value 체크, Include All option 체크, Custom all value에 .* 입력
- 변수 쿼리(Query):
```promql
label_values(kube_pod_info{namespace=~"${namespace:regex}"}, pod)
```

## 5. 운영 패널 구현 예시

### 수집 대상 실패 감시 (Scrape Targets Down)
- Visualization: Stat
- Query Type: Instant
- Unit: Short
- Thresholds: Base는 초록색(0), 1 이상은 빨간색(Red) 지정
- PromQL 질의식:
```promql
# 수집 실패 타깃 수 합산 (정상 시 0 반환)
sum(up == 0) or vector(0)
```

### 파드별 실시간 CPU 사용 코어량 (Pod CPU Usage)
- Visualization: Time series
- Unit: Cores (또는 Short)
- Legend: namespace / pod
- 특징: 시간 범위 변경 시 자동 해상도 대응을 위해 $__rate_interval 사용
- PromQL 질의식:
```promql
# 파드별 실시간 CPU 코어 사용량 추이 ($__rate_interval 자동 해상도 연동)
sum by (namespace, pod) (
  rate(container_cpu_usage_seconds_total{
    namespace=~"${namespace:regex}",
    pod=~"${pod:regex}",
    container!="",
    container!="POD"
  }[$__rate_interval])
)
```

### 파드별 실제 워킹셋 메모리 점유량 (Pod Working Set Memory)
- Visualization: Time series
- Unit: Data > bytes (IEC) 지정 (KiB, MiB, GiB 자동 단위 환산)
- Legend: namespace / pod
- PromQL 질의식:
```promql
# 파드별 워킹셋 메모리 점유량 합산
sum by (namespace, pod) (
  container_memory_working_set_bytes{
    namespace=~"${namespace:regex}",
    pod=~"${pod:regex}",
    container!="",
    container!="POD"
  }
)
```
