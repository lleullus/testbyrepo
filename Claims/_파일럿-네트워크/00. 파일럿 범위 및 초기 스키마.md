# 네트워크 Conditional Claim 파일럿

## 목적

이 파일럿은 주차별 VOC의 운영 답변을 바로 FAQ로 옮기지 않고, **어떤 조건에서 어떤 주소·구성 판단이 성립하는지**를 Claim 단위로 분리할 수 있는지 검증한다.

원본 VOC는 수정하지 않는다. 파일럿 Claim은 기존 가이드나 현재 정책을 대체하지 않으며, 명시한 근거와 관측 시점 안에서만 사용한다.

## 파일럿 질문

> DKS와 외부 시스템 사이의 DNS 등록 또는 방화벽 신청에서 어느 IP를 사용해야 하는가?

이 질문은 하나의 답으로 닫히지 않는다. 파일럿에서는 다음 조건이 답을 실제로 갈라놓는지 확인한다.

- 서비스 모델: DKS-N / DKS-C / 자료에서 미확인
- 통신 방향: 외부 → DKS / DKS → 외부
- 목적: DNS 등록 / HTTP·HTTPS 인바운드 / 외부 DB·API 아웃바운드 / ALB 백엔드 구성
- 노출 지점: 내부 Ingress Service IP / Cluster LB VIP / Worker Node IP 대역 / Egress SNAT IP

## 초기 Claim 스키마

각 파일럿 Claim은 다음 항목을 가진다.

1. **Claim**: 현재 근거에서 정당화하려는 한 문장
2. **적용 조건**: Claim을 적용하기 전에 확인해야 할 조건
3. **근거 사슬**: 원문 사실에서 Claim까지의 추론
4. **근거표**: 원본 파일과 행, Claim과의 관계
5. **말하지 않는 것**: 인접 사례에 잘못 확장하지 않도록 한계 명시
6. **반례·경쟁 설명**: Claim을 깨뜨리거나 범위를 좁힐 수 있는 자료
7. **검증 상태**: 관측된 과거 답변인지, 현재 정책까지 확인했는지 구분

## 파일럿 완료 조건

- 서로 다른 답변을 하나의 문장으로 강제 병합하지 않는다.
- 서비스 모델이나 통신 방향이 자료에 없으면 `unknown`으로 남긴다.
- 최소 하나의 반례 또는 범위 경계 후보를 각 Claim에서 확인한다.
- 현재 정책을 확인하지 않은 Claim은 과거 관측 사실과 현재 지침을 구분한다.
- 완결성 점검 후 살아남은 필드만 전체 VOC 적용 설계에 반영한다.
