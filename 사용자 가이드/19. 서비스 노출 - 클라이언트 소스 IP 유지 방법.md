# 서비스 노출 - 클라이언트 소스 IP 유지 방법

## 요청 접수 - VOC

클라이언트 소스 IP 유지를 위한 AVI / Contour 설정 변경은 신청 양식을 필요로 합니다. 프로젝트명, 클러스터(여러개인 경우 쉼표로 구분), 작업 요청 일시를 기입해주세요.

## 사전 준비

### 1. 사전 작업: Ingress/HttpRoute/HttpProxy 설정에서 사용하는 인증서 정보를 확인 해야 합니다.

→ 대상: 클러스터 전체(모든 네임스페이스)

※ Contour Controller는 구조가 변경 되는 사항으로 클러스터 전체 시크릿 정보와 Route 구조를 수집하여 검증 단계를 거치고 업그레이드가 진행 됩니다.

#### 1.1 시스템 네임스페이스 활성화

※ 시스템 네임스페이스는 기본적으로 비활성화 되어 있습니다. 콘솔 화면에서 확인하기 위해서는 시스템 설정에서 활성화 해야 합니다.

#### 1.2 envoy config_dump 에서 시크릿 정보를 가져와서 모든 시크릿 상태를 확인 합니다.

→ contour `useProxyProtocol` 기능 활성화시 리스너 업데이트 할때 시크릿 정보와 설정 정보를 검증하게 됩니다.

**DKS-C 콘솔 화면에서 확인**

1. 워크로드 > 데몬셋 클릭
2. `tanzu-system-ingress` 네임스페이스 선택 > `envoy` 선택
3. Pods 탭 화면 선택
4. envoy pod 클릭 > Terminal 탭화면 선택 > 애플리케이션 `envoy` 선택
5. command 사용 → `"<네임스페이스>/<시크릿명>"` 으로 시크릿 정보를 가져 옵니다.

```bash
curl -s "http://localhost:9001/config_dump" | grep -A 10 -i tls_certificate_sds_secret_configs | grep -i '"name"' | grep '/' | sed -n '/\// {s/[" ,:]//g; s/\/[^\/]*$//; s/^name//; p}' | sort -u
```

6. 구성 > 시크릿 클릭 > 네임스페이스 선택 > 시크릿 상세 정보에서 데이터를 확인
7. openssl 명령으로 매칭 확인

```bash
## Secret에서 인증서 추출 후 MD5 확인 -> 값이 일치해야 합니다.
openssl x509 -noout -modulus -in tls.crt | openssl md5
(stdin)= 27290b70bb984b7aca320afe79589019
openssl rsa -noout -modulus -in tls.key | openssl md5
(stdin)= 27290b70bb984b7aca320afe79589019
```

**kubectl 로 확인**

```bash
## envoy config 설정 확인
$ kubectl -n tanzu-system-ingress exec -it daemonset/envoy -c envoy -- curl -s "http://localhost:9001/config_dump"

## 시크릿 정보만 가져오기
# -> "<네임스페이스>/<시크릿명>" 으로 시크릿 정보를 가져 옵니다.
$ kubectl -n tanzu-system-ingress exec -it daemonset/envoy -c envoy -- curl -s "http://localhost:9001/config_dump" | grep -A 10 -i tls_certificate_sds_secret_configs | grep -i '"name"' | grep '/' | sed -n '/\// {s/[" ,:]//g; s/\/[^\/]*$//; s/^name//; p}' | sort -u

## Secret에서 인증서 추출 후 MD5 확인 -> 값이 일치해야 합니다.
$ kubectl -n tanzu-system-ingress get secret public-cert -o jsonpath='{.data.tls\.crt}' | base64 -d | openssl x509 -noout -modulus | openssl md5
(stdin)= 27290b70bb984b7aca320afe79589019

$ kubectl -n tanzu-system-ingress get secret public-cert -o jsonpath='{.data.tls\.key}' | base64 -d | openssl rsa -noout -modulus | openssl md5
(stdin)= 27290b70bb984b7aca320afe79589019
```

### 2. 사전 작업: 인증서 포맷을 확인 해야 합니다.

- 시크릿은 `kubernetes.io/tls` type 으로 생성되어야 합니다.
- 시크릿 data key name은 `tls.crt`, `tls.key` 만 사용할 수 있습니다.
- PEM format 인증서만 지원 합니다.

※ Contour는 암호화된 개인키 (Encrypted) `-----BEGIN ENCRYPTED PRIVATE KEY-----` 포맷을 지원하지 않습니다.
→ 키에 비밀번호가 걸려 있으면 Envoy가 이를 복호화 하지 못해 인그레스가 에러를 발생하며 멈춥니다. 파일 내부에 `ENCRYPTED`라는 단어가 있으면 안 됩니다.

#### 1. 허용되는 인증서 헤더/푸터 (PEM 포맷)

인증서 파일(`tls.crt`)을 텍스트 편집기로 열었을 때, 반드시 다음과 같은 텍스트 형태로 감싸져 있어야 합니다.

```text
-----BEGIN CERTIFICATE-----
... (Base64 인코딩 데이터) ...
-----END CERTIFICATE-----
```

#### 2. 허용되는 키 포맷 (PEM 포맷)

텍스트 편집기로 개인키 파일을 열었을 때, 첫 줄과 마지막 줄이 아래 중 하나로 시작하고 끝나야 합니다.

```text
## PKCS#8 포맷 (가장 권장)
-----BEGIN PRIVATE KEY-----
... (Base64 인코딩 데이터) ...
-----END PRIVATE KEY-----

## PKCS#1 포맷 (RSA 전용)
-----BEGIN RSA PRIVATE KEY-----
... (Base64 인코딩 데이터) ...
-----END RSA PRIVATE KEY-----

## EC(타원곡선) 포맷
-----BEGIN EC PRIVATE KEY-----
... (Base64 인코딩 데이터) ...
-----END EC PRIVATE KEY-----
```
