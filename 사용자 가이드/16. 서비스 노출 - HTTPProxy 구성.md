# 서비스 노출 - HTTPProxy 구성

VKS 사용자 클러스터는 클러스터가 생성될 때 외부의 트래픽을 받아서 운영할 수 있는 `envoy` 와 `contour` GatewayClass 까지만 생성됩니다. VKS 사용자 클러스터에 대한 외부 접근을 허용하기 위해서는 정식 도메인 발급과 TLS 인증서 등을 사용해서 HTTPProxy 설정을 직접 수행하셔야 합니다.

※ HTTPProxy 흐름도 (원문 이미지, 붙여넣기에 없음)

## 사전 준비

사전 작업(도메인 신청, 방화벽 오픈)은 [[15. 서비스 노출 - Gateway 구성]]의 "사전 준비"와 동일하다. 원문도 같은 문구를 반복한다.

### 1. 사전 작업: 도메인 신청이 완료 되어야 합니다.

※ 도메인(Wildcard Domain) 신청이 완료 되어야 합니다. 도메인 신청은 **Ingress IP**로 신청해야 합니다.

도메인 신청은 DS IAM에서 진행하며, Wildcard Domain으로 생성되어야 합니다. 아래 형식의 메일 결재를 통해 DS IAM에서 Domain 신청 후, Wildcard가 포함된 DNS로 전환 부탁드립니다. 아래 양식으로 메모 결재 진행 필요하며, DNS만 필요하거나 인증서만 필요한 경우 해당 항목만 포함하여 신청 부탁드립니다.

### 2. 사전 작업: 방화벽 오픈

※ 외부 시스템에서 DKS-C 서비스 접근이 필요할 때는 방화벽 오픈이 필요합니다.
※ Ingress IP (LB)는 **80, 443 port만** 열려 있습니다. Cluster 별로 IP를 분리하여 제공하기 때문에 할당 받으신 Ingress IP를 dest로 방화벽 신청해야 합니다.

| Source | Destination |
|---|---|
| 외부시스템, local 등 | DKS Pod (Ingress IP) |

※ DKS-C 서비스에서 외부 시스템 접근이 필요할 때는 방화벽 오픈이 필요합니다. Cluster 별로 IP를 분리하여 제공하기 때문에 할당 받으신 Egress IP를 source로 방화벽 신청해야 합니다.

| Source | Destination |
|---|---|
| DKS Pod (Egress IP) | 외부시스템 |

## HTTPProxy 생성 하기

참고: https://projectcontour.io/docs/1.33/config/request-routing/

- VKS 클러스터의 외부 트래픽을 분기 하기 위한 Contour가 제공하는 자체 라우팅 규칙(CRD)입니다.

> [!warning]
> Ingress와 Gateway API 병행 시, 동일 도메인(Host)에 대한 설정 중복으로 인한 트래픽 경로 누락 및 라우팅 간섭 주의

### HTTPProxy 설정 요약 (HTTP/WebSocket)

- `ingressClassName`: 시스템에서 자동 생성한 contour controller 사용 (고정값)
- `virtualhost.tls`: 도메인 인증서
- `virtualhost.fqdn`: 사용자 서비스 연결 도메인
- `conditions`
- `services`: 사용자 서비스 연결

#### 방법 1) yaml을 통한 인증서 secret 생성

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: test-cert
  namespace: test-user
type: kubernetes.io/tls
data:
  tls.crt: |
    MIIC2DCCAcCgAwIBAgIBATANBgkqhkiG9w0BAQsFADAD...   # Base64 인코딩된 인증서 데이터
  tls.key: |
    MIIEogIBAAKCAQEAw3z9R4L2o9X...                     # Base64 인코딩된 개인키 데이터
```

#### 방법 2) kubectl 을 통해서도 가능합니다.

이때 인증서 파일 내용은 base64 encoding 된 것이 아니라 원본이면 됩니다.

```bash
kubectl -n test-user create secret tls public-cert \
  --cert=./tls.crt \
  --key=./tls.key
```

#### 테스트 백엔드 및 HTTPProxy

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: whoami-test
  namespace: test-contour
spec:
  replicas: 2   # 스티키 세션 테스트를 위해 파드를 2개 띄웁니다.
  selector:
    matchLabels:
      app: whoami
  template:
    metadata:
      labels:
        app: whoami
    spec:
      containers:
      - name: whoami
        image: packages-dev.dks.samsungds.net/docker.io/traefik/whoami:latest
        ports:
        - containerPort: 80
---
apiVersion: v1
kind: Service
metadata:
  name: whoami-service
  namespace: test-contour
spec:
  ports:
  - port: 80
    targetPort: 80
  selector:
    app: whoami
```

```yaml
apiVersion: projectcontour.io/v1
kind: HTTPProxy
metadata:
  name: whoami-advanced-proxy
  namespace: test-contour
spec:
  ingressClassName: contour   # 시스템 자동 설치된 contour controller 사용 (고정값)
  virtualhost:
    fqdn: httpproxy.example.com   # 1. 트래픽을 받아올 외부 도메인
    tls:                          # tls 설정이 있으면 https로 redirect 됩니다.
      secretName: public-cert     # HTTPS 통신을 위한 인증서 Secret 이름
  routes:
    # --------------------------------------------------------
    # [설정 1] 웹소켓 에코 테스트용 경로 (/echo)
    # --------------------------------------------------------
    - conditions:
        - prefix: /echo   # Contour는 경로 조건만 맞으면 일반 HTTP와 WebSocket을 모두 자동 수용합니다.
      services:
        - name: whoami-service
          port: 80
    # --------------------------------------------------------
    # [설정 2] 기본 웹 화면 접속 경로 (/)
    # --------------------------------------------------------
    - conditions:
        - prefix: /
      # [기능 1] 요청/응답 헤더 조작 설정
      requestHeadersPolicy:
        set:
          - name: X-Custom-Request-Header
            value: "Hello-Contour"   # 백엔드로 보낼 때 헤더 주입
      responseHeadersPolicy:
        set:
          - name: X-Custom-Response-Header
            value: "Envoy-Proxy"     # 클라이언트에게 돌려줄 때 헤더 주입
      # [기능 2] 쿠키 기반 스티키 세션 설정 (로드밸런싱 전략)
      loadBalancerPolicy:
        strategy: Cookie   # Envoy가 자동으로 'X-Contour-Session-Affinity' 쿠키 발급
      services:
        - name: whoami-service
          port: 80
```

### HTTPProxy 설정 요약 (gRPC)

- `ingressClassName`: 시스템에서 자동 생성한 contour controller 사용 (고정값)
- `virtualhost.tls`: 도메인 인증서
- `virtualhost.fqdn`: 사용자 서비스 연결 도메인
- `conditions`
- `services`: 사용자 서비스 연결
- `protocol: h2c` — **[필수]** gRPC(HTTP/2 cleartext) 통신 처리를 위한 프로토콜 지정

인증서 Secret 생성은 위 "방법 1) yaml", "방법 2) kubectl"과 동일하다. 원문도 같은 내용을 반복한다.

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: grpc-echo
  namespace: test-contour
spec:
  selector:
    matchLabels:
      app: grpc-echo
  replicas: 1
  template:
    metadata:
      labels:
        app: grpc-echo
    spec:
      containers:
      - name: grpc-echo
        image: packages-dev.dks.samsungds.net/docker.io/projectcontour/yages:v0.1.0
        ports:
        - containerPort: 9000
          protocol: TCP
        env:
        - name: POD_NAME
          valueFrom:
            fieldRef:
              fieldPath: metadata.name
        - name: NAMESPACE
          valueFrom:
            fieldRef:
              fieldPath: metadata.namespace
        - name: GRPC_ECHO_SERVER
          value: "true"
        - name: SERVICE_NAME
          value: grpc-echo
---
apiVersion: v1
kind: Service
metadata:
  name: grpc-echo-svc
  namespace: test-contour
spec:
  type: ClusterIP
  ports:
  - port: 3000
    protocol: TCP
    targetPort: 9000
    appProtocol: kubernetes.io/h2c
  selector:
    app: grpc-echo
```

```yaml
apiVersion: projectcontour.io/v1
kind: HTTPProxy
metadata:
  name: test-grpc-proxy
  namespace: test-contour
spec:
  ingressClassName: contour   # 시스템 자동 설치된 contour controller 사용 (고정값)
  virtualhost:
    fqdn: grpc.example.com    # 1. 트래픽을 받아올 외부 도메인
    tls:                      # tls 설정이 있으면 https로 redirect 됩니다.
      secretName: public-cert # HTTPS 통신을 위한 인증서 Secret 이름
  routes:
    # --------------------------------------------------------
    # [설정 1] gRPC 통신 테스트용 경로 (/yages.Echo)
    # --------------------------------------------------------
    - conditions:
        - prefix: /yages.Echo/Ping   # Matches a specific gRPC method.
      services:
        - name: grpc-echo-svc
          port: 3000
          # [필수] gRPC(HTTP/2 cleartext) 통신 처리를 위한 프로토콜 지정
          protocol: h2c
    - conditions:
        - prefix: /                  # Matches everything else.
      services:
        - name: grpc-echo-svc
          port: 3000
          # [필수] gRPC(HTTP/2 cleartext) 통신 처리를 위한 프로토콜 지정
          protocol: h2c
```

```bash
$ grpcurl -d '{"text": "hello"}' -insecure -authority grpc.example.com grpc.example.com:443 yages.Echo.Reverse

  "text": "olleh"
}
```
