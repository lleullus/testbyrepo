# CI/CD 파이프라인 입문 가이드

> **이 문서는?** DKS Pipeline Tool 을 처음 사용하는 분들을 위한 가이드입니다. 각 설정 항목의 의미와 올바른 입력 방법을 단계별로 설명합니다.

## CI/CD 란 무엇인가?

**한 줄 요약**: CI/CD는 개발자가 코드를 Push하면, 빌드·배포까지 자동으로 처리해주는 파이프라인입니다.

### 핵심 구성 요소

| 구성 요소 | 역할 | 사내 시스템 |
|---|---|---|
| Git | 소스코드 저장소 | 예시) github.samsungds.net |
| Harbor | Docker 이미지 저장소 | 예시) harbor.dks.samsungds.net |
| Kubernetes | 컨테이너 실행 환경 | 예시) DKS-C 클러스터 등 |
| Pipeline Tool | CI/CD 자동화 도구 | DKS Platform, P-DEP, S-DEP 등 |

### 전체 흐름 한눈에 보기

(원문 흐름도 이미지는 붙여넣기에 없음)

## 1. 기본 정보 입력

소스코드 체크아웃 경로와 글로벌 환경변수, 그리고 빌드된 이미지 주소 등, 전체 스텝에서 공통으로 참조되는 런타임 상태값을 제공합니다.

### 1.1 파이프라인 이름

파이프라인을 식별하는 이름입니다. 날짜, 목적 등을 조합하여 알아보기 쉽게 작성합니다.

| 항목 | 예시 |
|---|---|
| 파이프라인 이름 | `260714-sample-app` |

### 1.2 설명

파이프라인의 목적이나 배포 대상 앱을 간략히 기술합니다.

| 항목 | 예시 |
|---|---|
| 설명 | `test application` |

### 1.3 소스 레포지토리 연결

CI가 소스코드를 어느 Git 저장소에서 가져올지 지정합니다.

#### 1.3.1 소스 레포지토리

사내 Git 연동 시 등록된 자격증명(Credential) 이름을 선택합니다. 설정>레포지토리 관리 메뉴에서 등록된 레포지토리가 보여지게 됩니다. → [[21. (CI-CD) 사전준비]] 의 "소스 Repository 등록"

#### 1.3.2 브랜치

빌드할 소스코드의 Git 브랜치 이름을 선택합니다.

| 항목 | 예시 |
|---|---|
| 브랜치 | `main` |

### 1.4 환경변수 (Optional)

파이프라인 전체 스텝(CI/CD 모두)에서 공통으로 참조할 변수를 Key:Value 형태로 정의합니다. 필수 항목이 아니며, 버전 관리나 설정값 외부화가 필요할 때 사용합니다.

| Key | Value | 설명 |
|---|---|---|
| `RUN_MODE` | `prod` | CI/CD 스텝 내 `{{RUN_MODE}}` 형태로 참조 가능 |
| `APP_NAME` | `sample` | CI/CD 스텝 내 `{{APP_NAME}}` 형태로 참조 가능 |

## 2. CI (Continuous Integration)

소스코드 체크아웃 경로와 글로벌 환경변수, 그리고 빌드된 이미지 주소 등, 전체 스텝에서 공통으로 참조되는 런타임 상태값을 제공합니다.

**CI 단계 흐름**: Git 소스코드 체크아웃 → Dockerfile 기반 이미지 빌드 → Harbor에 이미지 Push → 빌드된 이미지 주소를 환경변수로 CD에 전달

### 2.1 빌드 구성

#### 2.1.1 소스 레포지토리 (Git)

CI가 소스코드를 가져올 Git 저장소 URL입니다.

| 항목 | 올바른 예시 | 잘못된 예시 |
|---|---|---|
| Git URL | ✔ `https://github.samsungds.net/DKS-dscloud-paas-dev/devops-examples` | ✘ `.../ss_k8s/tree/main/calculator-app` |

> [!warning] 주의
> 저장소 최상위 URL만 입력합니다. 특정 폴더 경로는 2.1.8(도커파일 경로)에서 지정합니다.

#### 2.1.2 이미지 레지스트리 (Harbor)

빌드된 이미지를 저장할 Harbor 를 선택합니다. 자동으로 등록(설정/레지스트리)된 Harbor 중 선택하면 됩니다.

#### 2.1.3 빌드 이미지

빌드 결과물로 Harbor에 저장될 컨테이너 이미지의 전체 경로입니다.

base 이미지 vs 빌드 이미지 차이

| 구분 | 설명 | 예시 |
|---|---|---|
| base 이미지 | Dockerfile의 `FROM`에 쓰인 이미지. 빌드의 재료 | `harbor.dks.samsungds.net/docker.io/library/golang:1.25.10` |
| 빌드 이미지 | 이 파이프라인이 만들어서 Harbor에 Push할 결과물 | `harbor.dks.samsungds.net/.../dev-20260727-145445` (사내 레파지토리) |

#### 2.1.4 자동 태그 사용 (미사용 / 사용)

| 옵션 | 동작 | 권장 여부 |
|---|---|---|
| 사용 | CI가 일시 기반으로 태그 자동 생성 (예: `prefix-20260501-122031345`) | ✅ 권장 |
| 미사용 | 태그 직접 지정 | 특별한 태그 규칙이 필요한 경우 |

#### 2.1.5 빌드 이미지 태그 (미사용)

자동 태그를 미사용으로 설정한 경우, 태그를 직접 지정합니다.

| 태그 입력값 | 최종 태그 예시 |
|---|---|
| `dks-dev` | `harbor.dks.samsungds.net/.../<imageName>:dks-dev` |

#### 2.1.6 컨테이너 이미지 환경변수 `{{APP_BUILD_IMAGE_01}}`

CI가 빌드한 이미지의 전체 경로를 담는 런타임 환경변수입니다. CD 단계의 deployment.yaml에서 이 값을 참조하여 이미지 주소가 자동으로 치환됩니다.

```yaml
# deployment.yaml 참조 예시
# https://github.samsungds.net/DKS-dscloud-paas-dev/devops-examples/blob/main/k8s/deployment.yaml
...
      containers:
      - name: rollouts-demos
        image: {{APP_BUILD_IMAGE_01}}   # CI가 빌드한 이미지의 전체 경로를 담는 런타임 환경변수
        env:
        - name: RUN_MODE
          value: "{{RUN_MODE}}"
        - name: APP_NAME
          value: "{{APP_NAME}}"
        imagePullPolicy: Always
        ports:
        - name: http
          containerPort: 8080
          protocol: TCP
        resources:
          requests:
            memory: 32Mi
            cpu: 5m
      imagePullSecrets:
      - name: {{IMAGE_PULL_SECRET_01}}
```

| 항목 | 기본값 | 설명 |
|---|---|---|
| 컨테이너 이미지 환경변수 | `{{APP_BUILD_IMAGE_01}}` | 특별한 이유가 없으면 기본값 사용 권장 |

#### 2.1.7 이미지 풀시크릿 환경변수 `{{IMAGE_PULL_SECRET_01}}`

Kubernetes가 Harbor에서 이미지를 가져올 때 사용하는 인증 정보 변수입니다.

```yaml
# deployment.yaml 참조 예시
# https://github.samsungds.net/DKS-dscloud-paas-dev/devops-examples/blob/main/k8s/deployment.yaml
...
      containers:
      - name: rollouts-demos
        image: {{APP_BUILD_IMAGE_01}}
        env:
        - name: RUN_MODE
          value: "{{RUN_MODE}}"
        - name: APP_NAME
          value: "{{APP_NAME}}"
        imagePullPolicy: Always
        ports:
        - name: http
          containerPort: 8080
          protocol: TCP
        resources:
          requests:
            memory: 32Mi
            cpu: 5m
      imagePullSecrets:
      - name: {{IMAGE_PULL_SECRET_01}}   # Harbor에서 이미지를 가져올 때 사용하는 인증 정보 변수
```

| 항목 | 기본값 | 설명 |
|---|---|---|
| 이미지 풀시크릿 환경변수 | `{{IMAGE_PULL_SECRET_01}}` | 특별한 이유가 없으면 기본값 사용 권장 |

#### 2.1.8 도커파일

> **Dockerfile 이란?** 앱을 컨테이너로 만드는 레시피 파일입니다. "어떤 OS를 기반으로, 어떤 패키지를 설치하고, 어떤 코드를 실행할지"를 정의합니다.

**DIRECT_INPUT**: Dockerfile 내용을 Pipeline Tool UI에 직접 붙여넣는 방식입니다.

```dockerfile
FROM harbor.dks.samsungds.net/docker.io/library/golang:1.25.10 as build
WORKDIR /go/src/app
COPY . .
RUN make

FROM scratch
COPY *.html ./
COPY *.png ./
COPY *.js ./
COPY *.ico ./
COPY *.css ./
COPY --from=build /go/src/app/rollouts-demo /rollouts-demo

ARG COLOR
ENV COLOR=${COLOR}
ARG ERROR_RATE
ENV ERROR_RATE=${ERROR_RATE}
ARG LATENCY
ENV LATENCY=${LATENCY}

ENTRYPOINT [ "/rollouts-demo" ]
```

빠른 테스트에 유용하나, 운영 환경에서는 Git 이력 관리가 가능한 FILE_URL 방식을 권장합니다.

**FILE_URL**: Git 저장소에 저장된 Dockerfile의 경로를 지정하는 방식입니다. 코드와 함께 Git으로 관리되어 변경 이력 추적이 가능합니다.

| 항목 | 올바른 예시 | 잘못된 예시 |
|---|---|---|
| 도커파일 경로 | ✔ `Dockerfile` | ✘ `k8s/deployment.yaml` |

Git 저장소 루트 기준의 상대 경로를 입력합니다. deployment.yaml 경로를 입력하지 않도록 주의하세요.

## 3. CD (Continuous Deployment)

소스코드 체크아웃 경로와 글로벌 환경변수, 그리고 빌드된 이미지 주소 등, 전체 스텝에서 공통으로 참조되는 런타임 상태값을 제공합니다.

**CD 단계 흐름**: CI에서 전달받은 이미지 주소 (`{{APP_BUILD_IMAGE_01}}`) → deployment.yaml 이미지 주소 치환 → Kubernetes 클러스터에 배포 (`kubectl apply`) → Pod 기동 및 서비스 운영

### 3.1 배포 대상 클러스터 및 네임스페이스 선택

#### 3.1.1 클러스터

| 항목 | 예시 | 설명 |
|---|---|---|
| 클러스터 | `dks-test-cluster` | DKS Platform에 등록된 클러스터 이름 |

#### 3.1.2 네임스페이스

> **네임스페이스란?** 하나의 Kubernetes 클러스터를 여러 팀/서비스가 격리된 공간으로 나눠 사용하는 단위입니다. 네임스페이스가 다르면 같은 클러스터 안에서도 서로 영향을 주지 않습니다.

| 항목 | 예시 | 설명 |
|---|---|---|
| 네임스페이스 | `test-ns` | 팀 또는 서비스 단위로 사전 생성된 네임스페이스 |

### 3.2 배포 리소스 정의

> **deployment.yaml 이란?** Kubernetes에게 "이 이미지를 몇 개의 Pod로, 어떤 리소스 제한으로 실행해라"를 지시하는 파일입니다. 운영 환경에서는 Git 이력 관리가 가능한 레포지토리 파일 방식을 권장합니다.

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: rollouts-demos
  labels:
    app: rollouts-demos
spec:
  replicas: 3
  revisionHistoryLimit: 1
  selector:
    matchLabels:
      app: rollouts-demos
  template:
    metadata:
      labels:
        app: rollouts-demos
    spec:
      containers:
      - name: rollouts-demos
        image: {{APP_BUILD_IMAGE_01}}   # CI가 빌드한 이미지로 자동 치환
        env:
        - name: RUN_MODE
          value: "{{RUN_MODE}}"         # 환경 변수 정의
        - name: APP_NAME
          value: "{{APP_NAME}}"         # 환경 변수 정의
        imagePullPolicy: Always
        ports:
        - name: http
          containerPort: 8080
          protocol: TCP
        resources:
          requests:
            memory: 32Mi
            cpu: 5m
      imagePullSecrets:
      - name: {{IMAGE_PULL_SECRET_01}}  # Harbor 인증 정보로 자동 치환
```

배포 파일 경로 — Git 저장소에 저장된 배포 YAML의 경로를 지정하는 방식입니다. (원문은 "Dockerfile의 경로"로 적혀 있으나 문맥상 배포 파일 경로다.) 코드와 함께 Git으로 관리되어 변경 이력 추적이 가능합니다.

| 항목 | 올바른 예시 | 잘못된 예시 |
|---|---|---|
| 배포 파일 경로 | ✔ `k8s/deployment.yaml` | ✘ `Dockerfile` |

deployment.yaml 안에 `{{APP_BUILD_IMAGE_01}}`, `{{IMAGE_PULL_SECRET_01}}` 변수가 반드시 포함되어 있어야 CI에서 빌드한 이미지 정보가 올바르게 반영됩니다.

## 4. 자주 발생하는 오류 및 해결 방법

| 단계 | 오류 메시지 | 원인 | 해결 방법 |
|---|---|---|---|
| CI | `invalid tag "...ubuntu:latest:test-tag-1"` | 빌드 이미지 경로에 `:latest` 태그 직접 입력 | 이미지 경로에서 태그 제거 |
| CI | `invalid tag "...devops-example/devops-example/..."` | 이미지 레지스트리와 이미지 이름에 프로젝트명 중복 입력 | 이미지 이름에서 중복 경로 제거 |
| CI | `failed to build: no such file` | 도커파일 경로 오류 또는 Git에 파일 없음 | `폴더/Dockerfile` 형태인지, Git에 파일 존재하는지 확인 |
| CD | Pod `ImagePullBackOff` | K8s가 Harbor에서 이미지를 가져오지 못함 | 이미지 이름/태그가 Harbor에 존재하는지, ImagePullSecret 확인 |
| CD | `deployment.yaml 적용 실패` | 배포 파일 경로에 잘못된 파일 입력 | 경로가 `k8s/deployment.yaml`을 가리키는지 확인 |

## 5. 파이프라인 설정 전 체크리스트

### 사전 준비

- [ ] Git 저장소에 Dockerfile이 존재하는가?
- [ ] Git 저장소에 `k8s/deployment.yaml`이 존재하는가?
- [ ] deployment.yaml 안에 `{{APP_BUILD_IMAGE_01}}`, `{{IMAGE_PULL_SECRET_01}}` 변수가 포함되어 있는가?
- [ ] Harbor에 base 이미지(`harbor.dks.samsungds.net/docker.io/library/golang:1.25.10` 등)가 push 되어 있는가?
- [ ] DKS Platform에 Git 자격증명이 등록되어 있는가?
- [ ] 배포할 K8s 네임스페이스가 생성되어 있는가?

### 설정 항목 확인

- [ ] 소스 레포지토리: Git URL이 아닌 자격증명 이름을 선택했는가?
- [ ] 이미지 레지스트리: Harbor 전체 URL이 아닌 프로젝트 이름만 입력했는가?
- [ ] 빌드 이미지: base 이미지가 아닌 결과물 이미지 이름을 입력했는가? (태그 미포함)
- [ ] 도커파일 경로: `폴더/Dockerfile` 형태인가? (yaml 파일 경로 X)
- [ ] 배포 파일 경로: `k8s/deployment.yaml`을 가리키는가? (Dockerfile 경로 X)
