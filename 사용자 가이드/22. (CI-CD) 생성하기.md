# (CI/CD) 생성하기

## CI/CD 메뉴 이동

CI/CD 생성을 하려면 먼저 ① 버튼을 클릭하여 CI/CD 메뉴로 이동한 후, ② 버튼을 클릭하여 생성화면으로 이동합니다. (원문 스크린샷 없음)

## CI/CD 생성

**Pipeline Context**: CI/CD 환경변수, 그리고 빌드된 이미지 주소 등, 전체 스텝에서 공통으로 참조되는 런타임 상태값을 제공합니다.

### 1단계. 기본 정보 입력

파이프라인 이름, 설명 입력합니다.

**파이프라인 이름**: 파이프라인을 식별하는 이름입니다. 날짜, 목적 등을 조합하여 알아보기 쉽게 작성합니다. 이름은 영어 대소문자, 숫자, 하이픈(-)만 가능합니다.

| 항목 | 예시 |
|---|---|
| 파이프라인 이름 | `(어플리케이션)-(배포환경)-(컴포넌트)` 조합 |

예시: `demo-app-dev-sample-dashboard`, `demo-app-dev-sample-api`, `demo-app-prod-sample-dashboard`, `demo-app-prod-sample-api`

**설명**: 파이프라인의 목적이나 배포 대상 앱을 간략히 기술합니다.

| 항목 | 예시 |
|---|---|
| 설명 | 개발환경용 sample-dashboard 파이프라인입니다. |

**소스 레포지토리 연결**: CI/CD에서 사용할 소스코드 레포지토리와 브랜치를 선택합니다.

- **소스 레포지토리**: 사용할 레포지토리를 선택해주세요. 설정 > 레포지토리 관리 메뉴에서 등록된 레포지토리가 보여지게 됩니다. (소스 레포지토리 관리에 대한 더 자세한 내용은 [[21. (CI-CD) 사전준비]]의 "소스 Repository 등록"을 확인하세요.)
- **브랜치**: 소스 레포지토리 항목에서 선택한 레포지토리의 Git 브랜치가 보여지게 됩니다. 사용할 브랜치를 선택해주세요.

**환경변수**: 환경 변수는 CI/CD 전체에서 공통적으로 사용할 수 있는 공통 환경 변수를 정의합니다.

버튼: **취소** — CI/CD 생성을 취소하고 목록으로 이동합니다. **다음** — 다음 단계로 이동합니다.

### 2단계. CI 단계의 컨테이너 이미지 빌드

쿠버네티스(k8s) 클러스터는 소스 코드나 단순 실행 파일을 직접 구동할 수 없습니다. 따라서 CI 단계에서는 애플리케이션 소스 코드를 k8s가 인식하고 제어할 수 있는 표준 컨테이너 이미지 규격(OCI Standard)으로 변환하는 작업을 수행합니다.

아래와 같은 단계로 진행됩니다.

1. **소스 코드 다운로드 (Source Checkout)**: 소스 레포지토리의 소스 코드를 Git으로부터 다운로드합니다.
2. **컨테이너 이미지 빌드 (Image Build via Dockerfile)**: Dockerfile을 기반으로, 다운로드한 소스 코드를 컴파일하고 의존성 패키지를 설치하여 k8s에서 구동할 수 있는 표준 컨테이너 이미지(Artifact) 형태로 빌드합니다. Dockerfile은 소스 코드에서 참조하거나, CI 단계에서 직접 작성 할 수 있습니다.
3. **이미지 레지스트리 Push (Harbor Push)**: 빌드가 완료된 이미지는 k8s 노드가 접근할 수 있는 자동으로 등록(설정/레지스트리)된 Harbor로 Push 합니다. Push된 이미지 주소는 컨테이너 이미지 환경변수에 저장되어 CD 단계의 YAML 파일의 컨테이너 이미지 정보에 이 변수를 사용할 수 있습니다.

컨테이너 이미지 주소 예시: `harbor.dks.samsungds.net/dks-registry-1/demo-sample-api:dev-20260806-130616358`

| 이미지 레지스트리 | 빌드 이미지 | 빌드 이미지 태그 |
|---|---|---|
| `harbor.dks.samsungds.net/dks-registry-1` | `demo-sample-api` | `dev-20260806-130616358` |

입력 항목

- **Pipeline Context**: CI/CD 환경변수, 그리고 빌드된 이미지 주소 등, 전체 스텝에서 공통으로 참조되는 런타임 상태값을 제공합니다.
- **소스 레포지토리**: 기본 정보 입력 단계에서 선택한 소스 레포지토리 정보(Endpoint URL, 브랜치)가 보여집니다.
- **이미지 레지스트리**: 이미지 레지스트리를 선택합니다. 설정 > 레지스트리 관리 메뉴에서 등록된 레지스트리가 보여지게 됩니다. (이미지 레지스트리 관리에 대한 더 자세한 내용은 [[21. (CI-CD) 사전준비]]의 "등록된 registry 확인"을 확인하세요.)
- **빌드 이미지**: 빌드 이미지 이름을 입력합니다. 영문 소문자, 숫자, 구분 기호(`-`, `_`, `.`) 만 가능합니다.
- **자동태그 사용**: 자동태그 사용여부를 선택합니다. (사용 | 미사용)
  - **'사용' 선택 (권장)**: 자동태그를 사용으로 선택하면 일시 기반으로 태그가 자동 생성됩니다.
    1. 빌드 이미지 태그 (prefix): 자동태그에서 사용하는 prefix를 입력합니다. (ex. `prefix-20260501-122031345`)
    2. 자동증가 유형: 자동태그는 일시 유형으로 생성됩니다 (ex. `prefix-20260501-122031345`) — YYYY(년), MM(월), DD(일), hh(시), mm(분), ss(초), SSS(밀리초)
    3. 컨테이너 이미지 주소: 자동태그를 사용하여 이미지 빌드시 생성되는 컨테이너 이미지 주소 예시를 보여줍니다.
  - **'미사용' 선택**: 자동태그를 미사용으로 선택하면 입력한 빌드 이미지 태그로 태그가 생성됩니다.
    1. 빌드 이미지 태그를 입력합니다.
    2. 컨테이너 이미지 주소: 이미지 빌드시 생성되는 컨테이너 이미지 주소를 보여줍니다.
- **컨테이너 이미지 주소**: 이미지 레지스트리, 빌드 이미지, 빌드 이미지 태그를 입력하면 자동으로 컨테이너 이미지 주소를 완성하여 보여줍니다.
- **컨테이너 이미지 환경변수**: 빌드된 컨테이너 이미지 주소가 자동으로 할당되는 변수입니다. CD 단계의 YAML 파일의 컨테이너 이미지 정보에 이 변수를 사용하면 매번 수정 없이 최신 이미지를 동적으로 참조하여 배포합니다.
- **이미지 풀시크릿 환경변수**: 빌드된 컨테이너 이미지의 인증 정보가 자동으로 할당되는 변수입니다. CD 단계의 YAML 파일의 이미지 풀시크릿 정보에 이 변수를 사용하면 매번 수정 없이 인증정보를 동적으로 참조하여 배포합니다.
- **도커파일**: 이미지 생성을 위한 도커파일 빌드 스크립트를 작성합니다.
  - `DIRECT_INPUT`: 도커파일을 직접 작성합니다.
  - `FILE_URL`: 소스 레포지토리에 있는 도커파일을 사용합니다.

주요 명령어

| 명령어 | 설명 |
|---|---|
| `FROM <image>:<tag>` | 베이스 이미지를 설정합니다. (예: `FROM node:18-alpine`) |
| `WORKDIR <dir>` | 컨테이너 내 작업 디렉토리를 설정합니다 (cd와 유사). |
| `COPY <src> <dest>` | 호스트의 파일/디렉토리를 이미지로 복사합니다. |
| `RUN <command>` | 이미지 빌드 중 명령어를 실행합니다 (패키지 설치 등). |
| `EXPOSE <port>` | 컨테이너가 리슨하는 포트를 명시합니다. |
| `CMD ["command", "param"]` | 컨테이너가 시작될 때 실행할 기본 명령어를 설정합니다. |

버튼: **이전** — 이전 단계로 이동. **취소** — CI/CD 생성을 취소하고 목록으로 이동. **이 단계 건너뛰기** — CI 단계를 작성하지 않고 다음 단계로 이동합니다. (CI와 CD중 1개는 필수 구성입니다) **다음** — 다음 단계로 이동.

### 3단계. CD 단계 (배포)

- **소스 레포지토리**: 기본 정보 입력 단계에서 선택한 소스코드 레포지토리를 표시합니다.
- **배포 대상 클러스터 및 네임스페이스 선택**: 배포 대상 클러스터와 네임스페이스를 선택합니다.
  - 클러스터: 프로젝트 내의 클러스터를 표시합니다.
  - 네임스페이스: 선택한 클러스터 내의 네임스페이스를 표시합니다.
- **배포 리소스 정의**: 배포할 리소스를 작성합니다.
  - `YAML 직접입력`: 배포할 리소스를 직접 작성합니다.
  - `레포지토리 파일`: 소스 레포지토리에 있는 배포 리소스 파일을 사용합니다.

레포지토리 디렉토리 구조 (예시)

```text
project
├── README.md
└── deploy
    ├── deploy.yaml
    ├── config.yaml
    ├── file
    │   └── deploy.yaml
    ├── app
    │   └── deploy.yaml
    └── svc
        └── deploy
            └── deploy.yaml
    └── env
        └── config.yaml
```

| 예시 | 경로 패턴 | 의미 |
|---|---|---|
| 1 | `deploy/deploy.yaml` | deploy 디렉토리의 deploy.yaml 파일 |
| 2 | `deploy/app` | deploy/app 디렉토리의 모든 파일 |
| 3 | `deploy/**` | deploy 디렉토리의 모든 파일을 포함한 하위의 모든 디렉토리의 모든 파일 |
| 4 | `deploy/**/*.yaml` | deploy 디렉토리 하위의 모든 디렉토리의 yaml 확장자를 가진 모든 파일 |
| 5 | `deploy/svc/**/*.yaml` | deploy/svc 디렉토리 하위의 모든 디렉토리의 yaml 확장자를 가진 모든 파일 |

빌드 이미지 환경 변수 활용: Pipeline Context를 보면 Global Environment와 Container Image 환경변수를 확인할 수 있습니다. 배포 리소스에서 해당 환경 변수를 `{{환경변수Key}}` 이렇게 치환할 곳에 설정해놓으면 배포시 해당 KEY에 해당하는 VALUE로 치환되어 배포됩니다.

- 컨테이너 이미지 환경변수
- 이미지 풀시크릿 환경변수
- 전역 환경변수 (Global Environment)

**리소스 추가**: 리소스 추가 버튼을 클릭하면 배포 리소스 입력폼이 추가됩니다.

버튼: **이전**, **취소**, **이 단계 건너뛰기** — CD 단계를 작성하지 않고 다음 단계로 이동합니다. (CI와 CD중 1개는 필수 구성입니다) **다음**.

### 4단계. 확인 및 생성

- **기본 정보**: 파이프라인 이름, 설명, 소스 레포지토리, 브랜치, 엔드포인트, 환경변수를 확인합니다.
- **빌드(CI)**: 이미지 레지스트리, 자동태그, 컨테이너 이미지, 컨테이너 이미지 환경변수, 이미지 풀시크릿 환경변수, 도커파일을 확인합니다.
- **배포(CD)**: 배포 대상 클러스터와 네임스페이스 그리고 배포할 YAML 리소스를 확인합니다.

버튼: **이전**, **취소**, **파이프라인 생성하기** — 위와 같은 정보로 파이프라인을 생성합니다.
