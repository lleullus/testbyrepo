# 서비스 노출 - Gateway 구성

VKS 사용자 클러스터는 클러스터가 생성될 때 외부의 트래픽을 받아서 운영할 수 있는 `envoy` 와 `contour` GatewayClass 까지만 생성됩니다. VKS 사용자 클러스터에 대한 외부 접근을 허용하기 위해서는 정식 도메인 발급과 TLS 인증서 등을 사용해서 `Contour` Gateway 및 HTTPRoute 처리를 직접 수행하셔야 합니다.

※ Gateway 흐름도 (원문 이미지, 붙여넣기에 없음)

## 사전 준비

### 1. 사전 작업: 도메인 신청이 완료 되어야 합니다.

※ 도메인(Wildcard Domain) 신청이 완료 되어야 합니다. 도메인 신청은 **Ingress IP**로 신청해야 합니다.

도메인 신청은 DS IAM에서 진행하며, Wildcard Domain으로 생성되어야 합니다. 아래 형식의 메일 결재를 통해 DS IAM에서 Domain 신청 후, Wildcard가 포함된 DNS로 전환 부탁드립니다. 아래 양식으로 메모 결재 진행 필요하며, DNS만 필요하거나 인증서만 필요한 경우 해당 항목만 포함하여 신청 부탁드립니다.

### 2. 사전 작업: 방화벽 오픈

※ 외부 시스템에서 DKS-C 서비스 접근이 필요할 때는 방화벽 오픈이 필요합니다.
※ Ingress IP (LB)는 **80, 443 port만** 열려 있습니다. Cluster 별로 IP를 분리하여 제공하기 때문에 할당 받으신 Ingress IP를 dest로 방화벽 신청해야 합니다.

| Source | Destination |
|---|---|
| 외부시스템, local 등 | DKS Pod (Ingress IP) |

※ DKS-C 서비스에서 외부 시스템 접근이 필요할 때는 방화벽 오픈이 필요합니다. Cluster 별로 IP를 분리하여 제공하기 때문에 할당 받으신 Egress IP를 source로 방화벽 신청해야 합니다.

| Source | Destination |
|---|---|
| DKS Pod (Egress IP) | 외부시스템 |

## Gateway 생성 하기

### 1. 시스템 네임스페이스 활성화

※ 시스템 네임스페이스는 기본적으로 비활성화 되어 있습니다. 콘솔 화면에서 확인하기 위해서는 시스템 설정에서 활성화 해야 합니다.

### 2. Gateway 생성

참고:

- https://kubernetes.io/docs/concepts/services-networking/gateway/
- https://gateway-api.sigs.k8s.io/docs/introduction/

Gateway API 핵심 리소스 레퍼런스 (v1.2.1 기준) - Standard Channel
※ Experimental Channel API 레퍼런스는 지원하지 않습니다.

| 리소스 종류 | 소속 채널 | 설명 | 주요 역할 |
|---|---|---|---|
| GatewayClass | Standard (GA) | 클러스터 내 인프라 레이어의 템플릿(예: Envoy, Nginx 프록시 구현체 등)을 정의합니다. | 인프라 관리자가 로드밸런서 구현체를 공급 및 관리. |
| Gateway | Standard (GA) | 트래픽이 유입되는 실제 진입점(Entrypoint) 인터페이스입니다. | 클러스터 운영자가 포트, 프로토콜, TLS 인증서 바인딩을 정의. |
| HTTPRoute | Standard (GA) | HTTP 및 HTTPS 트래픽에 대한 호스트명, 경로, 헤더 매칭 및 백엔드 서비스 매핑을 담당합니다. | 서비스 개발자가 소속 어플리케이션의 라우팅 규칙 설정. |
| GRPCRoute | Standard (GA) | gRPC 프로토콜 전용 트래픽 일치 및 규칙을 정의합니다. v1.2.1 기준 v1 스펙만 제공됩니다. | 서비스 개발자가 고성능 gRPC 통신 트래픽을 제어. |
| TLSRoute | Experimental | TLS를 종료(Terminate)하지 않고 SNI(Server Name Indication) 통과 및 패스스루 라우팅을 수행합니다. | 서비스 개발자가 종단간(E2E) 암호화 트래픽 통과 규칙 정의. |
| ReferenceGrant | Standard (GA) | 네임스페이스 경계를 넘어 타 네임스페이스의 백엔드 리소스를 안전하게 참조하도록 허가합니다. | 백엔드 소유자/운영자가 외부 Namespace로부터의 연결을 보안 검증. |

- VKS 클러스터의 외부 트래픽을 분기 하기 위한 Kubernetes Gateway API 입니다.
  ※ 모든 네임스페이스에 대한 route 정의를 합니다. (80, 443)
- GatewayClass는 기본 생성되는 `contour`를 사용해야 합니다. → Contour Controller와 연결되어 있는 GatewayClass 입니다.
- Contour Gateway는 `tanzu-system-ingress` 시스템 네임스페이스에 생성 해야 합니다. → Contour Controller와 연결되어 있는 Gateway 입니다.
- Contour Gateway는 `contour` name 으로 생성 해야 합니다. → Contour Controller와 연결되어 있는 Gateway 입니다.

Gateway 설정 요약

- `gatewayClassName`: 시스템에서 자동 생성한 gatewayClass 이름
- `name`: "contour" 고정값 사용
- `namespace`: "tanzu-system-ingress" 고정값 사용
- `allowedRoutes`: 라우트 설정

```yaml
apiVersion: gateway.networking.k8s.io/v1
kind: Gateway
metadata:
  name: contour                    # Contour Controller 에서 사용 (고정값)
  namespace: tanzu-system-ingress  # 시스템 네임스페이스 사용 (고정값)
spec:
  gatewayClassName: contour        # 시스템 자동 생성되 gatewayclass name 사용 (고정값)
  listeners:
  - allowedRoutes:                 # 모든 네임스페이스의 라우트 설정
      namespaces:
        from: All
    name: http
    port: 80
    protocol: HTTP
  - allowedRoutes:                 # 모든 네임스페이스의 라우트 설정
      namespaces:
        from: All
    name: https
    port: 443
    protocol: HTTPS
    tls:
      certificateRefs:
      - group: ''
        kind: Secret
        name: public-cert          # Your TLS Secret's name
      mode: Terminate
```

### 3. HTTPRoute 생성

Kubernetes Gateway API 를 통해 라우팅 될 수 있도록 HTTPRoute 정보를 구성해 줘야 합니다.

- https://gateway-api.sigs.k8s.io/guides/user-guides/http-routing/

HTTPRoute 설정 요약

- `parentRefs`: Contour Gateway 사용
- `backendRefs`: 사용자 backend 서비스

weight 설정 요약

- 정의: 여러 백엔드 서비스 간의 트래픽 분산 비율.
- 작동 방식: 절대값이 아닌 상대적 비중으로 계산. (예: 1:1은 50%씩, 9:1은 90%와 10% 분산)
- 기본값: 1 (설정된 모든 백엔드로 트래픽을 균등하게 배분).
- 특이 사항: 0으로 설정 시 해당 백엔드로의 트래픽을 완전히 차단.

Gateway API v1.2 필터 분류 표

| 필터 타입명 (type) | 적용 채널 | 주요 기능 설명 | 핵심 매개변수 (Stanza) |
|---|---|---|---|
| RequestHeaderModifier | Standard (GA) | 백엔드로 요청을 보내기 전, HTTP 요청 헤더를 추가/수정/삭제합니다. | set, add, remove |
| ResponseHeaderModifier | Standard (GA) | 클라이언트에 응답을 돌려주기 전, HTTP 응답 헤더를 추가/수정/삭제합니다. | set, add, remove |
| URLRewrite | Standard (GA) | 백엔드가 이해할 수 있도록 호스트명(Hostname)이나 URL 경로(Path)를 재작성합니다. | hostname, path |
| RequestRedirect | Standard (GA) | 클라이언트에게 301 이나 302 상태 코드를 반환하여 새로운 URL로 브라우저 이동을 유도합니다. | hostname, path, statusCode |
| RequestMirror | Standard (GA) | 실시간 트래픽을 백엔드로 보내는 동시에, 테스트용 백엔드로 트래픽을 복사(미러링) 전송합니다. | backendRef, percent / fraction (v1.2 추가) |
| ExtensionRef | Core / Custom | Gateway API 표준 스펙 외에 인프라 솔루션(예: Envoy, Istio 등)이 제공하는 커스텀 필터를 플러그인 형태로 장착합니다. | group, kind, name |

HTTPRoute 1 — HTTP(80) → HTTPS 리다이렉트

```yaml
apiVersion: gateway.networking.k8s.io/v1beta1
kind: HTTPRoute
metadata:
  name: redirect-httproute
  namespace: test-contour
spec:
  hostnames:
  - gateway.example.com
  parentRefs:
  - group: gateway.networking.k8s.io
    kind: Gateway
    name: contour          # Contour Gateway 사용(고정값)
    sectionName: http      # Gateway의 80포트 리스너 이름
  rules:
  # HTTP 리스너(80)로 들어온 요청은 HTTPS로 리다이렉트
  - matches:
    - path:
        type: PathPrefix
        value: /
    filters:
    - type: RequestRedirect
      requestRedirect:
        scheme: https
        statusCode: 301
```

HTTPRoute 2 — Method (POST) + Query Parameter 매칭 & URL Rewrite

```yaml
apiVersion: gateway.networking.k8s.io/v1beta1
kind: HTTPRoute
metadata:
  name: parameter-httproute
  namespace: test-contour
spec:
  hostnames:
  - gateway.example.com
  parentRefs:
  - group: gateway.networking.k8s.io
    kind: Gateway
    name: contour          # Contour Gateway 사용(고정값)
    sectionName: https     # Gateway의 443포트 리스너 이름
  rules:
  # --------------------------------------------------
  # Method (POST) + Query Parameter 매칭 & URL Rewrite
  # --------------------------------------------------
  - matches:
    - method: POST
      path:
        type: PathPrefix
        value: /api/v1/data
      queryParams:
      - type: Exact
        name: type
        value: json
    filters:
    - type: URLRewrite
      urlRewrite:
        path:
          type: ReplacePrefixMatch
          replacePrefixMatch: /v1/target-json
    backendRefs:
    - name: whoami-service
      port: 80
```

HTTPRoute 3 — 헤더 매칭 & Request/Response Header 수정

```yaml
apiVersion: gateway.networking.k8s.io/v1beta1
kind: HTTPRoute
metadata:
  name: headers-httproute
  namespace: test-contour
spec:
  hostnames:
  - gateway.example.com
  parentRefs:
  - group: gateway.networking.k8s.io
    kind: Gateway
    name: contour          # Contour Gateway 사용(고정값)
    sectionName: https     # Gateway의 443포트 리스너 이름
  rules:
  # --------------------------------------------------
  # 헤더 매칭 & Request/Response Header 수정 (요청/응답 헤더 추가/삭제)
  # --------------------------------------------------
  - matches:
    - method: GET
      path:
        type: PathPrefix
        value: /admin
      headers:
      - name: X-User-Role
        value: "admin"
    filters:
    - type: RequestHeaderModifier
      requestHeaderModifier:
        set:
        - name: X-Internal-Route
          value: "backend-allowed"
        remove:
        - "X-Token"
    - type: ResponseHeaderModifier
      responseHeaderModifier:
        set:
        - name: "X-Content-Type-Options"
          value: "nosniff"             # 보안 취약점 방어 헤더 추가
        - name: "Cache-Control"
          value: "no-store, max-age=0" # 민감 정보 API 브라우저 캐싱 방지
        remove:
        - "X-Powered-By"               # 백엔드 서버 종류(예: Express, PHP)를 숨기기 위해 응답에서 삭제
        - "server"                     # 인프라 노출 방지를 위해 서버 소프트웨어 이름 삭제
    backendRefs:
    - name: whoami-service
      port: 80
```

HTTPRoute 4 — CORS 정책 (Response Header 직접 주입)

원문은 이 HTTPRoute도 `metadata.name: headers-httproute`로 적혀 있어 3번과 이름이 같다. 원문 그대로 옮겼으며, 함께 적용하려면 이름을 달리해야 한다.

```yaml
apiVersion: gateway.networking.k8s.io/v1beta1
kind: HTTPRoute
metadata:
  name: headers-httproute
  namespace: test-contour
spec:
  hostnames:
  - gateway.example.com
  parentRefs:
  - group: gateway.networking.k8s.io
    kind: Gateway
    name: contour          # Contour Gateway 사용(고정값)
    sectionName: https     # Gateway의 443포트 리스너 이름
  rules:
  # --------------------------------------------------
  # CORS 정책 (Response Header 직접 주입)
  # ResponseHeaderModifier를 사용하여 브라우저용 CORS 응답 헤더 주입
  # --------------------------------------------------
  - matches:
    - path:
        type: PathPrefix
        value: /public
    filters:
    - type: ResponseHeaderModifier   # 응답값에 헤더를 실어 보냄
      responseHeaderModifier:
        set:
        - name: "Access-Control-Allow-Origin"
          value: "https://my-frontend.com"
        - name: "Access-Control-Allow-Methods"
          value: "GET, POST, OPTIONS"
        - name: "Access-Control-Allow-Headers"
          value: "Content-Type, Authorization"
        - name: "Access-Control-Max-Age"
          value: "100"
    backendRefs:
    - name: whoami-service
      port: 80
```

### 4. GRPCRoute 생성

Kubernetes Gateway API 를 통해 라우팅 될 수 있도록 GRPCRoute 정보를 구성해 줘야 합니다.

grpc 서비스 생성 샘플

```yaml
apiVersion: gateway.networking.k8s.io/v1
kind: GRPCRoute
metadata:
  name: grpc-echo-route
  namespace: test-user
  labels:
    app: grpc-echo
spec:
  parentRefs:
  - group: gateway.networking.k8s.io
    kind: Gateway
    name: contour                    # your contour gateway
    namespace: tanzu-system-ingress
    # sectionName: https
  hostnames:
  - "grpc.khtstpc01.sol2.dks.samsungds.net"
  rules:
  - matches:
    - method:
        service: "grpc.reflection.v1alpha.ServerReflection"
    backendRefs:
    - name: grpc-echo-svc
      namespace: test-user
      port: 3000
  - backendRefs:
    - name: grpc-echo-svc
      namespace: test-user
      port: 3000
```

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: grpc-echo
  namespace: test-user
spec:
  selector:
    matchLabels:
      app: grpc-echo
  replicas: 1
  template:
    metadata:
      labels:
        app: grpc-echo
    spec:
      containers:
      - name: grpc-echo
        image: dcr.cloud.samsungds.net/dkssol-cache/ghcr.io/projectcontour/yages:v0.1.0
        ports:
        - containerPort: 9000
          protocol: TCP
        env:
        - name: POD_NAME
          valueFrom:
            fieldRef:
              fieldPath: metadata.name
        - name: NAMESPACE
          valueFrom:
            fieldRef:
              fieldPath: metadata.namespace
        - name: GRPC_ECHO_SERVER
          value: "true"
        - name: SERVICE_NAME
          value: grpc-echo
---
apiVersion: v1
kind: Service

  name: grpc-echo-svc
  namespace: test-user

  type: ClusterIP

    appProtocol: kubernetes.io/h2c

    app: grpc-echo
```

```bash
yages.Echo
```
