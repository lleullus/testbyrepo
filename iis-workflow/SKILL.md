# IIS

One current Main owns the latest request. Do not spawn an Outer Main or add a controller database. Use the user's language. This is a host-independent skill/document workflow using ordinary tools and independent invocations, not an authenticated semantic engine.

## Interpret the current request first

| Request | Authorized path and stop |
| --- | --- |
| Discussion/review/status | Inspect and explain; no implied product mutation or execution of a next pointer. |
| Investigation | Collect bounded evidence and requested handoff; it is not product authority. |
| Thesis only | Define/refine or assess requested meaning, preserve originals and stop. Assessment-only remains read-only. |
| Scope only | Fix current outcome from originals and actual state; stop before methods/implementation. |
| Planning only | Ground Plan plus Assurance Baseline, validate structure and return unresolved premises; no implementation, attack or status write. |
| Implementation only | Current Plan/Baseline and real preconditions → authorized implementation/self-check; Scope stays ready. |
| Assurance only | Bind the exact existing Scope/target; prepare invocation-local Baseline; observations/gates/independent attacks/closure. No fresh implementation Plan prerequisite or automatic repair. |
| Standalone Probe | Bounded user-requested target investigation; canonical Scope may be absent. No delivery completion eligibility. |
| Done Scope diagnosis | Distinguish historical completion from current target; do not reopen/rewrite done. |
| Status-only recording | Consume already current evidence and authority; do not implicitly run implementation or assurance. |
| Build specified outcome | Perform necessary authorized stages until assigned result is met, not merely one internal task. |
| Fail/report, no re-entry or stop | Obey ceiling, stop new work, preserve evidence and contain/settle actual effects. |

Current user instruction overrides historical artifacts and standing preferences. Explicit Thesis intents (start/continue/integrate/assess) refine Thesis-only scope; they are not workflow modes. Deployment, purchases, credentials, destructive effects and operating installation need their own concrete current authority. Cancellation receipt alone is not containment.

## Compact request and selections

Derive assigned outcome, required means versus candidates, stages/effects, stop/continuation ceiling, selected modes/models and observable finish. One paragraph suffices; no persistent mandate/session ledger. Never turn an agent recommendation into user approval.

Preserve explicit current user actor/model/effort/mode or an identifiable user-selected host policy. Ambient defaults are not consent. Before delegated execution ask once only for genuinely missing enabled role fields, or return MODEL_SELECTION_REQUIRED in noninteractive work. Do not ask for disabled/DIRECT roles or advisory discussion. Unavailable capability/model is its actual limit, not an automatic substitute. Probe fan-out and evaluation calls are never silently activated as ordinary Python tests.

An affirmative current `/승인게이트` requires showing the exact request contract and direct approval before dependent planning/delivery mutation; quotation/negation does not activate it. Read-only investigation and owning Thesis storage remain permitted. It creates no per-artifact ceremony. Optional alternative methods/consensus require current authority, not an automatic roster.

## Product and evidence sources

Thesis owns complete product meaning, behavior/UI, failure/recovery/preservation, false-success distinctions and authoritative readback. Reuse sufficient originals; revise only meaning actually changed. Product-Thesis reads its bounded exploration reference. A Brief or investigation is an inspection lens, not an approval or new stage. Preserve complete promises even when current construction is smaller.

Scope at `docs/planning/work/<slug>/SCOPE.md` applies exact bound Thesis and approved Transition sources to current Outcome/Acceptance. Main uses scope-shaper instructions directly; no separate Shaper invocation. Fix one current outcome before methods without recreating Spec/Ticket/Matt/Increment hierarchies. Validate canonical schema/paths/actual source digests, not semantic sufficiency by hash.

An optional approved Transition Baseline retains Block/invariant/order/entry/exit/readback/continuation/abort and atomic boundaries. Presence alone does not activate it or expand the request. Reuse already fixed boundaries rather than reselecting for convenience. Assurance Baseline is an evidence execution method inside Plan (or invocation-local for assurance-only), never Transition or product authority.

Reuse investigation evidence with exact source/readback locators and deciding applicability conditions. Reopen changed load-bearing premises, not the whole repo. A historical dismissal, current source hash or stored done does not prove current behavior. No evidence registry or stale success cache.

## Canonical delivery flow

1. Investigate only deciding facts; perform/reuse sufficient Thesis and applicable approved Transition.
2. Main fixes/reuses exact ready Scope against current state under scope-shaper.
3. Planner writes grounded method plus Assurance Baseline under scope-plan. Check originals/structure/executable preconditions. There is no separate overall method approval role or approval artifact lifecycle.
4. Current authorized implementer changes product/project tooling and self-checks under scope-implement. Preserve correction evidence and non-obvious execution handoff.
5. Seal exact committed source, build artifact/runtime/mechanism and originals under [Assurance](references/assurance.md). No automatic commit. Unsealed target returns TARGET_NOT_SEALED, never a claim that HEAD includes working-tree changes.
6. Acquire required native gates and direct observations on the final execution binding. A failed/unobservable direct result blocks even if other tests pass. Reuse only genuinely attributable same-binding native self-check captures.
7. Dispatch required independent adversarial Prober lanes with surface/budget/isolation boundaries. Preserve hypotheses before narrative disclosure; scout is not given Planner candidate findings. Share safety immediately. This is bounded counterexample search, not every-Acceptance re-adjudication.
8. Fan in every required and actually started invocation and effect unchanged. Run structural evidence closure. No new Aggregator/final judge is introduced.
9. Only current EVIDENCE_COMPLETE plus current user authority, unchanged target/originals, settled effects and requested completion permission permits Main's status-only recording below. Reconcile remaining required outcomes before declaring the whole request complete.

Tools in `tools/assurance.py` perform Baseline/binding/evidence/closure checks and bounded native foreground gate capture. They never select risk/meaning, dispatch agents, repair products, write Scope or authenticate arbitrary JSON. Follow `references/assurance.md` for exact data and CLI. Runtime/production success requires actual authoritative observations; build/lint/no-finding alone is insufficient.

## Main and delegated owners

Before delegation read [Delegated Role Dispatch](references/delegated-role-dispatch.md), the role caller contract and exact applicable projection. Pass original paths/digests, current request/authority/stop/model selection, target and accessible evidence from one source snapshot. A summary is not an original. Scope authoring remains Main work; Product Thesis/investigation delegation obeys their own selection policy.

Main checks actual completed-invocation attribution, currentness, required-result coverage, accessibility, limits and settlement, not a second whole-Scope semantic verdict. Intermediate messages/process exits/label strings alone are not completed evidence. Do not poll normal progress or duplicate workers' execution. Replacement on the same mutable surface waits for settlement or actual containment.

Predeclare lane roster/surfaces; keep started optional lanes, failed/cancelled attempts and their material findings/effects. Different worktrees do not isolate DB/cache/queue/session/provider state. Isolate resources or serialize the irreducible shared boundary. Use native host coordination; no IIS scheduler or runtime plugin is required. Installed bytes, invocation-loaded contract and actual behavior are distinct.

Main's request ownership is not product repair authority. Use the user-selected implementer, including an explicitly selected Main/DIRECT actor, for actual corrections. Forward exact finding/reproducer/raw evidence, current target, regression/sibling guidance and execution prerequisites. Do not repair through source/config/runtime effects disguised as fan-in. Safe read-only inspection, separately authorized containment and status recording remain distinct.

## Re-entry

Route by the decision that must change, not role vocabulary:

- Product promise/policy/success meaning: Product-Thesis owner creates affected immutable revision and bounded ripple analysis. Unrelated revisions do not automatically invalidate bound work.
- Approved transition boundary/order/invariant: its existing authority revises that contract before dependent Scope/method changes.
- Scope omission or current construction choice: Main corrects from adopted originals/current evidence under scope-shaper; no invented Acceptance during probing.
- Method/cause/interface/persistence/readback/target-effect/safety premise: planning owner revises affected Plan/Baseline, preserving old attempts and reasons. No independent approval cycle returns.
- Faithful implementation correction under unchanged material method: existing authorized actor corrects/self-checks. Size/new fact/regression alone is not material revision; preserve why the premise stands.
- Concrete product counterexample: authorized implementer gets usable reproducer/evidence, corrects and hands off exact new target. Reacquire completion evidence on the new binding; previous outputs are navigation, not carried-forward success.
- Observation/oracle/tooling gap: its authorized tooling/evidence owner repairs or acquires the smallest deciding observation. Missing evidence is not automatically a product defect.
- Unknown external/non-idempotent effect: actual effect owner obtains applied/not-applied readback or contains; no blind retry or smaller Scope to hide uncertainty.

A still-running actor may correct invocation-local read-only argument/selector usage with unchanged target/contract/mechanism/assertion and no effect (or attributable settlement), preserving both attempts. This does not reopen a completed actor, relax assertions, substitute identity/state or authorize shared tooling changes.

During normal attacks wait for terminal search/effect settlement before product mutation. Urgent safety/data-loss containment or independent target drift may interrupt; preserve partial evidence and stop/settle without labeling COMPLETE. Fresh invocation preserves selected actor/model/effort unless explicitly changed, not the old invocation lifetime. No-repeat/no-reentry and stage limits still win.

Historical done remains historical if later work regresses it; connect relevant obligations/evidence to current repair, not reopen every prior Scope. A source hash or impact statement does not retain old completion evidence. No LLM evidence-retention approver is introduced.

## Completion recording

Immediately before writing, check current ready Scope/originals, final binding/closure and native host attribution, all started invocation/effect settlement, no unresolved material counterexample/candidate/required observation gap, current user permission and exact requested boundary. Unknown does not become no-finding. Closure is structural evidence completeness, not a semantic credential or permission by itself.

Preserve the ready Scope preimage and exact digest with closure/result references. Use ordinary file tools to change only the single `Status: ready` to `Status: done`. Read back actual bytes, require status-only delta (the helper's recording command can check it), and run canonical Scope validation. Product/Acceptance changes or unexplained concurrent drift are not a recording exception; do not overwrite unrelated changes. Failed/unavailable edit/readback is uncertain/blocked, not done.

Preserve original lane results/raw observations, final source target, closure and actual write/readback separately in existing result locations. Never relabel evidence as executed on a later recording commit. If durable access is unavailable, report it. Do not create a second verdict or completion database.

One Scope success is not automatically the whole user request. Continue only current-authorized remaining required outcomes; stop at requested stage. Cross-invocation auto-continuation needs explicit continuing authority and actual execution capability, not a saved next pointer. Report actual evidence, limits and exact next owner where needed.
