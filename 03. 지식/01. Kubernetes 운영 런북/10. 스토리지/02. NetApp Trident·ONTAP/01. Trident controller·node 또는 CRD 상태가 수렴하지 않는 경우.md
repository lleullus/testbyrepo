# Trident controller·node 또는 CRD 상태가 수렴하지 않는 경우

## 입력값과 빠른 수집

설치 namespace만 최초 입력한다. workload kind/name, controller chain, Pod/container, CSI driver, CR resource와 CRD는 current discovery와 inventory에서 선택한다. 특정 Trident release의 이름·status schema·설치 방식을 다른 환경에 적용하지 않는다.

| 입력 종류 | 변수 | 출처와 gate |
|---|---|---|
| 최초 입력 | `NS` | 승인된 Trident 설치 inventory의 namespace |
| API 확인 자동값 | workload/ReplicaSet/Pod UID·RV·owner, containerID·node, CRD lifecycle | 매 사용 직전 current API에서 갱신 |
| 계산 후보값 | `POD_RE` | workload 이름을 regex escape한 조회 후보. owner chain 확인 전 확정 아님 |
| 운영자 선택값 | workload·Pod·container, CSI driver, CR resource/name/scope·CRD, UTC 창 | 세로 inventory와 discovery를 확인한 뒤 선택 |

### 2. current inventory

세 출력이 모두 성공해야 선택한다. Pod는 container/port, status/containerID, controller owner를 같은 블록으로 보여 준다. Secret data와 전체 manifest는 출력하지 않는다.

`if [ "$INPUT_READY" = true ]; then kubectl get deployments -n "$NS" -o custom-columns='KIND:.kind,NAME:.metadata.name,UID:.metadata.uid,RV:.metadata.resourceVersion,GEN:.metadata.generation,OBSERVED:.status.observedGeneration,DESIRED:.spec.replicas,UPDATED:.status.updatedReplicas,READY:.status.readyReplicas,AVAILABLE:.status.availableReplicas' && kubectl get daemonsets -n "$NS" -o custom-columns='KIND:.kind,NAME:.metadata.name,UID:.metadata.uid,RV:.metadata.resourceVersion,GEN:.metadata.generation,OBSERVED:.status.observedGeneration,DESIRED:.status.desiredNumberScheduled,CURRENT:.status.currentNumberScheduled,UPDATED:.status.updatedNumberScheduled,READY:.status.numberReady,AVAILABLE:.status.numberAvailable,MISSCHEDULED:.status.numberMisscheduled' && kubectl get pods -n "$NS" -o json | jq -r '.items[] | "\n=== Pod: \(.metadata.name) ===\nUID/RV: \(.metadata.uid)/\(.metadata.resourceVersion)\nNode/phase: \(.spec.nodeName // "-") / \(.status.phase // "-")\nController owner: \([.metadata.ownerReferences[]? | select(.controller==true) | "\(.kind)/\(.name)/\(.uid)"] | join(","))\nContainer lifecycle: \([.spec.containers[] as $c | ($c.name) + " image=" + ($c.image // "-") + " ports=" + ([$c.ports[]? | ((.name // "unnamed") + ":" + (.containerPort|tostring))] | join(",")) + " containerID=" + (([.status.containerStatuses[]? | select(.name==$c.name)][0].containerID) // "-") + " ready=" + (([.status.containerStatuses[]? | select(.name==$c.name)][0].ready) // false | tostring)] | join("; "))"' && kubectl api-resources --api-group=trident.netapp.io --verbs=get,list -o wide; fi`

빈 목록은 정상 증거가 아니다. discovery 실패, RBAC, 설치 방식 또는 namespace 불일치를 먼저 구분한다.

### 3. workload·Pod·container 선택과 latest gate

`WORKLOAD_KIND='PASTE_TRIDENT_WORKLOAD_KIND_HERE'; WORKLOAD='PASTE_TRIDENT_WORKLOAD_NAME_HERE'; POD='PASTE_TRIDENT_POD_NAME_HERE'; CONTAINER='PASTE_TRIDENT_CONTAINER_NAME_HERE'; DRIVER='PASTE_TRIDENT_CSI_DRIVER_HERE'`

`refresh_component(){ unset IDENTITY_READY RELATION_READY OWNER_READY CONTAINER_READY NODE_READY HOST_READY TIME_READY ARGUMENT_READY SELECTION_READY AUTH_READY EVIDENCE_READY MUTATION_READY ROLLBACK_READY NORMALIZATION_READY WORKLOAD_UID WORKLOAD_RV WORKLOAD_GEN WORKLOAD_OBSERVED POD_UID POD_RV POD_NODE CONTAINER_ID POD_RE; IDENTITY_READY=false; RELATION_READY=false; OWNER_READY=false; CONTAINER_READY=false; NODE_READY=false; ARGUMENT_READY=false; SELECTION_READY=false; [ "$INPUT_READY" = true ] || return 1; [ "$WORKLOAD_KIND" = deployment ] || [ "$WORKLOAD_KIND" = daemonset ] || { printf '%s\n' '중단: workload kind는 deployment 또는 daemonset' >&2; return 1; }; local w p owner_kind owner_name owner_uid r; w="$(kubectl get "$WORKLOAD_KIND" "$WORKLOAD" -n "$NS" -o json)" || return 1; p="$(kubectl get pod "$POD" -n "$NS" -o json)" || return 1; WORKLOAD_UID="$(jq -r '.metadata.uid' <<<"$w")"; WORKLOAD_RV="$(jq -r '.metadata.resourceVersion' <<<"$w")"; WORKLOAD_GEN="$(jq -r '.metadata.generation' <<<"$w")"; WORKLOAD_OBSERVED="$(jq -r '.status.observedGeneration // 0' <<<"$w")"; owner_kind="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)][0].kind // empty' <<<"$p")"; owner_name="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)][0].name // empty' <<<"$p")"; owner_uid="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)][0].uid // empty' <<<"$p")"; if [ "$WORKLOAD_KIND" = daemonset ]; then [ "$owner_kind" = DaemonSet ] && [ "$owner_name" = "$WORKLOAD" ] && [ "$owner_uid" = "$WORKLOAD_UID" ] || { printf '%s\n' '중단: DaemonSet→Pod owner relation 불일치' >&2; return 1; }; else [ "$owner_kind" = ReplicaSet ] || { printf '%s\n' '중단: Deployment Pod의 controller가 ReplicaSet이 아님' >&2; return 1; }; r="$(kubectl get replicaset "$owner_name" -n "$NS" -o json)" || return 1; [ "$(jq -r '.metadata.uid' <<<"$r")" = "$owner_uid" ] && [ "$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)][0].kind // empty' <<<"$r")" = Deployment ] && [ "$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)][0].name // empty' <<<"$r")" = "$WORKLOAD" ] && [ "$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)][0].uid // empty' <<<"$r")" = "$WORKLOAD_UID" ] || { printf '%s\n' '중단: Deployment→ReplicaSet→Pod relation 불일치' >&2; return 1; }; fi; jq -e --arg c "$CONTAINER" 'any(.spec.containers[]?; .name==$c)' <<<"$p" >/dev/null || return 1; CONTAINER_ID="$(jq -r --arg c "$CONTAINER" '[.status.containerStatuses[]? | select(.name==$c)][0].containerID // empty' <<<"$p")"; [ -n "$CONTAINER_ID" ] || { printf '%s\n' '중단: current running containerID 없음' >&2; return 1; }; POD_UID="$(jq -r '.metadata.uid' <<<"$p")"; POD_RV="$(jq -r '.metadata.resourceVersion' <<<"$p")"; POD_NODE="$(jq -r '.spec.nodeName // empty' <<<"$p")"; POD_RE="^$(printf '%s' "$WORKLOAD" | sed 's/[][\\.^$*+?(){}|]/\\&/g').*$"; IDENTITY_READY=true; RELATION_READY=true; OWNER_READY=true; CONTAINER_READY=true; NODE_READY=true; ARGUMENT_READY=true; SELECTION_READY=true; export WORKLOAD_UID WORKLOAD_RV WORKLOAD_GEN WORKLOAD_OBSERVED POD_UID POD_RV POD_NODE CONTAINER_ID POD_RE; printf 'SELECTION_READY=true workload=%s/%s uid=%s rv=%s gen=%s observed=%s pod=%s uid=%s rv=%s node=%s container=%s containerID=%s regex=%s\n' "$WORKLOAD_KIND" "$WORKLOAD" "$WORKLOAD_UID" "$WORKLOAD_RV" "$WORKLOAD_GEN" "$WORKLOAD_OBSERVED" "$POD" "$POD_UID" "$POD_RV" "$POD_NODE" "$CONTAINER" "$CONTAINER_ID" "$POD_RE"; }`

Pod가 교체되면 이름/UID/containerID를 재사용하지 않는다. current workload controller chain에 속하는 replacement를 inventory에서 다시 선택하고 위 명령을 재실행한다.

### 1. workload와 로그

`if refresh_component; then kubectl get "$WORKLOAD_KIND" "$WORKLOAD" -n "$NS" -o wide && kubectl get pod "$POD" -n "$NS" -o custom-columns='POD:.metadata.name,UID:.metadata.uid,RV:.metadata.resourceVersion,NODE:.spec.nodeName,PHASE:.status.phase,READY:.status.containerStatuses[*].ready,RESTARTS:.status.containerStatuses[*].restartCount,OWNER-KIND:.metadata.ownerReferences[?(@.controller==true)].kind,OWNER:.metadata.ownerReferences[?(@.controller==true)].name,OWNER-UID:.metadata.ownerReferences[?(@.controller==true)].uid'; fi`

`START_INPUT='PASTE_TRIDENT_START_RFC3339_HERE'; END_INPUT='PASTE_TRIDENT_END_RFC3339_HERE'; refresh_time(){ unset TIME_READY START_RFC3339 END_RFC3339 COLLECTED_AT; TIME_READY=false; [[ "$START_INPUT" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] && [[ "$END_INPUT" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] || return 1; local se ee; se="$(date -u -d "$START_INPUT" +%s 2>/dev/null)" || return 1; ee="$(date -u -d "$END_INPUT" +%s 2>/dev/null)" || return 1; START_RFC3339="$(date -u -d "@$se" '+%Y-%m-%dT%H:%M:%SZ')"; END_RFC3339="$(date -u -d "@$ee" '+%Y-%m-%dT%H:%M:%SZ')"; [ "$START_RFC3339" = "$START_INPUT" ] && [ "$END_RFC3339" = "$END_INPUT" ] && [ "$se" -lt "$ee" ] || return 1; COLLECTED_AT="$(date -u '+%Y-%m-%dT%H:%M:%SZ')"; TIME_READY=true; export START_RFC3339 END_RFC3339 COLLECTED_AT; }`

`refresh_auth(){ AUTH_READY=false; [ "$SELECTION_READY" = true ] || return 1; [ "$(kubectl auth can-i get "$WORKLOAD_KIND/$WORKLOAD" -n "$NS")" = yes ] && [ "$(kubectl auth can-i get "pods/$POD" -n "$NS")" = yes ] && [ "$(kubectl auth can-i get "pods/$POD" --subresource=log -n "$NS")" = yes ] || return 1; AUTH_READY=true; }`

`if refresh_component && refresh_time && refresh_auth; then kubectl logs "$POD" -n "$NS" -c "$CONTAINER" --timestamps --since-time="$START_RFC3339" --tail=300 | awk -v end="$END_RFC3339" '$1 < end' | grep -E -i -C 3 'observedGeneration|condition|crd|api|version|register|NodeGetInfo|GetPluginInfo|provision|error|failed|timeout|incompatible'; RC=("${PIPESTATUS[@]}"); if [ "${RC[0]}" -ne 0 ]; then EVIDENCE_READY=false; printf '중단: producer rc=%s\n' "${RC[0]}" >&2; elif [ "${RC[1]}" -ne 0 ]; then EVIDENCE_READY=false; printf '중단: 시간 filter rc=%s\n' "${RC[1]}" >&2; elif [ "${RC[2]}" -eq 1 ]; then EVIDENCE_READY=false; printf '%s\n' '미확정: filter 일치 없음' >&2; elif [ "${RC[2]}" -ne 0 ]; then EVIDENCE_READY=false; printf '중단: 증상 filter rc=%s\n' "${RC[2]}" >&2; else EVIDENCE_READY=true; printf 'EVIDENCE_READY=true pod_uid=%s owner_uid=%s containerID=%s collected=%s\n' "$POD_UID" "$OWNER_UID" "$CONTAINER_ID" "$COLLECTED_AT"; fi; fi`

generation/observedGeneration 수렴은 Pod readiness나 CR 처리 성공을 보장하지 않는다. filter 없음도 오류 부재가 아니다. 민감정보가 보이면 출력을 중단하고 오류 유형·UTC 시각만 기록한다.

### 2. CSI registration

`if refresh_component && [ "$(kubectl auth can-i get "csidrivers.storage.k8s.io/$DRIVER")" = yes ] && [ "$(kubectl auth can-i get "csinodes.storage.k8s.io/$POD_NODE")" = yes ] && [ "$(kubectl auth can-i get "nodes/$POD_NODE")" = yes ]; then NODE_JSON="$(kubectl get node "$POD_NODE" -o json)" && CSINODE_JSON="$(kubectl get csinode "$POD_NODE" -o json)" && [ "$(jq -r '.metadata.name' <<<"$NODE_JSON")" = "$POD_NODE" ] && [ "$(jq -r '.metadata.name' <<<"$CSINODE_JSON")" = "$POD_NODE" ] && kubectl get csidriver "$DRIVER" -o custom-columns='NAME:.metadata.name,UID:.metadata.uid,RV:.metadata.resourceVersion,ATTACH-REQUIRED:.spec.attachRequired,POD-INFO:.spec.podInfoOnMount,FS-GROUP:.spec.fsGroupPolicy' && jq -nr --argjson n "$NODE_JSON" --argjson c "$CSINODE_JSON" --arg d "$DRIVER" '"node=\($n.metadata.name) node-uid=\($n.metadata.uid) machine-id=\($n.status.nodeInfo.machineID) csinode-uid=\($c.metadata.uid) csinode-rv=\($c.metadata.resourceVersion) driver-present=\(any($c.spec.drivers[]?; .name==$d)) topology-keys=\([$c.spec.drivers[]? | select(.name==$d) | .topologyKeys[]?] | join(","))"'; else printf '%s\n' '중단: component 또는 exact Node/CSIDriver/CSINode RBAC·identity gate 실패' >&2; fi`

CSINode entry는 current kubelet registration 상태의 API 표현이며 node plugin process, volume mount, backend 정상을 보장하지 않는다. entry가 없으면 같은 Pod UID/containerID·node·시간의 plugin 로그와 kubelet owner 증거로 이관한다. CRI 확인이 필요하면 kubelet current `containerRuntimeEndpoint` exact 값과 socket provider가 확인된 경우에만 사용하고 기본 socket을 추측하지 않는다.

### 3. CR과 CRD lifecycle

`CR_RESOURCE='PASTE_TRIDENT_API_RESOURCE_HERE'; CR_NAME='PASTE_TRIDENT_CR_NAME_HERE'; CR_SCOPE='PASTE_TRIDENT_CR_SCOPE_HERE'; CRD='PASTE_TRIDENT_CRD_NAME_HERE'`

`refresh_cr(){ unset IDENTITY_READY RELATION_READY OWNER_READY CONTAINER_READY NODE_READY HOST_READY TIME_READY ARGUMENT_READY SELECTION_READY AUTH_READY EVIDENCE_READY MUTATION_READY ROLLBACK_READY NORMALIZATION_READY WORKLOAD_UID WORKLOAD_RV POD_UID POD_RV CONTAINER_ID CR_UID CR_RV CR_API CR_KIND CRD_UID CRD_RV; IDENTITY_READY=false; RELATION_READY=false; ARGUMENT_READY=false; SELECTION_READY=false; [[ "$CR_RESOURCE" =~ ^[a-z0-9.]+$ ]] && [[ "$CRD" =~ ^[a-z0-9.-]+$ ]] || return 1; [ "$CR_SCOPE" = Namespaced ] || [ "$CR_SCOPE" = Cluster ] || return 1; kubectl api-resources --api-group=trident.netapp.io -o name | grep -Fx -- "$CR_RESOURCE" >/dev/null || return 1; local cj dj; if [ "$CR_SCOPE" = Namespaced ]; then cj="$(kubectl get "$CR_RESOURCE" "$CR_NAME" -n "$NS" -o json)" || return 1; else cj="$(kubectl get "$CR_RESOURCE" "$CR_NAME" -o json)" || return 1; fi; dj="$(kubectl get crd "$CRD" -o json)" || return 1; [ "$(jq -r '.spec.group' <<<"$dj")" = trident.netapp.io ] && jq -e '(.spec.versions | type=="array" and length>0)' <<<"$dj" >/dev/null || return 1; CR_UID="$(jq -r '.metadata.uid' <<<"$cj")"; CR_RV="$(jq -r '.metadata.resourceVersion' <<<"$cj")"; CR_API="$(jq -r '.apiVersion' <<<"$cj")"; CR_KIND="$(jq -r '.kind' <<<"$cj")"; CRD_UID="$(jq -r '.metadata.uid' <<<"$dj")"; CRD_RV="$(jq -r '.metadata.resourceVersion' <<<"$dj")"; IDENTITY_READY=true; RELATION_READY=true; ARGUMENT_READY=true; SELECTION_READY=true; export CR_UID CR_RV CR_API CR_KIND CRD_UID CRD_RV; printf 'SELECTION_READY=true cr=%s/%s uid=%s rv=%s api=%s kind=%s crd=%s uid=%s rv=%s scope=%s\n' "$CR_RESOURCE" "$CR_NAME" "$CR_UID" "$CR_RV" "$CR_API" "$CR_KIND" "$CRD" "$CRD_UID" "$CRD_RV" "$CR_SCOPE"; }`

`if refresh_cr; then if [ "$CR_SCOPE" = Namespaced ]; then CR_JSON="$(kubectl get "$CR_RESOURCE" "$CR_NAME" -n "$NS" -o json)"; else CR_JSON="$(kubectl get "$CR_RESOURCE" "$CR_NAME" -o json)"; fi && CRD_JSON="$(kubectl get crd "$CRD" -o json)" && jq '{apiVersion,kind,metadata:{name:.metadata.name,uid:.metadata.uid,resourceVersion:.metadata.resourceVersion,generation:.metadata.generation},status:{status:.status.status,message:.status.message,conditions:.status.conditions,observedGeneration:.status.observedGeneration}}' <<<"$CR_JSON" && jq '{name:.metadata.name,uid:.metadata.uid,resourceVersion:.metadata.resourceVersion,group:.spec.group,versions:[.spec.versions[]|{name,served,storage}],storedVersions:.status.storedVersions,conditions:.status.conditions}' <<<"$CRD_JSON"; fi`

CR schema에 없는 field의 `null`은 정상값이 아니다. 해당 release schema에서 field가 없는지, 권한/API 실패인지 구분한다. `served=false`, storage version 불일치, `storedVersions` 잔류 또는 `Established!=True`면 설치 bundle·conversion·upgrade owner에게 이관한다. CRD delete/reapply로 우회하지 않는다.

## 정확한 RBAC·audit

각 command의 `auth can-i`는 현재 context와 exact verb/resource/namespace에만 유효하며 실제 요청 성공을 보장하지 않는다. 변경 또는 민감한 진단 전 control-plane owner에게 audit record의 실제 subject, impersonation, verb, objectRef, response code와 canonical UTC 시각을 요청한다. request/response body는 저장하지 않는다.

## 상태 변경 분리

이 런북에는 controller/DaemonSet restart, CRD 변경, manifest reapply, upgrade, uninstall/reinstall, `wipeout` 명령을 두지 않는다. 별도 변경은 fresh workload/owner/Pod/containerID/CR/CRD/CSINode evidence, exact RBAC·audit, Trident·storage·workload owner 승인, 변경 창, provisioning/resize/attach in-flight 수와 quorum, 작업 멱등성, 중단 조건, **실제로 검증된** rollback을 요구한다. CRD/API migration과 삭제는 rollback 가능하다고 가정하지 않는다.

## 정상화 검증

`NORMALIZATION_READY=false; if refresh_component; then kubectl get "$WORKLOAD_KIND" "$WORKLOAD" -n "$NS" -o wide && kubectl get pod "$POD" -n "$NS" -o custom-columns='POD:.metadata.name,UID:.metadata.uid,RV:.metadata.resourceVersion,NODE:.spec.nodeName,PHASE:.status.phase,READY:.status.containerStatuses[*].ready,RESTARTS:.status.containerStatuses[*].restartCount'; printf 'component identity gate passed at=%s; CRD, registration, PVC 기능과 재발 관찰은 아직 필요\n' "$(date -u '+%Y-%m-%dT%H:%M:%SZ')"; fi`

교체 Pod는 current owner chain으로 다시 선택하고 old UID/containerID를 폐기한다. component desired/ready와 generation/observedGeneration, CR status/observed generation, CRD served/storage/storedVersions/Established, CSINode driver entry, 새 오류 부재가 모두 수렴해야 한다. 실제 PVC provisioning·mount·resize/read/write가 승인된 표본에서 성공해야 최종 정상화한다. 메트릭 부재는 정상으로 처리하지 않는다.

## 증거 보존과 환경별 미검증

보존: UTC 창, workload/ReplicaSet/Pod UID·RV·owner chain, containerID·node, CR UID·RV/apiVersion/kind/status, CRD UID·RV/served/storage/storedVersions/conditions, CSIDriver/CSINode identity, producer/filter rc, audit exact fields, 승인·변경·기능 결과. 저장 금지: Secret/token/private key, 내부 endpoint, 전체 manifest·전체 로그·credential.

Trident version·support matrix, 설치 방식, CR schema, Snapshot API, controller/node inventory와 kubelet/CRI 경계는 환경별 미검증이다. 현재 release의 공식 support matrix 확인 전 upgrade를 일반 복구로 사용하지 않는다.
