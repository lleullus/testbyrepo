# ONTAP API·SVM·LIF·aggregate 문제로 provisioning이 실패하는 경우

## 입력값과 빠른 수집

PVC UID를 기준으로 `PVC → StorageClass/provisioner → Trident controller owner/container → ONTAP management API → SVM·management LIF·aggregate`를 연결한다. 아직 PV가 없는 정상적인 provisioning 실패를 PV 필수 조건으로 만들지 않는다. volume handle, Secret data, credential header, token, private key와 ONTAP 응답 원문은 출력하거나 저장하지 않는다.

| 입력 종류 | 변수 | 출처와 gate |
|---|---|---|
| 최초 입력 | `NS`, `PVC` | 최초 `ProvisioningFailed`가 발생한 exact namespace/name |
| API 확인 자동값 | PVC/SC/PV UID·RV, provisioner/driver, claim relation | current API 세트를 모두 검증한 뒤에만 등록 |
| 계산 후보값 | `PVC_RE` | PVC 이름을 regex escape한 값. bounded 출력 뒤 로그·PromQL에 사용 |
| 운영자 선택값 | Trident Pod/container, UTC 창, ONTAP HTTPS endpoint·SVM/aggregate UUID | current inventory와 승인된 ONTAP inventory를 확인한 뒤 입력 |

### 1. 실행 위치·도구·최초 identity

Kubernetes와 ONTAP API 명령은 승인된 kubeconfig와 ONTAP 접근 경로가 있는 **같은 작업 PC 또는 bastion의 Bash**에서 실행한다. `127.0.0.1`이나 node shell을 사용하지 않는다. ONTAP 연결은 `작업 host의 curl → 승인된 HTTPS management endpoint → ONTAP REST API`이며 Data LIF에 API를 보내지 않는다.

`TOOLS_READY=false; MISSING=''; for T in kubectl jq sed grep awk date curl mktemp; do command -v "$T" >/dev/null 2>&1 || MISSING="$MISSING $T"; done; if [ -n "${BASH_VERSION:-}" ] && [ -z "$MISSING" ]; then TOOLS_READY=true; printf 'TOOLS_READY=true bash=%s\n' "$BASH_VERSION"; else printf '중단: Bash 또는 도구 누락:%s\n' "$MISSING" >&2; fi`

`unset INPUT_READY IDENTITY_READY RELATION_READY OWNER_READY CONTAINER_READY NODE_READY HOST_READY TIME_READY ARGUMENT_READY SELECTION_READY AUTH_READY EVIDENCE_READY MUTATION_READY ROLLBACK_READY NORMALIZATION_READY PVC_UID PVC_RV SC SC_UID SC_RV PROVISIONER PV PV_UID PV_RV DRIVER PVC_RE CTRL_UID CTRL_RV CTRL_OWNER_KIND CTRL_OWNER_NAME CTRL_OWNER_UID CTRL_CONTAINER_ID CTRL_NODE START_RFC3339 END_RFC3339 COLLECTED_AT ONTAP_READY; NS='PASTE_PROVISIONING_NAMESPACE_HERE'; PVC='PASTE_PROVISIONING_PVC_HERE'; INPUT_READY=false; if [ "$TOOLS_READY" != true ]; then printf '%s\n' '중단: TOOLS_READY가 아니다.' >&2; elif P0="$(kubectl get pvc "$PVC" -n "$NS" -o json)"; then EXPECTED_PVC_UID="$(jq -r '.metadata.uid' <<<"$P0")"; [ -n "$EXPECTED_PVC_UID" ] || { printf '%s\n' '중단: PVC UID 없음' >&2; exit 1; }; INPUT_READY=true; export NS PVC EXPECTED_PVC_UID; printf 'INPUT_READY=true pvc=%s/%s uid=%s\n' "$NS" "$PVC" "$EXPECTED_PVC_UID"; else printf '%s\n' '중단: PVC exact 조회 실패' >&2; fi`

### 2. current PVC·SC·조건부 PV 등록

재실행할 때는 모든 downstream READY와 자동값을 먼저 폐기한다. PVC가 `Pending`이고 PV가 없으면 current PVC·SC까지만 유효하게 등록한다. PV가 있으면 claimRef와 driver까지 일치해야 한다.

`refresh_claim(){ unset IDENTITY_READY RELATION_READY OWNER_READY CONTAINER_READY NODE_READY HOST_READY TIME_READY ARGUMENT_READY SELECTION_READY AUTH_READY EVIDENCE_READY MUTATION_READY ROLLBACK_READY NORMALIZATION_READY PVC_UID PVC_RV SC SC_UID SC_RV PROVISIONER PV PV_UID PV_RV DRIVER PVC_RE ONTAP_READY; IDENTITY_READY=false; RELATION_READY=false; ARGUMENT_READY=false; [ "$INPUT_READY" = true ] || return 1; local p s v; p="$(kubectl get pvc "$PVC" -n "$NS" -o json)" || return 1; [ "$(jq -r '.metadata.uid' <<<"$p")" = "$EXPECTED_PVC_UID" ] || { printf '%s\n' '중단: PVC UID 교체' >&2; return 1; }; SC="$(jq -r '.spec.storageClassName // empty' <<<"$p")"; [ -n "$SC" ] || { printf '%s\n' '중단: StorageClass 없음' >&2; return 1; }; s="$(kubectl get storageclass "$SC" -o json)" || return 1; PVC_UID="$EXPECTED_PVC_UID"; PVC_RV="$(jq -r '.metadata.resourceVersion' <<<"$p")"; SC_UID="$(jq -r '.metadata.uid' <<<"$s")"; SC_RV="$(jq -r '.metadata.resourceVersion' <<<"$s")"; PROVISIONER="$(jq -r '.provisioner // empty' <<<"$s")"; PV="$(jq -r '.spec.volumeName // empty' <<<"$p")"; PVC_RE="$(printf '%s' "$PVC" | sed 's/[][\\.^$*+?(){}|]/\\&/g')"; [ -n "$PROVISIONER" ] || return 1; if [ -n "$PV" ]; then v="$(kubectl get pv "$PV" -o json)" || return 1; [ "$(jq -r '.spec.claimRef.uid // empty' <<<"$v")" = "$PVC_UID" ] && [ "$(jq -r '.spec.claimRef.namespace // empty' <<<"$v")" = "$NS" ] && [ "$(jq -r '.spec.claimRef.name // empty' <<<"$v")" = "$PVC" ] || { printf '%s\n' '중단: PV claimRef 불일치' >&2; return 1; }; DRIVER="$(jq -r '.spec.csi.driver // empty' <<<"$v")"; [ "$DRIVER" = "$PROVISIONER" ] || { printf '%s\n' '중단: SC provisioner/PV driver 불일치' >&2; return 1; }; PV_UID="$(jq -r '.metadata.uid' <<<"$v")"; PV_RV="$(jq -r '.metadata.resourceVersion' <<<"$v")"; fi; IDENTITY_READY=true; RELATION_READY=true; ARGUMENT_READY=true; export PVC_UID PVC_RV SC SC_UID SC_RV PROVISIONER PV PV_UID PV_RV DRIVER PVC_RE; printf 'RELATION_READY=true pvc=%s/%s/%s sc=%s/%s/%s provisioner=%s pv=%s pv_uid=%s driver=%s regex=%s\n' "$NS" "$PVC" "$PVC_UID" "$SC" "$SC_UID" "$SC_RV" "$PROVISIONER" "${PV:--}" "${PV_UID:--}" "${DRIVER:--}" "$PVC_RE"; }`

`if refresh_claim; then kubectl get pvc "$PVC" -n "$NS" -o custom-columns='PVC:.metadata.name,UID:.metadata.uid,RV:.metadata.resourceVersion,PHASE:.status.phase,REQUEST:.spec.resources.requests.storage,SC:.spec.storageClassName,PV:.spec.volumeName,CONDITIONS:.status.conditions[*].type' && kubectl get storageclass "$SC" -o custom-columns='SC:.metadata.name,UID:.metadata.uid,RV:.metadata.resourceVersion,PROVISIONER:.provisioner,BINDING:.volumeBindingMode,RECLAIM:.reclaimPolicy'; if [ -n "$PV" ]; then kubectl get pv "$PV" -o custom-columns='PV:.metadata.name,UID:.metadata.uid,RV:.metadata.resourceVersion,PHASE:.status.phase,CLAIM-NS:.spec.claimRef.namespace,CLAIM:.spec.claimRef.name,CLAIM-UID:.spec.claimRef.uid,DRIVER:.spec.csi.driver'; fi; fi`

`Pending`은 `WaitForFirstConsumer`의 정상 중간 상태일 수 있다. `Bound`와 PV 존재도 ONTAP create·mount·실제 workload 기능을 보장하지 않는다.

| 지금 보이는 것 | 먼저 볼 것 | 그다음 어디를 볼지 | 상세 절 |

### 1. Event·Trident request

UTC 창과 현재 controller Pod/container를 inventory에서 선택한다. controller Pod는 current controller owner 객체와 containerID를 다시 확인한다.

`TRIDENT_NS='PASTE_PROVISIONER_TRIDENT_NAMESPACE_HERE'; CTRL_POD='PASTE_PROVISIONER_CONTROLLER_POD_HERE'; CTRL_CONTAINER='PASTE_PROVISIONER_CONTROLLER_CONTAINER_HERE'; START_INPUT='PASTE_PROVISIONER_START_RFC3339_HERE'; END_INPUT='PASTE_PROVISIONER_END_RFC3339_HERE'`

`refresh_time(){ unset TIME_READY EVIDENCE_READY START_RFC3339 END_RFC3339 COLLECTED_AT; TIME_READY=false; [[ "$START_INPUT" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] && [[ "$END_INPUT" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] || return 1; local s e; s="$(date -u -d "$START_INPUT" +%s 2>/dev/null)" || return 1; e="$(date -u -d "$END_INPUT" +%s 2>/dev/null)" || return 1; START_RFC3339="$(date -u -d "@$s" '+%Y-%m-%dT%H:%M:%SZ')"; END_RFC3339="$(date -u -d "@$e" '+%Y-%m-%dT%H:%M:%SZ')"; [ "$START_RFC3339" = "$START_INPUT" ] && [ "$END_RFC3339" = "$END_INPUT" ] && [ "$s" -lt "$e" ] || return 1; COLLECTED_AT="$(date -u '+%Y-%m-%dT%H:%M:%SZ')"; TIME_READY=true; export START_RFC3339 END_RFC3339 COLLECTED_AT; }`

`refresh_controller(){ unset OWNER_READY CONTAINER_READY NODE_READY SELECTION_READY AUTH_READY EVIDENCE_READY CTRL_UID CTRL_RV CTRL_OWNER_KIND CTRL_OWNER_NAME CTRL_OWNER_UID CTRL_CONTAINER_ID CTRL_NODE; OWNER_READY=false; CONTAINER_READY=false; NODE_READY=false; SELECTION_READY=false; [ "$RELATION_READY" = true ] || return 1; local p ref o; p="$(kubectl get pod "$CTRL_POD" -n "$TRIDENT_NS" -o json)" || return 1; jq -e --arg c "$CTRL_CONTAINER" 'any(.spec.containers[]?; .name==$c)' <<<"$p" >/dev/null || return 1; CTRL_UID="$(jq -r '.metadata.uid' <<<"$p")"; CTRL_RV="$(jq -r '.metadata.resourceVersion' <<<"$p")"; CTRL_CONTAINER_ID="$(jq -r --arg c "$CTRL_CONTAINER" '[.status.containerStatuses[]? | select(.name==$c)][0].containerID // empty' <<<"$p")"; CTRL_NODE="$(jq -r '.spec.nodeName // empty' <<<"$p")"; ref="$(jq -c '[.metadata.ownerReferences[]? | select(.controller==true)][0] // empty' <<<"$p")"; [ -n "$CTRL_CONTAINER_ID" ] && [ -n "$ref" ] || return 1; CTRL_OWNER_KIND="$(jq -r '.kind' <<<"$ref")"; CTRL_OWNER_NAME="$(jq -r '.name' <<<"$ref")"; CTRL_OWNER_UID="$(jq -r '.uid' <<<"$ref")"; o="$(kubectl get "$CTRL_OWNER_KIND" "$CTRL_OWNER_NAME" -n "$TRIDENT_NS" -o json)" || return 1; [ "$(jq -r '.metadata.uid' <<<"$o")" = "$CTRL_OWNER_UID" ] || return 1; OWNER_READY=true; CONTAINER_READY=true; NODE_READY=true; SELECTION_READY=true; export CTRL_UID CTRL_RV CTRL_OWNER_KIND CTRL_OWNER_NAME CTRL_OWNER_UID CTRL_CONTAINER_ID CTRL_NODE; printf 'SELECTION_READY=true controller=%s/%s uid=%s rv=%s owner=%s/%s/%s node=%s container=%s containerID=%s\n' "$TRIDENT_NS" "$CTRL_POD" "$CTRL_UID" "$CTRL_RV" "$CTRL_OWNER_KIND" "$CTRL_OWNER_NAME" "$CTRL_OWNER_UID" "$CTRL_NODE" "$CTRL_CONTAINER" "$CTRL_CONTAINER_ID"; }`

`refresh_auth(){ AUTH_READY=false; [ "$(kubectl auth can-i get "persistentvolumeclaims/$PVC" -n "$NS")" = yes ] && [ "$(kubectl auth can-i list events -n "$NS")" = yes ] && [ "$(kubectl auth can-i get "pods/$CTRL_POD" -n "$TRIDENT_NS")" = yes ] && [ "$(kubectl auth can-i get "pods/$CTRL_POD" --subresource=log -n "$TRIDENT_NS")" = yes ] || return 1; AUTH_READY=true; }`

`if refresh_claim && refresh_time && refresh_controller && refresh_auth; then kubectl get events -n "$NS" --field-selector "involvedObject.kind=PersistentVolumeClaim,involvedObject.name=$PVC,involvedObject.uid=$PVC_UID" -o json | jq -r --arg s "$START_RFC3339" --arg e "$END_RFC3339" '.items[] | (.eventTime // .series.lastObservedTime // .lastTimestamp // .firstTimestamp // .metadata.creationTimestamp) as $t | select($t >= $s and $t < $e) | select(.reason=="ProvisioningFailed" or (.message|test("failed to provision|CreateVolume|unauthorized|permission|SVM|aggregate|quota|space|timeout";"i"))) | "time=\($t) reason=\(.reason) count=\(.series.count // .count // 1) message=\(.message)"' | grep -E -i -C 1 'ProvisioningFailed|failed to provision|CreateVolume|unauthorized|permission|SVM|aggregate|quota|space|timeout'; RC=("${PIPESTATUS[@]}"); if [ "${RC[0]}" -ne 0 ] || [ "${RC[1]}" -ne 0 ]; then EVIDENCE_READY=false; printf '중단: Event producer/parser 실패 producer=%s parser=%s\n' "${RC[0]}" "${RC[1]}" >&2; elif [ "${RC[2]}" -eq 1 ]; then EVIDENCE_READY=false; printf '%s\n' '미확정: current UID·시간 창의 Event 일치 없음' >&2; elif [ "${RC[2]}" -ne 0 ]; then EVIDENCE_READY=false; printf '중단: Event filter 실패 rc=%s\n' "${RC[2]}" >&2; else EVIDENCE_READY=true; printf 'EVIDENCE_READY=true pvc_uid=%s collected=%s\n' "$PVC_UID" "$COLLECTED_AT"; fi; fi`

`if refresh_claim && refresh_time && refresh_controller && refresh_auth; then kubectl logs "$CTRL_POD" -n "$TRIDENT_NS" -c "$CTRL_CONTAINER" --timestamps --since-time="$START_RFC3339" --tail=400 | awk -v end="$END_RFC3339" '$1 < end' | grep -E -i -C 3 "$PVC_RE|CreateVolume|provision|401|403|unauthorized|permission denied|forbidden|timeout|SVM|aggregate|quota|capacity|error"; RC=("${PIPESTATUS[@]}"); if [ "${RC[0]}" -ne 0 ] || [ "${RC[1]}" -ne 0 ]; then EVIDENCE_READY=false; printf '중단: log producer/time filter 실패 producer=%s time=%s\n' "${RC[0]}" "${RC[1]}" >&2; elif [ "${RC[2]}" -eq 1 ]; then EVIDENCE_READY=false; printf '%s\n' '미확정: controller filter 일치 없음' >&2; elif [ "${RC[2]}" -ne 0 ]; then EVIDENCE_READY=false; printf '중단: 증상 filter 실패 rc=%s\n' "${RC[2]}" >&2; else EVIDENCE_READY=true; printf 'EVIDENCE_READY=true pvc_uid=%s controller_uid=%s owner_uid=%s containerID=%s collected=%s\n' "$PVC_UID" "$CTRL_UID" "$CTRL_OWNER_UID" "$CTRL_CONTAINER_ID" "$COLLECTED_AT"; fi; fi`

producer 실패와 no-match는 정상으로 해석하지 않는다. 로그에 credential·token·내부 주소·개인정보가 보이면 출력을 중단하고 UTC 시각, PVC UID, RPC와 redacted 오류 유형만 기록한다.

### 2. ONTAP management API

현재 ONTAP version이 REST 경로를 지원하고, 승인된 curl config가 CA 검증과 read-only 인증을 제공할 때만 사용한다. config 경로는 작업 host의 절대경로이며 내용을 출력하지 않는다. `-k`로 TLS 검증을 끄지 않는다.

`ONTAP_BASE_URL='PASTE_ONTAP_HTTPS_BASE_URL_HERE'; ONTAP_CURL_CONFIG='PASTE_ONTAP_CURL_CONFIG_PATH_HERE'; SVM_UUID='PASTE_ONTAP_SVM_UUID_HERE'`

`validate_ontap(){ unset ONTAP_READY HOST_READY AUTH_READY; ONTAP_READY=false; HOST_READY=false; AUTH_READY=false; [ "$RELATION_READY" = true ] && [ "$TIME_READY" = true ] || return 1; [[ "$ONTAP_BASE_URL" =~ ^https://[A-Za-z0-9._:-]+$ ]] && [[ "$SVM_UUID" =~ ^[A-Fa-f0-9-]+$ ]] && [[ "$ONTAP_CURL_CONFIG" == /* ]] && [ -f "$ONTAP_CURL_CONFIG" ] && [ -r "$ONTAP_CURL_CONFIG" ] || return 1; HOST_READY=true; AUTH_READY=true; ONTAP_READY=true; }`

`ontap_get(){ local path="$1" filter="$2" body code rc; refresh_claim && refresh_time && validate_ontap || { printf '%s\n' '중단: current claim/time/ONTAP READY 실패' >&2; return 1; }; body="$(mktemp)" || return 1; code="$(curl --config "$ONTAP_CURL_CONFIG" --silent --show-error --max-time 15 -o "$body" -w '%{http_code}' "$ONTAP_BASE_URL$path")"; rc=$?; if [ "$rc" -ne 0 ]; then printf '중단: ONTAP transport/TLS 실패 rc=%s\n' "$rc" >&2; elif [ "$code" != 200 ]; then printf '중단: ONTAP HTTP 실패 code=%s path=%s\n' "$code" "$path" >&2; rc=1; elif ! jq -e 'type=="object"' "$body" >/dev/null; then printf '%s\n' '중단: ONTAP JSON API 응답 아님' >&2; rc=1; else jq "$filter" "$body"; rc=$?; fi; rm -f "$body"; return "$rc"; }`

`ontap_get "/api/svm/svms/$SVM_UUID" '{uuid,name,state,subtype}'`

`ontap_get "/api/network/ip/interfaces?svm.uuid=$SVM_UUID&services=data_core,data_nfs&fields=uuid,name,enabled,services,service_policy" '{num_records,records:[.records[]|{uuid,name,enabled,services,service_policy}]}'`

SVM `online`과 management API HTTP 200은 create 권한·aggregate capacity·Data LIF NFS 기능을 보장하지 않는다. `401/403`은 인증·API role, timeout/TLS는 management network·certificate, 빈 `records`는 query/schema/권한/실제 LIF 부재를 구분한다. 이 API 응답을 Data LIF mount 성공 증거로 사용하지 않는다.

### 3. aggregate와 create capacity

Trident의 redacted request/inventory가 실제 selected aggregate를 확인한 경우에만 UUID를 넣는다. 다른 aggregate로 임의 우회하지 않는다.

`AGGREGATE_UUID='PASTE_ONTAP_AGGREGATE_UUID_HERE'`

`if [[ "$AGGREGATE_UUID" =~ ^[A-Fa-f0-9-]+$ ]] && refresh_claim && refresh_time && validate_ontap; then ontap_get "/api/storage/aggregates/$AGGREGATE_UUID?fields=uuid,name,state,space" '{uuid,name,state,space:{block_storage:.space.block_storage}}'; else printf '%s\n' '중단: aggregate UUID 또는 current READY 실패' >&2; fi`

볼 것은 selected aggregate UUID, `online`, usable/available space와 같은 UTC 창의 create request 크기다. ONTAP aggregate 여유만으로 SVM quota, qtree/volume 제한, snapshot reserve와 정책 headroom을 보장하지 않는다. API field가 없거나 권한상 redacted이면 0으로 간주하지 않고 ONTAP capacity owner에게 exact UUID·HTTP status·관측 시각을 넘긴다.

## 원인 확정 기준

- 인증·권한: current PVC UID의 CreateVolume과 ONTAP 단일 요청에서 `401/403` 또는 role denial이 같은 창에 일치한다.
- SVM/LIF: selected SVM UUID가 backend inventory와 다르거나 offline이고 Trident 오류가 같은 request를 가리킨다.
- capacity/quota: selected aggregate UUID와 request size가 일치하며 usable space 또는 승인 quota가 직접 부족하다.
- 미확정: PVC UID, controller UID/containerID, request 시각, SVM/aggregate UUID 중 하나라도 연결되지 않는다.

## Prometheus 쿼리 생성

metric과 label이 실제 수집되는 경우에만 출력된 완성 쿼리를 사용한다. 빈 결과는 0이나 정상 상태가 아니다.

`if refresh_claim; then printf 'kube_persistentvolumeclaim_status_phase{namespace="%s",persistentvolumeclaim=~"^%s$",phase="Pending"}==1\n' "$NS" "$PVC_RE"; printf 'time()-kube_persistentvolumeclaim_created{namespace="%s",persistentvolumeclaim=~"^%s$"}\n' "$NS" "$PVC_RE"; fi`

## 상태 변경·rollback 경계

이 런북에는 backend/StorageClass/Secret/ONTAP policy 변경, PVC 삭제·재생성, 수동 volume create, Trident restart 명령을 두지 않는다. 별도 제품 절차는 fresh PVC/SC/PV/controller/SVM/aggregate identity, 단일 auditID의 timestamp·verb·resource/subresource·namespace/name·requestURI·status와 current lifecycle UID 관계, exact RBAC subject, 승인 ID, 동시 provisioning과 duplicate-volume 방지, 멱등성, 변경 창, 중단 조건과 실제 검증된 rollback을 요구한다. PVC 삭제나 이미 생성된 volume 삭제는 rollback으로 간주하지 않는다.

## 정상화 검증

교체 controller Pod의 이름·UID·containerID는 재사용하지 않는다. current owner chain에서 다시 선택하고 `refresh_claim`, `refresh_controller`, 시간·권한 gate를 새로 통과한다. PVC/PV가 새로 생기면 새 PV UID와 claimRef UID를 등록한다.

`NORMALIZATION_READY=false; if refresh_claim && refresh_time && refresh_controller && refresh_auth; then kubectl get pvc "$PVC" -n "$NS" -o custom-columns='PVC:.metadata.name,UID:.metadata.uid,RV:.metadata.resourceVersion,PHASE:.status.phase,SC:.spec.storageClassName,PV:.spec.volumeName,CONDITIONS:.status.conditions[*].type' && { [ -z "$PV" ] || kubectl get pv "$PV" -o custom-columns='PV:.metadata.name,UID:.metadata.uid,RV:.metadata.resourceVersion,CLAIM-UID:.spec.claimRef.uid,DRIVER:.spec.csi.driver'; }; printf 'current object gate passed at=%s; functional and recurrence gates are still required\n' "$COLLECTED_AT"; fi`

최종 `NORMALIZATION_READY=true`는 승인 관찰 창에 새 `ProvisioningFailed`·Trident create 오류가 없고, 단일 PV/ONTAP volume mapping에 duplicate가 없으며, SVM/aggregate/quota가 정상이고 실제 workload mount/read/write가 성공한 뒤에만 운영 기록에서 승인한다. 명령 성공이나 `Bound` 하나만으로 승인하지 않는다.

## 증거·감사·미검증

보존: canonical UTC 창, PVC/SC/조건부 PV UID·RV와 relation, controller Pod·owner UID/containerID, redacted RPC·auditID, ONTAP HTTP status, SVM/aggregate UUID와 상태 판정, 승인·rollback·기능 결과. 저장 금지: volume handle 원문, Secret data, curl config 내용, authorization header, token/private key, 내부 주소와 전체 API body·로그.

Kubernetes와 `kubectl`은 `1.26.x` 기준이다. Trident/ONTAP version·REST field, backend schema, management endpoint, API role, SVM/LIF/aggregate/quota 모델과 metrics는 환경별 미검증이다. 실제 version이 위 REST API를 지원하지 않으면 URI를 추측하지 않고 해당 ONTAP owner의 승인 read-only surface로 같은 identity 필드를 확인한다.
