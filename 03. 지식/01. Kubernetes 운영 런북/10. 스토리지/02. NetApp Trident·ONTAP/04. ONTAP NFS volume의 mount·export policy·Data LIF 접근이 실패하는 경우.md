# ONTAP NFS volume의 mount·export policy·Data LIF 접근이 실패하는 경우

## 입력값과 빠른 수집

current identity를 `Pod/owner → PVC → PV/CSI driver → Trident node Pod/container → Node UID/machineID → NFS Data LIF·junction·export policy` 순서로 연결한다. ONTAP management LIF는 API plane, Data LIF는 NFS data plane이다. 서로 바꾸거나 volume handle, client IP/CIDR, Secret·credential 원문을 티켓에 저장하지 않는다.

| 입력 종류 | 변수 | 출처와 gate |
|---|---|---|
| 최초 입력 | `NS`, `POD` | `FailedMount`가 발생한 exact Pod namespace/name |
| API 확인 자동값 | Pod/owner/PVC/PV UID·RV, driver, node UID/machineID | current API 관계가 모두 맞은 뒤 등록 |
| 계산 후보값 | `POD_RE`, `PVC_RE` | literal 이름을 regex escape한 값. bounded 출력 뒤 쿼리에 사용 |
| 운영자 선택값 | PVC, Trident node Pod/container, UTC 창, 승인 SSH host, Data LIF·junction·mount target, ONTAP UUID | Event·CSI·inventory의 current relation을 확인한 뒤 입력 |

### 1. 실행 위치·도구·Pod identity

Kubernetes 명령은 승인된 kubeconfig가 있는 같은 작업 PC 또는 bastion의 Bash에서 실행한다. node 명령은 승인 host로 SSH한 뒤 원격 hostname과 `/etc/machine-id`를 current Kubernetes Node와 다시 대조한다. 작업 PC 변수가 SSH에 자동 전달된다고 가정하지 않고 positional argument로 넘긴다.

`TOOLS_READY=false; MISSING=''; for T in kubectl jq sed grep awk date ssh curl mktemp; do command -v "$T" >/dev/null 2>&1 || MISSING="$MISSING $T"; done; if [ -n "${BASH_VERSION:-}" ] && [ -z "$MISSING" ]; then TOOLS_READY=true; printf 'TOOLS_READY=true bash=%s\n' "$BASH_VERSION"; else printf '중단: Bash 또는 도구 누락:%s\n' "$MISSING" >&2; fi`

### 2. PVC 후보와 current storage relation

먼저 current Pod의 PVC 후보를 관계가 보존된 블록으로 본다. 복수 PVC면 Event의 volume 이름과 Pod spec을 대조하고 mount 실패 대상 하나를 선택한다.

`if [ "$INPUT_READY" = true ]; then kubectl get pod "$POD" -n "$NS" -o json | jq -r --arg uid "$EXPECTED_POD_UID" 'select(.metadata.uid==$uid) | "=== Pod: \(.metadata.name) ===\nUID/RV: \(.metadata.uid)/\(.metadata.resourceVersion)\nNode: \(.spec.nodeName // "-")\nOwner: \([.metadata.ownerReferences[]? | select(.controller==true) | "\(.kind)/\(.name)/\(.uid)"] | join(","))\nPVC 후보: \([.spec.volumes[]? | select(.persistentVolumeClaim != null) | "volume=\(.name),pvc=\(.persistentVolumeClaim.claimName)"] | join("; "))"'; fi`

`PVC='PASTE_NFS_PVC_HERE'`

`if refresh_storage; then kubectl get pod "$POD" -n "$NS" -o custom-columns='POD:.metadata.name,UID:.metadata.uid,RV:.metadata.resourceVersion,NODE:.spec.nodeName,PHASE:.status.phase,OWNER-KIND:.metadata.ownerReferences[?(@.controller==true)].kind,OWNER:.metadata.ownerReferences[?(@.controller==true)].name,OWNER-UID:.metadata.ownerReferences[?(@.controller==true)].uid' && kubectl get pvc "$PVC" -n "$NS" -o custom-columns='PVC:.metadata.name,UID:.metadata.uid,RV:.metadata.resourceVersion,PHASE:.status.phase,PV:.spec.volumeName,SC:.spec.storageClassName,ACCESS:.spec.accessModes' && kubectl get pv "$PV" -o custom-columns='PV:.metadata.name,UID:.metadata.uid,RV:.metadata.resourceVersion,CLAIM-NS:.spec.claimRef.namespace,CLAIM:.spec.claimRef.name,CLAIM-UID:.spec.claimRef.uid,DRIVER:.spec.csi.driver'; fi`

PV volume handle 원문은 출력하지 않는다. `Bound`, CSIDriver 존재와 `CSINode` entry는 NFS route·export policy·mount 성공을 보장하지 않는다.

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | current Pod UID에 `FailedMount`, `NodePublishVolume`, `mount.nfs`, `access denied`, route/timeout, junction 오류가 발생한다. |
| 적용 | Bound PVC/PV와 Trident CSI driver, target node, Data LIF·junction·policy를 연결할 수 있다. |
| 제외 | create provisioning은 [[03. ONTAP API·SVM·LIF·aggregate 문제로 provisioning이 실패하는 경우]], attach/Multi-Attach는 [[03. VolumeAttachment가 수렴하지 않거나 Multi-Attach가 발생하는 경우]], 일반 mount source는 [[16. Linux 기반/04. 디스크·파일시스템·입출력/06. 예상한 mount가 없거나 source·option이 다른 경우|Linux mount 런북]]으로 이동한다. |

검색 문자열: `FailedMount`, `MountVolume.SetUp failed`, `NodePublishVolume`, `mount.nfs`, `permission denied`, `access denied`, `No route to host`, `Connection timed out`, `Connection refused`, `Stale file handle`, `junction`, `nfsvers`.

## 관측별 진단 경로

| 지금 보이는 것 | 먼저 볼 것 | 그다음 어디를 볼지 | 상세 절 |
|---|---|---|---|
| `access denied`·`permission denied` | Data LIF·junction·client match | export policy·Unix permission | [[#2. Data LIF·export policy]] |
| route·timeout·refused | target node source route와 NFS service | network/ONTAP service owner | [[#3. 승인 node 점검]] |
| `not found`·stale handle | PV mapping과 volume UUID·junction | ONTAP volume owner | [[#2. Data LIF·export policy]] |
| `mount.nfs`·option 오류 | current node plugin log와 actual mount | OS NFS client/driver option owner | [[#1. Event·CSI node evidence]], [[#3. 승인 node 점검]] |

### 1. Event·CSI node evidence

target node에 실제 배치된 Trident node Pod와 container를 current inventory에서 선택한다. container 이름을 추측하거나 첫 container를 자동 선택하지 않는다.

`TRIDENT_NS='PASTE_NFS_TRIDENT_NAMESPACE_HERE'; NODE_POD='PASTE_NFS_NODE_POD_HERE'; NODE_CONTAINER='PASTE_NFS_NODE_CONTAINER_HERE'; START_INPUT='PASTE_NFS_START_RFC3339_HERE'; END_INPUT='PASTE_NFS_END_RFC3339_HERE'`

`refresh_time(){ unset TIME_READY EVIDENCE_READY START_RFC3339 END_RFC3339 COLLECTED_AT; TIME_READY=false; [[ "$START_INPUT" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] && [[ "$END_INPUT" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] || return 1; local s e; s="$(date -u -d "$START_INPUT" +%s 2>/dev/null)" || return 1; e="$(date -u -d "$END_INPUT" +%s 2>/dev/null)" || return 1; START_RFC3339="$(date -u -d "@$s" '+%Y-%m-%dT%H:%M:%SZ')"; END_RFC3339="$(date -u -d "@$e" '+%Y-%m-%dT%H:%M:%SZ')"; [ "$START_RFC3339" = "$START_INPUT" ] && [ "$END_RFC3339" = "$END_INPUT" ] && [ "$s" -lt "$e" ] || return 1; COLLECTED_AT="$(date -u '+%Y-%m-%dT%H:%M:%SZ')"; TIME_READY=true; export START_RFC3339 END_RFC3339 COLLECTED_AT; }`

`refresh_node_plugin(){ unset CONTAINER_READY SELECTION_READY AUTH_READY EVIDENCE_READY NODE_POD_UID NODE_POD_RV NODE_OWNER_KIND NODE_OWNER_NAME NODE_OWNER_UID NODE_CONTAINER_ID; CONTAINER_READY=false; SELECTION_READY=false; [ "$RELATION_READY" = true ] || return 1; local p ref o; p="$(kubectl get pod "$NODE_POD" -n "$TRIDENT_NS" -o json)" || return 1; [ "$(jq -r '.spec.nodeName // empty' <<<"$p")" = "$NODE" ] || { printf '%s\n' '중단: node plugin Pod가 target node와 다름' >&2; return 1; }; jq -e --arg c "$NODE_CONTAINER" 'any(.spec.containers[]?; .name==$c)' <<<"$p" >/dev/null || return 1; NODE_POD_UID="$(jq -r '.metadata.uid' <<<"$p")"; NODE_POD_RV="$(jq -r '.metadata.resourceVersion' <<<"$p")"; NODE_CONTAINER_ID="$(jq -r --arg c "$NODE_CONTAINER" '[.status.containerStatuses[]? | select(.name==$c)][0].containerID // empty' <<<"$p")"; ref="$(jq -c '[.metadata.ownerReferences[]? | select(.controller==true)][0] // empty' <<<"$p")"; [ -n "$NODE_CONTAINER_ID" ] && [ -n "$ref" ] || return 1; NODE_OWNER_KIND="$(jq -r '.kind' <<<"$ref")"; NODE_OWNER_NAME="$(jq -r '.name' <<<"$ref")"; NODE_OWNER_UID="$(jq -r '.uid' <<<"$ref")"; o="$(kubectl get "$NODE_OWNER_KIND" "$NODE_OWNER_NAME" -n "$TRIDENT_NS" -o json)" || return 1; [ "$(jq -r '.metadata.uid' <<<"$o")" = "$NODE_OWNER_UID" ] || return 1; CONTAINER_READY=true; SELECTION_READY=true; export NODE_POD_UID NODE_POD_RV NODE_OWNER_KIND NODE_OWNER_NAME NODE_OWNER_UID NODE_CONTAINER_ID; printf 'SELECTION_READY=true nodePod=%s/%s uid=%s rv=%s owner=%s/%s/%s node=%s container=%s containerID=%s\n' "$TRIDENT_NS" "$NODE_POD" "$NODE_POD_UID" "$NODE_POD_RV" "$NODE_OWNER_KIND" "$NODE_OWNER_NAME" "$NODE_OWNER_UID" "$NODE" "$NODE_CONTAINER" "$NODE_CONTAINER_ID"; }`

`refresh_auth(){ AUTH_READY=false; [ "$(kubectl auth can-i get "pods/$POD" -n "$NS")" = yes ] && [ "$(kubectl auth can-i list events -n "$NS")" = yes ] && [ "$(kubectl auth can-i get "pods/$NODE_POD" -n "$TRIDENT_NS")" = yes ] && [ "$(kubectl auth can-i get "pods/$NODE_POD" --subresource=log -n "$TRIDENT_NS")" = yes ] || return 1; AUTH_READY=true; }`

`if refresh_storage && refresh_time && refresh_node_plugin && refresh_auth; then kubectl get events -n "$NS" --field-selector "involvedObject.kind=Pod,involvedObject.name=$POD,involvedObject.uid=$POD_UID" -o json | jq -r --arg s "$START_RFC3339" --arg e "$END_RFC3339" '.items[] | (.eventTime // .series.lastObservedTime // .lastTimestamp // .firstTimestamp // .metadata.creationTimestamp) as $t | select($t >= $s and $t < $e) | select(.reason=="FailedMount" or (.message|test("MountVolume|NodePublishVolume|mount.nfs|permission|access denied|route|timeout|refused|stale|junction";"i"))) | "time=\($t) reason=\(.reason) count=\(.series.count // .count // 1) message=\(.message)"' | grep -E -i -C 1 'FailedMount|MountVolume|NodePublishVolume|mount.nfs|permission|access denied|route|timeout|refused|stale|junction'; RC=("${PIPESTATUS[@]}"); if [ "${RC[0]}" -ne 0 ] || [ "${RC[1]}" -ne 0 ]; then EVIDENCE_READY=false; printf '중단: Event producer/parser 실패 producer=%s parser=%s\n' "${RC[0]}" "${RC[1]}" >&2; elif [ "${RC[2]}" -eq 1 ]; then EVIDENCE_READY=false; printf '%s\n' '미확정: current Pod UID·시간 창의 Event 없음' >&2; elif [ "${RC[2]}" -ne 0 ]; then EVIDENCE_READY=false; printf '중단: Event filter 실패 rc=%s\n' "${RC[2]}" >&2; else EVIDENCE_READY=true; printf 'EVIDENCE_READY=true pod_uid=%s collected=%s\n' "$POD_UID" "$COLLECTED_AT"; fi; fi`

`if refresh_storage && refresh_time && refresh_node_plugin && refresh_auth; then kubectl logs "$NODE_POD" -n "$TRIDENT_NS" -c "$NODE_CONTAINER" --timestamps --since-time="$START_RFC3339" --tail=400 | awk -v end="$END_RFC3339" '$1 < end' | grep -E -i -C 3 "$POD_RE|$PVC_RE|NodePublishVolume|mount|nfs|export|junction|permission|timeout|route|refused|stale|error"; RC=("${PIPESTATUS[@]}"); if [ "${RC[0]}" -ne 0 ] || [ "${RC[1]}" -ne 0 ]; then EVIDENCE_READY=false; printf '중단: log producer/time filter 실패 producer=%s time=%s\n' "${RC[0]}" "${RC[1]}" >&2; elif [ "${RC[2]}" -eq 1 ]; then EVIDENCE_READY=false; printf '%s\n' '미확정: CSI node filter 일치 없음' >&2; elif [ "${RC[2]}" -ne 0 ]; then EVIDENCE_READY=false; printf '중단: 증상 filter 실패 rc=%s\n' "${RC[2]}" >&2; else EVIDENCE_READY=true; printf 'EVIDENCE_READY=true pod_uid=%s node_uid=%s node_pod_uid=%s owner_uid=%s containerID=%s collected=%s\n' "$POD_UID" "$NODE_UID" "$NODE_POD_UID" "$NODE_OWNER_UID" "$NODE_CONTAINER_ID" "$COLLECTED_AT"; fi; fi`

no-match는 오류 부재가 아니다. Secret·credential·client address가 보이면 출력을 중단하고 identity·UTC·redacted 오류만 남긴다.

### 2. Data LIF·export policy

Data LIF와 junction은 PV 원문에서 추측하지 않고 Trident/ONTAP owner가 current volume mapping에서 확인한 값을 사용한다. ONTAP REST는 배포 version이 지원하고 승인 curl config가 CA 검증·read-only 인증을 제공할 때만 사용한다.

`DATA_LIF='PASTE_NFS_DATA_LIF_HERE'; JUNCTION_PATH='PASTE_NFS_JUNCTION_PATH_HERE'; ONTAP_BASE_URL='PASTE_NFS_ONTAP_HTTPS_BASE_URL_HERE'; ONTAP_CURL_CONFIG='PASTE_NFS_ONTAP_CURL_CONFIG_PATH_HERE'; SVM_UUID='PASTE_NFS_SVM_UUID_HERE'; VOLUME_UUID='PASTE_NFS_VOLUME_UUID_HERE'; EXPORT_POLICY_ID='PASTE_NFS_EXPORT_POLICY_ID_HERE'`

`validate_ontap_nfs(){ unset ONTAP_READY HOST_READY AUTH_READY; ONTAP_READY=false; HOST_READY=false; AUTH_READY=false; [ "$RELATION_READY" = true ] && [ "$TIME_READY" = true ] || return 1; [[ "$DATA_LIF" =~ ^[A-Za-z0-9._:-]+$ ]] && [[ "$JUNCTION_PATH" == /* ]] && [[ "$ONTAP_BASE_URL" =~ ^https://[A-Za-z0-9._:-]+$ ]] && [[ "$SVM_UUID" =~ ^[A-Fa-f0-9-]+$ ]] && [[ "$VOLUME_UUID" =~ ^[A-Fa-f0-9-]+$ ]] && [[ "$EXPORT_POLICY_ID" =~ ^[0-9]+$ ]] && [[ "$ONTAP_CURL_CONFIG" == /* ]] && [ -f "$ONTAP_CURL_CONFIG" ] && [ -r "$ONTAP_CURL_CONFIG" ] || return 1; HOST_READY=true; AUTH_READY=true; ONTAP_READY=true; }`

`ontap_nfs_get(){ local path="$1" filter="$2" body code rc; refresh_storage && refresh_time && validate_ontap_nfs || { printf '%s\n' '중단: current storage/time/ONTAP READY 실패' >&2; return 1; }; body="$(mktemp)" || return 1; code="$(curl --config "$ONTAP_CURL_CONFIG" --silent --show-error --max-time 15 -o "$body" -w '%{http_code}' "$ONTAP_BASE_URL$path")"; rc=$?; if [ "$rc" -ne 0 ]; then printf '중단: ONTAP transport/TLS 실패 rc=%s\n' "$rc" >&2; elif [ "$code" != 200 ]; then printf '중단: ONTAP HTTP 실패 code=%s path=%s\n' "$code" "$path" >&2; rc=1; elif ! jq -e 'type=="object"' "$body" >/dev/null; then printf '%s\n' '중단: ONTAP JSON API 응답 아님' >&2; rc=1; else jq "$filter" "$body"; rc=$?; fi; rm -f "$body"; return "$rc"; }`

`ontap_nfs_get "/api/storage/volumes/$VOLUME_UUID?fields=uuid,name,state,svm,nas" '{uuid,name,state,svm:{uuid:.svm.uuid,name:.svm.name},nas:{path:.nas.path,export_policy:.nas.export_policy,security_style:.nas.security_style}}'`

`ontap_nfs_get "/api/protocols/nfs/export-policies/$EXPORT_POLICY_ID/rules?fields=index,clients,protocols,ro_rule,rw_rule,superuser" '{num_records,records:[.records[]|{index,clients,protocols,ro_rule,rw_rule,superuser}]}'`

`ontap_nfs_get "/api/network/ip/interfaces?svm.uuid=$SVM_UUID&services=data_nfs&fields=uuid,name,enabled,services,service_policy" '{num_records,records:[.records[]|{uuid,name,enabled,services,service_policy}]}'`

터미널에서 current node source 주소가 policy client set에 match하는지만 판정하고 주소/CIDR 원문은 보존하지 않는다. `permission denied`는 Data LIF 도달 성공 범위일 수 있지만 export policy, Unix permission, protocol 중 하나를 단독 확정하지 않는다. management API 200도 Data LIF NFS listener와 route를 보장하지 않는다.

### 3. 승인 node 점검

Data LIF, junction과 target node mapping이 확인된 경우에만 실행한다. kubelet unit과 mount target은 current CSI/kubelet evidence에서 선택하며 임의 host path를 만들지 않는다.

`APPROVED_HOST='PASTE_NFS_APPROVED_SSH_HOST_HERE'; EXPECTED_REMOTE_HOST='PASTE_NFS_EXPECTED_REMOTE_HOSTNAME_HERE'; KUBELET_UNIT='PASTE_NFS_KUBELET_UNIT_HERE'; MOUNT_TARGET='PASTE_NFS_MOUNT_TARGET_HERE'`

`validate_node_args(){ unset HOST_READY; HOST_READY=false; [ "$NODE_READY" = true ] && [ "$TIME_READY" = true ] || return 1; [[ "$APPROVED_HOST" =~ ^[A-Za-z0-9._:@-]+$ ]] && [[ "$EXPECTED_REMOTE_HOST" =~ ^[A-Za-z0-9._-]+$ ]] && [[ "$KUBELET_UNIT" =~ ^[A-Za-z0-9_.@-]+$ ]] && [[ "$MOUNT_TARGET" == /* ]] && [[ "$DATA_LIF" =~ ^[A-Za-z0-9._:-]+$ ]] || return 1; HOST_READY=true; }`

`if refresh_storage && refresh_time && refresh_node_plugin && validate_node_args; then ssh -- "$APPROVED_HOST" bash -c 'set -u; expected=$1; machine=$2; unit=$3; start=$4; end=$5; actual=$(hostname -f); actual_machine=$(cat /etc/machine-id); [ "$actual" = "$expected" ] && [ "$actual_machine" = "$machine" ] || exit 40; sudo journalctl -u "$unit" --since "$start" --until "$end" --no-pager | grep -E -i -C 3 "mount|nfs|volume|NodePublishVolume|permission|access denied|timeout|route|refused|stale|failed|error"; rc=("${PIPESTATUS[@]}"); [ "${rc[0]}" -eq 0 ] || exit 41; [ "${rc[1]}" -eq 0 ] || exit "$((50+rc[1]))"' bash "$EXPECTED_REMOTE_HOST" "$NODE_MACHINE_ID" "$KUBELET_UNIT" "$START_RFC3339" "$END_RFC3339"; RC=$?; case "$RC" in 0) EVIDENCE_READY=true; printf 'journal evidence ready node=%s uid=%s at=%s\n' "$NODE" "$NODE_UID" "$COLLECTED_AT";; 40) EVIDENCE_READY=false; printf '%s\n' '중단: remote hostname/machine-id 불일치' >&2;; 41) EVIDENCE_READY=false; printf '%s\n' '중단: journal producer 실패' >&2;; 51) EVIDENCE_READY=false; printf '%s\n' '미확정: journal filter 일치 없음' >&2;; *) EVIDENCE_READY=false; printf '중단: SSH/journal/filter 실패 rc=%s\n' "$RC" >&2;; esac; fi`

`if refresh_storage && refresh_time && validate_node_args; then ssh -- "$APPROVED_HOST" bash -c 'set -u; expected=$1; machine=$2; lif=$3; target=$4; actual=$(hostname -f); actual_machine=$(cat /etc/machine-id); [ "$actual" = "$expected" ] && [ "$actual_machine" = "$machine" ] || exit 40; ip route get "$lif" || exit 41; getent ahosts "$lif" || exit 42; if findmnt -M "$target" >/dev/null 2>&1; then findmnt -M "$target" -o TARGET,SOURCE,FSTYPE,OPTIONS || exit 43; else printf "mount-target-not-mounted=%s\n" "$target"; fi' bash "$EXPECTED_REMOTE_HOST" "$NODE_MACHINE_ID" "$DATA_LIF" "$MOUNT_TARGET"; RC=$?; case "$RC" in 0) EVIDENCE_READY=true; printf 'node route/mount evidence ready node=%s uid=%s at=%s\n' "$NODE" "$NODE_UID" "$(date -u '+%Y-%m-%dT%H:%M:%SZ')";; 40) EVIDENCE_READY=false; printf '%s\n' '중단: remote identity 불일치' >&2;; 41) EVIDENCE_READY=false; printf '%s\n' 'Data LIF route 실패' >&2;; 42) EVIDENCE_READY=false; printf '%s\n' 'Data LIF name resolution 실패' >&2;; *) EVIDENCE_READY=false; printf '중단: node producer 실패 rc=%s\n' "$RC" >&2;; esac; fi`

`rpcinfo`는 NFSv3/rpcbind 사용이 승인된 환경에서만 node owner가 같은 identity gate로 추가 확인한다. NFSv4 환경이나 도구 부재를 export policy 실패로 해석하지 않는다. route 성공은 NFS port·export·mount 성공을 보장하지 않고, `findmnt` 성공은 workload read/write를 보장하지 않는다.

## 원인 확정 기준

- export policy: current volume UUID·policy ID와 target node source identity가 같은 시각에 연결되고 client/protocol/rw rule이 직접 불일치한다.
- Data LIF/network: current Node UID/machineID의 route 또는 NFS service 실패와 CSI/kubelet timeout이 같은 창에 일치한다.
- junction/volume: current PV relation의 redacted mapping과 ONTAP volume UUID/junction이 다르고 `not found`·stale handle이 일치한다.
- node client/option: route·policy는 정상이고 current mount producer가 지원되지 않는 protocol/option을 직접 반환한다.
- 미확정: Pod/PVC/PV/node/plugin/ONTAP identity 또는 시간 창 중 하나라도 연결되지 않는다.

## Prometheus 쿼리 생성

metric이 실제 존재할 때만 출력된 완성 쿼리를 사용한다. regular container metric과 init container metric을 섞지 않는다.

`if refresh_storage; then printf 'kube_pod_container_status_waiting_reason{namespace="%s",pod=~"^%s$",reason="ContainerCreating"}==1\n' "$NS" "$POD_RE"; printf 'kubelet_volume_stats_health_status_abnormal{namespace="%s",persistentvolumeclaim=~"^%s$"}==1\n' "$NS" "$PVC_RE"; fi`

빈 결과는 metric 미지원, CSI stats 미노출, label 불일치, 조회 cluster/time 오류와 권한/API 실패를 구분한다. 이 쿼리는 export policy나 Data LIF route를 직접 증명하지 않는다.

## 상태 변경·rollback 경계

이 런북에는 export policy/backend/StorageClass 변경, PVC 삭제, 수동 mount/umount, Trident restart, junction 변경 명령을 두지 않는다. 별도 제품 절차는 fresh Pod/owner/PVC/PV/node/plugin/volume/policy identity, exact RBAC·단일 auditID, 승인 ID, 같은 policy의 전체 client 영향, RWO/quorum과 in-flight I/O, idempotence, 중단 조건, 검증된 rollback을 요구한다. 접근 범위를 전체 client로 넓히거나 management LIF를 Data LIF로 대체하지 않는다.

## 정상화 검증

교체 Pod는 이전 이름·UID를 재사용하지 않는다. current workload owner/selector에서 단일 replacement를 확인한 뒤 최초 입력부터 다시 등록한다. node plugin 교체도 current DaemonSet owner, target node, 새 Pod UID/containerID로 다시 선택한다.

`NORMALIZATION_READY=false; if refresh_storage && refresh_time && refresh_node_plugin && validate_node_args; then kubectl get pod "$POD" -n "$NS" -o custom-columns='POD:.metadata.name,UID:.metadata.uid,RV:.metadata.resourceVersion,NODE:.spec.nodeName,PHASE:.status.phase,READY:.status.containerStatuses[*].ready,RESTARTS:.status.containerStatuses[*].restartCount' && kubectl get pvc "$PVC" -n "$NS" -o custom-columns='PVC:.metadata.name,UID:.metadata.uid,RV:.metadata.resourceVersion,PHASE:.status.phase,PV:.spec.volumeName' && kubectl get pv "$PV" -o custom-columns='PV:.metadata.name,UID:.metadata.uid,RV:.metadata.resourceVersion,CLAIM-UID:.spec.claimRef.uid,DRIVER:.spec.csi.driver'; printf 'current identity gate passed at=%s; NFS function and recurrence gates are still required\n' "$COLLECTED_AT"; fi`

최종 `NORMALIZATION_READY=true`는 current Data LIF route와 NFS service, volume/junction/policy client match, CSI NodePublishVolume, exact mount source/fstype/options가 정상이고 새 `FailedMount`·CSI/kubelet 오류가 승인 관찰 창 동안 없으며 실제 애플리케이션 read/write와 공유 consistency 검사가 성공한 뒤에만 운영 기록에서 승인한다. `Running`, `Bound`, route 또는 mount 한 번의 성공만으로 닫지 않는다.

## 증거·감사·미검증

보존: canonical UTC 창, Pod/owner/PVC/PV/node/plugin UID·RV와 containerID, redacted volume UUID·policy ID·junction match 판정, producer/filter rc, ONTAP HTTP status, exact audit fields, 승인·rollback·기능 결과. 저장 금지: volume handle, client IP/CIDR, Data/management LIF 원문이 포함된 전체 body, Secret/token/private key, curl config 내용, 전체 로그·데이터 내용.

Kubernetes와 `kubectl`은 `1.26.x` 기준이다. Trident/ONTAP version·REST field, NFSv3/v4·service policy, export rule semantics, node OS/client 도구, route/firewall과 mount option은 환경별 미검증이다. REST 미지원이면 URI를 추측하지 않고 승인된 ONTAP read-only surface에서 같은 UUID와 relation을 검증한다.
