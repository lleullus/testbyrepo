# 같은 CSI driver에서 여러 volume·Node 장애가 반복되는 경우

## 입력값과 빠른 수집

이 문서는 같은 CSI driver의 서로 다른 volume 또는 Node에서 동일 단계의 오류가 반복될 때 사용한다. 대표 표본 하나의 exact identity를 먼저 고정하고 나머지 표본은 승인된 storage inventory에서 같은 방식으로 각각 검증한다. PV·VolumeAttachment 목록 전체, volume handle 원문, Secret, token, 인증서 개인키는 출력하지 않는다.

| 입력 종류 | 변수 | 출처와 gate |
|---|---|---|
| 최초 입력 | `DRIVER`, `PV`, `VA` | Event·status 또는 승인 inventory의 exact 이름. PV driver와 VolumeAttachment PV 관계가 맞아야 한다. |
| API 확인 자동값 | `PV_UID/RV`, `VA_UID/RV`, `PVC_UID/RV`, `NODE`, claim 관계 | 매 단계 직전 API에서 새로 읽으며 UID가 최초 identity와 다르면 중단한다. |
| 계산 후보값 | `DRIVER_RE` | literal driver를 정규식 escape한 값. bounded 출력 확인 전 사용하지 않는다. |
| 운영자 선택값 | controller/node Pod·container, UTC 창, 승인 SSH host | 현재 inventory와 Pod/container/node 관계를 검증한 뒤에만 사용한다. |

### 1. 실행 위치·도구·최초 identity

Kubernetes 명령은 승인된 context가 설정된 작업 PC 또는 bastion의 **같은 Bash**에서 실행한다. node 명령은 뒤에서 승인된 SSH host를 별도 검증한다.

**도구 gate**

`TOOLS_READY=false; MISSING=''; for T in kubectl jq grep sed awk date ssh; do command -v "$T" >/dev/null 2>&1 || MISSING="$MISSING $T"; done; if [ -n "${BASH_VERSION:-}" ] && [ -z "$MISSING" ]; then TOOLS_READY=true; printf 'TOOLS_READY=true bash=%s\n' "$BASH_VERSION"; else printf '중단: Bash 또는 도구 누락:%s\n' "$MISSING" >&2; fi`

**현재 Kubernetes client identity 확인**

`kubectl config view --minify -o json | jq -r '. as $x | "context=\($x["current-context"]|@sh) user-key=\($x.contexts[0].context.user|@sh) cluster-key=\($x.contexts[0].context.cluster|@sh)"'`

`user-key`는 kubeconfig 참조 이름일 뿐 실제 인증 주체를 단독 보장하지 않는다. RBAC는 현재 요청의 `auth can-i`, 감사는 control-plane owner가 제공한 audit record의 `user.username`, `verb`, `objectRef.resource/namespace/name`, `responseStatus.code`, `requestReceivedTimestamp`를 exact 대조한다. audit request·response body와 credential은 수집하지 않는다.

**입력·모든 파생 상태 무효화**

`unset INPUT_READY IDENTITY_READY RELATION_READY OWNER_READY CONTAINER_READY NODE_READY HOST_READY TIME_READY ARGUMENT_READY SELECTION_READY AUTH_READY EVIDENCE_READY MUTATION_READY ROLLBACK_READY NORMALIZATION_READY PV_UID PV_RV VA_UID VA_RV PVC_NS PVC PVC_UID PVC_RV NODE DRIVER_RE CTRL_POD_UID CTRL_POD_RV CTRL_CONTAINER_ID CTRL_NODE NODE_POD_UID NODE_POD_RV NODE_CONTAINER_ID; DRIVER='PASTE_CSI_DRIVER_HERE'; PV='PASTE_REPRESENTATIVE_PV_HERE'; VA='PASTE_VOLUMEATTACHMENT_HERE'; INPUT_READY=false; if [ "$TOOLS_READY" != true ]; then printf '%s\n' '중단: TOOLS_READY가 아니다.' >&2; elif PV0="$(kubectl get pv "$PV" -o json)" && VA0="$(kubectl get volumeattachment "$VA" -o json)" && [ "$(jq -r '.spec.csi.driver // empty' <<<"$PV0")" = "$DRIVER" ] && [ "$(jq -r '.spec.source.persistentVolumeName // empty' <<<"$VA0")" = "$PV" ]; then EXPECTED_PV_UID="$(jq -r '.metadata.uid' <<<"$PV0")"; EXPECTED_VA_UID="$(jq -r '.metadata.uid' <<<"$VA0")"; EXPECTED_CLAIM_UID="$(jq -r '.spec.claimRef.uid // empty' <<<"$PV0")"; INPUT_READY=true; export DRIVER PV VA EXPECTED_PV_UID EXPECTED_VA_UID EXPECTED_CLAIM_UID; printf 'INPUT_READY=true driver=%s pv=%s pv_uid=%s va=%s va_uid=%s\n' "$DRIVER" "$PV" "$EXPECTED_PV_UID" "$VA" "$EXPECTED_VA_UID"; else printf '%s\n' '중단: exact PV/VolumeAttachment 조회 또는 driver/PV 관계 불일치' >&2; fi`

### 2. latest identity·관계 refresh

다음 함수는 **모든 READY와 이전 UID/RV·owner·containerID·node·host·time·regex·selection·authorization·evidence·mutation·rollback·normalization을 먼저 무효화**한다. 세 API 호출과 관계 검증이 모두 성공한 뒤에만 새 값을 공개한다. 실패 뒤에는 이전 값이 남지 않는다.

`refresh_scope(){ unset IDENTITY_READY RELATION_READY OWNER_READY CONTAINER_READY NODE_READY HOST_READY TIME_READY ARGUMENT_READY SELECTION_READY AUTH_READY EVIDENCE_READY MUTATION_READY ROLLBACK_READY NORMALIZATION_READY PV_UID PV_RV VA_UID VA_RV PVC_NS PVC PVC_UID PVC_RV NODE DRIVER_RE; IDENTITY_READY=false; RELATION_READY=false; ARGUMENT_READY=false; [ "$INPUT_READY" = true ] || { printf '%s\n' '중단: INPUT_READY가 아니다.' >&2; return 1; }; local pvj vaj pvcj claim_ns claim_name; pvj="$(kubectl get pv "$PV" -o json)" || return 1; vaj="$(kubectl get volumeattachment "$VA" -o json)" || return 1; [ "$(jq -r '.metadata.uid' <<<"$pvj")" = "$EXPECTED_PV_UID" ] || { printf '%s\n' '중단: PV UID 교체' >&2; return 1; }; [ "$(jq -r '.metadata.uid' <<<"$vaj")" = "$EXPECTED_VA_UID" ] || { printf '%s\n' '중단: VolumeAttachment UID 교체' >&2; return 1; }; [ "$(jq -r '.spec.csi.driver // empty' <<<"$pvj")" = "$DRIVER" ] && [ "$(jq -r '.spec.attacher // empty' <<<"$vaj")" = "$DRIVER" ] && [ "$(jq -r '.spec.source.persistentVolumeName // empty' <<<"$vaj")" = "$PV" ] || { printf '%s\n' '중단: driver/attacher/PV 관계 변경' >&2; return 1; }; claim_ns="$(jq -r '.spec.claimRef.namespace // empty' <<<"$pvj")"; claim_name="$(jq -r '.spec.claimRef.name // empty' <<<"$pvj")"; [ -n "$claim_ns" ] && [ -n "$claim_name" ] || { printf '%s\n' '중단: claimRef 없음' >&2; return 1; }; pvcj="$(kubectl get pvc "$claim_name" -n "$claim_ns" -o json)" || return 1; [ "$(jq -r '.metadata.uid' <<<"$pvcj")" = "$EXPECTED_CLAIM_UID" ] && [ "$(jq -r '.spec.volumeName // empty' <<<"$pvcj")" = "$PV" ] || { printf '%s\n' '중단: PV/PVC relation 변경' >&2; return 1; }; PV_UID="$EXPECTED_PV_UID"; PV_RV="$(jq -r '.metadata.resourceVersion' <<<"$pvj")"; VA_UID="$EXPECTED_VA_UID"; VA_RV="$(jq -r '.metadata.resourceVersion' <<<"$vaj")"; PVC_NS="$claim_ns"; PVC="$claim_name"; PVC_UID="$EXPECTED_CLAIM_UID"; PVC_RV="$(jq -r '.metadata.resourceVersion' <<<"$pvcj")"; NODE="$(jq -r '.spec.nodeName // empty' <<<"$vaj")"; DRIVER_RE="$(printf '%s' "$DRIVER" | sed 's/[][\\.^$*+?(){}|]/\\&/g')"; [ -n "$NODE" ] || { printf '%s\n' '중단: attachment node 없음' >&2; return 1; }; IDENTITY_READY=true; RELATION_READY=true; ARGUMENT_READY=true; export PV_UID PV_RV VA_UID VA_RV PVC_NS PVC PVC_UID PVC_RV NODE DRIVER_RE; printf 'IDENTITY_READY=true RELATION_READY=true pv=%s/%s pvc=%s/%s va=%s/%s node=%s regex=%s\n' "$PV_UID" "$PV_RV" "$PVC_UID" "$PVC_RV" "$VA_UID" "$VA_RV" "$NODE" "$DRIVER_RE"; }`

**현재 상태를 사람용 블록으로 출력**

`if refresh_scope; then kubectl get volumeattachment "$VA" -o custom-columns='NAME:.metadata.name,UID:.metadata.uid,RV:.metadata.resourceVersion,ATTACHER:.spec.attacher,NODE:.spec.nodeName,PV:.spec.source.persistentVolumeName,ATTACHED:.status.attached,ATTACH-ERROR:.status.attachError.message,DETACH-ERROR:.status.detachError.message' && kubectl get pv "$PV" -o custom-columns='NAME:.metadata.name,UID:.metadata.uid,RV:.metadata.resourceVersion,PHASE:.status.phase,CLAIM-NS:.spec.claimRef.namespace,CLAIM:.spec.claimRef.name,CLAIM-UID:.spec.claimRef.uid,DRIVER:.spec.csi.driver' && kubectl get pvc "$PVC" -n "$PVC_NS" -o custom-columns='NAME:.metadata.name,UID:.metadata.uid,RV:.metadata.resourceVersion,PHASE:.status.phase,PV:.spec.volumeName,ACCESS:.spec.accessModes,SC:.spec.storageClassName'; fi`

성공 gate는 세 UID와 PV→PVC, VolumeAttachment→PV, driver→attacher 관계가 같은 최신 조회에서 일치하는 것이다. `attached=true`는 node stage·mount·실제 workload 기능을 보장하지 않는다. 오류 message가 비어 있어도 API 실패·미기록·관측 시각 불일치를 배제하지 않는다.

### 1. controller 경로

inventory에서 실제 controller와 node plugin을 찾은 뒤 한 번만 선택한다. container 이름은 Pod spec과 status의 같은 index 관계로 검증하며 첫 번째 container를 자동 선택하지 않는다.

`CTRL_NS='PASTE_CSI_CONTROLLER_NAMESPACE_HERE'; CTRL_POD='PASTE_CSI_CONTROLLER_POD_HERE'; CTRL_CONTAINER='PASTE_CSI_CONTROLLER_CONTAINER_HERE'; NODE_NS='PASTE_CSI_NODE_NAMESPACE_HERE'; NODE_POD='PASTE_CSI_NODE_POD_HERE'; NODE_CONTAINER='PASTE_CSI_NODE_CONTAINER_HERE'; SELECTION_READY=false`

`refresh_components(){ unset OWNER_READY CONTAINER_READY NODE_READY SELECTION_READY CTRL_POD_UID CTRL_POD_RV CTRL_CONTAINER_ID CTRL_NODE NODE_POD_UID NODE_POD_RV NODE_CONTAINER_ID; OWNER_READY=false; CONTAINER_READY=false; NODE_READY=false; SELECTION_READY=false; [ "$RELATION_READY" = true ] || return 1; local cj nj; cj="$(kubectl get pod "$CTRL_POD" -n "$CTRL_NS" -o json)" || return 1; nj="$(kubectl get pod "$NODE_POD" -n "$NODE_NS" -o json)" || return 1; jq -e --arg c "$CTRL_CONTAINER" 'any(.spec.containers[]?; .name==$c)' <<<"$cj" >/dev/null || return 1; jq -e --arg c "$NODE_CONTAINER" 'any(.spec.containers[]?; .name==$c)' <<<"$nj" >/dev/null || return 1; [ "$(jq -r '.spec.nodeName // empty' <<<"$nj")" = "$NODE" ] || { printf '%s\n' '중단: node plugin Pod가 attachment node와 다름' >&2; return 1; }; CTRL_POD_UID="$(jq -r '.metadata.uid' <<<"$cj")"; CTRL_POD_RV="$(jq -r '.metadata.resourceVersion' <<<"$cj")"; CTRL_NODE="$(jq -r '.spec.nodeName // empty' <<<"$cj")"; CTRL_CONTAINER_ID="$(jq -r --arg c "$CTRL_CONTAINER" '[.status.containerStatuses[]? | select(.name==$c)][0].containerID // empty' <<<"$cj")"; NODE_POD_UID="$(jq -r '.metadata.uid' <<<"$nj")"; NODE_POD_RV="$(jq -r '.metadata.resourceVersion' <<<"$nj")"; NODE_CONTAINER_ID="$(jq -r --arg c "$NODE_CONTAINER" '[.status.containerStatuses[]? | select(.name==$c)][0].containerID // empty' <<<"$nj")"; [ -n "$CTRL_CONTAINER_ID" ] && [ -n "$NODE_CONTAINER_ID" ] || { printf '%s\n' '중단: running containerID 없음' >&2; return 1; }; OWNER_READY=true; CONTAINER_READY=true; NODE_READY=true; SELECTION_READY=true; export CTRL_POD_UID CTRL_POD_RV CTRL_CONTAINER_ID CTRL_NODE NODE_POD_UID NODE_POD_RV NODE_CONTAINER_ID; printf 'SELECTION_READY=true controller=%s/%s uid=%s rv=%s node=%s container=%s containerID=%s nodePod=%s/%s uid=%s rv=%s node=%s container=%s containerID=%s\n' "$CTRL_NS" "$CTRL_POD" "$CTRL_POD_UID" "$CTRL_POD_RV" "$CTRL_NODE" "$CTRL_CONTAINER" "$CTRL_CONTAINER_ID" "$NODE_NS" "$NODE_POD" "$NODE_POD_UID" "$NODE_POD_RV" "$NODE" "$NODE_CONTAINER" "$NODE_CONTAINER_ID"; }`

Pod 자체 identity만으로 CSI 배포 관계를 확정하지 않는다. 다음 gate는 두 Pod의 current controller owner kind/name/UID를 읽고 owner 객체의 current UID와 다시 대조한다.

`refresh_component_owners(){ unset OWNER_READY CTRL_OWNER_KIND CTRL_OWNER_NAME CTRL_OWNER_UID NODE_OWNER_KIND NODE_OWNER_NAME NODE_OWNER_UID; OWNER_READY=false; [ "$SELECTION_READY" = true ] || return 1; local cj nj co no coj noj; cj="$(kubectl get pod "$CTRL_POD" -n "$CTRL_NS" -o json)" || return 1; nj="$(kubectl get pod "$NODE_POD" -n "$NODE_NS" -o json)" || return 1; [ "$(jq -r '.metadata.uid' <<<"$cj")" = "$CTRL_POD_UID" ] && [ "$(jq -r '.metadata.uid' <<<"$nj")" = "$NODE_POD_UID" ] || { printf '%s\n' '중단: component Pod UID 교체' >&2; return 1; }; co="$(jq -c '[.metadata.ownerReferences[]? | select(.controller==true)][0] // empty' <<<"$cj")"; no="$(jq -c '[.metadata.ownerReferences[]? | select(.controller==true)][0] // empty' <<<"$nj")"; [ -n "$co" ] && [ -n "$no" ] || { printf '%s\n' '중단: controller owner 없음' >&2; return 1; }; CTRL_OWNER_KIND="$(jq -r '.kind' <<<"$co")"; CTRL_OWNER_NAME="$(jq -r '.name' <<<"$co")"; CTRL_OWNER_UID="$(jq -r '.uid' <<<"$co")"; NODE_OWNER_KIND="$(jq -r '.kind' <<<"$no")"; NODE_OWNER_NAME="$(jq -r '.name' <<<"$no")"; NODE_OWNER_UID="$(jq -r '.uid' <<<"$no")"; coj="$(kubectl get "$CTRL_OWNER_KIND" "$CTRL_OWNER_NAME" -n "$CTRL_NS" -o json)" || return 1; noj="$(kubectl get "$NODE_OWNER_KIND" "$NODE_OWNER_NAME" -n "$NODE_NS" -o json)" || return 1; [ "$(jq -r '.metadata.uid' <<<"$coj")" = "$CTRL_OWNER_UID" ] && [ "$(jq -r '.metadata.uid' <<<"$noj")" = "$NODE_OWNER_UID" ] || { printf '%s\n' '중단: component owner UID 교체' >&2; return 1; }; OWNER_READY=true; export CTRL_OWNER_KIND CTRL_OWNER_NAME CTRL_OWNER_UID NODE_OWNER_KIND NODE_OWNER_NAME NODE_OWNER_UID; printf 'OWNER_READY=true controller-owner=%s/%s/%s node-owner=%s/%s/%s\n' "$CTRL_OWNER_KIND" "$CTRL_OWNER_NAME" "$CTRL_OWNER_UID" "$NODE_OWNER_KIND" "$NODE_OWNER_NAME" "$NODE_OWNER_UID"; }`

Pod가 교체되면 이전 UID/containerID는 폐기하고 현재 inventory의 owner relation으로 replacement Pod를 다시 선택한 뒤 selection 명령을 재실행한다. 이름이 비슷하다는 이유로 replacement를 선택하지 않는다.

### 2. node 경로

`CSINode` 등록은 plugin process와 mount 성공을 보장하지 않는다. 최신 identity gate 뒤 exact node에서 driver 등록을 확인한다.

`if refresh_scope && kubectl auth can-i get csinodes >/dev/null 2>&1 && [ "$(kubectl auth can-i get csinodes)" = yes ]; then AUTH_READY=true; kubectl get csinode "$NODE" -o json | jq -r --arg d "$DRIVER" '"node=\(.metadata.name) uid=\(.metadata.uid) rv=\(.metadata.resourceVersion) driver-present=\(any(.spec.drivers[]?; .name==$d)) topology-keys=\([.spec.drivers[]? | select(.name==$d) | .topologyKeys[]?] | join(","))"'; else AUTH_READY=false; printf '%s\n' '중단: CSINode exact get 권한 또는 조회 실패' >&2; fi`

### 3. 시간·권한·증거 gate

시간은 UTC RFC3339 초 단위로 round-trip하고 시작이 종료보다 앞서는지 확인한다.

`START_INPUT='PASTE_CSI_START_RFC3339_HERE'; END_INPUT='PASTE_CSI_END_RFC3339_HERE'; refresh_time(){ unset TIME_READY START_RFC3339 END_RFC3339 COLLECTED_AT; TIME_READY=false; [[ "$START_INPUT" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] && [[ "$END_INPUT" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] || return 1; local se ee; se="$(date -u -d "$START_INPUT" +%s 2>/dev/null)" || return 1; ee="$(date -u -d "$END_INPUT" +%s 2>/dev/null)" || return 1; START_RFC3339="$(date -u -d "@$se" '+%Y-%m-%dT%H:%M:%SZ')"; END_RFC3339="$(date -u -d "@$ee" '+%Y-%m-%dT%H:%M:%SZ')"; [ "$START_RFC3339" = "$START_INPUT" ] && [ "$END_RFC3339" = "$END_INPUT" ] && [ "$se" -lt "$ee" ] || { printf '%s\n' '중단: canonical UTC RFC3339 또는 시간 순서 오류' >&2; return 1; }; COLLECTED_AT="$(date -u '+%Y-%m-%dT%H:%M:%SZ')"; TIME_READY=true; export START_RFC3339 END_RFC3339 COLLECTED_AT; printf 'TIME_READY=true start=%s end=%s collected=%s\n' "$START_RFC3339" "$END_RFC3339" "$COLLECTED_AT"; }`

`refresh_auth(){ AUTH_READY=false; [ "$SELECTION_READY" = true ] || return 1; [ "$(kubectl auth can-i get "pods/$CTRL_POD" -n "$CTRL_NS")" = yes ] && [ "$(kubectl auth can-i get "pods/$CTRL_POD" --subresource=log -n "$CTRL_NS")" = yes ] && [ "$(kubectl auth can-i get "pods/$NODE_POD" -n "$NODE_NS")" = yes ] && [ "$(kubectl auth can-i get "pods/$NODE_POD" --subresource=log -n "$NODE_NS")" = yes ] && [ "$(kubectl auth can-i get "persistentvolumes/$PV")" = yes ] && [ "$(kubectl auth can-i get "volumeattachments.storage.k8s.io/$VA")" = yes ] || { printf '%s\n' '중단: exact RBAC gate 실패' >&2; return 1; }; AUTH_READY=true; }`

controller 로그는 producer와 filter 종료를 분리한다. filter `1`은 일치 없음이지 정상 증거가 아니다. producer 비정상은 로그 수집 실패다. raw tail을 자동 출력하지 않는다.

`if refresh_scope && refresh_components && refresh_component_owners && refresh_time && refresh_auth; then kubectl logs "$CTRL_POD" -n "$CTRL_NS" -c "$CTRL_CONTAINER" --timestamps --since-time="$START_RFC3339" --tail=300 | awk -v end="$END_RFC3339" '$1 < end' | grep -E -i -C 3 "$DRIVER_RE|ControllerPublishVolume|ControllerUnpublishVolume|deadline|timeout|unavailable|permission denied|not found|I/O error"; RC=("${PIPESTATUS[@]}"); if [ "${RC[0]}" -ne 0 ]; then EVIDENCE_READY=false; printf '중단: log producer 실패 rc=%s\n' "${RC[0]}" >&2; elif [ "${RC[1]}" -ne 0 ]; then EVIDENCE_READY=false; printf '중단: 시간 filter 실패 rc=%s\n' "${RC[1]}" >&2; elif [ "${RC[2]}" -eq 1 ]; then EVIDENCE_READY=false; printf '%s\n' '미확정: filter 일치 없음. 정상으로 판정하지 않고 같은 창을 owner UI에서 확인한다.' >&2; elif [ "${RC[2]}" -ne 0 ]; then EVIDENCE_READY=false; printf '중단: 증상 filter 실패 rc=%s\n' "${RC[2]}" >&2; else EVIDENCE_READY=true; printf 'EVIDENCE_READY=true collected=%s controller_uid=%s owner_uid=%s containerID=%s\n' "$COLLECTED_AT" "$CTRL_POD_UID" "$CTRL_OWNER_UID" "$CTRL_CONTAINER_ID"; fi; fi`

node plugin 로그도 같은 latest gate를 사용한다.

`if refresh_scope && refresh_components && refresh_component_owners && refresh_time && refresh_auth; then kubectl logs "$NODE_POD" -n "$NODE_NS" -c "$NODE_CONTAINER" --timestamps --since-time="$START_RFC3339" --tail=300 | awk -v end="$END_RFC3339" '$1 < end' | grep -E -i -C 3 "$DRIVER_RE|NodeStageVolume|NodePublishVolume|device|mount|filesystem|deadline|timeout|permission|I/O error"; RC=("${PIPESTATUS[@]}"); if [ "${RC[0]}" -ne 0 ]; then EVIDENCE_READY=false; printf '중단: log producer 실패 rc=%s\n' "${RC[0]}" >&2; elif [ "${RC[1]}" -ne 0 ]; then EVIDENCE_READY=false; printf '중단: 시간 filter 실패 rc=%s\n' "${RC[1]}" >&2; elif [ "${RC[2]}" -eq 1 ]; then EVIDENCE_READY=false; printf '%s\n' '미확정: filter 일치 없음' >&2; elif [ "${RC[2]}" -ne 0 ]; then EVIDENCE_READY=false; printf '중단: 증상 filter 실패 rc=%s\n' "${RC[2]}" >&2; else EVIDENCE_READY=true; printf 'EVIDENCE_READY=true collected=%s node_pod_uid=%s owner_uid=%s containerID=%s\n' "$COLLECTED_AT" "$NODE_POD_UID" "$NODE_OWNER_UID" "$NODE_CONTAINER_ID"; fi; fi`

`DeadlineExceeded`는 endpoint·network·backend 지연 후보, `permission denied`는 CSI/storage 권한 후보, `not found`는 redacted inventory mapping 후보, `I/O error`는 device/filesystem 후보다. 어느 문자열도 단독으로 공통 원인을 확정하지 않는다. 로그에 credential·token·개인정보가 보이면 즉시 출력을 중단하고 시각·오류 유형만 기록한다.

### 4. 승인된 node journal

Node 접근은 플랫폼 inventory가 `NODE`와 연결한 승인 host에서만 수행한다. host, 원격 hostname과 kubelet unit은 운영자 선택값이며 안전한 문자만 허용한다. SSH 원격 명령은 positional argument만 사용하고 `eval`하지 않는다.

`APPROVED_HOST='PASTE_APPROVED_NODE_SSH_HOST_HERE'; EXPECTED_REMOTE_HOST='PASTE_EXPECTED_REMOTE_HOSTNAME_HERE'; KUBELET_UNIT='PASTE_KUBELET_UNIT_HERE'; validate_host(){ unset HOST_READY; HOST_READY=false; [ "$NODE_READY" = true ] || return 1; [[ "$APPROVED_HOST" =~ ^[A-Za-z0-9._:@-]+$ ]] && [[ "$EXPECTED_REMOTE_HOST" =~ ^[A-Za-z0-9._-]+$ ]] && [[ "$KUBELET_UNIT" =~ ^[A-Za-z0-9_.@-]+$ ]] || { printf '%s\n' '중단: host/unit 문자 검증 실패' >&2; return 1; }; HOST_READY=true; }`

`refresh_node_machine(){ unset NODE_UID NODE_MACHINE_ID; NODE_READY=false; [ "$RELATION_READY" = true ] || return 1; local n; n="$(kubectl get node "$NODE" -o json)" || return 1; NODE_UID="$(jq -r '.metadata.uid' <<<"$n")"; NODE_MACHINE_ID="$(jq -r '.status.nodeInfo.machineID // empty' <<<"$n")"; [ -n "$NODE_UID" ] && [ -n "$NODE_MACHINE_ID" ] || { printf '%s\n' '중단: Node UID/machineID 없음' >&2; return 1; }; NODE_READY=true; export NODE_UID NODE_MACHINE_ID; printf 'NODE_READY=true node=%s uid=%s machineID=%s\n' "$NODE" "$NODE_UID" "$NODE_MACHINE_ID"; }`

`if refresh_scope && refresh_components && refresh_component_owners && refresh_node_machine && refresh_time && validate_host; then ssh -- "$APPROVED_HOST" bash -c 'set -u; expected=$1; machine=$2; unit=$3; start=$4; end=$5; actual=$(hostname -f); actual_machine=$(cat /etc/machine-id); [ "$actual" = "$expected" ] && [ "$actual_machine" = "$machine" ] || { printf "중단: remote identity mismatch expected=%s actual=%s\n" "$expected" "$actual" >&2; exit 40; }; sudo journalctl -u "$unit" --since "$start" --until "$end" --no-pager | grep -E -i -C 3 "csi|volume|stage|publish|mount|device|filesystem|deadline|timeout|failed|error"; rc=("${PIPESTATUS[@]}"); [ "${rc[0]}" -eq 0 ] || exit 41; [ "${rc[1]}" -eq 0 ] || exit "$((50+rc[1]))"' bash "$EXPECTED_REMOTE_HOST" "$NODE_MACHINE_ID" "$KUBELET_UNIT" "$START_RFC3339" "$END_RFC3339"; SSH_RC=$?; case "$SSH_RC" in 0) EVIDENCE_READY=true; printf 'node evidence collected node=%s node_uid=%s at=%s\n' "$NODE" "$NODE_UID" "$COLLECTED_AT";; 40) EVIDENCE_READY=false; printf '%s\n' '중단: remote identity 불일치' >&2;; 41) EVIDENCE_READY=false; printf '%s\n' '중단: journal producer 실패' >&2;; 51) EVIDENCE_READY=false; printf '%s\n' '미확정: journal filter 일치 없음' >&2;; *) EVIDENCE_READY=false; printf '중단: SSH/journal/filter 실패 rc=%s\n' "$SSH_RC" >&2;; esac; fi`

## 원인 확정 기준

- controller 공통: 서로 다른 PV/VA UID에서 같은 controller Pod UID/containerID와 UTC 창에 같은 publish 단계 오류가 있고 storage endpoint 증거가 일치한다.
- node 공통: 서로 다른 Node의 current node plugin UID/containerID와 kubelet journal에서 같은 stage/publish 실패가 겹친다.
- 단일 Node: controller는 성공하고 한 Node의 plugin/kubelet/device 증거에만 실패가 남는다.
- 미확정: 표본 UID, 시각, driver/attacher, controller/node 관계 또는 storage evidence 중 하나라도 연결되지 않는다.

## 상태 변경 분리

이 런북에는 CSI restart·rollout, VolumeAttachment/PV/PVC 삭제, force detach, filesystem repair/format 명령을 두지 않는다. 별도 제품 절차로 변경하려면 fresh identity·relation·evidence, exact RBAC와 audit 주체, data/workload/storage owner 승인, 변경 창, RWO·quorum·in-flight operation, 멱등성, 중단 조건, 실행 전 검증된 rollback을 모두 기록해야 한다. rollback이 실제로 검증되지 않으면 `ROLLBACK_READY=false`, 따라서 `MUTATION_READY=false`다. 삭제·detach처럼 원상복구가 보장되지 않는 작업을 rollback 가능으로 기록하지 않는다.

## 정상화 검증

변경 또는 외부 복구 뒤 이전 Pod UID·containerID를 재사용하지 않는다. controller/node Pod replacement는 현재 owner relation과 target node로 다시 선택하고, `refresh_scope`, `refresh_components`, 시간·권한 gate를 새로 통과한다.

`NORMALIZATION_READY=false; if refresh_scope && refresh_components && refresh_component_owners && refresh_node_machine && [ "$(kubectl get volumeattachment "$VA" -o json | jq -r --arg uid "$VA_UID" 'select(.metadata.uid==$uid) | .status.attached // false')" = true ]; then kubectl get pvc "$PVC" -n "$PVC_NS" -o custom-columns='PVC:.metadata.name,UID:.metadata.uid,PV:.spec.volumeName,PHASE:.status.phase' && kubectl get volumeattachment "$VA" -o custom-columns='VA:.metadata.name,UID:.metadata.uid,NODE:.spec.nodeName,PV:.spec.source.persistentVolumeName,ATTACHED:.status.attached,ATTACH-ERROR:.status.attachError.message,DETACH-ERROR:.status.detachError.message'; printf 'object/component gate passed at=%s; functional observation is still required\n' "$(date -u '+%Y-%m-%dT%H:%M:%SZ')"; else printf '%s\n' '정상화 미충족: identity/relation/owner/node/attachment gate 실패' >&2; fi`

이 출력은 객체·component 관계 gate만 통과했다는 뜻이다. 같은 driver의 모든 승인 표본에서 새 publish/stage/mount 오류가 관찰 창 동안 없고, storage service와 Linux device/filesystem이 정상이며, 영향 workload의 실제 read/write 또는 제품 기능이 성공해야 최종 정상화한다. 메트릭이 없으면 정상이나 0으로 기록하지 않고 `미수집/label 불일치/조회 범위/권한/API 실패`를 구분한다.

## 증거 보존과 환경별 미검증

보존: UTC 수집 창, PV/PVC/VolumeAttachment UID·RV와 관계, driver/attacher, node, controller/node Pod UID·owner·containerID, producer/filter 결과, redacted storage correlation ID, audit exact fields, 승인·변경·rollback·기능 검증 결과. 저장 금지: volume handle 원문, Secret/token/private key, 내부 endpoint 원문, 전체 YAML·전체 로그·개인정보.

Kubernetes와 `kubectl`은 `1.26.x` 기준이다. CSI 배포 topology, controller/node selector, kubelet unit, storage API·서비스·권한, Linux device/filesystem은 환경별 미검증이다. CRI를 확인해야 하는 별도 분기에서는 kubelet의 현재 `containerRuntimeEndpoint` exact 값과 socket provider가 검증된 경우에만 `crictl --runtime-endpoint "$CRI_ENDPOINT"`를 사용하며 기본 socket을 추측하지 않는다.
