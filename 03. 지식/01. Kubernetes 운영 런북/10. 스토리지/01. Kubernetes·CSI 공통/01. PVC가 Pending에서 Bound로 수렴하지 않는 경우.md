# PVC가 Pending에서 Bound로 수렴하지 않는 경우

## 입력값과 빠른 수집

진단 경로는 `PVC UID·spec → StorageClass UID·provisioner·binding mode → consumer Pod·topology → PV·CSI driver → provisioner controller → storage API`다. `Pending`은 아직 binding되지 않았다는 상태이며 `WaitForFirstConsumer`에서는 정상 중간 상태일 수 있다.

| 종류 | 변수 | 등록 기준 |
|---|---|---|
| 최초 입력 | `CONTEXT`, `NS`, `PVC` | exact PVC 조회 성공 |
| API 자동값 | PVC UID·RV·owner·spec, StorageClass UID·RV·provisioner, 조건부 PV·CSI relation | 모든 필요한 조회 성공 뒤 등록 |
| 계산 후보 | consumer Pod 후보, 완성 PromQL | namespace API 결과이며 임의 선택 금지 |
| 운영자 선택값 | consumer Pod, CSI controller Pod·regular container, UTC 증거 창 | Event·inventory 확인 뒤 선택 |

Secret data, token, private key와 volume handle 원문은 출력하지 않는다.

**모든 조회·log가 직접 호출할 current gate:** `refresh_pvc(){ local cj sj vj cu co; AUTO_READY=false; cj="$(kubectl --context "$CONTEXT" get pvc "$PVC" -n "$NS" -o json)" || { invalidate_pvc; return 1; }; cu="$(jq -r '.metadata.uid' <<<"$cj")"; if [ "$cu" != "$PVC_UID" ] || [ "$(jq -r '.spec.storageClassName // ""' <<<"$cj")" != "$SC" ] || [ "$(jq -r '.spec.volumeName // ""' <<<"$cj")" != "$PV" ]; then invalidate_pvc; printf '%s\n' '중단: PVC UID·StorageClass·PV relation 변경, 자동값 재등록' >&2; return 1; fi; if [ "$PVC_OWNER_KIND" != None ]; then co="$(kubectl --context "$CONTEXT" get "$PVC_OWNER_KIND" "$PVC_OWNER_NAME" -n "$NS" -o jsonpath='{.metadata.uid}' 2>/dev/null)" || { invalidate_pvc; return 1; }; [ "$co" = "$PVC_OWNER_UID" ] || { invalidate_pvc; return 1; }; fi; if [ -n "$SC" ]; then sj="$(kubectl --context "$CONTEXT" get storageclass "$SC" -o json)" || { invalidate_pvc; return 1; }; [ "$(jq -r '.metadata.uid' <<<"$sj")" = "$SC_UID" ] && [ "$(jq -r '.provisioner' <<<"$sj")" = "$PROVISIONER" ] || { invalidate_pvc; return 1; }; SC_JSON="$sj"; fi; if [ -n "$PV" ]; then vj="$(kubectl --context "$CONTEXT" get pv "$PV" -o json)" || { invalidate_pvc; return 1; }; [ "$(jq -r '.metadata.uid' <<<"$vj")" = "$PV_UID" ] && jq -e --arg ns "$NS" --arg n "$PVC" --arg u "$PVC_UID" '.spec.claimRef.namespace==$ns and .spec.claimRef.name==$n and .spec.claimRef.uid==$u' <<<"$vj" >/dev/null || { invalidate_pvc; return 1; }; PV_JSON="$vj"; PV_RV="$(jq -r '.metadata.resourceVersion' <<<"$vj")"; fi; PVC_JSON="$cj"; PVC_RV="$(jq -r '.metadata.resourceVersion' <<<"$cj")"; PVC_PHASE="$(jq -r '.status.phase // ""' <<<"$cj")"; AUTO_READY=true; return 0; }`

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | current PVC UID가 Pending이며 의도한 소비 경로에서 Bound로 수렴하지 않음 |
| 적용 | PVC spec, StorageClass binding/topology, consumer와 provisioner 증거 확인 가능 |
| 제외 | attach·Multi-Attach는 [[03. VolumeAttachment가 수렴하지 않거나 Multi-Attach가 발생하는 경우]], mount는 [[25. Pod 이벤트에 FailedMount·FailedAttachVolume이 기록된 경우]] |

검색 문자열: `Pending`, `ProvisioningFailed`, `FailedBinding`, `waiting for first consumer`, `no persistent volumes available`, `CreateVolume`, `deadline exceeded`, `permission denied`.

## 최초 확인과 분기

**PVC·StorageClass 실행:** `refresh_pvc && kubectl --context "$CONTEXT" get pvc "$PVC" -n "$NS" -o custom-columns='NAME:.metadata.name,UID:.metadata.uid,RV:.metadata.resourceVersion,PHASE:.status.phase,VOLUME:.spec.volumeName,STORAGE-CLASS:.spec.storageClassName,ACCESS:.spec.accessModes,MODE:.spec.volumeMode,REQUEST:.spec.resources.requests.storage,CREATED:.metadata.creationTimestamp' && { [ -z "$SC" ] || kubectl --context "$CONTEXT" get storageclass "$SC" -o custom-columns='NAME:.metadata.name,UID:.metadata.uid,RV:.metadata.resourceVersion,PROVISIONER:.provisioner,BINDING:.volumeBindingMode,TOPOLOGY:.allowedTopologies,RECLAIM:.reclaimPolicy'; }`

**PVC UID Event 실행:** `refresh_pvc && kubectl --context "$CONTEXT" get events -n "$NS" --field-selector "involvedObject.kind=PersistentVolumeClaim,involvedObject.name=$PVC,involvedObject.uid=$PVC_UID" --sort-by=.metadata.creationTimestamp -o custom-columns='CREATED:.metadata.creationTimestamp,FIRST:.firstTimestamp,LAST:.lastTimestamp,EVENT-TIME:.eventTime,SERIES-LAST:.series.lastObservedTime,TYPE:.type,REASON:.reason,COUNT:.count,MESSAGE:.message'`

Event API 성공과 빈 결과를 구분한다. 이름만 같은 replacement PVC Event를 섞지 않는다.

| 지금 보이는 것 | 먼저 볼 것 | 다음 경로 |
|---|---|---|
| `WaitForFirstConsumer` | 실제 consumer·required topology | [[#1. consumer·topology|1]] |
| `no persistent volumes available` | access/mode/capacity/class/selector | static inventory 또는 provisioner |
| `ProvisioningFailed` | current controller identity와 bounded log | [[#2. CSI provisioner|2]] |
| 이미 `Bound` | PV claimRef와 CSI relation | mount/attach 런북 |

### 1. consumer·topology

**후보 수집:** `if ! refresh_pvc; then printf '%s\n' '중단: fresh PVC gate 실패' >&2; elif PODS_JSON="$(kubectl --context "$CONTEXT" get pods -n "$NS" -o json)"; then jq -r --arg pvc "$PVC" '.items[] | select(any(.spec.volumes[]?; .persistentVolumeClaim.claimName==$pvc)) | "Pod=\(.metadata.name) UID=\(.metadata.uid) RV=\(.metadata.resourceVersion) owner=\([.metadata.ownerReferences[]? | select(.controller==true) | "\(.kind)/\(.name)/\(.uid)"]|join(",")) node=\(.spec.nodeName // "-") phase=\(.status.phase // "-") nodeSelector=\(.spec.nodeSelector) requiredAffinity=\(.spec.affinity.nodeAffinity.requiredDuringSchedulingIgnoredDuringExecution // {})"' <<<"$PODS_JSON"; else printf '%s\n' '중단: Pod API producer 실패' >&2; fi; unset PODS_JSON`

빈 후보는 consumer 미생성일 수 있다. 복수 후보를 임의 선택하지 않는다.

**consumer 선택:** `CONSUMER_POD='PASTE_CONSUMER_POD_HERE'`

**consumer current gate:** `CONSUMER_READY=false; unset CONSUMER_UID CONSUMER_RV CONSUMER_OWNER_KIND CONSUMER_OWNER_NAME CONSUMER_OWNER_UID CONSUMER_NODE; if ! refresh_pvc; then printf '%s\n' '중단: fresh PVC gate 실패' >&2; elif CP="$(kubectl --context "$CONTEXT" get pod "$CONSUMER_POD" -n "$NS" -o json)" && jq -e --arg pvc "$PVC" 'any(.spec.volumes[]?; .persistentVolumeClaim.claimName==$pvc)' <<<"$CP" >/dev/null; then CONSUMER_UID="$(jq -r '.metadata.uid' <<<"$CP")"; CONSUMER_RV="$(jq -r '.metadata.resourceVersion' <<<"$CP")"; CONSUMER_NODE="$(jq -r '.spec.nodeName // ""' <<<"$CP")"; CONSUMER_OWNER_KIND="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)][0].kind // "None"' <<<"$CP")"; CONSUMER_OWNER_NAME="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)][0].name // "None"' <<<"$CP")"; CONSUMER_OWNER_UID="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)][0].uid // "None"' <<<"$CP")"; CONSUMER_READY=true; export CONSUMER_POD CONSUMER_UID CONSUMER_NODE; printf 'CONSUMER_READY=true pod=%s uid=%s rv=%s node=%s owner=%s/%s/%s\n' "$CONSUMER_POD" "$CONSUMER_UID" "$CONSUMER_RV" "${CONSUMER_NODE:-unscheduled}" "$CONSUMER_OWNER_KIND" "$CONSUMER_OWNER_NAME" "$CONSUMER_OWNER_UID"; else printf '%s\n' '중단: consumer→PVC relation 실패' >&2; fi; unset CP`

**consumer current gate 함수:** `refresh_consumer_pvc(){ local cp ok on ou co; CONSUMER_READY=false; cp="$(kubectl --context "$CONTEXT" get pod "$CONSUMER_POD" -n "$NS" -o json)" || return 1; ok="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)][0].kind // "None"' <<<"$cp")"; on="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)][0].name // "None"' <<<"$cp")"; ou="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)][0].uid // "None"' <<<"$cp")"; [ "$(jq -r '.metadata.uid' <<<"$cp")/$ok/$on/$ou" = "$CONSUMER_UID/$CONSUMER_OWNER_KIND/$CONSUMER_OWNER_NAME/$CONSUMER_OWNER_UID" ] && jq -e --arg pvc "$PVC" 'any(.spec.volumes[]?; .persistentVolumeClaim.claimName==$pvc)' <<<"$cp" >/dev/null || return 1; if [ "$CONSUMER_OWNER_KIND" != None ]; then co="$(kubectl --context "$CONTEXT" get "$CONSUMER_OWNER_KIND" "$CONSUMER_OWNER_NAME" -n "$NS" -o jsonpath='{.metadata.uid}' 2>/dev/null)" || return 1; [ "$co" = "$CONSUMER_OWNER_UID" ] || return 1; fi; CONSUMER_RV="$(jq -r '.metadata.resourceVersion' <<<"$cp")"; CONSUMER_NODE="$(jq -r '.spec.nodeName // ""' <<<"$cp")"; CONSUMER_READY=true; return 0; }`

**topology 실행:** `refresh_pvc && refresh_consumer_pvc && kubectl --context "$CONTEXT" get pod "$CONSUMER_POD" -n "$NS" -o custom-columns='NAME:.metadata.name,UID:.metadata.uid,NODE:.spec.nodeName,NODE-SELECTOR:.spec.nodeSelector,AFFINITY:.spec.affinity,TOLERATIONS:.spec.tolerations' && kubectl --context "$CONTEXT" get nodes -o custom-columns='NAME:.metadata.name,UID:.metadata.uid,ZONE:.metadata.labels.topology\.kubernetes\.io/zone,REGION:.metadata.labels.topology\.kubernetes\.io/region,READY:.status.conditions[?(@.type=="Ready")].status'`

`WaitForFirstConsumer`에서 consumer가 없으면 기다림이 failure 증거가 아니다. Pod `FailedScheduling`이면 scheduler 런북으로 이관하고 PVC·node label·affinity를 수정하지 않는다.

### 2. CSI provisioner

**controller·시간 선택:** `CSI_NS='PASTE_CSI_NAMESPACE_HERE'; CSI_POD='PASTE_CSI_CONTROLLER_POD_HERE'; CSI_CONTAINER='PASTE_CSI_PROVISIONER_CONTAINER_HERE'; START_RFC3339='PASTE_LOG_START_UTC_RFC3339_HERE'; END_RFC3339='PASTE_LOG_END_UTC_RFC3339_HERE'`

**controller identity·canonical window gate:** `CSI_READY=false; WINDOW_READY=false; unset CSI_POD_UID CSI_POD_RV CSI_CONTAINER_ID CSI_OWNER_KIND CSI_OWNER_NAME CSI_OWNER_UID START_EPOCH END_EPOCH; if ! refresh_pvc; then printf '%s\n' '중단: fresh PVC gate 실패' >&2; elif [ -z "$PROVISIONER" ] || [ "$PROVISIONER" = None ]; then printf '%s\n' '중단: provisioner 미확정' >&2; elif XP="$(kubectl --context "$CONTEXT" get pod "$CSI_POD" -n "$CSI_NS" -o json)" && XID="$(jq -er --arg c "$CSI_CONTAINER" '[.status.containerStatuses[]? | select(.name==$c and .state.running != null) | .containerID] | if length==1 and .[0]!="" then .[0] else error("CSI container relation") end' <<<"$XP")"; then CSI_POD_UID="$(jq -r '.metadata.uid' <<<"$XP")"; CSI_POD_RV="$(jq -r '.metadata.resourceVersion' <<<"$XP")"; CSI_CONTAINER_ID="$XID"; CSI_OWNER_KIND="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)][0].kind // "None"' <<<"$XP")"; CSI_OWNER_NAME="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)][0].name // "None"' <<<"$XP")"; CSI_OWNER_UID="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)][0].uid // "None"' <<<"$XP")"; START_EPOCH="$(date -u -d "$START_RFC3339" +%s 2>/dev/null)" || START_EPOCH=''; END_EPOCH="$(date -u -d "$END_RFC3339" +%s 2>/dev/null)" || END_EPOCH=''; CREATED_EPOCH="$(date -u -d "$PVC_CREATED" +%s 2>/dev/null)" || CREATED_EPOCH=''; if [[ "$START_RFC3339" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] && [[ "$END_RFC3339" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] && [ -n "$START_EPOCH" ] && [ -n "$END_EPOCH" ] && [ -n "$CREATED_EPOCH" ] && [ "$(date -u -d "@$START_EPOCH" '+%Y-%m-%dT%H:%M:%SZ')" = "$START_RFC3339" ] && [ "$(date -u -d "@$END_EPOCH" '+%Y-%m-%dT%H:%M:%SZ')" = "$END_RFC3339" ] && (( CREATED_EPOCH <= END_EPOCH && START_EPOCH < END_EPOCH )); then CSI_READY=true; WINDOW_READY=true; export CSI_NS CSI_POD CSI_CONTAINER START_RFC3339 END_RFC3339; printf 'CSI_READY=true pod=%s uid=%s container=%s currentID=%s owner=%s/%s/%s\nWINDOW_READY=true start=%s end=%s\n' "$CSI_POD" "$CSI_POD_UID" "$CSI_CONTAINER" "$CSI_CONTAINER_ID" "$CSI_OWNER_KIND" "$CSI_OWNER_NAME" "$CSI_OWNER_UID" "$START_RFC3339" "$END_RFC3339"; else printf '%s\n' '중단: canonical window 또는 PVC 생성 시각 관계 오류' >&2; fi; else printf '%s\n' '중단: current CSI controller/container 확인 실패' >&2; fi; unset XP XID CREATED_EPOCH`

**CSI current gate 함수:** `refresh_csi_pvc(){ local xp cid ok on ou co; CSI_READY=false; xp="$(kubectl --context "$CONTEXT" get pod "$CSI_POD" -n "$CSI_NS" -o json)" || return 1; cid="$(jq -r --arg c "$CSI_CONTAINER" '[.status.containerStatuses[]? | select(.name==$c and .state.running != null) | .containerID] | if length==1 then .[0] else empty end' <<<"$xp")"; ok="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)][0].kind // "None"' <<<"$xp")"; on="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)][0].name // "None"' <<<"$xp")"; ou="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)][0].uid // "None"' <<<"$xp")"; [ "$(jq -r '.metadata.uid' <<<"$xp")/$cid/$ok/$on/$ou" = "$CSI_POD_UID/$CSI_CONTAINER_ID/$CSI_OWNER_KIND/$CSI_OWNER_NAME/$CSI_OWNER_UID" ] || return 1; if [ "$CSI_OWNER_KIND" != None ]; then co="$(kubectl --context "$CONTEXT" get "$CSI_OWNER_KIND" "$CSI_OWNER_NAME" -n "$CSI_NS" -o jsonpath='{.metadata.uid}' 2>/dev/null)" || return 1; [ "$co" = "$CSI_OWNER_UID" ] || return 1; fi; CSI_POD_RV="$(jq -r '.metadata.resourceVersion' <<<"$xp")"; PVC_RE="^$(printf '%s' "$PVC" | sed 's/[][\\.^$*+?(){}|]/\\&/g')$"; CSI_READY=true; return 0; }`

**CSI log direct fresh gate·producer/filter 분리:** `LOG_READY=false; if ! refresh_pvc || ! refresh_csi_pvc || [ "$WINDOW_READY" != true ]; then printf '%s\n' '중단: fresh PVC/CSI/window gate 실패' >&2; elif kubectl --context "$CONTEXT" auth can-i get pods/log -n "$CSI_NS" --quiet; then RAW="$(mktemp)"; CUT="$(mktemp)"; if kubectl --context "$CONTEXT" logs "$CSI_POD" -n "$CSI_NS" -c "$CSI_CONTAINER" --timestamps --since-time="$START_RFC3339" --tail=500 >"$RAW"; then if awk -v end="$END_RFC3339" '$1 <= end' "$RAW" >"$CUT"; then if grep -E -i -C 3 "$PVC_RE|$PVC_UID|provision|CreateVolume|failed|permission|denied|quota|timeout|deadline|already exists" "$CUT"; then LOG_READY=true; elif [ "$?" -eq 1 ]; then printf '%s\n' 'filter no-match: 오류 부재가 아님' >&2; else printf '%s\n' 'regex filter 오류' >&2; fi; else printf '%s\n' '시간 filter 오류' >&2; fi; else printf '%s\n' 'log producer 실패' >&2; fi; rm -f "$RAW" "$CUT"; else printf '%s\n' '중단: pods/log RBAC current gate 실패' >&2; fi`

controller 이름·container는 inventory에서 확인하며 provisioner 문자열만으로 추측하지 않는다. `CreateVolume` 오류를 PVC UID·Event 시각과 연결한다. 민감정보가 보이면 보존을 중단한다.

## 변경 경계·정상화·PromQL

PVC/PV 삭제, claimRef 수정, 강제 bind, StorageClass 교체 명령은 제공하지 않는다. 별도 변경은 fresh PVC/owner/SC UID, current controller revision/containerID, 직접 원인, 승인 ID, 데이터·quota·topology 영향, 멱등성, 중단·rollback이 필요하다. replacement PVC는 새 UID로 전부 재등록한다.

**정상화 gate:** `refresh_pvc && kubectl --context "$CONTEXT" get pvc "$PVC" -n "$NS" -o custom-columns='NAME:.metadata.name,UID:.metadata.uid,RV:.metadata.resourceVersion,PHASE:.status.phase,VOLUME:.spec.volumeName,STORAGE-CLASS:.spec.storageClassName,CREATED:.metadata.creationTimestamp' && { [ -z "$(jq -r '.spec.volumeName // ""' <<<"$PVC_JSON")" ] || kubectl --context "$CONTEXT" get pv "$(jq -r '.spec.volumeName' <<<"$PVC_JSON")" -o custom-columns='NAME:.metadata.name,UID:.metadata.uid,PHASE:.status.phase,CLAIM-NS:.spec.claimRef.namespace,CLAIM:.spec.claimRef.name,CLAIM-UID:.spec.claimRef.uid,DRIVER:.spec.csi.driver'; }`

정상화는 `storage CreateVolume → PV claimRef → PVC Bound → consumer scheduling → attachment/mount → 실제 data read/write·서비스` 순서다. Bound나 Pod Running만으로 닫지 않고 승인된 관찰 창의 새 Warning 부재를 확인한다.

**완성 PromQL 생성:** `QUERY_READY=false; if ! refresh_pvc; then printf '%s\n' '중단: fresh gate 실패' >&2; else NS_Q="$(printf '%s' "$NS" | sed 's/\\/\\\\/g; s/"/\\"/g')"; PVC_Q="$(printf '%s' "$PVC" | sed 's/\\/\\\\/g; s/"/\\"/g')"; QUERY_READY=true; printf 'kube_persistentvolumeclaim_status_phase{namespace="%s",persistentvolumeclaim="%s",phase="Pending"} == 1\n' "$NS_Q" "$PVC_Q"; printf 'kube_persistentvolumeclaim_resource_requests_storage_bytes{namespace="%s",persistentvolumeclaim="%s"}\n' "$NS_Q" "$PVC_Q"; printf 'time() - kube_persistentvolumeclaim_created{namespace="%s",persistentvolumeclaim="%s"}\n' "$NS_Q" "$PVC_Q"; fi`

empty vector, metric·label 미지원, 권한/query 오류와 시간 범위를 분리한다. 보존 항목은 PVC/PV/SC/controller/consumer UID·RV·owner, canonical 창, 결정적 Event/log, CSI driver, topology, 승인·rollback·기능 결과다. 실제 Kubernetes·CSI·storage·Prometheus 환경은 미검증이다.
