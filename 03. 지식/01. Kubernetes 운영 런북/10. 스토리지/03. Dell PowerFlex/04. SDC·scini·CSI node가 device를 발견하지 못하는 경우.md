# SDC·scini·CSI node가 device를 발견하지 못하는 경우

## 입력값과 빠른 수집

연결 경로는 `승인된 작업 host → API server → consumer Pod/PVC/PV → VolumeAttachment → Node UID/machineID → CSI node Pod/current container → 승인 SSH host의 /etc/machine-id → SDC registration/scini → block device/mount`다. 작업 PC 변수는 SSH에 자동 전달되지 않으며 아래 함수는 positional argument로만 전달한다.

| 구분 | 값 | gate |
|---|---|---|
| 최초 입력 | namespace, consumer Pod, 대상 PVC | 승인된 consumer |
| API 자동값 | Pod/PVC/PV/VA/driver/node UID·RV, machineID, CSI node lifecycle | current exact relation |
| 계산 후보 | escaped volume regex | literal escape |
| 운영자 선택 | CSI node Pod/container, 승인 SSH host, kubelet unit, module/device, UTC 창 | inventory·로그·udev 근거 |

```bash

POD='PASTE_POD_HERE'
PVC='PASTE_TARGET_PVC_HERE'

CSI_NODE_CONTAINER='PASTE_CSI_NODE_CONTAINER_HERE'

KERNEL_MODULE='PASTE_SCINI_MODULE_HERE'

return 1; }; POD_JSON="$pod"; PVC_JSON="$pvc"; PV_JSON="$pv"; VA_JSON="$va"; DRIVER_JSON="$driver"; NODE_JSON="$node"; CSI_POD_JSON="$csi"; POD_UID="$(jq -r '.metadata.uid' <<<"$pod")"; POD_RV="$(jq -r '.metadata.resourceVersion' <<<"$pod")"; POD_OWNER_UID="$(jq -r '[.metadata.ownerReferences[]?|select(.controller==true)][0].uid // empty' <<<"$pod")"; NODE_UID="$(jq -r '.metadata.uid' <<<"$node")"; PVC_RV="$(jq -r '.metadata.resourceVersion' <<<"$pvc")"; OBSERVED_AT="$(date -u '+%Y-%m-%dT%H:%M:%SZ')"; ID_READY=true; SELECTION_READY=true; printf 'ID_READY=true Pod=%s uid=%s owner=%s/%s:%s node=%s nodeUID=%s machineID=%s\nPVC=%s uid=%s PV=%s uid=%s VA=%s uid=%s attached=true driver=%s uid=%s\nCSI-node=%s uid=%s owner=%s/%s:%s regular-container=%s containerID=%s observed=%s\n' "$POD" "$POD_UID" "$POD_OWNER_KIND" "$POD_OWNER_NAME" "$POD_OWNER_UID" "$NODE" "$NODE_UID" "$MACHINE_ID" "$PVC" "$PVC_UID" "$PV" "$PV_UID" "$VA" "$VA_UID" "$DRIVER" "$DRIVER_UID" "$CSI_NODE_POD" "$CSI_POD_UID" "$CSI_OWNER_KIND" "$CSI_OWNER_NAME" "$CSI_OWNER_UID" "$CSI_NODE_CONTAINER" "$CSI_CONTAINER_ID" "$OBSERVED_AT"; }
consumer_owner_gate(){ [ "$ID_READY" = true ] || return 1; local resource; case "$POD_OWNER_KIND" in ReplicaSet) resource=replicaset ;; StatefulSet) resource=statefulset ;; DaemonSet) resource=daemonset ;; Job) resource=job ;; *) fail '지원하지 않는 consumer owner kind'; return 1 ;; esac; [ "$(kubectl get "$resource" "$POD_OWNER_NAME" -n "$NS" -o jsonpath='{.metadata.uid}')" = "$POD_OWNER_UID" ] || { fail 'consumer current owner UID 변경'; return 1; }; }
auth_gate(){ AUTH_READY=false; [ "$ID_READY" = true ] || return 1; [ "$(kubectl auth can-i get "pods/$CSI_NODE_POD" --subresource=log -n "$CSI_NS")" = yes ] || { fail "현재 주체 get pods/$CSI_NODE_POD/log 거부 namespace=$CSI_NS"; return 1; }; AUTH_READY=true; }
window_log(){ local source="$1" output="$2" start end line stamp epoch; start="$(date -u -d "$START_RFC3339" +%s)" || return 2; end="$(date -u -d "$END_RFC3339" +%s)" || return 2; : >"$output" || return 2; while IFS= read -r line; do stamp="${line%% *}"; epoch="$(date -u -d "$stamp" +%s 2>/dev/null)" || return 2; if [ "$epoch" -ge "$start" ] && [ "$epoch" -le "$end" ]; then printf '%s\n' "$line" >>"$output" || return 2; fi; done <"$source"; }
```

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | 같은 PV/node의 VA가 attached인데 CSI node가 device를 찾지 못함 |
| 적용 | consumer→PVC→PV→VA→Node machineID→CSI node lifecycle→승인 SSH host를 연결 가능 |
| 제외 | attached=false, VA 없음/Multi-Attach는 [[03. volume mapping·MDM·권한 문제로 attach·publish가 실패하는 경우]] |

검색 문자열: `NodeStageVolume`, `NodePublishVolume`, `device not found`, `no such device`, `scini`, `SDC`, `MDM`, `udev`, `block device`.

`csi_evidence`로 CSI 실패를 고정한 뒤에만 `host_evidence`를 실행한다. remote 경계에서 API machineID를 `/etc/machine-id`와 재검증하며, node 전용 도구는 remote 분기에서만 요구한다. device path는 CSI/udev 증거로 선택하며 추측하지 않는다. 이 문서는 CRI를 사용하지 않으므로 `crictl`이나 추정 socket을 실행하지 않는다.

## 판정과 변경 경계

| 관측 | 다음 owner | 비보장 |
|---|---|---|
| module 없음/미로드 | node/kernel·PowerFlex SDC owner | module 존재만으로 SDC 등록을 보장하지 않음 |
| SDC 미등록 또는 MDM 연결 실패 | PowerFlex/MDM/network owner | endpoint 연결만으로 mapping을 보장하지 않음 |
| block device 없음 | CSI node→SDC/scini→MDM mapping | attached=true는 node device를 보장하지 않음 |
| device 있음, mount/fstype 오류 | Linux filesystem/multipath owner | device 존재는 데이터 무결성을 보장하지 않음 |

Secret, token, endpoint, SDC GUID 원문은 출력하지 않는다. Kubernetes `pods/log` RBAC, SSH authorization, PowerFlex authorization/audit은 각각 별도 경계다.

module reload, reboot, SDC/MDM 재등록, CSI/kubelet 재시작, force detach, VA 삭제, multipath flush와 filesystem repair 명령은 제공하지 않는다. 변경은 fresh identity·host evidence, 다른 volume/workload 영향, 승인 ID, 이전 원본, rollback 담당자와 중단 조건이 필요하다.

정상화는 `MDM/mapping → SDC registration → scini → 기대 block device identity → CSI stage/publish → mount → consumer 기능 → 같은 창의 오류 재발 없음` 순서다. CSI Pod 교체 시 DaemonSet current selector에서 target Node의 단일 새 Pod를 골라 새 UID/containerID로 전체 등록한다. Node Ready, Pod Running, attached=true 또는 device 등장 하나만으로 닫지 않는다. PromQL 빈 vector는 metric 미지원·label/cluster/time/API 오류 후보다.
