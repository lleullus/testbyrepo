# Pod의 DNS 질의가 timeout·SERVFAIL로 실패하는 경우

## 입력값과 빠른 수집

API 명령은 승인된 작업 PC 또는 bastion의 같은 Bash에서 실행한다. 질의 hop은 `client Pod UID·현재 regular containerID/network namespace → 적용된 resolv.conf·dnsPolicy/dnsConfig → nameserver → DNS Service UID/ClusterIP:53 → EndpointSlice UID·Service owner UID → current DNS Pod UID/IP·containerID → CoreDNS process → 조건부 upstream`이다. `hostNetwork=true`이면 client resolver는 node network namespace를 공유한다.

| lifecycle | 값 | 등록 계약 |
|---|---|---|
| 최초 입력 | client namespace/Pod, exact RBAC subject, incident ID | 운영 기록의 exact 값 한 번 입력 |
| API 확인 자동값 | client UID/RV/node/owner, container 후보, dnsPolicy/dnsConfig | 전체 API 성공 뒤 원자 등록 |
| 계산 후보값 | DNS Service/Slice/Pod/container, resolver 도구 | bounded 출력 뒤 선택 |
| 운영자 선택값 | client container, query name, UTC window, DNS Service, Slice·DNS Pod/container | current relation과 canonical time 검증 |

실제 query name, 응답 주소, nameserver, Secret·token은 증거에 저장하지 않는다.

### client 선택·canonical UTC

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | current client container에서 같은 질의가 `timeout`, `SERVFAIL`, `i/o timeout`, `no servers could be reached`로 실패한다. |
| 적용 | client resolver 설정과 DNS Service→Slice→current DNS Pod relation을 같은 UTC 창에 연결할 수 있다. |
| 제외 | `NXDOMAIN`은 이름·search suffix 경로, DNS Service/Slice 자체 문제는 [[06. 클러스터 네트워크/02. Service·EndpointSlice/02. Service endpoint가 잘못되거나 오래된 Pod를 가리키는 경우]], CoreDNS 공통 장애는 [[07. DNS/02. CoreDNS/01. CoreDNS Pod·Service가 Ready하지 않거나 질의에 응답하지 않는 경우]]로 이동한다. |

검색 문자열: `timeout`, `SERVFAIL`, `i/o timeout`, `no servers could be reached`, `nameserver`, `dnsPolicy`, `dnsConfig`, `CoreDNS`, `kube-dns`.

## 명령별 fresh gate와 resolver 증거

`fresh_app(){ local a cid; a="$(kubectl get pod "$APP_POD" -n "$APP_NS" -o json)" || return 1; cid="$(jq -r --arg c "$APP_CONTAINER" '.status.containerStatuses[]? | select(.name==$c) | .containerID // empty' <<<"$a")"; [ "$(jq -r '.metadata.uid' <<<"$a")" = "$APP_UID" ] && [ "$(jq -r '.metadata.resourceVersion' <<<"$a")" = "$APP_RV" ] && [ "$(jq -r '.spec.nodeName' <<<"$a")" = "$APP_NODE" ] && [ "$(jq -r '.metadata.ownerReferences[]? | select(.controller==true) | .kind' <<<"$a")" = "$APP_OWNER_KIND" ] && [ "$(jq -r '.metadata.ownerReferences[]? | select(.controller==true) | .name' <<<"$a")" = "$APP_OWNER_NAME" ] && [ "$(jq -r '.metadata.ownerReferences[]? | select(.controller==true) | .uid' <<<"$a")" = "$APP_OWNER_UID" ] && [ "$cid" = "$APP_CONTAINER_ID" ]; }`

### 1. 적용된 resolver와 응답 유형

`if [ "$AUTH_READY" != true ] || [ "$RELATION_READY" != true ] || [ "$TIME_READY" != true ] || ! fresh_app; then RESOLVER_READY=false; printf '%s\n' '중단: fresh resolv.conf exec gate 실패' >&2; elif RESOLV_OUT="$(kubectl exec "$APP_POD" -n "$APP_NS" -c "$APP_CONTAINER" -- sh -c 'test -r /etc/resolv.conf || exit 2; exec sed -n "/^[[:space:]]*\(nameserver\|search\|options\)[[:space:]]/p" /etc/resolv.conf')"; then RESOLVER_READY=true; printf '%s\nRESOLVER_READY=true hostNetwork=%s dnsPolicy=%s\n' "$RESOLV_OUT" "$HOST_NETWORK" "$DNS_POLICY"; else printf '%s\n' '중단: resolv.conf producer/tool 실패' >&2; fi`

화면에서 nameserver/search/ndots를 확인하되 원문은 저장하지 않는다. `ClusterFirst`, `Default`, `ClusterFirstWithHostNet`, `None`의 기대와 실제 적용이 다르면 owner template/kubelet/NodeLocal DNSCache 경로로 이관한다.

`CLIENT_EVIDENCE_READY=false; EVIDENCE_READY=false; if [ "$AUTH_READY" != true ] || [ "$RESOLVER_READY" != true ] || [ "$TIME_READY" != true ] || [ "$ARGV_READY" != true ] || ! fresh_app; then printf '%s\n' '중단: fresh DNS query gate 실패' >&2; elif QUERY_OUT="$(kubectl exec "$APP_POD" -n "$APP_NS" -c "$APP_CONTAINER" -- sh -c 'if command -v dig >/dev/null 2>&1; then dig +time=2 +tries=1 "$1" A; rc=$?; tool=dig; elif command -v nslookup >/dev/null 2>&1; then nslookup "$1"; rc=$?; tool=nslookup; elif command -v getent >/dev/null 2>&1; then getent hosts "$1"; rc=$?; tool=getent; else printf "%s\n" "resolver-tool-unavailable" >&2; exit 127; fi; printf "resolver_tool=%s query_rc=%s\n" "$tool" "$rc"' sh "$QUERY_NAME" 2>&1)"; then CLIENT_EVIDENCE_READY=true; OBSERVED_AT="$(date -u '+%Y-%m-%dT%H:%M:%SZ')"; printf '%s\nCLIENT_EVIDENCE_READY=true observed_at=%s\n' "$QUERY_OUT" "$OBSERVED_AT"; else printf '중단: query exec producer/tool 실패: %s\n' "$QUERY_OUT" >&2; fi`

`NXDOMAIN`, `SERVFAIL`, timeout을 같은 원인으로 기록하지 않는다. `query_rc`는 도구 결과이고 exec producer 성공과 별개다. DNS 응답 성공은 application 연결 성공을 보장하지 않는다.

### 2. DNS Service·EndpointSlice·current DNS Pod 등록

실제 resolver nameserver와 클러스터 설정을 대조한 뒤 DNS Service를 선택한다. NodeLocal DNSCache 주소이면 그 agent의 실제 upstream Service가 확인되기 전에는 다음 hop을 추측하지 않는다.

`DNS_NS='PASTE_DNS_NAMESPACE_HERE'; DNS_SVC='PASTE_DNS_SERVICE_HERE'`

`DNS_READY=false; CANDIDATE_READY=false; EVIDENCE_READY=false; unset DNS_SVC_UID DNS_SVC_RV DNS_CLUSTER_IP DNS_SELECTOR; if [ "$RESOLVER_READY" != true ] || [ "$TIME_READY" != true ] || ! fresh_app || ! [[ "$DNS_NS" =~ ^[a-z0-9]([-a-z0-9]*[a-z0-9])?$ && "$DNS_SVC" =~ ^[a-z0-9]([-a-z0-9]*[a-z0-9])?$ ]]; then printf '%s\n' '중단: DNS Service selection/fresh client gate 실패' >&2; elif ! kubectl auth can-i get services -n "$DNS_NS" -q || ! kubectl auth can-i get endpointslices.discovery.k8s.io -n "$DNS_NS" -q || ! kubectl auth can-i get pods -n "$DNS_NS" -q || ! kubectl auth can-i get pods/log -n "$DNS_NS" -q; then printf '중단: exact DNS get services/slices/pods/pods-log RBAC 부족 subject=%s\n' "$AUDIT_SUBJECT" >&2; elif DS="$(kubectl get service "$DNS_SVC" -n "$DNS_NS" -o json)" && ES="$(kubectl get endpointslice -n "$DNS_NS" -l "kubernetes.io/service-name=$DNS_SVC" -o json)" && DP="$(kubectl get pods -n "$DNS_NS" -o json)"; then DU="$(jq -r '.metadata.uid // empty' <<<"$DS")"; BAD_OWNER="$(jq -r --arg u "$DU" '[.items[] | select(([.metadata.ownerReferences[]? | select(.kind=="Service" and .uid==$u and .controller==true)] | length)!=1)] | length' <<<"$ES")"; DNS_SELECTOR_TMP="$(jq -r '(.spec.selector // {}) | to_entries | sort_by(.key) | map("\(.key)=\(.value)") | join(",")' <<<"$DS")"; if [ -z "$DU" ] || [ -z "$DNS_SELECTOR_TMP" ] || [ "$(jq -r '.items | length' <<<"$ES")" -eq 0 ] || [ "$BAD_OWNER" != 0 ]; then printf '%s\n' '중단: DNS Service identity/selector/Slice owner/후보 불완전' >&2; else DNS_SVC_UID="$DU"; DNS_SVC_RV="$(jq -r '.metadata.resourceVersion' <<<"$DS")"; DNS_CLUSTER_IP="$(jq -r '.spec.clusterIP // empty' <<<"$DS")"; DNS_SELECTOR="$DNS_SELECTOR_TMP"; DNS_READY=true; CANDIDATE_READY=true; printf 'DNS_READY=true service_uid=%s rv=%s clusterIP_registered=%s selector=%s\n' "$DNS_SVC_UID" "$DNS_SVC_RV" "$([ -n "$DNS_CLUSTER_IP" ]; printf '%s' "$?")" "$DNS_SELECTOR"; jq -r '"=== DNS Service port ===",(.spec.ports[]? | "name=\(.name // \"-\") port=\(.port) target=\(.targetPort) protocol=\(.protocol)")' <<<"$DS"; jq -r '.items[] | "=== Slice: \(.metadata.name) uid=\(.metadata.uid) rv=\(.metadata.resourceVersion) owner=\([.metadata.ownerReferences[]? | \"\(.kind)/\(.name)/\(.uid)\"]|join(\",\")) ===\n" + ([.endpoints[]? | "target=\(.targetRef.name // \"-\")/\(.targetRef.uid // \"-\") ready=\(.conditions.ready // \"-\") serving=\(.conditions.serving // \"-\") terminating=\(.conditions.terminating // \"-\")"] | join("\n"))' <<<"$ES"; jq -r --arg sel "$DNS_SELECTOR" '.items[] | select(.metadata.labels as $l | ($sel|split(",")|map(split("=") as $p | $l[$p[0]]==$p[1])|all)) | "DNS Pod 후보 name=\(.metadata.name) uid=\(.metadata.uid) node=\(.spec.nodeName) containers=\([.spec.containers[].name]|join(\",\"))"' <<<"$DP"; fi; else printf '%s\n' '중단: DNS API producer 실패' >&2; fi`

후보 filter 오류, 성공/no-match, API producer 실패를 구분한다. Slice·Pod가 비면 정상으로 해석하지 않는다.

`SLICE='PASTE_DNS_ENDPOINTSLICE_HERE'; DNS_POD='PASTE_DNS_POD_HERE'; DNS_CONTAINER='PASTE_DNS_CONTAINER_HERE'`

`SELECTION_READY=false; RELATION_READY=false; unset SLICE_UID SLICE_RV DNS_POD_UID DNS_POD_RV DNS_POD_IP DNS_NODE DNS_CONTAINER_ID; if [ "$DNS_READY" != true ] || [ "$TIME_READY" != true ] || ! fresh_app || ! [[ "$SLICE" =~ ^[a-z0-9]([-a-z0-9.]*[a-z0-9])?$ && "$DNS_POD" =~ ^[a-z0-9]([-a-z0-9.]*[a-z0-9])?$ && "$DNS_CONTAINER" =~ ^[a-z0-9]([-a-z0-9.]*[a-z0-9])?$ ]]; then printf '%s\n' '중단: DNS target selection gate 실패' >&2; elif ES="$(kubectl get endpointslice "$SLICE" -n "$DNS_NS" -o json)" && DP="$(kubectl get pod "$DNS_POD" -n "$DNS_NS" -o json)" && [ "$(jq -r '.metadata.ownerReferences[]? | select(.kind=="Service" and .controller==true) | .uid' <<<"$ES")" = "$DNS_SVC_UID" ]; then DPU="$(jq -r '.metadata.uid' <<<"$DP")"; EPC="$(jq -r --arg p "$DNS_POD" --arg u "$DPU" '[.endpoints[]? | select(.targetRef.kind=="Pod" and .targetRef.namespace==$ENV.DNS_NS and .targetRef.name==$p and .targetRef.uid==$u and (.conditions.ready==true or .conditions.serving==true))] | length' <<<"$ES")"; CID="$(jq -r --arg c "$DNS_CONTAINER" '.status.containerStatuses[]? | select(.name==$c) | .containerID // empty' <<<"$DP")"; if [ "$EPC" != 1 ] || [ -z "$CID" ]; then printf '%s\n' '중단: exact endpoint target 또는 active DNS container identity 불일치' >&2; else SLICE_UID="$(jq -r '.metadata.uid' <<<"$ES")"; SLICE_RV="$(jq -r '.metadata.resourceVersion' <<<"$ES")"; DNS_POD_UID="$DPU"; DNS_POD_RV="$(jq -r '.metadata.resourceVersion' <<<"$DP")"; DNS_POD_IP="$(jq -r '.status.podIP' <<<"$DP")"; DNS_NODE="$(jq -r '.spec.nodeName' <<<"$DP")"; DNS_CONTAINER_ID="$CID"; SELECTION_READY=true; RELATION_READY=true; printf 'SELECTION_READY=true slice_uid=%s dns_pod_uid=%s node=%s container=%s containerID=%s\n' "$SLICE_UID" "$DNS_POD_UID" "$DNS_NODE" "$DNS_CONTAINER" "$DNS_CONTAINER_ID"; fi; else printf '%s\n' '중단: DNS Slice/Pod producer 또는 owner relation 실패' >&2; fi`

`fresh_dns(){ local s e p cid; fresh_app || return 1; s="$(kubectl get service "$DNS_SVC" -n "$DNS_NS" -o json)" || return 1; e="$(kubectl get endpointslice "$SLICE" -n "$DNS_NS" -o json)" || return 1; p="$(kubectl get pod "$DNS_POD" -n "$DNS_NS" -o json)" || return 1; cid="$(jq -r --arg c "$DNS_CONTAINER" '.status.containerStatuses[]? | select(.name==$c) | .containerID // empty' <<<"$p")"; [ "$(jq -r '.metadata.uid' <<<"$s")" = "$DNS_SVC_UID" ] && [ "$(jq -r '.metadata.resourceVersion' <<<"$s")" = "$DNS_SVC_RV" ] && [ "$(jq -r '.metadata.uid' <<<"$e")" = "$SLICE_UID" ] && [ "$(jq -r '.metadata.resourceVersion' <<<"$e")" = "$SLICE_RV" ] && [ "$(jq -r '.metadata.ownerReferences[]? | select(.kind=="Service" and .controller==true) | .uid' <<<"$e")" = "$DNS_SVC_UID" ] && [ "$(jq -r '.metadata.uid' <<<"$p")" = "$DNS_POD_UID" ] && [ "$(jq -r '.metadata.resourceVersion' <<<"$p")" = "$DNS_POD_RV" ] && [ "$(jq -r '.status.podIP' <<<"$p")" = "$DNS_POD_IP" ] && [ "$cid" = "$DNS_CONTAINER_ID" ] && [ "$(jq -r --arg u "$DNS_POD_UID" '[.endpoints[]? | select(.targetRef.uid==$u)] | length' <<<"$e")" = 1 ]; }`

### 3. CoreDNS bounded log와 upstream 분기

`LOG_READY=false; EVIDENCE_READY=false; if [ "$AUTH_READY" != true ] || [ "$CLIENT_EVIDENCE_READY" != true ] || [ "$RELATION_READY" != true ] || [ "$TIME_READY" != true ] || ! fresh_dns; then printf '%s\n' '중단: fresh DNS log gate 실패' >&2; elif LOGS="$(kubectl logs "$DNS_POD" -n "$DNS_NS" -c "$DNS_CONTAINER" --timestamps --since-time="$START_RFC3339" --tail=200)"; then FILTERED="$(grep -E -i -C 3 'SERVFAIL|timeout|forward|proxy|upstream|i/o timeout|no such host|refused' <<<"$LOGS")"; FRC=$?; if [ "$FRC" -eq 0 ]; then LOG_READY=true; EVIDENCE_READY=true; printf '%s\nLOG_READY=true EVIDENCE_READY=true\n' "$FILTERED"; elif [ "$FRC" -eq 1 ]; then LOG_READY=true; EVIDENCE_READY=true; printf '%s\n' 'LOG_READY=true EVIDENCE_READY=true filter-no-match: 오류 부재가 아니다.'; else printf 'filter-error rc=%s\n' "$FRC" >&2; fi; else printf '%s\n' '중단: kubectl logs producer 실패' >&2; fi`

timeout은 client→nameserver Service/dataplane/policy와 CoreDNS 지연 후보, `SERVFAIL`과 같은 시각의 `forward` 오류는 upstream 후보다. 내부 이름은 성공하고 외부 이름만 실패할 때만 upstream route·firewall로 이관한다. 전체 Corefile·upstream 주소·로그를 저장하지 않는다.

## 변경·rollback·정상화

Pod 삭제·rollout, dnsPolicy/dnsConfig·NetworkPolicy·Service·Corefile patch, CoreDNS restart 명령은 제공하지 않는다. 별도 owner 절차는 fresh target/evidence, exact subject/RBAC, 승인 ID·UTC window, 영향 namespace·availability/quorum, 멱등성, 중단 조건과 검증된 rollback 원본을 요구한다.

`MUTATION_READY=false; ROLLBACK_READY=false; NORMALIZATION_READY=false; if [ "$AUTH_READY" != true ] || [ "$EVIDENCE_READY" != true ] || [ "$RELATION_READY" != true ] || [ "$TIME_READY" != true ] || [ "$ARGV_READY" != true ] || ! fresh_dns; then printf '%s\n' '중단: fresh 변경 gate 실패' >&2; else printf '%s\n' '진단 완료: 이 런북에는 변경 명령이 없다.'; fi`

변경·rollback 뒤 `invalidate_all`로 기존 app/DNS Pod/Slice/containerID relation과 selection을 폐기한다. replacement는 owner kind/name/UID, current Pod UID/RV/node/containerID와 새 Slice UID/RV·Service owner·targetRef 단일 관계를 다시 등록한다. 정상화는 `설정 원본 → client resolv.conf → DNS Service/Slice/current DNS Pod → query 응답 유형·지연 → 승인된 실제 application 요청` 순으로 검증하고 관찰 창 동안 timeout·SERVFAIL·새 Warning·restart 증가가 없어야 한다. DNS 응답 한 번, Pod `Running`, endpoint `ready=true`는 정상화가 아니다.

## Prometheus 빠른 관측

실제 metric과 labels를 확인한 환경에서만 등록값으로 완성 query를 생성한다.

`if [ "$DNS_READY" != true ] || [ "$RELATION_READY" != true ] || [ "$TIME_READY" != true ] || ! fresh_dns; then printf '%s\n' '중단: fresh query gate 실패' >&2; else printf 'sum by (rcode) (rate(coredns_dns_responses_total{pod="%s",rcode=~"SERVFAIL|REFUSED"}[5m]))\n' "$DNS_POD"; fi`

빈 결과는 정상/0이 아니다. query producer·권한 오류, metric 미수집, 이름/label 불일치, 시간 범위 오류와 no-series를 분리한다. 이 query는 특정 client UID, Service dataplane, upstream 원인을 증명하지 않는다.

## 증거·미검증

UTC window, incident ID, exact subject/RBAC, client UID/RV/owner/node/containerID와 resolver 위치·정책 요약, DNS Service/Slice/DNS Pod UID/RV/owner/node/containerID·conditions, 응답 유형, producer/filter 결과와 승인·rollback·replacement·실제 기능만 보존한다. 실제 query/address/nameserver, Secret, token, kubeconfig, private key, payload, 전체 Corefile·로그는 저장하지 않는다.

NodeLocal DNSCache, stub domain, CNI/NetworkPolicy, CoreDNS plugin·upstream과 실제 Kubernetes 1.26 환경은 미검증이다.
