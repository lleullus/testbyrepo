# 외부 도메인만 해석되지 않거나 upstream DNS 전달이 실패하는 경우

## 입력값과 빠른 수집

실행 hop은 `current client Pod resolver → DNS Service UDP/TCP 53 → selected CoreDNS Pod/plugin → upstream resolver UDP/TCP 53 → authoritative DNS`다. client query, CoreDNS process, target node egress와 authoritative 응답은 서로 다른 실행 위치와 책임 경계다.

| 분류 | 변수 | 출처와 gate |
|---|---|---|
| 최초 입력 | client namespace/Pod, DNS namespace/Service | 승인된 실제 객체 |
| API 자동값 | client·Service·CoreDNS Pod·owner·node·ConfigMap UID/RV와 current containerID | 현재 selector·owner·key 관계가 모두 맞을 때 등록 |
| 계산 후보 | `DNS_POD_RE` | 선택 CoreDNS Pod 이름 regex escape |
| 운영자 선택 | regular containers, 내부 기준 이름, 외부 이름, Corefile ConfigMap/key, 승인 SSH target/upstream 목적지, UTC 창 | 실제 구현·증거·inventory에서 선택 |

upstream_fresh() {
  FRESH_READY=false; CLIENT_READY=false; CONFIG_READY=false; LOG_READY=false; HOST_READY=false; QUERY_READY=false
  local c s d m cn dn co do_ ccid dcid
  [ "$AUTO_READY" = true ] || return 1
  c="$(kubectl get pod "$POD" -n "$NS" -o json)" || return 1; s="$(kubectl get service "$DNS_SERVICE" -n "$DNS_NS" -o json)" || return 1; d="$(kubectl get pod "$DNS_POD" -n "$DNS_NS" -o json)" || return 1; m="$(kubectl get configmap "$CONFIGMAP" -n "$DNS_NS" -o json)" || return 1
  cn="$(kubectl get node "$CLIENT_NODE" -o json)" || return 1; dn="$(kubectl get node "$DNS_NODE" -o json)" || return 1; co="$(kubectl get "$CLIENT_OWNER_KIND" "$CLIENT_OWNER_NAME" -n "$NS" -o json)" || return 1; do_="$(kubectl get "$DNS_OWNER_KIND" "$DNS_OWNER_NAME" -n "$DNS_NS" -o json)" || return 1
  ccid="$(jq -r --arg x "$CONTAINER" '[.status.containerStatuses[]?|select(.name==$x)][0].containerID//empty' <<<"$c")"; dcid="$(jq -r --arg x "$DNS_CONTAINER" '[.status.containerStatuses[]?|select(.name==$x)][0].containerID//empty' <<<"$d")"
  [ "$(jq -r '.metadata.uid' <<<"$c")" = "$CLIENT_UID" ] && [ "$(jq -r '[.metadata.ownerReferences[]?|select(.controller==true)][0].uid//.metadata.uid' <<<"$c")" = "$CLIENT_OWNER_UID" ] && [ "$(jq -r '.metadata.uid' <<<"$co")" = "$CLIENT_OWNER_UID" ] && [ "$(jq -r '.metadata.uid' <<<"$cn")" = "$CLIENT_NODE_UID" ] && [ "$(jq -r '.status.nodeInfo.machineID' <<<"$cn")" = "$CLIENT_MACHINE_ID" ] && [ "$ccid" = "$CLIENT_CONTAINER_ID" ] && [ "$(jq -r '.metadata.uid' <<<"$s")" = "$SERVICE_UID" ] && jq -e --argjson sel "$(jq -c '.spec.selector' <<<"$s")" '.metadata.labels as $l|($sel|to_entries|all($l[.key]==.value))' <<<"$d" >/dev/null && [ "$(jq -r '.metadata.uid' <<<"$d")" = "$DNS_POD_UID" ] && [ "$(jq -r '[.metadata.ownerReferences[]?|select(.controller==true)][0].uid//.metadata.uid' <<<"$d")" = "$DNS_OWNER_UID" ] && [ "$(jq -r '.metadata.uid' <<<"$do_")" = "$DNS_OWNER_UID" ] && [ "$(jq -r '.metadata.uid' <<<"$dn")" = "$DNS_NODE_UID" ] && [ "$(jq -r '.status.nodeInfo.machineID' <<<"$dn")" = "$DNS_MACHINE_ID" ] && [ "$dcid" = "$DNS_CONTAINER_ID" ] && [ "$(jq -r '.metadata.uid' <<<"$m")" = "$CONFIGMAP_UID" ] && jq -e --arg k "$CORE_KEY" '.data|has($k)' <<<"$m" >/dev/null && jq -e --arg cm "$CONFIGMAP" --arg key "$CORE_KEY" 'any(.spec.volumes[]?;.configMap.name==$cm and ((.configMap.items|not) or any(.configMap.items[]?;.key==$key)))' <<<"$d" >/dev/null || return 1
  FRESH_READY=true
}

upstream_logs() {
  upstream_fresh || { printf '%s\n' '중단: fresh identity gate 실패' >&2; return 1; }
  [ "$(kubectl auth can-i get pods/log -n "$DNS_NS")" = yes ] || return 1
  local raw rc line ts epoch end_epoch window out frc
  raw="$(kubectl logs "$DNS_POD" -n "$DNS_NS" -c "$DNS_CONTAINER" --timestamps --since-time="$START_RFC3339" --tail=500)"; rc=$?; [ "$rc" -eq 0 ] || { printf 'producer rc=%s\n' "$rc" >&2; return "$rc"; }
  end_epoch="$(date -u -d "$END_RFC3339" +%s)"; window=''
  while IFS= read -r line; do ts="${line%% *}"; epoch="$(date -u -d "$ts" +%s 2>/dev/null)" || return 2; [ "$epoch" -le "$end_epoch" ] && window+="$line"$'\n'; done <<<"$raw"
  [ -n "$window" ] || { printf '%s\n' '증거 창 empty' >&2; return 3; }
  if out="$(grep -E -i -C 3 'SERVFAIL|forward|upstream|timeout|i/o timeout|no such host|refused|network unreachable' <<<"$window")"; then LOG_READY=true; printf '%s\n' "$out"; else frc=$?; printf 'filter no-match rc=%s; 오류 부재 아님\n' "$frc" >&2; return "$frc"; fi
}

복수 CoreDNS Pod에서 첫 후보를 자동 선택하지 않는다. `DNS_POD`를 바꾸면 selector·owner·node·containerID·ConfigMap 상태를 모두 폐기하고 다시 등록한다.

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | 같은 current client에서 내부 이름은 성공하지만 외부 이름만 NXDOMAIN·SERVFAIL·timeout인 경우 |
| 적용 | DNS Service→selected CoreDNS Pod/plugin→target node/upstream을 같은 UTC 창에 연결할 수 있는 경우 |
| 제외 | 내부·외부가 모두 실패하면 [[07. DNS/02. CoreDNS/01. CoreDNS Pod·Service가 Ready하지 않거나 질의에 응답하지 않는 경우]], Service 이름만 실패하면 [[01. Kubernetes Service 이름이 NXDOMAIN이거나 잘못된 주소를 반환하는 경우]]로 이동한다. |

검색 문자열: `NXDOMAIN`, `SERVFAIL`, `i/o timeout`, `forward`, `healthcheck`, `network unreachable`, `connection refused`.

## 관측별 진단 경로

| 지금 보이는 것 | 먼저 볼 것 | 그다음 어디를 볼지 | 상세 절 |
|---|---|---|---|
| 내부 성공, 외부 NXDOMAIN | authoritative record/stub zone | DNS owner | [[#1. 동일 client 비교와 plugin 경로|1]] |
| 내부 성공, 외부 SERVFAIL | forward/plugin log와 upstream response | CoreDNS/upstream owner | [[#1. 동일 client 비교와 plugin 경로|1]] |
| 내부 성공, 외부 timeout | selected CoreDNS node→upstream route | network owner | [[#2. 조건부 target node egress|2]] |
| 내부·외부 모두 실패 | DNS Service endpoint와 resolver | 공통 DNS 경로 | [[#1. 동일 client 비교와 plugin 경로|1]] |

### 1. 동일 client 비교와 plugin 경로

`if upstream_fresh && [ "$FRESH_READY" = true ] && [ "$(kubectl auth can-i create pods/exec -n "$NS")" = yes ]; then kubectl exec "$POD" -n "$NS" -c "$CONTAINER" -- sh -c 'if command -v dig >/dev/null 2>&1; then dig +time=2 +tries=1 "$1" A; r1=$?; dig +time=2 +tries=1 "$2" A; r2=$?; elif command -v nslookup >/dev/null 2>&1; then nslookup "$1"; r1=$?; nslookup "$2"; r2=$?; elif command -v getent >/dev/null 2>&1; then getent ahosts "$1"; r1=$?; getent ahosts "$2"; r2=$?; else exit 127; fi; printf "internal_rc=%s external_rc=%s\n" "$r1" "$r2"; [ "$r1" -eq 0 ]' sh "$INTERNAL_QUERY" "$EXTERNAL_QUERY"; RC=$?; printf 'clientUID=%s containerID=%s compare_rc=%s observed=%s window=%s..%s\n' "$CLIENT_UID" "$CLIENT_CONTAINER_ID" "$RC" "$(date -u '+%Y-%m-%dT%H:%M:%SZ')" "$START_RFC3339" "$END_RFC3339"; else printf '%s\n' '중단: fresh client exec gate 실패' >&2; fi`

`getent`는 NXDOMAIN과 SERVFAIL을 분류하지 못한다. 내부도 실패하면 upstream lane을 닫는다. query·응답 주소·resolver 원문은 저장하지 않는다.

`if upstream_fresh && [ "$FRESH_READY" = true ]; then kubectl get service "$DNS_SERVICE" -n "$DNS_NS" -o custom-columns='UID:.metadata.uid,RV:.metadata.resourceVersion,PORTS:.spec.ports[*].port,PROTOCOLS:.spec.ports[*].protocol,TARGET-PORTS:.spec.ports[*].targetPort,SELECTOR:.spec.selector' && kubectl get endpointslice -n "$DNS_NS" -l "kubernetes.io/service-name=$DNS_SERVICE" -o custom-columns='UID:.metadata.uid,RV:.metadata.resourceVersion,TARGET-UID:.endpoints[*].targetRef.uid,READY:.endpoints[*].conditions.ready,SERVING:.endpoints[*].conditions.serving,PORTS:.ports[*].port,PROTOCOLS:.ports[*].protocol'; else printf '%s\n' '중단: fresh Service/CoreDNS gate 실패' >&2; fi`

EndpointSlice target UID와 UDP/TCP port를 current Pod와 대조한다. 빈 출력은 API/RBAC 실패와 실제 endpoint 0개를 구분한다.

`if upstream_fresh && [ "$FRESH_READY" = true ]; then RAW="$(kubectl get configmap "$CONFIGMAP" -n "$DNS_NS" -o json | jq -r --arg k "$CORE_KEY" '.data[$k]//empty')"; PRC=$?; if [ "$PRC" -ne 0 ] || [ -z "$RAW" ]; then printf '중단: Corefile producer/empty rc=%s\n' "$PRC" >&2; elif OUT="$(grep -E -i '^[[:space:]]*(forward|proxy|kubernetes|cache|errors|reload)([[:space:]]|\{|$)' <<<"$RAW")"; then CONFIG_READY=true; sed -E 's/^[[:space:]]*([^[:space:]{]+).*/\1/' <<<"$OUT"; printf 'configmap=%s uid=%s currentRV=%s key=%s\n' "$CONFIGMAP" "$CONFIGMAP_UID" "$(kubectl get configmap "$CONFIGMAP" -n "$DNS_NS" -o jsonpath='{.metadata.resourceVersion}')" "$CORE_KEY"; else FRC=$?; printf 'plugin filter no-match rc=%s\n' "$FRC" >&2; fi; unset RAW OUT; else printf '%s\n' '중단: fresh ConfigMap gate 실패' >&2; fi`

Corefile 원문·zone·upstream 주소를 출력하거나 저장하지 않는다.

`upstream_logs`

### 2. 조건부 target node egress

내부 질의가 성공하고 CoreDNS log가 upstream timeout/refused를 같은 창에 기록한 경우에만 node owner가 실행한다. `SSH_TARGET`은 inventory상 current `DNS_NODE`에 대응해야 한다. 원격 경계에서는 Kubernetes Node의 machineID와 `/etc/machine-id`를 재검증한다. 작업 PC 변수는 positional argument로만 전달하고 동적 shell 평가는 사용하지 않는다.

`if upstream_logs >/dev/null && [ "$FRESH_READY" = true ] && [ "$LOG_READY" = true ] && [[ "$SSH_TARGET" =~ ^[A-Za-z0-9._@:-]+$ ]] && [[ "$UPSTREAM_DEST" =~ ^([0-9]{1,3}\.){3}[0-9]{1,3}$|^[0-9A-Fa-f:]+$ ]]; then ssh "$SSH_TARGET" 'set -eu; command -v ip >/dev/null 2>&1; expected_machine=$1; destination=$2; actual_machine=$(tr -d "\n" </etc/machine-id); [ "$actual_machine" = "$expected_machine" ] || { printf "machine-id-mismatch expected=%s actual=%s\n" "$expected_machine" "$actual_machine" >&2; exit 42; }; printf "host=%s machineID=%s observed=" "$(hostname -f)" "$actual_machine"; date -u "+%Y-%m-%dT%H:%M:%SZ"; ip route get "$destination"' sh "$DNS_MACHINE_ID" "$UPSTREAM_DEST"; RC=$?; if [ "$RC" -eq 0 ]; then HOST_READY=true; else HOST_READY=false; printf '중단: remote producer/identity rc=%s\n' "$RC" >&2; fi; else HOST_READY=false; printf '%s\n' '중단: fresh/log/SSH/destination gate 실패' >&2; fi`

`ip`는 원격 target node 분기에서만 필요하다. route 성공은 UDP/TCP 53, firewall, return path와 authoritative 응답을 보장하지 않는다. packet capture, 반복 query, firewall 해제와 route 변경은 이 문서에서 실행하지 않는다.

## Prometheus 빠른 관측

CoreDNS series에 current Pod를 식별하는 `pod` label이 실제 있을 때만 사용한다.

`if upstream_fresh && [ "$FRESH_READY" = true ]; then QUERY_READY=true; printf 'sum(increase(coredns_proxy_healthcheck_failures_total{pod=~"%s",proxy_name="forward"}[5m])) > 0\n' "$DNS_POD_RE"; printf 'increase(coredns_forward_healthcheck_broken_total{pod=~"%s"}[5m]) > 0\n' "$DNS_POD_RE"; printf 'histogram_quantile(0.99,sum by(le)(rate(coredns_proxy_request_duration_seconds_bucket{pod=~"%s",proxy_name="forward"}[5m])))\n' "$DNS_POD_RE"; else QUERY_READY=false; printf '%s\n' '중단: fresh PromQL gate 실패' >&2; fi`

완성 query를 입력 UTC 창에서 사용한다. unsupported metric 또는 empty 결과는 0이 아니며 metric 이름, plugin, scrape/API, label과 권한을 확인한다. upstream `to` label은 저장 전에 마스킹한다.

## 변경·정상화

이 문서는 CoreDNS ConfigMap, NodeLocal, NetworkPolicy, route/firewall와 Pod DNS 변경 명령을 제공하지 않는다. 별도 mutation lane에는 fresh 객체/host UID/current RV와 owner/selector/revision/image digest, 같은 UTC 창의 내부·외부 response와 plugin/log/route 증거, 승인 ID·변경 시각, cluster/replica/quorum, upstream rate limit·요청 멱등성, 검증된 rollback revision이 필요하다.

Pod 교체나 rollback 뒤 모든 UID/RV/node/containerID와 gate를 폐기한다. current owner UID·selector·revision·creationTimestamp로 단일 새 Pod를 다시 선택한다. 정상화는 `client resolver → DNS Service/endpoint → CoreDNS process/plugin → target node egress → upstream response → 내부/외부 query → 실제 외부 의존 기능` 순으로 확인하며 승인 관찰 창에 재발이 없어야 한다.

## 증거 보존

UTC 창, client·Service·CoreDNS Pod·owner·node·ConfigMap·EndpointSlice UID/current RV, regular containerID runtime prefix, port/protocol/condition, response 유형/rc, 비식별 plugin/log/route, remote machineID 검증과 승인·rollback ID를 보존한다. domain/upstream/address/label 원문, Secret/token, Corefile·전체 log/audit body는 저장하지 않는다.
