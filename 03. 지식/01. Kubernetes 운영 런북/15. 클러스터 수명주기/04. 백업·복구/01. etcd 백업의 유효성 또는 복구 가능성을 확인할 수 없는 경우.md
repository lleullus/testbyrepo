# etcd 백업의 유효성 또는 복구 가능성을 확인할 수 없는 경우

## 입력값과 빠른 수집

| 구분 | 값 | 출처와 gate |
|---|---|---|
| 최초 입력 | `BACKUP_RECORD`, `ARTIFACT_ID` | 승인 backup inventory의 exact 식별자 |
| API 확인 자동값 | `RECORD_RV`, `ARTIFACT_OWNER`, `SOURCE_CLUSTER_UID`, `ARTIFACT_REVISION`, `ARTIFACT_HASH`, `ARTIFACT_SIZE` | 같은 immutable record에서 확인 |
| 계산 후보값 | `ARTIFACT_RE`, `SOURCE_RE` | literal regex escape, 출력 대조 전 미확정 |
| 운영자 선택값 | `START_RFC3339`, `END_RFC3339`, 조건부 `APPROVED_HOST`, `VALIDATION_MACHINE_ID`, `ARTIFACT_PATH`, `SNAPSHOT_TOOL` | 승인 검증 window와 격리 host identity·copy/tool owner 기록 |

경로는 `작업 PC/bastion -> backup inventory API -> storage/provider equipment -> immutable artifact -> 격리 검증 host -> snapshot tool`이다. restore는 별도 경로인 `격리 restore target -> etcd member topology -> API server -> Kubernetes object/workload 기능`에서만 검증한다. 운영 member endpoint·TLS·data directory를 추측하지 않는다.

### artifact refresh

`refresh_artifact(){ unset AUTO_READY CANDIDATE_READY AUTH_READY EVIDENCE_READY MUTATION_READY ROLLBACK_READY NORMALIZATION_READY RECORD_RV ARTIFACT_OWNER SOURCE_CLUSTER_UID ARTIFACT_REVISION ARTIFACT_HASH ARTIFACT_SIZE CURRENT_NODE APPROVED_HOST CONTAINER_IDS RELATIONS ARGV_RE ARTIFACT_RE SOURCE_RE ARTIFACT_PATH SNAPSHOT_TOOL; AUTO_READY=false; CANDIDATE_READY=false; [ "$INPUT_READY" = true ] && [ "$SELECTION_READY" = true ] || { printf '%s\n' '중단: 입력·시간 gate가 없다.' >&2; return 1; }; local data count rv owner source rev hash size are sre; data="$(approved_backup_get --record "$BACKUP_RECORD" --exact-artifact "$ARTIFACT_ID" --output json)" || { printf '%s\n' 'producer 실패: backup inventory 조회 실패' >&2; return 1; }; count="$(jq -r '.items|length' <<<"$data")" || { printf '%s\n' 'filter 오류: inventory JSON parse 실패' >&2; return 1; }; [ "$count" = 1 ] || { printf 'no match: exact artifact count=%s\n' "$count" >&2; return 1; }; rv="$(jq -r '.items[0].resourceVersion // empty' <<<"$data")"; owner="$(jq -r '.items[0].owner // empty' <<<"$data")"; source="$(jq -r '.items[0].sourceClusterUID // empty' <<<"$data")"; rev="$(jq -r '.items[0].snapshotRevision // empty' <<<"$data")"; hash="$(jq -r '.items[0].sha256 // empty' <<<"$data")"; size="$(jq -r '.items[0].sizeBytes // empty' <<<"$data")"; return 1; }; are="$(printf '%s' "$ARTIFACT_ID" | sed 's/[][\\.^$*+?(){}|]/\\&/g')"; sre="$(printf '%s' "$source" | sed 's/[][\\.^$*+?(){}|]/\\&/g')" || return 1; RECORD_RV="$rv"; ARTIFACT_OWNER="$owner"; SOURCE_CLUSTER_UID="$source"; ARTIFACT_REVISION="$rev"; ARTIFACT_HASH="${hash,,}"; ARTIFACT_SIZE="$size"; ARTIFACT_RE="^${are}$"; SOURCE_RE="^${sre}$"; RELATIONS="record:$BACKUP_RECORD@$RECORD_RV->artifact:$ARTIFACT_ID->source:$SOURCE_CLUSTER_UID@revision:$ARTIFACT_REVISION"; }`

`approved_backup_get`은 조직의 승인 read-only helper 계약이다. 없으면 owner가 같은 필드를 제공할 때까지 중단한다. refresh는 현재 IDs/RV/owners/container IDs/node·host/relations/time 파생값/argv-regex와 이후 gate를 먼저 폐기하며 실패 시 stale 값이 없다.

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | artifact는 있으나 hash/size/revision/source identity/status 또는 restore test가 없어 복구 가능성을 판단할 수 없는 경우 |
| 적용 | immutable record, 격리 copy와 source/target 관계를 읽기 전용으로 대조하는 경우 |
| 제외 | managed control-plane restore와 실제 member/data-dir 변경은 provider/control-plane owner의 승인 절차로 이관 |

검색 문자열: `snapshot`, `revision`, `cluster ID`, `sha256`, `total keys`, `corrupt`, `incomplete`, `expired`, `restore`, `quorum`, `encryption config`.

## 관측별 진단 경로

| 지금 보이는 것 | 먼저 볼 것 | 그다음 어디를 볼지 | 상세 절 |
|---|---|---|---|
| artifact absent/expired/incomplete | exact storage object와 retention | backup/storage equipment owner | [[#1. artifact와 snapshot status]] |
| hash·size 불일치 | 격리 copy 계산값 | replication/transfer 경계 | [[#1. artifact와 snapshot status]] |

### 1. artifact와 snapshot status

storage/provider equipment object ID와 immutable/retention/status는 inventory relation에 정확히 연결한다. URI query, credential, storage Secret은 출력하지 않는다. provider API producer 실패, object no match, response filter 오류를 분리한다.

격리 host와 copy path/tool은 owner가 승인한 경우에만 선택한다. SSH host/path/tool은 allowlist하고 positional argument로 전달하며 `eval`하지 않는다. `etcdctl` 또는 `etcdutl` 중 실제 version이 snapshot format을 지원하는 도구 하나만 사용한다.

```bash
APPROVED_HOST_INPUT='PASTE_APPROVED_VALIDATION_HOST_HERE'
VALIDATION_MACHINE_ID_INPUT='PASTE_EXPECTED_VALIDATION_MACHINE_ID_HERE'
ARTIFACT_PATH_INPUT='PASTE_ISOLATED_ARTIFACT_PATH_HERE'
SNAPSHOT_TOOL_INPUT='PASTE_ETCDCTL_OR_ETCDUTL_HERE'
unset APPROVED_HOST VALIDATION_MACHINE_ID ARTIFACT_PATH SNAPSHOT_TOOL
EVIDENCE_READY=false
if ! refresh_artifact; then
  printf '%s\n' '중단: artifact를 최신 상태로 refresh하지 못했다.' >&2
elif [ "$AUTO_READY" != true ] || ! [[ "$APPROVED_HOST_INPUT" =~ ^[A-Za-z0-9._@:-]+$ ]] || ! [[ "$VALIDATION_MACHINE_ID_INPUT" =~ ^[A-Fa-f0-9]{32}$ ]] || [[ "$ARTIFACT_PATH_INPUT" != /* ]] || ! [[ "$ARTIFACT_PATH_INPUT" =~ ^/[A-Za-z0-9._/@+-]+$ ]] || { [ "$SNAPSHOT_TOOL_INPUT" != etcdctl ] && [ "$SNAPSHOT_TOOL_INPUT" != etcdutl ]; }; then
  printf '%s\n' '중단: fresh artifact 또는 host identity/path/tool 선택 오류' >&2
elif RESULT="$(ssh -- "$APPROVED_HOST_INPUT" bash -s -- "$ARTIFACT_PATH_INPUT" "$SNAPSHOT_TOOL_INPUT" "$VALIDATION_MACHINE_ID_INPUT" <<'REMOTE'
set -eu
path=$1
tool=$2
expected_machine_id=$3
actual_machine_id=$(tr -d '\n' </etc/machine-id)
[ "$actual_machine_id" = "$expected_machine_id" ]
[ -f "$path" ] || { printf '%s\n' 'NO_MATCH=file'; exit 3; }
command -v "$tool" >/dev/null
hash=$(sha256sum -- "$path")
hash=${hash%% *}
size=$(stat -c '%s' -- "$path")
status=$("$tool" snapshot status "$path" --write-out=json)
printf 'REMOTE_HOST=%s\nMACHINE_ID=%s\nHASH=%s\nSIZE=%s\n' "$(hostname -f 2>/dev/null || hostname)" "$actual_machine_id" "$hash" "$size"
printf 'TOOL_VERSION_BEGIN\n'
"$tool" version
printf 'TOOL_VERSION_END\nSTATUS=%s\n' "$status"
REMOTE
)"; then
  CALC_HASH=$(sed -n 's/^HASH=//p' <<<"$RESULT")
  CALC_SIZE=$(sed -n 's/^SIZE=//p' <<<"$RESULT")
  STATUS_JSON=$(sed -n 's/^STATUS=//p' <<<"$RESULT")
  if ! STATUS_REVISION=$(jq -er 'if type=="array" then .[0].revision else .revision end' <<<"$STATUS_JSON"); then
    printf '%s\n' 'filter 오류: snapshot status JSON/revision 해석 실패' >&2
  elif [ "${CALC_HASH,,}" != "$ARTIFACT_HASH" ] || [ "$CALC_SIZE" != "$ARTIFACT_SIZE" ] || [ "$STATUS_REVISION" != "$ARTIFACT_REVISION" ]; then
    printf 'no match: record와 copy 불일치 hash=%s size=%s revision=%s\n' "${CALC_HASH:--}" "${CALC_SIZE:--}" "${STATUS_REVISION:--}" >&2
  else
    APPROVED_HOST=$APPROVED_HOST_INPUT
    VALIDATION_MACHINE_ID=$VALIDATION_MACHINE_ID_INPUT
    ARTIFACT_PATH=$ARTIFACT_PATH_INPUT
    SNAPSHOT_TOOL=$SNAPSHOT_TOOL_INPUT
    EVIDENCE_READY=true
    printf 'EVIDENCE_READY=true host=%s machine-id=%s path=%s tool=%s hash=%s size=%s revision=%s\n' "$APPROVED_HOST" "$VALIDATION_MACHINE_ID" "$ARTIFACT_PATH" "$SNAPSHOT_TOOL" "$CALC_HASH" "$CALC_SIZE" "$STATUS_REVISION"
  fi
else
  RC=$?
  if [ "$RC" -eq 3 ] && [ "$RESULT" = 'NO_MATCH=file' ]; then
    printf '%s\n' 'no match: 승인 경로에 regular artifact file이 없음' >&2
  else
    printf 'producer 실패: SSH/identity/tool/status 실패 rc=%s\n' "$RC" >&2
  fi
fi
unset APPROVED_HOST_INPUT VALIDATION_MACHINE_ID_INPUT ARTIFACT_PATH_INPUT SNAPSHOT_TOOL_INPUT RESULT CALC_HASH CALC_SIZE STATUS_JSON STATUS_REVISION RC
```

`EVIDENCE_READY=true`는 원격 `/etc/machine-id`, 계산 hash/size와 status revision이 record와 모두 exact match할 때만 설정된다. status JSON parser 오류는 filter 오류, 불일치는 no match, file/tool/SSH non-zero는 producer 실패다. hash 일치는 source cluster identity·encryption compatibility·restore 성공을 보장하지 않는다.

### 2. restore 가능성과 변경 gate

source cluster UID/ID, etcd version, member topology, encryption config의 비밀 없는 reference, target identity/topology, Kubernetes/CRD compatibility와 격리 restore test가 모두 필요하다. snapshot hash/revision에서 cluster identity를 추측하지 않는다. 운영 endpoint·TLS key·data directory·member credential을 수집하지 않는다.

실제 restore/member 변경/API server restart는 진단과 분리한다. mutation 직전 artifact를 refresh하고 evidence ID, 승인 ID, RPO/RTO와 canonical window, 운영 quorum/current state 보존, 실행 주체, 한 member씩의 순서와 external side effect를 확인한다. restore는 일반적으로 멱등하지 않으며 동일 target 재실행이 data/cluster identity를 교체할 수 있으므로 명시적 재실행 판단이 필요하다. rollback은 기존 data·cluster identity를 보존한 복원 절차와 owner를 증명해야 한다.

hash/status/source mismatch, quorum 감소, API write/Ready 저하, unexpected member 또는 provider evidence 부재가 stop 조건이다. replacement artifact를 만들거나 restore 후에는 이전 ID/relation을 버리고 새 artifact record RV·hash/revision/source relation, target member IDs와 Kubernetes object relation을 재등록한다.

정상화는 `artifact identity -> isolated restore -> etcd member/quorum -> API readyz -> CRD/RBAC/workload object -> desired/Ready/PDB -> 실제 요청·Job/queue side effect`와 재발 관찰을 통과해야 한다. snapshot status 성공이나 API 기동만으로 복구 가능/정상을 선언하지 않는다.

## 메트릭 사용 경계

현재 etcd metric은 immutable artifact ID·hash·revision을 직접 식별하지 않으며 `cluster_uid`도 표준 label 계약이 아니다. 따라서 이 문서는 artifact 검증용 범용 PromQL을 제공하지 않는다. 환경별 external label과 `SOURCE_CLUSTER_UID`의 exact mapping이 증명돼도 current member 상태는 별도 보조 증거일 뿐 artifact 정상·손상을 판정하지 않는다.

## 증거·근거와 미검증

record/RV, artifact ID·status·retention·size/hash/revision, source UID, 격리 host/tool/version/status, target/quorum/RPO/RTO, 승인·rollback·replacement relation과 실제 기능만 보존한다. artifact credential, TLS/private key, encryption 원문, member credential와 DB 원문은 보존하지 않는다.
