# Node drain·교체·제거가 완료되지 않는 경우

## 입력값과 빠른 수집

| 구분 | 값 | 출처와 gate |
|---|---|---|
| 최초 입력 | `INPUT_NODE`, `CHANGE_RECORD` | 승인 change record의 exact node name과 ID |
| API 확인 자동값 | `NODE_UID`, `NODE_RV`, `NODE_MACHINE_ID`, `PROVIDER_ID`, `LEASE_RV`, `POD_RELATIONS` | current Node·Lease·Pod API |
| 계산 후보값 | `NODE_RE`, `ARGV_RE` | literal escape 결과, host/runtime 선택에 사용 전 대조 |
| 운영자 선택값 | `START_RFC3339`, `END_RFC3339`, 조건부 `APPROVED_HOST`, `DRAIN_TIMEOUT` | 승인 window와 inventory/change record |

기본 경로는 `작업 PC/bastion kubectl -> API server -> eviction API -> workload controller -> scheduler -> replacement Pod/node`다. host 확인은 `작업 PC/bastion -> 승인 SSH host -> node -> kubelet -> active CRI endpoint -> runtime -> exact container provider/id`다. provider 장비는 `change record -> provider inventory -> instance/equipment ID -> Node providerID` 관계가 정확히 일치할 때만 owner가 접근한다.

`refresh_node(){ unset AUTO_READY CANDIDATE_READY AUTH_READY EVIDENCE_READY CRI_READY MUTATION_READY ROLLBACK_READY NORMALIZATION_READY NODE_UID NODE_RV PROVIDER_ID LEASE_RV NODE_OWNER CURRENT_NODE APPROVED_HOST CONTAINER_IDS POD_RELATIONS RELATIONS ARGV_RE NODE_RE CRI_ENDPOINT RUNTIME_PROVIDER; `can-i`는 실제 요청 성공을 보장하지 않는다. `Forbidden`을 빈 Pod 목록으로 해석하지 않는다. `list pods --all-namespaces`는 이 exact node의 field selector 증거에만 쓰며 Secret·env·전체 YAML은 수집하지 않는다. eviction/create/delete/patch 권한은 mutation 승인 전 요구하지 않는다.

## 관측별 진단 경로

| 지금 보이는 것 | 먼저 볼 것 | 그다음 어디를 볼지 | 상세 절 |
|---|---|---|---|
| PDB violation | exact PDB UID/RV·selector와 healthy/allowed | matched owner·quorum | [[#1. workload·storage 경계]] |
| unmanaged·emptyDir·hostPath·DaemonSet | full controller owner와 volume type | workload/storage owner | [[#1. workload·storage 경계]] |
| Terminating·unmount·runtime 오류 | Pod UID·containerID·node heartbeat | Pod lifecycle·CRI | [[#2. host·CRI 경계]] |
| drain/삭제/교체 재실행 필요 | fresh target·approval·window | 제한된 mutation | [[#3. 변경과 정상화]] |

### 1. workload·storage 경계

PDB는 drain 오류가 지목한 exact namespace/name만 UID/RV, min/max, current/desired healthy, disruptionsAllowed, selector로 조회한다. selector를 완전한 kubectl selector로 변환할 수 없으면 matched Pod를 추측하지 않는다. unmanaged Pod, `emptyDir`, hostPath/local volume, PVC/PV/VolumeAttachment는 삭제 전에 data owner·backup·detach 관계를 확인한다. DaemonSet이 남는 것은 `--ignore-daemonsets`의 정상 동작일 수 있으나 host process 종료나 node 제거 완료를 보장하지 않는다. StatefulSet/외부 quorum은 leader/member와 replacement readiness를 제품 owner가 확인한다.

### 2. host·CRI 경계

node가 NotReady/Unknown이거나 Terminating Pod와 runtime 오류가 함께 있을 때만 연다. 승인 host는 inventory의 Node UID/providerID와 정확히 연결하고, SSH remote identity가 다르면 중단한다. OpenSSH가 원격 argv를 문자열로 전달하므로 host·node 값은 allowlist 후 remote script positional argument로만 사용하며 `eval`하지 않는다.

```bash
APPROVED_HOST_INPUT='PASTE_APPROVED_NODE_SSH_HOST_HERE'
APPROVED_HOST=''
CRI_READY=false
if [ "$AUTO_READY" != true ] || ! [[ "$APPROVED_HOST_INPUT" =~ ^[A-Za-z0-9._@:-]+$ ]]; then
  printf '%s\n' '중단: fresh Node 또는 승인 host 형식이 없다.' >&2
elif ! NODE_NOW="$(kubectl get node "$CURRENT_NODE" -o json)"; then
  printf '%s\n' 'producer 실패: current Node 재조회 실패' >&2
elif [ "$(jq -r '.metadata.uid // empty' <<<"$NODE_NOW")" != "$NODE_UID" ] || [ "$(jq -r '.metadata.resourceVersion // empty' <<<"$NODE_NOW")" != "$NODE_RV" ] || [ "$(jq -r '.status.nodeInfo.machineID // empty' <<<"$NODE_NOW")" != "$NODE_MACHINE_ID" ]; then
  printf '%s\n' '중단: Node UID/resourceVersion/machineID가 바뀌었으므로 refresh_current_node를 다시 실행한다.' >&2
elif CRI_DATA="$(ssh -- "$APPROVED_HOST_INPUT" bash -s -- "$CURRENT_NODE" "$NODE_MACHINE_ID" <<'REMOTE'
set -eu
expected_node=$1
expected_machine_id=$2
remote_host=$(hostname -f 2>/dev/null || hostname)
actual_machine_id=$(tr -d '\n' </etc/machine-id)
[ "$actual_machine_id" = "$expected_machine_id" ]
main_pid=$(systemctl show kubelet -p MainPID --value)
case $main_pid in ''|0|*[!0-9]*) printf '%s\n' 'active kubelet MainPID 없음' >&2; exit 1;; esac
pid_start=$(sed -n 's/^[^)]*) \([^ ]* \)\{19\}\([^ ]*\).*/\2/p' "/proc/$main_pid/stat")
[ -n "$pid_start" ]
argv=$(tr '\0' '\n' <"/proc/$main_pid/cmdline")
endpoint=$(printf '%s\n' "$argv" | sed -n 's/^--container-runtime-endpoint=//p' | sed -n '1p')
case $endpoint in unix:///*) ;; *) printf '%s\n' 'active kubelet argv의 strict unix CRI endpoint 없음' >&2; exit 1;; esac
printf 'remote_host=%s machine-id=%s expected_node=%s main_pid=%s pid-start=%s cri_endpoint=%s\n' "$remote_host" "$actual_machine_id" "$expected_node" "$main_pid" "$pid_start" "$endpoint"
REMOTE
)"; then
  APPROVED_HOST=$APPROVED_HOST_INPUT
  CRI_ENDPOINT=$(sed -n 's/.* cri_endpoint=//p' <<<"$CRI_DATA")
  [ -n "$CRI_ENDPOINT" ] && CRI_READY=true
  printf 'CRI_READY=%s approved-host=%s %s\n' "$CRI_READY" "$APPROVED_HOST" "$CRI_DATA"
else
  printf '%s\n' 'producer 실패: SSH/remote identity/active kubelet endpoint 확인 실패' >&2
fi
unset APPROVED_HOST_INPUT NODE_NOW CRI_DATA
```

config file이나 systemd environment로 endpoint를 전달해 active argv에 값이 없으면 기본 socket을 추측하지 않는다. node owner가 active kubelet effective config에서 endpoint를 증명해야 한다.

이 절은 active kubelet argv의 endpoint 발견까지만 수행한다. socket provider service, socket inode/owner PID, Pod status의 current `containerID` provider/id를 같은 시점에 검증하지 않았으므로 여기서는 `crictl`을 실행하지 않는다. runtime 조사가 필요하면 [[04. 노드·런타임/03. 컨테이너 런타임·CRI 이상/07. runtime 상태와 Pod container ID가 일치하지 않는 경우]]에서 endpoint exact match, provider 관계와 current container identity를 새로 등록한다. 이름 prefix·짧은 ID·기본 endpoint를 사용하지 않는다.

### 3. 변경과 정상화

cordon/drain/delete/uncordon/provider 교체는 진단과 분리한다. mutation 직전 `refresh_current_node`로 exact Node UID/RV·machineID·Lease·남은 Pod 관계를 다시 얻고 evidence ID, 승인 ID, 실행 window, timeout, PDB/local data/storage/quorum, replacement capacity와 provider equipment relation을 확인한다. eviction·API 재시도의 멱등성, 이미 퇴거된 workload와 외부 Job side effect를 검토한다. rollback은 cordon 해제와 workload/data 복구를 구분하며 uncordon이 Pod를 원복하지 않음을 승인한다.

`--force`, `--delete-emptydir-data`, PDB/finalizer 완화는 일반 경로가 아니다. Ready 감소, PDB/quorum 위험, volume/process 잔류, replacement 미확보가 stop 조건이다. Node delete는 host/runtime/provider 장비를 종료하지 않는다.

변경 뒤 기존 Node/Pod/container/provider 관계를 모두 폐기한다. replacement Node 이름·UID·providerID·Lease, replacement Pod UID·owner·containerID와 volume relation을 새로 등록한다. 정상화는 drain 예외만 남음, old host/process·volume 정리, replacement Ready/Lease, workload desired/Ready·quorum, 실제 요청/Job 결과와 재발 관찰을 확인한다.
