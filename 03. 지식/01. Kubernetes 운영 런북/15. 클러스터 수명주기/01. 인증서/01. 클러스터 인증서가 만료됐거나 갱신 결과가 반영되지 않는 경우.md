# 클러스터 인증서가 만료됐거나 갱신 결과가 반영되지 않는 경우

## 입력값과 빠른 수집

| 구분 | 값 | 출처와 gate |
|---|---|---|
| 최초 입력 | `INPUT_COMPONENT`, `INPUT_ENDPOINT_HOST`, `INPUT_ENDPOINT_PORT` | 사건 기록의 component와 실제 TLS endpoint |
| API 확인 자동값 | `CERT_OWNER`, `ACTIVE_SERIAL`, `ACTIVE_FINGERPRINT`, `ACTIVE_NOT_BEFORE`, `ACTIVE_NOT_AFTER` | 현재 endpoint가 제시한 공개 인증서 |
| 계산 후보값 | `ENDPOINT_AUTHORITY`, `COMPONENT_RE` | 검증된 host:port와 literal regex, 실제 SNI는 아님 |
| 운영자 선택값 | `SNI_NAME`, `START_RFC3339`, `END_RFC3339`, 조건부 `APPROVED_HOST` | inventory·오류 기록과 승인 접근 경로에서 선택 |

연결 경로는 `작업 PC/bastion의 openssl -> DNS/LB -> TLS endpoint -> 현재 serving process -> 공개 인증서 source`다. node 확인이 필요한 경우에만 `작업 PC/bastion -> 승인 SSH host -> node -> component process`를 추가한다. container가 source를 mount하면 `node/kubelet -> Pod UID -> container name·ID -> mount` 관계를 별도로 확인한다. 한 hop의 성공은 다음 hop과 실제 API 기능을 보장하지 않는다.

**도구 확인**

`TOOLS_READY=false; MISSING=''; if [ -z "${BASH_VERSION:-}" ]; then printf '%s\n' '중단: Bash가 아니다.' >&2; else for T in kubectl openssl jq sed date; do command -v "$T" >/dev/null 2>&1 || MISSING="$MISSING $T"; done; if [ -z "$MISSING" ]; then TOOLS_READY=true; printf '%s\n' 'TOOLS_READY=true'; else printf '중단: 없는 도구=%s\n' "$MISSING" >&2; fi; fi`

**입력과 모든 파생 상태 초기화**

`unset INPUT_READY AUTO_READY CANDIDATE_READY SELECTION_READY AUTH_READY EVIDENCE_READY MUTATION_READY ROLLBACK_READY NORMALIZATION_READY CERT_OWNER CERT_SOURCE_UID CERT_SOURCE_RV ACTIVE_SERIAL ACTIVE_FINGERPRINT ACTIVE_NOT_BEFORE ACTIVE_NOT_AFTER CURRENT_NODE APPROVED_HOST CONTAINER_IDS RELATIONS START_RFC3339 END_RFC3339 START_EPOCH END_EPOCH ARGV_RE COMPONENT_RE ENDPOINT_AUTHORITY SNI_NAME; INPUT_COMPONENT='PASTE_EXACT_COMPONENT_HERE'; INPUT_ENDPOINT_HOST='PASTE_TLS_ENDPOINT_HOST_HERE'; INPUT_ENDPOINT_PORT='PASTE_TLS_ENDPOINT_PORT_HERE'; INPUT_READY=false; if [ "$TOOLS_READY" != true ]; then printf '%s\n' '중단: TOOLS_READY가 아니다.' >&2; elif ! [[ "$INPUT_COMPONENT" =~ ^[A-Za-z0-9_.:/@+-]+$ ]] || ! [[ "$INPUT_ENDPOINT_HOST" =~ ^[A-Za-z0-9.-]+$ ]] || ! [[ "$INPUT_ENDPOINT_PORT" =~ ^[0-9]+$ ]] || (( INPUT_ENDPOINT_PORT < 1 || INPUT_ENDPOINT_PORT > 65535 )); then printf '%s\n' '중단: component 또는 endpoint 형식이 잘못됐다.' >&2; else INPUT_READY=true; export INPUT_COMPONENT INPUT_ENDPOINT_HOST INPUT_ENDPOINT_PORT; printf 'INPUT_READY=true component=%s endpoint=%s:%s\n' "$INPUT_COMPONENT" "$INPUT_ENDPOINT_HOST" "$INPUT_ENDPOINT_PORT"; fi`

**시간·SNI 선택과 canonical UTC 검증**

`SNI_INPUT='PASTE_CONFIRMED_SNI_OR_NONE_HERE'; START_INPUT='PASTE_START_UTC_RFC3339_HERE'; END_INPUT='PASTE_END_UTC_RFC3339_HERE'; unset SNI_NAME START_RFC3339 END_RFC3339 START_EPOCH END_EPOCH; SELECTION_READY=false; if [ "$INPUT_READY" != true ]; then printf '%s\n' '중단: INPUT_READY가 아니다.' >&2; elif [ "$SNI_INPUT" != NONE ] && ! [[ "$SNI_INPUT" =~ ^[A-Za-z0-9.-]+$ ]]; then printf '%s\n' '중단: SNI 형식이 잘못됐다.' >&2; elif ! [[ "$START_INPUT" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] || ! [[ "$END_INPUT" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]]; then printf '%s\n' '중단: 시각 형식은 UTC YYYY-MM-DDTHH:MM:SSZ여야 한다.' >&2; elif S="$(date -u -d "$START_INPUT" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" && E="$(date -u -d "$END_INPUT" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" && [ "$S" = "$START_INPUT" ] && [ "$E" = "$END_INPUT" ] && SE="$(date -u -d "$S" +%s)" && EE="$(date -u -d "$E" +%s)" && [ "$SE" -lt "$EE" ]; then [ "$SNI_INPUT" = NONE ] || SNI_NAME="$SNI_INPUT"; START_RFC3339="$S"; END_RFC3339="$E"; START_EPOCH="$SE"; END_EPOCH="$EE"; SELECTION_READY=true; export SNI_NAME START_RFC3339 END_RFC3339; printf 'SELECTION_READY=true sni=%s start=%s end=%s\n' "${SNI_NAME:-none}" "$START_RFC3339" "$END_RFC3339"; else printf '%s\n' '중단: canonical UTC round-trip 또는 start<end 검증 실패' >&2; fi; unset SNI_INPUT START_INPUT END_INPUT S E SE EE`

### 현재 인증서 refresh

refresh는 기존 ID·resourceVersion·owner·container ID·node/host·관계·시간 파생값·argv/regex와 이후 gate를 먼저 비운다. producer 실패, 인증 실패, parser/filter 실패와 no match 어느 경우에도 이전 인증서를 남기지 않는다.

`refresh_certificate(){ unset AUTO_READY CANDIDATE_READY AUTH_READY EVIDENCE_READY MUTATION_READY ROLLBACK_READY NORMALIZATION_READY CERT_OWNER CERT_SOURCE_UID CERT_SOURCE_RV ACTIVE_SERIAL ACTIVE_FINGERPRINT ACTIVE_NOT_BEFORE ACTIVE_NOT_AFTER CURRENT_NODE APPROVED_HOST CONTAINER_IDS RELATIONS ARGV_RE COMPONENT_RE ENDPOINT_AUTHORITY; AUTO_READY=false; CANDIDATE_READY=false; [ "$INPUT_READY" = true ] && [ "$SELECTION_READY" = true ] || { printf '%s\n' '중단: 입력·선택 gate가 준비되지 않았다.' >&2; return 1; }; local pem meta serial fp nb na re; if [ -n "${SNI_NAME:-}" ]; then pem="$(openssl s_client -connect "$INPUT_ENDPOINT_HOST:$INPUT_ENDPOINT_PORT" -servername "$SNI_NAME" -showcerts </dev/null 2>/dev/null)" || { printf '%s\n' 'producer 실패: TLS handshake 실패' >&2; return 1; }; else pem="$(openssl s_client -connect "$INPUT_ENDPOINT_HOST:$INPUT_ENDPOINT_PORT" -showcerts </dev/null 2>/dev/null)" || { printf '%s\n' 'producer 실패: TLS handshake 실패' >&2; return 1; }; fi; meta="$(openssl x509 -noout -serial -dates -fingerprint -sha256 <<<"$pem")" || { printf '%s\n' 'filter 오류: 공개 인증서 parse 실패' >&2; return 1; }; serial="$(sed -n 's/^serial=//p' <<<"$meta")"; fp="$(sed -n 's/^sha256 Fingerprint=//Ip' <<<"$meta")"; nb="$(sed -n 's/^notBefore=//p' <<<"$meta")"; na="$(sed -n 's/^notAfter=//p' <<<"$meta")"; [ -n "$serial" ] && [ -n "$fp" ] && [ -n "$nb" ] && [ -n "$na" ] || { printf '%s\n' 'no match: leaf certificate metadata가 불완전하다.' >&2; return 1; }; re="$(printf '%s' "$INPUT_COMPONENT" | sed 's/[][\\.^$*+?(){}|]/\\&/g')" || return 1; ACTIVE_SERIAL="$serial"; ACTIVE_FINGERPRINT="$fp"; ACTIVE_NOT_BEFORE="$nb"; ACTIVE_NOT_AFTER="$na"; ENDPOINT_AUTHORITY="$INPUT_ENDPOINT_HOST:$INPUT_ENDPOINT_PORT"; COMPONENT_RE="^${re}$"; RELATIONS="endpoint:$ENDPOINT_AUTHORITY->component:$INPUT_COMPONENT->fingerprint:$ACTIVE_FINGERPRINT"; AUTO_READY=true; CANDIDATE_READY=true; printf 'AUTO_READY=true serial=%s fingerprint=%s notBefore=%s notAfter=%s relation=%s regex=%s\n' "$ACTIVE_SERIAL" "$ACTIVE_FINGERPRINT" "$ACTIVE_NOT_BEFORE" "$ACTIVE_NOT_AFTER" "$RELATIONS" "$COMPONENT_RE"; }`

`refresh_certificate`

`openssl s_client`가 출력한 chain의 첫 인증서를 읽는 이 절은 현재 endpoint 관측이다. 공개 파일·Secret·provider 산출물의 active 사용을 아직 증명하지 않는다. `-k`, trust 완화, private key 옵션은 사용하지 않는다.

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | endpoint가 expired/not-yet-valid 인증서를 제시하거나 승인 갱신 산출물과 active fingerprint가 다른 경우 |
| 적용 | endpoint·component·usage·source·process 관계를 serial/fingerprint와 시각으로 연결할 수 있는 경우 |
| 제외 | 사용자 kubeconfig 인증은 API 인증 런북, Ingress/Gateway TLS는 해당 L7 TLS 런북, 애플리케이션 TLS는 서비스 owner로 이관 |

검색 문자열: `certificate expired`, `not yet valid`, `x509`, `unknown authority`, `rotation`, `renew`, `reload`, `old certificate`.

## 관측별 진단 경로

| 지금 보이는 것 | 먼저 볼 것 | 그다음 어디를 볼지 | 상세 절 |
|---|---|---|---|
| active 기간이 현재 UTC 밖 | clock·SNI·endpoint identity | PKI owner와 현재 source | [[#1. active와 산출물 관계]] |
| 산출물은 새 fingerprint, active는 이전 값 | process active reference·reload 계약 | component owner | [[#1. active와 산출물 관계]] |
| node Ready·client TLS도 감소 | node/CSR metadata와 bounded 오류 | node·CA trust owner | [[#2. node와 권한 경계]] |
| 갱신·reload·restart 필요 | quorum·승인·rollback | 별도 변경 | [[#3. 변경과 정상화]] |

### 1. active와 산출물 관계

승인된 renewal record에서 공개 인증서 source의 UID/resourceVersion·owner와 fingerprint만 확인한다. file이면 public certificate만 `openssl x509 -in`으로 읽고, Secret은 metadata/type만 보며 `.data`를 출력하지 않는다. provider object도 비밀 없는 object ID/revision만 사용한다. source fingerprint와 active fingerprint가 같아야 `source -> process -> endpoint` 관계가 성립한다. 파일 존재나 갱신 성공 메시지는 active 사용을 보장하지 않는다.

현재 `notBefore/notAfter`는 `date -u -d`로 epoch 변환해 `START_EPOCH/END_EPOCH` 및 현재 UTC와 비교하되 parse 실패를 만료로 간주하지 않는다. endpoint 인증서의 SAN/issuer는 필요한 비민감 필드만 별도 확인한다.

### 2. node와 권한 경계

Kubernetes CSR은 `kubectl auth can-i get certificatesigningrequests.certificates.k8s.io`가 `yes`인 경우에도 실제 get 성공을 별도 확인한다. `list`가 불필요하면 요구하지 않고 request/certificate byte, kubeconfig와 private key를 출력하지 않는다. `Forbidden`은 CSR 없음이 아니다. approve/deny 권한과 상태 변경은 이 진단에 포함하지 않는다. audit는 승인된 CSR name·username·condition·creation time과 TLS 오류 분류만 certificate owner가 제공한다.

node shell이 꼭 필요한 경우 inventory에서 승인 host를 선택하고 실제 원격 hostname과 node providerID/address 관계를 확인한다. SSH 인자를 allowlist로 검증하고 remote script의 positional argument로 전달하며 `eval`을 쓰지 않는다.

```bash
APPROVED_HOST_INPUT='PASTE_APPROVED_SSH_HOST_HERE'
EXPECTED_MACHINE_ID_INPUT='PASTE_EXPECTED_MACHINE_ID_HERE'
APPROVED_HOST=''
AUTH_READY=false
if [ "$AUTO_READY" != true ] || ! [[ "$APPROVED_HOST_INPUT" =~ ^[A-Za-z0-9._@:-]+$ ]] || ! [[ "$EXPECTED_MACHINE_ID_INPUT" =~ ^[A-Fa-f0-9]{32}$ ]]; then
  printf '%s\n' '중단: fresh 인증서 또는 승인 host/machine identity 형식이 없다.' >&2
elif ssh -- "$APPROVED_HOST_INPUT" bash -s -- "$INPUT_COMPONENT" "$EXPECTED_MACHINE_ID_INPUT" <<'REMOTE'
set -eu
component=$1
expected_machine_id=$2
actual_machine_id=$(tr -d '\n' </etc/machine-id)
[ "$actual_machine_id" = "$expected_machine_id" ]
printf 'remote-host=%s machine-id=%s component=%s\n' "$(hostname -f 2>/dev/null || hostname)" "$actual_machine_id" "$component"
REMOTE
then
  APPROVED_HOST=$APPROVED_HOST_INPUT
  AUTH_READY=true
  printf 'AUTH_READY=true approved-host=%s\n' "$APPROVED_HOST"
else
  printf '%s\n' '중단: SSH 또는 remote identity 확인 실패' >&2
fi
unset APPROVED_HOST_INPUT EXPECTED_MACHINE_ID_INPUT
```

원격 hostname을 inventory의 node UID/providerID와 대조하기 전에는 node 인증서 source·process 명령을 실행하지 않는다. container source라면 Pod UID, owner UID, node, container name과 현재 `containerID` provider/id를 같은 refresh에서 등록한다. 이름만 같은 replacement container에는 이전 관계를 적용하지 않는다.

### 3. 변경과 정상화

renewal, CSR 승인, CA/trust 변경, reload/restart는 진단과 분리한다. mutation 직전 exact endpoint/component/source identity와 active fingerprint를 refresh하고 evidence ID, 승인 ID, 변경 창, 한 번에 한 quorum member/node, 실행 주체와 중단 조건을 확인한다. private key 생성·배포는 PKI 통제를 따른다. 재시도·재발급의 멱등성과 serial 중복/외부 CA side effect를 확인한다. rollback은 이전 승인 인증서·trust·process revision의 복원 경로와 담당자를 증명해야 한다.

변경 뒤 기존 값을 폐기하고 새 source UID/RV·serial/fingerprint·process/container ID·endpoint 관계를 재등록한다. 정상화는 `새 source -> active process reference -> endpoint fingerprint/기간/SAN -> TLS 검증 -> API/node health -> 실제 workload 요청`과 재발 관찰을 통과해야 한다. 파일만 새롭거나 handshake 한 번 성공한 것으로 닫지 않는다.

## 메트릭 사용 경계

표준 certificate metric에는 이 문서의 endpoint authority·active fingerprint·source UID를 함께 연결하는 공통 label 계약이 없다. 따라서 범용 PromQL은 제공하지 않는다. 환경별 target label이 현재 endpoint와 exact match한다고 증명된 경우에만 monitoring owner가 완성 query를 생성하며, metric 부재를 TTL 정상이나 0으로 해석하지 않는다. TTL metric도 active fingerprint와 갱신 반영을 증명하지 않는다.

## 증거·근거와 미검증

endpoint/component, canonical UTC 창, public serial/fingerprint/기간/SAN/issuer, source UID/RV/owner, process·container 관계, 비민감 CSR/TLS 오류, 승인·rollback·재등록·실제 기능 결과만 보존한다. PEM 원문, private key, Secret data, token, kubeconfig, 내부 URL은 보존하지 않는다.
