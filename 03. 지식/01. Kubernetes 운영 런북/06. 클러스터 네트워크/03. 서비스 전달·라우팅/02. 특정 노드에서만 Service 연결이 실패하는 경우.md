# 특정 노드에서만 Service 연결이 실패하는 경우

## 입력값과 빠른 수집

API 명령은 승인된 작업 PC/bastion의 같은 Bash에서 실행한다. 비교 hop은 `실패 client Pod UID/container/node → 같은 Service ClusterIP:port → node-local dataplane → 같은 EndpointSlice`와 `정상 client Pod UID/container/node → 동일한 Service·endpoint`다. Linux read는 CMDB와 Kubernetes Node UID가 일치한 승인 SSH host에서만 실행한다.

| lifecycle | 값 | 등록 계약 |
|---|---|---|
| 최초 입력 | Service, 실패·정상 client Pod, exact RBAC subject, incident ID | 실제 실패와 이미 존재하는 정상 비교 workload만 입력 |
| API 확인 자동값 | Service UID/RV·ClusterIP, 두 client UID/RV·node, Slice UID/RV·owner, node UID | 모든 lookup 성공 뒤 원자 등록 |
| 계산 후보값 | 동일 container·port, 두 node dataplane Pod, endpoint IP, escaped regex | bounded 비교 출력, 첫 후보 자동 선택 금지 |
| 운영자 선택값 | 두 container, protocol/port, endpoint, dataplane Pod/mode, UTC window, 두 approved SSH host/machine ID | exact relation·argv·host identity 검증 |

**도구와 초기 입력**

`invalidate_all`은 재수집 전에 identity·resourceVersion·owner·containerID·node·approved host·relation·time·argv/regex·selection·authorization·evidence·mutation·rollback·normalization READY를 모두 폐기한다. 실패 lookup은 stale/부분 값을 남기지 않는다. exact subject는 audit/승인 기록에서 확인한다.

### 원자적 자동 수집

`invalidate_all; AUTO_READY=false; if [ "$INPUT_READY" != true ]; then printf '%s\n' '중단: INPUT_READY가 아니다.' >&2; elif ! kubectl auth can-i get services -n "$NS" -q || ! kubectl auth can-i get endpointslices.discovery.k8s.io -n "$NS" -q || ! kubectl auth can-i get pods -n "$CLIENT_NS" -q || ! kubectl auth can-i get nodes -q || ! kubectl auth can-i create pods/exec -n "$CLIENT_NS" -q; jq -r '"Fail containers:",(.spec.containers[]?|.name)' <<<"$FJ"; jq -r '"Healthy containers:",(.spec.containers[]?|.name)' <<<"$HJ"; fi; else printf '%s\n' '중단: producer API 실패, stale 값 없음' >&2; fi`

producer 실패, 후보 filter 오류, filter 성공/no-match를 구분한다. EndpointSlice가 비거나 두 client가 같은 node면 이 런북 진입 조건이 아니다.

### 선택·시간·relation

`FAIL_CONTAINER='PASTE_FAILING_CONTAINER_HERE'; HEALTHY_CONTAINER='PASTE_HEALTHY_CONTAINER_HERE'; SERVICE_PORT='PASTE_SERVICE_PORT_HERE'; ENDPOINT_IP='PASTE_ENDPOINT_IP_HERE'; ENDPOINT_PORT='PASTE_ENDPOINT_PORT_HERE'; PROTOCOL='PASTE_TCP_OR_UDP_HERE'; START_RFC3339='PASTE_START_UTC_HERE'; END_RFC3339='PASTE_END_UTC_HERE'`

`SELECTION_READY=false; RELATION_READY=false; TIME_READY=false; ARGV_READY=false; EVIDENCE_READY=false; UTC_RE='^[0-9]{4}-(0[1-9]|1[0-2])-([0-2][0-9]|3[01])T([01][0-9]|2[0-3]):[0-5][0-9]:[0-5][0-9]Z$'; if [ "$AUTO_READY" != true ] || [ "$AUTH_READY" != true ]; then printf '%s\n' '중단: AUTO/AUTH gate 실패' >&2; elif ! [[ "$FAIL_CONTAINER" =~ ^[a-z0-9]([-a-z0-9.]*[a-z0-9])?$ && "$HEALTHY_CONTAINER" =~ ^[a-z0-9]([-a-z0-9.]*[a-z0-9])?$ && "$SERVICE_PORT" =~ ^[0-9]+$ && "$ENDPOINT_PORT" =~ ^[0-9]+$ && "$ENDPOINT_IP" =~ ^[0-9A-Fa-f:.]+$ && "$PROTOCOL" =~ ^(TCP|UDP)$ && "$START_RFC3339" =~ $UTC_RE && "$END_RFC3339" =~ $UTC_RE ]] || (( SERVICE_PORT < 1 || SERVICE_PORT > 65535 || ENDPOINT_PORT < 1 || ENDPOINT_PORT > 65535 )); then printf '%s\n' '중단: selection/argv 형식 오류' >&2; elif [ "$(date -u -d "$START_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" != "$START_RFC3339" ] || [ "$(date -u -d "$END_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" != "$END_RFC3339" ] || [ "$(date -u -d "$START_RFC3339" +%s)" -ge "$(date -u -d "$END_RFC3339" +%s)" ]; then printf '%s\n' '중단: canonical UTC/start<end 실패' >&2; elif FJ="$(kubectl get pod "$FAIL_POD" -n "$CLIENT_NS" -o json)" && HJ="$(kubectl get pod "$HEALTHY_POD" -n "$CLIENT_NS" -o json)" && SJ="$(kubectl get service "$SVC" -n "$NS" -o json)" && EJ="$(kubectl get endpointslice -n "$NS" -l "kubernetes.io/service-name=$SVC" -o json)" && [ "$(jq -r '.metadata.uid' <<<"$FJ")" = "$FAIL_UID" ] && [ "$(jq -r '.metadata.uid' <<<"$HJ")" = "$HEALTHY_UID" ] && [ "$(jq -r '.metadata.uid' <<<"$SJ")" = "$SVC_UID" ] && jq -e --arg c "$FAIL_CONTAINER" 'any(.spec.containers[]?;.name==$c)' <<<"$FJ" >/dev/null && jq -e --arg c "$HEALTHY_CONTAINER" 'any(.spec.containers[]?;.name==$c)' <<<"$HJ" >/dev/null && [ "$(jq -r --arg ip "$ENDPOINT_IP" '[.items[].endpoints[]?|select(any(.addresses[]?;.==$ip) and (.conditions.ready==true or .conditions.serving==true))]|length' <<<"$EJ")" -eq 1 ]; then FAIL_CONTAINER_ID="$(jq -r --arg c "$FAIL_CONTAINER" '.status.containerStatuses[]?|select(.name==$c)|.containerID // empty' <<<"$FJ")"; HEALTHY_CONTAINER_ID="$(jq -r --arg c "$HEALTHY_CONTAINER" '.status.containerStatuses[]?|select(.name==$c)|.containerID // empty' <<<"$HJ")"; ENDPOINT_UID="$(jq -r --arg ip "$ENDPOINT_IP" '.items[].endpoints[]?|select(any(.addresses[]?;.==$ip))|.targetRef.uid' <<<"$EJ")"; SELECTION_READY=true; RELATION_READY=true; TIME_READY=true; ARGV_READY=true; EVIDENCE_READY=true; printf 'SELECTION_READY=true fail=%s/%s node=%s cid=%s healthy=%s/%s node=%s cid=%s service=%s:%s endpoint=%s:%s uid=%s protocol=%s window=%s/%s\n' "$FAIL_POD" "$FAIL_UID" "$FAIL_NODE" "${FAIL_CONTAINER_ID:--}" "$HEALTHY_POD" "$HEALTHY_UID" "$HEALTHY_NODE" "${HEALTHY_CONTAINER_ID:--}" "$CLUSTER_IP" "$SERVICE_PORT" "$ENDPOINT_IP" "$ENDPOINT_PORT" "$ENDPOINT_UID" "$PROTOCOL" "$START_RFC3339" "$END_RFC3339"; else printf '%s\n' '중단: fresh client/container/Service/endpoint 관계 실패' >&2; fi`

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | 동일 Service·protocol·port·UTC 창에서 실패 node client만 실패하고 정상 node client는 성공한다. |
| 제외 | 둘 다 실패하면 공통 Service/endpoint/policy, endpoint 직접 경로도 실패하면 CNI/route, DNS 이름만 실패하면 DNS 경로다. |

검색 문자열: `node-specific`, `syncProxyRules`, `KUBE-SVC`, `ipvs`, `eBPF`, `no route to host`, `connection timed out`.

## 명령별 fresh gate

`fresh_pair(){ local s f h fcid hcid; s="$(kubectl get service "$SVC" -n "$NS" -o json)" || return 1; f="$(kubectl get pod "$FAIL_POD" -n "$CLIENT_NS" -o json)" || return 1; h="$(kubectl get pod "$HEALTHY_POD" -n "$CLIENT_NS" -o json)" || return 1; fcid="$(jq -r --arg c "$FAIL_CONTAINER" '.status.containerStatuses[]? | select(.name==$c) | .containerID // empty' <<<"$f")"; hcid="$(jq -r --arg c "$HEALTHY_CONTAINER" '.status.containerStatuses[]? | select(.name==$c) | .containerID // empty' <<<"$h")"; [ "$(jq -r '.metadata.uid' <<<"$s")" = "$SVC_UID" ] && [ "$(jq -r '.metadata.resourceVersion' <<<"$s")" = "$SVC_RV" ] && [ "$(jq -r '.metadata.uid' <<<"$f")" = "$FAIL_UID" ] && [ "$(jq -r '.metadata.resourceVersion' <<<"$f")" = "$FAIL_RV" ] && [ "$(jq -r '.spec.nodeName' <<<"$f")" = "$FAIL_NODE" ] && [ -n "$fcid" ] && [ "$fcid" = "$FAIL_CONTAINER_ID" ] && [ "$(jq -r '.metadata.uid' <<<"$h")" = "$HEALTHY_UID" ] && [ "$(jq -r '.metadata.resourceVersion' <<<"$h")" = "$HEALTHY_RV" ] && [ "$(jq -r '.spec.nodeName' <<<"$h")" = "$HEALTHY_NODE" ] && [ -n "$hcid" ] && [ "$hcid" = "$HEALTHY_CONTAINER_ID" ]; }`

**동일 VIP 조건 비교**

`FAIL_EVIDENCE_READY=false; EVIDENCE_READY=false; if [ "$AUTH_READY" != true ] || [ "$RELATION_READY" != true ] || [ "$TIME_READY" != true ] || [ "$ARGV_READY" != true ] || [ "$PROTOCOL" != TCP ] || ! fresh_pair; then printf '%s\n' '중단: fresh failing exec gate 실패' >&2; elif FAIL_OUT="$(kubectl exec "$FAIL_POD" -n "$CLIENT_NS" -c "$FAIL_CONTAINER" -- sh -c 'command -v nc >/dev/null 2>&1 || exit 127; nc -vz -w 3 "$1" "$2"; rc=$?; printf "probe_rc=%s\n" "$rc"' sh "$CLUSTER_IP" "$SERVICE_PORT" 2>&1)"; then FAIL_EVIDENCE_READY=true; printf '%s\nFAIL_EVIDENCE_READY=true\n' "$FAIL_OUT"; else printf '중단: failing exec producer 실패: %s\n' "$FAIL_OUT" >&2; fi`

`HEALTHY_EVIDENCE_READY=false; EVIDENCE_READY=false; if [ "$AUTH_READY" != true ] || [ "$RELATION_READY" != true ] || [ "$TIME_READY" != true ] || [ "$ARGV_READY" != true ] || [ "$PROTOCOL" != TCP ] || ! fresh_pair; then printf '%s\n' '중단: fresh healthy exec gate 실패' >&2; elif HEALTHY_OUT="$(kubectl exec "$HEALTHY_POD" -n "$CLIENT_NS" -c "$HEALTHY_CONTAINER" -- sh -c 'command -v nc >/dev/null 2>&1 || exit 127; nc -vz -w 3 "$1" "$2"; rc=$?; printf "probe_rc=%s\n" "$rc"' sh "$CLUSTER_IP" "$SERVICE_PORT" 2>&1)"; then HEALTHY_EVIDENCE_READY=true; [ "$FAIL_EVIDENCE_READY" = true ] && EVIDENCE_READY=true; printf '%s\nHEALTHY_EVIDENCE_READY=true EVIDENCE_READY=%s\n' "$HEALTHY_OUT" "$EVIDENCE_READY"; else printf '중단: healthy exec producer 실패: %s\n' "$HEALTHY_OUT" >&2; fi`

두 실행의 producer 실패/도구 부재, connect 실패, 성공을 구분한다. 정상 비교가 실패하면 node-specific 결론을 폐기한다. TCP 성공은 application 성공이 아니며 승인된 기존 synthetic으로 실제 기능을 별도 확인한다.

### 두 dataplane identity와 로그

`if [ "$AUTH_READY" != true ] || [ "$RELATION_READY" != true ] || [ "$TIME_READY" != true ] || ! fresh_pair; then EVIDENCE_READY=false; printf '%s\n' '중단: fresh dataplane candidate gate 실패' >&2; else kubectl get pods -n kube-system --field-selector "spec.nodeName=$FAIL_NODE" -o custom-columns='POD:.metadata.name,UID:.metadata.uid,RV:.metadata.resourceVersion,OWNER:.metadata.ownerReferences[?(@.controller==true)].uid,IMAGE:.spec.containers[*].image,READY:.status.containerStatuses[*].ready,CONTAINER-ID:.status.containerStatuses[*].containerID'; kubectl get pods -n kube-system --field-selector "spec.nodeName=$HEALTHY_NODE" -o custom-columns='POD:.metadata.name,UID:.metadata.uid,RV:.metadata.resourceVersion,OWNER:.metadata.ownerReferences[?(@.controller==true)].uid,IMAGE:.spec.containers[*].image,READY:.status.containerStatuses[*].ready,CONTAINER-ID:.status.containerStatuses[*].containerID'; fi`

같은 owner·image·mode인지 확인한다. mode가 다르거나 대체 dataplane이면 kube-proxy 명령을 섞지 않는다. 로그를 사용할 때는 exact Pod UID/container와 canonical UTC window를 같은 원라인에서 재검증하고, `set -o pipefail`로 producer failure, filter no-match(1), filter error(>1)를 분리한다. 전체 로그·Secret·token은 저장하지 않는다.

### 승인 host와 안전 SSH

`FAIL_HOST='PASTE_FAILING_APPROVED_HOST_HERE'; FAIL_MACHINE_ID='PASTE_FAILING_MACHINE_ID_HERE'; HEALTHY_HOST='PASTE_HEALTHY_APPROVED_HOST_HERE'; HEALTHY_MACHINE_ID='PASTE_HEALTHY_MACHINE_ID_HERE'`

`HOST_READY=false; FAIL_HOST_READY=false; HEALTHY_HOST_READY=false; if ! command -v ssh >/dev/null 2>&1; then printf '%s\n' '중단: node 분기에 ssh가 필요하다.' >&2; elif [ "$RELATION_READY" != true ] || [ "$TIME_READY" != true ] || ! fresh_pair || ! [[ "$FAIL_HOST" =~ ^[A-Za-z0-9][A-Za-z0-9.-]*$ && "$HEALTHY_HOST" =~ ^[A-Za-z0-9][A-Za-z0-9.-]*$ && "$FAIL_MACHINE_ID" =~ ^[a-fA-F0-9]{32}$ && "$HEALTHY_MACHINE_ID" =~ ^[a-fA-F0-9]{32}$ && "$ENDPOINT_IP" =~ ^[0-9A-Fa-f:.]+$ ]]; then printf '%s\n' '중단: host/argv gate 실패' >&2; elif [ "$(kubectl get node "$FAIL_NODE" -o jsonpath='{.metadata.uid}')" = "$FAIL_NODE_UID" ] && [ "$(kubectl get node "$HEALTHY_NODE" -o jsonpath='{.metadata.uid}')" = "$HEALTHY_NODE_UID" ] && [ "$(ssh -o BatchMode=yes -o ClearAllForwardings=yes -o PermitLocalCommand=no -o RequestTTY=no -- "$FAIL_HOST" cat /etc/machine-id)" = "$FAIL_MACHINE_ID" ] && [ "$(ssh -o BatchMode=yes -o ClearAllForwardings=yes -o PermitLocalCommand=no -o RequestTTY=no -- "$HEALTHY_HOST" cat /etc/machine-id)" = "$HEALTHY_MACHINE_ID" ]; then FAIL_HOST_READY=true; HEALTHY_HOST_READY=true; HOST_READY=true; printf 'HOST_READY=true fail=%s/%s healthy=%s/%s\n' "$FAIL_NODE" "$FAIL_NODE_UID" "$HEALTHY_NODE" "$HEALTHY_NODE_UID"; else printf '%s\n' '중단: Node UID↔approved host↔machine-id 관계 실패' >&2; fi`

`if [ "$HOST_READY" != true ] || [ "$RELATION_READY" != true ] || [ "$TIME_READY" != true ] || [ "$ARGV_READY" != true ] || ! fresh_pair || [ "$(kubectl get node "$FAIL_NODE" -o jsonpath='{.metadata.uid}')" != "$FAIL_NODE_UID" ] || [ "$(ssh -o BatchMode=yes -o ClearAllForwardings=yes -o PermitLocalCommand=no -o RequestTTY=no -- "$FAIL_HOST" cat /etc/machine-id)" != "$FAIL_MACHINE_ID" ]; then EVIDENCE_READY=false; printf '%s\n' '중단: fresh failing host gate 실패' >&2; else ssh -o BatchMode=yes -o ClearAllForwardings=yes -o PermitLocalCommand=no -o RequestTTY=no -- "$FAIL_HOST" ip route get "$ENDPOINT_IP"; fi`

`if [ "$HOST_READY" != true ] || [ "$RELATION_READY" != true ] || [ "$TIME_READY" != true ] || [ "$ARGV_READY" != true ] || ! fresh_pair || [ "$(kubectl get node "$HEALTHY_NODE" -o jsonpath='{.metadata.uid}')" != "$HEALTHY_NODE_UID" ] || [ "$(ssh -o BatchMode=yes -o ClearAllForwardings=yes -o PermitLocalCommand=no -o RequestTTY=no -- "$HEALTHY_HOST" cat /etc/machine-id)" != "$HEALTHY_MACHINE_ID" ]; then EVIDENCE_READY=false; printf '%s\n' '중단: fresh healthy host gate 실패' >&2; else ssh -o BatchMode=yes -o ClearAllForwardings=yes -o PermitLocalCommand=no -o RequestTTY=no -- "$HEALTHY_HOST" ip route get "$ENDPOINT_IP"; fi`

SSH는 fixed command와 regex 검증된 argument만 사용하며 `eval`, agent/port forwarding, remote shell interpolation을 금지한다. dataplane rule/map은 exact mode와 owner 승인 경로에서 두 node의 같은 bounded key만 비교한다.

## 변경·rollback·정상화

proxy/CNI 재시작, route/rule/map/conntrack 수정, Pod 삭제·재배치 명령은 제공하지 않는다. 별도 mutation은 fresh target/evidence, exact subject/RBAC, UTC window, node/Service 영향·quorum, 멱등성, 검증된 rollback 자료가 있어야 한다.

`MUTATION_READY=false; ROLLBACK_READY=false; NORMALIZATION_READY=false; if [ "$AUTH_READY" != true ] || [ "$EVIDENCE_READY" != true ] || [ "$RELATION_READY" != true ] || [ "$TIME_READY" != true ] || [ "$ARGV_READY" != true ] || ! fresh_pair; then printf '%s\n' '중단: fresh 변경 gate 실패' >&2; else printf '%s\n' '진단 완료: 변경 명령 없음'; fi`

변경/rollback 뒤 모든 identity와 selection을 `invalidate_all`로 폐기하고 replacement client/dataplane Pod UID·node·containerID와 host relation을 재등록한다. 정상화는 `두 node dataplane 선언·sync → rule/map → endpoint route → 동일 endpoint 연결 → 동일 VIP 연결 → 실제 application 기능`을 같은 조건으로 역검증하며 관찰 창 동안 재발·새 Warning·restart 증가가 없어야 한다.

## Prometheus 빠른 관측

`if [ "$AUTO_READY" != true ] || [ "$TIME_READY" != true ] || [ "$RELATION_READY" != true ] || ! fresh_pair; then printf '%s\n' '중단: fresh query identity gate 실패' >&2; else FAIL_NODE_RE="$(printf '%s' "$FAIL_NODE" | sed 's/[][\\.^$*+?(){}|]/\\&/g')"; HEALTHY_NODE_RE="$(printf '%s' "$HEALTHY_NODE" | sed 's/[][\\.^$*+?(){}|]/\\&/g')"; printf 'up{job=~".*(kube-proxy|cilium|calico|service-proxy).*",node=~"^(%s|%s)$"}\n' "$FAIL_NODE_RE" "$HEALTHY_NODE_RE"; fi`

생성 query의 node label이 실제 없으면 사용하지 않는다. 빈 결과는 producer/권한/metric/label/time/no-series를 분리하고 정상으로 보지 않는다. `up=1`은 rule/map·forwarding·기능 정상을 보장하지 않는다.

## 증거와 미검증

UTC window, exact subject/RBAC, Service UID/RV, 두 client·node·dataplane UID/RV/containerID, endpoint, host relation, producer/filter 분류, 승인·rollback·replacement·실제 기능 결과를 보존한다. Secret/token/kubeconfig/private key/payload/전체 ruleset·로그는 저장하지 않는다. dataplane mode, host 접근과 CNI 경로는 환경별 미검증이다.
