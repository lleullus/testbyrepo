# ClusterIP Service에 연결할 수 없는 경우

## 입력값과 빠른 수집

Kubernetes API 명령은 승인된 작업 PC 또는 bastion의 같은 Bash에서 실행한다. 연결 hop은 `작업 host kubectl → API server → client Pod UID/container → Pod network namespace → ClusterIP:SERVICE_PORT → 확인된 Service dataplane → EndpointSlice ENDPOINT_IP:ENDPOINT_PORT → target Pod UID/listener → application`이다. Linux 명령은 별도 승인된 node SSH host에서만 실행한다.

| lifecycle | 값 | 계약 |
|---|---|---|
| 최초 입력 | Service namespace/name, client namespace/Pod, exact RBAC subject, 사건 ID | 문서 전체에서 한 번 입력 |
| API 확인 자동값 | Service UID/RV·ClusterIP·port, Slice UID/RV·owner, client Pod UID/RV·node·container 후보, endpoint target UID | 전체 API 성공 뒤 원자 등록 |
| 계산 후보값 | endpoint·container·dataplane Pod 후보, escaped regex | bounded 출력 후 선택 |
| 운영자 선택값 | client container, endpoint Pod, Service/endpoint port, protocol, UTC window, 조건부 approved SSH host/machine ID | relation·argv·identity 검증 |

**Bash·도구 확인**

재수집 전 `invalidate_all`은 identity·resourceVersion·owner·containerID·node·approved host·relation·time·argv/regex·selection·authorization·evidence·mutation·rollback·normalization과 모든 READY를 폐기한다. 실패 lookup은 이전 값을 남기지 않는다. `AUDIT_SUBJECT`는 승인/audit 기록의 실제 subject이며 kubeconfig user alias로 대체하지 않는다.

### 원자적 자동 수집

`invalidate_all; AUTO_READY=false; if [ "$INPUT_READY" != true ]; then printf '%s\n' '중단: INPUT_READY가 아니다.' >&2; elif ! kubectl auth can-i get services -n "$NS" -q || ! kubectl auth can-i get endpointslices.discovery.k8s.io -n "$NS" -q || ! kubectl auth can-i get pods -n "$CLIENT_NS" -q || ! kubectl auth can-i create pods/exec -n "$CLIENT_NS" -q; API producer 실패, filter 오류, 성공 후 후보 0건을 구분한다. Slice 0건은 dataplane 진단으로 진행하지 않고 EndpointSlice 생성 런북으로 이동한다. 빈 후보나 metric은 성공/0이 아니다.

### 선택·시간·관계 gate

`CLIENT_CONTAINER='PASTE_CLIENT_CONTAINER_HERE'; ENDPOINT_POD='PASTE_ENDPOINT_POD_HERE'; SERVICE_PORT='PASTE_SERVICE_PORT_HERE'; ENDPOINT_PORT='PASTE_ENDPOINT_PORT_HERE'; PROTOCOL='PASTE_TCP_OR_UDP_HERE'; START_RFC3339='PASTE_START_UTC_HERE'; END_RFC3339='PASTE_END_UTC_HERE'`

`SELECTION_READY=false; RELATION_READY=false; TIME_READY=false; ARGV_READY=false; EVIDENCE_READY=false; unset CLIENT_CONTAINER_ID SLICE_UID SLICE_RV ENDPOINT_IP ENDPOINT_UID ENDPOINT_NODE; UTC_RE='^[0-9]{4}-(0[1-9]|1[0-2])-([0-2][0-9]|3[01])T([01][0-9]|2[0-3]):[0-5][0-9]:[0-5][0-9]Z$'; if [ "$AUTO_READY" != true ] || [ "$AUTH_READY" != true ]; then printf '%s\n' '중단: AUTO/AUTH gate 실패' >&2; elif ! ## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | 같은 client Pod UID에서 endpoint 직접 경로와 구분해 ClusterIP 경로가 timeout/refused다. |
| 적용 | Service UID/RV, usable endpoint UID, client UID/containerID/node와 protocol/port를 같은 UTC 창에 연결했다. |
| 제외 | endpoint UID/port가 틀리면 Service·EndpointSlice 런북, 이름 해석이면 DNS 런북, NetworkPolicy 직접 증거가 있으면 보안 런북으로 이동한다. |

검색 문자열: `ClusterIP`, `connection refused`, `i/o timeout`, `no route to host`, `syncProxyRules`, `KUBE-SVC`, `ipvs`, `eBPF`.

## fresh gate와 진단

`fresh_relation(){ local s c p e cid; s="$(kubectl get service "$SVC" -n "$NS" -o json)" || return 1; c="$(kubectl get pod "$CLIENT_POD" -n "$CLIENT_NS" -o json)" || return 1; p="$(kubectl get pod "$ENDPOINT_POD" -n "$NS" -o json)" || return 1; e="$(kubectl get endpointslice -n "$NS" -l "kubernetes.io/service-name=$SVC" -o json)" || return 1; cid="$(jq -r --arg n "$CLIENT_CONTAINER" '.status.containerStatuses[]? | select(.name==$n) | .containerID // empty' <<<"$c")"; [ "$(jq -r '.metadata.uid' <<<"$s")" = "$SVC_UID" ] && [ "$(jq -r '.metadata.resourceVersion' <<<"$s")" = "$SVC_RV" ] && [ "$(jq -r '.metadata.uid' <<<"$c")" = "$CLIENT_UID" ] && [ "$(jq -r '.metadata.resourceVersion' <<<"$c")" = "$CLIENT_RV" ] && [ "$(jq -r '.spec.nodeName' <<<"$c")" = "$CLIENT_NODE" ] && [ -n "$cid" ] && [ "$cid" = "$CLIENT_CONTAINER_ID" ] && [ "$(jq -r '.metadata.uid' <<<"$p")" = "$ENDPOINT_UID" ] && [ "$(jq -r '.spec.nodeName' <<<"$p")" = "$ENDPOINT_NODE" ] && [ "$(jq -r --arg u "$SLICE_UID" '.items[]|select(.metadata.uid==$u)|.metadata.resourceVersion' <<<"$e")" = "$SLICE_RV" ] && [ "$(jq -r --arg u "$SLICE_UID" --arg su "$SVC_UID" '[.items[] | select(.metadata.uid==$u) | .metadata.ownerReferences[]? | select(.kind=="Service" and .controller==true and .uid==$su)] | length' <<<"$e")" = 1 ] && [ "$(jq -r --arg u "$SLICE_UID" --arg pu "$ENDPOINT_UID" --arg ip "$ENDPOINT_IP" --argjson port "$ENDPOINT_PORT" --arg proto "$PROTOCOL" '[.items[] | select(.metadata.uid==$u) as $x | $x.endpoints[]? | select(.targetRef.uid==$pu and any(.addresses[]?; .==$ip)) as $ep | $x.ports[]? | select(.port==$port and .protocol==$proto)] | length' <<<"$e")" = 1 ]; }`

### 동일 client에서 VIP와 endpoint 분리

실제 요청은 HTTP라고 가정하지 않는다. 아래 TCP 확인은 `PROTOCOL=TCP`, active containerID와 client image의 `nc`가 확인되고 application owner가 해당 connect를 승인한 경우에만 각 목적지에 한 번 실행한다. 고정 명령과 검증된 숫자/IP positional argument를 사용하며 `eval`하지 않는다.

`VIP_EVIDENCE_READY=false; EVIDENCE_READY=false; if [ "$AUTH_READY" != true ] || [ "$RELATION_READY" != true ] || [ "$TIME_READY" != true ] || [ "$ARGV_READY" != true ] || [ "$PROTOCOL" != TCP ] || ! fresh_relation; then printf '%s\n' '중단: fresh VIP exec gate 실패' >&2; elif VIP_OUT="$(kubectl exec "$CLIENT_POD" -n "$CLIENT_NS" -c "$CLIENT_CONTAINER" -- sh -c 'command -v nc >/dev/null 2>&1 || { printf "%s\n" "nc-unavailable" >&2; exit 127; }; nc -vz -w 3 "$1" "$2"; rc=$?; printf "probe_rc=%s\n" "$rc"' sh "$CLUSTER_IP" "$SERVICE_PORT" 2>&1)"; then VIP_EVIDENCE_READY=true; printf '%s\nVIP_EVIDENCE_READY=true\n' "$VIP_OUT"; else printf '중단: VIP exec producer 실패: %s\n' "$VIP_OUT" >&2; fi`

`ENDPOINT_EVIDENCE_READY=false; EVIDENCE_READY=false; if [ "$AUTH_READY" != true ] || [ "$RELATION_READY" != true ] || [ "$TIME_READY" != true ] || [ "$ARGV_READY" != true ] || [ "$PROTOCOL" != TCP ] || ! fresh_relation; then printf '%s\n' '중단: fresh endpoint exec gate 실패' >&2; elif ENDPOINT_OUT="$(kubectl exec "$CLIENT_POD" -n "$CLIENT_NS" -c "$CLIENT_CONTAINER" -- sh -c 'command -v nc >/dev/null 2>&1 || { printf "%s\n" "nc-unavailable" >&2; exit 127; }; nc -vz -w 3 "$1" "$2"; rc=$?; printf "probe_rc=%s\n" "$rc"' sh "$ENDPOINT_IP" "$ENDPOINT_PORT" 2>&1)"; then ENDPOINT_EVIDENCE_READY=true; [ "$VIP_EVIDENCE_READY" = true ] && EVIDENCE_READY=true; printf '%s\nENDPOINT_EVIDENCE_READY=true EVIDENCE_READY=%s\n' "$ENDPOINT_OUT" "$EVIDENCE_READY"; else printf '중단: endpoint exec producer 실패: %s\n' "$ENDPOINT_OUT" >&2; fi`

VIP 실패·endpoint 성공은 Service dataplane 후보다. 둘 다 실패하면 endpoint listener, CNI route, policy 또는 application 후보다. `refused`는 listener/REJECT 후보, timeout은 drop/route/latency 후보이며 단독 원인 확정이 아니다. TCP 성공은 TLS/HTTP/application 성공이 아니다. producer exec 실패, `nc` 부재, connect no-match/실패를 구분한다.

### dataplane 구현체와 로그

client node의 kube-system Pod 후보를 fresh gate로 읽고 owner·image·UID를 확인한다. 이름으로 kube-proxy를 추측하지 않는다.

`if [ "$AUTH_READY" != true ] || [ "$RELATION_READY" != true ] || [ "$TIME_READY" != true ] || ! fresh_relation || ! kubectl auth can-i get pods -n kube-system -q; then EVIDENCE_READY=false; printf '%s\n' '중단: fresh dataplane read/RBAC gate 실패' >&2; else kubectl get pods -n kube-system --field-selector "spec.nodeName=$CLIENT_NODE" -o custom-columns='POD:.metadata.name,UID:.metadata.uid,RV:.metadata.resourceVersion,OWNER-KIND:.metadata.ownerReferences[?(@.controller==true)].kind,OWNER-NAME:.metadata.ownerReferences[?(@.controller==true)].name,OWNER-UID:.metadata.ownerReferences[?(@.controller==true)].uid,IMAGE:.spec.containers[*].image,READY:.status.containerStatuses[*].ready,CONTAINER-ID:.status.containerStatuses[*].containerID'; fi`

`DP_READY=false; unset DP_UID DP_RV DP_CONTAINER_ID DP_OWNER_KIND DP_OWNER_NAME DP_OWNER_UID; if [ "$AUTH_READY" != true ] || [ "$RELATION_READY" != true ] || [ "$TIME_READY" != true ] || ! fresh_relation || ! kubectl auth can-i get pods -n kube-system -q || ! kubectl auth can-i get pods/log -n kube-system -q || ! [[ "$DP_POD" =~ ^[a-z0-9]([-a-z0-9.]*[a-z0-9])?$ && "$DP_CONTAINER" =~ ^[a-z0-9]([-a-z0-9.]*[a-z0-9])?$ && "$DP_MODE" =~ ^(iptables-legacy|iptables-nft|ipvs|ebpf|other)$ ]]; then printf '%s\n' '중단: fresh dataplane selection/RBAC gate 실패' >&2; elif DJ="$(kubectl get pod "$DP_POD" -n kube-system -o json)" && [ "$(jq -r '.spec.nodeName' <<<"$DJ")" = "$CLIENT_NODE" ]; then DP_UID="$(jq -r '.metadata.uid' <<<"$DJ")"; DP_RV="$(jq -r '.metadata.resourceVersion' <<<"$DJ")"; DP_CONTAINER_ID="$(jq -r --arg c "$DP_CONTAINER" '.status.containerStatuses[]? | select(.name==$c) | .containerID // empty' <<<"$DJ")"; DP_OWNER_KIND="$(jq -r '.metadata.ownerReferences[]? | select(.controller==true) | .kind' <<<"$DJ")"; DP_OWNER_NAME="$(jq -r '.metadata.ownerReferences[]? | select(.controller==true) | .name' <<<"$DJ")"; DP_OWNER_UID="$(jq -r '.metadata.ownerReferences[]? | select(.controller==true) | .uid' <<<"$DJ")"; if [ -z "$DP_UID$DP_RV$DP_CONTAINER_ID$DP_OWNER_KIND$DP_OWNER_NAME$DP_OWNER_UID" ]; then printf '%s\n' '중단: dataplane current container/owner identity 불완전' >&2; else DP_READY=true; printf 'DP_READY=true pod=%s uid=%s rv=%s owner=%s/%s/%s node=%s container=%s containerID=%s mode=%s\n' "$DP_POD" "$DP_UID" "$DP_RV" "$DP_OWNER_KIND" "$DP_OWNER_NAME" "$DP_OWNER_UID" "$CLIENT_NODE" "$DP_CONTAINER" "$DP_CONTAINER_ID" "$DP_MODE"; fi; else printf '%s\n' '중단: dataplane Pod/container/node lookup 실패' >&2; fi`

`EVIDENCE_READY=false; if [ "$DP_READY" != true ] || [ "$AUTH_READY" != true ] || [ "$TIME_READY" != true ] || ! fresh_relation; then printf '%s\n' '중단: fresh dataplane log gate 실패' >&2; elif DJ="$(kubectl get pod "$DP_POD" -n kube-system -o json)" && [ "$(jq -r '.metadata.uid' <<<"$DJ")" = "$DP_UID" ] && [ "$(jq -r '.metadata.resourceVersion' <<<"$DJ")" = "$DP_RV" ] && [ "$(jq -r '.metadata.ownerReferences[]? | select(.controller==true) | .uid' <<<"$DJ")" = "$DP_OWNER_UID" ] && [ "$(jq -r --arg c "$DP_CONTAINER" '.status.containerStatuses[]? | select(.name==$c) | .containerID' <<<"$DJ")" = "$DP_CONTAINER_ID" ] && LOGS="$(kubectl logs "$DP_POD" -n kube-system -c "$DP_CONTAINER" --timestamps --since-time="$START_RFC3339" --tail=200)"; then FILTERED="$(grep -E -i -C 3 'sync|service|endpoint|iptables|ipvs|proxier|error|failed|stale' <<<"$LOGS")"; FRC=$?; if [ "$FRC" -eq 0 ]; then EVIDENCE_READY=true; printf '%s\nEVIDENCE_READY=true\n' "$FILTERED"; elif [ "$FRC" -eq 1 ]; then EVIDENCE_READY=true; printf '%s\n' 'EVIDENCE_READY=true filter-no-match: 오류 없음이 아님'; else printf 'filter-error rc=%s\n' "$FRC" >&2; fi; else printf '%s\n' '중단: dataplane API/log producer 또는 current identity 실패' >&2; fi`

로그 producer 실패는 filter no-match와 다르다. no-match이면 같은 Pod/container/window의 승인된 bounded tail을 별도 fresh gate로 확인하며 Secret·token·주소 원문이 보이면 저장을 중단한다.

### 조건부 node host 확인

node shell은 API 증거로 `CLIENT_NODE`와 Node UID를 확인하고 CMDB의 SSH alias·machine-id 관계가 승인된 경우에만 사용한다. SSH destination은 엄격한 hostname regex, remote 명령 인자는 검증된 IP만 허용한다. `eval`, shell interpolation, agent/port forwarding을 사용하지 않는다.

`APPROVED_HOST='PASTE_APPROVED_SSH_HOST_HERE'; APPROVED_MACHINE_ID='PASTE_APPROVED_MACHINE_ID_HERE'; APPROVED_NODE_UID='PASTE_CLIENT_NODE_UID_HERE'`

`HOST_READY=false; if ! command -v ssh >/dev/null 2>&1; then printf '%s\n' '중단: node 분기에 ssh가 필요하다.' >&2; elif [ "$RELATION_READY" != true ] || [ "$TIME_READY" != true ] || ! fresh_relation || ! [[ "$APPROVED_HOST" =~ ^[A-Za-z0-9][A-Za-z0-9.-]*$ && "$APPROVED_MACHINE_ID" =~ ^[a-fA-F0-9]{32}$ && "$APPROVED_NODE_UID" =~ ^[a-f0-9-]{36}$ && "$ENDPOINT_IP" =~ ^[0-9A-Fa-f:.]+$ ]]; then printf '%s\n' '중단: host/argv 형식 또는 fresh relation 실패' >&2; elif NJ="$(kubectl get node "$CLIENT_NODE" -o json)" && [ "$(jq -r '.metadata.uid' <<<"$NJ")" = "$APPROVED_NODE_UID" ] && REMOTE_ID="$(ssh -o BatchMode=yes -o ClearAllForwardings=yes -o PermitLocalCommand=no -o RequestTTY=no -- "$APPROVED_HOST" cat /etc/machine-id)" && [ "$REMOTE_ID" = "$APPROVED_MACHINE_ID" ]; then HOST_READY=true; printf 'HOST_READY=true node=%s node_uid=%s ssh_host=%s machine_id_verified=true\n' "$CLIENT_NODE" "$APPROVED_NODE_UID" "$APPROVED_HOST"; else printf '%s\n' '중단: Kubernetes Node↔approved host↔machine-id 관계 실패' >&2; fi`

`if [ "$HOST_READY" != true ] || [ "$RELATION_READY" != true ] || [ "$TIME_READY" != true ] || [ "$ARGV_READY" != true ] || ! fresh_relation || [ "$(kubectl get node "$CLIENT_NODE" -o jsonpath='{.metadata.uid}')" != "$APPROVED_NODE_UID" ] || [ "$(ssh -o BatchMode=yes -o ClearAllForwardings=yes -o PermitLocalCommand=no -o RequestTTY=no -- "$APPROVED_HOST" cat /etc/machine-id)" != "$APPROVED_MACHINE_ID" ]; then EVIDENCE_READY=false; printf '%s\n' '중단: fresh host/node identity gate 실패' >&2; else ssh -o BatchMode=yes -o ClearAllForwardings=yes -o PermitLocalCommand=no -o RequestTTY=no -- "$APPROVED_HOST" ip route get "$ENDPOINT_IP"; fi`

dataplane mode가 API/config와 owner 문서로 exact 확인된 경우에만 해당 **한 경로**의 bounded read-only rule 조회를 owner 절차에서 수행한다. iptables, nft, IPVS, eBPF를 동시에 실행하지 않는다. 이 런북은 구현체별 host 명령을 일반화하지 않는다.

## 변경·rollback·정상화

진단과 mutation을 분리한다. rule/route/conntrack 변경, proxy/CNI 재시작, Pod 삭제·재배치 명령은 제공하지 않는다. 별도 변경에는 fresh target/evidence, exact subject와 권한, UTC window, node/Service 영향과 quorum, 멱등성, 검증된 rollback 설정이 필요하다.

`MUTATION_READY=false; ROLLBACK_READY=false; NORMALIZATION_READY=false; if [ "$AUTH_READY" != true ] || [ "$EVIDENCE_READY" != true ] || [ "$RELATION_READY" != true ] || [ "$TIME_READY" != true ] || [ "$ARGV_READY" != true ] || ! fresh_relation; then printf '%s\n' '중단: fresh 변경 gate 실패' >&2; else printf '%s\n' '진단 완료: 변경 명령 없음, 플랫폼 owner 절차로 이관'; fi`

변경/rollback 뒤 기존 client·endpoint·dataplane Pod/containerID/node host 관계를 모두 폐기하고 `invalidate_all`부터 재등록한다. replacement 선택과 재등록 없이 정상화하지 않는다. 정상화는 `dataplane 선언/동기화 → node rule/map → endpoint route → endpoint TCP → ClusterIP TCP → protocol/application success → workload 핵심 기능` 역순이며 관찰 창 동안 재발·새 Warning·restart 증가가 없어야 한다.

## Prometheus 빠른 관측

`if [ "$AUTO_READY" != true ] || [ "$TIME_READY" != true ] || [ "$RELATION_READY" != true ] || ! fresh_relation; then printf '%s\n' '중단: fresh query identity gate 실패' >&2; else printf 'kube_service_info{namespace="%s",service="%s"}\n' "$NS" "$SVC"; fi`

빈 query는 정상화가 아니다. query producer/인증 실패, metric 미수집, label/시간 범위 오류와 실제 no-series를 분리한다. `up=1`도 rule/map·packet forwarding·application 성공을 보장하지 않는다.

## 증거·미검증

UTC window, 사건 ID, exact subject/RBAC, Service/Slice/client/endpoint/dataplane UID·RV·owner·node·containerID, protocol/port, producer/filter 결과, approved host relation, 변경/rollback/replacement/실제 기능 결과를 보존한다. Secret, token, kubeconfig, 개인키, 환경변수, payload, 전체 로그·ruleset은 저장하지 않는다.

kube-proxy mode, 대체 dataplane, node SSH 경로, rule/map 명령과 CNI route는 환경별 미검증이다.
