# 노드 간 Pod 통신에서 MTU·라우팅 문제가 의심되는 경우

## 입력값과 빠른 수집

API 명령은 승인된 작업 PC 또는 bastion의 같은 Bash에서 실행한다. 진단 hop은 `source Pod UID·현재 containerID/network namespace → source Node UID → 승인 SSH host/machine-id → source route·interface/MTU → underlay·overlay → destination Node UID → destination Pod UID/IP·listener`다. Service 이름에서만 실패하면 [[01. ClusterIP Service에 연결할 수 없는 경우]]로 이동한다.

| lifecycle | 값 | 등록 계약 |
|---|---|---|
| 최초 입력 | source/destination namespace·Pod, exact RBAC subject, incident ID | 운영 기록의 exact 값 한 번 입력 |
| API 확인 자동값 | 두 Pod UID/RV/IP/node/owner, 두 Node UID/machineID, container·port 후보 | 모든 API 호출 성공 후 원자 등록 |
| 계산 후보값 | container, protocol/port, route interface, CNI Pod 후보 | bounded 출력 뒤 선택, 첫 후보 자동 선택 금지 |
| 운영자 선택값 | source container, destination port/protocol, UTC window, 승인 host/machine-id/interface, 조건부 CNI Pod/container | current identity와 형식 검증 |

**Bash·API 도구 확인**

### 선택·UTC·current container relation

`SRC_CONTAINER='PASTE_SOURCE_CONTAINER_HERE'; PROTOCOL='PASTE_TCP_OR_UDP_HERE'; DST_PORT='PASTE_DESTINATION_PORT_HERE'; START_RFC3339='PASTE_START_UTC_HERE'; END_RFC3339='PASTE_END_UTC_HERE'`

`SELECTION_READY=false; RELATION_READY=false; TIME_READY=false; ARGV_READY=false; EVIDENCE_READY=false; unset SRC_CONTAINER_ID; UTC_RE='^[0-9]{4}-(0[1-9]|1[0-2])-([0-2][0-9]|3[01])T([01][0-9]|2[0-3]):[0-5][0-9]:[0-5][0-9]Z$'; if [ "$AUTO_READY" != true ] || [ "$AUTH_READY" != true ]; then printf '%s\n' '중단: AUTO/AUTH gate 실패' >&2; elif ! ## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | 서로 다른 node의 current Pod UID 사이에서 direct Pod IP timeout·`no route to host`·큰 payload만 실패·PMTU 증상이 재현된다. |
| 적용 | 양 Pod/Node identity와 같은 protocol/port·UTC evidence window를 연결했다. |
| 제외 | Service VIP만 실패하면 [[01. ClusterIP Service에 연결할 수 없는 경우]], policy 직접 증거는 [[12. 보안/03. NetworkPolicy/01. NetworkPolicy 적용 결과가 의도한 통신 허용·차단과 다른 경우]], sandbox 생성 실패는 [[06. 클러스터 네트워크/01. Pod 네트워크·CNI/02. 특정 노드에서 Pod 네트워크 생성이 반복 실패하는 경우]]로 이동한다. |

검색 문자열: `no route to host`, `connection timed out`, `message too long`, `packet too big`, `frag needed`, `PMTU`, `MTU`, `vxlan`, `geneve`, `route`.

## 명령별 fresh gate와 진단

`fresh_pair(){ local s d sn dn cid; s="$(kubectl get pod "$SRC_POD" -n "$SRC_NS" -o json)" || return 1; d="$(kubectl get pod "$DST_POD" -n "$DST_NS" -o json)" || return 1; sn="$(kubectl get node "$SRC_NODE" -o json)" || return 1; dn="$(kubectl get node "$DST_NODE" -o json)" || return 1; cid="$(jq -r --arg c "$SRC_CONTAINER" '.status.containerStatuses[]? | select(.name==$c) | .containerID // empty' <<<"$s")"; [ "$(jq -r '.metadata.uid' <<<"$s")" = "$SRC_UID" ] && [ "$(jq -r '.metadata.resourceVersion' <<<"$s")" = "$SRC_RV" ] && [ "$(jq -r '.status.podIP' <<<"$s")" = "$SRC_IP" ] && [ "$(jq -r '.spec.nodeName' <<<"$s")" = "$SRC_NODE" ] && [ "$(jq -r '.metadata.ownerReferences[]? | select(.controller==true) | .kind' <<<"$s")" = "$SRC_OWNER_KIND" ] && [ "$(jq -r '.metadata.ownerReferences[]? | select(.controller==true) | .name' <<<"$s")" = "$SRC_OWNER_NAME" ] && [ "$(jq -r '.metadata.ownerReferences[]? | select(.controller==true) | .uid' <<<"$s")" = "$SRC_OWNER_UID" ] && [ "$cid" = "$SRC_CONTAINER_ID" ] && [ "$(jq -r '.metadata.uid' <<<"$d")" = "$DST_UID" ] && [ "$(jq -r '.metadata.resourceVersion' <<<"$d")" = "$DST_RV" ] && [ "$(jq -r '.status.podIP' <<<"$d")" = "$DST_IP" ] && [ "$(jq -r '.spec.nodeName' <<<"$d")" = "$DST_NODE" ] && [ "$(jq -r '.metadata.ownerReferences[]? | select(.controller==true) | .kind' <<<"$d")" = "$DST_OWNER_KIND" ] && [ "$(jq -r '.metadata.ownerReferences[]? | select(.controller==true) | .name' <<<"$d")" = "$DST_OWNER_NAME" ] && [ "$(jq -r '.metadata.ownerReferences[]? | select(.controller==true) | .uid' <<<"$d")" = "$DST_OWNER_UID" ] && [ "$(jq -r '.metadata.uid' <<<"$sn")" = "$SRC_NODE_UID" ] && [ "$(jq -r '.metadata.uid' <<<"$dn")" = "$DST_NODE_UID" ] && { [ -z "$SRC_MACHINE_API" ] || [ "$(jq -r '.status.nodeInfo.machineID // empty' <<<"$sn")" = "$SRC_MACHINE_API" ]; } && { [ -z "$DST_MACHINE_API" ] || [ "$(jq -r '.status.nodeInfo.machineID // empty' <<<"$dn")" = "$DST_MACHINE_API" ]; }; }`

### 1. 같은 source network namespace의 direct probe

승인된 무부작용 TCP connect에만 사용한다. `nc`의 연결 결과는 `probe_rc`, `kubectl exec` producer 결과는 외부 exit로 분리한다.

`PROBE_READY=false; EVIDENCE_READY=false; if [ "$AUTH_READY" != true ] || [ "$RELATION_READY" != true ] || [ "$TIME_READY" != true ] || [ "$ARGV_READY" != true ] || [ "$PROTOCOL" != TCP ] || ! fresh_pair; then printf '%s\n' '중단: fresh probe gate 실패' >&2; elif PROBE_OUT="$(kubectl exec "$SRC_POD" -n "$SRC_NS" -c "$SRC_CONTAINER" -- sh -c 'command -v nc >/dev/null 2>&1 || { printf "%s\n" "nc-unavailable" >&2; exit 127; }; nc -vz -w 3 "$1" "$2"; rc=$?; printf "probe_rc=%s\n" "$rc"' sh "$DST_IP" "$DST_PORT" 2>&1)"; then PROBE_READY=true; EVIDENCE_READY=true; OBSERVED_AT="$(date -u '+%Y-%m-%dT%H:%M:%SZ')"; printf '%s\nPROBE_READY=true observed_at=%s\n' "$PROBE_OUT" "$OBSERVED_AT"; else printf '중단: exec producer/tool 실패: %s\n' "$PROBE_OUT" >&2; fi`

`probe_rc=0`은 TCP connect만 보장한다. timeout은 drop/route/지연 후보, refused는 listener/REJECT 후보며 MTU 원인을 단독 확정하지 않는다. UDP와 application 기능은 별도 승인 probe가 필요하다.

### 2. 승인 host identity와 route·MTU

두 SSH alias는 CMDB가 각 Kubernetes Node UID에 승인한 host여야 한다. API machineID는 보조 비교값이고 원격 `/etc/machine-id`를 경계에서 다시 확인한다.

`SRC_HOST='PASTE_SOURCE_APPROVED_HOST_HERE'; SRC_MACHINE_ID='PASTE_SOURCE_MACHINE_ID_HERE'; DST_HOST='PASTE_DESTINATION_APPROVED_HOST_HERE'; DST_MACHINE_ID='PASTE_DESTINATION_MACHINE_ID_HERE'`

`HOST_READY=false; if ! command -v ssh >/dev/null 2>&1; then printf '%s\n' '중단: node 분기에 ssh가 필요하다.' >&2; elif [ "$RELATION_READY" != true ] || [ "$TIME_READY" != true ] || ! fresh_pair || ! [[ "$SRC_HOST" =~ ^[A-Za-z0-9][A-Za-z0-9.-]*$ && "$DST_HOST" =~ ^[A-Za-z0-9][A-Za-z0-9.-]*$ && "$SRC_MACHINE_ID" =~ ^[a-fA-F0-9]{32}$ && "$DST_MACHINE_ID" =~ ^[a-fA-F0-9]{32}$ ]]; then printf '%s\n' '중단: host selection/fresh relation 실패' >&2; elif SRMID="$(ssh -o BatchMode=yes -o ClearAllForwardings=yes -o PermitLocalCommand=no -o RequestTTY=no -- "$SRC_HOST" cat /etc/machine-id)" && DRMID="$(ssh -o BatchMode=yes -o ClearAllForwardings=yes -o PermitLocalCommand=no -o RequestTTY=no -- "$DST_HOST" cat /etc/machine-id)" && [ "$SRMID" = "$SRC_MACHINE_ID" ] && [ "$DRMID" = "$DST_MACHINE_ID" ]; then HOST_READY=true; printf 'HOST_READY=true source=%s/%s destination=%s/%s api_machine_match=%s/%s\n' "$SRC_NODE" "$SRC_NODE_UID" "$DST_NODE" "$DST_NODE_UID" "$([ -z "$SRC_MACHINE_API" ] || [ "$SRC_MACHINE_API" = "$SRC_MACHINE_ID" ]; printf '%s' "$?")" "$([ -z "$DST_MACHINE_API" ] || [ "$DST_MACHINE_API" = "$DST_MACHINE_ID" ]; printf '%s' "$?")"; else printf '%s\n' '중단: approved host machine identity 실패' >&2; fi`

`ROUTE_READY=false; if [ "$HOST_READY" != true ] || [ "$RELATION_READY" != true ] || [ "$TIME_READY" != true ] || ! fresh_pair || [ "$(ssh -o BatchMode=yes -o ClearAllForwardings=yes -o PermitLocalCommand=no -o RequestTTY=no -- "$SRC_HOST" cat /etc/machine-id)" != "$SRC_MACHINE_ID" ]; then printf '%s\n' '중단: fresh source host gate 실패' >&2; else printf -v Q_DST_IP '%q' "$DST_IP"; if ROUTE_OUT="$(ssh -o BatchMode=yes -o ClearAllForwardings=yes -o PermitLocalCommand=no -o RequestTTY=no -- "$SRC_HOST" "ip route get -- $Q_DST_IP" 2>&1)"; then ROUTE_READY=true; EVIDENCE_READY=true; printf '%s\nROUTE_READY=true\n' "$ROUTE_OUT"; else printf '중단: route producer 실패: %s\n' "$ROUTE_OUT" >&2; fi; fi`

route 출력의 실제 `dev`를 양 node에서 확인한 뒤 interface를 선택한다. 이름을 `eth0`, `cni0`, `vxlan`로 추측하지 않는다.

`SRC_IFACE='PASTE_SOURCE_INTERFACE_HERE'; DST_IFACE='PASTE_DESTINATION_INTERFACE_HERE'`

`if [ "$HOST_READY" != true ] || [ "$ROUTE_READY" != true ] || [ "$RELATION_READY" != true ] || ! fresh_pair || ! [[ "$SRC_IFACE" =~ ^[A-Za-z0-9_.:@-]+$ && "$DST_IFACE" =~ ^[A-Za-z0-9_.:@-]+$ ]] || [ "$(ssh -o BatchMode=yes -o ClearAllForwardings=yes -o PermitLocalCommand=no -o RequestTTY=no -- "$SRC_HOST" cat /etc/machine-id)" != "$SRC_MACHINE_ID" ] || [ "$(ssh -o BatchMode=yes -o ClearAllForwardings=yes -o PermitLocalCommand=no -o RequestTTY=no -- "$DST_HOST" cat /etc/machine-id)" != "$DST_MACHINE_ID" ]; then EVIDENCE_READY=false; printf '%s\n' '중단: fresh interface/host gate 실패' >&2; else printf -v Q_SRC_IF '%q' "$SRC_IFACE"; printf -v Q_DST_IF '%q' "$DST_IFACE"; ssh -o BatchMode=yes -o ClearAllForwardings=yes -o PermitLocalCommand=no -o RequestTTY=no -- "$SRC_HOST" "ip -details link show dev $Q_SRC_IF" && ssh -o BatchMode=yes -o ClearAllForwardings=yes -o PermitLocalCommand=no -o RequestTTY=no -- "$DST_HOST" "ip -details link show dev $Q_DST_IF"; fi`

underlay/overlay MTU 차이와 encapsulation overhead가 직접 맞아야 MTU 원인 후보다. link MTU 하나나 `tracepath` 성공만으로 application payload를 보장하지 않는다.

### 3. 조건부 CNI evidence

먼저 두 node의 kube-system 후보를 current Pod/Node gate로 출력한다.

## 변경·rollback·정상화

route/MTU/rule/CNI 설정 변경, interface 재기동, Pod 삭제·재배치, packet capture 명령은 제공하지 않는다. 별도 owner 절차는 fresh target/evidence, exact subject·권한, 승인 ID와 UTC window, node/namespace 영향·quorum, 멱등성, 중단 조건과 검증된 rollback 원본을 요구한다.

`MUTATION_READY=false; ROLLBACK_READY=false; NORMALIZATION_READY=false; if [ "$AUTH_READY" != true ] || [ "$EVIDENCE_READY" != true ] || [ "$RELATION_READY" != true ] || [ "$TIME_READY" != true ] || [ "$ARGV_READY" != true ] || ! fresh_pair; then printf '%s\n' '중단: fresh 변경 gate 실패' >&2; else printf '%s\n' '진단 완료: 이 런북에는 변경 명령이 없다.'; fi`

변경·rollback 뒤 `invalidate_all`로 기존 Pod/Node/containerID/host/interface/CNI selection을 폐기한다. replacement는 owner kind/name/UID, current Pod UID/RV/IP/node, active containerID와 단일 host 관계를 다시 등록한다. 정상화는 `CNI 선언·route → 양 host interface/MTU → destination route → direct Pod TCP/승인 protocol → MTU 경계가 있는 실제 핵심 기능` 순으로 역검증하고, 관찰 창 동안 timeout·`no route`·CNI Warning·restart 증가가 없어야 한다. `Running`, link up, 작은 probe 한 번은 정상화가 아니다.

## 증거·미검증

UTC window, incident ID, exact subject/RBAC, 두 Pod UID/RV/IP/owner/node, source containerID, Node UID와 approved host machine-id, route dev/src, interface/MTU, CNI Pod UID/containerID, producer/filter/probe 결과와 승인·rollback·replacement·실제 기능만 보존한다. Secret, token, kubeconfig, private key, payload, 전체 로그·ruleset·capture는 저장하지 않는다.

Kubernetes 1.26 환경의 CNI, encapsulation, underlay MTU, route table, node SSH와 CNI 로그 위치는 실제 환경 미검증이다.
