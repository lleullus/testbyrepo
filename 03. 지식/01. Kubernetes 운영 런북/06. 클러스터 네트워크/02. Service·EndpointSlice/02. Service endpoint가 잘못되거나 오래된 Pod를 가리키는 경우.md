# Service endpoint가 잘못되거나 오래된 Pod를 가리키는 경우

## 입력값과 빠른 수집

이 런북의 명령은 승인된 kubeconfig가 있는 작업 PC 또는 bastion의 **같은 Bash**에서 실행한다. 실행 경로는 `작업 host의 kubectl → API server → Service·EndpointSlice·Pod 객체`다. 실제 요청을 확인할 때만 `승인된 기존 client Pod/container → Service port → EndpointSlice address → 현재 Pod listener` hop을 추가한다.

| lifecycle | 값 | 등록·폐기 계약 |
|---|---|---|
| 최초 입력 | `NS`, `SVC`, `AUDIT_SUBJECT`, `INCIDENT_ID` | 운영 기록의 exact namespace·Service·RBAC subject·사건 ID를 한 번 입력한다. |
| API 확인 자동값 | `SVC_UID`, `SVC_RV`, selector, Slice UID·owner UID, endpoint target UID, 현재 Pod UID·node | 모든 API 조회가 성공한 뒤 한 번에 등록한다. |
| 계산 후보값 | selector 문자열, endpoint 후보 목록, escaped regex | bounded 출력으로 확인하며 자동 선택하지 않는다. |
| 운영자 선택값 | `SLICE`, `POD`, 관측 시작·종료 | 후보 출력과 사건 시각을 확인한 뒤 등록한다. |

`PASTE_..._HERE` 문자열은 각각 이 문서에 한 번만 있다. 재수집 전에는 identity·resourceVersion·owner·container ID·node·승인 host·relation·time·argv/regex·selection·authorization·evidence·mutation·rollback·normalization 값과 모든 `..._READY`를 무효화한다. 조회 실패는 이전 값을 남기지 않는다.

**Bash·도구 확인**

`TOOLS_READY=false; MISSING=''; for T in kubectl jq date grep sed; do command -v "$T" >/dev/null 2>&1 || MISSING="$MISSING $T"; done; if [ -z "${BASH_VERSION:-}" ]; then printf '%s\n' '중단: Bash에서 실행한다.' >&2; elif [ -n "$MISSING" ]; then printf '중단: 없는 도구=%s\n' "$MISSING" >&2; else TOOLS_READY=true; printf 'TOOLS_READY=true bash=%s\n' "$BASH_VERSION"; fi`

**최초 입력과 전체 무효화 함수 등록**

`invalidate_all(){ unset AUTO_READY CANDIDATE_READY SELECTION_READY AUTH_READY EVIDENCE_READY HOST_READY RELATION_READY TIME_READY ARGV_READY MUTATION_READY ROLLBACK_READY NORMALIZATION_READY SVC_UID SVC_RV SVC_SELECTOR SELECTOR_RE SLICE SLICE_UID SLICE_RV SLICE_OWNER_UID POD POD_UID POD_RV POD_NODE ENDPOINT_UID ENDPOINT_ADDRESS ENDPOINT_READY START_RFC3339 END_RFC3339 OBSERVED_AT CHANGE_ID APPROVAL_ID ROLLBACK_REF; }; invalidate_all; NS='PASTE_NAMESPACE_HERE'; SVC='PASTE_SERVICE_HERE'; AUDIT_SUBJECT='PASTE_EXACT_RBAC_SUBJECT_HERE'; INCIDENT_ID='PASTE_INCIDENT_ID_HERE'; INPUT_READY=false; if [ "$TOOLS_READY" != true ]; then printf '%s\n' '중단: TOOLS_READY가 아니다.' >&2; elif ! [[ "$NS" =~ ^[a-z0-9]([-a-z0-9]*[a-z0-9])?$ && "$SVC" =~ ^[a-z0-9]([-a-z0-9]*[a-z0-9])?$ && "$AUDIT_SUBJECT" =~ ^[^[:space:]]+$ && "$INCIDENT_ID" =~ ^[A-Za-z0-9._:-]+$ ]]; then printf '%s\n' '중단: 입력 형식이 잘못됐다.' >&2; else INPUT_READY=true; export NS SVC AUDIT_SUBJECT INCIDENT_ID; printf 'INPUT_READY=true ns=%s service=%s subject=%s incident=%s\n' "$NS" "$SVC" "$AUDIT_SUBJECT" "$INCIDENT_ID"; fi`

`AUDIT_SUBJECT`는 승인 기록과 audit log에서 확인한 실제 요청 주체다. kubeconfig의 user key만으로 실제 subject를 추측하지 않는다. 아래 `can-i`는 현재 credential의 권한 결과이며 subject 동일성을 증명하지 않으므로 둘이 맞지 않으면 중단한다.

### 원자적 자동 수집

다음 명령은 먼저 모든 파생 상태를 폐기한다. Service와 관련 Slice 목록을 모두 읽고, exact Service UID owner 관계와 selector를 확인한 경우에만 값을 등록한다.

`invalidate_all; AUTO_READY=false; if [ "$INPUT_READY" != true ]; then printf '%s\n' '중단: INPUT_READY가 아니다.' >&2; elif ! kubectl auth can-i get services -n "$NS" -q || ! kubectl auth can-i get endpointslices.discovery.k8s.io -n "$NS" -q || ! kubectl auth can-i get pods -n "$NS" -q; then printf '중단: 현재 credential의 exact read RBAC 부족 subject=%s\n' "$AUDIT_SUBJECT" >&2; elif SVC_TMP="$(kubectl get service "$SVC" -n "$NS" -o json)" && SLICE_TMP="$(kubectl get endpointslice -n "$NS" -l "kubernetes.io/service-name=$SVC" -o json)"; then UID_TMP="$(jq -r '.metadata.uid // empty' <<<"$SVC_TMP")"; RV_TMP="$(jq -r '.metadata.resourceVersion // empty' <<<"$SVC_TMP")"; SELECTOR_TMP="$(jq -r '(.spec.selector // {}) | to_entries | sort_by(.key) | map("\(.key)=\(.value)") | join(",")' <<<"$SVC_TMP")"; BAD_OWNER="$(jq -r --arg uid "$UID_TMP" '[.items[] | select(([.metadata.ownerReferences[]? | select(.kind=="Service" and .uid==$uid)]|length)!=1)]|length' <<<"$SLICE_TMP")"; if [ -z "$UID_TMP" ] || [ -z "$RV_TMP" ] || [ -z "$SELECTOR_TMP" ] || [ "$BAD_OWNER" != 0 ]; then printf '%s\n' '중단: selector가 없거나 Slice owner가 exact Service UID와 다르다.' >&2; else SVC_UID="$UID_TMP"; SVC_RV="$RV_TMP"; SVC_SELECTOR="$SELECTOR_TMP"; SELECTOR_RE="$(printf '%s' "$SVC_SELECTOR" | sed 's/[][\\.^$*+?(){}|]/\\&/g')"; AUTO_READY=true; AUTH_READY=true; CANDIDATE_READY=true; printf 'AUTO_READY=true service_uid=%s service_rv=%s selector=%s selector_regex=%s\n' "$SVC_UID" "$SVC_RV" "$SVC_SELECTOR" "$SELECTOR_RE"; jq -r '.items[] | "=== Slice: \(.metadata.name) ===\nUID: \(.metadata.uid)\nresourceVersion: \(.metadata.resourceVersion)\nowner: \([.metadata.ownerReferences[]? | "\(.kind)/\(.name)/\(.uid)"]|join(","))\n" + ([.endpoints[]? | "target: \(.targetRef.kind // "-")/\(.targetRef.namespace // "-")/\(.targetRef.name // "-")/\(.targetRef.uid // "-") address=\(.addresses|join(",")) ready=\(.conditions.ready // "-") serving=\(.conditions.serving // "-") terminating=\(.conditions.terminating // "-")"]|join("\n"))' <<<"$SLICE_TMP"; fi; else printf '%s\n' '중단: Service 또는 EndpointSlice producer API 실패, 이전 값 없음' >&2; fi`

`AUTO_READY=true`여도 endpoint가 비어 있으면 정상이나 stale로 해석하지 않는다. producer API 실패, selector가 만든 no-match, API 성공 후 빈 endpoint 집합을 구분한다. Slice가 없으면 [[01. Service에 EndpointSlice endpoint가 생성되지 않는 경우]]로 이동한다.

### 선택·UTC 시간·관계 등록

`SLICE='PASTE_ENDPOINTSLICE_HERE'; POD='PASTE_TARGET_POD_HERE'; START_RFC3339='PASTE_START_UTC_HERE'; END_RFC3339='PASTE_END_UTC_HERE'`

정규식은 UTC `Z` 형식만 허용하고 `date` round-trip과 `start < end`를 모두 확인한다. 선택 등록은 Slice→Service owner와 endpoint→Pod targetRef를 검증한다. 현재 Pod가 `NotFound`이면 삭제된 lifecycle 증거로 허용하되, `Forbidden`·timeout·기타 API 오류를 삭제로 해석하지 않는다.

`SELECTION_READY=false; RELATION_READY=false; TIME_READY=false; ARGV_READY=false; EVIDENCE_READY=false; unset SLICE_UID SLICE_RV SLICE_OWNER_UID POD_UID POD_RV POD_NODE ENDPOINT_UID ENDPOINT_ADDRESS ENDPOINT_READY; UTC_RE='^[0-9]{4}-(0[1-9]|1[0-2])-([0-2][0-9]|3[01])T([01][0-9]|2[0-3]):[0-5][0-9]:[0-5][0-9]Z$'; if [ "$AUTO_READY" != true ] || [ "$AUTH_READY" != true ]; then printf '%s\n' '중단: AUTO/AUTH gate가 아니다.' >&2; elif ! [[ "$SLICE" =~ ^[a-z0-9]([-a-z0-9.]*[a-z0-9])?$ && "$POD" =~ ^[a-z0-9]([-a-z0-9.]*[a-z0-9])?$ && "$START_RFC3339" =~ $UTC_RE && "$END_RFC3339" =~ $UTC_RE ]]; then printf '%s\n' '중단: 선택값 또는 canonical UTC 형식 오류' >&2; elif [ "$(date -u -d "$START_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" != "$START_RFC3339" ] || [ "$(date -u -d "$END_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" != "$END_RFC3339" ] || [ "$(date -u -d "$START_RFC3339" +%s)" -ge "$(date -u -d "$END_RFC3339" +%s)" ]; then printf '%s\n' '중단: UTC round-trip 또는 start<end 실패' >&2; elif SJ="$(kubectl get endpointslice "$SLICE" -n "$NS" -o json)" && [ "$(jq -r '.metadata.ownerReferences[]? | select(.kind=="Service" and .controller==true) | .uid' <<<"$SJ")" = "$SVC_UID" ]; then EP_COUNT="$(jq -r --arg pod "$POD" '[.endpoints[]? | select(.targetRef.kind=="Pod" and .targetRef.namespace==$ENV.NS and .targetRef.name==$pod)]|length' <<<"$SJ")"; if [ "$EP_COUNT" != 1 ]; then printf '중단: 선택 Pod endpoint 수=%s\n' "$EP_COUNT" >&2; else POD_RAW="$(kubectl get --raw "/api/v1/namespaces/$NS/pods/$POD" 2>/dev/null)" || true; POD_REASON="$(jq -r '.reason // empty' <<<"${POD_RAW:-{}}" 2>/dev/null)"; if [ "$POD_REASON" = NotFound ]; then POD_UID='ABSENT'; POD_RV='ABSENT'; POD_NODE='ABSENT'; elif jq -e '.kind=="Pod" and .metadata.uid and .metadata.resourceVersion and .spec.nodeName' <<<"$POD_RAW" >/dev/null 2>&1; then POD_UID="$(jq -r '.metadata.uid' <<<"$POD_RAW")"; POD_RV="$(jq -r '.metadata.resourceVersion' <<<"$POD_RAW")"; POD_NODE="$(jq -r '.spec.nodeName' <<<"$POD_RAW")"; else printf '%s\n' '중단: Pod lookup 실패는 NotFound가 아니며 stale 값을 남기지 않음' >&2; exit 1; fi; SLICE_UID="$(jq -r '.metadata.uid' <<<"$SJ")"; SLICE_RV="$(jq -r '.metadata.resourceVersion' <<<"$SJ")"; SLICE_OWNER_UID="$SVC_UID"; ENDPOINT_UID="$(jq -r --arg pod "$POD" '.endpoints[] | select(.targetRef.kind=="Pod" and .targetRef.namespace==$ENV.NS and .targetRef.name==$pod) | .targetRef.uid' <<<"$SJ")"; ENDPOINT_ADDRESS="$(jq -r --arg pod "$POD" '.endpoints[] | select(.targetRef.kind=="Pod" and .targetRef.namespace==$ENV.NS and .targetRef.name==$pod) | .addresses|join(",")' <<<"$SJ")"; ENDPOINT_READY="$(jq -r --arg pod "$POD" '.endpoints[] | select(.targetRef.kind=="Pod" and .targetRef.namespace==$ENV.NS and .targetRef.name==$pod) | "ready=\(.conditions.ready // "-") serving=\(.conditions.serving // "-") terminating=\(.conditions.terminating // "-")"' <<<"$SJ")"; TIME_READY=true; ARGV_READY=true; SELECTION_READY=true; RELATION_READY=true; EVIDENCE_READY=true; printf 'SELECTION_READY=true slice=%s/%s rv=%s owner_uid=%s endpoint_uid=%s current_pod_uid=%s pod_rv=%s node=%s address=%s %s window=%s/%s\n' "$SLICE" "$SLICE_UID" "$SLICE_RV" "$SLICE_OWNER_UID" "$ENDPOINT_UID" "$POD_UID" "$POD_RV" "$POD_NODE" "$ENDPOINT_ADDRESS" "$ENDPOINT_READY" "$START_RFC3339" "$END_RFC3339"; fi; else printf '%s\n' '중단: Slice 조회 또는 exact owner 관계 실패' >&2; fi`

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | endpoint targetRef UID가 현재 Pod UID와 다르거나, `NotFound` Pod UID가 남거나, selector 집합과 endpoint 집합이 다르다. |
| 적용 | 같은 관측 창에서 Service UID/RV, Slice UID/RV·owner UID, endpoint target UID와 현재 Pod lifecycle을 연결할 수 있다. |
| 제외 | endpoint가 하나도 없으면 [[01. Service에 EndpointSlice endpoint가 생성되지 않는 경우]], port/listener 문제면 [[03. Service port·targetPort로 backend에 연결되지 않는 경우]], 전달 문제면 [[03. 서비스 전달·라우팅/01. ClusterIP Service에 연결할 수 없는 경우]]로 이동한다. |

검색 문자열: `targetRef`, `resourceVersion`, `ownerReferences`, `NotFound`, `ready=false`, `serving=false`, `terminating=true`, `stale endpoint`.

## 관측별 진단 경로

| 지금 보이는 것 | 먼저 볼 것 | 다음 분기 |
|---|---|---|
| `ENDPOINT_UID != POD_UID` | 이름 재사용, 두 UID와 RV·시각 | replacement 뒤 controller 수렴 |
| `POD_UID=ABSENT` | exact `NotFound`, endpoint UID·owner | 삭제 후 stale endpoint |
| UID 일치, `terminating=true` | Pod deletionTimestamp와 serving/ready | 정상 drain 또는 지연 |
| selector Pod 집합과 endpoint 집합 불일치 | label·UID 집합, Service RV | selector/label 또는 controller |

### 명령별 fresh gate와 bounded 증거

모든 읽기 명령은 바로 앞이 아니라 **같은 원라인 안에서** 현재 Service·Slice UID/RV·owner 관계를 다시 검사한다. RV가 바뀌면 재수집하며 이전 증거와 섞지 않는다.

`fresh_relation(){ local s j p; s="$(kubectl get service "$SVC" -n "$NS" -o json)" || return 1; j="$(kubectl get endpointslice "$SLICE" -n "$NS" -o json)" || return 1; p="$(kubectl get pod "$POD" -n "$NS" --ignore-not-found -o json)" || return 1; [ "$(jq -r '.metadata.uid' <<<"$s")" = "$SVC_UID" ] && [ "$(jq -r '.metadata.resourceVersion' <<<"$s")" = "$SVC_RV" ] && [ "$(jq -r '.metadata.uid' <<<"$j")" = "$SLICE_UID" ] && [ "$(jq -r '.metadata.resourceVersion' <<<"$j")" = "$SLICE_RV" ] && [ "$(jq -r '.metadata.ownerReferences[]? | select(.kind=="Service" and .controller==true) | .uid' <<<"$j")" = "$SVC_UID" ] && [ "$(jq -r --arg pod "$POD" --arg uid "$ENDPOINT_UID" '[.endpoints[]? | select(.targetRef.kind=="Pod" and .targetRef.namespace==$ENV.NS and .targetRef.name==$pod and .targetRef.uid==$uid)] | length' <<<"$j")" = 1 ] && { if [ "$POD_UID" = ABSENT ]; then [ -z "$p" ]; else [ "$(jq -r '.metadata.uid' <<<"$p")" = "$POD_UID" ] && [ "$(jq -r '.metadata.resourceVersion' <<<"$p")" = "$POD_RV" ] && [ "$(jq -r '.spec.nodeName' <<<"$p")" = "$POD_NODE" ]; fi; }; }`

**현재 selector Pod와 endpoint UID 집합 비교**

`EVIDENCE_READY=false; if [ "$AUTH_READY" != true ] || [ "$SELECTION_READY" != true ] || [ "$RELATION_READY" != true ] || [ "$TIME_READY" != true ] || ! fresh_relation; then printf '%s\n' '중단: fresh identity/RV/owner/time gate 실패, 재수집한다.' >&2; elif POD_SET="$(kubectl get pods -n "$NS" -l "$SVC_SELECTOR" -o custom-columns='POD:.metadata.name,UID:.metadata.uid,RV:.metadata.resourceVersion,NODE:.spec.nodeName,IP:.status.podIP,PHASE:.status.phase,READY:.status.conditions[?(@.type=="Ready")].status,DELETING:.metadata.deletionTimestamp,OWNER-UID:.metadata.ownerReferences[?(@.controller==true)].uid')"; then OBSERVED_AT="$(date -u '+%Y-%m-%dT%H:%M:%SZ')"; EVIDENCE_READY=true; printf '%s\n' "$POD_SET"; printf 'EVIDENCE_READY=true observed_at=%s incident=%s\n' "$OBSERVED_AT" "$INCIDENT_ID"; else printf '%s\n' '중단: Pod producer API 실패, selector no-match로 해석하지 않는다.' >&2; fi`

`kubectl` producer가 실패하면 selector no-match로 해석하지 않는다. producer 성공·필터 성공·출력 0건은 selector no-match, producer 성공·필터 nonzero는 filter 오류다. `grep`을 사용할 때도 pipeline status를 확인하고 no-match(`1`)와 filter 오류(`>1`)를 구분한다.

판정은 다음과 같다.

- endpoint UID와 현재 Pod UID가 다르면 이름·IP가 같아도 stale/name-reuse 후보다.
- Pod가 exact `NotFound`이고 endpoint가 남아 있으면 삭제 후 수렴 지연 후보다. API 실패를 삭제로 바꾸지 않는다.
- UID가 같고 삭제 중이며 `terminating=true`이면 drain 후보이지 stale 확정이 아니다.
- Service RV나 Slice RV가 바뀌면 이전 selector·endpoint 관계를 폐기하고 자동 수집부터 다시 한다.

## 변경·rollback·정상화

읽기 진단과 상태 변경을 분리한다. 이 문서는 live EndpointSlice patch/delete, Pod 삭제, label·selector 변경 명령을 제공하지 않는다. 별도 관리 원본 변경은 fresh target/evidence, exact 승인자·subject, 유효 UTC window, quorum·서비스 영향, 멱등성, 검증된 rollback 자료가 모두 있을 때만 owner 절차에서 수행한다.

`MUTATION_READY=false; ROLLBACK_READY=false; NORMALIZATION_READY=false; if [ "$AUTH_READY" != true ] || [ "$EVIDENCE_READY" != true ] || [ "$RELATION_READY" != true ] || [ "$TIME_READY" != true ] || ! fresh_relation; then printf '%s\n' '중단: fresh 변경 gate 실패' >&2; else printf '%s\n' '진단 완료: 변경 명령 없음. 승인된 관리 원본 절차로 이관한다.'; fi`

변경 후 기존 Slice·Pod identity와 `SELECTION_READY`를 재사용하지 않는다. `invalidate_all` 후 새 Service RV, replacement Pod UID/node, 새 Slice UID/RV·owner·target 관계를 재등록한다. rollback도 같은 fresh gate와 승인 window 안에서 검증된 이전 선언 원본으로만 수행하고, rollback 뒤 다시 전부 재등록한다.

정상화는 `관리 원본 → Service UID·selector → 새 Pod UID·label/Ready → 새 Slice owner UID → targetRef UID/address/conditions → 실제 Service 요청` 순으로 확인한다. 현재 UID만 남고 관찰 창 동안 stale UID 재유입·새 Warning·restart 증가가 없으며 승인된 실제 요청과 핵심 기능이 성공해야 `NORMALIZATION_READY=true`다. 빈 endpoint metric, Pod `Running`, `ready=true` 하나는 성공이 아니다.

## Prometheus 빠른 관측

metric과 label이 실제 존재할 때만 사용한다. 등록된 값으로 완성 쿼리를 생성하며 출력 한 줄만 UI에 붙여 넣는다.

`if [ "$AUTO_READY" != true ] || [ "$TIME_READY" != true ] || [ "$RELATION_READY" != true ] || ! fresh_relation; then printf '%s\n' '중단: fresh query identity gate 실패' >&2; else printf 'kube_endpoint_address{namespace="%s",endpoint="%s"}\n' "$NS" "$SVC"; fi`

빈 결과는 정상화가 아니다. query producer 실패, 인증/권한 오류, metric 미수집, label 불일치, 범위 밖 시간, 실제 no-series를 분리한다. PromQL은 UID·owner·resourceVersion을 증명하지 못하므로 API 관계를 대체하지 않는다.

## 증거 보존과 근거

UTC window, incident ID, exact RBAC subject와 `can-i` 결과, Service/Slice/Pod UID·RV·owner·node·lifecycle 관계, endpoint conditions, 승인·rollback·재등록·실제 기능 결과만 보존한다. Secret, token, kubeconfig, 인증서 개인키, 요청 body, 전체 YAML과 불필요한 주소 원문은 저장하지 않는다.

- EndpointSlice controller 지연, drain 계약과 metrics label은 환경별 미검증이다.
