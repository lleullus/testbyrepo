# Service에 EndpointSlice endpoint가 생성되지 않는 경우

## 입력값과 빠른 수집

연결 경로는 `작업 PC → API server → current Service UID·selector·ports → selector가 고른 current Pod UID·IP·container ports → Service UID가 소유한 EndpointSlice UID·ports·targetRef → backend listener/실제 요청`이다. 이 문서는 EndpointSlice 생성·관계까지 담당하며 listener 이후는 [[03. Service port·targetPort로 backend에 연결되지 않는 경우]]로 넘긴다.

| 종류 | 변수 | 출처·gate |
|---|---|---|
| 최초 입력 | `NS`, `SERVICE` | 승인된 namespace와 exact Service 이름 |
| API 자동값 | Service UID/RV/type/clusterIP, selector JSON/string, port relation | exact Service API 응답 |
| 계산 후보 | selector Pod 목록, EndpointSlice 목록, endpoint/port relation | 각 list API가 성공한 경우만 계산 |
| 운영자 선택 | UTC 증거 창, 실제 요청 방법 | 첫 오류/Event와 서비스 계약 |

**도구·모든 downstream 초기화:** `unset INPUT_READY SERVICE_READY RELATION_READY WINDOW_READY SERVICE_UID SERVICE_RV SERVICE_TYPE CLUSTER_IP SELECTOR_JSON SELECTOR_STRING PORT_REL START_RFC3339 END_RFC3339 EVIDENCE_RFC3339 START_EPOCH END_EPOCH EVIDENCE_EPOCH SERVICE_JSON PODS_JSON SLICES_JSON; TOOLS_READY=false; MISSING=''; for T in kubectl jq date; do command -v "$T" >/dev/null 2>&1 || MISSING="$MISSING $T"; done; if [ -z "${BASH_VERSION:-}" ] || [ -n "$MISSING" ]; then printf '중단: Bash/도구 gate 실패:%s\n' "$MISSING" >&2; else TOOLS_READY=true; fi`

**최초 입력:** `NS='PASTE_NAMESPACE_HERE'; SERVICE='PASTE_SERVICE_HERE'; INPUT_READY=false; [ "$TOOLS_READY" = true ] && [ -n "$NS" ] && [ -n "$SERVICE" ] && INPUT_READY=true || printf '%s\n' '중단: 최초 입력 불완전' >&2`

**Service 자동 등록:** `SERVICE_READY=false; RELATION_READY=false; unset SERVICE_UID SERVICE_RV SERVICE_TYPE CLUSTER_IP SELECTOR_JSON SELECTOR_STRING PORT_REL SERVICE_JSON PODS_JSON SLICES_JSON; if [ "$INPUT_READY" != true ]; then printf '%s\n' '중단: INPUT_READY=false' >&2; else J=$(kubectl get service "$SERVICE" -n "$NS" -o json) && U=$(jq -er '.metadata.uid' <<<"$J") && R=$(jq -er '.metadata.resourceVersion' <<<"$J") && T=$(jq -er '.spec.type' <<<"$J") && CI=$(jq -r '.spec.clusterIP//""' <<<"$J") && SJ=$(jq -c '.spec.selector//{}' <<<"$J") && SS=$(jq -r '.spec.selector//{}|to_entries|sort_by(.key)|map("\(.key)=\(.value)")|join(",")' <<<"$J") && PR=$(jq -cr '[.spec.ports[]?|{name:(.name//""),protocol:(.protocol//"TCP"),servicePort:.port,targetPort:(.targetPort//.port),appProtocol:(.appProtocol//"")}]' <<<"$J") || { printf '%s\n' '중단: Service API/field 수집 실패' >&2; unset J U R T CI SJ SS PR; }; if [ -n "${U:-}" ]; then SERVICE_JSON=$J; SERVICE_UID=$U; SERVICE_RV=$R; SERVICE_TYPE=$T; CLUSTER_IP=$CI; SELECTOR_JSON=$SJ; SELECTOR_STRING=$SS; PORT_REL=$PR; SERVICE_READY=true; printf 'SERVICE_READY=true service=%s/%s uid=%s rv=%s type=%s clusterIP=%s selector=%s ports=%s\n' "$NS" "$SERVICE" "$SERVICE_UID" "$SERVICE_RV" "$SERVICE_TYPE" "${CLUSTER_IP:-none}" "${SELECTOR_STRING:-none}" "$PORT_REL"; fi; unset J U R T CI SJ SS PR; fi`

**direct current Service gate:** `refresh_service(){ local j u r t ci sj ss pr; SERVICE_READY=false; RELATION_READY=false; unset PODS_JSON SLICES_JSON; j=$(kubectl get service "$SERVICE" -n "$NS" -o json) || return 1; u=$(jq -er '.metadata.uid' <<<"$j") || return 1; r=$(jq -er '.metadata.resourceVersion' <<<"$j") || return 1; t=$(jq -er '.spec.type' <<<"$j") || return 1; ci=$(jq -r '.spec.clusterIP//""' <<<"$j"); sj=$(jq -c '.spec.selector//{}' <<<"$j") || return 1; ss=$(jq -r '.spec.selector//{}|to_entries|sort_by(.key)|map("\(.key)=\(.value)")|join(",")' <<<"$j") || return 1; pr=$(jq -cr '[.spec.ports[]?|{name:(.name//""),protocol:(.protocol//"TCP"),servicePort:.port,targetPort:(.targetPort//.port),appProtocol:(.appProtocol//"")}]' <<<"$j") || return 1; [ "$u" = "$SERVICE_UID" ] && [ "$t" = "$SERVICE_TYPE" ] && [ "$ci" = "$CLUSTER_IP" ] && [ "$sj" = "$SELECTOR_JSON" ] && [ "$ss" = "$SELECTOR_STRING" ] && [ "$pr" = "$PORT_REL" ] || { printf '%s\n' '중단: Service lifecycle/spec 변경; 전체 재등록' >&2; return 1; }; SERVICE_JSON=$j; SERVICE_RV=$r; SERVICE_READY=true; }`

**direct current relation gate 등록:** `refresh_relation(){ local pj ej; refresh_service || return 1; if [ -n "$SELECTOR_STRING" ]; then pj=$(kubectl get pods -n "$NS" -l "$SELECTOR_STRING" -o json) || return 1; else pj='{"items":[]}'; fi; ej=$(kubectl get endpointslices.discovery.k8s.io -n "$NS" -l "kubernetes.io/service-name=$SERVICE" -o json) || return 1; PODS_JSON=$pj; SLICES_JSON=$ej; RELATION_READY=true; }`

`SERVICE_READY=true`는 Service identity·selector·ports만 확정한다. selector가 비었거나 `ExternalName`이면 자동 Pod endpoint 생성 대상이 아니므로 생성 실패로 해석하지 않는다.

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | selector Service에서 EndpointSlice list가 0개이거나 endpoint 주소가 0개 |
| 적용 | Service UID·selector·ports와 candidate Pod·slice relation을 current API로 대조 가능 |
| 제외 | selector 없음·`ExternalName`, DNS는 [[07. DNS/03. 서비스·외부 이름 해석/01. Kubernetes Service 이름이 NXDOMAIN이거나 잘못된 주소를 반환하는 경우]], ClusterIP 전달은 [[06. 클러스터 네트워크/03. 서비스 전달·라우팅/01. ClusterIP Service에 연결할 수 없는 경우]] |

검색 문자열: `EndpointSlice`, `kubernetes.io/service-name`, `endpointslice.kubernetes.io/managed-by`, `ownerReferences`, `ready=false`, `serving=false`, `No resources found`, `selector`.

## 최초 확인·관계 등록

**RBAC와 current 관계 수집:** `refresh_service || exit $?; CAN_SERVICE=$(kubectl auth can-i get services --subresource='' -n "$NS" 2>&1); RC1=$?; CAN_SLICE=$(kubectl auth can-i list endpointslices.discovery.k8s.io -n "$NS" 2>&1); RC2=$?; printf 'service_get rc=%s allowed=%s\nslice_list rc=%s allowed=%s\n' "$RC1" "$CAN_SERVICE" "$RC2" "$CAN_SLICE"; [ "$RC1" -eq 0 ] && [ "$RC2" -eq 0 ] && [ "$CAN_SERVICE" = yes ] && [ "$CAN_SLICE" = yes ] || { printf '%s\n' '중단: 현재 주체의 실제 verb/resource/namespace 권한 불충족' >&2; exit 1; }; refresh_relation || { printf '%s\n' '중단: Pod/EndpointSlice list 실패; 0개로 해석 금지' >&2; exit 1; }; printf 'RELATION_READY=true pods=%s slices=%s endpoints=%s observed=%s\n' "$(jq '.items|length' <<<"$PODS_JSON")" "$(jq '.items|length' <<<"$SLICES_JSON")" "$(jq '[.items[].endpoints[]?]|length' <<<"$SLICES_JSON")" "$(date -u '+%Y-%m-%dT%H:%M:%SZ')"; unset CAN_SERVICE CAN_SLICE RC1 RC2`

**사람이 비교할 관계 출력:** `refresh_relation || { printf '%s\n' '중단: current 관계 재수집 실패' >&2; exit 1; }; printf '%s\n' '=== Service ==='; jq -r '"UID/RV: \(.metadata.uid)/\(.metadata.resourceVersion)\nType/ClusterIP: \(.spec.type)/\(.spec.clusterIP)\nSelector: \(.spec.selector)\nPorts: \([.spec.ports[]?|"\(.name//"unnamed") \(.protocol//"TCP") \(.port)->\(.targetPort//.port)"]|join("; "))"' <<<"$SERVICE_JSON"; jq -r '.items[]|"\n=== Pod: \(.metadata.name) ===\nUID: \(.metadata.uid)\nOwner: \([.metadata.ownerReferences[]?|select(.controller==true)|"\(.kind)/\(.name)/\(.uid)"]|join(","))\nIP: \(.status.podIP//"empty")\nReady: \([.status.conditions[]?|select(.type=="Ready")][0].status//"missing")\nDeleting: \(.metadata.deletionTimestamp//"no")\nContainer/Ports: \([.spec.containers[]?|"\(.name)=\([.ports[]?|"\(.name//"unnamed"):\(.containerPort)/\(.protocol//"TCP")"]|join(","))"]|join("; "))"' <<<"$PODS_JSON"; jq -r '.items[]|"\n=== EndpointSlice: \(.metadata.name) ===\nUID/RV: \(.metadata.uid)/\(.metadata.resourceVersion)\nOwner: \([.metadata.ownerReferences[]?|select(.controller==true)|"\(.kind)/\(.name)/\(.uid)"]|join(","))\nManaged-by: \(.metadata.labels["endpointslice.kubernetes.io/managed-by"]//"none")\nAddressType: \(.addressType)\nPorts: \([.ports[]?|"\(.name//"unnamed"):\(.port//"nil")/\(.protocol//"TCP")"]|join("; "))\nEndpoints: \([.endpoints[]?|"\(.addresses|join(",")) target=\(.targetRef.kind//"none")/\(.targetRef.namespace//"none")/\(.targetRef.name//"none")/\(.targetRef.uid//"none") ready=\(.conditions.ready//"nil") serving=\(.conditions.serving//"nil") terminating=\(.conditions.terminating//"nil")"]|join("; "))"' <<<"$SLICES_JSON"`

**관계 검증:** `refresh_relation || exit $?; BAD_OWNER=$(jq --arg name "$SERVICE" --arg uid "$SERVICE_UID" '[.items[]|select((.metadata.labels["kubernetes.io/service-name"]!=$name) or ([.metadata.ownerReferences[]?|select(.controller==true and .kind=="Service" and .name==$name and .uid==$uid)]|length)!=1)]|length' <<<"$SLICES_JSON") || exit 1; BAD_TARGET=$(jq --argjson pods "$PODS_JSON" '[.items[].endpoints[]? as $ep|select($ep.targetRef.kind=="Pod" and (($ep.targetRef.namespace//"") == "" or ($ep.targetRef.uid//"") == "" or ([$pods.items[]|select(.metadata.namespace==$ep.targetRef.namespace and .metadata.name==$ep.targetRef.name and .metadata.uid==$ep.targetRef.uid)]|length)!=1))]|length' <<<"$SLICES_JSON") || exit 1; if [ "$BAD_OWNER" -eq 0 ] && [ "$BAD_TARGET" -eq 0 ]; then printf 'owner_target_relation=valid service_uid=%s\n' "$SERVICE_UID"; else printf '중단: bad_owner=%s bad_target=%s\n' "$BAD_OWNER" "$BAD_TARGET" >&2; exit 1; fi; unset BAD_OWNER BAD_TARGET`

> [!warning]
> `RELATION_READY=true`는 세 list/get 호출의 성공만 뜻한다. endpoint 0개, `ready=true`, 선언된 `containerPort`는 각각 backend listener나 실제 요청 성공을 보장하지 않는다.

## 시간 gate·Event

**엄격한 UTC 창:** `unset WINDOW_READY START_EPOCH END_EPOCH EVIDENCE_EPOCH; START_RFC3339='PASTE_START_RFC3339_HERE'; END_RFC3339='PASTE_END_RFC3339_HERE'; EVIDENCE_RFC3339='PASTE_EVIDENCE_RFC3339_HERE'; RFC3339_RE='^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$'; WINDOW_READY=false; if [[ "$START_RFC3339" =~ $RFC3339_RE ]] && [[ "$END_RFC3339" =~ $RFC3339_RE ]] && [[ "$EVIDENCE_RFC3339" =~ $RFC3339_RE ]]; then START_EPOCH=$(date -u -d "$START_RFC3339" +%s 2>/dev/null) && END_EPOCH=$(date -u -d "$END_RFC3339" +%s 2>/dev/null) && EVIDENCE_EPOCH=$(date -u -d "$EVIDENCE_RFC3339" +%s 2>/dev/null) || true; fi; if [ -n "${START_EPOCH:-}" ] && [ "$(date -u -d "@$START_EPOCH" '+%Y-%m-%dT%H:%M:%SZ')" = "$START_RFC3339" ] && [ "$(date -u -d "@$END_EPOCH" '+%Y-%m-%dT%H:%M:%SZ')" = "$END_RFC3339" ] && [ "$(date -u -d "@$EVIDENCE_EPOCH" '+%Y-%m-%dT%H:%M:%SZ')" = "$EVIDENCE_RFC3339" ] && [ "$START_EPOCH" -lt "$END_EPOCH" ] && [ "$START_EPOCH" -le "$EVIDENCE_EPOCH" ] && [ "$EVIDENCE_EPOCH" -lt "$END_EPOCH" ]; then WINDOW_READY=true; else unset START_EPOCH END_EPOCH EVIDENCE_EPOCH; printf '%s\n' '중단: canonical UTC/relation 위반' >&2; fi`

**Service UID Event:** `refresh_service || exit $?; [ "$WINDOW_READY" = true ] || exit 1; E=$(kubectl get events -n "$NS" --field-selector "involvedObject.kind=Service,involvedObject.name=$SERVICE,involvedObject.uid=$SERVICE_UID" --sort-by=.metadata.creationTimestamp -o json); RC=$?; if [ "$RC" -ne 0 ]; then printf 'Event 수집 실패 rc=%s\n' "$RC" >&2; elif [ "$(jq '.items|length' <<<"$E")" -eq 0 ]; then printf '%s\n' 'Event 0건: controller 정상 증거 아님'; else jq -r '.items[]|[.metadata.creationTimestamp,.eventTime,.firstTimestamp,.lastTimestamp,.series.lastObservedTime,.reason,.message]|@tsv' <<<"$E"; fi; unset E RC`

Event/audit가 창 밖이거나 다른 lifecycle UID면 사용하지 않는다. audit은 활성화·승인 reader가 확인된 경우에만 단일 auditID의 timestamp, verb, `endpointslices` resource, namespace/name, requestURI, status와 current Service/slice UID 관계를 담당자에게 요청하며 actor 상세·token은 저장하지 않는다.

## 관측별 진단 경로

| 지금 보이는 것 | 먼저 볼 것 | 다음 경로 |
|---|---|---|
| selector 없음·ExternalName | Service type·계약 | 수동 slice owner 또는 DNS owner |
| selector Pod 0개·slice 0개 | selector exact match | Service/workload 원본 |
| candidate Pod 있음·slice 0개 | Service UID/RV와 controller watch | EndpointSlice controller owner |
| slice 있으나 endpoint 0개 | owner·managed-by·Pod IP/Ready/deleting | readiness 또는 controller |
| endpoint 존재·요청 실패 | Service port→targetPort→slice port→Pod port/listener | [[03. Service port·targetPort로 backend에 연결되지 않는 경우]] |

Kubernetes 1.26의 selector 기반 EndpointSlice는 Service와 같은 namespace의 selector Pod를 대상으로 한다. Ready False는 traffic-ready 조건을 바꾸지만 selector match와 slice 객체 생성 자체를 같은 것으로 만들지 않는다. controller 배포 형태와 로그 위치를 추측하지 않는다.

## 완성 PromQL

Prometheus와 kube-state-metrics가 해당 metric을 실제 수집할 때만 사용한다.

**Service identity query 생성:** `refresh_service || exit $?; printf 'kube_service_info{namespace="%s",service="%s"}\n' "$NS" "$SERVICE"`

**legacy ready endpoint query 생성:** `refresh_service || exit $?; printf 'sum(kube_endpoint_address{namespace="%s",endpoint="%s",ready="true"})\n' "$NS" "$SERVICE"`

빈 결과는 metric 미지원·수집 allowlist·RBAC·stale 범위 후보이며 API의 slice 부재가 아니다. legacy Endpoints metric은 EndpointSlice owner/targetRef/port 관계를 보장하지 않는다.

## 변경·rollback·정상화

Service selector·Pod label 변경, EndpointSlice 수동 생성/삭제, controller restart 명령은 제공하지 않는다. 변경 owner는 fresh Service UID/RV·selector·ports, candidate Pod UID/owner/IP/Ready, slice UID/RV·owner/managed-by/ports/targetRef, UTC 증거, 승인 ID·영향·idempotence를 실행 직전에 확인한다. 관리 원본과 검증된 rollback revision·명령·trigger가 없으면 중단한다.

replacement 뒤에는 이전 Pod/slice UID와 모든 READY를 폐기한다. 새 slice는 current Service UID owner, selector의 current Pod UID targetRef, Service targetPort와 일관된 slice port를 다시 등록한다. 정상화는 `실제 Service 요청·핵심 기능 → backend listener → slice endpoint/port/conditions → Pod Ready/IP → Service selector/ports → controller Event 재발 없음` 역순이며 slice 존재나 HTTP 한 번만으로 닫지 않는다.

## 증거·미검증·상위 문서

보존: UTC 창, Service UID/RV/type/selector/ports, slice UID/RV/owner/managed-by/ports/conditions, targetRef Pod UID/IP/Ready/deletion, UID 제한 Event, RBAC verb/resource/namespace 결과, 변경 승인·rollback·실제 요청. Secret·token·private key·전체 YAML/Event/audit actor 상세는 저장하지 않는다. controller 배포·로그·audit·metric은 실제 환경 미검증이다.
