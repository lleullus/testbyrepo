# Service port·targetPort로 backend에 연결되지 않는 경우

## 입력값과 빠른 수집

명령은 승인된 kubeconfig가 있는 작업 PC 또는 bastion의 같은 Bash에서 실행한다. 연결 hop은 `승인된 기존 client Pod/container → Service DNS 또는 ClusterIP:SERVICE_PORT → Service TARGET_PORT 해석 → EndpointSlice ENDPOINT_PORT → targetRef Pod UID/IP → 선택 CONTAINER의 실제 LISTENER_PORT → application`이다. 한 hop의 성공은 다음 hop을 보장하지 않는다.

| lifecycle | 값 | gate |
|---|---|---|
| 최초 입력 | `NS`, `SVC`, exact `AUDIT_SUBJECT`, `INCIDENT_ID` | 형식과 운영 기록 일치 |
| API 확인 자동값 | Service UID/RV, selector, Slice UID/RV·owner UID, target Pod UID/RV·node, container-port 관계 | API 호출 전체 성공 뒤 원자 등록 |
| 계산 후보값 | Service port 후보, named targetPort 해석, EndpointSlice port, escaped selector/regex | bounded 출력 확인 전 미확정 |
| 운영자 선택값 | Slice, Pod, container, Service port, endpoint port, protocol, UTC window | exact relation·숫자 범위·시간 round-trip 검증 |

**도구 확인**

`TOOLS_READY=false; MISSING=''; for T in kubectl jq date grep sed; do command -v "$T" >/dev/null 2>&1 || MISSING="$MISSING $T"; done; if [ -z "${BASH_VERSION:-}" ]; then printf '%s\n' '중단: Bash 필요' >&2; elif [ -n "$MISSING" ]; then printf '중단: 없는 도구=%s\n' "$MISSING" >&2; else TOOLS_READY=true; printf 'TOOLS_READY=true bash=%s\n' "$BASH_VERSION"; fi`

**최초 입력·재수집 무효화 계약**

`invalidate_all(){ unset AUTO_READY CANDIDATE_READY SELECTION_READY AUTH_READY EVIDENCE_READY HOST_READY RELATION_READY TIME_READY ARGV_READY MUTATION_READY ROLLBACK_READY NORMALIZATION_READY SVC_UID SVC_RV SVC_SELECTOR SELECTOR_RE SLICE SLICE_UID SLICE_RV POD POD_UID POD_RV POD_NODE CONTAINER CONTAINER_ID SERVICE_PORT TARGET_PORT ENDPOINT_PORT PROTOCOL PORT_RELATION START_RFC3339 END_RFC3339 OBSERVED_AT APPROVAL_ID CHANGE_ID ROLLBACK_REF; }; invalidate_all; NS='PASTE_NAMESPACE_HERE'; SVC='PASTE_SERVICE_HERE'; AUDIT_SUBJECT='PASTE_EXACT_RBAC_SUBJECT_HERE'; INCIDENT_ID='PASTE_INCIDENT_ID_HERE'; INPUT_READY=false; if [ "$TOOLS_READY" != true ]; then printf '%s\n' '중단: TOOLS_READY가 아니다.' >&2; elif ! [[ "$NS" =~ ^[a-z0-9]([-a-z0-9]*[a-z0-9])?$ && "$SVC" =~ ^[a-z0-9]([-a-z0-9]*[a-z0-9])?$ && "$AUDIT_SUBJECT" =~ ^[^[:space:]]+$ && "$INCIDENT_ID" =~ ^[A-Za-z0-9._:-]+$ ]]; then printf '%s\n' '중단: 입력 형식 오류' >&2; else INPUT_READY=true; export NS SVC AUDIT_SUBJECT INCIDENT_ID; printf 'INPUT_READY=true ns=%s service=%s subject=%s incident=%s\n' "$NS" "$SVC" "$AUDIT_SUBJECT" "$INCIDENT_ID"; fi`

재수집은 반드시 `invalidate_all`로 identity·resourceVersion·owner·containerID·node·승인 host·relation·time·argv/regex·selection·authorization·evidence·mutation·rollback·normalization과 모든 READY를 먼저 폐기한다. `AUDIT_SUBJECT`는 audit/승인 기록의 실제 subject이고 kubeconfig user alias로 추측하지 않는다.

### 원자적 자동 수집

`invalidate_all; AUTO_READY=false; if [ "$INPUT_READY" != true ]; then printf '%s\n' '중단: INPUT_READY가 아니다.' >&2; elif ! kubectl auth can-i get services -n "$NS" -q || ! kubectl auth can-i get endpointslices.discovery.k8s.io -n "$NS" -q || ! kubectl auth can-i get pods -n "$NS" -q || ! kubectl auth can-i create pods/exec -n "$NS" -q; then printf '중단: 현재 credential의 exact read/exec RBAC 부족 subject=%s\n' "$AUDIT_SUBJECT" >&2; elif SJ="$(kubectl get service "$SVC" -n "$NS" -o json)" && EJ="$(kubectl get endpointslice -n "$NS" -l "kubernetes.io/service-name=$SVC" -o json)" && PJ="$(kubectl get pods -n "$NS" -o json)"; then UID_TMP="$(jq -r '.metadata.uid // empty' <<<"$SJ")"; RV_TMP="$(jq -r '.metadata.resourceVersion // empty' <<<"$SJ")"; SEL_TMP="$(jq -r '(.spec.selector // {})|to_entries|sort_by(.key)|map("\(.key)=\(.value)")|join(",")' <<<"$SJ")"; BAD_OWNER="$(jq -r --arg u "$UID_TMP" '[.items[]|select(([.metadata.ownerReferences[]?|select(.kind=="Service" and .uid==$u)]|length)!=1)]|length' <<<"$EJ")"; if [ -z "$UID_TMP" ] || [ -z "$RV_TMP" ] || [ -z "$SEL_TMP" ] || [ "$BAD_OWNER" != 0 ]; then printf '%s\n' '중단: Service identity/selector 또는 Slice owner 관계 오류' >&2; else SVC_UID="$UID_TMP"; SVC_RV="$RV_TMP"; SVC_SELECTOR="$SEL_TMP"; SELECTOR_RE="$(printf '%s' "$SVC_SELECTOR" | sed 's/[][\\.^$*+?(){}|]/\\&/g')"; AUTO_READY=true; AUTH_READY=true; CANDIDATE_READY=true; printf 'AUTO_READY=true service_uid=%s rv=%s selector=%s selector_regex=%s\n' "$SVC_UID" "$SVC_RV" "$SVC_SELECTOR" "$SELECTOR_RE"; jq -r '"=== Service ports ===",(.spec.ports[]?|"name=\(.name // "-") service=\(.port) target=\(.targetPort) protocol=\(.protocol) appProtocol=\(.appProtocol // "-")")' <<<"$SJ"; jq -r '.items[]|"=== Slice: \(.metadata.name) uid=\(.metadata.uid) rv=\(.metadata.resourceVersion) ===\nowner=\([.metadata.ownerReferences[]?|"\(.kind)/\(.name)/\(.uid)"]|join(","))\nports=\([.ports[]?|"\(.name // "-"):\(.port)/\(.protocol)"]|join(","))\n"+([.endpoints[]?|"target=\(.targetRef.name // "-")/\(.targetRef.uid // "-") address=\(.addresses|join(",")) ready=\(.conditions.ready // "-")"]|join("\n"))' <<<"$EJ"; jq -r --arg sel "$SEL_TMP" '.items[]|select(.metadata.labels as $l|($sel|split(",")|all(split("=") as $p|$l[$p[0]]==$p[1])))|"=== Pod: \(.metadata.name) uid=\(.metadata.uid) rv=\(.metadata.resourceVersion) node=\(.spec.nodeName // "-") ===\n"+([.spec.containers[]?|"container=\(.name) ports=\([.ports[]?|"\(.name // "-"):\(.containerPort)/\(.protocol)"]|join(",")) containerID=\([. as $c|$PJ.items[]?|select(.metadata.name==$ENV.POD)|.status.containerStatuses[]?|select(.name==$c.name)|.containerID] | first // "not-materialized")"]|join("\n"))' <<<"$PJ" 2>/dev/null || printf '%s\n' '참고: Pod 후보 출력 필터 오류, raw 전체를 저장하지 말고 selector를 재검토한다.' >&2; fi; else printf '%s\n' '중단: API producer 실패, 이전 값 없음' >&2; fi`

후보 출력의 보조 `jq`가 실패하면 API producer 실패와 구분해 **filter 오류**로 기록한다. filter가 성공했지만 Pod가 0개면 selector no-match다. 빈 EndpointSlice port/metric은 정상 또는 `0`이 아니다.

### 선택·관계·시간 gate

`SLICE='PASTE_ENDPOINTSLICE_HERE'; POD='PASTE_TARGET_POD_HERE'; CONTAINER='PASTE_CONTAINER_HERE'; SERVICE_PORT='PASTE_SERVICE_PORT_HERE'; ENDPOINT_PORT='PASTE_ENDPOINT_PORT_HERE'; PROTOCOL='PASTE_TCP_OR_UDP_HERE'; START_RFC3339='PASTE_START_UTC_HERE'; END_RFC3339='PASTE_END_UTC_HERE'`

`SELECTION_READY=false; RELATION_READY=false; TIME_READY=false; ARGV_READY=false; EVIDENCE_READY=false; unset SLICE_UID SLICE_RV POD_UID POD_RV POD_NODE CONTAINER_ID TARGET_PORT PORT_RELATION; UTC_RE='^[0-9]{4}-(0[1-9]|1[0-2])-([0-2][0-9]|3[01])T([01][0-9]|2[0-3]):[0-5][0-9]:[0-5][0-9]Z$'; if [ "$AUTO_READY" != true ] || [ "$AUTH_READY" != true ]; then printf '%s\n' '중단: AUTO/AUTH gate 실패' >&2; elif ! [[ "$SLICE" =~ ^[a-z0-9]([-a-z0-9.]*[a-z0-9])?$ && "$POD" =~ ^[a-z0-9]([-a-z0-9.]*[a-z0-9])?$ && "$CONTAINER" =~ ^[a-z0-9]([-a-z0-9.]*[a-z0-9])?$ && "$SERVICE_PORT" =~ ^[0-9]+$ && "$ENDPOINT_PORT" =~ ^[0-9]+$ && "$PROTOCOL" =~ ^(TCP|UDP)$ && "$START_RFC3339" =~ $UTC_RE && "$END_RFC3339" =~ $UTC_RE ]] || (( SERVICE_PORT < 1 || SERVICE_PORT > 65535 || ENDPOINT_PORT < 1 || ENDPOINT_PORT > 65535 )); then printf '%s\n' '중단: 선택/argv 형식 오류' >&2; elif [ "$(date -u -d "$START_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" != "$START_RFC3339" ] || [ "$(date -u -d "$END_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" != "$END_RFC3339" ] || [ "$(date -u -d "$START_RFC3339" +%s)" -ge "$(date -u -d "$END_RFC3339" +%s)" ]; then printf '%s\n' '중단: UTC round-trip/start<end 실패' >&2; elif SJ="$(kubectl get service "$SVC" -n "$NS" -o json)" && EJ="$(kubectl get endpointslice "$SLICE" -n "$NS" -o json)" && PJ="$(kubectl get pod "$POD" -n "$NS" -o json)" && [ "$(jq -r '.metadata.uid' <<<"$SJ")" = "$SVC_UID" ] && [ "$(jq -r '.metadata.ownerReferences[]?|select(.kind=="Service" and .controller==true)|.uid' <<<"$EJ")" = "$SVC_UID" ] && jq -e --arg pod "$POD" --arg uid "$(jq -r '.metadata.uid' <<<"$PJ")" 'any(.endpoints[]?;.targetRef.kind=="Pod" and .targetRef.namespace==$ENV.NS and .targetRef.name==$pod and .targetRef.uid==$uid)' <<<"$EJ" >/dev/null && jq -e --arg c "$CONTAINER" 'any(.spec.containers[]?;.name==$c)' <<<"$PJ" >/dev/null; then MATCH="$(jq -r --argjson p "$SERVICE_PORT" --arg proto "$PROTOCOL" '[.spec.ports[]?|select(.port==$p and .protocol==$proto)]|length' <<<"$SJ")"; EPMATCH="$(jq -r --argjson p "$ENDPOINT_PORT" --arg proto "$PROTOCOL" '[.ports[]?|select(.port==$p and .protocol==$proto)]|length' <<<"$EJ")"; if [ "$MATCH" != 1 ] || [ "$EPMATCH" -lt 1 ]; then printf '중단: Service port 후보=%s EndpointSlice port 후보=%s\n' "$MATCH" "$EPMATCH" >&2; else SLICE_UID="$(jq -r '.metadata.uid' <<<"$EJ")"; SLICE_RV="$(jq -r '.metadata.resourceVersion' <<<"$EJ")"; POD_UID="$(jq -r '.metadata.uid' <<<"$PJ")"; POD_RV="$(jq -r '.metadata.resourceVersion' <<<"$PJ")"; POD_NODE="$(jq -r '.spec.nodeName' <<<"$PJ")"; CONTAINER_ID="$(jq -r --arg c "$CONTAINER" '.status.containerStatuses[]?|select(.name==$c)|.containerID // empty' <<<"$PJ")"; TARGET_PORT="$(jq -r --argjson p "$SERVICE_PORT" --arg proto "$PROTOCOL" '.spec.ports[]|select(.port==$p and .protocol==$proto)|.targetPort' <<<"$SJ")"; PORT_RELATION="service=$SERVICE_PORT target=$TARGET_PORT endpoint=$ENDPOINT_PORT protocol=$PROTOCOL"; SELECTION_READY=true; RELATION_READY=true; TIME_READY=true; ARGV_READY=true; EVIDENCE_READY=true; printf 'SELECTION_READY=true service_uid=%s slice=%s/%s rv=%s pod=%s/%s rv=%s node=%s container=%s containerID=%s %s window=%s/%s\n' "$SVC_UID" "$SLICE" "$SLICE_UID" "$SLICE_RV" "$POD" "$POD_UID" "$POD_RV" "$POD_NODE" "$CONTAINER" "${CONTAINER_ID:--}" "$PORT_RELATION" "$START_RFC3339" "$END_RFC3339"; fi; else printf '%s\n' '중단: fresh Service/Slice/Pod/container/owner 관계 조회 실패, stale 없음' >&2; fi`

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | 현재 targetRef Pod UID는 맞지만 Service port→targetPort→EndpointSlice port→listener 관계가 끊기거나 연결이 refused/timeout이다. |
| 제외 | targetRef UID가 다르면 [[02. Service endpoint가 잘못되거나 오래된 Pod를 가리키는 경우]], ClusterIP dataplane이면 [[03. 서비스 전달·라우팅/01. ClusterIP Service에 연결할 수 없는 경우]], L7 host/TLS이면 관련 Ingress·Gateway 런북으로 이동한다. |

검색 문자열: `targetPort`, `named port`, `connection refused`, `i/o timeout`, `no route to host`, `appProtocol`, `listener`.

## 명령별 fresh gate

`fresh_relation(){ local s e p cid; s="$(kubectl get service "$SVC" -n "$NS" -o json)" || return 1; e="$(kubectl get endpointslice "$SLICE" -n "$NS" -o json)" || return 1; p="$(kubectl get pod "$POD" -n "$NS" -o json)" || return 1; cid="$(jq -r --arg c "$CONTAINER" '.status.containerStatuses[]? | select(.name==$c) | .containerID // empty' <<<"$p")"; [ "$(jq -r '.metadata.uid' <<<"$s")" = "$SVC_UID" ] && [ "$(jq -r '.metadata.resourceVersion' <<<"$s")" = "$SVC_RV" ] && [ "$(jq -r '.metadata.uid' <<<"$e")" = "$SLICE_UID" ] && [ "$(jq -r '.metadata.resourceVersion' <<<"$e")" = "$SLICE_RV" ] && [ "$(jq -r '.metadata.uid' <<<"$p")" = "$POD_UID" ] && [ "$(jq -r '.metadata.resourceVersion' <<<"$p")" = "$POD_RV" ] && [ "$(jq -r '.spec.nodeName' <<<"$p")" = "$POD_NODE" ] && [ -n "$cid" ] && [ "$cid" = "$CONTAINER_ID" ] && [ "$(jq -r '.metadata.ownerReferences[]?|select(.kind=="Service" and .controller==true)|.uid' <<<"$e")" = "$SVC_UID" ] && [ "$(jq -r --arg pod "$POD" --arg uid "$POD_UID" '[.endpoints[]? | select(.targetRef.kind=="Pod" and .targetRef.namespace==$ENV.NS and .targetRef.name==$pod and .targetRef.uid==$uid)] | length' <<<"$e")" = 1 ]; }`

### 선언 관계 재확인

`if [ "$AUTH_READY" != true ] || [ "$SELECTION_READY" != true ] || [ "$RELATION_READY" != true ] || [ "$TIME_READY" != true ] || ! fresh_relation; then EVIDENCE_READY=false; printf '%s\n' '중단: fresh identity/RV/owner/node/time gate 실패' >&2; else OBSERVED_AT="$(date -u '+%Y-%m-%dT%H:%M:%SZ')"; kubectl get service "$SVC" -n "$NS" -o jsonpath='{range .spec.ports[*]}name={.name} service={.port} target={.targetPort} protocol={.protocol} appProtocol={.appProtocol}{"\n"}{end}'; kubectl get endpointslice "$SLICE" -n "$NS" -o jsonpath='uid={.metadata.uid} rv={.metadata.resourceVersion}{"\n"}{range .ports[*]}name={.name} endpoint={.port} protocol={.protocol}{"\n"}{end}{range .endpoints[*]}target={.targetRef.name}/{.targetRef.uid} address={.addresses} ready={.conditions.ready} serving={.conditions.serving}{"\n"}{end}'; printf 'observed_at=%s incident=%s\n' "$OBSERVED_AT" "$INCIDENT_ID"; fi`

숫자 targetPort는 EndpointSlice 숫자와 직접 비교한다. named targetPort는 선택 Pod의 **선택 container** port name에서 숫자로 해석되고 Slice에 materialize됐는지 본다. 다른 container의 같은 이름을 대신 쓰지 않는다. `containerPort` 선언은 listener가 아니다.

### 실제 listener 확인

이 명령은 container image에 `ss`가 이미 있고 `CONTAINER_ID`가 fresh Pod status와 같은 경우에만 실행한다. 패키지 설치, debug Pod 생성, `eval`, 임의 shell 문자열 조합은 금지한다. `ENDPOINT_PORT`는 숫자 regex와 범위 gate를 통과한 positional argument다.

`EVIDENCE_READY=false; if [ "$AUTH_READY" != true ] || [ "$SELECTION_READY" != true ] || [ "$RELATION_READY" != true ] || [ "$ARGV_READY" != true ] || [ "$TIME_READY" != true ] || ! fresh_relation; then printf '%s\n' '중단: fresh exec gate 실패' >&2; elif [ -z "$CONTAINER_ID" ]; then printf '%s\n' '중단: 선택 container의 active containerID 없음' >&2; else LISTENER_OUT="$(kubectl exec "$POD" -n "$NS" -c "$CONTAINER" -- sh -c 'command -v ss >/dev/null 2>&1 || { printf "%s\n" "ss-unavailable" >&2; exit 127; }; case "$1" in TCP) exec ss -lnt "sport = :$2" ;; UDP) exec ss -lnu "sport = :$2" ;; *) exit 2 ;; esac' sh "$PROTOCOL" "$ENDPOINT_PORT")"; RC=$?; if [ "$RC" -eq 0 ]; then EVIDENCE_READY=true; printf '%s\nEVIDENCE_READY=true\n' "$LISTENER_OUT"; elif [ "$RC" -eq 127 ]; then printf '%s\n' '중단: container에 ss가 없다.' >&2; else printf '중단: exec producer 실패 rc=%s\n' "$RC" >&2; fi; fi`

`LISTEN`이 없으면 filter no-match이며 process가 해당 TCP port에 listen하지 않는 후보지만 UDP·다른 protocol을 부정하지 않는다. `ss` exit `127`은 도구 부재, exec 실패는 API/kubelet/runtime/container lifecycle 문제다. producer exec 실패와 listener no-match를 섞지 않는다. `ready=true`는 이 listener와 application 성공을 보장하지 않는다.

실제 요청은 기존 승인 synthetic에서 같은 source Pod UID/container, protocol, host/path와 무부작용성이 확인된 경우에만 owner 절차로 실행한다. 이 문서는 인증 header·token·body를 만들지 않는다. TCP 성공, HTTP status, application success/data를 별도 기록하며 빈 body·빈 metric을 성공으로 보지 않는다.

## 변경·rollback·정상화

진단과 mutation을 분리한다. live Service/EndpointSlice/Pod patch·edit·delete 명령은 제공하지 않는다. 승인된 선언 원본의 port 계약 변경은 fresh target/evidence, exact subject/RBAC, UTC window, 영향·quorum, 멱등성, 중단 조건, 검증된 rollback revision이 모두 확인된 owner 절차에서만 수행한다.

`MUTATION_READY=false; ROLLBACK_READY=false; NORMALIZATION_READY=false; if [ "$AUTH_READY" != true ] || [ "$EVIDENCE_READY" != true ] || [ "$RELATION_READY" != true ] || [ "$TIME_READY" != true ] || [ "$ARGV_READY" != true ] || ! fresh_relation; then printf '%s\n' '중단: fresh 변경 gate 실패' >&2; else printf '%s\n' '진단 완료: 이 런북에는 변경 명령이 없다.'; fi`

변경 또는 rollback 후 기존 Pod/Slice/containerID/selection 증거는 폐기한다. `invalidate_all` 후 replacement Pod UID·node·active containerID, 새 Slice UID/RV·Service owner UID, 새 port relation을 등록한다. 정상화는 `선언 원본 → Service port/targetPort → Slice port/protocol → replacement targetRef UID → active containerID/listener → Service dataplane → 실제 application 기능` 순으로 확인하고 관찰 창 동안 refused/timeout·Ready 감소·restart 증가가 없어야 한다.

## Prometheus 빠른 관측

`if [ "$AUTO_READY" != true ] || [ "$TIME_READY" != true ] || [ "$RELATION_READY" != true ] || ! fresh_relation; then printf '%s\n' '중단: fresh query identity gate 실패' >&2; else printf 'kube_endpoint_ports{namespace="%s",endpoint="%s"}\n' "$NS" "$SVC"; fi`

빈 결과는 metric 미수집, label 불일치, query/filter 오류, 범위 오류, 실제 no-series를 분리한다. metric은 named targetPort 해석, UID/RV, listener와 application 성공을 증명하지 않는다.

## 증거·근거

UTC window, incident ID, exact subject와 RBAC 결과, Service/Slice/Pod UID·RV·owner·node, containerID, port relation, producer/filter/no-match 분류, 승인·rollback·replacement 재등록·실제 기능 결과를 보존한다. Secret, token, kubeconfig, 개인키, 환경변수, argv 원문, 요청/응답 body는 저장하지 않는다.

- [Kubernetes v1.26 Services](https://v1-26.docs.kubernetes.io/docs/concepts/services-networking/service/)
- [Kubernetes v1.26 EndpointSlices](https://v1-26.docs.kubernetes.io/docs/concepts/services-networking/endpoint-slices/)
- listener 도구, L7 protocol과 dataplane 구현은 환경별 미검증이다.
