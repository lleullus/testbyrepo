# Kubernetes 운영 런북

격리된 멀티클러스터 환경에서 운영자가 증상으로 진입해 Kubernetes 객체, 컴포넌트, 컨테이너 런타임과 Linux 기반 계층까지 원인을 좁히는 문서 체계다.

> [!important] 기준 버전
> Kubernetes Server와 `kubectl` 모두 `1.26.x`를 기준으로 작성한다. 배포판, CNI, 런타임, OS 또는 스토리지 구현체에 따라 달라지는 절차는 런북의 적용 조건에 따로 표시한다.

## 사용 방법

1. 장애 화면의 상태명, 이벤트 reason 또는 오류 문자열을 `Ctrl+F`로 검색한다.
2. 일치하는 증상 런북에서 대상 클러스터와 영향 범위를 먼저 확인한다.
3. 읽기 전용 진단으로 원인 경로를 좁힌다.
4. 관측 결과에 해당하는 분기만 따라간다.
5. 승인 조건을 충족한 복구만 수행하고 실제 서비스까지 정상화됐는지 검증한다.

## 작성 계약

새 런북은 [[01. Kubernetes 1.26 런북 작성 기준]]을 따른다.

핵심 규칙:

- 제목은 운영자가 보는 증상이나 오류 문자열로 작성한다.
- 명령은 원라인이며 context, namespace와 대상을 생략하지 않는다.
- 진단, 상태 변경, 정상화 검증을 분리한다.
- 출력이 다음 행동을 결정하지 않는 명령은 넣지 않는다.
- 확인되지 않은 환경별 절차는 `미검증`으로 표시한다.
- 복구 성공과 근본 원인 확정을 같은 것으로 기록하지 않는다.

## 인접 지식과 경계

- 이 허브는 실제 장애 대응용 런북을 관리한다.
- 명령 선택을 훈련하는 학습 자료는 [[00. 인프라 엔지니어링 역량 허브|인프라 실력 키우기]]에서 관리한다.
- 실제 클러스터 식별자, 내부 주소, 계정, 자격 증명과 운영 로그 원문은 이 지식 영역에 저장하지 않는다.
