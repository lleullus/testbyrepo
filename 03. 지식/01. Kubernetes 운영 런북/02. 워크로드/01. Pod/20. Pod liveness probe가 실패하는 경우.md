# Pod liveness probe가 실패하는 경우

## 입력값과 빠른 수집

이 런북은 `startupProbe`가 성공했거나 정의되지 않은 뒤 같은 Pod UID에서 `Liveness probe failed:`가 먼저 보이고, `Killing`·`Last State`·restartCount 변화가 이어지는 경우를 다룬다. `Killing`만으로 liveness 원인을 확정하지 않는다.

| 구분 | 값과 출처 | 유효성 gate |
|---|---|---|
| 최초 입력 | `NS`, `POD`: 승인된 namespace와 Pod 이름을 운영자가 한 번 입력 | exact-name API 조회 성공 |
| API 확인 자동값 | `POD_UID`, `NODE`, `PHASE`, `POD_IP`, `OWNER`, `OBSERVED_AT`, `POD_RE`, `CONTAINER_ID`, `RESTART_COUNT`, `LAST_STATE`, liveness probe의 `PROBE_SCHEME`, `PROBE_PATH`, `PROBE_HOST` | API 호출 성공, UID·node·container 후보가 비어 있지 않음 |
| 계산 후보값 | `PROBE_PORT`: named/numeric port를 동일 container의 선언 port로 해석한 후보 | 단일 probe와 port 관계, 숫자 범위 확인 |
| 운영자 선택값 | `CONTAINER`, `START_RFC3339`, `START_JOURNAL`, `END_JOURNAL`, `NODE_HOST`, 조건부 `SERVICE`, 조건부 `DEPLOYMENT` | Event 대상·UTC 시간·원격 node·Service/owner 관계 확인 |

각 `PASTE_..._HERE`는 이 문서에서 한 번만 입력한다. 이후 값은 같은 Bash의 등록 변수와 gate를 재사용하며, 찾아 바꾸기·모두 바꾸기를 요구하지 않는다.

실행 host는 승인된 작업 PC 또는 bastion의 동일한 Bash 터미널이다. `kubectl`은 API server에 연결하고 logs/exec는 `API server → 대상 node/kubelet → runtime → container`를 거친다. node journal은 승인된 node shell과 실제 kubelet/runtime unit에서만 실행한다. 아래 host 도구 확인이 실패하면 다음 단계로 진행하지 않는다. API read와 logs/exec 권한은 별도이며 `auth can-i=yes`는 실제 대상 요청 성공을 보장하지 않는다.

**Bash와 host 도구 확인 — 아래 한 줄 전체를 복사**

`TOOLS_READY=false; MISSING_TOOLS=''; if [ -z "${BASH_VERSION:-}" ]; then printf '%s\n' '중단: 같은 Bash에서 실행한다.' >&2; else for TOOL in kubectl jq grep sed date mktemp ssh; do command -v "$TOOL" >/dev/null 2>&1 || MISSING_TOOLS="$MISSING_TOOLS $TOOL"; done; if [ -z "$MISSING_TOOLS" ]; then TOOLS_READY=true; printf 'TOOLS_READY=true shell=%s\n' "$BASH_VERSION"; else printf '중단: 없는 host 도구=%s\n' "$MISSING_TOOLS" >&2; fi; fi`

**최초 입력·이전 파생값과 연결 상태 초기화 — 같은 Bash에서 한 번 실행**

`INPUT_READY=true`가 아니면 context·namespace·Pod identity·API 권한을 먼저 고친다. namespace 미확정 탐색은 정확한 후보를 확인하는 1회성 입력 보조로만 사용하고, 이후 namespaced 명령에서 자동 선택하지 않는다.

**Pod 자동값 수집·등록 — Pod별 세로 출력과 container/port 관계를 보존하는 한 줄**

`AUTO_READY=false; if [ "$INPUT_READY" != true ]; then printf '%s\n' '중단: INPUT_READY가 아니다.' >&2; elif POD_JSON="$(kubectl get pod "$POD" -n "$NS" -o json)" && POD_UID_TMP="$(jq -r '.metadata.uid // empty' <<<"$POD_JSON")" && NODE_TMP="$(jq -r '.spec.nodeName // empty' <<<"$POD_JSON")" && PHASE_TMP="$(jq -r '.status.phase // empty' <<<"$POD_JSON")" && POD_IP_TMP="$(jq -r '.status.podIP // empty' <<<"$POD_JSON")" && OWNER_TMP="$(jq -r '[.metadata.ownerReferences[]? | "\(.kind)/\(.name)"] | join(",")' <<<"$POD_JSON")" && CONTAINER_COUNT_TMP="$(jq '.spec.containers | length' <<<"$POD_JSON")" && OBSERVED_AT_TMP="$(date -u '+%Y-%m-%dT%H:%M:%SZ')" && POD_RE_TMP="$(printf '%s' "$POD" | sed 's/[][\\.^$*+?(){}|]/\\&/g')" && jq -r '"=== 대상 Pod ===\n이름: \(.metadata.name)\nPod UID: \(.metadata.uid)\nNode: \(.spec.nodeName // "-")\nPhase: \(.status.phase // "-")\nPod IP: \(.status.podIP // "-")\nPod 시작 시각: \(.status.startTime // "-")\n상위 owner: \(([.metadata.ownerReferences[]? | "\(.kind)/\(.name)"] | join(",")) // "-")\nContainer/port 후보:\n" + ([.spec.containers[]? | "- \(.name): \([.ports[]? | ((.name // "unnamed") + ":" + (.containerPort|tostring))] | join(",") // "없음")"] | join("\n")) + "\nContainer 상태/ID:\n" + ([.status.containerStatuses[]? | "- \(.name): ready=\(.ready // false), restart=\(.restartCount // 0), state=\(.state | to_entries[0].key // "-"), lastState=\(.lastState | to_entries[0].key // "-"), container ID=\(.containerID // "-")"] | join("\n"))' <<<"$POD_JSON" && [ -n "$POD_UID_TMP" ] && [ -n "$NODE_TMP" ] && [ -n "$PHASE_TMP" ] && [ "$CONTAINER_COUNT_TMP" -ge 1 ]; then POD_UID="$POD_UID_TMP"; NODE="$NODE_TMP"; PHASE="$PHASE_TMP"; POD_IP="$POD_IP_TMP"; OWNER="$OWNER_TMP"; OBSERVED_AT="$OBSERVED_AT_TMP"; POD_RE="^${POD_RE_TMP}$"; AUTO_READY=true; export POD_UID NODE PHASE POD_IP OWNER OBSERVED_AT POD_RE; printf 'AUTO_READY=true\nPod UID=%s\nNode=%s\nPhase=%s\n관측 시각=%s\nPOD_RE=%s\n' "$POD_UID" "$NODE" "$PHASE" "$OBSERVED_AT" "$POD_RE"; else printf '%s\n' '중단: Pod API 실패, UID/node/container 후보 누락, 또는 출력 생성 실패' >&2; unset POD_UID NODE PHASE POD_IP OWNER OBSERVED_AT POD_RE; fi`

성공 출력은 Pod UID·node·phase·시작 시각·UTC 관측 시각과 container별 port·state·lastState·restart·container ID를 함께 보여 줘야 한다. `AUTO_READY`가 아니면 일부 등록값을 유효하게 남기지 않는다. Pod `Running`은 application health, listener, liveness 성공을 보장하지 않는다.

**Event 대상 container 선택 — 출력 확인 뒤 한 번 입력**

`CONTAINER='PASTE_CONTAINER_HERE'; SELECTION_READY=false; unset CONTAINER_ID RESTART_COUNT LAST_STATE; if [ "$AUTO_READY" != true ]; then printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; elif [ -z "$CONTAINER" ]; then printf '%s\n' '중단: CONTAINER를 선택한다.' >&2; elif jq -e --arg c "$CONTAINER" 'any(.spec.containers[]?; .name==$c and .livenessProbe != null)' <<<"$POD_JSON" >/dev/null && CONTAINER_STATUS_COUNT_TMP="$(jq -r --arg c "$CONTAINER" '[.status.containerStatuses[]? | select(.name==$c)] | length' <<<"$POD_JSON")" && [ "$CONTAINER_STATUS_COUNT_TMP" -eq 1 ] && CONTAINER_ID_TMP="$(jq -r --arg c "$CONTAINER" '[.status.containerStatuses[]? | select(.name==$c) | .containerID] | .[0] // empty' <<<"$POD_JSON")" && RESTART_COUNT_TMP="$(jq -r --arg c "$CONTAINER" '[.status.containerStatuses[]? | select(.name==$c) | .restartCount] | .[0] // empty' <<<"$POD_JSON")" && LAST_STATE_TMP="$(jq -r --arg c "$CONTAINER" '[.status.containerStatuses[]? | select(.name==$c) | (.lastState | to_entries[0].key // "-")] | .[0] // empty' <<<"$POD_JSON")" && [ -n "$CONTAINER_ID_TMP" ] && [ -n "$RESTART_COUNT_TMP" ]; then CONTAINER_ID="$CONTAINER_ID_TMP"; RESTART_COUNT="$RESTART_COUNT_TMP"; LAST_STATE="$LAST_STATE_TMP"; SELECTION_READY=true; export CONTAINER CONTAINER_ID RESTART_COUNT LAST_STATE; printf 'SELECTION_READY=true container=%s container_id=%s restart=%s last_state=%s pod_uid=%s\n' "$CONTAINER" "$CONTAINER_ID" "$RESTART_COUNT" "$LAST_STATE" "$POD_UID"; else printf '중단: livenessProbe·container status·container ID가 단일하게 확인되지 않음 container=%s\n' "$CONTAINER" >&2; unset CONTAINER_ID RESTART_COUNT LAST_STATE; fi`

복수 container 또는 복수 후보를 첫 번째 값으로 선택하지 않는다. container ID가 바뀌면 이전 로그·Event와 비교하지 않고 Pod 자동 수집부터 다시 한다.

이후 Pod API를 다시 조회하는 모든 경로는 최초 `$POD_UID`와 대조한다. mismatch·빈 UID·API 실패는 `UID_READY=false`로 닫고 기존 결과를 사용하지 않는다.

`pod_uid_gate(){ local current; UID_READY=false; if current="$(kubectl get pod "$POD" -n "$NS" -o jsonpath='{.metadata.uid}')" && [ -n "$current" ]; then if [ "$current" = "$POD_UID" ]; then UID_READY=true; CURRENT_POD_UID="$current"; printf 'UID_READY=true pod=%s uid=%s\n' "$POD" "$current"; return 0; else printf '중단: Pod UID mismatch initial=%s current=%s\n' "$POD_UID" "$current" >&2; return 1; fi; else printf '중단: Pod 재조회 실패 또는 UID 없음 pod=%s\n' "$POD" >&2; return 1; fi; }`

`container_evidence_gate(){ local current_json current_uid status_count status expected_container_id current_container_id current_state current_ready current_restart failure_reason; EVIDENCE_READY=false; expected_container_id="${CONTAINER_ID:-}"; if [ "${SELECTION_READY:-false}" != true ] || [ -z "$expected_container_id" ]; then failure_reason='selection gate가 닫혔거나 선택한 container ID가 없음'; elif ! current_json="$(command kubectl get pod "$POD" -n "$NS" -o json 2>/dev/null)"; then failure_reason='현재 Pod status 재조회 실패'; else current_uid="$(jq -r '.metadata.uid // empty' <<<"$current_json")"; status_count="$(jq -r --arg c "$CONTAINER" '[.status.containerStatuses[]? | select(.name==$c)] | length' <<<"$current_json")"; status="$(jq -r --arg c "$CONTAINER" '[.status.containerStatuses[]? | select(.name==$c) | [(.containerID // ""), ((.state // {}) | keys[0] // ""), ((.ready // false) | tostring), ((.restartCount // "") | tostring)] | @tsv] | if length==1 then .[0] else empty end' <<<"$current_json")"; if [ "$current_uid" != "$POD_UID" ]; then failure_reason="Pod UID mismatch initial=$POD_UID current=$current_uid"; elif [ "${status_count:-0}" -ne 1 ] || [ -z "$status" ]; then failure_reason="selected container status가 단일하게 확인되지 않음 container=$CONTAINER"; else IFS=$'\t' read -r current_container_id current_state current_ready current_restart <<<"$status"; if [ -z "$current_container_id" ]; then failure_reason="selected container의 current containerID가 비어 있음 container=$CONTAINER"; elif [ "$current_container_id" != "$expected_container_id" ]; then failure_reason="containerID mismatch selected=$expected_container_id current=$current_container_id container=$CONTAINER"; else UID_READY=true; CURRENT_POD_UID="$current_uid"; CURRENT_CONTAINER_ID="$current_container_id"; CURRENT_CONTAINER_STATE="$current_state"; CURRENT_CONTAINER_READY="$current_ready"; CURRENT_CONTAINER_RESTART_COUNT="$current_restart"; EVIDENCE_READY=true; printf 'CONTAINER_EVIDENCE_READY=true pod_uid=%s container=%s container_id=%s status=%s ready=%s restart=%s\n' "$current_uid" "$CONTAINER" "$current_container_id" "$current_state" "$current_ready" "$current_restart"; return 0; fi; fi; fi; SELECTION_READY=false; EVIDENCE_READY=false; AUTO_READY=false; unset POD_JSON CONTAINER_ID CURRENT_CONTAINER_ID CURRENT_CONTAINER_STATE CURRENT_CONTAINER_READY CURRENT_CONTAINER_RESTART_COUNT; printf '중단: %s; selection/evidence gate를 닫고 자동수집부터 재시작한다.\n' "$failure_reason" >&2; return 1; }`

`kubectl(){ if [ "${1:-}" = exec ] || [ "${1:-}" = logs ]; then container_evidence_gate || return 1; fi; command kubectl "$@"; }`

`ssh(){ case "$*" in *journalctl*) container_evidence_gate || return 1;; esac; command ssh "$@"; }`

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | 실행 중인 container에서 liveness failure가 보이고 kubelet이 해당 container를 kill한 뒤 재시작했거나 시도하는 경우 |
| 적용 | 같은 Pod UID의 `Warning Unhealthy`에 `Liveness probe failed:` 실제 suffix가 있고 `Normal Killing`, `restartCount`, `Last State`가 시간순으로 이어지는 경우 |
| 제외 | `Startup probe failed`가 직접 원인이면 [[21. Pod startup probe가 실패하는 경우]], readiness만 실패하면 [[19. Pod readiness probe가 실패하는 경우]], `OOMKilled`·`Evicted`·runtime stop이 선행이면 각각 [[11. Pod STATUS가 OOMKilled인 경우]], [[12. Pod STATUS가 Evicted인 경우]], [[01. Pod STATUS가 Error인 경우]]로 이동한다. |

검색 문자열: `Liveness probe failed`, `Warning Unhealthy`, `Killing`, `HTTP probe failed`, `dial tcp`, `connection refused`, `command`, `rpc error`, `Startup probe failed`, `OOMKilled`, `Evicted`

`startupProbe`가 있는 경우 startup 성공 전에는 liveness와 readiness가 실행되지 않는다. 그 구간의 `Ready=False`나 시작 지연을 liveness 재시작으로 해석하지 않는다. `failureThreshold * periodSeconds`는 판정 계획값일 뿐 정확한 kill 시각이 아니며 timeout·kubelet scheduling·node 부하·Event 집계·termination grace·restart backoff가 wall-clock을 바꾼다. 1.26 기본값은 `initialDelaySeconds=0`, `periodSeconds=10`, `timeoutSeconds=1`, `failureThreshold=3`, `successThreshold=1`이며 실제 spec을 우선한다.

## 최초 확인

실행 경로는 `작업 host → kubectl client → API server → kubelet/node → runtime → container state와 Event`다. API server에서 `get`이 성공해도 kubelet probe 실행과 application 정상은 보장하지 않는다.

**현재 identity·state·probe 확인 — 한 줄**

`DESCRIBE_READY=false; if [ "$SELECTION_READY" != true ]; then printf '%s\n' '중단: SELECTION_READY가 아니다.' >&2; elif pod_uid_gate && kubectl get pod "$POD" -n "$NS" -o wide && kubectl describe pod "$POD" -n "$NS"; then DESCRIBE_READY=true; printf 'DESCRIBE_READY=true pod=%s uid=%s container=%s container_id=%s\n' "$POD" "$POD_UID" "$CONTAINER" "$CONTAINER_ID"; else printf '%s\n' '중단: Pod 상태 또는 describe 조회 실패/UID mismatch' >&2; fi`

출력에서 `State`, `Last State.terminated.reason`, exitCode, signal, startedAt, finishedAt, restartCount, startup probe 성공 여부를 확인한다. describe에 표시된 UID가 `$POD_UID`와 다르면 이름 재사용으로 보고 중단한다.

**UID 제한 Event 한 번 조회 — liveness와 Killing 순서를 확인하는 한 줄**

`EVENT_READY=false; KILLING_READY=false; EVENT_OUTPUT=''; if [ "$DESCRIBE_READY" != true ]; then printf '%s\n' '중단: DESCRIBE_READY가 아니다.' >&2; elif pod_uid_gate && EVENT_OUTPUT="$(kubectl get events -n "$NS" --field-selector "involvedObject.kind=Pod,involvedObject.name=$POD,involvedObject.uid=$POD_UID" --sort-by=.metadata.creationTimestamp -o custom-columns='UID:.involvedObject.uid,CREATED:.metadata.creationTimestamp,FIRST:.firstTimestamp,LAST:.lastTimestamp,EVENT-TIME:.eventTime,SERIES-LAST:.series.lastObservedTime,TYPE:.type,REASON:.reason,COUNT:.count,MESSAGE:.message')" && [ -n "$EVENT_OUTPUT" ]; then printf '%s\n' "$EVENT_OUTPUT"; if grep -Fq 'Liveness probe failed:' <<<"$EVENT_OUTPUT"; then EVENT_READY=true; fi; if grep -Fq 'Killing' <<<"$EVENT_OUTPUT"; then KILLING_READY=true; fi; if [ "$EVENT_READY" = true ]; then printf 'EVENT_READY=true pod_uid=%s killing=%s\n' "$POD_UID" "$KILLING_READY"; else printf '%s\n' '중단: Event 조회는 성공했지만 liveness failure suffix가 없음; startup/readiness/다른 원인으로 분기' >&2; fi; else printf '%s\n' '중단: UID 제한 Event API 실패 또는 빈 결과; 정상·오류 없음으로 해석하지 않음' >&2; fi`

Event에서 첫 `Liveness probe failed:` suffix → `Normal Killing`의 `Container ... failed liveness probe, will be restarted` → `Last State`·finishedAt → restartCount 증가를 시간순으로 대조한다. `Killing`만 있거나 restartCount가 증가하지 않으면 증거 불완전이다. `Last State.reason=OOMKilled`·Evicted가 선행하면 liveness를 직접 kill 원인으로 기록하지 않는다. Event의 빈 시각이나 집계 COUNT는 정상·장애 해소를 의미하지 않는다.

### Unhealthy → Killing → Last State

진입 증거는 `EVENT_READY=true`이고 liveness suffix와 Killing message가 같은 UID에서 시간순으로 보이는 경우다. 최초 필요값은 `$POD_UID`, `$CONTAINER_ID`, `$START_RFC3339`이며 앞의 API·Event와 운영자가 선택한 시간에서 온다.

`START_RFC3339='PASTE_START_RFC3339_HERE'; TIME_READY=false; START_EPOCH=''; if [ "$EVENT_READY" != true ]; then printf '%s\n' '중단: EVENT_READY가 아니다.' >&2; elif [[ "$START_RFC3339" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] && START_EPOCH="$(date -u -d "$START_RFC3339" +%s 2>/dev/null)" && [ -n "$START_EPOCH" ]; then TIME_READY=true; export START_RFC3339 START_EPOCH; printf 'TIME_READY=true start_utc=%s epoch=%s pod_uid=%s container_id=%s\n' "$START_RFC3339" "$START_EPOCH" "$POD_UID" "$CONTAINER_ID"; else printf '%s\n' '중단: START_RFC3339 형식 또는 UTC 시각이 유효하지 않음' >&2; fi`

`logs_filtered(){ local mode="$1" pattern="$2" log_file producer_rc filter_output filter_rc; if [ "$TIME_READY" != true ] || [ "$SELECTION_READY" != true ] || ! pod_uid_gate; then printf '%s\n' '중단: log 시간·container 선택·UID gate가 아니다.' >&2; return 1; fi; log_file="$(mktemp)"; if ! container_evidence_gate; then rm -f "$log_file"; return 1; fi; if [ "$mode" = previous ]; then kubectl logs "$POD" -n "$NS" -c "$CONTAINER" --previous --timestamps --since-time="$START_RFC3339" --tail=200 >"$log_file"; else kubectl logs "$POD" -n "$NS" -c "$CONTAINER" --timestamps --since-time="$START_RFC3339" --tail=200 >"$log_file"; fi; producer_rc=$?; LOG_PRODUCER_RC="$producer_rc"; if [ "$producer_rc" -ne 0 ]; then printf 'logs producer 실패 rc=%s mode=%s pod_uid=%s container_id=%s\n' "$producer_rc" "$mode" "$POD_UID" "$CONTAINER_ID" >&2; rm -f "$log_file"; return "$producer_rc"; fi; filter_output="$(grep -E -i -C 3 "$pattern" "$log_file")"; filter_rc=$?; LOG_FILTER_RC="$filter_rc"; if [ "$filter_rc" -eq 0 ]; then printf '%s\n' "$filter_output"; elif [ "$filter_rc" -eq 1 ]; then printf 'logs filter no-match producer_rc=0 filter_rc=1 mode=%s pod_uid=%s container_id=%s\n' "$mode" "$POD_UID" "$CONTAINER_ID" >&2; else printf 'logs filter 실패 producer_rc=0 filter_rc=%s mode=%s\n' "$filter_rc" "$mode" >&2; rm -f "$log_file"; return "$filter_rc"; fi; rm -f "$log_file"; return 0; }`

성공 gate는 suffix·Killing·Last State·restartCount의 직접 시각을 비교할 수 있는 것이다. `finishedAt`가 suffix보다 먼저면 application 또는 runtime 종료가 선행한 것이며 liveness가 결과를 기록한 것일 수 있다. 다음은 로그·kubelet·probe type 분기로 내려간다.

### 공통 current/previous 로그와 kubelet 증거

로그 경로는 `작업 host → API server → kubelet → runtime log stream → 현재 또는 이전 container process output`이다. Pod 이름만으로 충분하다고 보지 않고 `$POD_UID`, `$CONTAINER_ID`, `$START_RFC3339`를 결과에 기록한다.

**현재 bounded 로그 — stream 실패와 빈 필터를 분리하는 한 줄**

`LOG_READY=false; LOG_PRODUCER_RC=''; LOG_FILTER_RC=''; if logs_filtered current 'panic|fatal|error|exception|timeout|refused|denied|permission|oom|killed|health|probe|listen|bind|dependency'; then LOG_READY=true; printf 'LOG_STREAM_READY=true producer_rc=%s filter_rc=%s pod_uid=%s container_id=%s window_start=%s\n' "$LOG_PRODUCER_RC" "$LOG_FILTER_RC" "$POD_UID" "$CONTAINER_ID" "$START_RFC3339"; else printf '중단: logs stream producer/filter 실패 producer_rc=%s filter_rc=%s pod_uid=%s container_id=%s\n' "$LOG_PRODUCER_RC" "$LOG_FILTER_RC" "$POD_UID" "$CONTAINER_ID" >&2; fi`

`LOG_READY=true`는 stream을 읽었다는 gate다. 필터가 비면 같은 시간창의 비식별화된 tail로만 재확인한다. Secret·token·개인키·개인정보가 보이면 출력과 보존을 중단한다.

**필터가 비었을 때 current tail 재확인 — bounded 한 줄**

`if [ "$LOG_READY" != true ]; then printf '%s\n' '중단: LOG_READY가 아니다.' >&2; elif pod_uid_gate && kubectl logs "$POD" -n "$NS" -c "$CONTAINER" --timestamps --since-time="$START_RFC3339" --tail=50; then printf 'current tail stream 성공 producer_rc=0 pod_uid=%s container_id=%s window_start=%s\n' "$POD_UID" "$CONTAINER_ID" "$START_RFC3339"; else printf '%s\n' 'current tail producer 실패 또는 UID mismatch: 로그 계층 오류를 확인' >&2; fi`

**이전 container 로그 — restart 또는 Last State가 있을 때만 한 줄**

`PREVIOUS_READY=false; if [ "$LOG_READY" != true ]; then printf '%s\n' '중단: LOG_READY가 아니다.' >&2; elif [ "$RESTART_COUNT" -gt 0 ] || [ "$LAST_STATE" = terminated ]; then if logs_filtered previous 'panic|fatal|error|exception|timeout|refused|denied|permission|oom|killed|health|probe|listen|bind|dependency'; then PREVIOUS_READY=true; printf 'PREVIOUS_LOG_STREAM_READY=true producer_rc=%s filter_rc=%s pod_uid=%s container_id=%s window_start=%s\n' "$LOG_PRODUCER_RC" "$LOG_FILTER_RC" "$POD_UID" "$CONTAINER_ID" "$START_RFC3339"; else printf 'previous logs producer/filter 실패 producer_rc=%s filter_rc=%s pod_uid=%s container_id=%s\n' "$LOG_PRODUCER_RC" "$LOG_FILTER_RC" "$POD_UID" "$CONTAINER_ID" >&2; fi; else printf '%s\n' '중단: restart 또는 terminated Last State 근거가 없어 previous 로그를 실행하지 않음' >&2; fi`

`--previous` 성공은 직전 instance의 stream 범위만 보장하며 현재 container ID의 로그와 동일한 lifecycle이라고 보장하지 않는다. 결과가 없으면 Last State의 startedAt·finishedAt·reason·exitCode로 가능한 범위를 제한한다.

**previous filter가 비었을 때 tail 재확인 — restart 또는 terminated Last State 조건**

`if [ "$LOG_READY" != true ]; then printf '%s\n' '중단: LOG_READY가 아니다.' >&2; elif [ "$RESTART_COUNT" -gt 0 ] || [ "$LAST_STATE" = terminated ]; then if pod_uid_gate && kubectl logs "$POD" -n "$NS" -c "$CONTAINER" --previous --timestamps --since-time="$START_RFC3339" --tail=50; then printf 'previous tail stream 성공 producer_rc=0 pod_uid=%s container_id=%s window_start=%s\n' "$POD_UID" "$CONTAINER_ID" "$START_RFC3339"; else printf '%s\n' 'previous tail producer 실패 또는 UID mismatch: 이전 instance를 확인' >&2; fi; else printf '%s\n' '중단: restart 또는 terminated Last State 근거가 없어 previous tail을 실행하지 않음' >&2; fi`

### Probe type과 target

진입 증거는 Event suffix가 있고 `$SELECTION_READY=true`인 경우다. `$CONTAINER`와 `$POD_JSON`에서 liveness·startup probe, HTTP header 이름, TCP host/port, exec command, gRPC port/service, timing을 읽는다.

`TARGET_READY=false; unset PROBE_SCHEME PROBE_PATH PROBE_HOST PROBE_PATH_HAS_QUERY HTTP_HEADER_COUNT HTTP_HEADER_NAMES; if [ "$EVENT_READY" != true ] || [ "$SELECTION_READY" != true ]; then printf '%s\n' '중단: Event와 container 선택 gate가 아니다.' >&2; elif TARGET_OUTPUT="$(jq -r --arg c "$CONTAINER" '.spec.containers[] | select(.name==$c) | "container=\(.name) HTTP=\(.livenessProbe.httpGet.host // "-")/\((.livenessProbe.httpGet.path // "-") | split("?")[0])/\(.livenessProbe.httpGet.port // "-")/\(.livenessProbe.httpGet.scheme // "-") TCP=\(.livenessProbe.tcpSocket.host // "-")/\(.livenessProbe.tcpSocket.port // "-") exec_binary=\(.livenessProbe.exec.command[0] // "-") exec_arg_count=\((.livenessProbe.exec.command // [])|length) gRPC=\(.livenessProbe.grpc.port // "-")/\(.livenessProbe.grpc.service // "-") timing=\(.livenessProbe.initialDelaySeconds // 0),\(.livenessProbe.timeoutSeconds // 1),\(.livenessProbe.periodSeconds // 10),\(.livenessProbe.failureThreshold // 3),\(.livenessProbe.successThreshold // 1),\(.livenessProbe.terminationGracePeriodSeconds // "Pod-level/default") ports=\([.ports[]? | ((.name // "unnamed") + ":" + (.containerPort|tostring))] | join(",") // "없음")"' <<<"$POD_JSON")" && [ -n "$TARGET_OUTPUT" ]; then PROBE_SCHEME="$(jq -r --arg c "$CONTAINER" '.spec.containers[] | select(.name==$c) | .livenessProbe.httpGet.scheme // empty' <<<"$POD_JSON")"; PROBE_PATH="$(jq -r --arg c "$CONTAINER" '.spec.containers[] | select(.name==$c) | (.livenessProbe.httpGet.path // "") | split("?")[0]' <<<"$POD_JSON")"; PROBE_PATH_HAS_QUERY="$(jq -r --arg c "$CONTAINER" '.spec.containers[] | select(.name==$c) | (.livenessProbe.httpGet.path // "") | contains("?")' <<<"$POD_JSON")"; PROBE_HOST="$(jq -r --arg c "$CONTAINER" '.spec.containers[] | select(.name==$c) | .livenessProbe.httpGet.host // empty' <<<"$POD_JSON")"; HTTP_HEADER_COUNT="$(jq -r --arg c "$CONTAINER" '[.spec.containers[] | select(.name==$c) | .livenessProbe.httpGet.httpHeaders[]?.name | select(type=="string")] | length' <<<"$POD_JSON")"; HTTP_HEADER_NAMES="$(jq -r --arg c "$CONTAINER" '[.spec.containers[] | select(.name==$c) | .livenessProbe.httpGet.httpHeaders[]?.name | select(type=="string")] | unique | if length==0 then "-" else join(",") end' <<<"$POD_JSON")"; TARGET_READY=true; export PROBE_SCHEME PROBE_PATH PROBE_HOST PROBE_PATH_HAS_QUERY HTTP_HEADER_COUNT HTTP_HEADER_NAMES; printf '%s\n' "$TARGET_OUTPUT"; printf 'TARGET_READY=true scheme=%s path=%s query_present=%s host=%s http_headers_count=%s http_header_names=%s\n' "${PROBE_SCHEME:--}" "${PROBE_PATH:--}" "${PROBE_PATH_HAS_QUERY:-false}" "${PROBE_HOST:--}" "$HTTP_HEADER_COUNT" "$HTTP_HEADER_NAMES"; else printf '%s\n' '중단: 선택 container의 livenessProbe 또는 target field가 현재 spec에서 확인되지 않음' >&2; fi`

target 출력이 비거나 named port가 다른 container에만 있으면 API field 부재·selector 오류·manifest drift를 분리하고 manifest owner에게 되돌린다. `containerPort` 선언은 실제 bind와 protocol을 보장하지 않는다. startup probe가 아직 성공하지 않았다는 증거면 [[21. Pod startup probe가 실패하는 경우]]로 이동한다.

**probe port 해석 — named/numeric port를 단일 관계로 확정하는 한 줄**

`PORT_READY=false; unset PROBE_PORT_RAW PROBE_PORT; if [ "$TARGET_READY" != true ]; then printf '%s\n' '중단: TARGET_READY가 아니다.' >&2; elif PROBE_PORT_RAW="$(jq -r --arg c "$CONTAINER" '.spec.containers[] | select(.name==$c) | (.livenessProbe.httpGet.port // .livenessProbe.tcpSocket.port // .livenessProbe.grpc.port // empty)' <<<"$POD_JSON")" && [ -n "$PROBE_PORT_RAW" ]; then if [[ "$PROBE_PORT_RAW" =~ ^[0-9]+$ ]]; then PROBE_PORT="$PROBE_PORT_RAW"; else PORT_MATCHES="$(jq -r --arg c "$CONTAINER" --arg p "$PROBE_PORT_RAW" '[.spec.containers[] | select(.name==$c) | .ports[]? | select(.name==$p) | .containerPort] | if length==1 then .[0]|tostring else empty end' <<<"$POD_JSON")"; [ -n "$PORT_MATCHES" ] && PROBE_PORT="$PORT_MATCHES"; fi; if [[ "${PROBE_PORT:-}" =~ ^[0-9]+$ ]] && (( PROBE_PORT >= 1 && PROBE_PORT <= 65535 )); then PORT_READY=true; export PROBE_PORT; printf 'PORT_READY=true raw=%s resolved=%s container=%s\n' "$PROBE_PORT_RAW" "$PROBE_PORT" "$CONTAINER"; else printf '중단: probe port가 단일 숫자 port로 해석되지 않음 raw=%s\n' "$PROBE_PORT_RAW" >&2; unset PROBE_PORT; fi; else printf '%s\n' '중단: probe port가 비어 있음' >&2; fi`

`PORT_READY=true`는 선언된 숫자 후보만 확정하며 process listener나 HTTP/gRPC 정상은 보장하지 않는다. 빈 결과는 field 부재·named port 불일치·API 오류 후보로 기록하고 port를 임의 변경하지 않는다.

### HTTP

진입 증거는 `HTTP probe failed with statuscode`, 4xx·5xx, timeout 또는 refused suffix가 있고 `$PORT_READY=true`인 경우다. HTTP 경로는 `작업 host → API server → kubelet/node → Pod IP:$PROBE_PORT → HTTP/HTTPS listener → application route/dependency`다. `127.0.0.1` 보조 확인은 container network namespace이며 kubelet의 Pod IP 경로를 대신하지 않는다.

**container 내부 HTTP 보조 확인 — transport·HTTP status를 분리하는 한 줄**

`HTTP_OBS_READY=false; if [ "$PORT_READY" != true ] || [ "$LOG_READY" != true ] || [ "$TARGET_READY" != true ]; then printf '%s\n' '중단: PORT_READY·LOG_READY·TARGET_READY가 아니다.' >&2; elif ! jq -e --arg c "$CONTAINER" 'any(.spec.containers[]?; .name==$c and .livenessProbe.httpGet != null)' <<<"$POD_JSON" >/dev/null; then printf '%s\n' '중단: selected livenessProbe.httpGet가 없어 localhost HTTP 보조 관측을 실행하지 않음; TCP/gRPC/exec target은 해당 경로로 이관' >&2; elif [ "${HTTP_HEADER_COUNT:-0}" -gt 0 ] || [ "${PROBE_PATH_HAS_QUERY:-false}" = true ]; then printf '이관: httpHeaders names=%s count=%s 또는 query path가 있어 localhost HTTP 동등 관측을 실행하지 않고 application owner/kubelet evidence로 이관한다. query_present=%s\n' "${HTTP_HEADER_NAMES:--}" "${HTTP_HEADER_COUNT:-0}" "${PROBE_PATH_HAS_QUERY:-false}" >&2; elif [ -n "$PROBE_HOST" ]; then printf '중단: custom probe host=%s는 localhost 결과와 같지 않음; kubelet Pod IP 경로를 확인\n' "$PROBE_HOST" >&2; elif pod_uid_gate && kubectl exec "$POD" -n "$NS" -c "$CONTAINER" -- sh -c 'scheme="$1"; port="$2"; path="$3"; if command -v curl >/dev/null 2>&1; then rc=0; out="$(curl --noproxy "*" -sS -o /dev/null -w "transport=ok http_status=%{http_code} time_total=%{time_total}" --connect-timeout 3 --max-time 5 "${scheme}://127.0.0.1:${port}${path}")" || rc=$?; printf "%s curl_rc=%s\n" "$out" "$rc"; [ "$rc" -eq 0 ]; elif command -v wget >/dev/null 2>&1; then if wget -qO /dev/null -T 3 "${scheme}://127.0.0.1:${port}${path}"; then printf "%s\n" "transport=ok http_status=unreported"; else printf "%s\n" "transport=failed http_status=000" >&2; exit 1; fi; else printf "%s\n" "probe_tool_missing=curl,wget" >&2; exit 127; fi' sh "${PROBE_SCHEME:-http}" "$PROBE_PORT" "${PROBE_PATH:-/}"; then HTTP_OBS_READY=true; printf 'HTTP_OBS_READY=true pod_uid=%s container_id=%s\n' "$POD_UID" "$CONTAINER_ID"; else printf '%s\n' 'HTTP 보조 확인 실패: transport·listener·container 도구 계층을 다음 분기로 확인' >&2; fi`

`HTTP_OBS_READY=true`는 container loopback의 transport와 status 관측만 보장한다. 200 이상 400 미만은 probe 성공 범위지만 application 기능·dependency 정상·Service 요청 성공을 단독 보장하지 않는다. 404는 path/route, 401/403은 인증·인가 계약, 5xx는 app/dependency, refused는 bind/listener, timeout은 app hang·resource·node·network 후보로 내려간다. HTTPS certificate 검증을 `-k`로 우회하지 않는다.

### TCP

진입 증거는 `dial tcp`, refused 또는 timeout suffix다. 경로는 `작업 host → API server → kubelet/node → Pod IP:$PROBE_PORT → TCP listener → process accept loop`이며 Service port/DNS는 사용하지 않는다.

**listener bounded 확인 — tool failure를 감추지 않는 한 줄**

`if [ "$PORT_READY" != true ]; then printf '%s\n' '중단: PORT_READY가 아니다.' >&2; elif kubectl exec "$POD" -n "$NS" -c "$CONTAINER" -- sh -c 'if command -v ss >/dev/null 2>&1; then ss -lnt; elif command -v netstat >/dev/null 2>&1; then netstat -lnt; else printf "%s\n" "listener_tool_missing=ss,netstat" >&2; exit 127; fi'; then printf 'listener stream 성공 pod_uid=%s container_id=%s port=%s\n' "$POD_UID" "$CONTAINER_ID" "$PROBE_PORT"; else printf '%s\n' 'listener 조회 실패: exec/runtime 또는 image 도구 계층으로 이관; 다른 도구로 덮지 않음' >&2; fi`

listener가 없으면 bind·app 초기화로, listener가 있는데 node probe만 timeout/refused이면 Pod IP·NetworkPolicy·CNI·kubelet/resource로 이동한다. TCP open은 HTTP/gRPC 기능이나 실제 Service 요청 성공을 보장하지 않는다. 빈 출력은 정상 listener 없음으로 단정하지 않는다.

### exec

진입 증거는 `command ... exited`, no such file, permission denied 또는 exec timeout suffix다. 경로는 `작업 host → API server → kubelet → runtime exec stream → container namespace → binary/argv`이며 Pod IP·Service DNS는 경로가 아니다.

**첫 binary 존재만 확인 — probe command 전체 실행을 피하는 한 줄**

`if [ "$TARGET_READY" != true ] || [ "$LOG_READY" != true ]; then printf '%s\n' '중단: TARGET_READY 또는 LOG_READY가 아니다.' >&2; elif EXEC_BINARY="$(jq -r --arg c "$CONTAINER" '.spec.containers[] | select(.name==$c) | .livenessProbe.exec.command[0] // empty' <<<"$POD_JSON")" && [ -n "$EXEC_BINARY" ]; then if kubectl exec "$POD" -n "$NS" -c "$CONTAINER" -- sh -c 'command -v "$1" >/dev/null 2>&1' sh "$EXEC_BINARY"; then printf 'exec_binary=present pod_uid=%s container_id=%s binary=%s\n' "$POD_UID" "$CONTAINER_ID" "$EXEC_BINARY"; else printf 'exec binary 확인 실패: PATH·image·runtime exec 계층을 확인 binary=%s\n' "$EXEC_BINARY" >&2; fi; else printf '%s\n' '중단: exec binary가 spec에서 확인되지 않음' >&2; fi`

1.26의 `ExecProbeTimeout`은 GA·기본 활성화다. binary 존재는 argv·exit code 0·파일 lifecycle·권한·resource pressure를 보장하지 않는다. command를 무조건 성공하게 하거나 진단 중 전체 argv를 임의 `exec`하지 않는다. image에 shell이 없으면 owner에게 manifest/image와 container ID를 이관한다.

### gRPC

진입 증거는 `rpc error` 또는 gRPC health 오류 suffix다. 경로는 `작업 host → API server → kubelet/node → Pod IP:$PROBE_PORT → gRPC Health Checking Protocol listener`다. `GRPCContainerProbe`는 1.26 Beta·기본 활성화지만 feature gate와 API 수용을 먼저 확인한다.

gRPC port는 숫자만 허용되고 named port·custom host·TLS/auth parameter를 사용하지 않는다. `Unavailable`, `DeadlineExceeded`, `NOT_SERVING`은 failure 후보이며 application health service 미구현, Pod IP bind, NetworkPolicy/CNI, node 지연을 분리한다. gate가 꺼졌거나 API가 field를 거부하면 HTTP/TCP/exec로 임의 변경하지 않고 cluster administrator와 application owner에게 이관한다. 빈 결과는 정상이나 health service 없음으로 기록하지 않는다.

### 앱·kubelet·resource·node 지연

진입 증거는 liveness timeout과 app hang·GC pause·deadlock 또는 resource pressure가 같은 시간창에 보이는 경우다. `$START_JOURNAL`·`$END_JOURNAL`은 승인된 node 접근과 실제 unit을 확인한 뒤 선택한다.

`NODE_HOST`는 작업 PC에서 접속할 승인된 remote host이며 Kubernetes `$NODE`의 SSH 별칭으로 자동 추측하지 않는다. SSH gate가 remote `hostname`을 Kubernetes `$NODE`와 정확히 대조한 뒤에만 remote journal/CRI를 실행한다. 대조 실패·SSH host key/권한 실패·hostname mapping 불일치는 node owner에게 이관하고 작업 PC의 local journal/CRI를 실행하지 않는다.

`NODE_HOST='PASTE_NODE_HOST_HERE'; NODE_SSH_READY=false; REMOTE_NODE=''; if [ "$EVENT_READY" != true ]; then printf '%s\n' '중단: EVENT_READY가 아니다.' >&2; elif [ -z "$NODE_HOST" ]; then printf '%s\n' '중단: NODE_HOST를 선택한다.' >&2; elif pod_uid_gate && REMOTE_NODE="$(ssh -o BatchMode=yes -o ConnectTimeout=10 "$NODE_HOST" hostname 2>&1)"; then REMOTE_NODE="${REMOTE_NODE//$'\r'/}"; if [ "$REMOTE_NODE" = "$NODE" ]; then NODE_SSH_READY=true; printf 'NODE_SSH_READY=true kubernetes_node=%s remote_node=%s node_host=%s pod_uid=%s\n' "$NODE" "$REMOTE_NODE" "$NODE_HOST" "$POD_UID"; else printf '중단: remote identity mismatch kubernetes_node=%s remote_node=%s node_host=%s\n' "$NODE" "$REMOTE_NODE" "$NODE_HOST" >&2; fi; else printf '중단: SSH remote identity 조회 실패 node_host=%s; local journal/CRI를 실행하지 않음\n' "$NODE_HOST" >&2; fi`

**container resource·node condition 확인 — API 범위를 나눈 한 줄**

## 제한적 복구와 안전 gate

상태 변경은 직접 원인이 확정되고 승인된 workload template 경로가 확인된 경우에만 별도 작업으로 수행한다. 이 진단 문서에는 `delete`, `patch`, `restart`, `rollout` mutation 명령을 넣지 않는다.

- **Trigger:** 같은 UID의 failure suffix와 `Killing`, Last State/restart 또는 app·kubelet·resource 증거 중 최소 두 계층이 직접 원인을 지지한다.
- **Authority:** 대상 workload·owner·승인된 context·namespace·권한과 변경 범위가 확인됐다.
- **Scope:** restart·traffic·data·quorum·leader·중복 처리 영향, 관찰 시간과 실제 서비스 검증 방법을 기록했다.
- **Allowed:** 직접 확인된 path/port/scheme/command/gRPC service 수정, 측정된 정상 시작 시간에 맞춘 startup 보호, app hang 원인 수정, liveness에서 외부 dependency를 분리하는 설계 변경만 승인 절차로 검토한다.
- **Forbidden:** liveness/startup 삭제, `failureThreshold`·`timeoutSeconds` 무작정 증가, 항상 성공 endpoint, 원인 확인 전 Pod 삭제·강제 재시작을 하지 않는다.
- **Rollback/stop:** 새 suffix·Killing·restart 증가, Ready·실제 요청·latency 악화, 새 Warning·resource pressure가 보이면 중단하고 승인된 이전 revision으로 되돌리거나 owner에게 이관한다.
- **Verification:** 변경 전 probe spec·restartCount·Pod UID·EndpointSlice·실제 service metric을 보존하고, 변경 뒤 새 UID와 liveness chain·Ready·EndpointSlice·실제 기능을 역순으로 검증한다.

Deployment인 경우 승인된 revision과 owner가 확인된 뒤에만 읽기 전용 rollout 상태를 본다. StatefulSet은 ordinal·PVC·quorum·순차 교체, DaemonSet은 node별 desired/current/ready, Job/CronJob은 멱등성과 외부 중복을 별도로 확인한다.

## 정상화와 실제 서비스 검증

정상화는 `liveness` 성공 한 번이나 container `Running`으로 선언하지 않는다. 원인 경로를 `application 기능 → HTTP/API 또는 protocol → process listener → Pod IP/kubelet → runtime → container/Pod identity` 역순으로 확인한다.

1. 같은 Pod UID에서 새로운 `Liveness probe failed:`와 liveness `Killing`이 관찰 창 동안 반복되지 않는다.
2. 대상 container가 `Running`이고 Last State가 갱신된 뒤 restartCount가 안정적이다.
3. Pod `Ready=True`, 원하는 replica/Ready 수와 새 Warning Event 부재를 확인한다. `Ready=True`는 실제 Service 기능을 보장하지 않는다.
4. Service가 실제로 있고 승인된 검증이 필요할 때만 `SERVICE`를 선택해 selector·EndpointSlice와 대상 Pod IP·port를 대조한다. EndpointSlice `ready=true`도 모든 process listener와 기능 성공을 보장하지 않는다.
5. 승인된 health check·synthetic transaction·핵심 기능 지표로 실제 요청 성공률·latency와 liveness 원인 재발을 bounded 시간 동안 관찰한다.

| (.targetPort // .port) as $target | if ($target|type)=="number" then select($target==$probe) | $target else select(any($cports[]?; .name==$target and .containerPort==$probe)) | ([$cports[]? | select(.name==$target) | .containerPort][0]) end] | unique | if length==1 then .[0]|tostring else empty end' <<<"$service_json")"; if [ -z "$target_port" ]; then printf '중단: Service targetPort와 선택 probe port 관계가 단일하게 확인되지 않음 service=%s probe_port=%s\n' "$SERVICE" "$PROBE_PORT" >&2; else matches="$(jq -r --arg uid "$POD_UID" --arg target "$target_port" '[.items[]? as $slice | $slice.endpoints[]? | select(.targetRef.uid==$uid) | $slice.ports[]? | select((.port|tostring)==$target) | "\($slice.metadata.uid)\t\(.targetRef.uid)\t\(.port)"] | unique[]?' <<<"$endpoint_json")"; if [ -z "$matches" ]; then printf '중단: EndpointSlice에 targetRef.uid=%s와 backend port=%s가 함께 없음\n' "$POD_UID" "$target_port" >&2; else printf 'SERVICE_UID=%s\nPOD_UID=%s\nSERVICE_SELECTOR=%s\nSERVICE_TARGET_PORT=%s\nEndpointSlice UID<TAB>targetRef UID<TAB>backend port:\n%s\n' "$(jq -r '.metadata.uid' <<<"$service_json")" "$POD_UID" "$(jq -c '.spec.selector' <<<"$service_json")" "$target_port" "$matches"; SERVICE_READY=true; fi; fi; fi; else printf '중단: Pod/Service/EndpointSlice API 조회 실패 service=%s\n' "$SERVICE" >&2; fi; }`

`if [ "$SERVICE_INPUT_READY" != true ]; then printf '%s\n' '중단: SERVICE_INPUT_READY가 아니다.' >&2; elif service_relation_gate; then printf 'SERVICE_READY=%s service=%s pod_uid=%s\n' "$SERVICE_READY" "$SERVICE" "$POD_UID"; else printf '%s\n' 'SERVICE_READY=false: selector·targetPort·EndpointSlice targetRef UID 관계를 승인하지 않음' >&2; fi`

## Prometheus 빠른 관측

실제 `prober_probe_total`의 비표준 `pod_uid` label과 KSM metric의 표준 `uid` label이 각각 수집되는 경우에만 사용한다. `prober_probe_total`의 `pod_uid`를 KSM metric selector에 사용하거나 두 metric의 label을 혼용하지 않는다. `POD_RE`는 Pod 이름을 regex escape한 자동값이며 PromQL 안을 직접 수정하지 않는다. 생성된 한 줄만 Prometheus/Grafana에 붙여 넣는다.

**liveness probe 실패 증가 PromQL 생성 — bounded 한 줄**

`if [ "$SELECTION_READY" != true ] || [ -z "${POD_RE:-}" ] || [ -z "${POD_UID:-}" ]; then printf '%s\n' '중단: SELECTION_READY·POD_RE 또는 POD_UID가 아니다.' >&2; else printf '%s\n' "sum by(namespace,pod,pod_uid,container)(increase(prober_probe_total{namespace=\"$NS\",pod=~\"$POD_RE\",pod_uid=\"$POD_UID\",container=\"$CONTAINER\",probe_type=\"Liveness\",result!=\"successful\"}[15m]))"; fi`

**restart 증가 PromQL 생성 — bounded 한 줄**

`if [ "$SELECTION_READY" != true ] || [ -z "${POD_RE:-}" ] || [ -z "${POD_UID:-}" ]; then printf '%s\n' '중단: SELECTION_READY·POD_RE 또는 POD_UID가 아니다.' >&2; else printf '%s\n' "sum by(namespace,pod,uid,container)(increase(kube_pod_container_status_restarts_total{namespace=\"$NS\",pod=~\"$POD_RE\",uid=\"$POD_UID\",container=\"$CONTAINER\"}[15m]))"; fi`

쿼리 빈 결과는 정상·0이 아니다. metric 미수집, label 불일치, query 범위, 권한/API 오류를 구분하고 HTTP transport·status·API data를 따로 확인한다. PromQL만으로 liveness가 kill 원인이라고 확정하거나 상태 변경을 승인하지 않는다.
