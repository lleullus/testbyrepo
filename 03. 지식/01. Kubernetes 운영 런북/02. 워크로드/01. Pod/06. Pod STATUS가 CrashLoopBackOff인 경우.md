# Pod STATUS가 CrashLoopBackOff인 경우

## 입력값과 빠른 수집

이 문서는 대상 container의 현재 `state.waiting.reason=CrashLoopBackOff`라는 kubelet backoff 상태를 주 진입으로 다룬다. `CrashLoopBackOff`는 원인이 아니며 `lastState.terminated.reason`, `exitCode`, 재시작 원점, current/previous log, 같은 Pod UID의 Event를 함께 확인한다. 값은 최초 입력, API 확인 자동값, 계산 후보, 운영자 선택값으로 분류한다.

| 구분 | 값 | 출처와 유효성 gate |
|---|---|---|
| 최초 입력 | `NS`, `POD` | 운영자가 승인된 namespace와 정확한 Pod 이름을 한 번 입력한다. |
| API 확인 자동값 | `POD_UID`, `NODE`, `PHASE`, `POD_START`, `OWNER`, `REPLICASET`, container별 state·lastState·reason·exit·시각·restart·container ID, container/port 후보 | Pod API의 한 응답과 owner 후보 출력으로 등록한다. 복수 controller owner·빈 UID·container 부재·API 실패면 자동값 세트를 무효화한다. |
| 계산 후보 | `NS_RE`, `POD_RE`, `CONTAINER_RE`, 생성 PromQL | 등록된 이름을 escape한 bounded 후보이며 query 출력 전에는 확정하지 않는다. |
| 운영자 선택값 | `CONTAINER`, `START_RFC3339`, `SERVICE`, `NODE_HOST`, `RUNTIME_UNIT`, `CRI_ENDPOINT`, `DEPLOYMENT`, `APPROVAL_ID`, `ROLLBACK_REVISION`, journal 시간 | 현재 CrashLoop container와 직접 증거의 시간·Service·승인된 node evidence 목적지·실제 runtime unit/CRI endpoint·승인된 Deployment 변경의 승인·rollback 기록을 확인한 뒤 분기에서 선택한다. `NODE_HOST`는 node journal/CRI evidence 직전에 선택한다. |

실행 host는 승인된 작업 PC 또는 bastion의 **같은 Bash 터미널**이다. `NODE_HOST`는 승인된 SSH 목적지이고 Node API의 `spec.nodeName`이나 machineID를 대체하지 않는다. Kubernetes API 명령은 실행 host → kubectl client → API server이며 logs는 API server → 대상 node kubelet → CRI/runtime → 선택 container/application stream으로 이어진다. node/runtime evidence는 실행 host → `node_exec` → remote node Bash → `sudo`/journal/CRI 경계로 이어진다. 필수 도구는 `kubectl`, `jq`, `grep`, `sed`, `date`이며 Pod·Event read 권한과 namespace 접근 권한이 필요하다. node/runtime 분기에는 별도로 `ssh`, remote `journalctl`, remote `sudo`, remote `crictl`, 실제 kubelet/runtime unit·CRI endpoint 권한을 확인한다. 도구·exact-name API·UID gate가 실패하면 다음 단계로 진행하지 않는다.

`journalctl`, `crictl`과 runtime socket 명령은 작업 PC의 network namespace에서 직접 실행하지 않는다. 같은 Bash에 등록한 `NODE_HOST`로 `node_exec`를 호출해 remote node에서 실행하며, `kubectl` API 조회 성공은 node journal·runtime 접근 성공을 보장하지 않는다.

**Bash와 필수 도구 확인 — 아래 한 줄 전체를 복사**

`TOOLS_READY=false; MISSING_TOOLS=''; TOOL=''; if [ -z "${BASH_VERSION:-}" ]; then printf '%s\n' '중단: Bash가 아니다. Bash 셸에서 다시 실행한다.' >&2; else for TOOL in kubectl jq grep sed date; do command -v "$TOOL" >/dev/null 2>&1 || MISSING_TOOLS="$MISSING_TOOLS $TOOL"; done; if [ -n "$MISSING_TOOLS" ]; then printf '중단: 없는 필수 도구=%s\n' "$MISSING_TOOLS" >&2; else TOOLS_READY=true; grep(){ command grep "$@"; local FILTER_RC=$?; if [ "$FILTER_RC" -gt 1 ]; then printf '중단: grep filter 실패 rc=%s\n' "$FILTER_RC" >&2; exit "$FILTER_RC"; fi; return "$FILTER_RC"; }; refresh_current_identity(){ local c="$1" identity_json identity_uid identity_id; if [ -z "${POD:-}" ] || [ -z "${NS:-}" ] || [ -z "${POD_UID:-}" ]; then return 1; fi; if ! identity_json="$(command kubectl get pod "$POD" -n "$NS" -o json)"; then return 1; fi; if ! identity_uid="$(jq -r '.metadata.uid // empty' <<<"$identity_json")"; then return 1; fi; if [ "$identity_uid" != "$POD_UID" ]; then return 1; fi; if ! identity_id="$(jq -r --arg c "$c" '([.status.containerStatuses[]?, .status.initContainerStatuses[]?] | map(select(.name==$c) | .containerID // empty) | if length==1 then .[0] else empty end)' <<<"$identity_json")"; then return 1; fi; if [ -z "$identity_id" ]; then return 1; fi; CONTAINER_ID="$identity_id"; return 0; }; kubectl(){ if [ "${1:-}" = logs ]; then local c='' previous='' arg=''; for arg in "$@"; do if [ "$previous" = -c ]; then c="$arg"; break; fi; previous="$arg"; done; if [ -z "$c" ] || ! refresh_current_identity "$c"; then printf '중단: logs 직전 current Pod UID/containerID 재조회 실패 pod=%s uid=%s container=%s\n' "${POD:--}" "${POD_UID:--}" "${c:--}" >&2; return 1; fi; fi; command kubectl "$@"; }; printf 'TOOLS_READY=true shell=Bash version=%s\n' "$BASH_VERSION"; fi; fi`

**최초 입력·이전 파생값과 연결 상태 초기화 — 같은 Bash에서 한 번 실행**

`unset INPUT_READY AUTO_READY PROMQL_READY POD_JSON POD_UID NODE NODE_HOST PHASE POD_START OWNER REPLICASET CONTAINER_RE NS_RE POD_RE QUERY CONTAINER CONTAINER_ID START_RFC3339 SERVICE RUNTIME_UNIT CRI_ENDPOINT DEPLOYMENT APPROVAL_ID ROLLBACK_REVISION TIME_READY JOURNAL_READY JOURNAL_START JOURNAL_END SELECTION_READY LOG_READY PREVIOUS_READY SERVICE_READY RUNTIME_READY DEPLOYMENT_READY NODE_IDENTITY_READY NODE_EXEC_READY NODE_API_JSON NODE_API_NAME NODE_API_MACHINE_ID NODE_REMOTE_HOST NODE_REMOTE_MACHINE_ID NODE_HOSTNAME_MATCH NODE_JOURNAL_READY IMPACT_READY CHANGE_APPROVAL_READY NEW_POD_UID_READY; NS='PASTE_NAMESPACE_HERE'; POD='PASTE_POD_HERE'; INPUT_READY=false; if [ "$TOOLS_READY" != true ]; then printf '%s\n' '중단: 도구 확인을 먼저 통과한다.' >&2; elif [ -z "$NS" ] || [ -z "$POD" ]; then printf '%s\n' '중단: NS와 POD를 입력한다.' >&2; elif kubectl get pod "$POD" -n "$NS" -o json >/dev/null 2>&1; then INPUT_READY=true; printf 'INPUT_READY=true namespace=%s pod=%s\n' "$NS" "$POD"; else printf '중단: Pod exact-name 조회 실패 namespace=%s pod=%s\n' "$NS" "$POD" >&2; fi`

`INPUT_READY=true`가 아니면 namespace·Pod·권한을 다시 확인한다. namespace를 모를 때만 승인된 범위에서 `kubectl get pods -A`를 사용하고 exact namespace가 확정되면 namespaced 조회로 돌아온다. 같은 Pod 이름으로 재생성된 객체는 새 UID와 새 조사다.

### API 자동 수집

**대상별 세로 출력과 자동 등록 — 아래 한 줄 전체를 복사**

`AUTO_READY=false; unset POD_UID NODE PHASE POD_START OWNER REPLICASET NS_RE POD_RE; if [ "$INPUT_READY" != true ]; then printf '%s\n' '중단: INPUT_READY가 아니다.' >&2; elif POD_JSON="$(kubectl get pod "$POD" -n "$NS" -o json)" && OWNER_COUNT_TMP="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)] | length' <<<"$POD_JSON")" && CONTAINER_COUNT_TMP="$(jq -r '[.spec.containers[]?] | length' <<<"$POD_JSON")" && POD_UID_TMP="$(jq -r '.metadata.uid // empty' <<<"$POD_JSON")" && NODE_TMP="$(jq -r '.spec.nodeName // "-"' <<<"$POD_JSON")" && PHASE_TMP="$(jq -r '.status.phase // "-"' <<<"$POD_JSON")" && POD_START_TMP="$(jq -r '.status.startTime // "-"' <<<"$POD_JSON")" && RS_TMP="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true and .kind=="ReplicaSet") | .name] | if length==1 then .[0] else "-" end' <<<"$POD_JSON")" && jq -r '"=== 대상 Pod ===\nPod 이름: \(.metadata.name)\nPod UID: \(.metadata.uid)\nNamespace: \(.metadata.namespace)\nNode: \(.spec.nodeName // "-")\nPhase: \(.status.phase // "-")\nPod 시작 시각: \(.status.startTime // "-")\n상위 owner: " + ([.metadata.ownerReferences[]? 성공 gate는 동일 Pod UID의 container별 current·last 상태, 종료 시각·reason·exitCode·restartCount·container ID, Init 상태, node·phase·Pod 시각·owner·ReplicaSet·container/port 관계가 세로 블록으로 보이고 `AUTO_READY=true`가 된 경우다. API 실패·복수 controller owner·빈 UID·container 부재·출력 실패면 부분 등록하지 않는다. 현재 `CrashLoopBackOff`는 backoff 상태만 보장하며 원인·application 정상·재시작 후 기능 정상은 보장하지 않는다.

| 구분 | 판단 기준 |

| 적용 | 현재 waiting 상태와 실패 container·Pod UID가 특정되고 일반 container 반복 종료 pipeline을 확인할 수 있는 범위다. `restartCount`는 보조 증거다. |
| 제외 | 현재 CrashLoopBackOff 없이 restartCount만 증가하면 [[17. Pod restartCount가 계속 증가하는 경우\|restartCount 런북]]으로 이동한다. 첫 미완료 Init은 [[05. Pod가 Init 단계에서 진행되지 않는 경우\|Init]], image pull은 [[07. Pod STATUS가 ImagePullBackOff·ErrImagePull인 경우\|image]], config는 [[09. Pod STATUS가 CreateContainerConfigError인 경우\|config]], sandbox는 [[24. 검색 문자열: `CrashLoopBackOff`, `Back-off restarting failed container`, `OOMKilled`, `Liveness probe failed`, `Startup probe failed`, `Killing`, `reason=Error`, `exitCode=137`, `panic`, `fatal`, `connection refused`, `OCI runtime`

로그에는 Secret 값·token·개인키·개인정보가 포함될 수 있다. 필요한 오류 유형·시각·비식별화 문자열만 기록하고 원문 전체를 저장하지 않는다.

## 최초 확인

**현재 상태와 UID 제한 Event — 각 줄을 순서대로 복사**

`if [ "$AUTO_READY" != true ]; then printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; else kubectl get pod "$POD" -n "$NS" -o wide && kubectl describe pod "$POD" -n "$NS"; fi`

`if [ "$AUTO_READY" != true ]; then printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; else kubectl get events -n "$NS" --field-selector "involvedObject.kind=Pod,involvedObject.name=$POD,involvedObject.uid=$POD_UID" --sort-by=.metadata.creationTimestamp -o custom-columns='CREATED:.metadata.creationTimestamp,FIRST:.firstTimestamp,LAST:.lastTimestamp,EVENT:.eventTime,SERIES-LAST:.series.lastObservedTime,TYPE:.type,REASON:.reason,COUNT:.count,MESSAGE:.message'; fi`

`get`에서 `STATUS`, `READY`, `RESTARTS`, `NODE`, `AGE`, 자동 수집과 `describe`에서 대상 container의 State·Last State·Reason·Exit Code·Restart Count·startedAt·finishedAt·Conditions·첫 Event message를 본다. Event `FIRST`, `LAST`, `EVENT`, `SERIES-LAST`, `COUNT` 중 실제 값과 lastState 종료 시각을 같은 UID에 대조한다. Event 빈 출력은 오류 없음이 아니라 UID·범위·권한·보존 기간을 확인해야 하는 결과다. Event 조회는 문서 전체에서 한 번만 실행한다.

`get`, `describe` 또는 UID 제한 Event 중 하나라도 실패하면 부분 출력으로 원인을 확정하지 않고 API/RBAC·UID·대상 이름을 확인한 뒤 최초 확인을 다시 실행한다.

## 현재·previous 로그 준비

`current`는 현재 instance, `--previous`는 같은 Pod UID·container의 직전 종료 instance 하나다. `START_RFC3339`는 collection 시각이 아니라 같은 UID의 Event 시각·lastState 종료 시각·restart 시작 시각 중 이른 값보다 로그 지연 여유만큼 앞선 운영자 선택값이다. current는 현재 state가 running 또는 terminated일 때, previous는 `restartCount >= 1`이고 lastState.terminated가 있을 때만 실행한다.

**로그 시작 시각 등록 — 로그 분기에 들어가기 전 한 번 실행**

`TIME_READY=false; START_RFC3339='PASTE_START_RFC3339_HERE'; START_EPOCH=''; if [[ "$START_RFC3339" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] && START_EPOCH="$(date -u -d "$START_RFC3339" +%s 2>/dev/null)" && [ -n "$START_EPOCH" ]; then TIME_READY=true; printf 'TIME_READY=true start=%s epoch=%s\n' "$START_RFC3339" "$START_EPOCH"; else printf '중단: UTC RFC3339 시각 형식 또는 date 변환 오류=%s\n' "$START_RFC3339" >&2; fi`

**실패 container와 current/previous gate — 아래 한 줄 전체를 복사**

`SELECTION_READY=false; LOG_READY=false; PREVIOUS_READY=false; CONTAINER='PASTE_CONTAINER_HERE'; CONTAINER_ID=''; CONTAINER_RE=''; CURRENT_OUTPUT=''; PREVIOUS_OUTPUT=''; CURRENT_RC=0; PREVIOUS_RC=0; if [ "$AUTO_READY" != true ] || [ "$TIME_READY" != true ]; then printf '%s\n' '중단: AUTO_READY 또는 TIME_READY가 아니다.' >&2; elif CURRENT_JSON="$(kubectl get pod "$POD" -n "$NS" -o json)" && UID_NOW="$(jq -r '.metadata.uid // empty' <<<"$CURRENT_JSON")" && CONTAINER_STATE="$(jq -r --arg c "$CONTAINER" '[.status.containerStatuses[]? | select(.name==$c)] | if length==1 then .[0] else {} end' <<<"$CURRENT_JSON")" && CONTAINER_ID_TMP="$(jq -r --arg c "$CONTAINER" '[.status.containerStatuses[]? | select(.name==$c) | .containerID // "-"] | if length==1 then .[0] else empty end' <<<"$CURRENT_JSON")" && jq -e --arg c "$CONTAINER" 'any(.status.containerStatuses[]?; .name==$c and .state.waiting.reason=="CrashLoopBackOff")' <<<"$CURRENT_JSON" >/dev/null && [ "$UID_NOW" = "$POD_UID" ] && [ -n "$CONTAINER_ID_TMP" ]; then CONTAINER_ID="$CONTAINER_ID_TMP"; CONTAINER_RE_TMP="$(printf '%s' "$CONTAINER" | sed 's/[][\\.^$*+?(){}|]/\\&/g')"; CONTAINER_RE="^${CONTAINER_RE_TMP}$"; if jq -e 'has("running") or has("terminated")' <<<"$CONTAINER_STATE" >/dev/null; then LOG_READY=true; fi; RESTART_COUNT="$(jq -r '.restartCount // 0' <<<"$CONTAINER_STATE")"; LAST_STATE="$(jq -c '.lastState // {}' <<<"$CONTAINER_STATE")"; if [ "$RESTART_COUNT" -ge 1 ] && jq -e 'has("terminated")' <<<"$LAST_STATE" >/dev/null; then PREVIOUS_READY=true; fi; SELECTION_READY=true; printf 'SELECTION_READY=true pod=%s uid=%s container=%s containerID=%s current=%s previous=%s restart=%s regex=%s\n' "$POD" "$POD_UID" "$CONTAINER" "$CONTAINER_ID" "$LOG_READY" "$PREVIOUS_READY" "$RESTART_COUNT" "$CONTAINER_RE"; else printf '중단: 선택 container의 CrashLoopBackOff·UID·container ID 확인 실패.\n' >&2; fi`

`SELECTION_READY=true`는 선택 container가 현재 같은 UID에서 CrashLoopBackOff임을 확인한 것이다. `LOG_READY=false`이면 process가 현재 시작되지 않았을 수 있으므로 current logs를 실행하지 않는다. container ID·UID가 비면 현재 객체를 다시 수집하고, 다른 container가 backoff인지 임의로 선택하지 않는다.

연결 경로는 실행 host → kubectl client/API server → 대상 node kubelet → CRI/runtime stream → 선택 container process/application이다. API server 또는 stream 준비 성공은 직전 instance 보존·process 지속·application 기능 정상의 증거가 아니다.

**current 로그 — current gate 통과 시 한 줄 전체를 복사**

`if [ "$SELECTION_READY" != true ] || [ "$LOG_READY" != true ]; then printf '%s\n' '중단: SELECTION_READY·LOG_READY가 아니다.' >&2; else CURRENT_OUTPUT="$(kubectl logs "$POD" -n "$NS" -c "$CONTAINER" --timestamps --since-time="$START_RFC3339" --tail=200)"; CURRENT_RC=$?; if [ "$CURRENT_RC" -ne 0 ]; then printf 'current stream 실패 계층=API/kubelet/runtime pod=%s uid=%s container=%s containerID=%s rc=%s\n' "$POD" "$POD_UID" "$CONTAINER" "$CONTAINER_ID" "$CURRENT_RC" >&2; else CURRENT_FILTER_RC=0; printf '%s\n' "$CURRENT_OUTPUT" | grep -E -i -C 3 'panic|fatal|error|exception|timeout|refused|denied|permission|oom|killed|signal|probe|health|config|not found|no such file|exec format|certificate|tls|no such host|startup|migration|dependency|shutdown|completed'; CURRENT_FILTER_RC=$?; if [ "$CURRENT_FILTER_RC" -eq 0 ]; then :; elif [ "$CURRENT_FILTER_RC" -eq 1 ]; then printf '%s\n' 'current 필터 빈 결과: 오류 부재가 아니다.' >&2; else printf 'current log filter 실패 rc=%s\n' "$CURRENT_FILTER_RC" >&2; fi; fi; fi`

**previous 로그 — previous gate 통과 시 한 줄 전체를 복사**

`if [ "$SELECTION_READY" != true ] || [ "$PREVIOUS_READY" != true ]; then printf '%s\n' '중단: SELECTION_READY 또는 previous gate가 아니다.' >&2; else PREVIOUS_OUTPUT="$(kubectl logs "$POD" -n "$NS" -c "$CONTAINER" --previous --timestamps --since-time="$START_RFC3339" --tail=200)"; PREVIOUS_RC=$?; if [ "$PREVIOUS_RC" -ne 0 ]; then printf 'previous stream 실패 계층=API/kubelet/runtime 또는 보존·rotation pod=%s uid=%s container=%s rc=%s\n' "$POD" "$POD_UID" "$CONTAINER" "$PREVIOUS_RC" >&2; else PREVIOUS_FILTER_RC=0; printf '%s\n' "$PREVIOUS_OUTPUT" | grep -E -i -C 3 'panic|fatal|error|exception|timeout|refused|denied|permission|oom|killed|signal|probe|health|config|not found|no such file|exec format|certificate|tls|no such host|startup|migration|dependency|shutdown|completed'; PREVIOUS_FILTER_RC=$?; if [ "$PREVIOUS_FILTER_RC" -eq 0 ]; then :; elif [ "$PREVIOUS_FILTER_RC" -eq 1 ]; then printf '%s\n' 'previous 필터 빈 결과: 오류 부재나 로그 존재를 뜻하지 않는다.' >&2; else printf 'previous log filter 실패 rc=%s\n' "$PREVIOUS_FILTER_RC" >&2; fi; fi; fi`

`container is waiting`, `container not found`, Forbidden, API 연결 오류는 [[27. Pod 로그를 가져올 수 없는 경우\|로그 런북]], `previous terminated container ... not found`·보존·rotation·권한 오류는 [[28. Pod의 이전 컨테이너 로그를 가져올 수 없는 경우\|이전 로그 런북]]으로 이관한다. stream 준비 성공은 container process와 application 기능 정상의 증거가 아니다. Secret·token·개인정보가 보이면 출력을 중단한다.

previous 결과는 같은 Pod UID·`CONTAINER`·`START_RFC3339` 범위로 기록한다. API가 직전 instance의 container ID를 제공하지 않으면 현재 `CONTAINER_ID`를 previous ID로 오해하지 않고 `미제공`으로 남긴다.

필터가 비면 같은 instance·container·시간 범위의 마지막 50행만 재확인한다. current/previous 결과는 서로 다른 instance로 기록한다.

**bounded tail — 해당 gate를 통과한 한 줄만 복사**

`if [ "$SELECTION_READY" = true ] && [ "$LOG_READY" = true ]; then kubectl logs "$POD" -n "$NS" -c "$CONTAINER" --timestamps --since-time="$START_RFC3339" --tail=50; else printf '%s\n' '중단: current tail gate가 아니다.' >&2; fi`

`if [ "$SELECTION_READY" = true ] && [ "$PREVIOUS_READY" = true ]; then kubectl logs "$POD" -n "$NS" -c "$CONTAINER" --previous --timestamps --since-time="$START_RFC3339" --tail=50; else printf '%s\n' '중단: previous tail gate가 아니다.' >&2; fi`

## 관측 결과별 장애 파이프라인

### 1. `OOMKilled` 또는 종료 코드 `137`

진입 증거는 선택 container의 last/current reason 또는 exit code와 같은 시각의 Event가 OOM을 가리키는 경우다. 137만으로 OOM을 확정하지 않는다. 연결 경로는 실행 host → API server → Pod node/kubelet → cgroup·kernel → container process다.

**resource·node 범위 확인 — 각 줄을 순서대로 복사**

`if [ "$SELECTION_READY" != true ]; then printf '%s\n' '중단: SELECTION_READY가 아니다.' >&2; else kubectl get pod "$POD" -n "$NS" -o jsonpath="{range .spec.containers[?(@.name=='$CONTAINER')]}image={.image}{" resources="}{.resources}{" securityContext="}{.securityContext}{end}" && kubectl describe node "$NODE" && kubectl get pods -A -o wide --field-selector "spec.nodeName=$NODE"; fi`

fi; else printf '중단: Node API 조회 또는 SSH remote identity preflight 실패 node=%s sshHost=%s\n' "$NODE" "$NODE_HOST" >&2; fi`

### 2. probe Event 또는 `Killing`

진입 증거는 UID 제한 Event의 probe 실패와 container 종료 시각이 연결된 경우다. readiness 실패만으로 재시작을 확정하지 않는다. 연결 경로는 실행 host → API server → kubelet probe worker → runtime → application listener다.

**probe 설정과 process 실행 구조 확인 — 아래 한 줄 전체를 복사**

`PROBE_SPEC_JSON=''; PROBE_SPEC_RC=0; if [ "$SELECTION_READY" != true ]; then printf '%s\n' '중단: SELECTION_READY가 아니다.' >&2; else PROBE_SPEC_JSON="$(kubectl get pod "$POD" -n "$NS" -o json)"; PROBE_SPEC_RC=$?; if [ "$PROBE_SPEC_RC" -ne 0 ]; then printf 'probe spec API 조회 실패 rc=%s pod=%s uid=%s\n' "$PROBE_SPEC_RC" "$POD" "$POD_UID" >&2; elif jq -e --arg c "$CONTAINER" --arg uid "$POD_UID" '.metadata.uid==$uid and ([.spec.containers[]? | select(.name==$c)] | length)==1' <<<"$PROBE_SPEC_JSON" >/dev/null; then jq -r --arg c "$CONTAINER" 'def timing($p): {initialDelaySeconds:($p.initialDelaySeconds // 0),timeoutSeconds:($p.timeoutSeconds // 1),periodSeconds:($p.periodSeconds // 10),failureThreshold:($p.failureThreshold // 3),successThreshold:($p.successThreshold // 1)}; def probe($p): if $p == null then {type:"none"} elif $p.httpGet != null then {type:"httpGet",target:{host:($p.httpGet.host // "-"),path:($p.httpGet.path // "-"),port:($p.httpGet.port // "-"),scheme:($p.httpGet.scheme // "-")},timing:timing($p)} elif $p.tcpSocket != null then {type:"tcpSocket",target:{host:($p.tcpSocket.host // "-"),port:($p.tcpSocket.port // "-")},timing:timing($p)} elif $p.exec != null then {type:"exec",target:{commandDeclared:(((($p.exec.command // []) | length) > 0)),argvCount:(($p.exec.command // []) | length)},timing:timing($p)} elif $p.grpc != null then {type:"grpc",target:{port:($p.grpc.port // "-"),service:($p.grpc.service // "-")},timing:timing($p)} else {type:"unknown"} end; .spec.containers[] | select(.name==$c) | {container:.name,liveness:probe(.livenessProbe),startup:probe(.startupProbe),readiness:probe(.readinessProbe)}' <<<"$PROBE_SPEC_JSON"; else printf '중단: current Pod UID 또는 container spec 대조 실패 pod=%s uid=%s container=%s\n' "$POD" "$POD_UID" "$CONTAINER" >&2; fi; fi`

`kubectl` API 성공은 probe 선언을 읽었다는 범위만 보장하며 실제 listener·protocol·인증을 보장하지 않는다. 앱 listen 시각보다 kubelet probe 실패가 빠르면 probe·기동 예산, probe 응답 후 종료하면 application exit, `failed to start container`면 runtime 경로다. 직접 liveness 근거는 [[20. Pod liveness probe가 실패하는 경우\|liveness]], startup 근거는 [[21. Pod startup probe가 실패하는 경우\|startup]]으로 이관한다. HTTP probe라면 transport·HTTP status·application response를 분리하고 TLS 검증을 끄지 않는다.

**probe 시간 범위의 kubelet journal — 앞의 `JOURNAL_READY=true` gate와 node 권한을 통과한 경우 한 줄 전체를 복사**

### 3. `reason=Error`와 non-zero exit 또는 application fatal

진입 증거는 lastState/current의 non-zero exit 또는 current/previous log의 `panic`·`fatal`이 같은 UID·container·시간으로 연결된 경우다. 연결 경로는 실행 host → API server → kubelet → CRI/OCI runtime → Linux process/filesystem → application dependency다.

**image entrypoint·실행 구조·securityContext 요약 확인 — 아래 한 줄 전체를 복사**

`ENTRYPOINT_SPEC_JSON=''; ENTRYPOINT_SPEC_RC=0; if [ "$SELECTION_READY" != true ]; then printf '%s\n' '중단: SELECTION_READY가 아니다.' >&2; else ENTRYPOINT_SPEC_JSON="$(kubectl get pod "$POD" -n "$NS" -o json)"; ENTRYPOINT_SPEC_RC=$?; if [ "$ENTRYPOINT_SPEC_RC" -ne 0 ]; then printf 'entrypoint spec API 조회 실패 rc=%s pod=%s uid=%s\n' "$ENTRYPOINT_SPEC_RC" "$POD" "$POD_UID" >&2; elif jq -e --arg c "$CONTAINER" --arg uid "$POD_UID" '.metadata.uid==$uid and ([.spec.containers[]? | select(.name==$c)] | length)==1' <<<"$ENTRYPOINT_SPEC_JSON" >/dev/null; then jq -r --arg c "$CONTAINER" '.spec.containers[] | select(.name==$c) | "container=\(.name) image=\(.image // "-") command_declared=\(.command != null) command_argv_count=\(((.command // []) | length)) args_declared=\(.args != null) args_count=\(((.args // []) | length)) workingDir_declared=\(.workingDir != null) securityContext_declared=\(.securityContext != null)"' <<<"$ENTRYPOINT_SPEC_JSON"; else printf '중단: current Pod UID 또는 container spec 대조 실패 pod=%s uid=%s container=%s\n' "$POD" "$POD_UID" "$CONTAINER" >&2; fi; fi`

### 4. 설정·파일·권한·외부 연결 오류

진입 증거는 current/previous log의 config key·file·permission·`connection refused`·`no such host`·TLS 오류와 Pod spec 참조가 연결된 경우다. 자동 출력에서 ConfigMap·Secret 값은 읽지 않고 이름·key·mount 관계만 확인한다. 연결 경로는 실행 host → API server → Pod DNS/Service/EndpointSlice/NetworkPolicy → 외부 DB/API·queue·certificate/firewall → application이다.

**실제 Service 선택 — 증거가 확인된 경우 한 번 실행**

HTTP/API 확인이 필요하면 실행 host·주소·port·protocol을 실제 spec과 승인된 인증으로 확인하고 transport→HTTP status→application success/data를 나누며 TLS 검증을 `-k`로 우회하지 않는다.

### 5. kubelet 또는 runtime 오류만 보이는 경우

## 복구 전 gate와 상태 변경

`delete`, `rollout`, `patch`, `scale`은 다음이 모두 확인되기 전에는 실행하지 않는다. lastState reason·exitCode·restartCount, current/previous 로그와 UID 제한 Event의 직접 근거, probe·application·config·OOM·runtime 중 첫 실패 layer와 owner, namespace·Pod UID·node·Ready/replica·Service endpoint와 외부 호출·데이터 중복 위험, 승인된 원본 반영·rollback revision·실행 권한·중단 조건을 기록한다. Pod를 backoff 제거 목적으로 무조건 삭제하지 않는다.

Deployment rollout을 고려할 때 Pod → ReplicaSet → Deployment의 `controller=true`, revision·observed generation·desired/ready/available을 먼저 확인한다. StatefulSet·DaemonSet·Job/CronJob·quorum workload에는 일반 Deployment 명령을 적용하지 않는다.

`rollout restart`가 non-zero이거나 대상·권한 오류를 내면 `rollout status`와 재시도를 실행하지 않는다. status 성공도 실제 기능과 재발 부재를 보장하지 않는다.

## 정상화 검증

진단 pipeline을 역순으로 확인한다. 새 container가 원하는 image로 시작 → process가 지속 → probe 성공 → kubelet/runtime Warning 중단 → restart 증가 정지 → Service/EndpointSlice와 실제 DB/API 요청 또는 핵심 기능 정상 순서다. OOM이면 node pressure·kernel 기록 안정, dependency면 DNS·NetworkPolicy·endpoint·외부 응답까지 확인한다.

## Prometheus 빠른 관측

PromQL은 같은 Bash에 등록된 `NS_RE`, `POD_RE`, `CONTAINER_RE`로 완성한다. 사용자는 생성된 한 줄만 Prometheus 또는 Grafana에 붙여 넣는다. metric 부재와 API·권한·조회 실패를 구분하며 빈 결과를 정상·0·backoff 해소로 해석하지 않는다.

**현재 CrashLoopBackOff PromQL 생성 — 아래 한 줄 전체를 복사**

`PROMQL_UID_NOW=''; PROMQL_UID_RC=0; if [ "$PROMQL_READY" != true ] || [ "$SELECTION_READY" != true ]; then printf '%s\n' '중단: PROMQL_READY·SELECTION_READY가 아니다.' >&2; else PROMQL_UID_NOW="$(kubectl get pod "$POD" -n "$NS" -o jsonpath='{.metadata.uid}')"; PROMQL_UID_RC=$?; if [ "$PROMQL_UID_RC" -ne 0 ]; then PROMQL_READY=false; AUTO_READY=false; SELECTION_READY=false; printf '중단: PromQL 직전 exact Pod UID 재조회 실패 rc=%s pod=%s\n' "$PROMQL_UID_RC" "$POD" >&2; elif [ "$PROMQL_UID_NOW" != "$POD_UID" ]; then PROMQL_READY=false; AUTO_READY=false; SELECTION_READY=false; printf '중단: PromQL 직전 Pod UID mismatch 최초=%s 현재=%s. 재수집한다.\n' "$POD_UID" "$PROMQL_UID_NOW" >&2; else QUERY="kube_pod_container_status_waiting_reason{namespace=~\"$NS_RE\",pod=~\"$POD_RE\",uid=\"$POD_UID\",container=~\"$CONTAINER_RE\",reason=\"CrashLoopBackOff\"}==1"; if [ "${#QUERY}" -gt 500 ]; then printf '%s\n' '중단: 생성 쿼리가 비정상적으로 길다.' >&2; else printf 'PromQL=%s\n' "$QUERY"; fi; fi; fi`

**최근 restart 증가 PromQL 생성 — 아래 한 줄 전체를 복사**

`PROMQL_UID_NOW=''; PROMQL_UID_RC=0; if [ "$PROMQL_READY" != true ] || [ "$SELECTION_READY" != true ]; then printf '%s\n' '중단: PROMQL_READY·SELECTION_READY가 아니다.' >&2; else PROMQL_UID_NOW="$(kubectl get pod "$POD" -n "$NS" -o jsonpath='{.metadata.uid}')"; PROMQL_UID_RC=$?; if [ "$PROMQL_UID_RC" -ne 0 ]; then PROMQL_READY=false; AUTO_READY=false; SELECTION_READY=false; printf '중단: PromQL 직전 exact Pod UID 재조회 실패 rc=%s pod=%s\n' "$PROMQL_UID_RC" "$POD" >&2; elif [ "$PROMQL_UID_NOW" != "$POD_UID" ]; then PROMQL_READY=false; AUTO_READY=false; SELECTION_READY=false; printf '중단: PromQL 직전 Pod UID mismatch 최초=%s 현재=%s. 재수집한다.\n' "$POD_UID" "$PROMQL_UID_NOW" >&2; else QUERY="kube_pod_container_status_last_terminated_reason{namespace=~\"$NS_RE\",pod=~\"$POD_RE\",uid=\"$POD_UID\",container=~\"$CONTAINER_RE\"}==1"; if [ "${#QUERY}" -gt 500 ]; then printf '%s\n' '중단: 생성 쿼리가 비정상적으로 길다.' >&2; else printf 'PromQL=%s\n' "$QUERY"; fi; fi; fi`

last terminated reason metric은 kube-state-metrics 버전에 따라 미수집·실험적일 수 있다. 실제 `uid`·`container` label과 metric 존재를 확인하고 `lastState`, exit code, UTC 시각과 previous log를 원인 판정 기준으로 삼는다.

## 증거 보존

UTC 확인 시각, context 식별자, namespace·Pod UID·node, STATUS·phase, container current/last state·reason·exitCode·restartCount·container ID, image·command·probe·resource의 민감값을 제외한 설정, 첫 Event 시각·reason·비식별화 message, 시간 범위가 있는 로그 요약, kubelet/runtime 오류, owner·승인·변경·정상화 결과를 보존한다. Secret data, token, 인증서 개인키, 개인정보와 전체 로그 원문은 저장하지 않는다.
