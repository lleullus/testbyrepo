# Pod STATUS가 Evicted인 경우

## 입력값과 빠른 수집

### 실행 계약

최초 입력·Kubernetes API는 승인된 작업 PC 또는 bastion의 **같은 Bash**에서 실행한다. `kubectl`, `jq`, `sed`, `grep`, `date`, `ssh`가 필수이며 확인 실패 뒤에는 진행하지 않는다. node의 memory·filesystem·PID·journal·runtime 명령은 작업 PC가 아니라 승인된 `NODE_HOST`로 SSH remote command를 실행한다. 작업 PC Bash 변수가 node shell에 자동 공유된다고 가정하지 않는다.

연결 hop은 `실행 host → kubectl client/API server → 대상 node/kubelet → Linux memory·filesystem·PID 또는 runtime/CRI → workload·Service/application`이다. API server, SSH host, runtime socket, filesystem mount와 Service endpoint는 다른 주소·권한·protocol이다. 한 hop 성공은 다음 hop이나 실제 기능 정상을 보장하지 않는다.

Evicted는 같은 이름의 새 Pod가 아니라 최초 `POD_UID`의 과거 사건이다. 모든 사건 Pod 재조회는 최초 UID와 대조하고 mismatch이면 기존 사건 gate를 무효화한다. 변경 후 새 Pod는 별도 new-identity gate에서 기존 UID와 다르고 top-level owner chain이 맞는 경우에만 등록한다.

| 구분 | 등록 값 | 출처·선택 기준 |
|---|---|---|
| 최초 입력 | `NS`, `POD` | 운영자가 승인된 namespace와 Pod 이름을 한 번 입력한다. |
| API 확인 자동값 | `POD_UID`, `NODE`, `PHASE`, `REASON`, `POD_CREATED`, `QOS`, `POD_RE`, `PVC_LIST`, `WORKLOAD_KIND`, `WORKLOAD_NAME`, `WORKLOAD_UID`, `WORKLOAD_SELECTOR` | Pod API와 top-level owner chain에서 등록한다. |
| 계산 후보 | `END_JOURNAL`, `POST_CHANGE_READY` | 현재 UTC 시각·변경 후 후보 조회로 만든다. |
| 운영자 선택값 | `NODE_HOST`, `KUBELET_UNIT`, `START_JOURNAL`, `NODEFS_PATH`, `IMAGEFS_PATH`, `RUNTIME_UNIT`, `RUNTIME_DATA_PATH`, `CONTAINER`, `SERVICE`, `NEW_REQUEST`, `NEW_LIMIT`, `APPROVAL_ID`, `CHANGE_WINDOW_START`, `CHANGE_WINDOW_END`, `NEW_POD`, `FUNCTION_CHECK_ID`, `FUNCTION_CHECK_RESULT`, `FUNCTION_CHECK_START`, `FUNCTION_CHECK_END` | node inventory·실제 mount·runtime·Service 영향·승인 기록을 확인한 뒤 선택한다. 기능 확인 값은 서비스 owner가 제공한 bounded check 결과만 사용한다. |

### API 자동 수집과 identity gate

**Pod·Pod/PVC 관계 출력 — 아래 한 줄 전체를 복사**

`if [ "$INPUT_READY" != true ]; then printf '%s\n' '중단: INPUT_READY가 아니다.' >&2; elif POD_JSON="$(kubectl get pod "$POD" -n "$NS" -o json)" && jq -e '.metadata.uid and .metadata.name' >/dev/null <<<"$POD_JSON"; then jq -r '"=== Evicted 대상 Pod ===\n이름: \(.metadata.name)\nUID: \(.metadata.uid)\nNode: \(.spec.nodeName // "-")\nPhase: \(.status.phase // "-")\nReason: \(.status.reason // "-")\n축출 message: \(.status.message // "-")\nQoS: \(.status.qosClass // "-")\n생성 시각: \(.metadata.creationTimestamp // "-")\nOwner: " + (([.metadata.ownerReferences[]? | select(.controller==true) | "\(.kind)/\(.name) UID=\(.uid)"] | join(", ")) // "-") + "\nPod/PVC 관계:\n" + (([.spec.volumes[]? | select(.persistentVolumeClaim != null) | "  PVC: \(.persistentVolumeClaim.claimName)"] | if length == 0 then "  PVC 없음" else join("\n") end)) + "\nContainer 자원:\n" + (([.spec.containers[]? | "  \(.name): requests=\(.resources.requests.memory // "-")/\(.resources.requests["ephemeral-storage"] // "-") limits=\(.resources.limits.memory // "-")/\(.resources.limits["ephemeral-storage"] // "-")"] | if length == 0 then "  container 없음" else join("\n") end))' <<<"$POD_JSON"; else printf '%s\n' '중단: Pod API 또는 JSON 확인 실패. 빈 출력은 대상 없음·권한·API 오류를 구분한다.' >&2; fi`

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | Pod가 `status.phase=Failed`, `status.reason=Evicted`이고 축출 message가 있는 경우 |
| 적용 | 최초 Pod UID·축출 node·현재 workload 영향 범위를 확인할 수 있는 경우 |
| 제외 | `Failed`이지만 `Evicted`가 아니면 [[01. Pod STATUS가 Error인 경우#관측별 진단 경로|Error 런북]], `Preempted`, 일반 Job 실패, node NotReady 자체는 해당 문서로 이관한다. `reason=OOMKilled` 세부는 [[11. Pod STATUS가 OOMKilled인 경우#관측별 진단 경로|OOMKilled 런북]]으로 보조 호출한다. |

검색 문자열: `Evicted`, `phase=Failed`, `reason=Evicted`, `status.message`, `MemoryPressure`, `DiskPressure`, `PIDPressure`, `ephemeral-storage`, `eviction threshold`, `nodefs`, `imagefs`, `inode`, `PID`, `kubelet`, `container runtime`, `image garbage collection`.

## 최초 확인

`MEMORY_EVIDENCE_READY=true`는 최초 `POD_UID` Event가 memory eviction임을 보이고, 같은 node의 `MemoryPressure=True` 또는 memory node Event가 확인된 경우에만 열린다. `DiskPressure`, `PIDPressure`, `nodefs`, `imagefs`, `ephemeral-storage`, inode, PID가 직접 확인되면 `MEMORY_RESOURCE_FORBIDDEN=true`를 유지하고 이후 memory 변경을 다시 열지 않는다.

### 1. Memory pressure

**kubelet memory journal, producer·filter rc 분리 — 아래 한 줄 전체를 복사**

현재 memory가 정상이어도 과거 peak 부재를 의미하지 않는다. `free`와 `/proc/meminfo`는 대상 container limit 증거가 아니다.

### 2. Disk pressure, filesystem과 inode

**nodefs/imagefs 선택과 mount gate — 아래 한 줄 전체를 복사**

`NODEFS_PATH='PASTE_NODEFS_PATH_HERE'; IMAGEFS_PATH='PASTE_IMAGEFS_PATH_HERE'; DISK_READY=false; if [ "$NODE_HOST_READY" != true ] || [ "$NODE_TOOLS_READY" != true ]; then printf '%s\n' '중단: node identity·도구 gate가 아니다.' >&2; elif [ -n "$NODEFS_PATH" ] && node_exec "findmnt -T $(printf '%q' "$NODEFS_PATH")" >/dev/null 2>&1; then DISK_READY=true; export NODEFS_PATH IMAGEFS_PATH; printf 'DISK_READY=true nodefs=%s imagefs=%s\n' "$NODEFS_PATH" "${IMAGEFS_PATH:--}"; else printf '%s\n' '중단: 실제 nodefs mount가 확인되지 않았다.' >&2; fi`

**filesystem·inode와 kubelet signal — 확인된 node에서 아래 한 줄 전체를 복사**

`if [ "$DISK_READY" != true ] || [ "$JOURNAL_READY" != true ]; then printf '%s\n' '중단: DISK_READY 또는 JOURNAL_READY가 아니다.' >&2; else REMOTE_CMD="df -hT $(printf '%q' "$NODEFS_PATH"); df -ih $(printf '%q' "$NODEFS_PATH"); if [ -n "$IMAGEFS_PATH" ]; then df -hT $(printf '%q' "$IMAGEFS_PATH"); df -ih $(printf '%q' "$IMAGEFS_PATH"); fi"; FS_RC=0; FS_OUTPUT="$(node_exec "$REMOTE_CMD")" || FS_RC=$?; if [ "$FS_RC" -ne 0 ]; then printf 'filesystem producer 실패 rc=%s\n' "$FS_RC" >&2; else printf '%s\n' "$FS_OUTPUT"; fi; JOURNAL_RC=0; JOURNAL_OUTPUT="$(node_exec "sudo journalctl -u $(printf '%q' "$KUBELET_UNIT") --since $(printf '%q' "$START_JOURNAL") --until $(printf '%q' "$END_JOURNAL") --no-pager")" || JOURNAL_RC=$?; if [ "$JOURNAL_RC" -ne 0 ]; then printf 'kubelet journal producer 실패 rc=%s\n' "$JOURNAL_RC" >&2; else FILTER_RC=0; FILTER_OUTPUT="$(printf '%s\n' "$JOURNAL_OUTPUT" | grep -E -i -C 3 "$POD_UID|$POD|evict|disk|nodefs|imagefs|inodesFree|ephemeral-storage|threshold|no space")" || FILTER_RC=$?; if [ "$FILTER_RC" -eq 0 ]; then printf '%s\n' "$FILTER_OUTPUT"; else printf 'filesystem filter 결과 없음 rc=%s: pressure 부재가 아니다.\n' "$FILTER_RC" >&2; fi; fi; fi`

`nodefs.available`, `imagefs.available`, `nodefs.inodesFree`, `no space left on device`가 같은 시각이면 kubelet signal과 실제 mount를 연결한다. path가 없으면 추측하지 않고 storage owner에게 이관한다.

### 3. PID pressure

**PID 보조 관측 — 확인된 node에서 아래 한 줄 전체를 복사**

### 6. 증거 불충분

Pod message, node condition, UID 제한 Event, kubelet/runtime journal, Linux evidence가 만료·부재·상충하면 `Evicted`만 확정하고 `memory/disk/PID`는 미확정으로 기록한다. 상태 변경을 보류하고 보존된 metrics·kubelet 로그·filesystem/inode/PID 기록을 담당자에게 요청한다.

## 복구 전 안전 gate와 승인된 상태 변경

변경 전에는 최초 Pod UID, node와 verified NODE_HOST, 직접 pressure 근거, top-level owner UID/selector, PDB/quorum, 대체 capacity, 승인자·rollback을 기록한다. `delete`, `cordon`, `drain`, kubelet/runtime restart, 수동 image/log 삭제는 이 문서에서 실행하지 않는다.

### Workload memory resource 조정

Trigger는 OOMKilled 또는 memory 근거와 resource 조정 필요성이 직접 연결된 경우다. `ephemeral-storage`, nodefs, imagefs, inode, PID 근거만 있으면 memory 변경을 하지 않는다. 대상은 top-level Deployment·StatefulSet·DaemonSet template이며 ReplicaSet에는 적용하지 않는다.

`RESOURCE_CHANGE_READY`를 열기 전에 `MEMORY_EVIDENCE_READY=true`이고 `MEMORY_RESOURCE_FORBIDDEN!=true`인지 다시 확인한다.

## Prometheus 빠른 관측

node blast-radius 쿼리와 현재 사건 Pod identity 쿼리는 분리한다. 모든 문자열은 등록 변수로 생성하며 출력 한 줄만 사용한다.

**현재 사건 Pod UID 확인 PromQL 생성 — 아래 한 줄 전체를 복사**

`if [ "$AUTO_READY" != true ]; then printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; else QUERY="$(printf 'kube_pod_info{namespace="%s",pod="%s",uid="%s"}' "$NS" "$POD" "$POD_UID")"; printf '%s\n' "$QUERY" | head -c 1000; printf '\n'; unset QUERY; fi`

**현재 사건 Evicted reason PromQL 생성 — 아래 한 줄 전체를 복사**

`if [ "$AUTO_READY" != true ]; then printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; else QUERY="$(printf 'kube_pod_status_reason{namespace="%s",pod="%s",uid="%s",reason="Evicted"}==1' "$NS" "$POD" "$POD_UID")"; printf '%s\n' "$QUERY" | head -c 1000; printf '\n'; unset QUERY; fi`

**node blast-radius PromQL 생성 — 아래 한 줄 전체를 복사**

`if [ "$AUTO_READY" != true ] || [ -z "$NODE" ]; then printf '%s\n' '중단: AUTO_READY 또는 node가 아니다.' >&2; else QUERY="$(printf 'count by(node)((kube_pod_status_reason{reason="Evicted"}==1)*on(namespace,pod,uid)group_left(node)(kube_pod_info{node="%s"}))' "$NODE")"; printf '%s\n' "$QUERY" | head -c 1000; printf '\n'; unset QUERY; fi`

현재 사건 query는 Pod UID identity 확인용이며 blast-radius query는 같은 node의 범위 확인용이다. metric 부재·label 불일치·조회 실패와 pressure 부재를 구분한다.

## 증거 보존

최초·새 Pod UID, node와 verified NODE_HOST remote hostname/machineID, UTC 시각, top owner kind/name/UID/selector, Pod/PVC 관계, node condition, UID 제한 Event, journal/runtime producer·filter rc, filesystem/inode/memory/PID 값, 승인·변경·정상화 결과를 보존한다. Secret·token·개인키·개인정보와 전체 로그는 저장하지 않는다.
