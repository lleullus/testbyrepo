# Pod STATUS가 CreateContainerError·RunContainerError인 경우

## 입력값과 빠른 수집

### 실행 계약

모든 최초 입력·Kubernetes API 명령은 승인된 작업 PC 또는 bastion의 **같은 Bash**에서 실행한다. `kubectl`, `jq`, `sed`, `grep`, `date`, `ssh` 확인이 실패하면 다음 단계로 가지 않는다. node 명령은 작업 PC의 Bash 변수나 shell 상태가 자동 공유된다고 가정하지 않으며, 승인된 `NODE_HOST`를 등록하고 SSH로만 전달한다.

연결 hop은 `실행 host → kubectl client/API server → 대상 node의 kubelet → 확인된 CRI endpoint/socket → OCI create/start → container/application`이다. API server transport, SSH host, CRI socket과 container application은 서로 다른 주소·protocol·권한 경계다. 한 hop 성공은 다음 hop이나 application 정상을 보장하지 않는다.

| 구분 | 등록 값 | 출처·선택 기준 |
|---|---|---|
| 최초 입력 | `NS`, `POD` | 운영자가 승인된 namespace와 Pod 이름을 한 번 입력한다. |
| API 확인 자동값 | `POD_UID`, `NODE`, `PHASE`, `POD_CREATED`, `POD_RE`, `CONTAINER_ID_RAW`, `CONTAINER_REASON`, `WORKLOAD_KIND`, `WORKLOAD_NAME`, `WORKLOAD_UID`, `WORKLOAD_SELECTOR` | 현재 Pod API와 UID owner chain에서 확정한다. ReplicaSet은 최상위 Deployment를 찾는 중간 객체일 뿐 변경 권한 owner가 아니다. |
| 계산 후보 | `END_JOURNAL`, `CRI_ID`, `ROLLBACK_START` | 현재 UTC 시각·확인된 runtime scheme로 만들며 gate 전에는 사용하지 않는다. |
| 운영자 선택값 | `CONTAINER`, `NODE_HOST`, `KUBELET_UNIT`, `START_JOURNAL`, `RUNTIME_UNIT`, `CRI_ENDPOINT`, `CRI_SOCKET`, `MOUNT_PATH`, `START_AUDIT`, `END_AUDIT`, `APPROVAL_ID`, `CHANGE_WINDOW_START`, `CHANGE_WINDOW_END`, `ROLLBACK_REVISION`, `NEW_POD`, `FUNCTION_CHECK_ID`, `FUNCTION_CHECK_RESULT`, `FUNCTION_CHECK_START`, `FUNCTION_CHECK_END` | 출력·승인 inventory·실제 node 구현을 확인한 뒤 해당 분기 직전에 선택한다. 복수 후보를 임의 선택하지 않으며, 기능 확인 값은 서비스 owner가 제공한 bounded check 결과만 사용한다. |

**Bash·필수 도구 확인 — 아래 한 줄 전체를 복사**

`TOOLS_READY=false; MISSING_TOOLS=''; if [ -z "${BASH_VERSION:-}" ]; then printf '%s\n' '중단: 같은 Bash에서 실행한다.' >&2; else for TOOL in kubectl jq sed grep date ssh; do command -v "$TOOL" >/dev/null 2>&1 || MISSING_TOOLS="$MISSING_TOOLS $TOOL"; done; if [ -z "$MISSING_TOOLS" ]; then TOOLS_READY=true; printf 'TOOLS_READY=true shell=%s\n' "$BASH_VERSION"; else printf '중단: 없는 도구=%s\n' "$MISSING_TOOLS" >&2; fi; fi`

### API 자동 수집과 identity gate

**대상별 기본 정보 출력 — 아래 한 줄 전체를 복사**

`if [ "$INPUT_READY" != true ]; then printf '%s\n' '중단: INPUT_READY가 아니다.' >&2; elif POD_JSON="$(kubectl get pod "$POD" -n "$NS" -o json)" && jq -e '.metadata.uid and .metadata.name' >/dev/null <<<"$POD_JSON"; then jq -r '"=== 대상 Pod ===\n이름: \(.metadata.name)\nUID: \(.metadata.uid)\nNode: \(.spec.nodeName // "-")\nPhase: \(.status.phase // "-")\n생성 시각: \(.metadata.creationTimestamp // "-")\nOwner: " + (([.metadata.ownerReferences[]? | select(.controller==true) | "\(.kind)/\(.name) UID=\(.uid)"] | join(", ")) // "-") + "\n" + ([.spec.containers[]? as $c | "Container: \($c.name)\n  Port 후보: " + (([$c.ports[]? | "\(.name // "unnamed"): \(.containerPort)"] | if length == 0 then "-" else join(", ") end)) + "\n  상태: " + (([.status.containerStatuses[]? | select(.name==$c.name) | if .state.waiting then "waiting/\(.state.waiting.reason // "-")" elif .state.terminated then "terminated/\(.state.terminated.reason // "-")" elif .state.running then "running" else "unknown" end] | .[0]) // "unknown"))] | join("\n"))' <<<"$POD_JSON"; else printf '%s\n' '중단: Pod API 또는 JSON 확인 실패. 빈 출력은 대상 없음·권한·API 오류를 구분한다.' >&2; fi`

raw command·args, Secret·token·개인정보는 출력하지 않는다. image와 `command`·`args`의 존재 여부 및 개수만 비민감 요약으로 확인하고, 실제 원문은 승인된 manifest 검토에서만 대조한다.

**최초 Pod 자동값 등록 — 아래 한 줄 전체를 복사**

`invalidate_pod_pipeline; RESOURCE_CHANGE_APPLIED=false; ROLLBACK_TARGET_READY=false; ROLLBACK_TARGET_RECHECK_READY=false; unset AUTO_READY POD_UID NODE PHASE POD_CREATED POD_RE; AUTO_READY=false; if [ "$INPUT_READY" != true ]; then printf '%s\n' '중단: INPUT_READY가 아니다.' >&2; elif POD_JSON="$(kubectl get pod "$POD" -n "$NS" -o json)" && POD_UID_TMP="$(jq -r '.metadata.uid // empty' <<<"$POD_JSON")" && NODE_TMP="$(jq -r '.spec.nodeName // empty' <<<"$POD_JSON")" && PHASE_TMP="$(jq -r '.status.phase // empty' <<<"$POD_JSON")" && POD_CREATED_TMP="$(jq -r '.metadata.creationTimestamp // empty' <<<"$POD_JSON")" && POD_RE_TMP="$(printf '%s' "$POD" | sed 's/[][\\.^$*+?(){}|]/\\&/g')"; then if [ -n "$POD_UID_TMP" ] && [ -n "$NODE_TMP" ] && [ -n "$PHASE_TMP" ]; then POD_UID="$POD_UID_TMP"; NODE="$NODE_TMP"; PHASE="$PHASE_TMP"; POD_CREATED="$POD_CREATED_TMP"; POD_RE="^${POD_RE_TMP}$"; AUTO_READY=true; export NS POD POD_UID NODE PHASE POD_CREATED POD_RE; printf 'AUTO_READY=true\nPod UID: %s\nNode: %s\nPhase: %s\n생성 시각: %s\nPod 정규식 후보: %s\n' "$POD_UID" "$NODE" "$PHASE" "$POD_CREATED" "$POD_RE"; else printf '%s\n' '중단: UID·node·phase가 비었다. 부분 등록값을 폐기했다.' >&2; fi; else printf '%s\n' '중단: API 자동값 등록 실패. 이전 값은 유효하지 않다.' >&2; fi`

`AUTO_READY=true`가 아니면 다음 단계로 가지 않는다. 이후 모든 대상 Pod 재조회는 최초 `POD_UID`와 비교하며 mismatch이면 `POD_IDENTITY_READY=false`로 gate를 무효화한다.

**Pod UID 검증 helper 등록 — 같은 Bash에서 한 번 실행**

ReplicaSet owner가 Deployment로 연결되지 않거나 owner UID chain이 비면 `WORKLOAD_KIND`, `WORKLOAD_NAME`, `WORKLOAD_UID`, selector를 유효하게 등록하지 않는다. ReplicaSet에 `set resources`를 실행하지 않는다.

**운영자 선택 container와 status gate — 아래 한 줄 전체를 복사**

`CONTAINER='PASTE_CONTAINER_HERE'; SELECTION_READY=false; unset CONTAINER_ID_RAW CONTAINER_REASON; if verify_pod_identity && CONTAINER_REASON_TMP="$(jq -r --arg c "$CONTAINER" '[.status.containerStatuses[]? | select(.name==$c) | (.state.waiting.reason // .lastState.terminated.reason // "")][0] // empty' <<<"$POD_JSON")" && CONTAINER_ID_TMP="$(jq -r --arg c "$CONTAINER" '[.status.containerStatuses[]? | select(.name==$c) | (.containerID // .lastState.terminated.containerID // "")][0] // empty' <<<"$POD_JSON")"; then if [ "$CONTAINER_REASON_TMP" = CreateContainerError ] || [ "$CONTAINER_REASON_TMP" = RunContainerError ]; then CONTAINER_ID_RAW="$CONTAINER_ID_TMP"; CONTAINER_REASON="$CONTAINER_REASON_TMP"; SELECTION_READY=true; export CONTAINER CONTAINER_ID_RAW CONTAINER_REASON; printf 'SELECTION_READY=true container=%s reason=%s containerID=%s\n' "$CONTAINER" "$CONTAINER_REASON" "${CONTAINER_ID_RAW:--}"; else printf '중단: 선택 container reason이 범위를 벗어남 reason=%s\n' "${CONTAINER_REASON_TMP:--}" >&2; fi; else printf '%s\n' '중단: UID 검증·container 조회 실패. 임의 선택하지 않는다.' >&2; fi`

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | `STATUS` 또는 대상 container `state.waiting.reason`이 `CreateContainerError`·`RunContainerError`인 경우 |
| 적용 | 최초 Pod UID·container·node와 create/start 시각을 확인할 수 있는 경우 |
| 제외 | `CreateContainerConfigError`는 [[09. Pod STATUS가 CreateContainerConfigError인 경우]], image pull은 [[07. Pod STATUS가 ImagePullBackOff·ErrImagePull인 경우]], 실행 후 종료·재시작은 [[06. Pod STATUS가 CrashLoopBackOff인 경우]], init·ephemeral은 [[02. 워크로드/01. Pod/36. 멀티 컨테이너 Pod에서 특정 컨테이너만 실패하는 경우|멀티 컨테이너 Pod 컨테이너별 실패]]로 이관한다. |

검색 문자열: `CreateContainerError`, `RunContainerError`, `failed to create container`, `failed to start container`, `executable file not found`, `permission denied`, `exec format error`, `OCI runtime`, `containerd://`, `cri-o://`, `docker://`, `SELinux`, `AppArmor`, `SECCOMP`, `seccomp`, `syscall`.

## 최초 확인

**Pod identity gate 뒤 읽기 전용 최초 확인 — 아래 한 줄 전체를 복사**

`if verify_pod_identity; then DESCRIBE_RC=0; kubectl describe pod "$POD" -n "$NS" || DESCRIBE_RC=$?; if [ "$DESCRIBE_RC" -eq 0 ] && kubectl get events -n "$NS" --field-selector involvedObject.kind=Pod,involvedObject.name="$POD",involvedObject.uid="$POD_UID" --sort-by=.metadata.creationTimestamp -o custom-columns='EVENT-UID:.metadata.uid,CREATED:.metadata.creationTimestamp,FIRST-SEEN:.firstTimestamp,LAST-SEEN:.lastTimestamp,EVENT-TIME:.eventTime,SERIES-LAST:.series.lastObservedTime,TYPE:.type,REASON:.reason,COUNT:.count,MESSAGE:.message'; then printf '%s\n' '최초 확인 성공: UID 일치 후 Event와 state를 시간 대조한다.'; else printf '중단: describe 또는 Event 실패 rc=%s. 빈 Event는 오류 없음이 아니다.\n' "$DESCRIBE_RC" >&2; fi; else printf '%s\n' '중단: Pod UID mismatch 또는 재조회 실패.' >&2; fi`

`describe`에서 State, Last State, waiting reason·message, exit code, restart count와 첫 실패 시각을 본다. Event 조회 성공은 API/Event 범위만 보장하며 kubelet·runtime·application 정상은 보장하지 않는다.

## 관측별 진단 경로

| 지금 보이는 것 | 먼저 볼 것 | 그다음 어디를 볼지 | 상세 절 |
|---|---|---|---|
| `executable file not found`, `exec format error` | image 실행 경로와 node architecture | 비민감 command/args 요약, image manifest, runtime | [[#1. image entrypoint와 commandargs|1]] → [[#4. node·kubelet·runtime create/start|4]] |
| `permission denied`, `operation not permitted` | securityContext와 실행·mount 경로 | SELinux/AppArmor, seccomp, filesystem | [[#2. securityContext|2]] → [[#5. Linux filesystem과 보안 정책|5]] |
| `mount`, `read-only file system` | volumeMount와 실제 host mapping | kubelet, filesystem, LSM | [[#3. mount와 filesystem|3]] → [[#5. Linux filesystem과 보안 정책|5]] |
| `OCI runtime`, `failed to create task` | node와 같은 시간대 kubelet 오류 | 확인된 runtime·CRI | [[#4. node·kubelet·runtime create/start|4]] |
| reason만 있고 결정적 message가 없음 | 첫 Event와 container ID | kubelet journal, ID가 있으면 CRI inspect | [[#1. image entrypoint와 commandargs|1]] → [[#4. node·kubelet·runtime create/start|4]] |

표는 길 안내일 뿐이다. reason 하나 또는 `Running`만으로 원인을 확정하거나 정상화를 선언하지 않는다.

### 1. image entrypoint와 command/args

진입 증거는 실행 파일·architecture 오류다. `verify_pod_identity`가 성공한 `$POD_JSON`만 사용하며 raw command/args는 출력하지 않는다.

**비민감 image·command/args 요약 — 아래 한 줄 전체를 복사**

`if verify_pod_identity && jq -r --arg c "$CONTAINER" '[.spec.containers[]? | select(.name==$c) | {container:.name,image:.image,imagePullPolicy:.imagePullPolicy,commandPresent:((.command // [])|length>0),argsCount:((.args // [])|length),ports:(.ports // [])}]' <<<"$POD_JSON" && kubectl get node "$NODE" -o jsonpath='{.metadata.name}{" architecture="}{.status.nodeInfo.architecture}{" os="}{.status.nodeInfo.operatingSystem}{"\n"}'; then printf '%s\n' '성공 gate: 비민감 image·command/args 존재 요약과 node architecture를 확보했다.'; else printf '%s\n' '중단: UID 검증·API 조회 실패. 빈 command/args는 image ENTRYPOINT/CMD 사용일 수 있다.' >&2; fi`

`executable file not found`는 승인된 비민감 manifest의 image 내부 경로와 대조하고, `exec format error`는 architecture와 image manifest를 대조한다. raw command/args·Secret·token·개인정보는 저장하지 않는다. 임의 image 변경이나 command 덮어쓰기는 하지 않고 owner에게 이관한다. 실행 파일 자체가 없거나 exec 확인이 필요하면 [[02. 워크로드/01. Pod/32. Pod exec 명령을 찾을 수 없는 경우|Pod exec 명령을 찾을 수 없는 경우]]와 혼동하지 않는다.

### 2. securityContext

`permission denied`, `operation not permitted`, `must run as non-root`가 진입 증거다.

**보안 설정 비민감 요약 — 아래 한 줄 전체를 복사**

`if verify_pod_identity && jq -r --arg c "$CONTAINER" '{podSecurityContext:.spec.securityContext,container:([.spec.containers[]? | select(.name==$c) | {name,securityContext}][0]),appArmor:([.metadata.annotations // {} | to_entries[]? | select(.key|startswith("container.apparmor.security.beta.kubernetes.io/")) | .key][0] // "-"),seccomp:(.spec.securityContext.seccompProfile // "-")}' <<<"$POD_JSON"; then printf '%s\n' '성공 gate: selected container와 Pod의 보안 설정 요약을 확보했다.'; else printf '%s\n' '중단: UID 검증·securityContext 조회 실패.' >&2; fi`

`runAsUser`, `runAsGroup`, `runAsNonRoot`, privilege, capabilities, read-only root, seccomp와 admission 결과를 대조한다. `avc: denied`·`apparmor="DENIED"`가 path·시간과 직접 일치하면 [[16. Linux 기반/06. 격리·권한 경계/06. SELinux·AppArmor가 작업을 거부한 경우|SELinux·AppArmor 런북]], `SECCOMP`와 syscall·arch·code가 직접 일치하면 [[16. Linux 기반/06. 격리·권한 경계/05. seccomp가 syscall을 거부한 경우|seccomp 런북]]으로 이관한다. 정책 완화는 승인 없이 실행하지 않는다.

### 3. mount와 filesystem

`mount`, `read-only file system`, `no such file or directory`가 volume 또는 실행 path와 함께 나타난 경우다.

**Pod volume 관계 — 아래 한 줄 전체를 복사**

`if verify_pod_identity && jq -r --arg c "$CONTAINER" '{mounts:([.spec.containers[]? | select(.name==$c) | .volumeMounts[]? | {name,mountPath,subPath,readOnly}]),volumes:([.spec.volumes[]? | {name,pvc:(.persistentVolumeClaim.claimName // "-"),secret:(.secret.secretName // "-"),configMap:(.configMap.name // "-")}])}' <<<"$POD_JSON"; then printf '%s\n' '성공 gate: volume 이름·container path 관계를 확보했다. host path는 아직 미확정이다.'; else printf '%s\n' '중단: UID 검증·volume 조회 실패.' >&2; fi`

Pod `mountPath`를 node path로 넣지 않는다. Secret·ConfigMap 참조 해석 오류면 [[09. Pod STATUS가 CreateContainerConfigError인 경우|CreateContainerConfigError]], 확인된 host mapping의 read-only·filesystem 오류면 [[16. Linux 기반/04. 디스크·파일시스템·입출력/06. 예상한 mount가 없거나 source·option이 다른 경우|filesystem/mount 런북]]으로 이관한다.

### 4. node·kubelet·runtime create/start

node 진단은 `NODE_HOST_READY=true`일 때만 실행한다.

**승인된 NODE_HOST와 Kubernetes node identity 대조 — 아래 한 줄 전체를 복사**

`NODE_HOST='PASTE_NODE_HOST_HERE'; NODE_HOST_READY=false; NODE_IDENTITY_READY=false; if [ "$AUTO_READY" != true ]; then printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; elif NODE_API_JSON="$(kubectl get node "$NODE" -o json)" && K8S_MACHINE_ID="$(jq -r '.status.nodeInfo.machineID // empty' <<<"$NODE_API_JSON")" && REMOTE_IDENTITY="$(ssh -- "$NODE_HOST" 'hostname -s; cat /etc/machine-id')"; then REMOTE_HOSTNAME="$(printf '%s\n' "$REMOTE_IDENTITY" | sed -n '1p')"; REMOTE_MACHINE_ID="$(printf '%s\n' "$REMOTE_IDENTITY" | sed -n '2p')"; K8S_HOST_MATCH="$(jq -r --arg h "$REMOTE_HOSTNAME" '([.metadata.name] + [.status.addresses[]?.address]) | any(. == $h)' <<<"$NODE_API_JSON")"; if [ -n "$K8S_MACHINE_ID" ] && [ "$REMOTE_MACHINE_ID" = "$K8S_MACHINE_ID" ] && [ "$K8S_HOST_MATCH" = true ]; then NODE_IDENTITY_READY=true; NODE_HOST_READY=true; export NODE_HOST REMOTE_HOSTNAME REMOTE_MACHINE_ID NODE_HOST_READY; printf 'NODE_HOST_READY=true node=%s host=%s machineID=%s\n' "$NODE" "$REMOTE_HOSTNAME" "$REMOTE_MACHINE_ID"; else printf '중단: Kubernetes node와 remote identity 불일치 node=%s host=%s machineID=%s\n' "$NODE" "$REMOTE_HOSTNAME" "$REMOTE_MACHINE_ID" >&2; fi; else printf '%s\n' '중단: node API 또는 SSH identity 조회 실패. 작업 PC에서 node 명령을 실행하지 않는다.' >&2; fi`

`NODE_HOST_READY=true`가 아니면 node 명령·journal·CRI·cgroup·filesystem을 실행하지 않는다. SSH는 명시된 scalar만 `printf '%q'`로 remote command에 넣어 전달하며 작업 PC 변수를 remote 환경변수로 가정하지 않는다.

**SSH remote command helper 등록 — 같은 Bash에서 한 번 실행**

`node_exec(){ local remote_command="$1"; if [ "$NODE_HOST_READY" != true ]; then printf '%s\n' '중단: NODE_HOST_READY가 아니다.' >&2; return 125; else ssh -- "$NODE_HOST" "$remote_command"; fi; }`

**node 도구·unit 후보 확인 — 아래 한 줄 전체를 복사**

`NODE_TOOLS_READY=false; REMOTE_CMD='for t in systemctl journalctl grep date; do command -v "$t" >/dev/null 2>&1 || exit 127; done; sudo -n true'; REMOTE_RC=0; REMOTE_OUTPUT="$(node_exec "$REMOTE_CMD")" || REMOTE_RC=$?; if [ "$REMOTE_RC" -ne 0 ]; then printf '중단: remote node 도구·sudo 확인 실패 rc=%s\n' "$REMOTE_RC" >&2; else NODE_TOOLS_READY=true; UNIT_RC=0; UNIT_OUTPUT="$(node_exec 'systemctl list-units --type=service --all --no-legend')" || UNIT_RC=$?; if [ "$UNIT_RC" -ne 0 ]; then printf '중단: systemctl unit 목록 producer 실패 rc=%s\n' "$UNIT_RC" >&2; else UNIT_FILTER_RC=0; UNIT_FILTER_OUTPUT="$(printf '%s\n' "$UNIT_OUTPUT" | grep -E -i '(^| )(kubelet|containerd|crio|cri-o|cri-docker|cri-dockerd)(\.service)?( |$)')" || UNIT_FILTER_RC=$?; if [ "$UNIT_FILTER_RC" -eq 0 ]; then NODE_TOOLS_READY=true; printf '%s\n' "$UNIT_FILTER_OUTPUT"; else printf '%s\n' 'matching unit 없음: unit을 추측하지 않는다.' >&2; fi; fi; fi`

`NODE_TOOLS_READY=true`가 아니면 journal로 진행하지 않는다. `systemctl` producer rc와 `grep` filter rc를 분리했으며 빈 filter는 unit 부재 또는 후보 불일치이지 service 정상의 증거가 아니다.

**kubelet journal 시간·unit gate — 아래 한 줄 전체를 복사**

`KUBELET_UNIT='PASTE_KUBELET_UNIT_HERE'; START_JOURNAL='PASTE_START_JOURNAL_HERE'; END_JOURNAL=''; JOURNAL_READY=false; KUBELET_UNIT_READY=false; if [ "$NODE_TOOLS_READY" != true ]; then printf '%s\n' '중단: NODE_TOOLS_READY가 아니다.' >&2; elif END_JOURNAL="$(date -u '+%Y-%m-%d %H:%M:%S UTC')" && [ -n "$KUBELET_UNIT" ] && [[ "$KUBELET_UNIT" != PASTE_* ]] && [ -n "$START_JOURNAL" ]; then REMOTE_CMD="systemctl show $(printf '%q' "$KUBELET_UNIT") --property=Id,LoadState,ActiveState --no-pager"; SHOW_RC=0; SHOW_OUTPUT="$(node_exec "$REMOTE_CMD")" || SHOW_RC=$?; ACTIVE_RC=0; ACTIVE_OUTPUT="$(node_exec "systemctl is-active $(printf '%q' "$KUBELET_UNIT")")" || ACTIVE_RC=$?; if [ "$SHOW_RC" -eq 0 ] && [ "$ACTIVE_RC" -eq 0 ] && printf '%s\n' "$SHOW_OUTPUT" | grep -Fxq "Id=$KUBELET_UNIT" && printf '%s\n' "$SHOW_OUTPUT" | grep -Fxq 'LoadState=loaded' && printf '%s\n' "$SHOW_OUTPUT" | grep -Fxq 'ActiveState=active' && [ "$ACTIVE_OUTPUT" = active ]; then KUBELET_UNIT_READY=true; JOURNAL_READY=true; export KUBELET_UNIT_READY KUBELET_UNIT START_JOURNAL END_JOURNAL; printf 'KUBELET_UNIT_READY=true JOURNAL_READY=true unit=%s since=%s until=%s\n' "$KUBELET_UNIT" "$START_JOURNAL" "$END_JOURNAL"; else printf '중단: kubelet unit exact loaded·active 확인 실패 producer_rc=%s active_rc=%s\n' "$SHOW_RC" "$ACTIVE_RC" >&2; fi; else printf '%s\n' '중단: 유효한 journal 시간·kubelet unit 또는 node 도구가 없다.' >&2; fi`

`JOURNAL_READY=false;`

**kubelet journal strict 시간·순서 재검증 — 아래 한 줄 전체를 복사**

`JOURNAL_STRICT_READY=false; if [ "$KUBELET_UNIT_READY" = true ] && [[ "$START_JOURNAL" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}[[:space:]][0-9]{2}:[0-9]{2}:[0-9]{2}[[:space:]]UTC$ ]] && [[ "$END_JOURNAL" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}[[:space:]][0-9]{2}:[0-9]{2}:[0-9]{2}[[:space:]]UTC$ ]] && START_JOURNAL_EPOCH="$(date -u -d "$START_JOURNAL" +%s 2>/dev/null)" && END_JOURNAL_EPOCH="$(date -u -d "$END_JOURNAL" +%s 2>/dev/null)" && (( START_JOURNAL_EPOCH < END_JOURNAL_EPOCH )); then JOURNAL_STRICT_READY=true; export JOURNAL_STRICT_READY START_JOURNAL_EPOCH END_JOURNAL_EPOCH; else JOURNAL_READY=false; printf '%s\n' '중단: kubelet unit 또는 journal 시간 형식·순서 검증 실패. 로그를 읽지 않는다.' >&2; fi; if [ "$JOURNAL_STRICT_READY" = true ]; then JOURNAL_READY=true; fi`

**kubelet journal 읽기 — 아래 한 줄 전체를 복사**

`if [ "$JOURNAL_READY" != true ] || [ "$KUBELET_UNIT_READY" != true ]; then printf '%s\n' '중단: JOURNAL_READY·KUBELET_UNIT_READY가 아니다.' >&2; else REMOTE_CMD="sudo journalctl -u $(printf '%q' "$KUBELET_UNIT") --since $(printf '%q' "$START_JOURNAL") --until $(printf '%q' "$END_JOURNAL") --no-pager"; PRODUCER_RC=0; JOURNAL_OUTPUT="$(node_exec "$REMOTE_CMD")" || PRODUCER_RC=$?; if [ "$PRODUCER_RC" -ne 0 ]; then printf '중단: kubelet journal producer 실패 rc=%s\n' "$PRODUCER_RC" >&2; else FILTER_RC=0; FILTER_OUTPUT="$(printf '%s\n' "$JOURNAL_OUTPUT" | grep -E -i -C 3 "$POD_UID|$CONTAINER|createcontainer|runcontainer|failed to create|failed to start|oci|permission denied|mount|exec format|rpc error")" || FILTER_RC=$?; if [ "$FILTER_RC" -eq 0 ]; then printf '%s\n' "$FILTER_OUTPUT"; else printf '필터 결과 없음 rc=%s: 오류 부재가 아니라 증거 공백이다.\n' "$FILTER_RC" >&2; fi; fi; fi`

`journalctl` producer rc가 0인 뒤 filter rc를 따로 판정한다. UID·시간·container를 보존하며 `rpc error`는 확인된 CRI로 내려갈 후보일 뿐 application 정상의 증거가 아니다.

**runtime endpoint/socket 입력 — 초기화 뒤, actual endpoint gate 전에 아래 한 줄 전체를 복사**

`CRI_ENDPOINT='PASTE_CRI_ENDPOINT_HERE'; CRI_SOCKET='PASTE_CRI_SOCKET_HERE'; KUBELET_CONFIG_PATH='';`

**kubelet 실제 runtime endpoint exact-match — runtime 명령 전에 아래 한 줄 전체를 복사**

`KUBELET_ENDPOINT_MATCH_READY=false; KUBELET_RUNTIME_ENDPOINT=''; KUBELET_EXECSTART=''; if [ "$NODE_TOOLS_READY" != true ] || [ -z "$CRI_ENDPOINT" ] || [[ "$CRI_ENDPOINT" == *CRI_ENDPOINT_HERE ]]; then JOURNAL_READY=false; RUNTIME_READY=false; CRI_READY=false; printf '%s\n' '중단: node 도구 또는 CRI endpoint 선택값이 유효하지 않다.' >&2; else KUBELET_EXECSTART_RC=0; KUBELET_EXECSTART="$(node_exec "systemctl show $(printf '%q' "$KUBELET_UNIT") --property=ExecStart --value --no-pager")" || KUBELET_EXECSTART_RC=$?; if [ "$KUBELET_EXECSTART_RC" -ne 0 ]; then JOURNAL_READY=false; RUNTIME_READY=false; CRI_READY=false; printf '중단: kubelet ExecStart producer 실패 rc=%s. CRI_READY를 열지 않는다.\n' "$CRI_ENDPOINT" "${KUBELET_RUNTIME_ENDPOINT:--}" >&2; fi; fi; fi`

### 5. Linux filesystem과 보안 정책

filesystem 절은 `NODE_HOST_READY=true`, `NODE_TOOLS_READY=true`, `JOURNAL_READY=true`와 확인된 host path가 모두 있어야 한다. `START_AUDIT`·`END_AUDIT`는 audit 시간 형식의 운영자 선택값이며 `END_AUDIT`를 자동 계산값으로 취급하지 않는다.

**host path·audit window gate — 아래 한 줄 전체를 복사**

`MOUNT_PATH='PASTE_MOUNT_PATH_HERE'; START_AUDIT='PASTE_START_AUDIT_HERE'; END_AUDIT='PASTE_END_AUDIT_HERE'; MOUNT_READY=false; if [ "$NODE_HOST_READY" != true ] || [ "$NODE_TOOLS_READY" != true ] || [ "$JOURNAL_READY" != true ]; then printf '%s\n' '중단: node identity·도구·journal 시간 gate가 아니다.' >&2; elif [ -z "$MOUNT_PATH" ] || [ -z "$START_AUDIT" ] || [ -z "$END_AUDIT" ]; then printf '%s\n' '중단: 확인된 host path와 audit window가 필요하다.' >&2; else MOUNT_READY=true; export MOUNT_PATH START_AUDIT END_AUDIT; printf 'MOUNT_READY=true path=%s audit=%s..%s\n' "$MOUNT_PATH" "$START_AUDIT" "$END_AUDIT"; fi`

**filesystem·kernel·audit 읽기 — 아래 한 줄 전체를 복사**

`if [ "$MOUNT_READY" != true ]; then printf '%s\n' '중단: MOUNT_READY가 아니다.' >&2; else REMOTE_CMD="namei -l $(printf '%q' "$MOUNT_PATH") && stat -c '%A %U %G %a %n' $(printf '%q' "$MOUNT_PATH") && findmnt -T $(printf '%q' "$MOUNT_PATH") -o TARGET,SOURCE,FSTYPE,OPTIONS && df -h $(printf '%q' "$MOUNT_PATH") && df -i $(printf '%q' "$MOUNT_PATH")"; FS_RC=0; FS_OUTPUT="$(node_exec "$REMOTE_CMD")" || FS_RC=$?; if [ "$FS_RC" -ne 0 ]; then printf 'filesystem producer 실패 rc=%s\n' "$FS_RC" >&2; else printf '%s\n' "$FS_OUTPUT"; KERNEL_CMD="sudo journalctl -k --since $(printf '%q' "$START_JOURNAL") --until $(printf '%q' "$END_JOURNAL") --no-pager"; KERNEL_RC=0; KERNEL_OUTPUT="$(node_exec "$KERNEL_CMD")" || KERNEL_RC=$?; if [ "$KERNEL_RC" -ne 0 ]; then printf 'kernel journal producer 실패 rc=%s\n' "$KERNEL_RC" >&2; else KERNEL_FILTER_RC=0; KERNEL_FILTER_OUTPUT="$(printf '%s\n' "$KERNEL_OUTPUT" | grep -E -i -C 3 "$MOUNT_PATH|I/O error|read-only|overlay|xfs|ext4|filesystem|apparmor|avc: denied|seccomp|SECCOMP|syscall|denied")" || KERNEL_FILTER_RC=$?; if [ "$KERNEL_FILTER_RC" -eq 0 ]; then printf '%s\n' "$KERNEL_FILTER_OUTPUT"; else printf 'kernel filter 결과 없음 rc=%s: 오류 부재가 아니다.\n' "$KERNEL_FILTER_RC" >&2; fi; fi; fi; AUDIT_CMD="sudo env LC_TIME=C TZ=UTC ausearch -m AVC,USER_AVC -ts $(printf '%q' "$START_AUDIT") -te $(printf '%q' "$END_AUDIT")"; AUDIT_RC=0; AUDIT_OUTPUT="$(node_exec "$AUDIT_CMD")" || AUDIT_RC=$?; if [ "$AUDIT_RC" -ne 0 ]; then printf 'audit producer 실패 rc=%s\n' "$AUDIT_RC" >&2; else printf '%s\n' "$AUDIT_OUTPUT"; fi; fi`

`avc: denied`, `apparmor="DENIED"` 또는 `SECCOMP`가 같은 path·process·시간과 일치하면 관련 Linux 런북으로 이관한다. `setenforce 0`, profile 해제, remount·fsck는 실행하지 않는다. 빈 filter는 오류 없음이 아니다.

## 복구 전 안전 gate와 승인된 rollback

진단과 변경을 분리한다. trigger는 create/start 오류와 UID·시간·owner chain·runtime/filesystem 직접 증거가 연결된 경우다. authority는 top-level Deployment owner와 서비스 담당자의 승인이고, ReplicaSet에는 변경하지 않는다. 영향은 승인된 Deployment와 새 Pod이며 runtime·node·filesystem 오류를 해결한다고 보장하지 않는다. 중단 조건은 rollback 뒤 새 Warning·Ready 감소·동일 오류·실제 요청 실패다.

`if [ "$ROLLOUT_READY" != true ]; then ROLLBACK_APPLIED=false; POST_CHANGE_READY=false; printf '%s\n' '중단: rollout status·observedGeneration 성공 전 새 Pod를 선택하지 않는다.' >&2; fi`

**변경 후 새 Pod 후보 출력 — rollback 성공 뒤 아래 한 줄 전체를 복사**

`POST_CHANGE_READY=false; if [ "$ROLLBACK_APPLIED" != true ] || [ "$WORKLOAD_SELECTOR" = - ]; then printf '%s\n' '중단: 성공한 rollback·selector gate가 아니다.' >&2; elif CANDIDATE_JSON="$(kubectl get pods -n "$NS" -l "$WORKLOAD_SELECTOR" -o json)" && jq -e '.items | type == "array"' >/dev/null <<<"$CANDIDATE_JSON"; then jq -r --arg old "$POD_UID" --arg start "$ROLLBACK_START" '[.items[] | select(.metadata.uid != $old and .metadata.creationTimestamp >= $start) | "=== 새 Pod 후보 ===\n이름: \(.metadata.name)\nUID: \(.metadata.uid)\n생성 시각: \(.metadata.creationTimestamp)\nPhase: \(.status.phase // "-")\nOwner: \([.metadata.ownerReferences[]? | select(.controller==true) | "\(.kind)/\(.name) UID=\(.uid)"] | join(","))"] | if length == 0 then "후보 없음" else join("\n") end' <<<"$CANDIDATE_JSON"; POST_CHANGE_READY=true; export CANDIDATE_JSON; else printf '%s\n' '중단: 후보 API/schema 조회 실패. old UID를 재사용하지 않는다.' >&2; fi`

**새 Pod identity·owner/revision 등록 — 후보 확인 후 아래 한 줄 전체를 복사**

`NEW_POD='PASTE_NEW_POD_HERE'; NEW_POD_READY=false; if [ "$POST_CHANGE_READY" != true ] || [ "$ROLLBACK_APPLIED" != true ] || [ -z "$ROLLBACK_START" ]; then printf '%s\n' '중단: candidate JSON·성공한 rollback·change start gate가 아니다.' >&2; elif CANDIDATE_JSON="$(kubectl get pods -n "$NS" -l "$WORKLOAD_SELECTOR" -o json)" && NEW_POD_JSON="$(kubectl get pod "$NEW_POD" -n "$NS" -o json)" && NEW_POD_UID="$(jq -r '.metadata.uid // empty' <<<"$NEW_POD_JSON")" && NEW_OWNER_KIND="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)][0].kind // empty' <<<"$NEW_POD_JSON")" && NEW_OWNER_NAME="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)][0].name // empty' <<<"$NEW_POD_JSON")" && NEW_OWNER_UID="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)][0].uid // empty' <<<"$NEW_POD_JSON")" && NEW_RS_JSON="$(kubectl get replicaset "$NEW_OWNER_NAME" -n "$NS" -o json)" && NEW_RS_UID="$(jq -r '.metadata.uid // empty' <<<"$NEW_RS_JSON")" && NEW_RS_TOP_KIND="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)][0].kind // empty' <<<"$NEW_RS_JSON")" && NEW_RS_TOP_NAME="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)][0].name // empty' <<<"$NEW_RS_JSON")" && NEW_RS_TOP_UID="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)][0].uid // empty' <<<"$NEW_RS_JSON")" && NEW_RS_REVISION="$(jq -r '.metadata.annotations["deployment.kubernetes.io/revision"] // empty' <<<"$NEW_RS_JSON")" && jq -e --arg pod "$NEW_POD" --arg uid "$NEW_POD_UID" --arg old "$POD_UID" --arg start "$ROLLBACK_START" 'any(.items[]; .metadata.name==$pod and .metadata.uid==$uid and .metadata.uid != $old and (.metadata.creationTimestamp // "") >= $start)' >/dev/null <<<"$CANDIDATE_JSON" && [ "$NEW_OWNER_KIND" = ReplicaSet ] && [ -n "$NEW_OWNER_UID" ] && [ "$NEW_RS_UID" = "$NEW_OWNER_UID" ] && [ "$NEW_RS_TOP_KIND" = Deployment ] && [ "$NEW_RS_TOP_NAME" = "$WORKLOAD_NAME" ] && [ "$NEW_RS_TOP_UID" = "$WORKLOAD_UID" ] && [ "$NEW_RS_REVISION" = "$ROLLBACK_REVISION" ]; then NEW_POD_READY=true; export NEW_POD NEW_POD_UID NEW_OWNER_KIND NEW_OWNER_NAME NEW_OWNER_UID; printf 'NEW_POD_READY=true pod=%s uid=%s directOwner=%s/%s ownerUID=%s topOwner=%s/%s topUID=%s revision=%s\n' "$NEW_POD" "$NEW_POD_UID" "$NEW_OWNER_KIND" "$NEW_OWNER_NAME" "$NEW_OWNER_UID" "$NEW_RS_TOP_KIND" "$NEW_RS_TOP_NAME" "$NEW_RS_TOP_UID" "$NEW_RS_REVISION"; else printf '%s\n' '중단: candidate membership·created>=rollback start·direct ReplicaSet UID·RS→Deployment UID/revision gate 실패.' >&2; fi`

## 정상화 검증

**새 Pod·Deployment·기능 확인 — 아래 한 줄 전체를 복사**

`if [ "$ROLLBACK_APPLIED" != true ] || [ "$NEW_POD_READY" != true ]; then printf '%s\n' '중단: 성공한 rollback·NEW_POD_READY가 아니다.' >&2; elif NEW_STATUS="$(kubectl get pod "$NEW_POD" -n "$NS" -o json)" && NEW_CURRENT_UID="$(jq -r '.metadata.uid // empty' <<<"$NEW_STATUS")" && [ "$NEW_CURRENT_UID" = "$NEW_POD_UID" ] && kubectl get deployment "$WORKLOAD_NAME" -n "$NS" && kubectl rollout status deployment/"$WORKLOAD_NAME" -n "$NS" --timeout=5m; then printf '정상화 객체 gate: newPod=%s uid=%s deploymentUID=%s\n' "$NEW_POD" "$NEW_POD_UID" "$WORKLOAD_UID"; else printf '%s\n' '중단: 새 Pod UID·Deployment 상태·rollout 확인 실패.' >&2; fi`

새 Pod가 `Running`·`Ready`여도 listener·실제 요청·핵심 기능을 보장하지 않는다. 원인 path의 runtime/kubelet/filesystem 오류 중단, desired/Ready, 새 Warning 부재, 실제 서비스 요청·핵심 기능과 재발 관찰을 역순으로 확인한다. UID mismatch가 다시 발생하면 정상화 gate를 무효화한다.

**owner-provided bounded function check — 아래 한 줄 전체를 복사**

`if [ "$ROLLOUT_READY" != true ]; then NEW_POD_READY=false; FUNCTION_READY=false; NORMALIZATION_READY=false; printf '%s\n' '중단: ROLLOUT_READY=true 없이는 기능·정상화 gate를 열지 않는다.' >&2; fi`

실제 서비스 요청·핵심 기능의 자동화 정보가 이 런북에 없으므로 `FUNCTION_READY=false`가 안전 기본이다. `Running`, `Ready`, rollout, HTTP 200, Service 또는 EndpointSlice만으로 `FUNCTION_READY`를 열지 않는다. 서비스 owner가 bounded check의 식별자·pass 결과·UTC 시작/종료 시각을 제공하기 전에는 정상화하지 않는다.

`FUNCTION_CHECK_ID='PASTE_OWNER_FUNCTION_CHECK_ID_HERE'; FUNCTION_CHECK_RESULT='PASTE_OWNER_FUNCTION_CHECK_RESULT_HERE'; FUNCTION_CHECK_START='PASTE_OWNER_FUNCTION_CHECK_START_HERE'; FUNCTION_CHECK_END='PASTE_OWNER_FUNCTION_CHECK_END_HERE'; FUNCTION_READY=false; NORMALIZATION_READY=false; if [ "$NEW_POD_READY" != true ] || [ "$ROLLOUT_READY" != true ] || [ "$FUNCTION_CHECK_ID" = "PASTE"_"OWNER_FUNCTION_CHECK_ID_HERE" ] || [ "$FUNCTION_CHECK_RESULT" != pass ]; then printf '%s\n' '중단: 새 Pod·rollout 또는 owner-provided bounded function check gate가 아니다.' >&2; elif ! [[ "$FUNCTION_CHECK_START" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}[[:space:]][0-9]{2}:[0-9]{2}:[0-9]{2}[[:space:]]UTC$ ]] || ! [[ "$FUNCTION_CHECK_END" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}[[:space:]][0-9]{2}:[0-9]{2}:[0-9]{2}[[:space:]]UTC$ ]] || ! FUNCTION_CHECK_START_EPOCH="$(date -u -d "$FUNCTION_CHECK_START" +%s 2>/dev/null)" || ! FUNCTION_CHECK_END_EPOCH="$(date -u -d "$FUNCTION_CHECK_END" +%s 2>/dev/null)" || (( FUNCTION_CHECK_START_EPOCH >= FUNCTION_CHECK_END_EPOCH )); then printf '%s\n' '중단: owner function check의 bounded UTC window가 유효하지 않다.' >&2; else FUNCTION_READY=true; export FUNCTION_CHECK_ID FUNCTION_CHECK_RESULT FUNCTION_CHECK_START FUNCTION_CHECK_END FUNCTION_READY; printf 'FUNCTION_READY=true check=%s result=pass window=%s..%s\n' "$FUNCTION_CHECK_ID" "$FUNCTION_CHECK_START" "$FUNCTION_CHECK_END"; fi`

`NORMALIZATION_READY=false; if [ "$NEW_POD_READY" = true ] && [ "$FUNCTION_READY" = true ]; then NORMALIZATION_READY=true; export NORMALIZATION_READY; printf 'NORMALIZATION_READY=true\n'; else printf '%s\n' '중단: FUNCTION_READY=true 없이는 NORMALIZATION_READY를 열지 않는다.' >&2; fi`

## 증거 보존

최초·새 Pod UID, namespace, node, verified `NODE_HOST`와 remote hostname/machineID, UTC 관측 시각, owner chain의 kind/name/UID/revision, container reason·ID, bounded journal producer/filter rc, CRI endpoint·info/inspect rc, filesystem·LSM 결과와 승인·rollback·정상화 결과를 보존한다. raw command/args, Secret·token·인증서·개인키·개인정보와 전체 로그는 보존하지 않는다.

## Prometheus 빠른 관측

PromQL은 직접 수정하지 않고 등록된 `NS`, `POD`, `POD_RE`로 생성한다. 아래 출력만 Prometheus/Grafana에 붙여 넣는다. 빈 결과는 metric 부재·label 불일치·조회 범위 오류이며 API/권한 실패와 구분한다.

**waiting reason PromQL 생성 — 아래 한 줄 전체를 복사**

`if [ "$AUTO_READY" != true ]; then printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; else QUERY="$(printf 'kube_pod_container_status_waiting_reason{namespace="%s",pod="%s",uid="%s",reason=~"CreateContainerError|RunContainerError"}==1' "$NS" "$POD" "$POD_UID")"; printf '%s\n' "$QUERY" | head -c 1000; printf '\n'; unset QUERY; fi`

**restart 증가 PromQL 생성 — 아래 한 줄 전체를 복사**

`if [ "$AUTO_READY" != true ]; then printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; else QUERY="$(printf 'sum by(namespace,pod,uid,container)(increase(kube_pod_container_status_restarts_total{namespace="%s",pod="%s",uid="%s"}[15m]))>0' "$NS" "$POD" "$POD_UID")"; printf '%s\n' "$QUERY" | head -c 1000; printf '\n'; unset QUERY; fi`
