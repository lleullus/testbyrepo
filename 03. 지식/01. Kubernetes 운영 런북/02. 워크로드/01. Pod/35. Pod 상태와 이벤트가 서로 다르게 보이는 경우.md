# Pod 상태와 이벤트가 서로 다르게 보이는 경우

## 입력값과 빠른 수집

`kubectl` printer의 `STATUS`와 Pod API의 phase·Conditions·container state, 별도 Event 객체는 서로 다른 관측이다. 같은 Pod 이름이라도 삭제·재생성될 수 있으므로 UID와 UTC 시각을 먼저 묶는다.

| 종류 | 값 | 출처와 사용 범위 |
|---|---|---|
| 최초 입력 | `CTX`, `NS`, `POD` | 승인된 context와 namespace·Pod 이름. 같은 Bash에서 한 번만 입력한다. |
| API 확인 자동값 | `POD_UID`, `NODE`, `PHASE`, `RESOURCE_VERSION`, `POD_CREATED`, `OBSERVED_AT` | Pod API snapshot에서 등록한다. Conditions, current/Last State, owner와 node도 같은 snapshot에서 확인한다. |
| 계산 후보 | `POD_RE`, `PROM_WINDOW` | Pod 이름을 escape한 PromQL matcher와 기본 관측 창. 후보 수·현재 UID를 확인한 뒤 사용한다. |
| 운영자 선택값 | `CONTAINER`, `SERVICE`, `START_RFC3339`, `START_JOURNAL`, `END_JOURNAL`, `NODE_HOST`, `KUBELET_UNIT` | 해당 로그·Service·node 분기에 들어갈 때 관측 결과와 승인된 시간 범위·remote node·실제 kubelet unit으로 선택한다. |

### 실행 계약과 도구 gate

명령은 승인된 작업 PC 또는 bastion의 **같은 Bash 터미널**에서 실행한다. `kubectl`과 Kubernetes Server는 1.26.x 기준이며 입력한 context가 승인된 대상이어야 한다. 기본 도구는 `kubectl`, `jq`, `grep`, `sed`, `date`다. node journal 분기는 추가로 SSH 접근, 원격 `journalctl`, `systemctl`, `sudo` 권한을 확인한 뒤에만 진행한다. 도구 또는 권한 확인이 실패하면 다음 단계로 진행하지 않는다.

`TOOLS_READY=false; if [ -z "${BASH_VERSION:-}" ]; then printf '%s\n' '중단: 같은 Bash에서 실행한다.' >&2; else MISSING_TOOLS=''; for TOOL in kubectl jq grep sed date; do command -v "$TOOL" >/dev/null 2>&1 || MISSING_TOOLS="$MISSING_TOOLS $TOOL"; done; if [ -z "$MISSING_TOOLS" ]; then TOOLS_READY=true; printf 'TOOLS_READY=true shell=%s\n' "$BASH_VERSION"; else printf '중단: 없는 도구=%s\n' "$MISSING_TOOLS" >&2; fi; fi`

### 최초 입력과 이전 상태 초기화

이전 UID·정규식·시간·선택값과 gate를 지워 이전 Pod 결과가 새 Pod에 섞이지 않게 한다. 아래 세 PASTE 값만 직접 바꾸며 각각 문서 전체에서 한 번만 나타난다.

`reset_pod35_downstream(){ unset AUTO_READY POD_UID NODE PHASE RESOURCE_VERSION POD_CREATED OBSERVED_AT POD_RE PROM_WINDOW CONTAINER SERVICE START_RFC3339 START_CANONICAL START_EPOCH END_CANONICAL END_EPOCH START_JOURNAL END_JOURNAL NODE_HOST KUBELET_UNIT STATUS_LOG_READY SERVICE_READY ENDPOINT_READY EVENT_READY UID_RECHECK_READY NODE_TOOLS_READY NODE_REMOTE_READY SELECTION_READY CONTAINER_API_OK POD_JSON POD_CHECK_JSON POD_EVENT_CHECK_JSON POD_LOG_CHECK_JSON SERVICE_JSON SERVICE_ENDPOINT_JSON POD_ENDPOINT_JSON ENDPOINTS_JSON POD_LABELS_JSON CURRENT_POD_JSON CURRENT_UID CURRENT_CREATED CURRENT_RESOURCE_VERSION NODE_JSON NODE_JOURNAL_POD_JSON JOURNAL_CMD NODE_INSPECT_CMD PIPE_RC SSH_RC GREP_RC; AUTO_READY=false; STATUS_LOG_READY=false; SERVICE_READY=false; ENDPOINT_READY=false; EVENT_READY=false; UID_RECHECK_READY=false; NODE_TOOLS_READY=false; NODE_REMOTE_READY=false; SELECTION_READY=false; CONTAINER_API_OK=false; }; reset_pod35_downstream; unset INPUT_READY; CTX='PASTE_CONTEXT_HERE'; NS='PASTE_NAMESPACE_HERE'; POD='PASTE_POD_HERE'; INPUT_READY=false; if [ "$TOOLS_READY" != true ]; then printf '%s\n' '중단: TOOLS_READY가 아니다.' >&2; elif [ -z "$CTX" ] || [ -z "$NS" ] || [ -z "$POD" ]; then printf '%s\n' '중단: CTX·NS·POD를 입력한다.' >&2; elif kubectl --context "$CTX" get pod "$POD" -n "$NS" -o name >/dev/null 2>&1; then INPUT_READY=true; export CTX NS POD; printf 'INPUT_READY=true context=%s namespace=%s pod=%s\n' "$CTX" "$NS" "$POD"; else printf '중단: exact-name Pod 조회 실패 context=%s namespace=%s pod=%s\n' "$CTX" "$NS" "$POD" >&2; fi`

`INPUT_READY=true`가 아니면 API 자동 수집을 실행하지 않는다. namespace를 모르면 broad query 결과를 임의로 선택하지 말고 승인된 namespace를 확인한 뒤 입력 절을 다시 실행한다.

### API 자동 수집과 등록

출력은 대상 Pod 한 개의 block으로 표시하고 UID·node·phase·관측 시각, owner, Conditions, container별 current/Last State·restart·시각을 사람이 바로 대조할 수 있게 한다. Event는 이 Pod UID로만 조회한다. API 호출 실패·필수값 누락·정규식 생성 실패는 부분 등록 없이 중단한다.

`if [ "$INPUT_READY" != true ]; then printf '%s\n' '중단: INPUT_READY가 아니다.' >&2; elif POD_JSON="$(kubectl --context "$CTX" get pod "$POD" -n "$NS" -o json)"; then jq -r '"=== 대상 Pod ===\n네임스페이스: \(.metadata.namespace)\nPod: \(.metadata.name)\nUID: \(.metadata.uid)\nNode: \(.spec.nodeName // "-")\nPhase: \(.status.phase // "-")\nResourceVersion: \(.metadata.resourceVersion // "-")\n생성 시각: \(.metadata.creationTimestamp // "-")\n삭제 시각: \(.metadata.deletionTimestamp // "-")\nOwner: " + ([.metadata.ownerReferences[]? | "\(.kind)/\(.name) UID=\(.uid) controller=\(.controller // false)"] | join("; ")) + "\n\n=== Conditions ===\n" + ([.status.conditions[]? | "Type=\(.type) Status=\(.status) Reason=\(.reason // "-") LastTransition=\(.lastTransitionTime // "-")"] | join("\n")) + "\n\n=== Container status ===\n" + ([.status.containerStatuses[]? | "Container=\(.name) Ready=\(.ready) ID=\(.containerID // "-") Current=\(.state | tostring) Last=\(.lastState | tostring) Restart=\(.restartCount) Started=\(.state.running.startedAt // "-") Finished=\(.state.terminated.finishedAt // "-")"] | join("\n"))' <<<"$POD_JSON"; else printf '%s\n' '중단: Pod API snapshot 조회 실패' >&2; fi`

`reset_pod35_downstream && if [ "$INPUT_READY" != true ]; then printf '%s\n' '중단: INPUT_READY가 아니다.' >&2; elif POD_JSON="$(kubectl --context "$CTX" get pod "$POD" -n "$NS" -o json)" && OBSERVED_AT="$(date -u '+%Y-%m-%dT%H:%M:%SZ')" && POD_UID_TMP="$(jq -r '.metadata.uid // empty' <<<"$POD_JSON")" && NODE_TMP="$(jq -r '.spec.nodeName // empty' <<<"$POD_JSON")" && PHASE_TMP="$(jq -r '.status.phase // empty' <<<"$POD_JSON")" && RESOURCE_VERSION_TMP="$(jq -r '.metadata.resourceVersion // empty' <<<"$POD_JSON")" && POD_CREATED_TMP="$(jq -r '.metadata.creationTimestamp // empty' <<<"$POD_JSON")"; then POD_RE_ESCAPED="$(printf '%s' "$POD" | sed 's/[][\\.^$*+?(){}|]/\\&/g')"; if [ -z "$POD_UID_TMP" ] || [ -z "$PHASE_TMP" ] || [ -z "$RESOURCE_VERSION_TMP" ] || [ -z "$POD_CREATED_TMP" ] || [ -z "$POD_RE_ESCAPED" ]; then printf '%s\n' '중단: 필수 자동값이 비어 있어 부분 등록을 폐기함' >&2; else POD_UID="$POD_UID_TMP"; NODE="$NODE_TMP"; PHASE="$PHASE_TMP"; RESOURCE_VERSION="$RESOURCE_VERSION_TMP"; POD_CREATED="$POD_CREATED_TMP"; POD_RE="^${POD_RE_ESCAPED}$"; PROM_WINDOW='15m'; AUTO_READY=true; export POD_UID NODE PHASE RESOURCE_VERSION POD_CREATED OBSERVED_AT POD_RE PROM_WINDOW; printf 'AUTO_READY=true 관측시각=%s UID=%s Node=%s Phase=%s Created=%s ResourceVersion=%s POD_RE=%s PROM_WINDOW=%s\n' "$OBSERVED_AT" "$POD_UID" "${NODE:--}" "$PHASE" "$POD_CREATED" "$RESOURCE_VERSION" "$POD_RE" "$PROM_WINDOW"; fi; unset POD_UID_TMP NODE_TMP PHASE_TMP RESOURCE_VERSION_TMP POD_CREATED_TMP POD_RE_ESCAPED; else printf '%s\n' '중단: API 자동값 수집 실패; 이전 파생값을 사용하지 않음' >&2; fi`

후속 Pod snapshot은 최초 자동값의 `$POD_UID`와 대조한다. 함수가 `jq` 실패 또는 UID mismatch를 반환하면 호출한 분기의 gate를 열지 않고 stale status·container·node 값을 사용하지 않는다.

`pod_uid_matches(){ local pod_json="$1" current_uid; current_uid="$(jq -r '.metadata.uid // empty' <<<"$pod_json")" || { AUTO_READY=false; STATUS_LOG_READY=false; SERVICE_READY=false; ENDPOINT_READY=false; EVENT_READY=false; NODE_TOOLS_READY=false; NODE_REMOTE_READY=false; UID_RECHECK_READY=false; SELECTION_READY=false; CONTAINER_API_OK=false; return 1; }; if [ -n "$current_uid" ] && [ "$current_uid" = "$POD_UID" ]; then return 0; else AUTO_READY=false; STATUS_LOG_READY=false; SERVICE_READY=false; ENDPOINT_READY=false; EVENT_READY=false; NODE_TOOLS_READY=false; NODE_REMOTE_READY=false; UID_RECHECK_READY=false; SELECTION_READY=false; CONTAINER_API_OK=false; return 1; fi; }`

`pod_uid_node_matches(){ local pod_json="$1" current_node; if ! pod_uid_matches "$pod_json"; then NODE_TOOLS_READY=false; return 1; fi; current_node="$(jq -r '.spec.nodeName // empty' <<<"$pod_json")" || { NODE_TOOLS_READY=false; return 1; }; if [ -n "$current_node" ] && [ "$current_node" = "$NODE" ]; then return 0; else NODE_TOOLS_READY=false; return 1; fi; }`

`endpoint_relation_ready(){ local service_json="$1" pod_json="$2" endpoints_json="$3" service_ports pod_ports; service_ports="$(jq -c '.spec.ports // []' <<<"$service_json")" || return 1; pod_ports="$(jq -c '[.spec.containers[]?.ports[]?] // []' <<<"$pod_json")" || return 1; jq -e --arg uid "$POD_UID" --argjson service_ports "$service_ports" --argjson pod_ports "$pod_ports" 'def target($sp): ($sp.targetPort // $sp.port); def endpoint_port_match($sp; $ep): ((((target($sp) | type) == "number" and $ep.port == target($sp)) or ((target($sp) | type) == "string" and any($pod_ports[]?; .name == target($sp) and $ep.port == .containerPort))) and (($ep.protocol // "TCP") == ($sp.protocol // "TCP")) and (($ep.name // "") == ($sp.name // ""))); [.items[]? as $slice | select(($slice.addressType // "") | IN("IPv4","IPv6","FQDN")) | select(any($slice.endpoints[]?; .targetRef.uid==$uid and .conditions.ready==true and ((.conditions.serving // true) != false) and ((.conditions.terminating // false) != true))) | select(($service_ports | length) > 0) | select(all($service_ports[]; . as $sp | any($slice.ports[]?; . as $ep | endpoint_port_match($sp; $ep))))] | length > 0' <<<"$endpoints_json" >/dev/null; }`

`AUTO_READY=true`와 현재 UID·UTC 관측 시각이 확인된 경우에만 최초 확인으로 간다. `Running`, `Ready=True`, `ContainersReady=True`는 Event의 현재성, 실제 Service 기능, node·runtime 정상화를 보장하지 않는다.

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | `kubectl get pod`의 `STATUS`·`READY`·`RESTARTS`와 `describe`의 Conditions·container state·Events가 서로 다른 시점 또는 의미처럼 보이는 경우 |
| 적용 | 같은 context·namespace·Pod UID와 resourceVersion·실제 시간 필드를 대조할 수 있는 경우 |
| 제외 | `ErrImagePull`·`ImagePullBackOff`는 [[07. Pod STATUS가 ImagePullBackOff·ErrImagePull인 경우]], `FailedMount`·`FailedAttachVolume`은 [[25. Pod 이벤트에 FailedMount·FailedAttachVolume이 기록된 경우]], `FailedScheduling`은 [[18. Pod 이벤트에 FailedScheduling이 기록된 경우]], `Unknown`·`ContainerStatusUnknown`은 [[14. Pod STATUS가 Unknown·ContainerStatusUnknown인 경우]], `CrashLoopBackOff`는 [[06. Pod STATUS가 CrashLoopBackOff인 경우]]로 이동한다. |

검색 문자열: `STATUS`, `READY`, `RESTARTS`, `phase`, `conditions`, `current state`, `Last State`, `restartCount`, `resource UID`, `creationTimestamp`, `lastTransitionTime`, `eventTime`, `firstTimestamp`, `lastTimestamp`, `count`, `series`, `kubelet`, `runtime`, `CrashLoopBackOff`.

표시 불일치만으로 현재 장애·원인·node 장애를 확정하지 않는다. 빈 Event는 정상·0·오류 없음이 아니며 UID·selector·권한·TTL·보존 범위를 분리한다.

## 최초 확인

`AUTO_READY=true`일 때만 같은 관측 시각에 다음 명령을 순서대로 실행한다.

`if [ "$AUTO_READY" = true ] && POD_CHECK_JSON="$(kubectl --context "$CTX" get pod "$POD" -n "$NS" -o json)" && pod_uid_matches "$POD_CHECK_JSON"; then jq -r '"Pod=" + .metadata.name + " UID=" + .metadata.uid + " Node=" + (.spec.nodeName // "-") + " Phase=" + (.status.phase // "-") + " ResourceVersion=" + (.metadata.resourceVersion // "-")' <<<"$POD_CHECK_JSON"; else printf '%s\n' '중단: AUTO_READY, Pod API 또는 최초 UID 검증 실패' >&2; fi`

`STATUS`, `READY`, `RESTARTS`, `NODE`, `AGE`, IP와 Pod 교체 여부를 본다. printer `STATUS`는 API의 독립 필드가 아니라 현재 Pod 정보의 요약이다.

`if [ "$AUTO_READY" = true ] && POD_CHECK_JSON="$(kubectl --context "$CTX" get pod "$POD" -n "$NS" -o json)" && pod_uid_matches "$POD_CHECK_JSON"; then kubectl --context "$CTX" describe pod "$POD" -n "$NS"; else printf '%s\n' '중단: 최초 UID와 Pod describe 대상이 일치하지 않음' >&2; fi`

Conditions의 Type·Status·Reason·Message·Last Transition, container의 State·Last State·Reason·Exit Code·Restart Count, Events의 Type·Reason·Message·보이는 시간을 확인한다. `describe` 성공만으로 Event가 현재 사건이라는 뜻은 아니다.

`EVENT_READY=false; if [ "$AUTO_READY" = true ] && POD_EVENT_CHECK_JSON="$(kubectl --context "$CTX" get pod "$POD" -n "$NS" -o json)" && pod_uid_matches "$POD_EVENT_CHECK_JSON" && kubectl --context "$CTX" get events -n "$NS" --field-selector "involvedObject.kind=Pod,involvedObject.name=$POD,involvedObject.uid=$POD_UID" --sort-by=.metadata.creationTimestamp -o custom-columns='EVENT-UID:.metadata.uid,INVOLVED-UID:.involvedObject.uid,CREATED:.metadata.creationTimestamp,FIRST-SEEN:.firstTimestamp,LAST-SEEN:.lastTimestamp,EVENT-TIME:.eventTime,SERIES-LAST:.series.lastObservedTime,TYPE:.type,REASON:.reason,COUNT:.count,SOURCE:.source.component,REPORTER:.reportingController,REPORTER-INSTANCE:.reportingInstance,MESSAGE:.message'; then EVENT_READY=true; else printf '%s\n' '중단: Event 실행 직전 Pod API 또는 최초 UID 검증 실패' >&2; fi`

이 Event 조회는 이 절에서 한 번만 실행한다. 성공 gate는 각 행의 `INVOLVED-UID`가 `$POD_UID`와 같은지 확인하는 것이다. header만 있거나 행이 없으면 정상으로 해석하지 말고 UID·field selector·권한·Event TTL·보존 범위를 확인한다. legacy core `v1 Event`의 source·first/last timestamp와 `events.k8s.io/v1`의 reporter·eventTime·series 필드명은 구분한다.

## 관측별 진단 경로

| 지금 보이는 것 | 먼저 볼 것 | 그다음 어디를 볼지 | 상세 절 |
|---|---|---|---|
| printer `STATUS`만 다름 | phase·Conditions·current state | Ready와 실제 Service 기능 | [[#STATUS만 다르고 현재 조건이 정상인 경우]] |
| `phase=Running`인데 Ready가 아님 | condition 전환 시각과 container `ready` | probe·Service·EndpointSlice | [[#Running이지만 Ready가 아닌 경우]] |
| current state는 정상, Last State/Event는 실패 | started/finished·restart와 Event 집계 시각 | 직전 종료와 현재 장애 분리 | [[#current state와 Last State가 다른 시기인 경우]] |
| Event가 없거나 다른 Pod처럼 보임 | Pod UID·resourceVersion·Event UID·TTL | 삭제·재생성·범위·보존 한계 | [[#UID와 시간 필드가 다른 경우]] |
| Event가 현재 status와 맞지 않음 | Event time/reporter와 현재 state | Event 집계·지연·보존 | [[#Event가 현재 status와 맞지 않는 경우]] |
| 같은 UID·시간에 status·Event·로그가 맞음 | 결정적 오류와 Pod UID | kubelet·runtime 직접 로그 | [[#kubelet과 runtime을 후보로 두는 경우]] |

각 상세 절은 진입 증거, 최초 필요값과 출처, 범위 제한 읽기 명령, 성공 gate, 실패·빈 결과의 의미, 다음 행동·이관을 모두 닫는다.

### 공통 운영자 선택값 등록

아래 값은 API로 자동 확정할 수 없어 해당 분기의 실제 관측을 보고 고른다. PASTE 값은 문서 전체에서 한 번만 바꾸며, 사용하지 않는 분기의 값은 그 분기 명령을 실행하지 않는다.

`CONTAINER='PASTE_CONTAINER_HERE'; SERVICE='PASTE_SERVICE_HERE'; START_RFC3339='PASTE_START_RFC3339_HERE'; START_CANONICAL=''; START_EPOCH=''; SELECTION_READY=false; export CONTAINER SERVICE START_RFC3339; printf '선택값 등록 container=%s service=%s start=%s\n' "$CONTAINER" "$SERVICE" "$START_RFC3339"`

## STATUS만 다르고 현재 조건이 정상인 경우

**진입 증거:** printer의 문자열만 다르고 같은 T0의 phase·Conditions·container current state가 정상 후보일 때다. `Running`은 실행 중이라는 뜻이지 Ready나 실제 요청 성공을 뜻하지 않는다.

**필수값:** `CONTAINER`, `START_RFC3339`는 위 선택값이며 Pod API의 container 이름과 오류 관측 전 UTC 시각에서 온다. `CONTAINER`가 현재 Pod에 없거나 시간이 RFC3339 UTC가 아니면 중단한다.

`STATUS_LOG_READY=false; if [ "$AUTO_READY" != true ]; then printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; elif [[ ! "$START_RFC3339" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]]; then printf '%s\n' '중단: START_RFC3339 형식 오류' >&2; elif ! START_CANONICAL="$(date -u -d "$START_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" || [ "$START_CANONICAL" != "$START_RFC3339" ] || ! START_EPOCH="$(date -u -d "$START_RFC3339" '+%s' 2>/dev/null)"; then printf '중단: START_RFC3339 canonical calendar round-trip 실패=%s\n' "$START_RFC3339" >&2; elif POD_JSON="$(kubectl --context "$CTX" get pod "$POD" -n "$NS" -o json)" && pod_uid_matches "$POD_JSON" && jq -e --arg c "$CONTAINER" 'any(.spec.containers[]?; .name==$c)' <<<"$POD_JSON" >/dev/null; then STATUS_LOG_READY=true; export START_CANONICAL START_EPOCH; printf 'STATUS_LOG_READY=true UID=%s container=%s start=%s epoch=%s\n' "$POD_UID" "$CONTAINER" "$START_RFC3339" "$START_EPOCH"; else printf '%s\n' '중단: container 후보, API 조회 또는 최초 UID 검증 실패' >&2; fi`

## Running이지만 Ready가 아닌 경우

**진입 증거:** phase가 `Running`이고 `Ready` 또는 `ContainersReady`가 `False`일 때다. **필수값:** `SERVICE`는 실제 selector가 이 Pod를 선택하는지 확인한 뒤 운영자가 고른 값이다.

## current state와 Last State가 다른 시기인 경우

**진입 증거:** `state.running.startedAt` 또는 `state.waiting`은 현재 instance를 가리키고, `lastState.terminated.finishedAt`, reason, exitCode, restartCount 또는 Event는 이전 instance를 가리킬 때다. 이 값들은 자동 수집한 동일 Pod UID의 snapshot에서 온다.

**성공 gate:** 현재 `state`, Last State, `restartCount`, Event의 실제 채워진 timestamp와 같은 시간창의 로그가 서로 일치할 때만 이전 종료 원인을 기록한다. `resourceVersion`은 시각이나 단조 증가 원인 순서가 아니다.

분기 순서는 `Last State reason/exitCode → image entrypoint·command·args·securityContext → current/previous log와 probe → resource limit·사용량 → kubelet → runtime·OCI → cgroup·kernel OOM·filesystem`이다. `OOMKilled`는 해당 container limit·사용량을 먼저 보고 다른 Pod의 동시성, node pressure와 kernel OOM으로 확장한다. 특정 container 상태만으로 node 원인을 확정하지 않는다.

`CrashLoopBackOff`는 backoff의 현재 표현이지 최초 원인이 아니다. 로그가 비면 process가 로그 전에 종료됐는지와 runtime·kubelet start 거부를 분리한다. 빈 로그는 원인 없음이 아니다.

**실패 의미와 다음 행동:** state·Event·로그의 UID 또는 시간창이 다르면 kubelet/runtime 원인으로 분류하지 않고 UID·시간 필드 분기로 돌아간다. 모두 맞아도 직접 kubelet/runtime 로그 전까지 후보로만 둔다.

## Event가 현재 status와 맞지 않는 경우

**진입 증거:** 같은 UID의 Event reason/message가 현재 status와 다르거나 Event가 없고 현재 status가 비정상일 때다. Event는 Pod status의 하위 필드가 아니라 별도 API 객체이며 `count`·`series`로 집계될 수 있다.

최초 Event 조회의 `eventTime`, `series.lastObservedTime`, legacy `firstTimestamp`·`lastTimestamp`, `metadata.creationTimestamp`, `count`, reporter와 현재 Pod transition·container state를 비교한다. `creationTimestamp`는 Event 객체 생성 시각이지 incident 시각이 아니다. 오래된 Warning과 현재 정상 state는 과거 사건 후보다.

**성공 gate:** Event `INVOLVED-UID`, 실제 채워진 시간, reason/message와 status의 state·종료 시각·restart가 같은 시간 범위에서 일치할 때만 현재 사건 후보로 둔다. Event 없음은 정상·오류 없음이 아니며 TTL·저장 용량·정리·조회 지연·권한을 확인한다.

**다음 행동:** 현재 status가 비정상인데 Event가 없으면 status·로그·UID를 보존하고 API/Event backend 담당자에게 이관한다. 같은 UID·시간이라는 사실만으로 node 계층으로 내려가지 않는다.

`if [ "$NODE_TOOLS_READY" = true ]; then kubectl --context "$CTX" get node "$NODE" -o wide && kubectl --context "$CTX" get lease "$NODE" -n kube-node-lease -o jsonpath='{.spec.holderIdentity}{"\t"}{.spec.renewTime}{"\t"}{.metadata.resourceVersion}{"\n"}' && kubectl --context "$CTX" describe node "$NODE"; else printf '%s\n' '중단: NODE_TOOLS_READY가 아니다.' >&2; fi`

Node에서 `Ready`, `MemoryPressure`, `DiskPressure`, `PIDPressure`, taint, Lease renewTime, 같은 시각의 kubelet Event를 본다. `Ready`와 최근 Lease는 API가 heartbeat를 관측했다는 범위만 보장하며 process·host liveness의 증명은 아니다.

`if [ "$NODE_TOOLS_READY" = true ] && NODE_JOURNAL_POD_JSON="$(kubectl --context "$CTX" get pod "$POD" -n "$NS" -o json)" && pod_uid_node_matches "$NODE_JOURNAL_POD_JSON" && node_journal_preflight; then printf -v JOURNAL_CMD 'sudo -n journalctl -u %q --since %q --until %q --no-pager' "$KUBELET_UNIT" "$START_JOURNAL" "$END_JOURNAL"; ssh -- "$NODE_HOST" "$JOURNAL_CMD" | grep -E -i -C 3 "$POD_UID|$POD|syncpod|probe|kill|start|sandbox|runtime|oom|evict|failed|error"; PIPE_RC=("${PIPESTATUS[@]}"); SSH_RC="${PIPE_RC[0]}"; GREP_RC="${PIPE_RC[1]}"; if [ "$SSH_RC" -ne 0 ]; then printf '중단: node journal producer/SSH 실패 rc=%s UID=%s node=%s host=%s kubelet=%s\n' "$SSH_RC" "$POD_UID" "$NODE" "$NODE_HOST" "$KUBELET_UNIT" >&2; elif [ "$GREP_RC" -gt 1 ]; then printf '중단: node journal 필터 도구 실패 rc=%s UID=%s node=%s host=%s kubelet=%s\n' "$GREP_RC" "$POD_UID" "$NODE" "$NODE_HOST" "$KUBELET_UNIT" >&2; fi; else NODE_TOOLS_READY=false; printf '%s\n' '중단: NODE_TOOLS_READY, API/SSH remote identity, 실제 kubelet unit 또는 실행 직전 Pod UID/node gate 검증 실패' >&2; fi`

`failed to start container`, `failed to create pod sandbox`, `PLEG is not healthy`, `eviction manager`, `failed to StartContainer`가 Pod UID·시간창과 맞으면 kubelet/runtime 후보를 직접 검증한다. 필터 빈 결과는 kubelet 정상이나 장애 없음이 아니며 unit·로그 보존·시간대를 확인한다. `probe`·`kill`만 있으면 승인된 rollout·삭제·eviction과 대조한다. runtime 구현체가 미확정이면 containerd·CRI-O 명령을 발명하지 않고 node/runtime 담당자에게 Pod UID·container ID·UTC 창을 이관한다.

## 제한적 복구와 정상화

이 문서는 진단 중 `delete`, `rollout`, `scale`, `patch`, `edit`, `drain` 명령을 제공하지 않는다. 상태 변경은 같은 Pod UID의 status·container state·Event와 실제 서비스 영향이 시간창에서 직접 일치하고 owner의 공식 절차·승인을 통과한 경우에만 별도 변경 기록에서 수행한다.

**안전 gate:** 변경 기록에는 trigger, owner·desired/ready·PDB·quorum·대체 Pod·Job 멱등성, 실행 RBAC·승인자, 대상·영향, 중단 조건, rollback, 실행 후 역순 검증 명령과 관찰 창을 적는다. Ready 감소, 동일 오류 반복, 새 Warning, quorum 위험, 실제 지표 악화가 보이면 중단한다.

정상화는 `Running`이나 새 Pod 생성으로 선언하지 않는다. 승인된 관찰 시간을 기록하고 printer → phase/Conditions → current/Last State → UID/time → Event → kubelet/runtime 순서를 역순으로 확인한다. 원하는 Ready 수·동일 오류/종료 reason/restart 증가 중단·새 Warning 부재·실제 요청·핵심 기능·Job 결과를 확인한다. Prometheus sample이 늦거나 이전 UID이면 정상화 근거에서 제외한다.

## Prometheus 빠른 관측

메트릭과 `namespace`, `pod`, `uid` label이 실제 수집될 때만 사용한다. `kube_pod_container_status_ready`는 `condition` label을 사용하지 않으며 sample value `0/1`로 판정한다. 모든 PromQL은 등록된 변수로 완성 문자열을 생성하며 사용자는 출력 한 줄만 외부 UI에 붙여 넣는다. metric 부재·label 불일치·조회 실패·빈 결과를 정상/0으로 해석하지 않는다.

`if [ "$AUTO_READY" = true ]; then printf '%s\n' "count by(namespace,pod,uid)(kube_pod_info{namespace=\"$NS\",pod=~\"$POD_RE\",uid=\"$POD_UID\"})"; else printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; fi`

결과가 현재 namespace·Pod regex·최초 UID에 대해 1 series이고 `namespace`, `pod`, `uid` label이 존재할 때만 kube-state-metrics label 계약을 통과시킨다.

`if [ "$AUTO_READY" = true ]; then printf '%s\n' "changes(kube_pod_status_phase{namespace=\"$NS\",pod=~\"$POD_RE\",uid=\"$POD_UID\"}[$PROM_WINDOW])>0"; else printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; fi`

`if [ "$AUTO_READY" = true ]; then printf '%s\n' "kube_pod_container_status_ready{namespace=\"$NS\",pod=~\"$POD_RE\",uid=\"$POD_UID\"} == 0"; else printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; fi`

`if [ "$AUTO_READY" = true ]; then printf '%s\n' "sum by(namespace,pod,uid,container)(increase(kube_pod_container_status_restarts_total{namespace=\"$NS\",pod=~\"$POD_RE\",uid=\"$POD_UID\"}[$PROM_WINDOW]))"; else printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; fi`

`if [ "$AUTO_READY" = true ]; then printf '%s\n' "time()-timestamp(kube_pod_status_phase{namespace=\"$NS\",pod=~\"$POD_RE\",uid=\"$POD_UID\"})"; else printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; fi`

sample age가 scrape 주기보다 크거나 series가 없으면 metrics lag·미수집·라벨 불일치 후보다. API status와 Event 시간축만으로 과거 순서나 정상화를 확정하지 않는다.
