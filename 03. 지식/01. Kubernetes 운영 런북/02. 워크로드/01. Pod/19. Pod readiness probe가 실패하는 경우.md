# Pod readiness probe가 실패하는 경우

## 입력값과 빠른 수집

이 런북은 같은 Pod UID의 `Warning Unhealthy` Event에 `Readiness probe failed:` suffix가 있고, kubelet이 container를 계속 실행하면서 `Ready=False`에 영향을 주는 경우를 다룬다. `Ready=False`만으로 probe 실패를 단정하지 않는다.

| 구분 | 값과 출처 | 유효성 gate |
|---|---|---|
| 최초 입력 | `NS`, `POD`: 승인된 namespace와 Pod 이름을 운영자가 한 번 입력 | exact-name API 조회 성공 |
| API 확인 자동값 | `POD_UID`, `NODE`, `PHASE`, `POD_IP`, `OWNER`, `OBSERVED_AT`, `POD_RE`, 현재 container ID·`RESTART_COUNT`와 readiness probe의 `PROBE_SCHEME`, `PROBE_PATH`, `PROBE_HOST`: Pod API와 UTC 시각 | 호출 성공, UID·node·container 후보가 비어 있지 않음 |
| 계산 후보값 | `PROBE_PORT`: 숫자 port 또는 named port를 선언된 container port로 해석한 후보, `POD_RE`: PromQL용 escaped regex | 대상 container의 단일 probe와 port 관계 확인 |
| 운영자 선택값 | `CONTAINER`, `START_RFC3339`, `START_JOURNAL`, `END_JOURNAL`, `NODE_HOST`, 조건부 `SERVICE`: Event·관측 시각·승인된 원격 node·Service 존재를 보고 선택 | 선택값 형식·대상 관계·권한 확인 |

각 `PASTE_..._HERE`는 이 문서에서 한 번만 입력한다. 이후 값은 같은 Bash의 등록 변수와 gate를 재사용하며, 찾아 바꾸기·모두 바꾸기를 요구하지 않는다.

실행 host는 승인된 작업 PC 또는 bastion의 동일한 Bash 터미널이다. `kubectl`은 API server에 연결하고, Pod 로그·exec는 API server→대상 node의 kubelet→runtime→container 경로를 사용한다. node journal은 승인된 node shell에서만 실행한다. 아래 도구 확인이 실패하면 이후 명령을 실행하지 않는다. `kubectl` API 조회 권한, logs/exec 권한, 조건부 node journal 권한은 별도로 확인해야 하며 `auth can-i=yes`는 실제 요청 성공을 보장하지 않는다.

**Bash와 host 도구 확인 — 아래 한 줄 전체를 복사**

`TOOLS_READY=false; MISSING_TOOLS=''; if [ -z "${BASH_VERSION:-}" ]; then printf '%s\n' '중단: 같은 Bash에서 실행한다.' >&2; else for TOOL in kubectl jq grep sed date mktemp ssh; do command -v "$TOOL" >/dev/null 2>&1 || MISSING_TOOLS="$MISSING_TOOLS $TOOL"; done; if [ -z "$MISSING_TOOLS" ]; then TOOLS_READY=true; printf 'TOOLS_READY=true shell=%s\n' "$BASH_VERSION"; else printf '중단: 없는 host 도구=%s\n' "$MISSING_TOOLS" >&2; fi; fi`

**최초 입력과 이전 파생값 초기화 — 같은 Bash에서 한 번 실행**

`unset INPUT_READY AUTO_READY SELECTION_READY PORT_READY DESCRIBE_READY EVENT_READY TARGET_READY LOG_READY HTTP_OBS_READY JOURNAL_READY SERVICE_READY SERVICE_INPUT_READY UID_READY EVIDENCE_READY NODE_SSH_READY POD_JSON POD_UID NODE PHASE POD_IP OWNER OBSERVED_AT POD_RE CONTAINER CONTAINER_ID CURRENT_CONTAINER_ID CURRENT_CONTAINER_STATE CURRENT_CONTAINER_READY CURRENT_CONTAINER_RESTART_COUNT RESTART_COUNT PROBE_PORT_RAW PROBE_PORT PROBE_SCHEME PROBE_PATH PROBE_HOST START_RFC3339 START_EPOCH START_JOURNAL END_JOURNAL START_JOURNAL_EPOCH END_JOURNAL_EPOCH NODE_HOST REMOTE_NODE CURRENT_POD_UID SERVICE EVENT_OUTPUT LOG_PRODUCER_RC LOG_FILTER_RC JOURNAL_OUTPUT JOURNAL_PRODUCER_RC JOURNAL_FILTER_RC; NS='PASTE_NAMESPACE_HERE'; POD='PASTE_POD_HERE'; INPUT_READY=false; if [ "$TOOLS_READY" != true ]; then printf '%s\n' '중단: 도구 확인을 먼저 통과한다.' >&2; elif [ -z "$NS" ] || [ -z "$POD" ]; then printf '%s\n' '중단: NS와 POD를 입력한다.' >&2; elif kubectl get pod "$POD" -n "$NS" -o name >/dev/null 2>&1; then INPUT_READY=true; export NS POD; printf 'INPUT_READY=true namespace=%s pod=%s\n' "$NS" "$POD"; else printf '중단: Pod API 조회 실패 또는 권한 없음 namespace=%s pod=%s\n' "$NS" "$POD" >&2; fi`

`INPUT_READY=true`가 아니면 namespace·Pod identity·현재 context의 API 권한을 확인하고 멈춘다. namespace를 모르는 경우에만 `kubectl get pods -A`를 승인된 범위에서 실행해 후보를 확인하며, 복수 후보를 임의로 고르지 않고 정확한 namespace를 최초 입력에 반영한다.

**Pod 자동값 수집·등록 — 대상별 세로 블록과 관계를 확인하는 한 줄**

`AUTO_READY=false; if [ "$INPUT_READY" != true ]; then printf '%s\n' '중단: INPUT_READY가 아니다.' >&2; elif POD_JSON="$(kubectl get pod "$POD" -n "$NS" -o json)" && POD_UID_TMP="$(jq -r '.metadata.uid // empty' <<<"$POD_JSON")" && NODE_TMP="$(jq -r '.spec.nodeName // empty' <<<"$POD_JSON")" && PHASE_TMP="$(jq -r '.status.phase // empty' <<<"$POD_JSON")" && POD_IP_TMP="$(jq -r '.status.podIP // empty' <<<"$POD_JSON")" && OWNER_TMP="$(jq -r '[.metadata.ownerReferences[]? | "\(.kind)/\(.name)"] | join(",")' <<<"$POD_JSON")" && CONTAINER_COUNT_TMP="$(jq '.spec.containers | length' <<<"$POD_JSON")" && OBSERVED_AT_TMP="$(date -u '+%Y-%m-%dT%H:%M:%SZ')" && POD_RE_TMP="$(printf '%s' "$POD" | sed 's/[][\\.^$*+?(){}|]/\\&/g')" && jq -r '"=== 대상 Pod ===\n이름: \(.metadata.name)\nPod UID: \(.metadata.uid)\nNode: \(.spec.nodeName // "-" )\nPhase: \(.status.phase // "-")\nPod IP: \(.status.podIP // "-")\nPod 시작 시각: \(.status.startTime // "-")\n상위 owner: \(([.metadata.ownerReferences[]? | "\(.kind)/\(.name)"] | join(",")) // "-")\nContainer/port 후보:\n" + ([.spec.containers[]? | "- \(.name): \([.ports[]? | ((.name // "unnamed") + ":" + (.containerPort|tostring))] | join(",") // "없음")"] | join("\n")) + "\nContainer 상태/ID:\n" + ([.status.containerStatuses[]? | "- \(.name): ready=\(.ready // false), restart=\(.restartCount // 0), state=\(.state | to_entries[0].key // "-") , container ID=\(.containerID // "-")"] | join("\n"))' <<<"$POD_JSON" && [ -n "$POD_UID_TMP" ] && [ -n "$NODE_TMP" ] && [ -n "$PHASE_TMP" ] && [ "$CONTAINER_COUNT_TMP" -ge 1 ]; then POD_UID="$POD_UID_TMP"; NODE="$NODE_TMP"; PHASE="$PHASE_TMP"; POD_IP="$POD_IP_TMP"; OWNER="$OWNER_TMP"; OBSERVED_AT="$OBSERVED_AT_TMP"; POD_RE="^${POD_RE_TMP}$"; AUTO_READY=true; export POD_UID NODE PHASE POD_IP OWNER OBSERVED_AT POD_RE; printf 'AUTO_READY=true\nPod UID=%s\nNode=%s\nPhase=%s\n관측 시각=%s\nPOD_RE=%s\n' "$POD_UID" "$NODE" "$PHASE" "$OBSERVED_AT" "$POD_RE"; else printf '%s\n' '중단: Pod API 실패, UID/node/container 후보 누락, 또는 출력 생성 실패' >&2; unset POD_UID NODE PHASE POD_IP OWNER OBSERVED_AT POD_RE; fi`

성공 출력은 `Pod UID`, node, phase, UTC 관측 시각과 `container/port` 및 container ID 대응을 모두 보여 줘야 한다. `AUTO_READY`가 아니면 이전 값이나 일부 API 결과를 사용하지 않는다. Pod가 `Running`이어도 listener·application·Service endpoint 정상은 보장하지 않으며, node가 비어 있으면 probe 장애 런북을 계속하지 않고 scheduling 경로로 이관한다.

**Event와 일치할 container 선택 — 출력 확인 후 한 번 입력**

`CONTAINER='PASTE_CONTAINER_HERE'; SELECTION_READY=false; unset CONTAINER_ID; if [ "$AUTO_READY" != true ]; then printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; elif [ -z "$CONTAINER" ]; then printf '%s\n' '중단: CONTAINER를 선택한다.' >&2; elif jq -e --arg c "$CONTAINER" 'any(.spec.containers[]?; .name==$c and .readinessProbe != null)' <<<"$POD_JSON" >/dev/null && CONTAINER_ID_TMP="$(jq -r --arg c "$CONTAINER" '[.status.containerStatuses[]? | select(.name==$c) | .containerID] | if length==1 then .[0] else empty end' <<<"$POD_JSON")" && [ -n "$CONTAINER_ID_TMP" ]; then CONTAINER_ID="$CONTAINER_ID_TMP"; SELECTION_READY=true; export CONTAINER CONTAINER_ID; printf 'SELECTION_READY=true container=%s container_id=%s pod_uid=%s\n' "$CONTAINER" "$CONTAINER_ID" "$POD_UID"; else printf '중단: 선택한 container가 없거나 readinessProbe·container ID가 단일하게 확인되지 않음 container=%s\n' "$CONTAINER" >&2; unset CONTAINER_ID; fi`

`CONTAINER`는 자동으로 첫 번째 후보를 선택하지 않는다. `CONTAINER_ID`는 status에서 읽은 현재 runtime identity이며 로그·exec 결과와 함께 보존한다. 대상 container가 아직 생성되지 않았거나 ID가 바뀌면 stale 결과를 버리고 자동 수집부터 다시 한다.

이후 Pod API를 다시 조회하는 모든 경로는 최초 `$POD_UID`와 대조한다. mismatch·빈 UID·API 실패는 `UID_READY=false`로 닫고 기존 결과를 사용하지 않는다.

`pod_uid_gate(){ local current; UID_READY=false; if current="$(kubectl get pod "$POD" -n "$NS" -o jsonpath='{.metadata.uid}')" && [ -n "$current" ]; then if [ "$current" = "$POD_UID" ]; then UID_READY=true; CURRENT_POD_UID="$current"; printf 'UID_READY=true pod=%s uid=%s\n' "$POD" "$current"; return 0; else printf '중단: Pod UID mismatch initial=%s current=%s\n' "$POD_UID" "$current" >&2; return 1; fi; else printf '중단: Pod 재조회 실패 또는 UID 없음 pod=%s\n' "$POD" >&2; return 1; fi; }`

`container_evidence_gate(){ local current_json current_uid status_count status expected_container_id current_container_id current_state current_ready current_restart failure_reason; EVIDENCE_READY=false; expected_container_id="${CONTAINER_ID:-}"; if [ "${SELECTION_READY:-false}" != true ] || [ -z "$expected_container_id" ]; then failure_reason='selection gate가 닫혔거나 선택한 container ID가 없음'; elif ! current_json="$(command kubectl get pod "$POD" -n "$NS" -o json 2>/dev/null)"; then failure_reason='현재 Pod status 재조회 실패'; else current_uid="$(jq -r '.metadata.uid // empty' <<<"$current_json")"; status_count="$(jq -r --arg c "$CONTAINER" '[.status.containerStatuses[]? | select(.name==$c)] | length' <<<"$current_json")"; status="$(jq -r --arg c "$CONTAINER" '[.status.containerStatuses[]? | select(.name==$c) | [(.containerID // ""), ((.state // {}) | keys[0] // ""), ((.ready // false) | tostring), ((.restartCount // "") | tostring)] | @tsv] | if length==1 then .[0] else empty end' <<<"$current_json")"; if [ "$current_uid" != "$POD_UID" ]; then failure_reason="Pod UID mismatch initial=$POD_UID current=$current_uid"; elif [ "${status_count:-0}" -ne 1 ] || [ -z "$status" ]; then failure_reason="selected container status가 단일하게 확인되지 않음 container=$CONTAINER"; else IFS=$'\t' read -r current_container_id current_state current_ready current_restart <<<"$status"; if [ -z "$current_container_id" ]; then failure_reason="selected container의 current containerID가 비어 있음 container=$CONTAINER"; elif [ "$current_container_id" != "$expected_container_id" ]; then failure_reason="containerID mismatch selected=$expected_container_id current=$current_container_id container=$CONTAINER"; else UID_READY=true; CURRENT_POD_UID="$current_uid"; CURRENT_CONTAINER_ID="$current_container_id"; CURRENT_CONTAINER_STATE="$current_state"; CURRENT_CONTAINER_READY="$current_ready"; CURRENT_CONTAINER_RESTART_COUNT="$current_restart"; EVIDENCE_READY=true; printf 'CONTAINER_EVIDENCE_READY=true pod_uid=%s container=%s container_id=%s status=%s ready=%s restart=%s\n' "$current_uid" "$CONTAINER" "$current_container_id" "$current_state" "$current_ready" "$current_restart"; return 0; fi; fi; fi; SELECTION_READY=false; EVIDENCE_READY=false; AUTO_READY=false; unset POD_JSON CONTAINER_ID CURRENT_CONTAINER_ID CURRENT_CONTAINER_STATE CURRENT_CONTAINER_READY CURRENT_CONTAINER_RESTART_COUNT; printf '중단: %s; selection/evidence gate를 닫고 자동수집부터 재시작한다.\n' "$failure_reason" >&2; return 1; }`

`kubectl(){ if [ "${1:-}" = exec ] || [ "${1:-}" = logs ]; then container_evidence_gate || return 1; fi; command kubectl "$@"; }`

`ssh(){ case "$*" in *journalctl*) container_evidence_gate || return 1;; esac; command ssh "$@"; }`

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | 같은 Pod UID의 `Warning Unhealthy` Event message에 `Readiness probe failed:`와 실제 suffix가 있고 대상 container를 확인할 수 있는 경우 |
| 적용 | readiness probe의 HTTP·TCP·exec·gRPC target, path·port·scheme, timeout·threshold, application 응답, kubelet 실행 결과를 분리하는 경우 |
| 제외 | `Ready=False`·`ContainersReady=False`만 있고 suffix가 없으면 [[16. Pod가 Running이지만 Ready가 아닌 경우#진입 판단|aggregate Ready·readinessGate·EndpointSlice 진단]]으로 이동한다. `Liveness probe failed`, `Killing`, `Startup probe failed`가 직접 보이면 각각 [[20. Pod liveness probe가 실패하는 경우]], [[21. Pod startup probe가 실패하는 경우]]로 이동한다. OOMKilled·Evicted·runtime 오류가 먼저면 해당 원인 런북으로 이동한다. |

검색 문자열: `Readiness probe failed`, `Warning Unhealthy`, `HTTP probe failed with statuscode`, `dial tcp`, `connection refused`, `context deadline exceeded`, `command`, `rpc error`, `Liveness probe failed`, `Startup probe failed`

readiness 실패는 kubelet이 container를 계속 실행하면서 container `ready=false`와 Pod `Ready=False`에 영향을 주는 신호다. container kill·restart의 신호가 아니며, `Running`·`Ready=False`·probe 한 번의 성공은 application 또는 실제 Service 요청 정상의 증거가 아니다.

## 최초 확인

실행 경로는 `작업 host → kubectl client → API server → 대상 node/kubelet → Pod/container 상태와 Event`다. `kubectl` API server 접근 성공은 kubelet·runtime·application 접근 성공을 보장하지 않는다. `describe`는 상태와 Event의 넓은 읽기이며, 아래 명시적 Event 조회는 현재 Pod UID와 `Unhealthy`로 범위를 제한한다.

**Pod 상태와 spec 확인 — 성공 gate를 유지하는 한 줄**

`DESCRIBE_READY=false; if [ "$SELECTION_READY" != true ]; then printf '%s\n' '중단: SELECTION_READY가 아니다.' >&2; elif pod_uid_gate && kubectl get pod "$POD" -n "$NS" -o wide && kubectl describe pod "$POD" -n "$NS"; then DESCRIBE_READY=true; printf 'DESCRIBE_READY=true pod=%s uid=%s container=%s container_id=%s\n' "$POD" "$POD_UID" "$CONTAINER" "$CONTAINER_ID"; else printf '%s\n' '중단: 현재 Pod 상태 또는 describe 조회 실패/UID mismatch' >&2; fi`

성공 gate는 출력의 Pod UID가 자동 수집한 `$POD_UID`와 같고, 대상 container의 `State`, `Last State`, `Restart Count`, probe 설정을 확인할 수 있는 것이다. UID가 다르면 Pod 이름 재사용으로 판단하고 자동 수집부터 다시 한다.

**UID 제한 Event 한 번 조회 — message와 실제 시각을 보존하는 한 줄**

`EVENT_READY=false; EVENT_OUTPUT=''; if [ "$DESCRIBE_READY" != true ]; then printf '%s\n' '중단: DESCRIBE_READY가 아니다.' >&2; elif pod_uid_gate && EVENT_OUTPUT="$(kubectl get events -n "$NS" --field-selector "involvedObject.kind=Pod,involvedObject.name=$POD,involvedObject.uid=$POD_UID,reason=Unhealthy" --sort-by=.metadata.creationTimestamp -o custom-columns='UID:.involvedObject.uid,REASON:.reason,COUNT:.count,CREATED:.metadata.creationTimestamp,FIRST:.firstTimestamp,LAST:.lastTimestamp,EVENT-TIME:.eventTime,SERIES-LAST:.series.lastObservedTime,MESSAGE:.message')" && [ -n "$EVENT_OUTPUT" ]; then printf '%s\n' "$EVENT_OUTPUT"; if grep -Fq 'Readiness probe failed:' <<<"$EVENT_OUTPUT"; then EVENT_READY=true; printf 'EVENT_READY=true pod_uid=%s\n' "$POD_UID"; else printf '%s\n' '중단: Event 조회는 성공했지만 readiness failure suffix가 없음; Ready=False·다른 probe·selector 불일치를 분기' >&2; fi; else printf '%s\n' '중단: UID 제한 Event API 실패 또는 빈 결과; 정상·오류 없음으로 해석하지 않음' >&2; fi`

Event에서 첫 `Readiness probe failed:` 뒤 suffix, 대상 container, 실제로 채워진 `CREATED`·`FIRST`·`LAST`·`EVENT-TIME`·`SERIES-LAST`와 `COUNT`를 기록한다. 빈 Event는 정상이나 실패 없음이 아니다. 보존 기간 만료, reason·UID selector 불일치, 권한, API 오류일 수 있으므로 `EVENT_READY=true`라는 조회 성공과 probe 증거 존재를 분리한다. `failureThreshold * periodSeconds`는 대략적인 연속 실패 구간일 뿐 traffic 제외 시각이 아니다.

## 관측별 진단 경로

| 지금 보이는 것 | 먼저 볼 것 | 그다음 어디를 볼지 | 상세 절 |
|---|---|---|---|
| HTTP status, timeout, connection refused | HTTP path·port·scheme·host와 application bind | application log → container 내부 path → kubelet/node | [[#HTTP probe와 application 응답|HTTP]] |
| TCP connect 오류 | 숫자·named port와 실제 listener | application bind → Pod IP·NetworkPolicy·kubelet | [[#TCP probe와 listener|TCP]] |
| exec exit·timeout | exec binary·argv·exit code·파일 권한 | image PATH·resource·application 초기화 | [[#exec probe binary와 timeout|exec]] |
| gRPC 오류 | 숫자 port·health service·1.26 feature gate | Pod IP의 gRPC Health Checking Protocol → kubelet | [[#gRPC probe|gRPC]] |
| probe 성공 후 EndpointSlice 또는 실제 요청 실패 | Pod Ready와 Service endpoint의 UID·시각 | aggregate Ready와 Service endpoint canonical 절 | [[#Service EndpointSlice와 실제 요청으로 이관|이관]] |

이 표는 원인을 확정하지 않는 길 안내다. 한 hop의 성공은 다음 hop과 application 정상의 증거가 아니다.

### Probe target과 port 관계

진입 증거는 Event suffix가 있고 자동 수집한 동일 UID·container가 선택된 경우다. 필수값은 `$CONTAINER`와 `$POD_JSON`에서 읽는 probe field, port 선언 관계다. API server에서 대상 Pod의 probe type·target·timing과 container port를 같은 읽기 범위로 확인한다.

`TARGET_READY=false; unset PROBE_SCHEME PROBE_PATH PROBE_HOST PROBE_PATH_HAS_QUERY HTTP_HEADER_COUNT HTTP_HEADER_NAMES; if [ "$EVENT_READY" != true ] || [ "$SELECTION_READY" != true ]; then printf '%s\n' '중단: Event와 container 선택 gate가 아니다.' >&2; elif TARGET_OUTPUT="$(jq -r --arg c "$CONTAINER" '.spec.containers[] | select(.name==$c) | "container=\(.name) HTTP=\(.readinessProbe.httpGet.host // "-")/\((.readinessProbe.httpGet.path // "-") | split("?")[0])/\(.readinessProbe.httpGet.port // "-")/\(.readinessProbe.httpGet.scheme // "-") TCP=\(.readinessProbe.tcpSocket.host // "-")/\(.readinessProbe.tcpSocket.port // "-") exec_binary=\(.readinessProbe.exec.command[0] // "-") exec_arg_count=\((.readinessProbe.exec.command // [])|length) gRPC=\(.readinessProbe.grpc.port // "-")/\(.readinessProbe.grpc.service // "-") timing=\(.readinessProbe.initialDelaySeconds // 0),\(.readinessProbe.timeoutSeconds // 1),\(.readinessProbe.periodSeconds // 10),\(.readinessProbe.failureThreshold // 3),\(.readinessProbe.successThreshold // 1) ports=\([.ports[]? | ((.name // "unnamed") + ":" + (.containerPort|tostring))] | join(",") // "없음")"' <<<"$POD_JSON")" && [ -n "$TARGET_OUTPUT" ]; then PROBE_SCHEME="$(jq -r --arg c "$CONTAINER" '.spec.containers[] | select(.name==$c) | .readinessProbe.httpGet.scheme // empty' <<<"$POD_JSON")"; PROBE_PATH="$(jq -r --arg c "$CONTAINER" '.spec.containers[] | select(.name==$c) | (.readinessProbe.httpGet.path // "") | split("?")[0]' <<<"$POD_JSON")"; PROBE_PATH_HAS_QUERY="$(jq -r --arg c "$CONTAINER" '.spec.containers[] | select(.name==$c) | (.readinessProbe.httpGet.path // "") | contains("?")' <<<"$POD_JSON")"; PROBE_HOST="$(jq -r --arg c "$CONTAINER" '.spec.containers[] | select(.name==$c) | .readinessProbe.httpGet.host // empty' <<<"$POD_JSON")"; HTTP_HEADER_COUNT="$(jq -r --arg c "$CONTAINER" '[.spec.containers[] | select(.name==$c) | .readinessProbe.httpGet.httpHeaders[]?.name | select(type=="string")] | length' <<<"$POD_JSON")"; HTTP_HEADER_NAMES="$(jq -r --arg c "$CONTAINER" '[.spec.containers[] | select(.name==$c) | .readinessProbe.httpGet.httpHeaders[]?.name | select(type=="string")] | unique | if length==0 then "-" else join(",") end' <<<"$POD_JSON")"; TARGET_READY=true; export PROBE_SCHEME PROBE_PATH PROBE_HOST PROBE_PATH_HAS_QUERY HTTP_HEADER_COUNT HTTP_HEADER_NAMES; printf '%s\n' "$TARGET_OUTPUT"; printf 'TARGET_READY=true scheme=%s path=%s query_present=%s host=%s http_headers_count=%s http_header_names=%s\n' "${PROBE_SCHEME:--}" "${PROBE_PATH:--}" "${PROBE_PATH_HAS_QUERY:-false}" "${PROBE_HOST:--}" "$HTTP_HEADER_COUNT" "$HTTP_HEADER_NAMES"; else printf '%s\n' '중단: 선택 container의 readinessProbe 또는 target field가 현재 spec에서 확인되지 않음' >&2; fi`

성공 gate는 target 유형과 container port 관계를 사람이 비교할 수 있게 출력하는 것이다. named port는 이후 `PORT_READY`에서 같은 container의 단일 선언으로 해석한다. `containerPort` 선언은 process listener·bind 주소·HTTP protocol·Service endpoint를 보장하지 않는다. probe field가 비거나 후보가 둘 이상이면 target을 추측하지 않고 manifest owner에게 이관한다.

**port 후보 해석 — 숫자와 named port를 섞지 않는 한 줄**

`PORT_READY=false; unset PROBE_PORT_RAW PROBE_PORT; if [ "$TARGET_READY" != true ]; then printf '%s\n' '중단: TARGET_READY가 아니다.' >&2; elif PROBE_PORT_RAW="$(jq -r --arg c "$CONTAINER" '.spec.containers[] | select(.name==$c) | (.readinessProbe.httpGet.port // .readinessProbe.tcpSocket.port // .readinessProbe.grpc.port // empty)' <<<"$POD_JSON")" && [ -n "$PROBE_PORT_RAW" ]; then if [[ "$PROBE_PORT_RAW" =~ ^[0-9]+$ ]]; then PROBE_PORT="$PROBE_PORT_RAW"; else PORT_MATCHES="$(jq -r --arg c "$CONTAINER" --arg p "$PROBE_PORT_RAW" '[.spec.containers[] | select(.name==$c) | .ports[]? | select(.name==$p) | .containerPort] | if length==1 then .[0]|tostring else empty end' <<<"$POD_JSON")"; [ -n "$PORT_MATCHES" ] && PROBE_PORT="$PORT_MATCHES"; fi; if [[ "${PROBE_PORT:-}" =~ ^[0-9]+$ ]] && (( PROBE_PORT >= 1 && PROBE_PORT <= 65535 )); then PORT_READY=true; export PROBE_PORT; printf 'PORT_READY=true raw=%s resolved=%s container=%s\n' "$PROBE_PORT_RAW" "$PROBE_PORT" "$CONTAINER"; else printf '중단: probe port가 숫자 또는 단일 named port로 해석되지 않음 raw=%s\n' "$PROBE_PORT_RAW" >&2; unset PROBE_PORT; fi; else printf '%s\n' '중단: probe port가 비어 있음' >&2; fi`

빈 port 출력은 field 부재 또는 현재 spec/API 변형일 수 있고 listener 없음이나 정상 port를 뜻하지 않는다. `PORT_READY=true`도 실제 process listen을 보장하지 않으므로 HTTP·TCP 분기에서 별도 application gate를 둔다.

### HTTP probe와 application 응답

진입 증거는 Event suffix에 HTTP status, timeout, refused 중 하나가 있고 `$PORT_READY=true`인 경우다. `$START_RFC3339`는 장애 결정 시각보다 조금 앞선 UTC 운영자 선택값이며, same Bash에서 한 번만 등록한다.

`START_RFC3339='PASTE_START_RFC3339_HERE'; TIME_READY=false; START_EPOCH=''; if [ "$PORT_READY" != true ]; then printf '%s\n' '중단: PORT_READY가 아니다.' >&2; elif [[ "$START_RFC3339" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] && START_EPOCH="$(date -u -d "$START_RFC3339" +%s 2>/dev/null)" && [ -n "$START_EPOCH" ]; then TIME_READY=true; export START_RFC3339 START_EPOCH; printf 'TIME_READY=true start_utc=%s epoch=%s pod_uid=%s container_id=%s\n' "$START_RFC3339" "$START_EPOCH" "$POD_UID" "$CONTAINER_ID"; else printf '중단: START_RFC3339 형식 또는 UTC 시각이 유효하지 않음\n' >&2; fi`

`logs_filtered(){ local mode="$1" pattern="$2" log_file producer_rc filter_output filter_rc; if [ "$TIME_READY" != true ] || [ "$SELECTION_READY" != true ] || ! pod_uid_gate; then printf '%s\n' '중단: log 시간·container 선택·UID gate가 아니다.' >&2; return 1; fi; log_file="$(mktemp)"; if ! container_evidence_gate; then rm -f "$log_file"; return 1; fi; if [ "$mode" = previous ]; then kubectl logs "$POD" -n "$NS" -c "$CONTAINER" --previous --timestamps --since-time="$START_RFC3339" --tail=200 >"$log_file"; else kubectl logs "$POD" -n "$NS" -c "$CONTAINER" --timestamps --since-time="$START_RFC3339" --tail=200 >"$log_file"; fi; producer_rc=$?; LOG_PRODUCER_RC="$producer_rc"; if [ "$producer_rc" -ne 0 ]; then printf 'logs producer 실패 rc=%s mode=%s pod_uid=%s container_id=%s\n' "$producer_rc" "$mode" "$POD_UID" "$CONTAINER_ID" >&2; rm -f "$log_file"; return "$producer_rc"; fi; filter_output="$(grep -E -i -C 3 "$pattern" "$log_file")"; filter_rc=$?; LOG_FILTER_RC="$filter_rc"; if [ "$filter_rc" -eq 0 ]; then printf '%s\n' "$filter_output"; elif [ "$filter_rc" -eq 1 ]; then printf 'logs filter no-match producer_rc=0 filter_rc=1 mode=%s pod_uid=%s container_id=%s\n' "$mode" "$POD_UID" "$CONTAINER_ID" >&2; else printf 'logs filter 실패 producer_rc=0 filter_rc=%s mode=%s\n' "$filter_rc" "$mode" >&2; rm -f "$log_file"; return "$filter_rc"; fi; rm -f "$log_file"; return 0; }`

실행 경로는 `작업 host → API server → kubelet/node → runtime → container network namespace → 127.0.0.1 또는 Pod IP listener → HTTP/HTTPS application`이다. `127.0.0.1`은 exec를 수행한 container network namespace의 loopback이며 node나 Service 주소가 아니다. `host`가 비어 있으면 kubelet은 Pod IP를 대상으로 하며, Service DNS를 probe target으로 가정하지 않는다.

**현재 container 로그 bounded 수집 — stream 준비와 결과를 분리하는 한 줄**

`LOG_READY=false; LOG_PRODUCER_RC=''; LOG_FILTER_RC=''; if logs_filtered current 'readiness|health|probe|listen|bind|timeout|refused|503|404|401|403|dependency|database|queue|upstream'; then LOG_READY=true; printf 'LOG_STREAM_READY=true producer_rc=%s filter_rc=%s pod_uid=%s container_id=%s window_start=%s\n' "$LOG_PRODUCER_RC" "$LOG_FILTER_RC" "$POD_UID" "$CONTAINER_ID" "$START_RFC3339"; else printf '중단: logs stream producer/filter 실패 producer_rc=%s filter_rc=%s pod_uid=%s container_id=%s\n' "$LOG_PRODUCER_RC" "$LOG_FILTER_RC" "$POD_UID" "$CONTAINER_ID" >&2; fi`

`kubectl logs` 성공은 로그 stream을 읽었다는 범위만 보장하고 application route 정상이나 probe 성공을 보장하지 않는다. 필터가 비면 같은 시간창의 비식별화된 마지막 50행을 제한적으로 재확인한다. `restartCount`가 1 이상이거나 `Last State`가 이전 instance를 가리킬 때만 `--previous`를 사용하며, 이전 container ID와 현재 ID를 섞지 않는다. Secret·token·개인키·개인정보가 보이면 보존을 중단한다.

**필터가 비었을 때 current tail 재확인 — bounded 한 줄**

`if [ "$LOG_READY" != true ]; then printf '%s\n' '중단: LOG_READY가 아니다.' >&2; elif pod_uid_gate && container_evidence_gate && kubectl logs "$POD" -n "$NS" -c "$CONTAINER" --timestamps --since-time="$START_RFC3339" --tail=50; then printf 'current tail stream 성공 producer_rc=0 pod_uid=%s container_id=%s window_start=%s\n' "$POD_UID" "$CONTAINER_ID" "$START_RFC3339"; else printf '%s\n' 'current tail producer 실패 또는 UID/containerID gate mismatch: 로그 계층 오류를 확인하고 자동수집부터 재시작' >&2; fi`

**restart가 있을 때 previous 로그 bounded 재확인 — 한 줄**

`PREVIOUS_READY=false; RESTART_COUNT=''; if [ "$LOG_READY" != true ]; then printf '%s\n' '중단: LOG_READY가 아니다.' >&2; elif RESTART_COUNT="$(jq -r --arg c "$CONTAINER" '[.status.containerStatuses[]? | select(.name==$c) | .restartCount] | .[0] // empty' <<<"$POD_JSON")" && [ -n "$RESTART_COUNT" ] && [ "$RESTART_COUNT" -gt 0 ] && pod_uid_gate && container_evidence_gate && kubectl logs "$POD" -n "$NS" -c "$CONTAINER" --previous --timestamps --since-time="$START_RFC3339" --tail=50; then PREVIOUS_READY=true; printf 'previous tail stream 성공 producer_rc=0 pod_uid=%s container_id=%s window_start=%s\n' "$POD_UID" "$CONTAINER_ID" "$START_RFC3339"; else printf '%s\n' '중단: restartCount가 0·비어 있거나 previous producer 실패/UID/containerID gate mismatch' >&2; fi`

HTTP status 해석은 200 이상 400 미만만 probe 성공 범위다. `404`는 path·route 후보, `401/403`은 인증·인가 계약, `5xx`는 application/dependency 후보, `connection refused`는 listener·Pod IP 경로 후보, timeout은 listener 이후의 application·node·resource·network 경로 후보다. HTTPS probe의 certificate 검증 동작과 Service TLS 정상은 별도이며 TLS 검증 우회 옵션을 사용하지 않는다.

**container 내부 보조 HTTP 확인 — transport와 HTTP status를 따로 보는 한 줄**

`HTTP_OBS_READY=false; if [ "$PORT_READY" != true ] || [ "$LOG_READY" != true ] || [ "$TARGET_READY" != true ]; then printf '%s\n' '중단: PORT_READY·LOG_READY·TARGET_READY가 아니다.' >&2; elif ! jq -e --arg c "$CONTAINER" 'any(.spec.containers[]?; .name==$c and .readinessProbe.httpGet != null)' <<<"$POD_JSON" >/dev/null; then printf '%s\n' '중단: selected readinessProbe.httpGet가 없어 localhost HTTP 보조 관측을 실행하지 않음; TCP/gRPC/exec target은 해당 경로로 이관' >&2; elif [ "${HTTP_HEADER_COUNT:-0}" -gt 0 ] || [ "${PROBE_PATH_HAS_QUERY:-false}" = true ]; then printf '이관: httpHeaders names=%s count=%s 또는 query path가 있어 localhost HTTP 동등 관측을 실행하지 않고 application owner/kubelet evidence로 이관한다. query_present=%s\n' "${HTTP_HEADER_NAMES:--}" "${HTTP_HEADER_COUNT:-0}" "${PROBE_PATH_HAS_QUERY:-false}" >&2; elif [ -n "$PROBE_HOST" ]; then printf '중단: PROBE_HOST=%s가 설정되어 localhost HTTP 보조 관측을 중단하고 kubelet Pod IP/custom host 경로로 이관한다.\n' "$PROBE_HOST" >&2; elif pod_uid_gate && kubectl exec "$POD" -n "$NS" -c "$CONTAINER" -- sh -c 'scheme="$1"; port="$2"; path="$3"; if command -v curl >/dev/null 2>&1; then rc=0; out="$(curl --noproxy "*" -sS -o /dev/null -w "transport=ok http_status=%{http_code} time_total=%{time_total}" --connect-timeout 3 --max-time 5 "${scheme}://127.0.0.1:${port}${path}")" || rc=$?; printf "%s curl_rc=%s\n" "$out" "$rc"; [ "$rc" -eq 0 ]; elif command -v wget >/dev/null 2>&1; then if wget -qO /dev/null -T 3 "${scheme}://127.0.0.1:${port}${path}"; then printf "%s\n" "transport=ok http_status=unreported"; else printf "%s\n" "transport=failed http_status=000" >&2; exit 1; fi; else printf "%s\n" "probe_tool_missing=curl,wget" >&2; exit 127; fi' sh "${PROBE_SCHEME:-http}" "$PROBE_PORT" "${PROBE_PATH:-/}"; then HTTP_OBS_READY=true; printf 'HTTP_OBS_READY=true pod_uid=%s container_id=%s\n' "$POD_UID" "$CONTAINER_ID"; else printf '%s\n' 'HTTP 관측 실패: container 도구·loopback listener·transport 계층을 다음 분기로 확인' >&2; fi`

이 결과가 성공해도 localhost listener와 transport가 응답한 것뿐이며 kubelet node의 Pod IP probe, 인증 계약, Service 요청 성공을 보장하지 않는다. localhost 성공과 Event timeout/refused가 다르면 kubelet·Pod IP·NetworkPolicy·CNI·node 경로로, route가 `503`이면 health 계약과 dependency owner로 이동한다. 응답 body·header는 저장하지 않는다.

### TCP probe와 listener

진입 증거는 `dial tcp`, `connection refused`, timeout 또는 TCP target이 Event suffix에 있고 `$PORT_READY=true`인 경우다. 필요한 값은 API에서 해석한 `$PROBE_PORT`와 자동 수집한 Pod UID·node·container ID다.

연결 경로는 `작업 host → API server → kubelet/node → Pod IP:$PROBE_PORT → TCP listener → application process`다. Service port·Service DNS·containerPort 선언은 이 경로의 remote endpoint와 같지 않다.

**container listener bounded 확인 — 도구 실패를 대체 경로로 숨기지 않는 한 줄**

`if [ "$PORT_READY" != true ]; then printf '%s\n' '중단: PORT_READY가 아니다.' >&2; elif kubectl exec "$POD" -n "$NS" -c "$CONTAINER" -- sh -c 'if command -v ss >/dev/null 2>&1; then ss -lnt; elif command -v netstat >/dev/null 2>&1; then netstat -lnt; else printf "%s\n" "listener_tool_missing=ss,netstat" >&2; exit 127; fi'; then printf 'listener stream 성공 pod_uid=%s container_id=%s port=%s\n' "$POD_UID" "$CONTAINER_ID" "$PROBE_PORT"; else printf '%s\n' 'listener 조회 실패: container 도구 또는 exec/runtime 계층으로 이관; 다른 도구로 실패를 덮지 않음' >&2; fi`

listener가 없으면 application 초기화·bind owner로, listener가 있는데 kubelet만 refused/timeout이면 Pod IP·NetworkPolicy·CNI·node kubelet 경로로 이동한다. TCP 연결 성공은 HTTP/gRPC 기능이나 실제 Service 요청 성공을 보장하지 않는다. 빈 listener 출력은 listener 없음, 권한, namespace 도구 제약을 구분할 추가 증거가 필요한 결과다.

### exec probe binary와 timeout

진입 증거는 Event suffix에 `command ... exited`, `no such file`, `permission denied`, exec timeout이 있고 target command가 확인된 경우다. 필수값은 선택 container의 `readinessProbe.exec.command`와 `$START_RFC3339`; command 전체를 임의 실행하지 않는다.

실행 경로는 `작업 host → API server → kubelet → runtime exec stream → container process namespace → exec binary`다. Pod IP·Service DNS·HTTP listener는 exec probe의 경로가 아니다.

**현재 image의 첫 binary 존재만 확인 — side effect 없는 한 줄**

`if [ "$TARGET_READY" != true ] || [ "$TIME_READY" != true ]; then printf '%s\n' '중단: TARGET_READY 또는 TIME_READY가 아니다.' >&2; elif EXEC_BINARY="$(jq -r --arg c "$CONTAINER" '.spec.containers[] | select(.name==$c) | .readinessProbe.exec.command[0] // empty' <<<"$POD_JSON")" && [ -n "$EXEC_BINARY" ]; then if kubectl exec "$POD" -n "$NS" -c "$CONTAINER" -- sh -c 'command -v "$1" >/dev/null 2>&1' sh "$EXEC_BINARY"; then printf 'exec_binary=present pod_uid=%s container_id=%s binary=%s\n' "$POD_UID" "$CONTAINER_ID" "$EXEC_BINARY"; else printf 'exec_binary 확인 실패: PATH·image·runtime exec 계층을 확인 binary=%s\n' "$EXEC_BINARY" >&2; fi; else printf '%s\n' '중단: exec binary가 spec에서 확인되지 않음' >&2; fi`

`ExecProbeTimeout`은 Kubernetes 1.26에서 GA·기본 활성화이므로 timeout을 무시한다고 가정하지 않는다. binary 존재는 argv·working directory·exit code 0·mount·resource 상태를 보장하지 않는다. command가 없거나 빈 결과면 API field 부재와 대상 유형 불일치를 먼저 확인하고, shell이 없는 image에서는 image/manifest owner에게 이관한다.

### gRPC probe

진입 증거는 `rpc error` 또는 gRPC health 오류가 같은 UID의 readiness Event에 있고 숫자 port·service가 spec에서 확인된 경우다. Kubernetes 1.26의 `GRPCContainerProbe`는 Beta·기본 활성화지만 kubelet/API server feature gate와 API 수용 여부를 확인하기 전에는 기본 기능으로 단정하지 않는다.

경로는 `작업 host에서 API server로 읽기 → kubelet/node → Pod IP:$PROBE_PORT → gRPC Health Checking Protocol listener`다. built-in probe는 named port·custom host·TLS/authentication parameter를 사용하지 않는다.

`kubectl get --raw`로 feature gate를 추측하거나 TLS를 우회하지 않는다. API field가 거부됐거나 gate가 꺼졌다면 HTTP/TCP/exec로 임의 변경하지 않고 application owner와 cluster administrator에게 UID·UTC 시각·suffix를 이관한다. `Unavailable`, `DeadlineExceeded`, `NOT_SERVING`은 모두 failure 후보이며 application health service 미구현과 network 경로를 분리한다. 빈 gRPC 결과는 metric 부재나 field 부재와 오류를 구분할 수 없으므로 정상으로 기록하지 않는다.

### kubelet의 실제 probe 실행 결과

진입 증거는 container 내부 localhost 결과와 Event suffix가 다르거나, 여러 Pod에서 같은 UTC 창의 probe timeout이 함께 보이는 경우다. `$START_JOURNAL`과 `$END_JOURNAL`은 node 접근 승인과 실제 kubelet unit·journal 위치를 확인한 뒤 운영자가 한 번 선택한다.

노드 경로는 `작업 host → 승인된 node 접속 → systemd journal → kubelet → Pod IP/container runtime → application`이다. journal의 node local 주소와 Pod IP, probe의 remote port를 섞지 않는다.

`NODE_HOST`는 작업 PC에서 접속할 승인된 remote host이며 Kubernetes `$NODE`의 SSH 별칭으로 자동 추측하지 않는다. SSH gate가 remote `hostname`을 Kubernetes `$NODE`와 정확히 대조한 뒤에만 remote journal을 실행한다. 대조 실패·SSH host key/권한 실패·hostname mapping 불일치는 node owner에게 이관하고 작업 PC의 local journal을 실행하지 않는다.

`NODE_HOST='PASTE_NODE_HOST_HERE'; NODE_SSH_READY=false; REMOTE_NODE=''; if [ "$EVENT_READY" != true ]; then printf '%s\n' '중단: EVENT_READY가 아니다.' >&2; elif [ -z "$NODE_HOST" ]; then printf '%s\n' '중단: NODE_HOST를 선택한다.' >&2; elif pod_uid_gate && REMOTE_NODE="$(ssh -o BatchMode=yes -o ConnectTimeout=10 "$NODE_HOST" hostname 2>&1)"; then REMOTE_NODE="${REMOTE_NODE//$'\r'/}"; if [ "$REMOTE_NODE" = "$NODE" ]; then NODE_SSH_READY=true; printf 'NODE_SSH_READY=true kubernetes_node=%s remote_node=%s node_host=%s pod_uid=%s\n' "$NODE" "$REMOTE_NODE" "$NODE_HOST" "$POD_UID"; else printf '중단: remote identity mismatch kubernetes_node=%s remote_node=%s node_host=%s\n' "$NODE" "$REMOTE_NODE" "$NODE_HOST" >&2; fi; else printf '중단: SSH remote identity 조회 실패 node_host=%s; local journal을 실행하지 않음\n' "$NODE_HOST" >&2; fi`

`START_JOURNAL='PASTE_START_JOURNAL_HERE'; END_JOURNAL='PASTE_END_JOURNAL_HERE'; JOURNAL_READY=false; START_JOURNAL_EPOCH=''; END_JOURNAL_EPOCH=''; if [ "$NODE_SSH_READY" != true ]; then printf '%s\n' '중단: NODE_SSH_READY가 아니다.' >&2; elif [[ "$START_JOURNAL" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}\ [0-9]{2}:[0-9]{2}:[0-9]{2}\ UTC$ ]] && [[ "$END_JOURNAL" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}\ [0-9]{2}:[0-9]{2}:[0-9]{2}\ UTC$ ]] && START_JOURNAL_EPOCH="$(date -u -d "$START_JOURNAL" +%s 2>/dev/null)" && END_JOURNAL_EPOCH="$(date -u -d "$END_JOURNAL" +%s 2>/dev/null)" && [ -n "$START_JOURNAL_EPOCH" ] && [ -n "$END_JOURNAL_EPOCH" ] && (( START_JOURNAL_EPOCH < END_JOURNAL_EPOCH )); then if REMOTE_JOURNAL_TOOLS="$(ssh -o BatchMode=yes -o ConnectTimeout=10 "$NODE_HOST" 'command -v journalctl >/dev/null 2>&1 && sudo -n journalctl --version >/dev/null 2>&1' 2>&1)"; then JOURNAL_READY=true; printf 'JOURNAL_READY=true remote_node=%s node_host=%s window=%s..%s\n' "$REMOTE_NODE" "$NODE_HOST" "$START_JOURNAL" "$END_JOURNAL"; else printf '중단: remote journalctl/sudo 전제 실패 output=%s\n' "$REMOTE_JOURNAL_TOOLS" >&2; fi; else printf '%s\n' '중단: journal 형식 또는 시간 순서가 유효하지 않음 start=YYYY-MM-DD HH:MM:SS UTC end=YYYY-MM-DD HH:MM:SS UTC, start<end' >&2; fi`

`remote_journal_filtered(){ local unit="$1" pattern="$2" remote_output producer_rc filter_output filter_rc; JOURNAL_FILTER_RC=0; if [ "$NODE_SSH_READY" != true ] || [ "$JOURNAL_READY" != true ]; then printf '%s\n' '중단: remote journal gate가 아니다.' >&2; return 1; elif remote_output="$(ssh -o BatchMode=yes -o ConnectTimeout=10 "$NODE_HOST" "sudo journalctl -u $unit --since \"$START_JOURNAL\" --until \"$END_JOURNAL\" --no-pager --lines=2000" 2>&1)"; then producer_rc=0; else producer_rc=$?; fi; JOURNAL_PRODUCER_RC="$producer_rc"; if [ "$producer_rc" -ne 0 ]; then printf 'remote journal producer 실패 rc=%s unit=%s remote_node=%s\n' "$producer_rc" "$unit" "$REMOTE_NODE" >&2; return "$producer_rc"; elif [ -z "$remote_output" ]; then printf 'remote journal producer rc=0 records=empty unit=%s; 정상·오류 없음으로 해석하지 않음\n' "$unit" >&2; JOURNAL_FILTER_RC=1; return 0; else filter_output="$(printf '%s\n' "$remote_output" | grep -E -i -C 3 "$pattern")"; filter_rc=$?; JOURNAL_FILTER_RC="$filter_rc"; if [ "$filter_rc" -eq 0 ]; then printf '%s\n' "$filter_output"; elif [ "$filter_rc" -eq 1 ]; then printf 'remote journal filter no-match producer_rc=0 filter_rc=1 unit=%s pod_uid=%s\n' "$unit" "$POD_UID" >&2; else printf 'remote journal filter 실패 producer_rc=0 filter_rc=%s unit=%s\n' "$filter_rc" "$unit" >&2; return "$filter_rc"; fi; fi; }`

**승인된 node에서 bounded kubelet journal 읽기 — 한 줄**

`if [ "$JOURNAL_READY" != true ] || [ "$NODE_SSH_READY" != true ]; then printf '%s\n' '중단: JOURNAL_READY 또는 NODE_SSH_READY가 아니다.' >&2; elif remote_journal_filtered kubelet "$POD_UID|$POD|$CONTAINER|probe|readiness|unhealthy|timeout|refused|exec|grpc|http"; then if [ "$JOURNAL_FILTER_RC" -eq 1 ]; then printf 'kubelet journal filter no-match producer_rc=%s filter_rc=1 pod_uid=%s remote_node=%s\n' "$JOURNAL_PRODUCER_RC" "$POD_UID" "$REMOTE_NODE"; else printf 'kubelet journal stream 성공 producer_rc=%s filter_rc=%s pod_uid=%s remote_node=%s\n' "$JOURNAL_PRODUCER_RC" "$JOURNAL_FILTER_RC" "$POD_UID" "$REMOTE_NODE"; fi; else printf 'kubelet journal remote 수집 실패 producer_rc=%s filter_rc=%s pod_uid=%s remote_node=%s\n' "$JOURNAL_PRODUCER_RC" "$JOURNAL_FILTER_RC" "$POD_UID" "$REMOTE_NODE" >&2; fi`

`HTTP probe failed with statuscode: 503`은 route 응답과 health 계약을, `connection refused`는 Pod IP bind·NetworkPolicy·CNI를, 여러 Pod의 동일 timeout은 kubelet/node 부하 후보를 뜻한다. journal filter가 비어도 kubelet 정상은 보장하지 않는다. 실제 unit·로그 위치가 미확정이면 명령을 발명하지 않고 node owner에게 이관한다.

### Service EndpointSlice와 실제 요청으로 이관

readiness probe는 kubelet node에서 target으로 실행되고 실제 요청은 client→Service selector·port/targetPort→EndpointSlice→Pod IP listener를 거친다. probe 성공은 Pod aggregate Ready, `readinessGates`, EndpointSlice 포함, 실제 application 기능을 보장하지 않는다.

Service가 실제로 존재하고 승인된 요청 검증이 필요할 때만 `SERVICE`를 선택한다.

`SERVICE='PASTE_SERVICE_HERE'; SERVICE_INPUT_READY=false; if [ "$EVENT_READY" != true ]; then printf '%s\n' '중단: EVENT_READY가 아니다.' >&2; elif [ -n "$SERVICE" ]; then SERVICE_INPUT_READY=true; export SERVICE; printf 'SERVICE_INPUT_READY=true service=%s\n' "$SERVICE"; else printf '%s\n' '중단: SERVICE를 선택한다.' >&2; fi`

`service_relation_gate(){ local pod_json service_json endpoint_json labels cports target_port matches current_uid; SERVICE_READY=false; if [ "$SERVICE_INPUT_READY" != true ] || [ "$PORT_READY" != true ]; then printf '%s\n' '중단: SERVICE_INPUT_READY 또는 PORT_READY가 아니다.' >&2; elif ! pod_uid_gate; then printf '%s\n' '중단: Service 관계 확인 전 Pod UID gate 실패' >&2; elif pod_json="$(kubectl get pod "$POD" -n "$NS" -o json)" && service_json="$(kubectl get svc "$SERVICE" -n "$NS" -o json)" && endpoint_json="$(kubectl get endpointslice -n "$NS" -l "kubernetes.io/service-name=$SERVICE" -o json)"; then current_uid="$(jq -r '.metadata.uid // empty' <<<"$pod_json")"; labels="$(jq -c '.metadata.labels // {}' <<<"$pod_json")"; cports="$(jq -c --arg c "$CONTAINER" '[.spec.containers[] | select(.name==$c) | .ports[]?]' <<<"$pod_json")"; if [ "$current_uid" != "$POD_UID" ]; then printf '중단: Service 관계 Pod UID mismatch initial=%s current=%s\n' "$POD_UID" "$current_uid" >&2; elif ! jq -e --argjson labels "$labels" '(.spec.selector // {}) | to_entries as $entries | ($entries|length)>0 and all($entries[]; $labels[.key] == .value)' <<<"$service_json" >/dev/null; then printf '중단: Service selector가 현재 Pod labels와 일치하지 않음 service=%s pod_uid=%s\n' "$SERVICE" "$POD_UID" >&2; else target_port="$(jq -r --argjson probe "$PROBE_PORT" --argjson cports "$cports" '[.spec.ports[]? | (.targetPort // .port) as $target | if ($target|type)=="number" then select($target==$probe) | $target else select(any($cports[]?; .name==$target and .containerPort==$probe)) | ([$cports[]? | select(.name==$target) | .containerPort][0]) end] | unique | if length==1 then .[0]|tostring else empty end' <<<"$service_json")"; if [ -z "$target_port" ]; then printf '중단: Service targetPort와 선택 probe port 관계가 단일하게 확인되지 않음 service=%s probe_port=%s\n' "$SERVICE" "$PROBE_PORT" >&2; else matches="$(jq -r --arg uid "$POD_UID" --arg target "$target_port" '[.items[]? as $slice | $slice.endpoints[]? | select(.targetRef.uid==$uid) | $slice.ports[]? | select((.port|tostring)==$target) | "\($slice.metadata.uid)\t\(.targetRef.uid)\t\(.port)"] | unique[]?' <<<"$endpoint_json")"; if [ -z "$matches" ]; then printf '중단: EndpointSlice에 targetRef.uid=%s와 backend port=%s가 함께 없음\n' "$POD_UID" "$target_port" >&2; else printf 'SERVICE_UID=%s\nPOD_UID=%s\nSERVICE_SELECTOR=%s\nSERVICE_TARGET_PORT=%s\nEndpointSlice UID<TAB>targetRef UID<TAB>backend port:\n%s\n' "$(jq -r '.metadata.uid' <<<"$service_json")" "$POD_UID" "$(jq -c '.spec.selector' <<<"$service_json")" "$target_port" "$matches"; SERVICE_READY=true; fi; fi; fi; else printf '중단: Pod/Service/EndpointSlice API 조회 실패 service=%s\n' "$SERVICE" >&2; fi; }`

`if [ "$SERVICE_INPUT_READY" != true ]; then printf '%s\n' '중단: SERVICE_INPUT_READY가 아니다.' >&2; elif service_relation_gate; then printf 'SERVICE_READY=%s service=%s pod_uid=%s\n' "$SERVICE_READY" "$SERVICE" "$POD_UID"; else printf '%s\n' 'SERVICE_READY=false: selector·targetPort·EndpointSlice targetRef UID 관계를 승인하지 않음' >&2; fi`

성공 gate는 Service identity·selector·port가 출력되는 것이다. 실패·빈 결과·복수 후보이면 임의로 선택하지 않고 workload owner에게 확인한다. selector·EndpointSlice의 canonical 진단은 [[16. Pod가 Running이지만 Ready가 아닌 경우#3. Service·EndpointSlice 포함 여부와 실제 요청|16번 Service·EndpointSlice 절]]로 이관하며, probe 성공은 EndpointSlice 포함이나 실제 요청 성공을 보장하지 않는다.

## 제한적 복구와 안전 gate

probe target·path·port·scheme·command·timing 변경은 진단과 분리한다. 다음을 모두 만족하기 전에는 `patch`, `delete`, `rollout`, `restart`를 이 문서에서 실행하지 않는다.

- **Trigger:** 같은 Pod UID의 Event suffix와 application·kubelet 결과가 설정 오류 또는 측정된 startup 지연을 직접 가리킨다.
- **Authority:** workload owner와 application·probe·mesh/dependency 담당자, 변경 승인자가 확인됐다.
- **Scope:** 모든 replica의 endpoint·오류율·latency·dependency 영향과 rollout 범위를 기록했다.
- **Safety:** probe 삭제, `failureThreshold`·`timeoutSeconds`의 무작위 증가, 항상 성공하는 endpoint, NetworkPolicy 완화를 복구로 제시하지 않는다.
- **Stop:** 새 Warning, 같은 suffix 재발, 잘못된 endpoint 유입, dependency 오류·latency 증가가 보이면 중단하고 rollback 또는 owner에게 이관한다.
- **Rollback:** 승인된 이전 workload template/revision과 rollback artifact가 확인된 경우에만 같은 관리 경로로 되돌린다.
- **Verification:** 새 Pod의 이름과 UID를 다시 수집하고 suffix 중단, container·Pod Ready, readinessGate, EndpointSlice, 실제 요청과 핵심 지표를 역순으로 확인한다.

`Running` 또는 probe 한 번의 성공은 정상화가 아니다. 완화 성공과 근본 원인 해결을 별도로 기록한다.

## 정상화와 실제 서비스 검증

원인 경로를 역순으로 확인한다. application 기능·실제 요청 → HTTP/API 또는 protocol 결과 → process listener → Pod IP/kubelet 경로 → container/Pod identity·condition 순서다.

1. 같은 Pod UID에서 새 `Readiness probe failed:` suffix가 관찰 창 동안 반복되지 않는다.
2. 대상 container가 의도한 `Running` 상태이고 `restartCount`가 readiness 진단 때문에 증가하지 않는다.
3. Pod `Ready=True`, 필요한 replica/Ready 수, 새 Warning Event 부재를 확인한다. `Ready=True`는 실제 Service 기능을 보장하지 않는다.
4. Service가 있는 경우 selector·EndpointSlice의 대상 Pod UID·주소·port와 실제 요청 status·latency·핵심 기능을 승인된 절차로 확인한다.
5. 동일 오류가 재발하지 않는 bounded 관찰 창과 UTC 재평가 시각을 기록한다.

## Prometheus 빠른 관측

Prometheus endpoint와 실제 label 수집 여부가 확인된 경우에만 사용한다. 비표준 `prober_probe_total`의 `pod_uid` label은 해당 label이 실제 노출되는 경우에만 사용하고, KSM metric에는 표준 `uid` label을 사용한다. 두 metric의 label을 혼용하지 않는다. `POD_RE`는 자동으로 escape한 regex이며 문서에서 query 내부를 수정하지 않는다. 아래 생성 명령의 출력 한 줄만 Prometheus/Grafana에 붙여 넣는다.

**readiness probe 실패 PromQL 생성 — bounded 한 줄**

`if [ "$SELECTION_READY" != true ] || [ -z "${POD_RE:-}" ]; then printf '%s\n' '중단: SELECTION_READY 또는 POD_RE가 아니다.' >&2; else printf '%s\n' "sum by(namespace,pod,pod_uid,container)(increase(prober_probe_total{namespace=\"$NS\",pod=~\"$POD_RE\",pod_uid=\"$POD_UID\",container=\"$CONTAINER\",probe_type=\"Readiness\",result!=\"successful\"}[15m]))"; fi`

**container Ready=false PromQL 생성 — bounded 한 줄**

`if [ "$SELECTION_READY" != true ] || [ -z "${POD_RE:-}" ] || [ -z "${POD_UID:-}" ]; then printf '%s\n' '중단: SELECTION_READY·POD_RE 또는 POD_UID가 아니다.' >&2; else printf '%s\n' "kube_pod_container_status_ready{namespace=\"$NS\",pod=~\"$POD_RE\",uid=\"$POD_UID\",container=\"$CONTAINER\"} == 0"; fi`

쿼리 결과가 비면 정상·0·오류 없음으로 기록하지 않는다. metric 미수집, label 불일치, 조회 시간 범위, 권한·Prometheus query 실패를 나누고, `HTTP 401/403`, `5xx`, transport 실패와 빈 data를 구분한다. PromQL은 probe target·Event·application·kubelet 증거를 대신하지 않으며 Pod aggregate Ready·EndpointSlice·실제 서비스 정상화를 승인하지 않는다.

## 증거 보존과 미검증

UTC 관측 시각, namespace, Pod UID·node·phase·Pod IP, container·container ID, probe type·target·path·port·scheme·timing, Event UID·COUNT·시각·suffix, application·kubelet 로그의 bounded 시간 범위와 결정적 오류, Service·EndpointSlice·실제 요청 결과, 승인·변경·rollback·정상화 결과를 보존한다. Secret·token·인증서 개인키·개인정보·HTTP response body·전체 probe YAML과 민감한 exec argv는 저장하지 않는다.

Pod 내부 `sh`·curl·wget·ss·netstat, kubelet unit·journal 접근, CNI·NetworkPolicy·Service mesh, 외부 DB/API/queue health 계약과 서비스 지표는 환경별 미검증이다. Kubernetes Server와 `kubectl` 기준은 `1.26.x`다. `GRPCContainerProbe`는 1.26 Beta·기본 활성화지만 cluster feature gate와 API 수용 여부를 확인해야 한다.
