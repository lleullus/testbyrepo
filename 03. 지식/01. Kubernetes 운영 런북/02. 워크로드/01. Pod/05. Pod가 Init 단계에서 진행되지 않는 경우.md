# Pod가 Init 단계에서 진행되지 않는 경우

## 입력값과 빠른 수집

이 문서는 첫 미완료 Init이 다음 Init 또는 일반 container로 진행되지 않는 경우를 소유한다. 값은 최초 입력, API 확인 자동값, 계산 후보, 운영자 선택값으로 분류한다. 최초 입력은 namespace와 Pod뿐이다. Pod UID·node·phase·Pod 시작 시각·owner·Init 선언 순서·container ID·volume과 ConfigMap/Secret/PVC 참조 관계는 API가 자동 등록한다. 이름에서 만든 정규식은 계산 후보이며, 첫 미완료 Init은 선언 순서와 status를 이용해 계산한 후보다. resource 이름·로그 시각·일반 container·journal 범위·Deployment는 관측 후 운영자가 선택한다.

| 구분 | 값 | 출처와 유효성 gate |
|---|---|---|
| 최초 입력 | `NS`, `POD` | 승인된 namespace와 정확한 Pod 이름을 한 번 입력한다. |
| API 확인 자동값 | `POD_UID`, `NODE`, `PHASE`, `POD_START`, `OWNER`, `INIT_CONTAINER`, Init/일반 container 상태·restart·container ID, image·mount·PVC/ConfigMap/Secret 참조 | Pod API 호출과 세로 관계 출력이 모두 성공해야 등록한다. 복수 controller owner·빈 UID·출력 실패면 부분 등록하지 않는다. |
| 계산 후보 | `NS_RE`, `POD_RE`, 첫 미완료 Init, 생성 PromQL | API 등록값으로 계산하고 escape·bounded 출력 뒤에만 사용한다. 첫 미완료 Init은 선언 순서상 첫 non-success 상태다. |
| 운영자 선택값 | `START_RFC3339`, `REF_KIND`, `REF_NAME`, `REF_KEY`, `SERVICE`, `NETWORKPOLICY`, `JOURNAL_START`, `JOURNAL_END`, `NODE_HOST`, `CONTAINER`, `DEPLOYMENT`, `APPROVAL_ID`, `ROLLBACK_REVISION`, `INIT_IDEMPOTENT` | 오류 증거와 관계 출력에 맞는 값을 분기 직전에 선택한다. `NODE_HOST`는 node journal evidence 직전에 승인된 SSH 목적지로 선택한다. kind/name/key가 선택 Init의 실제 참조와 일치하지 않거나 side effect 멱등성·승인·rollback 근거가 없으면 중단한다. |

실행 host는 승인된 작업 PC 또는 bastion이며 모든 명령은 **같은 Bash 터미널**에서 실행한다. `NODE_HOST`는 승인된 SSH 목적지이고 Node API의 `spec.nodeName`이나 machineID를 대체하지 않는다. `kubectl` 명령의 hop은 실행 host → kubectl client → Kubernetes API server이며, Pod logs는 API server → 대상 node의 kubelet → CRI/runtime → container stream으로 이어진다. node evidence는 실행 host → `node_exec` → remote node Bash → `sudo`/journal 경계로 이어진다. 필수 도구는 `kubectl`, `jq`, `grep`, `sed`, `date`이고 namespace와 Pod read 권한이 필요하다. node journal을 선택한 경우에는 별도로 `ssh`, remote `journalctl`, remote `sudo`, 실제 kubelet unit 권한을 확인한다. 도구 확인·exact-name API·UID gate가 실패하면 다음 단계로 진행하지 않는다.

`journalctl`은 작업 PC의 network namespace에서 직접 실행하지 않는다. 같은 Bash에 등록한 `NODE_HOST`로 `node_exec`를 호출해 remote node에서 실행하며, `kubectl` API 성공은 kubelet·kernel journal 접근 성공을 보장하지 않는다.

**Bash와 필수 도구 확인 — 아래 한 줄 전체를 복사**

`TOOLS_READY=false; MISSING_TOOLS=''; TOOL=''; if [ -z "${BASH_VERSION:-}" ]; then printf '%s\n' '중단: Bash가 아니다. Bash 셸에서 다시 실행한다.' >&2; else for TOOL in kubectl jq grep sed date; do command -v "$TOOL" >/dev/null 2>&1 || MISSING_TOOLS="$MISSING_TOOLS $TOOL"; done; if [ -n "$MISSING_TOOLS" ]; then printf '중단: 없는 필수 도구=%s\n' "$MISSING_TOOLS" >&2; else TOOLS_READY=true; grep(){ command grep "$@"; local FILTER_RC=$?; if [ "$FILTER_RC" -gt 1 ]; then printf '중단: grep filter 실패 rc=%s\n' "$FILTER_RC" >&2; exit "$FILTER_RC"; fi; return "$FILTER_RC"; }; refresh_current_identity(){ local c="$1" identity_json identity_uid identity_id; if [ -z "${POD:-}" ] || [ -z "${NS:-}" ] || [ -z "${POD_UID:-}" ]; then return 1; fi; if ! identity_json="$(command kubectl get pod "$POD" -n "$NS" -o json)"; then return 1; fi; if ! identity_uid="$(jq -r '.metadata.uid // empty' <<<"$identity_json")"; then return 1; fi; if [ "$identity_uid" != "$POD_UID" ]; then return 1; fi; if ! identity_id="$(jq -r --arg c "$c" '([.status.containerStatuses[]?, .status.initContainerStatuses[]?] | map(select(.name==$c) | .containerID // empty) | if length==1 then .[0] else empty end)' <<<"$identity_json")"; then return 1; fi; if [ -z "$identity_id" ]; then return 1; fi; CONTAINER_ID="$identity_id"; return 0; }; kubectl(){ if [ "${1:-}" = logs ]; then local c='' previous='' arg=''; for arg in "$@"; do if [ "$previous" = -c ]; then c="$arg"; break; fi; previous="$arg"; done; if [ -z "$c" ] || ! refresh_current_identity "$c"; then printf '중단: logs 직전 current Pod UID/containerID 재조회 실패 pod=%s uid=%s container=%s\n' "${POD:--}" "${POD_UID:--}" "${c:--}" >&2; return 1; fi; fi; command kubectl "$@"; }; printf 'TOOLS_READY=true shell=Bash version=%s\n' "$BASH_VERSION"; fi; fi`

`TOOLS_READY=true`가 아니면 아래 입력과 API 자동 수집을 실행하지 않는다. node 도구가 없다는 이유로 container 원인으로 단정하지 않는다.

**최초 입력·이전 파생값과 연결 상태 초기화 — 같은 Bash에서 한 번 실행**

`INPUT_READY=true`가 아니면 namespace·Pod·권한을 다시 확인한다. namespace를 모를 때만 승인된 범위에서 `kubectl get pods -A`를 사용하고, 확정한 뒤에는 즉시 namespaced 명령으로 돌아온다. Pod가 재생성된 경우 이름이 같아도 새 UID를 새 조사로 취급한다.

### API 자동 수집

**대상별 세로 출력과 자동 등록 — 아래 한 줄 전체를 복사**

`AUTO_READY=false; unset POD_UID NODE PHASE POD_START OWNER INIT_CONTAINER INIT_CONTAINER_ID CONTAINER_ID NS_RE POD_RE; if [ "$INPUT_READY" != true ]; then printf '%s\n' '중단: INPUT_READY가 아니다.' >&2; elif POD_JSON="$(kubectl get pod "$POD" -n "$NS" -o json)" && OWNER_COUNT_TMP="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)] | length' <<<"$POD_JSON")" && CONTAINER_COUNT_TMP="$(jq -r '[.spec.containers[]?] | length' <<<"$POD_JSON")" && POD_UID_TMP="$(jq -r '.metadata.uid // empty' <<<"$POD_JSON")" && NODE_TMP="$(jq -r '.spec.nodeName // "-"' <<<"$POD_JSON")" && PHASE_TMP="$(jq -r '.status.phase // "-"' <<<"$POD_JSON")" && POD_START_TMP="$(jq -r '.status.startTime // "-"' <<<"$POD_JSON")" && INIT_TMP="$(jq -r '[.spec.initContainers[]? | .name] as $names | [.status.initContainerStatuses[]? | select(.state.terminated.exitCode != 0 or .state.terminated == null) | .name] as $unfinished | ($names | map(select(. as $n | $unfinished | index($n) != null)) | .[0] // "-")' <<<"$POD_JSON")" && INIT_ID_TMP="$(jq -r --arg i "$INIT_TMP" '[.status.initContainerStatuses[]? | select(.name==$i) | .containerID // "-"] | if length==1 then .[0] else "-" end' <<<"$POD_JSON")" && CONTAINER_ID_TMP="$(jq -r '[.status.containerStatuses[]? | .containerID // "-"] | join(",")' <<<"$POD_JSON")" && jq -r '"=== 대상 Pod ===\nPod 이름: \(.metadata.name)\nPod UID: \(.metadata.uid)\nNamespace: \(.metadata.namespace)\nNode: \(.spec.nodeName // "-")\nPhase: \(.status.phase // "-")\nPod 시작 시각: \(.status.startTime // "-")\n상위 owner: " + ([.metadata.ownerReferences[]? | select(.controller==true) | "\(.kind)/\(.name)"] | join(",") // "-") + "\nInit 순서/이미지/상태: " + ([.spec.initContainers[]? | .name as $n | "\($n) / image=\(.image) / mount=\([.volumeMounts[]?.name] | join(",") // "-")"] | join("; ") // "-") + "\nInit current·last: " + ([.status.initContainerStatuses[]? | "\(.name) / 현재=\(((.state // {}) | keys | join(","))) / 직전=\(((.lastState // {}) | keys | join(","))) / reason=\(.state.waiting.reason // .state.terminated.reason // "-") / exit=\(.state.terminated.exitCode // "-") / finished=\(.state.terminated.finishedAt // "-") / restart=\(.restartCount // 0) / container ID=\(.containerID // "-")"] | join("; ") // "-") + "\n일반 container/Port 후보: " + ([.spec.containers[]? | select(.controller==true) | "\(.kind)/\(.name)"] | if length==1 then .[0] else "-" end' <<<"$POD_JSON")"; INIT_CONTAINER="$INIT_TMP"; INIT_CONTAINER_ID="$INIT_ID_TMP"; CONTAINER_ID="$CONTAINER_ID_TMP"; NS_RE_TMP="$(printf '%s' "$NS" | sed 's/[][\\.^$*+?(){}|]/\\&/g')"; POD_RE_TMP="$(printf '%s' "$POD" | sed 's/[][\\.^$*+?(){}|]/\\&/g')"; NS_RE="^${NS_RE_TMP}$"; POD_RE="^${POD_RE_TMP}$"; AUTO_READY=true; PROMQL_READY=true; printf 'AUTO_READY=true UID=%s NODE=%s PHASE=%s INIT_CONTAINER=%s INIT_CONTAINER_ID=%s\n' "$POD_UID" "$NODE" "$PHASE" "$INIT_CONTAINER" "$INIT_CONTAINER_ID"; printf '정규식 후보: namespace=%s pod=%s\n' "$NS_RE" "$POD_RE"; fi; else printf '%s\n' '중단: API 자동 수집 실패. 이전 자동값은 유효하지 않다.' >&2; fi`

성공 gate는 Pod UID·node·phase·시각, 첫 미완료 Init의 선언 순서·image·mount·current/last 상태·container ID, 일반 container/port 관계와 volume 참조가 대상별로 출력되고 `AUTO_READY=true`가 된 경우다. API 실패·복수 controller owner·빈 UID·container 부재·출력 실패면 부분 등록하지 않는다. PVC `Bound`, node `Ready`, Init `running`은 각각 다음 hop이나 process 완료를 보장하지 않는다.

**첫 미완료 Init 실행 계약 확인 — 자동값 gate 통과 후 한 줄 전체를 복사**

`if [ "$AUTO_READY" != true ] || [ "$INIT_CONTAINER" = - ]; then printf '%s\n' '중단: AUTO_READY 또는 실제 INIT_CONTAINER가 아니다.' >&2; else INIT_SPEC_JSON="$(kubectl get pod "$POD" -n "$NS" -o json)"; INIT_SPEC_RC=$?; if [ "$INIT_SPEC_RC" -ne 0 ]; then printf 'Init spec API 조회 실패 rc=%s pod=%s uid=%s\n' "$INIT_SPEC_RC" "$POD" "$POD_UID" >&2; elif jq -e --arg i "$INIT_CONTAINER" --arg uid "$POD_UID" '.metadata.uid==$uid and any(.spec.initContainers[]?; .name==$i)' <<<"$INIT_SPEC_JSON" >/dev/null; then jq -r --arg i "$INIT_CONTAINER" '. as $pod | ($pod.spec.initContainers[]? | select(.name==$i)) as $init | "Init 이름: \($init.name)\nimage: \($init.image)\nimagePullPolicy: \($init.imagePullPolicy // "-")\ncommand_declared: \($init.command != null)\ncommand_argv_count: \((($init.command // []) | length))\nargs_declared: \($init.args != null)\nargs_count: \((($init.args // []) | length))\nsecurityContext_declared: \($init.securityContext != null)\nmount: " + ([$init.volumeMounts[]? | "\(.name):\(.mountPath)"] | join(",") // "-") + "\nenv 참조: " + ([$init.env[]?.valueFrom? | ((.configMapKeyRef.name // "") + ":" + (.configMapKeyRef.key // "")) , ((.secretKeyRef.name // "") + ":" + (.secretKeyRef.key // ""))] | map(select(length>1)) | join(",") // "-") + "\nenvFrom 참조: " + ([$init.envFrom[]? | ((.configMapRef.name // "") + ":configmap"), ((.secretRef.name // "") + ":secret")] | map(select(length>1)) | join(",") // "-") + "\nserviceAccount_declared: \($pod.spec.serviceAccountName != null)\nimagePullSecrets_count: \((($pod.spec.imagePullSecrets // []) | length))"' <<<"$INIT_SPEC_JSON"; else printf '중단: current Pod UID 또는 INIT_CONTAINER spec 대조 실패 pod=%s uid=%s\n' "$POD" "$POD_UID" >&2; fi; fi`

이 명령은 image reference·pull policy·command/args 선언 여부·개수·securityContext 선언 여부·mount·ConfigMap/Secret 참조 이름·serviceAccount 선언 여부·imagePullSecrets 개수만 출력하며 Secret 값은 읽지 않는다. 출력 실패나 대상 UID 변경이면 registry·config·권한 분기로 진행하지 않고 API/RBAC와 UID를 다시 확인한다.

## 진입 판단

|---|---|
| 사용 | `Init:0/2`, `Init:1/2`, Init `waiting`·`running`·`terminated`, non-zero exit 또는 `restartCount` 증가로 첫 Init이 성공하지 않아 진행되지 않는 경우다. `PodInitializing` 단독은 [[04. Pod STATUS가 PodInitializing인 경우\|printer 상태 런북]]에서 먼저 대조한다. |
| 적용 | 대상 Pod UID, Init 선언 순서와 첫 미완료 Init이 확인된 Kubernetes 1.26.x Pod다. 첫 Init의 image·mount·sandbox·dependency·process 파이프라인을 이 문서가 소유한다. |
| 제외 | 모든 Init exit code가 0이고 printer만 `PodInitializing`이면 [[04. Pod STATUS가 PodInitializing인 경우\|printer 런북]]으로 돌아간다. Init 완료 후 일반 container 반복 종료는 [[06. ## 최초 확인

**현재 상태·관계 확인 — 아래 한 줄 전체를 복사**

`if [ "$AUTO_READY" != true ]; then printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; else kubectl get pod "$POD" -n "$NS" -o wide && kubectl get pod "$POD" -n "$NS" -o jsonpath='{.metadata.uid}{"\n"}{.status.phase}{"\n"}{range .status.initContainerStatuses[*]}init/{.name}{" current-waiting="}{.state.waiting.reason}{" current-running="}{.state.running.startedAt}{" current-terminated="}{.state.terminated.reason}{" current-exit="}{.state.terminated.exitCode}{" current-finished="}{.state.terminated.finishedAt}{" last-terminated="}{.lastState.terminated.reason}{" last-exit="}{.lastState.terminated.exitCode}{" last-finished="}{.lastState.terminated.finishedAt}{" restarts="}{.restartCount}{"\n"}{end}{range .status.containerStatuses[*]}container/{.name}{" current-waiting="}{.state.waiting.reason}{" current-running="}{.state.running.startedAt}{" current-terminated="}{.state.terminated.reason}{" current-exit="}{.state.terminated.exitCode}{" last-terminated="}{.lastState.terminated.reason}{" last-exit="}{.lastState.terminated.exitCode}{" restarts="}{.restartCount}{"\n"}{end}' && kubectl describe pod "$POD" -n "$NS"; fi`

**같은 UID의 Event 한 번 확인 — 아래 한 줄 전체를 복사**

`if [ "$AUTO_READY" != true ]; then printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; else kubectl get events -n "$NS" --field-selector "involvedObject.kind=Pod,involvedObject.name=$POD,involvedObject.uid=$POD_UID" --sort-by=.metadata.creationTimestamp -o custom-columns='CREATED:.metadata.creationTimestamp,FIRST-SEEN:.firstTimestamp,LAST-SEEN:.lastTimestamp,EVENT-TIME:.eventTime,SERIES-LAST:.series.lastObservedTime,TYPE:.type,REASON:.reason,COUNT:.count,MESSAGE:.message'; fi`

`get`에서 `STATUS`, `READY`, `RESTARTS`, `NODE`, `AGE`와 Init 선언 순서를 본다. status에서 current·last state, `reason`, `exitCode`, `finishedAt`, `restartCount`를 구분한다. `describe`에서 Init별 State·Last State·Reason·Exit Code·Restart Count와 첫 Event message·시각을 본다. Event 빈 출력은 오류 없음이 아니라 UID·범위·권한·보존 기간 문제 후보다. `FIRST-SEEN`, `LAST-SEEN`, `EVENT-TIME`, `SERIES-LAST`, `COUNT` 중 채워진 시각만 종료 시각과 대조한다.

`get`, status JSONPath 또는 `describe` 중 하나라도 실패하면 부분 출력으로 다음 분기를 선택하지 않는다. API/RBAC·UID·대상 이름을 확인하고 최초 확인을 다시 실행한다.

## 관측별 진단 경로

### 1. 첫 Init이 시작 전 `waiting`인 경우

진입 증거는 첫 미완료 Init의 current state가 `waiting`이고 Event suffix에 image pull·mount·sandbox·config 단서가 있는 경우다. process가 시작되지 않았을 수 있으므로 로그 빈 결과만으로 process 실패를 확정하지 않는다. 참조 선택은 API 출력의 volume·env 관계를 보고 수행하며 복수 후보를 임의로 첫 번째 선택하지 않는다.

### 2. 첫 Init이 `running`이지만 진행되지 않는 경우

진입 증거는 첫 미완료 Init이 current `running`이고 로그에 retry·lock·timeout 또는 dependency 대기가 있는 경우다. 연결 경로는 실행 host → kubectl/API server → kubelet/runtime → Init container/application process → 내부 Service/EndpointSlice·Pod DNS·NetworkPolicy 또는 외부 DB/API다.

**현재 Init 로그 — 아래 한 줄 전체를 복사**

`LOG_OUTPUT=''; LOG_RC=0; FILTERED=''; FILTER_RC=0; if [ "$TIME_READY" != true ] || [ "$AUTO_READY" != true ] || [ "$INIT_CONTAINER" = - ]; then printf '%s\n' '중단: TIME_READY·AUTO_READY·실제 INIT_CONTAINER가 아니다.' >&2; else LOG_OUTPUT="$(kubectl logs "$POD" -n "$NS" -c "$INIT_CONTAINER" --timestamps --since-time="$START_RFC3339" --tail=200)"; LOG_RC=$?; if [ "$LOG_RC" -ne 0 ]; then printf 'Init log stream 실패 계층=API/kubelet/runtime rc=%s pod=%s uid=%s init=%s containerID=%s\n' "$LOG_RC" "$POD" "$POD_UID" "$INIT_CONTAINER" "$INIT_CONTAINER_ID" >&2; else FILTERED="$(printf '%s\n' "$LOG_OUTPUT" | grep -E -i -C 3 'panic|fatal|error|exception|timeout|refused|denied|permission|no such host|tls|waiting|retry|migration|lock|oom|killed')"; FILTER_RC=$?; if [ "$FILTER_RC" -eq 0 ]; then printf '%s\n' "$FILTERED"; elif [ "$FILTER_RC" -eq 1 ]; then printf '%s\n' '필터 결과 없음: 오류 부재가 아니다. 같은 시간 범위 tail로 재확인한다.' >&2; else printf 'Init log filter 실패 rc=%s\n' "$FILTER_RC" >&2; fi; fi; fi`

실제 Service 이름이 로그 또는 선언값에서 확인된 경우에만 다음 선택을 한다. Service `port`와 EndpointSlice `port`는 역할이 다르며, endpoint가 `ready`여도 모든 listener·protocol·application 기능을 보장하지 않는다.

**dependency 분기 진입 전 Pod UID 재확인 — 아래 한 줄 전체를 복사**

`DEPENDENCY_UID_READY=false; if [ "$AUTO_READY" = true ] && DEPENDENCY_POD_JSON="$(kubectl get pod "$POD" -n "$NS" -o json)" && DEPENDENCY_UID="$(jq -r '.metadata.uid // empty' <<<"$DEPENDENCY_POD_JSON")" && [ "$DEPENDENCY_UID" = "$POD_UID" ]; then DEPENDENCY_UID_READY=true; printf 'DEPENDENCY_UID_READY=true pod=%s uid=%s\n' "$POD" "$DEPENDENCY_UID"; else AUTO_READY=false; printf '중단: dependency 분기 Pod UID가 최초 UID와 다르거나 재조회 실패. 관련 gate를 닫고 처음부터 재수집한다.\n' >&2; fi`

**내부 dependency 선택 — evidence 확인 후 한 번 실행**

`SERVICE_READY=false; POLICY_READY=false; SERVICE='PASTE_SERVICE_HERE'; NETWORKPOLICY='PASTE_NETWORKPOLICY_HERE'; if [ "$TIME_READY" != true ] || [ "$AUTO_READY" != true ]; then printf '%s\n' '중단: TIME_READY·AUTO_READY가 아니다.' >&2; elif [ -n "$SERVICE" ] && SERVICE_JSON="$(kubectl get service "$SERVICE" -n "$NS" -o json)"; then SERVICE_READY=true; printf 'SERVICE_READY=true service=%s\n' "$SERVICE"; printf '%s\n' "$SERVICE_JSON" | jq -r '"Service UID: \(.metadata.uid)\nselector: \(.spec.selector // {})\nport: " + ([.spec.ports[]? | "\(.name // "unnamed")/\(.port) -> \(.targetPort)"] | join(",") // "-")'; else printf '중단: 실제 Service 이름 API 조회 실패 service=%s\n' "$SERVICE" >&2; fi; if [ -n "$NETWORKPOLICY" ] && NETWORKPOLICY_JSON="$(kubectl get networkpolicy "$NETWORKPOLICY" -n "$NS" -o json)"; then POLICY_READY=true; printf 'POLICY_READY=true policy=%s uid=%s\n' "$NETWORKPOLICY" "$(jq -r '.metadata.uid' <<<"$NETWORKPOLICY_JSON")"; else printf '%s\n' 'NetworkPolicy 이름·적용 여부가 증거로 확인되지 않으면 정책 정상·차단을 추정하지 않는다.' >&2; fi`

**Service와 EndpointSlice 범위 읽기 — 각각 한 줄씩 복사**

`if [ "$SERVICE_READY" != true ]; then printf '%s\n' '중단: SERVICE_READY가 아니다.' >&2; else kubectl get service "$SERVICE" -n "$NS" -o wide; fi`

`if [ "$SERVICE_READY" != true ]; then printf '%s\n' '중단: SERVICE_READY가 아니다.' >&2; else kubectl get endpointslice -n "$NS" -l "kubernetes.io/service-name=$SERVICE" -o wide; fi`

`if [ "$POLICY_READY" != true ]; then printf '%s\n' '중단: POLICY_READY가 아니다.' >&2; else kubectl get networkpolicy "$NETWORKPOLICY" -n "$NS" -o yaml; fi`

Service·EndpointSlice·Policy API 호출 성공은 API 객체를 읽었다는 범위만 보장한다. EndpointSlice 빈 결과는 selector 불일치·backend Pod 부재·API 범위·권한 문제 후보이지 연결 성공이나 정책 허용을 뜻하지 않는다. 내부 endpoint가 확인됐는데 timeout·TLS·인증 오류가 남으면 외부 dependency owner로 이관한다. HTTPS라면 승인된 CA·client 인증을 사용하고 TLS 검증을 `-k`로 우회하지 않는다. DB lock 해제·schema 변경·migration 재실행은 이 로그만으로 수행하지 않는다.

### 3. Init이 반복 실패하거나 종료된 경우

진입 증거는 current Init이 `terminated`이거나 `restartCount`가 증가한 경우다. `state.terminated`는 현재 instance, `lastState.terminated`는 직전 instance다. `OOMKilled`와 exit code 137은 Event·resource·node 시각이 맞을 때만 함께 원인 후보로 쓴다.

**current와 previous 상태 gate — 아래 한 줄 전체를 복사**

`CURRENT_LOG_READY=false; PREVIOUS_LOG_READY=false; CURRENT_OUTPUT=''; PREVIOUS_OUTPUT=''; CURRENT_RC=0; PREVIOUS_RC=0; if [ "$TIME_READY" != true ] || [ "$AUTO_READY" != true ] || [ "$INIT_CONTAINER" = - ]; then printf '%s\n' '중단: TIME_READY·AUTO_READY·실제 INIT_CONTAINER가 아니다.' >&2; elif CURRENT_JSON="$(kubectl get pod "$POD" -n "$NS" -o json)" && [ "$(jq -r '.metadata.uid' <<<"$CURRENT_JSON")" = "$POD_UID" ]; then CURRENT_STATE="$(jq -r --arg i "$INIT_CONTAINER" '[.status.initContainerStatuses[]? | select(.name==$i)] | if length==1 then .[0].state else {} end' <<<"$CURRENT_JSON")"; LAST_STATE="$(jq -r --arg i "$INIT_CONTAINER" '[.status.initContainerStatuses[]? | select(.name==$i)] | if length==1 then .[0].lastState else {} end' <<<"$CURRENT_JSON")"; RESTART_COUNT="$(jq -r --arg i "$INIT_CONTAINER" '[.status.initContainerStatuses[]? | select(.name==$i) | .restartCount] | if length==1 then .[0] else 0 end' <<<"$CURRENT_JSON")"; if jq -e 'has("running") or has("terminated")' <<<"$CURRENT_STATE" >/dev/null; then CURRENT_LOG_READY=true; fi; if [ "$RESTART_COUNT" -ge 1 ] && jq -e 'has("terminated")' <<<"$LAST_STATE" >/dev/null; then PREVIOUS_LOG_READY=true; fi; printf 'LOG_GATE current=%s previous=%s pod=%s uid=%s init=%s restart=%s\n' "$CURRENT_LOG_READY" "$PREVIOUS_LOG_READY" "$POD" "$POD_UID" "$INIT_CONTAINER" "$RESTART_COUNT"; else printf '중단: current Pod UID 변경 또는 상태 조회 실패\n' >&2; fi`

`CURRENT_LOG_READY=true`가 아니면 process가 시작되지 않았을 수 있으므로 current logs를 호출하지 않고 status·Event·waiting 경로로 이동한다. `PREVIOUS_LOG_READY=true`가 아니면 `--previous`를 실행하지 않는다.

연결 경로는 실행 host → kubectl client/API server → 대상 node kubelet → CRI/runtime log stream → Init container process다. API server 또는 stream 준비가 성공해도 로그 보존·process·application 정상은 보장하지 않는다.

**current 로그 — gate 통과 시 한 줄 전체를 복사**

`if [ "$CURRENT_LOG_READY" != true ]; then printf '%s\n' '중단: current log gate가 아니다.' >&2; else CURRENT_OUTPUT="$(kubectl logs "$POD" -n "$NS" -c "$INIT_CONTAINER" --timestamps --since-time="$START_RFC3339" --tail=200)"; CURRENT_RC=$?; if [ "$CURRENT_RC" -ne 0 ]; then printf 'current stream 실패 pod=%s uid=%s init=%s containerID=%s rc=%s\n' "$POD" "$POD_UID" "$INIT_CONTAINER" "$INIT_CONTAINER_ID" "$CURRENT_RC" >&2; else CURRENT_FILTER_RC=0; printf '%s\n' "$CURRENT_OUTPUT" | grep -E -i -C 3 'panic|fatal|error|exception|timeout|refused|denied|permission|not found|migration|lock|oom|killed|signal'; CURRENT_FILTER_RC=$?; if [ "$CURRENT_FILTER_RC" -eq 0 ]; then :; elif [ "$CURRENT_FILTER_RC" -eq 1 ]; then printf '%s\n' 'current 필터 빈 결과: 오류 부재가 아니다.' >&2; else printf 'current log filter 실패 rc=%s\n' "$CURRENT_FILTER_RC" >&2; fi; fi; fi`

**직전 instance 로그 — gate 통과 시 한 줄 전체를 복사**

`if [ "$PREVIOUS_LOG_READY" != true ]; then printf '%s\n' '중단: restartCount 또는 lastState.terminated gate가 아니다.' >&2; else PREVIOUS_OUTPUT="$(kubectl logs "$POD" -n "$NS" -c "$INIT_CONTAINER" --previous --timestamps --since-time="$START_RFC3339" --tail=200)"; PREVIOUS_RC=$?; if [ "$PREVIOUS_RC" -ne 0 ]; then printf 'previous stream 실패 pod=%s uid=%s init=%s rc=%s\n' "$POD" "$POD_UID" "$INIT_CONTAINER" "$PREVIOUS_RC" >&2; else PREVIOUS_FILTER_RC=0; printf '%s\n' "$PREVIOUS_OUTPUT" | grep -E -i -C 3 'panic|fatal|error|exception|timeout|refused|denied|permission|not found|migration|lock|oom|killed|signal'; PREVIOUS_FILTER_RC=$?; if [ "$PREVIOUS_FILTER_RC" -eq 0 ]; then :; elif [ "$PREVIOUS_FILTER_RC" -eq 1 ]; then printf '%s\n' 'previous 필터 빈 결과: previous 로그 존재나 오류 부재를 보장하지 않는다.' >&2; else printf 'previous log filter 실패 rc=%s\n' "$PREVIOUS_FILTER_RC" >&2; fi; fi; fi`

`previous terminated container not found`, Forbidden, API 연결 오류 또는 로그 보존·rotation 오류는 [[28. Pod의 이전 컨테이너 로그를 가져올 수 없는 경우\|이전 로그 런북]]으로 이동한다. `--previous` 빈 출력은 정상 증거가 아니다. 종료된 Init에는 `exec`하지 않는다.

previous 결과는 같은 Pod UID·`INIT_CONTAINER`·`START_RFC3339` 범위로 기록한다. API가 previous container ID를 제공하지 않으면 현재 `INIT_CONTAINER_ID`를 previous ID로 오해하지 말고 `미제공`으로 남긴다.

필터가 비면 current/previous 각각 같은 UID·container·시간 범위의 마지막 50행만 재확인한다. 빈 tail 또는 tail 조회 실패도 오류 부재가 아니며, 이전 로그 보존 경계로 이관한다.

**current bounded tail — current gate 통과 시 한 줄 전체를 복사**

`if [ "$CURRENT_LOG_READY" != true ]; then printf '%s\n' '중단: current log gate가 아니다.' >&2; else kubectl logs "$POD" -n "$NS" -c "$INIT_CONTAINER" --timestamps --since-time="$START_RFC3339" --tail=50; fi`

**previous bounded tail — previous gate 통과 시 한 줄 전체를 복사**

`if [ "$PREVIOUS_LOG_READY" != true ]; then printf '%s\n' '중단: previous log gate가 아니다.' >&2; else kubectl logs "$POD" -n "$NS" -c "$INIT_CONTAINER" --previous --timestamps --since-time="$START_RFC3339" --tail=50; fi`

node·kernel·runtime 증거가 필요할 때 연결 경로는 실행 host → API server로 얻은 Pod UID/node → node kubelet·CRI/runtime → Linux kernel/cgroup → Init process다. 실제 kubelet unit·node 권한·journalctl을 확인하지 못하면 limit을 임의로 올리거나 runtime 명령을 발명하지 않는다.

이 절도 앞의 `JOURNAL_READY=true`와 `NODE_JOURNAL_READY=true` gate를 먼저 통과해야 한다. gate가 실패하면 journal·node 상태 조회를 실행하지 않고 owner에게 확인된 Pod UID·node·UTC 시각을 이관한다.

**OOM·runtime journal — node gate 통과 시 한 줄 전체를 복사**

`KERNEL_OUTPUT=''; KUBELET_OUTPUT=''; KERNEL_RC=0; KUBELET_RC=0; KERNEL_FILTER_RC=0; KUBELET_FILTER_RC=0; if [ "$NODE_JOURNAL_READY" != true ] || [ "$NODE_EXEC_READY" != true ] || [ "$JOURNAL_READY" != true ]; then printf '%s\n' '중단: NODE_JOURNAL_READY·NODE_EXEC_READY·JOURNAL_READY가 아니다.' >&2; else KERNEL_OUTPUT="$(node_exec 'set -u; start="$1"; end="$2"; pod_uid="$3"; node="$4"; api_machine="$5"; stream="$6"; match="$7"; remote_machine="$(< /etc/machine-id)" || exit 11; [ "$remote_machine" = "$api_machine" ] || exit 12; [ -n "$start" ] && [ -n "$end" ] && [ -n "$pod_uid" ] && [ -n "$node" ] && [ -n "$match" ] || exit 13; if [ "$stream" = kernel ]; then sudo journalctl -k --since "$start" --until "$end" --no-pager; elif [ "$stream" = kubelet ]; then sudo journalctl -u kubelet --since "$start" --until "$end" --no-pager; else exit 14; fi' "$JOURNAL_START" "$JOURNAL_END" "$POD_UID" "$NODE" "$NODE_API_MACHINE_ID" kernel "$POD_UID")"; KERNEL_RC=$?; KUBELET_OUTPUT="$(node_exec 'set -u; start="$1"; end="$2"; pod_uid="$3"; node="$4"; api_machine="$5"; stream="$6"; match="$7"; remote_machine="$(< /etc/machine-id)" || exit 11; [ "$remote_machine" = "$api_machine" ] || exit 12; [ -n "$start" ] && [ -n "$end" ] && [ -n "$pod_uid" ] && [ -n "$node" ] && [ -n "$match" ] || exit 13; if [ "$stream" = kernel ]; then sudo journalctl -k --since "$start" --until "$end" --no-pager; elif [ "$stream" = kubelet ]; then sudo journalctl -u kubelet --since "$start" --until "$end" --no-pager; else exit 14; fi' "$JOURNAL_START" "$JOURNAL_END" "$POD_UID" "$NODE" "$NODE_API_MACHINE_ID" kubelet "$INIT_CONTAINER")"; KUBELET_RC=$?; if [ "$KERNEL_RC" -ne 0 ] || [ "$KUBELET_RC" -ne 0 ]; then printf 'remote node journal 실패 kernel_rc=%s kubelet_rc=%s node=%s sshHost=%s\n' "$KERNEL_RC" "$KUBELET_RC" "$NODE" "$NODE_HOST" >&2; elif [ -z "$KERNEL_OUTPUT" ] && [ -z "$KUBELET_OUTPUT" ]; then printf '%s\n' 'node journal 빈 출력: OOM·eviction 없음으로 해석하지 않는다.' >&2; else printf '%s\n' "$KERNEL_OUTPUT" | grep -E -i -C 3 "$POD_UID|out of memory|killed process|oom|memory cgroup|evict"; KERNEL_FILTER_RC=$?; printf '%s\n' "$KUBELET_OUTPUT" | grep -E -i -C 3 "$POD_UID|$INIT_CONTAINER|oom|evict|runtime|cgroup|failed|error"; KUBELET_FILTER_RC=$?; if [ "$KERNEL_FILTER_RC" -gt 1 ] || [ "$KUBELET_FILTER_RC" -gt 1 ]; then printf 'node journal filter 실패 kernel_rc=%s kubelet_rc=%s\n' "$KERNEL_FILTER_RC" "$KUBELET_FILTER_RC" >&2; elif [ "$KERNEL_FILTER_RC" -eq 1 ] && [ "$KUBELET_FILTER_RC" -eq 1 ]; then printf '%s\n' 'node journal 필터 무일치: OOM·eviction 없음으로 해석하지 않는다.' >&2; fi; fi; fi`

`eviction manager`는 node pressure 후보이고, `Out of memory: Killed process`는 대상 cgroup·종료 시각과 연결될 때만 해당 Init OOM 근거다. 여러 Pod가 같은 시각에 실패하면 단일 Init resource 변경으로 닫지 않는다. `kubectl describe node "$NODE"`에서 `MemoryPressure`, `DiskPressure`, `PIDPressure`, allocatable과 eviction 표시를 읽고, 연결되지 않으면 node/runtime owner로 이관한다.

**node 상태 확인 — node journal gate 통과 후 한 줄 전체를 복사**

`if [ "$NODE_JOURNAL_READY" != true ]; then printf '%s\n' '중단: NODE_JOURNAL_READY가 아니다.' >&2; else kubectl describe node "$NODE"; fi`

`describe node` 실패·빈 출력은 pressure 없음이 아니다. node 권한·API 범위·관측 시각을 확인하고 node owner로 이관한다.

### 4. Init은 완료됐지만 다음 단계로 보이지 않는 경우

진입 증거는 모든 Init의 `state.terminated.exitCode=0`인데 일반 container가 `waiting.reason=PodInitializing` 또는 다른 waiting 상태인 경우다. 이때 Init 원인으로 계속 분류하지 않는다. 일반 container의 image·mount·sandbox·config·start 문제는 해당 런북으로 이관한다.

연결 경로는 실행 host → kubectl/API server → 대상 node의 kubelet/runtime → 일반 container → application dependency다. `Running`이나 container ID 생성은 listener·application readiness를 보장하지 않는다.

**일반 container 선택과 UID gate — 분기 진입 후 한 번 실행**

`CONTAINER_READY=false; CONTAINER='PASTE_CONTAINER_HERE'; CONTAINER_ID=''; if [ "$AUTO_READY" != true ]; then printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; elif CURRENT_JSON="$(kubectl get pod "$POD" -n "$NS" -o json)" && UID_NOW="$(jq -r '.metadata.uid' <<<"$CURRENT_JSON")" && CONTAINER_ID_TMP="$(jq -r --arg c "$CONTAINER" '[.status.containerStatuses[]? | select(.name==$c) | .containerID // "-"] | if length==1 then .[0] else empty end' <<<"$CURRENT_JSON")" && jq -e --arg c "$CONTAINER" 'any(.status.containerStatuses[]?; .name==$c)' <<<"$CURRENT_JSON" >/dev/null && [ "$UID_NOW" = "$POD_UID" ] && [ -n "$CONTAINER_ID_TMP" ]; then CONTAINER_ID="$CONTAINER_ID_TMP"; CONTAINER_READY=true; printf 'CONTAINER_READY=true pod=%s uid=%s container=%s containerID=%s\n' "$POD" "$POD_UID" "$CONTAINER" "$CONTAINER_ID"; else printf '중단: 일반 container·UID·container ID 확인 실패\n' >&2; fi`

일반 container가 실제 `running` 또는 `terminated`인 경우에만 application 로그를 보조 증거로 사용한다. `waiting`이면 process가 시작되지 않았을 수 있어 로그를 호출하지 않는다. `connection refused`는 application dependency 경로이며 Init 원인으로 되돌리지 않는다.

**일반 container bounded 로그 — 현재 상태가 시작된 경우에만 복사**

`CONTAINER_STATUS_OUTPUT=''; CONTAINER_STATUS_RC=0; STARTED_MATCH=''; STARTED_FILTER_RC=1; APP_OUTPUT=''; APP_RC=0; APP_FILTERED=''; APP_FILTER_RC=0; if [ "$CONTAINER_READY" != true ] || [ "$TIME_READY" != true ]; then printf '%s\n' '중단: CONTAINER_READY·TIME_READY가 아니다.' >&2; else CONTAINER_STATUS_OUTPUT="$(kubectl get pod "$POD" -n "$NS" -o jsonpath="{range .status.containerStatuses[?(@.name=='$CONTAINER')]}{.state.running.startedAt}{.state.terminated.startedAt}{end}")"; CONTAINER_STATUS_RC=$?; if [ "$CONTAINER_STATUS_RC" -ne 0 ]; then printf 'container status producer 실패 rc=%s pod=%s uid=%s container=%s\n' "$CONTAINER_STATUS_RC" "$POD" "$POD_UID" "$CONTAINER" >&2; else STARTED_MATCH="$(printf '%s\n' "$CONTAINER_STATUS_OUTPUT" | grep -E '[0-9]')"; STARTED_FILTER_RC=$?; if [ "$STARTED_FILTER_RC" -eq 0 ] && [ -n "$STARTED_MATCH" ]; then APP_OUTPUT="$(kubectl logs "$POD" -n "$NS" -c "$CONTAINER" --timestamps --since-time="$START_RFC3339" --tail=200)"; APP_RC=$?; if [ "$APP_RC" -ne 0 ]; then printf 'application log producer 실패 계층=API/kubelet/runtime rc=%s pod=%s uid=%s container=%s\n' "$APP_RC" "$POD" "$POD_UID" "$CONTAINER" >&2; else APP_FILTERED="$(printf '%s\n' "$APP_OUTPUT" | grep -E -i -C 3 'panic|fatal|error|exception|timeout|refused|denied|permission|not found|killed')"; APP_FILTER_RC=$?; if [ "$APP_FILTER_RC" -eq 0 ] && [ -n "$APP_FILTERED" ]; then printf '%s\n' "$APP_FILTERED"; elif [ "$APP_FILTER_RC" -eq 1 ]; then printf '%s\n' 'application log producer는 성공했지만 필터 무일치다.' >&2; else printf 'application log filter 실패 rc=%s\n' "$APP_FILTER_RC" >&2; fi; fi; elif [ "$STARTED_FILTER_RC" -eq 1 ]; then printf '%s\n' '일반 container 실행 시각 filter 무일치: 로그 producer를 실행하지 않고 status/Event로 이관한다.' >&2; else printf 'container 실행 시각 filter 실패 rc=%s\n' "$STARTED_FILTER_RC" >&2; fi; fi; fi`

`ErrImagePull`·`ImagePullBackOff`는 [[07. Pod STATUS가 ImagePullBackOff·ErrImagePull인 경우\|image]], `InvalidImageName`·`ErrImageNeverPull`은 [[08. Pod STATUS가 InvalidImageName·ErrImageNeverPull인 경우\|invalid image]], `FailedMount`·`FailedCreatePodSandBox`는 각각 [[25. Pod 이벤트에 FailedMount·FailedAttachVolume이 기록된 경우\|mount]], [[24. Pod 이벤트에 FailedCreatePodSandBox가 기록된 경우\|sandbox]], `CreateContainerConfigError`는 [[09. Pod STATUS가 CreateContainerConfigError인 경우\|config]], `CreateContainerError`·`RunContainerError`는 [[10. Pod STATUS가 CreateContainerError·RunContainerError인 경우\|container start]]로 이동한다. 로그 stream 성공도 application 기능을 보장하지 않는다.

## 복구 전 gate와 제한적 변경

삭제·rollout·patch·edit·재실행은 다음을 모두 확인하기 전에는 실행하지 않는다. 첫 미완료 Init의 선언 순서·current/last state·reason·exitCode·restartCount, 최초 Event와 결정적 로그의 시간·message, image/mount/dependency/OOM의 직접 근거, namespace·Pod UID·owner·node·Ready/replica 영향, 외부 호출·migration·데이터 중복·quorum 위험, 원인 수정 반영·실행 권한·서비스 owner 승인·rollback·중단 조건을 기록한다. Job/CronJob·StatefulSet·단독 Pod·멱등성이 확인되지 않은 migration에는 Deployment 절차를 적용하지 않는다.

**승인된 Deployment 대상 등록 — 변경을 고려할 때 한 번 실행**

## Prometheus 빠른 관측

PromQL은 등록된 `NS_RE`, `POD_RE`, 최초 `POD_UID`로 완성본을 생성한다. 사용자는 출력된 한 줄만 Prometheus 또는 Grafana에 붙여 넣고 쿼리 내부를 수정하지 않는다. metric 부재와 조회/API 실패를 구분하며 빈 결과를 0·정상·Init 완료로 해석하지 않는다. 재조회 UID가 최초 UID와 다르면 관련 gate를 닫고 이전 query를 재사용하지 않는다.
