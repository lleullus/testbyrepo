# Pod startup probe가 실패하는 경우

## 입력값과 빠른 수집

이 런북은 `startupProbe`가 정의된 container에서 **첫 성공 전** 같은 Pod UID의 `Startup probe failed:`가 반복되고, 실패 예산 소진 뒤 `Killing`·재시작 또는 Pod 종료가 이어지는 경우를 다룬다. startup 성공 뒤의 liveness는 [[20. Pod liveness probe가 실패하는 경우]]로 이관한다.

| 구분 | 값과 출처 | 유효성 gate |
|---|---|---|
| 최초 입력 | `NS`, `POD`: 승인된 namespace와 Pod 이름을 운영자가 한 번 입력 | exact-name API 조회 성공 |
| API 확인 자동값 | `POD_UID`, `NODE`, `PHASE`, `POD_IP`, `OWNER`, `OBSERVED_AT`, `POD_RE`, `CONTAINER_ID`, `RESTART_COUNT`, `LAST_STATE`, startup probe의 `PROBE_SCHEME`, `PROBE_PATH`, `PROBE_HOST` | API 호출 성공, UID·node·container 후보가 비어 있지 않음 |
| 계산 후보값 | `PROBE_PORT`: startup probe의 numeric/named port를 같은 container 선언으로 해석한 후보 | 단일 port 관계와 숫자 범위 확인 |
| 운영자 선택값 | `CONTAINER`, `START_RFC3339`, `START_JOURNAL`, `END_JOURNAL`, `NODE_HOST`, 조건부 `PVC`, `SERVICE`, `DEPLOYMENT` | Event 대상·시간·원격 node·volume/service owner 관계 확인 |

각 `PASTE_..._HERE`는 이 문서에서 한 번만 입력한다. 이후 값은 같은 Bash의 등록 변수와 gate를 재사용하며, 찾아 바꾸기·모두 바꾸기를 요구하지 않는다.

실행 host는 승인된 작업 PC 또는 bastion의 동일한 Bash 터미널이다. `kubectl` API 호출은 API server를 거치고 logs/exec는 `API server → 대상 node/kubelet → runtime → container`를 거친다. Pod 내부 `127.0.0.1`은 container network namespace의 loopback이다. node journal과 runtime 명령은 승인된 node shell·실제 unit·권한을 확인한 뒤 실행한다. 도구 확인이 실패하면 다음 단계로 진행하지 않는다. API read, logs/exec, node journal 권한은 각각의 실제 요청으로 확인하며 `auth can-i=yes`는 실제 get/logs/exec/journal 요청 성공을 보장하지 않는다.

**Bash와 host 도구 확인 — 아래 한 줄 전체를 복사**

`TOOLS_READY=false; MISSING_TOOLS=''; if [ -z "${BASH_VERSION:-}" ]; then printf '%s\n' '중단: 같은 Bash에서 실행한다.' >&2; else for TOOL in kubectl jq grep sed date mktemp ssh; do command -v "$TOOL" >/dev/null 2>&1 || MISSING_TOOLS="$MISSING_TOOLS $TOOL"; done; if [ -z "$MISSING_TOOLS" ]; then TOOLS_READY=true; printf 'TOOLS_READY=true shell=%s\n' "$BASH_VERSION"; else printf '중단: 없는 host 도구=%s\n' "$MISSING_TOOLS" >&2; fi; fi`

**최초 입력·이전 파생값과 연결 상태 초기화 — 같은 Bash에서 한 번 실행**

`unset INPUT_READY AUTO_READY SELECTION_READY PORT_READY DESCRIBE_READY EVENT_READY TARGET_READY TIME_READY LOG_READY PREVIOUS_READY JOURNAL_READY RESOURCE_READY MOUNT_READY MOUNT_PVC_READY SERVICE_READY SERVICE_INPUT_READY RUNTIME_READY ROLLOUT_READY DEPLOYMENT_READY DEPLOYMENT_INPUT_READY UID_READY EVIDENCE_READY NODE_SSH_READY POD_JSON POD_UID NODE PHASE POD_IP OWNER OBSERVED_AT POD_RE CONTAINER CONTAINER_ID CURRENT_CONTAINER_ID CURRENT_CONTAINER_STATE CURRENT_CONTAINER_READY CURRENT_CONTAINER_RESTART_COUNT RESTART_COUNT LAST_STATE PROBE_PORT_RAW PROBE_PORT PROBE_SCHEME PROBE_PATH PROBE_HOST START_RFC3339 START_EPOCH START_JOURNAL END_JOURNAL START_JOURNAL_EPOCH END_JOURNAL_EPOCH NODE_HOST REMOTE_NODE CURRENT_POD_UID PVC SERVICE DEPLOYMENT EVENT_OUTPUT LOG_PRODUCER_RC LOG_FILTER_RC JOURNAL_OUTPUT JOURNAL_PRODUCER_RC JOURNAL_FILTER_RC; NS='PASTE_NAMESPACE_HERE'; POD='PASTE_POD_HERE'; INPUT_READY=false; if [ "$TOOLS_READY" != true ]; then printf '%s\n' '중단: 도구 확인을 먼저 통과한다.' >&2; elif [ -z "$NS" ] || [ -z "$POD" ]; then printf '%s\n' '중단: NS와 POD를 입력한다.' >&2; elif kubectl get pod "$POD" -n "$NS" -o name >/dev/null 2>&1; then INPUT_READY=true; export NS POD; printf 'INPUT_READY=true namespace=%s pod=%s\n' "$NS" "$POD"; else printf '중단: Pod API 조회 실패 또는 권한 없음 namespace=%s pod=%s\n' "$NS" "$POD" >&2; fi`

`INPUT_READY=true`가 아니면 namespace·Pod 이름·API 권한을 확인하고 멈춘다. namespace 미확정 탐색은 후보를 확인하는 1회성 보조로만 사용하고 복수 후보를 첫 번째로 고르지 않는다.

**Pod 자동값 수집·등록 — identity·시각·container/port 관계를 보존하는 한 줄**

`AUTO_READY=false; if [ "$INPUT_READY" != true ]; then printf '%s\n' '중단: INPUT_READY가 아니다.' >&2; elif POD_JSON="$(kubectl get pod "$POD" -n "$NS" -o json)" && POD_UID_TMP="$(jq -r '.metadata.uid // empty' <<<"$POD_JSON")" && NODE_TMP="$(jq -r '.spec.nodeName // empty' <<<"$POD_JSON")" && PHASE_TMP="$(jq -r '.status.phase // empty' <<<"$POD_JSON")" && POD_IP_TMP="$(jq -r '.status.podIP // empty' <<<"$POD_JSON")" && OWNER_TMP="$(jq -r '[.metadata.ownerReferences[]? | "\(.kind)/\(.name)"] | join(",")' <<<"$POD_JSON")" && CONTAINER_COUNT_TMP="$(jq '.spec.containers | length' <<<"$POD_JSON")" && OBSERVED_AT_TMP="$(date -u '+%Y-%m-%dT%H:%M:%SZ')" && POD_RE_TMP="$(printf '%s' "$POD" | sed 's/[][\\.^$*+?(){}|]/\\&/g')" && jq -r '"=== 대상 Pod ===\n이름: \(.metadata.name)\nPod UID: \(.metadata.uid)\nNode: \(.spec.nodeName // "-")\nPhase: \(.status.phase // "-")\nPod IP: \(.status.podIP // "-")\nPod 시작 시각: \(.status.startTime // "-")\n상위 owner: \(([.metadata.ownerReferences[]? | "\(.kind)/\(.name)"] | join(",")) // "-")\nContainer/port 후보:\n" + ([.spec.containers[]? | "- \(.name): \([.ports[]? | ((.name // "unnamed") + ":" + (.containerPort|tostring))] | join(",") // "없음")"] | join("\n")) + "\nContainer 상태/ID:\n" + ([.status.containerStatuses[]? | "- \(.name): ready=\(.ready // false), restart=\(.restartCount // 0), state=\(.state | to_entries[0].key // "-"), lastState=\(.lastState | to_entries[0].key // "-"), container ID=\(.containerID // "-")"] | join("\n"))' <<<"$POD_JSON" && [ -n "$POD_UID_TMP" ] && [ -n "$NODE_TMP" ] && [ -n "$PHASE_TMP" ] && [ "$CONTAINER_COUNT_TMP" -ge 1 ]; then POD_UID="$POD_UID_TMP"; NODE="$NODE_TMP"; PHASE="$PHASE_TMP"; POD_IP="$POD_IP_TMP"; OWNER="$OWNER_TMP"; OBSERVED_AT="$OBSERVED_AT_TMP"; POD_RE="^${POD_RE_TMP}$"; AUTO_READY=true; export POD_UID NODE PHASE POD_IP OWNER OBSERVED_AT POD_RE; printf 'AUTO_READY=true\nPod UID=%s\nNode=%s\nPhase=%s\n관측 시각=%s\nPOD_RE=%s\n' "$POD_UID" "$NODE" "$PHASE" "$OBSERVED_AT" "$POD_RE"; else printf '%s\n' '중단: Pod API 실패, UID/node/container 후보 누락, 또는 출력 생성 실패' >&2; unset POD_UID NODE PHASE POD_IP OWNER OBSERVED_AT POD_RE; fi`

성공 출력은 Pod UID·node·phase·시작 시각·UTC 관측 시각, container별 startup probe와 port 후보, state·lastState·restart·container ID를 사람이 비교할 수 있게 보여 줘야 한다. `AUTO_READY`가 아니면 부분 등록값을 사용하지 않는다. Pod `Running`은 startup target 도달·application 초기화 완료·Ready를 보장하지 않는다.

**Event 대상 container 선택 — 출력 확인 뒤 한 번 입력**

`CONTAINER='PASTE_CONTAINER_HERE'; SELECTION_READY=false; unset CONTAINER_ID RESTART_COUNT LAST_STATE; if [ "$AUTO_READY" != true ]; then printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; elif [ -z "$CONTAINER" ]; then printf '%s\n' '중단: CONTAINER를 선택한다.' >&2; elif jq -e --arg c "$CONTAINER" 'any(.spec.containers[]?; .name==$c and .startupProbe != null)' <<<"$POD_JSON" >/dev/null && CONTAINER_STATUS_COUNT_TMP="$(jq -r --arg c "$CONTAINER" '[.status.containerStatuses[]? | select(.name==$c)] | length' <<<"$POD_JSON")" && [ "$CONTAINER_STATUS_COUNT_TMP" -eq 1 ] && CONTAINER_ID_TMP="$(jq -r --arg c "$CONTAINER" '[.status.containerStatuses[]? | select(.name==$c) | .containerID] | .[0] // empty' <<<"$POD_JSON")" && RESTART_COUNT_TMP="$(jq -r --arg c "$CONTAINER" '[.status.containerStatuses[]? | select(.name==$c) | .restartCount] | .[0] // empty' <<<"$POD_JSON")" && LAST_STATE_TMP="$(jq -r --arg c "$CONTAINER" '[.status.containerStatuses[]? | select(.name==$c) | (.lastState | to_entries[0].key // "-")] | .[0] // empty' <<<"$POD_JSON")" && [ -n "$CONTAINER_ID_TMP" ] && [ -n "$RESTART_COUNT_TMP" ]; then CONTAINER_ID="$CONTAINER_ID_TMP"; RESTART_COUNT="$RESTART_COUNT_TMP"; LAST_STATE="$LAST_STATE_TMP"; SELECTION_READY=true; export CONTAINER CONTAINER_ID RESTART_COUNT LAST_STATE; printf 'SELECTION_READY=true container=%s container_id=%s restart=%s last_state=%s pod_uid=%s\n' "$CONTAINER" "$CONTAINER_ID" "$RESTART_COUNT" "$LAST_STATE" "$POD_UID"; else printf '중단: startupProbe·container status·container ID가 단일하게 확인되지 않음 container=%s\n' "$CONTAINER" >&2; unset CONTAINER_ID RESTART_COUNT LAST_STATE; fi`

복수 container를 임의로 선택하지 않는다. container ID가 바뀌면 이전 로그·Event·runtime 결과를 현재 Pod 결과와 섞지 않고 자동 수집부터 다시 한다.

이후 Pod API를 다시 조회하는 모든 경로는 최초 `$POD_UID`와 대조한다. mismatch·빈 UID·API 실패는 `UID_READY=false`로 닫고 기존 결과를 사용하지 않는다.

`pod_uid_gate(){ local current; UID_READY=false; if current="$(kubectl get pod "$POD" -n "$NS" -o jsonpath='{.metadata.uid}')" && [ -n "$current" ]; then if [ "$current" = "$POD_UID" ]; then UID_READY=true; CURRENT_POD_UID="$current"; printf 'UID_READY=true pod=%s uid=%s\n' "$POD" "$current"; return 0; else printf '중단: Pod UID mismatch initial=%s current=%s\n' "$POD_UID" "$current" >&2; return 1; fi; else printf '중단: Pod 재조회 실패 또는 UID 없음 pod=%s\n' "$POD" >&2; return 1; fi; }`

`container_evidence_gate(){ local current_json current_uid status_count status expected_container_id current_container_id current_state current_ready current_restart failure_reason; EVIDENCE_READY=false; expected_container_id="${CONTAINER_ID:-}"; if [ "${SELECTION_READY:-false}" != true ] || [ -z "$expected_container_id" ]; then failure_reason='selection gate가 닫혔거나 선택한 container ID가 없음'; elif ! current_json="$(command kubectl get pod "$POD" -n "$NS" -o json 2>/dev/null)"; then failure_reason='현재 Pod status 재조회 실패'; else current_uid="$(jq -r '.metadata.uid // empty' <<<"$current_json")"; status_count="$(jq -r --arg c "$CONTAINER" '[.status.containerStatuses[]? | select(.name==$c)] | length' <<<"$current_json")"; status="$(jq -r --arg c "$CONTAINER" '[.status.containerStatuses[]? | select(.name==$c) | [(.containerID // ""), ((.state // {}) | keys[0] // ""), ((.ready // false) | tostring), ((.restartCount // "") | tostring)] | @tsv] | if length==1 then .[0] else empty end' <<<"$current_json")"; if [ "$current_uid" != "$POD_UID" ]; then failure_reason="Pod UID mismatch initial=$POD_UID current=$current_uid"; elif [ "${status_count:-0}" -ne 1 ] || [ -z "$status" ]; then failure_reason="selected container status가 단일하게 확인되지 않음 container=$CONTAINER"; else IFS=$'\t' read -r current_container_id current_state current_ready current_restart <<<"$status"; if [ -z "$current_container_id" ]; then failure_reason="selected container의 current containerID가 비어 있음 container=$CONTAINER"; elif [ "$current_container_id" != "$expected_container_id" ]; then failure_reason="containerID mismatch selected=$expected_container_id current=$current_container_id container=$CONTAINER"; else UID_READY=true; CURRENT_POD_UID="$current_uid"; CURRENT_CONTAINER_ID="$current_container_id"; CURRENT_CONTAINER_STATE="$current_state"; CURRENT_CONTAINER_READY="$current_ready"; CURRENT_CONTAINER_RESTART_COUNT="$current_restart"; EVIDENCE_READY=true; printf 'CONTAINER_EVIDENCE_READY=true pod_uid=%s container=%s container_id=%s status=%s ready=%s restart=%s\n' "$current_uid" "$CONTAINER" "$current_container_id" "$current_state" "$current_ready" "$current_restart"; return 0; fi; fi; fi; SELECTION_READY=false; EVIDENCE_READY=false; AUTO_READY=false; unset POD_JSON CONTAINER_ID CURRENT_CONTAINER_ID CURRENT_CONTAINER_STATE CURRENT_CONTAINER_READY CURRENT_CONTAINER_RESTART_COUNT; printf '중단: %s; selection/evidence gate를 닫고 자동수집부터 재시작한다.\n' "$failure_reason" >&2; return 1; }`

`kubectl(){ if [ "${1:-}" = exec ] || [ "${1:-}" = logs ]; then container_evidence_gate || return 1; fi; command kubectl "$@"; }`

`ssh(){ case "$*" in *journalctl*) container_evidence_gate || return 1;; esac; command ssh "$@"; }`

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | startupProbe가 있는 container가 시작 또는 초기화 중이고 startup failure가 반복되는 경우 |
| 적용 | 같은 Pod UID의 `Warning Unhealthy` message에 `Startup probe failed:` 실제 suffix가 있고 target·초기화 상태·실패 예산을 확인할 수 있는 경우 |
| 제외 | startup 성공 뒤 liveness만 실패하면 [[20. Pod liveness probe가 실패하는 경우]], readiness만 실패하면 [[19. Pod readiness probe가 실패하는 경우]], image pull·init·scheduling·mount가 최초 원인이면 각각 [[07. Pod STATUS가 ImagePullBackOff·ErrImagePull인 경우]], [[05. Pod가 Init 단계에서 진행되지 않는 경우]], [[01. Pod STATUS가 Error인 경우]], [[25. Pod 이벤트에 FailedMount·FailedAttachVolume이 기록된 경우]]로 이동한다. |

검색 문자열: `Startup probe failed`, `Unhealthy`, `Killing`, `connection refused`, `context deadline exceeded`, `HTTP probe failed`, `exec probe`, `rpc error`, `CrashLoopBackOff`, `startupProbe`, `failureThreshold`, `periodSeconds`

startupProbe 성공 전에는 liveness와 readiness check가 실행되지 않는다. 그 구간의 `Ready=False`는 readiness failure나 liveness 재시작의 증거가 아니다. `initialDelaySeconds + failureThreshold * periodSeconds`는 계획용 예산일 뿐 정확한 kill 시각이 아니며 probe 실행 시간·kubelet scheduling·node 부하·Event 지연·termination grace·restart backoff가 실제 시각을 바꾼다. startup `successThreshold`는 1이어야 한다. 1.26 기본값은 `initialDelaySeconds=0`, `periodSeconds=10`, `timeoutSeconds=1`, `failureThreshold=3`, `successThreshold=1`이며 실제 spec과 API gate를 우선한다.

## 최초 확인

실행 경로는 `작업 host → kubectl client → API server → kubelet/node → runtime → container state와 Event`다. API server 조회 성공은 kubelet probe 실행이나 application 초기화를 보장하지 않는다.

**현재 identity·state·startup target 확인 — 한 줄**

`DESCRIBE_READY=false; if [ "$SELECTION_READY" != true ]; then printf '%s\n' '중단: SELECTION_READY가 아니다.' >&2; elif pod_uid_gate && kubectl get pod "$POD" -n "$NS" -o wide && kubectl describe pod "$POD" -n "$NS"; then DESCRIBE_READY=true; printf 'DESCRIBE_READY=true pod=%s uid=%s container=%s container_id=%s\n' "$POD" "$POD_UID" "$CONTAINER" "$CONTAINER_ID"; else printf '%s\n' '중단: Pod 상태 또는 describe 조회 실패/UID mismatch' >&2; fi`

출력에서 startup target/type, `State`, `Last State.reason`, exit code, restartCount, Conditions, 첫 startup suffix와 `Killing` message를 확인한다. describe의 UID가 `$POD_UID`와 다르면 이름 재사용으로 보고 중단한다.

**UID 제한 Event 한 번 조회 — startup suffix와 lifecycle을 보존하는 한 줄**

`EVENT_READY=false; EVENT_OUTPUT=''; if [ "$DESCRIBE_READY" != true ]; then printf '%s\n' '중단: DESCRIBE_READY가 아니다.' >&2; elif pod_uid_gate && EVENT_OUTPUT="$(kubectl get events -n "$NS" --field-selector "involvedObject.kind=Pod,involvedObject.name=$POD,involvedObject.uid=$POD_UID" --sort-by=.metadata.creationTimestamp -o custom-columns='UID:.involvedObject.uid,CREATED:.metadata.creationTimestamp,FIRST:.firstTimestamp,LAST:.lastTimestamp,EVENT-TIME:.eventTime,SERIES-LAST:.series.lastObservedTime,TYPE:.type,REASON:.reason,COUNT:.count,MESSAGE:.message')" && [ -n "$EVENT_OUTPUT" ]; then printf '%s\n' "$EVENT_OUTPUT"; if grep -Fq 'Startup probe failed:' <<<"$EVENT_OUTPUT"; then EVENT_READY=true; printf 'EVENT_READY=true pod_uid=%s\n' "$POD_UID"; else printf '%s\n' '중단: Event 조회는 성공했지만 startup failure suffix가 없음; 다른 lifecycle 원인으로 분기' >&2; fi; else printf '%s\n' '중단: UID 제한 Event API 실패 또는 빈 결과; 정상·원인 없음으로 해석하지 않음' >&2; fi`

`Startup probe failed:` suffix만 있고 `Killing`·restartCount 증가가 없으면 아직 실패 예산이 소진되지 않았거나 lifecycle 증거가 불완전하다. `Killing`만 있고 suffix가 없으면 startup 원인으로 확정하지 않고 [[22. Pod 이벤트에 Killing이 반복되는 경우]] 또는 [[01. Pod STATUS가 Error인 경우]]로 이동한다. Event 시각이 비거나 집계 COUNT만 있어도 정상·원인 없음으로 해석하지 않는다.

표는 원인을 확정하지 않는 길 안내다. 각 상세 절은 같은 Pod UID·container ID·UTC 시간창을 유지한다.

### 공통 로그와 kubelet 증거

진입 증거는 `EVENT_READY=true`이고 startup suffix가 보이는 경우다. `$START_RFC3339`는 suffix보다 조금 앞선 UTC 운영자 선택값이다.

`START_RFC3339='PASTE_START_RFC3339_HERE'; TIME_READY=false; START_EPOCH=''; if [ "$EVENT_READY" != true ]; then printf '%s\n' '중단: EVENT_READY가 아니다.' >&2; elif [[ "$START_RFC3339" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] && START_EPOCH="$(date -u -d "$START_RFC3339" +%s 2>/dev/null)" && [ -n "$START_EPOCH" ]; then TIME_READY=true; export START_RFC3339 START_EPOCH; printf 'TIME_READY=true start_utc=%s epoch=%s pod_uid=%s container_id=%s\n' "$START_RFC3339" "$START_EPOCH" "$POD_UID" "$CONTAINER_ID"; else printf '%s\n' '중단: START_RFC3339 형식 또는 UTC 시각이 유효하지 않음' >&2; fi`

`logs_filtered(){ local mode="$1" pattern="$2" log_file producer_rc filter_output filter_rc; if [ "$TIME_READY" != true ] || [ "$SELECTION_READY" != true ] || ! pod_uid_gate; then printf '%s\n' '중단: log 시간·container 선택·UID gate가 아니다.' >&2; return 1; fi; log_file="$(mktemp)"; if ! container_evidence_gate; then rm -f "$log_file"; return 1; fi; if [ "$mode" = previous ]; then kubectl logs "$POD" -n "$NS" -c "$CONTAINER" --previous --timestamps --since-time="$START_RFC3339" --tail=200 >"$log_file"; else kubectl logs "$POD" -n "$NS" -c "$CONTAINER" --timestamps --since-time="$START_RFC3339" --tail=200 >"$log_file"; fi; producer_rc=$?; LOG_PRODUCER_RC="$producer_rc"; if [ "$producer_rc" -ne 0 ]; then printf 'logs producer 실패 rc=%s mode=%s pod_uid=%s container_id=%s\n' "$producer_rc" "$mode" "$POD_UID" "$CONTAINER_ID" >&2; rm -f "$log_file"; return "$producer_rc"; fi; filter_output="$(grep -E -i -C 3 "$pattern" "$log_file")"; filter_rc=$?; LOG_FILTER_RC="$filter_rc"; if [ "$filter_rc" -eq 0 ]; then printf '%s\n' "$filter_output"; elif [ "$filter_rc" -eq 1 ]; then printf 'logs filter no-match producer_rc=0 filter_rc=1 mode=%s pod_uid=%s container_id=%s\n' "$mode" "$POD_UID" "$CONTAINER_ID" >&2; else printf 'logs filter 실패 producer_rc=0 filter_rc=%s mode=%s\n' "$filter_rc" "$mode" >&2; rm -f "$log_file"; return "$filter_rc"; fi; rm -f "$log_file"; return 0; }`

로그 경로는 `작업 host → API server → kubelet → runtime log stream → current/previous container output`이다. `LOG_READY`는 stream 성공 gate이며 application 정상 gate가 아니다.

**현재 bounded 로그 — stream 실패와 빈 필터를 분리하는 한 줄**

`LOG_READY=false; LOG_PRODUCER_RC=''; LOG_FILTER_RC=''; if logs_filtered current 'startup|entrypoint|config|migration|cache|data|listen|bind|ready|health|probe|panic|fatal|error|timeout|refused|denied|permission|oom|killed|dependency'; then LOG_READY=true; printf 'LOG_STREAM_READY=true producer_rc=%s filter_rc=%s pod_uid=%s container_id=%s window_start=%s\n' "$LOG_PRODUCER_RC" "$LOG_FILTER_RC" "$POD_UID" "$CONTAINER_ID" "$START_RFC3339"; else printf '중단: logs stream producer/filter 실패 producer_rc=%s filter_rc=%s pod_uid=%s container_id=%s\n' "$LOG_PRODUCER_RC" "$LOG_FILTER_RC" "$POD_UID" "$CONTAINER_ID" >&2; fi`

`restartCount>0` 또는 `Last State.terminated`가 이전 instance를 가리킬 때만 previous 로그를 실행한다. 빈 필터 결과는 같은 시간창의 비식별화된 tail로 재확인하되 Secret·token·개인정보가 보이면 중단한다. 이전 로그가 없으면 Last State의 startedAt·finishedAt·reason·exitCode 범위로 결론을 제한한다.

**필터가 비었을 때 current tail 재확인 — bounded 한 줄**

`if [ "$LOG_READY" != true ]; then printf '%s\n' '중단: LOG_READY가 아니다.' >&2; elif pod_uid_gate && kubectl logs "$POD" -n "$NS" -c "$CONTAINER" --timestamps --since-time="$START_RFC3339" --tail=50; then printf 'current tail stream 성공 producer_rc=0 pod_uid=%s container_id=%s window_start=%s\n' "$POD_UID" "$CONTAINER_ID" "$START_RFC3339"; else printf '%s\n' 'current tail producer 실패 또는 UID mismatch: 로그 계층 오류를 확인' >&2; fi`

**조건부 previous 로그 — lifecycle 근거가 있을 때만 한 줄**

`PREVIOUS_READY=false; if [ "$LOG_READY" != true ]; then printf '%s\n' '중단: LOG_READY가 아니다.' >&2; elif [ "$RESTART_COUNT" -gt 0 ] || [ "$LAST_STATE" = terminated ]; then if logs_filtered previous 'startup|entrypoint|config|migration|cache|data|listen|bind|ready|health|probe|panic|fatal|error|timeout|refused|denied|permission|oom|killed|dependency'; then PREVIOUS_READY=true; printf 'PREVIOUS_LOG_STREAM_READY=true producer_rc=%s filter_rc=%s pod_uid=%s container_id=%s window_start=%s\n' "$LOG_PRODUCER_RC" "$LOG_FILTER_RC" "$POD_UID" "$CONTAINER_ID" "$START_RFC3339"; else printf 'previous logs producer/filter 실패 producer_rc=%s filter_rc=%s pod_uid=%s container_id=%s\n' "$LOG_PRODUCER_RC" "$LOG_FILTER_RC" "$POD_UID" "$CONTAINER_ID" >&2; fi; else printf '%s\n' '중단: restart 또는 terminated Last State 근거가 없어 previous 로그를 실행하지 않음' >&2; fi`

**previous filter가 비었을 때 tail 재확인 — 조건부 bounded 한 줄**

`if [ "$LOG_READY" != true ]; then printf '%s\n' '중단: LOG_READY가 아니다.' >&2; elif [ "$RESTART_COUNT" -gt 0 ] || [ "$LAST_STATE" = terminated ]; then if pod_uid_gate && kubectl logs "$POD" -n "$NS" -c "$CONTAINER" --previous --timestamps --since-time="$START_RFC3339" --tail=50; then printf 'previous tail stream 성공 producer_rc=0 pod_uid=%s container_id=%s window_start=%s\n' "$POD_UID" "$CONTAINER_ID" "$START_RFC3339"; else printf '%s\n' 'previous tail producer 실패 또는 UID mismatch: 이전 instance를 확인' >&2; fi; else printf '%s\n' '중단: restart 또는 terminated Last State 근거가 없어 previous tail을 실행하지 않음' >&2; fi`

### 승인된 Node identity

`NODE_HOST`는 작업 PC에서 접속할 승인된 remote host이며 Kubernetes `$NODE`의 SSH 별칭으로 자동 추측하지 않는다. SSH gate가 remote `hostname`을 Kubernetes `$NODE`와 정확히 대조한 뒤에만 remote journal/CRI를 실행한다. 대조 실패·SSH host key/권한 실패·hostname mapping 불일치는 node owner에게 이관하고 작업 PC의 local journal/CRI를 실행하지 않는다.

`NODE_HOST='PASTE_NODE_HOST_HERE'; NODE_SSH_READY=false; REMOTE_NODE=''; if [ "$EVENT_READY" != true ]; then printf '%s\n' '중단: EVENT_READY가 아니다.' >&2; elif [ -z "$NODE_HOST" ]; then printf '%s\n' '중단: NODE_HOST를 선택한다.' >&2; elif pod_uid_gate && REMOTE_NODE="$(ssh -o BatchMode=yes -o ConnectTimeout=10 "$NODE_HOST" hostname 2>&1)"; then REMOTE_NODE="${REMOTE_NODE//$'\r'/}"; if [ "$REMOTE_NODE" = "$NODE" ]; then NODE_SSH_READY=true; printf 'NODE_SSH_READY=true kubernetes_node=%s remote_node=%s node_host=%s pod_uid=%s\n' "$NODE" "$REMOTE_NODE" "$NODE_HOST" "$POD_UID"; else printf '중단: remote identity mismatch kubernetes_node=%s remote_node=%s node_host=%s\n' "$NODE" "$REMOTE_NODE" "$NODE_HOST" >&2; fi; else printf '중단: SSH remote identity 조회 실패 node_host=%s; local journal/CRI를 실행하지 않음\n' "$NODE_HOST" >&2; fi`

**승인된 node의 kubelet journal 준비 — 도구·권한 실패 뒤 진행하지 않는 한 줄**

`START_JOURNAL='PASTE_START_JOURNAL_HERE'; END_JOURNAL='PASTE_END_JOURNAL_HERE'; JOURNAL_READY=false; START_JOURNAL_EPOCH=''; END_JOURNAL_EPOCH=''; if [ "$NODE_SSH_READY" != true ]; then printf '%s\n' '중단: NODE_SSH_READY가 아니다.' >&2; elif [[ "$START_JOURNAL" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}\ [0-9]{2}:[0-9]{2}:[0-9]{2}\ UTC$ ]] && [[ "$END_JOURNAL" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}\ [0-9]{2}:[0-9]{2}:[0-9]{2}\ UTC$ ]] && START_JOURNAL_EPOCH="$(date -u -d "$START_JOURNAL" +%s 2>/dev/null)" && END_JOURNAL_EPOCH="$(date -u -d "$END_JOURNAL" +%s 2>/dev/null)" && [ -n "$START_JOURNAL_EPOCH" ] && [ -n "$END_JOURNAL_EPOCH" ] && (( START_JOURNAL_EPOCH < END_JOURNAL_EPOCH )); then if REMOTE_JOURNAL_TOOLS="$(ssh -o BatchMode=yes -o ConnectTimeout=10 "$NODE_HOST" 'command -v journalctl >/dev/null 2>&1 && sudo -n journalctl --version >/dev/null 2>&1' 2>&1)"; then JOURNAL_READY=true; printf 'JOURNAL_READY=true remote_node=%s node_host=%s window=%s..%s\n' "$REMOTE_NODE" "$NODE_HOST" "$START_JOURNAL" "$END_JOURNAL"; else printf '중단: remote journalctl/sudo 전제 실패 output=%s\n' "$REMOTE_JOURNAL_TOOLS" >&2; fi; else printf '%s\n' '중단: journal 형식 또는 시간 순서가 유효하지 않음 start=YYYY-MM-DD HH:MM:SS UTC end=YYYY-MM-DD HH:MM:SS UTC, start<end' >&2; fi`

`remote_journal_filtered(){ local unit="$1" pattern="$2" remote_output producer_rc filter_output filter_rc; JOURNAL_FILTER_RC=0; if [ "$NODE_SSH_READY" != true ] || [ "$JOURNAL_READY" != true ]; then printf '%s\n' '중단: remote journal gate가 아니다.' >&2; return 1; elif remote_output="$(ssh -o BatchMode=yes -o ConnectTimeout=10 "$NODE_HOST" "sudo journalctl -u $unit --since \"$START_JOURNAL\" --until \"$END_JOURNAL\" --no-pager --lines=2000" 2>&1)"; then producer_rc=0; else producer_rc=$?; fi; JOURNAL_PRODUCER_RC="$producer_rc"; if [ "$producer_rc" -ne 0 ]; then printf 'remote journal producer 실패 rc=%s unit=%s remote_node=%s\n' "$producer_rc" "$unit" "$REMOTE_NODE" >&2; return "$producer_rc"; elif [ -z "$remote_output" ]; then printf 'remote journal producer rc=0 records=empty unit=%s; 정상·오류 없음으로 해석하지 않음\n' "$unit" >&2; JOURNAL_FILTER_RC=1; return 0; else filter_output="$(printf '%s\n' "$remote_output" | grep -E -i -C 3 "$pattern")"; filter_rc=$?; JOURNAL_FILTER_RC="$filter_rc"; if [ "$filter_rc" -eq 0 ]; then printf '%s\n' "$filter_output"; elif [ "$filter_rc" -eq 1 ]; then printf 'remote journal filter no-match producer_rc=0 filter_rc=1 unit=%s pod_uid=%s\n' "$unit" "$POD_UID" >&2; else printf 'remote journal filter 실패 producer_rc=0 filter_rc=%s unit=%s\n' "$filter_rc" >&2; return "$filter_rc"; fi; fi; }`

**bounded kubelet journal — 한 줄**

`if [ "$JOURNAL_READY" != true ] || [ "$NODE_SSH_READY" != true ]; then printf '%s\n' '중단: JOURNAL_READY 또는 NODE_SSH_READY가 아니다.' >&2; elif remote_journal_filtered kubelet "$POD_UID|$POD|$CONTAINER|startup|probe|unhealthy|killing|timeout|refused|mount|oom|error|runtime|cni"; then if [ "$JOURNAL_FILTER_RC" -eq 1 ]; then printf 'kubelet journal filter no-match producer_rc=%s filter_rc=1 pod_uid=%s remote_node=%s\n' "$JOURNAL_PRODUCER_RC" "$POD_UID" "$REMOTE_NODE"; else printf 'kubelet journal stream 성공 producer_rc=%s filter_rc=%s pod_uid=%s remote_node=%s\n' "$JOURNAL_PRODUCER_RC" "$JOURNAL_FILTER_RC" "$POD_UID" "$REMOTE_NODE"; fi; else printf 'kubelet journal remote 수집 실패 producer_rc=%s filter_rc=%s pod_uid=%s remote_node=%s\n' "$JOURNAL_PRODUCER_RC" "$JOURNAL_FILTER_RC" "$POD_UID" "$REMOTE_NODE" >&2; fi`

같은 시간의 `migration step` 진전은 느린 정상 기동 후보이고, panic·permission·bind·OOMKilled는 각각 app/config, mount, port, resource 경로다. journal filter가 비어도 kubelet 정상은 보장하지 않는다.

### Probe type과 target

진입 증거는 startup suffix가 있고 선택 container의 startupProbe가 현재 spec에 존재하는 경우다. `$CONTAINER`와 `$POD_JSON`에서 HTTP host/path/scheme/header 이름, TCP host/port, exec command, gRPC port/service, timing을 읽는다.

`TARGET_READY=false; unset PROBE_SCHEME PROBE_PATH PROBE_HOST PROBE_PATH_HAS_QUERY HTTP_HEADER_COUNT HTTP_HEADER_NAMES; if [ "$EVENT_READY" != true ] || [ "$SELECTION_READY" != true ]; then printf '%s\n' '중단: Event와 container 선택 gate가 아니다.' >&2; elif TARGET_OUTPUT="$(jq -r --arg c "$CONTAINER" '.spec.containers[] | select(.name==$c) | "container=\(.name) HTTP=\(.startupProbe.httpGet.host // "-")/\((.startupProbe.httpGet.path // "-") | split("?")[0])/\(.startupProbe.httpGet.port // "-")/\(.startupProbe.httpGet.scheme // "-") TCP=\(.startupProbe.tcpSocket.host // "-")/\(.startupProbe.tcpSocket.port // "-") exec_binary=\(.startupProbe.exec.command[0] // "-") exec_arg_count=\((.startupProbe.exec.command // [])|length) gRPC=\(.startupProbe.grpc.port // "-")/\(.startupProbe.grpc.service // "-") timing=\(.startupProbe.initialDelaySeconds // 0),\(.startupProbe.timeoutSeconds // 1),\(.startupProbe.periodSeconds // 10),\(.startupProbe.failureThreshold // 3),\(.startupProbe.successThreshold // 1),\(.startupProbe.terminationGracePeriodSeconds // "Pod-level/default") ports=\([.ports[]? | ((.name // "unnamed") + ":" + (.containerPort|tostring))] | join(",") // "없음")"' <<<"$POD_JSON")" && [ -n "$TARGET_OUTPUT" ]; then PROBE_SCHEME="$(jq -r --arg c "$CONTAINER" '.spec.containers[] | select(.name==$c) | .startupProbe.httpGet.scheme // empty' <<<"$POD_JSON")"; PROBE_PATH="$(jq -r --arg c "$CONTAINER" '.spec.containers[] | select(.name==$c) | (.startupProbe.httpGet.path // "") | split("?")[0]' <<<"$POD_JSON")"; PROBE_PATH_HAS_QUERY="$(jq -r --arg c "$CONTAINER" '.spec.containers[] | select(.name==$c) | (.startupProbe.httpGet.path // "") | contains("?")' <<<"$POD_JSON")"; PROBE_HOST="$(jq -r --arg c "$CONTAINER" '.spec.containers[] | select(.name==$c) | .startupProbe.httpGet.host // empty' <<<"$POD_JSON")"; HTTP_HEADER_COUNT="$(jq -r --arg c "$CONTAINER" '[.spec.containers[] | select(.name==$c) | .startupProbe.httpGet.httpHeaders[]?.name | select(type=="string")] | length' <<<"$POD_JSON")"; HTTP_HEADER_NAMES="$(jq -r --arg c "$CONTAINER" '[.spec.containers[] | select(.name==$c) | .startupProbe.httpGet.httpHeaders[]?.name | select(type=="string")] | unique | if length==0 then "-" else join(",") end' <<<"$POD_JSON")"; TARGET_READY=true; export PROBE_SCHEME PROBE_PATH PROBE_HOST PROBE_PATH_HAS_QUERY HTTP_HEADER_COUNT HTTP_HEADER_NAMES; printf '%s\n' "$TARGET_OUTPUT"; printf 'TARGET_READY=true scheme=%s path=%s query_present=%s host=%s http_headers_count=%s http_header_names=%s\n' "${PROBE_SCHEME:--}" "${PROBE_PATH:--}" "${PROBE_PATH_HAS_QUERY:-false}" "${PROBE_HOST:--}" "$HTTP_HEADER_COUNT" "$HTTP_HEADER_NAMES"; else printf '%s\n' '중단: 선택 container의 startupProbe 또는 target field가 현재 spec에서 확인되지 않음' >&2; fi`

성공 gate는 target과 container port 관계가 출력되는 것이다. named port가 단일 선언으로 대조되지 않으면 port를 추측하지 않고 manifest owner에게 이관한다. 선언된 `containerPort`는 process listener·bind·protocol을 보장하지 않는다.

**startup probe port 해석 — 한 줄**

`PORT_READY=false; unset PROBE_PORT_RAW PROBE_PORT; if [ "$TARGET_READY" != true ]; then printf '%s\n' '중단: TARGET_READY가 아니다.' >&2; elif PROBE_PORT_RAW="$(jq -r --arg c "$CONTAINER" '.spec.containers[] | select(.name==$c) | (.startupProbe.httpGet.port // .startupProbe.tcpSocket.port // .startupProbe.grpc.port // empty)' <<<"$POD_JSON")" && [ -n "$PROBE_PORT_RAW" ]; then if [[ "$PROBE_PORT_RAW" =~ ^[0-9]+$ ]]; then PROBE_PORT="$PROBE_PORT_RAW"; else PORT_MATCHES="$(jq -r --arg c "$CONTAINER" --arg p "$PROBE_PORT_RAW" '[.spec.containers[] | select(.name==$c) | .ports[]? | select(.name==$p) | .containerPort] | if length==1 then .[0]|tostring else empty end' <<<"$POD_JSON")"; [ -n "$PORT_MATCHES" ] && PROBE_PORT="$PORT_MATCHES"; fi; if [[ "${PROBE_PORT:-}" =~ ^[0-9]+$ ]] && (( PROBE_PORT >= 1 && PROBE_PORT <= 65535 )); then PORT_READY=true; export PROBE_PORT; printf 'PORT_READY=true raw=%s resolved=%s container=%s\n' "$PROBE_PORT_RAW" "$PROBE_PORT" "$CONTAINER"; else printf '중단: startup port가 단일 숫자 port로 해석되지 않음 raw=%s\n' "$PROBE_PORT_RAW" >&2; unset PROBE_PORT; fi; else printf '%s\n' '중단: startup port가 비어 있음' >&2; fi`

`PORT_READY=true`는 숫자 endpoint 후보만 확인한다. 빈 결과는 field 부재·named port 불일치·조회 실패 후보이며 정상 listener나 startup 성공이 아니다.

### HTTP

진입 증거는 HTTP 4xx·5xx, timeout 또는 refused suffix다. 경로는 `작업 host → API server → kubelet/node → Pod IP:$PROBE_PORT → HTTP/HTTPS listener → 초기화 route/dependency`다. custom host는 localhost 보조 결과로 대체하지 않는다.

**container 내부 HTTP 보조 확인 — transport와 HTTP status를 분리하는 한 줄**

`HTTP_OBS_READY=false; if [ "$PORT_READY" != true ] || [ "$LOG_READY" != true ] || [ "$TARGET_READY" != true ]; then printf '%s\n' '중단: PORT_READY·LOG_READY·TARGET_READY가 아니다.' >&2; elif ! jq -e --arg c "$CONTAINER" 'any(.spec.containers[]?; .name==$c and .startupProbe.httpGet != null)' <<<"$POD_JSON" >/dev/null; then printf '%s\n' '중단: selected startupProbe.httpGet가 없어 localhost HTTP 보조 관측을 실행하지 않음; TCP/gRPC/exec target은 해당 경로로 이관' >&2; elif [ "${HTTP_HEADER_COUNT:-0}" -gt 0 ] || [ "${PROBE_PATH_HAS_QUERY:-false}" = true ]; then printf '이관: httpHeaders names=%s count=%s 또는 query path가 있어 localhost HTTP 동등 관측을 실행하지 않고 application owner/kubelet evidence로 이관한다. query_present=%s\n' "${HTTP_HEADER_NAMES:--}" "${HTTP_HEADER_COUNT:-0}" "${PROBE_PATH_HAS_QUERY:-false}" >&2; elif [ -n "$PROBE_HOST" ]; then printf '중단: custom startup host=%s는 localhost와 같지 않음; kubelet Pod IP 경로를 확인\n' "$PROBE_HOST" >&2; elif pod_uid_gate && kubectl exec "$POD" -n "$NS" -c "$CONTAINER" -- sh -c 'scheme="$1"; port="$2"; path="$3"; if command -v curl >/dev/null 2>&1; then rc=0; out="$(curl --noproxy "*" -sS -o /dev/null -w "transport=ok http_status=%{http_code} time_total=%{time_total}" --connect-timeout 3 --max-time 5 "${scheme}://127.0.0.1:${port}${path}")" || rc=$?; printf "%s curl_rc=%s\n" "$out" "$rc"; [ "$rc" -eq 0 ]; elif command -v wget >/dev/null 2>&1; then if wget -qO /dev/null -T 3 "${scheme}://127.0.0.1:${port}${path}"; then printf "%s\n" "transport=ok http_status=unreported"; else printf "%s\n" "transport=failed http_status=000" >&2; exit 1; fi; else printf "%s\n" "probe_tool_missing=curl,wget" >&2; exit 127; fi' sh "${PROBE_SCHEME:-http}" "$PROBE_PORT" "${PROBE_PATH:-/}"; then HTTP_OBS_READY=true; printf 'HTTP_OBS_READY=true pod_uid=%s container_id=%s\n' "$POD_UID" "$CONTAINER_ID"; else printf '%s\n' 'HTTP 보조 확인 실패: transport·listener·초기화 계층을 다음 분기로 확인' >&2; fi`

HTTP 200 이상 400 미만은 probe 성공 범위지만 초기화 완료·dependency 정상·Ready·실제 Service 요청 성공을 단독 보장하지 않는다. 404는 path/route, 401/403은 인증·인가, 5xx는 app/dependency, refused는 bind/listener, timeout은 초기화 hang·resource·node·network 후보다. HTTPS certificate 검증을 우회하지 않는다.

### TCP

진입 증거는 TCP refused 또는 timeout suffix다. 경로는 `작업 host → API server → kubelet/node → Pod IP:$PROBE_PORT → listener → initialization process`이며 Service DNS/port는 자동으로 사용되지 않는다.

**listener bounded 확인 — 한 줄**

`if [ "$PORT_READY" != true ]; then printf '%s\n' '중단: PORT_READY가 아니다.' >&2; elif kubectl exec "$POD" -n "$NS" -c "$CONTAINER" -- sh -c 'if command -v ss >/dev/null 2>&1; then ss -lnt; elif command -v netstat >/dev/null 2>&1; then netstat -lnt; else printf "%s\n" "listener_tool_missing=ss,netstat" >&2; exit 127; fi'; then printf 'listener stream 성공 pod_uid=%s container_id=%s port=%s\n' "$POD_UID" "$CONTAINER_ID" "$PROBE_PORT"; else printf '%s\n' 'listener 조회 실패: exec/runtime 또는 image tool 계층으로 이관' >&2; fi`

listener가 없으면 app 초기화·port owner로, listener가 있는데 timeout이면 Pod IP·NetworkPolicy·CNI·node resource로 이동한다. TCP open은 application readiness나 실제 Service 요청을 보장하지 않는다. 빈 listener 출력은 정상으로 해석하지 않는다.

### exec

진입 증거는 exec exit 오류·file missing·permission denied·timeout suffix다. 경로는 `작업 host → API server → kubelet → runtime exec stream → container namespace → command binary/file`이며 Pod IP·Service DNS는 경로가 아니다.

**첫 binary 존재만 확인 — side effect를 만들지 않는 한 줄**

`if [ "$TARGET_READY" != true ] || [ "$LOG_READY" != true ]; then printf '%s\n' '중단: TARGET_READY 또는 LOG_READY가 아니다.' >&2; elif EXEC_BINARY="$(jq -r --arg c "$CONTAINER" '.spec.containers[] | select(.name==$c) | .startupProbe.exec.command[0] // empty' <<<"$POD_JSON")" && [ -n "$EXEC_BINARY" ]; then if kubectl exec "$POD" -n "$NS" -c "$CONTAINER" -- sh -c 'command -v "$1" >/dev/null 2>&1' sh "$EXEC_BINARY"; then printf 'exec_binary=present pod_uid=%s container_id=%s binary=%s\n' "$POD_UID" "$CONTAINER_ID" "$EXEC_BINARY"; else printf 'exec binary 확인 실패: PATH·image·runtime exec 계층을 확인 binary=%s\n' "$EXEC_BINARY" >&2; fi; else printf '%s\n' '중단: exec binary가 spec에서 확인되지 않음' >&2; fi`

1.26의 `ExecProbeTimeout`은 GA·기본 활성화다. binary 존재는 argv·exit code 0·파일 생성 순서·mount·권한·resource 상태를 보장하지 않는다. command를 삭제하거나 무조건 성공하게 만들지 않고, 진단 중 전체 probe command를 임의 실행하지 않는다.

### gRPC

진입 증거는 `rpc error` 또는 gRPC health 오류 suffix다. 경로는 `작업 host → API server → kubelet/node → Pod IP:$PROBE_PORT → gRPC Health Checking Protocol → initialization state`다.

`GRPCContainerProbe`는 1.26 Beta·기본 활성화지만 feature gate와 API 수용 확인 전 기본 기능으로 단정하지 않는다. gRPC probe는 숫자 port·optional service만 사용하며 named port·custom host·TLS/auth parameter를 사용하지 않는다. `Unavailable`, `DeadlineExceeded`, `NOT_SERVING`은 failure 후보이고 health service 미구현과 dependency 미준비·network 경로를 분리한다. gate가 꺼졌거나 API가 field를 거부하면 HTTP/TCP/exec로 임의 변경하지 않고 owner에게 이관한다.

### 애플리케이션 초기화 단계

진입 증거는 target이 API spec과 맞지만 startup suffix가 반복되는 경우다. 다음 순서에서 마지막 진전 시각과 suffix 시각을 같은 UTC 기준으로 대조한다.

```text
entrypoint 실행
→ 설정·환경 로드
→ migration
→ cache/data load
→ listener bind
→ startup target 성공
→ liveness/readiness 실행 시작
```

로그의 migration 진전·cache load가 계속되고 target이 예산 뒤 성공하면 느린 정상 기동 후보다. panic·설정 누락·permission denied·bind address already in use·OOMKilled가 직접 보이면 app/config·mount/security·port·resource 계층으로 이관한다. startup 실패 구간에서 liveness를 조정하지 않는다.

### CPU·memory·disk

진입 증거는 초기화 timeout·종료와 resource pressure가 같은 시간창에 보이는 경우다. `$POD`, `$CONTAINER`, `$NODE`는 API 자동값·선택값에서 이미 gate를 통과해야 한다.

`RESOURCE_READY=false; if [ "$SELECTION_READY" != true ]; then printf '%s\n' '중단: SELECTION_READY가 아니다.' >&2; elif pod_uid_gate && kubectl get pod "$POD" -n "$NS" -o jsonpath='{range .spec.containers[?(@.name=="'$CONTAINER'")]}container={.name}{" requests="}{.resources.requests}{" limits="}{.resources.limits}{"\n"}{end}' && kubectl top pod "$POD" -n "$NS" --containers && kubectl get node "$NODE" -o custom-columns='NODE:.metadata.name,READY:.status.conditions[?(@.type=="Ready")].status,MEMORYPRESSURE:.status.conditions[?(@.type=="MemoryPressure")].status,DISKPRESSURE:.status.conditions[?(@.type=="DiskPressure")].status,PIDPRESSURE:.status.conditions[?(@.type=="PIDPressure")].status' && kubectl describe node "$NODE"; then RESOURCE_READY=true; printf 'RESOURCE_READY=true node=%s pod_uid=%s container_id=%s\n' "$NODE" "$POD_UID" "$CONTAINER_ID"; else printf '%s\n' 'resource 조회 실패 또는 Metrics Server/API 권한 미확인/UID mismatch; empty를 0으로 해석하지 않음' >&2; fi`

limit 대비 CPU/memory, CPU throttling 지표, `OOMKilled`, ephemeral storage와 node pressure를 함께 확인한다. `kubectl top` 실패는 usage 0이 아니며 Metrics Server·APIService·권한 문제일 수 있다. container cgroup limit 또는 node pressure가 직접 보이면 startup timing 완화가 아니라 해당 owner로 이관한다.

### Mount와 파일 의존성

진입 증거는 로그·Event에 설정/인증서/data/exec target missing, `FailedMount`, missing key, read-only 또는 PVC 대기가 보이는 경우다. 출력에서 Pod volume과 선택 container의 mountPath·volume 관계를 먼저 확인한다.

**volume·mount 관계 출력 — Pod scope로 제한한 한 줄**

`MOUNT_READY=false; if [ "$SELECTION_READY" != true ]; then printf '%s\n' '중단: SELECTION_READY가 아니다.' >&2; elif jq -e --arg c "$CONTAINER" 'any(.spec.containers[]?; .name==$c)' <<<"$POD_JSON" >/dev/null && MOUNT_OUTPUT="$(jq -r --arg c "$CONTAINER" '"=== volume 관계 ===\nPod UID: \(.metadata.uid)\n" + ([.spec.volumes[]? | "volume=\(.name) config=\(.configMap.name // "-") secret=\(.secret.secretName // "-") pvc=\(.persistentVolumeClaim.claimName // "-")"] | join("\n")) + "\nmount:\n" + ([.spec.containers[] | select(.name==$c) | .volumeMounts[]? | "container=\($c) mount=\(.mountPath) volume=\(.name) readOnly=\(.readOnly // false)"] | join("\n"))' <<<"$POD_JSON")" && [ -n "$MOUNT_OUTPUT" ]; then printf '%s\n' "$MOUNT_OUTPUT"; MOUNT_READY=true; printf 'MOUNT_READY=true pod_uid=%s container_id=%s\n' "$POD_UID" "$CONTAINER_ID"; else printf '%s\n' 'volume/mount API 또는 출력 실패: empty를 관계 정상으로 해석하지 않음' >&2; fi`

`MOUNT_READY=true`는 object 관계 출력 성공만 보장한다. volume source와 mountPath가 비거나 여러 PVC 후보가 있으면 PVC를 임의 선택하지 않는다. PVC가 실제로 관련될 때만 아래 운영자 선택을 수행한다.

`PVC='PASTE_PVC_HERE'; MOUNT_PVC_READY=false; if [ "$MOUNT_READY" != true ]; then printf '%s\n' '중단: MOUNT_READY가 아니다.' >&2; elif jq -e --arg pvc "$PVC" 'any(.spec.volumes[]?.persistentVolumeClaim?; .claimName==$pvc)' <<<"$POD_JSON" >/dev/null && kubectl get pvc "$PVC" -n "$NS" -o custom-columns='PVC:.metadata.name,UID:.metadata.uid,CREATED:.metadata.creationTimestamp,PHASE:.status.phase,PV:.spec.volumeName,CAPACITY:.status.capacity.storage,ACCESS:.status.accessModes,STORAGE-CLASS:.spec.storageClassName'; then MOUNT_PVC_READY=true; printf 'MOUNT_PVC_READY=true pvc=%s pod_uid=%s\n' "$PVC" "$POD_UID"; else printf 'PVC 관계 또는 조회 실패 pvc=%s: 이름·scope·권한·Pod volume mapping을 확인하고 빈 결과를 Bound/정상으로 해석하지 않음\n' "$PVC" >&2; fi`

PVC `Bound`는 file 접근·CSI attach·filesystem 정상이나 startup 성공을 보장하지 않는다. `FailedMount`·missing key·read-only·미바인딩 PVC는 각각 PVC/CSI/kubelet/OS owner로 이관한다. Secret 원문과 인증서 개인키는 읽거나 저장하지 않는다.

### Pod DNS와 Service

진입 증거는 app log가 Service/DNS를 기다리거나 startup target 도달 전 연결 오류를 보이는 경우다. 내부 Service 경로는 `container network namespace → DNS resolver → Service ClusterIP/EndpointSlice → backend Pod IP/port`; 외부 dependency는 이 경로 밖이다.

`SERVICE='PASTE_SERVICE_HERE'; SERVICE_INPUT_READY=false; if [ "$MOUNT_READY" != true ]; then printf '%s\n' '중단: MOUNT_READY가 아니다.' >&2; elif [ -n "$SERVICE" ]; then SERVICE_INPUT_READY=true; export SERVICE; printf 'SERVICE_INPUT_READY=true service=%s\n' "$SERVICE"; else printf '%s\n' '중단: SERVICE를 선택한다.' >&2; fi`

성공 gate는 selector·Service port/targetPort·EndpointSlice 주소와 conditions·Pod DNS policy를 함께 확인하는 것이다. EndpointSlice가 비면 backend Ready·selector를 확인하고 [[19. Pod readiness probe가 실패하는 경우]]로 연결한다. ### 외부 DB·API·queue

진입 증거는 내부 Service가 정상인데 app log가 외부 dependency 연결·인증·migration lock·rate limit에서 멈추는 경우다. 외부 system으로의 실제 확인은 application owner가 지정한 side-effect-free 승인 절차와 도구를 사용한다. 이 런북은 임의 DNS·TCP·HTTP·DB 명령을 발명하거나 외부 상태 변경·재처리를 실행하지 않는다.

성공 gate는 Pod 내부 DNS/TCP/TLS/auth 관측과 외부 owner의 service health evidence가 같은 UTC 창에서 일치하는 것이다. 빈 로그는 dependency 정상이나 credential 정상의 증거가 아니다. 인증 실패·timeout·TLS 오류·migration lock·queue 권한 오류를 해당 owner에게 Pod UID·container ID·시간창과 함께 이관한다.

### kubelet과 container runtime

진입 증거는 Pod spec·app log·resource·mount·dependency가 직접 원인을 설명하지 못하고 probe 실행 또는 lifecycle만 비정상인 경우다. 경로는 `작업 host → API server → node/kubelet → CRI/runtime → container ID → probe process`다.

`RUNTIME_READY=false; if [ "$RESOURCE_READY" != true ] || [ "$NODE_SSH_READY" != true ] || [ "$JOURNAL_READY" != true ]; then printf '%s\n' '중단: RESOURCE_READY·NODE_SSH_READY·JOURNAL_READY가 아니다.' >&2; elif RUNTIME_VERSION="$(kubectl get node "$NODE" -o jsonpath='{.status.nodeInfo.containerRuntimeVersion}')" && [ -n "$RUNTIME_VERSION" ]; then printf 'runtime=%s node=%s pod_uid=%s remote_node=%s\n' "$RUNTIME_VERSION" "$NODE" "$POD_UID" "$REMOTE_NODE"; if [[ "$RUNTIME_VERSION" == containerd://* ]]; then if remote_journal_filtered containerd "$CONTAINER_ID|$POD_UID|stop|start|oci|error|timeout|oom"; then if [ "$JOURNAL_FILTER_RC" -eq 1 ]; then printf 'containerd journal filter no-match producer_rc=%s filter_rc=1 pod_uid=%s remote_node=%s\n' "$JOURNAL_PRODUCER_RC" "$POD_UID" "$REMOTE_NODE"; else RUNTIME_READY=true; printf 'containerd journal stream 성공 producer_rc=%s filter_rc=%s pod_uid=%s remote_node=%s\n' "$JOURNAL_PRODUCER_RC" "$JOURNAL_FILTER_RC" "$POD_UID" "$REMOTE_NODE"; fi; else printf 'containerd remote 수집 실패 producer_rc=%s filter_rc=%s pod_uid=%s remote_node=%s\n' "$JOURNAL_PRODUCER_RC" "$JOURNAL_FILTER_RC" "$POD_UID" "$REMOTE_NODE" >&2; fi; else printf '%s\n' 'container runtime 구현체 또는 API 조회 미확정; containerd/CRI 명령을 추측하지 않음' >&2; fi; else printf '%s\n' '중단: runtime version API 조회 실패' >&2; fi`

`containerRuntimeVersion`의 scheme을 CRI endpoint로 재사용하지 않는다. `failed to exec in container`, `OCI runtime exec failed`가 있으면 runtime/Linux owner로, startup suffix만 반복되면 app target 분기로 이동한다. runtime journal 빈 결과도 오류 없음이 아니며 node·runtime owner에게 bounded evidence를 이관한다.

## 분기별 결론과 제한적 복구

### 느린 정상 기동

초기화 로그가 계속 진전하고 startup target이 예산 이후 성공하며 CPU·memory·disk·mount·dependency가 정상일 때만 느린 정상 기동 후보로 기록한다. owner가 승인하고 측정된 worst-case 초기화 시간이 근거로 남은 경우에만 startup 시간 예산을 조정한다. 기대 효과는 정상 초기화를 기다리는 것이며 dead start·잘못된 target·외부 장애를 해결하지 않는다.

### Dead start 또는 app 초기화 실패

예산 소진, 같은 초기화 단계 반복, target listener 부재, panic·설정·파일 권한 오류가 직접 확인되면 승인된 app/image/config revision만 배포한다. 기존 Pod를 먼저 삭제하지 않는다. 새 revision에서 같은 startup failure나 restart 증가가 나오면 rollout을 중단하고 승인된 이전 revision으로 rollback한다.

### Resource·mount·network·dependency 실패

직접 오류가 확인된 담당 계층에서만 승인된 변경을 수행한다. resource limit, PVC/Storage, NetworkPolicy/Service, 외부 DB/API/queue를 이 런북에서 임의로 변경하거나 재처리하지 않는다. 수정 후 app 초기화 → startup 성공 → Ready → EndpointSlice → 실제 요청 순으로 역검증한다.

### 복구 gate와 상태 변경 격리

상태 변경 전 승인된 context·namespace·Pod/owner, 직접 오류, 예상 replica·traffic·data·quorum 영향, 권한·승인, rollback artifact, 관찰 시간과 중단 조건을 기록한다. probe 변경은 target 오류 또는 측정된 정상 startup 지연이라는 직접 근거가 있을 때만 승인된 workload template 경로에서 수행한다.

허용하지 않는 조치는 startup/liveness/readiness 삭제, `failureThreshold`·`periodSeconds`·`timeoutSeconds` 무작정 증가, 항상 성공 endpoint, 원인 확인 전 Pod 삭제·강제 재시작이다. 진단 문서에는 mutation 명령을 넣지 않는다.

`ROLLOUT_READY=false; if [ "$DEPLOYMENT_READY" != true ]; then printf '%s\n' '중단: DEPLOYMENT_READY가 아니다.' >&2; elif kubectl rollout status "deployment/$DEPLOYMENT" -n "$NS" --timeout=120s; then ROLLOUT_READY=true; printf 'ROLLOUT_READY=true deployment=%s namespace=%s\n' "$DEPLOYMENT" "$NS"; else printf '%s\n' 'rollout 상태 실패: Deployment/revision/API 권한을 확인하고 rollback을 자동 실행하지 않음' >&2; fi`

StatefulSet은 ordinal·PVC·quorum, DaemonSet은 node별 desired/current/ready, Job은 재실행 멱등성을 별도로 확인한다. rollout 상태 성공은 application 기능·실제 요청·startup 재발 부재를 보장하지 않는다.

## 정상화와 실제 서비스 검증

정상화는 startup 성공과 `Running`만으로 선언하지 않는다. `application 기능 → API/protocol → process listener → Pod IP/kubelet → runtime → container/Pod identity`를 역순으로 확인한다.

1. 같은 Pod UID에서 startup suffix와 startup `Killing`이 bounded 관찰 시간 동안 반복되지 않고 restartCount가 안정적이다.
2. container가 `Running`이고 Pod `Ready=True`, 필요한 replica/Ready 수와 새 Warning Event 부재를 확인한다. startup 전 `Ready=False`는 readiness failure로 세지 않는다.
3. startup 성공 이후 liveness/readiness가 의도대로 동작하는지 별도로 확인한다.
4. Service가 있는 경우 `$SERVICE_READY=true`인 selector·EndpointSlice·대상 Pod IP를 확인하고, 승인된 실제 요청·핵심 기능·latency를 검증한다. EndpointSlice나 Ready는 실제 기능 성공을 보장하지 않는다.
5. 원인 계층 오류가 재발하지 않는 bounded 관찰 창과 다음 UTC 재평가 시각을 기록한다. 시간 예산 완화 성공과 app/image/config 근본 원인 해결을 분리한다.

## Prometheus 빠른 관측

실제 `prober_probe_total`의 비표준 `pod_uid` label과 KSM metric의 표준 `uid` label이 각각 수집되는 경우에만 사용한다. `prober_probe_total`의 `pod_uid`를 KSM metric selector에 사용하거나 두 metric의 label을 혼용하지 않는다. `POD_RE`는 자동 escaped regex이고 query 내부를 직접 수정하지 않는다. 아래 생성 명령의 출력 한 줄만 Prometheus/Grafana에 붙여 넣는다.

**startup probe 실패 증가 PromQL 생성 — bounded 한 줄**

`if [ "$SELECTION_READY" != true ] || [ -z "${POD_RE:-}" ] || [ -z "${POD_UID:-}" ]; then printf '%s\n' '중단: SELECTION_READY·POD_RE 또는 POD_UID가 아니다.' >&2; else printf '%s\n' "sum by(namespace,pod,pod_uid,container)(increase(prober_probe_total{namespace=\"$NS\",pod=~\"$POD_RE\",pod_uid=\"$POD_UID\",container=\"$CONTAINER\",probe_type=\"Startup\",result!=\"successful\"}[15m]))"; fi`

**restart 증가 PromQL 생성 — bounded 한 줄**

`if [ "$SELECTION_READY" != true ] || [ -z "${POD_RE:-}" ] || [ -z "${POD_UID:-}" ]; then printf '%s\n' '중단: SELECTION_READY·POD_RE 또는 POD_UID가 아니다.' >&2; else printf '%s\n' "sum by(namespace,pod,uid,container)(increase(kube_pod_container_status_restarts_total{namespace=\"$NS\",pod=~\"$POD_RE\",uid=\"$POD_UID\",container=\"$CONTAINER\"}[15m]))"; fi`

쿼리 빈 결과는 startup 성공·restart 0이 아니다. metric 미수집, label 불일치, query 범위, 권한/API failure를 구분한다. PromQL만으로 startup 성공, liveness/readiness 실행, application 초기화 완료 또는 원인을 확정하지 않는다.
