# 멀티 컨테이너 Pod의 로그 대상을 특정할 수 없는 경우

## 입력값과 빠른 수집

| 종류 | 값 | 출처와 사용 시점 |
|---|---|---|
| 최초 입력 | `NS`, `POD` | 운영자가 승인된 namespace와 Pod 이름을 한 번 입력한다. |
| API 자동값 | `POD_UID`, `NODE`, `PHASE`, `OBSERVED_AT`, `UID_READY`, default-container annotation, regular/init/ephemeral의 spec·status·state·containerID·port 관계 | Pod API에서 대상별 세로 블록으로 자동 등록하고 후속 명령 직전에 current UID를 대조한다. |
| 계산 후보값 | `NS_RE`, `POD_RE`, `POD_UID_RE`, `CONTAINER_RE` | 이름과 UID를 regex에 넣을 때 escape한 조회 후보다. 자동 확정하지 않는다. |
| 운영자 선택값 | `CONTAINER`, `CONTAINER_KIND`, `START_RFC3339`, 비교할 `COMPARE_CONTAINER`, `COMPARE_KIND` | 오류 원문과 자동 출력의 종류·상태를 대조한 뒤 선택한다. 첫 번째 container나 annotation만으로 고르지 않는다. |

### 1. 실행 위치·도구·최초 입력

모든 명령은 승인된 작업 PC 또는 bastion의 **같은 Bash 터미널**에서 실행한다. `kubectl logs`의 실제 경로는 `실행 host → kubectl client → API server HTTPS → 대상 node의 kubelet → runtime → 선택한 container`이며, API server 도달은 kubelet·runtime·application 로그 정상의 증거가 아니다. API 읽기 권한, 대상 namespace의 Pod 조회와 `pods/log` 권한 전제를 먼저 확인한다. TLS 검증을 끄지 않는다.

**필수 도구 확인 — 아래 한 줄 전체를 복사**

`TOOLS_READY=false; MISSING_TOOLS=''; if [ -z "${BASH_VERSION:-}" ]; then printf '%s\n' '중단: 같은 Bash에서 실행한다.' >&2; else for TOOL in kubectl jq grep sed date; do command -v "$TOOL" >/dev/null 2>&1 || MISSING_TOOLS="$MISSING_TOOLS $TOOL"; done; if [ -z "$MISSING_TOOLS" ]; then TOOLS_READY=true; printf 'TOOLS_READY=true Bash=%s\n' "$BASH_VERSION"; else printf '중단: 없는 도구=%s\n' "$MISSING_TOOLS" >&2; fi; fi`

`TOOLS_READY=true`가 아니면 다음 단계로 진행하지 않는다. `jq`가 없으면 raw JSON을 저장하거나 이름을 추측하지 말고 승인된 UI 또는 Pod owner에게 같은 kind·name·status 필드를 요청한다.

**입력·이전 상태 초기화 — 같은 Bash에서 한 번 실행**

`unset INPUT_READY AUTO_READY SELECTION_READY START_READY START_CANONICAL UID_READY EVENT_UID_READY STATE_READY CURRENT_READY PREVIOUS_READY COMPARE_READY QUERY_READY NS POD POD_UID NODE PHASE OBSERVED_AT POD_JSON CONTAINER CONTAINER_KIND START_RFC3339 STATUS_COUNT CURRENT_ID EXECUTED_AT COMPARE_CONTAINER COMPARE_KIND COMPARE_STATUS_COUNT COMPARE_CURRENT_ID COMPARE_EXECUTED_AT NS_RE POD_RE POD_UID_RE CONTAINER_RE; NS='PASTE_NAMESPACE_HERE'; POD='PASTE_POD_HERE'; INPUT_READY=false; if [ "$TOOLS_READY" != true ]; then printf '%s\n' '중단: 도구 확인을 먼저 통과한다.' >&2; elif [ -z "$NS" ] || [ -z "$POD" ]; then printf '%s\n' '중단: NS와 POD를 입력한다.' >&2; elif kubectl get pod "$POD" -n "$NS" >/dev/null 2>&1; then INPUT_READY=true; export NS POD; printf 'INPUT_READY=true namespace=%s pod=%s\n' "$NS" "$POD"; else printf '중단: Pod 조회 실패 namespace=%s pod=%s\n' "$NS" "$POD" >&2; fi`

`INPUT_READY=true`가 아니면 중단한다. Pod 이름을 broad query로 다른 namespace에서 찾거나 이름을 재사용하지 않는다.

### 2. API 자동 수집

**Pod·container·port·status 관계 자동 등록 — 아래 한 줄 전체를 복사**

`unset AUTO_READY POD_UID NODE PHASE OBSERVED_AT POD_JSON; AUTO_READY=false; if [ "$INPUT_READY" != true ]; then printf '%s\n' '중단: INPUT_READY가 아니다.' >&2; elif POD_JSON="$(kubectl get pod "$POD" -n "$NS" -o json)" && POD_UID_TMP="$(jq -r '.metadata.uid // empty' <<<"$POD_JSON")" && NODE_TMP="$(jq -r '.spec.nodeName // "-"' <<<"$POD_JSON")" && PHASE_TMP="$(jq -r '.status.phase // "-"' <<<"$POD_JSON")" && OBSERVED_AT_TMP="$(date -u '+%Y-%m-%dT%H:%M:%SZ')" && [ -n "$POD_UID_TMP" ]; then printf '%s\n' '=== Pod 대상 ==='; jq -r --arg observed "$OBSERVED_AT_TMP" '"이름: \(.metadata.name)\nUID: \(.metadata.uid)\nNode: \(.spec.nodeName // "-")\nPhase: \(.status.phase // "-")\nPod 생성 시각(UTC): \(.metadata.creationTimestamp // "-")\nDefault container annotation: \(.metadata.annotations["kubectl.kubernetes.io/default-container"] // "없음")\n관측 시각(UTC): \($observed)" + "\n" + ([.spec.containers[]? | "Kind: regular\nContainer: \(.name)\nContainer/Port 후보: \([.ports[]? | ((.name // "unnamed") + ":" + (.containerPort|tostring))] | join(", "))"] | join("\n")) + "\n" + ([.spec.initContainers[]? | "Kind: init\nContainer: \(.name)\nContainer/Port 후보: \([.ports[]? | ((.name // "unnamed") + ":" + (.containerPort|tostring))] | join(", "))"] | join("\n")) + "\n" + ([.spec.ephemeralContainers[]? | "Kind: ephemeral\nContainer: \(.name)\nContainer/Port 후보: \([.ports[]? | ((.name // "unnamed") + ":" + (.containerPort|tostring))] | join(", "))"] | join("\n")) + "\n" + ([.status.containerStatuses[]? | "Status kind: regular\nContainer: \(.name)\nState: "+(if .state.running then "Running/"+(.state.running.startedAt // "-") elif .state.waiting then "Waiting/"+(.state.waiting.reason // "-") elif .state.terminated then "Terminated/"+(.state.terminated.finishedAt // "-") else "없음" end)+"\nContainer ID: \(.containerID // "-")\nRestart count: \(.restartCount // 0)\nPrevious reason: \(.lastState.terminated.reason // "-")\nPrevious finishedAt: \(.lastState.terminated.finishedAt // "-")"] | join("\n")) + "\n" + ([.status.initContainerStatuses[]? | "Status kind: init\nContainer: \(.name)\nState: "+(if .state.running then "Running/"+(.state.running.startedAt // "-") elif .state.waiting then "Waiting/"+(.state.waiting.reason // "-") elif .state.terminated then "Terminated/"+(.state.terminated.finishedAt // "-") else "없음" end)+"\nContainer ID: \(.containerID // "-")\nRestart count: \(.restartCount // 0)"] | join("\n")) + "\n" + ([.status.ephemeralContainerStatuses[]? | "Status kind: ephemeral\nContainer: \(.name)\nState: "+(if .state.running then "Running/"+(.state.running.startedAt // "-") elif .state.waiting then "Waiting/"+(.state.waiting.reason // "-") elif .state.terminated then "Terminated/"+(.state.terminated.finishedAt // "-") else "없음" end)+"\nContainer ID: \(.containerID // "-")\nRestart count: \(.restartCount // 0)"] | join("\n"))' <<<"$POD_JSON"; POD_UID="$POD_UID_TMP"; NODE="$NODE_TMP"; PHASE="$PHASE_TMP"; OBSERVED_AT="$OBSERVED_AT_TMP"; AUTO_READY=true; export POD_UID NODE PHASE OBSERVED_AT; printf 'AUTO_READY=true 관측시각(UTC)=%s\n' "$OBSERVED_AT"; else printf '%s\n' '중단: Pod API 조회 실패 또는 UID 없음; 자동값을 무효화한다.' >&2; unset POD_JSON POD_UID NODE PHASE OBSERVED_AT; fi`

성공 gate는 UID·node·phase·UTC 관측 시각과 함께 각 container의 **kind, 이름, 그 container에 속한 port 후보, 같은 이름의 status와 state**가 세로로 보이는 것이다. `containerPort`는 선언 후보일 뿐 process listener·protocol·로그 존재를 보장하지 않는다. 이름이 spec에만 있고 status가 없으면 아직 시작되지 않았거나 status가 갱신되지 않은 것이며 로그가 있다고 단정하지 않는다. `AUTO_READY=true`가 아니면 이후 단계로 가지 않는다.

**후속 명령용 current UID gate — 아래 한 줄 전체를 복사**

`unset UID_READY CURRENT_JSON CURRENT_UID; UID_READY=false; if [ "$AUTO_READY" != true ]; then printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; elif CURRENT_JSON="$(kubectl get pod "$POD" -n "$NS" -o json)" && CURRENT_UID="$(jq -r '.metadata.uid // empty' <<<"$CURRENT_JSON")" && [ "$CURRENT_UID" = "$POD_UID" ]; then POD_JSON="$CURRENT_JSON"; UID_READY=true; export POD_JSON UID_READY; printf 'UID_READY=true pod=%s uid=%s 관측시각(UTC)=%s\n' "$POD" "$POD_UID" "$(date -u '+%Y-%m-%dT%H:%M:%SZ')"; else printf '중단: 자동 수집 후 current UID 재조회 실패 또는 UID 변경; 이후 명령을 실행하지 않는다.\n' >&2; unset CURRENT_JSON CURRENT_UID POD_JSON; fi`

`UID_READY=true`가 아니면 최초 확인, container 선택, Event, logs, 비교 명령을 실행하지 않는다. Pod 이름 재사용과 stale API 응답을 막기 위해 `POD_UID`와 재조회 UID가 같아야 한다.

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | `Defaulted container`, `container name must be specified`, `container not found` 또는 current·previous 중 대상이 불명확한 경우 |
| 적용 | regular·init·ephemeral의 선언 이름과 같은 kind의 status를 대조해 하나의 로그 대상을 고를 수 있는 경우 |
| 제외 | 로그 전송·보존 실패는 [[27. Pod 로그를 가져올 수 없는 경우]], `--previous` 보존은 [[28. Pod의 이전 컨테이너 로그를 가져올 수 없는 경우]], `pods/log` RBAC는 [[30. Pod 로그 권한이 거부되는 경우]], exec는 [[31. Pod exec 대상 컨테이너를 찾을 수 없는 경우]]로 이동한다. |

검색 문자열: `Defaulted container`, `Default container name`, `container name must be specified`, `a container name must be specified for pod`, `container not found`, `previous terminated container`, `Forbidden`.

`kubectl logs`는 `pods/log`, `kubectl exec`는 `pods/exec` 경로다. 권한·stream·후속 조치를 서로 대체하지 않는다. `--all-containers`로 대상이 정해지지 않은 로그를 한꺼번에 수집하지 않는다.

## 최초 확인

재시작·Waiting 분기에서만 UID 제한 Event를 한 번 조회한다. `describe`는 대상 Pod의 state·last state·reason·exit code·restart count·conditions와 Event의 첫 실패 message를 보는 용도다.

**대상 Pod 요약 — 아래 한 줄 전체를 복사**

`if [ "$AUTO_READY" = true ] && [ "$UID_READY" = true ]; then kubectl get pod "$POD" -n "$NS" -o custom-columns='POD:.metadata.name,UID:.metadata.uid,PHASE:.status.phase,NODE:.spec.nodeName,READY:.status.containerStatuses[*].ready,RESTARTS:.status.containerStatuses[*].restartCount'; else printf '%s\n' '중단: AUTO_READY와 current UID gate가 아니다.' >&2; fi`

**필요할 때만 상세 상태 — 아래 한 줄 전체를 복사**

`if [ "$AUTO_READY" = true ] && [ "$UID_READY" = true ]; then kubectl describe pod "$POD" -n "$NS"; else printf '%s\n' '중단: AUTO_READY와 current UID gate가 아니다.' >&2; fi`

**재시작·Waiting Event — 아래 한 줄 전체를 복사**

`unset EVENT_UID_READY EVENT_JSON EVENT_UID; EVENT_UID_READY=false; if [ "$AUTO_READY" != true ] || [ "$UID_READY" != true ]; then printf '%s\n' '중단: AUTO_READY와 current UID gate가 아니다.' >&2; elif EVENT_JSON="$(kubectl get pod "$POD" -n "$NS" -o json)" && EVENT_UID="$(jq -r '.metadata.uid // empty' <<<"$EVENT_JSON")" && [ "$EVENT_UID" = "$POD_UID" ]; then if kubectl get events -n "$NS" --field-selector="involvedObject.kind=Pod,involvedObject.name=$POD,involvedObject.uid=$EVENT_UID" --sort-by=.metadata.creationTimestamp -o custom-columns='CREATED:.metadata.creationTimestamp,FIRST:.firstTimestamp,LAST:.lastTimestamp,EVENT-TIME:.eventTime,SERIES-LAST:.series.lastObservedTime,TYPE:.type,REASON:.reason,MESSAGE:.message'; then EVENT_UID_READY=true; printf 'EVENT_UID_READY=true uid=%s\n' "$EVENT_UID"; else printf '중단: Event API 조회 실패 uid=%s; 빈 결과나 실패를 원인 부재로 해석하지 않는다.\n' "$EVENT_UID" >&2; fi; else printf '중단: Event 직전 current UID 재조회 실패 또는 UID 변경; Event를 조회하지 않는다.\n' >&2; fi`

get에서 볼 것은 UID·phase·node·Ready·restart와 자동 수집의 kind/name/status 일치다. Event가 없거나 한 번만 집계돼도 원인·로그 부재가 아니다. message에 Secret·token·개인정보가 보이면 저장하지 않는다.

## 관측별 진단 경로

| 지금 보이는 것 | 먼저 볼 것 | 그다음 어디를 볼지 | 상세 절 |
|---|---|---|---|
| `Defaulted container` 또는 대상 생략 | annotation과 세 종류의 spec 이름 | 실제 이름을 `-c`로 고정 | [[#1. spec·status·기본 선택 대조\|1]] |
| `container name must be specified` 또는 `container not found` | kind별 spec/status 이름 | 선택값 재검증 또는 대상 이관 | [[#1. spec·status·기본 선택 대조\|1]] |
| regular·init·ephemeral status가 있음 | state·containerID·restart·시각 | current와 previous 분리 | [[#2. current와 previous 로그\|2]] |
| init만 있거나 완료됨 | init status와 종료 reason | 해당 init current 로그와 regular 기동 경로 | [[#2. current와 previous 로그\|2]] |
| ephemeral이 있음 | 주입된 컨테이너 자체 status | regular와 섞지 않은 ephemeral 로그 | [[#2. current와 previous 로그\|2]] |
| spec 이름은 있으나 status 없음 | 아직 시작되지 않았는지와 UID 제한 Event | 로그 명령 중단 | [[#1. spec·status·기본 선택 대조\|1]] |
| `previous ... not found` | 해당 kind의 restart·lastState·UID | regular는 28번, init·ephemeral은 이 문서의 owner/중앙 수집 경로 | regular: [[28. Pod의 이전 컨테이너 로그를 가져올 수 없는 경우]] |

길 안내 표는 원인을 확정하지 않는다. `Running`, `Ready`, 또는 이름 선택 성공은 application 정상·로그 보존·다음 hop 성공을 보장하지 않는다.

### 1. spec·status·기본 선택 대조

진입 증거: 대상 생략·이름 오류가 있거나 자동 출력에서 kind와 status를 아직 하나로 맞추지 못한 경우다. 최초 필요값은 API 자동값 `POD_UID`, `POD_JSON`, regular/init/ephemeral 이름과 status다.

**선택값 등록·검증 — 아래 한 줄 전체를 복사**

`CONTAINER='PASTE_CONTAINER_HERE'; CONTAINER_KIND='PASTE_CONTAINER_KIND_HERE'; SELECTION_READY=false; STATE_READY=false; STATUS_COUNT=''; CURRENT_ID=''; EXECUTED_AT=''; if [ "$AUTO_READY" != true ] || [ "$UID_READY" != true ]; then printf '%s\n' '중단: AUTO_READY와 UID_READY가 필요하다.' >&2; elif [ "$CONTAINER_KIND" != regular ] && [ "$CONTAINER_KIND" != init ] && [ "$CONTAINER_KIND" != ephemeral ]; then printf '중단: CONTAINER_KIND는 regular, init, ephemeral 중 하나여야 함\n' >&2; elif jq -e --arg kind "$CONTAINER_KIND" --arg c "$CONTAINER" 'if $kind=="regular" then ([.spec.containers[]? | select(.name==$c)]|length)==1 else if $kind=="init" then ([.spec.initContainers[]? | select(.name==$c)]|length)==1 else ([.spec.ephemeralContainers[]? | select(.name==$c)]|length)==1 end end' <<<"$POD_JSON" >/dev/null; then STATUS_COUNT="$(jq --arg kind "$CONTAINER_KIND" --arg c "$CONTAINER" 'if $kind=="regular" then [.status.containerStatuses[]? | select(.name==$c)]|length elif $kind=="init" then [.status.initContainerStatuses[]? | select(.name==$c)]|length else [.status.ephemeralContainerStatuses[]? | select(.name==$c)]|length end' <<<"$POD_JSON")"; CURRENT_ID="$(jq -r --arg kind "$CONTAINER_KIND" --arg c "$CONTAINER" 'if $kind=="regular" then ([.status.containerStatuses[]? | select(.name==$c)][0] | .containerID // empty) elif $kind=="init" then ([.status.initContainerStatuses[]? | select(.name==$c)][0] | .containerID // empty) else ([.status.ephemeralContainerStatuses[]? | select(.name==$c)][0] | .containerID // empty) end' <<<"$POD_JSON")"; EXECUTED_AT="$(jq -r --arg kind "$CONTAINER_KIND" --arg c "$CONTAINER" 'if $kind=="regular" then ([.status.containerStatuses[]? | select(.name==$c)][0] | .state.running.startedAt // .state.terminated.finishedAt // empty) elif $kind=="init" then ([.status.initContainerStatuses[]? | select(.name==$c)][0] | .state.running.startedAt // .state.terminated.finishedAt // empty) else ([.status.ephemeralContainerStatuses[]? | select(.name==$c)][0] | .state.running.startedAt // .state.terminated.finishedAt // empty) end' <<<"$POD_JSON")"; if [ "$STATUS_COUNT" = 1 ]; then SELECTION_READY=true; STATE_READY=true; export CONTAINER CONTAINER_KIND STATUS_COUNT CURRENT_ID EXECUTED_AT SELECTION_READY STATE_READY; printf 'SELECTION_READY=true kind=%s container=%s status-count=%s current-id=%s executed-at=%s STATE_READY=%s\n' "$CONTAINER_KIND" "$CONTAINER" "$STATUS_COUNT" "${CURRENT_ID:--}" "${EXECUTED_AT:--}" "$STATE_READY"; else printf '중단: 선택한 kind/name의 status가 정확히 하나가 아님 count=%s; logs를 호출하지 않는다.\n' "$STATUS_COUNT" >&2; fi; else printf '중단: 선택한 kind와 이름이 spec에 정확히 하나로 존재하지 않음\n' >&2; fi`

성공 gate는 kind와 이름이 해당 spec에 정확히 하나 있고, status가 있으면 같은 kind의 status 하나와 일치하는 것이다. status count가 0이면 아직 시작되지 않았거나 status 갱신이 늦은 것이므로 로그 명령을 실행하지 않는다. annotation이 없거나 잘못돼도 `-c`는 항상 실제 이름으로 명시한다. annotation은 선택 힌트이지 역할·상태·원인·권한 증명이 아니다.

`NotFound`는 다른 namespace나 이름을 추측하지 말고 입력값을 재검증한다. `STATE_READY=true`가 아니면 2절의 logs stream으로 가지 않는다.

### 2. current와 previous 로그

진입 증거: `SELECTION_READY=true`, `STATE_READY=true`이며 selected kind의 status가 running·terminated·직전 terminated 중 적어도 하나를 제공한다. `state.waiting`이고 시작 시각·containerID가 없으면 current 로그를 반복하지 않고 Event와 상태 owner로 이동한다. init 완료는 완료된 현재 init 시도의 로그이고, ephemeral은 주입된 컨테이너의 별도 로그다.

**시간 선택 — 같은 Bash에서 한 번 실행**

`START_RFC3339='PASTE_START_RFC3339_HERE'; START_READY=false; unset START_CANONICAL; if [[ ! "$START_RFC3339" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]]; then printf '중단: START_RFC3339는 strict UTC Z 형식이어야 함 %s\n' "$START_RFC3339" >&2; elif START_CANONICAL="$(date -u -d "$START_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" && [ "$START_CANONICAL" = "$START_RFC3339" ]; then START_READY=true; export START_RFC3339 START_CANONICAL START_READY; printf 'START_READY=true strict_utc=true start=%s\n' "$START_RFC3339"; else printf '중단: START_RFC3339 canonical round-trip 실패 %s\n' "$START_RFC3339" >&2; fi`

**logs 직전 UID 재검증 — 아래 한 줄 전체를 복사**

`UID_READY=false; if [ "$SELECTION_READY" != true ] || [ "$START_READY" != true ]; then printf '%s\n' '중단: selection·start gate가 필요하다.' >&2; elif CHECK_JSON="$(kubectl get pod "$POD" -n "$NS" -o json)" && CHECK_UID="$(jq -r '.metadata.uid // empty' <<<"$CHECK_JSON")" && [ "$CHECK_UID" = "$POD_UID" ]; then POD_JSON="$CHECK_JSON"; UID_READY=true; export POD_JSON UID_READY; printf 'UID_READY=true pod=%s uid=%s 관측시각(UTC)=%s\n' "$POD" "$POD_UID" "$(date -u '+%Y-%m-%dT%H:%M:%SZ')"; else printf '중단: logs 직전 API 실패 또는 Pod UID 변경; 이전 선택값을 폐기한다.\n' >&2; unset CHECK_JSON CHECK_UID POD_JSON; fi`

시간 형식 성공은 strict `YYYY-MM-DDTHH:MM:SSZ` regex와 UTC canonical round-trip을 모두 통과한 경우다. 자연어·offset·비정규 timestamp는 거부한다. 시간 범위의 정확성을 보장하지 않으므로 동일 UID와 선택 kind/name의 status 시각을 함께 기록한다.

**각 logs 실행 직전 fresh kind·status·current ID·executedAt gate 함수 등록 — 같은 Bash에서 한 번 실행**

`refresh_log_target_gate(){ local kind="$1" c="$2" json uid spec_count status_count current_id executed_at; FRESH_LOG_TARGET_READY=false; if [ "$AUTO_READY" != true ] || [ "$UID_READY" != true ] || [ -z "$kind" ] || [ -z "$c" ]; then printf '%s\n' '중단: AUTO_READY·UID_READY·kind·container가 필요하다.' >&2; return 1; elif [ "$kind" != regular ] && [ "$kind" != init ] && [ "$kind" != ephemeral ]; then printf '중단: 지원하지 않는 kind=%s\n' "$kind" >&2; return 1; elif json="$(kubectl get pod "$POD" -n "$NS" -o json)" && uid="$(jq -r '.metadata.uid // empty' <<<"$json")" && spec_count="$(jq --arg kind "$kind" --arg c "$c" 'if $kind=="regular" then [.spec.containers[]? | select(.name==$c)]|length elif $kind=="init" then [.spec.initContainers[]? | select(.name==$c)]|length else [.spec.ephemeralContainers[]? | select(.name==$c)]|length end' <<<"$json")" && status_count="$(jq --arg kind "$kind" --arg c "$c" 'if $kind=="regular" then [.status.containerStatuses[]? | select(.name==$c)]|length elif $kind=="init" then [.status.initContainerStatuses[]? | select(.name==$c)]|length else [.status.ephemeralContainerStatuses[]? | select(.name==$c)]|length end' <<<"$json")" && current_id="$(jq -r --arg kind "$kind" --arg c "$c" 'if $kind=="regular" then ([.status.containerStatuses[]? | select(.name==$c)][0] | .containerID // empty) elif $kind=="init" then ([.status.initContainerStatuses[]? | select(.name==$c)][0] | .containerID // empty) else ([.status.ephemeralContainerStatuses[]? | select(.name==$c)][0] | .containerID // empty) end' <<<"$json")" && executed_at="$(jq -r --arg kind "$kind" --arg c "$c" 'if $kind=="regular" then ([.status.containerStatuses[]? | select(.name==$c)][0] | .state.running.startedAt // .state.terminated.finishedAt // empty) elif $kind=="init" then ([.status.initContainerStatuses[]? | select(.name==$c)][0] | .state.running.startedAt // .state.terminated.finishedAt // empty) else ([.status.ephemeralContainerStatuses[]? | select(.name==$c)][0] | .state.running.startedAt // .state.terminated.finishedAt // empty) end' <<<"$json")" && [ "$uid" = "$POD_UID" ] && [ "$spec_count" = 1 ] && [ "$status_count" = 1 ] && [ -n "$current_id" ] && [ -n "$executed_at" ]; then POD_JSON="$json"; FRESH_LOG_TARGET_READY=true; export POD_JSON FRESH_LOG_TARGET_READY; printf 'FRESH_LOG_TARGET_READY=true kind=%s status-count=%s current-id=%s executedAt=%s uid=%s\n' "$kind" "$status_count" "$current_id" "$executed_at" "$uid"; return 0; else printf '중단: fresh kind/status/current containerID/executedAt gate 실패 kind=%s status-count=%s current-id=%s executedAt=%s expected-uid=%s actual-uid=%s\n' "$kind" "${status_count:--}" "${current_id:--}" "${executed_at:--}" "$POD_UID" "${uid:--}" >&2; return 1; fi; }`

연결 경로는 `작업 PC/Bash → kubectl client → API server HTTPS → 대상 node·kubelet → runtime → 선택 container log stream`이다. `kubectl logs`의 API status, kubelet 도달성, runtime log 존재와 application 출력은 각각 별도 증거다.

**current 오류 구간 조회 — 아래 한 줄 전체를 복사**

`if [ "$SELECTION_READY" != true ] || [ "$STATE_READY" != true ] || [ "$UID_READY" != true ] || [ "$START_READY" != true ] || ! refresh_log_target_gate "$CONTAINER_KIND" "$CONTAINER"; then printf '%s\n' '중단: 선택·상태·UID·시간과 fresh kind/status/current ID/executedAt gate가 필요하다.' >&2; else kubectl logs "$POD" -n "$NS" -c "$CONTAINER" --timestamps --since-time="$START_RFC3339" --tail=200 | grep -E -i -C 3 'panic|fatal|error|exception|timeout|refused|denied|permission|oom|killed'; rc=${PIPESTATUS[0]}; if [ "$rc" -ne 0 ]; then printf 'current log stream 실패 rc=%s; [[27. Pod 로그를 가져올 수 없는 경우]]로 이관한다.\n' "$rc" >&2; else printf '%s\n' 'current stream 성공; 필터 무출력은 오류 부재가 아니다.'; fi; fi`

성공 gate는 selected kind/name의 제한된 current stream이다. `grep` 무출력이면 같은 범위의 마지막 50행을 한 번만 확인하고, 빈 출력은 정상·오류 없음이 아니다. `Forbidden`은 [[30. Pod 로그 권한이 거부되는 경우]], 이름 오류는 1절, `connection refused`·`i/o timeout`·`x509`는 [[27. Pod 로그를 가져올 수 없는 경우]]로 반환한다.

**current 제한 tail — 아래 한 줄 전체를 복사**

`if [ "$SELECTION_READY" = true ] && [ "$STATE_READY" = true ] && [ "$UID_READY" = true ] && [ "$START_READY" = true ] && refresh_log_target_gate "$CONTAINER_KIND" "$CONTAINER"; then kubectl logs "$POD" -n "$NS" -c "$CONTAINER" --timestamps --since-time="$START_RFC3339" --tail=50; else printf '%s\n' '중단: current tail와 fresh kind/status/current ID/executedAt gate가 아니다.' >&2; fi`

`restartCount`가 증가하고 같은 kind/name의 `lastState.terminated`가 있을 때만 previous를 별도로 조회한다. `--previous`는 모든 과거 instance가 아니며 현재 Pod UID의 직전 instance 하나다.

**previous 오류 구간 조회 — 아래 한 줄 전체를 복사**

`if [ "$SELECTION_READY" != true ] || [ "$STATE_READY" != true ] || [ "$UID_READY" != true ] || [ "$START_READY" != true ] || ! refresh_log_target_gate "$CONTAINER_KIND" "$CONTAINER" || ! jq -e --arg kind "$CONTAINER_KIND" --arg c "$CONTAINER" 'if $kind=="regular" then any(.status.containerStatuses[]?; .name==$c and .restartCount>0 and .lastState.terminated!=null) elif $kind=="init" then any(.status.initContainerStatuses[]?; .name==$c and .restartCount>0 and .lastState.terminated!=null) else any(.status.ephemeralContainerStatuses[]?; .name==$c and .restartCount>0 and .lastState.terminated!=null) end' <<<"$POD_JSON" >/dev/null; then printf '%s\n' '중단: previous 후보 또는 선택·UID·시간·fresh kind/status/current ID/executedAt gate가 아니다.' >&2; else kubectl logs "$POD" -n "$NS" -c "$CONTAINER" --previous --timestamps --since-time="$START_RFC3339" --tail=200 | grep -E -i -C 3 'panic|fatal|error|exception|timeout|refused|denied|permission|oom|killed'; rc=${PIPESTATUS[0]}; if [ "$rc" -ne 0 ]; then if [ "$CONTAINER_KIND" = regular ]; then printf 'previous log stream 실패 rc=%s; regular 대상이므로 [[28. Pod의 이전 컨테이너 로그를 가져올 수 없는 경우]]로 이동한다.\n' "$rc" >&2; else printf 'previous log stream 실패 rc=%s; kind=%s는 28번 regular runtime 절로 보내지 않고 owner/중앙 로그 수집기로 이관한다.\n' "$rc" "$CONTAINER_KIND" >&2; fi; else printf '%s\n' 'previous stream 성공; 종료 reason·finishedAt과 대조한다.'; fi; fi`

성공은 같은 UID·kind·name의 직전 instance stream 준비만 보장한다. `previous ... not found`이면 current 로그·UID·kind·restart·lastState·containerID·runtime 보존 후보를 기록한다. `CONTAINER_KIND=regular`일 때만 [[28. Pod의 이전 컨테이너 로그를 가져올 수 없는 경우]]로 이관한다. `init`·`ephemeral`은 28번의 regular 전용 runtime 절로 보내지 않고, 이 문서의 kind/status/UID 증거와 함께 해당 workload owner 또는 중앙 로그 수집기로 이관한다. `Waiting`에 containerID가 없으면 previous 부재로 해석하지 않는다. 민감정보가 보이면 출력·저장을 중단한다.

### 3. 여러 컨테이너 비교

진입 증거: 하나의 로그 대상은 정했지만 regular·init·ephemeral 또는 sidecar 간 오류 시각을 비교해야 하는 경우다. `--all-containers`는 사용하지 않는다. 비교 대상도 자동으로 첫 번째를 고르지 않는다.

**비교 대상 선택 — 아래 한 줄 전체를 복사**

`COMPARE_CONTAINER='PASTE_COMPARE_CONTAINER_HERE'; COMPARE_KIND='PASTE_COMPARE_KIND_HERE'; COMPARE_READY=false; COMPARE_STATUS_COUNT=''; COMPARE_CURRENT_ID=''; COMPARE_EXECUTED_AT=''; if [ "$AUTO_READY" != true ] || [ "$UID_READY" != true ]; then printf '%s\n' '중단: AUTO_READY와 UID_READY가 필요하다.' >&2; elif [ "$COMPARE_KIND" != regular ] && [ "$COMPARE_KIND" != init ] && [ "$COMPARE_KIND" != ephemeral ]; then printf '%s\n' '중단: COMPARE_KIND가 유효하지 않다.' >&2; elif jq -e --arg kind "$COMPARE_KIND" --arg c "$COMPARE_CONTAINER" 'if $kind=="regular" then ([.spec.containers[]? | select(.name==$c)]|length)==1 else if $kind=="init" then ([.spec.initContainers[]? | select(.name==$c)]|length)==1 else ([.spec.ephemeralContainers[]? | select(.name==$c)]|length)==1 end end' <<<"$POD_JSON" >/dev/null; then COMPARE_STATUS_COUNT="$(jq --arg kind "$COMPARE_KIND" --arg c "$COMPARE_CONTAINER" 'if $kind=="regular" then [.status.containerStatuses[]? | select(.name==$c)]|length elif $kind=="init" then [.status.initContainerStatuses[]? | select(.name==$c)]|length else [.status.ephemeralContainerStatuses[]? | select(.name==$c)]|length end' <<<"$POD_JSON")"; COMPARE_CURRENT_ID="$(jq -r --arg kind "$COMPARE_KIND" --arg c "$COMPARE_CONTAINER" 'if $kind=="regular" then ([.status.containerStatuses[]? | select(.name==$c)][0] | .containerID // empty) elif $kind=="init" then ([.status.initContainerStatuses[]? | select(.name==$c)][0] | .containerID // empty) else ([.status.ephemeralContainerStatuses[]? | select(.name==$c)][0] | .containerID // empty) end' <<<"$POD_JSON")"; COMPARE_EXECUTED_AT="$(jq -r --arg kind "$COMPARE_KIND" --arg c "$COMPARE_CONTAINER" 'if $kind=="regular" then ([.status.containerStatuses[]? | select(.name==$c)][0] | .state.running.startedAt // .state.terminated.finishedAt // empty) elif $kind=="init" then ([.status.initContainerStatuses[]? | select(.name==$c)][0] | .state.running.startedAt // .state.terminated.finishedAt // empty) else ([.status.ephemeralContainerStatuses[]? | select(.name==$c)][0] | .state.running.startedAt // .state.terminated.finishedAt // empty) end' <<<"$POD_JSON")"; if [ "$COMPARE_STATUS_COUNT" = 1 ] && [ -n "$COMPARE_CURRENT_ID" ] && [ -n "$COMPARE_EXECUTED_AT" ]; then COMPARE_READY=true; export COMPARE_CONTAINER COMPARE_KIND COMPARE_STATUS_COUNT COMPARE_CURRENT_ID COMPARE_EXECUTED_AT COMPARE_READY; printf 'COMPARE_READY=true kind=%s container=%s status-count=%s current-id=%s executed-at=%s\n' "$COMPARE_KIND" "$COMPARE_CONTAINER" "$COMPARE_STATUS_COUNT" "$COMPARE_CURRENT_ID" "$COMPARE_EXECUTED_AT"; else printf '중단: 비교 대상은 정확히 하나의 kind별 status, current containerID, 실행 이력이 필요함 status-count=%s current-id=%s executed-at=%s\n' "$COMPARE_STATUS_COUNT" "${COMPARE_CURRENT_ID:--}" "${COMPARE_EXECUTED_AT:--}" >&2; fi; else printf '%s\n' '중단: 비교 대상 kind/name이 spec에 정확히 하나로 존재하지 않는다.' >&2; fi`

`COMPARE_READY=true`가 아니면 비교 명령을 실행하지 않는다. 두 대상은 같은 `START_RFC3339`, 같은 Pod UID 관측창에서 분리해 기록한다. 이름만으로 app·sidecar·collector 역할을 확정하지 말고 image·command·volume과 workload 계약을 비민감 범위에서 대조한다. port 선언은 실제 listener나 HTTP/HTTPS protocol을 보장하지 않는다.

**선택한 두 container 오류 구간 비교 — 아래 한 줄 전체를 복사**

`if [ "$SELECTION_READY" = true ] && [ "$COMPARE_READY" = true ] && [ "$COMPARE_STATUS_COUNT" = 1 ] && [ -n "$COMPARE_CURRENT_ID" ] && [ -n "$COMPARE_EXECUTED_AT" ] && [ "$STATE_READY" = true ] && [ "$UID_READY" = true ] && [ "$START_READY" = true ] && refresh_log_target_gate "$CONTAINER_KIND" "$CONTAINER" && refresh_log_target_gate "$COMPARE_KIND" "$COMPARE_CONTAINER"; then for KIND_NAME in "$CONTAINER_KIND/$CONTAINER" "$COMPARE_KIND/$COMPARE_CONTAINER"; do KIND="${KIND_NAME%%/*}"; NAME="${KIND_NAME#*/}"; printf '\n=== %s ===\n' "$KIND_NAME"; kubectl logs "$POD" -n "$NS" -c "$NAME" --timestamps --since-time="$START_RFC3339" --tail=200 | grep -E -i -C 3 'panic|fatal|error|exception|timeout|refused|denied|permission|oom|killed'; PIPE_RC=("${PIPESTATUS[@]}"); if [ "${PIPE_RC[0]}" -ne 0 ]; then printf '대상별 current stream 실패 kind/name=%s rc=%s\n' "$KIND_NAME" "${PIPE_RC[0]}" >&2; fi; done; else printf '%s\n' '중단: 두 대상의 선택·status·current ID·실행 이력·UID·시간과 각 대상 fresh kind/status/current ID/executedAt gate가 필요하다.' >&2; fi`

이 명령은 출력 stream마다 대상 kind/name을 붙이는 범위 제한 비교다. 한 대상 실패가 다른 대상의 성공을 의미하지 않는다. 필터 무출력은 오류 부재가 아니며, `Forbidden`·stream 오류는 해당 대상의 권한·API·kubelet 경계로 분리한다.

## Prometheus 빠른 관측

kube-state-metrics가 실제로 수집될 때만 사용한다. `regular` container에만 이 문서의 `kube_pod_container_*` query를 적용하며, `init`·`ephemeral`은 해당 regular 전용 KSM metric을 사용하지 않고 Pod kind/status, current containerID·실행 시각, 로그·runtime 증거로 판단한다. metric query transport/API 실패와 빈 series를 구분한다.

**PromQL 완성본 생성 — 아래 한 줄 전체를 복사**

`QUERY_READY=false; if [ "$SELECTION_READY" != true ] || [ "$AUTO_READY" != true ] || [ "$UID_READY" != true ] || [ -z "$POD_UID" ]; then printf '%s\n' '중단: 자동값·Pod UID·UID_READY·container 선택이 필요하다.' >&2; elif [ "$CONTAINER_KIND" != regular ]; then printf 'QUERY_READY=false kind=%s: regular 전용 kube-state-metrics container query는 적용하지 않는다. Pod spec/status와 kind별 로그·runtime 증거를 사용한다.\n' "$CONTAINER_KIND"; export QUERY_READY; else NS_RE="$(printf '%s' "$NS" | sed 's/[][\\.^$*+?(){}|]/\\&/g')"; POD_RE="$(printf '%s' "$POD" | sed 's/[][\\.^$*+?(){}|]/\\&/g')"; POD_UID_RE="$(printf '%s' "$POD_UID" | sed 's/[][\\.^$*+?(){}|]/\\&/g')"; CONTAINER_RE="$(printf '%s' "$CONTAINER" | sed 's/[][\\.^$*+?(){}|]/\\&/g')"; printf 'kube_pod_container_info{namespace=~"%s",pod=~"%s",uid=~"%s",container=~"%s"}\n' "$NS_RE" "$POD_RE" "$POD_UID_RE" "$CONTAINER_RE"; printf 'kube_pod_container_status_ready{namespace=~"%s",pod=~"%s",uid=~"%s",container=~"%s"}==0\n' "$NS_RE" "$POD_RE" "$POD_UID_RE" "$CONTAINER_RE"; printf 'sum by(namespace,pod,uid,container)(increase(kube_pod_container_status_restarts_total{namespace=~"%s",pod=~"%s",uid=~"%s",container=~"%s"}[15m]))>0\n' "$NS_RE" "$POD_RE" "$POD_UID_RE" "$CONTAINER_RE"; QUERY_READY=true; export NS_RE POD_RE POD_UID_RE CONTAINER_RE QUERY_READY; printf 'QUERY_READY=true kind=regular matcher는 namespace·pod·uid·container bounded 출력만 사용한다.\n'; fi`

`QUERY_READY=true`는 query 문자열 생성 성공일 뿐 metric 존재·API success·대상 kind별 수집을 보장하지 않는다. 빈 결과는 metric 미수집, label 불일치, 시간 범위 문제로 분리하고 query transport/API 오류나 권한 실패와 섞지 않는다. init·ephemeral 구분과 current/previous는 Pod spec/status와 명시적 이름으로 확정한다.

## 정상화와 상태 변경 경계

정상화는 역순으로 `application 기능 → 로그 stream·API data → kubelet/runtime → Pod UID·kind/name·state`를 확인한다. 동일 UID에서 대상 container의 Ready·restart 증가 중단·새 Warning 없음·반복 오류 없음·실제 서비스 기능과 재발 관찰을 함께 확인한다. `Running`, `Ready`, 로그 조회 성공은 application 정상이나 pipeline 정상의 단독 증거가 아니다.

이 문서는 상태 변경 명령을 제공하지 않는다. Pod 삭제·restart·scale·patch·ephemeral injection·exec가 필요하면 증거와 영향 분석, 서비스 owner 승인, least privilege, 중단·rollback·실행 후 검증을 별도 절차로 닫는다. 보존 항목은 namespace, Pod UID, node, kind/name, containerID, current/previous, UTC 관측 시각, 사용 명령의 성공·실패와 비식별 오류 구간이다. Secret·token·개인정보·로그 원문은 저장하지 않는다.
