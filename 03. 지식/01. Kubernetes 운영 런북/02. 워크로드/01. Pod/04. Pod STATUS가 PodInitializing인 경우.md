# Pod STATUS가 PodInitializing인 경우

## 입력값과 빠른 수집

값은 최초 입력, API 확인 자동값, 계산 후보, 운영자 선택값으로 나눈다. 최초에는 승인된 namespace와 Pod만 입력한다. UID·node·phase·시각·owner·container와 port 관계는 Kubernetes API에서 자동 등록한다. namespace와 Pod 정규식은 이름에서 계산하는 후보이며, 실제 쿼리에 사용하기 전에 escape 결과를 확인한다. 일반 container 이름·로그 시작 시각·Deployment 변경 대상은 상태와 증거를 본 뒤 운영자가 선택한다.

| 구분 | 값 | 출처와 사용 범위 |
|---|---|---|
| 최초 입력 | `NS`, `POD` | 운영자가 승인된 namespace와 정확한 Pod 이름을 한 번 입력한다. |
| API 확인 자동값 | `POD_UID`, `NODE`, `PHASE`, `POD_START`, `OWNER`, `INIT_CONTAINER`, `CONTAINER_ID`, container/port 후보, Init 상태 | Pod API의 같은 응답에서 등록한다. 빈 값·복수 controller owner·API 실패면 세트를 등록하지 않는다. |
| 계산 후보 | `NS_RE`, `POD_RE`, 생성된 PromQL | 등록된 이름을 정규식으로 escape한 값이다. 후보 출력과 길이 확인 전에는 관측에 사용하지 않는다. |
| 운영자 선택값 | `CONTAINER`, `START_RFC3339`, `DEPLOYMENT`, `APPROVAL_ID`, `ROLLBACK_REVISION` | printer 불일치 분기의 일반 container, 최초 결정적 시각보다 로그 지연 여유만큼 앞선 시각, 승인된 Deployment 변경의 승인·rollback 기록이다. 상태 변경이 없으면 입력하지 않는다. |

명령은 승인된 작업 PC 또는 bastion의 **같은 Bash 터미널**에서 실행한다. 이 문서의 API 명령은 `kubectl` client에서 Kubernetes API server로 가며, node journal은 node에 권한을 갖고 접속한 host에서 실행한다. 터미널을 바꾸면 변수와 gate를 처음부터 다시 등록한다. 필수 도구는 `kubectl`, `jq`, `grep`, `sed`, `date`이며 API 읽기 권한과 대상 namespace 접근 권한이 필요하다. node journal은 별도로 node 접근·`sudo`·실제 kubelet unit·`journalctl` 권한이 확인된 경우에만 사용한다. 도구 확인 또는 exact-name API 확인이 실패하면 다음 단계로 진행하지 않는다.

**Bash와 필수 도구 확인 — 아래 한 줄 전체를 복사**

`TOOLS_READY=false; MISSING_TOOLS=''; TOOL=''; if [ -z "${BASH_VERSION:-}" ]; then printf '%s\n' '중단: Bash가 아니다. Bash 셸에서 다시 실행한다.' >&2; else for TOOL in kubectl jq grep sed date; do command -v "$TOOL" >/dev/null 2>&1 || MISSING_TOOLS="$MISSING_TOOLS $TOOL"; done; if [ -n "$MISSING_TOOLS" ]; then printf '중단: 없는 필수 도구=%s\n' "$MISSING_TOOLS" >&2; else TOOLS_READY=true; grep(){ command grep "$@"; local FILTER_RC=$?; if [ "$FILTER_RC" -gt 1 ]; then printf '중단: grep filter 실패 rc=%s\n' "$FILTER_RC" >&2; exit "$FILTER_RC"; fi; return "$FILTER_RC"; }; refresh_current_identity(){ local c="$1" identity_json identity_uid identity_id; if [ -z "${POD:-}" ] || [ -z "${NS:-}" ] || [ -z "${POD_UID:-}" ]; then return 1; fi; if ! identity_json="$(command kubectl get pod "$POD" -n "$NS" -o json)"; then return 1; fi; if ! identity_uid="$(jq -r '.metadata.uid // empty' <<<"$identity_json")"; then return 1; fi; if [ "$identity_uid" != "$POD_UID" ]; then return 1; fi; if ! identity_id="$(jq -r --arg c "$c" '([.status.containerStatuses[]?, .status.initContainerStatuses[]?] | map(select(.name==$c) | .containerID // empty) | if length==1 then .[0] else empty end)' <<<"$identity_json")"; then return 1; fi; if [ -z "$identity_id" ]; then return 1; fi; CONTAINER_ID="$identity_id"; return 0; }; kubectl(){ if [ "${1:-}" = logs ]; then local c='' previous='' arg=''; for arg in "$@"; do if [ "$previous" = -c ]; then c="$arg"; break; fi; previous="$arg"; done; if [ -z "$c" ] || ! refresh_current_identity "$c"; then printf '중단: logs 직전 current Pod UID/containerID 재조회 실패 pod=%s uid=%s container=%s\n' "${POD:--}" "${POD_UID:--}" "${c:--}" >&2; return 1; fi; fi; command kubectl "$@"; }; printf 'TOOLS_READY=true shell=Bash version=%s\n' "$BASH_VERSION"; fi; fi`

`TOOLS_READY=true`가 아니면 아래 입력·수집 명령을 실행하지 않는다. `jq`나 `kubectl`이 없으면 raw JSON을 저장하거나 임의의 대체 명령으로 진행하지 말고 승인된 UI 또는 담당 owner에게 같은 필드 확인을 요청한다.

**최초 입력·이전 파생값 초기화 — 같은 Bash에서 한 번 실행**

`unset INPUT_READY AUTO_READY PROMQL_READY POD_JSON POD_UID NODE PHASE POD_START OWNER INIT_CONTAINER CONTAINER_ID NS_RE POD_RE QUERY CONTAINER START_RFC3339 DEPLOYMENT SELECTION_READY EXECUTION_READY CURRENT_LOG_READY PREVIOUS_LOG_READY LOG_OUTPUT LOG_RC FILTERED APPROVAL_ID ROLLBACK_REVISION OWNER_CHAIN_READY IMPACT_READY CHANGE_APPROVAL_READY NEW_POD_UID_READY; NS='PASTE_NAMESPACE_HERE'; POD='PASTE_POD_HERE'; INPUT_READY=false; if [ "$TOOLS_READY" != true ]; then printf '%s\n' '중단: 도구 확인을 먼저 통과한다.' >&2; elif [ -z "$NS" ] || [ -z "$POD" ]; then printf '%s\n' '중단: NS와 POD를 입력한다.' >&2; elif kubectl get pod "$POD" -n "$NS" -o json >/dev/null 2>&1; then INPUT_READY=true; printf 'INPUT_READY=true namespace=%s pod=%s\n' "$NS" "$POD"; else printf '중단: Pod exact-name 조회 실패 namespace=%s pod=%s\n' "$NS" "$POD" >&2; fi`

입력 명령의 API 성공은 해당 이름의 현재 Pod가 있다는 뜻만 보장한다. `INPUT_READY=true`가 아니면 context·namespace·권한을 확인하고, Pod 이름만 알고 namespace를 모를 때만 승인된 범위에서 `kubectl get pods -A`로 찾은 뒤 정확한 입력을 다시 등록한다. 이름이 재생성되면 이전 UID의 증거를 재사용하지 않는다.

### API 자동 수집

**대상별 관계 출력과 자동 등록 — 아래 한 줄 전체를 복사**

`AUTO_READY=false; unset POD_UID NODE PHASE POD_START OWNER INIT_CONTAINER CONTAINER_ID NS_RE POD_RE; if [ "$INPUT_READY" != true ]; then printf '%s\n' '중단: INPUT_READY가 아니다.' >&2; elif POD_JSON="$(kubectl get pod "$POD" -n "$NS" -o json)" && OWNER_COUNT_TMP="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)] | length' <<<"$POD_JSON")" && CONTAINER_COUNT_TMP="$(jq -r '[.spec.containers[]?] | length' <<<"$POD_JSON")" && POD_UID_TMP="$(jq -r '.metadata.uid // empty' <<<"$POD_JSON")" && NODE_TMP="$(jq -r '.spec.nodeName // "-"' <<<"$POD_JSON")" && PHASE_TMP="$(jq -r '.status.phase // "-"' <<<"$POD_JSON")" && POD_START_TMP="$(jq -r '.status.startTime // "-"' <<<"$POD_JSON")" && INIT_TMP="$(jq -r '[.spec.initContainers[]? | .name] as $names | [.status.initContainerStatuses[]? | select(.state.terminated.exitCode != 0 or .state.terminated == null) | .name] as $unfinished | ($names | map(select(. as $n | $unfinished | index($n) != null)) | .[0] // "-")' <<<"$POD_JSON")" && CONTAINER_ID_TMP="$(jq -r '[.status.containerStatuses[]? | select(.state.running != null or .state.terminated != null) | .containerID // "-"] | join(",")' <<<"$POD_JSON")" && jq -r '"=== 대상 Pod ===\nPod 이름: \(.metadata.name)\nPod UID: \(.metadata.uid)\nNamespace: \(.metadata.namespace)\nNode: \(.spec.nodeName // "-")\nPhase: \(.status.phase // "-")\nPod 시작 시각: \(.status.startTime // "-")\n상위 owner: " + ([.metadata.ownerReferences[]? | select(.controller==true) | "\(.kind)/\(.name)"] | join(",") // "-") + "\nContainer/Port 후보: " + ([.spec.containers[]? | "\(.name)=\([.ports[]? | ((.name // "unnamed") + ":" + (.containerPort|tostring))] | join(","))"] | join("; ") // "-") + "\nInit 순서/현재·직전 상태: " + ([.status.initContainerStatuses[]? | "\(.name) / 현재=\(((.state // {}) | keys | join(","))) / 직전=\(((.lastState // {}) | keys | join(","))) / exit=\(.state.terminated.exitCode // "-") / finished=\(.state.terminated.finishedAt // "-") / restart=\(.restartCount // 0)"] | join("; ") // "-") + "\n일반 container 상태: " + ([.status.containerStatuses[]? | "\(.name) / 현재=\(((.state // {}) | keys | join(","))) / 직전=\(((.lastState // {}) | keys | join(","))) / container ID=\(.containerID // "-")"] | join("; ") // "-")' <<<"$POD_JSON"; then if [ "$OWNER_COUNT_TMP" -gt 1 ] || [ "$CONTAINER_COUNT_TMP" -lt 1 ] || [ -z "$POD_UID_TMP" ]; then printf '중단: owner 후보 수 또는 container 수가 기대 범위가 아님 owner=%s container=%s\n' "$OWNER_COUNT_TMP" "$CONTAINER_COUNT_TMP" >&2; else POD_UID="$POD_UID_TMP"; NODE="$NODE_TMP"; PHASE="$PHASE_TMP"; POD_START="$POD_START_TMP"; OWNER="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true) | "\(.kind)/\(.name)"] | if length==1 then .[0] else "-" end' <<<"$POD_JSON")"; INIT_CONTAINER="$INIT_TMP"; CONTAINER_ID="$CONTAINER_ID_TMP"; NS_RE_TMP="$(printf '%s' "$NS" | sed 's/[][\\.^$*+?(){}|]/\\&/g')"; POD_RE_TMP="$(printf '%s' "$POD" | sed 's/[][\\.^$*+?(){}|]/\\&/g')"; NS_RE="^${NS_RE_TMP}$"; POD_RE="^${POD_RE_TMP}$"; AUTO_READY=true; PROMQL_READY=true; printf 'AUTO_READY=true UID=%s NODE=%s PHASE=%s POD_START=%s INIT_CONTAINER=%s\n' "$POD_UID" "$NODE" "$PHASE" "$POD_START" "$INIT_CONTAINER"; printf '정규식 후보: namespace=%s pod=%s\n' "$NS_RE" "$POD_RE"; fi; else printf '%s\n' '중단: 자동 수집 API 호출 실패. 이전 값은 유효하지 않다.' >&2; fi`

성공 gate는 동일 응답에서 대상별 세로 블록, UID·node·phase·Pod 시작 시각, owner, container/port 관계와 Init·일반 container 상태가 출력되고 `AUTO_READY=true`가 등록되는 것이다. `INIT_CONTAINER`는 선언 순서상 첫 미완료 Init을 계산한 값이며 임의의 첫 후보 선택이 아니다. API 실패·복수 controller owner·container 부재·빈 UID 또는 출력 실패면 모든 자동값을 무효로 하고 중단한다. `Running`, `Ready` 또는 `PodInitializing` printer는 application 정상이나 Init 원인 해소를 보장하지 않는다.

## 최초 확인

**현재 객체·상태 확인 — 아래 한 줄 전체를 복사**

`if [ "$AUTO_READY" != true ]; then printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; else kubectl get pod "$POD" -n "$NS" -o wide && kubectl get pod "$POD" -n "$NS" -o jsonpath='{.status.phase}{"\n"}{range .status.initContainerStatuses[*]}init/{.name}{" current-waiting="}{.state.waiting.reason}{" current-running="}{.state.running.startedAt}{" current-terminated="}{.state.terminated.reason}{" current-exit="}{.state.terminated.exitCode}{" current-finished="}{.state.terminated.finishedAt}{" last-terminated="}{.lastState.terminated.reason}{" last-exit="}{.lastState.terminated.exitCode}{" last-finished="}{.lastState.terminated.finishedAt}{" restarts="}{.restartCount}{"\n"}{end}{range .status.containerStatuses[*]}container/{.name}{" current-waiting="}{.state.waiting.reason}{" current-running="}{.state.running.startedAt}{" current-terminated="}{.state.terminated.reason}{" current-exit="}{.state.terminated.exitCode}{" last-terminated="}{.lastState.terminated.reason}{" last-exit="}{.lastState.terminated.exitCode}{" restarts="}{.restartCount}{"\n"}{end}' && kubectl describe pod "$POD" -n "$NS"; fi`

**UID 제한 Event 확인 — 아래 한 줄 전체를 복사**

`if [ "$AUTO_READY" != true ]; then printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; else kubectl get events -n "$NS" --field-selector "involvedObject.kind=Pod,involvedObject.name=$POD,involvedObject.uid=$POD_UID" --sort-by=.metadata.creationTimestamp -o custom-columns='CREATED:.metadata.creationTimestamp,FIRST-SEEN:.firstTimestamp,LAST-SEEN:.lastTimestamp,EVENT-TIME:.eventTime,SERIES-LAST:.series.lastObservedTime,TYPE:.type,REASON:.reason,COUNT:.count,MESSAGE:.message'; fi`

`get`에서는 `STATUS`, `READY`, `RESTARTS`, `NODE`, `AGE`, status에서는 Init 선언 순서와 current·last state, `reason`, `exitCode`, `finishedAt`, `restartCount`, 일반 container의 waiting reason을 본다. `describe`에서는 Conditions와 첫 실패 Event의 message·시각을 본다. Event의 `FIRST-SEEN`, `LAST-SEEN`, `EVENT-TIME`, `SERIES-LAST`, `COUNT` 중 채워진 값을 `finishedAt`·로그 시각과 대조한다. Event 빈 결과는 정상·오류 없음이 아니라 UID·namespace·API 범위·권한·Event 보존 기간을 다시 확인해야 하는 결과다. 이 문서의 별도 Event 조회는 한 번뿐이다.

`get`, status JSONPath 또는 `describe` 중 하나라도 실패하면 출력이 부분적으로 남아도 다음 분기로 진행하지 않는다. API/RBAC·UID·대상 이름을 확인한 뒤 최초 확인을 다시 하고, 성공한 `get`만으로 Init·application 정상화를 선언하지 않는다.

|---|---|---|---|
| 첫 미완료 Init이 `waiting`, `running`, `terminated`이거나 restart가 증가 | Init current·last state, exit code, restartCount | Init image·mount·dependency·process | [[05. Pod가 Init 단계에서 진행되지 않는 경우\|Init 단계 상세 진단으로 이동]] |
| 모든 Init이 exit code 0인데 일반 container의 waiting reason만 `PodInitializing` | 일반 container state, Conditions, UID 제한 Event 시각 | printer 불일치와 controller owner | [[#1. 모든 Init이 완료됐는데 printer가 PodInitializing인 경우\|1]] |
| Init 완료 후 일반 container에 image·config·mount·sandbox waiting reason | 일반 container reason과 Event suffix | 전용 image·config·mount·sandbox 런북 | 관련 제외 링크로 이관 |
| node 미배정 또는 `FailedScheduling` | phase, Conditions, Event message | scheduler와 node 배치 조건 | [[02. Pod STATUS가 Pending인 경우\|Pending 런북]] / [[18. Pod 이벤트에 FailedScheduling이 기록된 경우\|FailedScheduling]] |

표는 경로 선택용이며 원인 확정이나 상태 변경 승인이 아니다. 빈 로그·Event는 process 정상이나 원인 해소를 보장하지 않는다. Secret data·token·개인정보가 보이면 출력을 중단하고 오류 유형만 비식별화해 기록한다.

### 1. 모든 Init이 완료됐는데 printer가 PodInitializing인 경우

진입 증거는 최초 확인 status에서 모든 Init의 `state.terminated.exitCode=0`이고 일반 container에 `state.waiting.reason=PodInitializing`만 남은 같은 UID 관측이다. `ErrImagePull`, `FailedMount`, `FailedCreatePodSandBox`, `CreateContainerConfigError`, `CreateContainerError`, `RunContainerError`가 있으면 이 절을 중단하고 해당 런북으로 이동한다.

이 분기는 작업 host → `kubectl` client → Kubernetes API server → 대상 Pod의 kubelet/runtime → 일반 container/application 로그 순서로 연결된다. API server까지 성공해도 kubelet stream 준비나 application 정상은 보장하지 않는다. 로그를 읽을 때는 출력된 container 후보 중 실제 상태가 `running` 또는 `terminated`인 하나를 운영자가 고른다.

**일반 container와 로그 시작 시각 선택 — 분기 진입 후 같은 Bash에서 한 번 실행**

`SELECTION_READY=false; EXECUTION_READY=false; CURRENT_LOG_READY=false; PREVIOUS_LOG_READY=false; CONTAINER='PASTE_CONTAINER_HERE'; START_RFC3339='PASTE_START_RFC3339_HERE'; CONTAINER_ID='-'; START_EPOCH=''; if [ "$AUTO_READY" != true ]; then printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; elif [[ ! "$START_RFC3339" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]]; then printf '중단: START_RFC3339 형식 오류=%s\n' "$START_RFC3339" >&2; elif START_EPOCH="$(date -u -d "$START_RFC3339" +%s 2>/dev/null)" && [ -n "$START_EPOCH" ] && POD_JSON_NOW="$(kubectl get pod "$POD" -n "$NS" -o json)" && UID_NOW="$(jq -r '.metadata.uid // empty' <<<"$POD_JSON_NOW")" && CONTAINER_STATE="$(jq -c --arg c "$CONTAINER" '[.status.containerStatuses[]? | select(.name==$c)] | if length==1 then .[0] else empty end' <<<"$POD_JSON_NOW")" && [ "$UID_NOW" = "$POD_UID" ] && [ -n "$CONTAINER_STATE" ]; then CONTAINER_ID="$(jq -r '.containerID // "-"' <<<"$CONTAINER_STATE")"; if jq -e '.state.running != null or .state.terminated != null' <<<"$CONTAINER_STATE" >/dev/null; then CURRENT_LOG_READY=true; EXECUTION_READY=true; fi; if jq -e '.lastState.terminated != null' <<<"$CONTAINER_STATE" >/dev/null; then PREVIOUS_LOG_READY=true; EXECUTION_READY=true; fi; SELECTION_READY=true; printf 'SELECTION_READY=true pod=%s uid=%s container=%s containerID=%s currentLog=%s previousLog=%s executionHistory=%s start=%s\n' "$POD" "$POD_UID" "$CONTAINER" "$CONTAINER_ID" "$CURRENT_LOG_READY" "$PREVIOUS_LOG_READY" "$EXECUTION_READY" "$START_RFC3339"; else printf '중단: 선택 container·최초 Pod UID·시간 형식 또는 API 재조회 확인 실패. waiting이면 status/Event 경로만 사용한다.\n' >&2; fi`

`START_RFC3339`는 최초 실패 Event·상태 종료 시각·결정적 로그 시각 중 이른 값보다 운영 환경의 로그 지연 여유만큼 앞서야 한다. `SELECTION_READY=true`는 같은 Pod UID의 선택 container 상태와 container ID를 확인했다는 뜻이다. API/RBAC 오류, UID 변경, container가 아직 `waiting`이거나 container ID가 비면 application 정상으로 해석하지 말고 [[05. Pod가 Init 단계에서 진행되지 않는 경우\|Init 상세]] 또는 owner로 이관한다.

`SELECTION_READY=true`이고 `EXECUTION_READY=false`이면 현재 container가 실제로 실행된 이력이 없는 waiting 대상이다. 이 경우 logs/previous logs를 실행하지 않고 최초 status·UID 제한 Event·owner를 기준으로 [[05. Pod가 Init 단계에서 진행되지 않는 경우\|Init 상세]] 또는 해당 일반 container 런북으로 이관한다. `CURRENT_LOG_READY`와 `PREVIOUS_LOG_READY`는 각각 현재·직전 실행 instance가 실제로 존재할 때만 열린다.

**현재 container 제한 로그 — 아래 한 줄 전체를 복사**

`LOG_OUTPUT=''; LOG_RC=0; FILTERED=''; FILTER_RC=0; if [ "$SELECTION_READY" != true ] || [ "$CURRENT_LOG_READY" != true ]; then printf '%s\n' '중단: SELECTION_READY 또는 CURRENT_LOG_READY가 아니다. waiting·미실행 대상은 status/Event로 이관한다.' >&2; else LOG_OUTPUT="$(kubectl logs "$POD" -n "$NS" -c "$CONTAINER" --timestamps --since-time="$START_RFC3339" --tail=200)"; LOG_RC=$?; if [ "$LOG_RC" -ne 0 ]; then printf '로그 producer 실패 계층=API/kubelet/runtime rc=%s pod=%s uid=%s container=%s containerID=%s\n' "$LOG_RC" "$POD" "$POD_UID" "$CONTAINER" "$CONTAINER_ID" >&2; else FILTERED="$(printf '%s\n' "$LOG_OUTPUT" | grep -E -i -C 3 'panic|fatal|error|exception|timeout|refused|denied|permission|not found|killed')"; FILTER_RC=$?; if [ "$FILTER_RC" -eq 0 ]; then printf '%s\n' "$FILTERED"; elif [ "$FILTER_RC" -eq 1 ]; then printf '%s\n' '로그 producer는 성공했지만 필터 무일치다. 같은 시간 범위 tail로 재확인한다.' >&2; else printf '로그 filter 실패 rc=%s\n' "$FILTER_RC" >&2; fi; fi; fi`

로그 stream 실패는 `container is waiting`, `container not found`, Forbidden, API 연결 오류와 로그 보존 문제를 구분해 [[27. Pod 로그를 가져올 수 없는 경우]]로 이관한다. 필터가 빈 것은 오류 없음이 아니다. current container가 실제 시작된 경우에만 다음 bounded tail을 실행한다. `kubectl logs`의 성공은 해당 stream을 읽었다는 범위만 보장하며 process listener·application 기능을 보장하지 않는다.

**필터 없는 bounded tail — 아래 한 줄 전체를 복사**

`if [ "$SELECTION_READY" != true ] || [ "$CURRENT_LOG_READY" != true ]; then printf '%s\n' '중단: current 실행 이력 gate가 아니다.' >&2; else kubectl logs "$POD" -n "$NS" -c "$CONTAINER" --timestamps --since-time="$START_RFC3339" --tail=50; fi`

**직전 실행 이력 로그 — previous gate 통과 시 한 줄 전체를 복사**

`PREVIOUS_OUTPUT=''; PREVIOUS_RC=0; PREVIOUS_FILTERED=''; PREVIOUS_FILTER_RC=0; if [ "$SELECTION_READY" != true ] || [ "$PREVIOUS_LOG_READY" != true ]; then printf '%s\n' '중단: previous 실행 이력 gate가 아니다. waiting status만 있으면 status/Event로 이관한다.' >&2; else PREVIOUS_OUTPUT="$(kubectl logs "$POD" -n "$NS" -c "$CONTAINER" --previous --timestamps --since-time="$START_RFC3339" --tail=200)"; PREVIOUS_RC=$?; if [ "$PREVIOUS_RC" -ne 0 ]; then printf 'previous 로그 producer 실패 계층=API/kubelet/runtime/보존 rc=%s pod=%s uid=%s container=%s containerID=%s\n' "$PREVIOUS_RC" "$POD" "$POD_UID" "$CONTAINER" "$CONTAINER_ID" >&2; else PREVIOUS_FILTERED="$(printf '%s\n' "$PREVIOUS_OUTPUT" | grep -E -i -C 3 'panic|fatal|error|exception|timeout|refused|denied|permission|not found|killed')"; PREVIOUS_FILTER_RC=$?; if [ "$PREVIOUS_FILTER_RC" -eq 0 ]; then printf '%s\n' "$PREVIOUS_FILTERED"; elif [ "$PREVIOUS_FILTER_RC" -eq 1 ]; then printf '%s\n' 'previous 로그 producer는 성공했지만 필터 무일치다.' >&2; else printf 'previous 로그 filter 실패 rc=%s\n' "$PREVIOUS_FILTER_RC" >&2; fi; fi; fi`

로그에 민감정보가 보이면 출력을 중단한다. 일반 container가 실제로 `running` 또는 `terminated`가 아니거나 상태가 이미 `ErrImagePull`·mount·sandbox·config로 바뀌었으면 로그를 원인 증거로 확대하지 말고 관측별 경로의 전용 런북으로 이동한다.

### PromQL 빠른 관측

`PROMQL_READY=true`이고 같은 Bash에서 등록된 `NS_RE`, `POD_RE`, 최초 `POD_UID`를 사용할 때만 PromQL을 생성한다. 사용자는 생성된 한 줄만 Prometheus 또는 Grafana에 붙여 넣으며 쿼리 내부를 직접 수정하지 않는다. 정규식은 이름을 escape한 bounded 후보다. 재생성 Pod UID가 다르면 이전 query를 재사용하지 않는다.

**Init 상태 PromQL 생성 — 아래 한 줄 전체를 복사**

`PROMQL_UID_NOW=''; PROMQL_UID_RC=0; if [ "$PROMQL_READY" != true ] || [ -z "$POD_UID" ]; then printf '%s\n' '중단: PROMQL_READY 또는 최초 Pod UID가 아니다.' >&2; else PROMQL_UID_NOW="$(kubectl get pod "$POD" -n "$NS" -o jsonpath='{.metadata.uid}')"; PROMQL_UID_RC=$?; if [ "$PROMQL_UID_RC" -ne 0 ]; then PROMQL_READY=false; AUTO_READY=false; SELECTION_READY=false; printf '중단: PromQL 직전 exact Pod UID 재조회 실패 rc=%s pod=%s\n' "$PROMQL_UID_RC" "$POD" >&2; elif [ "$PROMQL_UID_NOW" != "$POD_UID" ]; then PROMQL_READY=false; AUTO_READY=false; SELECTION_READY=false; printf '중단: PromQL 직전 Pod UID mismatch 최초=%s 현재=%s. 재수집한다.\n' "$POD_UID" "$PROMQL_UID_NOW" >&2; else QUERY="kube_pod_status_phase{namespace=~\"$NS_RE\",pod=~\"$POD_RE\",uid=\"$POD_UID\",phase=\"Pending\"}==1"; if [ "${#QUERY}" -gt 500 ]; then printf '%s\n' '중단: 생성 쿼리가 비정상적으로 길다.' >&2; else printf 'PromQL=%s\n' "$QUERY"; fi; fi; fi`

**Init waiting PromQL 생성 — 아래 한 줄 전체를 복사**

`PROMQL_UID_NOW=''; PROMQL_UID_RC=0; if [ "$PROMQL_READY" != true ] || [ -z "$POD_UID" ]; then printf '%s\n' '중단: PROMQL_READY 또는 최초 Pod UID가 아니다.' >&2; else PROMQL_UID_NOW="$(kubectl get pod "$POD" -n "$NS" -o jsonpath='{.metadata.uid}')"; PROMQL_UID_RC=$?; if [ "$PROMQL_UID_RC" -ne 0 ]; then PROMQL_READY=false; AUTO_READY=false; SELECTION_READY=false; printf '중단: PromQL 직전 exact Pod UID 재조회 실패 rc=%s pod=%s\n' "$PROMQL_UID_RC" "$POD" >&2; elif [ "$PROMQL_UID_NOW" != "$POD_UID" ]; then PROMQL_READY=false; AUTO_READY=false; SELECTION_READY=false; printf '중단: PromQL 직전 Pod UID mismatch 최초=%s 현재=%s. 재수집한다.\n' "$POD_UID" "$PROMQL_UID_NOW" >&2; else QUERY="kube_pod_init_container_status_waiting{namespace=~\"$NS_RE\",pod=~\"$POD_RE\",uid=\"$POD_UID\"}==1"; if [ "${#QUERY}" -gt 500 ]; then printf '%s\n' '중단: 생성 쿼리가 비정상적으로 길다.' >&2; else printf 'PromQL=%s\n' "$QUERY"; fi; fi; fi`

metric 조회 실패, HTTP/API 또는 권한 실패와 빈 결과를 구분한다. 빈 결과는 metric 미수집·label 불일치·조회 시간 범위 문제일 수 있으며 `0`, 정상, Init 순서 성공으로 해석하지 않는다. PromQL은 command 실패·외부 dependency·Init process 종료 원인을 직접 설명하지 않으므로 UID와 UTC 관측 시각의 Pod status·Event·로그를 우선한다.

## 복구 전 gate와 조건부 변경

진단과 상태 변경은 분리한다. 삭제·patch·edit·무조건 재시작은 제시하지 않는다. rollout은 첫 미완료 Init의 이름·state·reason·exitCode·restartCount, Pod UID·owner·node, Ready/replica 영향, 외부 호출·migration·데이터 중복 위험과 직접 원인 수정 증거를 기록하고 서비스 owner의 승인과 rollback·중단 조건을 확인한 뒤에만 고려한다. Job/CronJob·StatefulSet·단독 Pod·멱등성이 확인되지 않은 migration에는 적용하지 않는다.

**변경 대상 등록 — 승인된 Deployment owner인 경우에만 분기 진입 후 한 번 실행**

`DEPLOYMENT='PASTE_DEPLOYMENT_HERE'`

`DEPLOYMENT`는 재입력하지 않는다. 승인 ID와 rollback revision은 변경 분기에서만 입력한다. 승인 ID 원문은 출력·로그에 남기지 않는다.

**Pod→ReplicaSet→Deployment chain·selector·승인 gate — 아래 한 줄 전체를 복사**

`OWNER_CHAIN_READY=false; REPLICASET=''; APPROVAL_ID='PASTE_APPROVAL_ID_HERE'; ROLLBACK_REVISION='PASTE_ROLLBACK_REVISION_HERE'; POD_CHAIN_JSON=''; RS_CHAIN_JSON=''; DEPLOYMENT_JSON=''; HISTORY_OUTPUT=''; HISTORY_RC=0; if [ "$AUTO_READY" != true ] || [ -z "$DEPLOYMENT" ] || [ -z "$APPROVAL_ID" ] || ! [[ "$ROLLBACK_REVISION" =~ ^[0-9]+$ ]]; then printf '%s\n' '중단: AUTO_READY·DEPLOYMENT·승인 ID·숫자 rollback revision gate가 아니다.' >&2; elif POD_CHAIN_JSON="$(kubectl get pod "$POD" -n "$NS" -o json)" && UID_NOW="$(jq -r '.metadata.uid // empty' <<<"$POD_CHAIN_JSON")" && [ "$UID_NOW" = "$POD_UID" ] && REPLICASET="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true and .kind=="ReplicaSet") | .name] | if length==1 then .[0] else empty end' <<<"$POD_CHAIN_JSON")" && [ -n "$REPLICASET" ] && RS_CHAIN_JSON="$(kubectl get rs "$REPLICASET" -n "$NS" -o json)" && DEPLOYMENT_JSON="$(kubectl get deployment "$DEPLOYMENT" -n "$NS" -o json)"; then if jq -e --arg rs "$REPLICASET" --arg dep "$DEPLOYMENT" --argjson rsobj "$RS_CHAIN_JSON" --argjson depobj "$DEPLOYMENT_JSON" '(.metadata.ownerReferences[]? | select(.controller==true and .kind=="ReplicaSet" and .name==$rs)) as $podOwner | ($rsobj.metadata.ownerReferences[]? | select(.controller==true and .kind=="Deployment" and .name==$dep)) as $rsOwner | ($depobj.spec.selector.matchLabels // {}) as $depSelector | ($rsobj.spec.selector.matchLabels // {}) as $rsSelector | ($rsobj.spec.template.metadata.labels // {}) as $templateLabels | (.metadata.labels // {}) as $podLabels | (($depobj.spec.selector.matchExpressions // [])|length)==0 and (($rsobj.spec.selector.matchExpressions // [])|length)==0 and ($podOwner.uid==$rsobj.metadata.uid) and ($rsOwner.uid==$depobj.metadata.uid) and ($depSelector|length)>0 and all($depSelector|to_entries[]; $templateLabels[.key]==.value and $podLabels[.key]==.value) and all($rsSelector|to_entries[]; $podLabels[.key]==.value)' <<<"$POD_CHAIN_JSON" >/dev/null; then HISTORY_OUTPUT="$(kubectl rollout history deployment "$DEPLOYMENT" -n "$NS")"; HISTORY_RC=$?; if [ "$HISTORY_RC" -ne 0 ]; then printf '중단: rollback history producer 실패 rc=%s deployment=%s\n' "$HISTORY_RC" "$DEPLOYMENT" >&2; elif printf '%s\n' "$HISTORY_OUTPUT" | grep -Eq "(^|[[:space:]])${ROLLBACK_REVISION}([[:space:]]|$)"; then OWNER_CHAIN_READY=true; printf 'OWNER_CHAIN_READY=true podUID=%s replicaset=%s deployment=%s rollbackRevision=%s approval=recorded\n' "$POD_UID" "$REPLICASET" "$DEPLOYMENT" "$ROLLBACK_REVISION"; else printf '중단: rollback revision이 history filter와 일치하지 않음 revision=%s\n' "$ROLLBACK_REVISION" >&2; fi; else printf '%s\n' '중단: Pod·ReplicaSet·Deployment UID chain 또는 selector 검증 실패. 변경하지 않고 owner에게 이관한다.' >&2; fi; else printf '중단: Pod 재조회/API/UID/owner chain 조회 실패 pod=%s 최초UID=%s\n' "$POD" "$POD_UID" >&2; fi`

이 gate는 재조회 Pod UID가 최초 `POD_UID`와 같고, Pod owner UID→ReplicaSet UID→Deployment owner UID, matchLabels selector, 승인 ID 존재와 rollback history 일치를 모두 확인해야 열린다. matchExpressions·복수 owner·빈 출력·producer 실패·filter 무일치는 검증 실패이며 `OWNER_CHAIN_READY`를 열지 않는다.

**변경 전 영향 snapshot gate — 아래 한 줄 전체를 복사**

`IMPACT_READY=false; if [ "$OWNER_CHAIN_READY" != true ]; then printf '%s\n' '중단: OWNER_CHAIN_READY가 아니다.' >&2; elif jq -e '(.spec.replicas|type=="number") and (.status.readyReplicas|type=="number") and (.status.availableReplicas|type=="number")' <<<"$DEPLOYMENT_JSON" >/dev/null; then IMPACT_READY=true; jq -c '{desired:.spec.replicas,ready:.status.readyReplicas,available:.status.availableReplicas}' <<<"$DEPLOYMENT_JSON"; else OWNER_CHAIN_READY=false; printf '%s\n' '중단: Deployment 영향 범위 desired/ready/available snapshot 검증 실패' >&2; fi`

**Init 멱등성·data/quorum 승인 gate — 변경 명령 전에 한 번 실행**

`CHANGE_APPROVAL_READY=false; INIT_IDEMPOTENT='PASTE_INIT_IDEMPOTENT_HERE'; DATA_QUORUM_APPROVAL_ID='PASTE_DATA_QUORUM_APPROVAL_ID_HERE'; if [ "$OWNER_CHAIN_READY" != true ] || [ "$IMPACT_READY" != true ] || [ "$INIT_IDEMPOTENT" != yes ] || [ -z "$DATA_QUORUM_APPROVAL_ID" ]; then printf '%s\n' '중단: owner chain·impact·INIT_IDEMPOTENT=yes·data/quorum 승인 gate가 아니다.' >&2; else CHANGE_APPROVAL_READY=true; printf 'CHANGE_APPROVAL_READY=true initIdempotent=recorded dataQuorumApproval=recorded\n'; fi`

실행 trigger는 직접 원인이 승인된 Deployment 입력에 반영되고 서비스 owner가 승인한 경우다. 영향은 해당 Deployment replica 교체와 Init 재실행이며 외부 dependency 정상·데이터 멱등성·migration 안전을 보장하지 않는다. Init side effect·멱등성, quorum, 외부 호출과 데이터 중복 위험을 별도 승인 기록에서 확인하지 못하면 변경하지 않는다. 같은 Init reason/exitCode, restart 증가, 새 Warning, Ready 감소, query gap 또는 외부 영향 확대가 보이면 즉시 중단하고 승인된 rollback revision과 owner에게 이관한다.

**승인된 Deployment 재평가 — 각 줄을 순서대로 복사**

`if [ "$OWNER_CHAIN_READY" != true ] || [ "$IMPACT_READY" != true ] || [ "$CHANGE_APPROVAL_READY" != true ]; then printf '%s\n' '중단: OWNER_CHAIN_READY·IMPACT_READY·CHANGE_APPROVAL_READY가 아니다. owner에게 이관한다.' >&2; else kubectl rollout restart "deployment/$DEPLOYMENT" -n "$NS"; fi`

`if [ "$OWNER_CHAIN_READY" != true ] || [ "$IMPACT_READY" != true ] || [ "$CHANGE_APPROVAL_READY" != true ]; then printf '%s\n' '중단: OWNER_CHAIN_READY·IMPACT_READY·CHANGE_APPROVAL_READY가 아니다. owner에게 이관한다.' >&2; else kubectl rollout status "deployment/$DEPLOYMENT" -n "$NS" --timeout=5m; fi`

**rollout 후 Pod→ReplicaSet UID→승인된 Deployment name/UID chain·새 UID 전체 자동수집 재등록 — status 다음 한 번 실행**

`NEW_POD_UID_READY=false; NEW_PODS_JSON=''; NEW_POD=''; NEW_POD_UID=''; NEW_POD_CREATED=''; DEPLOYMENT_SELECTOR=''; OLD_POD="$POD"; OLD_POD_UID="$POD_UID"; DEPLOYMENT_UID=''; AUTO_READY=false; PROMQL_READY=false; if [ "$OWNER_CHAIN_READY" != true ] || [ "$IMPACT_READY" != true ] || [ "$CHANGE_APPROVAL_READY" != true ]; then printf '%s\n' '중단: 변경 승인 gate가 아니다.' >&2; elif DEPLOYMENT_UID="$(jq -r '.metadata.uid // empty' <<<"$DEPLOYMENT_JSON")" && DEPLOYMENT_SELECTOR="$(jq -r '[.spec.selector.matchLabels // {} | to_entries[] | "\(.key)=\(.value)"] | join(",")' <<<"$DEPLOYMENT_JSON")" && [ -n "$DEPLOYMENT_UID" ] && [ -n "$DEPLOYMENT_SELECTOR" ]; then NEW_PODS_JSON="$(kubectl get pods -n "$NS" -l "$DEPLOYMENT_SELECTOR" -o json)"; NEW_PODS_RC=$?; if [ "$NEW_PODS_RC" -ne 0 ]; then printf '중단: Deployment selector Pod 목록 producer 실패 rc=%s selector=%s\n' "$NEW_PODS_RC" "$DEPLOYMENT_SELECTOR" >&2; else while IFS= read -r CANDIDATE_POD; do [ -n "$CANDIDATE_POD" ] || continue; CANDIDATE_JSON="$(kubectl get pod "$CANDIDATE_POD" -n "$NS" -o json)" || continue; CANDIDATE_RS="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true and .kind=="ReplicaSet")] | if length==1 then .[0].name else empty end' <<<"$CANDIDATE_JSON")" || continue; [ -n "$CANDIDATE_RS" ] || continue; CANDIDATE_RS_JSON="$(kubectl get rs "$CANDIDATE_RS" -n "$NS" -o json)" || continue; CANDIDATE_RS_UID="$(jq -r '.metadata.uid // empty' <<<"$CANDIDATE_RS_JSON")" || continue; if jq -e --arg old "$OLD_POD_UID" --arg rs "$CANDIDATE_RS" --arg rsuid "$CANDIDATE_RS_UID" --arg dep "$DEPLOYMENT" --arg depuid "$DEPLOYMENT_UID" --argjson rsobj "$CANDIDATE_RS_JSON" --argjson depobj "$DEPLOYMENT_JSON" '($depobj.metadata.name==$dep and $depobj.metadata.uid==$depuid) and ($rsobj.metadata.uid==$rsuid) and ([.metadata.ownerReferences[]? | select(.controller==true and .kind=="ReplicaSet" and .name==$rs and .uid==$rsuid)] | length)==1 and ([$rsobj.metadata.ownerReferences[]? | select(.controller==true and .kind=="Deployment")] | length)==1 and ([$rsobj.metadata.ownerReferences[]? | select(.controller==true and .kind=="Deployment" and .name==$dep and .uid==$depuid)] | length)==1 and (.metadata.uid != $old and (.metadata.uid // "") != "" and (.metadata.creationTimestamp // "") != "") and (($depobj.spec.selector.matchExpressions // [])|length)==0 and (($rsobj.spec.selector.matchExpressions // [])|length)==0 and (($depobj.spec.selector.matchLabels // {})|length)>0 and (($rsobj.spec.selector.matchLabels // {})|length)>0' <<<"$CANDIDATE_JSON" >/dev/null; then NEW_POD="$CANDIDATE_POD"; NEW_POD_JSON="$CANDIDATE_JSON"; NEW_REPLICASET="$CANDIDATE_RS"; NEW_REPLICASET_UID="$CANDIDATE_RS_UID"; break; fi; done < <(jq -r --arg old "$OLD_POD_UID" '[.items[]? | select(.metadata.uid != $old and (.metadata.uid // "") != "" and (.metadata.creationTimestamp // "") != "" and any(.metadata.ownerReferences[]?; .controller==true and .kind=="ReplicaSet"))] | sort_by(.metadata.creationTimestamp) | reverse[] | .metadata.name' <<<"$NEW_PODS_JSON"); if [ -z "$NEW_POD" ]; then printf '%s\n' '중단: selector 후보에서 Pod→ReplicaSet UID→승인된 Deployment name/UID chain을 통과한 replacement Pod를 찾지 못함' >&2; else register_replacement_pod_04(){ local j="$1" owner_count container_count uid node phase start init cid nsre podre owner; owner_count="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)] | length' <<<"$j")" || return 1; container_count="$(jq -r '[.spec.containers[]?] | length' <<<"$j")" || return 1; uid="$(jq -r '.metadata.uid // empty' <<<"$j")" || return 1; node="$(jq -r '.spec.nodeName // "-"' <<<"$j")" || return 1; phase="$(jq -r '.status.phase // "-"' <<<"$j")" || return 1; start="$(jq -r '.status.startTime // "-"' <<<"$j")" || return 1; init="$(jq -r '[.spec.initContainers[]? | .name] as $names | [.status.initContainerStatuses[]? | select(.state.terminated.exitCode != 0 or .state.terminated == null) | .name] as $unfinished | ($names | map(select(. as $n | $unfinished | index($n) != null)) | .[0] // "-")' <<<"$j")" || return 1; cid="$(jq -r '[.status.containerStatuses[]? | select(.state.running != null or .state.terminated != null) | .containerID // "-"] | join(",")' <<<"$j")" || return 1; owner="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true) | "\(.kind)/\(.name)"] | if length==1 then .[0] else "-" end' <<<"$j")" || return 1; [ "$owner_count" -le 1 ] && [ "$container_count" -ge 1 ] && [ -n "$uid" ] || return 1; nsre="$(printf '%s' "$NS" | sed 's/[][\\.^$*+?(){}|]/\\&/g')" || return 1; podre="$(printf '%s' "$NEW_POD" | sed 's/[][\\.^$*+?(){}|]/\\&/g')" || return 1; [ -n "$nsre" ] && [ -n "$podre" ] || return 1; POD_JSON="$j"; POD="$NEW_POD"; POD_UID="$uid"; NODE="$node"; PHASE="$phase"; POD_START="$start"; OWNER="$owner"; INIT_CONTAINER="$init"; CONTAINER_ID="$cid"; NS_RE="^${nsre}$"; POD_RE="^${podre}$"; AUTO_READY=true; PROMQL_READY=true; return 0; }; if register_replacement_pod_04 "$NEW_POD_JSON" && NEW_POD_CREATED="$(jq -r '.metadata.creationTimestamp // empty' <<<"$NEW_POD_JSON")" && [ -n "$NEW_POD_CREATED" ] && jq -r '"=== replacement Pod ===\nPod 이름: \(.metadata.name)\nPod UID: \(.metadata.uid)\nNamespace: \(.metadata.namespace)\nNode: \(.spec.nodeName // "-")\nPhase: \(.status.phase // "-")\nPod 시작 시각: \(.status.startTime // "-")\n상위 owner: " + ([.metadata.ownerReferences[]? | select(.controller==true) | "\(.kind)/\(.name) UID=\(.uid)"] | join(",") // "-") + "\nInit·일반 container 상태: " + ([.status.initContainerStatuses[]?, .status.containerStatuses[]? | "\(.name) / 현재=\(((.state // {}) | keys | join(","))) / 직전=\(((.lastState // {}) | keys | join(","))) / ID=\(.containerID // "-")"] | join("; ") // "-")' <<<"$NEW_POD_JSON"; then NEW_POD_UID="$POD_UID"; NEW_POD_UID_READY=true; printf 'NEW_POD_UID_READY=true pod=%s uid=%s created=%s rs=%s rsUID=%s deployment=%s deploymentUID=%s autoValues=reregistered\n' "$POD" "$POD_UID" "$NEW_POD_CREATED" "$NEW_REPLICASET" "$NEW_REPLICASET_UID" "$DEPLOYMENT" "$DEPLOYMENT_UID"; else AUTO_READY=false; PROMQL_READY=false; POD="$OLD_POD"; POD_UID="$OLD_POD_UID"; printf '%s\n' '중단: replacement Pod 새 UID 기준 전체 자동수집값 재등록 실패' >&2; fi; fi; fi; else printf '%s\n' '중단: 승인된 Deployment UID 또는 selector가 비어 있다.' >&2; fi`

첫 명령이 non-zero이거나 대상·권한 오류를 내면 두 번째 명령과 재시도를 실행하지 않는다. replacement는 selector 후보를 그대로 신뢰하지 않고 Pod owner UID, ReplicaSet UID, 승인된 Deployment name/UID와 selector/template label을 같은 chain에서 검증한다. 통과한 새 Pod의 UID를 기준으로 `POD_UID`, node, phase, 시각, owner, Init, container ID, 정규식과 `AUTO_READY`를 전체 재등록한다. `rollout status` 성공은 controller 관측 범위만 보장하므로 새 UID·Warning·Ready·실제 기능을 정상화 절에서 다시 검증한다.

## 정상화 검증

원인 경로를 역순으로 확인한다. image면 runtime pull 성공과 kubelet Warning 중단 → Init exit code 0, mount면 Linux mount·CSI·kubelet 성공 → Init exit code 0, dependency면 endpoint/DNS·NetworkPolicy 또는 외부 응답 → Init 종료, runtime/Linux면 node 오류 중단 → 다음 Init 실행 순서다.

**정상화 전 최초 Pod UID 재확인 — 아래 한 줄 전체를 복사**

`NORMALIZATION_UID_READY=false; NORMALIZATION_CREATED=''; if [ "$NEW_POD_UID_READY" = true ] && [ "$AUTO_READY" = true ] && NORMALIZATION_POD_JSON="$(kubectl get pod "$POD" -n "$NS" -o json)" && NORMALIZATION_UID="$(jq -r '.metadata.uid // empty' <<<"$NORMALIZATION_POD_JSON")" && NORMALIZATION_CREATED="$(jq -r '.metadata.creationTimestamp // empty' <<<"$NORMALIZATION_POD_JSON")" && [ "$NORMALIZATION_UID" = "$POD_UID" ] && [ -n "$NORMALIZATION_CREATED" ]; then NORMALIZATION_UID_READY=true; printf 'NORMALIZATION_UID_READY=true pod=%s uid=%s created=%s\n' "$POD" "$NORMALIZATION_UID" "$NORMALIZATION_CREATED"; else AUTO_READY=false; PROMQL_READY=false; printf '중단: 정상화 새 Pod UID/created 재조회가 최초 등록과 다르거나 API 조회 실패. 관련 gate를 닫는다.\n' >&2; fi`

**현재 UID의 상태 재확인 — 각 줄을 순서대로 복사**

`if [ "$AUTO_READY" != true ]; then printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; else kubectl get pod "$POD" -n "$NS" -o jsonpath='{.metadata.uid}{"\n"}{.status.phase}{"\n"}{range .status.initContainerStatuses[*]}init={.name}{" exit="}{.state.terminated.exitCode}{" reason="}{.state.terminated.reason}{" restarts="}{.restartCount}{"\n"}{end}{range .status.containerStatuses[*]}container={.name}{" ready="}{.ready}{" state="}{.state}{" restarts="}{.restartCount}{"\n"}{end}'; fi`

`if [ "$AUTO_READY" != true ]; then printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; else kubectl describe pod "$POD" -n "$NS"; fi`

정상화 gate는 같은 또는 승인된 새 Pod UID에서 모든 Init exit code 0, 일반 container의 `Running`·`Ready`, 관찰 창 동안 restart 증가와 새 Warning 없음, 원하는 replica와 실제 요청 또는 승인된 Job 결과 정상이다. `Running`, `Ready`, 새 Pod 생성 또는 rollout status만으로 application 기능과 원인 해소를 선언하지 않는다. 새 UID가 생기면 이전 UID 증거와 섞지 않고 원인 경로와 재발 관찰 시각을 별도로 기록한다.

## 증거 보존

namespace, Pod UID, node, UTC 관측 시각, STATUS·phase, Init 순서·이름·current/last state·reason·exitCode·restartCount, container ID, 첫 Event의 시각·Reason·비식별화 message, image reference, mount/PVC/ConfigMap·Secret key 이름, Service/EndpointSlice, owner, 변경 trigger·승인·검증·중단 여부를 보존한다. Secret data, token, 인증서 개인키, 개인정보와 전체 로그 원문은 보존하지 않는다.
