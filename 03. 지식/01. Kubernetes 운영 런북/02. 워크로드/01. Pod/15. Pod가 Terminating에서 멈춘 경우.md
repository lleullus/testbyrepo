# Pod가 Terminating에서 멈춘 경우

## 입력값과 빠른 수집

`Terminating`은 Pod phase가 아니다. `metadata.deletionTimestamp`가 설정된 객체를 kubectl printer가 그렇게 표시하는 것이며, 실제 phase·container state·finalizer·volume·kubelet 처리는 별도로 확인한다. `--force --grace-period=0`은 API object를 없앨 뿐 process 종료, preStop 완료, volume unmount/detach, 외부 작업 취소를 보장하지 않는다.

| 분류 | 이 문서에서 쓰는 값 | 출처와 처리 |
|---|---|---|
| 최초 입력 | `NS`, `POD` | 운영자가 승인된 namespace와 Pod 이름을 한 번 입력한다. |
| API 자동값 | `POD_UID`, `NODE`, `PHASE`, `OWNER_KIND`, `OWNER_NAME`, `OWNER_UID`, `POD_CREATED`, `DELETION`, `GRACE`, `FINALIZERS`, container/status/ID 후보, `END_RFC3339` | 대상 Pod API와 UTC 시각에서 등록한다. UID·deletion 시각·owner를 확인하지 못하면 중단한다. |
| 계산 후보 | `NS_RE`, `POD_RE`, `UID_RE`, `PROMQL_READY`, `CONTAINER_ID_RAW` | PromQL selector와 CRI ID용으로 생성한다. selector·scheme을 검증하기 전 확정하지 않는다. |
| 운영자 선택값 | `CONTAINER`, `START_RFC3339`, `START_JOURNAL`, `END_JOURNAL`, `NODE_HOST` | 자동 후보와 종료·Event 시각, 승인된 node 접속 mapping을 확인한 뒤 입력한다. |
| finalizer 선택값 | `CONTROLLER_NAMESPACE`, `CONTROLLER_LABEL`, `CONTROLLER_POD`, `CONTROLLER_CONTAINER` | finalizer owner와 실제 controller deployment를 확인한 경우에만 입력한다. |
| volume 선택값 | `PVC`, `NODE_MOUNT_PATH` | Pod→PVC→PV→VolumeAttachment 자동 mapping과 PV·node·CSI driver·CSINode evidence를 확인한 뒤 node filesystem path를 별도로 선택·검증한다. CSI Pod/container 로그는 이 문서에서 직접 선택하지 않고 storage owner에게 이관한다. |

Pod spec의 `volumeMount.mountPath`는 container namespace 안의 경로이며 node filesystem 경로가 아니다. 이 문서는 `NODE_MOUNT_PATH`를 별도로 입력·절대경로 검증하고, node `findmnt`·mountpoint와 PV/VolumeAttachment evidence가 맞지 않으면 storage owner에게 이관한다.
| runtime 선택값 | `RUNTIME_SERVICE` | node에서 실제 확인한 runtime unit을 입력한다. CRI endpoint는 active kubelet ExecStart 또는 config-file에서 gate가 내부 등록하며 기본 socket을 추측하지 않는다. |
| 변경 선택값 | `APPROVAL_ID`, `OWNER_SELECTOR` | 강제 삭제와 replacement 검증 승인을 받은 경우에만 입력한다. selector는 owner 선언에서 그대로 가져온다. |

### 1. 실행 host·도구·최초 입력

기본 명령은 승인된 context가 설정된 **작업 PC 또는 bastion의 같은 Bash 터미널**에서 실행한다. API 명령의 실제 경로는 작업 host → kubectl client → API server다. logs는 API server → kubelet/runtime → container, volume·runtime 명령은 승인된 `NODE_HOST` → Linux/systemd/CSI/runtime로 내려간다. 한 hop의 성공은 다음 hop이나 애플리케이션 정상의 증거가 아니다. PowerShell, CMD, 새 Bash로 바꾸면 gate와 변수가 사라진다.

필수 도구는 `kubectl`, `jq`, `grep`, `sed`, `date`다. 확인 실패 시 초기화·API 수집을 포함한 다음 단계로 진행하지 않는다. `ssh`, `sudo`, `journalctl`, `systemctl`, `findmnt`, `mountpoint`, `crictl`은 해당 branch에서 별도 권한 gate를 통과한 경우에만 사용한다.

`TOOLS_READY=false; MISSING_TOOLS=''; if [ -z "${BASH_VERSION:-}" ]; then printf '%s\n' '중단: 같은 Bash 터미널에서 실행한다.' >&2; else for TOOL in kubectl jq grep sed date; do command -v "$TOOL" >/dev/null 2>&1 || MISSING_TOOLS="$MISSING_TOOLS $TOOL"; done; if [ -z "$MISSING_TOOLS" ]; then TOOLS_READY=true; printf 'TOOLS_READY=true Bash=%s\n' "$BASH_VERSION"; else printf '중단: 없는 도구=%s\n' "$MISSING_TOOLS" >&2; fi; fi`

`TOOLS_READY=true`가 아니면 도구·권한을 먼저 복구한다. 전체 Pod YAML과 Secret·token·개인키·개인정보는 저장하거나 출력하지 않는다.

### 3. 기본값 자동 수집·등록

자동 수집은 Pod UID·node·phase·owner·deletion/grace/finalizer와 container/status/ID를 대상별 세로 블록으로 출력한다. API 호출 또는 필수 field가 실패하면 이전 파생값을 남기지 않는다. `date -u`는 조사 종료 시각이며 deletion 시작 시각으로 사용하지 않는다.



`AUTO_READY=false; unset POD_UID NODE PHASE OWNER_KIND OWNER_NAME OWNER_UID POD_CREATED DELETION GRACE FINALIZERS END_RFC3339; if [ "$INPUT_READY" != true ]; then printf '%s\n' '중단: INPUT_READY가 아니다.' >&2; elif POD_JSON="$(kubectl get pod "$POD" -n "$NS" -o json)" && POD_UID_TMP="$(printf '%s' "$POD_JSON" | jq -er '.metadata.uid')" && NODE_TMP="$(printf '%s' "$POD_JSON" | jq -r '.spec.nodeName // "-"')" && PHASE_TMP="$(printf '%s' "$POD_JSON" | jq -r '.status.phase // "-"')" && OWNER_KIND_TMP="$(printf '%s' "$POD_JSON" | jq -r '([.metadata.ownerReferences[]? | select(.controller==true)][0].kind // "none")')" && OWNER_NAME_TMP="$(printf '%s' "$POD_JSON" | jq -r '([.metadata.ownerReferences[]? | select(.controller==true)][0].name // "-")')" && OWNER_UID_TMP="$(printf '%s' "$POD_JSON" | jq -r '([.metadata.ownerReferences[]? | select(.controller==true)][0].uid // "-")')" && POD_CREATED_TMP="$(printf '%s' "$POD_JSON" | jq -r '.metadata.creationTimestamp // "-"')" && DELETION_TMP="$(printf '%s' "$POD_JSON" | jq -r '.metadata.deletionTimestamp // "-"')" && GRACE_TMP="$(printf '%s' "$POD_JSON" | jq -r '.spec.terminationGracePeriodSeconds // "-"')" && FINALIZERS_TMP="$(printf '%s' "$POD_JSON" | jq -r '(.metadata.finalizers // []) | join(",")')" && CONTAINER_BLOCK_TMP="$(printf '%s' "$POD_JSON" | jq -r '.status.containerStatuses[]? | ["컨테이너: " + .name, "ready=" + ((.ready // "-") | tostring), "id=" + (.containerID // "-"), "current=" + (((.state // {}) | keys | join(","))), "last=" + (((.lastState // {}) | keys | join(","))), "restart=" + ((.restartCount // "-") | tostring)] | join(" ")')" && END_RFC3339_TMP="$(date -u '+%Y-%m-%dT%H:%M:%SZ')"; then POD_UID="$POD_UID_TMP"; NODE="$NODE_TMP"; PHASE="$PHASE_TMP"; OWNER_KIND="$OWNER_KIND_TMP"; OWNER_NAME="$OWNER_NAME_TMP"; OWNER_UID="$OWNER_UID_TMP"; POD_CREATED="$POD_CREATED_TMP"; DELETION="$DELETION_TMP"; GRACE="$GRACE_TMP"; FINALIZERS="$FINALIZERS_TMP"; END_RFC3339="$END_RFC3339_TMP"; printf '=== Pod: %s ===\nUID: %s\nNode: %s\nPhase: %s\nOwner: %s/%s UID=%s\nPod 생성 시각: %s\nDeletion timestamp: %s\nGrace period: %s\nFinalizers: %s\n%s\n관측 종료 시각(UTC): %s\n' "$POD" "$POD_UID" "$NODE" "$PHASE" "$OWNER_KIND" "$OWNER_NAME" "$OWNER_UID" "$POD_CREATED" "$DELETION" "$GRACE" "${FINALIZERS:--}" "$CONTAINER_BLOCK_TMP" "$END_RFC3339"; AUTO_READY=true; export POD_UID NODE PHASE OWNER_KIND OWNER_NAME OWNER_UID POD_CREATED DELETION GRACE FINALIZERS END_RFC3339; else printf '%s\n' '중단: Pod API 또는 필수 field 수집 실패. 부분 등록값을 사용하지 않는다.' >&2; unset POD_UID NODE PHASE OWNER_KIND OWNER_NAME OWNER_UID POD_CREATED DELETION GRACE FINALIZERS END_RFC3339; fi`

`AUTO_READY=true`이고 UID·deletion timestamp·owner·container ID·관측 시각이 보여야 다음 단계로 간다. `DELETION`이 비어 있거나 `-`이면 Terminating 증상을 현재 API가 확인하지 못한 것이므로 삭제 명령으로 내려가지 않는다. `FINALIZERS` 빈 값은 정리 완료가 아니라 다른 branch 후보일 수 있다.

### 4. 운영자 선택값과 시간 gate

자동 출력에서 종료 원인과 관련된 `CONTAINER`를 한 번 선택한다. `START_RFC3339`는 deletion 시각과 첫 관련 Event보다 조금 앞선 UTC 시각으로 정하고, journal 범위도 같은 사건을 포함한다. `NODE_HOST`는 API node 이름이 실제 SSH 접속 대상이라는 승인 기록이 있을 때만 채운다. 이 값들은 해당 branch가 아니면 사용하지 않는다.

`CONTAINER='PASTE_CONTAINER_HERE'; START_RFC3339='PASTE_START_RFC3339_HERE'; START_JOURNAL='PASTE_START_JOURNAL_HERE'; END_JOURNAL='PASTE_END_JOURNAL_HERE'; NODE_HOST='PASTE_NODE_HOST_HERE'; NODE_MOUNT_PATH='PASTE_NODE_MOUNT_PATH_HERE'`
`SELECTION_READY=false; unset POD_CHECK_JSON CURRENT_POD_UID CONTAINER_ID CONTAINER_ID_TMP; if [ "$AUTO_READY" != true ]; then printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; elif POD_CHECK_JSON="$(kubectl get pod "$POD" -n "$NS" -o json)" && CURRENT_POD_UID="$(printf '%s' "$POD_CHECK_JSON" | jq -er '.metadata.uid')" && [ "$CURRENT_POD_UID" = "$POD_UID" ] && printf '%s' "$POD_CHECK_JSON" | jq -e --arg container "$CONTAINER" 'any(.spec.containers[]?; .name==$container)' >/dev/null && CONTAINER_ID_TMP="$(printf '%s' "$POD_CHECK_JSON" | jq -r --arg container "$CONTAINER" '.status.containerStatuses[]? | select(.name==$container) | .containerID // "-"' )"; then CONTAINER_ID="$CONTAINER_ID_TMP"; SELECTION_READY=true; export CONTAINER CONTAINER_ID; printf 'SELECTION_READY=true pod=%s uid=%s container=%s id=%s\n' "$POD" "$POD_UID" "$CONTAINER" "$CONTAINER_ID"; else printf '중단: 현재 UID가 바뀌었거나 container 후보가 아님 container=%s\n' "$CONTAINER" >&2; fi`

`TIME_READY=false; if [ "$SELECTION_READY" != true ]; then printf '%s\n' '중단: SELECTION_READY가 아니다.' >&2; elif [[ "$START_RFC3339" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] && [ -n "$START_JOURNAL" ] && [ -n "$END_JOURNAL" ]; then TIME_READY=true; export START_RFC3339 START_JOURNAL END_JOURNAL NODE_HOST; printf 'TIME_READY=true start=%s journal=%s..%s node=%s\n' "$START_RFC3339" "$START_JOURNAL" "$END_JOURNAL" "$NODE_HOST"; else printf '%s\n' '중단: 시간 범위가 비어 있거나 START_RFC3339 형식이 맞지 않는다.' >&2; fi`

`NODE_HOST_READY=false; NODE_IDENTITY_READY=false; unset NODE_GATE_JSON NODE_GATE_UID NODE_GATE_NODE NODE_API_JSON NODE_MACHINE_ID NODE_HOSTNAME REMOTE_IDENTITY_OUT REMOTE_MACHINE_ID REMOTE_HOSTNAME REMOTE_FQDN; if [ "$AUTO_READY" != true ] || [ -z "$NODE" ] || [ "$NODE" = "-" ] || [ -z "$NODE_HOST" ] || [[ "$NODE_HOST" == *NODE_HOST_HERE ]]; then printf '%s\n' '중단: API NODE와 NODE_HOST 입력 gate가 아니다.' >&2; elif NODE_API_JSON="$(kubectl get node "$NODE" -o json)" && NODE_MACHINE_ID="$(printf '%s' "$NODE_API_JSON" | jq -er '.status.nodeInfo.machineID // empty')" && NODE_HOSTNAME="$(printf '%s' "$NODE_API_JSON" | jq -er '[.status.addresses[]? | select(.type == "Hostname") | .address][0] // empty')" && NODE_GATE_JSON="$(kubectl get pod "$POD" -n "$NS" -o json)" && NODE_GATE_UID="$(printf '%s' "$NODE_GATE_JSON" | jq -er '.metadata.uid')" && NODE_GATE_NODE="$(printf '%s' "$NODE_GATE_JSON" | jq -er '.spec.nodeName')" && REMOTE_IDENTITY_OUT="$(ssh -- "$NODE_HOST" 'printf "%s\t%s\t%s\n" "$(cat /etc/machine-id)" "$(hostname --short)" "$(hostname --fqdn 2>/dev/null || true)"')" && [ "$NODE_GATE_UID" = "$POD_UID" ] && [ "$NODE_GATE_NODE" = "$NODE" ]; then IFS=$'\t' read -r REMOTE_MACHINE_ID REMOTE_HOSTNAME REMOTE_FQDN <<<"$REMOTE_IDENTITY_OUT"; if [ -n "$NODE_MACHINE_ID" ] && [ -n "$NODE_HOSTNAME" ] && [ "$REMOTE_MACHINE_ID" = "$NODE_MACHINE_ID" ] && { [ "$REMOTE_HOSTNAME" = "$NODE_HOSTNAME" ] || [ "$REMOTE_FQDN" = "$NODE_HOSTNAME" ]; }; then NODE_HOST_READY=true; NODE_IDENTITY_READY=true; START_JOURNAL_Q="$(printf '%q' "$START_JOURNAL")"; END_JOURNAL_Q="$(printf '%q' "$END_JOURNAL")"; export NODE_HOST NODE_HOST_READY NODE_IDENTITY_READY START_JOURNAL_Q END_JOURNAL_Q; printf 'NODE_HOST_READY=true NODE_IDENTITY_READY=true pod=%s uid=%s api_node=%s machine_id=%s api_hostname=%s remote_hostname=%s node_host=%s\n' "$POD" "$NODE_GATE_UID" "$NODE_GATE_NODE" "$NODE_MACHINE_ID" "$NODE_HOSTNAME" "$REMOTE_HOSTNAME" "$NODE_HOST"; else printf '중단: Node API machineID/hostname과 remote machine-id/hostname 불일치 node=%s machine_id_match=%s hostname_match=%s node_host=%s\n' "$NODE" "$([ "$REMOTE_MACHINE_ID" = "$NODE_MACHINE_ID" ] && printf true || printf false)" "$([ "$REMOTE_HOSTNAME" = "$NODE_HOSTNAME" ] || [ "$REMOTE_FQDN" = "$NODE_HOSTNAME" ] && printf true || printf false)" "$NODE_HOST" >&2; fi; else printf '중단: Node API·remote identity 조회 실패 또는 현재 Pod UID/node 변경 expected_node=%s api_node=%s node_host=%s\n' "$NODE" "${NODE_GATE_NODE:--}" "$NODE_HOST" >&2; fi`

`NODE_MOUNT_PATH_READY=false; if [ -n "$NODE_MOUNT_PATH" ] && [[ "$NODE_MOUNT_PATH" != *NODE_MOUNT_PATH_HERE ]] && [[ "$NODE_MOUNT_PATH" = /* ]] && [[ "$NODE_MOUNT_PATH" != *$'\n'* ]]; then NODE_MOUNT_PATH_READY=true; printf 'NODE_MOUNT_PATH_READY=true path=%s; node path is independently selected and validated\n' "$NODE_MOUNT_PATH"; else printf '%s\n' '중단: NODE_MOUNT_PATH는 Pod volumeMount.mountPath와 분리한 절대 node path로 입력·검증해야 한다.' >&2; fi`

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | `kubectl get pod`의 `STATUS=Terminating`이 grace period 이후에도 유지되거나 deletion 요청 뒤 객체가 사라지지 않는 경우 |
| 적용 | `metadata.deletionTimestamp`가 설정된 namespaced Pod의 종료가 finalizer·preStop·volume·node 경로 중 어디에서 멈췄는지 확인하는 경우 |
| 제외 | phase가 Pending·Running·Succeeded·Failed·Unknown인 일반 증상은 해당 Pod 런북으로, Ready 실패는 [[16. Pod가 Running이지만 Ready가 아닌 경우]], restart 증가는 [[17. Pod restartCount가 계속 증가하는 경우]], Unknown은 [[14. Pod STATUS가 Unknown·ContainerStatusUnknown인 경우]]로 이동한다. Killing 반복은 [[22. Pod 이벤트에 Killing이 반복되는 경우]]로 이관한다. |

검색 문자열: `Terminating`, `deletionTimestamp`, `deletionGracePeriodSeconds`, `finalizers`, `preStop`, `FailedPreStopHook`, `FailedUnmount`, `FailedDetachVolume`, `node unreachable`, `kubelet`, `Lease`, `force delete`.

`Running`, `Ready`, `Bound` 또는 `containerPort` 선언은 종료 완료·listener·volume detach를 보장하지 않는다. finalizer 문자열만 보고 제거하거나 deletion timestamp의 경과 시간만으로 force delete를 승인하지 않는다.

## 최초 확인

`FIRST_CHECK_READY=false; if [ "$SELECTION_READY" != true ] || [ "$AUTO_READY" != true ]; then printf '%s\n' '중단: 자동 수집·container 선택 gate를 통과하지 못했다.' >&2; elif kubectl describe pod "$POD" -n "$NS" && kubectl get events -n "$NS" --field-selector "involvedObject.kind=Pod,involvedObject.name=$POD,involvedObject.uid=$POD_UID" --sort-by=.metadata.creationTimestamp -o custom-columns='EVENT-UID:.metadata.uid,INVOLVED-UID:.involvedObject.uid,CREATED:.metadata.creationTimestamp,FIRST:.firstTimestamp,LAST:.lastTimestamp,EVENT-TIME:.eventTime,SERIES-LAST:.series.lastObservedTime,TYPE:.type,REASON:.reason,COUNT:.count,MESSAGE:.message'; then FIRST_CHECK_READY=true; printf 'FIRST_CHECK_READY=true pod=%s uid=%s\n' "$POD" "$POD_UID"; else printf '%s\n' '중단: describe·Event API 조회 중 하나가 실패했다.' >&2; fi`

`FIRST_CHECK_READY=true`이면 자동 수집의 `DELETION`, `GRACE`, `FINALIZERS`, `PHASE`, `NODE`, owner를 `describe`의 container `State`, `Last State`, `Reason`, `Exit Code`, `Restart Count`, Conditions, 첫 `Killing`·`FailedPreStopHook`·`FailedUnmount`·`FailedDetachVolume` message와 대조한다. Event는 이 절에서 한 번만 UID로 제한한다. Event가 비어도 정상·detach 완료·finalizer 완료로 해석하지 않는다. Event 시각은 실제로 채워진 `eventTime`, `series.lastObservedTime`, `lastTimestamp`, `firstTimestamp` 순으로 container·deletion 시각과 대조한다.

|---|---|---|---|

| `FailedUnmount`·`FailedDetachVolume` 또는 PVC | Pod volume→PVC/PV→VolumeAttachment | CSI → kubelet → Linux mount | [[#3. volume unmount와 CSI·kubelet·Linux|3]] |

공통 로그 helper는 모든 진단 분기보다 먼저 등록한다. 등록 gate가 통과하지 않으면 helper 호출도 중단한다.

`FILTER_READY=false; scoped_filter() { if [ "$FILTER_READY" != true ]; then printf '%s\n' '중단: FILTER_READY가 아니다.' >&2; return 1; fi; FILTER_LABEL="$1"; FILTER_PATTERN="$2"; shift 2; "$@" 2>&1 | grep -E -i -C 3 "$FILTER_PATTERN"; FILTER_PIPE_STATUS=("${PIPESTATUS[@]}"); if [ "${FILTER_PIPE_STATUS[0]}" -ne 0 ]; then printf '로그 producer 실패 label=%s rc=%s\n' "$FILTER_LABEL" "${FILTER_PIPE_STATUS[0]}" >&2; return 1; elif [ "${FILTER_PIPE_STATUS[1]}" -eq 0 ]; then :; elif [ "${FILTER_PIPE_STATUS[1]}" -eq 1 ]; then printf '필터 결과 없음 label=%s; 오류 부재로 해석하지 않는다.\n' "$FILTER_LABEL"; else printf '필터 실행 실패 label=%s rc=%s\n' "$FILTER_LABEL" "${FILTER_PIPE_STATUS[1]}" >&2; return 1; fi; }; if [ "$(type -t scoped_filter 2>/dev/null)" = function ]; then FILTER_READY=true; printf 'FILTER_READY=true\n'; else printf '%s\n' '중단: scoped_filter helper 등록 실패' >&2; fi`

### 1. finalizer와 controller owner

진입 증거는 `FINALIZERS`가 비어 있지 않은 경우다. 실행 경로는 작업 host → API server → finalizer owner/controller → 외부 API·정리 대상이다. finalizer 문자열만으로 owner를 확정하거나 제거하지 않는다.

`CONTROLLER_NAMESPACE='PASTE_CONTROLLER_NAMESPACE_HERE'; CONTROLLER_LABEL='PASTE_CONTROLLER_LABEL_HERE'; CONTROLLER_POD='PASTE_CONTROLLER_POD_HERE'; CONTROLLER_CONTAINER='PASTE_CONTROLLER_CONTAINER_HERE'; FINALIZER_READY=false; if [ "$FIRST_CHECK_READY" != true ] || [ -z "$FINALIZERS" ]; then printf '%s\n' '중단: FINALIZERS 또는 최초 확인 gate가 없다.' >&2; elif OWNER_CHECK_JSON="$(kubectl get "$OWNER_KIND" "$OWNER_NAME" -n "$NS" -o json)" && OWNER_CHECK_UID="$(printf '%s' "$OWNER_CHECK_JSON" | jq -er '.metadata.uid')" && [ "$OWNER_CHECK_UID" = "$OWNER_UID" ] && kubectl get pod "$POD" -n "$NS" -o jsonpath='{.metadata.finalizers}{"\n"}{range .metadata.ownerReferences[*]}{.kind}/{.name}{" controller="}{.controller}{" uid="}{.uid}{"\n"}{end}' && kubectl get "$OWNER_KIND" "$OWNER_NAME" -n "$NS" -o custom-columns='NAME:.metadata.name,UID:.metadata.uid,DELETION:.metadata.deletionTimestamp,GENERATION:.metadata.generation,OBSERVED:.status.observedGeneration,REPLICAS:.status.replicas,READY:.status.readyReplicas,AVAILABLE:.status.availableReplicas' && kubectl get pods -n "$CONTROLLER_NAMESPACE" -l "$CONTROLLER_LABEL" -o wide; then FINALIZER_READY=true; printf 'FINALIZER_READY=true pod=%s uid=%s owner=%s/%s owner_uid=%s controller=%s/%s\n' "$POD" "$POD_UID" "$OWNER_KIND" "$OWNER_NAME" "$OWNER_CHECK_UID" "$CONTROLLER_NAMESPACE" "$CONTROLLER_POD"; else printf '중단: finalizer·owner kind/name/UID·controller 후보 조회 실패 expected_owner_uid=%s current_owner_uid=%s\n' "$OWNER_UID" "${OWNER_CHECK_UID:--}" >&2; fi`

`CONTROLLER_READY=false; unset CONTROLLER_CHECK_JSON CONTROLLER_POD_UID CONTROLLER_OWNER_KIND CONTROLLER_OWNER_NAME CONTROLLER_OWNER_UID CONTROLLER_OWNER_JSON CONTROLLER_OWNER_CURRENT_UID; if [ "$FINALIZER_READY" != true ]; then printf '%s\n' '중단: FINALIZER_READY가 아니다.' >&2; elif CONTROLLER_CHECK_JSON="$(kubectl get pod "$CONTROLLER_POD" -n "$CONTROLLER_NAMESPACE" -l "$CONTROLLER_LABEL" -o json)" && CONTROLLER_POD_UID="$(printf '%s' "$CONTROLLER_CHECK_JSON" | jq -er '.metadata.uid')" && CONTROLLER_OWNER_KIND="$(printf '%s' "$CONTROLLER_CHECK_JSON" | jq -er '([.metadata.ownerReferences[]? | select(.controller==true)][0].kind // empty)')" && CONTROLLER_OWNER_NAME="$(printf '%s' "$CONTROLLER_CHECK_JSON" | jq -er '([.metadata.ownerReferences[]? | select(.controller==true)][0].name // empty)')" && CONTROLLER_OWNER_UID="$(printf '%s' "$CONTROLLER_CHECK_JSON" | jq -er '([.metadata.ownerReferences[]? | select(.controller==true)][0].uid // empty)')" && CONTROLLER_OWNER_JSON="$(kubectl get "$CONTROLLER_OWNER_KIND" "$CONTROLLER_OWNER_NAME" -n "$CONTROLLER_NAMESPACE" -o json)" && CONTROLLER_OWNER_CURRENT_UID="$(printf '%s' "$CONTROLLER_OWNER_JSON" | jq -er '.metadata.uid')" && [ "$CONTROLLER_OWNER_CURRENT_UID" = "$CONTROLLER_OWNER_UID" ] && printf '%s' "$CONTROLLER_CHECK_JSON" | jq -e --arg container "$CONTROLLER_CONTAINER" 'any(.spec.containers[]?; .name==$container)' >/dev/null; then CONTROLLER_READY=true; printf 'CONTROLLER_READY=true namespace=%s pod=%s uid=%s owner=%s/%s owner_uid=%s container=%s\n' "$CONTROLLER_NAMESPACE" "$CONTROLLER_POD" "$CONTROLLER_POD_UID" "$CONTROLLER_OWNER_KIND" "$CONTROLLER_OWNER_NAME" "$CONTROLLER_OWNER_UID" "$CONTROLLER_CONTAINER"; else printf '중단: controller Pod owner kind/name/UID chain·container·Pod UID 검증 실패 expected_owner_uid=%s current_owner_uid=%s\n' "${CONTROLLER_OWNER_UID:--}" "${CONTROLLER_OWNER_CURRENT_UID:--}" >&2; fi`

`FINALIZER_READY=true`는 finalizer 문자열과 선택한 controller 후보가 조회된 범위만 보장한다. owner가 없거나 controller Pod 후보가 여러 개인 경우 임의로 첫 번째를 사용하지 않는다. `CONTROLLER_READY=true`이고 `TIME_READY=true`일 때만 controller 로그를 읽고, producer rc와 filter 무일치를 구분한다: `if [ "$CONTROLLER_READY" != true ] || [ "$TIME_READY" != true ]; then printf '%s\n' '중단: CONTROLLER_READY 또는 TIME_READY가 아니다.' >&2; else scoped_filter "controller/$CONTROLLER_POD" 'finalizer|timeout|conflict|permission denied|forbidden|error|failed' kubectl logs "$CONTROLLER_POD" -n "$CONTROLLER_NAMESPACE" -c "$CONTROLLER_CONTAINER" --timestamps --since-time="$START_RFC3339" --tail=200; fi` 예상 `finalizer cleanup timeout`은 controller·외부 API, `forbidden`은 RBAC·owner 권한 경로다. 필터가 비면 producer가 성공한 경우에만 `kubectl logs "$CONTROLLER_POD" -n "$CONTROLLER_NAMESPACE" -c "$CONTROLLER_CONTAINER" --timestamps --since-time="$START_RFC3339" --tail=50`으로 재확인한다. finalizer 제거·patch는 owner 승인 없이는 실행하지 않는다.

로그 gate 직전에 선택한 controller Pod의 현재 UID와 label·container를 다시 확인한다. controller 후보가 0개·여러 개이거나 UID가 바뀌거나 container가 없으면 로그를 실행하지 않는다.

`CONTROLLER_READY=true`일 때만 controller 로그를 실행한다. 로그 stream 준비 성공은 cleanup 완료를 보장하지 않는다. controller가 대상을 찾지 못하거나 외부 API timeout이면 해당 controller·외부 리소스 담당으로 이관하고 Pod UID·finalizer·controller UID·UTC 시각을 보존한다.

### 2. preStop와 grace

진입 증거는 finalizer가 없고 grace period가 지났는데 container가 `Running`이거나 `FailedPreStopHook`이 보이는 경우다. 실행 경로는 작업 host → API server → kubelet → runtime → container process → application dependency다. API object·Running·로그 stream 성공은 process 종료나 flush 완료를 보장하지 않는다.

`PRESTOP_READY=false; if [ "$FIRST_CHECK_READY" != true ] || [ -n "$FINALIZERS" ]; then printf '%s\n' '중단: finalizer가 없고 최초 확인이 통과한 경로가 아니다.' >&2; elif kubectl get pod "$POD" -n "$NS" -o jsonpath='{range .status.containerStatuses[*]}{.name}{" container-id="}{.containerID}{" state="}{.state}{" last-state="}{.lastState}{" restarts="}{.restartCount}{"\n"}{end}' && kubectl get pod "$POD" -n "$NS" -o jsonpath='{.spec.terminationGracePeriodSeconds}{"\n"}'; then PRESTOP_READY=true; printf 'PRESTOP_READY=true pod=%s uid=%s container=%s\n' "$POD" "$POD_UID" "$CONTAINER"; else printf '%s\n' '중단: preStop·container 상태 조회 실패' >&2; fi`

`PRESTOP_PREVIOUS_READY=false; PRESTOP_RESTART_COUNT=0; PRESTOP_LAST_TERMINATED=false; unset PRESTOP_CHECK_JSON PRESTOP_CHECK_UID; if [ "$PRESTOP_READY" = true ] && [ "$TIME_READY" = true ] && PRESTOP_CHECK_JSON="$(kubectl get pod "$POD" -n "$NS" -o json)" && PRESTOP_CHECK_UID="$(printf '%s' "$PRESTOP_CHECK_JSON" | jq -er '.metadata.uid')" && [ "$PRESTOP_CHECK_UID" = "$POD_UID" ] && PRESTOP_RESTART_COUNT="$(printf '%s' "$PRESTOP_CHECK_JSON" | jq -er --arg container "$CONTAINER" '([.status.containerStatuses[]? | select(.name==$container)][0].restartCount // 0)')" && [ "$PRESTOP_RESTART_COUNT" -gt 0 ] && printf '%s' "$PRESTOP_CHECK_JSON" | jq -e --arg container "$CONTAINER" 'any(.status.containerStatuses[]?; .name==$container and ((.lastState.terminated // null) != null))' >/dev/null; then PRESTOP_LAST_TERMINATED=true; PRESTOP_PREVIOUS_READY=true; printf 'PRESTOP_PREVIOUS_READY=true pod=%s uid=%s container=%s restartCount=%s lastState=terminated\n' "$POD" "$PRESTOP_CHECK_UID" "$CONTAINER" "$PRESTOP_RESTART_COUNT"; else printf 'PRESTOP_PREVIOUS_READY=false; previous 로그 조건은 restartCount>0 및 lastState.terminated가 모두 필요하다.\n'; fi`

preStop `command`·`args`에는 Secret·token·개인정보가 포함될 수 있으므로 값은 저장하지 않고 hook 형태와 exit/timeout만 기록한다. `PRESTOP_READY=true`이고 `TIME_READY=true`일 때 producer rc와 filter 무일치를 구분해 `if [ "$PRESTOP_READY" != true ] || [ "$TIME_READY" != true ]; then printf '%s\n' '중단: PRESTOP_READY 또는 TIME_READY가 아니다.' >&2; else scoped_filter "prestop/$POD" 'shutdown|drain|flush|dependency|timeout|ack|signal|error|failed' kubectl logs "$POD" -n "$NS" -c "$CONTAINER" --timestamps --since-time="$START_RFC3339" --tail=200; fi`를 실행한다. producer가 성공하고 필터가 비면 `kubectl logs "$POD" -n "$NS" -c "$CONTAINER" --timestamps --since-time="$START_RFC3339" --tail=50`만 확인한다. `shutdown requested; waiting for DB drain`은 application dependency, `FailedPreStopHook`은 hook exit/timeout으로 이관한다.

`PRESTOP_PREVIOUS_READY=true`이고 current container `restartCount>0` 및 `.lastState.terminated`가 같은 fresh UID snapshot에서 모두 확인된 경우에만 `if [ "$PRESTOP_PREVIOUS_READY" = true ] && [ "$TIME_READY" = true ]; then scoped_filter "prestop-previous/$POD" 'shutdown|drain|flush|dependency|timeout|ack|signal|error|failed' kubectl logs "$POD" -n "$NS" -c "$CONTAINER" --previous --timestamps --since-time="$START_RFC3339" --tail=200; else printf '%s\n' '중단: restartCount>0·lastState.terminated·TIME_READY 조건을 모두 충족하지 않는다.'; fi`를 실행한다. 이전 로그가 없거나 producer가 실패하거나 필터가 비면 로그 보존·GC를 확인하고 [[28. Pod의 이전 컨테이너 로그를 가져올 수 없는 경우]]로 이관한다. 종료 hook을 우회하거나 grace를 줄여 flush를 생략하지 않는다.

### 3. volume unmount와 CSI·kubelet·Linux

진입 증거는 Pod에 PVC가 있고 UID로 제한한 Event에서 `FailedUnmount`·`FailedDetachVolume`가 mapped volume과 일치하거나 mapped PV/VolumeAttachment node에서 잔류 mount가 확인된 경우다. 실행 경로는 작업 host → API server → PVC/PV/VolumeAttachment → CSI controller/node plugin → kubelet volume manager → Linux mount/device다. PVC `Bound`나 VolumeAttachment `attached=true`는 filesystem unmount와 process 종료를 보장하지 않는다.

`PVC='PASTE_PVC_HERE'; VOLUME_READY=false; unset PV PV_UID VOLUME_ATTACHMENT VOLUME_ID VOLUME_DRIVER; if [ "$FIRST_CHECK_READY" != true ]; then printf '%s\n' '중단: FIRST_CHECK_READY가 아니다.' >&2; elif POD_VOLUME_JSON="$(kubectl get pod "$POD" -n "$NS" -o json)" && printf '%s' "$POD_VOLUME_JSON" | jq -e --arg pvc "$PVC" 'any(.spec.volumes[]?; .persistentVolumeClaim.claimName==$pvc)' >/dev/null && PVC_JSON="$(kubectl get pvc "$PVC" -n "$NS" -o json)" && PV_TMP="$(printf '%s' "$PVC_JSON" | jq -er '.spec.volumeName')" && PV_JSON="$(kubectl get pv "$PV_TMP" -o json)" && PV_UID_TMP="$(printf '%s' "$PV_JSON" | jq -er '.metadata.uid')" && VOLUME_ID_TMP="$(printf '%s' "$PV_JSON" | jq -r '.spec.csi.volumeHandle // "-"')" && VOLUME_DRIVER_TMP="$(printf '%s' "$PV_JSON" | jq -r '.spec.csi.driver // "-"')" && VA_JSON="$(kubectl get volumeattachment -o json)" && VA_COUNT_TMP="$(printf '%s' "$VA_JSON" | jq -r --arg pv "$PV_TMP" '[.items[] | select(.spec.source.persistentVolumeName==$pv)] | length')" && [ "$VA_COUNT_TMP" -eq 1 ] && VOLUME_ATTACHMENT_TMP="$(printf '%s' "$VA_JSON" | jq -er --arg pv "$PV_TMP" '.items[] | select(.spec.source.persistentVolumeName==$pv) | .metadata.name')"; then PV="$PV_TMP"; PV_UID="$PV_UID_TMP"; VOLUME_ID="$VOLUME_ID_TMP"; VOLUME_DRIVER="$VOLUME_DRIVER_TMP"; VOLUME_ATTACHMENT="$VOLUME_ATTACHMENT_TMP"; printf '=== Volume mapping ===\nPod: %s UID=%s Node=%s\nPVC: %s\nPV: %s UID=%s\nCSI driver: %s\nVolumeAttachment: %s\nVolume ID: %s\n' "$POD" "$POD_UID" "$NODE" "$PVC" "$PV" "$PV_UID" "$VOLUME_DRIVER" "$VOLUME_ATTACHMENT" "$VOLUME_ID"; VOLUME_READY=true; export PVC PV PV_UID VOLUME_ATTACHMENT VOLUME_ID VOLUME_DRIVER; else printf '중단: Pod→PVC→PV→VolumeAttachment가 없거나 후보 수가 1이 아니며 CSI driver를 확정할 수 없음 pvc=%s\n' "$PVC" >&2; unset PV PV_UID VOLUME_ATTACHMENT VOLUME_ID VOLUME_DRIVER; fi`

`VOLUME_READY=true`이고 `claimName`, PVC `volumeName`, PV UID/claimRef/nodeAffinity, VolumeAttachment의 PV·node·attacher·attached·detachError가 같은 관계로 출력돼야 다음 단계로 간다. PV가 CSI가 아니면 `VOLUME_ID=-`일 수 있으며 CSI 명령을 추측하지 않는다. VolumeAttachment가 0개 또는 여러 개이면 정상 detach·오류 없음으로 해석하지 않고 storage owner에게 mapping을 이관한다.

`VOLUME_RELATION_READY=false; unset VA_REL_JSON VA_REL_PV VA_REL_NODE VA_REL_ATTACHER VA_REL_ATTACHED VA_REL_DETACH_ERROR; if [ "$VOLUME_READY" != true ] || [ "$VOLUME_DRIVER" = "-" ]; then printf '%s\n' '중단: VOLUME_READY 또는 CSI driver가 아니다.' >&2; elif VA_REL_JSON="$(kubectl get volumeattachment "$VOLUME_ATTACHMENT" -o json)" && VA_REL_PV="$(jq -er '.spec.source.persistentVolumeName' <<<"$VA_REL_JSON")" && VA_REL_NODE="$(jq -er '.spec.nodeName' <<<"$VA_REL_JSON")" && VA_REL_ATTACHER="$(jq -er '.spec.attacher' <<<"$VA_REL_JSON")" && VA_REL_ATTACHED="$(jq -r '.status.attached // false' <<<"$VA_REL_JSON")" && VA_REL_DETACH_ERROR="$(jq -r '.status.detachError.message // "-"' <<<"$VA_REL_JSON")" && [ "$VA_REL_PV" = "$PV" ] && [ "$VA_REL_NODE" = "$NODE" ] && [ "$VA_REL_ATTACHER" = "$VOLUME_DRIVER" ]; then VOLUME_RELATION_READY=true; printf 'VOLUME_RELATION_READY=true pv=%s node=%s attacher=%s attached=%s detachError=%s observed_at=%s\n' "$VA_REL_PV" "$VA_REL_NODE" "$VA_REL_ATTACHER" "$VA_REL_ATTACHED" "$VA_REL_DETACH_ERROR" "$(date -u '+%Y-%m-%dT%H:%M:%SZ')"; else printf '중단: VolumeAttachment PV/node/attacher·CSI driver 관계 또는 attached/detachError 조회가 일치하지 않는다.\n' >&2; fi`

`if [ "$VOLUME_RELATION_READY" != true ]; then VOLUME_READY=false; fi`

`CSI_READY=true`이고 `NODE_HOST_READY=true`이며 node 접근 권한과 `findmnt`·`mountpoint`가 실제로 확인된 경우에만 node의 mapped volume과 mountpoint를 확인한다. `ssh -- "$NODE_HOST" 'sudo -n findmnt -rn -o TARGET,SOURCE,FSTYPE,OPTIONS'`의 producer rc와 filter 무일치를 구분하고, remote `mountpoint`의 rc는 원격 shell에서 저장한다: `NODE_MOUNT_PATH_Q="$(printf '%q' "$NODE_MOUNT_PATH")"; ssh -- "$NODE_HOST" "sudo -n mountpoint -q $NODE_MOUNT_PATH_Q; MOUNTPOINT_RC=\$?; printf 'mountpoint_exit=%s\n' \"\$MOUNTPOINT_RC\""`. `findmnt`가 mapped volume mount를 보여 주거나 기존 Event가 해당 mapping과 일치할 때만 다음을 실행한다.

## 제한된 상태 변경 경계

> [!danger] 강제 삭제는 일반 복구가 아니다
> `--force --grace-period=0`은 API object를 지우는 최후 수단이다. process 종료, preStop 완료, volume unmount/detach, 외부 작업 취소와 데이터 무결성을 보장하지 않는다. finalizer·preStop·volume·node pipeline의 evidence 없이 실행하지 않는다.

Trigger는 grace 초과와 deletion 잔류가 scheduling/controller를 직접 막고, finalizer·preStop·volume·node 경로의 관측 결과가 기록된 경우다. Authority는 올바른 context를 다시 확인한 cluster 운영자와 workload·storage·node 담당자의 승인이다. StatefulSet ordinal·leader·quorum, PDB, Job 외부 side effect, RWO volume과 이전 process 위험을 평가한다. API deletion은 rollback할 수 없으므로 실행 전 증거와 중단 조건을 닫고, 실행 후 owner의 replacement·process·mount·volume·실제 기능 검증을 수행한다. node unreachable, volume attach 불명확, 중복 실행 배제 실패, 새 Warning·데이터 오류가 있으면 중단한다.

이 런북은 서버 측 UID precondition을 전달하는 승인된 API 절차가 없으므로 `delete`·`--force` 명령을 제공하지 않는다. 상태 변경은 현재 UID·controller owner·deletion 상태와 승인 증거를 owner 절차로 이관하고, owner가 Kubernetes API `DeleteOptions.preconditions.uid=$POD_UID`를 원자적으로 전달하는 별도 절차에서 수행한다.

### controller-managed Pod replacement 검증

승인된 owner selector가 있고 controller-managed Pod인 경우에만 replacement 후보를 조회한다. selector는 owner 선언에서 확인한 값을 그대로 사용하며 이름·label을 추측하지 않는다. 후보가 0개 또는 여러 개면 임의로 첫 번째를 선택하지 않고 정상화를 선언하지 않는다.

`REPLACEMENT_READY=false; unset REPLACEMENTS_JSON REPLACEMENT_COUNT REPLACEMENT_POD REPLACEMENT_POD_UID REPLACEMENT_CHECK_JSON REPLACEMENT_CHECK_UID REPLACEMENT_OWNER_KIND REPLACEMENT_OWNER_NAME REPLACEMENT_OWNER_UID; if [ "$APPROVAL_READY" != true ] || [ "$OWNER_KIND" = none ]; then printf '%s\n' '중단: replacement gate가 아니다.' >&2; elif REPLACEMENTS_JSON="$(kubectl get pods -n "$NS" -l "$OWNER_SELECTOR" -o json)" && REPLACEMENT_COUNT="$(printf '%s' "$REPLACEMENTS_JSON" | jq -r --arg old "$POD" --arg kind "$OWNER_KIND" --arg owner "$OWNER_NAME" --arg owner_uid "$OWNER_UID" '[.items[] | select(.metadata.name!=$old and any(.metadata.ownerReferences[]?; .controller==true and .kind==$kind and .name==$owner and .uid==$owner_uid))] | length')" && [ "$REPLACEMENT_COUNT" -eq 1 ] && REPLACEMENT_POD="$(printf '%s' "$REPLACEMENTS_JSON" | jq -er --arg old "$POD" --arg kind "$OWNER_KIND" --arg owner "$OWNER_NAME" --arg owner_uid "$OWNER_UID" '.items[] | select(.metadata.name!=$old and any(.metadata.ownerReferences[]?; .controller==true and .kind==$kind and .name==$owner and .uid==$owner_uid)) | .metadata.name')" && REPLACEMENT_POD_UID="$(printf '%s' "$REPLACEMENTS_JSON" | jq -er --arg pod "$REPLACEMENT_POD" '.items[] | select(.metadata.name==$pod) | .metadata.uid')"; then if REPLACEMENT_CHECK_JSON="$(kubectl get pod "$REPLACEMENT_POD" -n "$NS" -o json)" && REPLACEMENT_CHECK_UID="$(printf '%s' "$REPLACEMENT_CHECK_JSON" | jq -er '.metadata.uid')" && REPLACEMENT_OWNER_KIND="$(printf '%s' "$REPLACEMENT_CHECK_JSON" | jq -er '([.metadata.ownerReferences[]? | select(.controller==true)][0].kind // empty)')" && REPLACEMENT_OWNER_NAME="$(printf '%s' "$REPLACEMENT_CHECK_JSON" | jq -er '([.metadata.ownerReferences[]? | select(.controller==true)][0].name // empty)')" && REPLACEMENT_OWNER_UID="$(printf '%s' "$REPLACEMENT_CHECK_JSON" | jq -er '([.metadata.ownerReferences[]? | select(.controller==true)][0].uid // empty)')" && [ "$REPLACEMENT_CHECK_UID" = "$REPLACEMENT_POD_UID" ] && [ "$REPLACEMENT_OWNER_KIND" = "$OWNER_KIND" ] && [ "$REPLACEMENT_OWNER_NAME" = "$OWNER_NAME" ] && [ "$REPLACEMENT_OWNER_UID" = "$OWNER_UID" ]; then printf 'replacement 후보 pod=%s uid=%s owner=%s/%s owner_uid=%s\n' "$REPLACEMENT_POD" "$REPLACEMENT_CHECK_UID" "$REPLACEMENT_OWNER_KIND" "$REPLACEMENT_OWNER_NAME" "$REPLACEMENT_OWNER_UID"; REPLACEMENT_READY=true; else printf '중단: replacement Pod UID 또는 owner kind/name/UID chain 재검증 실패 pod=%s expected_pod_uid=%s current_pod_uid=%s expected_owner=%s/%s/%s current_owner=%s/%s/%s\n' "$REPLACEMENT_POD" "$REPLACEMENT_POD_UID" "${REPLACEMENT_CHECK_UID:--}" "$OWNER_KIND" "$OWNER_NAME" "$OWNER_UID" "${REPLACEMENT_OWNER_KIND:--}" "${REPLACEMENT_OWNER_NAME:--}" "${REPLACEMENT_OWNER_UID:--}" >&2; fi; else printf '중단: replacement 후보 수가 1이 아니거나 owner selector/API 조회 실패 count=%s\n' "${REPLACEMENT_COUNT:--}" >&2; fi`

`REPLACEMENT_READY=true`이어도 생성 시각이 old deletion 이후인지, owner kind/name·UID chain이 기대한 controller인지, 필요한 모든 container가 Ready인지 확인한다. `kubectl get pod "$REPLACEMENT_POD" -n "$NS" -o custom-columns='NAME:.metadata.name,UID:.metadata.uid,OWNER-KIND:.metadata.ownerReferences[*].kind,OWNER-NAME:.metadata.ownerReferences[*].name,OWNER-UID:.metadata.ownerReferences[*].uid,READY:.status.containerStatuses[*].ready,CREATED:.metadata.creationTimestamp'`와 `kubectl get lease "$NODE" -n kube-node-lease -o custom-columns='NAME:.metadata.name,RENEW-TIME:.spec.renewTime,HOLDER:.spec.holderIdentity'`를 실행한다. `READY`는 process listener·실제 요청·old process 종료를 보장하지 않으므로 desired/Ready, 실제 요청·Job 결과, old runtime process·mount·VolumeAttachment를 역순으로 확인한다.

### standalone Pod 종료 검증

owner가 없거나 standalone이면 replacement를 기대하지 않는다. old object 부재만으로 정상화하지 않고 `STANDALONE_READY=true`, node 접근·runtime endpoint·권한과 PVC 관계를 실제로 확인할 때만 종료를 확인한다. no-PVC는 CRI 종료 확인만 수행하고 mount 확인은 명시적으로 건너뛴다. `CRI_ENDPOINT_Q="$(printf '%q' "$CRI_ENDPOINT")"; CONTAINER_ID_Q="$(printf '%q' "$CONTAINER_ID_RAW")"; NODE_MOUNT_PATH_Q="$(printf '%q' "$NODE_MOUNT_PATH")"; if [ "$STANDALONE_READY" = true ] && [ "$NODE" != "-" ] && [ "$NODE_HOST_READY" = true ] && [ "$NODE_IDENTITY_READY" = true ] && [ "$STANDALONE_VOLUME_READY" = true ] && [ "$RUNTIME_READY" = true ]; then ssh -- "$NODE_HOST" "sudo -n command -v crictl >/dev/null 2>&1 && sudo -n crictl --runtime-endpoint=$CRI_ENDPOINT_Q inspect $CONTAINER_ID_Q | jq -c '{id:.status.id,state:.status.state,exitCode:.status.exitCode,reason:.status.reason,finishedAt:.status.finishedAt}'"; if [ "$STANDALONE_MOUNT_REQUIRED" = true ] && [ "$NODE_MOUNT_PATH_READY" = true ]; then scoped_filter "standalone-mount/$POD" "$POD_UID|$VOLUME_ID|$NODE_MOUNT_PATH" ssh -- "$NODE_HOST" "sudo -n findmnt -rn -o TARGET,SOURCE,FSTYPE,OPTIONS"; kubectl get volumeattachment "$VOLUME_ATTACHMENT" -o custom-columns='NAME:.metadata.name,ATTACHED:.status.attached,NODE:.spec.nodeName,ERROR:.status.detachError.message'; else printf '%s\n' 'standalone no-PVC 또는 NODE_MOUNT_PATH 미검증: CRI 종료만 검증하고 mount 확인은 건너뛴다.'; fi; else printf '%s\n' 'standalone 종료 검증 조건이 닫히지 않아 정상화하지 않는다.'; fi`

old container가 runtime에 없거나 실행 중이 아니고 Pod UID·volume mount가 없으며 VolumeAttachment가 없거나 `ATTACHED=false`인 경우에만 standalone 종료를 검토한다. 하나라도 남아 있거나 조회할 수 없으면 정상화하지 않는다. replacement 생성은 요구하지 않는다.

## 정상화와 증거

정상화는 원인 경로를 역순으로 확인한다. application graceful shutdown·실제 기능 → container process/runtime → kubelet termination → CSI unmount/detach·Linux mount → finalizer/controller cleanup → API object 부재와 새 owner UID/Ready 순으로 본다. controller-managed Pod는 old object 부재, 새 owner·UID·created·Ready, old process·mount·VolumeAttachment 종료, desired/Ready와 실제 요청·Job 결과를 모두 확인한다. standalone Pod는 replacement가 아니라 old process·mount·VolumeAttachment 종료와 실제 영향 해소를 확인한다.

새 Warning, 데이터 오류, 이전 process·volume attach, finalizer 잔류, selector 불일치가 있으면 정상화하지 않는다. owner 절차의 API deletion request 성공, `NotFound`, 새 Pod `Running`, PVC `Bound`, `ATTACHED=false` 각각은 단독 정상화 근거가 아니다. 보존할 것은 삭제 전후 UTC 시각, context, Pod/owner/node UID, deletion/grace/finalizer, preStop·container state, UID 제한 Event, PVC/PV/VolumeAttachment, CSI·kubelet·runtime·host evidence, 승인자·실행 명령·전후 UID·서비스 지표다.

`PROMQL_READY=false; unset NS_RE POD_RE UID_RE; if [ "$AUTO_READY" != true ]; then printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; elif NS_RE="$(printf '%s' "$NS" | sed 's/[][\\.^$*+?(){}|]/\\&/g')" && POD_RE="$(printf '%s' "$POD" | sed 's/[][\\.^$*+?(){}|]/\\&/g')" && UID_RE="$(printf '%s' "$POD_UID" | sed 's/[][\\.^$*+?(){}|]/\\&/g')" && [ -n "$NS_RE" ] && [ -n "$POD_RE" ] && [ -n "$UID_RE" ]; then PROMQL_READY=true; printf 'PROMQL_READY=true namespace=%.120s pod=%.120s uid=%.120s\n' "$NS_RE" "$POD_RE" "$UID_RE"; else printf '%s\n' '중단: PromQL selector 생성 실패' >&2; fi`

`PROMQL_READY=true`일 때만 `printf 'time()-kube_pod_deletion_timestamp{namespace=~"%s",pod=~"%s",uid=~"%s"}\n' "$NS_RE" "$POD_RE" "$UID_RE"`과 `printf 'kube_pod_info{namespace=~"%s",pod=~"%s",uid=~"%s"}\n' "$NS_RE" "$POD_RE" "$UID_RE"`를 실행해 완성된 한 줄만 Prometheus 또는 Grafana에 넣는다. `printf 'count by(namespace,pod,uid)(kube_pod_deletion_timestamp{namespace=~"%s",pod=~"%s",uid=~"%s"}) * count by(namespace,pod,uid)(kube_pod_status_reason{namespace=~"%s",pod=~"%s",uid=~"%s",reason="NodeLost"}==0)\n' "$NS_RE" "$POD_RE" "$UID_RE" "$NS_RE" "$POD_RE" "$UID_RE"`도 같은 방식으로 생성한다. Prometheus transport·HTTP status·query API success/data를 분리하고 빈 결과를 정상·0·detach 완료로 해석하지 않는다. metric 부재, label 불일치, scrape lag, 조회 범위, 권한/API 실패를 구분하며 반환 UID와 sample 시각을 API·Event·Lease와 대조한다.
