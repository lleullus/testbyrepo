# 멀티 컨테이너 Pod에서 특정 컨테이너만 실패하는 경우

## 입력값과 빠른 수집

regular app, sidecar, init, ephemeral container는 Pod 안에서도 서로 다른 수명주기와 상태를 가진다. 한 컨테이너의 `ready=false`·restart·exit만으로 Pod 전체, owner, node 또는 runtime 원인을 확정하지 않는다. 실패 컨테이너와 모든 후속 증거는 같은 Pod UID와 UTC 관측 시각에 묶는다.

| 종류 | 값 | 출처와 사용 범위 |
|---|---|---|
| 최초 입력 | `CTX`, `NS`, `POD` | 승인된 context와 namespace·Pod 이름. 같은 Bash에서 한 번만 입력한다. |
| API 확인 자동값 | `POD_UID`, `NODE`, `PHASE`, `OWNER_KIND`, `OWNER_NAME`, `OWNER_UID`, `OBSERVED_AT` | Pod API에서 UID·node·phase·controller owner와 시각을 등록한다. controller owner가 없거나 복수이면 owner 범위 판단을 중단한다. |
| 계산 후보 | `POD_RE`, `PROM_WINDOW` | Pod 이름을 정규식으로 escape한 값과 기본 PromQL 관측 창이다. |
| 운영자 선택값 | `CONTAINER`, `CONTAINER_KIND`, `START_RFC3339`, `SERVICE`, `START_JOURNAL`, `NODE_HOST`, `KUBELET_UNIT`, `RUNTIME_UNIT`, `CRI_SOCKET` | API 출력과 실제 role·시간·승인 remote node·node 구현·실제 systemd unit을 확인한 뒤 해당 분기에서만 선택한다. image command/args·Secret 원문·token·개인키는 저장하지 않는다. |

### 실행 계약과 도구 gate

명령은 승인된 작업 PC 또는 bastion의 **같은 Bash 터미널**에서 실행한다. `kubectl`과 Kubernetes Server는 1.26.x 기준이고 입력한 context를 고정한다. 기본 도구는 `kubectl`, `jq`, `grep`, `sed`, `date`다. node 계층은 추가로 SSH, 원격 `journalctl`, `systemctl`, `sudo`, 확인된 runtime unit과 CRI socket이 필요하다. 도구·권한·구현체 확인이 실패하면 다음 단계로 진행하지 않는다.

`TOOLS_READY=false; if [ -z "${BASH_VERSION:-}" ]; then printf '%s\n' '중단: 같은 Bash에서 실행한다.' >&2; else MISSING_TOOLS=''; for TOOL in kubectl jq grep sed date; do command -v "$TOOL" >/dev/null 2>&1 || MISSING_TOOLS="$MISSING_TOOLS $TOOL"; done; if [ -z "$MISSING_TOOLS" ]; then TOOLS_READY=true; printf 'TOOLS_READY=true shell=%s\n' "$BASH_VERSION"; else printf '중단: 없는 도구=%s\n' "$MISSING_TOOLS" >&2; fi; fi`

### 최초 입력과 이전 상태 초기화

이전 Pod UID·owner·정규식·선택값·gate를 지워 다른 Pod나 다른 container 결과가 섞이지 않게 한다. 아래 세 PASTE 값만 직접 바꾸며 각각 문서 전체에서 한 번만 나타난다.

`INPUT_READY=true`가 아니면 다음 API 호출을 실행하지 않는다. namespace를 모르면 broad query로 첫 번째 Pod를 고르지 말고 승인된 namespace를 확인한 뒤 입력 절을 다시 실행한다.

### API 자동 수집과 등록

자동 출력은 Pod별 block 안에 UID·node·phase·관측 시각, regular/init/ephemeral의 선언과 status 이름, container별 port 후보와 state·ID·restart, controller owner를 묶어 보여 준다. `containerPort`는 선언 후보이며 실제 listener·protocol·application 성공을 보장하지 않는다.

`if [ "$INPUT_READY" != true ]; then printf '%s\n' '중단: INPUT_READY가 아니다.' >&2; elif POD_JSON="$(kubectl --context "$CTX" get pod "$POD" -n "$NS" -o json)"; then jq -r '"=== 대상 Pod ===\n네임스페이스: \(.metadata.namespace)\nPod: \(.metadata.name)\nUID: \(.metadata.uid)\n노드: \(.spec.nodeName // "-")\n단계: \(.status.phase // "-")\nPod 시작: \(.status.startTime // "-")\nOwner:\n" + ([.metadata.ownerReferences[]? | "  \(.kind)/\(.name) UID=\(.uid) controller=\(.controller // false)"] | join("\n")) + "\n\n=== Regular container과 포트 후보 ===\n" + ([.spec.containers[]? as $c | (first(.status.containerStatuses[]? | select(.name==$c.name)) // {}) as $s | "컨테이너: \($c.name)\n  이미지: \($c.image)\n  포트 후보: \([ $c.ports[]? | ((.name // "unnamed") + ":" + (.containerPort|tostring)) ] | join(", ") | if .=="" then "-" else . end)\n  현재 상태: \($s.state // "-")\n  이전 상태: \($s.lastState // "-")\n  ID/준비/재시작: \($s.containerID // "-") / \($s.ready // "-") / \($s.restartCount // "-")"] | join("\n\n")) + "\n\n=== Init container과 상태 ===\n" + ([.spec.initContainers[]? as $c | (first(.status.initContainerStatuses[]? | select(.name==$c.name)) // {}) as $s | "Init 컨테이너: \($c.name)\n  이미지: \($c.image)\n  현재 상태: \($s.state // "-")\n  이전 상태: \($s.lastState // "-")\n  ID/재시작: \($s.containerID // "-") / \($s.restartCount // "-")"] | join("\n\n")) + "\n\n=== Ephemeral container과 상태 ===\n" + ([.spec.ephemeralContainers[]? as $c | (first(.status.ephemeralContainerStatuses[]? | select(.name==$c.name)) // {}) as $s | "Ephemeral 컨테이너: \($c.name)\n  대상 컨테이너: \($c.targetContainerName // "-")\n  이미지: \($c.image)\n  현재 상태: \($s.state // "-")\n  이전 상태: \($s.lastState // "-")\n  ID/재시작: \($s.containerID // "-") / \($s.restartCount // "-")"] | join("\n\n"))' <<<"$POD_JSON"; else printf '%s\n' '중단: Pod API snapshot 조회 실패' >&2; fi`

`reset_pod36_downstream && if [ "$INPUT_READY" != true ]; then printf '%s\n' '중단: INPUT_READY가 아니다.' >&2; elif POD_JSON="$(kubectl --context "$CTX" get pod "$POD" -n "$NS" -o json)" && OBSERVED_AT="$(date -u '+%Y-%m-%dT%H:%M:%SZ')" && POD_UID_TMP="$(jq -r '.metadata.uid // empty' <<<"$POD_JSON")" && NODE_TMP="$(jq -r '.spec.nodeName // empty' <<<"$POD_JSON")" && PHASE_TMP="$(jq -r '.status.phase // empty' <<<"$POD_JSON")" && OWNER_COUNT_TMP="$(jq '[.metadata.ownerReferences[]? | select(.controller==true)] | length' <<<"$POD_JSON")"; then POD_RE_ESCAPED="$(printf '%s' "$POD" | sed 's/[][\\.^$*+?(){}|]/\\&/g')"; if [ -z "$POD_UID_TMP" ] || [ -z "$PHASE_TMP" ] || [ -z "$POD_RE_ESCAPED" ]; then printf '%s\n' '중단: 필수 자동값이 비어 있어 부분 등록을 폐기함' >&2; else POD_UID="$POD_UID_TMP"; NODE="$NODE_TMP"; PHASE="$PHASE_TMP"; POD_RE="^${POD_RE_ESCAPED}$"; PROM_WINDOW='15m'; if [ "$OWNER_COUNT_TMP" -eq 1 ]; then OWNER_KIND="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)][0].kind' <<<"$POD_JSON")"; OWNER_NAME="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)][0].name' <<<"$POD_JSON")"; OWNER_UID="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)][0].uid' <<<"$POD_JSON")"; OWNER_READY=true; else OWNER_KIND=''; OWNER_NAME=''; OWNER_UID=''; OWNER_READY=false; fi; AUTO_READY=true; export POD_UID NODE PHASE OWNER_KIND OWNER_NAME OWNER_UID OWNER_READY OBSERVED_AT POD_RE PROM_WINDOW; printf 'AUTO_READY=true 관측시각=%s UID=%s Node=%s Phase=%s Owner=%s/%s ownerReady=%s POD_RE=%s PROM_WINDOW=%s\n' "$OBSERVED_AT" "$POD_UID" "${NODE:--}" "$PHASE" "${OWNER_KIND:--}" "${OWNER_NAME:--}" "$OWNER_READY" "$POD_RE" "$PROM_WINDOW"; fi; unset POD_UID_TMP NODE_TMP PHASE_TMP OWNER_COUNT_TMP POD_RE_ESCAPED; else printf '%s\n' '중단: API 자동값 수집 실패; 이전 파생값을 사용하지 않음' >&2; fi`

후속 Pod snapshot은 최초 자동값의 `$POD_UID`와 대조한다. `jq` 실패 또는 UID mismatch면 해당 분기의 gate를 닫고 stale container·owner·service 값을 사용하지 않는다.

`pod_uid_matches(){ local pod_json="$1" current_uid; current_uid="$(jq -r '.metadata.uid // empty' <<<"$pod_json")" || { AUTO_READY=false; OWNER_READY=false; OWNER_RESOURCE_READY=false; NORMALIZATION_READY=false; CONTAINER_READY=false; CONTAINER_API_OK=false; unset CONTAINER_CURRENT_ID; SERVICE_READY=false; ENDPOINT_READY=false; EVENT_READY=false; NODE_REMOTE_READY=false; NODE_TOOLS_READY=false; NODE_RUNTIME_PREFLIGHT_READY=false; return 1; }; if [ -n "$current_uid" ] && [ "$current_uid" = "$POD_UID" ]; then return 0; else AUTO_READY=false; OWNER_READY=false; OWNER_RESOURCE_READY=false; NORMALIZATION_READY=false; CONTAINER_READY=false; CONTAINER_API_OK=false; unset CONTAINER_CURRENT_ID; SERVICE_READY=false; ENDPOINT_READY=false; EVENT_READY=false; NODE_REMOTE_READY=false; NODE_TOOLS_READY=false; NODE_RUNTIME_PREFLIGHT_READY=false; return 1; fi; }`

`pod_uid_node_matches(){ local pod_json="$1" current_node; if ! pod_uid_matches "$pod_json"; then NODE_TOOLS_READY=false; return 1; fi; current_node="$(jq -r '.spec.nodeName // empty' <<<"$pod_json")" || { NODE_TOOLS_READY=false; return 1; }; if [ -n "$current_node" ] && [ "$current_node" = "$NODE" ]; then return 0; else NODE_TOOLS_READY=false; return 1; fi; }`

`endpoint_relation_ready(){ local service_json="$1" pod_json="$2" endpoints_json="$3" service_ports pod_ports; service_ports="$(jq -c '.spec.ports // []' <<<"$service_json")" || return 1; pod_ports="$(jq -c '[.spec.containers[]?.ports[]?] // []' <<<"$pod_json")" || return 1; jq -e --arg uid "$POD_UID" --argjson service_ports "$service_ports" --argjson pod_ports "$pod_ports" 'def target($sp): ($sp.targetPort // $sp.port); def endpoint_port_match($sp; $ep): ((((target($sp) | type) == "number" and $ep.port == target($sp)) or ((target($sp) | type) == "string" and any($pod_ports[]?; .name == target($sp) and $ep.port == .containerPort))) and (($ep.protocol // "TCP") == ($sp.protocol // "TCP")) and (($ep.name // "") == ($sp.name // ""))); [.items[]? as $slice | select(($slice.addressType // "") | IN("IPv4","IPv6","FQDN")) | select(any($slice.endpoints[]?; .targetRef.uid==$uid and .conditions.ready==true and ((.conditions.serving // true) != false) and ((.conditions.terminating // false) != true))) | select(($service_ports | length) > 0) | select(all($service_ports[]; . as $sp | any($slice.ports[]?; . as $ep | endpoint_port_match($sp; $ep))))] | length > 0' <<<"$endpoints_json" >/dev/null; }`

`node_runtime_gate(){ local node_json node_api_name node_machine remote remote_host remote_machine pod_json; NODE_REMOTE_READY=false; if [ "$AUTO_READY" != true ] || [ -z "$NODE" ] || [ -z "$NODE_HOST" ] || [[ "$NODE_HOST" == PASTE_* ]] || ! [[ "$NODE_HOST" =~ ^[A-Za-z0-9._:-]+$ ]] || ! [[ "$KUBELET_UNIT" =~ ^[A-Za-z0-9_.@-]+(\.service)?$ ]] || ! [[ "$RUNTIME_UNIT" =~ ^[A-Za-z0-9_.@-]+(\.service)?$ ]] || ! then NODE_REMOTE_READY=true; export NODE_HOST NODE_REMOTE_READY; printf 'NODE_REMOTE_READY=true api-node=%s api-machineID=%s remote-hostname=%s remote-machine-id=%s kubelet=%s runtime=%s socket=%s pod-uid=%s\n' "$node_api_name" "$node_machine" "$remote_host" "$remote_machine" "$KUBELET_UNIT" "$RUNTIME_UNIT" "$CRI_SOCKET" "$POD_UID"; return 0; else printf '중단: remote journal 도구·sudo·실제 kubelet/runtime unit loaded/active·CRI socket 검증 실패 host=%s kubelet=%s runtime=%s socket=%s\n' "$NODE_HOST" "$KUBELET_UNIT" "$RUNTIME_UNIT" "$CRI_SOCKET" >&2; return 1; fi; else printf '중단: Node API·현재 Pod UID/node identity 조회 실패 node=%s\n' "$NODE" >&2; return 1; fi; }`

`AUTO_READY=true`와 현재 UID가 확인된 경우에만 최초 확인으로 간다. owner가 없거나 controller owner가 복수이면 `OWNER_READY=false`로 기록하고 상태 변경·owner 범위 판단을 하지 않는다. `Running`이나 한 container의 `ready=true`는 Pod 전체 기능을 보장하지 않는다.

namespace가 입력되지 않은 경우에만 다음 broad query로 후보를 출력하고, 복수 후보를 자동 선택하지 않는다. 후보에서 승인된 namespace를 확인한 뒤 입력 초기화 절을 다시 실행한다.

`NAMESPACE_DISCOVERY_READY=false; if [ "$TOOLS_READY" = true ] && [ -z "$NS" ] && [ -n "$POD" ]; then if POD_CANDIDATES="$(kubectl --context "$CTX" get pods -A --field-selector "metadata.name=$POD" -o custom-columns='NAMESPACE:.metadata.namespace,POD:.metadata.name,UID:.metadata.uid,PHASE:.status.phase,NODE:.spec.nodeName' --no-headers)" && [ -n "$POD_CANDIDATES" ]; then printf '%s\n' "$POD_CANDIDATES"; NAMESPACE_DISCOVERY_READY=true; else printf '%s\n' '중단: namespace discovery API 실패 또는 후보 없음' >&2; fi; else printf '%s\n' 'broad query는 실제 NS가 비어 있고 도구 gate가 통과한 경우에만 사용한다.'; fi`

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | regular app 또는 sidecar, init, ephemeral 중 특정 container만 `waiting`, `terminated`, probe 실패 또는 restart 상태인 경우 |
| 적용 | 같은 Pod UID에서 실패 container의 이름·종류·state를 확인하고 owner·서비스 영향을 분리할 수 있는 경우 |
| 제외 | 스케줄링·image pull·volume mount처럼 container 축보다 앞선 최초 증상은 해당 증상 런북으로 이동한다. create/start·OCI·runtime·Linux 보안 원인은 [[02. 워크로드/01. Pod/10. Pod STATUS가 CreateContainerError·RunContainerError인 경우|Pod create/start 런북]]과 node/runtime·보안 담당자로 이관한다. ephemeral은 workload 복구 container로 취급하지 않는다. |

검색 문자열: `containerStatuses`, `initContainerStatuses`, `ephemeralContainerStatuses`, `ready`, `readinessProbe`, `state`, `lastState`, `restartCount`, `CrashLoopBackOff`, `OOMKilled`, `sidecar`, `init container`, `ephemeral container`, `proxy`, `shared volume`, `process namespace`, `ownerReferences`, `Secret`.

특정 container 실패만으로 Pod 전체·owner·node·runtime 원인을 확정하지 않는다. Secret 원문·token·개인키와 개인정보는 저장하지 않는다.

## 최초 확인

`AUTO_READY=true`일 때만 같은 관측 시각에 다음을 실행한다.

`if [ "$AUTO_READY" = true ] && POD_CHECK_JSON="$(kubectl --context "$CTX" get pod "$POD" -n "$NS" -o json)" && pod_uid_matches "$POD_CHECK_JSON"; then jq -r '"Pod=" + .metadata.name + " UID=" + .metadata.uid + " Node=" + (.spec.nodeName // "-") + " Phase=" + (.status.phase // "-")' <<<"$POD_CHECK_JSON"; else printf '%s\n' '중단: AUTO_READY, Pod API 또는 최초 UID 검증 실패' >&2; fi`

`READY`, `RESTARTS`, `NODE`, IP와 전체 Pod phase를 본다. 한 regular 또는 sidecar의 ready 결과는 다른 container나 실제 Service 기능을 보장하지 않는다.

`if [ "$AUTO_READY" = true ] && POD_CHECK_JSON="$(kubectl --context "$CTX" get pod "$POD" -n "$NS" -o json)" && pod_uid_matches "$POD_CHECK_JSON"; then kubectl --context "$CTX" describe pod "$POD" -n "$NS"; else printf '%s\n' '중단: 최초 UID와 Pod describe 대상이 일치하지 않음' >&2; fi`

container별 State·Last State·Reason·Exit Code·Restart Count·Ready, probe 실패, Conditions, mount·environment 참조 이름과 첫 Event message를 본다. command/args·securityContext의 민감한 원문은 증거로 저장하지 않는다.

`EVENT_READY=false; if [ "$AUTO_READY" = true ] && POD_EVENT_CHECK_JSON="$(kubectl --context "$CTX" get pod "$POD" -n "$NS" -o json)" && pod_uid_matches "$POD_EVENT_CHECK_JSON" && kubectl --context "$CTX" get events -n "$NS" --field-selector "involvedObject.kind=Pod,involvedObject.name=$POD,involvedObject.uid=$POD_UID" --sort-by=.metadata.creationTimestamp -o custom-columns='EVENT-UID:.metadata.uid,INVOLVED-UID:.involvedObject.uid,CREATED:.metadata.creationTimestamp,FIRST-SEEN:.firstTimestamp,LAST-SEEN:.lastTimestamp,EVENT-TIME:.eventTime,SERIES-LAST:.series.lastObservedTime,TYPE:.type,REASON:.reason,COUNT:.count,MESSAGE:.message'; then EVENT_READY=true; else printf '%s\n' '중단: Event 실행 직전 Pod API 또는 최초 UID 검증 실패' >&2; fi`

이 Event 조회는 최초 확인에서 한 번만 실행한다. `INVOLVED-UID`가 `$POD_UID`와 같은지, 실제 채워진 시간과 container 종료 시각을 대조한다. 빈 결과는 정상·오류 없음이 아니며 UID·selector·권한·TTL을 확인한다.

## 컨테이너 선언과 status 분리

### regular container

**진입 증거:** regular app 또는 sidecar의 state/ready/restart가 증상과 일치할 때다. `AUTO_READY=true`와 Pod UID가 필수다.

`if [ "$AUTO_READY" = true ] && POD_JSON="$(kubectl --context "$CTX" get pod "$POD" -n "$NS" -o json)" && pod_uid_matches "$POD_JSON"; then jq -r 'def timing: ("initialDelaySeconds=" + ((.initialDelaySeconds // "-") | tostring) + ",periodSeconds=" + ((.periodSeconds // "-") | tostring) + ",timeoutSeconds=" + ((.timeoutSeconds // "-") | tostring) + ",successThreshold=" + ((.successThreshold // "-") | tostring) + ",failureThreshold=" + ((.failureThreshold // "-") | tostring)); def safe_path: (.httpGet.path // "-") as $path | if ($path | contains("?")) then "query-present-redacted owner-handoff=required" else $path end; def probe_summary: if . == null then "-" elif .httpGet then ("type=httpGet path=" + safe_path + " port=" + ((.httpGet.port // "-") | tostring) + " scheme=" + (.httpGet.scheme // "-") + " header-names=" + ([.httpGet.httpHeaders[]?.name] | join(",")) + " timing=" + timing) elif .tcpSocket then ("type=tcpSocket port=" + ((.tcpSocket.port // "-") | tostring) + " timing=" + timing) elif .grpc then ("type=grpc port=" + ((.grpc.port // "-") | tostring) + " timing=" + timing) elif .exec then ("type=exec timing=" + timing) else "type=unknown" end; {spec: [.spec.containers[]? | {name,image,securityContext,resources,probes:{readiness:(.readinessProbe | probe_summary),liveness:(.livenessProbe | probe_summary),startup:(.startupProbe | probe_summary)},volumeMounts}], status: [.status.containerStatuses[]? | {name,containerID,state,lastState,restartCount,ready}]}' <<<"$POD_JSON"; else printf '%s\n' '중단: 최초 UID와 Pod snapshot이 일치하지 않거나 API 실패' >&2; fi`

**성공 gate:** 선택 가능한 container 이름과 그 container의 image·resources·probe·securityContext·mount·current/last state가 확인된다. `ready=false`는 readiness 계약의 결과이지 종료 증거가 아니다. 출력이 없거나 API가 실패하면 image·설정을 추측하지 않고 owner에게 이관한다.

`httpGet.path`에 query(`?`)가 있으면 query 원문과 값을 보존하지 않고 `query-present-redacted owner-handoff=required`로 기록한 뒤 owner에게 이관한다.

**진입 증거:** `initContainerStatuses`에서 선언 순서와 첫 실패 init이 보일 때다.

### ephemeral container

**진입 증거:** `ephemeralContainerStatuses`에서 debug container의 state/lastState/restart가 보일 때다. ephemeral은 workload 복구 container가 아니다.

`if [ "$AUTO_READY" = true ] && POD_JSON="$(kubectl --context "$CTX" get pod "$POD" -n "$NS" -o json)" && pod_uid_matches "$POD_JSON"; then jq -r '{spec: [.spec.ephemeralContainers[]? | {name,targetContainerName,image,securityContext}], status: [.status.ephemeralContainerStatuses[]? | {name,containerID,state,lastState,restartCount}]}' <<<"$POD_JSON"; else printf '%s\n' '중단: 최초 UID와 Pod snapshot이 일치하지 않거나 API 실패' >&2; fi`

## 대상 container current/previous 로그

**진입 증거:** 특정 container의 state/lastState·restart 또는 probe/애플리케이션 오류가 로그로 분리돼야 할 때다. `CONTAINER`, `CONTAINER_KIND`, `START_RFC3339`는 위 API 출력과 관측 시각을 보고 운영자가 고른다.

`selected_container_current_id(){ jq -r --arg c "$CONTAINER" --arg kind "$CONTAINER_KIND" 'if $kind == "regular" then (([.status.containerStatuses[]? | select(.name == $c) | .containerID // empty] | first) // empty) elif $kind == "init" then (([.status.initContainerStatuses[]? | select(.name == $c) | .containerID // empty] | first) // empty) elif $kind == "ephemeral" then (([.status.ephemeralContainerStatuses[]? | select(.name == $c) | .containerID // empty] | first) // empty) else empty end' <<<"$1"; }`

`CONTAINER='PASTE_CONTAINER_HERE'; CONTAINER_KIND='PASTE_CONTAINER_KIND_HERE'; START_RFC3339='PASTE_START_RFC3339_HERE'; CONTAINER_READY=false; CONTAINER_API_OK=false; CONTAINER_CURRENT_ID=''; START_CANONICAL=''; START_EPOCH=''; if [ "$AUTO_READY" != true ]; then printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; elif [ "$CONTAINER_KIND" != regular ] && [ "$CONTAINER_KIND" != init ] && [ "$CONTAINER_KIND" != ephemeral ]; then printf '%s\n' '중단: container 종류가 regular·init·ephemeral 중 하나여야 한다.' >&2; elif [[ ! "$START_RFC3339" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]]; then printf '%s\n' '중단: UTC 시간 형식 오류' >&2; elif ! START_CANONICAL="$(date -u -d "$START_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" || [ "$START_CANONICAL" != "$START_RFC3339" ] || ! START_EPOCH="$(date -u -d "$START_RFC3339" '+%s' 2>/dev/null)"; then printf '중단: START_RFC3339 canonical calendar round-trip 실패=%s\n' "$START_RFC3339" >&2; elif POD_JSON="$(kubectl --context "$CTX" get pod "$POD" -n "$NS" -o json)" && pod_uid_matches "$POD_JSON"; then CONTAINER_API_OK=false; case "$CONTAINER_KIND" in regular) if jq -e --arg c "$CONTAINER" 'any(.spec.containers[]?; .name==$c)' <<<"$POD_JSON" >/dev/null; then CONTAINER_API_OK=true; fi;; init) if jq -e --arg c "$CONTAINER" 'any(.spec.initContainers[]?; .name==$c)' <<<"$POD_JSON" >/dev/null; then CONTAINER_API_OK=true; fi;; ephemeral) if jq -e --arg c "$CONTAINER" 'any(.spec.ephemeralContainers[]?; .name==$c)' <<<"$POD_JSON" >/dev/null; then CONTAINER_API_OK=true; fi;; esac; CONTAINER_CURRENT_ID="$(selected_container_current_id "$POD_JSON")"; if [ "$CONTAINER_API_OK" = true ] && [ -n "$CONTAINER_CURRENT_ID" ]; then CONTAINER_READY=true; export CONTAINER CONTAINER_KIND CONTAINER_CURRENT_ID START_RFC3339 START_CANONICAL START_EPOCH; printf 'CONTAINER_READY=true container=%s kind=%s containerID=%s start=%s canonical=%s epoch=%s UID=%s\n' "$CONTAINER" "$CONTAINER_KIND" "$CONTAINER_CURRENT_ID" "$START_RFC3339" "$START_CANONICAL" "$START_EPOCH" "$POD_UID"; else printf '%s\n' '중단: 선택 container가 현재 Pod에 없거나 current containerID가 없음' >&2; fi; else printf '%s\n' '중단: 선택 container, API 또는 최초 UID 검증 실패' >&2; fi`

`CONTAINER_READY=true`가 아니면 logs를 실행하지 않는다. 이름을 추측하거나 `--all-containers`로 범위를 넓히지 않는다.

`logs_filtered(){ local pod_json current_container_id api_rc grep_rc pipeline_status; if ! pod_json="$(kubectl --context "$CTX" get pod "$POD" -n "$NS" -o json)" || ! pod_uid_matches "$pod_json"; then printf '%s\n' '중단: logs 실행 직전 Pod API 또는 최초 UID 검증 실패' >&2; return 1; fi; if ! **연결 경계:** `실행 host → kubectl/API server HTTPS → API server streaming proxy → node/kubelet/runtime → 선택한 container stdout/stderr`다. Pod `Running`이나 log stream 연결은 application 기능과 다른 container의 정상화를 보장하지 않는다.

`if [ "$CONTAINER_READY" = true ]; then logs_filtered; else printf '%s\n' '중단: CONTAINER_READY가 아니다.' >&2; fi`

`ERROR dial tcp ... connection refused`는 process와 외부 endpoint 경계를 분리할 신호이지 DB·Service·firewall 중 하나를 단독 확정하지 않는다. `OOMKilled`·`killed process`는 limit·node pressure와 대조하고, `probe failed`·`unhealthy`는 probe 계약과 Event로 이동한다. `permission denied`·`no such file`은 [[02. 워크로드/01. Pod/10. Pod STATUS가 CreateContainerError·RunContainerError인 경우|image 실행·mount·securityContext create/start 런북]]으로 이관한다.

필터 빈 결과는 오류 부재가 아니다. 같은 시간 범위의 제한된 tail만 확인한다.

`if [ "$CONTAINER_READY" = true ] && POD_LOG_CHECK_JSON="$(kubectl --context "$CTX" get pod "$POD" -n "$NS" -o json)" && pod_uid_matches "$POD_LOG_CHECK_JSON" && [ -n "$CONTAINER_CURRENT_ID" ] && [ "$(selected_container_current_id "$POD_LOG_CHECK_JSON")" = "$CONTAINER_CURRENT_ID" ]; then if kubectl --context "$CTX" logs "$POD" -n "$NS" -c "$CONTAINER" --timestamps --since-time="$START_RFC3339" --tail=50; then :; else printf '중단: logs tail API/stream 실패 UID=%s\n' "$POD_UID" >&2; fi; else CONTAINER_READY=false; printf '%s\n' '중단: CONTAINER_READY 또는 실행 직전 UID/containerID gate가 아니다.' >&2; fi`

`CONTAINER_KIND`가 `regular` 또는 `init`이고 `lastState.terminated`·restart 증가로 직전 instance가 필요할 때만 previous를 실행한다. ephemeral은 재시작되지 않으므로 previous를 정상 증거로 기대하지 않는다.

`if [ "$CONTAINER_READY" = true ] && [ "$CONTAINER_KIND" != ephemeral ]; then previous_logs_filtered; else printf '%s\n' '중단: previous 조건이 아니거나 CONTAINER_READY가 아니다.' >&2; fi`

## 컨테이너 역할 분기

공통 흐름은 `실패한 container state/로그 → shared network·volume·process namespace → sidecar 계약·owner·Service 영향 → node·runtime·Linux 공통 원인`이다. 컨테이너 고유 증거가 없는데 마지막 계층으로 건너뛰지 않는다. 같은 Pod는 network namespace와 선언된 volume을 공유할 수 있지만 process namespace 공유는 `shareProcessNamespace`가 활성화된 경우에 한정된다. Kubernetes 1.26에서 sidecar는 별도 container kind가 아니다.

### regular app container 실패

`status.containerStatuses`의 실패 app에 대해 `ready`, current/Last State, reason, exitCode, startedAt/finishedAt, restartCount를 다른 container와 비교한다. 현재 state가 정상이고 Last State만 종료라면 과거 재시작과 현재 장애를 분리한다. image entrypoint·command/args·securityContext·환경 변수와 ConfigMap/Secret 참조·mount·probe를 대조하되 민감한 원문은 저장하지 않는다.

`Error`·비정상 exit는 create/start·OCI·실행 권한 원인을 [[02. 워크로드/01. Pod/10. Pod STATUS가 CreateContainerError·RunContainerError인 경우|Pod create/start 런북]]으로 이관한다. `OOMKilled`는 해당 container memory limit·사용량을 먼저 확인하고 node pressure·kernel OOM으로 확장한다. `CrashLoopBackOff`는 backoff 표현이지 근본 원인이 아니므로 [[02. 워크로드/01. Pod/06. Pod STATUS가 CrashLoopBackOff인 경우|CrashLoopBackOff 런북]]으로 이동한다.

app만 실패하고 sidecar가 정상이어도 sidecar를 원인으로 만들지 않는다. app readiness·Service backend·실제 요청 오류를 확인하고, 여러 container가 같은 시간에 실패할 때만 shared 자원 분기로 이동한다.

[[#관측별 진단 경로|← 관측별 진단 경로로 돌아가기]]

### sidecar container 실패

sidecar의 `ready=false`만으로 process 실패를 확정하지 않는다. state·lastState·restartCount, readinessProbe 존재와 실패 Event, Pod Ready condition을 함께 확인한다. sidecar가 제공한 proxy·인증·로그 계약과 app process 상태를 별도로 확인한다.

proxy sidecar는 app port가 살아 있어도 traffic interception, mTLS, 인증, timeout, routing 또는 readiness gate를 깨뜨릴 수 있다. `sidecar state/exit/probe → app·proxy listen port와 localhost → network namespace·redirect·Service endpoint → proxy configuration·certificate·upstream → CNI·kube-proxy·NetworkPolicy·외부 route` 순서로 확인한다. `localhost`는 Pod network namespace의 주소이며 실행 host의 loopback과 다르다.

log sidecar는 app 실행과 별개일 수 있지만 shared volume의 파일 소비, permission, rotation, backpressure와 로그 유실을 만들 수 있다. Secret·인증 sidecar는 Secret 이름·key와 projected mount·갱신 시각·service account/RBAC·파일 권한만 확인하고 Secret·token·개인키 원문을 출력하지 않는다.

sidecar 종료 순서가 app 종료보다 앞선다는 사실만으로 원인을 확정하지 않는다. preStop·lifecycle·shared process namespace·실제 signal과 Event·runtime evidence를 맞춘다.

[[#관측별 진단 경로|← 관측별 진단 경로로 돌아가기]]

### init container 실패

init은 선언 순서와 성공 종료를 우선 본다. 첫 실패 init의 `lastState.reason/exitCode`, image·command·mount·Secret/ConfigMap 참조, DNS·Service·외부 dependency 도달성을 확인한다. init을 건너뛰거나 regular만 재시작해 정상화하지 않는다. mount·권한은 create/start 런북으로, 전체 init 정체는 init 단계 런북으로 이관한다.

`실패한 init 이름·순서 → Last State·exitCode → image·mount → DNS·Service·외부 dependency → kubelet mount/start → runtime·node filesystem/network` 순서가 다음 파이프라인이다. 빈 init 로그는 process가 출력 전에 종료됐거나 보존되지 않은 후보다.

### ephemeral container 실패

ephemeral은 실행 중인 Pod의 debug 목적 추가 container다. state·lastState·restartCount는 debug 자체의 관측이며 Service readiness의 근거가 아니다. debug image의 shell/tool, securityContext, target process namespace, 권한, 추가·종료 시각을 확인한다.

ephemeral 추가 자체가 Pod spec/status와 증거를 바꿀 수 있으므로 추가 전후를 별도로 기록한다. ephemeral 실패를 workload 원인이나 복구 승인 근거로 확정하지 않고, 필요하면 debug 변경을 중단한 뒤 regular container의 원본 관측으로 돌아간다.

## shared network volume process namespace 분기

**진입 증거:** 두 개 이상 container가 같은 시각에 실패하거나, 한 container 오류가 shared 자원 계약과 직접 연결될 때다. 한 container만 실패하고 공통 증거가 없으면 이 분기로 확장하지 않는다.

`특정 container state/로그 → shared network의 port·DNS·route·redirect·NetworkPolicy → shared volume의 source·mount·subPath·권한·filesystem → shareProcessNamespace·PID·signal·supervisor → kubelet/runtime·node/Linux` 순서로 내려간다.

network namespace를 공유해도 port 충돌, localhost 오해, proxy redirect, DNS·route·NetworkPolicy 계약은 별도다. sandbox/CNI 증거는 [[02. 워크로드/01. Pod/24. Pod 이벤트에 FailedCreatePodSandBox가 기록된 경우|FailedCreatePodSandBox 런북]]으로 이관한다. volume은 source·mountPath/subPath·readOnly·UID/GID·securityContext·파일 생성 순서·disk full/read-only를 app과 sidecar별로 나눈다. PVC·CSI·kubelet mount가 여러 Pod에서 같은 시각에 실패하면 storage/filesystem 계층으로 내려간다.

`shareProcessNamespace=true`일 때만 process namespace 공유를 가정한다. supervisor·PID 1·signal·preStop가 다른 process를 종료한다는 직접 근거가 없으면 shared Pod라는 이유로 인과를 만들지 않는다.

## owner와 서비스 영향

**진입 증거:** `OWNER_READY=true`이고 controller owner kind/name/UID가 현재 Pod UID와 연결되거나 Service가 실제 Pod를 선택할 때다. owner가 없거나 복수이면 상태 변경 없이 담당자에게 이관한다.

owner의 desired/ready, rollout·partition·quorum·Job 결과를 Pod 하나와 분리한다. Deployment 재생성, StatefulSet 순서, DaemonSet node 범위, Job 외부 재호출은 영향이 다르다.

**controller owner resource와 Pod owner UID 대조**

Pod의 `ownerReferences[controller=true]` kind에 맞는 resource만 조회한다. 이름만 같은 새 resource의 상태를 현재 Pod에 연결하지 않으며, current owner UID가 Pod의 `OWNER_UID`와 다르면 desired/ready·Job completion을 사용하지 않는다.

## node runtime Linux 공통 원인

**진입 증거:** 같은 시각에 여러 container가 실패하거나, Pod UID와 Event가 공통 원인을 가리키거나, kubelet이 start/kill/mount 실패를 기록하거나, 같은 node의 다른 Pod가 같은 증상을 보일 때만 node 계층으로 이동한다.

**필수값:** `NODE`는 API 자동값이다. `NODE_HOST`는 승인된 SSH 목적지이며 `START_JOURNAL`은 오류 전 UTC 시각을 운영자가 선택하고 `END_JOURNAL`은 같은 Bash에서 자동으로 현재 UTC로 계산한다. `KUBELET_UNIT`, `RUNTIME_UNIT`, `CRI_SOCKET`은 node 설정·service manager에서 확인한 실제 값이며 runtime version이나 기본 socket에서 추측하지 않는다.

`if [ "$NODE_TOOLS_READY" = true ] && [ "$NODE_RUNTIME_PREFLIGHT_READY" = true ] && KUBELET_JOURNAL_POD_JSON="$(kubectl --context "$CTX" get pod "$POD" -n "$NS" -o json)" && pod_uid_node_matches "$KUBELET_JOURNAL_POD_JSON" && node_runtime_gate; then printf -v JOURNAL_CMD 'sudo -n journalctl -u %q --since %q --until %q --no-pager' "$KUBELET_UNIT" "$START_JOURNAL" "$END_JOURNAL"; ssh -- "$NODE_HOST" "$JOURNAL_CMD" | grep -E -i -C 3 "$POD_UID|$POD|$CONTAINER|failed|error|oom|evict|mount|sandbox|cni|runtime|probe|kill"; PIPE_RC=("${PIPESTATUS[@]}"); SSH_RC="${PIPE_RC[0]}"; GREP_RC="${PIPE_RC[1]}"; if [ "$SSH_RC" -ne 0 ]; then printf '중단: kubelet journal producer/SSH 실패 rc=%s UID=%s node=%s host=%s kubelet=%s\n' "$SSH_RC" "$POD_UID" "$NODE" "$NODE_HOST" "$KUBELET_UNIT" >&2; elif [ "$GREP_RC" -gt 1 ]; then printf '중단: kubelet journal 필터 도구 실패 rc=%s UID=%s node=%s host=%s kubelet=%s\n' "$GREP_RC" "$POD_UID" "$NODE" "$NODE_HOST" "$KUBELET_UNIT" >&2; fi; else NODE_TOOLS_READY=false; printf '%s\n' '중단: NODE_TOOLS_READY, API/SSH remote identity, unit/CRI gate 또는 실행 직전 Pod UID/node gate 검증 실패' >&2; fi`

`failed to create pod sandbox`, `failed to StartContainer`, `Killing`, `probe`, `eviction`, OCI·cgroup·filesystem·network namespace 오류가 Pod UID·container·시간창과 맞는지 본다. 필터가 비면 kubelet 정상으로 확정하지 않고 로그 보존·시간대·unit을 확인한다.

`if [ "$NODE_TOOLS_READY" = true ] && [ "$NODE_RUNTIME_PREFLIGHT_READY" = true ] && RUNTIME_JOURNAL_POD_JSON="$(kubectl --context "$CTX" get pod "$POD" -n "$NS" -o json)" && pod_uid_node_matches "$RUNTIME_JOURNAL_POD_JSON" && node_runtime_gate; then printf -v JOURNAL_CMD 'sudo -n journalctl -u %q --since %q --until %q --no-pager' "$RUNTIME_UNIT" "$START_JOURNAL" "$END_JOURNAL"; ssh -- "$NODE_HOST" "$JOURNAL_CMD" | grep -E -i -C 3 "$POD_UID|$CONTAINER|create|start|kill|shim|oci|cgroup|snapshot|filesystem|permission|no space|read-only|error"; PIPE_RC=("${PIPESTATUS[@]}"); SSH_RC="${PIPE_RC[0]}"; GREP_RC="${PIPE_RC[1]}"; if [ "$SSH_RC" -ne 0 ]; then printf '중단: runtime journal producer/SSH 실패 rc=%s UID=%s node=%s host=%s runtime=%s\n' "$SSH_RC" "$POD_UID" "$NODE" "$NODE_HOST" "$RUNTIME_UNIT" >&2; elif [ "$GREP_RC" -gt 1 ]; then printf '중단: runtime journal 필터 도구 실패 rc=%s UID=%s node=%s host=%s runtime=%s\n' "$GREP_RC" "$POD_UID" "$NODE" "$NODE_HOST" "$RUNTIME_UNIT" >&2; fi; else NODE_TOOLS_READY=false; printf '%s\n' '중단: NODE_TOOLS_READY, API/SSH remote identity, unit/CRI gate 또는 실행 직전 Pod UID/node gate 검증 실패' >&2; fi`

runtime 로그에서 OCI create/start/kill, cgroup, snapshot/filesystem, network namespace 오류가 직접 확인되면 Linux·storage·CNI 계층으로 내려간다. runtime 구현체가 미확정이거나 로그가 비면 명령을 발명하지 말고 Pod UID·container ID·정확한 UTC 창을 이관한다. 공통 증거가 없으면 실패 container 고유 원인으로 돌아간다.

## 제한적 복구와 상태 변경 gate

Pod를 무조건 삭제하거나 특정 container만 임의 재시작하지 않는다. 상태 변경은 실패 container의 직접 근거와 실제 서비스 영향이 같은 시간창에서 일치하고, context·namespace·Pod UID·controller owner·role·대체 Pod·PDB·quorum·Job 멱등성·sidecar 종료 계약을 확인한 뒤 owner의 공식 절차와 승인으로만 수행한다.

**안전 gate:** 변경 기록에는 trigger, 권한·승인자, 대상과 영향 범위, 예상 효과와 보장하지 않는 것, 중단 조건, rollback, 실행 후 검증을 적는다. Ready 감소, 동일 exit reason 반복, 새 Warning, 외부 중복 처리, quorum 위험 또는 실제 지표 악화 시 중단한다. ephemeral 추가는 진단 상태 변경이며 서비스 복구 명령으로 사용하지 않는다.

## 정상화와 증거 보존

정상화는 role별 state·ready, current/Last State, restartCount와 init 성공 순서를 먼저 확인하고, ephemeral은 readiness 근거에서 제외한다. 다음을 모두 관찰 창 동안 확인한다.

- 종료 reason·probe 실패·restart 증가와 새 Warning이 없다.
- controller owner current UID와 Pod owner UID가 맞고, kind별 desired/ready 또는 Job completion, Service selector·EndpointSlice와 target Pod UID가 맞다.
- 실제 요청·핵심 기능·proxy/인증/log 기능·Job 결과가 정상이다.
- 필요했던 shared network·volume·process namespace·node/runtime 증거가 해소됐다.

검증 순서는 `실제 application 기능 → API·metric 결과 → process/listener → remote endpoint → shared·전달 경로 → Service/EndpointSlice → owner·Pod identity`의 역순으로 원인 경로를 확인한다. Pod `Running`, 한 container `ready=true`, Endpoint `ready=true`, 새 Pod 생성은 단독 정상화 근거가 아니다. 완화 성공과 근본 원인 확정을 분리한다.

증거에는 UTC 관측 시각, context, namespace/name, Pod UID·owner UID·current owner UID, node, container 역할·이름·ID·state·restart, owner kind별 desired/ready 또는 Job completion, get·describe·Event 원본, 로그 시간창, runtime·kubelet/Linux 증거와 Secret 참조 이름만 보존한다. Secret 원문·token·개인키·개인정보는 저장하지 않는다.

## Prometheus 빠른 관측

메트릭과 `namespace`, `pod`, `uid`, `container` label이 실제 수집될 때만 사용한다. `kube_pod_container_status_ready`는 `condition` label을 사용하지 않으며 sample value `0/1`로 판정한다. `POD_RE`와 등록 변수를 사용해 완성된 PromQL을 생성하고 출력만 외부 UI에 붙여 넣는다. metric 부재·label 불일치·조회 실패·빈 결과를 0이나 정상으로 기록하지 않는다.

`if [ "$AUTO_READY" = true ]; then printf '%s\n' "count by(namespace,pod,uid)(kube_pod_info{namespace=\"$NS\",pod=~\"$POD_RE\",uid=\"$POD_UID\"})"; else printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; fi`

결과가 현재 namespace·Pod regex·최초 UID에 대해 1 series이고 `namespace`, `pod`, `uid` label이 존재할 때만 kube-state-metrics label 계약을 통과시킨다.

`if [ "$AUTO_READY" = true ]; then printf '%s\n' "kube_pod_container_info{namespace=\"$NS\",pod=~\"$POD_RE\",uid=\"$POD_UID\",container!=\"POD\"}"; else printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; fi`

`if [ "$AUTO_READY" = true ]; then printf '%s\n' "kube_pod_container_status_ready{namespace=\"$NS\",pod=~\"$POD_RE\",uid=\"$POD_UID\"} == 0"; else printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; fi`

`if [ "$AUTO_READY" = true ]; then printf '%s\n' "kube_pod_container_status_waiting_reason{namespace=\"$NS\",pod=~\"$POD_RE\",uid=\"$POD_UID\"}"; else printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; fi`

`if [ "$AUTO_READY" = true ]; then printf '%s\n' "sum by(namespace,pod,uid,container)(increase(kube_pod_container_status_restarts_total{namespace=\"$NS\",pod=~\"$POD_RE\",uid=\"$POD_UID\"}[$PROM_WINDOW]))"; else printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; fi`

한 container의 정상 metric으로 Pod 전체 기능을 정상화하지 않는다. Prometheus sample의 UID와 관측 시각이 API snapshot과 맞는지 확인한다.
