# Pod 로그를 가져올 수 없는 경우

## 입력값과 빠른 수집

최초 입력은 namespace와 Pod뿐이다. Pod UID, node, phase, container·status·container ID·시각은 API 자동값이다. container, 로그 시작 시각, audit/journal 시간과 실제 node 로그 경로는 자동 출력 확인 뒤 운영자가 선택한다. 로그 원문, Secret, token, 개인키와 개인정보는 입력값이나 증거로 저장하지 않는다.

| 구분 | 값 | 출처와 유효성 gate |
|---|---|---|
| 최초 입력 | `NS`, `POD` | 승인된 namespace와 정확한 Pod 이름을 한 번 입력하고 exact-name API 조회가 성공해야 한다. |
| API 자동값 | `POD_UID`, `NODE`, `PHASE`, `POD_JSON`, `EVENTS_JSON`, `OBSERVED_AT`, 선택 container의 `CONTAINER_ID`, `CONTAINER_KIND`, state, start·finish 시각 | Pod·UID 제한 Event API와 선택한 container status가 같은 UID로 대조돼야 한다. |
| 계산 후보 | `POD_RE`, `CONTAINER_RE`, `RUNTIME_CONTAINER_ID`, `START_READY`, `POD_IDENTITY_READY` | 이름 regex, runtime ID prefix 제거, UTC 형식과 현재 UID gate다. 실제 검증 전에는 확정하지 않는다. |
| 운영자 선택값 | `CONTAINER`, `START_RFC3339`, audit/journal 시간, `KUBELET_UNIT`, `POD_LOGS_DIR`, `CRI_LOG_PATH`, `CRI_RUNTIME_ENDPOINT`, `REMOTE_HOST` | 자동 수집의 container·port·status 관계와 실제 node/runtime 설정을 확인한 뒤 해당 분기에서 한 번 선택한다. |

### 1. 실행 위치·도구·대상 지정

kubectl 명령은 승인된 작업 PC 또는 bastion의 **같은 Bash 터미널**에서 실행한다. `sh`, PowerShell, CMD로 바꾸거나 새 Bash를 열면 단계 gate와 변수 상태가 사라진다. `kubectl logs`는 Pod 대상 확인과 `pods/log` subresource 접근을 분리해 확인한다. node journal·runtime 명령은 작업 PC 변수에 의존하지 않는 승인된 SSH 원격 Bash에서 Pod UID·container ID·Node machine identity·시간 gate를 다시 검증한 뒤에만 실행한다.

**Bash·필수 도구 확인 — 아래 한 줄 전체를 복사**

`TOOLS_READY=false; MISSING_TOOLS=''; if [ -z "${BASH_VERSION:-}" ]; then printf '%s\n' '중단: 같은 Bash에서 실행한다.' >&2; else for TOOL in kubectl jq grep sed date mktemp ssh; do command -v "$TOOL" >/dev/null 2>&1 || MISSING_TOOLS="$MISSING_TOOLS $TOOL"; done; if [ -z "$MISSING_TOOLS" ]; then TOOLS_READY=true; printf 'TOOLS_READY=true Bash=%s\n' "$BASH_VERSION"; else printf '중단: 없는 도구=%s\n' "$MISSING_TOOLS" >&2; fi; fi`

`TOOLS_READY=true`가 아니면 다음 명령을 실행하지 않는다. node 전용 도구는 node 분기에서 별도 확인하며, 도구가 없다고 로그 부재나 runtime 장애로 단정하지 않는다.

**최초 입력·이전 상태 초기화 — 같은 Bash에서 한 번 실행**

`unset INPUT_READY AUTO_READY CONTAINER_READY LOG_READY RBAC_READY API_READY LOG_ENDPOINT_READY NODE_READY RUNTIME_READY PROMQL_READY POD_UID NODE PHASE POD_JSON EVENTS_JSON EVENTS_READY STATUS_JSON RUNTIME_JSON OBSERVED_AT CONTAINER CONTAINER_ID RUNTIME_CONTAINER_ID STARTED_AT FINISHED_AT WAITING_REASON TERMINATED_REASON RESTART_COUNT START_RFC3339 START_AUDIT END_AUDIT KUBELET_UNIT POD_LOGS_DIR CRI_LOG_PATH START_JOURNAL END_JOURNAL CRI_RUNTIME_ENDPOINT POD_RE CONTAINER_RE; NS='PASTE_NAMESPACE_HERE'; POD='PASTE_POD_HERE'; INPUT_READY=false; if [ "$TOOLS_READY" != true ]; then printf '%s\n' '중단: 도구 확인을 먼저 통과한다.' >&2; elif [ -z "$NS" ] || [ -z "$POD" ]; then printf '%s\n' '중단: NS와 POD를 입력한다.' >&2; elif kubectl get pod "$POD" -n "$NS" -o name >/dev/null 2>&1; then INPUT_READY=true; export NS POD; printf 'INPUT_READY=true namespace=%s pod=%s\n' "$NS" "$POD"; else printf '중단: 정확한 Pod 조회 실패 namespace=%s pod=%s\n' "$NS" "$POD" >&2; fi`

`unset POD_IDENTITY_READY NODE_API_READY NODE_API_JSON NODE_HOST_READY NODE_HOST ACTUAL_NODE_HOST NODE_REMOTE_READY NODE_MACHINE_ID NODE_REMOTE_MACHINE_ID JOURNAL_TIME_READY JOURNAL_START_EPOCH JOURNAL_END_EPOCH JOURNAL_START_CANONICAL JOURNAL_END_CANONICAL CURRENT_CONTAINER_READY CURRENT_CONTAINER_KIND CURRENT_CONTAINER_ID CURRENT_STATUS_JSON CURRENT_POD_JSON`

`INPUT_READY=true`가 아니면 namespace·Pod 이름·권한을 확인하고 이후 단계로 진행하지 않는다.

### 2. API 자동 수집

**Pod·container·status 자동 수집 — 아래 한 줄 전체를 복사**

`unset AUTO_READY POD_UID NODE PHASE POD_JSON OBSERVED_AT; AUTO_READY=false; if [ "$INPUT_READY" != true ]; then printf '%s\n' '중단: INPUT_READY가 아니다.' >&2; elif POD_JSON="$(kubectl get pod "$POD" -n "$NS" -o json)" && POD_UID_TMP="$(jq -r '.metadata.uid // empty' <<<"$POD_JSON")" && [ -n "$POD_UID_TMP" ] && OBSERVED_AT_TMP="$(date -u '+%Y-%m-%dT%H:%M:%SZ')"; then POD_UID="$POD_UID_TMP"; NODE="$(jq -r '.spec.nodeName // "-"' <<<"$POD_JSON")"; PHASE="$(jq -r '.status.phase // "-"' <<<"$POD_JSON")"; OBSERVED_AT="$OBSERVED_AT_TMP"; AUTO_READY=true; export POD_UID NODE PHASE OBSERVED_AT; jq -r '"=== Pod ===\n이름: \(.metadata.name)\nUID: \(.metadata.uid)\n노드: \(.spec.nodeName // "미할당")\n상태: \(.status.phase // "-")\nPod 시작 시각: \(.status.startTime // .metadata.creationTimestamp // "-")\n"' <<<"$POD_JSON"; jq -r '.spec.initContainers[]? | "=== 초기화 컨테이너 ===\n컨테이너: \(.name)\n포트 후보: " + ([.ports[]? | ((.name // "unnamed")+":"+(.containerPort|tostring))] | join(","))' <<<"$POD_JSON"; jq -r '.spec.containers[]? | "=== 컨테이너 ===\n컨테이너: \(.name)\n포트 후보: " + ([.ports[]? | ((.name // "unnamed")+":"+(.containerPort|tostring))] | join(","))' <<<"$POD_JSON"; jq -r '.spec.ephemeralContainers[]? | "=== 임시 컨테이너 ===\n컨테이너: \(.name)\n포트 후보: " + ([.ports[]? | ((.name // "unnamed")+":"+(.containerPort|tostring))] | join(","))' <<<"$POD_JSON"; jq -r '([.status.initContainerStatuses[]?,.status.containerStatuses[]?,.status.ephemeralContainerStatuses[]?] | .[]) | "=== 컨테이너 상태 ===\n컨테이너: \(.name)\n실행 시각: \(.state.running.startedAt // "-")\n대기 사유: \(.state.waiting.reason // "-")\n종료 사유: \(.state.terminated.reason // "-")\n종료 코드: \(.state.terminated.exitCode // "-")\n재시작 횟수: \(.restartCount // 0)\n컨테이너 ID: \(.containerID // "-")\n마지막 종료 시각: \(.lastState.terminated.finishedAt // "-")\n"' <<<"$POD_JSON"; printf 'AUTO_READY=true 관측 시각=%s\n' "$OBSERVED_AT"; else unset POD_UID NODE PHASE POD_JSON OBSERVED_AT; printf '%s\n' '중단: Pod API 조회 또는 UID 추출 실패' >&2; fi`

자동 출력은 container와 port를 같은 블록에 두고, status의 container ID·state·restart·시각을 함께 보여 줘야 한다. `containerPort`는 선언 후보이며 실제 listener·protocol·application 정상은 보장하지 않는다.

```text
=== Container ===
Container: api
Port 후보: http:8080
=== Container status ===
Container: api
Running 시각: 2026-07-29T09:00:00Z
Waiting reason: -
Restart count: 0
Container ID: containerd://abc...
```

`AUTO_READY=true`와 Pod UID가 확인돼야 다음으로 간다. status가 없거나 container ID가 비어 있는 것은 로그가 없다는 뜻이 아니라 아직 생성되지 않았거나 API field가 없는 상태일 수 있다.

**초기 Pod UID 재조회 gate — 아래 한 줄 전체를 복사**

`refresh_pod_identity(){ POD_IDENTITY_READY=false; CURRENT_POD_UID="$(kubectl get pod "$POD" -n "$NS" -o jsonpath='{.metadata.uid}' 2>/dev/null)"; if [ "$AUTO_READY" = true ] && [ -n "$CURRENT_POD_UID" ] && [ "$CURRENT_POD_UID" = "$POD_UID" ]; then POD_IDENTITY_READY=true; printf 'POD_IDENTITY_READY=true uid=%s\n' "$CURRENT_POD_UID"; return 0; else unset AUTO_READY CONTAINER_READY LOG_READY RBAC_READY API_READY LOG_ENDPOINT_READY NODE_READY RUNTIME_READY PROMQL_READY; printf '중단: Pod UID mismatch 또는 재조회 실패 expected=%s actual=%s\n' "$POD_UID" "${CURRENT_POD_UID:--}" >&2; return 1; fi; }; refresh_pod_identity`

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | `kubectl logs`가 실패하거나 빈 결과를 반환하고 container 선택·상태·권한·API·kubelet·runtime·rotation 경계를 분리해야 하는 경우 |
| 적용 | 대상 namespace, Pod UID, 선택 container와 현재 container ID를 확인할 수 있거나 로그 미생성 상태를 판단해야 하는 경우 |
| 제외 | `--previous`는 [[28. Pod의 이전 컨테이너 로그를 가져올 수 없는 경우]], 멀티 컨테이너 대상 선택은 [[29. 멀티 컨테이너 Pod의 로그 대상을 특정할 수 없는 경우]], `pods/log` RBAC는 [[30. Pod 로그 권한이 거부되는 경우]]로 이동한다. |

검색 문자열: `container name must be specified`, `container not found`, `ContainerCreating`, `CreateContainerConfigError`, `Forbidden`, `pods/log`, `connection refused`, `i/o timeout`, `x509`, `unable to retrieve container logs`, `no such file or directory`, `log rotation`.

이 문서는 `--previous` 없이 현재 container instance의 로그 접근을 다룬다. 현재 instance는 선택한 container의 현재 `state`와 `containerID`가 소유한다. `lastState.terminated`의 이전 ID는 28번 문서의 소유다.

## 최초 확인

진입 판단을 통과하고 `AUTO_READY=true`일 때만 실행한다.

**Pod 상세 확인 — 아래 한 줄 전체를 복사**

`if [ "$AUTO_READY" != true ]; then printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; else kubectl describe pod "$POD" -n "$NS"; fi`

`describe`에서 대상 container의 state·reason·container ID, node, 로그 관련 오류와 Conditions를 본다. Event가 없거나 집계됐다는 사실을 로그 부재 원인으로 확정하지 않는다. API 조회 성공은 Pod metadata를 읽었다는 범위만 보장한다.

**UID 제한 Event 확인 — 아래 한 줄 전체를 복사**

`EVENTS_READY=false; if [ "$AUTO_READY" != true ]; then printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; elif EVENTS_JSON="$(kubectl get events -n "$NS" --field-selector "involvedObject.kind=Pod,involvedObject.name=$POD,involvedObject.uid=$POD_UID" -o json)"; then EVENTS_READY=true; if [ "$(jq '.items|length' <<<"$EVENTS_JSON")" -eq 0 ]; then printf '%s\n' 'Event 결과: 없음 (정상·오류 없음으로 해석하지 않음)'; else jq -r '.items | sort_by(.eventTime // .lastTimestamp // .firstTimestamp // .metadata.creationTimestamp)[] | "이벤트 UID=\(.metadata.uid // "-") 대상 UID=\(.involvedObject.uid // "-") 시각=\(.eventTime // .lastTimestamp // .firstTimestamp // .metadata.creationTimestamp // "-") 사유=\(.reason // "-") 메시지=\(.message // "-")"' <<<"$EVENTS_JSON"; fi; else printf '%s\n' '중단: UID 제한 Event API 조회 실패' >&2; fi`

`EVENTS_READY=true`는 Event API 응답을 받았다는 범위다. 빈 결과는 오류 없음이 아니며, 다른 Pod UID의 Event를 현재 container 로그 원인으로 섞지 않는다.

표는 길 안내이며 원인을 확정하지 않는다. stream·API·node·runtime 각 hop의 성공 범위를 분리한다.

## 1. container 선택과 상태 분리

진입 증거는 container 선택 오류, `Waiting`, `ContainerCreating` 또는 current log의 빈 결과다. 최초 운영자 선택값은 자동 출력에서 이름을 확인한 `CONTAINER`이며, 멀티 컨테이너에서 첫 번째를 임의 선택하지 않는다.

연결 경로: **작업 PC의 kubectl client → API server HTTPS endpoint → `pods/log` subresource → kubelet node endpoint → runtime log source → 선택한 current container**. API server 응답 성공은 kubelet·runtime의 log bytes와 application 정상화를 보장하지 않는다.

**container 선택값 등록 — 자동 출력과 오류 message를 대조한 뒤 한 번 실행**

`CONTAINER='PASTE_CONTAINER_HERE'`

**선택 container와 현재 status 등록 — 아래 한 줄 전체를 복사**

`CONTAINER_READY=false; unset CONTAINER_ID CONTAINER_KIND STARTED_AT FINISHED_AT WAITING_REASON TERMINATED_REASON RESTART_COUNT; if [ "$AUTO_READY" != true ]; then printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; elif jq -e --arg c "$CONTAINER" 'any([.spec.initContainers[]?,.spec.containers[]?,.spec.ephemeralContainers[]?][]?; .name==$c)' <<<"$POD_JSON" >/dev/null; then STATUS_JSON="$(jq -c --arg c "$CONTAINER" '[.status.initContainerStatuses[]?,.status.containerStatuses[]?,.status.ephemeralContainerStatuses[]?] | map(select(.name==$c)) | if length==1 then .[0] else empty end' <<<"$POD_JSON")"; CONTAINER_KIND="$(jq -r --arg c "$CONTAINER" 'if any(.spec.containers[]?; .name==$c) then "regular" elif any(.spec.initContainers[]?; .name==$c) then "init" elif any(.spec.ephemeralContainers[]?; .name==$c) then "ephemeral" else empty end' <<<"$POD_JSON")"; if [ -n "$STATUS_JSON" ] && [ -n "$CONTAINER_KIND" ]; then CONTAINER_ID="$(jq -r '.containerID // "-"' <<<"$STATUS_JSON")"; STARTED_AT="$(jq -r '.state.running.startedAt // "-"' <<<"$STATUS_JSON")"; FINISHED_AT="$(jq -r '.lastState.terminated.finishedAt // .state.terminated.finishedAt // "-"' <<<"$STATUS_JSON")"; WAITING_REASON="$(jq -r '.state.waiting.reason // "-"' <<<"$STATUS_JSON")"; TERMINATED_REASON="$(jq -r '.state.terminated.reason // "-"' <<<"$STATUS_JSON")"; RESTART_COUNT="$(jq -r '.restartCount // 0' <<<"$STATUS_JSON")"; else CONTAINER_ID='-'; STARTED_AT='-'; FINISHED_AT='-'; WAITING_REASON='-'; TERMINATED_REASON='-'; RESTART_COUNT='-'; fi; CONTAINER_READY=true; export CONTAINER CONTAINER_ID CONTAINER_KIND STARTED_AT FINISHED_AT WAITING_REASON TERMINATED_REASON RESTART_COUNT; printf 'CONTAINER_READY=true kind=%s container=%s id=%s running=%s waiting=%s terminated=%s restart=%s\n' "$CONTAINER_KIND" "$CONTAINER" "$CONTAINER_ID" "$STARTED_AT" "$WAITING_REASON" "$TERMINATED_REASON" "$RESTART_COUNT"; else printf '중단: spec에 없는 container 또는 복수 status 후보 container=%s\n' "$CONTAINER" >&2; fi`

**current container kind·status·ID 재조회/대조 helper — 이후 logs/raw endpoint/runtime 직전에 실행**

`refresh_current_container_identity(){ CURRENT_CONTAINER_READY=false; refresh_pod_identity || return 1; CURRENT_POD_JSON="$(kubectl get pod "$POD" -n "$NS" -o json 2>/dev/null)" || { printf '%s\n' '중단: current Pod 재조회 실패' >&2; return 1; }; CURRENT_CONTAINER_KIND="$(jq -r --arg c "$CONTAINER" 'if any(.spec.containers[]?; .name==$c) then "regular" elif any(.spec.initContainers[]?; .name==$c) then "init" elif any(.spec.ephemeralContainers[]?; .name==$c) then "ephemeral" else empty end' <<<"$CURRENT_POD_JSON")"; CURRENT_STATUS_JSON="$(jq -c --arg c "$CONTAINER" '[.status.initContainerStatuses[]?,.status.containerStatuses[]?,.status.ephemeralContainerStatuses[]?] | map(select(.name==$c)) | if length==1 then .[0] else empty end' <<<"$CURRENT_POD_JSON")"; CURRENT_CONTAINER_ID="$(jq -r '.containerID // "-"' <<<"$CURRENT_STATUS_JSON")"; if [ -n "$CURRENT_STATUS_JSON" ] && [ "$CURRENT_CONTAINER_KIND" = "$CONTAINER_KIND" ] && [ "$CURRENT_CONTAINER_ID" = "$CONTAINER_ID" ]; then CURRENT_CONTAINER_READY=true; printf 'CURRENT_CONTAINER_READY=true kind=%s container=%s current_id=%s state=%s\n' "$CURRENT_CONTAINER_KIND" "$CONTAINER" "$CURRENT_CONTAINER_ID" "$(jq -r '(.state|keys[0]) // "-"' <<<"$CURRENT_STATUS_JSON")"; return 0; else unset LOG_READY RBAC_READY API_READY LOG_ENDPOINT_READY NODE_READY RUNTIME_READY PROMQL_READY; printf '중단: current container kind/status/ID mismatch expected_kind=%s actual_kind=%s expected_id=%s actual_id=%s\n' "$CONTAINER_KIND" "${CURRENT_CONTAINER_KIND:--}" "$CONTAINER_ID" "${CURRENT_CONTAINER_ID:--}" >&2; return 1; fi; }; refresh_current_container_identity`

`refresh_current_container_identity_or_invalidate(){ if refresh_current_container_identity; then return 0; else AUTO_READY=false; CONTAINER_READY=false; unset LOG_READY RBAC_READY API_READY LOG_ENDPOINT_READY NODE_READY RUNTIME_READY PROMQL_READY; return 1; fi; }`

**current Pod UID 재조회 gate — 파생값 사용 전에 아래 한 줄 전체를 복사**

`refresh_current_container_identity_or_invalidate`

Pod의 이전 컨테이너 로그를 가져올 수 없는 경우]]로 이동한다. container ID가 `-`면 current stream을 성공으로 해석하지 않는다.

## 2. RBAC와 API subresource 분리

진입 증거는 `Forbidden`, `cannot get resource pods/log` 또는 auth 결과다. 연결 경로는 **작업 PC의 kubectl client → API server HTTPS endpoint → Pod resource 확인 → pods/log subresource 요청 → kubelet stream**이다. `pods` 권한 성공은 `pods/log` 성공을 보장하지 않고, `pods/log` 권한 성공은 kubelet·runtime 로그 존재를 보장하지 않는다.

**Pod·pods/log 권한 확인 — 아래 한 줄 전체를 복사**

`refresh_current_container_identity_or_invalidate`

`RBAC_READY=false; if [ "$AUTO_READY" != true ]; then printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; elif POD_AUTH="$(kubectl auth can-i get "pods/$POD" -n "$NS")" && LOG_AUTH="$(kubectl auth can-i get "pods/$POD" --subresource=log -n "$NS")"; then RBAC_READY=true; printf 'RBAC_READY=true pods=%s pods_log=%s subject=current-kubectl\n' "$POD_AUTH" "$LOG_AUTH"; else printf '%s\n' '중단: auth can-i 조회 실패' >&2; fi`

`no` 또는 `cannot get resource pods/log`이면 [[30. Pod 로그 권한이 거부되는 경우]]로 이동한다. `pods=no`·`pods/log=yes`도 일반 `kubectl logs`의 사전 Pod 조회가 막힐 수 있다. Role·RoleBinding을 임의 생성하거나 cluster-admin을 부여하지 않는다. `yes`는 현재 주체의 권한만 증명한다.

## 3. API server endpoint·audit와 TLS

진입 증거는 API 연결 실패, `connection refused`, `i/o timeout`, `x509` 또는 raw log endpoint 차이다. 연결 경로는 **작업 PC의 kubectl client → kubeconfig가 지정한 API server HTTPS endpoint 또는 proxy → API server의 Pod log handler → kubelet endpoint → runtime → current container**다. API 주소·port·proxy와 kubelet endpoint·port는 서로 다른 역할이며 환경에서 확인하지 않고 10250 같은 기본값을 추측하지 않는다. TLS 검증은 끄지 않는다.

**API endpoint 확인 — 아래 한 줄 전체를 복사**

`refresh_current_container_identity_or_invalidate`

`API_READY=false; LOG_ENDPOINT_READY=false; if [ "$CONTAINER_READY" != true ]; then printf '%s\n' '중단: CONTAINER_READY가 아니다.' >&2; else if kubectl get --raw '/readyz?verbose' >/dev/null 2>&1; then API_READY=true; printf 'API_TRANSPORT=success API_READY=true endpoint=readyz\n'; else printf 'API_TRANSPORT=failure API_READY=false endpoint=readyz\n' >&2; fi; if kubectl get --raw "/api/v1/namespaces/$NS/pods/$POD/log?container=$CONTAINER&tailLines=10&timestamps=true" >/dev/null 2>&1; then LOG_ENDPOINT_READY=true; printf 'LOG_ENDPOINT_TRANSPORT=success LOG_ENDPOINT_READY=true pod=%s uid=%s container=%s\n' "$POD" "$POD_UID" "$CONTAINER"; else printf 'LOG_ENDPOINT_TRANSPORT=failure LOG_ENDPOINT_READY=false pod=%s uid=%s container=%s\n' "$POD" "$POD_UID" "$CONTAINER" >&2; fi; fi`

이 명령은 transport와 client 요청 성공만 표시하며 로그 본문은 버린다. `/readyz` 성공은 API server ready 범위이고 kubelet·Pod log 성공을 보장하지 않는다. `API_READY=true`, `LOG_ENDPOINT_READY=false`면 4절로 이동하고, log endpoint 성공이면 1절의 bounded current-instance 조회로 돌아간다. `404`는 namespace·Pod UID·container status, `400`은 요청 parameter, `403`은 2절, `connection refused`·timeout·`x509`은 API·kubelet 경로 후보다.

HTTP status와 API data는 kubectl raw의 exit code와 섞지 않는다. API audit가 있는 환경에서 platform owner가 실제 저장 위치에 맞춰 다음을 확인한다.

- 시간: audit 시작부터 종료까지
- request: `GET /api/v1/namespaces/NS/pods/POD/log`, `container=CONTAINER`, `responseStatus.code`, `user.username`, `stageTimestamp`
- `200`: API server가 log request를 처리한 범위이며 kubelet response·node 경로로 이동
- `403`: 실행 subject와 `pods/log` RBAC 대조
- `404`·`400`: Pod UID·container status·parameter 대조
- record 없음: audit 비활성·수집 지연 가능성

**audit 시간 등록 — audit owner가 확인한 범위에서 한 번 실행**

`START_AUDIT='PASTE_START_AUDIT_HERE'; END_AUDIT='PASTE_END_AUDIT_HERE'`

TLS certificate verification을 `-k`나 다른 검증 비활성화 옵션으로 우회하지 않는다. audit 원문과 로그 본문을 증거에 저장하지 않는다.

## 4. API server에서 kubelet과 node reachability

진입 증거는 API audit 또는 raw endpoint가 request를 받았지만 kubelet log endpoint가 timeout·connection refused·x509로 실패한 경우다. API server에서 node kubelet까지의 실제 hop은 **API server → 확인된 node address·kubelet endpoint → kubelet log handler → CRI/runtime log source**다. `Node Ready`는 node condition의 보조 증거이며 kubelet log handler·runtime log 파일을 보장하지 않는다.

`unable to retrieve container logs`, `failed to read log`, `connection refused`, timeout, x509를 같은 Pod UID·container ID·시각으로 대조한다. journal 빈 출력은 오류 없음이 아니며 unit·시간·도구·권한·node 범위 오류일 수 있다. node address, kubelet certificate, firewall, kubelet restart와 TLS 설정은 이 문서에서 변경하지 않는다.

## 5. runtime container ID와 log rotation

진입 증거는 kubelet 요청 경로가 정상인데 symlink 대상 또는 log file이 없거나, current Pod status ID와 file/runtime ID가 다른 경우다. 연결 경로는 **작업 PC의 SSH → 확인된 node의 podLogsDir/CRI log path → kubelet이 기록한 file 또는 symlink → 확인된 CRI endpoint → runtime container ID**다. `/var/log/pods`, `/var/log/containers`, containerd socket을 기본값으로 추측하지 않는다.

**runtime ID 계산 후보 — current status의 prefix만 제거하고 아래 한 줄 전체를 복사**

`refresh_current_container_identity_or_invalidate`

`RUNTIME_CONTAINER_ID=''; if [ "$CONTAINER_READY" != true ] || [ "$CONTAINER_ID" = - ]; then printf '%s\n' '중단: current container ID가 없다.' >&2; else RUNTIME_CONTAINER_ID="${CONTAINER_ID#*://}"; if [ -n "$RUNTIME_CONTAINER_ID" ] && [ "$RUNTIME_CONTAINER_ID" != "$CONTAINER_ID" ]; then printf 'RUNTIME_CONTAINER_ID=%s source=%s\n' "$RUNTIME_CONTAINER_ID" "$CONTAINER_ID"; else printf '중단: containerID prefix 또는 값 확인 실패 id=%s\n' "$CONTAINER_ID" >&2; unset RUNTIME_CONTAINER_ID; fi; fi`

`RUNTIME_CONTAINER_ID`는 계산 후보이며 CRI 구현체·endpoint 확인 전에는 runtime command의 대상이 아니다.

**원격 node log path 대조 — 작업 PC의 같은 Bash에서 아래 한 줄 전체를 복사**

`LOG_PATH_REMOTE_READY=false; if [ "$NODE_API_READY" != true ] || [ "$POD_IDENTITY_READY" != true ] || [ "$CONTAINER_READY" != true ] || [ "$JOURNAL_TIME_READY" != true ] || [ -z "$POD_LOGS_DIR" ] || [ -z "$CRI_LOG_PATH" ]; then printf '%s\n' '중단: 원격 log path 검증 전 Pod·container·node·시간·path gate가 필요하다.' >&2; elif ssh -- "$REMOTE_HOST" bash -s -- "$NS" "$POD" "$POD_UID" "$NODE" "$REMOTE_HOST" "$CONTAINER" "$POD_LOGS_DIR" "$CRI_LOG_PATH" <<< 'set -u; ns="$1"; pod="$2"; pod_uid="$3"; node="$4"; expected_host="$5"; container="$6"; logs_dir="$7"; cri_path="$8"; missing=""; for tool in kubectl hostname cat readlink ls; do command -v "$tool" >/dev/null 2>&1 || missing="$missing $tool"; done; if [ -n "$missing" ]; then printf "중단: remote log path 도구 확인 실패 missing=%s\\n" "$missing" >&2; exit 1; fi; actual_host="$(hostname -f 2>/dev/null || hostname)"; api_node="$(kubectl get node "$node" -o "jsonpath={.metadata.name}" 2>/dev/null)"; api_machine="$(kubectl get node "$node" -o "jsonpath={.status.nodeInfo.machineID}" 2>/dev/null)"; local_machine="$(cat /etc/machine-id 2>/dev/null)"; current_uid="$(kubectl get pod "$pod" -n "$ns" -o "jsonpath={.metadata.uid}" 2>/dev/null)"; current_node="$(kubectl get pod "$pod" -n "$ns" -o "jsonpath={.spec.nodeName}" 2>/dev/null)"; if [ "$api_node" = "$node" ] && [ "$current_uid" = "$pod_uid" ] && [ "$current_node" = "$node" ] && [ "$api_machine" = "$local_machine" ] && [ "$actual_host" = "$expected_host" ]; then printf "LOG_PATH_REMOTE_READY=true host=%s pod_uid=%s node=%s container=%s machine_id_verified=true\\n" "$actual_host" "$current_uid" "$current_node" "$container"; readlink -f "$cri_path"; ls -l "$logs_dir/${ns}_${pod}_${pod_uid}/$container"; else printf "중단: remote log path UID/node/machine identity/host gate 실패 pod_uid=%s current_uid=%s node=%s current_node=%s host=%s expected_host=%s\\n" "$pod_uid" "$current_uid" "$node" "$current_node" "$actual_host" "$expected_host" >&2; exit 1; fi' ; then LOG_PATH_REMOTE_READY=true; else printf '%s\n' '중단: self-contained SSH log path handoff 실패' >&2; fi`

symlink와 실제 파일이 있고 시각·container ID가 맞으면 kubelet/runtime read 권한·endpoint 응답을 다시 확인한다. symlink 대상 또는 file이 없으면 log GC·rotation·삭제·보존 한계 후보다. 파일 복사·삭제·복원이나 rotation 설정 변경을 하지 말고 6절로 이동한다. status ID와 file ID가 다르면 재시작·Pod 재생성·runtime 시각을 대조한다.

**CRI endpoint 선택값 등록 — 실제 kubelet 설정과 node owner 승인을 확인한 뒤 한 번 실행**

`CRI_RUNTIME_ENDPOINT='PASTE_CRI_RUNTIME_ENDPOINT_HERE'`

**원격 CRI 도구·endpoint·inspect — 작업 PC의 같은 Bash에서 아래 한 줄 전체를 복사**

`RUNTIME_READY=false; if [ "$NODE_API_READY" != true ] || [ "$POD_IDENTITY_READY" != true ] || [ "$CONTAINER_READY" != true ] || [ "$LOG_PATH_REMOTE_READY" != true ] || [ -z "$RUNTIME_CONTAINER_ID" ] || [ -z "$CRI_RUNTIME_ENDPOINT" ]; then printf '%s\n' '중단: 원격 runtime inspect 전 node·Pod·container·log path·runtime gate가 필요하다.' >&2; elif ssh -- "$REMOTE_HOST" bash -s -- "$NS" "$POD" "$POD_UID" "$NODE" "$REMOTE_HOST" "$CONTAINER" "$CONTAINER_KIND" "$CONTAINER_ID" "$CRI_RUNTIME_ENDPOINT" "$RUNTIME_CONTAINER_ID" <<< 'set -u; ns="$1"; pod="$2"; pod_uid="$3"; node="$4"; expected_host="$5"; container="$6"; kind="$7"; expected_id="$8"; endpoint="$9"; runtime_id="${10}"; missing=""; for tool in kubectl hostname cat crictl jq; do command -v "$tool" >/dev/null 2>&1 || missing="$missing $tool"; done; if [ -n "$missing" ]; then printf "중단: remote runtime 도구 확인 실패 missing=%s\\n" "$missing" >&2; exit 1; fi; case "$kind" in regular) status_path="{.status.containerStatuses[?(@.name==\"$container\")].containerID}";; init) status_path="{.status.initContainerStatuses[?(@.name==\"$container\")].containerID}";; ephemeral) status_path="{.status.ephemeralContainerStatuses[?(@.name==\"$container\")].containerID}";; *) printf "중단: 알 수 없는 container kind=%s\\n" "$kind" >&2; exit 1;; esac; actual_host="$(hostname -f 2>/dev/null || hostname)"; api_node="$(kubectl get node "$node" -o "jsonpath={.metadata.name}" 2>/dev/null)"; api_machine="$(kubectl get node "$node" -o "jsonpath={.status.nodeInfo.machineID}" 2>/dev/null)"; local_machine="$(cat /etc/machine-id 2>/dev/null)"; current_uid="$(kubectl get pod "$pod" -n "$ns" -o "jsonpath={.metadata.uid}" 2>/dev/null)"; current_node="$(kubectl get pod "$pod" -n "$ns" -o "jsonpath={.spec.nodeName}" 2>/dev/null)"; current_id="$(kubectl get pod "$pod" -n "$ns" -o "jsonpath=$status_path" 2>/dev/null)"; if [ "$api_node" = "$node" ] && [ "$current_uid" = "$pod_uid" ] && [ "$current_node" = "$node" ] && [ "$current_id" = "$expected_id" ] && [ "$expected_id" != - ] && [ "$api_machine" = "$local_machine" ] && [ "$actual_host" = "$expected_host" ] && RUNTIME_JSON="$(crictl --runtime-endpoint="$endpoint" inspect "$runtime_id" 2>/dev/null)" && jq -e ".status.id != null" <<<"$RUNTIME_JSON" >/dev/null; then printf "RUNTIME_READY=true host=%s pod_uid=%s node=%s container=%s container_id=%s machine_id_verified=true\\n" "$actual_host" "$current_uid" "$node" "$container" "$expected_id"; jq -c "{id:.status.id,state:.status.state,createdAt:.status.createdAt,startedAt:.status.startedAt,finishedAt:.status.finishedAt,logPath:.status.logPath}" <<<"$RUNTIME_JSON"; else printf "중단: remote runtime UID/node/container ID/machine identity/host/inspect gate 실패 pod_uid=%s current_uid=%s node=%s current_node=%s expected_id=%s current_id=%s host=%s expected_host=%s endpoint=%s id=%s\\n" "$pod_uid" "$current_uid" "$node" "$current_node" "$expected_id" "$current_id" "$actual_host" "$expected_host" "$endpoint" "$runtime_id" >&2; exit 1; fi' ; then RUNTIME_READY=true; else printf '중단: self-contained SSH runtime handoff 실패 endpoint=%s id=%s\\n' "$CRI_RUNTIME_ENDPOINT" "$RUNTIME_CONTAINER_ID" >&2; fi`

`jq` schema가 다르거나 inspect 실패면 전체 결과를 저장하지 말고 runtime owner에게 state·log path·created/finished 시각만 요청한다. `RUNTIME_READY=true`는 runtime metadata 조회 성공이며 로그 bytes 보존·application 정상·kubelet stream 성공을 보장하지 않는다.

## 6. 중앙 로그 수집 fallback

진입 증거는 node file이 rotation·삭제됐거나 kubelet endpoint가 복구되지 않은 경우다. 중앙 수집기에서 **namespace·Pod UID·Pod 이름·container 이름·runtime container ID·node·START_RFC3339부터 조사 종료 시각**을 모두 필터로 사용한다. 증상 필터는 `panic|fatal|error|exception|timeout|refused|denied|permission|oom|killed`다.

UID와 container ID가 같은 current instance의 bounded 결과가 있으면 원인 분석으로 이동한다. 결과 없음은 보존 기간·수집 지연·multiline parsing·collector input/output·UID filter 오류를 구분해야 하며 로그가 없었다는 뜻이 아니다. 중앙 수집기 원문을 런북 증거 파일에 저장하지 않고, 민감정보가 보이면 조회·공유를 중단하고 필요한 오류 문자열만 제한된 위치에 기록한다.

## 상태 변경 gate

이 문서는 읽기 전용 진단만 제공한다. Pod 삭제, rollout restart, patch, scale, kubelet 재시작, node drain, log file 조작, TLS 검증 비활성화를 로그 문제 해결책으로 실행하지 않는다. 별도 변경은 다음을 모두 충족한 승인 절차에서만 검토한다.

- **Trigger:** 원인 layer, 영향 범위, current instance의 UID·container ID·로그 보존 상태와 service owner가 확인됐다.
- **Authority/approval:** API server·namespace·Pod UID·container, 최소 권한, 변경 창, 증거 보존, 승인자와 rollback을 대조했다.
- **대상·중단:** 승인된 대상만 바꾸며 Ready 감소, restart 증가, 새 Warning, 다른 consumer 영향 또는 민감정보 노출 시 중단한다.
- **효과의 한계:** 로그 접근 회복은 application 정상이나 과거 로그 복구를 보장하지 않는다.

## 정상화와 증거

정상화는 `application 기능 → current container stream → API status·pods/log → API server→kubelet → node file/symlink → runtime metadata → object identity` 역순으로 확인한다.

**Pod identity·현재 container 상태 — 아래 한 줄 전체를 복사**

`refresh_current_container_identity_or_invalidate`

`NORMAL_READY=false; NORMAL_JSON=''; NORMAL_UID=''; NORMAL_STATUS=''; if [ "$CONTAINER_READY" != true ] || [ "$POD_IDENTITY_READY" != true ] || [ "$CONTAINER_KIND" != regular ] && [ "$CONTAINER_KIND" != init ] && [ "$CONTAINER_KIND" != ephemeral ]; then printf '%s\n' '중단: CONTAINER_READY·Pod UID gate·container kind가 필요하다.' >&2; elif NORMAL_JSON="$(kubectl get pod "$POD" -n "$NS" -o json 2>/dev/null)"; then NORMAL_UID="$(jq -r --arg c "$CONTAINER" --arg kind "$CONTAINER_KIND" '. as $pod | (if $kind=="regular" then ($pod.status.containerStatuses // []) elif $kind=="init" then ($pod.status.initContainerStatuses // []) else ($pod.status.ephemeralContainerStatuses // []) end) as $statuses | if ([$statuses[]? | select(.name==$c)] | length)==1 then $pod.metadata.uid else empty end' <<<"$NORMAL_JSON")"; NORMAL_STATUS="$(jq -c --arg c "$CONTAINER" --arg kind "$CONTAINER_KIND" '(if $kind=="regular" then (.status.containerStatuses // []) elif $kind=="init" then (.status.initContainerStatuses // []) else (.status.ephemeralContainerStatuses // []) end) | map(select(.name==$c)) | if length==1 then .[0] else empty end' <<<"$NORMAL_JSON")"; if [ -n "$NORMAL_STATUS" ] && [ "$NORMAL_UID" = "$POD_UID" ]; then NORMAL_READY=true; printf 'NORMAL_READY=true kind=%s pod_uid=%s container=%s status=' "$CONTAINER_KIND" "$NORMAL_UID" "$CONTAINER"; jq -c '{name,ready,restartCount,state,lastState,containerID}' <<<"$NORMAL_STATUS"; else unset CONTAINER_READY LOG_READY PROMQL_READY; printf '중단: 정상화 재조회 UID mismatch 또는 kind별 status 없음 expected=%s actual=%s kind=%s\n' "$POD_UID" "${NORMAL_UID:--}" "$CONTAINER_KIND" >&2; fi; else unset CONTAINER_READY LOG_READY PROMQL_READY; printf '%s\n' '중단: 정상화 Pod 재조회 실패' >&2; fi`

current Pod UID와 올바른 container의 log 접근 성공, 원하는 Ready 상태, 관찰 기간 restartCount 증가 중단, 같은 오류 반복 없음, 새 Warning 없음, 실제 서비스 요청 또는 핵심 기능 성공을 각각 확인한다. `Running`, `Ready`, `pods/log auth yes`, HTTP 200 또는 stream process 생존은 다음 hop과 application 기능의 정상화를 단독 보장하지 않는다. 중앙 수집기에서 과거 log를 찾은 것은 kubelet endpoint 복구와 별도로 기록한다.

보존 대상은 실행 시각, 비밀 없는 context 식별자, namespace, Pod/UID, container, node, runtime ID, phase·state·lastState·restartCount의 필요한 필드, API audit status, kubelet의 비식별 오류 구간, file·symlink 존재 여부, 중앙 수집기 조회 시간·filter·결과 유무다. 로그 원문·Secret·token·개인키·개인정보는 보존하지 않는다.

## Prometheus 빠른 관측

KSM metric과 실제 label이 수집되는 환경에서만 사용한다. metric 부재, label 불일치, query 범위 오류와 API 조회 실패를 구분한다. 이름을 regex에 넣을 때 escape한 변수를 만들고 완성 query만 출력한다.

**PromQL selector 계산 — 같은 Bash에서 아래 한 줄 전체를 복사**

`refresh_current_container_identity_or_invalidate`

`unset POD_RE CONTAINER_RE PROMQL_READY; POD_RE="$(printf '%s' "$POD" | sed 's/[][\\.^$*+?(){}|]/\\&/g')"; CONTAINER_RE="$(printf '%s' "$CONTAINER" | sed 's/[][\\.^$*+?(){}|]/\\&/g')"; if [ "$CONTAINER_READY" = true ] && [ -n "$POD_RE" ] && [ -n "$CONTAINER_RE" ]; then PROMQL_READY=true; printf 'PROMQL_READY=true pod_re=%s container_re=%s\n' "$POD_RE" "$CONTAINER_RE"; else printf '%s\n' '중단: CONTAINER_READY 또는 regex 계산 실패' >&2; fi`

**Pod·container info PromQL 생성 — 아래 한 줄 전체를 복사**

`refresh_current_container_identity_or_invalidate`

`if [ "$PROMQL_READY" != true ] || [ "$POD_IDENTITY_READY" != true ] || [ "$CONTAINER_KIND" != regular ]; then printf '%s\n' '중단: PROMQL_READY·Pod UID gate 또는 regular container가 아니다. init/ephemeral에는 kube_pod_container_* PromQL을 적용하지 않는다.' >&2; else printf 'kube_pod_info{namespace="%s",pod=~"%s",uid="%s"}\nkube_pod_container_info{namespace="%s",pod=~"%s",uid="%s",container=~"%s"}\n' "$NS" "$POD_RE" "$POD_UID" "$NS" "$POD_RE" "$POD_UID" "$CONTAINER_RE"; fi`

**재시작 증가 PromQL 생성 — 아래 한 줄 전체를 복사**

`refresh_current_container_identity_or_invalidate`

`if [ "$PROMQL_READY" != true ] || [ "$POD_IDENTITY_READY" != true ] || [ "$CONTAINER_KIND" != regular ]; then printf '%s\n' '중단: PROMQL_READY·Pod UID gate 또는 regular container가 아니다. init/ephemeral에는 kube_pod_container_* PromQL을 적용하지 않는다.' >&2; else printf 'sum by(namespace,pod,uid,container)(increase(kube_pod_container_status_restarts_total{namespace="%s",pod=~"%s",uid="%s",container=~"%s"}[15m]))\n' "$NS" "$POD_RE" "$POD_UID" "$CONTAINER_RE"; fi`

query 출력이 비면 정상·재시작 0·로그 오류 없음으로 해석하지 않는다. `kubectl logs` stream, node file, rotation과 RBAC는 PromQL로 판정할 수 없으며 API audit·kubelet·runtime·중앙 수집기 evidence로 분기한다.
