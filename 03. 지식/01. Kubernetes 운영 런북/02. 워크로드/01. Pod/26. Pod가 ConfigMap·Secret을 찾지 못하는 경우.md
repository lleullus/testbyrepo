# Pod가 ConfigMap·Secret을 찾지 못하는 경우

## 입력값과 빠른 수집

최초 입력은 namespace와 Pod뿐이다. Pod UID, node, phase, owner, 참조 경로와 관측 시각은 API 자동값이다. object 이름·kind·key·volume path와 journal/audit 시간은 출력 확인 뒤 운영자가 선택한다. Secret 값·base64 data·token은 어떤 입력값이나 증거에도 넣지 않는다.

| 구분 | 값 | 출처와 유효성 gate |
|---|---|---|
| 최초 입력 | `NS`, `POD` | 승인된 namespace와 정확한 Pod 이름을 한 번 입력하고 exact-name API 조회가 성공해야 한다. |
| API 자동값 | `POD_UID`, `NODE`, `PHASE`, `OWNER_KIND`, `OWNER_NAME`, `POD_JSON`, `EVENTS_JSON`, `OBSERVED_AT` | Pod와 UID 제한 Event API 조회가 모두 성공해야 등록한다. |
| 계산 후보 | `OBJECT_RE`, `POD_IDENTITY_READY` | 선택한 object 이름을 regex escape한 bounded selector와 현재 Pod UID gate다. |
| 운영자 선택값 | `REF_MODE`, `REF_CONTAINER`, `REF_KIND`, `REF_NAME`, `REF_KEY`, `MOUNT_PATH`, journal/audit 시간, `KUBELET_SERVICE`, `REMOTE_HOST` | 자동 수집의 container·initContainer·volume·projected 관계와 실제 node host를 보고 해당 분기에서 선택한다. 복수 참조를 첫 번째로 고르지 않는다. |

### 1. 실행 위치·도구·대상 지정

kubectl 명령은 승인된 작업 PC 또는 bastion의 **같은 Bash 터미널**에서 실행한다. `sh`, PowerShell, CMD로 바꾸거나 새 Bash를 열면 gate와 변수 상태가 사라진다. Kubernetes API에는 Pod·Event·ConfigMap·Secret을 읽고 필요한 경우 `pods`와 `pods/log`가 아닌 object 접근 여부를 확인할 권한이 필요하다. node journal은 작업 PC 변수에 의존하지 않는 승인된 SSH 원격 Bash에서 Pod UID·Node machine identity·object·시간 gate를 다시 검증한다. Secret object 조회가 `Forbidden`이면 권한을 넓히지 않고 RBAC·audit owner로 이관한다.

**Bash·필수 도구 확인 — 아래 한 줄 전체를 복사**

`TOOLS_READY=false; MISSING_TOOLS=''; if [ -z "${BASH_VERSION:-}" ]; then printf '%s\n' '중단: 같은 Bash에서 실행한다.' >&2; else for TOOL in kubectl jq grep sed date head mktemp ssh; do command -v "$TOOL" >/dev/null 2>&1 || MISSING_TOOLS="$MISSING_TOOLS $TOOL"; done; if [ -z "$MISSING_TOOLS" ]; then TOOLS_READY=true; printf 'TOOLS_READY=true Bash=%s\n' "$BASH_VERSION"; else printf '중단: 없는 도구=%s\n' "$MISSING_TOOLS" >&2; fi; fi`

`TOOLS_READY=true`가 아니면 다음 단계로 진행하지 않는다. jq가 없으면 Secret 원문이나 전체 Pod YAML을 대체 수집하지 말고 승인된 UI 또는 owner에게 비밀 없는 필드 확인을 요청한다.

**최초 입력·이전 상태 초기화 — 같은 Bash에서 한 번 실행**

`unset INPUT_READY AUTO_READY SELECTION_READY OBJECT_READY KEY_READY VOLUME_READY KUBELET_READY PROMQL_READY POD_UID NODE PHASE OWNER_KIND OWNER_NAME POD_JSON EVENTS_JSON OBJECT_JSON OWNER_JSON OBSERVED_AT REF_KIND REF_NAME REF_KEY MOUNT_PATH START_JOURNAL END_JOURNAL START_AUDIT END_AUDIT KUBELET_SERVICE OBJECT_RE; NS='PASTE_NAMESPACE_HERE'; POD='PASTE_POD_HERE'; INPUT_READY=false; if [ "$TOOLS_READY" != true ]; then printf '%s\n' '중단: 도구 확인을 먼저 통과한다.' >&2; elif [ -z "$NS" ] || [ -z "$POD" ]; then printf '%s\n' '중단: NS와 POD를 입력한다.' >&2; elif kubectl get pod "$POD" -n "$NS" -o name >/dev/null 2>&1; then INPUT_READY=true; export NS POD; printf 'INPUT_READY=true namespace=%s pod=%s\n' "$NS" "$POD"; else printf '중단: 정확한 Pod 조회 실패 namespace=%s pod=%s\n' "$NS" "$POD" >&2; fi`

`unset POD_IDENTITY_READY NODE_API_READY NODE_API_JSON NODE_HOST NODE_REMOTE_READY NODE_MACHINE_ID NODE_REMOTE_MACHINE_ID JOURNAL_TIME_READY JOURNAL_START_EPOCH JOURNAL_END_EPOCH JOURNAL_START_CANONICAL JOURNAL_END_CANONICAL AUDIT_TIME_READY AUDIT_START_EPOCH AUDIT_END_EPOCH AUDIT_START_CANONICAL AUDIT_END_CANONICAL`

`INPUT_READY=true`가 아니면 namespace·Pod 이름·권한을 확인하고 이후 단계로 진행하지 않는다.

### 2. API 자동 수집

**Pod·Event·참조 경로 자동 수집 — 아래 한 줄 전체를 복사**

`unset AUTO_READY POD_UID NODE PHASE OWNER_KIND OWNER_NAME POD_JSON EVENTS_JSON OBSERVED_AT; AUTO_READY=false; if [ "$INPUT_READY" != true ]; then printf '%s\n' '중단: INPUT_READY가 아니다.' >&2; elif POD_JSON="$(kubectl get pod "$POD" -n "$NS" -o json)" && POD_UID_TMP="$(jq -r '.metadata.uid // empty' <<<"$POD_JSON")" && [ -n "$POD_UID_TMP" ] && EVENTS_JSON="$(kubectl get events -n "$NS" --field-selector "involvedObject.kind=Pod,involvedObject.name=$POD,involvedObject.uid=$POD_UID_TMP" -o json)" && OBSERVED_AT_TMP="$(date -u '+%Y-%m-%dT%H:%M:%SZ')"; then NODE_TMP="$(jq -r '.spec.nodeName // "-"' <<<"$POD_JSON")"; PHASE_TMP="$(jq -r '.status.phase // "-"' <<<"$POD_JSON")"; OWNER_KIND_TMP="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true) | .kind][0] // "-"' <<<"$POD_JSON")"; OWNER_NAME_TMP="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true) | .name][0] // "-"' <<<"$POD_JSON")"; POD_UID="$POD_UID_TMP"; NODE="$NODE_TMP"; PHASE="$PHASE_TMP"; OWNER_KIND="$OWNER_KIND_TMP"; OWNER_NAME="$OWNER_NAME_TMP"; OBSERVED_AT="$OBSERVED_AT_TMP"; AUTO_READY=true; export POD_UID NODE PHASE OWNER_KIND OWNER_NAME OBSERVED_AT; jq -r '"=== Pod ===\n이름: \(.metadata.name)\nUID: \(.metadata.uid)\n노드: \(.spec.nodeName // "미할당")\n상태: \(.status.phase // "-")\n시작 시각: \(.status.startTime // .metadata.creationTimestamp // "-")\n소유자: \(.metadata.ownerReferences[]? | select(.controller==true) | (.kind+"/"+.name) // "-")\n"' <<<"$POD_JSON"; jq -r '[.spec.initContainers[]?,.spec.containers[]?] | .[] as $c | "=== 참조 컨테이너 ===\n컨테이너: \($c.name)\n" + ([ $c.env[]? | if .valueFrom.configMapKeyRef then "env → ConfigMap/\(.valueFrom.configMapKeyRef.name) key=\(.valueFrom.configMapKeyRef.key) optional=\(.valueFrom.configMapKeyRef.optional // false)" elif .valueFrom.secretKeyRef then "env → Secret/\(.valueFrom.secretKeyRef.name) key=\(.valueFrom.secretKeyRef.key) optional=\(.valueFrom.secretKeyRef.optional // false)" else empty end ] + [ $c.envFrom[]? | if .configMapRef then "envFrom → ConfigMap/\(.configMapRef.name) optional=\(.configMapRef.optional // false) prefix=\(.prefix // "")" elif .secretRef then "envFrom → Secret/\(.secretRef.name) optional=\(.secretRef.optional // false) prefix=\(.prefix // "")" else empty end ] | join("\n"))' <<<"$POD_JSON"; jq -r '.spec.volumes[]? | "=== 참조 볼륨 ===\n볼륨: \(.name)\n" + (if .configMap then "ConfigMap/\(.configMap.name) optional=\(.configMap.optional // false) items=" + ([.configMap.items[]?.key] | join(",")) elif .secret then "Secret/\(.secret.secretName) optional=\(.secret.optional // false) items=" + ([.secret.items[]?.key] | join(",")) elif .projected then ("Projected sources:\n" + ([.projected.sources[]? | if .configMap then "  ConfigMap/\(.configMap.name) optional=\(.configMap.optional // false) items=" + ([.configMap.items[]?.key] | join(",")) elif .secret then "  Secret/\(.secret.name) optional=\(.secret.optional // false) items=" + ([.secret.items[]?.key] | join(",")) elif .serviceAccountToken then "  serviceAccountToken path=\(.serviceAccountToken.path)" elif .downwardAPI then "  downwardAPI paths=" + ([.downwardAPI.items[]?.path] | join(",")) else "  other projected source" end] | join("\n"))) elif .emptyDir then "emptyDir" else "other source" end) + "\n"' <<<"$POD_JSON"; if [ "$(jq '.items|length' <<<"$EVENTS_JSON")" -eq 0 ]; then printf '%s\n' '=== Event ===' '결과: 없음 (정상·오류 없음으로 해석하지 않음)'; else jq -r '.items | sort_by(.eventTime // .lastTimestamp // .firstTimestamp // .metadata.creationTimestamp)[] | "=== Event ===\n이벤트 UID: \(.metadata.uid // "-")\n대상 UID: \(.involvedObject.uid // "-")\n시각: \(.eventTime // .lastTimestamp // .firstTimestamp // .metadata.creationTimestamp // "-")\n유형/사유: \(.type // "-")/\(.reason // "-")\n메시지: \(.message // "-")\n"' <<<"$EVENTS_JSON"; fi; printf 'AUTO_READY=true 관측 시각=%s\n' "$OBSERVED_AT"; else unset POD_UID NODE PHASE OWNER_KIND OWNER_NAME POD_JSON EVENTS_JSON OBSERVED_AT; printf '%s\n' '중단: Pod·Event API 조회 또는 필수 identity 추출 실패' >&2; fi`

예상 출력은 container와 initContainer별 `env`, `envFrom`, object name, key, optional, prefix를 보존하고 volume·projected source별 object·items key·path 관계를 보존해야 한다.

```text
=== Container 참조 ===
Container: api
env → ConfigMap/api-config key=DATABASE_HOST optional=false
envFrom → Secret/api-credentials optional=false prefix=DB_
=== Volume 참조 ===
Volume: config
ConfigMap/api-config optional=false items=app.yaml
=== Event ===
대상 UID: 11111111-2222-3333-4444-555555555555
시각: 2026-07-29T09:01:00Z
유형/Reason: Warning/CreateContainerConfigError
```

`AUTO_READY=true`와 Pod UID가 확인돼야 다음으로 간다. Event가 없거나 빈 출력은 오류 없음의 증거가 아니다. 이후 Event 판단은 이 UID 제한 결과와 실제 시각을 사용하며 다른 이름으로 재생성된 Pod를 섞지 않는다.

**Pod UID 재조회 gate — 파생값 사용 전에 아래 한 줄 전체를 복사**

`refresh_pod_identity(){ local current; POD_IDENTITY_READY=false; CURRENT_POD_UID="$(kubectl get pod "$POD" -n "$NS" -o jsonpath='{.metadata.uid}' 2>/dev/null)"; if [ "$AUTO_READY" = true ] && [ -n "$CURRENT_POD_UID" ] && [ "$CURRENT_POD_UID" = "$POD_UID" ]; then POD_IDENTITY_READY=true; printf 'POD_IDENTITY_READY=true uid=%s\n' "$CURRENT_POD_UID"; return 0; else unset AUTO_READY OBJECT_READY KEY_READY VOLUME_READY KUBELET_READY PROMQL_READY; printf '중단: Pod UID mismatch 또는 재조회 실패 expected=%s actual=%s\n' "$POD_UID" "${CURRENT_POD_UID:--}" >&2; return 1; fi; }; refresh_pod_identity`

helper가 실패하거나 `POD_IDENTITY_READY=true`가 아니면 다음 파생 명령을 실행하지 않는다. 각 상세 분기 직전에 helper를 다시 실행하고, 실패 시 helper가 무효화한 downstream gate를 그대로 유지한다.

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | Pod가 `env`, `envFrom`, `valueFrom`, ConfigMap·Secret volume 또는 `projected` volume을 참조하지만 object·key·주입 결과가 없어 시작 실패가 보이는 경우 |
| 적용 | 대상 namespace, Pod UID와 참조 방식·object·key·path를 확인할 수 있는 경우 |
| 제외 | volume attach/PVC/CSI가 최초 원인이면 [[25. Pod 이벤트에 FailedMount·FailedAttachVolume이 기록된 경우]], 참조 이름·key가 CreateContainerConfigError의 일반 경계라면 [[09. Pod STATUS가 CreateContainerConfigError인 경우]], `pods/log` 권한이면 [[30. Pod 로그 권한이 거부되는 경우]]로 이동한다. |

검색 문자열: `configmap not found`, `secret not found`, `CreateContainerConfigError`, `FailedMount`, `MountVolume.SetUp failed`, `Unable to mount volumes`, `optional`, `envFrom`, `valueFrom`, `projected`, `items`.

Secret 동기화 구현체, CSI Secret Store, Admission 정책은 확인된 구현체 절차가 없으면 추측하지 않는다.

## 최초 확인

진입 판단을 통과하고 `AUTO_READY=true`일 때만 실행한다.

**Pod 상세 확인 — 아래 한 줄 전체를 복사**

`refresh_pod_identity`

`if [ "$AUTO_READY" != true ]; then printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; else kubectl describe pod "$POD" -n "$NS"; fi`

`describe`에서 실패 container, `CreateContainerConfigError`·`FailedMount`, 참조 object·key와 첫 실패 message를 본다. 명령 성공은 API object를 읽었다는 뜻이며 object 존재·key 유효·kubelet 주입·application 정상은 보장하지 않는다.

**UID 제한 Event 확인 — 아래 한 줄 전체를 복사**

`refresh_pod_identity`

`if [ "$AUTO_READY" != true ]; then printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; else jq -r '.items | sort_by(.eventTime // .lastTimestamp // .firstTimestamp // .metadata.creationTimestamp)[] | "시각=\(.eventTime // .lastTimestamp // .firstTimestamp // .metadata.creationTimestamp // "-") reason=\(.reason // "-") message=\(.message // "-")"' <<<"$EVENTS_JSON"; fi`

실제로 채워진 시각과 같은 Pod UID의 첫 NotFound·key·projection 오류를 본다. `CREATED` 또는 집계된 LAST만으로 원인을 확정하지 않는다.

## 관측별 진단 경로

| 지금 보이는 것 | 먼저 볼 것 | 그다음 어디를 볼지 | 상세 절 |
|---|---|---|---|
| `NotFound` 또는 object not found | 참조 이름과 Pod namespace | object 존재·namespace·선언 원본 | [[#1. 참조 object의 이름과 namespace\|object·namespace 진단]] |
| object는 있으나 key 또는 `items[].key`가 없음 | `valueFrom`, `envFrom`, volume items | key 집합·source별 optional | [[#2. valueFrom·volume items와 key\|key 진단]] |
| `envFrom` 실패 또는 일부 환경변수 누락 | 전체 key 집합·prefix·이름 충돌 | application 시작 계약 | [[#3. envFrom과 실제 주입 계약\|envFrom 진단]] |
| `FailedMount`, `projected`, `MountVolume.SetUp failed` | 모든 projected source·items·target path | kubelet 로그와 volume setup | [[#4. 일반 volume과 projected volume\|volume 진단]] · [[#5. kubelet과 API audit 증거\|kubelet·audit 진단]] |
| object·key는 맞지만 앱이 시작 후 실패 | 실제 주입 이름·형식·빈 값 처리 | application 로그·외부 dependency | [[#3. envFrom과 실제 주입 계약\|주입 계약 진단]] |
| API audit가 `403` 또는 `404` | request resource·namespace·subject | RBAC·이름 오류와 kubelet | [[#5. kubelet과 API audit 증거\|audit 진단]] |

표는 길 안내다. object가 있다는 성공은 key·volume setup·kubelet 권한·application 정상화를 보장하지 않는다.

## 1. 참조 object의 이름과 namespace

진입 증거는 Event·describe의 object 이름과 자동 수집된 Pod 참조가 일치하는 것이다. 연결 경로는 **작업 PC의 kubectl client → API server HTTPS endpoint → Pod namespace의 ConfigMap·Secret object**다. ConfigMap·Secret 참조는 다른 namespace를 가리키지 않는다. API server에 도달한 성공과 object의 data key 존재는 별개다.

**운영자 선택값 등록 — 자동 출력에서 조사할 하나의 참조를 고른 뒤 해당 분기에서 한 번 실행**

`REF_MODE='PASTE_REFERENCE_MODE_HERE'; REF_CONTAINER='PASTE_REFERENCE_CONTAINER_HERE'; REF_KIND='PASTE_CONFIGMAP_OR_SECRET_HERE'; REF_NAME='PASTE_OBJECT_NAME_HERE'; REF_KEY='PASTE_KEY_OR_MINUS_HERE'`

`REF_KIND`는 `configmap` 또는 `secret`이어야 하며 `REF_KEY`에 Secret value나 base64 data를 넣지 않는다. envFrom 전체 또는 volume source 전체를 확인해 특정 key가 필요 없으면 `-`를 사용한다. 복수 object가 있으면 Event·container·volume 관계와 실제 시각을 대조한 뒤 하나를 선택한다.

`REF_MODE`는 `env`, `envFrom`, `volume` 중 하나다. `REF_CONTAINER`는 자동 수집에서 확인한 정확한 regular 또는 init container 이름이며, volume mode에서만 `MOUNT_PATH`를 추가로 선택한다. 선택 object가 선택 container의 선언에 실제로 연결되지 않으면 다음 gate로 진행하지 않는다.

**참조 object 검증 — 아래 한 줄 전체를 복사**

`refresh_pod_identity`

`OBJECT_READY=false; if [ "$AUTO_READY" != true ]; then printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; elif [ "$REF_KIND" != configmap ] && [ "$REF_KIND" != secret ]; then printf '중단: REF_KIND가 configmap 또는 secret이 아님 kind=%s\n' "$REF_KIND" >&2; elif OBJECT_JSON="$(kubectl get "$REF_KIND" "$REF_NAME" -n "$NS" -o json 2>/dev/null)" && [ "$(jq -r '.metadata.namespace // empty' <<<"$OBJECT_JSON")" = "$NS" ]; then OBJECT_READY=true; export REF_KIND REF_NAME REF_KEY; printf 'OBJECT_READY=true kind=%s name=%s namespace=%s uid=%s created=%s\n' "$REF_KIND" "$REF_NAME" "$NS" "$(jq -r '.metadata.uid' <<<"$OBJECT_JSON")" "$(jq -r '.metadata.creationTimestamp' <<<"$OBJECT_JSON")"; else printf 'object 조회 실패: NotFound·Forbidden·namespace mismatch를 구분하고 Secret 권한을 넓히지 않는다. kind=%s name=%s namespace=%s\n' "$REF_KIND" "$REF_NAME" "$NS" >&2; fi`

`NotFound`는 이름 오기입·다른 namespace·생성 순서 후보다. `Forbidden`은 현재 운영자 권한 또는 API 정책 문제로, object를 다른 namespace에 복제하거나 Secret 권한을 넓히지 않는다. object가 존재하면 2절의 key 확인으로 이동한다. `Running`이나 `Ready`가 object 접근 성공을 의미하지 않는다.

**현재 운영자 권한 확인 — 아래 한 줄 전체를 복사**

`refresh_pod_identity`

`if [ "$OBJECT_READY" != true ]; then printf '%s\n' '중단: OBJECT_READY가 아니다.' >&2; elif [ "$REF_KIND" = configmap ]; then kubectl auth can-i get "configmaps/$REF_NAME" -n "$NS"; else kubectl auth can-i get "secrets/$REF_NAME" -n "$NS"; fi`

`yes`는 현재 kubectl 주체의 권한만 보여 주며 kubelet subject·실제 요청 성공을 보장하지 않는다. `no` 또는 계속된 `Forbidden`이면 API audit와 RBAC 담당자로 이동한다.

## 2. valueFrom·volume items와 key

진입 증거는 object는 존재하지만 `valueFrom` 또는 volume `items[].key` 오류가 같은 object와 함께 보이는 것이다. 최초 필요값 `REF_KEY`는 운영자 선택값이며 자동 수집의 선언과 대조한다. Secret은 key 이름만 출력하고 값을 읽지 않는다.

**object key 집합 확인 — 아래 한 줄 전체를 복사**

`refresh_pod_identity`

`if [ "$OBJECT_READY" != true ]; then printf '%s\n' '중단: OBJECT_READY가 아니다.' >&2; elif [ "$REF_KIND" = configmap ]; then jq -r '"ConfigMap data keys:" + ((.data // {})|keys|join(",")) + "\nConfigMap binaryData keys:" + ((.binaryData // {})|keys|join(","))' <<<"$OBJECT_JSON"; else jq -r '"Secret data keys:" + ((.data // {})|keys|join(","))' <<<"$OBJECT_JSON"; fi`

**선택 key 존재 gate — 아래 한 줄 전체를 복사**

`refresh_pod_identity`

`KEY_READY=false; if [ "$OBJECT_READY" != true ]; then printf '%s\n' '중단: OBJECT_READY가 아니다.' >&2; elif [ "$REF_KEY" = - ]; then KEY_READY=true; printf '%s\n' 'KEY_READY=true: 전체 key 집합 또는 volume source를 확인한다.'; elif [ "$REF_KIND" = configmap ] && { if [ "$REF_MODE" = volume ]; then jq -e --arg key "$REF_KEY" '((.data // {}) + (.binaryData // {})) | has($key)' <<<"$OBJECT_JSON" >/dev/null; else jq -e --arg key "$REF_KEY" '(.data // {}) | has($key)' <<<"$OBJECT_JSON" >/dev/null; fi; }; then KEY_READY=true; printf 'KEY_READY=true kind=%s key=%s\n' "$REF_KIND" "$REF_KEY"; elif [ "$REF_KIND" = secret ] && jq -e --arg key "$REF_KEY" '(.data // {}) | has($key)' <<<"$OBJECT_JSON" >/dev/null; then KEY_READY=true; printf 'KEY_READY=true kind=%s key=%s\n' "$REF_KIND" "$REF_KEY"; else printf '중단: 선언된 data key 없음 또는 key 확인 실패 kind=%s key=%s\n' "$REF_KIND" "$REF_KEY" >&2; fi`

**선택 container의 env·envFrom 참조 gate — 아래 한 줄 전체를 복사**

`refresh_pod_identity`

`ENV_REFERENCE_READY=false; ENV_REFERENCE_JSON=''; if [ "$OBJECT_READY" != true ] || [ "$KEY_READY" != true ]; then printf '%s\n' '중단: OBJECT_READY와 KEY_READY가 필요하다.' >&2; elif [ "$REF_MODE" = env ] && ENV_REFERENCE_JSON="$(jq -e -c --arg c "$REF_CONTAINER" --arg kind "$REF_KIND" --arg name "$REF_NAME" --arg key "$REF_KEY" '([.spec.initContainers[]?,.spec.containers[]?] | map(select(.name==$c))) as $cs | if ($cs|length)!=1 then error("container mismatch") else ($cs[0].env // [] | map(select(($kind=="configmap" and .valueFrom.configMapKeyRef.name==$name and .valueFrom.configMapKeyRef.key==$key) or ($kind=="secret" and .valueFrom.secretKeyRef.name==$name and .valueFrom.secretKeyRef.key==$key)))) as $refs | if ($refs|length)!=1 then error("env reference mismatch") else {mode:"env",container:$c,source:$kind,name:$name,key:$key,optional:($refs[0].valueFrom.configMapKeyRef.optional // $refs[0].valueFrom.secretKeyRef.optional // false)} end end' <<<"$POD_JSON")"; then ENV_REFERENCE_READY=true; export ENV_REFERENCE_JSON; jq -r '"=== 선택 참조 ===\n방식: \(.mode)\n컨테이너: \(.container)\n소스: \(.source)/\(.name)\nKey: \(.key)\nOptional: \(.optional)"' <<<"$ENV_REFERENCE_JSON"; elif [ "$REF_MODE" = envFrom ] && ENV_REFERENCE_JSON="$(jq -e -c --arg c "$REF_CONTAINER" --arg kind "$REF_KIND" --arg name "$REF_NAME" --arg key "$REF_KEY" '([.spec.initContainers[]?,.spec.containers[]?] | map(select(.name==$c))) as $cs | if ($cs|length)!=1 then error("container mismatch") else ($cs[0].envFrom // [] | map(select(($kind=="configmap" and .configMapRef.name==$name and $key=="-") or ($kind=="secret" and .secretRef.name==$name and $key=="-")))) as $refs | if ($refs|length)!=1 then error("envFrom reference mismatch") else {mode:"envFrom",container:$c,source:$kind,name:$name,key:$key,prefix:($refs[0].prefix // ""),optional:($refs[0].configMapRef.optional // $refs[0].secretRef.optional // false)} end end' <<<"$POD_JSON")"; then ENV_REFERENCE_READY=true; export ENV_REFERENCE_JSON; jq -r '"=== 선택 참조 ===\n방식: \(.mode)\n컨테이너: \(.container)\n소스: \(.source)/\(.name)\nPrefix: \(.prefix)\nOptional: \(.optional)"' <<<"$ENV_REFERENCE_JSON"; elif [ "$REF_MODE" = volume ]; then printf '%s\n' 'env reference gate 생략: volume join gate를 4절에서 실행한다.'; else printf '중단: 선택 container와 object 참조 관계 불일치 mode=%s container=%s\n' "$REF_MODE" "$REF_CONTAINER" >&2; fi`

환경변수 `valueFrom`에는 ConfigMap의 `.data` key만 유효하고, volume의 ConfigMap은 data·binaryData key를 선언 방식과 함께 대조한다. `grep` 결과 없음은 key 부재일 수 있지만 object schema·도구 출력 실패와 혼동하지 않는다. required source의 key가 없으면 owner template·선언 원본으로 돌아간다. `optional: true`는 해당 source 누락을 optional로 취급할 수 있을 뿐 application의 빈 환경변수·파일 부재 처리를 보장하지 않는다.

## 3. envFrom과 실제 주입 계약

진입 증거는 `envFrom` 또는 prefix가 있는 참조에서 object는 존재하지만 시작 후 필수 환경변수가 누락되는 것이다. 연결 경로는 **Pod spec → kubelet의 object fetch → container environment → application process**다. object key 전체, prefix, source별 optional과 환경변수 이름 충돌을 함께 비교한다. `envFrom`의 key 하나가 맞는다고 전체 주입을 보장하지 않는다.

**선언과 object key 대조 — 아래 한 줄 전체를 복사**

`refresh_pod_identity`

`if [ "$AUTO_READY" != true ] || [ "$OBJECT_READY" != true ] || [ "$KEY_READY" != true ] || [ "$REF_MODE" != envFrom ] || [ "$ENV_REFERENCE_READY" != true ]; then printf '%s\n' '중단: AUTO_READY·OBJECT_READY·KEY_READY·envFrom reference gate가 필요하다.' >&2; else jq -r '[.spec.initContainers[]?,.spec.containers[]?] | .[] as $c | "=== \($c.name) envFrom ===\n" + ([ $c.envFrom[]? | if .configMapRef then "ConfigMap/\(.configMapRef.name) optional=\(.configMapRef.optional // false) prefix=\(.prefix // "")" elif .secretRef then "Secret/\(.secretRef.name) optional=\(.secretRef.optional // false) prefix=\(.prefix // "")" else empty end ] | join("\n"))' <<<"$POD_JSON"; if [ "$REF_KIND" = configmap ]; then jq -r '"object data keys=" + ((.data // {})|keys|join(","))' <<<"$OBJECT_JSON"; else jq -r '"object data keys=" + ((.data // {})|keys|join(","))' <<<"$OBJECT_JSON"; fi; fi`

required `envFrom` object가 없으면 `CreateContainerConfigError`와 object 이름을 먼저 대조한다. object가 있으나 애플리케이션이 필수 환경변수 누락으로 종료하면 prefix·충돌·시작 계약으로 이동한다. `optional: true`인 source가 빠져도 Pod가 시작될 수 있으므로 이를 정상화로 기록하지 않는다. 실제 environment 값을 출력하지 않는다.

## 4. 일반 volume과 projected volume

진입 증거는 `FailedMount`, `projected` 또는 `MountVolume.SetUp failed`이며 모든 source를 확인해야 한다. 연결 경로는 **작업 PC의 kubectl client → API server → kubelet → volume source object → Pod mount target**다. source 하나의 성공은 projected 전체 성공을 보장하지 않는다.

**volume path 선택값 등록 — 자동 수집 결과에서 target path를 확인한 뒤 volume 분기에서 한 번 실행**

`MOUNT_PATH='PASTE_MOUNT_PATH_HERE'`

**volume source와 key 재확인 — 아래 한 줄 전체를 복사**

`refresh_pod_identity`

`VOLUME_READY=false; VOLUME_REFERENCE_JSON=''; if [ "$AUTO_READY" != true ] || [ "$OBJECT_READY" != true ] || [ "$KEY_READY" != true ] || [ "$REF_MODE" != volume ] || [ -z "$MOUNT_PATH" ]; then printf '%s\n' '중단: AUTO_READY·OBJECT_READY·KEY_READY·volume mode와 mount path가 필요하다.' >&2; elif VOLUME_REFERENCE_JSON="$(jq -e -c --arg c "$REF_CONTAINER" --arg kind "$REF_KIND" --arg name "$REF_NAME" --arg key "$REF_KEY" --arg path "$MOUNT_PATH" '([.spec.initContainers[]?,.spec.containers[]?] | map(select(.name==$c))) as $cs | if ($cs|length)!=1 then error("container mismatch") else ($cs[0].volumeMounts // [] | map(select(.mountPath==$path))) as $mounts | if ($mounts|length)!=1 then error("volumeMount mismatch") else ($mounts[0].name) as $volume | ([.spec.volumes[]? | select(.name==$volume)]) as $volumes | if ($volumes|length)!=1 then error("volume name mismatch") else $volumes[0] as $v | if ($kind=="configmap" and ($v.configMap.name // "")==$name) then ($v.configMap.items // [] | map(.key)) as $keys | if ($key=="-" or ($keys|length)==0 or (($keys|index($key))!=null)) then {mode:"volume",container:$c,volume:$volume,mountPath:$path,source:$kind,name:$name,key:$key,keys:$keys} else error("configmap item mismatch") end elif ($kind=="secret" and ($v.secret.secretName // "")==$name) then ($v.secret.items // [] | map(.key)) as $keys | if ($key=="-" or ($keys|length)==0 or (($keys|index($key))!=null)) then {mode:"volume",container:$c,volume:$volume,mountPath:$path,source:$kind,name:$name,key:$key,keys:$keys} else error("secret item mismatch") end elif $v.projected then ([$v.projected.sources[]? | select(($kind=="configmap" and (.configMap.name // "")==$name) or ($kind=="secret" and (.secret.name // "")==$name))]) as $sources | if ($sources|length)!=1 then error("projected source mismatch") else $sources[0] as $source | if $kind=="configmap" then ($source.configMap.items // [] | map(.key)) as $keys | if ($key=="-" or ($keys|length)==0 or (($keys|index($key))!=null)) then {mode:"volume",container:$c,volume:$volume,mountPath:$path,source:$kind,name:$name,key:$key,keys:$keys} else error("projected configmap item mismatch") end else ($source.secret.items // [] | map(.key)) as $keys | if ($key=="-" or ($keys|length)==0 or (($keys|index($key))!=null)) then {mode:"volume",container:$c,volume:$volume,mountPath:$path,source:$kind,name:$name,key:$key,keys:$keys} else error("projected secret item mismatch") end end else error("selected volume source mismatch") end end end' <<<"$POD_JSON")"; then VOLUME_READY=true; export VOLUME_REFERENCE_JSON; jq -r '"=== 선택 volume source ===\n컨테이너: \(.container)\nmountPath: \(.mountPath)\nvolumeMount.name: \(.volume)\nspec.volumes[name]: \(.volume)\n소스: \(.source)/\(.name)\nKey: \(.key)\nitems key: \((.keys // [])|join(","))"' <<<"$VOLUME_REFERENCE_JSON"; else printf '중단: MOUNT_PATH→volumeMount.name→spec.volumes[name]→source join 실패 container=%s path=%s object=%s/%s\n' "$REF_CONTAINER" "$MOUNT_PATH" "$REF_KIND" "$REF_NAME" >&2; fi`

`items[].key`와 target path가 모두 선언 원본과 맞고 object·key가 존재해야 kubelet 분기로 이동한다. path 충돌·중복 path·잘못된 items는 owner template와 대조하며 `defaultMode`만 바꾸어 object 부재를 해결하지 않는다. 빈 source 출력은 정상으로 해석하지 않고 Pod spec 조회 실패·path mismatch·source 없음으로 분기한다.

## 5. kubelet과 API audit 증거

진입 증거는 object·key·path가 맞는데 `CreateContainerConfigError` 또는 `FailedMount`가 지속되는 경우다. 연결 경로는 **작업 PC의 kubectl client → API server HTTPS request → kubelet node endpoint → object fetch 또는 volume setup → container**다. API server request 수신 성공은 kubelet 처리 성공을 보장하지 않는다. kubelet endpoint 주소·port·TLS는 환경별이므로 추측하지 않는다.

**journal 선택값 등록 — node의 실제 unit과 UTC 시간을 확인한 뒤 작업 PC에서 한 번 실행**

`KUBELET_SERVICE='PASTE_KUBELET_SERVICE_HERE'; START_JOURNAL='PASTE_START_JOURNAL_HERE'; END_JOURNAL='PASTE_END_JOURNAL_HERE'; REMOTE_HOST='PASTE_REMOTE_HOST_HERE'`

node shell에 작업 PC의 `POD_IDENTITY_READY`, `NODE_API_READY`, `JOURNAL_READY`를 복사하지 않는다. 아래 SSH command가 원격에서 현재 Pod UID·`spec.nodeName`, object 존재·namespace, Node API machine ID·remote `/etc/machine-id`, host mapping, 도구·sudo·unit·strict UTC/order gate를 다시 확인한다. remote `kubectl` 또는 machine identity 확인이 불가능하면 journal을 실행하지 않고 node/API owner에게 handoff한다.

**ConfigMap·Secret journal strict UTC canonical·order gate — 같은 Bash에서 아래 한 줄 전체를 복사**

`JOURNAL_TIME_READY=false; JOURNAL_START_EPOCH=''; JOURNAL_END_EPOCH=''; JOURNAL_START_CANONICAL=''; JOURNAL_END_CANONICAL=''; if [[ "$START_JOURNAL" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}\ [0-9]{2}:[0-9]{2}:[0-9]{2}\ UTC$ ]] && [[ "$END_JOURNAL" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}\ [0-9]{2}:[0-9]{2}:[0-9]{2}\ UTC$ ]] && JOURNAL_START_EPOCH="$(date -u -d "$START_JOURNAL" +%s 2>/dev/null)" && JOURNAL_END_EPOCH="$(date -u -d "$END_JOURNAL" +%s 2>/dev/null)" && JOURNAL_START_CANONICAL="$(date -u -d "$START_JOURNAL" '+%Y-%m-%d %H:%M:%S UTC' 2>/dev/null)" && JOURNAL_END_CANONICAL="$(date -u -d "$END_JOURNAL" '+%Y-%m-%d %H:%M:%S UTC' 2>/dev/null)" && [ "$JOURNAL_START_CANONICAL" = "$START_JOURNAL" ] && [ "$JOURNAL_END_CANONICAL" = "$END_JOURNAL" ] && [ "$JOURNAL_START_EPOCH" -lt "$JOURNAL_END_EPOCH" ]; then JOURNAL_TIME_READY=true; printf 'JOURNAL_TIME_READY=true start=%s end=%s\n' "$START_JOURNAL" "$END_JOURNAL"; else printf '중단: ConfigMap·Secret journal은 strict UTC canonical 형식과 시작 시각이 종료 시각보다 앞서야 한다 start=%s end=%s\n' "$START_JOURNAL" "$END_JOURNAL" >&2; fi`

**승인 remote host와 API node address mapping — 작업 PC의 같은 Bash에서 아래 한 줄 전체를 복사**

`NODE_API_READY=false; if [ "$POD_IDENTITY_READY" != true ] || [ "$AUTO_READY" != true ] || [ "$NODE" = - ] || [ -z "$REMOTE_HOST" ]; then printf '%s\n' '중단: Pod UID·AUTO_READY·API node·승인 REMOTE_HOST가 필요하다.' >&2; elif NODE_API_JSON="$(kubectl get node "$NODE" -o json 2>/dev/null)" && jq -e --arg host "$REMOTE_HOST" '[.metadata.name] + [.status.addresses[]?.address] | any(.==$host)' <<<"$NODE_API_JSON" >/dev/null; then NODE_API_READY=true; printf 'NODE_API_READY=true api_node=%s approved_remote_host=%s addresses=%s\n' "$NODE" "$REMOTE_HOST" "$(jq -r '[.status.addresses[]?.address] | join(",")' <<<"$NODE_API_JSON")"; else REMOTE_HOST=''; printf '중단: 승인 REMOTE_HOST가 API node name/address와 일치하지 않음 node=%s\n' "$NODE" >&2; fi`

**원격 UID·Node identity·object·journal read-only handoff — 작업 PC의 같은 Bash에서 아래 한 줄 전체를 복사**

`NODE_REMOTE_READY=false; if [ "$NODE_API_READY" != true ] || [ "$POD_IDENTITY_READY" != true ] || [ "$JOURNAL_TIME_READY" != true ] || [ "$OBJECT_READY" != true ] || [ -z "$POD_UID" ] || [ -z "$POD" ] || [ -z "$REF_NAME" ]; then printf '%s\n' '중단: 작업 PC의 API/object mapping은 handoff일 뿐이며 현재 Pod·object·시간 gate가 필요하다.' >&2; elif ssh -- "$REMOTE_HOST" bash -s -- "$NS" "$POD" "$POD_UID" "$NODE" "$REMOTE_HOST" "$KUBELET_SERVICE" "$START_JOURNAL" "$END_JOURNAL" "$REF_KIND" "$REF_NAME" <<< 'set -u; ns="$1"; pod="$2"; pod_uid="$3"; node="$4"; expected_host="$5"; unit="$6"; start="$7"; end="$8"; ref_kind="$9"; ref_name="${10}"; missing=""; for tool in kubectl journalctl systemctl date hostname cat grep; do command -v "$tool" >/dev/null 2>&1 || missing="$missing $tool"; done; if [ -n "$missing" ] || ! sudo -n -v >/dev/null 2>&1; then printf "중단: remote 도구·sudo read gate 실패 missing=%s\\n" "$missing" >&2; exit 1; fi; actual_host="$(hostname -f 2>/dev/null || hostname)"; short_host="$(hostname 2>/dev/null || true)"; api_node="$(kubectl get node "$node" -o "jsonpath={.metadata.name}" 2>/dev/null)"; api_machine="$(kubectl get node "$node" -o "jsonpath={.status.nodeInfo.machineID}" 2>/dev/null)"; local_machine="$(cat /etc/machine-id 2>/dev/null)"; current_uid="$(kubectl get pod "$pod" -n "$ns" -o "jsonpath={.metadata.uid}" 2>/dev/null)"; current_node="$(kubectl get pod "$pod" -n "$ns" -o "jsonpath={.spec.nodeName}" 2>/dev/null)"; object_ref="$(kubectl get "$ref_kind" "$ref_name" -n "$ns" -o name 2>/dev/null)"; start_epoch="$(date -u -d "$start" +%s 2>/dev/null)"; end_epoch="$(date -u -d "$end" +%s 2>/dev/null)"; start_canonical="$(date -u -d "$start" "+%Y-%m-%d %H:%M:%S UTC" 2>/dev/null)"; end_canonical="$(date -u -d "$end" "+%Y-%m-%d %H:%M:%S UTC" 2>/dev/null)"; if [[ "$start" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}\ [0-9]{2}:[0-9]{2}:[0-9]{2}\ UTC$ ]] && [[ "$end" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}\ [0-9]{2}:[0-9]{2}:[0-9]{2}\ UTC$ ]] && [ "$start_canonical" = "$start" ] && [ "$end_canonical" = "$end" ] && [ -n "$start_epoch" ] && [ -n "$end_epoch" ] && [ "$start_epoch" -lt "$end_epoch" ] && [ "$api_node" = "$node" ] && [ "$current_uid" = "$pod_uid" ] && [ "$current_node" = "$node" ] && [ -n "$object_ref" ] && [ "$api_machine" = "$local_machine" ] && { [ "$actual_host" = "$expected_host" ] || [ "$short_host" = "$expected_host" ]; } && systemctl cat "$unit" >/dev/null 2>&1 && sudo -n journalctl -u "$unit" --since "$start" --until "$end" --no-pager -n 0 >/dev/null 2>&1; then printf "NODE_REMOTE_READY=true pod_uid=%s node=%s object=%s machine_id_verified=true host=%s service=%s start=%s end=%s\\n" "$current_uid" "$current_node" "$object_ref" "$actual_host" "$unit" "$start" "$end"; sudo -n journalctl -u "$unit" --since "$start" --until "$end" --no-pager | grep -F -i -C 3 -e "$pod_uid" -e "$pod" -e "$ref_name" -e configmap -e secret -e projected -e volume -e mount -e env -e "not found" -e failed -e forbidden; statuses=("${PIPESTATUS[@]}"); if [ "${statuses[0]}" -ne 0 ]; then printf "중단: remote journal producer 실패 rc=%s\\n" "${statuses[0]}" >&2; exit 1; elif [ "${statuses[1]}" -gt 1 ]; then printf "중단: remote journal filter 실패 rc=%s\\n" "${statuses[1]}" >&2; exit 1; fi; exit 0; else printf "중단: remote UID/node/machine identity·object·strict UTC/order·unit gate 실패 pod_uid=%s current_uid=%s node=%s current_node=%s object=%s host=%s expected_host=%s\\n" "$pod_uid" "$current_uid" "$node" "$current_node" "$object_ref" "$actual_host" "$expected_host" >&2; exit 1; fi' ; then NODE_REMOTE_READY=true; printf 'NODE_REMOTE_READY=true remote_host=%s pod_uid=%s node=%s object=%s journal=true\\n' "$REMOTE_HOST" "$POD_UID" "$NODE" "$REF_NAME"; else printf '%s\\n' '중단: self-contained SSH node handoff 실패; journal을 실행하지 않음' >&2; fi`

예상 `MountVolume.SetUp failed ... configmap ... not found`는 source 이름·namespace·생성 순서로 돌아간다. `failed to sync pod ... secret` 또는 `CreateContainerConfigError`가 object·key·같은 Pod UID와 보이면 Pod spec과 대조한다. `permission denied`, API timeout, 인증서 오류는 kubelet을 임의 수정하지 말고 node/API owner에게 이관한다. journal 빈 결과는 오류 없음이 아니다.

API audit가 있는 환경에서만 플랫폼 담당자가 실제 저장 위치와 도구에 맞춰 다음 범위를 조회한다.

- 시간: `START_AUDIT`부터 `END_AUDIT`까지
- 필터: `verb=get`, `requestURI`의 `namespaces/NS/configmaps/REF_NAME` 또는 `secrets/REF_NAME`, Pod UID, kubelet subject, `responseStatus.code`
- `404`: 이름·namespace·생성 순서 후보
- `403`: 실제 subject의 RBAC·Admission 후보
- `200`: API server 처리 성공 범위이며 kubelet이 본 Pod spec/source와 node 시각으로 이동

**audit 시간 등록 — audit owner가 확인한 범위에서 한 번 실행**

`START_AUDIT='PASTE_START_AUDIT_HERE'; END_AUDIT='PASTE_END_AUDIT_HERE'`

**ConfigMap·Secret audit strict UTC canonical·order gate — audit owner 범위에서 아래 한 줄 전체를 복사**

`AUDIT_TIME_READY=false; AUDIT_START_EPOCH=''; AUDIT_END_EPOCH=''; AUDIT_START_CANONICAL=''; AUDIT_END_CANONICAL=''; if [[ "$START_AUDIT" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] && [[ "$END_AUDIT" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] && AUDIT_START_EPOCH="$(date -u -d "$START_AUDIT" +%s 2>/dev/null)" && AUDIT_END_EPOCH="$(date -u -d "$END_AUDIT" +%s 2>/dev/null)" && AUDIT_START_CANONICAL="$(date -u -d "$START_AUDIT" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" && AUDIT_END_CANONICAL="$(date -u -d "$END_AUDIT" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" && [ "$AUDIT_START_CANONICAL" = "$START_AUDIT" ] && [ "$AUDIT_END_CANONICAL" = "$END_AUDIT" ] && [ "$AUDIT_START_EPOCH" -lt "$AUDIT_END_EPOCH" ]; then AUDIT_TIME_READY=true; printf 'AUDIT_TIME_READY=true start=%s end=%s\n' "$START_AUDIT" "$END_AUDIT"; else printf '중단: ConfigMap·Secret audit은 strict UTC canonical 형식과 시작 시각이 종료 시각보다 앞서야 한다 start=%s end=%s\n' "$START_AUDIT" "$END_AUDIT" >&2; fi`

audit 원문과 Secret value는 증거로 저장하지 않는다. audit record가 없다고 API 요청이 없었다고 단정하지 않는다.

## 6. owner template와 선언 원본

진입 증거는 live Pod의 참조가 owner 관리 대상이거나 배포 순서·선언 원본이 의심되는 경우다. 자동 수집한 `OWNER_KIND`, `OWNER_NAME`을 사용하며 live Pod를 직접 수정하지 않는다. ReplicaSet·Job을 거쳐 Deployment·CronJob owner를 확인해야 하는 환경에서는 owner chain을 먼저 확정하고 이름을 추측하지 않는다.

**owner 참조 요약 — 아래 한 줄 전체를 복사**

`refresh_pod_identity`

`if [ "$AUTO_READY" != true ] || [ "$OWNER_KIND" = - ] || [ "$OWNER_NAME" = - ]; then printf '%s\n' '중단: controller owner가 확인되지 않았다.' >&2; elif OWNER_JSON="$(kubectl get "$OWNER_KIND" "$OWNER_NAME" -n "$NS" -o json 2>/dev/null)"; then jq -r '"=== owner ===\nkind/name: \(.kind // "-")/\(.metadata.name // "-")\nUID: \(.metadata.uid // "-")\n생성 시각: \(.metadata.creationTimestamp // "-")"' <<<"$OWNER_JSON"; jq -r '.. | objects | select(has("configMapKeyRef") or has("secretKeyRef") or has("configMapRef") or has("secretRef") or has("projected")) | tostring' <<<"$OWNER_JSON" | head -c 4000; printf '\n'; else printf '중단: owner 조회 실패 kind=%s name=%s\n' "$OWNER_KIND" "$OWNER_NAME" >&2; fi`

owner 출력은 선언의 source·key·optional·prefix·path를 비밀 없이 대조하는 범위다. `head`의 bounded 출력은 전체 YAML이나 Secret value가 아니며, owner가 `.spec.template`를 직접 갖지 않으면 상위 controller를 다시 확인한다. 변경 trigger는 object 부재·namespace/name 오류·data key 또는 volume key 부재·owner template 오기입이 읽기 결과로 확인된 경우다.

## 상태 변경 gate

object를 생성·덮어쓰기하거나 owner를 변경하는 명령은 이 문서에 제공하지 않는다. 별도 변경은 다음을 모두 충족한 뒤 승인된 변경 절차에서만 수행한다.

- **Trigger:** object namespace/name, env key, volume data·binary key·Secret key, source optional 또는 owner template 오류가 읽기 결과로 확정됐다.
- **Authority/approval:** API server·namespace·Pod UID, 같은 object consumer, immutable 여부, owner/object 관리자 승인, Secret 비노출, 변경 창과 rollback 원본을 대조했다.
- **대상·영향:** owner template와 의도한 namespace의 선언 원본만 대상으로 하며 live Pod 수정·임의 namespace 복제·Secret 값 추측은 금지한다.
- **중단:** 다른 consumer 영향, 새 Warning, restart 증가 또는 Secret 노출이 있으면 즉시 중단한다.
- **효과의 한계:** object/key 주입과 container 시작을 회복할 수 있어도 값 형식·빈 값·파일 경로를 application이 처리한다는 보장은 없다.

## 정상화와 증거

**Pod 상태와 재발 확인 — 아래 한 줄 전체를 복사**

`refresh_pod_identity`

`if [ "$AUTO_READY" != true ]; then printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; else kubectl get pod "$POD" -n "$NS" -o custom-columns='POD:.metadata.name,UID:.metadata.uid,PHASE:.status.phase,READY:.status.containerStatuses[*].ready,RESTARTS:.status.containerStatuses[*].restartCount,NODE:.spec.nodeName'; fi`

정상화는 `application 기능 → container 주입·파일 path → kubelet/API object fetch → object identity·namespace·key → Pod condition` 역순으로 확인한다. 같은 Pod UID의 object/key 오류와 restart 증가 중단, 관찰 기간 새 Warning 없음, 원하는 Ready 수, 실제 애플리케이션 요청 또는 핵심 기능 성공을 모두 확인한다. `Running`, `Ready`, `auth can-i=yes`, HTTP 200이 각각 object 존재·현재 condition·현재 주체 권한·transport/application 응답 전체를 보장하지 않는다. 새 Pod가 생성된 것만으로 정상화하지 않는다.

보존 대상은 관측 시각, namespace, Pod/UID/node/owner, 참조 방식, object kind/name/namespace/type, key 이름, optional·prefix·path, Event reason/message, phase·ready·restart, kubelet/audit의 비밀 없는 오류 구간과 실제 기능 결과다. Secret value·base64 data·token·개인키·전체 Pod YAML·민감한 로그는 보존하지 않는다.

## Prometheus 빠른 관측

KSM metric과 실제 label이 수집되는 환경에서만 사용한다. metric 부재, selector 불일치, 조회 실패와 object 부재를 구분한다. PromQL 내부를 직접 수정하지 않고 등록 변수로 완성 문자열을 생성한다.

**PromQL selector 계산 — 같은 Bash에서 아래 한 줄 전체를 복사**

`refresh_pod_identity`

`unset OBJECT_RE PROMQL_READY; OBJECT_RE="$(printf '%s' "$REF_NAME" | sed 's/[][\\.^$*+?(){}|]/\\&/g')"; if [ -n "$OBJECT_RE" ] && [ "$OBJECT_READY" = true ]; then PROMQL_READY=true; printf 'PROMQL_READY=true kind=%s object_re=%s\n' "$REF_KIND" "$OBJECT_RE"; else printf '%s\n' '중단: object selector 계산 또는 OBJECT_READY 실패' >&2; fi`

**ConfigMap·Secret info PromQL 생성 — 아래 한 줄 전체를 복사**

`refresh_pod_identity`

`if [ "$PROMQL_READY" != true ]; then printf '%s\n' '중단: PROMQL_READY가 아니다.' >&2; elif [ "$REF_KIND" = configmap ]; then printf 'kube_configmap_info{namespace="%s",configmap=~"%s"}\n' "$NS" "$OBJECT_RE"; else printf 'kube_secret_info{namespace="%s",secret=~"%s"}\n' "$NS" "$OBJECT_RE"; fi`

**Pod config error PromQL 생성 — 아래 한 줄 전체를 복사**

`refresh_pod_identity`

`if [ "$PROMQL_READY" != true ] || [ "$POD_IDENTITY_READY" != true ]; then printf '%s\n' '중단: PROMQL_READY와 Pod UID gate가 아니다.' >&2; else printf 'kube_pod_container_status_waiting_reason{namespace="%s",pod="%s",uid="%s",reason="CreateContainerConfigError"}==1\n' "$NS" "$POD" "$POD_UID"; fi`

출력이 비면 정상·0·오류 없음으로 기록하지 않는다. Prometheus API/transport 실패인지, KSM metric 미수집인지, label 불일치인지, 실제 series 부재인지 구분하고 Pod spec·Event·audit를 우선 근거로 삼는다.
