# Pod의 이전 컨테이너 로그를 가져올 수 없는 경우

## 입력값과 빠른 수집

이 문서의 값은 다음 네 종류로 나눈다.

| 종류 | 값 | 출처와 사용 시점 |
|---|---|---|
| 최초 입력 | `NS`, `POD` | 운영자가 승인된 namespace와 Pod 이름을 처음 한 번 입력한다. |
| API 자동값 | `POD_UID`, `NODE`, `PHASE`, `OBSERVED_AT`, container 상태, 현재·이전 `containerID`, `restartCount`, 종료 시각 | 같은 Pod API 응답과 UTC 시각에서 자동 등록한다. |
| 계산 후보값 | `PREVIOUS_RUNTIME_ID`, `NS_RE`, `POD_RE`, `CONTAINER_RE` | API에서 확인한 ID prefix와 이름으로 만들지만 실제 runtime·Prometheus 조회 전에 후보로만 취급한다. |
| 운영자 선택값 | `CONTAINER`, `START_RFC3339`, `END_RFC3339`, `INCIDENT_POD_UID`, `NODE_HOST`, `CRI_ENDPOINT` | 출력 증거, 장애 기록, node 담당자 확인 뒤 해당 분기에서 선택한다. `NODE_HOST`는 승인된 원격 접속 host이며 Node API address·원격 hostname과 대조한다. 복수 후보를 첫 번째로 고르지 않는다. |

### 1. 실행 위치·도구·최초 입력

일반 명령은 승인된 작업 PC 또는 bastion의 **같은 Bash 터미널**에서 실행한다. `kubectl`은 승인된 context로 API server에 HTTPS 요청을 보내고, 로그 stream은 API server에서 대상 node의 kubelet·runtime을 거쳐 container로 전달된다. runtime 명령은 `POD_UID`와 `PREVIOUS_RUNTIME_ID`를 수집한 **동일 Bash가 확인된 node host에서 실행될 때만** 이 문서의 변수로 실행한다. 작업 PC의 변수는 다른 node shell로 자동 전달되지 않으므로, 별도 node 세션이면 이 문서의 명령을 복사하지 말고 node 담당자에게 UID·runtime ID·시각·endpoint를 handoff해 담당자의 절차로 확인한다. API 읽기 권한과 대상 namespace의 Pod 조회 권한이 먼저 있어야 한다. TLS 검증을 끄지 않는다.

**필수 도구 확인 — 아래 한 줄 전체를 복사**

`TOOLS_READY=false; MISSING_TOOLS=''; if [ -z "${BASH_VERSION:-}" ]; then printf '%s\n' '중단: 같은 Bash에서 실행한다.' >&2; else for TOOL in kubectl jq grep sed date ssh; do command -v "$TOOL" >/dev/null 2>&1 || MISSING_TOOLS="$MISSING_TOOLS $TOOL"; done; if [ -z "$MISSING_TOOLS" ]; then TOOLS_READY=true; printf 'TOOLS_READY=true Bash=%s\n' "$BASH_VERSION"; else printf '중단: 없는 도구=%s\n' "$MISSING_TOOLS" >&2; fi; fi`

`TOOLS_READY=true`가 아니면 다음 단계로 진행하지 않는다. `jq`가 없으면 raw JSON을 저장하거나 수동으로 섞어 쓰지 말고 승인된 UI 또는 Kubernetes 담당자에게 같은 필드 확인을 요청한다.

재실행 때 이전 Pod·container·시간·runtime 값을 남기지 않는다. 이전 port-forward는 이 문서에 없지만, 같은 Bash에서 다른 런북의 stale 변수가 보이면 먼저 별도 세션을 연다.

**입력·이전 상태 초기화 — 같은 Bash에서 한 번 실행**

`unset INPUT_READY AUTO_READY SELECTION_READY START_READY START_CANONICAL END_CANONICAL STATE_READY CURRENT_READY PREVIOUS_READY PREVIOUS_RUNTIME_READY PREVIOUS_IDENTITY_READY NODE_IDENTITY_READY RUNTIME_INSPECT_READY QUERY_READY NS POD POD_UID NODE NODE_HOST NODE_JSON CURRENT_NODE_JSON REMOTE_NODE_NAME PHASE OBSERVED_AT CONTAINER START_RFC3339 END_RFC3339 INCIDENT_POD_UID CRI_ENDPOINT PREVIOUS_RUNTIME_ID NS_RE POD_RE POD_UID_RE CONTAINER_RE; NS='PASTE_NAMESPACE_HERE'; POD='PASTE_POD_HERE'; INPUT_READY=false; if [ "$TOOLS_READY" != true ]; then printf '%s\n' '중단: 도구 확인을 먼저 통과한다.' >&2; elif [ -z "$NS" ] || [ -z "$POD" ]; then printf '%s\n' '중단: NS와 POD를 입력한다.' >&2; elif kubectl get pod "$POD" -n "$NS" >/dev/null 2>&1; then INPUT_READY=true; export NS POD; printf 'INPUT_READY=true namespace=%s pod=%s\n' "$NS" "$POD"; else printf '중단: Pod 조회 실패 namespace=%s pod=%s\n' "$NS" "$POD" >&2; fi`

`INPUT_READY=true`가 아니면 namespace·Pod 이름·context·API 권한을 확인하고 멈춘다. Pod 이름이 재사용될 수 있으므로 이후 명령은 이름만으로 과거 로그를 추정하지 않는다.

### 2. API 자동 수집

**Pod 상태와 container 관계 자동 등록 — 아래 한 줄 전체를 복사**

`unset AUTO_READY POD_UID NODE PHASE OBSERVED_AT POD_JSON; AUTO_READY=false; if [ "$INPUT_READY" != true ]; then printf '%s\n' '중단: INPUT_READY가 아니다.' >&2; elif POD_JSON="$(kubectl get pod "$POD" -n "$NS" -o json)" && POD_UID_TMP="$(jq -r '.metadata.uid // empty' <<<"$POD_JSON")" && NODE_TMP="$(jq -r '.spec.nodeName // "-"' <<<"$POD_JSON")" && PHASE_TMP="$(jq -r '.status.phase // "-"' <<<"$POD_JSON")" && OBSERVED_AT_TMP="$(date -u '+%Y-%m-%dT%H:%M:%SZ')" && [ -n "$POD_UID_TMP" ]; then printf '%s\n' '=== Pod 대상 ==='; jq -r '"이름: \(.metadata.name)\nUID: \(.metadata.uid)\nNode: \(.spec.nodeName // "-")\nPhase: \(.status.phase // "-")\nPod 생성 시각(UTC): \(.metadata.creationTimestamp // "-")\n" + ([.spec.containers[]? | "Container: \(.name)\n선언 port 후보: \([.ports[]? | ((.name // "unnamed") + ":" + (.containerPort|tostring))] | join(", "))"] | join("\n")) + "\n" + ([.status.containerStatuses[]? | "Container 상태: \(.name)\n현재 상태 시각: \(.state.running.startedAt // .state.terminated.finishedAt // "-")\nWaiting reason: \(.state.waiting.reason // "-")\nTerminated reason: \(.state.terminated.reason // "-")\nExit code: \(.state.terminated.exitCode // "-")\nRestart count: \(.restartCount // 0)\n현재 container ID: \(.containerID // "-")\n직전 container ID: \(.lastState.terminated.containerID // "-")\n직전 종료 시각(UTC): \(.lastState.terminated.finishedAt // "-")"] | join("\n"))' <<<"$POD_JSON"; POD_UID="$POD_UID_TMP"; NODE="$NODE_TMP"; PHASE="$PHASE_TMP"; OBSERVED_AT="$OBSERVED_AT_TMP"; AUTO_READY=true; export POD_UID NODE PHASE OBSERVED_AT; printf 'AUTO_READY=true 관측시각(UTC)=%s\n' "$OBSERVED_AT"; else printf '%s\n' '중단: Pod API 조회 실패 또는 UID 없음; 이전 자동값은 무효다.' >&2; unset POD_JSON POD_UID NODE PHASE OBSERVED_AT; fi`

성공 gate는 한 Pod의 UID와 세로 출력에 node·phase·Pod 생성 시각·container 선언·현재/직전 status가 함께 보이는 것이다. 빈 container status는 정상·로그 없음의 증명이 아니라 아직 시작되지 않았거나 status 갱신이 늦은 경우, 권한·API 응답 문제 후보다. `AUTO_READY=true`가 아니면 이후 명령을 실행하지 않는다.

운영자는 출력에서 실제 이름 하나를 골라야 한다. `currentContainerID`는 현재 instance이고 `lastState.terminated.containerID`는 직전 종료 instance 후보다. `restartCount`와 `lastState.terminated`는 metadata이며 로그 보존을 보장하지 않는다. 이름과 종류가 여러 개면 [[29. 멀티 컨테이너 Pod의 로그 대상을 특정할 수 없는 경우]]로 먼저 이동한다.

**container 선택 — 아래 한 줄 전체를 복사**

`CONTAINER='PASTE_CONTAINER_HERE'; SELECTION_READY=false; if [ "$AUTO_READY" != true ]; then printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; elif jq -e --arg c "$CONTAINER" '([.spec.containers[]? | select(.name==$c)] | length)==1 and ([.status.containerStatuses[]? | select(.name==$c)] | length)<=1' <<<"$POD_JSON" >/dev/null; then SELECTION_READY=true; export CONTAINER; printf 'SELECTION_READY=true container=%s\n' "$CONTAINER"; else printf '중단: spec의 정확한 container 이름을 선택하지 않았거나 Pod 조회값이 없다.\n' >&2; fi`

`SELECTION_READY=true`이고 selected container의 status가 하나일 때만 이전 instance 판단을 진행한다. status가 없으면 로그를 만들지 않았다고 단정하지 말고 대상 선택 문서와 API status 갱신을 확인한다.

**previous 로그·runtime 직전 current identity refresh 함수 등록 — 같은 Bash에서 한 번 실행**

`refresh_previous_identity(){ PREVIOUS_IDENTITY_READY=false; unset FRESH_PREVIOUS_JSON FRESH_UID FRESH_SPEC_COUNT FRESH_STATUS_COUNT FRESH_CURRENT_ID FRESH_PREVIOUS_ID FRESH_PREVIOUS_FINISHED_AT FRESH_EXECUTED_AT; if [ "$SELECTION_READY" != true ]; then printf '%s\n' '중단: SELECTION_READY가 아니다.' >&2; return 1; elif FRESH_PREVIOUS_JSON="$(kubectl get pod "$POD" -n "$NS" -o json)" && FRESH_UID="$(jq -r '.metadata.uid // empty' <<<"$FRESH_PREVIOUS_JSON")" && FRESH_SPEC_COUNT="$(jq --arg c "$CONTAINER" '[.spec.containers[]? | select(.name==$c)] | length' <<<"$FRESH_PREVIOUS_JSON")" && FRESH_STATUS_COUNT="$(jq --arg c "$CONTAINER" '[.status.containerStatuses[]? | select(.name==$c)] | length' <<<"$FRESH_PREVIOUS_JSON")" && FRESH_CURRENT_ID="$(jq -r --arg c "$CONTAINER" '[.status.containerStatuses[]? | select(.name==$c)][0].containerID // empty' <<<"$FRESH_PREVIOUS_JSON")" && FRESH_PREVIOUS_ID="$(jq -r --arg c "$CONTAINER" '[.status.containerStatuses[]? | select(.name==$c)][0].lastState.terminated.containerID // empty' <<<"$FRESH_PREVIOUS_JSON")" && FRESH_PREVIOUS_FINISHED_AT="$(jq -r --arg c "$CONTAINER" '[.status.containerStatuses[]? | select(.name==$c)][0].lastState.terminated.finishedAt // empty' <<<"$FRESH_PREVIOUS_JSON")" && FRESH_EXECUTED_AT="$(jq -r --arg c "$CONTAINER" '[.status.containerStatuses[]? | select(.name==$c)][0] | .state.running.startedAt // .state.terminated.finishedAt // empty' <<<"$FRESH_PREVIOUS_JSON")" && [ "$FRESH_UID" = "$POD_UID" ] && [ "$FRESH_SPEC_COUNT" = 1 ] && [ "$FRESH_STATUS_COUNT" = 1 ] && [ -n "$FRESH_CURRENT_ID" ] && [ -n "$FRESH_PREVIOUS_ID" ] && [ -n "$FRESH_PREVIOUS_FINISHED_AT" ] && [ -n "$FRESH_EXECUTED_AT" ]; then PREVIOUS_RUNTIME_ID="${FRESH_PREVIOUS_ID#*://}"; POD_JSON="$FRESH_PREVIOUS_JSON"; PREVIOUS_IDENTITY_READY=true; export POD_JSON PREVIOUS_RUNTIME_ID PREVIOUS_IDENTITY_READY; printf 'PREVIOUS_IDENTITY_READY=true kind=regular status-count=%s current-id=%s lastState-id=%s lastState-finishedAt=%s executedAt=%s\n' "$FRESH_STATUS_COUNT" "$FRESH_CURRENT_ID" "$FRESH_PREVIOUS_ID" "$FRESH_PREVIOUS_FINISHED_AT" "$FRESH_EXECUTED_AT"; return 0; else printf '중단: fresh current kind/status/current ID/lastState identity 실패 expected-uid=%s actual-uid=%s status-count=%s current-id=%s lastState-id=%s lastState-finishedAt=%s executedAt=%s\n' "$POD_UID" "${FRESH_UID:--}" "${FRESH_STATUS_COUNT:--}" "${FRESH_CURRENT_ID:--}" "${FRESH_PREVIOUS_ID:--}" "${FRESH_PREVIOUS_FINISHED_AT:--}" "${FRESH_EXECUTED_AT:--}" >&2; return 1; fi; }`

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | `kubectl logs --previous`가 실패하거나 기대한 재시작 직전 로그를 반환하지 않는 경우 |
| 적용 | 같은 Pod UID, 명시한 container, `restartCount`, `lastState.terminated`, runtime ID와 UTC 시각을 대조할 수 있는 경우 |
| 제외 | 현재 instance 로그 전송·API·kubelet 경로는 [[27. Pod 로그를 가져올 수 없는 경우]], container 선택은 [[29. 멀티 컨테이너 Pod의 로그 대상을 특정할 수 없는 경우]], `pods/log` 권한은 [[30. Pod 로그 권한이 거부되는 경우]]로 이동한다. |

검색 문자열: `previous terminated container`, `not found`, `BadRequest`, `waiting to start`, `Forbidden`, `connection refused`, `i/o timeout`, `x509`, `no such file or directory`, `log rotation`, `GC`.

`--previous`는 동일한 Pod UID에서 지정한 container의 직전에 종료된 instance 하나만 조회한다. Pod 이름이 같아도 UID가 바뀌면 새 Pod의 `--previous`로 이전 UID 로그를 복구할 수 없다.

## 최초 확인

**현재 status를 UID로 재검증 — 아래 한 줄 전체를 복사**

`unset STATE_READY CURRENT_READY PREVIOUS_READY PREVIOUS_RUNTIME_READY PREVIOUS_RUNTIME_ID; STATE_READY=false; CURRENT_READY=false; PREVIOUS_READY=false; PREVIOUS_RUNTIME_READY=false; if [ "$SELECTION_READY" != true ]; then printf '%s\n' '중단: SELECTION_READY가 아니다.' >&2; elif CHECK_JSON="$(kubectl get pod "$POD" -n "$NS" -o json)" && CHECK_UID="$(jq -r '.metadata.uid // empty' <<<"$CHECK_JSON")" && [ "$CHECK_UID" = "$POD_UID" ]; then jq -r --arg c "$CONTAINER" '([.status.containerStatuses[]? | select(.name==$c)][0]) as $s | "관측시각(UTC): ", "UID: "+.metadata.uid, "Node: "+(.spec.nodeName // "-"), "Phase: "+(.status.phase // "-"), "Container: "+$c, "현재 state: "+(if $s.state.running then "Running/"+($s.state.running.startedAt // "-") elif $s.state.terminated then "Terminated/"+($s.state.terminated.finishedAt // "-") elif $s.state.waiting then "Waiting/"+($s.state.waiting.reason // "-") else "없음" end), "Restart count: "+(($s.restartCount // 0)|tostring), "직전 reason: "+($s.lastState.terminated.reason // "-"), "직전 exit code: "+(($s.lastState.terminated.exitCode // "-")|tostring), "직전 finishedAt: "+($s.lastState.terminated.finishedAt // "-"), "직전 container ID: "+($s.lastState.terminated.containerID // "-"), "현재 container ID: "+($s.containerID // "-")' <<<"$CHECK_JSON"; CURRENT_ID_TMP="$(jq -r --arg c "$CONTAINER" '[.status.containerStatuses[]? | select(.name==$c)][0].containerID // empty' <<<"$CHECK_JSON")"; PREVIOUS_TERMINATED_TMP="$(jq -r --arg c "$CONTAINER" '[.status.containerStatuses[]? | select(.name==$c)][0].lastState.terminated // empty' <<<"$CHECK_JSON")"; PREVIOUS_RUNTIME_ID_TMP="$(jq -r --arg c "$CONTAINER" '[.status.containerStatuses[]? | select(.name==$c)][0].lastState.terminated.containerID // empty' <<<"$CHECK_JSON")"; STATE_READY=true; if [ -n "$CURRENT_ID_TMP" ]; then CURRENT_READY=true; fi; if [ -n "$PREVIOUS_TERMINATED_TMP" ]; then PREVIOUS_READY=true; fi; if [ -n "$PREVIOUS_RUNTIME_ID_TMP" ]; then PREVIOUS_RUNTIME_ID="${PREVIOUS_RUNTIME_ID_TMP#*://}"; PREVIOUS_RUNTIME_READY=true; fi; export STATE_READY CURRENT_READY PREVIOUS_READY PREVIOUS_RUNTIME_READY PREVIOUS_RUNTIME_ID; printf 'STATE_READY=true CURRENT_READY=%s PREVIOUS_READY=%s PREVIOUS_RUNTIME_READY=%s\n' "$CURRENT_READY" "$PREVIOUS_READY" "$PREVIOUS_RUNTIME_READY"; else printf '중단: API 실패 또는 관측한 UID 변경; 이전 결과를 폐기한다.\n' >&2; unset CHECK_JSON CHECK_UID CURRENT_ID_TMP PREVIOUS_TERMINATED_TMP PREVIOUS_RUNTIME_ID_TMP; fi`

진입 증거는 위 명령의 동일 UID와 선택 container의 상태다. `restartCount=0` 또는 직전 terminated 상태 없음은 직전 instance 부재의 metadata 증거일 뿐 원인·로그 부재의 증명이 아니다. UID가 달라지면 현재 결과를 이전 장애와 섞지 않고 기존 증거의 UID로 중앙 수집기 분기를 사용한다. `STATE_READY=true`가 아니면 중단한다.

**같은 UID의 restart·Killing Event 확인 — 아래 한 줄 전체를 복사**

`if [ "$STATE_READY" = true ]; then kubectl get events -n "$NS" --field-selector="involvedObject.kind=Pod,involvedObject.name=$POD,involvedObject.uid=$POD_UID" --sort-by=.metadata.creationTimestamp -o custom-columns='CREATED:.metadata.creationTimestamp,FIRST:.firstTimestamp,LAST:.lastTimestamp,EVENT-TIME:.eventTime,TYPE:.type,REASON:.reason,MESSAGE:.message'; else printf '%s\n' '중단: STATE_READY가 아니다.' >&2; fi`

Event 성공 gate는 같은 UID의 reason과 실제 채워진 UTC 시각 필드가 제한된 범위로 보이는 것이다. Event가 없거나 `restart`·`Killing`이 없다고 이전 instance나 원인이 없었다고 판단하지 않는다. message에 민감정보가 있으면 reason·비식별 위치만 기록하고 2절의 로그·5절의 중앙 수집으로 진행한다.

표는 다음 확인을 고르는 길 안내다. 빈 출력은 정상·0·오류 없음으로 해석하지 않는다. 한 hop 성공은 다음 hop이나 application 정상의 증거가 아니다.

### 1. UID·state·instance 확인

진입 증거: `STATE_READY=true`이고 현재 API 응답의 UID가 최초 `POD_UID`와 같다. 최초 필요값은 API 자동값 `POD_UID`, `NODE`, `CONTAINER`, `CURRENT_ID_TMP`, `PREVIOUS_RUNTIME_ID`이며, `OBSERVED_AT`은 명령 실행 시 UTC 시각이다.

위 상태 명령의 성공 gate는 같은 UID, 선택 container의 state, `currentContainerID`, `lastState.terminated.containerID`, `finishedAt`가 구분되어 출력되는 것이다. `PREVIOUS_READY=true`가 아니면 현재 instance만 조사하고 `--previous`를 반복하지 않는다. `Waiting`에 current ID가 없으면 current 로그 미생성과 previous 로그 부재를 같은 현상으로 기록하지 않는다.

실패 의미: `Forbidden`은 [[30. Pod 로그 권한이 거부되는 경우]], container 이름 오류는 [[29. 멀티 컨테이너 Pod의 로그 대상을 특정할 수 없는 경우]], UID 변경은 4절·5절로 이동한다. API status가 비어 있는 것은 대상 없음, status 갱신 지연, 권한·API 실패 중 하나이며 원인 부재가 아니다.

### 2. current와 previous 로그

진입 증거: `CURRENT_READY=true` 또는 `PREVIOUS_READY=true`이고 `STATE_READY=true`다. 이 절의 시간은 장애 증거보다 조금 앞선 UTC 시각을 운영자가 선택한다.

**로그 시간 선택 — 같은 Bash에서 한 번 실행**

`START_RFC3339='PASTE_START_RFC3339_HERE'; START_READY=false; unset START_CANONICAL; if [[ ! "$START_RFC3339" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]]; then printf '중단: START_RFC3339는 strict UTC Z 형식이어야 함 %s\n' "$START_RFC3339" >&2; elif START_CANONICAL="$(date -u -d "$START_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" && [ "$START_CANONICAL" = "$START_RFC3339" ]; then START_READY=true; export START_RFC3339 START_CANONICAL START_READY; printf 'START_READY=true strict_utc=true start=%s\n' "$START_RFC3339"; else printf '중단: START_RFC3339 canonical round-trip 실패 %s\n' "$START_RFC3339" >&2; fi`

시간 선택 성공은 strict `YYYY-MM-DDTHH:MM:SSZ` regex와 UTC canonical round-trip을 모두 통과한 경우다. 자연어·offset·비정규 timestamp는 거부한다. 로그 범위와 실제 장애 시각이 맞다는 것은 보장하지 않으므로 `finishedAt`과 대조한다. `SELECTION_READY=true`가 아니면 로그 명령을 실행하지 않는다.

연결 경로는 `작업 PC/Bash → kubectl client → API server HTTPS → 대상 node의 kubelet log endpoint → container runtime log file/stream → 선택 container`다. API 주소·port는 kubeconfig, kubelet 주소·port와 runtime socket은 클러스터 구성에서 결정되며 이 문서에서 추측하지 않는다. API server에 도달한 것은 kubelet·runtime·application log 정상의 증거가 아니다.

**current 오류 구간 조회 — 아래 한 줄 전체를 복사**

`if [ "$STATE_READY" != true ] || [ "$CURRENT_READY" != true ] || [ "$START_READY" != true ] || [ "$SELECTION_READY" != true ]; then printf '%s\n' '중단: STATE_READY, CURRENT_READY, SELECTION_READY, START_READY가 필요하다.' >&2; else kubectl logs "$POD" -n "$NS" -c "$CONTAINER" --timestamps --since-time="$START_RFC3339" --tail=200 | grep -E -i -C 3 'panic|fatal|error|exception|timeout|refused|denied|permission|oom|killed'; rc=${PIPESTATUS[0]}; if [ "$rc" -ne 0 ]; then printf 'current log stream 실패 rc=%s; API/kubelet 경로로 이관한다.\n' "$rc" >&2; else printf '%s\n' 'current log stream 성공; grep 무출력은 오류 부재가 아니다.'; fi; fi`

성공 gate는 선택한 같은 UID의 current instance에 대해 제한된 stream이 준비된 것이다. 필터 결과가 비면 같은 시간 범위의 마지막 50행을 한 번 확인하되 빈 출력은 오류 없음이 아니다. `Forbidden`, `container not found`, `connection refused`, `i/o timeout`, `x509`는 각각 권한·대상 선택·API/kubelet 경로로 이관한다. 로그에 Secret·token·개인정보가 보이면 즉시 출력·저장을 중단하고 비식별 오류 유형과 UTC 위치만 기록한다.

**previous 오류 구간 조회 — 아래 한 줄 전체를 복사**

`if [ "$STATE_READY" != true ] || [ "$PREVIOUS_READY" != true ] || [ "$START_READY" != true ] || [ "$SELECTION_READY" != true ] || ! refresh_previous_identity; then printf '%s\n' '중단: STATE_READY, PREVIOUS_READY, SELECTION_READY, START_READY와 fresh current/lastState identity gate가 필요하다.' >&2; else kubectl logs "$POD" -n "$NS" -c "$CONTAINER" --previous --timestamps --since-time="$START_RFC3339" --tail=200 | grep -E -i -C 3 'panic|fatal|error|exception|timeout|refused|denied|permission|oom|killed'; rc=${PIPESTATUS[0]}; if [ "$rc" -ne 0 ]; then printf 'previous log stream 실패 rc=%s; 출력 문자열에 따라 다음 분기를 선택한다.\n' "$rc" >&2; else printf '%s\n' 'previous log stream 성공; grep 무출력은 보존·원인 부재의 증명이 아니다.'; fi; fi`

`--previous` 성공은 같은 UID·container의 직전 instance 하나에 대한 stream 준비만 보장한다. `previous terminated container ... not found` 또는 `no such file`은 직전 ID 미보존, runtime log rotation·GC·삭제, kubelet 매핑 실패를 모두 남긴 뒤 3절 또는 5절로 이동한다. 출력이 비면 `START_RFC3339`가 `finishedAt`보다 뒤인지 먼저 확인하고 더 이른 시각으로 재선택한다. 모든 과거 재시작 로그를 복원한 것이 아니다.

### 3. runtime 보존 확인

진입 증거: 같은 UID의 `PREVIOUS_RUNTIME_ID`와 `lastState.terminated.finishedAt`가 있고 `--previous`가 `not found`·`no such file`로 실패했다. `PREVIOUS_RUNTIME_ID`는 API의 이전 ID에서 `containerd://` 같은 prefix를 제거한 계산 후보다. `CRI_ENDPOINT`는 node 운영자가 실제 kubelet/CRI 설정에서 확인한 운영자 선택값이며 기본 socket을 추측하지 않는다.

runtime hop은 `node Bash → crictl client → 확인된 CRI endpoint socket → container runtime → 이전 container metadata/log`다. 작업 PC의 API hop과 node의 CRI socket hop을 같은 것으로 취급하지 않는다. node 접근 권한, `crictl`, `jq`, 확인된 endpoint와 대상 runtime ID가 모두 있어야 한다.

**Node API·approved NODE_HOST 원격 identity gate — CRI 전에 같은 Bash에서 한 번 실행**

`NODE_IDENTITY_READY=false; NODE_HOST='PASTE_NODE_HOST_HERE'; unset NODE_JSON CURRENT_NODE_JSON NODE_API_NAME CURRENT_POD_UID CURRENT_POD_NODE REMOTE_NODE_NAME; if [ "$AUTO_READY" != true ] || [ -z "$NODE" ] || [ -z "$NODE_HOST" ] || [[ "$NODE_HOST" == PASTE_* ]] || ! [[ "$NODE_HOST" =~ ^[A-Za-z0-9._:-]+$ ]]; then printf '%s\n' '중단: AUTO_READY, API가 확인한 NODE와 approved NODE_HOST가 필요하다.' >&2; elif NODE_JSON="$(kubectl get node "$NODE" -o json)" && CURRENT_NODE_JSON="$(kubectl get pod "$POD" -n "$NS" -o json)" && NODE_API_NAME="$(jq -r '.metadata.name // empty' <<<"$NODE_JSON")" && CURRENT_POD_UID="$(jq -r '.metadata.uid // empty' <<<"$CURRENT_NODE_JSON")" && CURRENT_POD_NODE="$(jq -r '.spec.nodeName // empty' <<<"$CURRENT_NODE_JSON")" && REMOTE_NODE_NAME="$(ssh -- "$NODE_HOST" 'hostname -s' 2>/dev/null)" && [ "$NODE_API_NAME" = "$NODE" ] && [ "$CURRENT_POD_UID" = "$POD_UID" ] && [ "$CURRENT_POD_NODE" = "$NODE" ] && jq -e --arg host "$NODE_HOST" --arg remote "$REMOTE_NODE_NAME" 'any(.status.addresses[]?; .address==$host) and any(.status.addresses[]?; .type=="Hostname" and .address==$remote)' <<<"$NODE_JSON" >/dev/null; then NODE_IDENTITY_READY=true; export NODE_HOST NODE_IDENTITY_READY; printf 'NODE_IDENTITY_READY=true api-node=%s approved-node-host=%s remote-hostname=%s pod-uid=%s\n' "$NODE_API_NAME" "$NODE_HOST" "$REMOTE_NODE_NAME" "$CURRENT_POD_UID"; else printf '중단: Node API NODE·approved NODE_HOST·원격 hostname·현재 Pod UID/node exact match 실패 node=%s node-api=%s host=%s remote-hostname=%s pod-uid=%s pod-node=%s\n' "$NODE" "${NODE_API_NAME:--}" "$NODE_HOST" "${REMOTE_NODE_NAME:--}" "${CURRENT_POD_UID:--}" "${CURRENT_POD_NODE:--}" >&2; fi`

`NODE_IDENTITY_READY=true`가 아니면 `crictl`을 실행하지 않는다. `NODE_HOST`는 승인된 SSH 대상일 뿐이며, Node API의 address와 원격 `hostname -s`가 같은 Node를 가리키는지 확인하지 못하면 node 담당자에게 handoff한다.

**node 도구·endpoint 선택 — node의 같은 Bash에서 한 번 실행**

`NODE_TOOLS_READY=false; CRI_ENDPOINT='PASTE_CRI_ENDPOINT_HERE'; if [ "$NODE_IDENTITY_READY" != true ] || [ "$PREVIOUS_RUNTIME_READY" != true ] || [ "$NODE" = - ] || [ -z "${BASH_VERSION:-}" ]; then printf '%s\n' '중단: NODE_IDENTITY_READY, previous runtime ID, 확인된 node와 node Bash가 필요하다.' >&2; elif [ -z "$CRI_ENDPOINT" ] || ! command -v jq >/dev/null 2>&1 || ! command -v date >/dev/null 2>&1; then printf '%s\n' '중단: 확인된 CRI_ENDPOINT, jq, date와 node Bash 권한이 필요하다.' >&2; else NODE_TOOLS_READY=true; export CRI_ENDPOINT; printf 'NODE_TOOLS_READY=true node=%s endpoint=%s previous-runtime-id=%s\n' "$NODE" "$CRI_ENDPOINT" "$PREVIOUS_RUNTIME_ID"; fi`

`NODE_TOOLS_READY=true`가 아니면 node 명령을 실행하지 않는다. endpoint가 비었거나 ID가 다른 경우 부분 결과를 유효하게 남기지 말고 node 담당자에게 확인한다.

**실제 CRI 실행 host 고정 — 아래 Bash block 전체를 같은 Bash에서 한 번 실행**

```bash
NODE_REMOTE_READY=false; unset REMOTE_CRICTL_PATH REMOTE_NODE_NAME_CHECK; if [ "$NODE_IDENTITY_READY" != true ] || [ -z "${NODE_HOST:-}" ] || [ -z "${REMOTE_NODE_NAME:-}" ] || [ -z "${CRI_ENDPOINT:-}" ] || [[ "$CRI_ENDPOINT" == PASTE_* ]]; then printf '%s\n' '중단: Node identity, approved NODE_HOST, remote hostname과 실제 CRI endpoint가 필요하다.' >&2; elif ! command -v jq >/dev/null 2>&1 || ! command -v date >/dev/null 2>&1; then printf '%s\n' '중단: 로컬 Bash의 jq와 date가 필요하다.' >&2; elif REMOTE_NODE_NAME_CHECK="$(ssh -- "$NODE_HOST" 'hostname -s' 2>/dev/null)" && REMOTE_CRICTL_PATH="$(ssh -- "$NODE_HOST" 'command -v crictl' 2>/dev/null)" && [[ "$REMOTE_NODE_NAME_CHECK" =~ ^[A-Za-z0-9._-]+$ ]] && [ "$REMOTE_NODE_NAME_CHECK" = "$REMOTE_NODE_NAME" ] && [ -n "$REMOTE_CRICTL_PATH" ]; then NODE_REMOTE_READY=true; NODE_TOOLS_READY=true; export NODE_REMOTE_READY NODE_TOOLS_READY; printf 'NODE_REMOTE_READY=true verified-ssh-host=%s remote-hostname=%s crictl=remote-only\n' "$NODE_HOST" "$REMOTE_NODE_NAME_CHECK"; else NODE_TOOLS_READY=false; printf '중단: approved NODE_HOST의 hostname 또는 remote crictl 검증 실패 host=%s expected-hostname=%s actual-hostname=%s\n' "$NODE_HOST" "$REMOTE_NODE_NAME" "${REMOTE_NODE_NAME_CHECK:--}" >&2; fi
crictl() { if [ "$NODE_IDENTITY_READY" != true ] || [ "$NODE_REMOTE_READY" != true ]; then printf '%s\n' '중단: 검증된 SSH node identity 없이 CRI를 실행하지 않는다.' >&2; return 70; fi; if [[ ! "$REMOTE_NODE_NAME" =~ ^[A-Za-z0-9._-]+$ ]]; then printf '%s\n' '중단: 검증된 remote hostname 형식이 안전하지 않다.' >&2; return 71; fi; for ARG in "$@"; do case "$ARG" in *[!A-Za-z0-9_./:=+@,-]*) printf '%s\n' '중단: CRI argument에 허용되지 않은 문자가 있다.' >&2; return 72;; esac; done; REMOTE_NODE_NAME_CHECK="$(ssh -- "$NODE_HOST" 'hostname -s' 2>/dev/null)" || { printf '%s\n' '중단: 실제 CRI 실행 직전 remote hostname 확인 실패.' >&2; return 73; }; if [ "$REMOTE_NODE_NAME_CHECK" != "$REMOTE_NODE_NAME" ]; then printf '중단: 검증한 host와 실제 CRI 실행 host 불일치 expected-hostname=%s actual-hostname=%s\n' "$REMOTE_NODE_NAME" "$REMOTE_NODE_NAME_CHECK" >&2; return 74; fi; ssh -- "$NODE_HOST" "test \"\$(hostname -s)\" = \"$REMOTE_NODE_NAME\" && command -v crictl >/dev/null 2>&1 && exec crictl $*"; }
```

이 block 뒤의 `crictl` 이름은 로컬 binary가 아니라 `NODE_HOST`의 hostname을 같은 SSH 대상에서 재확인한 뒤 원격 `crictl`을 실행하는 wrapper다. 따라서 검증에 사용한 host와 실제 CRI socket에 접근하는 host가 달라지면 `RUNTIME_INSPECT_READY`를 열지 않는다. endpoint·runtime ID·시간 인자는 shell metacharacter를 허용하지 않으며, raw inspect/log 원문은 저장하지 않는다.

**previous runtime metadata 조회 — 아래 한 줄 전체를 복사**

`unset INSPECT_JSON INSPECT_SUMMARY INSPECT_RC JQ_RC CREATED_AT_TMP STARTED_AT_TMP FINISHED_AT_TMP CREATED_EPOCH_TMP STARTED_EPOCH_TMP FINISHED_EPOCH_TMP RUNTIME_INSPECT_READY; RUNTIME_INSPECT_READY=false; if [ "$NODE_IDENTITY_READY" != true ] || [ "$NODE_TOOLS_READY" != true ] || [ "$PREVIOUS_RUNTIME_READY" != true ] || ! refresh_previous_identity; then printf '%s\n' '중단: NODE_IDENTITY_READY, NODE_TOOLS_READY, PREVIOUS_RUNTIME_READY와 fresh current/lastState identity가 필요하다.' >&2; else INSPECT_JSON="$(crictl --runtime-endpoint="$CRI_ENDPOINT" inspect "$PREVIOUS_RUNTIME_ID")"; INSPECT_RC=$?; if [ "$INSPECT_RC" -ne 0 ]; then printf 'crictl inspect producer 실패 rc=%s; jq를 실행하지 않고 runtime 담당자로 이관한다.\n' "$INSPECT_RC" >&2; else INSPECT_SUMMARY="$(jq -e -c 'if ((.status.id|type)!="string" or (.status.id|length)==0 or (.status.state|type)!="string" or (.status.state|length)==0 or (.status.createdAt|type)!="string" or (.status.createdAt|length)==0 or (.status.startedAt|type)!="string" or (.status.startedAt|length)==0 or (.status.finishedAt|type)!="string" or (.status.finishedAt|length)==0 or (.status.logPath|type)!="string" or (.status.logPath|length)==0) then error("CRI inspect schema mismatch: timestamps must be non-empty RFC3339Nano strings") else {id:.status.id,state:.status.state,createdAt:.status.createdAt,startedAt:.status.startedAt,finishedAt:.status.finishedAt,logPath:.status.logPath} end' <<<"$INSPECT_JSON")"; JQ_RC=$?; if [ "$JQ_RC" -ne 0 ] || [ -z "$INSPECT_SUMMARY" ]; then printf 'jq schema/producer 결과 검증 실패 jq_rc=%s; null/empty timestamp를 허용하지 않고 raw inspect를 저장하지 않는다.\n' "$JQ_RC" >&2; else CREATED_AT_TMP="$(jq -r '.createdAt' <<<"$INSPECT_SUMMARY")"; STARTED_AT_TMP="$(jq -r '.startedAt' <<<"$INSPECT_SUMMARY")"; FINISHED_AT_TMP="$(jq -r '.finishedAt' <<<"$INSPECT_SUMMARY")"; if [[ ! "$CREATED_AT_TMP" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}(\.[0-9]{1,9})?(Z|[+-][0-9]{2}:[0-9]{2})$ ]] || [[ ! "$STARTED_AT_TMP" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}(\.[0-9]{1,9})?(Z|[+-][0-9]{2}:[0-9]{2})$ ]] || [[ ! "$FINISHED_AT_TMP" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}(\.[0-9]{1,9})?(Z|[+-][0-9]{2}:[0-9]{2})$ ]]; then printf '중단: createdAt/startedAt/finishedAt가 RFC3339Nano string 형식이 아님; date parse를 실행하지 않는다.\n' >&2; elif CREATED_EPOCH_TMP="$(date -u -d "$CREATED_AT_TMP" '+%s' 2>/dev/null)" && STARTED_EPOCH_TMP="$(date -u -d "$STARTED_AT_TMP" '+%s' 2>/dev/null)" && FINISHED_EPOCH_TMP="$(date -u -d "$FINISHED_AT_TMP" '+%s' 2>/dev/null)"; then printf '%s\n' "$INSPECT_SUMMARY"; RUNTIME_INSPECT_READY=true; export RUNTIME_INSPECT_READY; printf 'RUNTIME_INSPECT_READY=true producer_rc=%s jq_rc=%s timestamp_schema=RFC3339Nano_string date_parse=success\n' "$INSPECT_RC" "$JQ_RC"; else printf '중단: RFC3339Nano string date parse 실패; inspect 결과를 runtime 담당자로 이관한다.\n' >&2; fi; fi; fi; unset INSPECT_JSON INSPECT_SUMMARY; fi`

성공 gate는 `crictl inspect` producer rc=0, `jq` rc=0, required `status.id/state/createdAt/startedAt/finishedAt/logPath` schema 통과, 세 timestamp의 non-empty RFC3339Nano string regex 통과와 별도 `date` parse 성공이다. timestamp가 `null`·empty이면 schema 단계에서 중단하고, string이지만 parse되지 않으면 date 단계에서 중단한다. 숫자 timestamp는 허용하지 않는다. 어느 하나라도 실패하면 `RUNTIME_INSPECT_READY`를 열지 않고 raw 전체를 저장하지 않는다. `crictl` 성공이 kubelet/API log path 성공이나 application 정상까지 보장하지 않는다. ID 없음·빈 log path·빈 로그는 GC·rotation·삭제·보존 만료 후보이며 중앙 수집기로 이동한다. schema가 다르면 ID·state·시각·경로만 runtime 담당자에게 요청한다.

**previous runtime 로그 bounded 조회 — 아래 한 줄 전체를 복사**

`if [ "$NODE_IDENTITY_READY" != true ] || [ "$NODE_TOOLS_READY" != true ] || [ "$RUNTIME_INSPECT_READY" != true ] || [ "$PREVIOUS_RUNTIME_READY" != true ] || [ "$SELECTION_READY" != true ] || [ "$START_READY" != true ] || ! refresh_previous_identity; then printf '%s\n' '중단: node identity·node tools·inspect producer/jq schema·previous runtime·selection·시간·fresh current/lastState identity gate가 필요하다.' >&2; else crictl --runtime-endpoint="$CRI_ENDPOINT" logs --timestamps --since="$START_RFC3339" --tail=200 "$PREVIOUS_RUNTIME_ID" | grep -E -i -C 3 'panic|fatal|error|exception|timeout|refused|denied|permission|oom|killed'; rc=${PIPESTATUS[0]}; if [ "$rc" -ne 0 ]; then printf 'runtime log 실패 rc=%s; runtime 보존·CRI 담당자로 이관한다.\n' "$rc" >&2; else printf '%s\n' 'runtime log stream 성공; grep 무출력은 원인 부재가 아니다.'; fi; fi`

runtime 로그는 현재 `containerID`로 대체하지 않는다. runtime 성공인데 `kubectl logs --previous`만 실패하면 kubelet이 이전 ID를 매핑·전달하는 API 경계를 [[27. Pod 로그를 가져올 수 없는 경우#4. API server에서 kubelet과 node reachability|27번 kubelet 절]]에서 확인한다. 로그 파일 복사·복원·삭제나 rotation 설정 변경은 하지 않는다.

### 4. Pod 재생성 UID 확인

진입 증거: 장애 당시 증거에 UID가 있고 현재 `POD_UID`와 다르다. `INCIDENT_POD_UID`는 기존 incident 기록에서만 가져오는 운영자 선택값이다.

**장애 당시 UID 등록 — 같은 Bash에서 한 번 실행**

`INCIDENT_POD_UID='PASTE_INCIDENT_POD_UID_HERE'; if [ "$AUTO_READY" != true ] || [ -z "$INCIDENT_POD_UID" ]; then printf '%s\n' '중단: 현재 자동값과 장애 증거 UID가 필요하다.' >&2; elif [ "$INCIDENT_POD_UID" = "$POD_UID" ]; then printf 'UID가 같음 current=%s incident=%s; 재생성 분기로 가지 않는다.\n' "$POD_UID" "$INCIDENT_POD_UID"; else printf 'UID_CHANGED=true current=%s incident=%s; 새 Pod의 --previous로 이전 UID를 찾지 않는다.\n' "$POD_UID" "$INCIDENT_POD_UID"; fi`

성공 gate는 두 UID와 각각의 관측 시각이 기존 증거에 함께 있는 것이다. 현재 Pod Event가 없다고 이전 UID의 Event나 원인이 없었다고 판단하지 않는다. 새 UID의 `--previous`는 이전 UID 로그 복구가 아니다. 이전 UID 로그는 5절의 중앙 수집기 범위로 이관한다.

### 5. 중앙 로그 fallback

진입 증거: `--previous`와 확인된 runtime path가 실패했거나 UID가 변경됐다. `END_RFC3339`는 장애 종료 또는 조사 종료 시각이며 운영자 선택값이다. 중앙 수집기의 실제 제품·URL·query 문법은 환경 계약을 확인하지 않고 발명하지 않는다.

**중앙 조회 시간 등록 — 같은 Bash에서 한 번 실행**

`END_RFC3339='PASTE_END_RFC3339_HERE'; CENTRAL_RANGE_READY=false; unset START_CANONICAL_TMP END_CANONICAL_TMP START_EPOCH_TMP END_EPOCH_TMP; if [ "$START_READY" != true ] || [ -z "${START_RFC3339:-}" ] || [ -z "$END_RFC3339" ]; then printf '중단: START_RFC3339와 END_RFC3339를 먼저 유효한 UTC 값으로 등록한다. end=%s\n' "$END_RFC3339" >&2; elif [[ ! "$START_RFC3339" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] || [[ ! "$END_RFC3339" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]]; then printf '중단: START/END는 strict UTC Z 형식이어야 함 start=%s end=%s\n' "$START_RFC3339" "$END_RFC3339" >&2; elif START_CANONICAL_TMP="$(date -u -d "$START_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" && END_CANONICAL_TMP="$(date -u -d "$END_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" && [ "$START_CANONICAL_TMP" = "$START_RFC3339" ] && [ "$END_CANONICAL_TMP" = "$END_RFC3339" ] && START_EPOCH_TMP="$(date -u -d "$START_RFC3339" '+%s' 2>/dev/null)" && END_EPOCH_TMP="$(date -u -d "$END_RFC3339" '+%s' 2>/dev/null)"; then if [ "$END_EPOCH_TMP" -ge "$START_EPOCH_TMP" ]; then CENTRAL_RANGE_READY=true; export END_RFC3339 CENTRAL_RANGE_READY; printf 'CENTRAL_RANGE_READY=true strict_utc=true start=%s end=%s start_epoch=%s end_epoch=%s uid=%s\n' "$START_RFC3339" "$END_RFC3339" "$START_EPOCH_TMP" "$END_EPOCH_TMP" "${INCIDENT_POD_UID:-$POD_UID}"; else printf '중단: END가 START보다 빠름 start=%s end=%s\n' "$START_RFC3339" "$END_RFC3339" >&2; fi; else printf '중단: START/END canonical round-trip 실패 start=%s end=%s\n' "$START_RFC3339" "$END_RFC3339" >&2; fi`

`CENTRAL_RANGE_READY=true`일 때만 중앙 수집기 담당자에게 `namespace=$NS`, `pod=$POD`, `uid=${INCIDENT_POD_UID:-$POD_UID}`, `container=$CONTAINER`, `node=$NODE`, `start=$START_RFC3339`, `end=$END_RFC3339`, 확인된 previous runtime ID를 전달한다. Pod 이름만 필터로 쓰지 않는다. 중앙 조회 범위는 다음과 같이 bounded 요청으로 기록한다.

```text
대상 UID: incident 증거의 UID 우선
시간 범위(UTC): START_RFC3339부터 END_RFC3339
대상: namespace, Pod, container, node, 확인된 previous runtime ID
필터: panic|fatal|error|exception|timeout|refused|denied|permission|oom|killed
```

중앙 결과의 성공 gate는 같은 UID·container·시간 범위의 로그 존재와 비식별 오류 구간이다. 빈 결과는 보존 기간, 수집 지연, multiline 처리, 필터 불일치, 권한·query 실패 중 하나이며 원인 부재가 아니다. 중앙에서 찾은 이전 UID 로그는 새 Pod의 `--previous` 복구가 아니므로 runtime·kubelet 복구와 별도로 기록한다.

## Prometheus 빠른 관측

Prometheus와 kube-state-metrics가 실제로 수집되는 경우에만 사용한다. metric 부재와 query transport/API 실패를 구분하고, 빈 series는 정상이나 0이 아니다. 이름을 regex matcher에 넣을 때 escape한 등록값을 쓴다.

**PromQL matcher·쿼리 생성 — 아래 한 줄 전체를 복사**

`QUERY_READY=false; if [ "$SELECTION_READY" != true ] || [ "$AUTO_READY" != true ] || [ -z "$POD_UID" ]; then printf '%s\n' '중단: 자동값·Pod UID·container 선택이 필요하다.' >&2; else NS_RE="$(printf '%s' "$NS" | sed 's/[][\\.^$*+?(){}|]/\\&/g')"; POD_RE="$(printf '%s' "$POD" | sed 's/[][\\.^$*+?(){}|]/\\&/g')"; POD_UID_RE="$(printf '%s' "$POD_UID" | sed 's/[][\\.^$*+?(){}|]/\\&/g')"; CONTAINER_RE="$(printf '%s' "$CONTAINER" | sed 's/[][\\.^$*+?(){}|]/\\&/g')"; printf 'sum by(namespace,pod,uid,container)(increase(kube_pod_container_status_restarts_total{namespace=~"%s",pod=~"%s",uid=~"%s",container=~"%s"}[15m]))>0\n' "$NS_RE" "$POD_RE" "$POD_UID_RE" "$CONTAINER_RE"; printf 'kube_pod_container_status_last_terminated_timestamp{namespace=~"%s",pod=~"%s",uid=~"%s",container=~"%s"}\n' "$NS_RE" "$POD_RE" "$POD_UID_RE" "$CONTAINER_RE"; QUERY_READY=true; export NS_RE POD_RE POD_UID_RE CONTAINER_RE QUERY_READY; printf 'QUERY_READY=true matcher는 namespace·pod·uid·container bounded 출력만 사용한다.\n'; fi`

`QUERY_READY=true`는 완성된 문자열을 생성했다는 뜻이지 Prometheus transport, HTTP status, query success 또는 metric 존재를 보장하지 않는다. query UI/API에서 오류가 나면 조회 실패로, HTTP/API가 성공했지만 series가 없으면 metric 미수집·label 불일치·시간 범위 문제로 분리한다. 종료 timestamp·reason 흔적이 있어도 previous 로그 보존은 보장하지 않는다.

## 상태 변경 gate

이 문서는 읽기 전용이다. Pod 삭제·rollout restart·patch·scale·kubelet 재시작·node drain·로그 파일 조작·TLS 검증 비활성화는 previous 로그 해결책으로 실행하지 않는다. 별도 변경이 필요하면 trigger는 원인 layer와 영향 범위·현재/이전 UID·보존 상태가 확인된 경우이고, authority는 서비스·node·로그 owner의 승인과 최소 권한이다. 대상, 승인 창, rollback, 중단 조건과 실행 후 검증을 별도 변경 기록에 닫는다. 새 Warning, Ready 감소, restart 증가, 민감정보 노출 또는 다른 consumer 영향이면 즉시 중단한다.

## 정상화와 증거 보존

정상화는 역순으로 `application 기능 → log stream·API data → kubelet/runtime 보존 → Pod UID·container state`를 확인한다. 같은 UID에서 원하는 Ready, restart 증가 중단, 같은 종료 reason 반복 없음, 새 Warning 없음, 실제 서비스 기능과 재발 관찰 창을 모두 확인한다. `Running`, `Ready`, `restartCount` 정지, `--previous` 성공은 각각 다음 계층과 application 정상의 증거가 아니다.

보존 항목은 namespace, Pod 이름, current·incident UID, container, node, current·previous runtime ID, UTC 관측 시각, state reason·exitCode·finishedAt, `--previous`·runtime·중앙 수집 결과의 유무와 비식별 오류 유형이다. Secret·token·개인키·로그 원문은 저장하지 않는다.

- `kubectl logs --previous`, Pod `metadata.uid`, `containerStatuses.restartCount`, `state`, `lastState.terminated`를 Kubernetes Server·`kubectl` 1.26.x 기준으로 사용한다.
