# Pod 이벤트에 FailedCreatePodSandBox가 기록된 경우

## 입력값과 빠른 수집

처음에는 namespace와 Pod만 입력한다. Pod API와 node API가 현재 Pod UID·phase·node·runtimeClass·hostNetwork·dnsPolicy·Pod IP·container/port 관계를 자동 등록한다. namespace와 Pod 이름은 PromQL용 escape 후보로 계산하고, CNI plugin Pod·container, 시간, runtime service·CRI endpoint·sandbox ID와 pause PID는 관측 결과를 본 뒤 운영자가 선택한다. API 실패·빈 후보·UID 불일치가 있으면 다음 단계로 진행하지 않고 파생값을 비운다.

| 종류 | 값 | 출처와 사용 범위 |
|---|---|---|
| 최초 입력 | `NS`, `POD` | 승인된 namespace와 대상 Pod 이름. 문서 전체에서 한 번만 입력한다. |
| API 자동값 | `POD_UID`, `NODE`, `PHASE`, `RUNTIME_CLASS`, `HOST_NETWORK`, `DNS_POLICY`, `POD_IP`, `POD_START`, `RUNTIME_VERSION`, `NODE_UID`, `SANDBOX_EVENT_UID`, `SANDBOX_EVENT_MESSAGE`, `SANDBOX_EVENT_TIME`, `SANDBOX_EVENT_EPOCH`, `SANDBOX_PID`, `NS_RE`, `POD_RE`, `OBSERVED_AT` | Pod·node API와 같은 UID의 정확히 하나인 canonical sandbox Event에서 등록한다. |
| 계산 후보 | `NS_RE`, `POD_RE` | PromQL label matcher 후보. escape 결과를 bounded 출력으로 확인한다. |
| 운영자 선택값 | `CNI_NAMESPACE`, `CNI_POD`, `CNI_CONTAINER`, `START_RFC3339`, `START_JOURNAL`, `END_JOURNAL`, `NODE_HOST`, `KUBELET_SERVICE`, `RUNTIME_SERVICE`, `CRI_ENDPOINT`, `SANDBOX_ID`, `PAUSE_PID`, `POD_INTERFACE`, `POD_ROUTE`, `FIREWALL_BACKEND`, `FIREWALL_TARGET` | node 범위 후보 출력·실제 구현·권한·UID 대조 뒤 필요한 상세 분기에서 한 번 선택한다. `NODE_HOST`는 승인된 remote host다. |

### 실행 위치·도구·권한 전제

kubectl·logs·port와 network 관측은 승인된 context에 연결된 작업 PC 또는 bastion의 **같은 Bash 터미널**에서 실행한다. 변수와 gate를 다음 명령에 전달하므로 터미널을 바꾸면 초기화 절부터 다시 실행한다. API 조회에는 Pod·Event·Node와 CNI Pod를 읽을 권한, `pods/log` 권한이 필요하다. node journal·CRI·network namespace 명령은 실제 node shell 접근, 확인된 systemd unit·CRI endpoint, 승인된 `sudo` 권한이 있을 때만 사용한다. Secret·token·인증서 개인키·개인정보·전체 방화벽 규칙과 로그 원문은 저장하지 않는다.

**Bash·필수 도구 확인 — 아래 한 줄 전체를 복사**

`TOOLS_READY=false; if [ -z "${BASH_VERSION:-}" ]; then printf '%s\n' '중단: 같은 Bash에서 실행한다.' >&2; else MISSING_TOOLS=''; for TOOL in kubectl jq grep sed date; do command -v "$TOOL" >/dev/null 2>&1 || MISSING_TOOLS="$MISSING_TOOLS $TOOL"; done; if [ -z "$MISSING_TOOLS" ]; then TOOLS_READY=true; printf 'TOOLS_READY=true Bash=%s\n' "$BASH_VERSION"; else printf '중단: 없는 도구=%s\n' "$MISSING_TOOLS" >&2; fi; fi`

`TOOLS_READY=true`가 아니면 다음 단계로 진행하지 않는다. `journalctl`, `sudo`, `crictl`, `nsenter`, `ip`, `iptables`는 해당 분기에서 실제 존재·권한·backend를 별도로 확인하며 실패하면 구현체별 명령을 추측하지 않고 owner에게 이관한다.

### 대상 지정·이전 상태 초기화·API 자동 등록

재실행 시작 시 이전 Pod·node·CNI·runtime·sandbox·PID·시간값을 모두 무효화한다. Pod와 node API, 필수 field 파싱, regex escape가 모두 성공한 경우에만 `AUTO_READY=true`가 된다.

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | 같은 Pod UID의 Event에서 `reason=FailedCreatePodSandBox` 또는 `Failed to create pod sandbox`가 확인되는 경우 |
| 적용 | `AUTO_READY=true`, Pod UID, node UID·name과 Event의 실제 시각·message를 확인할 수 있는 경우 |
| 제외 | `FailedMount`·`FailedAttachVolume`은 [[25. Pod 이벤트에 FailedMount·FailedAttachVolume이 기록된 경우]], `FailedScheduling`은 [[18. Pod 이벤트에 FailedScheduling이 기록된 경우]], image pull은 [[07. Pod STATUS가 ImagePullBackOff·ErrImagePull인 경우]], container start는 [[10. Pod STATUS가 CreateContainerError·RunContainerError인 경우]], probe 실패는 [[19. Pod readiness probe가 실패하는 경우]]·[[20. Pod liveness probe가 실패하는 경우]]·[[21. Pod startup probe가 실패하는 경우]]로 이동한다. |

검색 문자열: `FailedCreatePodSandBox`, `Failed to create pod sandbox`, `RunPodSandbox`, `networkPlugin`, `CNI`, `IPAM`, `ADD`, `setup network`, `DNS`, `route`, `pause`, `OCI`, `rpc error`, `permission denied`.

이 증상은 application container보다 sandbox 생성 경로를 먼저 본다. CNI, IPAM, runtime, OS 구현체와 실제 Pod·node가 확인되기 전에는 구현체별 명령을 만들지 않는다.

## 최초 확인

`AUTO_READY=true`일 때만 Pod get·describe를 실행한다. API 읽기 성공은 객체 identity를 확인한 범위이며, sandbox·CNI·runtime·application 성공을 보장하지 않는다.

**Pod 상태 확인 — 아래 한 줄 전체를 복사**

`FIRST_CHECK_READY=false; if [ "$AUTO_READY" != true ]; then printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; elif kubectl get pod "$POD" -n "$NS" -o wide && kubectl describe pod "$POD" -n "$NS"; then FIRST_CHECK_READY=true; printf 'FIRST_CHECK_READY=true pod=%s uid=%s node=%s node_uid=%s observed=%s\n' "$POD" "$POD_UID" "$NODE" "$NODE_UID" "$OBSERVED_AT"; else printf '%s\n' '중단: Pod get 또는 describe 실패.' >&2; fi`

볼 것: `STATUS`, `READY`, `RESTARTS`, `NODE`, `AGE`, Pod IP와 UID. `describe`의 Conditions와 `FailedCreatePodSandBox` Event 첫 message·node·시각을 본다.

**현재 Pod UID의 Event 한 번 수집 — 아래 한 줄 전체를 복사**

`EVENT_API_OK=false; EVENT_READY=false; unset EVENT_JSON; if [ "$FIRST_CHECK_READY" != true ]; then printf '%s\n' '중단: FIRST_CHECK_READY가 아니다.' >&2; elif EVENT_JSON="$(kubectl get events -n "$NS" --field-selector "involvedObject.kind=Pod,involvedObject.name=$POD,involvedObject.uid=$POD_UID" --sort-by=.metadata.creationTimestamp -o json)"; then if jq -e '.items | type == "array"' <<<"$EVENT_JSON" >/dev/null; then EVENT_API_OK=true; if jq -e '.items | length > 0' <<<"$EVENT_JSON" >/dev/null; then jq -r '.items[] | "=== Sandbox Event ===\nEvent UID: \(.metadata.uid)\n관련 Pod UID: \(.involvedObject.uid)\n생성 시각: \(.metadata.creationTimestamp // "-")\n최초 시각: \(.firstTimestamp // "-")\n마지막 시각: \(.lastTimestamp // "-")\nEvent 시각: \(.eventTime // "-")\nSeries 마지막 시각: \(.series.lastObservedTime // "-")\nType: \(.type // "-")\nReason: \(.reason // "-")\nCount: \(.count // 0)\nMessage: \(.message // "-")\n"' <<<"$EVENT_JSON"; EVENT_READY=true; printf 'EVENT_READY=true pod_uid=%s node=%s\n' "$POD_UID" "$NODE"; else printf '중단: 현재 Pod UID의 Event가 비어 있다. 정상·오류 없음으로 해석하지 말고 Event TTL·권한·관측 범위를 확인한다.\n' >&2; unset EVENT_JSON; fi; else printf '%s\n' '중단: Events API data가 배열이 아니다.' >&2; unset EVENT_JSON; fi; else printf '%s\n' '중단: Event API 조회 실패. Event 부재와 조회 실패를 구분하고 진행하지 않는다.' >&2; unset EVENT_JSON; fi`

Event의 `EVENT UID`, 관련 Pod UID, 실제로 채워진 시각 필드, `COUNT`, `REASON`, message suffix를 보존한다. 장애 시작 시각은 Event 시각과 Pod 생성 시각을 대조해 운영자가 정하고 수집 시각을 복사하지 않는다. Event message에 token·인증서·개인정보가 있으면 원문을 저장하지 않고 오류 suffix만 기록한다.

**같은 UID·시각의 FailedCreatePodSandBox 직접 증거 gate — 아래 한 줄 전체를 복사**

`SANDBOX_READY=false; SANDBOX_EVENT_TIME_READY=false; SANDBOX_EVENT_CANDIDATE_COUNT=0; unset SANDBOX_EVENT_UID SANDBOX_EVENT_MESSAGE SANDBOX_EVENT_TIME SANDBOX_EVENT_EPOCH SANDBOX_EVENT_CANDIDATES; if [ "$EVENT_READY" != true ]; then printf '%s\n' '중단: EVENT_READY가 아니다.' >&2; elif SANDBOX_EVENT_CANDIDATES="$(jq -c --arg uid "$POD_UID" '[.items[] | select(.involvedObject.uid==$uid and (.reason=="FailedCreatePodSandBox" or ((.message // "") | test("(^|[^A-Za-z])Failed to create pod sandbox([^A-Za-z]|$)"; "i")))) | select((.message // "") | (type == "string" and length > 0)) | ([.eventTime,.series.lastObservedTime,.lastTimestamp,.firstTimestamp] | map(select(type=="string" and length>0)) | .[0]) as $time | select($time != null) | {event_uid:.metadata.uid,message:.message,event_time:$time}]' <<<"$EVENT_JSON")" && SANDBOX_EVENT_CANDIDATE_COUNT="$(jq -er 'length' <<<"$SANDBOX_EVENT_CANDIDATES")" && [ "$SANDBOX_EVENT_CANDIDATE_COUNT" -eq 1 ] && SANDBOX_EVENT_UID="$(jq -er '.[0].event_uid' <<<"$SANDBOX_EVENT_CANDIDATES")" && SANDBOX_EVENT_MESSAGE="$(jq -er '.[0].message' <<<"$SANDBOX_EVENT_CANDIDATES")" && SANDBOX_EVENT_TIME="$(jq -er '.[0].event_time' <<<"$SANDBOX_EVENT_CANDIDATES")" && SANDBOX_EVENT_EPOCH="$(date -u -d "$SANDBOX_EVENT_TIME" +%s 2>/dev/null)"; then SANDBOX_READY=true; SANDBOX_EVENT_TIME_READY=true; printf 'SANDBOX_READY=true SANDBOX_EVENT_TIME_READY=true canonical_event_count=%s sandbox_event_uid=%s pod_uid=%s node=%s event_time=%s event_epoch=%s message=%s\n' "$SANDBOX_EVENT_CANDIDATE_COUNT" "$SANDBOX_EVENT_UID" "$POD_UID" "$NODE" "$SANDBOX_EVENT_TIME" "$SANDBOX_EVENT_EPOCH" "$SANDBOX_EVENT_MESSAGE"; else printf '중단: 같은 Pod UID의 canonical FailedCreatePodSandBox Event 후보가 정확히 하나가 아니거나 UID/message/time/epoch 파싱에 실패했다 count=%s. 다른 Event를 혼합하지 않는다.\n' "$SANDBOX_EVENT_CANDIDATE_COUNT" >&2; unset SANDBOX_EVENT_UID SANDBOX_EVENT_MESSAGE SANDBOX_EVENT_TIME SANDBOX_EVENT_EPOCH; fi`

`SANDBOX_READY=true`는 Event의 관련 UID가 현재 `$POD_UID`와 같고 정확한 reason 또는 직접 `Failed to create pod sandbox` message, 파싱 가능한 Event 시각이 모두 확인됐다는 뜻이다. 다른 UID·동명 Pod·시각 없는 Event는 sandbox 원인 근거로 사용하지 않는다.

**상세 진입 전 Pod UID 재조회 gate — 아래 한 줄 전체를 복사**

`POD_IDENTITY_READY=false; CURRENT_POD_UID=''; if [ "$SANDBOX_READY" != true ]; then printf '%s\n' '중단: SANDBOX_READY가 아니다.' >&2; elif CURRENT_POD_UID="$(kubectl get pod "$POD" -n "$NS" -o jsonpath='{.metadata.uid}')" && [ "$CURRENT_POD_UID" = "$POD_UID" ]; then POD_IDENTITY_READY=true; printf 'POD_IDENTITY_READY=true pod=%s uid=%s sandbox_event_time=%s\n' "$POD" "$CURRENT_POD_UID" "$SANDBOX_EVENT_TIME"; else SANDBOX_READY=false; printf '중단: 상세 진입 전 Pod UID mismatch 또는 재조회 실패 expected=%s actual=%s\n' "$POD_UID" "${CURRENT_POD_UID:--}" >&2; fi`

## 관측별 진단 경로

| 지금 보이는 것 | 먼저 볼 것 | 그다음 어디를 볼지 | 상세 절 |
|---|---|---|---|
| 한 node의 여러 Pod에서 같은 sandbox 실패 | node 범위와 첫 Event message | CNI node plugin → kubelet → runtime → Linux network | [[#1. CNI·IPAM 경로\|1]], [[#2. kubelet·runtime·CRI·OCI 경로\|2]], [[#3. CNI 이후 Linux network namespace·route·DNS\|3]] |
| 여러 node에서 `IPAM`, `pool exhausted`, `no available IP` | IP 할당 실패 범위 | IPAM owner 또는 [[03. Pod IP가 중복되거나 IPAM 주소 범위가 소진된 경우]] | [[#1. CNI·IPAM 경로\|1]] |
| CNI `ADD` 성공인데 `route`, `DNS`, interface가 없음 | sandbox network namespace의 주소·경로 | CNI 결과 → Linux netns/route/DNS | [[#3. CNI 이후 Linux network namespace·route·DNS\|3]] |
| `RunPodSandbox`, `OCI`, `rpc error`, runtime timeout | kubelet과 확인된 runtime service | CRI/OCI → node filesystem·cgroup | [[#2. kubelet·runtime·CRI·OCI 경로\|2]] |
| `pause`, `image`, `unauthorized`, `x509` | 실제 pause image와 registry 경로 | runtime pull → DNS/route/proxy/TLS → registry | [[#2. kubelet·runtime·CRI·OCI 경로\|2]] |

진단 순서는 `Event → runtime sandbox와 CNI/IPAM 구분 → CNI plugin·kubelet·runtime → Linux network namespace·route·DNS`다. 한 hop의 성공은 다음 hop이나 application 정상의 보장이 아니다.

## 관측 이후 장애 파이프라인

### 1. CNI·IPAM 경로

진입 증거는 Event suffix에 `networkPlugin`, `CNI ADD`, `failed to set up pod network`, `failed to allocate IP`, `address pool exhausted`, `no available IP`가 있고 같은 node·시각의 CNI evidence를 비교해야 하는 경우다. 연결 경로는 `실행 host → kubectl client/API server → 대상 node kubelet/runtime → CNI DaemonSet Pod·container → CNI ADD/IPAM → Pod network namespace`다. CNI Pod를 읽었다고 Pod sandbox나 IP allocation 성공을 보장하지 않는다.

`FIREWALL_BACKEND`는 `iptables-nft`, `iptables-legacy`, `nftables` 중 remote 실제 검출값과 일치해야 한다. `iptables -V`의 `(nf_tables)`·`(legacy)`와 `nft --version`을 먼저 확인하며, 확인되지 않은 backend나 target을 추측하지 않는다. nftables backend는 iptables 명령으로 대체하지 않고, 확인된 family/table/chain을 가진 node owner의 bounded nft read-only 절차로 이관한다.

[[ "$FIREWALL_BACKEND" =~ ^(iptables-nft|iptables-legacy|nftables)$ ]]; then printf '중단: FIREWALL_BACKEND는 iptables-nft, iptables-legacy 또는 nftables이어야 한다 value=%s\n' "$FIREWALL_BACKEND" >&2; false; else printf -v REMOTE_FW_DETECT_CMD 'if command -v iptables >/dev/null 2>&1; then iptables -V; fi; if command -v nft >/dev/null 2>&1; then nft --version; fi'; REMOTE_FIREWALL_INFO="$(ssh -o BatchMode=yes -o ConnectTimeout=10 -- "$NODE_HOST" "$REMOTE_FW_DETECT_CMD")"; FW_DETECT_RC=$?; if [ "$FW_DETECT_RC" -ne 0 ]; then printf '중단: remote firewall backend 검출 실패 rc=%s node=%s host=%s\n' "$FW_DETECT_RC" "$NODE" "$NODE_HOST" >&2; false; elif [ "$FIREWALL_BACKEND" = iptables-nft ] && printf '%s\n' "$REMOTE_FIREWALL_INFO" | grep -Eq 'iptables v.*\(nf_tables\)'; then FIREWALL_BACKEND_READY=true; elif [ "$FIREWALL_BACKEND" = iptables-legacy ] && printf '%s\n' "$REMOTE_FIREWALL_INFO" | grep -Eq 'iptables v.*\(legacy\)'; then FIREWALL_BACKEND_READY=true; elif [ "$FIREWALL_BACKEND" = nftables ] && printf '%s\n' "$REMOTE_FIREWALL_INFO" | grep -Eq '^nftables v'; then FIREWALL_BACKEND_READY=true; else printf '중단: 선택 backend가 remote 검출값과 일치하지 않는다 selected=%s remote=%s\n' "$FIREWALL_BACKEND" "$REMOTE_FIREWALL_INFO" >&2; false; fi; if [ "$FIREWALL_BACKEND_READY" = true ] && { [ "$FIREWALL_BACKEND" = iptables-nft ] || [ "$FIREWALL_BACKEND" = iptables-legacy ]; }; then printf -v REMOTE_FW_CMD 'sudo -n iptables -S %q' "$FIREWALL_TARGET"; ssh -o BatchMode=yes -o ConnectTimeout=10 -- "$NODE_HOST" "$REMOTE_FW_CMD"; FW_RC=$?; if [ "$FW_RC" -ne 0 ]; then FIREWALL_BACKEND_READY=false; printf '중단: verified %s firewall 조회 실패 rc=%s target=%s node=%s host=%s\n' "$FIREWALL_BACKEND" "$FW_RC" "$FIREWALL_TARGET" "$NODE" "$NODE_HOST" >&2; false; else FIREWALL_QUERY_READY=true; printf 'FIREWALL_QUERY_READY=true backend=%s target=%s rc=%s node=%s host=%s\n' "$FIREWALL_BACKEND" "$FIREWALL_TARGET" "$FW_RC" "$NODE" "$NODE_HOST"; true; fi; elif [ "$FIREWALL_BACKEND_READY" = true ] && [ "$FIREWALL_BACKEND" = nftables ]; then printf 'FIREWALL_NON_APPLICABLE backend=nftables target=%s; remote nft availability verified, node owner의 확인된 nft family/table/chain 절차로 이관한다.\n' "$FIREWALL_TARGET" >&2; true; else false; fi; fi`

전체 방화벽 규칙을 저장하지 않고 필요한 interface·route·drop 오류만 기록한다. host 규칙 변경·netns 조작·임의 route 추가는 이 런북의 복구가 아니다.

## 복구 전 권한·영향 gate와 제한적 action contract

기본 action은 Event UID·Pod UID·node 범위·실패 계층을 확정해 CNI/IPAM, runtime, kubelet 또는 node owner에게 이관하는 것이다. 상태 변경 전 다음을 모두 기록한다.

- **Trigger:** Event message와 동일 시각의 CNI/IPAM·kubelet·runtime·Linux 오류가 같은 Pod UID·node로 연결됐다.
- **Gate:** 대상 cluster, namespace, Pod UID, node UID, 서비스 영향, owner, 승인 범위와 증거 보존을 다시 대조했다.
- **대상·영향:** 확인된 CNI plugin·runtime·node만 대상으로 하고 다른 node·namespace·tenant의 blast radius를 평가한다.
- **권한·승인:** CNI/IPAM 설정은 network owner, runtime·node는 platform owner, workload·서비스 영향은 workload/service owner가 승인한다.
- **금지:** 원인 미확정 Pod 삭제, CNI/IPAM 설정 변경, CNI DaemonSet·runtime 재시작, pause image 변경, IP pool 변경과 임의 IP 회수를 일반 복구로 실행하지 않는다.
- **효과의 한계:** 승인된 owner 조치는 sandbox 재생성을 기대할 뿐 IP pool·registry·node 장애와 application Ready를 보장하지 않는다.
- **중단·rollback:** Warning/Event count 증가, 다른 node 확산, 정상 replica 감소, CNI/runtime health 악화, route·DNS 영향 증가 시 중단하고 변경 전 설정 또는 owner rollback 기준으로 이관한다.
- **검증:** CNI/IPAM 주소 할당, interface·route·DNS, runtime sandbox, kubelet Warning 중단, 같은 Pod UID Event 비반복, 원하는 Ready 수와 실제 요청·핵심 기능을 즉시와 재평가 시각에 확인한다.

## 정상화와 증거 보존

정상화는 경로를 역순으로 확인한다. 실제 서비스 요청·application 기능 → listener·DNS resolution → Pod remote network namespace interface/address/route → host veth·route·firewall → CNI/IPAM allocation → runtime sandbox·kubelet Warning 중단 → Pod UID·node identity 순서다. `Running`, Pod IP 존재, CNI Pod `Ready`, sandbox inspect 성공, Event 일시 중단은 각각 단독 정상화 근거가 아니다. 원하는 Ready 수와 실제 기능, 관찰 창의 재발 부재를 확인한다.

namespace, Pod UID, node UID/name, Event UID의 첫 message와 실제 시각, 같은 node·다른 node 범위, 확인된 CNI Pod/container/owner, kubelet·runtime service와 CRI endpoint, sandbox ID와 metadata, CNI/IPAM·runtime·Linux 오류의 필요한 행, 서비스 영향과 승인·이관 정보를 보존한다. Secret·token·인증서 개인키·개인정보·전체 로그와 방화벽 원문은 보존하지 않는다.

## Prometheus 빠른 관측

실제로 metric이 수집되는 경우에만 사용한다. 등록된 `$NS_RE`, `$POD_RE`, 현재 `$POD_UID`로 PromQL 완성본을 생성하고, UID label 계약이 없는 metric은 사용하지 않고 Event·API evidence로 이관한다. 출력 한 줄만 Prometheus 또는 Grafana에 붙여 넣는다. query transport/API 실패와 빈 series를 구분하며, 빈 결과를 Pending 정상·container 미생성·sandbox 오류 없음으로 해석하지 않는다.

**Pending phase PromQL 생성 — 아래 한 줄 전체를 복사**

`if [ "$AUTO_READY" != true ]; then printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; else printf 'kube_pod_status_phase{namespace=~"%s",pod=~"%s",uid="%s",phase="Pending"}==1\n' "$NS_RE" "$POD_RE" "$POD_UID"; fi`

**scheduled 상태 PromQL 생성 — 아래 한 줄 전체를 복사**

`if [ "$AUTO_READY" != true ]; then printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; else printf 'kube_pod_status_scheduled{namespace=~"%s",pod=~"%s",uid="%s",condition="true"}==1\n' "$NS_RE" "$POD_RE" "$POD_UID"; fi`

**container info 부재 PromQL 생성 — 아래 한 줄 전체를 복사**

`if [ "$AUTO_READY" != true ]; then printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; else printf 'absent_over_time(kube_pod_container_info{namespace=~"%s",pod=~"%s",uid="%s"}[10m])\n' "$NS_RE" "$POD_RE" "$POD_UID"; fi`

Pending·scheduled=true인데 container info가 관측 구간에 없으면 sandbox 또는 container 생성 전 경로의 보조 signal이다. exporter 누락·label 불일치와도 같으므로 FailedCreatePodSandBox를 직접 확정하지 않는다. CNI·IPAM·pause image·runtime 오류는 Event와 kubelet·runtime log로 판정한다.

## 1.26 경계와 미검증 항목

Kubernetes Server와 `kubectl`은 `1.26.x`를 기준으로 한다. CNI/IPAM 구현체, DaemonSet label, kubelet·runtime systemd unit, CRI endpoint, pause image 설정, OS 보안 정책, iptables/nftables backend와 log 위치는 환경별 미검증이다. 확인 전 특정 구현체 명령을 기본값으로 사용하지 않는다.
