# DaemonSet의 desired·current·ready scheduled 수가 수렴하지 않는 경우

## 입력값과 빠른 수집

실행 host는 승인된 `kubectl` context가 있는 작업 PC 또는 bastion의 같은 Bash다. 경로는 `작업 host → API server → DaemonSet controller 상태 → Node eligibility → Pod owner/node → kubelet·daemon 기능`이다. `desiredNumberScheduled`는 전체 Node 수가 아니라 controller가 계산한 eligible Node 수다.

| 구분 | 값 | 처리 |
|---|---|---|
| 최초 입력 | `NS`, `DS` | exact namespace/name을 한 번 입력한다. |
| API 자동값 | `DS_UID`, `DS_RV`, `DS_GENERATION`, `DS_SELECTOR`, `SPEC_DIGEST` | 현재 객체에서 등록한다. |
| 계산 후보 | owner UID가 같은 Pod의 node coverage, Node label·taint 후보 | API producer가 모두 성공한 뒤 계산한다. |
| 운영자 선택 | `FOCUS_NODE` | 출력에서 조사할 Node 하나를 고르고 UID·Pod relation을 검증한다. |

**현재 identity와 selector 자동 등록**

재등록 시 UID·resourceVersion·owner·node·관계·시간과 downstream `READY`를 모두 버린다. 이후 조회마다 현재 DaemonSet UID를 직접 재검사한다.

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | desired/current/ready/available 값이 서로 다르거나 observedGeneration이 뒤처진다. |
| 적용 | owner UID별 node coverage와 eligible 조건을 분리해 확인할 수 있다. |
| 제외 | `numberMisscheduled>0`이 주 증상이면 [[02. DaemonSet numberMisscheduled가 0이 아닌 경우]], old/new revision 정체는 [[03. DaemonSet rolling update의 updated scheduled 수가 수렴하지 않는 경우]]로 이동한다. |

검색 문자열: `desiredNumberScheduled`, `currentNumberScheduled`, `numberReady`, `numberAvailable`, `numberUnavailable`, `observedGeneration`, `FailedPlacement`, `FailedDaemonPod`.

## 최신 snapshot

Pod는 selector만으로 채택하지 않고 controller owner UID가 현재 DaemonSet UID와 정확히 같은 항목만 센다. init/regular container 상태는 구분한다.

`unset SNAPSHOT_READY SNAPSHOT_JSON SNAPSHOT_AT; SNAPSHOT_READY=false; if [ "$AUTO_READY" != true ]; then printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; elif DS_NOW="$(kubectl get daemonset "$DS" -n "$NS" -o json)"; then UID_NOW="$(jq -r '.metadata.uid' <<<"$DS_NOW")"; if [ "$UID_NOW" != "$DS_UID" ]; then AUTO_READY=false; printf '중단: DaemonSet UID 변경 old=%s current=%s\n' "$DS_UID" "$UID_NOW" >&2; elif PODS="$(kubectl get pods -n "$NS" -o json)" && NODES="$(kubectl get nodes -o json)"; then if ! OWNED="$(jq -c --arg uid "$DS_UID" '[.items[]|select(any(.metadata.ownerReferences[]?;.controller==true and .kind=="DaemonSet" and .uid==$uid))]' <<<"$PODS")"; then printf '%s\n' '중단: owner filter 오류' >&2; elif [ "$(jq 'length' <<<"$OWNED")" -eq 0 ]; then printf '%s\n' '중단: 현재 owner UID Pod가 0건이다.' >&2; else SNAPSHOT_AT="$(date -u +%Y-%m-%dT%H:%M:%SZ)"; SNAPSHOT_JSON="$(jq -n --argjson ds "$DS_NOW" --argjson pods "$OWNED" --argjson nodes "$NODES" --arg at "$SNAPSHOT_AT" '{observedAt:$at,ds:$ds,pods:$pods,nodes:$nodes.items}')"; SNAPSHOT_READY=true; jq -r '"SNAPSHOT_READY=true observedAt=\(.observedAt)\nUID=\(.ds.metadata.uid) generation=\(.ds.metadata.generation)/\(.ds.status.observedGeneration) desired/current/ready/available/unavailable/misscheduled/updated=\(.ds.status.desiredNumberScheduled)/\(.ds.status.currentNumberScheduled)/\(.ds.status.numberReady)/\(.ds.status.numberAvailable)/\(.ds.status.numberUnavailable)/\(.ds.status.numberMisscheduled)/\(.ds.status.updatedNumberScheduled)",(.pods[]|"=== Pod: \(.metadata.name) ===\nUID: \(.metadata.uid) ownerUID: \([.metadata.ownerReferences[]|select(.controller==true)][0].uid)\nNode: \(.spec.nodeName) revision: \(.metadata.labels["controller-revision-hash"])\nphase: \(.status.phase) deleting: \(.metadata.deletionTimestamp)\nregular: \([.status.containerStatuses[]?|"\(.name):ready=\(.ready),restart=\(.restartCount),containerID=\(.containerID//"-")"]|join(";"))\ninit: \([.status.initContainerStatuses[]?|"\(.name):ready=\(.ready),restart=\(.restartCount),containerID=\(.containerID//"-")"]|join(";"))")' <<<"$SNAPSHOT_JSON"; fi; else printf '%s\n' '중단: Pod 또는 Node API producer 실패' >&2; fi; else printf '%s\n' '중단: DaemonSet API producer 실패' >&2; fi`

## 관측별 진단 경로

| 지금 보이는 것 | 직접 gate | 다음 경로 |
|---|---|---|
| desired가 기대 Node 수와 다름 | template nodeName/nodeSelector/required affinity, 실제 Pod effective toleration과 Node label·taint | 정책 owner가 eligible 집합을 확정 |
| current가 desired보다 낮음 | eligible Node에 현재 owner UID Pod 존재 여부 | controller 생성 실패와 Pod scheduling을 분리 |
| current는 같고 ready/available이 낮음 | exact Pod UID의 regular/init 상태·restart·Ready·minReadySeconds | 해당 Pod 런북 |
| observedGeneration이 낮음 | 현재 generation/resourceVersion과 controller Event lifecycle | controller 조정 경로 |

**Node 후보 출력**

`if [ "$SNAPSHOT_READY" != true ]; then printf '%s\n' '중단: 최신 SNAPSHOT_READY가 아니다.' >&2; elif CUR="$(kubectl get daemonset "$DS" -n "$NS" -o json)" && [ "$(jq -r '.metadata.uid' <<<"$CUR")" = "$DS_UID" ]; then jq -r '.nodes[]|"=== Node: \(.metadata.name) ===\nUID: \(.metadata.uid)\nReady: \([.status.conditions[]?|select(.type=="Ready")|.status][0]//"-")\nlabels: \(.metadata.labels|to_entries|map(select(.key=="kubernetes.io/hostname" or .key=="topology.kubernetes.io/zone"))|from_entries)\ntaints: \(.spec.taints//[])"' <<<"$SNAPSHOT_JSON"; else SNAPSHOT_READY=false; printf '%s\n' '중단: 현재 DaemonSet identity 검사 실패' >&2; fi`

`FOCUS_NODE='PASTE_FOCUS_NODE_HERE'`

**Node와 Pod relation 선택 검증**

`unset NODE_READY NODE_UID NODE_RV FOCUS_POD FOCUS_POD_UID; NODE_READY=false; if [ "$SNAPSHOT_READY" != true ]; then printf '%s\n' '중단: 최신 SNAPSHOT_READY가 아니다.' >&2; elif NODE_JSON="$(kubectl get node "$FOCUS_NODE" -o json)" && CUR="$(kubectl get daemonset "$DS" -n "$NS" -o json)" && [ "$(jq -r '.metadata.uid' <<<"$CUR")" = "$DS_UID" ]; then NODE_UID="$(jq -r '.metadata.uid' <<<"$NODE_JSON")"; NODE_RV="$(jq -r '.metadata.resourceVersion' <<<"$NODE_JSON")"; MATCH="$(jq -c --arg node "$FOCUS_NODE" '[.pods[]|select(.spec.nodeName==$node)]' <<<"$SNAPSHOT_JSON")"; COUNT="$(jq 'length' <<<"$MATCH")"; if [ "$COUNT" -gt 1 ]; then printf '중단: 현재 owner UID Pod가 Node에 복수 count=%s\n' "$COUNT" >&2; elif [ "$COUNT" -eq 1 ]; then FOCUS_POD="$(jq -r '.[0].metadata.name' <<<"$MATCH")"; FOCUS_POD_UID="$(jq -r '.[0].metadata.uid' <<<"$MATCH")"; NODE_READY=true; printf 'NODE_READY=true node=%s nodeUID=%s pod=%s podUID=%s relation=spec.nodeName\n' "$FOCUS_NODE" "$NODE_UID" "$FOCUS_POD" "$FOCUS_POD_UID"; else NODE_READY=true; printf 'NODE_READY=true node=%s nodeUID=%s pod=none relation=missing-coverage-candidate\n' "$FOCUS_NODE" "$NODE_UID"; fi; else printf '%s\n' '중단: Node/DaemonSet API 검사 실패' >&2; fi`

**선택 Node 상세 조회**

`if [ "$NODE_READY" != true ]; then printf '%s\n' '중단: 최신 NODE_READY가 아니다.' >&2; elif NODE_NOW="$(kubectl get node "$FOCUS_NODE" -o json)" && [ "$(jq -r '.metadata.uid' <<<"$NODE_NOW")" = "$NODE_UID" ] && DS_NOW="$(kubectl get daemonset "$DS" -n "$NS" -o json)" && [ "$(jq -r '.metadata.uid' <<<"$DS_NOW")" = "$DS_UID" ]; then jq -n --argjson ds "$DS_NOW" --argjson node "$NODE_NOW" '{node:{name:$node.metadata.name,uid:$node.metadata.uid,ready:[$node.status.conditions[]?|select(.type=="Ready")][0],unschedulable:$node.spec.unschedulable,labels:$node.metadata.labels,taints:($node.spec.taints//[])},daemonTemplate:{nodeName:$ds.spec.template.spec.nodeName,nodeSelector:$ds.spec.template.spec.nodeSelector,requiredAffinity:$ds.spec.template.spec.affinity.nodeAffinity.requiredDuringSchedulingIgnoredDuringExecution,tolerations:$ds.spec.template.spec.tolerations,minReadySeconds:$ds.spec.minReadySeconds}}'; else NODE_READY=false; printf '%s\n' '중단: Node/DaemonSet identity drift' >&2; fi`

`Ready=False/Unknown`이나 `unschedulable`만으로 DaemonSet eligibility 제외를 확정하지 않는다. controller가 추가하는 toleration을 고려해 실제 생성 Pod의 effective toleration을 비교한다. Pod가 없으면 controller Event와 generation을, Pod가 Pending이면 exact UID·owner UID·node·init/regular reason을 해당 scheduling/runtime 런북으로 넘긴다. 노드 도구는 이 API 분기에서는 요구하지 않는다.

## 변경 전 gate

이 런북은 label·taint·affinity·toleration·selector 변경, Pod 삭제, rollout, cordon/drain 명령을 제공하지 않는다. 승인된 선언 경로 직전에만 다음 gate를 사용한다.

`APPROVAL_ID='PASTE_APPROVAL_ID_HERE'; EVIDENCE_ID='PASTE_EVIDENCE_ID_HERE'; CHANGE_START='PASTE_CHANGE_START_RFC3339_HERE'; CHANGE_END='PASTE_CHANGE_END_RFC3339_HERE'`

`unset MUTATION_READY REPLACEMENT_READY NORMALIZED_READY; MUTATION_READY=false; if [ "$NODE_READY" != true ]; then printf '%s\n' '중단: 최신 NODE_READY가 아니다.' >&2; elif [ -z "$APPROVAL_ID" ] || [ -z "$EVIDENCE_ID" ]; then printf '%s\n' '중단: 승인/evidence 없음' >&2; elif [[ ! "$CHANGE_START" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] || [[ ! "$CHANGE_END" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]]; then printf '%s\n' '중단: 변경 창 형식 오류' >&2; elif ! CS="$(date -u -d "$CHANGE_START" +%s)" || ! CE="$(date -u -d "$CHANGE_END" +%s)" || [ "$(date -u -d "@$CS" +%Y-%m-%dT%H:%M:%SZ)" != "$CHANGE_START" ] || [ "$(date -u -d "@$CE" +%Y-%m-%dT%H:%M:%SZ)" != "$CHANGE_END" ] || [ "$CS" -ge "$CE" ]; then printf '%s\n' '중단: 변경 창 round-trip/start<end 실패' >&2; elif CUR="$(kubectl get daemonset "$DS" -n "$NS" -o json)" && NODE_NOW="$(kubectl get node "$FOCUS_NODE" -o json)" && [ "$(jq -r '.metadata.uid' <<<"$CUR")" = "$DS_UID" ] && [ "$(jq -r '.metadata.resourceVersion' <<<"$CUR")" = "$DS_RV" ] && [ "$(jq -r '.metadata.uid' <<<"$NODE_NOW")" = "$NODE_UID" ] && [ "$(jq -S '.spec' <<<"$CUR" | sha256sum | cut -d' ' -f1)" = "$SPEC_DIGEST" ]; then MUTATION_READY=true; printf 'MUTATION_READY=true dsUID=%s nodeUID=%s digest=%s approval=%s window=%s..%s\n' "$DS_UID" "$NODE_UID" "$SPEC_DIGEST" "$APPROVAL_ID" "$CHANGE_START" "$CHANGE_END"; else SNAPSHOT_READY=false; NODE_READY=false; printf '%s\n' '중단: UID/resourceVersion/spec/node drift' >&2; fi`

`if [ "$MUTATION_READY" != true ]; then printf '%s\n' '중단: 최신 MUTATION_READY가 아니다.' >&2; elif CUR="$(kubectl get daemonset "$DS" -n "$NS" -o json)" && NODE_NOW="$(kubectl get node "$FOCUS_NODE" -o json)" && [ "$(jq -r '.metadata.uid' <<<"$CUR")" = "$DS_UID" ] && [ "$(jq -r '.metadata.resourceVersion' <<<"$CUR")" = "$DS_RV" ] && [ "$(jq -r '.metadata.uid' <<<"$NODE_NOW")" = "$NODE_UID" ]; then printf '승인 경계 재확인 approval=%s evidence=%s dsUID=%s nodeUID=%s\n' "$APPROVAL_ID" "$EVIDENCE_ID" "$DS_UID" "$NODE_UID"; else MUTATION_READY=false; printf '%s\n' '중단: 변경 직전 current identity drift' >&2; fi`

변경 기록에는 selector·revision·spec digest, node policy, daemon의 host/Service 기능, 다른 tenant/workload, quorum·idempotence 해당 여부, rollback 선언과 중단 조건을 기록한다. rollback 역시 현재 UID/resourceVersion/spec digest/approval/window를 새로 검사한다.

## replacement와 정상화

변경 후 이전 Pod UID·containerID·node relation과 모든 snapshot을 폐기한다. 현재 DaemonSet owner UID, 선택 Node UID, change window, non-deleting 조건으로 후보가 정확히 하나일 때만 등록한다.

`unset REPLACEMENT_READY NORMALIZED_READY REPLACEMENT_POD REPLACEMENT_POD_UID REPLACEMENT_POD_RV; REPLACEMENT_READY=false; SNAPSHOT_READY=false; NODE_READY=false; if [ "$MUTATION_READY" != true ]; then printf '%s\n' '중단: MUTATION_READY가 아니다.' >&2; elif CUR="$(kubectl get daemonset "$DS" -n "$NS" -o json)" && NODE_NOW="$(kubectl get node "$FOCUS_NODE" -o json)" && PODS="$(kubectl get pods -n "$NS" -o json)" && [ "$(jq -r '.metadata.uid' <<<"$CUR")" = "$DS_UID" ] && [ "$(jq -r '.metadata.uid' <<<"$NODE_NOW")" = "$NODE_UID" ]; then CAND="$(jq -c --arg uid "$DS_UID" --arg node "$FOCUS_NODE" --arg s "$CHANGE_START" --arg e "$CHANGE_END" '[.items[]|select(any(.metadata.ownerReferences[]?;.controller==true and .uid==$uid))|select(.spec.nodeName==$node and .metadata.creationTimestamp >= $s and .metadata.creationTimestamp < $e and .metadata.deletionTimestamp==null)]' <<<"$PODS")"; COUNT="$(jq 'length' <<<"$CAND")"; if [ "$COUNT" -eq 1 ]; then REPLACEMENT_POD="$(jq -r '.[0].metadata.name' <<<"$CAND")"; REPLACEMENT_POD_UID="$(jq -r '.[0].metadata.uid' <<<"$CAND")"; REPLACEMENT_POD_RV="$(jq -r '.[0].metadata.resourceVersion' <<<"$CAND")"; REPLACEMENT_READY=true; printf 'REPLACEMENT_READY=true pod=%s uid=%s rv=%s node=%s ownerUID=%s\n' "$REPLACEMENT_POD" "$REPLACEMENT_POD_UID" "$REPLACEMENT_POD_RV" "$FOCUS_NODE" "$DS_UID"; else printf '중단: replacement 후보 수=%s\n' "$COUNT" >&2; fi; else printf '%s\n' '중단: replacement API/identity 검사 실패' >&2; fi`

`NORMALIZED_READY=false; if [ "$REPLACEMENT_READY" != true ]; then printf '%s\n' '중단: 최신 REPLACEMENT_READY가 아니다.' >&2; elif CUR="$(kubectl get daemonset "$DS" -n "$NS" -o json)" && POD_NOW="$(kubectl get pod "$REPLACEMENT_POD" -n "$NS" -o json)" && NODE_NOW="$(kubectl get node "$FOCUS_NODE" -o json)" && [ "$(jq -r '.metadata.uid' <<<"$CUR")" = "$DS_UID" ] && [ "$(jq -r '.metadata.uid' <<<"$POD_NOW")" = "$REPLACEMENT_POD_UID" ] && [ "$(jq -r '.metadata.uid' <<<"$NODE_NOW")" = "$NODE_UID" ] && [ "$(jq -r '.spec.nodeName' <<<"$POD_NOW")" = "$FOCUS_NODE" ] && [ "$(jq -r '[.metadata.ownerReferences[]?|select(.controller==true and .uid==$uid)]|length' --arg uid "$DS_UID" <<<"$POD_NOW")" -eq 1 ]; then jq -n --argjson ds "$CUR" --argjson pod "$POD_NOW" '{status:{desired:$ds.status.desiredNumberScheduled,current:$ds.status.currentNumberScheduled,ready:$ds.status.numberReady,available:$ds.status.numberAvailable,unavailable:$ds.status.numberUnavailable,misscheduled:$ds.status.numberMisscheduled,updated:$ds.status.updatedNumberScheduled},replacement:{name:$pod.metadata.name,uid:$pod.metadata.uid,node:$pod.spec.nodeName,phase:$pod.status.phase,ready:[$pod.status.containerStatuses[]?.ready],restarts:[$pod.status.containerStatuses[]?.restartCount]}}'; NORMALIZED_READY=true; printf '%s\n' 'NORMALIZED_READY=true identity/owner/node 확인 완료; 실제 daemon 기능은 별도 gate'; else REPLACEMENT_READY=false; printf '%s\n' '중단: replacement 최신 relation 검사 실패' >&2; fi`

정상화는 의도한 eligible 집합, `observedGeneration>=generation`, desired=current=ready=available, unavailable=misscheduled=0, rollout이 아니면 updated=desired를 관찰 창 동안 확인한다. 이어 node별 daemon의 실제 수집·보호·프록시·device 기능과 승인된 Service/EndpointSlice가 있는 경우 그 Service UID와 endpoint targetRef Pod UID까지 확인한다. 숫자 수렴만으로 닫지 않는다.

## Prometheus 보조 관측

`if [ "$AUTO_READY" != true ]; then printf '%s\n' '중단: 최신 AUTO_READY가 아니다.' >&2; elif CUR="$(kubectl get daemonset "$DS" -n "$NS" -o json)" && [ "$(jq -r '.metadata.uid' <<<"$CUR")" = "$DS_UID" ]; then NS_Q="$(jq -Rn --arg v "$NS" '$v|@json')"; DS_Q="$(jq -Rn --arg v "$DS" '$v|@json')"; printf 'kube_daemonset_status_desired_number_scheduled{namespace=%s,daemonset=%s}-kube_daemonset_status_number_ready{namespace=%s,daemonset=%s}\n' "$NS_Q" "$DS_Q" "$NS_Q" "$DS_Q"; printf 'kube_daemonset_status_number_unavailable{namespace=%s,daemonset=%s}\n' "$NS_Q" "$DS_Q"; else AUTO_READY=false; printf '%s\n' '중단: 현재 identity 불일치' >&2; fi`

metric이 비면 0이나 성공이 아니다. kube-state-metrics namespace/name 시계열에는 현재 DaemonSet UID와 node eligibility가 없으므로 API owner UID 증거를 대체하지 않는다.

## 증거와 경계

UID/resourceVersion/spec digest, owner/node relation, status, regular/init 상태, containerID의 비민감 식별자, canonical 변경 창과 실제 기능 결과를 보존한다. Secret·token·전체 YAML/로그는 저장하지 않는다. Kubernetes 1.26 기준 정적 검토이며 controller, admission, node/runtime/CNI/CSI, Service와 실제 daemon 기능은 환경별 미검증이다.
