# DaemonSet numberMisscheduled가 0이 아닌 경우

## 입력값과 빠른 수집

실행 위치는 승인된 작업 PC 또는 bastion의 같은 Bash다. 경로는 `API server → 현재 DaemonSet UID → owner Pod의 nodeName → 현재 Node UID·label·taint → controller cleanup → 실제 daemon 기능`이다. selector에 맞는 Pod와 현재 DaemonSet이 소유한 Pod를 혼동하지 않는다.

| 구분 | 값 | gate |
|---|---|---|
| 최초 입력 | `NS`, `DS` | exact-name API 조회 |
| API 자동값 | `DS_UID`, `DS_RV`, `DS_GENERATION`, `DS_SELECTOR`, `SPEC_DIGEST` | current object에서 등록 |
| 계산 후보 | owner UID가 같은 Pod 중 node별 deletion/eligibility 후보 | producer와 filter를 분리 |
| 운영자 선택 | `FOCUS_POD` | Pod UID·owner UID·node·Node UID를 재검증 |

재등록은 Pod/Node UID·resourceVersion·owner·containerID·관계·시간과 모든 downstream `READY`를 폐기한다. 같은 이름으로 재생성된 DaemonSet에는 이전 misscheduled 증거를 연결하지 않는다.

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | 현재 DaemonSet의 `numberMisscheduled`가 0보다 크다. |
| 적용 | 현재 owner UID Pod가 현재 predicate상 제외된 Node에 남은 관계를 확인할 수 있다. |
| 제외 | 단순 Ready/coverage 부족은 [[01. DaemonSet의 desired·current·ready scheduled 수가 수렴하지 않는 경우]], revision update 정체는 [[03. DaemonSet rolling update의 updated scheduled 수가 수렴하지 않는 경우]]다. |

검색 문자열: `numberMisscheduled`, `deletionTimestamp`, `NoSchedule`, `NoExecute`, `NotReady`, `ownerReferences`, `FailedDaemonPod`.

`unset SNAPSHOT_READY SNAPSHOT_JSON; SNAPSHOT_READY=false; if [ "$AUTO_READY" != true ]; then printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; elif CUR="$(kubectl get daemonset "$DS" -n "$NS" -o json)"; then if [ "$(jq -r '.metadata.uid' <<<"$CUR")" != "$DS_UID" ]; then AUTO_READY=false; printf '%s\n' '중단: DaemonSet UID 변경' >&2; elif PODS="$(kubectl get pods -n "$NS" -o json)" && NODES="$(kubectl get nodes -o json)"; then if ! ## 관측별 진단 경로

| 관측 | 직접 증거 | 다음 행동 |
|---|---|---|
| Node가 현재 대상 밖 | DS nodeName/nodeSelector/required affinity, 실제 Pod toleration과 Node label·taint | 의도된 정책 변경인지 owner 확인 |
| Pod deletionTimestamp 존재 | exact Pod UID의 grace/finalizer, Node UID와 lifecycle | 반복 삭제 금지, Terminating 런북 |
| Node NotFound/Unknown | Node UID·Ready/Lease lifecycle | node owner로 이관 |
| selector는 맞지만 owner UID 불일치 | Pod controller owner UID | 다른 workload Pod를 세거나 삭제하지 않음 |

**현재 predicate 관계 출력**

`if [ "$POD_READY" != true ]; then printf '%s\n' '중단: 최신 POD_READY가 아니다.' >&2; elif CUR="$(kubectl get daemonset "$DS" -n "$NS" -o json)" && POD_NOW="$(kubectl get pod "$FOCUS_POD" -n "$NS" -o json)" && NODE_NOW="$(kubectl get node "$NODE" -o json)" && [ "$(jq -r '.metadata.uid' <<<"$CUR")" = "$DS_UID" ] && [ "$(jq -r '.metadata.uid' <<<"$POD_NOW")" = "$POD_UID" ] && [ "$(jq -r '.metadata.uid' <<<"$NODE_NOW")" = "$NODE_UID" ]; then jq -n --argjson ds "$CUR" --argjson pod "$POD_NOW" --argjson node "$NODE_NOW" '{daemon:{uid:$ds.metadata.uid,nodeName:$ds.spec.template.spec.nodeName,nodeSelector:$ds.spec.template.spec.nodeSelector,requiredAffinity:$ds.spec.template.spec.affinity.nodeAffinity.requiredDuringSchedulingIgnoredDuringExecution,templateTolerations:$ds.spec.template.spec.tolerations},pod:{uid:$pod.metadata.uid,node:$pod.spec.nodeName,effectiveTolerations:$pod.spec.tolerations,deletion:$pod.metadata.deletionTimestamp,finalizers:$pod.metadata.finalizers},node:{uid:$node.metadata.uid,ready:[$node.status.conditions[]?|select(.type=="Ready")][0],labels:$node.metadata.labels,taints:($node.spec.taints//[]),unschedulable:$node.spec.unschedulable}}'; else POD_READY=false; printf '%s\n' '중단: UID/relation drift' >&2; fi`

`Ready=False/Unknown`과 `unschedulable`은 단독 exclusion 증거가 아니다. Kubernetes 1.26 DaemonSet controller가 추가하는 toleration을 포함한 실제 Pod toleration을 사용한다. custom `NoSchedule`/`NoExecute`, label/required affinity/nodeName 불일치가 확인돼야 predicate 제외 후보로 기록한다. Node/journal/CRI 도구는 이 API 단계에서 요구하지 않으며, node 장애가 직접 확인된 별도 분기에서만 해당 런북으로 이관한다.

## 변경 gate

misscheduled 수치만 낮추기 위한 delete/force delete, label·taint·selector·affinity 변경, drain 명령은 제공하지 않는다.

`APPROVAL_ID='PASTE_APPROVAL_ID_HERE'; EVIDENCE_ID='PASTE_EVIDENCE_ID_HERE'; CHANGE_START='PASTE_CHANGE_START_RFC3339_HERE'; CHANGE_END='PASTE_CHANGE_END_RFC3339_HERE'`

`unset MUTATION_READY REPLACEMENT_READY NORMALIZED_READY; MUTATION_READY=false; if [ "$POD_READY" != true ]; then printf '%s\n' '중단: 최신 POD_READY가 아니다.' >&2; elif [ -z "$APPROVAL_ID" ] || [ -z "$EVIDENCE_ID" ]; then printf '%s\n' '중단: 승인/evidence 없음' >&2; elif [[ ! "$CHANGE_START" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] || [[ ! "$CHANGE_END" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]]; then printf '%s\n' '중단: 시간 형식 오류' >&2; elif ! CS="$(date -u -d "$CHANGE_START" +%s)" || ! CE="$(date -u -d "$CHANGE_END" +%s)" || [ "$(date -u -d "@$CS" +%Y-%m-%dT%H:%M:%SZ)" != "$CHANGE_START" ] || [ "$(date -u -d "@$CE" +%Y-%m-%dT%H:%M:%SZ)" != "$CHANGE_END" ] || [ "$CS" -ge "$CE" ]; then printf '%s\n' '중단: 시간 round-trip/start<end 실패' >&2; elif CUR="$(kubectl get daemonset "$DS" -n "$NS" -o json)" && POD_NOW="$(kubectl get pod "$FOCUS_POD" -n "$NS" -o json)" && NODE_NOW="$(kubectl get node "$NODE" -o json)" && [ "$(jq -r '.metadata.uid' <<<"$CUR")" = "$DS_UID" ] && [ "$(jq -r '.metadata.resourceVersion' <<<"$CUR")" = "$DS_RV" ] && [ "$(jq -S '.spec' <<<"$CUR" | sha256sum | cut -d' ' -f1)" = "$SPEC_DIGEST" ] && [ "$(jq -r '.metadata.uid' <<<"$POD_NOW")" = "$POD_UID" ] && [ "$(jq -r '.metadata.uid' <<<"$NODE_NOW")" = "$NODE_UID" ]; then MUTATION_READY=true; printf 'MUTATION_READY=true dsUID=%s podUID=%s nodeUID=%s digest=%s approval=%s window=%s..%s\n' "$DS_UID" "$POD_UID" "$NODE_UID" "$SPEC_DIGEST" "$APPROVAL_ID" "$CHANGE_START" "$CHANGE_END"; else SNAPSHOT_READY=false; POD_READY=false; printf '%s\n' '중단: fresh identity/spec/relation gate 실패' >&2; fi`

`if [ "$MUTATION_READY" != true ]; then printf '%s\n' '중단: 최신 MUTATION_READY가 아니다.' >&2; elif CUR="$(kubectl get daemonset "$DS" -n "$NS" -o json)" && POD_NOW="$(kubectl get pod "$FOCUS_POD" -n "$NS" -o json)" && NODE_NOW="$(kubectl get node "$NODE" -o json)" && [ "$(jq -r '.metadata.uid' <<<"$CUR")" = "$DS_UID" ] && [ "$(jq -r '.metadata.resourceVersion' <<<"$CUR")" = "$DS_RV" ] && [ "$(jq -r '.metadata.uid' <<<"$POD_NOW")" = "$POD_UID" ] && [ "$(jq -r '.metadata.uid' <<<"$NODE_NOW")" = "$NODE_UID" ]; then printf '승인 경계 재확인 approval=%s evidence=%s dsUID=%s podUID=%s nodeUID=%s\n' "$APPROVAL_ID" "$EVIDENCE_ID" "$DS_UID" "$POD_UID" "$NODE_UID"; else MUTATION_READY=false; printf '%s\n' '중단: 변경 직전 current relation drift' >&2; fi`

승인 기록은 변경 selector/revision/spec digest, 모든 tenant와 node 전역 영향, daemon 기능, volume·외부 side effect, quorum·idempotence, rollback 선언과 중단 조건을 포함한다. rollback도 현재 UID/resourceVersion/spec digest/approval/window를 다시 검사한다.

## replacement 재등록과 정상화

변경 뒤 이전 Pod UID·containerID·Node relation을 폐기한다. 현재 selector가 아니라 **현재 owner UID**, 동일 Node UID, change window, non-deleting 조건으로 정확히 한 후보만 등록한다.

`unset REPLACEMENT_READY NORMALIZED_READY REPLACEMENT_POD REPLACEMENT_POD_UID; REPLACEMENT_READY=false; SNAPSHOT_READY=false; POD_READY=false; if [ "$MUTATION_READY" != true ]; then printf '%s\n' '중단: MUTATION_READY가 아니다.' >&2; elif CUR="$(kubectl get daemonset "$DS" -n "$NS" -o json)" && NODE_NOW="$(kubectl get node "$NODE" -o json)" && PODS="$(kubectl get pods -n "$NS" -o json)" && [ "$(jq -r '.metadata.uid' <<<"$CUR")" = "$DS_UID" ] && [ "$(jq -r '.metadata.uid' <<<"$NODE_NOW")" = "$NODE_UID" ]; then CAND="$(jq -c --arg uid "$DS_UID" --arg node "$NODE" --arg s "$CHANGE_START" --arg e "$CHANGE_END" '[.items[]|select(any(.metadata.ownerReferences[]?;.controller==true and .uid==$uid))|select(.spec.nodeName==$node and .metadata.creationTimestamp >= $s and .metadata.creationTimestamp < $e and .metadata.deletionTimestamp==null)]' <<<"$PODS")"; COUNT="$(jq 'length' <<<"$CAND")"; if [ "$COUNT" -eq 1 ]; then REPLACEMENT_POD="$(jq -r '.[0].metadata.name' <<<"$CAND")"; REPLACEMENT_POD_UID="$(jq -r '.[0].metadata.uid' <<<"$CAND")"; REPLACEMENT_READY=true; printf 'REPLACEMENT_READY=true pod=%s uid=%s node=%s ownerUID=%s\n' "$REPLACEMENT_POD" "$REPLACEMENT_POD_UID" "$NODE" "$DS_UID"; else printf '중단: replacement 후보 수=%s\n' "$COUNT" >&2; fi; else printf '%s\n' '중단: replacement API/identity 실패' >&2; fi`

`NORMALIZED_READY=false; if [ "$REPLACEMENT_READY" != true ]; then printf '%s\n' '중단: 최신 REPLACEMENT_READY가 아니다.' >&2; elif CUR="$(kubectl get daemonset "$DS" -n "$NS" -o json)" && POD_NOW="$(kubectl get pod "$REPLACEMENT_POD" -n "$NS" -o json)" && NODE_NOW="$(kubectl get node "$NODE" -o json)" && [ "$(jq -r '.metadata.uid' <<<"$CUR")" = "$DS_UID" ] && [ "$(jq -r '.metadata.uid' <<<"$POD_NOW")" = "$REPLACEMENT_POD_UID" ] && [ "$(jq -r '.metadata.uid' <<<"$NODE_NOW")" = "$NODE_UID" ] && [ "$(jq -r '.spec.nodeName' <<<"$POD_NOW")" = "$NODE" ] && [ "$(jq -r '[.metadata.ownerReferences[]?|select(.controller==true and .uid==$uid)]|length' --arg uid "$DS_UID" <<<"$POD_NOW")" -eq 1 ]; then jq -n --argjson ds "$CUR" --argjson pod "$POD_NOW" '{misscheduled:$ds.status.numberMisscheduled,desired:$ds.status.desiredNumberScheduled,current:$ds.status.currentNumberScheduled,ready:$ds.status.numberReady,available:$ds.status.numberAvailable,replacement:{name:$pod.metadata.name,uid:$pod.metadata.uid,node:$pod.spec.nodeName,ready:[$pod.status.containerStatuses[]?.ready]}}'; NORMALIZED_READY=true; printf '%s\n' 'NORMALIZED_READY=true identity/owner/node 확인 완료; 실제 daemon 기능은 별도 확인'; else REPLACEMENT_READY=false; printf '%s\n' '중단: replacement relation drift' >&2; fi`

`numberMisscheduled=0`과 status 수렴 외에 현재 predicate, Node lifecycle, node별 단일 owner Pod, Warning/삭제 지연 부재, 다른 workload 영향과 실제 daemon/Service 기능을 관찰 창 동안 확인한다.

## Prometheus 보조 관측

`if [ "$AUTO_READY" != true ]; then printf '%s\n' '중단: 최신 AUTO_READY가 아니다.' >&2; elif CUR="$(kubectl get daemonset "$DS" -n "$NS" -o json)" && [ "$(jq -r '.metadata.uid' <<<"$CUR")" = "$DS_UID" ]; then NS_Q="$(jq -Rn --arg v "$NS" '$v|@json')"; DS_Q="$(jq -Rn --arg v "$DS" '$v|@json')"; printf 'kube_daemonset_status_number_misscheduled{namespace=%s,daemonset=%s}\n' "$NS_Q" "$DS_Q"; else AUTO_READY=false; printf '%s\n' '중단: identity drift' >&2; fi`

빈 metric은 성공이 아니다. 이 시계열에는 DaemonSet UID, Pod owner UID, 위반 predicate가 없으므로 current API 관계를 대체하지 않는다.

## 증거와 경계

DaemonSet/Pod/Node UID·resourceVersion, selector/spec digest, owner/node relation, deletion/container lifecycle, canonical 변경 창과 실제 기능 결과만 보존한다. 민감정보·전체 YAML/로그는 저장하지 않는다. Kubernetes 1.26 기준 정적 검토이며 controller cleanup, admission, runtime, node provider와 실제 daemon 기능은 환경별 미검증이다.
