# DaemonSet rolling update의 updated scheduled 수가 수렴하지 않는 경우

## 입력값과 빠른 수집

승인된 작업 PC 또는 bastion의 같은 Bash에서 실행한다. 경로는 `현재 DaemonSet spec/revision → ControllerRevision owner UID → node별 old/new Pod owner UID → Ready/Available → 실제 daemon 기능`이다. revision hash만 같거나 이름에 `old/new`가 포함된다는 이유로 관계를 만들지 않는다.

| 구분 | 값 | gate |
|---|---|---|
| 최초 입력 | `NS`, `DS` | exact-name 조회 |
| API 자동값 | `DS_UID`, `DS_RV`, `DS_GENERATION`, `DS_SELECTOR`, `LATEST_HASH`, `SPEC_DIGEST` | current DS와 owner ControllerRevision에서 등록 |
| 계산 후보 | node별 old/new Pod와 deletion 상태 | current owner UID로만 계산 |
| 운영자 선택 | `FOCUS_NODE` | Node UID와 node별 Pod relation 재검증 |

재등록 전에 UID·resourceVersion·owner·revision·containerID·node·시간과 downstream `READY`를 전부 폐기한다. ControllerRevision `revision` 숫자와 hash를 혼동하지 않는다.

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | `updatedNumberScheduled<desiredNumberScheduled` 또는 최신 revision Pod의 Ready/Available이 수렴하지 않는다. |
| 적용 | strategy, 최신 ControllerRevision owner UID와 node별 Pod relation을 확인할 수 있다. |
| 제외 | `OnDelete`의 의도된 미교체, desired coverage 자체 문제, misscheduled 주 증상은 각각 정책 owner, [[01. DaemonSet의 desired·current·ready scheduled 수가 수렴하지 않는 경우]], [[02. DaemonSet numberMisscheduled가 0이 아닌 경우]]로 이동한다. |

검색 문자열: `RollingUpdate`, `OnDelete`, `updatedNumberScheduled`, `maxUnavailable`, `maxSurge`, `controller-revision-hash`, `minReadySeconds`, `Terminating`.

## replacement 재등록과 정상화

변경 뒤 old/new 이름·UID·containerID를 버린다. 현재 owner UID, 선택 Node UID, 현재 최신 ControllerRevision hash, change window, non-deleting 조건으로 단일 후보만 등록한다.

## 증거와 경계

DaemonSet/ControllerRevision/Pod/Node UID·resourceVersion, selector/spec digest, strategy, owner/revision/node relation, regular/init/containerID, canonical 변경 창과 실제 daemon 결과를 보존한다. 민감정보·ControllerRevision data·전체 YAML/로그는 저장하지 않는다. Kubernetes 1.26 기준 정적 검토이며 admission, scheduler, runtime, CNI와 실제 기능은 환경별 미검증이다.
