# StatefulSet currentRevision과 updateRevision이 수렴하지 않는 경우

## 입력값과 빠른 수집

승인된 작업 PC의 같은 Bash에서 `StatefulSet UID/spec -> status current/update 이름 -> ControllerRevision UID/owner -> ordinal별 Pod UID/revision/container`를 연결한다. ControllerRevision `data`, Secret 값, token은 출력하지 않는다.

| 구분 | 값 | 계약 |
|---|---|---|
| 최초 입력 | namespace, StatefulSet, UTC 관측 창 | 한 번만 입력하고 canonical 검증한다. |
| API 자동값 | StatefulSet UID/resourceVersion/generation/spec digest/selector, strategy, current/update 이름 | API 성공 뒤 등록한다. |
| 계산 후보 | expected ordinal과 revision 분포 | owner UID가 맞는 현재 Pod만 계산한다. |
| 운영자 선택값 | 자세히 확인할 Pod | inventory에서 owner·UID를 보고 선택한다. |

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | `currentRevision != updateRevision`, updatedReplicas 미수렴 또는 Pod revision 분포가 status와 맞지 않는다. |
| 적용 | 두 ControllerRevision의 current owner UID와 ordinal별 Pod UID·revision을 연결할 수 있다. |
| 제외 | 승인된 non-zero partition·OnDelete는 [[03. StatefulSet rolling update partition 또는 OnDelete 전략 때문에 일부 Pod가 이전 revision인 경우]], 특정 ordinal 정체는 [[01. StatefulSet이 특정 ordinal에서 생성 또는 업데이트를 진행하지 않는 경우]]로 이동한다. |

검색 문자열: `currentRevision`, `updateRevision`, `updatedReplicas`, `controller-revision-hash`, `ControllerRevision`, `collisionCount`, `OrderedReady`, `partition`, `OnDelete`.

## 최초 확인

current/update 이름이 비어 있으면 controller가 status를 아직 만들지 못했거나 API 상태가 불완전한 분기다. 이름을 추측하지 않고 controller/control-plane owner로 이관한다.

```bash
REVISION_READY=false; INVENTORY_READY=false; POD_READY=false; EVENT_READY=false; NORMAL_READY=false; PROMQL_READY=false
unset CURRENT_CR_UID CURRENT_CR_RV CURRENT_CR_NUM CURRENT_CR_HASH UPDATE_CR_UID UPDATE_CR_RV UPDATE_CR_NUM UPDATE_CR_HASH
if [ "$AUTO_READY" != true ] || [ -z "$CURRENT_REV" ] || [ -z "$UPDATE_REV" ]; then printf '%s\n' '중단: current/update 이름이 모두 필요하다.' >&2
elif ! fresh_statefulset; then printf '%s\n' '중단: 최신 StatefulSet gate 실패' >&2
elif ! C_CUR="$(kubectl get controllerrevision "$CURRENT_REV" -n "$NS" -o json --request-timeout=15s)" || ! C_UPD="$(kubectl get controllerrevision "$UPDATE_REV" -n "$NS" -o json --request-timeout=15s)"; then printf '%s\n' '중단: ControllerRevision producer 실패' >&2
elif ! jq -e --arg u "$STS_UID" --arg n "$STS" 'any(.metadata.ownerReferences[]?;.controller==true and .kind=="StatefulSet" and .name==$n and .uid==$u)' <<<"$C_CUR" >/dev/null || ! jq -e --arg u "$STS_UID" --arg n "$STS" 'any(.metadata.ownerReferences[]?;.controller==true and .kind=="StatefulSet" and .name==$n and .uid==$u)' <<<"$C_UPD" >/dev/null; then printf '%s\n' '중단: ControllerRevision owner kind/name/UID 불일치' >&2
else CURRENT_CR_UID="$(jq -r '.metadata.uid' <<<"$C_CUR")"; CURRENT_CR_RV="$(jq -r '.metadata.resourceVersion' <<<"$C_CUR")"; CURRENT_CR_NUM="$(jq -r '.revision' <<<"$C_CUR")"; CURRENT_CR_HASH="$(jq -r '.metadata.labels["controller.kubernetes.io/hash"]//"-"' <<<"$C_CUR")"; UPDATE_CR_UID="$(jq -r '.metadata.uid' <<<"$C_UPD")"; UPDATE_CR_RV="$(jq -r '.metadata.resourceVersion' <<<"$C_UPD")"; UPDATE_CR_NUM="$(jq -r '.revision' <<<"$C_UPD")"; UPDATE_CR_HASH="$(jq -r '.metadata.labels["controller.kubernetes.io/hash"]//"-"' <<<"$C_UPD")"; REVISION_READY=true; printf 'REVISION_READY=true\ncurrent=%s uid=%s rv=%s numeric=%s hash=%s ownerUID=%s\nupdate=%s uid=%s rv=%s numeric=%s hash=%s ownerUID=%s\n' "$CURRENT_REV" "$CURRENT_CR_UID" "$CURRENT_CR_RV" "$CURRENT_CR_NUM" "$CURRENT_CR_HASH" "$STS_UID" "$UPDATE_REV" "$UPDATE_CR_UID" "$UPDATE_CR_RV" "$UPDATE_CR_NUM" "$UPDATE_CR_HASH" "$STS_UID"; fi
```

`metadata.name`, numeric `.revision`, `controller.kubernetes.io/hash`는 서로 다른 값이다. Pod label은 ControllerRevision 이름과만 직접 비교한다.

## 관측별 진단 경로

| 지금 보이는 것 | 먼저 볼 것 | 그다음 어디를 볼지 | 상세 절 |
|---|---|---|---|
| current/update 이름의 owner가 맞지 않는다 | ControllerRevision UID·owner kind/name/UID | collision·ownership 이관 | [[#최초 확인]] |
| Pod revision이 두 이름과 다르다 | Pod UID·owner와 해당 ControllerRevision metadata | stale Pod·label drift·다른 owner | [[#문제 Pod 등록과 시간 제한 Event]] |
| update revision Pod가 NotReady·deleting이다 | current containerID·Ready·reason과 ordinal 순서 | Pod 원인 또는 특정 ordinal 런북 | [[#문제 Pod 등록과 시간 제한 Event]] |
| revision과 replica가 수렴했다 | current ControllerRevision UID와 전체 새 Pod UID | 실제 기능과 재발 관찰 | [[#상태 변경 경계와 정상화]] |

```bash
fresh_revisions(){ REVISION_READY=false; fresh_statefulset || return 1; CUR_NOW="$(kubectl get controllerrevision "$CURRENT_REV" -n "$NS" -o json --request-timeout=15s)" || return 1; UPD_NOW="$(kubectl get controllerrevision "$UPDATE_REV" -n "$NS" -o json --request-timeout=15s)" || return 1; [ "$(jq -r '.metadata.uid' <<<"$CUR_NOW")" = "$CURRENT_CR_UID" ] && [ "$(jq -r '.metadata.uid' <<<"$UPD_NOW")" = "$UPDATE_CR_UID" ] || { printf '%s\n' '중단: ControllerRevision UID 교체' >&2; return 1; }; jq -e --arg u "$STS_UID" 'any(.metadata.ownerReferences[]?;.controller==true and .uid==$u)' <<<"$CUR_NOW" >/dev/null || return 1; jq -e --arg u "$STS_UID" 'any(.metadata.ownerReferences[]?;.controller==true and .uid==$u)' <<<"$UPD_NOW" >/dev/null || return 1; REVISION_READY=true; }
```

## ordinal별 revision inventory

```bash
INVENTORY_READY=false
if ! fresh_revisions; then printf '%s\n' '중단: 최신 revision identity 실패' >&2
elif ! P="$(kubectl get pods -n "$NS" -l "$SELECTOR" -o json --request-timeout=15s)"; then printf '%s\n' '중단: Pod producer 실패' >&2
else jq -r '"=== StatefulSet ===\nUID/RV: \(.metadata.uid)/\(.metadata.resourceVersion)\ngeneration/observed: \(.metadata.generation)/\(.status.observedGeneration//0)\nreplicas/current/ready/updated: \(.status.replicas//0)/\(.status.currentReplicas//0)/\(.status.readyReplicas//0)/\(.status.updatedReplicas//0)\ncollisionCount: \(.status.collisionCount//0)\npolicy/strategy/partition: \(.spec.podManagementPolicy)/\(.spec.updateStrategy.type)/\(.spec.updateStrategy.rollingUpdate.partition//0)\ncurrent/update: \(.status.currentRevision)/\(.status.updateRevision)"' <<<"$S_LIVE"; jq -r --arg u "$STS_UID" '.items[]|select(any(.metadata.ownerReferences[]?;.controller==true and .kind=="StatefulSet" and .uid==$u))|"\n=== Pod \(.metadata.name) ===\nUID/RV: \(.metadata.uid)/\(.metadata.resourceVersion)\nownerUID: "+$u+"\npod-name label/revision: \(.metadata.labels["statefulset.kubernetes.io/pod-name"]//"-")/\(.metadata.labels["controller-revision-hash"]//"-")\ncreated/deletion: \(.metadata.creationTimestamp)/\(.metadata.deletionTimestamp//"-")\nnode/phase/Ready: \(.spec.nodeName//"-")/\(.status.phase//"-")/\([.status.conditions[]?|select(.type=="Ready")][0].status//"-")\ncontainers: \((([.status.initContainerStatuses[]?|"init/\(.name):\(.containerID//"-")"])+([.status.containerStatuses[]?|"regular/\(.name):\(.containerID//"-")"]))|join(";"))"' <<<"$P"; OWNED_COUNT="$(jq --arg u "$STS_UID" '[.items[]|select(any(.metadata.ownerReferences[]?;.controller==true and .uid==$u))]|length' <<<"$P")"; if [ "$OWNED_COUNT" -ne "$REPLICAS" ]; then printf '분기: expected replica=%s current-owned-pod=%s\n' "$REPLICAS" "$OWNED_COUNT" >&2; fi; INVENTORY_READY=true; fi
```

- `observedGeneration < generation`: current spec 관측이 완료되지 않았다.
- `collisionCount` 증가 또는 revision owner UID 모순: ControllerRevision을 삭제·생성하지 않고 controller owner에게 이관한다.
- Pod revision이 current/update 어느 이름과도 다름: stale Pod·다른 owner·label drift를 Pod UID로 구분한다.
- update revision Pod가 NotReady·deleting이면 revision 생성 문제가 아니라 해당 ordinal 진행 조건 또는 Pod 원인이다.

```bash
fresh_pod_scope(){ [ "$POD_READY" = true ] || return 1; fresh_revisions || return 1; P_NOW="$(kubectl get pod "$POD" -n "$NS" -o json --request-timeout=15s)" || return 1; [ "$(jq -r '.metadata.uid' <<<"$P_NOW")" = "$POD_UID" ] || { printf '%s\n' '중단: Pod UID 교체, selection 재등록' >&2; return 1; }; jq -e --arg u "$STS_UID" 'any(.metadata.ownerReferences[]?;.controller==true and .uid==$u)' <<<"$P_NOW" >/dev/null || return 1; }
```

```bash
EVENT_READY=false
if ! fresh_pod_scope; then printf '%s\n' '중단: 최신 Pod/revision identity 실패' >&2
elif ! E="$(kubectl get events -n "$NS" -o json --request-timeout=15s)"; then printf '%s\n' '중단: Event producer 실패' >&2
elif ! ROWS="$(jq -er --arg su "$STS_UID" --arg pu "$POD_UID" --arg s "$OBS_START" --arg e "$OBS_END" '[.items[]|select(.involvedObject.uid==$su or .involvedObject.uid==$pu)|(.eventTime//.series.lastObservedTime//.lastTimestamp//.firstTimestamp//.metadata.creationTimestamp) as $t|select($t>=$s and $t<=$e)|{uid:.metadata.uid,involvedUID:.involvedObject.uid,time:$t,type,reason,count:(.count//.series.count//1),message}]' <<<"$E")"; then printf '%s\n' '중단: Event filter 오류' >&2
else jq -r 'if length==0 then "no-match: 현재 UID·시간 범위 Event 없음" else .[]|"event uid=\(.uid) involvedUID=\(.involvedUID) time=\(.time) type=\(.type) reason=\(.reason) count=\(.count) message=\(.message)" end' <<<"$ROWS"; EVENT_READY=true; fi
```

Pod revision이 두 이름과 다르면 그 이름의 ControllerRevision metadata가 실제 존재하고 현재 StatefulSet owner UID인지 별도 조회한다. 존재하지 않거나 owner가 다르면 stale/ownership 증거로 이관한다. revision이 update와 같지만 Ready가 아니면 mount·image·probe·OOM·종료 reason을 현재 containerID와 함께 해당 Pod 런북으로 넘긴다. audit은 단일 auditID의 timestamp, verb, resource/subresource, namespace/name, requestURI, status와 현재 lifecycle UID만 사용하고 actor 상세를 보존하지 않는다.

```bash
POD_REVISION_READY=false

else POD_CR_UID="$(jq -r '.metadata.uid' <<<"$POD_CR")"; POD_REVISION_READY=true; printf 'POD_REVISION_READY=true pod=%s uid=%s revision=%s controllerRevisionUID=%s ownerUID=%s\n' "$POD" "$POD_UID" "$POD_REV" "$POD_CR_UID" "$STS_UID"; fi
```

## 상태 변경 경계와 정상화

이 문서에는 ControllerRevision 삭제·생성, Pod 삭제, rollback, partition·template patch 명령이 없다. 변경은 현재 StatefulSet UID/resourceVersion/spec digest, 두 ControllerRevision UID, ordinal·PVC·quorum 영향, 승인 ID·UTC 창·멱등성·중단·되돌림을 재검사하는 제품별 절차로만 수행한다. 외부 변경 뒤에는 모든 READY를 폐기하고 새 status·ControllerRevision·Pod UID를 처음부터 재등록한다.

```bash
NORMAL_READY=false
if [ "$UPDATE_TYPE" != RollingUpdate ] || [ "$PARTITION" -ne 0 ]; then printf '%s\n' '분기: OnDelete/non-zero partition 정상화는 strategy 전용 런북에서 판단한다.' >&2
elif ! S2="$(kubectl get statefulset "$STS" -n "$NS" -o json --request-timeout=15s)" || [ "$(jq -r '.metadata.uid' <<<"$S2")" != "$STS_UID" ]; then printf '%s\n' '중단: current StatefulSet UID 검증 실패' >&2
elif [ "$(jq -cS '.spec' <<<"$S2"|sha256sum|sed 's/[[:space:]].*$//')" != "$SPEC_DIGEST" ]; then printf '%s\n' '중단: StatefulSet spec이 바뀌었다. 모든 값을 처음부터 재등록한다.' >&2
elif ! P2="$(kubectl get pods -n "$NS" -l "$SELECTOR" -o json --request-timeout=15s)" || ! C2="$(kubectl get controllerrevision "$(jq -r '.status.updateRevision//empty' <<<"$S2")" -n "$NS" -o json --request-timeout=15s)"; then printf '%s\n' '중단: 정상화 Pod/ControllerRevision producer 실패' >&2
elif ! jq -e --arg u "$STS_UID" 'any(.metadata.ownerReferences[]?;.controller==true and .uid==$u)' <<<"$C2" >/dev/null; then printf '%s\n' '미정상: current update ControllerRevision owner UID 불일치' >&2
else NEW_REV="$(jq -r '.metadata.name' <<<"$C2")"; NEW_CR_UID="$(jq -r '.metadata.uid' <<<"$C2")"; CURRENT_PODS="$(jq -c --arg u "$STS_UID" '[.items[]|select(any(.metadata.ownerReferences[]?;.controller==true and .uid==$u))|{name:.metadata.name,uid:.metadata.uid,rv:.metadata.resourceVersion,revision:(.metadata.labels["controller-revision-hash"]//"-"),node:(.spec.nodeName//"-"),ready:([.status.conditions[]?|select(.type=="Ready")][0].status//"False"),deletion:(.metadata.deletionTimestamp//"-"),containers:([.status.initContainerStatuses[]?|{kind:"init",name,containerID:(.containerID//"-")}]+[.status.containerStatuses[]?|{kind:"regular",name,containerID:(.containerID//"-")}])}]' <<<"$P2")"; if [ "$(jq -r '.metadata.generation==(.status.observedGeneration//0) and .status.currentRevision==.status.updateRevision and (.spec.replicas//1)==(.status.updatedReplicas//0) and (.spec.replicas//1)==(.status.readyReplicas//0)' <<<"$S2")" != true ]; then printf '%s\n' '미정상: generation/revision/replica 수렴 실패' >&2; elif [ "$(jq 'length' <<<"$CURRENT_PODS")" -ne "$REPLICAS" ]; then printf '%s\n' '미정상: current owner Pod 수가 expected replicas와 다르다.' >&2; elif [ "$(jq --arg r "$NEW_REV" '[.[]|select(.revision!=$r or .ready!="True" or .deletion!="-" or ([.containers[].containerID]|any(.=="-")))]|length' <<<"$CURRENT_PODS")" -ne 0 ]; then printf '%s\n' '미정상: current owner Pod revision/Ready/containerID 불충족' >&2; else NORMAL_READY=true; printf 'NORMAL_READY=true statefulSetUID=%s controllerRevision=%s uid=%s\ncurrentPods=%s\nobservedAt=%s\n' "$STS_UID" "$NEW_REV" "$NEW_CR_UID" "$CURRENT_PODS" "$(date -u '+%Y-%m-%dT%H:%M:%SZ')"; fi; fi
```

정상화 블록은 과거 선택 Pod 이름·UID를 사용하지 않고 current owner Pod 전체를 재등록한다. PVC workload이면 각 새 Pod claimName→PVC/PV/CSI identity를 다시 연결하고, Service endpoint targetRef UID, 같은 Warning·restart 재발 없음, 승인된 실제 read/write·핵심 기능과 quorum·leader·replication이 관찰 창 동안 안정적이어야 정상화한다.

## Prometheus 빠른 관측

```bash
PROMQL_READY=false
if ! fresh_pod_scope; then printf '%s\n' '중단: 최신 Pod/revision identity 실패' >&2
else printf 'kube_statefulset_replicas{namespace="%s",statefulset="%s"}-kube_statefulset_status_replicas_updated{namespace="%s",statefulset="%s"}\n' "$NS" "$STS" "$NS" "$STS"; printf 'kube_pod_status_ready{namespace="%s",pod="%s",uid="%s",condition="true"}\n' "$NS" "$POD" "$POD_UID"; PROMQL_READY=true; fi
```

metric·label 미지원, 빈 결과, stale series를 정상으로 해석하지 않는다. PromQL은 ControllerRevision UID·owner, ordinal 의도, PVC/quorum과 실제 기능을 증명하지 않는다.
