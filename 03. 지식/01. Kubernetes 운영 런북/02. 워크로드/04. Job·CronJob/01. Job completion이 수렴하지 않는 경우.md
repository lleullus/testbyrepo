# Job completion이 수렴하지 않는 경우

## 입력값과 빠른 수집

실행 경로는 `작업 PC Bash·kubectl → API server → Job UID → owner Pod UID → init/regular container instance → bounded logs`다. 최초 입력은 namespace와 Job 이름이다. Job·Pod UID/resourceVersion, owner와 containerID는 API 자동값, attempt Pod·container와 시간 창은 운영자 선택값이다.

**도구 확인**

`TOOLS_READY=false; MISSING=''; for T in kubectl jq date grep awk sha256sum cut; do command -v "$T" >/dev/null 2>&1 || MISSING="$MISSING $T"; done; if [ -n "${BASH_VERSION:-}" ] && [ -z "$MISSING" ]; then TOOLS_READY=true; printf '%s\n' 'TOOLS_READY=true'; else printf '중단: Bash 또는 도구 없음:%s\n' "$MISSING" >&2; fi`

**최초 입력·stale gate 폐기**

`unset INPUT_READY JOB_READY ATTEMPTS_READY ATTEMPT_READY WINDOW_READY LOG_READY NORMAL_READY JOB_JSON PODS_JSON JOB_UID JOB_RV JOB_CREATED JOB_SPEC_DIGEST JOB_OWNER_KIND JOB_OWNER_NAME JOB_OWNER_UID POD POD_UID POD_RV POD_CREATED POD_OWNER_UID CONTAINER_KIND CONTAINER CONTAINER_ID START_RFC3339 END_RFC3339 LOG_REGEX; INPUT_READY=false; JOB_READY=false; ATTEMPTS_READY=false; ATTEMPT_READY=false; WINDOW_READY=false; LOG_READY=false; NORMAL_READY=false; NS='PASTE_NAMESPACE_HERE'; JOB='PASTE_JOB_HERE'; if [ "$TOOLS_READY" = true ] && [ -n "$NS" ] && [ -n "$JOB" ]; then INPUT_READY=true; export NS JOB; printf 'INPUT_READY=true NS=%s JOB=%s\n' "$NS" "$JOB"; else printf '%s\n' '중단: 최초 입력 실패.' >&2; fi`

**Job identity·spec 등록**

`JOB_READY=false; ATTEMPTS_READY=false; ATTEMPT_READY=false; WINDOW_READY=false; LOG_READY=false; NORMAL_READY=false; unset JOB_JSON JOB_UID JOB_RV JOB_CREATED JOB_SPEC_DIGEST JOB_OWNER_KIND JOB_OWNER_NAME JOB_OWNER_UID; if [ "$INPUT_READY" != true ]; then printf '%s\n' '중단: INPUT_READY가 아니다.' >&2; elif D="$(kubectl get job "$JOB" -n "$NS" -o json)" && jq -e --arg n "$NS" --arg j "$JOB" '.metadata.namespace==$n and .metadata.name==$j and (.metadata.uid|length>0)' <<<"$D" >/dev/null; then JOB_JSON="$D"; JOB_UID="$(jq -r '.metadata.uid' <<<"$D")"; JOB_RV="$(jq -r '.metadata.resourceVersion' <<<"$D")"; JOB_CREATED="$(jq -r '.metadata.creationTimestamp' <<<"$D")"; JOB_SPEC_DIGEST="$(jq -cS '.spec' <<<"$D" | sha256sum | cut -d' ' -f1)"; JOB_OWNER_KIND="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)][0].kind // "-"' <<<"$D")"; JOB_OWNER_NAME="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)][0].name // "-"' <<<"$D")"; JOB_OWNER_UID="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)][0].uid // "-"' <<<"$D")"; JOB_READY=true; printf 'JOB_READY=true uid=%s rv=%s created=%s specDigest=%s owner=%s/%s ownerUID=%s completions=%s parallelism=%s backoff=%s deadline=%s active=%s succeeded=%s failed=%s\n' "$JOB_UID" "$JOB_RV" "$JOB_CREATED" "$JOB_SPEC_DIGEST" "$JOB_OWNER_KIND" "$JOB_OWNER_NAME" "$JOB_OWNER_UID" "$(jq -r '.spec.completions // "work-queue"' <<<"$D")" "$(jq -r '.spec.parallelism // 1' <<<"$D")" "$(jq -r '.spec.backoffLimit // 6' <<<"$D")" "$(jq -r '.spec.activeDeadlineSeconds // "-"' <<<"$D")" "$(jq -r '.status.active // 0' <<<"$D")" "$(jq -r '.status.succeeded // 0' <<<"$D")" "$(jq -r '.status.failed // 0' <<<"$D")"; else printf '%s\n' '중단: Job exact 조회 실패.' >&2; fi`

**현재 Job lifecycle 재검증 함수**

`fresh_job(){ local d u digest; d="$(kubectl get job "$JOB" -n "$NS" -o json)" || { JOB_READY=false; ATTEMPTS_READY=false; ATTEMPT_READY=false; WINDOW_READY=false; LOG_READY=false; NORMAL_READY=false; return 1; }; u="$(jq -r '.metadata.uid // empty' <<<"$d")"; digest="$(jq -cS '.spec' <<<"$d" | sha256sum | cut -d' ' -f1)"; if [ "$JOB_READY" != true ] || [ "$u" != "$JOB_UID" ] || [ "$digest" != "$JOB_SPEC_DIGEST" ]; then unset JOB_JSON PODS_JSON POD_UID CONTAINER_ID; JOB_READY=false; ATTEMPTS_READY=false; ATTEMPT_READY=false; WINDOW_READY=false; LOG_READY=false; NORMAL_READY=false; printf '%s\n' '중단: 같은 이름의 Job lifecycle 또는 spec이 바뀌었다.' >&2; return 1; fi; JOB_JSON="$d"; JOB_RV="$(jq -r '.metadata.resourceVersion' <<<"$d")"; return 0; }`

**attempt Pod 자동 등록**

`ATTEMPTS_READY=false; ATTEMPT_READY=false; WINDOW_READY=false; LOG_READY=false; NORMAL_READY=false; unset PODS_JSON POD POD_UID POD_RV POD_CREATED POD_OWNER_UID CONTAINER_KIND CONTAINER CONTAINER_ID START_RFC3339 END_RFC3339 LOG_REGEX; if ! fresh_job; then :; elif A="$(kubectl get pods -n "$NS" -o json)" && P="$(jq -c --arg uid "$JOB_UID" '[.items[] | select(any(.metadata.ownerReferences[]?; .controller==true and .kind=="Job" and .uid==$uid))] | sort_by(.metadata.creationTimestamp)' <<<"$A")"; then PODS_JSON="$P"; ATTEMPTS_READY=true; jq -r '.[] | "=== attempt \(.metadata.name) ===\nuid=\(.metadata.uid) rv=\(.metadata.resourceVersion) created=\(.metadata.creationTimestamp) deletion=\(.metadata.deletionTimestamp // "-") phase=\(.status.phase // "-") ownerUID=" + ([.metadata.ownerReferences[]? | select(.controller==true) | .uid] | join(",")) + "\ncontainers=" + ([.status.initContainerStatuses[]? | "init/\(.name) id=\(.containerID // "-") state=\((.state|keys[0]) // "-") restart=\(.restartCount)"] + [.status.containerStatuses[]? | "regular/\(.name) id=\(.containerID // "-") state=\((.state|keys[0]) // "-") restart=\(.restartCount)"] | join(";"))' <<<"$PODS_JSON"; printf 'ATTEMPTS_READY=true count=%s jobRV=%s\n' "$(jq 'length' <<<"$PODS_JSON")" "$JOB_RV"; else printf '%s\n' '중단: Pod API 조회 실패.' >&2; fi`

빈 배열은 attempt가 없다는 현재 관측이며 성공이 아니다. `job-name` label은 owner UID 검증을 대신하지 않는다. 삭제된 과거 Pod는 현재 목록에 없을 수 있다.

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | 고정 completion Job의 성공 수가 부족하거나 work-queue Job이 `Complete=True`로 수렴하지 않는 경우 |
| 적용 | Job UID와 각 current attempt owner UID를 연결할 수 있는 경우 |
| 제외 | `BackoffLimitExceeded`·`DeadlineExceeded` 재실행은 [[02. BackoffLimitExceeded 또는 DeadlineExceeded 뒤 재실행 판단이 필요한 경우]], Indexed Job은 [[03. Indexed Job의 completion index가 수렴하지 않는 경우]]로 이동한다. |

검색 문자열: `completions`, `parallelism`, `active`, `succeeded`, `failed`, `Complete`, `Failed`, `BackoffLimitExceeded`, `DeadlineExceeded`, `suspend`.

## 관측별 진단 경로

| 지금 보이는 것 | 먼저 볼 것 | 그다음 어디를 볼지 | 상세 절 |
|---|---|---|---|
| active Pod가 남음 | 해당 Pod UID·container instance·외부 watermark | bounded 로그로 진행/정체 분리 | [[#관측별 진단 경로\|attempt 선택]] |
| succeeded 부족, 새 attempt 없음 | suspend, deadline, backoff, condition | policy 또는 controller 이관 | [[#상태 변경 경계\|변경 경계]] |
| failed 증가·Failed=True | 모든 attempt 종료 reason·시각 | Pod 원인 또는 재실행 판단 문서 | [[02. BackoffLimitExceeded 또는 DeadlineExceeded 뒤 재실행 판단이 필요한 경우]] |
| Complete=True, 산출물 없음 | commit·ack·checksum | 업무 성공과 Kubernetes 완료 분리 | [[#정상화와 역순 검증\|정상화]] |

**attempt·container 선택**

`POD='PASTE_ATTEMPT_POD_HERE'; CONTAINER_KIND='PASTE_INIT_OR_REGULAR_HERE'; CONTAINER='PASTE_CONTAINER_HERE'; ATTEMPT_READY=false; WINDOW_READY=false; LOG_READY=false; NORMAL_READY=false; unset POD_UID POD_RV POD_CREATED POD_OWNER_UID CONTAINER_ID; if [ "$ATTEMPTS_READY" != true ] || ! fresh_job; then printf '%s\n' '중단: 최신 ATTEMPTS_READY가 필요하다.' >&2; elif [ "$CONTAINER_KIND" != init ] && [ "$CONTAINER_KIND" != regular ]; then printf '%s\n' '중단: container kind는 init 또는 regular다.' >&2; elif D="$(kubectl get pod "$POD" -n "$NS" -o json)" && jq -e --arg uid "$JOB_UID" 'any(.metadata.ownerReferences[]?; .controller==true and .kind=="Job" and .uid==$uid)' <<<"$D" >/dev/null && { [ "$CONTAINER_KIND" = init ] && jq -e --arg c "$CONTAINER" 'any(.spec.initContainers[]?; .name==$c)' <<<"$D" >/dev/null || [ "$CONTAINER_KIND" = regular ] && jq -e --arg c "$CONTAINER" 'any(.spec.containers[]?; .name==$c)' <<<"$D" >/dev/null; }; then POD_UID="$(jq -r '.metadata.uid' <<<"$D")"; POD_RV="$(jq -r '.metadata.resourceVersion' <<<"$D")"; POD_CREATED="$(jq -r '.metadata.creationTimestamp' <<<"$D")"; POD_OWNER_UID="$JOB_UID"; if [ "$CONTAINER_KIND" = init ]; then CONTAINER_ID="$(jq -r --arg c "$CONTAINER" '.status.initContainerStatuses[]? | select(.name==$c) | .containerID // empty' <<<"$D")"; else CONTAINER_ID="$(jq -r --arg c "$CONTAINER" '.status.containerStatuses[]? | select(.name==$c) | .containerID // empty' <<<"$D")"; fi; ATTEMPT_READY=true; printf 'ATTEMPT_READY=true pod=%s uid=%s rv=%s created=%s ownerUID=%s kind=%s container=%s containerID=%s\n' "$POD" "$POD_UID" "$POD_RV" "$POD_CREATED" "$POD_OWNER_UID" "$CONTAINER_KIND" "$CONTAINER" "${CONTAINER_ID:--}"; else printf '%s\n' '중단: Pod owner 또는 container 관계 검증 실패.' >&2; fi`

**현재 attempt container instance 재검증 함수**

`fresh_attempt(){ local d cid; fresh_job || return 1; d="$(kubectl get pod "$POD" -n "$NS" -o json)" || return 1; if [ "$CONTAINER_KIND" = init ]; then cid="$(jq -r --arg c "$CONTAINER" '.status.initContainerStatuses[]? | select(.name==$c) | .containerID // empty' <<<"$d")"; else cid="$(jq -r --arg c "$CONTAINER" '.status.containerStatuses[]? | select(.name==$c) | .containerID // empty' <<<"$d")"; fi; if [ "$ATTEMPT_READY" != true ] || [ -z "$CONTAINER_ID" ] || [ "$cid" != "$CONTAINER_ID" ] || ! jq -e --arg p "$POD_UID" --arg j "$JOB_UID" '.metadata.uid==$p and any(.metadata.ownerReferences[]?; .controller==true and .uid==$j)' <<<"$d" >/dev/null; then ATTEMPT_READY=false; WINDOW_READY=false; LOG_READY=false; printf '%s\n' '중단: attempt Pod 또는 current containerID가 바뀌었다. 재등록한다.' >&2; return 1; fi; return 0; }`

**canonical 로그 시간·regex 선택**

`START_RFC3339='PASTE_START_RFC3339_HERE'; END_RFC3339='PASTE_END_RFC3339_HERE'; LOG_REGEX='PASTE_LOG_REGEX_HERE'; WINDOW_READY=false; LOG_READY=false; if ! fresh_attempt; then printf '%s\n' '중단: 최신 ATTEMPT_READY와 current containerID가 필요하다.' >&2; elif ! [[ "$START_RFC3339" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ && "$END_RFC3339" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] || [ "$(date -u -d "$START_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" != "$START_RFC3339" ] || [ "$(date -u -d "$END_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" != "$END_RFC3339" ] || [ "$(date -u -d "$START_RFC3339" +%s)" -ge "$(date -u -d "$END_RFC3339" +%s)" ] || [ -z "$LOG_REGEX" ]; then printf '%s\n' '중단: canonical UTC start<end와 regex가 필요하다.' >&2; else WINDOW_READY=true; printf 'WINDOW_READY=true start=%s end=%s regex=%q\n' "$START_RFC3339" "$END_RFC3339" "$LOG_REGEX"; fi`

**bounded current log·pipeline 판정**

`LOG_READY=false; if [ "$WINDOW_READY" != true ] || ! fresh_attempt; then printf '%s\n' '중단: 최신 WINDOW_READY와 current containerID가 필요하다.' >&2; else RAW="$(kubectl logs "$POD" -n "$NS" -c "$CONTAINER" --timestamps --since-time="$START_RFC3339" --tail=400 2>&1)"; PRODUCER_RC=$?; if [ "$PRODUCER_RC" -ne 0 ]; then printf 'logs producer 실패 rc=%s\n' "$PRODUCER_RC" >&2; elif BOUNDED="$(awk -v s="$START_RFC3339" -v e="$END_RFC3339" '$1 >= s && $1 < e' <<<"$RAW")"; then if [ -z "$BOUNDED" ]; then printf '%s\n' '시간 필터 no-match: 수집 실패가 아니라 창 안의 행이 없음.'; elif MATCH="$(grep -E -i -C 3 -- "$LOG_REGEX" <<<"$BOUNDED")"; then printf '%s\n' "$MATCH"; LOG_READY=true; else FILTER_RC=$?; if [ "$FILTER_RC" -eq 1 ]; then printf '%s\n' 'regex no-match: 오류 없음이 아니라 같은 창의 Event·상태를 확인한다.'; else printf 'regex 필터 오류 rc=%s: WINDOW_READY부터 재등록한다.\n' "$FILTER_RC" >&2; fi; fi; else printf '%s\n' '시간 필터 오류.' >&2; fi; unset RAW BOUNDED MATCH; fi`

시간 필터는 RFC3339 UTC timestamp의 문자열 순서를 사용해 `START_RFC3339 <= timestamp < END_RFC3339`만 남긴다. 시작·종료·condition·Event와 외부 commit 시각이 창 안에서 연결되어야 한다. Secret·token·개인정보가 보이면 출력을 중단한다. `--previous`는 같은 Pod UID의 같은 container에 restart가 있고 이전 instance가 확인된 경우에만 별도 재등록 후 사용하며 다른 attempt를 대신하지 않는다.

## 상태 변경 경계

이 문서는 delete, patch, suspend 전환, Job 재생성 또는 수동 trigger를 실행하지 않는다. Job completion 정체가 외부 결과 미반영을 뜻하지 않는다. 재실행은 최신 Job UID/spec digest, 모든 attempt UID·containerID, 실패 원인 해소, 입력 범위, idempotency, commit·ack·watermark·checksum, 동시 실행 부재, 승인·창·rollback을 다시 검증해야 한다.

## 정상화와 역순 검증

`NORMAL_READY=false; if [ "$ATTEMPTS_READY" != true ] || ! fresh_job; then printf '%s\n' '중단: 최신 Job·attempt gate가 필요하다.' >&2; else jq -r '"uid=\(.metadata.uid) rv=\(.metadata.resourceVersion) active=\(.status.active // 0) succeeded=\(.status.succeeded // 0) failed=\(.status.failed // 0) start=\(.status.startTime // "-") completion=\(.status.completionTime // "-")", (.status.conditions[]? | "condition=\(.type) status=\(.status) reason=\(.reason // "-") transition=\(.lastTransitionTime // "-")")' <<<"$JOB_JSON"; NORMAL_READY=true; fi`

정상화는 같은 Job UID에서 `Complete=True`, active 0, 고정 completion의 succeeded=completions 또는 work-queue completion semantics, owner UID가 맞는 attempt, 동일 reason·restart·Warning 중단을 확인한다. 이어 실제 commit/ack, watermark, checksum과 중복 부재를 확인한다. 새 Job을 만들었다면 원본 변수와 READY를 폐기하고 새 이름·UID로 처음부터 등록한다.

**PromQL 완성본 생성**

`if [ "$JOB_READY" != true ] || ! fresh_job; then printf '%s\n' '중단: 최신 JOB_READY가 필요하다.' >&2; else printf 'kube_job_status_active{namespace=%s,job_name=%s}\n' "$(jq -Rn --arg v "$NS" '$v')" "$(jq -Rn --arg v "$JOB" '$v')"; fi`

metric/label 미지원과 빈 결과를 정상으로 해석하지 않는다. PromQL은 같은 이름 재생성 Job UID나 외부 업무 결과를 분리하지 못한다.

보존 대상은 Job·Pod UID/resourceVersion/owner/creation, spec digest, init/regular containerID, condition·Event·로그 시간 관계와 외부 결과 요약이다. Secret·token·개인키·전체 YAML·로그 원문은 저장하지 않는다.
