# Deployment의 새 ReplicaSet이 생성되지 않거나 revision·owner 관계가 맞지 않는 경우

## 입력값과 빠른 수집

승인된 작업 PC의 같은 Bash에서 `API server -> Deployment UID/template -> ReplicaSet controller owner UID/revision/hash -> Pod owner UID`를 확인한다. controller 로그·audit은 배포 위치와 승인된 접근 경로가 확인된 경우에만 별도 owner가 조회한다.

| 구분 | 값 | 처리 |
|---|---|---|
| 최초 입력 | namespace, Deployment, UTC 시작·종료 시각 | 한 번만 입력 |
| API 자동값 | UID/resourceVersion/generation/selector/revision/template digest | 조회가 모두 성공할 때 등록 |
| 계산 후보 | escaped 이름 regex, template digest | bounded 출력 후 사용 |
| 운영자 선택값 | 관계를 검증할 ReplicaSet | inventory에서 선택 |

```bash
elif ! S="$(jq -er '([.spec.selector.matchLabels|to_entries[]?|"\(.key)=\(.value)"]+[.spec.selector.matchExpressions[]?|if .operator=="In" then "\(.key) in (\(.values|join(",")))" elif .operator=="NotIn" then "\(.key) notin (\(.values|join(",")))" elif .operator=="Exists" then .key elif .operator=="DoesNotExist" then "!\(.key)" else error("operator") end])|join(",")|select(length>0)' <<<"$D")"; then printf '%s\n' '중단: selector filter 오류' >&2

else DEP_UID="$(jq -r '.metadata.uid' <<<"$D")"; DEP_RV="$(jq -r '.metadata.resourceVersion' <<<"$D")"; DEP_GEN="$(jq -r '.metadata.generation' <<<"$D")"; SELECTOR="$S"; DEP_RE="$(printf '%s' "$DEP"|sed 's/[][\\.^$*+?(){}|]/\\&/g')"; REVISION="$(jq -r '.metadata.annotations["deployment.kubernetes.io/revision"]//"-"' <<<"$D")"; TEMPLATE_DIGEST="$DIG"; OBS_START="$START_INPUT"; OBS_END="$END_INPUT"; AUTO_READY=true; printf 'AUTO_READY=true uid=%s rv=%s generation=%s revision=%s selector=%s digest=%s\n' "$DEP_UID" "$DEP_RV" "$DEP_GEN" "$REVISION" "$SELECTOR" "$TEMPLATE_DIGEST"; fi
```

```bash
fresh_deployment(){ TARGET_READY=false; unset D_LIVE S_LIVE DIG_LIVE; [ "$AUTO_READY" = true ] || return 1; D_LIVE="$(kubectl get deployment "$DEP" -n "$NS" -o json --request-timeout=15s)" || return 1; [ "$(jq -r '.metadata.uid' <<<"$D_LIVE")" = "$DEP_UID" ] || { printf '%s\n' '중단: Deployment UID 교체' >&2; return 1; }; S_LIVE="$(jq -er '([.spec.selector.matchLabels|to_entries[]?|"\(.key)=\(.value)"]+[.spec.selector.matchExpressions[]?|if .operator=="In" then "\(.key) in (\(.values|join(",")))" elif .operator=="NotIn" then "\(.key) notin (\(.values|join(",")))" elif .operator=="Exists" then .key elif .operator=="DoesNotExist" then "!\(.key)" else error("operator") end])|join(",")|select(length>0)' <<<"$D_LIVE")" || return 1; DIG_LIVE="$(jq -cS '.spec.template' <<<"$D_LIVE"|sha256sum|sed 's/[[:space:]].*$//')" || return 1; [ "$S_LIVE" = "$SELECTOR" ] && [ "$DIG_LIVE" = "$TEMPLATE_DIGEST" ] || { printf '%s\n' '중단: selector/template 변경, 자동값 재등록 필요' >&2; return 1; }; DEP_RV="$(jq -r '.metadata.resourceVersion' <<<"$D_LIVE")"; TARGET_READY=true; }
```

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | template 변경 뒤 새 RS가 없거나 RS owner/revision/hash/selector 관계가 모순된다. |
| 적용 | current Deployment UID와 직접 소유한 RS/Pod만 판정한다. |
| 제외 | 올바른 새 RS가 있고 Pod 수렴만 멈추면 [[01. Deployment rollout이 진행되지 않거나 ProgressDeadlineExceeded인 경우]]로 이동한다. |

검색 문자열: `observedGeneration`, `deployment.kubernetes.io/revision`, `pod-template-hash`, `ownerReferences`, `collision`, `admission`, `revert`.

## 최초 확인

```bash
INVENTORY_READY=false
if ! fresh_deployment; then printf '%s\n' '중단: 최신 target 실패' >&2
elif ! R="$(kubectl get rs -n "$NS" -l "$SELECTOR" -o json --request-timeout=15s)"; then printf '%s\n' '중단: RS producer 실패' >&2
elif ! P="$(kubectl get pods -n "$NS" -l "$SELECTOR" -o json --request-timeout=15s)"; then printf '%s\n' '중단: Pod producer 실패' >&2
else jq -r '"=== Deployment ===\nUID/RV: \(.metadata.uid)/\(.metadata.resourceVersion)\ngeneration/observed: \(.metadata.generation)/\(.status.observedGeneration//0)\nrevision: \(.metadata.annotations["deployment.kubernetes.io/revision"]//"-")\npaused: \(.spec.paused//false)\ncondition: \([.status.conditions[]?|"\(.type)=\(.status) reason=\(.reason//"-") at=\(.lastUpdateTime//"-")"]|join(";"))"' <<<"$D_LIVE"; OWNED="$(jq --arg u "$DEP_UID" '[.items[]|select(any(.metadata.ownerReferences[]?;.controller==true and .kind=="Deployment" and .uid==$u))]|length' <<<"$R")"; printf 'direct-owned-rs=%s\n' "$OWNED"; jq -r '.items[]|"\n=== RS \(.metadata.name) ===\nUID/RV: \(.metadata.uid)/\(.metadata.resourceVersion)\ncontroller owner: \([.metadata.ownerReferences[]?|select(.controller==true)|"\(.kind)/\(.name) uid=\(.uid)"]|join(";"))\nrevision/hash/created: \(.metadata.annotations["deployment.kubernetes.io/revision"]//"-")/\(.metadata.labels["pod-template-hash"]//"-")/\(.metadata.creationTimestamp)\nselector/template-labels: \(.spec.selector|tojson) / \(.spec.template.metadata.labels|tojson)"' <<<"$R"; jq -r '.items[]|"Pod \(.metadata.name) uid=\(.metadata.uid) rv=\(.metadata.resourceVersion) owner=\([.metadata.ownerReferences[]?|select(.controller==true)|"\(.kind)/\(.name) uid=\(.uid)"]|join(";")) hash=\(.metadata.labels["pod-template-hash"]//"-") node=\(.spec.nodeName//"-") created=\(.metadata.creationTimestamp) containers=\((([.status.initContainerStatuses[]?|"init/\(.name):\(.containerID//"-")"])+([.status.containerStatuses[]?|"regular/\(.name):\(.containerID//"-")"]))|join(";"))"' <<<"$P"; INVENTORY_READY=true; fi
```

`OWNED=0`은 조회 성공과 no-match를 구분한 결과다. template을 바꾸지 않은 generation 증가라면 새 RS 부재가 정상일 수 있다. `generation>observedGeneration`이면 controller 관측 전이며, template digest가 승인 원본과 다르면 admission/GitOps write 경로를 먼저 확인한다.

## 관측별 진단 경로

| 지금 보이는 것 | 먼저 볼 것 | 그다음 어디를 볼지 | 상세 절 |
|---|---|---|---|
| current template 변경 뒤 direct-owned RS가 없다 | generation·observedGeneration과 template digest | controller/admission/API 이관 | [[#UID·시간 제한 Event]] |
| RS는 있지만 owner·revision·hash가 모순된다 | RS UID와 controller owner kind/name/UID | 선택 RS identity 검증 | [[#ReplicaSet identity 검증]] |
| Pod owner가 선택 RS UID와 다르다 | Pod UID·owner UID·creation time | 다른 owner 또는 stale Pod 이관 | [[#ReplicaSet identity 검증]] |
| active RS와 Pod가 다시 수렴했다 | current owner·UID와 단일 active RS | 실제 기능과 재발 관찰 | [[#상태 변경 경계·정상화]] |

## ReplicaSet identity 검증

```bash
RS='PASTE_REPLICASET_HERE'
```

```bash
RS_READY=false; EVENT_READY=false; NORMAL_READY=false; PROMQL_READY=false
unset RS_UID RS_RV RS_OWNER_UID RS_REV RS_HASH RS_CREATED
if [ "$INVENTORY_READY" != true ] || ! fresh_deployment; then printf '%s\n' '중단: 최신 inventory/target 필요' >&2
elif ! X="$(kubectl get rs "$RS" -n "$NS" -o json --request-timeout=15s)"; then printf '%s\n' '중단: RS 조회 실패' >&2
elif ! jq -e --arg u "$DEP_UID" --arg n "$DEP" 'any(.metadata.ownerReferences[]?;.controller==true and .kind=="Deployment" and .name==$n and .uid==$u)' <<<"$X" >/dev/null; then printf '%s\n' '중단: controller owner kind/name/UID 불일치' >&2
else RS_UID="$(jq -r '.metadata.uid' <<<"$X")"; RS_RV="$(jq -r '.metadata.resourceVersion' <<<"$X")"; RS_OWNER_UID="$DEP_UID"; RS_REV="$(jq -r '.metadata.annotations["deployment.kubernetes.io/revision"]//"-"' <<<"$X")"; RS_HASH="$(jq -r '.metadata.labels["pod-template-hash"]//"-"' <<<"$X")"; RS_CREATED="$(jq -r '.metadata.creationTimestamp' <<<"$X")"; RS_READY=true; printf 'RS_READY=true rs=%s uid=%s rv=%s ownerUID=%s revision=%s hash=%s created=%s\n' "$RS" "$RS_UID" "$RS_RV" "$RS_OWNER_UID" "$RS_REV" "$RS_HASH" "$RS_CREATED"; fi
```

## UID·시간 제한 Event

```bash
EVENT_READY=false
if ! fresh_deployment; then printf '%s\n' '중단: 최신 target 실패' >&2
elif ! E="$(kubectl get events -n "$NS" -o json --request-timeout=15s)"; then printf '%s\n' '중단: Event producer 실패' >&2
elif ! ROWS="$(jq -er --arg u "$DEP_UID" --arg s "$OBS_START" --arg e "$OBS_END" '[.items[]|select(.involvedObject.uid==$u)|(.eventTime//.series.lastObservedTime//.lastTimestamp//.firstTimestamp//.metadata.creationTimestamp) as $t|select($t>=$s and $t<=$e)|{uid:.metadata.uid,time:$t,reason,count:(.count//.series.count//1),message}]' <<<"$E")"; then printf '%s\n' '중단: Event filter 오류' >&2
else jq -r 'if length==0 then "no-match: Event TTL/시간 범위 확인" else .[]|"event uid=\(.uid) time=\(.time) reason=\(.reason) count=\(.count) message=\(.message)" end' <<<"$ROWS"; EVENT_READY=true; fi
```

판정:

- observedGeneration이 현재 generation과 같고 template digest 변경이 입증됐지만 direct-owned RS가 없으면 controller create/admission/API 경계로 이관한다.
- RS owner UID가 다르거나 controller owner가 복수/없음, revision/hash/selector가 모순이면 orphan/adoption 경계다. ownerReferences·revision·hash를 수동 수정하지 않는다.
- Pod owner UID가 RS UID와 다르면 해당 Pod를 revision 증거로 세지 않는다.
- audit을 쓰는 경우 승인된 단일 `auditID`에서 timestamp/verb=`create`/resource=`replicasets`/namespace/name/requestURI/status와 현재 Deployment lifecycle UID 관계가 모두 일치해야 하며 actor 상세·token은 보존하지 않는다.

## 상태 변경 경계·정상화

이 문서에는 mutation 명령이 없다. apply/patch/delete/restart/owner 수정은 현재 UID/resourceVersion·template digest·selector·revision, 선언 원본/digest, 승인 ID·UTC window·가용성·멱등성·중단 조건·검증된 rollback target을 변경 시스템에서 재검사한 절차로만 수행한다.

```bash
NORMAL_READY=false
if ! fresh_deployment; then printf '%s\n' '중단: 최신 target 실패' >&2
elif ! R2="$(kubectl get rs -n "$NS" -l "$SELECTOR" -o json --request-timeout=15s)" || ! P2="$(kubectl get pods -n "$NS" -l "$SELECTOR" -o json --request-timeout=15s)"; then printf '%s\n' '중단: 정상화 producer 실패' >&2
elif [ "$(jq --arg u "$DEP_UID" '[.items[]|select(any(.metadata.ownerReferences[]?;.controller==true and .uid==$u))|select((.spec.replicas//0)>0)]|length' <<<"$R2")" -ne 1 ]; then printf '%s\n' '미정상: active RS가 단일 후보가 아님' >&2
else AUID="$(jq -r --arg u "$DEP_UID" '[.items[]|select(any(.metadata.ownerReferences[]?;.controller==true and .uid==$u))|select((.spec.replicas//0)>0)][0].metadata.uid' <<<"$R2")"; BAD="$(jq --arg u "$AUID" '[.items[]|select(any(.metadata.ownerReferences[]?;.controller==true and .uid==$u))|select(([.status.conditions[]?|select(.type=="Ready")][0].status//"False")!="True")]|length' <<<"$P2")"; if [ "$(jq -r '.metadata.generation==(.status.observedGeneration//0)' <<<"$D_LIVE")" = true ] && [ "$BAD" -eq 0 ]; then NORMAL_READY=true; printf 'NORMAL_READY=true deploymentUID=%s activeRSUID=%s observed=%s\n' "$DEP_UID" "$AUID" "$(date -u '+%Y-%m-%dT%H:%M:%SZ')"; else printf '%s\n' '미정상: generation 또는 Pod Ready 불충족' >&2; fi; fi
```

변경 뒤에는 selector+현재 Deployment UID+creation time으로 active RS 단일 후보를 다시 등록하고, 그 RS UID를 owner로 가진 새 Pod의 UID/resourceVersion/containerID/node를 전부 재수집한다. 실제 요청·핵심 기능과 재발 관찰까지 성공해야 정상화한다.

## Prometheus 빠른 관측

```bash
PROMQL_READY=false
if ! fresh_deployment; then printf '%s\n' '중단: 최신 target 실패' >&2; else printf 'kube_deployment_metadata_generation{namespace="%s",deployment="%s"}-kube_deployment_status_observed_generation{namespace="%s",deployment="%s"}\n' "$NS" "$DEP" "$NS" "$DEP"; printf 'count by (replicaset) (kube_replicaset_owner{namespace="%s",owner_kind="Deployment",owner_name="%s",owner_is_controller="true"})\n' "$NS" "$DEP"; PROMQL_READY=true; fi
```

metric/label 미지원·빈 결과·stale series를 정상으로 해석하지 않는다. PromQL은 owner UID/revision/hash를 증명하지 않는다.

## 증거와 관련 문서

Deployment·RS·Pod UID/resourceVersion/owner kind·name·UID, generation, selector, digest, revision/hash, creation time, containerID/node, Event UID·시간, 승인 원본만 보존한다. Secret·token·audit actor 상세·전체 YAML은 저장하지 않는다. 실제 환경 미검증이므로 draft를 유지한다.
