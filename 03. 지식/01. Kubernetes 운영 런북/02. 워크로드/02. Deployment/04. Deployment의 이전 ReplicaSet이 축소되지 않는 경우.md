# Deployment의 이전 ReplicaSet이 축소되지 않는 경우

## 입력값과 빠른 수집

승인된 작업 PC의 같은 Bash에서 `Deployment -> old/new ReplicaSet -> 각 RS 소유 Pod -> availability/termination`을 확인한다. PDB는 Eviction API 경로와 분리하며 node/CRI 명령은 사용하지 않는다.

```bash
fresh_pair(){ PAIR_READY=false; [ -n "${OLD_UID:-}" ] && [ -n "${NEW_UID:-}" ] || return 1; O_LIVE="$(kubectl get rs "$OLD_RS" -n "$NS" -o json --request-timeout=15s)" || return 1; N_LIVE="$(kubectl get rs "$NEW_RS" -n "$NS" -o json --request-timeout=15s)" || return 1; [ "$(jq -r '.metadata.uid' <<<"$O_LIVE")" = "$OLD_UID" ] && [ "$(jq -r '.metadata.uid' <<<"$N_LIVE")" = "$NEW_UID" ] || { printf '%s\n' '중단: old/new ReplicaSet UID 교체' >&2; return 1; }; jq -e --arg u "$DEP_UID" 'any(.metadata.ownerReferences[]?;.controller==true and .kind=="Deployment" and .uid==$u)' <<<"$O_LIVE" >/dev/null || return 1; jq -e --arg u "$DEP_UID" 'any(.metadata.ownerReferences[]?;.controller==true and .kind=="Deployment" and .uid==$u)' <<<"$N_LIVE" >/dev/null || return 1; PAIR_READY=true; }
```

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | 새 revision이 존재하지만 old RS `spec.replicas` 또는 old Pod가 남는다. |
| 적용 | strategy 예산, new availability, terminating Pod를 같은 owner UID로 분리한다. |
| 제외 | 새 RS 부재는 [[03. Deployment의 새 ReplicaSet이 생성되지 않거나 revision·owner 관계가 맞지 않는 경우]], old Pod 종료 정체는 [[15. Pod가 Terminating에서 멈춘 경우]]로 이동한다. |

검색 문자열: `maxSurge`, `maxUnavailable`, `availableReplicas`, `deletionTimestamp`, `paused`, `observedGeneration`.

## 관측별 진단 경로

| 지금 보이는 것 | 먼저 볼 것 | 그다음 어디를 볼지 | 상세 절 |
|---|---|---|---|
| new available이 desired보다 작다 | new RS Pod UID·Ready·containerID | availability 보호 또는 Pod 원인 | [[#판정]] |
| old Pod에 deletionTimestamp가 있다 | old RS UID·Pod UID·PVC 관계 | Terminating 원인 이관 | [[15. Pod가 Terminating에서 멈춘 경우]] |
| old/new 수가 strategy 예산 안이다 | maxSurge·maxUnavailable과 observedGeneration | 정상 진행 관찰 또는 controller owner | [[#판정]] |
| old RS가 0으로 수렴했다 | current active RS 단일 후보와 새 Pod UID | 실제 기능과 재발 관찰 | [[#상태 변경 경계·정상화]] |

## 판정

1. new available이 desired보다 작으면 old 유지가 availability 보호일 수 있다. new RS Pod UID/container reason을 해당 Pod 런북으로 넘긴다.
2. `RollingUpdate`에서 percent `maxSurge`는 desired 기준 올림, `maxUnavailable`은 내림이다. old+new current가 상한 안이고 available 하한 때문에 old가 남으면 정상 진행 후보다. `Recreate`에 적용하지 않는다.
3. old Pod에 deletionTimestamp가 있으면 해당 Pod UID/owner UID/created/deletion과 PVC 연결을 [[15. Pod가 Terminating에서 멈춘 경우]]로 넘긴다.
4. PDB `disruptionsAllowed=0`은 별도 drain/eviction 경로다. Deployment controller의 scale-down 직접 원인으로 단정하지 않는다.
5. `paused=true` 또는 generation 미관측이면 owner/controller 경로다. old RS를 직접 scale하거나 Pod를 삭제하지 않는다.

```bash
EVENT_READY=false
if [ "$PAIR_READY" != true ] || ! fresh_deployment || ! fresh_pair; then printf '%s\n' '중단: 최신 pair/target 필요' >&2
elif ! E="$(kubectl get events -n "$NS" -o json --request-timeout=15s)"; then printf '%s\n' '중단: Event producer 실패' >&2
elif ! ROWS="$(jq -er --arg du "$DEP_UID" --arg ou "$OLD_UID" --arg nu "$NEW_UID" --arg s "$OBS_START" --arg e "$OBS_END" '[.items[]|select(.involvedObject.uid==$du or .involvedObject.uid==$ou or .involvedObject.uid==$nu)|(.eventTime//.series.lastObservedTime//.lastTimestamp//.firstTimestamp//.metadata.creationTimestamp) as $t|select($t>=$s and $t<=$e)|{uid:.metadata.uid,involvedUID:.involvedObject.uid,time:$t,reason,message}]' <<<"$E")"; then printf '%s\n' '중단: Event filter 오류' >&2
else jq -r 'if length==0 then "no-match: Event TTL/범위 확인" else .[]|"event uid=\(.uid) involvedUID=\(.involvedUID) time=\(.time) reason=\(.reason) message=\(.message)" end' <<<"$ROWS"; EVENT_READY=true; fi
```

## 상태 변경 경계·정상화

이 문서에는 mutation 명령이 없다. old RS scale, Pod 삭제, PDB/strategy 완화는 현재 UID/resourceVersion/selector/revision/digest, 승인 ID·UTC window·가용성·멱등성·중단 조건·검증된 rollback target을 직접 재검사한 승인 절차로만 수행한다.

```bash
NORMAL_READY=false
if ! fresh_deployment; then printf '%s\n' '중단: 최신 target 실패' >&2
elif ! R2="$(kubectl get rs -n "$NS" -l "$SELECTOR" -o json --request-timeout=15s)" || ! P2="$(kubectl get pods -n "$NS" -l "$SELECTOR" -o json --request-timeout=15s)"; then printf '%s\n' '중단: 정상화 producer 실패' >&2
elif [ "$(jq --arg u "$DEP_UID" '[.items[]|select(any(.metadata.ownerReferences[]?;.controller==true and .uid==$u))|select((.spec.replicas//0)>0)]|length' <<<"$R2")" -ne 1 ]; then printf '%s\n' '미정상: active RS 단일 후보 아님' >&2
else AUID="$(jq -r --arg u "$DEP_UID" '[.items[]|select(any(.metadata.ownerReferences[]?;.controller==true and .uid==$u))|select((.spec.replicas//0)>0)][0].metadata.uid' <<<"$R2")"; OLD_LEFT="$(jq --arg u "$DEP_UID" --arg a "$AUID" '[.items[]|select(any(.metadata.ownerReferences[]?;.controller==true and .uid==$u))|select(.metadata.uid!=$a and ((.spec.replicas//0)>0 or (.status.replicas//0)>0))]|length' <<<"$R2")"; if [ "$(jq -r '.metadata.generation==(.status.observedGeneration//0) and (.spec.replicas//1)==(.status.availableReplicas//0)' <<<"$D_LIVE")" = true ] && [ "$OLD_LEFT" -eq 0 ]; then NORMAL_READY=true; printf 'NORMAL_READY=true deploymentUID=%s activeRSUID=%s observed=%s\n' "$DEP_UID" "$AUID" "$(date -u '+%Y-%m-%dT%H:%M:%SZ')"; else printf '%s\n' '미정상: available 또는 old RS 수렴 실패' >&2; fi; fi
```

변경 뒤 selector+현재 Deployment owner UID+creation time으로 단일 active RS를 재등록하고 모든 새 Pod UID/containerID/node identity를 다시 수집한다. 실제 기능과 동일 Warning/restart 재발 없음까지 확인한다.
