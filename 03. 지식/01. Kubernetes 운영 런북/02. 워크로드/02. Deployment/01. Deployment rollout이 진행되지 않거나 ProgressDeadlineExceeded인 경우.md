# Deployment rollout이 진행되지 않거나 ProgressDeadlineExceeded인 경우

## 입력값과 빠른 수집

실행 경로는 `승인된 작업 PC/Bash -> kubectl context -> API server -> Deployment -> ReplicaSet -> Pod`다. node shell, SSH, CRI는 이 런북에서 사용하지 않는다. Pod 내부 원인이 확인되면 Pod UID·container kind/name/current containerID·node identity와 시간 범위만 해당 런북으로 넘긴다.

| 구분 | 값 | 계약 |
|---|---|---|
| 최초 입력 | `NS`, `DEP`, `START_INPUT`, `END_INPUT` | 운영자가 한 번 입력한다. 시간은 canonical UTC RFC3339다. |
| API 자동값 | `DEP_UID`, `DEP_RV`, `DEP_GEN`, `SELECTOR`, `CURRENT_REVISION` | exact-name API 응답에서만 등록한다. |
| 계산 후보 | `DEP_RE`, `TEMPLATE_DIGEST` | regex escape와 digest 계산 성공 뒤에만 사용한다. |
| 운영자 선택값 | `RS`, `POD` | owner UID가 현재 Deployment/ReplicaSet과 일치하는 출력에서 선택한다. |

### 1. 실행 위치·도구·최초 입력

```bash
TOOLS_READY=false
missing=()
for tool in kubectl jq date sha256sum sed; do
  command -v "$tool" >/dev/null 2>&1 || missing+=("$tool")
done
if [ -z "${BASH_VERSION:-}" ]; then
  printf '%s\n' '중단: 같은 Bash에서 실행한다.' >&2
elif ((${#missing[@]})); then
  printf '중단: 없는 도구=%s\n' "${missing[*]}" >&2
else
  TOOLS_READY=true
  printf 'TOOLS_READY=true host=%s shell=bash\n' "$(hostname)"
fi
```

```bash
unset INPUT_READY AUTO_READY TARGET_READY SCOPE_READY EVENT_READY PROMQL_READY DEP_UID DEP_RV DEP_GEN DEP_OWNER_KIND DEP_OWNER_NAME DEP_OWNER_UID SELECTOR DEP_RE TEMPLATE_DIGEST CURRENT_REVISION OBS_START OBS_END RS RS_UID RS_RV RS_REV RS_HASH POD POD_UID POD_RV POD_CREATED POD_NODE NODE_UID MACHINE_ID CONTAINER_ROWS
INPUT_READY=false
AUTO_READY=false
TARGET_READY=false
SCOPE_READY=false
EVENT_READY=false
PROMQL_READY=false
NS='PASTE_NAMESPACE_HERE'
DEP='PASTE_DEPLOYMENT_HERE'
START_INPUT='PASTE_START_RFC3339_HERE'
END_INPUT='PASTE_END_RFC3339_HERE'
if [ "$TOOLS_READY" != true ]; then
  printf '%s\n' '중단: TOOLS_READY가 아니다.' >&2
elif [[ ! "$START_INPUT" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] || [[ ! "$END_INPUT" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]]; then
  printf '%s\n' '중단: 시간은 YYYY-MM-DDTHH:MM:SSZ 형식이어야 한다.' >&2
elif [ "$(date -u -d "$START_INPUT" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" != "$START_INPUT" ] || [ "$(date -u -d "$END_INPUT" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" != "$END_INPUT" ]; then
  printf '%s\n' '중단: 시간을 UTC로 round-trip할 수 없다.' >&2
elif (( $(date -u -d "$START_INPUT" +%s) >= $(date -u -d "$END_INPUT" +%s) )); then
  printf '%s\n' '중단: start는 end보다 빨라야 한다.' >&2
elif kubectl get deployment "$DEP" -n "$NS" --request-timeout=15s >/dev/null 2>&1; then
  INPUT_READY=true
  printf 'INPUT_READY=true namespace=%s deployment=%s start=%s end=%s\n' "$NS" "$DEP" "$START_INPUT" "$END_INPUT"
else
  printf '%s\n' '중단: exact-name Deployment 조회 실패' >&2
fi
```

각 `PASTE_..._HERE` 입력칸은 문서에서 한 번만 할당한다. 재등록할 때 아래 블록이 UID·resourceVersion·owner·containerID·node·시간·digest·regex와 모든 downstream READY를 먼저 폐기한다.

### 2. API 자동값 등록

```bash
unset AUTO_READY TARGET_READY SCOPE_READY EVENT_READY PROMQL_READY DEP_UID DEP_RV DEP_GEN DEP_OWNER_KIND DEP_OWNER_NAME DEP_OWNER_UID SELECTOR DEP_RE TEMPLATE_DIGEST CURRENT_REVISION OBS_START OBS_END RS RS_UID RS_RV RS_REV RS_HASH POD POD_UID POD_RV POD_CREATED POD_NODE NODE_UID MACHINE_ID CONTAINER_ROWS
AUTO_READY=false
TARGET_READY=false
SCOPE_READY=false
EVENT_READY=false
PROMQL_READY=false
if [ "$INPUT_READY" != true ]; then
  printf '%s\n' '중단: INPUT_READY가 아니다.' >&2
elif ! DEP_JSON="$(kubectl get deployment "$DEP" -n "$NS" -o json --request-timeout=15s)"; then
  printf '%s\n' '중단: Deployment API 조회 실패, 과거 gate 폐기됨' >&2
elif ! SELECTOR_TMP="$(jq -er '([.spec.selector.matchLabels|to_entries[]?|"\(.key)=\(.value)"] + [.spec.selector.matchExpressions[]?|if .operator=="In" then "\(.key) in (\(.values|join(",")))" elif .operator=="NotIn" then "\(.key) notin (\(.values|join(",")))" elif .operator=="Exists" then .key elif .operator=="DoesNotExist" then "!\(.key)" else error("unsupported selector operator") end])|join(",")|select(length>0)' <<<"$DEP_JSON")"; then
  printf '%s\n' '중단: selector 직렬화 실패' >&2
elif ! TEMPLATE_DIGEST_TMP="$(jq -cS '.spec.template' <<<"$DEP_JSON" | sha256sum | sed 's/[[:space:]].*$//')" || [ -z "$TEMPLATE_DIGEST_TMP" ]; then
  printf '%s\n' '중단: template digest 계산 실패' >&2
else
  DEP_UID="$(jq -r '.metadata.uid' <<<"$DEP_JSON")"
  DEP_RV="$(jq -r '.metadata.resourceVersion' <<<"$DEP_JSON")"
  DEP_GEN="$(jq -r '.metadata.generation' <<<"$DEP_JSON")"
  DEP_OWNER_KIND="$(jq -r '[.metadata.ownerReferences[]?|select(.controller==true)][0].kind // "-"' <<<"$DEP_JSON")"
  DEP_OWNER_NAME="$(jq -r '[.metadata.ownerReferences[]?|select(.controller==true)][0].name // "-"' <<<"$DEP_JSON")"
  DEP_OWNER_UID="$(jq -r '[.metadata.ownerReferences[]?|select(.controller==true)][0].uid // "-"' <<<"$DEP_JSON")"
  CURRENT_REVISION="$(jq -r '.metadata.annotations["deployment.kubernetes.io/revision"] // "-"' <<<"$DEP_JSON")"
  SELECTOR="$SELECTOR_TMP"
  DEP_RE="$(printf '%s' "$DEP" | sed 's/[][\\.^$*+?(){}|]/\\&/g')"
  TEMPLATE_DIGEST="$TEMPLATE_DIGEST_TMP"
  OBS_START="$START_INPUT"
  OBS_END="$END_INPUT"
  AUTO_READY=true
  printf 'AUTO_READY=true\nDeployment: %s/%s\nUID: %s\nresourceVersion: %s\ngeneration: %s\ncontroller owner: %s/%s uid=%s\nrevision: %s\nselector: %s\ntemplate digest: %s\ntime: %s .. %s\n' "$NS" "$DEP" "$DEP_UID" "$DEP_RV" "$DEP_GEN" "$DEP_OWNER_KIND" "$DEP_OWNER_NAME" "$DEP_OWNER_UID" "$CURRENT_REVISION" "$SELECTOR" "$TEMPLATE_DIGEST" "$OBS_START" "$OBS_END"
fi
```

다음 helper는 매 명령에서 exact-name API를 다시 읽고 UID를 고정하며 최신 resourceVersion을 갱신한다. 조회 실패나 UID 교체 시 `TARGET_READY=false`가 남는다.

```bash
fresh_deployment() {
  TARGET_READY=false
  unset DEP_LIVE DEP_RV_LIVE SELECTOR_LIVE TEMPLATE_DIGEST_LIVE
  [ "$AUTO_READY" = true ] || { printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; return 1; }
  DEP_LIVE="$(kubectl get deployment "$DEP" -n "$NS" -o json --request-timeout=15s)" || return 1
  [ "$(jq -r '.metadata.uid' <<<"$DEP_LIVE")" = "$DEP_UID" ] || { printf '%s\n' '중단: Deployment UID가 바뀌었다. 처음부터 재등록한다.' >&2; return 1; }
  SELECTOR_LIVE="$(jq -er '([.spec.selector.matchLabels|to_entries[]?|"\(.key)=\(.value)"] + [.spec.selector.matchExpressions[]?|if .operator=="In" then "\(.key) in (\(.values|join(",")))" elif .operator=="NotIn" then "\(.key) notin (\(.values|join(",")))" elif .operator=="Exists" then .key elif .operator=="DoesNotExist" then "!\(.key)" else error("unsupported selector operator") end])|join(",")|select(length>0)' <<<"$DEP_LIVE")" || return 1
  TEMPLATE_DIGEST_LIVE="$(jq -cS '.spec.template' <<<"$DEP_LIVE" | sha256sum | sed 's/[[:space:]].*$//')" || return 1
  [ "$SELECTOR_LIVE" = "$SELECTOR" ] && [ "$TEMPLATE_DIGEST_LIVE" = "$TEMPLATE_DIGEST" ] || { printf '%s\n' '중단: selector/template이 바뀌었다. 모든 자동값을 재등록한다.' >&2; return 1; }
  DEP_RV_LIVE="$(jq -r '.metadata.resourceVersion' <<<"$DEP_LIVE")"
  DEP_RV="$DEP_RV_LIVE"
  TARGET_READY=true
}
```

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | 현재 generation에서 `updatedReplicas` 또는 `availableReplicas`가 진행되지 않거나 `Progressing=False`, `ProgressDeadlineExceeded`가 관측된다. |
| 적용 | Deployment UID/generation, 직접 소유 ReplicaSet, Pod owner/container/node identity와 같은 관측 창을 연결할 수 있다. |
| 제외 | 새 ReplicaSet identity가 없거나 모순이면 [[03. Deployment의 새 ReplicaSet이 생성되지 않거나 revision·owner 관계가 맞지 않는 경우]], replica 전략 문제는 [[02. Deployment replica 수가 수렴하지 않는 경우]]로 이동한다. |

검색 문자열: `ProgressDeadlineExceeded`, `Progressing`, `observedGeneration`, `updatedReplicas`, `availableReplicas`, `paused`, `pod-template-hash`.

## 최초 확인

```bash
SCOPE_READY=false
unset RS_JSON PODS_JSON NODES_JSON
if ! fresh_deployment; then
  printf '%s\n' '중단: 최신 Deployment identity 확인 실패' >&2
elif ! RS_JSON="$(kubectl get replicasets -n "$NS" -l "$SELECTOR" -o json --request-timeout=15s)"; then
  printf '%s\n' '중단: ReplicaSet producer 실패' >&2
elif ! PODS_JSON="$(kubectl get pods -n "$NS" -l "$SELECTOR" -o json --request-timeout=15s)"; then
  printf '%s\n' '중단: Pod producer 실패' >&2
elif [ "$(jq --arg uid "$DEP_UID" '[.items[]|select(any(.metadata.ownerReferences[]?;.controller==true and .kind=="Deployment" and .uid==$uid))]|length' <<<"$RS_JSON")" -eq 0 ]; then
  printf '%s\n' '분기: 현재 Deployment UID가 직접 소유한 ReplicaSet이 없음' >&2
else
  jq -r '"=== Deployment ===\nUID: \(.metadata.uid)\nresourceVersion: \(.metadata.resourceVersion)\ngeneration/observed: \(.metadata.generation)/\(.status.observedGeneration // 0)\nrevision: \(.metadata.annotations["deployment.kubernetes.io/revision"] // "-")\nreplicas desired/updated/ready/available: \(.spec.replicas // 1)/\(.status.updatedReplicas // 0)/\(.status.readyReplicas // 0)/\(.status.availableReplicas // 0)\npaused: \(.spec.paused // false)\nProgressing: \([.status.conditions[]?|select(.type=="Progressing")|"\(.status) reason=\(.reason // "-") at=\(.lastUpdateTime // "-")"]|join("; "))"' <<<"$DEP_LIVE"
  jq -r --arg uid "$DEP_UID" '.items[]|select(any(.metadata.ownerReferences[]?;.controller==true and .kind=="Deployment" and .uid==$uid))|"\n=== ReplicaSet: \(.metadata.name) ===\nUID/resourceVersion: \(.metadata.uid)/\(.metadata.resourceVersion)\nowner: Deployment/\([.metadata.ownerReferences[]|select(.controller==true)][0].name) uid=\([.metadata.ownerReferences[]|select(.controller==true)][0].uid)\nrevision/hash: \(.metadata.annotations["deployment.kubernetes.io/revision"] // "-")/\(.metadata.labels["pod-template-hash"] // "-")\ncreated: \(.metadata.creationTimestamp)\ndesired/current/ready/available: \(.spec.replicas // 0)/\(.status.replicas // 0)/\(.status.readyReplicas // 0)/\(.status.availableReplicas // 0)"' <<<"$RS_JSON"
  jq -r --arg uid "$DEP_UID" --argjson rs "$RS_JSON" '.items[] as $p|($rs.items[]|select(.metadata.uid==([$p.metadata.ownerReferences[]?|select(.controller==true)][0].uid))|select(any(.metadata.ownerReferences[]?;.controller==true and .uid==$uid))) as $r|"\n=== Pod: \($p.metadata.name) ===\nUID/resourceVersion: \($p.metadata.uid)/\($p.metadata.resourceVersion)\nowner RS: \($r.metadata.name) uid=\($r.metadata.uid) revision=\($r.metadata.annotations["deployment.kubernetes.io/revision"] // "-")\nnode: \($p.spec.nodeName // "-")\ncreated/start: \($p.metadata.creationTimestamp)/\($p.status.startTime // "-")\nphase/Ready: \($p.status.phase // "-")/\([$p.status.conditions[]?|select(.type=="Ready")][0].status // "-")\ncontainers: \(([$p.status.initContainerStatuses[]?|"init/\(.name) id=\(.containerID // "-") ready=\(.ready // false) reason=\(.state.waiting.reason // .state.terminated.reason // "-")"]+[$p.status.containerStatuses[]?|"regular/\(.name) id=\(.containerID // "-") ready=\(.ready // false) reason=\(.state.waiting.reason // .state.terminated.reason // "-")"] )|join("; "))"' <<<"$PODS_JSON"
  SCOPE_READY=true
fi
```

`producer 실패`, `직접 소유 RS 없음`, `jq 오류`는 서로 다른 실패다. 빈 Pod 목록은 성공이나 정상화가 아니라 RS desired=0, 생성 실패 또는 selector/owner 불일치 분기다.

## 관측별 진단 경로

| 지금 보이는 것 | 먼저 볼 것 | 그다음 어디를 볼지 | 상세 절 |
|---|---|---|---|
| current revision RS가 없거나 owner가 다르다 | Deployment UID·revision과 RS owner UID | RS 생성·owner 관계 | [[03. Deployment의 새 ReplicaSet이 생성되지 않거나 revision·owner 관계가 맞지 않는 경우]] |
| updated는 늘지만 available이 멈췄다 | current RS Pod UID·Ready·containerID | 문제 Pod reason과 Event | [[#문제 ReplicaSet·Pod 등록]] |
| `ProgressDeadlineExceeded`가 현재 generation에 연결된다 | condition 시각과 UID 제한 Event | 원인 Pod 또는 controller owner | [[#시간 제한 Event와 판정]] |
| replica·owner가 수렴했다 | active RS 단일 후보와 새 Pod UID | 실제 기능과 재발 관찰 | [[#정상화 검증]] |

## 문제 ReplicaSet·Pod 등록

현재 revision/hash와 owner UID가 맞는 출력에서 하나씩 선택한다. Pod가 아직 없으면 이 블록을 실행하지 않고 새 RS 미생성/Pod 생성 실패 경로로 이관한다.

```bash
RS='PASTE_NEW_REPLICASET_HERE'
POD='PASTE_PROBLEM_POD_HERE'
```

```bash
SCOPE_READY=false
unset RS_UID RS_RV RS_REV RS_HASH POD_UID POD_RV POD_CREATED POD_NODE NODE_UID MACHINE_ID CONTAINER_ROWS
if ! fresh_deployment; then
  printf '%s\n' '중단: 최신 Deployment identity 확인 실패' >&2
elif ! RS_LIVE="$(kubectl get rs "$RS" -n "$NS" -o json --request-timeout=15s)" || ! POD_LIVE="$(kubectl get pod "$POD" -n "$NS" -o json --request-timeout=15s)"; then
  printf '%s\n' '중단: 선택 객체 조회 실패' >&2
elif ! jq -e --arg uid "$DEP_UID" 'any(.metadata.ownerReferences[]?;.controller==true and .kind=="Deployment" and .uid==$uid)' <<<"$RS_LIVE" >/dev/null; then
  printf '%s\n' '중단: ReplicaSet owner UID 불일치' >&2
elif ! jq -e --arg uid "$(jq -r '.metadata.uid' <<<"$RS_LIVE")" 'any(.metadata.ownerReferences[]?;.controller==true and .kind=="ReplicaSet" and .uid==$uid)' <<<"$POD_LIVE" >/dev/null; then
  printf '%s\n' '중단: Pod owner UID 불일치' >&2
elif [ -z "$(jq -r '.spec.nodeName // empty' <<<"$POD_LIVE")" ]; then
  printf '%s\n' '분기: Pod가 아직 node에 배치되지 않음' >&2
elif ! NODE_LIVE="$(kubectl get node "$(jq -r '.spec.nodeName' <<<"$POD_LIVE")" -o json --request-timeout=15s)"; then
  printf '%s\n' '중단: node identity 조회 실패' >&2
else
  RS_UID="$(jq -r '.metadata.uid' <<<"$RS_LIVE")"; RS_RV="$(jq -r '.metadata.resourceVersion' <<<"$RS_LIVE")"; RS_REV="$(jq -r '.metadata.annotations["deployment.kubernetes.io/revision"] // "-"' <<<"$RS_LIVE")"; RS_HASH="$(jq -r '.metadata.labels["pod-template-hash"] // "-"' <<<"$RS_LIVE")"
  POD_UID="$(jq -r '.metadata.uid' <<<"$POD_LIVE")"; POD_RV="$(jq -r '.metadata.resourceVersion' <<<"$POD_LIVE")"; POD_CREATED="$(jq -r '.metadata.creationTimestamp' <<<"$POD_LIVE")"; POD_NODE="$(jq -r '.spec.nodeName' <<<"$POD_LIVE")"
  NODE_UID="$(jq -r '.metadata.uid' <<<"$NODE_LIVE")"; MACHINE_ID="$(jq -r '.status.nodeInfo.machineID // empty' <<<"$NODE_LIVE")"
  CONTAINER_ROWS="$(jq -c '([.status.initContainerStatuses[]?|{kind:"init",name,containerID:(.containerID//"-")}]+[.status.containerStatuses[]?|{kind:"regular",name,containerID:(.containerID//"-")}])' <<<"$POD_LIVE")"
  SCOPE_READY=true
  printf 'SCOPE_READY=true RS=%s uid=%s rv=%s revision=%s hash=%s\nPod=%s uid=%s rv=%s created=%s\nNode=%s uid=%s machineID=%s\ncontainers=%s\n' "$RS" "$RS_UID" "$RS_RV" "$RS_REV" "$RS_HASH" "$POD" "$POD_UID" "$POD_RV" "$POD_CREATED" "$POD_NODE" "$NODE_UID" "$MACHINE_ID" "$CONTAINER_ROWS"
fi
```

## 시간 제한 Event와 판정

```bash
EVENT_READY=false
if [ "$SCOPE_READY" != true ] || ! fresh_deployment; then
  printf '%s\n' '중단: 최신 SCOPE_READY/TARGET_READY가 아니다.' >&2
elif [ "$POD_UID" != "$(kubectl get pod "$POD" -n "$NS" -o jsonpath='{.metadata.uid}' --request-timeout=15s 2>/dev/null)" ]; then
  printf '%s\n' '중단: Pod UID가 바뀌었다.' >&2
elif [ "$RS_UID" != "$(kubectl get rs "$RS" -n "$NS" -o jsonpath='{.metadata.uid}' --request-timeout=15s 2>/dev/null)" ]; then
  printf '%s\n' '중단: ReplicaSet UID가 바뀌었다.' >&2
elif ! POD_OWNER_NOW="$(kubectl get pod "$POD" -n "$NS" -o jsonpath='{.metadata.ownerReferences[?(@.controller==true)].uid}' --request-timeout=15s)" || [ "$POD_OWNER_NOW" != "$RS_UID" ]; then
  printf '%s\n' '중단: 현재 Pod owner UID가 선택한 ReplicaSet과 다르다.' >&2
elif ! EVENTS_JSON="$(kubectl get events -n "$NS" -o json --request-timeout=15s)"; then
  printf '%s\n' '중단: Event producer 실패' >&2
elif ! EVENT_ROWS="$(jq -er --arg duid "$DEP_UID" --arg puid "$POD_UID" --arg start "$OBS_START" --arg end "$OBS_END" '[.items[]|select(.involvedObject.uid==$duid or .involvedObject.uid==$puid)|(.eventTime // .series.lastObservedTime // .lastTimestamp // .firstTimestamp // .metadata.creationTimestamp) as $t|select($t >= $start and $t <= $end)|{uid:.metadata.uid,involvedUID:.involvedObject.uid,time:$t,type,reason,count:(.count // .series.count // 1),message}]' <<<"$EVENTS_JSON")"; then
  printf '%s\n' '중단: Event filter 오류' >&2
elif [ "$(jq 'length' <<<"$EVENT_ROWS")" -eq 0 ]; then
  printf '%s\n' '분기: 조회 성공, 현재 UID와 시간 범위에 맞는 Event 없음. Event TTL/범위를 확인한다.'
  EVENT_READY=true
else
  jq -r '.[]|"event uid=\(.uid) involvedUID=\(.involvedUID) time=\(.time) type=\(.type) reason=\(.reason) count=\(.count) message=\(.message)"' <<<"$EVENT_ROWS"
  EVENT_READY=true
fi
```

- `generation > observedGeneration`: controller가 현재 spec을 관측했다는 증거가 없다. control-plane owner에게 UID·generation·condition/Event 시간을 이관한다.
- `paused=true`: 승인 기록과 일치하면 의도된 정지다. 이 문서에서 자동 resume하지 않는다.
- 새 RS desired/current가 증가하지 않음: [[03. Deployment의 새 ReplicaSet이 생성되지 않거나 revision·owner 관계가 맞지 않는 경우]] 또는 Pod 생성 Event로 이동한다.
- updated는 증가하지만 available이 멈춤: 현재 Pod UID/containerID의 waiting/terminated/Ready reason을 [[16. Pod가 Running이지만 Ready가 아닌 경우]], [[19. Pod readiness probe가 실패하는 경우]] 등 직접 관측된 Pod 런북으로 넘긴다.
- `ProgressDeadlineExceeded`: condition 시각이 현재 generation/template 적용 뒤이고 같은 revision의 available이 부족할 때만 현재 timeout이다. 과거 condition을 patch로 지우지 않는다.

## 읽기 전용과 상태 변경 경계

이 런북에는 상태 변경 명령이 없다. `resume`, `restart`, `undo`, `scale`, Pod 삭제는 rollout 정체 관측만으로 실행하지 않는다. 변경이 필요하면 현재 Deployment UID/resourceVersion, selector, template digest, revision, owner, 승인 ID·UTC 변경 창·가용성·중단 조건·검증된 rollback target을 변경 시스템에서 다시 확인한다. rollback target을 결정할 수 없으면 [[05. Deployment rollback 대상 revision을 결정할 수 없는 경우]]로 이동한다.

## 정상화 검증

```bash
NORMAL_READY=false
if ! fresh_deployment; then
  printf '%s\n' '중단: 최신 Deployment identity 확인 실패' >&2
elif ! RS_NOW="$(kubectl get rs -n "$NS" -l "$SELECTOR" -o json --request-timeout=15s)" || ! PODS_NOW="$(kubectl get pods -n "$NS" -l "$SELECTOR" -o json --request-timeout=15s)"; then
  printf '%s\n' '중단: 정상화 producer 실패' >&2
elif [ "$(jq --arg uid "$DEP_UID" '[.items[]|select(any(.metadata.ownerReferences[]?;.controller==true and .uid==$uid))|select((.spec.replicas//0)>0)]|length' <<<"$RS_NOW")" -ne 1 ]; then
  printf '%s\n' '중단: 현재 Deployment UID의 active ReplicaSet이 단일 후보가 아니다.' >&2
else
  NEW_RS_UID="$(jq -r --arg uid "$DEP_UID" '[.items[]|select(any(.metadata.ownerReferences[]?;.controller==true and .uid==$uid))|select((.spec.replicas//0)>0)][0].metadata.uid' <<<"$RS_NOW")"
  BAD_PODS="$(jq --arg rsuid "$NEW_RS_UID" '[.items[]|select(any(.metadata.ownerReferences[]?;.controller==true and .uid==$rsuid))|select(([.status.conditions[]?|select(.type=="Ready")][0].status//"False")!="True" or ([.status.containerStatuses[]?.restartCount]|add//0)>0)]|length' <<<"$PODS_NOW")"
  if [ "$(jq -r '.metadata.generation == (.status.observedGeneration // 0) and (.spec.replicas // 1) == (.status.updatedReplicas // 0) and (.spec.replicas // 1) == (.status.availableReplicas // 0)' <<<"$DEP_LIVE")" != true ] || [ "$BAD_PODS" -ne 0 ]; then
    printf '%s\n' '미정상: generation/replica 또는 새 owner Pod Ready·restart 조건 불충족' >&2
  else
    NORMAL_READY=true
    printf 'NORMAL_READY=true deploymentUID=%s activeRSUID=%s observedAt=%s\n' "$DEP_UID" "$NEW_RS_UID" "$(date -u '+%Y-%m-%dT%H:%M:%SZ')"
  fi
fi
```

`NORMAL_READY=true`는 객체·owner 수렴만 확인한다. 승인된 실제 요청/핵심 기능, EndpointSlice를 사용하는 환경의 Service port-targetPort-endpoint port와 endpoint targetRef Pod UID, 새 Warning·동일 reason·restart 증가가 `OBS_END-OBS_START`와 동등한 재발 관찰 창에서 없음을 별도로 확인해야 정상화한다.

## Prometheus 빠른 관측

```bash
PROMQL_READY=false
if ! fresh_deployment; then
  printf '%s\n' '중단: 최신 TARGET_READY가 아니다.' >&2
else
  printf 'kube_deployment_status_condition{namespace="%s",deployment="%s",condition="Progressing",status="false",reason="ProgressDeadlineExceeded"} == 1\n' "$NS" "$DEP"
  printf 'kube_deployment_spec_replicas{namespace="%s",deployment="%s"} - kube_deployment_status_replicas_updated{namespace="%s",deployment="%s"}\n' "$NS" "$DEP" "$NS" "$DEP"
  printf 'kube_deployment_status_replicas_unavailable{namespace="%s",deployment="%s"}\n' "$NS" "$DEP"
  PROMQL_READY=true
fi
```

출력만 Prometheus/Grafana에 붙여 넣는다. kube-state-metrics의 metric/label 지원과 현재 cluster 범위를 확인하고, 빈 결과를 0이나 정상으로 해석하지 않는다. metric에는 Deployment UID와 Event message가 없으므로 API identity를 대체하지 못한다.

## 증거 보존과 관련 문서
