# Deployment rollback 대상 revision을 결정할 수 없는 경우

## 입력값과 빠른 수집

실행 경로는 `승인된 작업 PC의 같은 Bash -> API server -> Deployment -> 직접 소유 ReplicaSet -> 직접 소유 Pod`다. node·CRI·SSH는 사용하지 않는다. revision 번호, 높은 Ready 수, 직전 revision이라는 이유만으로 rollback 대상을 자동 선택하지 않는다.

| 구분 | 값 | 계약 |
|---|---|---|
| 최초 입력 | `NS`, `DEP`, 장애 관측 시작·종료 | 운영자가 한 번 입력하고 canonical UTC로 검증한다. |
| API 자동값 | Deployment UID/resourceVersion/generation/selector/current revision/template digest | exact-name API가 모두 성공한 뒤 등록한다. |
| 계산 후보 | RS revision, normalized template digest, 생성 시각 | 현재 Deployment owner UID와 연결된 후보만 출력한다. |
| 운영자 선택값 | candidate RS, evidence ID, approval ID, 변경 창, 최소 available 수 | 정상 이력·호환성·승인 근거를 확인한 뒤 등록한다. |

```bash
fresh_deployment(){ TARGET_READY=false; unset D_LIVE S_LIVE DIG_LIVE; [ "$AUTO_READY" = true ] || return 1; D_LIVE="$(kubectl get deployment "$DEP" -n "$NS" -o json --request-timeout=15s)" || return 1; [ "$(jq -r '.metadata.uid' <<<"$D_LIVE")" = "$DEP_UID" ] || { printf '%s\n' '중단: Deployment UID 교체' >&2; return 1; }; S_LIVE="$(jq -er '([.spec.selector.matchLabels|to_entries[]?|"\(.key)=\(.value)"]+[.spec.selector.matchExpressions[]?|if .operator=="In" then "\(.key) in (\(.values|join(",")))" elif .operator=="NotIn" then "\(.key) notin (\(.values|join(",")))" elif .operator=="Exists" then .key elif .operator=="DoesNotExist" then "!\(.key)" else error("operator") end])|join(",")|select(length>0)' <<<"$D_LIVE")" || return 1; DIG_LIVE="$(jq -cS '.spec.template|.metadata.labels|=with_entries(select(.key!="pod-template-hash"))' <<<"$D_LIVE"|sha256sum|sed 's/[[:space:]].*$//')" || return 1; [ "$S_LIVE" = "$SELECTOR" ] && [ "$DIG_LIVE" = "$TEMPLATE_DIGEST" ] || { printf '%s\n' '중단: selector/template 변경, 처음부터 재등록' >&2; return 1; }; DEP_RV="$(jq -r '.metadata.resourceVersion' <<<"$D_LIVE")"; TARGET_READY=true; }
```

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | 현재 template 회귀가 의심되지만 어느 과거 revision이 실제 정상·호환 상태였는지 결정되지 않았다. |
| 적용 | 현재 Deployment UID와 직접 소유 RS의 revision·normalized template, 해당 RS Pod의 과거 기능 증거를 연결할 수 있다. |
| 제외 | node·registry·dependency 공통 장애, 데이터 migration 비호환, 정상 이력 부재는 rollback 대상 미결정으로 종료한다. StatefulSet에는 적용하지 않는다. |

검색 문자열: `rollout history`, `deployment.kubernetes.io/revision`, `pod-template-hash`, `change-cause`, `ProgressDeadlineExceeded`, `Available`, `rollback`.

## 최초 확인

```bash
INVENTORY_READY=false
if ! fresh_deployment; then
  printf '%s\n' '중단: 최신 Deployment gate 실패' >&2
elif ! R="$(kubectl get rs -n "$NS" -l "$SELECTOR" -o json --request-timeout=15s)" || ! P="$(kubectl get pods -n "$NS" -l "$SELECTOR" -o json --request-timeout=15s)" || ! E="$(kubectl get events -n "$NS" -o json --request-timeout=15s)"; then
  printf '%s\n' '중단: RS/Pod/Event producer 실패' >&2
elif ! ER="$(jq -er --arg u "$DEP_UID" --arg s "$OBS_START" --arg e "$OBS_END" '[.items[]|select(.involvedObject.uid==$u)|(.eventTime//.series.lastObservedTime//.lastTimestamp//.firstTimestamp//.metadata.creationTimestamp) as $t|select($t>=$s and $t<=$e)|{uid:.metadata.uid,time:$t,type,reason,count:(.count//.series.count//1),message}]' <<<"$E")"; then
  printf '%s\n' '중단: Event filter 오류' >&2
else
  jq -r '"=== Deployment ===\nUID/RV: \(.metadata.uid)/\(.metadata.resourceVersion)\ngeneration/observed: \(.metadata.generation)/\(.status.observedGeneration//0)\ncurrent revision: \(.metadata.annotations["deployment.kubernetes.io/revision"]//"-")\ndesired/updated/ready/available: \(.spec.replicas//1)/\(.status.updatedReplicas//0)/\(.status.readyReplicas//0)/\(.status.availableReplicas//0)"' <<<"$D_LIVE"
  jq -r --arg u "$DEP_UID" '.items[]|select(any(.metadata.ownerReferences[]?;.controller==true and .kind=="Deployment" and .uid==$u))|"\n=== RS \(.metadata.name) ===\nUID/RV: \(.metadata.uid)/\(.metadata.resourceVersion)\nowner: Deployment/\([.metadata.ownerReferences[]|select(.controller==true)][0].name) uid=\($u)\nrevision/hash: \(.metadata.annotations["deployment.kubernetes.io/revision"]//"-")/\(.metadata.labels["pod-template-hash"]//"-")\ncreated: \(.metadata.creationTimestamp)\ndesired/current/ready/available: \(.spec.replicas//0)/\(.status.replicas//0)/\(.status.readyReplicas//0)/\(.status.availableReplicas//0)\ncontainers: \([.spec.template.spec.initContainers[]?|"init/\(.name)=\(.image)"]+[.spec.template.spec.containers[]?|"regular/\(.name)=\(.image)"]|join(";"))"' <<<"$R"
  jq -r --argjson r "$R" --arg u "$DEP_UID" '.items[] as $p|($r.items[]|select(.metadata.uid==([$p.metadata.ownerReferences[]?|select(.controller==true)][0].uid))|select(any(.metadata.ownerReferences[]?;.controller==true and .uid==$u))) as $x|"Pod \($p.metadata.name) uid=\($p.metadata.uid) ownerRS=\($x.metadata.name)/\($x.metadata.uid) revision=\($x.metadata.annotations["deployment.kubernetes.io/revision"]//"-") created=\($p.metadata.creationTimestamp) Ready=\([$p.status.conditions[]?|select(.type=="Ready")][0].status//"-") containers=\(([$p.status.initContainerStatuses[]?|"init/\(.name):\(.containerID//"-")"]+[$p.status.containerStatuses[]?|"regular/\(.name):\(.containerID//"-")"] )|join(";"))"' <<<"$P"
  jq -r 'if length==0 then "no-match: 현재 Deployment UID·시간 범위 Event 없음" else .[]|"event uid=\(.uid) time=\(.time) type=\(.type) reason=\(.reason) count=\(.count) message=\(.message)" end' <<<"$ER"
  INVENTORY_READY=true
fi
```

producer 실패, filter 오류, 조회 성공 후 no-match를 구분한다. 후보 RS의 image tag가 같아도 digest가 다를 수 있고, 과거 Ready 수는 당시 실제 요청·dependency·데이터 호환성을 보장하지 않는다.

| 지금 보이는 것 | 먼저 볼 것 | 그다음 어디를 볼지 | 상세 절 |
|---|---|---|---|
| 과거 RS는 있지만 정상 근거가 없다 | owner UID·revision·normalized digest와 실제 기능 증거 | target 미결정 또는 증거 등록 | [[#candidate와 승인 gate]] |
| 여러 revision에서 같은 node·registry·dependency 오류가 난다 | current/candidate Pod UID와 공통 실패 경로 | rollback 중단과 해당 owner 이관 | [[#candidate와 승인 gate]] |
| 단일 candidate와 승인 근거가 확정됐다 | fresh target·RBAC·변경 창·최소 가용성 | 제한된 rollback | [[#제한된 상태 변경]] |
| rollback API가 성공했다 | current template digest·active RS owner·새 Pod UID | 실제 기능과 재발 관찰 | [[#교체 객체 재등록과 정상화]] |

## candidate와 승인 gate

```bash
CANDIDATE_RS='PASTE_CANDIDATE_REPLICASET_HERE'
EVIDENCE_ID='PASTE_NORMAL_EVIDENCE_ID_HERE'
APPROVAL_ID='PASTE_APPROVAL_ID_HERE'
CHANGE_START_INPUT='PASTE_CHANGE_START_RFC3339_HERE'
CHANGE_END_INPUT='PASTE_CHANGE_END_RFC3339_HERE'
MIN_AVAILABLE_INPUT='PASTE_MIN_AVAILABLE_INTEGER_HERE'
```

```bash
CANDIDATE_READY=false; EVIDENCE_READY=false; AUTH_READY=false; ROLLBACK_READY=false; POST_READY=false; NORMAL_READY=false
unset CANDIDATE_UID CANDIDATE_RV CANDIDATE_REV CANDIDATE_DIGEST CANDIDATE_CREATED CHANGE_START CHANGE_END MIN_AVAILABLE MUTATION_AT POST_RS POST_RS_UID POST_REV POST_PODS
if [ "$INVENTORY_READY" != true ] || ! fresh_deployment; then
  printf '%s\n' '중단: 최신 inventory/Deployment 필요' >&2
elif [[ ! "$CHANGE_START_INPUT" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] || [[ ! "$CHANGE_END_INPUT" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] || [ "$(date -u -d "$CHANGE_START_INPUT" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" != "$CHANGE_START_INPUT" ] || [ "$(date -u -d "$CHANGE_END_INPUT" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" != "$CHANGE_END_INPUT" ] || (( $(date -u -d "$CHANGE_START_INPUT" +%s) >= $(date -u -d "$CHANGE_END_INPUT" +%s) )); then
  printf '%s\n' '중단: 변경 창 canonical 검증 실패' >&2
elif ! [[ "$MIN_AVAILABLE_INPUT" =~ ^[0-9]+$ ]]; then
  printf '%s\n' '중단: MIN_AVAILABLE은 0 이상의 정수여야 한다.' >&2
elif ! C="$(kubectl get rs "$CANDIDATE_RS" -n "$NS" -o json --request-timeout=15s)"; then
  printf '%s\n' '중단: candidate RS 조회 실패' >&2
elif ! jq -e --arg u "$DEP_UID" --arg n "$DEP" 'any(.metadata.ownerReferences[]?;.controller==true and .kind=="Deployment" and .name==$n and .uid==$u)' <<<"$C" >/dev/null; then
  printf '%s\n' '중단: candidate owner kind/name/UID 불일치' >&2
elif ! C_DIG="$(jq -cS '.spec.template|.metadata.labels|=with_entries(select(.key!="pod-template-hash"))' <<<"$C"|sha256sum|sed 's/[[:space:]].*$//')" || [ -z "$C_DIG" ]; then
  printf '%s\n' '중단: candidate digest 실패' >&2
elif [ "$C_DIG" = "$TEMPLATE_DIGEST" ]; then
  printf '%s\n' '중단: 현재 template과 candidate가 같아 rollback은 멱등 no-op이다.' >&2
else
  CANDIDATE_UID="$(jq -r '.metadata.uid' <<<"$C")"; CANDIDATE_RV="$(jq -r '.metadata.resourceVersion' <<<"$C")"; CANDIDATE_REV="$(jq -r '.metadata.annotations["deployment.kubernetes.io/revision"]//empty' <<<"$C")"; CANDIDATE_DIGEST="$C_DIG"; CANDIDATE_CREATED="$(jq -r '.metadata.creationTimestamp' <<<"$C")"; CHANGE_START="$CHANGE_START_INPUT"; CHANGE_END="$CHANGE_END_INPUT"; MIN_AVAILABLE="$MIN_AVAILABLE_INPUT"
  if ! [[ "$CANDIDATE_REV" =~ ^[1-9][0-9]*$ ]] || [ -z "$EVIDENCE_ID" ] || [ -z "$APPROVAL_ID" ]; then
    printf '%s\n' '중단: revision/evidence/approval가 유효하지 않다.' >&2
  elif ! CANDIDATE_CREATED_EPOCH="$(date -u -d "$CANDIDATE_CREATED" +%s 2>/dev/null)" || ! DEP_CREATED_EPOCH="$(date -u -d "$(jq -r '.metadata.creationTimestamp' <<<"$D_LIVE")" +%s 2>/dev/null)" || (( CANDIDATE_CREATED_EPOCH < DEP_CREATED_EPOCH || CANDIDATE_CREATED_EPOCH > $(date -u -d "$OBS_END" +%s) )); then
    printf '%s\n' '중단: candidate 생성 시각이 현재 Deployment lifecycle·장애 창과 맞지 않는다.' >&2
  else
    CANDIDATE_READY=true; EVIDENCE_READY=true
    printf 'CANDIDATE_READY=true rs=%s uid=%s rv=%s revision=%s created=%s digest=%s\nEVIDENCE_READY=true evidence=%s approval=%s window=%s..%s minAvailable=%s\n' "$CANDIDATE_RS" "$CANDIDATE_UID" "$CANDIDATE_RV" "$CANDIDATE_REV" "$CANDIDATE_CREATED" "$CANDIDATE_DIGEST" "$EVIDENCE_ID" "$APPROVAL_ID" "$CHANGE_START" "$CHANGE_END" "$MIN_AVAILABLE"
  fi
fi
```

`EVIDENCE_ID`는 candidate가 당시 같은 container image digest·설정 참조·데이터/API 호환성에서 정상이고, Warning·restart 없이 실제 핵심 요청을 통과했다는 비민감 증거를 가리켜야 한다. Secret 값·token·개인키는 출력하지 않는다. audit을 쓰면 단일 auditID의 timestamp, verb, resource/subresource, namespace/name, requestURI, status와 현재 lifecycle UID만 보존하고 actor 상세는 남기지 않는다.

```bash
AUTH_READY=false
if [ "$CANDIDATE_READY" != true ] || ! fresh_deployment; then
  printf '%s\n' '중단: 최신 candidate/Deployment 필요' >&2
elif [ "$(kubectl auth can-i patch "deployment/$DEP" -n "$NS" 2>/dev/null)" != yes ]; then
  printf '%s\n' '중단: 현재 주체의 patch deployments/name 권한이 확인되지 않았다.' >&2
else
  AUTH_READY=true
  printf 'AUTH_READY=true verb=patch resource=deployments namespace=%s name=%s\n' "$NS" "$DEP"
fi
```

`auth can-i` 성공은 실제 rollback 성공이나 admission 허용을 보장하지 않는다. 현재 subject·namespace·verb·resource·name에 대한 사전 점검일 뿐이다.

## 제한된 상태 변경

아래 명령은 candidate의 정상성, current regression, 공통 node·registry·dependency 원인 배제, blast radius, 최소 가용성, 데이터 호환성, 중단·되돌림 절차가 승인 기록에 모두 있을 때만 실행한다. `kubectl rollout undo`에는 resourceVersion precondition 옵션이 없으므로 명령 직전 UID·current digest·candidate UID/revision/digest를 다시 확인하고, 확인 뒤 다른 writer가 있으면 중단해야 한다.

```bash
prepare_rollback(){ ROLLBACK_READY=false; [ "$CANDIDATE_READY" = true ] && [ "$EVIDENCE_READY" = true ] && [ "$AUTH_READY" = true ] || return 1; NOW="$(date -u '+%Y-%m-%dT%H:%M:%SZ')"; (( $(date -u -d "$NOW" +%s) >= $(date -u -d "$CHANGE_START" +%s) && $(date -u -d "$NOW" +%s) <= $(date -u -d "$CHANGE_END" +%s) )) || { printf '%s\n' '중단: 승인 변경 창 밖' >&2; return 1; }; [ "$(kubectl auth can-i patch "deployment/$DEP" -n "$NS" 2>/dev/null)" = yes ] || { printf '%s\n' '중단: mutation 직전 RBAC 재검증 실패' >&2; return 1; }; fresh_deployment || return 1; C_LIVE="$(kubectl get rs "$CANDIDATE_RS" -n "$NS" -o json --request-timeout=15s)" || return 1; [ "$(jq -r '.metadata.uid' <<<"$C_LIVE")" = "$CANDIDATE_UID" ] || { printf '%s\n' '중단: candidate UID 교체' >&2; return 1; }; jq -e --arg u "$DEP_UID" 'any(.metadata.ownerReferences[]?;.controller==true and .kind=="Deployment" and .uid==$u)' <<<"$C_LIVE" >/dev/null || return 1; [ "$(jq -r '.metadata.annotations["deployment.kubernetes.io/revision"]//empty' <<<"$C_LIVE")" = "$CANDIDATE_REV" ] || return 1; C_DIG_LIVE="$(jq -cS '.spec.template|.metadata.labels|=with_entries(select(.key!="pod-template-hash"))' <<<"$C_LIVE"|sha256sum|sed 's/[[:space:]].*$//')" || return 1; [ "$C_DIG_LIVE" = "$CANDIDATE_DIGEST" ] || { printf '%s\n' '중단: candidate template 변경' >&2; return 1; }; [ "$(jq -r '.status.availableReplicas//0' <<<"$D_LIVE")" -ge "$MIN_AVAILABLE" ] || { printf '%s\n' '중단: 승인 최소 available 미달' >&2; return 1; }; ROLLBACK_READY=true; printf 'ROLLBACK_READY=true deploymentUID=%s rv=%s currentDigest=%s candidateUID=%s revision=%s candidateDigest=%s approval=%s\n' "$DEP_UID" "$DEP_RV" "$TEMPLATE_DIGEST" "$CANDIDATE_UID" "$CANDIDATE_REV" "$CANDIDATE_DIGEST" "$APPROVAL_ID"; }
```

```bash
if prepare_rollback && [ "$ROLLBACK_READY" = true ]; then
  if kubectl rollout undo "deployment/$DEP" -n "$NS" --to-revision="$CANDIDATE_REV"; then
    MUTATION_AT="$(date -u '+%Y-%m-%dT%H:%M:%SZ')"; MUTATION_DEP_UID="$DEP_UID"; MUTATION_SELECTOR="$SELECTOR"; EXPECTED_DIGEST="$CANDIDATE_DIGEST"; MUTATION_APPROVAL="$APPROVAL_ID"; printf 'mutation accepted at=%s approval=%s\n' "$MUTATION_AT" "$MUTATION_APPROVAL"; unset DEP_UID DEP_RV DEP_GEN SELECTOR TEMPLATE_DIGEST CURRENT_REVISION OBS_START OBS_END CANDIDATE_RS CANDIDATE_UID CANDIDATE_RV CANDIDATE_REV CANDIDATE_DIGEST CANDIDATE_CREATED EVIDENCE_ID APPROVAL_ID CHANGE_START CHANGE_END MIN_AVAILABLE POST_RS POST_RS_UID POST_REV POST_PODS; AUTO_READY=false; TARGET_READY=false; INVENTORY_READY=false; CANDIDATE_READY=false; EVIDENCE_READY=false; AUTH_READY=false; ROLLBACK_READY=false; POST_READY=false; NORMAL_READY=false; PROMQL_READY=false
  else
    printf '%s\n' '중단: rollback API 실패, 성공으로 기록하지 않는다.' >&2
  fi
fi
```

연속 undo는 금지한다. 되돌림이 필요하면 변경 전 template을 가진 실제 RS UID·revision·normalized digest를 새 candidate로 다시 등록하고 동일한 evidence·approval·가용성 gate를 통과한다.

## 교체 객체 재등록과 정상화

rollback 뒤 과거 `CURRENT_REVISION`, RS 이름, Pod UID를 재사용하지 않는다. Deployment는 같은 UID로 갱신될 수 있고 기존 RS를 다시 scale할 수도 있으므로 현재 template과 일치하는 active RS를 owner UID·digest로 단일 재선택한다. 새 Pod는 mutation 시각 이후 생성된 current owner Pod로 다시 수집한다.

```bash
POST_READY=false; NORMAL_READY=false
unset POST_RS POST_RS_UID POST_REV POST_PODS
if [ -z "${MUTATION_AT:-}" ]; then
  printf '%s\n' '중단: 이 Bash에서 성공한 mutation 시각이 없다.' >&2
elif ! D_POST="$(kubectl get deployment "$DEP" -n "$NS" -o json --request-timeout=15s)" || [ "$(jq -r '.metadata.uid' <<<"$D_POST")" != "$MUTATION_DEP_UID" ]; then
  printf '%s\n' '중단: post Deployment 조회 실패 또는 UID 교체' >&2
elif ! S_POST="$(jq -er '([.spec.selector.matchLabels|to_entries[]?|"\(.key)=\(.value)"]+[.spec.selector.matchExpressions[]?|if .operator=="In" then "\(.key) in (\(.values|join(",")))" elif .operator=="NotIn" then "\(.key) notin (\(.values|join(",")))" elif .operator=="Exists" then .key elif .operator=="DoesNotExist" then "!\(.key)" else error("operator") end])|join(",")|select(length>0)' <<<"$D_POST")" || [ "$S_POST" != "$MUTATION_SELECTOR" ]; then
  printf '%s\n' '중단: post selector 변경 또는 직렬화 실패' >&2
elif ! POST_DIG="$(jq -cS '.spec.template|.metadata.labels|=with_entries(select(.key!="pod-template-hash"))' <<<"$D_POST"|sha256sum|sed 's/[[:space:]].*$//')" || [ "$POST_DIG" != "$EXPECTED_DIGEST" ]; then
  printf '%s\n' '미정상: post template이 승인 candidate와 다르다.' >&2
elif ! R_POST="$(kubectl get rs -n "$NS" -l "$S_POST" -o json --request-timeout=15s)" || ! P_POST="$(kubectl get pods -n "$NS" -l "$S_POST" -o json --request-timeout=15s)"; then
  printf '%s\n' '중단: post RS/Pod producer 실패' >&2
else
  MATCHING_RS=(); RS_LOOKUP_FAILED=false
  mapfile -t ACTIVE_RS < <(jq -r --arg u "$MUTATION_DEP_UID" '.items[]|select(any(.metadata.ownerReferences[]?;.controller==true and .uid==$u))|select((.spec.replicas//0)>0)|.metadata.name' <<<"$R_POST")
  for RS_NAME in "${ACTIVE_RS[@]}"; do
    if ! RS_ONE="$(kubectl get rs "$RS_NAME" -n "$NS" -o json --request-timeout=15s)"; then
      RS_LOOKUP_FAILED=true; break
    fi
    RS_ONE_DIG="$(jq -cS '.spec.template|.metadata.labels|=with_entries(select(.key!="pod-template-hash"))' <<<"$RS_ONE"|sha256sum|sed 's/[[:space:]].*$//')" || { RS_LOOKUP_FAILED=true; break; }
    [ "$RS_ONE_DIG" = "$EXPECTED_DIGEST" ] && MATCHING_RS+=("$RS_NAME")
  done
  if [ "$RS_LOOKUP_FAILED" = true ]; then
    printf '%s\n' '중단: active RS identity/digest 재조회 실패' >&2
  elif [ "${#MATCHING_RS[@]}" -ne 1 ]; then
    printf '미정상: owner·active·candidate digest RS 단일 후보 아님 count=%s\n' "${#MATCHING_RS[@]}" >&2
  else
    POST_RS="${MATCHING_RS[0]}"; RS_POST_ONE="$(kubectl get rs "$POST_RS" -n "$NS" -o json --request-timeout=15s)"; POST_RS_UID="$(jq -r '.metadata.uid' <<<"$RS_POST_ONE")"; POST_RS_DIG="$(jq -cS '.spec.template|.metadata.labels|=with_entries(select(.key!="pod-template-hash"))' <<<"$RS_POST_ONE"|sha256sum|sed 's/[[:space:]].*$//')"; POST_REV="$(jq -r '.metadata.annotations["deployment.kubernetes.io/revision"]//"-"' <<<"$RS_POST_ONE")"
    if [ "$POST_RS_DIG" != "$EXPECTED_DIGEST" ]; then
      printf '%s\n' '미정상: active RS template digest 불일치' >&2
    else
      POST_PODS="$(jq -c --arg u "$POST_RS_UID" --arg t "$MUTATION_AT" '[.items[]|select(any(.metadata.ownerReferences[]?;.controller==true and .uid==$u))|select(.metadata.creationTimestamp>=$t)|{name:.metadata.name,uid:.metadata.uid,rv:.metadata.resourceVersion,node:(.spec.nodeName//"-"),created:.metadata.creationTimestamp,ready:([.status.conditions[]?|select(.type=="Ready")][0].status//"False"),containers:([.status.initContainerStatuses[]?|{kind:"init",name,containerID:(.containerID//"-")}]+[.status.containerStatuses[]?|{kind:"regular",name,containerID:(.containerID//"-")}])}]' <<<"$P_POST")"; DEP_UID="$(jq -r '.metadata.uid' <<<"$D_POST")"; DEP_RV="$(jq -r '.metadata.resourceVersion' <<<"$D_POST")"; DEP_GEN="$(jq -r '.metadata.generation' <<<"$D_POST")"; SELECTOR="$S_POST"; TEMPLATE_DIGEST="$POST_DIG"; CURRENT_REVISION="$(jq -r '.metadata.annotations["deployment.kubernetes.io/revision"]//"-"' <<<"$D_POST")"; AUTO_READY=true; POST_READY=true; printf 'POST_READY=true deploymentUID=%s activeRS=%s uid=%s revision=%s digest=%s\nnewPods=%s\n' "$DEP_UID" "$POST_RS" "$POST_RS_UID" "$POST_REV" "$POST_RS_DIG" "$POST_PODS"
    fi
  fi
fi
```

```bash
NORMAL_READY=false
if [ "$POST_READY" != true ]; then
  printf '%s\n' '중단: POST_READY가 아니다.' >&2
elif ! D_NOW="$(kubectl get deployment "$DEP" -n "$NS" -o json --request-timeout=15s)" || [ "$(jq -r '.metadata.uid' <<<"$D_NOW")" != "$DEP_UID" ]; then
  printf '%s\n' '중단: 현재 Deployment UID 검증 실패' >&2
elif ! RS_NOW="$(kubectl get rs "$POST_RS" -n "$NS" -o json --request-timeout=15s)" || [ "$(jq -r '.metadata.uid' <<<"$RS_NOW")" != "$POST_RS_UID" ]; then
  printf '%s\n' '중단: 현재 active RS UID 검증 실패' >&2
elif [ "$(jq -r '.metadata.generation==(.status.observedGeneration//0) and (.spec.replicas//1)==(.status.updatedReplicas//0) and (.spec.replicas//1)==(.status.readyReplicas//0) and (.spec.replicas//1)==(.status.availableReplicas//0)' <<<"$D_NOW")" != true ]; then
  printf '%s\n' '미정상: Deployment replica 수렴 실패' >&2
elif [ "$(jq 'length' <<<"$POST_PODS")" -ne "$(jq -r '.spec.replicas//1' <<<"$D_NOW")" ]; then
  printf '%s\n' '미정상: mutation 이후 current owner Pod 재등록 수가 desired와 다르다.' >&2
elif [ "$(jq '[.[]|select(.ready!="True" or ([.containers[].containerID]|any(.=="-")))]|length' <<<"$POST_PODS")" -ne 0 ]; then
  printf '%s\n' '미정상: 새 Pod Ready/current containerID 불충족' >&2
else
  NORMAL_READY=true
  printf 'NORMAL_READY=true deploymentUID=%s activeRSUID=%s observedAt=%s\n' "$DEP_UID" "$POST_RS_UID" "$(date -u '+%Y-%m-%dT%H:%M:%SZ')"

```

`NORMAL_READY=true`는 객체 수렴만 뜻한다. Service를 사용하면 service port·targetPort·EndpointSlice port와 endpoint `targetRef.uid`가 위 새 Pod UID 집합에 연결되는지 확인하고, 승인된 실제 요청·핵심 기능, 오류율·지연, 동일 Warning·restart 재발 없음이 승인 관찰 창을 통과해야 정상화한다.


metric·label 미지원, 빈 결과, stale series를 정상으로 해석하지 않는다. PromQL은 owner UID, revision, template digest, 실제 기능을 증명하지 않는다.

## 증거와 관련 문서
