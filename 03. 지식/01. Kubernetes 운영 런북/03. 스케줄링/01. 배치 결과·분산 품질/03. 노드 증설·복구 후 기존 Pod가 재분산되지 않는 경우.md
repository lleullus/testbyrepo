# 노드 증설·복구 후 기존 Pod가 재분산되지 않는 경우

## 입력값과 빠른 수집

Kubernetes 1.26의 기본 scheduler는 아직 node에 bind되지 않은 Pod를 배치한다. 새 Node가 생겼다는 이유만으로 이미 bind된 Pod를 이동시키지 않으므로, 이 런북은 "이동하지 않음"과 "선언된 분산 정책 위반"을 분리한다.

| 구분 | 값 | 확정 기준 |
|---|---|---|
| 최초 입력 | `NS`, 대표 `POD`, 증설·복구된 `TARGET_NODE` | 운영자가 승인된 대상 이름을 한 번만 입력 |
| API 자동값 | Pod/Node UID·resourceVersion, immediate owner와 selector, 현재 node, containerID, 생성 시각 | exact-name API와 owner 관계가 모두 일치 |
| 계산 후보 | `POD_RE`, owner selector의 현재 matching Pod 집합 | regex escape 및 selector API 조회 성공 전 미확정 |
| 운영자 선택 | 증거 시간 창, 의도한 분산 기준, 변경 승인 경로 | 변경 기록·SLO·PDB·quorum 확인 후 선택 |

실행 host는 승인된 kubeconfig를 가진 작업 PC 또는 bastion이며 모든 명령을 같은 Bash에서 실행한다. hop은 `작업 host의 kubectl → API server → Pod·owner·Node 객체`이고, 이 문서에는 SSH·exec·CRI 경로가 없다.

**도구 gate**

`TOOLS_READY=false; MISSING=''; for T in kubectl jq date hostname sed tr; do command -v "$T" >/dev/null 2>&1 || MISSING="$MISSING $T"; done; if [ -n "${BASH_VERSION:-}" ] && [ -z "$MISSING" ]; then TOOLS_READY=true; printf 'TOOLS_READY=true host=%s\n' "$(hostname -f)"; else printf '중단: Bash 또는 도구 누락:%s\n' "$MISSING" >&2; fi`

**최초 입력과 모든 파생 상태 폐기**

`unset INPUT_READY AUTO_READY WINDOW_READY EVIDENCE_READY CHANGE_READY REPLACEMENT_READY NORMAL_READY POD_UID POD_RV OWNER_KIND OWNER_RESOURCE OWNER_NAME OWNER_UID OWNER_SELECTOR POD_NODE NODE_UID NODE_RV CONTAINER_IDS HOST_ID RELATION COLLECT_RFC3339 POD_RE ARGV_RE START_RFC3339 END_RFC3339 START_EPOCH END_EPOCH INTENDED_DISTRIBUTION APPROVAL_ID NEW_POD NEW_POD_UID NEW_POD_RV NEW_NODE NEW_CREATED; NS='PASTE_REBALANCE_NAMESPACE_HERE'; POD='PASTE_REBALANCE_POD_HERE'; TARGET_NODE='PASTE_REBALANCE_TARGET_NODE_HERE'; INPUT_READY=false; if [ "$TOOLS_READY" != true ]; then printf '%s\n' '중단: TOOLS_READY가 아니다.' >&2; elif [ -z "$NS" ] || [ -z "$POD" ] || [ -z "$TARGET_NODE" ]; then printf '%s\n' '중단: 최초 입력이 비었다.' >&2; elif kubectl get pod "$POD" -n "$NS" >/dev/null 2>&1 && kubectl get node "$TARGET_NODE" >/dev/null 2>&1; then INPUT_READY=true; export NS POD TARGET_NODE; printf 'INPUT_READY=true ns=%s pod=%s target_node=%s\n' "$NS" "$POD" "$TARGET_NODE"; else printf '%s\n' '중단: exact-name Pod 또는 Node 조회 실패' >&2; fi`

재수집 명령은 시작할 때 UID·resourceVersion·owner·containerID·node·host·관계·time·argv-regex와 모든 downstream `READY`를 다시 폐기한다. 실패 경로는 어떤 READY도 `true`로 남기지 않는다.

**API 자동 등록**

`unset POD_NODE_IDENTITY_READY POD_NODE_UID CHANGE_TIME_READY CHANGE_RFC3339 CHANGE_EPOCH CHANGE_GATE_APPROVAL NEW_NODE_UID; POD_NODE_IDENTITY_READY=false; CHANGE_TIME_READY=false`

`unset AUTO_READY WINDOW_READY EVIDENCE_READY CHANGE_READY REPLACEMENT_READY NORMAL_READY POD_UID POD_RV OWNER_KIND OWNER_RESOURCE OWNER_NAME OWNER_UID OWNER_SELECTOR POD_NODE NODE_UID NODE_RV CONTAINER_IDS HOST_ID RELATION COLLECT_RFC3339 POD_RE ARGV_RE; AUTO_READY=false; if [ "$INPUT_READY" != true ]; then printf '%s\n' '중단: INPUT_READY가 아니다.' >&2; elif PJSON="$(kubectl get pod "$POD" -n "$NS" -o json)" && NJSON="$(kubectl get node "$TARGET_NODE" -o json)"; then OWNER_KIND="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)][0].kind // empty' <<<"$PJSON")"; OWNER_NAME="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)][0].name // empty' <<<"$PJSON")"; OWNER_UID="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)][0].uid // empty' <<<"$PJSON")"; OWNER_RESOURCE="$(printf '%s' "$OWNER_KIND" | tr '[:upper:]' '[:lower:]')"; if [ -z "$OWNER_UID" ] || ! OJSON="$(kubectl get "$OWNER_RESOURCE" "$OWNER_NAME" -n "$NS" -o json)" || [ "$(jq -r '.metadata.uid' <<<"$OJSON")" != "$OWNER_UID" ]; then printf '%s\n' '중단: controller owner exact relation 검증 실패' >&2; else OWNER_SELECTOR="$(jq -r '(.spec.selector.matchLabels // {}) | to_entries | map("\(.key)=\(.value)") | join(",")' <<<"$OJSON")"; POD_UID="$(jq -r '.metadata.uid' <<<"$PJSON")"; POD_RV="$(jq -r '.metadata.resourceVersion' <<<"$PJSON")"; POD_NODE="$(jq -r '.spec.nodeName // empty' <<<"$PJSON")"; CONTAINER_IDS="$(jq -r '[.status.containerStatuses[]?.containerID // empty] | sort | join(",")' <<<"$PJSON")"; NODE_UID="$(jq -r '.metadata.uid' <<<"$NJSON")"; NODE_RV="$(jq -r '.metadata.resourceVersion' <<<"$NJSON")"; HOST_ID="$(hostname -f)"; COLLECT_RFC3339="$(date -u '+%Y-%m-%dT%H:%M:%SZ')"; POD_RE="^$(printf '%s' "$POD" | sed 's/[][\\.^$*+?(){}|]/\\&/g')$"; ARGV_RE="$POD_RE"; RELATION="Pod/$POD[$POD_UID] -> $OWNER_KIND/$OWNER_NAME[$OWNER_UID] on Node/$POD_NODE"; if [ -n "$POD_UID" ] && [ -n "$POD_RV" ] && [ -n "$POD_NODE" ] && [ -n "$NODE_UID" ] && [ -n "$OWNER_SELECTOR" ]; then AUTO_READY=true; export POD_UID POD_RV OWNER_KIND OWNER_RESOURCE OWNER_NAME OWNER_UID OWNER_SELECTOR POD_NODE NODE_UID NODE_RV CONTAINER_IDS HOST_ID RELATION COLLECT_RFC3339 POD_RE ARGV_RE; printf 'AUTO_READY=true\n관계=%s\nowner_selector=%s\ntarget_node_uid=%s\ncontainer_ids=%s\n수집시각=%s\nhost=%s\n' "$RELATION" "$OWNER_SELECTOR" "$NODE_UID" "${CONTAINER_IDS:--}" "$COLLECT_RFC3339" "$HOST_ID"; else printf '%s\n' '중단: 자동값이 비었음' >&2; fi; fi; else printf '%s\n' '중단: Pod 또는 Node API 조회 실패' >&2; fi`

`containerID`가 비어 있으면 실행 중 container identity를 확인할 수 없으므로 replacement나 서비스 정상화 판단을 보류한다. owner selector는 `matchLabels`가 있는 controller에만 자동화한다. `matchExpressions`가 있거나 selector가 비면 임의 문자열로 축약하지 않고 workload owner에게 정확한 selector 확인을 이관한다.

**fresh identity 함수 등록**

`fresh_target(){ local p n uid owner_uid node cids host; [ "$AUTO_READY" = true ] || return 1; host="$(hostname -f)" || return 1; [ "$host" = "$HOST_ID" ] || { printf '%s\n' '중단: 실행 host 변경' >&2; return 1; }; p="$(kubectl get pod "$POD" -n "$NS" -o json)" || return 1; n="$(kubectl get node "$TARGET_NODE" -o json)" || return 1; uid="$(jq -r '.metadata.uid' <<<"$p")"; owner_uid="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)][0].uid // empty' <<<"$p")"; node="$(jq -r '.spec.nodeName // empty' <<<"$p")"; cids="$(jq -r '[.status.containerStatuses[]?.containerID // empty] | sort | join(",")' <<<"$p")"; if [ "$uid" != "$POD_UID" ] || [ "$owner_uid" != "$OWNER_UID" ] || [ "$node" != "$POD_NODE" ] || [ "$cids" != "$CONTAINER_IDS" ] || [ "$(jq -r '.metadata.uid' <<<"$n")" != "$NODE_UID" ]; then printf '%s\n' '중단: UID/owner/containerID/node 관계가 바뀜; 전체 재수집 필요' >&2; return 1; fi; POD_RV="$(jq -r '.metadata.resourceVersion' <<<"$p")"; NODE_RV="$(jq -r '.metadata.resourceVersion' <<<"$n")"; export POD_RV NODE_RV; }`

위 함수는 Pod의 owner reference만 확인하므로, 먼저 Pod가 실제 bind된 Node UID를 등록하고 이후 명령에는 current controller 객체 UID와 양쪽 Node UID까지 확인하는 아래 정의를 사용한다.

`unset POD_NODE_IDENTITY_READY POD_NODE_UID; POD_NODE_IDENTITY_READY=false; if [ "$AUTO_READY" != true ] || [ -z "$POD_NODE" ]; then printf '%s\n' '중단: bound Pod AUTO_READY 필요' >&2; elif PNJSON="$(kubectl get node "$POD_NODE" -o json)"; then POD_NODE_UID="$(jq -r '.metadata.uid' <<<"$PNJSON")"; POD_NODE_IDENTITY_READY=true; export POD_NODE_UID; printf 'POD_NODE_IDENTITY_READY=true node=%s uid=%s\n' "$POD_NODE" "$POD_NODE_UID"; else printf '%s\n' '중단: Pod의 current Node 조회 실패' >&2; fi`

`fresh_target(){ local p n pn o uid owner_uid node cids host; [ "$AUTO_READY" = true ] && [ "$POD_NODE_IDENTITY_READY" = true ] || return 1; host="$(hostname -f)" || return 1; [ "$host" = "$HOST_ID" ] || { printf '%s\n' '중단: 실행 host 변경' >&2; return 1; }; p="$(kubectl get pod "$POD" -n "$NS" -o json)" || return 1; n="$(kubectl get node "$TARGET_NODE" -o json)" || return 1; pn="$(kubectl get node "$POD_NODE" -o json)" || return 1; o="$(kubectl get "$OWNER_RESOURCE" "$OWNER_NAME" -n "$NS" -o json)" || return 1; uid="$(jq -r '.metadata.uid' <<<"$p")"; owner_uid="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)][0].uid // empty' <<<"$p")"; node="$(jq -r '.spec.nodeName // empty' <<<"$p")"; cids="$(jq -r '[.status.containerStatuses[]?.containerID // empty] | sort | join(",")' <<<"$p")"; if [ "$uid" != "$POD_UID" ] || [ "$owner_uid" != "$OWNER_UID" ] || [ "$(jq -r '.metadata.uid' <<<"$o")" != "$OWNER_UID" ] || [ "$node" != "$POD_NODE" ] || [ "$cids" != "$CONTAINER_IDS" ] || [ "$(jq -r '.metadata.uid' <<<"$n")" != "$NODE_UID" ] || [ "$(jq -r '.metadata.uid' <<<"$pn")" != "$POD_NODE_UID" ]; then printf '%s\n' '중단: UID/current owner/containerID/node 관계가 바뀜; 전체 재수집 필요' >&2; return 1; fi; POD_RV="$(jq -r '.metadata.resourceVersion' <<<"$p")"; NODE_RV="$(jq -r '.metadata.resourceVersion' <<<"$n")"; export POD_RV NODE_RV; }`

### 시간 창 선택과 검증

`START_RFC3339='PASTE_REBALANCE_START_UTC_HERE'; END_RFC3339='PASTE_REBALANCE_END_UTC_HERE'; WINDOW_READY=false; RFC3339_RE='^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$'; if [ "$AUTO_READY" != true ] || ! fresh_target; then printf '%s\n' '중단: fresh target gate 실패' >&2; elif [[ ! "$START_RFC3339" =~ $RFC3339_RE ]] || [[ ! "$END_RFC3339" =~ $RFC3339_RE ]]; then printf '%s\n' '중단: canonical UTC RFC3339 형식 필요' >&2; elif START_EPOCH="$(date -u -d "$START_RFC3339" +%s 2>/dev/null)" && END_EPOCH="$(date -u -d "$END_RFC3339" +%s 2>/dev/null)" && [ "$(date -u -d "@$START_EPOCH" '+%Y-%m-%dT%H:%M:%SZ')" = "$START_RFC3339" ] && [ "$(date -u -d "@$END_EPOCH" '+%Y-%m-%dT%H:%M:%SZ')" = "$END_RFC3339" ] && [ "$START_EPOCH" -lt "$END_EPOCH" ] && [ "$END_EPOCH" -le "$(date -u +%s)" ]; then WINDOW_READY=true; export START_RFC3339 END_RFC3339 START_EPOCH END_EPOCH; printf 'WINDOW_READY=true start=%s end=%s\n' "$START_RFC3339" "$END_RFC3339"; else printf '%s\n' '중단: round-trip/start<end/미래 상한 검증 실패' >&2; fi`

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | `TARGET_NODE`가 `Ready=True`이고 기존 Pod 분포가 그대로인 경우 |
| 적용 | owner selector·UID 관계, 현재 Pod node, required/preferred·topology 정책과 의도한 분산 기준을 대조할 수 있는 경우 |
| 제외 | 새 Pod의 `FailedScheduling`은 [[18. Pod 이벤트에 FailedScheduling이 기록된 경우]], Node가 `Ready=False/Unknown`이면 Node 상태 런북, controller 수렴 실패는 해당 Deployment·StatefulSet·DaemonSet 런북으로 이동 |

검색 문자열: `PodScheduled`, `nodeName`, `topologySpreadConstraints`, `podAntiAffinity`, `FailedScheduling`, `numberMisscheduled`, `descheduler`.

## 관측별 진단 경로

| 지금 보이는 것 | 먼저 볼 것 | 그다음 어디를 볼지 | 상세 절 |
|---|---|---|---|
| 모든 기존 Pod가 bound 상태 | Pod UID·node·생성 시각 | 자동 재균형 기대를 제거하고 선언 정책 평가 | [[#읽기 전용 진단|읽기 전용 진단]] |
| target Node가 후보가 아님 | Ready·unschedulable·taint·label | Node 또는 placement owner | [[#읽기 전용 진단|읽기 전용 진단]] |
| 새 replacement만 Pending | 같은 새 Pod UID의 Event | FailedScheduling 런북 | [[18. Pod 이벤트에 FailedScheduling이 기록된 경우]] |
| 분포 기준 자체가 없음 | owner 정책·SLO·변경 기록 부재 | 임의 균형을 만들지 않고 workload owner | [[#상태 변경 경계|상태 변경 경계]] |

## 읽기 전용 진단

**현재 Pod 집합과 owner 관계**

`EVIDENCE_READY=false; if [ "$WINDOW_READY" != true ] || ! fresh_target; then printf '%s\n' '중단: 최신 gate 실패' >&2; elif PODS_JSON="$(kubectl get pods -n "$NS" -l "$OWNER_SELECTOR" -o json)" && OJSON="$(kubectl get "$OWNER_RESOURCE" "$OWNER_NAME" -n "$NS" -o json)"; then jq -r --arg ouid "$OWNER_UID" '.items | sort_by(.metadata.name)[] | "=== Pod: \(.metadata.name) ===\nUID: \(.metadata.uid)\nOwner UID: \([.metadata.ownerReferences[]? | select(.controller==true)][0].uid // "-")\nNode: \(.spec.nodeName // "-")\nPhase/Ready: \(.status.phase // "-")/\([.status.containerStatuses[]?.ready] | join(","))\n생성: \(.metadata.creationTimestamp)"' <<<"$PODS_JSON"; printf '%s\n' '=== Placement 선언 ==='; jq '{generation:.metadata.generation,resourceVersion:.metadata.resourceVersion,nodeSelector:.spec.template.spec.nodeSelector,nodeAffinity:.spec.template.spec.affinity.nodeAffinity,podAntiAffinity:.spec.template.spec.affinity.podAntiAffinity,topologySpreadConstraints:.spec.template.spec.topologySpreadConstraints}' <<<"$OJSON"; if jq -e --arg ouid "$OWNER_UID" 'all(.items[]; any(.metadata.ownerReferences[]?; .uid==$ouid)) and (.items|length)>0' <<<"$PODS_JSON" >/dev/null; then EVIDENCE_READY=true; printf 'EVIDENCE_READY=true pod_count=%s window=%s..%s\n' "$(jq '.items|length' <<<"$PODS_JSON")" "$START_RFC3339" "$END_RFC3339"; else printf '%s\n' '중단: selector 결과에 다른 owner 또는 빈 집합' >&2; fi; else printf '%s\n' '중단: owner/Pod 조회 실패' >&2; fi`

**증설·복구 Node 후보성**

`if [ "$EVIDENCE_READY" != true ] || ! fresh_target; then printf '%s\n' '중단: 최신 evidence gate 실패' >&2; elif NJSON="$(kubectl get node "$TARGET_NODE" -o json)"; then jq '{name:.metadata.name,uid:.metadata.uid,resourceVersion:.metadata.resourceVersion,created:.metadata.creationTimestamp,ready:[.status.conditions[]?|select(.type=="Ready")|{status,reason,lastTransitionTime}],unschedulable:(.spec.unschedulable//false),taints:(.spec.taints//[]),allocatable:.status.allocatable,topologyLabels:(.metadata.labels|with_entries(select(.key|test("^(kubernetes.io/hostname|topology.kubernetes.io/)") )))}' <<<"$NJSON"; else printf '%s\n' '중단: Node 조회 실패' >&2; fi`

`Ready=True`는 모든 workload의 후보임을 보장하지 않는다. required node affinity, taint/toleration, topology domain, allocatable과 Pod capacity가 모두 맞아야 한다. 기존 Pod가 그대로인 것은 scheduler failure가 아니다.

**UID 제한 Event와 evidence window**

`if [ "$EVIDENCE_READY" != true ] || ! fresh_target; then printf '%s\n' '중단: 최신 evidence gate 실패' >&2; elif EVENTS_JSON="$(kubectl get events -n "$NS" --field-selector "involvedObject.kind=Pod,involvedObject.name=$POD,involvedObject.uid=$POD_UID" -o json)"; then jq -r --argjson s "$START_EPOCH" --argjson e "$END_EPOCH" '.items[] | (.eventTime // .series.lastObservedTime // .lastTimestamp // .firstTimestamp) as $raw | ($raw | strings | sub("\\.[0-9]+Z$";"Z") | fromdateiso8601?) as $t | select($t!=null and $t >= $s and $t <= $e) | [.reason,(.count//1),$raw,.message] | @tsv' <<<"$EVENTS_JSON"; else printf '%s\n' '중단: Event producer 실패; filter를 실행하지 않음' >&2; fi`

producer인 `kubectl`과 filter인 `jq`의 성공을 분리했다. 빈 filter 결과는 Event 부재일 수 있지만 권한/API 실패와 같지 않으며, 분산 정상의 단독 근거도 아니다.

## 상태 변경 경계

진단 중 `rollout restart`, Pod `delete`, `drain`, label·taint·affinity 변경 또는 descheduler 설치·실행을 제공하지 않는다. 변경은 다음이 모두 참일 때 기존 controller/GitOps 절차로만 수행한다.

- fresh Pod/owner/Node identity와 `EVIDENCE_READY=true`가 유지된다.
- 의도한 분산 기준 `INTENDED_DISTRIBUTION`, 승인 ID, 변경 창, PDB·quorum·Ready 여유, EndpointSlice와 실제 요청 baseline이 있다.
- 교체는 멱등하지 않을 수 있고 이미 축출된 Pod는 되돌릴 수 없음을 승인자가 이해한다.
- rollback은 검증된 이전 선언 revision으로만 하며, 새 Pending·Ready 감소·PDB 위반·서비스 오류가 보이면 중단한다.

**변경 기록 gate**

`INTENDED_DISTRIBUTION='PASTE_REBALANCE_APPROVED_POLICY_HERE'; APPROVAL_ID='PASTE_REBALANCE_APPROVAL_ID_HERE'; CHANGE_READY=false; if [ "$EVIDENCE_READY" != true ] || ! fresh_target; then printf '%s\n' '중단: fresh evidence가 아니다.' >&2; elif [ -z "$INTENDED_DISTRIBUTION" ] || [ -z "$APPROVAL_ID" ]; then printf '%s\n' '중단: 승인된 정책/승인 ID가 비었다.' >&2; else CHANGE_READY=true; export INTENDED_DISTRIBUTION APPROVAL_ID; printf 'CHANGE_READY=true owner=%s/%s approval=%s window=%s..%s\n' "$OWNER_KIND" "$OWNER_NAME" "$APPROVAL_ID" "$START_RFC3339" "$END_RFC3339"; fi`

이 gate는 변경을 실행하지 않는다. 승인된 외부 절차의 fresh target/evidence/approval/window/quorum/idempotence/rollback 확인 기록이다. 승인 ID는 변경 시도마다 고유해야 한다.

**승인 변경 시각 gate**

`CHANGE_RFC3339='PASTE_REBALANCE_CHANGE_UTC_HERE'; unset CHANGE_TIME_READY CHANGE_EPOCH CHANGE_GATE_APPROVAL REPLACEMENT_READY NORMAL_READY; CHANGE_TIME_READY=false; RFC3339_RE='^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$'; if [ "$CHANGE_READY" != true ] || ! fresh_target; then printf '%s\n' '중단: fresh change gate 실패' >&2; elif [[ ! "$CHANGE_RFC3339" =~ $RFC3339_RE ]] || ! CHANGE_EPOCH="$(date -u -d "$CHANGE_RFC3339" +%s 2>/dev/null)" || [ "$(date -u -d "@$CHANGE_EPOCH" '+%Y-%m-%dT%H:%M:%SZ')" != "$CHANGE_RFC3339" ] || [ "$CHANGE_EPOCH" -lt "$END_EPOCH" ] || [ "$CHANGE_EPOCH" -gt "$(date -u +%s)" ]; then printf '%s\n' '중단: 변경 시각 canonical/round-trip/evidence 이후 조건 실패' >&2; else CHANGE_GATE_APPROVAL="$APPROVAL_ID"; CHANGE_TIME_READY=true; export CHANGE_RFC3339 CHANGE_EPOCH CHANGE_GATE_APPROVAL; printf 'CHANGE_TIME_READY=true approval=%s change=%s\n' "$CHANGE_GATE_APPROVAL" "$CHANGE_RFC3339"; fi`

## replacement 재등록과 정상화

교체 후 과거 Pod 변수와 READY를 성공 근거로 사용하지 않는다. 승인된 controller 결과에서 확인한 새 Pod 이름만 입력하고, selector 결과 중 해당 이름이 정확히 한 개이며 owner·creation time이 변경 이후인지 검증한다.

`NEW_POD='PASTE_REBALANCE_REPLACEMENT_POD_HERE'; unset REPLACEMENT_READY NORMAL_READY NEW_POD_UID NEW_POD_RV NEW_NODE NEW_NODE_UID NEW_CREATED; REPLACEMENT_READY=false; printf 'replacement 입력 등록 pod=%s; 최종 gate 전 READY 아님\n' "$NEW_POD"`

위 command는 이름만 입력하고 READY를 만들지 않는다. 다음 명령이 current owner, 승인 ID, 실제 변경 시각과 새 Node UID를 확인한 결과만 최종 등록값으로 사용한다.

`REPLACEMENT_READY=false; unset NEW_NODE_UID; if [ "$CHANGE_TIME_READY" != true ] || [ "$CHANGE_GATE_APPROVAL" != "$APPROVAL_ID" ]; then printf '%s\n' '중단: current change-time/approval gate 실패' >&2; elif CANDIDATES="$(kubectl get pods -n "$NS" -l "$OWNER_SELECTOR" -o json)" && OJSON="$(kubectl get "$OWNER_RESOURCE" "$OWNER_NAME" -n "$NS" -o json)" && [ "$(jq --arg p "$NEW_POD" '[.items[]|select(.metadata.name==$p)]|length' <<<"$CANDIDATES")" -eq 1 ]; then NP="$(jq -c --arg p "$NEW_POD" '.items[]|select(.metadata.name==$p)' <<<"$CANDIDATES")"; NEW_NODE="$(jq -r '.spec.nodeName//empty' <<<"$NP")"; if [ -n "$NEW_NODE" ] && NJSON="$(kubectl get node "$NEW_NODE" -o json)"; then NEW_POD_UID="$(jq -r '.metadata.uid' <<<"$NP")"; NEW_POD_RV="$(jq -r '.metadata.resourceVersion' <<<"$NP")"; NEW_CREATED="$(jq -r '.metadata.creationTimestamp' <<<"$NP")"; NEW_NODE_UID="$(jq -r '.metadata.uid' <<<"$NJSON")"; if [ "$(jq -r '.metadata.uid' <<<"$OJSON")" = "$OWNER_UID" ] && [ "$(jq -r '[.metadata.ownerReferences[]?|select(.controller==true)][0].uid//empty' <<<"$NP")" = "$OWNER_UID" ] && [ "$(date -u -d "$NEW_CREATED" +%s)" -ge "$CHANGE_EPOCH" ]; then REPLACEMENT_READY=true; export NEW_POD NEW_POD_UID NEW_POD_RV NEW_NODE NEW_NODE_UID NEW_CREATED; printf 'REPLACEMENT_READY=true pod=%s uid=%s node=%s[%s] created=%s\n' "$NEW_POD" "$NEW_POD_UID" "$NEW_NODE" "$NEW_NODE_UID" "$NEW_CREATED"; else printf '%s\n' '중단: current owner/node/change-time relation 불일치' >&2; fi; else printf '%s\n' '중단: replacement Node 조회 실패' >&2; fi; else printf '%s\n' '중단: replacement/current owner producer 실패' >&2; fi`

**최종 current identity·container gate**

`NORMAL_READY=false; if [ "$REPLACEMENT_READY" != true ] || ! NP="$(kubectl get pod "$NEW_POD" -n "$NS" -o json)" || ! NN="$(kubectl get node "$NEW_NODE" -o json)" || ! OO="$(kubectl get "$OWNER_RESOURCE" "$OWNER_NAME" -n "$NS" -o json)"; then printf '%s\n' '중단: 정상화 producer 실패' >&2; elif [ "$(jq -r '.metadata.uid' <<<"$NP")" != "$NEW_POD_UID" ] || [ "$(jq -r '.metadata.uid' <<<"$NN")" != "$NEW_NODE_UID" ] || [ "$(jq -r '.metadata.uid' <<<"$OO")" != "$OWNER_UID" ] || [ "$(jq -r '[.metadata.ownerReferences[]?|select(.controller==true)][0].uid//empty' <<<"$NP")" != "$OWNER_UID" ]; then printf '%s\n' '중단: replacement current identity 불일치' >&2; elif [ "$(jq -r '.status.phase' <<<"$NP")" = Running ] && jq -e '(.status.containerStatuses|length)>0 and all(.status.containerStatuses[];.ready==true and (.containerID//"")!="")' <<<"$NP" >/dev/null; then NORMAL_READY=true; printf 'NORMAL_READY=true pod=%s[%s] node=%s[%s] containerIDs=%s\n' "$NEW_POD" "$NEW_POD_UID" "$NEW_NODE" "$NEW_NODE_UID" "$(jq -r '[.status.containerStatuses[].containerID]|sort|join(",")' <<<"$NP")"; else printf '%s\n' '중단: replacement container identity/Running/Ready 미수렴' >&2; fi`

`NORMAL_READY=true` 뒤에도 owner desired/ready/available, 선언된 topology 분포, 새 Warning 부재, EndpointSlice의 새 Pod endpoint와 실제 요청·핵심 기능을 같은 관찰 창에서 확인해야 한다. 균등해 보이는 count나 Pod `Running`만으로 정상화하지 않는다.

## Prometheus 빠른 관측

다음은 kube-state-metrics가 해당 metric과 label을 실제 노출할 때만 사용한다. 생성 명령의 출력만 Prometheus/Grafana에 붙인다.

`if [ "$EVIDENCE_READY" != true ] || ! fresh_target; then printf '%s\n' '중단: 최신 evidence gate 실패' >&2; else printf 'kube_pod_info{namespace="%s",pod="%s",uid="%s"}\n' "$NS" "$POD" "$POD_UID"; printf 'kube_node_status_condition{node="%s",condition="Ready",status="true"} == 1\n' "$TARGET_NODE"; fi`

결과가 비면 0이나 정상으로 해석하지 않는다. metric 부재, kube-state-metrics label allowlist, cluster/namespace 범위, scrape 실패를 먼저 구분한다. 이 질의는 descheduler 정책, PDB·quorum 또는 기존 Pod 자동 이동을 증명하지 않는다.

## 증거 보존과 완료 기준

UTC window, 실행 host, Pod/owner/Node UID·resourceVersion·관계·containerID·생성 시각, owner selector와 matching 집합, placement 선언, Node Ready·taint·label·allocatable, UID 제한 Event, 승인·rollback, replacement 단일 후보와 실제 서비스 결과를 보존한다. Secret·token·인증서 개인키·전체 annotation·불필요한 전체 로그는 저장하지 않는다.

환경별 미검증: descheduler 설치·정책, scheduler profile, admission 변경, node pool 구현, PDB/quorum 규칙과 서비스 endpoint는 실제 환경에서 검증되지 않았다. 이 문서 작성 중 실제 인프라 명령은 실행하지 않았다.
