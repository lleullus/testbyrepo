# Pod가 특정 topology domain에 과도하게 집중된 경우

## 입력값과 빠른 수집

승인된 작업 PC 또는 bastion의 같은 Bash에서 실행한다. 경로는 `대상 Pod UID → 직접 owner → 상위 controller UID·selector → matching Pod UID/node → Node UID/topology label → constraint/eligible domain → 실제 서비스 기능`이다. scheduler는 이미 bind된 Pod를 사후 재분산하지 않는다.

| 구분 | 값 | gate |
|---|---|---|
| 최초 입력 | `NS`, `TARGET_POD` | exact-name Pod 조회 |
| API 자동값 | Pod/Node UID·resourceVersion, direct owner, root controller UID·selector, spec digest | owner chain을 최대 한 단계 검증해 등록 |
| 계산 후보 | current root controller에 속한 Pod와 topology domain 분포 | selector 결과를 owner chain으로 다시 필터 |
| 운영자 선택 | `TOPOLOGY_KEY` | key 형식과 대상 Node의 현재 label 존재를 검증 |

재등록 전에 Pod/owner/root/Node UID·resourceVersion·containerID·관계·시간과 downstream `READY`를 모두 버린다. 이름만 같은 재생성 Pod·controller·Node에는 이전 분포를 연결하지 않는다.

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | bind된 동일 controller Pod가 zone/hostname/custom domain 한 곳에 과도하게 모인다. |
| 적용 | current root controller와 실제 topology constraint의 계산 모집단을 확정할 수 있다. |
| 제외 | Pending/FailedScheduling은 [[18. Pod 이벤트에 FailedScheduling이 기록된 경우]], preferred affinity가 주 증상이면 [[02. Pod affinity·anti-affinity의 선호 배치 결과가 기대와 다른 경우]]로 이동한다. |

검색 문자열: `topologySpreadConstraints`, `topologyKey`, `maxSkew`, `DoNotSchedule`, `ScheduleAnyway`, `labelSelector`, `deletionTimestamp`.

## current controller snapshot

후보 selector 결과의 각 Pod direct owner를 확인한다. root가 direct owner이면 UID가 직접 같아야 하고, ReplicaSet 같은 중간 owner가 있으면 그 owner의 현재 controller UID가 root UID와 같아야 한다. API producer 실패 시 부분 모집단을 사용하지 않는다.

`unset SNAPSHOT_READY SNAPSHOT_JSON; SNAPSHOT_READY=false; if [ "$AUTO_READY" != true ]; then printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; elif ROOT_NOW="$(kubectl get "$ROOT_KIND" "$ROOT_NAME" -n "$NS" -o json)" && POD_NOW="$(kubectl get pod "$TARGET_POD" -n "$NS" -o json)" && [ "$(jq -r '.metadata.uid' <<<"$ROOT_NOW")" = "$ROOT_UID" ] && [ "$(jq -r '.metadata.uid' <<<"$POD_NOW")" = "$POD_UID" ]; then if CAND_JSON="$(kubectl get pods -n "$NS" -l "$ROOT_SELECTOR" -o json)" && NODES_JSON="$(kubectl get nodes -o json)"; then mapfile -t CAND_NAMES < <(jq -r '.items[].metadata.name' <<<"$CAND_JSON"); OWNED='[]'; RELATION_FAILED=false; for P in "${CAND_NAMES[@]}"; do if ! PJ="$(kubectl get pod "$P" -n "$NS" -o json)"; then RELATION_FAILED=true; break; fi; DK="$(jq -r '[.metadata.ownerReferences[]?|select(.controller==true)][0].kind//empty' <<<"$PJ")"; DN="$(jq -r '[.metadata.ownerReferences[]?|select(.controller==true)][0].name//empty' <<<"$PJ")"; DU="$(jq -r '[.metadata.ownerReferences[]?|select(.controller==true)][0].uid//empty' <<<"$PJ")"; BELONGS=false; if [ "$DU" = "$ROOT_UID" ]; then BELONGS=true; elif [ -n "$DK" ] && [ -n "$DN" ] && OJ="$(kubectl get "$DK" "$DN" -n "$NS" -o json)" && [ "$(jq -r '.metadata.uid' <<<"$OJ")" = "$DU" ] && [ "$(jq -r '[.metadata.ownerReferences[]?|select(.controller==true and .uid==$uid)]|length' --arg uid "$ROOT_UID" <<<"$OJ")" -eq 1 ]; then BELONGS=true; fi; if [ "$BELONGS" = true ]; then OWNED="$(jq -c --argjson p "$PJ" '.+[$p]' <<<"$OWNED")" || { RELATION_FAILED=true; break; }; fi; done; if [ "$RELATION_FAILED" = true ]; then printf '%s\n' '중단: 후보 owner relation producer/filter 실패' >&2; elif [ "$(jq 'length' <<<"$OWNED")" -eq 0 ]; then printf '%s\n' '중단: current root controller Pod 0건' >&2; else SNAPSHOT_JSON="$(jq -n --argjson root "$ROOT_NOW" --argjson pods "$OWNED" --argjson nodes "$NODES_JSON" --arg at "$(date -u +%Y-%m-%dT%H:%M:%SZ)" '{observedAt:$at,root:$root,pods:$pods,nodes:$nodes.items}')"; SNAPSHOT_READY=true; jq -r '"SNAPSHOT_READY=true observedAt=\(.observedAt) root=\(.root.kind)/\(.root.metadata.name)/\(.root.metadata.uid)",(.pods[]|"=== Pod: \(.metadata.name) ===\nUID: \(.metadata.uid) directOwnerUID: \([.metadata.ownerReferences[]|select(.controller==true)][0].uid)\nNode: \(.spec.nodeName) phase: \(.status.phase) ready: \([.status.containerStatuses[]?.ready])\ncreated: \(.metadata.creationTimestamp) deletion: \(.metadata.deletionTimestamp)")' <<<"$SNAPSHOT_JSON"; fi; else printf '%s\n' '중단: Pod/Node API producer 실패' >&2; fi; else AUTO_READY=false; printf '%s\n' '중단: target/root identity drift' >&2; fi`

## 관측별 진단 경로

| 관측 | 직접 증거 | 판정 |
|---|---|---|
| `ScheduleAnyway` 집중 | exact constraint selector/maxSkew와 eligible domain | soft preference이며 기존 Pod 재배치 보장 없음 |
| `DoNotSchedule`와 새 Pending | same Pod UID의 FailedScheduling lifecycle | 전용 런북으로 이동 |
| terminating/replacement 혼재 | UID·creation/deletion 순서 | 한 시점 raw count로 위반 확정 금지 |
| topology label 누락 | current Node UID와 key 부재 | domain 수를 임의 보정하지 않음 |

**대상 Pod constraint 최신 조회**

`if [ "$TOPOLOGY_READY" != true ]; then printf '%s\n' '중단: 최신 TOPOLOGY_READY가 아니다.' >&2; elif POD_NOW="$(kubectl get pod "$TARGET_POD" -n "$NS" -o json)" && [ "$(jq -r '.metadata.uid' <<<"$POD_NOW")" = "$POD_UID" ]; then jq '{pod:.metadata.name,uid:.metadata.uid,node:.spec.nodeName,constraints:[.spec.topologySpreadConstraints[]?|{topologyKey,maxSkew,whenUnsatisfiable,labelSelector,minDomains,nodeAffinityPolicy,nodeTaintsPolicy}]}' <<<"$POD_NOW"; else TOPOLOGY_READY=false; printf '%s\n' '중단: target Pod UID drift' >&2; fi`

constraint `labelSelector`가 root selector와 다르면 그 selector의 모집단을 별도로 owner/UID 검증한다. eligible domain은 label distinct count가 아니라 nodeSelector·required affinity·taint/toleration·resource/PVC 조건을 통과한 Node domain이다. scheduler 내부 Filter/Score가 필요하면 Pod UID, schedulerName, bind 시각과 term을 control-plane owner에게 전달한다. 권한·로그 부재를 정책 정상으로 해석하지 않는다.

## 변경 gate

Pod delete/rollout/scale, maxSkew·selector·topologyKey·whenUnsatisfiable, Node label/taint 변경 명령은 제공하지 않는다.

승인 기록에는 selector·새 spec digest, desired/Ready, endpoint와 실제 요청, 다른 tenant, volume/quorum/외부 호출/idempotence, 영향·rollback 선언·중단 조건을 포함한다. rollback도 current controller UID/resourceVersion/new digest/approval/window를 재검사한다.

## replacement 재등록과 정상화

변경 후 기존 Pod/owner/Node UID와 snapshot을 폐기한다. current root controller UID와 current selector를 다시 읽고 change window 내 non-deleting 후보가 정확히 하나일 때만 replacement로 등록한다. 복수이면 변경 단위가 불명확하므로 중단한다.

`unset REPLACEMENT_READY NORMALIZED_READY REPLACEMENT_POD REPLACEMENT_POD_UID; REPLACEMENT_READY=false; SNAPSHOT_READY=false; TOPOLOGY_READY=false; if [ "$MUTATION_READY" != true ]; then printf '%s\n' '중단: MUTATION_READY가 아니다.' >&2; elif ROOT_NOW="$(kubectl get "$ROOT_KIND" "$ROOT_NAME" -n "$NS" -o json)" && [ "$(jq -r '.metadata.uid' <<<"$ROOT_NOW")" = "$ROOT_UID" ]; then NEW_SELECTOR="$(jq -r '([(.spec.selector.matchLabels//{})|to_entries[]|"\(.key)=\(.value)"]+[.spec.selector.matchExpressions[]?|if .operator=="In" then "\(.key) in (\(.values|join(",")))" elif .operator=="NotIn" then "\(.key) notin (\(.values|join(",")))" elif .operator=="Exists" then .key elif .operator=="DoesNotExist" then "!\(.key)" else error("unsupported") end])|join(",")' <<<"$ROOT_NOW")"; if PODS="$(kubectl get pods -n "$NS" -l "$NEW_SELECTOR" -o json)"; then CAND="$(jq -c --arg s "$CHANGE_START" --arg e "$CHANGE_END" '[.items[]|select(.metadata.creationTimestamp >= $s and .metadata.creationTimestamp < $e and .metadata.deletionTimestamp==null)]' <<<"$PODS")"; COUNT="$(jq 'length' <<<"$CAND")"; if [ "$COUNT" -eq 1 ]; then REPLACEMENT_POD="$(jq -r '.[0].metadata.name' <<<"$CAND")"; REPLACEMENT_POD_UID="$(jq -r '.[0].metadata.uid' <<<"$CAND")"; REPLACEMENT_READY=true; ROOT_SELECTOR="$NEW_SELECTOR"; printf 'REPLACEMENT_READY=true pod=%s uid=%s rootUID=%s selector=%s created=%s\n' "$REPLACEMENT_POD" "$REPLACEMENT_POD_UID" "$ROOT_UID" "$ROOT_SELECTOR" "$(jq -r '.[0].metadata.creationTimestamp' <<<"$CAND")"; else printf '중단: replacement 후보 수=%s\n' "$COUNT" >&2; fi; else printf '%s\n' '중단: replacement Pod producer 실패' >&2; fi; else printf '%s\n' '중단: current root identity 실패' >&2; fi`

`NORMALIZED_READY=false; if [ "$REPLACEMENT_READY" != true ]; then printf '%s\n' '중단: 최신 REPLACEMENT_READY가 아니다.' >&2; elif ROOT_NOW="$(kubectl get "$ROOT_KIND" "$ROOT_NAME" -n "$NS" -o json)" && POD_NOW="$(kubectl get pod "$REPLACEMENT_POD" -n "$NS" -o json)" && [ "$(jq -r '.metadata.uid' <<<"$ROOT_NOW")" = "$ROOT_UID" ] && [ "$(jq -r '.metadata.uid' <<<"$POD_NOW")" = "$REPLACEMENT_POD_UID" ]; then DK="$(jq -r '[.metadata.ownerReferences[]?|select(.controller==true)][0].kind//empty' <<<"$POD_NOW")"; DN="$(jq -r '[.metadata.ownerReferences[]?|select(.controller==true)][0].name//empty' <<<"$POD_NOW")"; DU="$(jq -r '[.metadata.ownerReferences[]?|select(.controller==true)][0].uid//empty' <<<"$POD_NOW")"; REL=false; if [ "$DU" = "$ROOT_UID" ]; then REL=true; elif OJ="$(kubectl get "$DK" "$DN" -n "$NS" -o json)" && [ "$(jq -r '.metadata.uid' <<<"$OJ")" = "$DU" ] && [ "$(jq -r '[.metadata.ownerReferences[]?|select(.controller==true and .uid==$uid)]|length' --arg uid "$ROOT_UID" <<<"$OJ")" -eq 1 ]; then REL=true; fi; if [ "$REL" = true ] && RNODE="$(jq -r '.spec.nodeName//empty' <<<"$POD_NOW")" && RNODE_JSON="$(kubectl get node "$RNODE" -o json)" && [ -n "$(jq -r --arg k "$TOPOLOGY_KEY" '.metadata.labels[$k]//empty' <<<"$RNODE_JSON")" ]; then NORMALIZED_READY=true; printf 'NORMALIZED_READY=true pod=%s uid=%s rootUID=%s node=%s nodeUID=%s topology=%s value=%s ready=%s\n' "$REPLACEMENT_POD" "$REPLACEMENT_POD_UID" "$ROOT_UID" "$RNODE" "$(jq -r '.metadata.uid' <<<"$RNODE_JSON")" "$TOPOLOGY_KEY" "$(jq -r --arg k "$TOPOLOGY_KEY" '.metadata.labels[$k]' <<<"$RNODE_JSON")" "$(jq -c '[.status.containerStatuses[]?.ready]' <<<"$POD_NOW")"; else printf '%s\n' '중단: replacement owner/node/topology relation 실패' >&2; fi; else REPLACEMENT_READY=false; printf '%s\n' '중단: replacement/root identity drift' >&2; fi`

정상화는 current selector+root UID 모집단을 다시 만들고 constraint selector별 domain count, desired=Ready, Pending/Warning/restart 부재를 관찰한다. Service workload는 current Service UID·selector, EndpointSlice service-name과 targetRef Pod UID, 실제 요청/핵심 기능까지 확인한다. 분포 개선만으로 정상화하지 않는다.

## 외부 관측 경계

일반 kube-state-metrics PromQL은 arbitrary `topologySpreadConstraints`, eligible domain과 current owner chain을 완전 재현하지 못하므로 이 런북은 불완전한 고정 쿼리를 제공하지 않는다. 외부 질의를 만들 경우 current root UID와 allowlist된 label 이름을 확인하고 matcher를 escape하며 regular/init Pod 상태를 구분하고, 빈 결과를 성공으로 취급하지 않는다.

## 증거와 경계

Pod/direct owner/root controller/Node UID·resourceVersion, current selector/spec digest, topology key/value, constraint, creation/deletion, canonical 변경 창과 실제 서비스 결과를 보존한다. Secret·token·개인정보·전체 YAML/로그는 저장하지 않는다. Kubernetes 1.26 기준 정적 검토이며 scheduler profile/score, managed control plane, admission, autoscaler와 실제 기능은 환경별 미검증이다.
