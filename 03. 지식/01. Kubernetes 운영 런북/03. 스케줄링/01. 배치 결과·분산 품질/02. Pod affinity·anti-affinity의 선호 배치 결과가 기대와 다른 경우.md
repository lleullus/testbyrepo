# Pod affinity·anti-affinity의 선호 배치 결과가 기대와 다른 경우

## 입력값과 빠른 수집

승인된 `kubectl` context가 있는 작업 PC 또는 bastion의 같은 Bash에서 실행한다. 경로는 `대상 Pod UID → 직접 owner UID → 현재 root controller UID·selector → preferred term → matching Pod UID·Node UID·topology domain → eligible Node → scheduler Score → 실제 기능`이다. `preferredDuringSchedulingIgnoredDuringExecution`은 점수 입력이며 특정 Node 선택이나 이미 bind된 Pod의 재배치를 보장하지 않는다.

| 구분 | 값 | 등록·검증 |
|---|---|---|
| 최초 입력 | `NS`, `TARGET_POD` | bound Pod의 namespace와 exact name을 한 번 입력한다. |
| API 자동값 | Pod·Node·direct owner·root controller UID/resourceVersion, current selector, spec digest | 모든 producer와 owner chain 검증이 성공할 때만 등록한다. |
| 계산 후보 | affinity/anti-affinity preferred term, selector, namespace, topology domain | current Pod spec과 API에서 계산하며 빈 결과를 정상으로 해석하지 않는다. |
| 운영자 선택 | `TERM_KIND`, `TERM_INDEX`, `MATCH_NS`, `WINDOW_START`, `WINDOW_END` | 출력 근거를 보고 선택하고 canonical UTC 시간 창을 검증한다. |

재등록 명령은 UID·resourceVersion·owner·Node·term·시간 창과 모든 downstream `READY`를 먼저 폐기한다. 같은 이름으로 재생성된 객체에는 이전 배치 증거를 연결하지 않는다. 위 owner chain은 Pod direct owner와 그 상위 controller 한 단계까지만 지원하며, 더 깊거나 selector가 없는 custom controller는 owner에게 이관한다.

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | 현재 bound Pod의 preferred affinity·anti-affinity 결과가 기대한 Node/domain과 다르다. |
| 적용 | current preferred term과 그 term의 namespace·selector가 매칭하는 Pod, Node topology와 eligible 후보를 같은 lifecycle에서 확인할 수 있다. |
| 제외 | required 조건으로 Pending/FailedScheduling이면 [[18. Pod 이벤트에 FailedScheduling이 기록된 경우]], topology spread constraint가 주 원인이면 [[01. Pod가 특정 topology domain에 과도하게 집중된 경우]]로 이동한다. |

검색 문자열: `preferredDuringSchedulingIgnoredDuringExecution`, `podAffinity`, `podAntiAffinity`, `weight`, `labelSelector`, `namespaces`, `namespaceSelector`, `topologyKey`, `FailedScheduling`.

## preferred term 선택과 snapshot

`TERM_KIND='PASTE_AFFINITY_OR_ANTI_AFFINITY_HERE'; TERM_INDEX='PASTE_ZERO_BASED_TERM_INDEX_HERE'; MATCH_NS='PASTE_MATCH_NAMESPACE_HERE'`

`unset TERM_READY SNAPSHOT_READY MUTATION_READY REPLACEMENT_READY NORMALIZED_READY TERM_JSON TERM_SELECTOR TOPOLOGY_KEY SNAPSHOT_JSON SNAPSHOT_AT; TERM_READY=false; if [ "$AUTO_READY" != true ] || [ "$WINDOW_READY" != true ]; then printf '%s\n' '중단: AUTO_READY/WINDOW_READY가 필요하다.' >&2; elif [ "$TERM_KIND" != affinity ] && [ "$TERM_KIND" != anti-affinity ]; then printf '%s\n' '중단: TERM_KIND는 affinity 또는 anti-affinity다.' >&2; elif [[ ! `unset SNAPSHOT_READY MUTATION_READY REPLACEMENT_READY NORMALIZED_READY SNAPSHOT_JSON SNAPSHOT_AT; SNAPSHOT_READY=false; if [ "$TERM_READY" != true ]; then printf '%s\n' '중단: 최신 TERM_READY가 아니다.' >&2; elif POD_NOW="$(kubectl get pod "$TARGET_POD" -n "$NS" -o json)" && ROOT_NOW="$(kubectl get "$ROOT_KIND" "$ROOT_NAME" -n "$NS" -o json)" && NODE_NOW="$(kubectl get node "$POD_NODE" -o json)" && [ "$(jq -r '.metadata.uid' <<<"$POD_NOW")" = "$POD_UID" ] && [ "$(jq -r '.metadata.resourceVersion' <<<"$POD_NOW")" = "$POD_RV" ] && [ "$(jq -r '.metadata.uid' <<<"$ROOT_NOW")" = "$ROOT_UID" ] && [ "$(jq -r '.metadata.uid' <<<"$NODE_NOW")" = "$NODE_UID" ]; then if MATCHING="$(kubectl get pods -n "$MATCH_NS" -l "$TERM_SELECTOR" -o json)" && NODES="$(kubectl get nodes -o json)" && EVENTS="$(kubectl get events -n "$NS" --field-selector "involvedObject.kind=Pod,involvedObject.name=$TARGET_POD" -o json)"; then if ! ## 관측별 진단 경로

| 지금 보이는 것 | 직접 gate | 다음 행동 |
|---|---|---|
| affinity인데 matching Pod domain을 선택하지 않음 | term weight·namespace·selector와 current matching Pod UID/domain | eligible Node와 다른 Score plugin을 대조한다. |
| anti-affinity인데 matching Pod와 같은 domain | 같은 term과 bind 시점 matching Pod lifecycle | soft preference, 대안 Node 부재, 다른 점수 후보를 분리한다. |
| matching Pod가 0건 또는 과다 | exact term selector·namespace와 생성/삭제 시각 | affinity 효과 없음 또는 anti-affinity 회피 대상 변화를 기록한다. |
| topology label `MISSING` | current Node UID와 exact key | Node label owner로 이관하며 domain을 임의 보정하지 않는다. |
| `FailedScheduling` | 같은 Pod UID와 시간 창의 Event | preferred 분석을 중단하고 required/자원 경로로 이동한다. |

**required 조건과 eligible Node 입력 출력**

`if [ "$SNAPSHOT_READY" != true ]; then printf '%s\n' '중단: 최신 SNAPSHOT_READY가 아니다.' >&2; elif POD_NOW="$(kubectl get pod "$TARGET_POD" -n "$NS" -o json)" && ROOT_NOW="$(kubectl get "$ROOT_KIND" "$ROOT_NAME" -n "$NS" -o json)" && [ "$(jq -r '.metadata.uid' <<<"$POD_NOW")" = "$POD_UID" ] && [ "$(jq -r '.metadata.resourceVersion' <<<"$POD_NOW")" = "$POD_RV" ] && [ "$(jq -r '.metadata.uid' <<<"$ROOT_NOW")" = "$ROOT_UID" ]; then jq '{pod:{uid:.metadata.uid,node:.spec.nodeName,schedulerName:.spec.schedulerName,nodeSelector:.spec.nodeSelector,requiredNodeAffinity:.spec.affinity.nodeAffinity.requiredDuringSchedulingIgnoredDuringExecution,requiredPodAffinity:.spec.affinity.podAffinity.requiredDuringSchedulingIgnoredDuringExecution,requiredPodAntiAffinity:.spec.affinity.podAntiAffinity.requiredDuringSchedulingIgnoredDuringExecution,tolerations:.spec.tolerations,requests:[.spec.initContainers[]?,.spec.containers[]?|{kind:(if .restartPolicy=="Always" then "sidecar-or-regular" else "regular-or-init" end),name,requests:.resources.requests}],volumes:.spec.volumes},status:{phase:.status.phase,conditions:.status.conditions,regular:[.status.containerStatuses[]?|{name,ready,restartCount,containerID}],init:[.status.initContainerStatuses[]?|{name,ready,restartCount,containerID}]}}' <<<"$POD_NOW"; else SNAPSHOT_READY=false; printf '%s\n' '중단: current Pod/root identity drift' >&2; fi`

taint/toleration, nodeSelector, required affinity, request/allocatable, Pod capacity, PVC topology를 통과한 Node만 eligible 후보로 본다. 위 출력은 scheduler Filter/Score 재현이 아니다. term·matching Pod·eligible 후보가 일치해도 결과가 설명되지 않으면 Pod UID, schedulerName, bind 시각, canonical 창, term JSON의 비민감 요약을 control-plane owner에게 전달한다. managed control plane 로그 접근이나 plugin 이름을 추측하지 않는다.

## 변경 전 gate

이 런북은 Pod 삭제·rollout·scale·patch, affinity·Node label·scheduler profile 변경 명령을 제공하지 않는다. 승인된 GitOps/선언 경로의 변경 직전에만 gate를 통과한다.

`APPROVAL_ID='PASTE_APPROVAL_ID_HERE'; EVIDENCE_ID='PASTE_EVIDENCE_ID_HERE'; CHANGE_START='PASTE_CHANGE_START_RFC3339_HERE'; CHANGE_END='PASTE_CHANGE_END_RFC3339_HERE'; APPROVED_SPEC_DIGEST='PASTE_APPROVED_ROOT_SPEC_SHA256_HERE'`

`unset MUTATION_READY REPLACEMENT_READY NORMALIZED_READY; MUTATION_READY=false; if [ "$SNAPSHOT_READY" != true ] || [ "$TERM_READY" != true ]; then printf '%s\n' '중단: 최신 SNAPSHOT_READY/TERM_READY가 필요하다.' >&2; elif [ -z "$APPROVAL_ID" ] || [ -z "$EVIDENCE_ID" ] || [[ ! "$APPROVED_SPEC_DIGEST" =~ ^[0-9a-f]{64}$ ]]; then printf '%s\n' '중단: 승인/evidence/승인 spec digest 오류' >&2; elif [[ ! "$CHANGE_START" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] || [[ ! "$CHANGE_END" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]]; then printf '%s\n' '중단: 변경 창 형식 오류' >&2; elif ! CS="$(date -u -d "$CHANGE_START" +%s)" || ! 승인에는 selector와 새 revision/digest, desired/Ready·availability, 다른 tenant와 topology, Service endpoint, volume·quorum·외부 호출·멱등성, 영향 범위, 중단 조건과 rollback 선언이 필요하다. rollback도 current controller UID/resourceVersion, rollback 대상 digest, 현재 Pod/revision, 승인과 새 시간 창을 직접 재검사한다. Kubernetes 변경은 이미 발생한 외부 side effect를 되돌리지 않는다.

## replacement 재등록과 정상화

변경 뒤 기존 Pod·owner·Node·term·snapshot을 재사용하지 않는다. current root UID와 **변경 후 selector**, 승인 digest, change window, non-deleting, owner chain 조건을 모두 만족하는 후보가 정확히 하나일 때만 등록한다.

`unset REPLACEMENT_READY NORMALIZED_READY REPLACEMENT_POD REPLACEMENT_POD_UID REPLACEMENT_NODE REPLACEMENT_NODE_UID SNAPSHOT_JSON; REPLACEMENT_READY=false; SNAPSHOT_READY=false; TERM_READY=false; if [ "$MUTATION_READY" != true ]; then printf '%s\n' '중단: MUTATION_READY가 아니다.' >&2; elif ROOT_NOW="$(kubectl get "$ROOT_KIND" "$ROOT_NAME" -n "$NS" -o json)" && [ "$(jq -r '.metadata.uid' <<<"$ROOT_NOW")" = "$ROOT_UID" ] && [ "$(jq -S '.spec' <<<"$ROOT_NOW" | sha256sum | cut -d' ' -f1)" = "$APPROVED_SPEC_DIGEST" ]; then if NEW_SELECTOR="$(jq -r '([(.spec.selector.matchLabels//{})|to_entries[]|"\(.key)=\(.value)"]+[.spec.selector.matchExpressions[]?|if .operator=="In" then "\(.key) in (\(.values|join(",")))" elif .operator=="NotIn" then "\(.key) notin (\(.values|join(",")))" elif .operator=="Exists" then .key elif .operator=="DoesNotExist" then "!\(.key)" else error("unsupported selector") end])|join(",")' <<<"$ROOT_NOW")" && [ -n "$NEW_SELECTOR" ] && PODS="$(kubectl get pods -n "$NS" -l "$NEW_SELECTOR" -o json)"; then CAND='[]'; RELATION_FAILED=false; while IFS= read -r P; do [ -n "$P" ] || continue; PJ="$(kubectl get pod "$P" -n "$NS" -o json)" || { RELATION_FAILED=true; break; }; CREATED="$(jq -r '.metadata.creationTimestamp' <<<"$PJ")"; DELETING="$(jq -r '.metadata.deletionTimestamp//empty' <<<"$PJ")"; [ "$CREATED" \< "$CHANGE_START" ] && continue; [ ! then REPLACEMENT_NODE_UID="$(jq -r '.metadata.uid' <<<"$RNODE")"; ROOT_SELECTOR="$NEW_SELECTOR"; ROOT_RV="$(jq -r '.metadata.resourceVersion' <<<"$ROOT_NOW")"; ROOT_SPEC_DIGEST="$APPROVED_SPEC_DIGEST"; else printf '%s\n' '중단: replacement Node producer 실패' >&2; fi; else printf '중단: replacement 후보 수=%s\n' "$(jq 'length' <<<"$CAND")" >&2; fi; else printf '%s\n' '중단: 변경 후 selector 계산/Pod producer 실패' >&2; 최종 정상화는 변경 후 term의 kind·weight·selector·namespace·topologyKey를 다시 등록하고 current matching Pod UID/domain과 eligible Node를 재계산한다. desired=Ready, 새 Pending/Warning/restart 부재를 관찰 창 동안 확인하고, Service workload면 current Service UID·selector, EndpointSlice service-name·port·targetRef Pod UID와 실제 요청/핵심 기능까지 확인한다. 기대 domain 배치 한 번이나 `NORMALIZED_READY=true`만으로 정상화를 선언하지 않는다.

## Prometheus 보조 관측

kube-state-metrics에 `kube_pod_info`의 `uid` label이 실제 존재할 때만 현재 대상 identity를 직접 연결한 완성 쿼리를 생성한다.

`if [ "$AUTO_READY" != true ]; then printf '%s\n' '중단: 최신 AUTO_READY가 아니다.' >&2; elif POD_NOW="$(kubectl get pod "$TARGET_POD" -n "$NS" -o json)" && [ "$(jq -r '.metadata.uid' <<<"$POD_NOW")" = "$POD_UID" ] && [ "$(jq -r '.metadata.resourceVersion' <<<"$POD_NOW")" = "$POD_RV" ]; then NS_Q="$(jq -Rn --arg v "$NS" '$v|@json')"; POD_Q="$(jq -Rn --arg v "$TARGET_POD" '$v|@json')"; UID_Q="$(jq -Rn --arg v "$POD_UID" '$v|@json')"; printf 'kube_pod_info{namespace=%s,pod=%s,uid=%s}\n' "$NS_Q" "$POD_Q" "$UID_Q"; else AUTO_READY=false; printf '%s\n' '중단: current Pod UID/resourceVersion 불일치' >&2; fi`

빈 결과는 성공이 아니며 metric/uid label 미지원, label 불일치, scrape 실패, 시간 범위와 권한을 구분한다. 일반 PromQL은 preferred term의 namespaceSelector, current matching Pod lifecycle, topology label과 scheduler Filter/Score를 완전 재현하지 못하므로 API snapshot을 대체하지 않는다.

## 증거와 경계

Pod/direct owner/root controller/Node UID·resourceVersion, selector/spec digest, preferred term, matching Pod UID·Node UID·domain, canonical 시간 창, 비민감 Event, 승인과 실제 기능 결과만 보존한다. Secret·token·개인정보·전체 YAML·scheduler 로그 원문은 저장하지 않는다. Kubernetes 1.26 기준 정적 검토이며 scheduler profile/plugin·Score, managed control plane, admission, autoscaler, kube-state-metrics label과 실제 서비스 기능은 환경별 미검증이다.
