# Pod label·selector 변경 후 topology spread·anti-affinity 계산 대상이 달라진 경우

## 입력값과 빠른 수집

controller owner selector와 topology spread·affinity term selector는 서로 다른 집합을 만들 수 있다. 여러 term도 합치지 않고 하나씩 검증한다.

| 구분 | 값 | gate |
|---|---|---|
| 최초 입력 | `NS`, 대표 `POD` | exact-name 조회 |
| API 자동값 | Pod/owner UID·resourceVersion, owner selector, node, containerID, placement 원문 | owner relation 일치 |
| 계산 후보 | escaped `POD_RE`, selector별 matching 집합과 domain count | selector 조회 성공 전 미확정 |
| 운영자 선택 | term 종류·index, 정확한 selector와 namespace, topology key, UTC window | 원문과 대조 후 선택 |

실행 host는 승인된 작업 PC/bastion의 같은 Bash다. hop은 `작업 host → kubectl → API server → owner·Pod·Node 객체`이며 SSH·exec·CRI 경로는 없다.

`TOOLS_READY=false; MISSING=''; for T in kubectl jq date hostname sed tr; do command -v "$T" >/dev/null 2>&1 || MISSING="$MISSING $T"; done; if [ -n "${BASH_VERSION:-}" ] && [ -z "$MISSING" ]; then TOOLS_READY=true; printf 'TOOLS_READY=true host=%s\n' "$(hostname -f)"; else printf '중단: Bash 또는 도구 누락:%s\n' "$MISSING" >&2; fi`

owner selector에 `matchExpressions`가 있으면 자동 생성값을 완전한 selector로 보지 않는다. owner가 제공하는 정확한 selector를 사용하고 이 문서의 자동 replacement 절차는 보류한다.

`fresh_target(){ local p host uid ouid node cids; [ "$AUTO_READY" = true ] || return 1; host="$(hostname -f)" || return 1; [ "$host" = "$HOST_ID" ] || { printf '%s\n' '중단: 실행 host 변경' >&2; return 1; }; p="$(kubectl get pod "$POD" -n "$NS" -o json)" || return 1; uid="$(jq -r '.metadata.uid' <<<"$p")"; ouid="$(jq -r '[.metadata.ownerReferences[]?|select(.controller==true)][0].uid//empty' <<<"$p")"; node="$(jq -r '.spec.nodeName//empty' <<<"$p")"; cids="$(jq -r '[.status.containerStatuses[]?.containerID//empty]|sort|join(",")' <<<"$p")"; if [ "$uid" != "$POD_UID" ] || [ "$ouid" != "$OWNER_UID" ] || [ "$node" != "$NODE" ] || [ "$cids" != "$CONTAINER_IDS" ]; then printf '%s\n' '중단: UID/owner/containerID/node 관계 변경; 전체 재수집' >&2; return 1; fi; POD_RV="$(jq -r '.metadata.resourceVersion' <<<"$p")"; export POD_RV; }`

대표 Pod의 current Node UID와 current controller 객체 UID까지 고정한 아래 fresh 정의를 이후 명령에 사용한다.

`unset NODE_IDENTITY_READY NODE_UID; NODE_IDENTITY_READY=false; if [ "$AUTO_READY" != true ] || [ -z "$NODE" ]; then printf '%s\n' '중단: bound Pod AUTO_READY 필요' >&2; elif NJSON="$(kubectl get node "$NODE" -o json)"; then NODE_UID="$(jq -r '.metadata.uid' <<<"$NJSON")"; NODE_IDENTITY_READY=true; export NODE_UID; printf 'NODE_IDENTITY_READY=true node=%s uid=%s\n' "$NODE" "$NODE_UID"; else printf '%s\n' '중단: current Node 조회 실패' >&2; fi`

`fresh_target(){ local p o n host uid ouid node cids; [ "$AUTO_READY" = true ] && [ "$NODE_IDENTITY_READY" = true ] || return 1; host="$(hostname -f)" || return 1; [ "$host" = "$HOST_ID" ] || { printf '%s\n' '중단: 실행 host 변경' >&2; return 1; }; p="$(kubectl get pod "$POD" -n "$NS" -o json)" || return 1; o="$(kubectl get "$OWNER_RESOURCE" "$OWNER_NAME" -n "$NS" -o json)" || return 1; n="$(kubectl get node "$NODE" -o json)" || return 1; uid="$(jq -r '.metadata.uid' <<<"$p")"; ouid="$(jq -r '[.metadata.ownerReferences[]?|select(.controller==true)][0].uid//empty' <<<"$p")"; node="$(jq -r '.spec.nodeName//empty' <<<"$p")"; cids="$(jq -r '[.status.containerStatuses[]?.containerID//empty]|sort|join(",")' <<<"$p")"; if [ "$uid" != "$POD_UID" ] || [ "$ouid" != "$OWNER_UID" ] || [ "$(jq -r '.metadata.uid' <<<"$o")" != "$OWNER_UID" ] || [ "$node" != "$NODE" ] || [ "$cids" != "$CONTAINER_IDS" ] || [ "$(jq -r '.metadata.uid' <<<"$n")" != "$NODE_UID" ]; then printf '%s\n' '중단: Pod/current owner/containerID/Node UID 관계 변경; 전체 재수집' >&2; return 1; fi; POD_RV="$(jq -r '.metadata.resourceVersion' <<<"$p")"; export POD_RV; }`

### term 선택과 UTC window

`TERM_KIND='PASTE_PLACEMENT_TERM_KIND_HERE'; TERM_INDEX='PASTE_PLACEMENT_TERM_INDEX_HERE'; PLACEMENT_NS='PASTE_PLACEMENT_NAMESPACE_HERE'; PLACEMENT_SELECTOR='PASTE_PLACEMENT_SELECTOR_HERE'; TOPOLOGY_KEY='PASTE_PLACEMENT_TOPOLOGY_KEY_HERE'; SELECTION_READY=false; if [ "$AUTO_READY" != true ] || ! fresh_target; then printf '%s\n' '중단: fresh target 실패' >&2; elif [[ ! "$TERM_KIND" =~ ^(topologySpread|podAffinity|requiredPodAntiAffinity|preferredPodAntiAffinity)$ ]] || [[ ! "$TERM_INDEX" =~ ^[0-9]+$ ]] || [ -z "$PLACEMENT_NS" ] || [ -z "$PLACEMENT_SELECTOR" ] || [ -z "$TOPOLOGY_KEY" ]; then printf '%s\n' '중단: term 선택값 형식 오류' >&2; elif ! kubectl get pods -n "$PLACEMENT_NS" -l "$PLACEMENT_SELECTOR" >/dev/null 2>&1; then printf '%s\n' '중단: placement selector API 검증 실패' >&2; else SELECTION_READY=true; export TERM_KIND TERM_INDEX PLACEMENT_NS PLACEMENT_SELECTOR TOPOLOGY_KEY; printf 'SELECTION_READY=true kind=%s index=%s ns=%s selector=%s topology=%s\n' "$TERM_KIND" "$TERM_INDEX" "$PLACEMENT_NS" "$PLACEMENT_SELECTOR" "$TOPOLOGY_KEY"; fi`

`START_RFC3339='PASTE_SELECTOR_DRIFT_START_UTC_HERE'; END_RFC3339='PASTE_SELECTOR_DRIFT_END_UTC_HERE'; WINDOW_READY=false; RFC3339_RE='^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$'; if [ "$SELECTION_READY" != true ] || ! fresh_target; then printf '%s\n' '중단: selection/fresh gate 실패' >&2; elif [[ ! "$START_RFC3339" =~ $RFC3339_RE ]] || [[ ! "$END_RFC3339" =~ $RFC3339_RE ]]; then printf '%s\n' '중단: canonical UTC RFC3339 필요' >&2; elif START_EPOCH="$(date -u -d "$START_RFC3339" +%s 2>/dev/null)" && END_EPOCH="$(date -u -d "$END_RFC3339" +%s 2>/dev/null)" && [ "$(date -u -d "@$START_EPOCH" '+%Y-%m-%dT%H:%M:%SZ')" = "$START_RFC3339" ] && [ "$(date -u -d "@$END_EPOCH" '+%Y-%m-%dT%H:%M:%SZ')" = "$END_RFC3339" ] && [ "$START_EPOCH" -lt "$END_EPOCH" ] && [ "$END_EPOCH" -le "$(date -u +%s)" ]; then WINDOW_READY=true; export START_RFC3339 END_RFC3339 START_EPOCH END_EPOCH; printf 'WINDOW_READY=true %s..%s\n' "$START_RFC3339" "$END_RFC3339"; else printf '%s\n' '중단: round-trip/start<end/미래 상한 실패' >&2; fi`

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | Pod label·selector 변경 뒤 owner 집합과 placement 계산 집합 또는 domain count가 달라진 경우 |
| 적용 | term 원문, namespace 범위, matching Pod UID·node·label, Node topology label을 대조 가능 |
| 제외 | 새 Pod hard constraint `FailedScheduling`은 [[18. Pod 이벤트에 FailedScheduling이 기록된 경우]], 일반 집중은 [[01. Pod가 특정 topology domain에 과도하게 집중된 경우]] |

검색 문자열: `topologySpreadConstraints`, `labelSelector`, `podAntiAffinity`, `matchLabels`, `matchExpressions`, `FailedScheduling`.

## 관측별 진단 경로

| 지금 보이는 것 | 먼저 볼 것 | 그다음 어디를 볼지 | 상세 절 |
|---|---|---|---|
| owner 집합과 term 집합이 다름 | selector 원문·namespace·matching UID | 의도된 별도 집합인지 owner 확인 | [[#읽기 전용 진단|읽기 전용 진단]] |

| label/selector 권위가 불명확 | current owner revision과 변경 기록 | mutation 보류 | [[#상태 변경 경계|상태 변경 경계]] |

## 읽기 전용 진단

`EVIDENCE_READY=false; if [ "$WINDOW_READY" != true ] || ! fresh_target; then printf '%s\n' '중단: 최신 window/identity gate 실패' >&2; elif OWNER_PODS="$(kubectl get pods -n "$NS" -l "$OWNER_SELECTOR" -o json)" && TERM_PODS="$(kubectl get pods -n "$PLACEMENT_NS" -l "$PLACEMENT_SELECTOR" -o json)"; then printf '%s\n' '=== owner 집합 ==='; jq -r --arg ouid "$OWNER_UID" '.items|sort_by(.metadata.name)[]|[.metadata.name,.metadata.uid,([.metadata.ownerReferences[]?|select(.controller==true)][0].uid//"-"),(.spec.nodeName//"-"),.metadata.creationTimestamp]|@tsv' <<<"$OWNER_PODS"; printf '%s\n' '=== placement term 집합 ==='; jq -r '.items|sort_by(.metadata.name)[]|[.metadata.name,.metadata.uid,(.spec.nodeName//"-"),(.metadata.labels|tojson),.metadata.creationTimestamp]|@tsv' <<<"$TERM_PODS"; if jq -e --arg ouid "$OWNER_UID" '(.items|length)>0 and all(.items[];any(.metadata.ownerReferences[]?;.uid==$ouid))' <<<"$OWNER_PODS" >/dev/null; then EVIDENCE_READY=true; printf 'EVIDENCE_READY=true owner_count=%s term_count=%s window=%s..%s\n' "$(jq '.items|length' <<<"$OWNER_PODS")" "$(jq '.items|length' <<<"$TERM_PODS")" "$START_RFC3339" "$END_RFC3339"; else printf '%s\n' '중단: owner selector 집합 relation 불일치' >&2; fi; else printf '%s\n' '중단: selector producer 실패' >&2; fi`

빈 placement 집합은 곧 오류가 아니다. selector 변경, namespace 범위, 의도된 zero match, API 실패를 분리한다. owner count와 term count가 다른 것도 selector 목적이 다르면 정상일 수 있다.

### Node/domain 관계

`if [ "$EVIDENCE_READY" != true ] || ! fresh_target; then printf '%s\n' '중단: 최신 evidence gate 실패' >&2; elif TERM_NODE_ROWS="$(jq -r '[.items[].spec.nodeName//empty]|unique[]' <<<"$TERM_PODS")"; then mapfile -t TERM_NODES <<<"$TERM_NODE_ROWS"; if [ -z "$TERM_NODE_ROWS" ]; then TERM_NODES=(); printf '%s\n' '중단: bound matching Pod가 없어 domain 계산 불가' >&2; elif NODES_JSON="$(kubectl get nodes "${TERM_NODES[@]}" -o json)"; then jq -r --arg k "$TOPOLOGY_KEY" '.items|sort_by(.metadata.name)[]|[.metadata.name,.metadata.uid,.metadata.resourceVersion,(.metadata.labels[$k]//"MISSING"),(.spec.unschedulable//false)]|@tsv' <<<"$NODES_JSON"; else printf '%s\n' '중단: Node producer 실패' >&2; fi; else FILTER_RC=$?; printf '중단: Node list filter rc=%s\n' "$FILTER_RC" >&2; fi`

각 Pod의 node를 같은 이름의 Node UID와 연결하고 `TOPOLOGY_KEY` 값으로 count한다. key 누락 Node가 있으면 `maxSkew`를 확정하지 않는다. required/preferred, `DoNotSchedule`/`ScheduleAnyway`, 여러 term을 섞지 않는다.

`if [ "$EVIDENCE_READY" != true ] || ! fresh_target; then printf '%s\n' '중단: 최신 evidence gate 실패' >&2; elif EVENTS_JSON="$(kubectl get events -n "$NS" --field-selector "involvedObject.kind=Pod,involvedObject.name=$POD,involvedObject.uid=$POD_UID" -o json)"; then jq -r --argjson s "$START_EPOCH" --argjson e "$END_EPOCH" '.items[]|(.eventTime//.series.lastObservedTime//.lastTimestamp//.firstTimestamp) as $raw|($raw|strings|sub("\\.[0-9]+Z$";"Z")|fromdateiso8601?) as $t|select($t!=null and $t>=$s and $t<=$e)|[.reason,(.count//1),$raw,.message]|@tsv' <<<"$EVENTS_JSON"; else printf '%s\n' '중단: Event producer 실패; filter 미실행' >&2; fi`

## 상태 변경 경계

진단 중 label patch, owner selector 확대, term 삭제, `whenUnsatisfiable` 완화, Pod 삭제를 하지 않는다. fresh target/evidence, 승인된 원본과 window, PDB·quorum·Ready·Endpoint baseline, 변경 멱등성, 검증된 이전 revision rollback이 모두 있어야 기존 GitOps 절차로 이관한다.

`APPROVAL_ID='PASTE_SELECTOR_DRIFT_APPROVAL_ID_HERE'; CHANGE_READY=false; if [ "$EVIDENCE_READY" != true ] || ! fresh_target; then printf '%s\n' '중단: fresh evidence가 아니다.' >&2; elif [ -z "$APPROVAL_ID" ]; then printf '%s\n' '중단: 승인 ID 필요' >&2; else CHANGE_READY=true; export APPROVAL_ID; printf 'CHANGE_READY=true owner=%s/%s term=%s[%s] approval=%s\n' "$OWNER_KIND" "$OWNER_NAME" "$TERM_KIND" "$TERM_INDEX" "$APPROVAL_ID"; fi`

이 명령은 mutation을 실행하지 않는다. 실제 mutation·rollback은 매 실행 직전 동일 identity와 승인된 revision을 재검사하는 관리 경로에서 수행한다. 새 `FailedScheduling`, owner relation 손상, Ready 감소, domain 집중 악화, 실제 요청 오류면 중단한다. 승인 ID는 변경 시도마다 고유해야 한다.

`CHANGE_RFC3339='PASTE_SELECTOR_DRIFT_CHANGE_UTC_HERE'; unset CHANGE_TIME_READY CHANGE_EPOCH CHANGE_GATE_APPROVAL REPLACEMENT_READY NORMAL_READY; CHANGE_TIME_READY=false; RFC3339_RE='^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$'; if [ "$CHANGE_READY" != true ] || ! fresh_target; then printf '%s\n' '중단: fresh change gate 실패' >&2; elif [[ ! "$CHANGE_RFC3339" =~ $RFC3339_RE ]] || ! CHANGE_EPOCH="$(date -u -d "$CHANGE_RFC3339" +%s 2>/dev/null)" || [ "$(date -u -d "@$CHANGE_EPOCH" '+%Y-%m-%dT%H:%M:%SZ')" != "$CHANGE_RFC3339" ] || [ "$CHANGE_EPOCH" -lt "$END_EPOCH" ] || [ "$CHANGE_EPOCH" -gt "$(date -u +%s)" ]; then printf '%s\n' '중단: 변경 시각 canonical/round-trip/evidence 이후 조건 실패' >&2; else CHANGE_GATE_APPROVAL="$APPROVAL_ID"; CHANGE_TIME_READY=true; export CHANGE_RFC3339 CHANGE_EPOCH CHANGE_GATE_APPROVAL; printf 'CHANGE_TIME_READY=true approval=%s change=%s\n' "$CHANGE_GATE_APPROVAL" "$CHANGE_RFC3339"; fi`

## replacement 재등록과 정상화

`NEW_POD='PASTE_SELECTOR_DRIFT_REPLACEMENT_POD_HERE'; unset REPLACEMENT_READY NORMAL_READY NEW_POD_UID NEW_POD_RV NEW_NODE NEW_NODE_UID NEW_CREATED; REPLACEMENT_READY=false; printf 'replacement 입력 등록 pod=%s; 최종 gate 전 READY 아님\n' "$NEW_POD"`

위 command는 이름만 입력하고 READY를 만들지 않는다. 다음 current owner·변경 시각·Node UID gate가 최종값을 다시 등록한다.

`REPLACEMENT_READY=false; unset NEW_NODE_UID; if [ "$CHANGE_TIME_READY" != true ] || [ "$CHANGE_GATE_APPROVAL" != "$APPROVAL_ID" ]; then printf '%s\n' '중단: current change-time/approval gate 실패' >&2; elif CANDIDATES="$(kubectl get pods -n "$NS" -l "$OWNER_SELECTOR" -o json)" && OJSON="$(kubectl get "$OWNER_RESOURCE" "$OWNER_NAME" -n "$NS" -o json)" && [ "$(jq --arg p "$NEW_POD" '[.items[]|select(.metadata.name==$p)]|length' <<<"$CANDIDATES")" -eq 1 ]; then NP="$(jq -c --arg p "$NEW_POD" '.items[]|select(.metadata.name==$p)' <<<"$CANDIDATES")"; NEW_NODE="$(jq -r '.spec.nodeName//empty' <<<"$NP")"; if [ -n "$NEW_NODE" ] && NJSON="$(kubectl get node "$NEW_NODE" -o json)"; then NEW_POD_UID="$(jq -r '.metadata.uid' <<<"$NP")"; NEW_POD_RV="$(jq -r '.metadata.resourceVersion' <<<"$NP")"; NEW_CREATED="$(jq -r '.metadata.creationTimestamp' <<<"$NP")"; NEW_NODE_UID="$(jq -r '.metadata.uid' <<<"$NJSON")"; if [ "$(jq -r '.metadata.uid' <<<"$OJSON")" = "$OWNER_UID" ] && [ "$(jq -r '[.metadata.ownerReferences[]?|select(.controller==true)][0].uid//empty' <<<"$NP")" = "$OWNER_UID" ] && [ "$(date -u -d "$NEW_CREATED" +%s)" -ge "$CHANGE_EPOCH" ]; then REPLACEMENT_READY=true; export NEW_POD NEW_POD_UID NEW_POD_RV NEW_NODE NEW_NODE_UID NEW_CREATED; printf 'REPLACEMENT_READY=true pod=%s[%s] node=%s[%s] created=%s\n' "$NEW_POD" "$NEW_POD_UID" "$NEW_NODE" "$NEW_NODE_UID" "$NEW_CREATED"; else printf '%s\n' '중단: current owner/node/change-time relation 불일치' >&2; fi; else printf '%s\n' '중단: replacement Node 조회 실패' >&2; fi; else printf '%s\n' '중단: replacement/current owner producer 실패' >&2; fi`

`NORMAL_READY=false; if [ "$REPLACEMENT_READY" != true ] || ! NP="$(kubectl get pod "$NEW_POD" -n "$NS" -o json)" || ! NN="$(kubectl get node "$NEW_NODE" -o json)" || ! OO="$(kubectl get "$OWNER_RESOURCE" "$OWNER_NAME" -n "$NS" -o json)" || ! TERM_NOW="$(kubectl get pods -n "$PLACEMENT_NS" -l "$PLACEMENT_SELECTOR" -o json)"; then printf '%s\n' '중단: 정상화 producer 실패' >&2; elif [ "$(jq -r '.metadata.uid' <<<"$NP")" != "$NEW_POD_UID" ] || [ "$(jq -r '.metadata.uid' <<<"$NN")" != "$NEW_NODE_UID" ] || [ "$(jq -r '.metadata.uid' <<<"$OO")" != "$OWNER_UID" ] || [ "$(jq -r '[.metadata.ownerReferences[]?|select(.controller==true)][0].uid//empty' <<<"$NP")" != "$OWNER_UID" ]; then printf '%s\n' '중단: replacement current identity 불일치' >&2; elif [ "$(jq -r '.status.phase' <<<"$NP")" = Running ] && jq -e '(.status.containerStatuses|length)>0 and all(.status.containerStatuses[];.ready==true and (.containerID//"")!="")' <<<"$NP" >/dev/null; then NEW_POD_RV="$(jq -r '.metadata.resourceVersion' <<<"$NP")"; NORMAL_READY=true; printf 'NORMAL_READY=true pod=%s[%s] node=%s[%s] term_count=%s containerIDs=%s\n' "$NEW_POD" "$NEW_POD_UID" "$NEW_NODE" "$NEW_NODE_UID" "$(jq '.items|length' <<<"$TERM_NOW")" "$(jq -r '[.status.containerStatuses[].containerID]|sort|join(",")' <<<"$NP")"; else printf '%s\n' '중단: replacement container Running/Ready 미수렴' >&2; fi`

placement term은 namespace와 selector에 따라 새 Pod 자체를 포함하지 않을 수 있다. 따라서 최종 gate는 term query 성공과 current 집합을 재등록하되, membership을 강제하지 않고 term 원문에 따른 기대 집합·domain count를 별도로 판정한다.

정상화는 owner desired/Ready, term별 matching 집합, Node topology label과 승인된 `maxSkew`, 새 Warning 부재, EndpointSlice와 실제 요청·Job 결과까지 확인한다. 새 Pod `Running`이나 count 일치만으로 닫지 않는다.

## Prometheus 빠른 관측

`if [ "$EVIDENCE_READY" != true ] || ! fresh_target; then printf '%s\n' '중단: 최신 evidence gate 실패' >&2; else printf 'kube_pod_info{namespace="%s",pod="%s",uid="%s"}\n' "$NS" "$POD" "$POD_UID"; printf 'kube_pod_status_unschedulable{namespace="%s",pod="%s"} == 1\n' "$NS" "$POD"; fi`

빈 결과는 0이 아니다. metric 부재·label 불일치·조회 범위·scrape 실패를 구분한다. arbitrary Kubernetes selector와 `matchExpressions`를 안전하게 PromQL label matcher로 자동 번역하지 않으며, metric만으로 term 집합을 확정하지 않는다.

## 증거 보존과 환경별 미검증

host, UTC window, Pod/owner/Node UID·resourceVersion·containerID·관계·생성 시각, owner/term selector 원문과 matching 집합, topology key/domain, Event, 승인·rollback, replacement와 실제 기능을 보존한다. Secret·token·개인키·전체 YAML은 저장하지 않는다.

scheduler profile, admission label 변경, namespaceSelector, node label 공급자, PDB/quorum과 실제 서비스 endpoint는 환경별 미검증이다. 실제 인프라 명령은 실행하지 않았다.
