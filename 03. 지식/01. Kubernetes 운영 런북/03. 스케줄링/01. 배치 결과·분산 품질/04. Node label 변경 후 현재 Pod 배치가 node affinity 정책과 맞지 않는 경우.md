# Node label 변경 후 현재 Pod 배치가 node affinity 정책과 맞지 않는 경우

## 입력값과 빠른 수집

`requiredDuringSchedulingIgnoredDuringExecution`과 `nodeSelector`는 scheduling 때 적용되며, 이후 Node label이 달라져도 기존 Pod를 자동 축출하지 않는다. 이 문서는 현재 drift, 변경 권위, 다음 replacement 위험을 분리한다.

| 구분 | 값 | gate |
|---|---|---|
| 최초 입력 | `NS`, `POD` | exact-name Pod 조회 |
| API 자동값 | Pod/Node UID·resourceVersion, owner·selector, node, containerID, 적용된 affinity | owner·node 관계 일치 |
| 계산 후보 | escaped `POD_RE`, selector matching 집합 | bounded 결과와 owner UID 검증 |
| 운영자 선택 | label key, 승인된 의도 값, UTC evidence window, 승인 ID | 변경 기록·node pool 계약 대조 |

실행 위치는 승인된 kubeconfig를 가진 작업 PC 또는 bastion의 같은 Bash다. hop은 `작업 host → kubectl → API server → Pod/owner/Node 객체`이며 SSH·exec·CRI를 사용하지 않는다.

`TOOLS_READY=false; MISSING=''; for T in kubectl jq date hostname sed tr; do command -v "$T" >/dev/null 2>&1 || MISSING="$MISSING $T"; done; if [ -n "${BASH_VERSION:-}" ] && [ -z "$MISSING" ]; then TOOLS_READY=true; printf 'TOOLS_READY=true host=%s\n' "$(hostname -f)"; else printf '중단: Bash 또는 도구 누락:%s\n' "$MISSING" >&2; fi`

`matchExpressions`가 있는 owner selector는 이 자동화에서 축약하지 않는다. 해당 경우 `AUTO_READY` 결과를 변경 근거로 쓰지 말고 owner가 제공하는 정확한 selector 경로로 이관한다.

`fresh_target(){ local p n host uid ouid node cids; [ "$AUTO_READY" = true ] || return 1; host="$(hostname -f)" || return 1; [ "$host" = "$HOST_ID" ] || { printf '%s\n' '중단: 실행 host 변경' >&2; return 1; }; p="$(kubectl get pod "$POD" -n "$NS" -o json)" || return 1; n="$(kubectl get node "$NODE" -o json)" || return 1; uid="$(jq -r '.metadata.uid' <<<"$p")"; ouid="$(jq -r '[.metadata.ownerReferences[]?|select(.controller==true)][0].uid//empty' <<<"$p")"; node="$(jq -r '.spec.nodeName//empty' <<<"$p")"; cids="$(jq -r '[.status.containerStatuses[]?.containerID//empty]|sort|join(",")' <<<"$p")"; if [ "$uid" != "$POD_UID" ] || [ "$ouid" != "$OWNER_UID" ] || [ "$node" != "$NODE" ] || [ "$cids" != "$CONTAINER_IDS" ] || [ "$(jq -r '.metadata.uid' <<<"$n")" != "$NODE_UID" ]; then printf '%s\n' '중단: UID/owner/containerID/node relation 변경; 전체 재수집' >&2; return 1; fi; POD_RV="$(jq -r '.metadata.resourceVersion' <<<"$p")"; NODE_RV="$(jq -r '.metadata.resourceVersion' <<<"$n")"; export POD_RV NODE_RV; }`

위 함수는 owner reference만 확인하므로 이후 명령에는 current controller 객체 UID도 확인하는 아래 정의를 사용한다.

`fresh_target(){ local p n o host uid ouid node cids; [ "$AUTO_READY" = true ] || return 1; host="$(hostname -f)" || return 1; [ "$host" = "$HOST_ID" ] || { printf '%s\n' '중단: 실행 host 변경' >&2; return 1; }; p="$(kubectl get pod "$POD" -n "$NS" -o json)" || return 1; n="$(kubectl get node "$NODE" -o json)" || return 1; o="$(kubectl get "$OWNER_RESOURCE" "$OWNER_NAME" -n "$NS" -o json)" || return 1; uid="$(jq -r '.metadata.uid' <<<"$p")"; ouid="$(jq -r '[.metadata.ownerReferences[]?|select(.controller==true)][0].uid//empty' <<<"$p")"; node="$(jq -r '.spec.nodeName//empty' <<<"$p")"; cids="$(jq -r '[.status.containerStatuses[]?.containerID//empty]|sort|join(",")' <<<"$p")"; if [ "$uid" != "$POD_UID" ] || [ "$ouid" != "$OWNER_UID" ] || [ "$(jq -r '.metadata.uid' <<<"$o")" != "$OWNER_UID" ] || [ "$node" != "$NODE" ] || [ "$cids" != "$CONTAINER_IDS" ] || [ "$(jq -r '.metadata.uid' <<<"$n")" != "$NODE_UID" ]; then printf '%s\n' '중단: UID/current owner/containerID/node relation 변경; 전체 재수집' >&2; return 1; fi; POD_RV="$(jq -r '.metadata.resourceVersion' <<<"$p")"; NODE_RV="$(jq -r '.metadata.resourceVersion' <<<"$n")"; export POD_RV NODE_RV; }`

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | bound Pod의 현재 Node label이 Pod에 적용된 required affinity 또는 `nodeSelector` 의도와 달라진 경우 |
| 적용 | 같은 Pod UID, 현재 Node UID, owner 원본, label 변경 기록과 node pool 계약이 있음 |
| 제외 | Pending Pod는 [[18. Pod 이벤트에 FailedScheduling이 기록된 경우]], DaemonSet 수렴·misscheduled는 해당 DaemonSet 런북으로 이동 |

검색 문자열: `nodeSelector`, `requiredDuringSchedulingIgnoredDuringExecution`, `PodScheduled`, `didn't match Pod's node affinity/selector`, `numberMisscheduled`.

## 읽기 전용 진단

`EVIDENCE_READY=false; if [ "$WINDOW_READY" != true ] || ! fresh_target; then printf '%s\n' '중단: 최신 window/identity gate 실패' >&2; elif PJSON="$(kubectl get pod "$POD" -n "$NS" -o json)" && NJSON="$(kubectl get node "$NODE" -o json)" && OJSON="$(kubectl get "$OWNER_RESOURCE" "$OWNER_NAME" -n "$NS" -o json)"; then printf '%s\n' '=== Pod 적용 정책 ==='; jq '{uid:.metadata.uid,resourceVersion:.metadata.resourceVersion,node:.spec.nodeName,podScheduled:[.status.conditions[]?|select(.type=="PodScheduled")|{status,reason,lastTransitionTime}],nodeSelector:.spec.nodeSelector,nodeAffinity:.spec.affinity.nodeAffinity,created:.metadata.creationTimestamp}' <<<"$PJSON"; printf '%s\n' '=== 현재 Node ==='; jq --arg k "$LABEL_KEY" '{uid:.metadata.uid,resourceVersion:.metadata.resourceVersion,ready:[.status.conditions[]?|select(.type=="Ready")|{status,reason,lastTransitionTime}],selectedLabel:.metadata.labels[$k],taints:(.spec.taints//[])}' <<<"$NJSON"; printf '%s\n' '=== Owner 원본 ==='; jq '{uid:.metadata.uid,generation:.metadata.generation,resourceVersion:.metadata.resourceVersion,templateNodeSelector:.spec.template.spec.nodeSelector,templateNodeAffinity:.spec.template.spec.affinity.nodeAffinity}' <<<"$OJSON"; EVIDENCE_READY=true; printf 'EVIDENCE_READY=true key=%s intended=%s window=%s..%s\n' "$LABEL_KEY" "$INTENDED_VALUE" "$START_RFC3339" "$END_RFC3339"; else printf '%s\n' '중단: evidence producer 중 하나가 실패' >&2; fi`

성공은 현재 세 객체의 관계를 확인할 뿐 변경 전 값이나 권위 있는 의도를 증명하지 않는다. 현재 값과 `INTENDED_VALUE`의 차이는 승인된 변경 기록·node pool 계약으로만 해석한다. `preferred` 불일치는 hard 위반이 아니다.

`if [ "$EVIDENCE_READY" != true ] || ! fresh_target; then printf '%s\n' '중단: 최신 evidence gate 실패' >&2; elif EVENTS_JSON="$(kubectl get events -n "$NS" --field-selector "involvedObject.kind=Pod,involvedObject.name=$POD,involvedObject.uid=$POD_UID" -o json)"; then jq -r --argjson s "$START_EPOCH" --argjson e "$END_EPOCH" '.items[] | (.eventTime//.series.lastObservedTime//.lastTimestamp//.firstTimestamp) as $raw | ($raw | strings | sub("\\.[0-9]+Z$";"Z") | fromdateiso8601?) as $t | select($t!=null and $t>=$s and $t<=$e) | [.reason,(.count//1),$raw,.message]|@tsv' <<<"$EVENTS_JSON"; else printf '%s\n' '중단: Event producer 실패; jq filter 미실행' >&2; fi`

빈 Event filter 결과는 오류 없음이나 정책 정상의 증거가 아니다. producer 성공, UID와 evidence window가 일치한 빈 집합일 뿐이다.

## 상태 변경 경계

이 문서는 `kubectl label`, `patch`, `edit`, Pod `delete`, `rollout restart`, `drain`을 제공하지 않는다. label 복구와 workload 정책 수정 중 어느 쪽이 권위 있는지 불명확하면 둘 다 보류한다.

필수 gate: fresh target/evidence, 승인된 변경 window, 다른 tenant의 label 의존성, PDB·quorum·Ready·Endpoint baseline, 변경 멱등성, 검증된 이전 node pool/workload revision rollback이다. 새 Pending·잘못된 node 배치·Ready 감소·서비스 오류가 보이면 중단한다.

`APPROVAL_ID='PASTE_LABEL_DRIFT_APPROVAL_ID_HERE'; CHANGE_READY=false; if [ "$EVIDENCE_READY" != true ] || ! fresh_target; then printf '%s\n' '중단: fresh evidence가 아니다.' >&2; elif [ -z "$APPROVAL_ID" ]; then printf '%s\n' '중단: 승인 ID 필요' >&2; else CHANGE_READY=true; export APPROVAL_ID; printf 'CHANGE_READY=true relation=%s key=%s intended=%s approval=%s\n' "$RELATION" "$LABEL_KEY" "$INTENDED_VALUE" "$APPROVAL_ID"; fi`

이 명령은 mutation이 아니라 승인 기록 gate다. 실제 mutation과 rollback은 동일 fresh identity를 다시 확인하는 승인된 GitOps/node pool 절차에서 수행한다. 승인 ID는 변경 시도마다 고유해야 한다.

`CHANGE_RFC3339='PASTE_LABEL_DRIFT_CHANGE_UTC_HERE'; unset CHANGE_TIME_READY CHANGE_EPOCH CHANGE_GATE_APPROVAL REPLACEMENT_READY NORMAL_READY; CHANGE_TIME_READY=false; RFC3339_RE='^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$'; if [ "$CHANGE_READY" != true ] || ! fresh_target; then printf '%s\n' '중단: fresh change gate 실패' >&2; elif [[ ! "$CHANGE_RFC3339" =~ $RFC3339_RE ]] || ! CHANGE_EPOCH="$(date -u -d "$CHANGE_RFC3339" +%s 2>/dev/null)" || [ "$(date -u -d "@$CHANGE_EPOCH" '+%Y-%m-%dT%H:%M:%SZ')" != "$CHANGE_RFC3339" ] || [ "$CHANGE_EPOCH" -lt "$END_EPOCH" ] || [ "$CHANGE_EPOCH" -gt "$(date -u +%s)" ]; then printf '%s\n' '중단: 변경 시각 canonical/round-trip/evidence 이후 조건 실패' >&2; else CHANGE_GATE_APPROVAL="$APPROVAL_ID"; CHANGE_TIME_READY=true; export CHANGE_RFC3339 CHANGE_EPOCH CHANGE_GATE_APPROVAL; printf 'CHANGE_TIME_READY=true approval=%s change=%s\n' "$CHANGE_GATE_APPROVAL" "$CHANGE_RFC3339"; fi`

## replacement 재등록과 정상화

`NEW_POD='PASTE_LABEL_DRIFT_REPLACEMENT_POD_HERE'; unset REPLACEMENT_READY NORMAL_READY NEW_POD_UID NEW_POD_RV NEW_NODE NEW_NODE_UID NEW_CREATED; REPLACEMENT_READY=false; printf 'replacement 입력 등록 pod=%s; 최종 gate 전 READY 아님\n' "$NEW_POD"`

위 command는 이름만 입력하고 READY를 만들지 않는다. 다음 current owner·변경 시각·Node UID gate가 최종값을 다시 등록한다.

`REPLACEMENT_READY=false; unset NEW_NODE_UID; if [ "$CHANGE_TIME_READY" != true ] || [ "$CHANGE_GATE_APPROVAL" != "$APPROVAL_ID" ]; then printf '%s\n' '중단: current change-time/approval gate 실패' >&2; elif CANDIDATES="$(kubectl get pods -n "$NS" -l "$OWNER_SELECTOR" -o json)" && OJSON="$(kubectl get "$OWNER_RESOURCE" "$OWNER_NAME" -n "$NS" -o json)" && [ "$(jq --arg p "$NEW_POD" '[.items[]|select(.metadata.name==$p)]|length' <<<"$CANDIDATES")" -eq 1 ]; then NP="$(jq -c --arg p "$NEW_POD" '.items[]|select(.metadata.name==$p)' <<<"$CANDIDATES")"; NEW_NODE="$(jq -r '.spec.nodeName//empty' <<<"$NP")"; if [ -n "$NEW_NODE" ] && NJSON="$(kubectl get node "$NEW_NODE" -o json)"; then NEW_POD_UID="$(jq -r '.metadata.uid' <<<"$NP")"; NEW_POD_RV="$(jq -r '.metadata.resourceVersion' <<<"$NP")"; NEW_CREATED="$(jq -r '.metadata.creationTimestamp' <<<"$NP")"; NEW_NODE_UID="$(jq -r '.metadata.uid' <<<"$NJSON")"; if [ "$(jq -r '.metadata.uid' <<<"$OJSON")" = "$OWNER_UID" ] && [ "$(jq -r '[.metadata.ownerReferences[]?|select(.controller==true)][0].uid//empty' <<<"$NP")" = "$OWNER_UID" ] && [ "$(date -u -d "$NEW_CREATED" +%s)" -ge "$CHANGE_EPOCH" ]; then REPLACEMENT_READY=true; export NEW_POD NEW_POD_UID NEW_POD_RV NEW_NODE NEW_NODE_UID NEW_CREATED; printf 'REPLACEMENT_READY=true pod=%s[%s] node=%s[%s] created=%s\n' "$NEW_POD" "$NEW_POD_UID" "$NEW_NODE" "$NEW_NODE_UID" "$NEW_CREATED"; else printf '%s\n' '중단: current owner/node/change-time relation 불일치' >&2; fi; else printf '%s\n' '중단: replacement Node 조회 실패' >&2; fi; else printf '%s\n' '중단: replacement/current owner producer 실패' >&2; fi`

`NORMAL_READY=false; if [ "$REPLACEMENT_READY" != true ] || ! NP="$(kubectl get pod "$NEW_POD" -n "$NS" -o json)" || ! NN="$(kubectl get node "$NEW_NODE" -o json)" || ! OO="$(kubectl get "$OWNER_RESOURCE" "$OWNER_NAME" -n "$NS" -o json)"; then printf '%s\n' '중단: 정상화 producer 실패' >&2; elif [ "$(jq -r '.metadata.uid' <<<"$NP")" != "$NEW_POD_UID" ] || [ "$(jq -r '.metadata.uid' <<<"$NN")" != "$NEW_NODE_UID" ] || [ "$(jq -r '.metadata.uid' <<<"$OO")" != "$OWNER_UID" ] || [ "$(jq -r '[.metadata.ownerReferences[]?|select(.controller==true)][0].uid//empty' <<<"$NP")" != "$OWNER_UID" ]; then printf '%s\n' '중단: replacement current identity 불일치' >&2; elif [ "$(jq -r --arg k "$LABEL_KEY" '.metadata.labels[$k]//empty' <<<"$NN")" = "$INTENDED_VALUE" ] && [ "$(jq -r '.status.phase' <<<"$NP")" = Running ] && jq -e '(.status.containerStatuses|length)>0 and all(.status.containerStatuses[];.ready==true and (.containerID//"")!="")' <<<"$NP" >/dev/null; then NEW_POD_RV="$(jq -r '.metadata.resourceVersion' <<<"$NP")"; NORMAL_READY=true; printf 'NORMAL_READY=true pod=%s[%s] node=%s[%s] label=%s containerIDs=%s\n' "$NEW_POD" "$NEW_POD_UID" "$NEW_NODE" "$NEW_NODE_UID" "$INTENDED_VALUE" "$(jq -r '[.status.containerStatuses[].containerID]|sort|join(",")' <<<"$NP")"; else printf '%s\n' '중단: label/policy 또는 container Running/Ready 미수렴' >&2; fi`

`NORMAL_READY=true` 뒤 owner generation/Ready/available, 새 Warning·FailedScheduling 부재, EndpointSlice의 새 Pod endpoint와 실제 요청·Job 결과를 관찰 창 동안 확인한다. label 일치나 `Running`만으로 정상화하지 않는다.

## Prometheus 빠른 관측

`if [ "$EVIDENCE_READY" != true ] || ! fresh_target; then printf '%s\n' '중단: 최신 evidence gate 실패' >&2; else printf 'kube_pod_info{namespace="%s",pod="%s",uid="%s"}\n' "$NS" "$POD" "$POD_UID"; printf 'kube_node_labels{node="%s"}\n' "$NODE"; fi`

metric이 비면 0이 아니다. kube-state-metrics 미수집, label allowlist, cluster 범위, scrape 실패를 구분한다. `kube_node_labels`는 변경 전 값·주체·시각이나 Pod affinity 식을 보존하지 않으므로 mutation 방향을 결정하지 못한다.

## 증거 보존과 환경별 미검증

실행 host, UTC window, Pod/owner/Node UID·resourceVersion·containerID·관계·생성 시각, 현재/owner placement 정책, label key의 현재값과 승인 의도값, 변경 기록, UID 제한 Event, 승인·rollback, replacement 단일 후보와 실제 기능을 보존한다. Secret·token·개인키·전체 YAML·불필요한 annotation은 저장하지 않는다.

node pool label 공급자, admission 변경, DaemonSet 재조정, PDB·quorum, 서비스 endpoint와 실제 Kubernetes 1.26 결과는 환경별 미검증이다. 실제 인프라 명령은 실행하지 않았다.
