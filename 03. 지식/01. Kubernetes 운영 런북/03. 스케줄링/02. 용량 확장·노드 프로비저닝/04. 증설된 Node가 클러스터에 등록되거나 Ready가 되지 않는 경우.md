# 증설된 Node가 클러스터에 등록되거나 Ready가 되지 않는 경우

## 입력값과 빠른 수집

실행 경로는 `승인된 작업 PC/Bash → Kubernetes API → Node·Lease`와, 조건부로 `작업 PC → SSH → provisioning record가 가리키는 host → kubelet journal`이다. 두 경로의 성공은 서로를 보장하지 않는다.

| 구분 | 값 | 출처와 gate |
|---|---|---|
| 최초 입력 | `PROVISIONING_ID`, `NODE` | 승인된 provisioning record의 ID와 exact Node mapping |
| API 확인 자동값 | `NODE_UID`, `NODE_RV`, `PROVIDER_ID`, `READY_STATUS`, `LEASE_UID`, `LEASE_RV` | 현재 API 응답이 모두 성공한 경우에만 등록 |
| 계산 후보값 | `NODE_RE`, `NODE_LABEL` | 현재 Node 이름을 regex/label용으로 escape; 외부 쿼리 전 출력 확인 |
| 운영자 선택값 | `SSH_HOST`, `REMOTE_HOSTNAME`, `EXPECTED_MACHINE_ID`, `START_RFC3339`, `END_RFC3339` | host 조사가 필요한 경우 승인된 record·접근 경로와 장애 창에서 선택 |

`NODE`가 아직 없으면 정상으로 간주하지 않되, 존재하지 않는 Node의 UID·Lease·host 관계를 만들지 않는다. bootstrap token, kubeconfig, 인증서·개인키, user-data 원문은 출력하거나 보존하지 않는다.

### 1. 도구와 최초 입력

`TOOLS_READY=false; MISSING=''; [ -n "${BASH_VERSION:-}" ] || MISSING="$MISSING bash"; for T in kubectl jq sed date ssh mktemp grep; do command -v "$T" >/dev/null 2>&1 || MISSING="$MISSING $T"; done; if [ -z "$MISSING" ]; then TOOLS_READY=true; printf 'TOOLS_READY=true\n'; else printf '중단: 없는 도구=%s\n' "$MISSING" >&2; fi`

`unset HOST_ID_READY EXPECTED_MACHINE_ID`

`unset INPUT_READY AUTO_READY QUERY_READY HOST_READY TIME_READY NODE_UID NODE_RV PROVIDER_ID READY_STATUS READY_REASON READY_TRANSITION LEASE_UID LEASE_RV LEASE_RENEW NODE_RE NODE_LABEL SSH_HOST REMOTE_HOSTNAME START_RFC3339 END_RFC3339; NODE_PRESENT=false; PROVISIONING_ID='PASTE_PROVISIONING_ID_HERE'; NODE='PASTE_EXPECTED_NODE_HERE'; INPUT_READY=false; if [ "$TOOLS_READY" = true ] && [ -n "$PROVISIONING_ID" ] && [ -n "$NODE" ]; then INPUT_READY=true; export PROVISIONING_ID NODE; printf 'INPUT_READY=true provisioning=%s node=%s\n' "$PROVISIONING_ID" "$NODE"; else printf '%s\n' '중단: 도구와 최초 입력을 확인한다.' >&2; fi`

재등록 명령은 Node/Lease identity, resourceVersion, owner·containerID·실행 node·host 관계, 시간·argv/regex 및 모든 downstream `READY`를 먼저 무효화한다. API가 실패하면 이전 값은 절대 사용하지 않는다.

### 2. Node와 Lease 자동 등록

`unset HOST_ID_READY EXPECTED_MACHINE_ID`

`unset AUTO_READY QUERY_READY HOST_READY TIME_READY NODE_UID NODE_RV PROVIDER_ID READY_STATUS READY_REASON READY_TRANSITION LEASE_UID LEASE_RV LEASE_RENEW NODE_RE NODE_LABEL SSH_HOST REMOTE_HOSTNAME START_RFC3339 END_RFC3339; NODE_PRESENT=false; AUTO_READY=false; if [ "$INPUT_READY" != true ]; then printf '%s\n' '중단: INPUT_READY가 아니다.' >&2; elif NODE_JSON="$(kubectl get node "$NODE" --ignore-not-found -o json)"; then if [ -z "$NODE_JSON" ]; then AUTO_READY=true; printf 'AUTO_READY=true NODE_PRESENT=false node=%s provisioning=%s\n' "$NODE" "$PROVISIONING_ID"; elif LEASE_JSON="$(kubectl get lease "$NODE" -n kube-node-lease -o json)"; then NODE_UID="$(jq -er '.metadata.uid' <<<"$NODE_JSON")" && NODE_RV="$(jq -er '.metadata.resourceVersion' <<<"$NODE_JSON")" && PROVIDER_ID="$(jq -r '.spec.providerID // empty' <<<"$NODE_JSON")" && READY_STATUS="$(jq -er '[.status.conditions[]? | select(.type=="Ready")][0].status' <<<"$NODE_JSON")" && READY_REASON="$(jq -r '[.status.conditions[]? | select(.type=="Ready")][0].reason // "-"' <<<"$NODE_JSON")" && READY_TRANSITION="$(jq -er '[.status.conditions[]? | select(.type=="Ready")][0].lastTransitionTime' <<<"$NODE_JSON")" && LEASE_UID="$(jq -er '.metadata.uid' <<<"$LEASE_JSON")" && LEASE_RV="$(jq -er '.metadata.resourceVersion' <<<"$LEASE_JSON")" && LEASE_RENEW="$(jq -er '.spec.renewTime' <<<"$LEASE_JSON")" && NODE_RE="$(printf '%s' "$NODE" | sed 's/[][\\.^$*+?(){}|]/\\&/g')" && NODE_LABEL="$(printf '%s' "$NODE" | sed 's/\\/\\\\/g;s/"/\\"/g')" && NODE_PRESENT=true && AUTO_READY=true && export NODE_UID NODE_RV PROVIDER_ID READY_STATUS READY_REASON READY_TRANSITION LEASE_UID LEASE_RV LEASE_RENEW NODE_RE NODE_LABEL; if [ "$AUTO_READY" = true ]; then printf 'AUTO_READY=true NODE_PRESENT=true\nNode: %s\nNode UID/RV: %s / %s\nProvider ID: %s\nReady: %s / %s / %s\nLease UID/RV/renew: %s / %s / %s\n' "$NODE" "$NODE_UID" "$NODE_RV" "${PROVIDER_ID:--}" "$READY_STATUS" "$READY_REASON" "$READY_TRANSITION" "$LEASE_UID" "$LEASE_RV" "$LEASE_RENEW"; else printf '%s\n' '중단: Node 또는 Lease 필수 필드가 비었음' >&2; fi; else printf '%s\n' '중단: Lease API 실패; stale 값 사용 금지' >&2; fi; else printf '%s\n' '중단: Node API 실패; 부재로 해석하지 않음' >&2; fi`

`NODE_PRESENT=false`이면 provisioning record의 instance identity, provider 상태, expected Node mapping, bootstrap 시작과 registration 요청 결과를 record owner에게 확인한다. API 403·timeout은 Node 부재가 아니며 RBAC 또는 API 경로로 분기한다. `NODE_PRESENT=true`이면 Node UID·providerID가 record와 exact match인지 확인하고, 다르면 Ready 여부와 무관하게 provisioning/template owner에게 이관한다.

**현재 Node·Lease identity 재검증 함수 등록**

`require_current_target(){ local n l; [ "$AUTO_READY" = true ] || { printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; return 1; }; n="$(kubectl get node "$NODE" --ignore-not-found -o json)" || { printf '%s\n' '중단: Node API 재조회 실패' >&2; return 1; }; if [ "$NODE_PRESENT" = false ]; then [ -z "$n" ] || { printf '%s\n' '중단: Node가 새로 등록됨; 자동 등록을 다시 실행한다.' >&2; return 1; }; return 0; fi; [ -n "$n" ] && [ "$(jq -r '.metadata.uid' <<<"$n")" = "$NODE_UID" ] || { printf '%s\n' '중단: Node UID 변경; 재등록 필요' >&2; return 1; }; l="$(kubectl get lease "$NODE" -n kube-node-lease -o json)" || { printf '%s\n' '중단: Lease API 재조회 실패' >&2; return 1; }; [ "$(jq -r '.metadata.uid' <<<"$l")" = "$LEASE_UID" ] && [ "$(jq -r '.spec.holderIdentity' <<<"$l")" = "$NODE" ] || { printf '%s\n' '중단: Lease identity 변경; 재등록 필요' >&2; return 1; }; }`

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | record상 인스턴스가 생성됐지만 Node가 없거나 현재 Node의 `Ready!=True` |
| 적용 | record identity → Node UID/providerID → Ready condition → Lease의 현재 관계를 검증할 수 있음 |
| 제외 | `Ready=True`이면 [[05. 증설된 Node가 Ready지만 Pod가 계속 FailedScheduling인 경우]], 일반 Pod 배치 실패면 [[18. Pod 이벤트에 FailedScheduling이 기록된 경우]] |

검색 문자열: `KubeletNotReady`, `NodeStatusUnknown`, `NetworkUnavailable`, `renewTime`, `providerID`, `bootstrap`, `registration`.

## 관측별 진단 경로

| 지금 보이는 것 | 직접 근거 | 다음 경계 |
|---|---|---|
| Node 객체 없음 | 성공한 exact-name 조회의 빈 결과와 active record | bootstrap/registration owner |
| `Ready=False`와 Lease 최신 | 현재 UID의 reason/message·Lease renew | kubelet/runtime/CNI owner |
| `Ready=Unknown`과 Lease 정체 | heartbeat·transition·renew의 시간관계 | node↔API/host owner |
| providerID 불일치 | record identity와 현재 UID/providerID | provisioning template owner |

## 현재 객체 상세 확인

`if [ "$NODE_PRESENT" != true ] || ! require_current_target; then printf '%s\n' '중단: 현재 Node/Lease identity가 필요하다.' >&2; else kubectl get node "$NODE" -o json | jq -er --arg uid "$NODE_UID" 'select(.metadata.uid==$uid) | "=== Node ===\n이름: \(.metadata.name)\nUID/RV: \(.metadata.uid) / \(.metadata.resourceVersion)\nProviderID: \(.spec.providerID // "-")\n" + ([.status.conditions[] | "\(.type): \(.status) reason=\(.reason // "-") heartbeat=\(.lastHeartbeatTime // "-") transition=\(.lastTransitionTime // "-") message=\(.message // "-")"] | join("\n"))'; fi`

성공 gate는 출력 UID가 `$NODE_UID`와 같고 Ready·pressure·NetworkUnavailable condition이 모두 현재 응답에서 나온 것이다. `Ready=False`는 kubelet이 비정상을 보고했다는 범위, `Unknown`은 controller가 상태를 확정하지 못했다는 범위다. 어느 것도 process 종료를 단독 증명하지 않는다.

## 조건부 host 확인

host journal은 record의 instance identity와 SSH target·원격 hostname 관계가 승인됐을 때만 사용한다. `SSH_HOST`는 접속 endpoint, `REMOTE_HOSTNAME`은 원격에서 다시 확인할 host identity다.

`SSH_HOST='PASTE_APPROVED_SSH_HOST_HERE'; REMOTE_HOSTNAME='PASTE_REMOTE_HOSTNAME_HERE'; START_RFC3339='PASTE_START_RFC3339_HERE'; END_RFC3339='PASTE_END_RFC3339_HERE'; TIME_READY=false; HOST_READY=false; if ! require_current_target; then printf '%s\n' '중단: current target identity가 필요하다.' >&2; elif [[ ! "$START_RFC3339" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] || [[ ! "$END_RFC3339" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]]; then printf '%s\n' '중단: UTC RFC3339 형식이 아님' >&2; elif START_EPOCH="$(date -u -d "$START_RFC3339" +%s)" && END_EPOCH="$(date -u -d "$END_RFC3339" +%s)" && [ "$(date -u -d "@$START_EPOCH" +%Y-%m-%dT%H:%M:%SZ)" = "$START_RFC3339" ] && [ "$(date -u -d "@$END_EPOCH" +%Y-%m-%dT%H:%M:%SZ)" = "$END_RFC3339" ] && [ "$START_EPOCH" -lt "$END_EPOCH" ]; then TIME_READY=true; export SSH_HOST REMOTE_HOSTNAME START_RFC3339 END_RFC3339; printf 'TIME_READY=true start=%s end=%s\n' "$START_RFC3339" "$END_RFC3339"; else printf '%s\n' '중단: date round-trip 또는 start<end 실패' >&2; fi`

`EXPECTED_MACHINE_ID='PASTE_APPROVED_MACHINE_ID_HERE'; HOST_ID_READY=false; if ! require_current_target; then printf '%s\n' '중단: current target identity가 필요하다.' >&2; elif [[ ! "$EXPECTED_MACHINE_ID" =~ ^[0-9a-f]{32}$ ]]; then printf '%s\n' '중단: provisioning record의 32자리 machine ID가 필요하다.' >&2; elif [ "$NODE_PRESENT" = true ] && { ! CURRENT_NODE_JSON="$(kubectl get node "$NODE" -o json)" || [ "$(jq -r '.metadata.uid' <<<"$CURRENT_NODE_JSON")" != "$NODE_UID" ] || [ "$(jq -r '.status.nodeInfo.machineID' <<<"$CURRENT_NODE_JSON")" != "$EXPECTED_MACHINE_ID" ]; }; then printf '%s\n' '중단: Node UID/machineID와 provisioning record 불일치' >&2; else HOST_ID_READY=true; export EXPECTED_MACHINE_ID; printf 'HOST_ID_READY=true machine_id=%s\n' "$EXPECTED_MACHINE_ID"; fi`

```bash
if [ "$TIME_READY" != true ] || [ "$HOST_ID_READY" != true ] || ! require_current_target; then printf '%s\n' '중단: current target·TIME·HOST_ID gate가 필요하다.' >&2; else HOST_READY=false; if ssh -- "$SSH_HOST" bash -s -- "$REMOTE_HOSTNAME" "$EXPECTED_MACHINE_ID" "$START_RFC3339" "$END_RFC3339" <<'REMOTE'
set -o nounset
expected=$1
expected_machine=$2
start=$3
end=$4
actual=$(hostname -f 2>/dev/null || hostname)
[ "$actual" = "$expected" ] || { printf '중단: 원격 host 불일치 expected=%s actual=%s\n' "$expected" "$actual" >&2; exit 20; }
[ -f /etc/machine-id ] && [ -r /etc/machine-id ] || { printf '%s\n' '중단: /etc/machine-id를 읽을 수 없음' >&2; exit 21; }
IFS= read -r actual_machine </etc/machine-id
[ "$actual_machine" = "$expected_machine" ] || { printf '중단: machine-id 불일치 expected=%s actual=%s\n' "$expected_machine" "$actual_machine" >&2; exit 22; }
[ "$(ps -p 1 -o comm=)" = systemd ] || { printf '%s\n' '중단: 원격 init이 systemd가 아님' >&2; exit 23; }
tmp=$(mktemp) || exit 24
trap 'rm -f "$tmp"' EXIT
if ! journalctl -u kubelet --since "$start" --until "$end" --no-pager >"$tmp"; then printf '%s\n' 'producer 오류: journalctl 실패' >&2; exit 25; fi
if grep -E -i -C 3 'register|node status|lease|KubeletNotReady|NetworkUnavailable|timeout|refused|x509|unauthorized|forbidden|runtime|cni' "$tmp"; then exit 0; else rc=$?; [ "$rc" -eq 1 ] && { printf '%s\n' 'filter no-match: 같은 창의 bounded 원문을 owner가 검토' >&2; exit 26; }; printf 'filter 오류: grep rc=%s\n' "$rc" >&2; exit 27; fi
REMOTE
then HOST_READY=true; printf 'HOST_READY=true host=%s\n' "$REMOTE_HOSTNAME"; else printf '%s\n' '중단: 원격 identity/journal gate 실패' >&2; fi; fi
```

SSH 대상은 옵션 뒤 positional argument로 전달하고, 원격에서는 `$1..$4`로만 받는다. `eval`, 문자열 명령 조립, host key 검증 우회는 금지한다. journal 시간 창은 Node condition/Lease와 겹쳐야 하며 필터 no-match는 오류 부재가 아니다. 실제 kubelet unit이 `kubelet`이 아니면 위 명령을 실행하지 말고 node owner가 확인한 unit의 전용 런북으로 이관한다.

CRI를 직접 조사해야 하면 [[04. 노드·런타임/03. 컨테이너 런타임·CRI 이상/02. CRI endpoint 연결이 거부되거나 timeout인 경우]]로 이관한다. active kubelet 설정에서 endpoint 후보가 정확히 하나이고, runtime socket provider와 exact match하며, 현재 host identity가 다시 확인되기 전에는 `crictl`을 실행하지 않는다.

## Prometheus 쿼리 생성

`QUERY_READY=false; if [ "$NODE_PRESENT" != true ] || ! require_current_target; then printf '%s\n' '중단: 현재 Node identity가 없다.' >&2; else QUERY_READY=true; printf 'kube_node_status_condition{node="%s",condition="Ready",status=~"false|unknown"} == 1\n' "$NODE_LABEL"; printf 'time()-kube_lease_renew_time{namespace="kube-node-lease",lease="%s"}\n' "$NODE_LABEL"; fi`

출력 완성본만 승인된 Prometheus/Grafana에서 같은 cluster와 시간 창으로 조회한다. 빈 결과는 정상이나 Node 부재가 아니라 metric 미수집, label 불일치, 조회 범위 오류 후보이고, HTTP/API 실패와 분리한다. metric은 현재 Node UID를 label로 보장하지 않으므로 API identity를 대체하지 않는다.

## 복구 전 gate와 정상화

이 런북은 mutation 명령을 제공하지 않는다. 재프로비저닝, Node 삭제, kubelet/runtime restart, 인증서 교체는 읽기 진단과 분리된 승인 절차에서만 수행한다. 그 절차는 실행 직전에 fresh provisioning record ID·template/spec/revision, Node UID/RV/providerID, owner, 영향 workload selector·PDB·quorum, image digest, evidence 시간 창, 승인 ID, 변경 창, 멱등성·중복 instance 위험과 rollback을 직접 gate해야 한다. API 실패 또는 identity 변경 시 승인은 무효다.

변경 후에는 replacement Node 이름만 재사용하지 말고 이 문서의 등록 절차를 처음부터 실행해 새 UID/RV/providerID·Lease UID/RV와 record 관계를 재등록한다. 정상화는 `record 성공 → Node exact identity → Ready=True → Lease 연속 갱신 → 예상 taint/label·allocatable → 원래 workload의 placement/Ready → 실제 서비스 기능` 순으로 확인한다. rollback도 같은 역순 검증과 관찰 창을 통과해야 하며, Ready 한 번이나 새 Node 생성만으로 닫지 않는다.

## 증거와 근거

UTC 수집 창, provisioning ID, 비민감 instance identity, Node name·UID/RV/providerID, Ready/pressure/network condition, Lease UID/RV/renewTime, 원격 hostname과 bounded 오류 행, 승인·replacement·실제 서비스 결과만 보존한다. RBAC은 `nodes get`, `leases.coordination.k8s.io get`과 필요한 경우 승인된 node journal 접근으로 제한한다. audit 조회는 별도 `audit` 권한과 보존 정책이 확인된 담당자에게 요청하며, 이 런북이 권한을 부여하지 않는다.
