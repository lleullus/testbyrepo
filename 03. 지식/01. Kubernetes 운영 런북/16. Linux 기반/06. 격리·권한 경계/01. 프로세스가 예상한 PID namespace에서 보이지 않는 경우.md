# 프로세스가 예상한 PID namespace에서 보이지 않는 경우

## 입력값과 빠른 수집

실행 hop은 `승인된 작업 PC/Bash → Kubernetes API`와 `작업 PC/Bash → SSH → 대상 Node host namespace → active kubelet endpoint → CRI socket provider → current container host PID → /proc PID namespace`다. 선택적으로 `작업 PC/Bash → API server → kubelet → current container exec → container PID namespace`를 사용한다. 작업 PC 변수는 SSH에 자동 전달되지 않으므로 모두 positional argument로 전달하며 원격에서 machine-id·boot ID를 다시 확인한다.

| 구분 | 값 | 계약 |
|---|---|---|
| 최초 입력 | `NS`, `POD`, `CONTAINER`, `SSH_DEST`, `EXPECTED_MACHINE_ID` | 승인된 namespace·Pod·regular/init container와 Node 접속 identity |
| API 확인 자동값 | `POD_UID`, current `POD_RV`, owner kind/name/UID, `NODE`, `NODE_UID`, `SYSTEM_UUID`, `HOST_BOOT_ID`, current `CONTAINER_ID`, `CONTAINER_KIND` | Pod·owner·Node API와 원격 host identity가 모두 맞을 때만 등록 |
| 계산 후보값 | active kubelet의 `CRI_ENDPOINT`, socket path | active kubelet argv 또는 엄격히 검증한 config에서 계산하며 socket provider 확인 전 미확정 |
| 운영자 선택값 | 없음 | host PID·namespace PID·inode는 CRI와 `/proc`에서 자동 관측하며 이름으로 추측하지 않음 |

각 고유 `PASTE_..._HERE` 입력칸은 문서에서 한 번만 사용한다. 이 절이나 snapshot을 재실행하면 과거 resourceVersion, owner, container ID, endpoint, provider PID, host PID/start ticks, namespace PID/inode와 모든 downstream READY를 먼저 폐기한다.

### 1. 대상·owner·container·Node identity 등록

```bash
TOOLS_READY=false; TARGET_READY=false; FRESH_READY=false; SNAPSHOT_READY=false; EXEC_READY=false
unset POD_UID POD_RV CURRENT_POD_RV OWNER_KIND OWNER_NAME OWNER_UID OWNER_RV CURRENT_OWNER_RV NODE NODE_UID NODE_RV CURRENT_NODE_RV SYSTEM_UUID API_BOOT_ID HOST_BOOT_ID HOST_FQDN RUNTIME_VERSION CONTAINER_KIND CONTAINER_ID CONTAINER_ID_SCHEME CONTAINER_OPAQUE_ID CONTAINER_STATE CRI_ENDPOINT CRI_SOCKET ENDPOINT_SOURCE KUBELET_PID KUBELET_START_TICKS PROVIDER_PID PROVIDER_START_TICKS PROVIDER_EXE PROVIDER_UNIT HOST_PID HOST_PID_START_TICKS PID_NS_INODE NSPID_VALUES NS_PID SNAPSHOT_AT EXEC_OUT
SSH_OPTS=(-o BatchMode=yes -o ConnectTimeout=10 -o StrictHostKeyChecking=yes -o LogLevel=ERROR)
NS='PASTE_PIDNS_NAMESPACE_HERE'
POD='PASTE_PIDNS_POD_HERE'
CONTAINER='PASTE_PIDNS_CONTAINER_HERE'
SSH_DEST='PASTE_PIDNS_SSH_DEST_HERE'
EXPECTED_MACHINE_ID='PASTE_PIDNS_MACHINE_ID_HERE'
MISSING=''; for tool in kubectl jq ssh; do command -v "$tool" >/dev/null 2>&1 || MISSING="$MISSING $tool"; done
if [ -z "${BASH_VERSION:-}" ] || [ -n "$MISSING" ] || [ -z "$NS" ] || [ -z "$POD" ] || [ -z "$CONTAINER" ] || [[ ! "$SSH_DEST" =~ ^[A-Za-z0-9][A-Za-z0-9._@:-]*$ ]] || [[ ! "$EXPECTED_MACHINE_ID" =~ ^[0-9a-f]{32}$ ]]; then
  printf '중단: Bash/도구/입력 gate 실패:%s\n' "$MISSING" >&2

    NODE_JSON="$(kubectl get node "$NODE" -o json)"; NODE_RC=$?
    if [ "$NODE_RC" -eq 0 ]; then NODE_UID="$(jq -r '.metadata.uid // empty' <<<"$NODE_JSON")"; NODE_RV="$(jq -r '.metadata.resourceVersion // empty' <<<"$NODE_JSON")"; SYSTEM_UUID="$(jq -r '.status.nodeInfo.systemUUID // empty' <<<"$NODE_JSON")"; API_BOOT_ID="$(jq -r '.status.nodeInfo.bootID // empty' <<<"$NODE_JSON")"; RUNTIME_VERSION="$(jq -r '.status.nodeInfo.containerRuntimeVersion // empty' <<<"$NODE_JSON")"; fi
    HOST_OUT="$(ssh "${SSH_OPTS[@]}" -- "$SSH_DEST" sh -s -- "$EXPECTED_MACHINE_ID" <<'REMOTE'
set -eu

    [ "$SSH_RC" -eq 0 ] && IFS=$'\t' read -r ACTUAL_MACHINE_ID HOST_BOOT_ID HOST_FQDN <<<"$HOST_OUT"

    unset POD_UID POD_RV OWNER_KIND OWNER_NAME OWNER_UID OWNER_RV NODE NODE_UID NODE_RV SYSTEM_UUID API_BOOT_ID HOST_BOOT_ID HOST_FQDN RUNTIME_VERSION CONTAINER_KIND CONTAINER_ID CONTAINER_ID_SCHEME CONTAINER_OPAQUE_ID CONTAINER_STATE
    printf '중단: Pod/owner/Node/container/remote identity 생산 실패 pod_rc=%s node_rc=%s ssh_rc=%s\n' "${POD_RC:-not-run}" "${NODE_RC:-not-run}" "${SSH_RC:-not-run}" >&2
  else
    TARGET_READY=true
    printf 'TARGET_READY=true\nNamespace: %s\nPod: %s\nPod UID: %s\nPod resourceVersion: %s\nOwner: %s/%s UID=%s resourceVersion=%s\nContainer: %s/%s ID=%s state=%s\nNode: %s UID=%s resourceVersion=%s systemUUID=%s\nMachine ID: %s\nBoot ID: %s\nRuntime: %s\nRemote host: %s\n' "$NS" "$POD" "$POD_UID" "$POD_RV" "$OWNER_KIND" "$OWNER_NAME" "$OWNER_UID" "$OWNER_RV" "$CONTAINER_KIND" "$CONTAINER" "$CONTAINER_ID" "$CONTAINER_STATE" "$NODE" "$NODE_UID" "$NODE_RV" "$SYSTEM_UUID" "$EXPECTED_MACHINE_ID" "$HOST_BOOT_ID" "$RUNTIME_VERSION" "$HOST_FQDN"
  fi
fi
unset POD_JSON OWNER_JSON NODE_JSON HOST_OUT ACTUAL_MACHINE_ID STATUS_PATH RUNTIME_FAMILY OWNER_COUNT POD_RC OWNER_RC NODE_RC SSH_RC
```

`TARGET_READY=true`는 exact Pod UID와 current resourceVersion, controller owner UID, container kind/name/current container ID, Node UID/systemUUID, API·remote boot ID와 승인 machine-id가 연결됐다는 뜻이다. container가 재시작하거나 Pod·Node가 교체되면 이름이 같아도 이전 PID·inode 증거를 재사용하지 않는다. `regular`과 `init`은 별도 status 배열에서 읽으며 종료된 init container를 현재 regular container처럼 취급하지 않는다.

### 2. 모든 후속 명령의 current API gate

```bash
invalidate_pidns() { FRESH_READY=false; SNAPSHOT_READY=false; EXEC_READY=false; unset CURRENT_POD_RV CURRENT_OWNER_RV CURRENT_NODE_RV CRI_ENDPOINT CRI_SOCKET ENDPOINT_SOURCE KUBELET_PID KUBELET_START_TICKS PROVIDER_PID PROVIDER_START_TICKS PROVIDER_EXE PROVIDER_UNIT HOST_PID HOST_PID_START_TICKS PID_NS_INODE NSPID_VALUES NS_PID SNAPSHOT_AT EXEC_OUT; }
assert_api_current() {
  local p n o rc kind id state count ok=true
  FRESH_READY=false; unset CURRENT_POD_RV CURRENT_OWNER_RV CURRENT_NODE_RV
  [ "$TARGET_READY" = true ] || { printf '%s\n' '중단: TARGET_READY가 아니다.' >&2; return 1; }
  p="$(kubectl get pod "$POD" -n "$NS" -o json)"; rc=$?; [ "$rc" -eq 0 ] || ok=false
  n="$(kubectl get node "$NODE" -o json)"; rc=$?; [ "$rc" -eq 0 ] || ok=false
  if [ "$ok" = true ]; then
    kind="$(jq -r --arg c "$CONTAINER" 'if any(.spec.containers[]?; .name==$c) then "regular" elif any(.spec.initContainers[]?; .name==$c) then "init" else empty end' <<<"$p")"
    if [ "$kind" = regular ]; then id="$(jq -r --arg c "$CONTAINER" '.status.containerStatuses[]? | select(.name==$c) | .containerID // empty' <<<"$p")"; state="$(jq -r --arg c "$CONTAINER" '.status.containerStatuses[]? | select(.name==$c) | (.state|keys[0]) // empty' <<<"$p")"; else id="$(jq -r --arg c "$CONTAINER" '.status.initContainerStatuses[]? | select(.name==$c) | .containerID // empty' <<<"$p")"; state="$(jq -r --arg c "$CONTAINER" '.status.initContainerStatuses[]? | select(.name==$c) | (.state|keys[0]) // empty' <<<"$p")"; fi
    count="$(jq '[.metadata.ownerReferences[]? | select(.controller==true)] | length' <<<"$p")"
    [ "$(jq -r '.metadata.uid // empty' <<<"$p")" = "$POD_UID" ] || ok=false
    [ "$(jq -r '.spec.nodeName // empty' <<<"$p")" = "$NODE" ] || ok=false
    [ "$kind" = "$CONTAINER_KIND" ] && [ "$id" = "$CONTAINER_ID" ] || ok=false
    [ "$(jq -r '.metadata.uid // empty' <<<"$n")" = "$NODE_UID" ] && [ "$(jq -r '.status.nodeInfo.systemUUID // empty' <<<"$n")" = "$SYSTEM_UUID" ] && [ "$(jq -r '.status.nodeInfo.bootID // empty' <<<"$n")" = "$HOST_BOOT_ID" ] || ok=false
    if [ "$OWNER_KIND" = none ]; then [ "$count" -eq 0 ] || ok=false; CURRENT_OWNER_RV=none; else
      [ "$count" -eq 1 ] && [ "$(jq -r '[.metadata.ownerReferences[] | select(.controller==true)][0].kind // empty' <<<"$p")" = "$OWNER_KIND" ] && [ "$(jq -r '[.metadata.ownerReferences[] | select(.controller==true)][0].name // empty' <<<"$p")" = "$OWNER_NAME" ] && [ "$(jq -r '[.metadata.ownerReferences[] | select(.controller==true)][0].uid // empty' <<<"$p")" = "$OWNER_UID" ] || ok=false
      o="$(kubectl get "$OWNER_KIND" "$OWNER_NAME" -n "$NS" -o json)"; rc=$?; [ "$rc" -eq 0 ] && [ "$(jq -r '.metadata.uid // empty' <<<"$o")" = "$OWNER_UID" ] || ok=false; [ "$ok" = true ] && CURRENT_OWNER_RV="$(jq -r '.metadata.resourceVersion // empty' <<<"$o")"
    fi
  fi
  if [ "$ok" != true ]; then invalidate_pidns; TARGET_READY=false; printf '%s\n' '중단: current Pod/owner/container/Node identity 조회 실패 또는 lifecycle 변경; 1절부터 재등록한다.' >&2; return 1; fi
  CURRENT_POD_RV="$(jq -r '.metadata.resourceVersion // empty' <<<"$p")"; CURRENT_NODE_RV="$(jq -r '.metadata.resourceVersion // empty' <<<"$n")"; CONTAINER_STATE="$state"
  [ -n "$CURRENT_POD_RV" ] && [ -n "$CURRENT_OWNER_RV" ] && [ -n "$CURRENT_NODE_RV" ] || { invalidate_pidns; TARGET_READY=false; printf '%s\n' '중단: current resourceVersion 생산 실패' >&2; return 1; }
  FRESH_READY=true
  printf 'FRESH_READY=true podUID=%s podRV=%s ownerUID=%s ownerRV=%s containerID=%s state=%s nodeUID=%s nodeRV=%s bootID=%s\n' "$POD_UID" "$CURRENT_POD_RV" "$OWNER_UID" "$CURRENT_OWNER_RV" "$CONTAINER_ID" "$CONTAINER_STATE" "$NODE_UID" "$CURRENT_NODE_RV" "$HOST_BOOT_ID"
}
```

API 조회 실패나 `Forbidden`은 대상 부재가 아니다. 이 함수가 실패하면 `TARGET_READY`와 모든 downstream gate가 무효화되므로 snapshot·exec를 계속하지 않는다. 성공해도 host identity와 active endpoint는 각 host 명령에서 다시 검증한다.

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | host에서 관측한 current container process가 예상 PID namespace에서 보이지 않거나 host PID와 namespace PID 관계가 설명되지 않음 |
| 적용 | current Pod UID/resourceVersion·owner·container ID·Node identity와 active kubelet CRI endpoint, socket provider, host PID/start ticks, `NSpid`와 PID namespace inode를 같은 snapshot으로 연결 가능 |
| 제외 | Pod exec streaming 자체 실패는 [[33. Pod exec 연결이 실패하는 경우]], sandbox 생성 실패는 [[24. Pod 이벤트에 FailedCreatePodSandBox가 기록된 경우]], stop/remove 잔류는 [[06. container stop·remove와 sandbox 정리가 완료되지 않는 경우]]로 이동 |

검색 문자열: `PID namespace`, `NSpid`, `ns/pid`, `No such process`, `process not found`, `container ID`, `sandbox`, `runc`, `shim`, `hostPID`, `shareProcessNamespace`.

PID 숫자가 다른 것 자체는 오류가 아니다. host PID와 namespace PID는 서로 다른 PID 계층의 식별자다. current container ID와 process start ticks, `NSpid`, namespace inode가 이어지기 전에는 process 소실이나 격리 손상을 확정하지 않는다.

|---|---|---|---|

| host PID와 namespace PID가 다름 | `NSpid` 계층과 PID namespace inode | 정상 PID translation 여부 | [[#2. container view와 inode 대조|2]] |

| container ID·Pod UID·Node boot ID가 바뀜 | old/new lifecycle identity | stale 증거 폐기 후 새 대상 등록 | [[#3. lifecycle·교체 분기|3]] |
| 다른 Pod/tenant process가 실제로 보임 | 양쪽 Pod UID·container ID와 inode | 보안·runtime owner 즉시 이관 | [[#4. 보안 경계와 상태 변경 금지|4]] |

### 1. active CRI와 host PID snapshot

아래 함수는 매번 API 상태를 fresh 확인한 뒤 대상 Node에서만 `systemctl`, `/proc`, `ss`, `crictl`과 `jq`를 요구한다. active kubelet PID의 NUL 구분 argv에서 `--container-runtime-endpoint`를 읽는다. flag가 없을 때만 active argv의 `--config` 절대경로를 사용하며 regular readable file, top-level key 정확히 하나, nonempty `unix:///absolute/path`를 모두 확인한다. 이 엄격한 fallback에 맞지 않으면 endpoint를 추측하지 않는다.

```bash
pidns_snapshot() {
  local out rc
  invalidate_pidns
  assert_api_current >/dev/null || return 1
  out="$(ssh "${SSH_OPTS[@]}" -- "$SSH_DEST" sudo -n bash -s -- "$EXPECTED_MACHINE_ID" "$HOST_BOOT_ID" "$CONTAINER_OPAQUE_ID" "$NS" "$POD" "$POD_UID" "$CONTAINER" <<'REMOTE'
set -euo pipefail
expected_machine=$1; expected_boot=$2; container_id=$3; ns=$4; pod=$5; pod_uid=$6; container_name=$7
[ "$(cat /etc/machine-id)" = "$expected_machine" ] || exit 42
[ "$(cat /proc/sys/kernel/random/boot_id)" = "$expected_boot" ] || exit 43
for tool in systemctl awk ss crictl jq readlink; do command -v "$tool" >/dev/null 2>&1 || exit 69; done
proc_start() { local raw rest; raw=$(<"/proc/$1/stat") || return 1; rest=${raw##*) }; set -- $rest; printf '%s\n' "${20}"; }
[ "$(systemctl show kubelet.service -p ActiveState --value)" = active ] || exit 70
kubelet_pid=$(systemctl show kubelet.service -p MainPID --value)
[[ "$kubelet_pid" =~ ^[1-9][0-9]*$ ]] && [ -r "/proc/$kubelet_pid/cmdline" ] || exit 71
kubelet_start=$(proc_start "$kubelet_pid")
mapfile -d '' -t argv <"/proc/$kubelet_pid/cmdline"
endpoints=(); configs=()
for ((i=0; i<${#argv[@]}; i++)); do
  case "${argv[$i]}" in
    --container-runtime-endpoint=*) endpoints+=("${argv[$i]#*=}") ;;
    --container-runtime-endpoint) ((i+1<${#argv[@]})) || exit 72; endpoints+=("${argv[$((++i))]}") ;;
    --config=*) configs+=("${argv[$i]#*=}") ;;
    --config) ((i+1<${#argv[@]})) || exit 72; configs+=("${argv[$((++i))]}") ;;
  esac
done
if ((${#endpoints[@]}==1)); then endpoint=${endpoints[0]}; endpoint_source=active-argv
elif ((${#endpoints[@]}==0 && ${#configs[@]}==1)); then
  config=${configs[0]}; [[ "$config" = /* ]] && [ -f "$config" ] && [ -r "$config" ] || exit 73
  endpoint=$(awk '/^containerRuntimeEndpoint:[[:space:]]*/ {n++; v=$0; sub(/^containerRuntimeEndpoint:[[:space:]]*/, "", v); sub(/[[:space:]]+#.*$/, "", v); gsub(/^[[:space:]]+|[[:space:]]+$/, "", v); if(v ~ /^".*"$/) v=substr(v,2,length(v)-2); print v} END {if(n!=1) exit 65}' "$config") || exit $?
  endpoint_source=validated-config
else exit 74; fi
[[ "$endpoint" =~ ^unix:///[^[:space:]#]+$ ]] || exit 75
socket=${endpoint#unix://}; [ -S "$socket" ] || exit 76
ss_out=$(ss -xlpnH); match_count=0; provider_line=''
while IFS= read -r line; do found=false; for field in $line; do [ "$field" = "$socket" ] && found=true; done; if [ "$found" = true ]; then provider_line=$line; match_count=$((match_count+1)); fi; done <<<"$ss_out"
[ "$match_count" -eq 1 ] || exit 77
[[ "$provider_line" =~ pid=([1-9][0-9]*) ]] || exit 78
provider_pid=${BASH_REMATCH[1]}; provider_start=$(proc_start "$provider_pid"); provider_exe=$(readlink -f "/proc/$provider_pid/exe")
provider_unit=$(systemctl show "$provider_pid" -p Id --value); provider_active=$(systemctl show "$provider_pid" -p ActiveState --value)
[ -n "$provider_unit" ] && [ "$provider_active" = active ] || exit 79
inspect=$(crictl --runtime-endpoint "$endpoint" --image-endpoint "$endpoint" inspect "$container_id") || exit $?
cri_id=$(jq -r '.status.id // empty' <<<"$inspect"); cri_state=$(jq -r '.status.state // empty' <<<"$inspect"); host_pid=$(jq -r '(.info.pid // .info.Pid // empty) | tostring' <<<"$inspect")
label_uid=$(jq -r '.status.annotations["io.kubernetes.pod.uid"] // .status.labels["io.kubernetes.pod.uid"] // empty' <<<"$inspect"); label_ns=$(jq -r '.status.annotations["io.kubernetes.pod.namespace"] // .status.labels["io.kubernetes.pod.namespace"] // empty' <<<"$inspect"); label_pod=$(jq -r '.status.annotations["io.kubernetes.pod.name"] // .status.labels["io.kubernetes.pod.name"] // empty' <<<"$inspect"); label_container=$(jq -r '.status.annotations["io.kubernetes.container.name"] // .status.labels["io.kubernetes.container.name"] // empty' <<<"$inspect")
[ "$cri_id" = "$container_id" ] && [ "$label_uid" = "$pod_uid" ] && [ "$label_ns" = "$ns" ] && [ "$label_pod" = "$pod" ] && [ "$label_container" = "$container_name" ] || exit 80
[ "$cri_state" = CONTAINER_RUNNING ] && [[ "$host_pid" =~ ^[1-9][0-9]*$ ]] && [ -r "/proc/$host_pid/status" ] || exit 81
host_start=$(proc_start "$host_pid"); pid_inode=$(stat -Lc '%i' "/proc/$host_pid/ns/pid")
nspid=$(awk '$1=="NSpid:" {sub(/^NSpid:[[:space:]]*/, ""); print; found=1} END {if(!found) exit 1}' "/proc/$host_pid/status") || exit 82
snapshot_at=$(date -u '+%Y-%m-%dT%H:%M:%SZ')
jq -n --arg endpoint "$endpoint" --arg socket "$socket" --arg source "$endpoint_source" --argjson kubeletPid "$kubelet_pid" --arg kubeletStart "$kubelet_start" --argjson providerPid "$provider_pid" --arg providerStart "$provider_start" --arg providerExe "$provider_exe" --arg providerUnit "$provider_unit" --argjson hostPid "$host_pid" --arg hostStart "$host_start" --arg inode "$pid_inode" --arg nspid "$nspid" --arg state "$cri_state" --arg at "$snapshot_at" '{endpoint:$endpoint,socket:$socket,endpointSource:$source,kubeletPid:$kubeletPid,kubeletStartTicks:$kubeletStart,providerPid:$providerPid,providerStartTicks:$providerStart,providerExe:$providerExe,providerUnit:$providerUnit,hostPid:$hostPid,hostPidStartTicks:$hostStart,pidNamespaceInode:$inode,nspid:$nspid,containerState:$state,snapshotAt:$at}'
REMOTE
)"; rc=$?
  if [ "$rc" -ne 0 ] || ! jq -e 'type=="object" and (.endpoint|type=="string") and (.hostPid|type=="number") and (.pidNamespaceInode|type=="string")' <<<"$out" >/dev/null 2>&1; then invalidate_pidns; printf '중단: active endpoint/CRI/PID snapshot 실패 rc=%s; endpoint나 PID를 추측하지 않는다.\n' "$rc" >&2; return 1; fi
  CRI_ENDPOINT="$(jq -r '.endpoint' <<<"$out")"; CRI_SOCKET="$(jq -r '.socket' <<<"$out")"; ENDPOINT_SOURCE="$(jq -r '.endpointSource' <<<"$out")"; KUBELET_PID="$(jq -r '.kubeletPid' <<<"$out")"; KUBELET_START_TICKS="$(jq -r '.kubeletStartTicks' <<<"$out")"; PROVIDER_PID="$(jq -r '.providerPid' <<<"$out")"; PROVIDER_START_TICKS="$(jq -r '.providerStartTicks' <<<"$out")"; PROVIDER_EXE="$(jq -r '.providerExe' <<<"$out")"; PROVIDER_UNIT="$(jq -r '.providerUnit' <<<"$out")"; HOST_PID="$(jq -r '.hostPid' <<<"$out")"; HOST_PID_START_TICKS="$(jq -r '.hostPidStartTicks' <<<"$out")"; PID_NS_INODE="$(jq -r '.pidNamespaceInode' <<<"$out")"; NSPID_VALUES="$(jq -r '.nspid' <<<"$out")"; NS_PID="$(awk '{print $NF}' <<<"$NSPID_VALUES")"; SNAPSHOT_AT="$(jq -r '.snapshotAt' <<<"$out")"
  if [[ ! "$NS_PID" =~ ^[1-9][0-9]*$ ]]; then invalidate_pidns; printf '%s\n' '중단: NSpid의 namespace PID를 확정하지 못함' >&2; return 1; fi
  SNAPSHOT_READY=true
  printf 'SNAPSHOT_READY=true\nPod UID/resourceVersion: %s/%s\nContainer: %s/%s ID=%s\nCRI endpoint: %s (%s)\nSocket provider: unit=%s pid=%s startTicks=%s exe=%s\nKubelet: pid=%s startTicks=%s\nHost PID/startTicks: %s/%s\nNSpid: %s\nNamespace PID: %s\nPID namespace inode: %s\nObserved UTC: %s\n' "$POD_UID" "$CURRENT_POD_RV" "$CONTAINER_KIND" "$CONTAINER" "$CONTAINER_ID" "$CRI_ENDPOINT" "$ENDPOINT_SOURCE" "$PROVIDER_UNIT" "$PROVIDER_PID" "$PROVIDER_START_TICKS" "$PROVIDER_EXE" "$KUBELET_PID" "$KUBELET_START_TICKS" "$HOST_PID" "$HOST_PID_START_TICKS" "$NSPID_VALUES" "$NS_PID" "$PID_NS_INODE" "$SNAPSHOT_AT"
}
```

`pidns_snapshot`

snapshot 성공은 다음 관계만 보장한다.

- active kubelet process argv 또는 엄격한 fallback config의 endpoint와 `crictl --runtime-endpoint`가 exact match한다.
- socket path를 실제 listen하는 provider PID·unit·start ticks와 current container ID의 CRI status가 연결된다.
- CRI의 Pod UID/namespace/name/container label과 API identity가 같고 container가 `CONTAINER_RUNNING`이다.
- host PID가 살아 있는 같은 순간의 process start ticks, `NSpid`와 PID namespace inode를 읽었다.

이 결과만으로 container view 가시성, application 기능 또는 격리 정상은 보장하지 않는다. rc `69~79`는 node 도구·active kubelet config·socket/provider gate 실패이고, `80`은 CRI 결과 identity 불일치, `81~82`는 container lifecycle 또는 `/proc` 매핑 실패다. 어떤 경우에도 기본 socket, runtime service나 PID를 추측하지 않는다.

### 2. container view와 inode 대조

`kubectl exec`는 current regular/init container가 Running이고 현재 주체에 exact namespace의 `create pods/exec` 권한이 있을 때만 보조 증거로 사용한다. `auth can-i=yes`는 실제 exec 성공이나 동일 subject/context를 단독 보장하지 않으므로 요청 전후 current identity를 다시 확인한다.

```bash
container_pidns_view() {
  local allowed auth_rc out rc host_rc
  EXEC_READY=false; unset EXEC_OUT
  [ "$TARGET_READY" = true ] || { printf '%s\n' '중단: TARGET_READY가 아니다.' >&2; return 1; }
  pidns_snapshot >/dev/null || return 1
  [ "$CONTAINER_STATE" = running ] || { printf '중단: current container state=%s\n' "$CONTAINER_STATE" >&2; return 1; }
  allowed="$(kubectl auth can-i create pods/exec -n "$NS")"; auth_rc=$?
  [ "$auth_rc" -eq 0 ] && [ "$allowed" = yes ] || { printf '중단: pods/exec authorization 실패 rc=%s result=%s\n' "$auth_rc" "${allowed:-empty}" >&2; return 1; }
  out="$(kubectl exec "$POD" -n "$NS" -c "$CONTAINER" -- sh -c 'set -eu; expected=$1; command -v stat >/dev/null 2>&1 || exit 69; self_inode=$(stat -Lc "%i" /proc/self/ns/pid); if [ -r "/proc/$expected/status" ]; then target_inode=$(stat -Lc "%i" "/proc/$expected/ns/pid"); nspid=$(awk '\''$1=="NSpid:" {sub(/^NSpid:[[:space:]]*/, ""); print; found=1} END {if(!found) exit 1}'\'' "/proc/$expected/status"); printf "target-visible=true\nself-pid-ns-inode=%s\ntarget-pid-ns-inode=%s\ntarget-NSpid=%s\n" "$self_inode" "$target_inode" "$nspid"; else printf "target-visible=false\nself-pid-ns-inode=%s\n" "$self_inode"; fi' sh "$NS_PID")"; rc=$?
  if [ "$rc" -ne 0 ]; then printf 'container view producer 실패 rc=%s\n' "$rc" >&2; return "$rc"; fi
  ssh "${SSH_OPTS[@]}" -- "$SSH_DEST" sudo -n bash -s -- "$EXPECTED_MACHINE_ID" "$HOST_BOOT_ID" "$KUBELET_PID" "$KUBELET_START_TICKS" "$PROVIDER_PID" "$PROVIDER_START_TICKS" "$HOST_PID" "$HOST_PID_START_TICKS" "$PID_NS_INODE" "$NSPID_VALUES" <<'REMOTE'
set -euo pipefail
proc_start() { local raw rest; raw=$(<"/proc/$1/stat") || return 1; rest=${raw##*) }; set -- $rest; printf '%s\n' "${20}"; }
[ "$(cat /etc/machine-id)" = "$1" ] && [ "$(cat /proc/sys/kernel/random/boot_id)" = "$2" ] || exit 42
[ "$(proc_start "$3")" = "$4" ] && [ "$(proc_start "$5")" = "$6" ] && [ "$(proc_start "$7")" = "$8" ] || exit 83
[ "$(stat -Lc '%i' "/proc/$7/ns/pid")" = "$9" ] || exit 84
actual_nspid=$(awk '$1=="NSpid:" {sub(/^NSpid:[[:space:]]*/, ""); print; found=1} END {if(!found) exit 1}' "/proc/$7/status")
[ "$actual_nspid" = "${10}" ] || exit 85
REMOTE
  host_rc=$?
  if [ "$host_rc" -ne 0 ]; then EXEC_READY=false; unset EXEC_OUT; printf '중단: exec 뒤 host PID/provider/kubelet snapshot 변경 rc=%s; 출력 폐기\n' "$host_rc" >&2; return "$host_rc"; fi
  assert_api_current >/dev/null || { printf '%s\n' '중단: exec 뒤 container identity 변경; 출력 폐기' >&2; return 1; }
  EXEC_OUT="$out"; EXEC_READY=true; printf 'EXEC_READY=true podUID=%s containerID=%s expectedNamespacePID=%s\n%s\n' "$POD_UID" "$CONTAINER_ID" "$NS_PID" "$EXEC_OUT"
}
```

`container_pidns_view`

판정:

- `target-visible=true`, target inode=`PID_NS_INODE`, target `NSpid`가 host snapshot과 같으면 host PID와 namespace PID가 다른 것은 정상 translation이다.
- self inode와 target inode가 같으면 exec process와 target process가 같은 PID namespace에 있다. `shareProcessNamespace=true`인 Pod에서는 container 간 공유가 정상일 수 있다.
- `target-visible=false`인데 current container ID와 host PID/start ticks가 그대로면 runtime이 보고한 process가 exec가 들어간 namespace와 다르다. current sandbox mapping과 runtime shim/task를 runtime owner에게 이관한다.
- container image에 `sh`, `stat`, `awk`가 없으면 rc `69` 또는 exec 실패다. 도구를 설치하거나 image를 변경하지 않고 host snapshot을 이관한다.
- exec 출력에는 전체 process 목록, argv, environment를 포함하지 않는다. 다른 tenant process가 관측되면 추가 열람을 중단한다.

Pod의 `hostPID`와 `shareProcessNamespace` 선언은 다음 fresh API 출력에서 bounded하게 확인한다.

```bash
POD_DECL_READY=false; unset POD_DECL_JSON POD_DECL_OUT
if assert_api_current >/dev/null; then
  POD_DECL_JSON="$(kubectl get pod "$POD" -n "$NS" -o json)"; PRODUCER_RC=$?
  if [ "$PRODUCER_RC" -ne 0 ]; then printf 'Pod producer 실패 rc=%s\n' "$PRODUCER_RC" >&2
  else
    POD_DECL_OUT="$(jq -er --arg uid "$POD_UID" --arg cid "$CONTAINER_ID" 'select(.metadata.uid==$uid and any(.status.containerStatuses[]?,.status.initContainerStatuses[]?; .containerID==$cid)) | "Pod UID: \(.metadata.uid)\nresourceVersion: \(.metadata.resourceVersion)\nhostPID: \(.spec.hostPID // false)\nshareProcessNamespace: \(.spec.shareProcessNamespace // false)\nruntimeClass: \(.spec.runtimeClassName // "-")\ncurrent container ID match: true"' <<<"$POD_DECL_JSON")"; FILTER_RC=$?
    if [ "$FILTER_RC" -eq 0 ]; then POD_DECL_READY=true; printf '%s\n' "$POD_DECL_OUT"; elif [ "$FILTER_RC" -eq 4 ]; then unset POD_DECL_OUT; printf '%s\n' 'jq no-match: current UID/container ID 불일치' >&2; else unset POD_DECL_JSON POD_DECL_OUT; printf 'jq filter 오류 rc=%s\n' "$FILTER_RC" >&2; fi
  fi
fi
```

마지막 명령은 producer가 성공해도 jq 출력이 비면 identity 불일치다. `hostPID=true`는 host PID namespace 사용을 선언하고, `shareProcessNamespace=true`는 같은 Pod container 간 공유를 선언한다. 둘 다 다른 Pod process 노출을 허용하는 근거가 아니다.

### 3. lifecycle·교체 분기

snapshot rc `80~82`, `No such process`, exec 전후 identity 변경은 namespace 손상보다 container 종료·재시작·Pod replacement race일 수 있다. 1절을 다시 실행해 current Pod UID/resourceVersion, container ID/state/restart count, last termination을 확인한다. old host PID/start ticks/inode를 새 container와 합치지 않는다.

```bash
LIFECYCLE_READY=false; unset LIFECYCLE_JSON LIFECYCLE_OUT
if assert_api_current >/dev/null; then
  LIFECYCLE_JSON="$(kubectl get pod "$POD" -n "$NS" -o json)"; PRODUCER_RC=$?
  if [ "$PRODUCER_RC" -ne 0 ]; then printf 'Pod producer 실패 rc=%s\n' "$PRODUCER_RC" >&2
  else
    LIFECYCLE_OUT="$(jq -er --arg uid "$POD_UID" --arg c "$CONTAINER" --arg cid "$CONTAINER_ID" 'select(.metadata.uid==$uid and any(.status.containerStatuses[]?,.status.initContainerStatuses[]?; .name==$c and .containerID==$cid)) | "Pod UID: \(.metadata.uid)\nresourceVersion: \(.metadata.resourceVersion)\nNode: \(.spec.nodeName)\n" + ([.status.containerStatuses[]?,.status.initContainerStatuses[]? | select(.name==$c) | "container/current ID: \(.name)/\(.containerID // "-")\nstate: \(.state|keys[0] // "-")\nlast reason: \(.lastState.terminated.reason // "-")\nlast finished: \(.lastState.terminated.finishedAt // "-")\nrestarts: \(.restartCount // 0)"] | join("\n"))' <<<"$LIFECYCLE_JSON")"; FILTER_RC=$?
    if [ "$FILTER_RC" -eq 0 ]; then LIFECYCLE_READY=true; printf '%s\n' "$LIFECYCLE_OUT"; elif [ "$FILTER_RC" -eq 4 ]; then unset LIFECYCLE_OUT; printf '%s\n' 'jq no-match: current UID/container ID 불일치' >&2; else unset LIFECYCLE_JSON LIFECYCLE_OUT; printf 'jq filter 오류 rc=%s\n' "$FILTER_RC" >&2; fi
  fi
fi
```

출력이 비면 정상이나 대상 없음으로 해석하지 않는다. API producer 실패, jq filter no-match, current UID/container 변경을 분리하고 1절부터 재등록한다. `RemoveContainer`, `RemovePodSandbox`, shim/task 잔류가 별도 runtime evidence에서 확인되면 [[06. container stop·remove와 sandbox 정리가 완료되지 않는 경우]]로 이동한다. CRI endpoint가 current active kubelet endpoint와 exact match하지 않는 상태에서는 `crictl`을 실행하지 않는다.

### 4. 보안 경계와 상태 변경 금지

다른 Pod나 host process가 예상 밖으로 실제 보이면 process 목록을 넓게 수집하지 않는다. 노출된 상대의 namespace/name, Pod UID, container ID, Node UID, 양쪽 PID namespace inode, 최소 process identifier와 관측 UTC만 별도 보안 evidence로 보존하고 runtime·보안 owner에게 즉시 이관한다. Secret, token, private key, `/proc/*/environ`, 전체 `cmdline`, `maps`, file descriptor와 tenant 데이터는 출력하거나 저장하지 않는다.

이 문서는 `nsenter`, `kill`, PID namespace 생성·변경, privileged/debug container 추가, runtime stop/remove/restart, sandbox 조작, Pod delete·rollout과 Node reboot를 실행하지 않는다. 별도 변경은 current Pod/owner/container/Node/runtime identity, 직접 evidence, 승인 ID·window, PDB/quorum·Job side effect·tenant 영향, idempotence, 중단 조건과 실제 원복 가능한 rollback이 있어야 한다. PID·container ID·Pod UID·Node boot ID 중 하나라도 바뀌면 기존 승인은 무효다.

## 원인 확정 기준

| 확정 범주 | 필요한 직접 근거 |
|---|---|
| 정상 PID translation | current CRI host PID/start ticks → `NSpid` → namespace PID가 이어지고 host/container target inode가 같음 |
| container lifecycle race | current container ID/state/restart·finished 시각이 바뀌고 old PID/start ticks가 더 이상 존재하지 않음 |
| 잘못된 runtime/sandbox mapping | current API·active endpoint·CRI identity는 같은데 host target inode와 current container view가 반복해서 다름 |
| 선언된 공유 | current Pod UID에서 `hostPID` 또는 `shareProcessNamespace` 선언과 실제 inode·visibility가 일치함 |
| 격리 위반 후보 | current identity가 다른 Pod/tenant process와 inode·visibility로 직접 연결됨 |

근거가 한 snapshot identity와 시각에서 이어지지 않으면 `미확정`으로 남긴다. PID 숫자 차이, `Running`, `Ready=True`, `crictl inspect` 한 번 성공 또는 exec 한 번 성공만으로 원인과 정상화를 닫지 않는다.

## 정상화와 증거

교체 Pod/container/Node는 기존 이름을 재사용하지 않고 1절부터 새 UID, resourceVersion, owner UID, container ID, Node UID·boot ID, active endpoint와 provider를 재등록한다. 정상화는 다음을 역순으로 확인한다.

1. current CRI container ID가 current Pod UID·container와 연결되고 provider PID/socket 관계가 유지된다.
2. host PID/start ticks, `NSpid`, namespace PID와 inode가 반복 snapshot에서 일관된다.
3. `hostPID`·`shareProcessNamespace` 선언과 승인된 container view visibility가 일치한다.
4. restart·sandbox/runtime 오류와 `No such process`가 승인된 재관찰 창에서 반복되지 않는다.
5. owner Ready 수, 실제 서비스 요청·Job 결과와 tenant 격리 기대가 정상이다.

보존: namespace/name, Pod UID와 관측 resourceVersion, owner kind/name/UID, regular/init container name·current ID, Node UID/systemUUID, machine-id·boot ID, kubelet PID/start ticks와 endpoint 출처, socket provider unit/PID/start ticks/exe, host PID/start ticks, `NSpid`, namespace PID/inode, producer rc, UTC 관측 시각, 기능·보안 판정과 별도 변경의 승인/rollback 결과. 전체 Pod JSON, CRI inspect 원문, argv, environment, credential과 tenant process 목록은 저장하지 않는다.

## 환경별 미검증

active kubelet argv/config layout, `crictl inspect`의 runtime-specific PID info, socket provider의 systemd mapping, container image 도구, PID namespace 보존과 실제 Kubernetes 1.26 환경은 미검증이다. 승인된 cluster·Node SSH·CRI 환경이 없어 실제 인프라 명령은 실행하지 않았다.
