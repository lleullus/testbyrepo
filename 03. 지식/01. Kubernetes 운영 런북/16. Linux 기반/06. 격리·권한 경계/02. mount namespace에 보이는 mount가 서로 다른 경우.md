# mount namespace에 보이는 mount가 서로 다른 경우

## 입력값과 빠른 수집

이 문서는 `작업 PC/Bastion의 kubectl -> API server`와 `작업 PC/Bastion의 ssh -> 승인된 target node -> 현재 container host PID의 mount namespace`를 연결한다. 작업 PC 변수가 SSH에 전달된다고 가정하지 않고 positional argument로 넘긴 뒤 원격에서 machine-id, PID 시작 tick과 mount namespace inode를 다시 검증한다.

| 종류 | 변수 | 출처 |
|---|---|---|
| 최초 입력 | `NS`, `POD`, `CONTAINER` | 운영자가 현재 장애 대상을 선택 |
| API 자동값 | `POD_UID`, `POD_RV`, owner kind/name/UID, `CONTAINER_ID`, `NODE`, `NODE_UID`, `NODE_MACHINE_ID` | Kubernetes API |
| 계산 후보 | 없음 | mount target이나 PID를 이름으로 추측하지 않음 |
| 운영자 선택 | `SSH_HOST`, `HOST_MACHINE_ID`, `HOST_PID`, `PID_START_TICKS`, `OBSERVED_TARGET`, `START_RFC3339`, `END_RFC3339` | 승인 host와 runtime이 현재 container ID에 연결해 준 PID evidence, 실제 오류 경로 |

`HOST_PID`와 `PID_START_TICKS`는 runtime owner가 현재 `CONTAINER_ID`에 연결해 확인한 값이어야 한다. 이 문서는 endpoint를 추측한 `crictl`, `ctr`, `docker`를 실행하지 않는다.

**도구 확인**

`TOOLS_READY=false; MISSING=''; for T in kubectl jq ssh date mktemp grep awk; do command -v "$T" >/dev/null 2>&1 || MISSING="$MISSING $T"; done; if [ -n "${BASH_VERSION:-}" ] && [ -z "$MISSING" ]; then TOOLS_READY=true; printf 'TOOLS_READY=true\n'; else printf '중단: Bash 또는 도구 없음:%s\n' "$MISSING" >&2; fi`

**최초 입력과 모든 downstream 상태 폐기**

`unset INPUT_READY AUTO_READY SELECTION_READY EVIDENCE_READY NORMALIZATION_READY POD_UID POD_RV OWNER_KIND OWNER_NAME OWNER_UID CONTAINER_KIND CONTAINER_ID NODE NODE_UID NODE_MACHINE_ID SSH_HOST HOST_MACHINE_ID HOST_PID PID_START_TICKS MNT_NS_INODE OBSERVED_TARGET START_RFC3339 END_RFC3339; NS='PASTE_NAMESPACE_HERE'; POD='PASTE_POD_HERE'; CONTAINER='PASTE_CONTAINER_HERE'; INPUT_READY=false; if [ "$TOOLS_READY" = true ] && [ -n "$NS" ] && [ -n "$POD" ] && [ -n "$CONTAINER" ]; then INPUT_READY=true; printf 'INPUT_READY=true NS=%s POD=%s CONTAINER=%s\n' "$NS" "$POD" "$CONTAINER"; else printf '%s\n' '중단: 입력 또는 도구 gate 실패' >&2; fi`

**API identity 자동 등록**

`AUTO_READY=false; SELECTION_READY=false; EVIDENCE_READY=false; NORMALIZATION_READY=false; unset POD_UID POD_RV OWNER_KIND OWNER_NAME OWNER_UID CONTAINER_KIND CONTAINER_ID NODE NODE_UID NODE_MACHINE_ID; if [ "$INPUT_READY" != true ]; then printf '%s\n' '중단: INPUT_READY가 아니다.' >&2; elif PJSON="$(kubectl get pod "$POD" -n "$NS" -o json)" && N="$(jq -r '.spec.nodeName // empty' <<<"$PJSON")" && [ -n "$N" ] && NJSON="$(kubectl get node "$N" -o json)"; then CID="$(jq -r --arg c "$CONTAINER" '[.status.containerStatuses[]?,.status.initContainerStatuses[]?] | map(select(.name==$c)) | if length==1 then .[0].containerID // empty else empty end' <<<"$PJSON")"; CKIND="$(jq -r --arg c "$CONTAINER" 'if any(.spec.containers[]?;.name==$c) then "regular" elif any(.spec.initContainers[]?;.name==$c) then "init" else empty end' <<<"$PJSON")"; OKIND="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)] | if length==1 then .[0].kind else "Pod" end' <<<"$PJSON")"; ONAME="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)] | if length==1 then .[0].name else .metadata.name end' <<<"$PJSON")"; OUID="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)] | if length==1 then .[0].uid else .metadata.uid end' <<<"$PJSON")"; if [ -z "$CID" ] || [ -z "$CKIND" ]; then printf '%s\n' '중단: 선택 container kind/current containerID가 유일하지 않거나 비어 있음' >&2; else POD_UID="$(jq -r '.metadata.uid' <<<"$PJSON")"; POD_RV="$(jq -r '.metadata.resourceVersion' <<<"$PJSON")"; OWNER_KIND="$OKIND"; OWNER_NAME="$ONAME"; OWNER_UID="$OUID"; CONTAINER_KIND="$CKIND"; CONTAINER_ID="$CID"; NODE="$N"; NODE_UID="$(jq -r '.metadata.uid' <<<"$NJSON")"; NODE_MACHINE_ID="$(jq -r '.status.nodeInfo.machineID // empty' <<<"$NJSON")"; AUTO_READY=true; printf 'AUTO_READY=true\nPod: %s uid=%s rv=%s\nOwner: %s/%s uid=%s\nContainer: kind=%s name=%s id=%s\nNode: %s uid=%s machineID=%s\n' "$POD" "$POD_UID" "$POD_RV" "$OWNER_KIND" "$OWNER_NAME" "$OWNER_UID" "$CONTAINER_KIND" "$CONTAINER" "$CONTAINER_ID" "$NODE" "$NODE_UID" "$NODE_MACHINE_ID"; fi; else printf '%s\n' '중단: Pod 또는 Node API 조회 실패' >&2; fi`

owner가 controller이면 현재 owner UID도 확인한다. standalone Pod는 owner tuple을 `Pod/name/UID`로 기록한다.

**fresh API guard 함수 등록**

`fresh_identity(){ EVIDENCE_READY=false; NORMALIZATION_READY=false; local p n cid ckind ouid selection_was="${SELECTION_READY:-false}"; SELECTION_READY=false; [ "$AUTO_READY" = true ] || { printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; return 1; }; p="$(kubectl get pod "$POD" -n "$NS" -o json)" || return 1; cid="$(jq -r --arg c "$CONTAINER" '[.status.containerStatuses[]?,.status.initContainerStatuses[]?] | map(select(.name==$c)) | if length==1 then .[0].containerID // empty else empty end' <<<"$p")"; ckind="$(jq -r --arg c "$CONTAINER" 'if any(.spec.containers[]?;.name==$c) then "regular" elif any(.spec.initContainers[]?;.name==$c) then "init" else empty end' <<<"$p")"; [ "$(jq -r '.metadata.uid' <<<"$p")" = "$POD_UID" ] && [ "$(jq -r '.metadata.resourceVersion' <<<"$p")" = "$POD_RV" ] && [ "$(jq -r '.spec.nodeName' <<<"$p")" = "$NODE" ] && [ "$ckind" = "$CONTAINER_KIND" ] && [ "$cid" = "$CONTAINER_ID" ] || { printf '%s\n' '중단: Pod UID/RV/node/container kind/ID가 변경됨. 자동 등록부터 재실행한다.' >&2; return 1; }; n="$(kubectl get node "$NODE" -o json)" || return 1; [ "$(jq -r '.metadata.uid' <<<"$n")" = "$NODE_UID" ] && [ "$(jq -r '.status.nodeInfo.machineID // empty' <<<"$n")" = "$NODE_MACHINE_ID" ] || { printf '%s\n' '중단: Node identity 변경' >&2; return 1; }; if [ "$OWNER_KIND" != Pod ]; then ouid="$(kubectl get "$OWNER_KIND" "$OWNER_NAME" -n "$NS" -o jsonpath='{.metadata.uid}')" || return 1; [ "$ouid" = "$OWNER_UID" ] || { printf '%s\n' '중단: owner UID 변경' >&2; return 1; }; fi; SELECTION_READY="$selection_was"; }`

**운영자 선택값 입력**

`SSH_HOST='PASTE_APPROVED_SSH_HOST_HERE'; HOST_MACHINE_ID='PASTE_REMOTE_MACHINE_ID_HERE'; HOST_PID='PASTE_RUNTIME_VERIFIED_PID_HERE'; PID_START_TICKS='PASTE_PID_START_TICKS_HERE'; OBSERVED_TARGET='PASTE_OBSERVED_MOUNT_TARGET_HERE'; START_RFC3339='PASTE_START_RFC3339_HERE'; END_RFC3339='PASTE_END_RFC3339_HERE'`

**선택값·시간·원격 identity 검증**

`SELECTION_READY=false; EVIDENCE_READY=false; NORMALIZATION_READY=false; unset MNT_NS_INODE; canon(){ [[ "$1" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] && [ "$(date -u -d "$1" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" = "$1" ]; }; if ! fresh_identity; then :; elif [ -z "$SSH_HOST" ] || [ "$HOST_MACHINE_ID" != "$NODE_MACHINE_ID" ] || ! [[ "$HOST_PID" =~ ^[1-9][0-9]*$ && "$PID_START_TICKS" =~ ^[1-9][0-9]*$ ]] || [[ "$OBSERVED_TARGET" != /* ]] || ! canon "$START_RFC3339" || ! canon "$END_RFC3339" || [ "$(date -u -d "$START_RFC3339" +%s)" -ge "$(date -u -d "$END_RFC3339" +%s)" ]; then printf '%s\n' '중단: 선택값 또는 UTC RFC3339 window가 유효하지 않음' >&2; elif R="$(ssh -o BatchMode=yes -- "$SSH_HOST" bash -c 'set -eu; mid=$1; pid=$2; start=$3; [ "$(cat /etc/machine-id)" = "$mid" ]; s=$(cat "/proc/$pid/stat"); r=${s##*) }; set -- $r; [ "${20}" = "$start" ]; stat -Lc %i "/proc/$pid/ns/mnt"' bash "$HOST_MACHINE_ID" "$HOST_PID" "$PID_START_TICKS")"; then MNT_NS_INODE="$R"; SELECTION_READY=true; printf 'SELECTION_READY=true host=%s pid=%s start=%s mnt_inode=%s target=%s window=%s..%s\n' "$SSH_HOST" "$HOST_PID" "$PID_START_TICKS" "$MNT_NS_INODE" "$OBSERVED_TARGET" "$START_RFC3339" "$END_RFC3339"; else printf '%s\n' '중단: 승인 host의 machine-id/PID/start/mount namespace 검증 실패' >&2; fi`

재조회나 대상 재등록은 `SELECTION_READY`, evidence와 normalization을 무효화한다. `POD_RV`가 바뀌면 의미 없는 metadata 변경일 수도 있지만, 이 세션에서는 보수적으로 자동 등록부터 다시 시작한다.

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | 같은 target의 host/container view에서 존재 여부, source, filesystem, options 또는 propagation이 다름 |
| 적용 | 위 identity tuple과 인접한 시간의 두 view를 비교 가능 |
| 제외 | sandbox 정리는 [[06. container stop·remove와 sandbox 정리가 완료되지 않는 경우]], exec 연결 자체 실패는 [[33. Pod exec 연결이 실패하는 경우]] |

검색 문자열: `mount namespace`, `mountinfo`, `propagation`, `shared`, `master`, `bind`, `overlay`, `read-only`, `device or resource busy`.

## 관측별 진단 경로

| 지금 보이는 것 | 먼저 볼 것 | 그다음 어디를 볼지 | 상세 절 |
|---|---|---|---|
| host에만 target 존재 | namespace inode와 target 행 | runtime bind/volume 선언 | [[#1. 두 mount view 수집]] |
| 양쪽 source 또는 fstype가 다름 | exact target의 source/fstype | volume·overlay·runtime owner | [[#2. 선언과 실제 mount 연결]] |
| options 또는 propagation이 다름 | `ro/rw`, `shared/master/private` | mount policy owner | [[#1. 두 mount view 수집]] |
| PID·container ID·inode 변경 | fresh identity gate | lifecycle race | [[#3. 시간 증거와 판정]] |

## 1. 두 mount view 수집

**host view, target node에서 실행**

`if [ "$SELECTION_READY" != true ] || ! fresh_identity; then printf '%s\n' '중단: current selection gate 실패' >&2; elif ssh -o BatchMode=yes -- "$SSH_HOST" bash -c 'set -eu; mid=$1; pid=$2; start=$3; inode=$4; target=$5; [ "$(cat /etc/machine-id)" = "$mid" ]; s=$(cat "/proc/$pid/stat"); r=${s##*) }; set -- $r; [ "${20}" = "$start" ]; [ "$(stat -Lc %i "/proc/$pid/ns/mnt")" = "$inode" ]; command -v findmnt >/dev/null; nsenter -t "$pid" -m -- findmnt -rn -M "$target" -o TARGET,SOURCE,FSTYPE,OPTIONS,PROPAGATION' bash "$HOST_MACHINE_ID" "$HOST_PID" "$PID_START_TICKS" "$MNT_NS_INODE" "$OBSERVED_TARGET"; then EVIDENCE_READY=true; else RC=$?; printf 'host mount 수집 실패 rc=%s; 빈 결과와 identity/tool 실패를 분리해 확인\n' "$RC" >&2; fi`

`nsenter`는 읽기 전용 `findmnt` 실행에만 사용한다. mount namespace 안에서 변경 명령을 실행하지 않는다.

**container view, API exec 경로에서 실행**

`if [ "$SELECTION_READY" != true ] || ! fresh_identity; then printf '%s\n' '중단: current selection gate 실패' >&2; elif kubectl exec "$POD" -n "$NS" -c "$CONTAINER" -- sh -c 'set -eu; command -v stat >/dev/null; command -v findmnt >/dev/null; printf "container-mnt-inode="; stat -Lc %i /proc/self/ns/mnt; findmnt -rn -M "$1" -o TARGET,SOURCE,FSTYPE,OPTIONS,PROPAGATION' sh "$OBSERVED_TARGET"; then EVIDENCE_READY=true; else RC=$?; printf 'container view 실패 rc=%s; exec/tool/target 없음은 정상 mount와 다름\n' "$RC" >&2; fi`

두 명령 성공은 각각 해당 hop의 view만 보장한다. 같은 `TARGET`이어도 source, fstype, options, propagation 중 하나가 다르면 같은 mount로 합치지 않는다.

## 2. 선언과 실제 mount 연결

`if ! fresh_identity; then printf '%s\n' '중단: current API gate 실패' >&2; elif P="$(kubectl get pod "$POD" -n "$NS" -o json)"; then if jq -r --arg c "$CONTAINER" --arg t "$OBSERVED_TARGET" '{pod:{uid:.metadata.uid,rv:.metadata.resourceVersion,node:.spec.nodeName},mounts:[(.spec.containers[]?,.spec.initContainers[]?)|select(.name==$c)|.volumeMounts[]?|select(.mountPath==$t)|{name,mountPath,subPath,readOnly}],volumes:[.spec.volumes[]|{name,kind:(if .persistentVolumeClaim then "pvc" elif .configMap then "configMap" elif .secret then "secret" elif .hostPath then "hostPath" elif .emptyDir then "emptyDir" else "other" end)}]}' <<<"$P"; then printf '%s\n' 'filter_success=true'; else RC=$?; printf 'filter_error rc=%s\n' "$RC" >&2; fi; else RC=$?; printf 'producer_error rc=%s\n' "$RC" >&2; fi`

Secret 값과 hostPath 원문은 저장하지 않는다. 선언은 runtime/Linux mount identity를 보장하지 않으며, 실제 target 행과 volume name 관계만 연결한다.

## 3. 시간 증거와 판정

**Pod log producer와 filter 결과 분리**

`if ! fresh_identity; then printf '%s\n' '중단: current API gate 실패' >&2; else F="$(mktemp)" || exit 1; B="${F}.bounded"; if kubectl logs "$POD" -n "$NS" -c "$CONTAINER" --timestamps --since-time="$START_RFC3339" --tail=300 >"$F"; then if awk -v end="$END_RFC3339" '$1 <= end' "$F" >"$B"; then if grep -E -i -C 3 'mount|bind|overlay|read-only|permission denied|device or resource busy' "$B"; then printf '%s\n' 'filter_match=true'; else RC=$?; if [ "$RC" -eq 1 ]; then printf '%s\n' 'filter_match=false; 오류 부재가 아니라 bounded window에 match 없음'; else printf 'symptom_filter_error rc=%s\n' "$RC" >&2; fi; fi; else RC=$?; printf 'time_filter_error rc=%s\n' "$RC" >&2; fi; else RC=$?; printf 'producer_error rc=%s\n' "$RC" >&2; fi; rm -f "$F" "$B"; fi`

원인은 같은 Pod/container identity와 window에서 다음처럼 확정한다.

- host/container namespace inode가 다르고 차이가 volume/runtime 계약으로 설명되면 정상 격리다.
- exact target의 source/fstype가 다르고 Pod volume 또는 runtime bind evidence가 연결되면 해당 owner 경로다.
- source는 같고 `ro/rw` 또는 propagation만 다르면 mount option/propagation 경로다.
- PID, start tick, inode 또는 current container ID가 바뀌면 이전 evidence를 폐기한다.

## 변경 경계와 정상화

이 런북은 `mount`, `umount`, remount, propagation 변경, runtime stop/remove/restart, Pod 삭제를 제공하지 않는다. 별도 변경은 current UID/owner/container ID/node/PID/mount tuple, incident·approval ID, 영향 범위, 원본 설정, rollback owner가 모두 fresh하게 확인된 절차에서만 수행한다.

정상화 직전 `fresh_identity`와 selection 검증을 다시 실행하고 다음을 확인한다.

1. 현재 container ID와 runtime PID/start tick/mount inode가 새 evidence와 일치한다.
2. exact target의 source/fstype/options/propagation이 승인 계약과 일치한다.
3. 최초 실패 동작이 실제로 성공한다.
4. 같은 UTC 관찰 창에 mount 오류·restart·Warning이 재발하지 않는다.
5. 실제 요청 또는 핵심 기능과 데이터 접근이 정상이다.

`Running`, 명령 성공 또는 한 번 보이는 mount만으로 정상화하지 않는다. replacement Pod/container라면 이름을 재사용하지 말고 controller selector/owner UID/creation time으로 단일 새 후보를 다시 고른 뒤 이 문서를 처음부터 실행한다.
