# seccomp가 syscall을 거부한 경우

## 입력값과 빠른 수집

직접 증거는 `current Pod/container -> runtime 확인 host PID/start -> /proc/PID Seccomp 상태 -> 같은 node·PID·UTC window의 단일 SECCOMP audit serial -> arch/syscall/code`다. `operation not permitted`, profile 이름, `Seccomp: 2` 중 하나만으로 seccomp를 확정하지 않는다.

| 종류 | 변수 | 출처 |
|---|---|---|
| 최초 입력 | `NS`, `POD`, `CONTAINER` | 운영자 |
| API 자동값 | Pod UID/resourceVersion, owner tuple, current container ID, Node UID/machineID | API |
| 계산 후보 | 없음 | syscall 숫자·profile을 추측하지 않음 |
| 운영자 선택 | 승인 host, runtime PID/start, UTC window, 단일 audit serial | runtime·kernel audit evidence |

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | 동일 process·시각에 `type=SECCOMP`와 syscall 거부가 있음 |
| 적용 | effective API declaration, current PID Seccomp 상태와 단일 audit event를 대조 가능 |
| 제외 | AVC/AppArmor는 [[06. SELinux·AppArmor가 작업을 거부한 경우]], capability 후보는 [[04. capability 부족으로 operation not permitted가 발생한 경우]] |

검색 문자열: `type=SECCOMP`, `audit`, `arch=`, `syscall=`, `code=`, `pid=`, `comm=`, `SCMP_ACT_ERRNO`, `operation not permitted`.

## 관측별 진단 경로

| 지금 보이는 것 | 먼저 볼 것 | 그다음 어디를 볼지 | 상세 절 |
|---|---|---|---|
| profile 선언이 기대와 다름 | API effective Pod/container 값 | admission/workload owner | [[#1. effective 선언]] |
| `Seccomp: 2`와 filter 존재 | 단일 SECCOMP event | runtime/profile owner | [[#2. process와 audit 직접 연결]] |
| EPERM이나 SECCOMP event 불일치 | capability·LSM·mount | 다른 경계 이관 | [[#3. 반대 증거와 확정 기준]] |
| audit PID·시간 불일치 | current PID/start와 serial | evidence 폐기 | [[#2. process와 audit 직접 연결]] |

## 1. effective 선언

`if ! fresh_identity; then printf '%s\n' '중단: current API gate 실패' >&2; elif P="$(kubectl get pod "$POD" -n "$NS" -o json)"; then jq -r --arg c "$CONTAINER" '{uid:.metadata.uid,resourceVersion:.metadata.resourceVersion,podSeccomp:.spec.securityContext.seccompProfile,container:([(.spec.containers[]?,.spec.initContainers[]?)|select(.name==$c)|{name,seccomp:.securityContext.seccompProfile,capabilities:.securityContext.capabilities,privileged:.securityContext.privileged,allowPrivilegeEscalation:.securityContext.allowPrivilegeEscalation}][0])}' <<<"$P"; else printf '%s\n' 'producer_error: Pod 조회 실패' >&2; fi`

`RuntimeDefault`는 runtime의 default profile, `Localhost`는 node-local profile 요청이다. API 값은 runtime 적용 성공을 보장하지 않는다. Localhost path를 임의 탐색하거나 profile 원문을 출력하지 않는다.

## 2. process와 audit 직접 연결

**현재 process seccomp 상태**

`if [ "$SELECTION_READY" != true ] || ! fresh_identity; then printf '%s\n' '중단: current selection gate 실패' >&2; elif ssh -o BatchMode=yes -- "$SSH_HOST" bash -c 'set -eu; mid=$1; pid=$2; start=$3; [ "$(cat /etc/machine-id)" = "$mid" ]; s=$(cat "/proc/$pid/stat"); r=${s##*) }; set -- $r; [ "${20}" = "$start" ]; grep -E "^(Name|Pid|NSpid|NoNewPrivs|Seccomp|Seccomp_filters|CapEff|CapBnd):" "/proc/$pid/status"' bash "$HOST_MACHINE_ID" "$HOST_PID" "$PID_START_TICKS"; then EVIDENCE_READY=true; else RC=$?; printf 'process producer/filter 실패 rc=%s\n' "$RC" >&2; fi`

**단일 audit serial 조회, producer/filter/no-match 분리**

`AUDIT_READY=false; if [ "$SELECTION_READY" != true ] || ! fresh_identity; then printf '%s\n' '중단: current selection gate 실패' >&2; elif ssh -o BatchMode=yes -- "$SSH_HOST" bash -c 'set -eu; mid=$1; pid=$2; starttick=$3; since=$4; until=$5; serial=$6; [ "$(cat /etc/machine-id)" = "$mid" ]; s=$(cat "/proc/$pid/stat"); r=${s##*) }; set -- $r; [ "${20}" = "$starttick" ]; f=$(mktemp); m=${f}.match; trap '\''rm -f "$f" "$m"'\'' EXIT; journalctl -k --since "$since" --until "$until" --no-pager >"$f" || exit 2; if grep -E "type=SECCOMP|SECCOMP" "$f" >"$m"; then if grep -E "audit\([^)]*:${serial}\)" "$m"; then exit 0; else rc=$?; [ "$rc" -eq 1 ] && exit 3; exit "$rc"; fi; else rc=$?; [ "$rc" -eq 1 ] && exit 4; exit "$rc"; fi' bash "$HOST_MACHINE_ID" "$HOST_PID" "$PID_START_TICKS" "$START_RFC3339" "$END_RFC3339" "$AUDIT_SERIAL"; then AUDIT_READY=true; printf 'AUDIT_READY=true serial=%s\n' "$AUDIT_SERIAL"; else RC=$?; case "$RC" in 2) printf '%s\n' 'producer_error: kernel journal 조회 실패' >&2;; 3) printf '%s\n' 'filter_match=false: serial 불일치' >&2;; 4) printf '%s\n' 'filter_match=false: window에 SECCOMP record 없음' >&2;; *) printf 'filter_error rc=%s\n' "$RC" >&2;; esac; fi`

출력에서 `type=SECCOMP`, audit serial, kernel timestamp, `arch`, `syscall`, `code`, `pid`, `comm`만 redaction해 보존한다. path, argv, actor·UID 상세는 저장하지 않는다. audit PID가 `HOST_PID`와 같고 사건 시간이 window 안이며 하나의 serial만 선택됐을 때만 다음 판정으로 간다. syscall이 숫자면 `arch`를 먼저 확인하고 승인된 node의 기존 `ausyscall` 매핑으로만 이름을 해석한다.

## 3. 반대 증거와 확정 기준

다음 세 조건이 모두 필요하다.

1. current API declaration과 runtime process에서 seccomp filter가 확인된다.
2. 단일 audit serial의 PID·시간·arch·syscall·code가 실제 실패 operation과 일치한다.
3. 같은 사건의 capability, SELinux/AppArmor, mount/filesystem 증거가 더 직접적인 원인이 아니다.

`Seccomp: 2`만 있고 audit가 없으면 audit 미수집·보존·권한 문제와 실제 거부 부재를 구분할 수 없으므로 미확정이다. `SCMP_ACT_ERRNO` 후보도 profile artifact와 audit code가 연결되기 전에는 확정하지 않는다.

## 변경 경계와 정상화

`unconfined`, `privileged`, capability 추가, profile disable/unload·즉석 allowlist, runtime restart, 무조건 Pod delete/rollout은 금지한다. 이 문서는 mutation 명령을 제공하지 않는다. 별도 변경은 current owner UID/revision/selector/image digest, 승인된 profile artifact hash·새 값, approval ID·변경 시간, availability, idempotence와 검증된 rollback artifact를 실제 명령에서 다시 확인해야 한다.

replacement가 생기면 owner selector·owner UID·creation time으로 단일 새 Pod를 재선택하고 자동값부터 다시 등록한다. 정상화는 새 UID/container ID/PID의 effective profile, 동일 syscall 성공, 새 SECCOMP audit 부재, Ready·실제 기능과 관찰 창의 재발 부재를 모두 확인한다. audit 미수집을 거부 부재로 해석하지 않는다.

## 증거 경계

보존: UTC window, Pod/owner/container/node identity, runtime PID/start, 단일 audit serial, arch/syscall/code와 일치 판정. 제외: audit actor 상세, path·argv, 전체 journal, environment, token, Secret, private key.
