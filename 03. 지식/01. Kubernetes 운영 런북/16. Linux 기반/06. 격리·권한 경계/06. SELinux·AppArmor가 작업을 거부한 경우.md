# SELinux·AppArmor가 작업을 거부한 경우

## 입력값과 빠른 수집

SELinux와 AppArmor는 독립적으로 판정한다. `current Pod/container -> runtime 확인 host PID/start -> node의 실제 활성 LSM -> 단일 audit serial의 process·operation·profile/context·시간`이 연결돼야 한다. `permission denied`만으로 두 LSM을 동시에 가정하지 않는다.

| 종류 | 변수 | 출처 |
|---|---|---|
| 최초 입력 | `NS`, `POD`, `CONTAINER` | 운영자 |
| API 자동값 | Pod UID/resourceVersion, owner tuple, current container ID, Node UID/machineID | API |
| 계산 후보 | 없음 | LSM 종류와 profile/context를 추측하지 않음 |
| 운영자 선택 | `LSM_KIND`, 승인 host, runtime PID/start, canonical UTC window, 단일 audit serial | 직접 audit evidence |

**모든 조회의 current guard**

`fresh_identity(){ LSM_READY=false; AUDIT_READY=false; EVIDENCE_READY=false; MUTATION_READY=false; ROLLBACK_READY=false; NORMALIZATION_READY=false; local p n cid ckind ouid selection_was="${SELECTION_READY:-false}"; SELECTION_READY=false; [ "$AUTO_READY" = true ] || return 1; p="$(kubectl get pod "$POD" -n "$NS" -o json)" || return 1; cid="$(jq -r --arg c "$CONTAINER" '[.status.containerStatuses[]?,.status.initContainerStatuses[]?] | map(select(.name==$c)) | if length==1 then .[0].containerID // empty else empty end' <<<"$p")"; ckind="$(jq -r --arg c "$CONTAINER" 'if any(.spec.containers[]?;.name==$c) then "regular" elif any(.spec.initContainers[]?;.name==$c) then "init" else empty end' <<<"$p")"; [ "$(jq -r '.metadata.uid' <<<"$p")" = "$POD_UID" ] && [ "$(jq -r '.metadata.resourceVersion' <<<"$p")" = "$POD_RV" ] && [ "$(jq -r '.spec.nodeName' <<<"$p")" = "$NODE" ] && [ "$ckind" = "$CONTAINER_KIND" ] && [ "$cid" = "$CONTAINER_ID" ] || { printf '%s\n' '중단: Pod/RV/node/container kind/ID 변경' >&2; return 1; }; n="$(kubectl get node "$NODE" -o json)" || return 1; [ "$(jq -r '.metadata.uid' <<<"$n")" = "$NODE_UID" ] && [ "$(jq -r '.status.nodeInfo.machineID // empty' <<<"$n")" = "$NODE_MACHINE_ID" ] || return 1; if [ "$OWNER_KIND" != Pod ]; then ouid="$(kubectl get "$OWNER_KIND" "$OWNER_NAME" -n "$NS" -o jsonpath='{.metadata.uid}')" || return 1; [ "$ouid" = "$OWNER_UID" ] || return 1; fi; SELECTION_READY="$selection_was"; }`

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | 같은 process·operation·시각에 SELinux AVC 또는 AppArmor DENIED 직접 record가 있음 |
| 적용 | 활성 모듈, process label, API declaration과 단일 audit event를 대조 가능 |
| 제외 | `SECCOMP`는 [[05. seccomp가 syscall을 거부한 경우]], capability 후보는 [[04. capability 부족으로 operation not permitted가 발생한 경우]] |

검색 문자열: `avc: denied`, `USER_AVC`, `apparmor="DENIED"`, `scontext=`, `tcontext=`, `tclass=`, `profile=`, `operation=`, `requested_mask=`, `denied_mask=`.

## 관측별 진단 경로

| 지금 보이는 것 | 먼저 볼 것 | 그다음 어디를 볼지 | 상세 절 |
|---|---|---|---|
| AVC와 context가 있음 | SELinux mode·process label | policy/context owner | [[#2. 활성 모듈과 직접 audit]] |
| AppArmor DENIED와 profile이 있음 | enabled·process label | profile owner | [[#2. 활성 모듈과 직접 audit]] |
| permission denied만 있음 | 직접 LSM record | seccomp/capability/filesystem | [[#3. 확정과 반대 증거]] |
| selected LSM이 비활성 | 다른 LSM 자동 선택 금지 | 미확정/이관 | [[#2. 활성 모듈과 직접 audit]] |

## 1. API effective security 선언

`if ! fresh_identity; then printf '%s\n' '중단: current API gate 실패' >&2; elif P="$(kubectl get pod "$POD" -n "$NS" -o json)"; then jq -r --arg c "$CONTAINER" '{uid:.metadata.uid,resourceVersion:.metadata.resourceVersion,podSELinux:.spec.securityContext.seLinuxOptions,container:([(.spec.containers[]?,.spec.initContainers[]?)|select(.name==$c)|{name,seLinuxOptions:.securityContext.seLinuxOptions,seccomp:.securityContext.seccompProfile,capabilities:.securityContext.capabilities,privileged:.securityContext.privileged}][0]),appArmorAnnotation:.metadata.annotations["container.apparmor.security.beta.kubernetes.io/"+$c]}' <<<"$P"; else printf '%s\n' 'producer_error: Pod 조회 실패' >&2; fi`

API 선언은 host module 활성·실제 process label·거부를 보장하지 않는다. annotation 전체, Secret, token은 출력하지 않는다.

## 2. 활성 모듈과 직접 audit

**선택한 LSM 활성 상태와 process label**

`LSM_READY=false; if [ "$SELECTION_READY" != true ] || ! fresh_identity; then printf '%s\n' '중단: current selection gate 실패' >&2; elif ssh -o BatchMode=yes -- "$SSH_HOST" bash -c 'set -eu; mid=$1; pid=$2; start=$3; kind=$4; [ "$(cat /etc/machine-id)" = "$mid" ]; s=$(cat "/proc/$pid/stat"); r=${s##*) }; set -- $r; [ "${20}" = "$start" ]; if [ "$kind" = SELinux ]; then command -v getenforce >/dev/null; mode=$(getenforce); printf "selinux_mode=%s\n" "$mode"; [ "$mode" != Disabled ]; else [ -r /sys/module/apparmor/parameters/enabled ]; enabled=$(cat /sys/module/apparmor/parameters/enabled); printf "apparmor_enabled=%s\n" "$enabled"; [ "$enabled" = Y ]; fi; printf "process_label="; cat "/proc/$pid/attr/current"' bash "$HOST_MACHINE_ID" "$HOST_PID" "$PID_START_TICKS" "$LSM_KIND"; then LSM_READY=true; printf 'LSM_READY=true kind=%s\n' "$LSM_KIND"; else RC=$?; printf 'LSM 활성/PID 검증 실패 rc=%s\n' "$RC" >&2; fi`

SELinux `Permissive`는 record가 있어도 enforcement로 차단한 것이 아닐 수 있으므로 audit action과 실제 errno를 함께 본다. AppArmor는 kernel enabled만으로 선택 profile enforcement를 보장하지 않는다.

**단일 audit serial 조회**

`AUDIT_READY=false; if [ "$SELECTION_READY" != true ] || ! fresh_identity; then printf '%s\n' '중단: current LSM selection gate 실패' >&2; elif ssh -o BatchMode=yes -- "$SSH_HOST" bash -c 'set -eu; mid=$1; pid=$2; starttick=$3; kind=$4; since=$5; until=$6; serial=$7; [ "$(cat /etc/machine-id)" = "$mid" ]; s=$(cat "/proc/$pid/stat"); r=${s##*) }; set -- $r; [ "${20}" = "$starttick" ]; if [ "$kind" = SELinux ]; then command -v getenforce >/dev/null; [ "$(getenforce)" != Disabled ]; pattern="avc: denied|USER_AVC"; else [ "$(cat /sys/module/apparmor/parameters/enabled)" = Y ]; pattern="apparmor=.?DENIED"; fi; f=$(mktemp); m=${f}.match; trap '\''rm -f "$f" "$m"'\'' EXIT; journalctl -k --since "$since" --until "$until" --no-pager >"$f" || exit 2; if grep -E -i "$pattern" "$f" >"$m"; then if grep -E "audit\([^)]*:${serial}\)" "$m"; then exit 0; else rc=$?; [ "$rc" -eq 1 ] && exit 3; exit "$rc"; fi; else rc=$?; [ "$rc" -eq 1 ] && exit 4; exit "$rc"; fi' bash "$HOST_MACHINE_ID" "$HOST_PID" "$PID_START_TICKS" "$LSM_KIND" "$START_RFC3339" "$END_RFC3339" "$AUDIT_SERIAL"; then LSM_READY=true; AUDIT_READY=true; printf 'LSM_READY=true AUDIT_READY=true kind=%s serial=%s\n' "$LSM_KIND" "$AUDIT_SERIAL"; else RC=$?; case "$RC" in 2) printf '%s\n' 'producer_error: kernel journal 실패' >&2;; 3) printf '%s\n' 'filter_match=false: serial 불일치' >&2;; 4) printf '%s\n' 'filter_match=false: selected LSM record 없음' >&2;; *) printf 'filter/LSM error rc=%s\n' "$RC" >&2;; esac; fi`

SELinux는 `scontext`(process), `tcontext`(target), `tclass`, denied permission을 구분한다. AppArmor는 `profile`, `operation`, requested/denied mask를 구분한다. PID·audit timestamp·operation이 현재 사건과 맞아야 한다. path, comm/exe, subject·UID 상세는 통제 화면에서만 확인하고 증거에는 유형으로 redaction한다.

## 3. 확정과 반대 증거

확정 조건:

1. 선택한 LSM이 node에서 활성이고 current PID의 process label이 확인됐다.
2. 단일 audit serial이 current PID·사건 window·실패 operation에 연결된다.
3. SELinux면 enforcing 여부와 context/class/permission, AppArmor면 profile/operation/mask가 실제 실패를 설명한다.
4. seccomp, capability, POSIX mode/ACL/read-only mount와 runtime 오류를 별도 증거로 분리했다.

audit no-match는 LSM 정상의 증거가 아니다. 보존·권한·시간·logging 설정 실패일 수 있다. selected LSM이 비활성이어도 다른 LSM을 자동 선택하지 않는다.

## 변경 경계와 정상화

`setenforce 0`, permissive 전환, profile disable/unload, `unconfined`, `privileged`, capability 추가, `audit2allow`, `semanage`, `chcon`, `apparmor_parser`, runtime restart와 무조건 rollout은 금지한다. mutation은 제공하지 않는다. 별도 변경은 current owner UID/revision/selector/image digest, 승인 policy artifact hash·새 값, approval ID·변경 시간, availability와 원본 artifact rollback을 명령 자체에서 재검증해야 한다.

replacement가 생기면 owner selector·owner UID·creation time으로 단일 새 Pod를 재선택하고 전체 READY를 재등록한다. 정상화는 정책이 여전히 enforcing인 상태에서 process label과 effective 선언이 승인값이고, 동일 operation이 성공하며, 새 AVC/DENIED·restart·Warning이 관찰 창에 없고 실제 요청·기능이 정상일 때만 선언한다. audit 수집 실패를 거부 부재로 해석하지 않는다.

## 증거 경계

보존: UTC window, current identity tuple, selected LSM/mode, PID/start/process label, 단일 serial의 operation·profile/context/class/mask와 일치 판정. 제외: 전체 audit/journal, 민감 path, actor·UID·argv, environment, token, Secret, private key.
