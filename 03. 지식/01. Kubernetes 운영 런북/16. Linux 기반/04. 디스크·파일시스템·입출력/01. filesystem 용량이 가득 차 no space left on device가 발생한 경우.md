# filesystem 용량이 가득 차 no space left on device가 발생한 경우

## 입력값과 빠른 수집

실행 경로는 `운영자 Bash -> 직접 SSH -> 대상 host -> 오류 path -> 실제 mount/source -> filesystem`이다. `/`, kubelet 또는 runtime 경로를 기본값으로 가정하지 않는다. 다른 host/path로 바꾸거나 실패하면 host·boot, mount/device, PID/start time, 시간 창과 downstream gate를 먼저 무효화한다.

| 구분 | 값 | 계약 |
|---|---|---|
| 최초 입력 | `SSH_TARGET`, `EXPECTED_MACHINE_ID_SHA256` | 승인된 직접 SSH endpoint와 machine-id 파일 hash |
| 운영자 선택 | `AFFECTED_PATH`, UTC journal 창 | 실제 오류 메시지와 사건 기록에서 선택 |
| system-auto | `BOOT_ID`, `MOUNT_KEY`, `DEVICE_KEY` | `findmnt -T`와 `stat`에서 등록 |
| 계산값 | bytes/inode 사용률, bounded top-level 합계 | 같은 mount identity에서 계산 |
| 조건부 system-auto | deleted-open PID/start time | `lsof` 결과가 있을 때만 등록 |

### 1. host 등록

```bash
unset HOST_READY TARGET_READY TIME_READY PROCESS_READY DOWNSTREAM_READY HOSTNAME_ACTUAL BOOT_ID AFFECTED_PATH MOUNT_KEY DEVICE_KEY START_RFC3339 END_RFC3339 TARGET_PID PID_START_TICKS; SSH_TARGET='PASTE_SSH_TARGET_HERE'; EXPECTED_MACHINE_ID_SHA256='PASTE_MACHINE_ID_SHA256_HERE'; HOST_READY=false; if [ -z "${BASH_VERSION:-}" ] || ! command -v ssh >/dev/null 2>&1 || ! command -v date >/dev/null 2>&1 || ! [[ "$SSH_TARGET" =~ ^[A-Za-z0-9._-]+@([A-Za-z0-9._-]+|\[[0-9A-Fa-f:]+\])$ ]] || ! [[ "$EXPECTED_MACHINE_ID_SHA256" =~ ^[0-9a-f]{64}$ ]]; then printf '%s\n' '중단: Bash, ssh, date 또는 최초 입력 오류' >&2; elif OUT="$(ssh -o BatchMode=yes -o ConnectTimeout=10 -o ProxyCommand=none -o ProxyJump=none -- "$SSH_TARGET" 'set -euo pipefail; sum=$(sha256sum /etc/machine-id); [ "${sum%% *}" = "$1" ] || exit 70; printf "%s\n%s\n" "$(hostname --fqdn 2>/dev/null || hostname)" "$(cat /proc/sys/kernel/random/boot_id)"' bash "$EXPECTED_MACHINE_ID_SHA256")"; then mapfile -t HOST_META <<<"$OUT"; if [ "${#HOST_META[@]}" -eq 2 ] && [ -n "${HOST_META[0]}" ] && [[ "${HOST_META[1]}" =~ ^[0-9a-fA-F-]{36}$ ]]; then HOSTNAME_ACTUAL=${HOST_META[0]}; BOOT_ID=${HOST_META[1]}; HOST_READY=true; printf 'HOST_READY=true host=%s boot_id=%s direct-hop-only=true\n' "$HOSTNAME_ACTUAL" "$BOOT_ID"; else unset HOSTNAME_ACTUAL BOOT_ID; printf '%s\n' '중단: host metadata 형식 오류' >&2; fi; else unset HOSTNAME_ACTUAL BOOT_ID; printf '%s\n' '중단: SSH/machine identity 실패' >&2; fi
```

### 2. 오류 path와 mount 등록

```bash
unset MOUNT_KEY DEVICE_KEY TARGET_PID PID_START_TICKS START_RFC3339 END_RFC3339; TARGET_READY=false; PROCESS_READY=false; TIME_READY=false; DOWNSTREAM_READY=false; AFFECTED_PATH='PASTE_AFFECTED_PATH_HERE'; if [ "$HOST_READY" != true ] || [ "${AFFECTED_PATH#/}" = "$AFFECTED_PATH" ]; then printf '%s\n' '중단: host gate 또는 절대 path 오류' >&2; elif OUT="$(ssh -o BatchMode=yes -o ConnectTimeout=10 -o ProxyCommand=none -o ProxyJump=none -- "$SSH_TARGET" 'set -euo pipefail; expected=$1; boot=$2; path=$3; sum=$(sha256sum /etc/machine-id); [ "${sum%% *}" = "$expected" ] && [ "$(cat /proc/sys/kernel/random/boot_id)" = "$boot" ] || exit 70; [ -e "$path" ] || [ -e "$(dirname -- "$path")" ] || exit 71; probe=$path; [ -e "$probe" ] || probe=$(dirname -- "$probe"); mount=$(findmnt -T "$probe" -n -o TARGET,SOURCE,FSTYPE,OPTIONS); [ -n "$mount" ] || exit 72; dev=$(stat -Lc "%d" -- "$probe"); printf "%s\n%s\n" "$mount" "$dev"' bash "$EXPECTED_MACHINE_ID_SHA256" "$BOOT_ID" "$AFFECTED_PATH")"; then mapfile -t TARGET_META <<<"$OUT"; MOUNT_KEY=${TARGET_META[0]}; DEVICE_KEY=${TARGET_META[1]}; TARGET_READY=true; printf 'TARGET_READY=true path=%s mount=%s stat_device=%s\n' "$AFFECTED_PATH" "$MOUNT_KEY" "$DEVICE_KEY"; else unset MOUNT_KEY DEVICE_KEY; printf '%s\n' '중단: path/mount 등록 실패' >&2; fi
```

`MOUNT_KEY`의 target/source/FSTYPE/options와 `DEVICE_KEY`가 바뀌면 remount·device mapping 변경으로 취급하고 재등록한다.

### 3. 시간 창 등록

```bash
TIME_READY=false; DOWNSTREAM_READY=false; START_RFC3339='PASTE_START_RFC3339_HERE'; END_RFC3339='PASTE_END_RFC3339_HERE'; if S=$(date -u -d "$START_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null) && E=$(date -u -d "$END_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null) && [ "$S" = "$START_RFC3339" ] && [ "$E" = "$END_RFC3339" ] && [ "$(date -u -d "$S" +%s)" -lt "$(date -u -d "$E" +%s)" ]; then TIME_READY=true; printf 'TIME_READY=true start=%s end=%s\n' "$S" "$E"; else printf '%s\n' '중단: 엄격한 UTC RFC3339 roundtrip/order 실패' >&2; fi
```

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | `ENOSPC`, `no space left on device` 또는 같은 mount의 bytes/inode 고갈 |
| 적용 | 오류 path와 실제 mount/source가 연결됨 |
| 제외 | `ro`/I/O 오류면 [[03. filesystem이 read-only로 remount된 경우]] 또는 [[04. block device I-O error가 반복되는 경우]], inode-only면 [[02. filesystem inode가 고갈된 경우]] |

검색 문자열: `no space left on device`, `ENOSPC`, `DiskPressure`, `inodesFree`, `deleted`, `read-only file system`, `I/O error`.

## 관측별 진단 경로

| 지금 보이는 것 | 먼저 볼 것 | 다음 판단 |
|---|---|---|
| bytes `Avail` 고갈 | 같은 mount의 inode와 reserved/quota 경계 | bytes owner 좁히기 |
| bytes 여유, `IFree` 고갈 | inode snapshot과 생성 경로 | inode 런북 이관 |
| 삭제 후 `df` 미회복 | deleted-open FD와 process identity | process owner 이관 |
| `ro` 또는 I/O error | source와 kernel journal 시간 | filesystem/device 런북 이관 |

## 직접 진단

각 실행은 machine-id, boot, mount와 filesystem device를 새로 확인한다. `du`는 같은 filesystem의 한 단계만 집계하며 실패를 빈 사용량으로 해석하지 않는다.

```bash
if [ "$TARGET_READY" != true ]; then printf '%s\n' '중단: target gate가 아니다.' >&2; exit 1; fi; ssh -o BatchMode=yes -o ConnectTimeout=10 -o ProxyCommand=none -o ProxyJump=none -- "$SSH_TARGET" 'set -euo pipefail; expected=$1; boot=$2; path=$3; mount_key=$4; device_key=$5; sum=$(sha256sum /etc/machine-id); [ "${sum%% *}" = "$expected" ] && [ "$(cat /proc/sys/kernel/random/boot_id)" = "$boot" ] || exit 70; probe=$path; [ -e "$probe" ] || probe=$(dirname -- "$probe"); [ "$(findmnt -T "$probe" -n -o TARGET,SOURCE,FSTYPE,OPTIONS)" = "$mount_key" ] && [ "$(stat -Lc "%d" -- "$probe")" = "$device_key" ] || exit 71; target=$(findmnt -T "$probe" -n -o TARGET); printf "observed_at=%s path=%s mount=%s\n" "$(date -u +%Y-%m-%dT%H:%M:%SZ)" "$path" "$mount_key"; df -hT -- "$target"; df -iT -- "$target"; if command -v du >/dev/null 2>&1; then set +e; sudo du -x -h --max-depth=1 -- "$target"; producer_rc=$?; set -e; printf "du_rc=%s\n" "$producer_rc"; [ "$producer_rc" -eq 0 ] || exit "$producer_rc"; else printf "%s\n" "du unavailable"; fi' bash "$EXPECTED_MACHINE_ID_SHA256" "$BOOT_ID" "$AFFECTED_PATH" "$MOUNT_KEY" "$DEVICE_KEY"
```

`df`와 `du` 차이는 deleted-open, reserved blocks, snapshots, quota 또는 backend accounting 후보이며 자동으로 특정 원인을 확정하지 않는다. 전체 파일 목록, 내용, PVC 데이터와 runtime metadata는 읽지 않는다.

### deleted-open 조건부 확인

`lsof`가 설치되어 있고 `df`가 큰데 bounded `du`가 설명하지 못할 때만 실행한다. 출력의 PID를 선택하기 전에는 close/restart를 제안하지 않는다.

```bash
if [ "$TARGET_READY" != true ]; then printf '%s\n' '중단: target gate가 아니다.' >&2; exit 1; fi; ssh -o BatchMode=yes -o ConnectTimeout=10 -o ProxyCommand=none -o ProxyJump=none -- "$SSH_TARGET" 'set -euo pipefail; expected=$1; boot=$2; path=$3; mount_key=$4; device_key=$5; sum=$(sha256sum /etc/machine-id); [ "${sum%% *}" = "$expected" ] && [ "$(cat /proc/sys/kernel/random/boot_id)" = "$boot" ] || exit 70; probe=$path; [ -e "$probe" ] || probe=$(dirname -- "$probe"); [ "$(findmnt -T "$probe" -n -o TARGET,SOURCE,FSTYPE,OPTIONS)" = "$mount_key" ] && [ "$(stat -Lc "%d" -- "$probe")" = "$device_key" ] || exit 71; command -v lsof >/dev/null 2>&1 || { printf "%s\n" "lsof unavailable" >&2; exit 72; }; sudo lsof -nP +L1 -F pcufdis' bash "$EXPECTED_MACHINE_ID_SHA256" "$BOOT_ID" "$AFFECTED_PATH" "$MOUNT_KEY" "$DEVICE_KEY"
```

```bash
unset PID_START_TICKS; PROCESS_READY=false; DOWNSTREAM_READY=false; TARGET_PID='PASTE_DELETED_OPEN_PID_HERE'; if [ "$TARGET_READY" != true ] || ! [[ "$TARGET_PID" =~ ^[0-9]+$ ]]; then printf '%s\n' '중단: PID 선택 오류' >&2; elif PID_START_TICKS="$(ssh -o BatchMode=yes -o ConnectTimeout=10 -o ProxyCommand=none -o ProxyJump=none -- "$SSH_TARGET" 'set -euo pipefail; expected=$1; boot=$2; path=$3; mount_key=$4; device_key=$5; pid=$6; sum=$(sha256sum /etc/machine-id); [ "${sum%% *}" = "$expected" ] && [ "$(cat /proc/sys/kernel/random/boot_id)" = "$boot" ] || exit 70; probe=$path; [ -e "$probe" ] || probe=$(dirname -- "$probe"); [ "$(findmnt -T "$probe" -n -o TARGET,SOURCE,FSTYPE,OPTIONS)" = "$mount_key" ] && [ "$(stat -Lc "%d" -- "$probe")" = "$device_key" ] || exit 71; [ -r "/proc/$pid/stat" ] || exit 72; printf "%s\n" "$(cut -d" " -f22 "/proc/$pid/stat")"' bash "$EXPECTED_MACHINE_ID_SHA256" "$BOOT_ID" "$AFFECTED_PATH" "$MOUNT_KEY" "$DEVICE_KEY" "$TARGET_PID")"; then PROCESS_READY=true; printf 'PROCESS_READY=true pid=%s start_ticks=%s\n' "$TARGET_PID" "$PID_START_TICKS"; else unset PID_START_TICKS; printf '%s\n' '중단: process 등록 실패' >&2; fi
```

### bounded journal

```bash
if [ "$TARGET_READY" != true ] || [ "$TIME_READY" != true ]; then printf '%s\n' '중단: target/time gate가 완전하지 않다.' >&2; exit 1; fi; ssh -o BatchMode=yes -o ConnectTimeout=10 -o ProxyCommand=none -o ProxyJump=none -- "$SSH_TARGET" 'set -euo pipefail; expected=$1; boot=$2; path=$3; mount_key=$4; device_key=$5; since=$6; until=$7; sum=$(sha256sum /etc/machine-id); [ "${sum%% *}" = "$expected" ] && [ "$(cat /proc/sys/kernel/random/boot_id)" = "$boot" ] || exit 70; probe=$path; [ -e "$probe" ] || probe=$(dirname -- "$probe"); [ "$(findmnt -T "$probe" -n -o TARGET,SOURCE,FSTYPE,OPTIONS)" = "$mount_key" ] && [ "$(stat -Lc "%d" -- "$probe")" = "$device_key" ] || exit 71; s=$(date -u -d "$since" +%Y-%m-%dT%H:%M:%SZ); e=$(date -u -d "$until" +%Y-%m-%dT%H:%M:%SZ); [ "$s" = "$since" ] && [ "$e" = "$until" ] && [ "$(date -u -d "$s" +%s)" -lt "$(date -u -d "$e" +%s)" ] || exit 72; set +e; raw=$(TZ=UTC journalctl -k --since "$since" --until "$until" --no-pager -o short-iso-precise); producer_rc=$?; set -e; [ "$producer_rc" -eq 0 ] || { printf "journal producer failed rc=%s\n" "$producer_rc" >&2; exit "$producer_rc"; }; set +e; printf "%s\n" "$raw" | grep -E -i -C 3 -- "no space left on device|ENOSPC|read-only|I/O error|filesystem|quota"; filter_rc=${PIPESTATUS[1]}; set -e; printf "producer_rc=%s filter_rc=%s requested_window=%s/%s\n" "$producer_rc" "$filter_rc" "$since" "$until"; [ "$filter_rc" -eq 0 ] || [ "$filter_rc" -eq 1 ]' bash "$EXPECTED_MACHINE_ID_SHA256" "$BOOT_ID" "$AFFECTED_PATH" "$MOUNT_KEY" "$DEVICE_KEY" "$START_RFC3339" "$END_RFC3339"
```

filter rc=1은 일치 행 없음이지 kernel 오류 부재가 아니다. 출력의 첫·마지막 실제 UTC timestamp와 journal 보존 범위를 요청 창과 함께 기록한다. 민감정보가 보이면 출력을 중단하고 비민감 오류 유형·시각만 남긴다.

## 복구 전 안전 gate와 정상화

이 문서는 삭제, truncate, FD close, process/daemon restart, image prune, remount, fsck, detach, reboot 명령을 제공하지 않는다. 외부 변경은 실행 직전에 host/process/mount/device/evidence identity를 다시 확인하고 trigger, 승인 ID, maintenance window, 대체 가용성, 영향 범위, 멱등성, 중단 조건과 검증된 rollback/보상 절차가 있어야 한다. 삭제는 일반 rollback이 없으며 재생성된 process/device/mount는 새 identity로 등록한다.

정상화는 직접 진단과 journal을 새 UTC 창에서 반복해 bytes와 inode, deleted-open 또는 quota/accounting 원인, 새 read-only/I/O 오류를 확인한다. 실제 service write/read, 기존 health check·요청 또는 Job 산출물이 정상이고 재발 창을 통과해야 한다. `df` 한 번의 회복만으로 정상화하지 않는다.

## 증거 보존과 환경별 미검증

host/boot, path, mount target/source/FSTYPE/options, filesystem device identity, UTC 창, `df`·bounded `du`, deleted-open PID/start time, journal producer/filter rc와 실제 timestamp, 실제 기능 결과를 보존한다. machine-id 원문, 전체 파일 목록·내용·argv·환경변수·민감정보는 저장하지 않는다. Kubernetes nodefs/imagefs/PVC 경로는 실제 object UID와 runtime/storage endpoint 계약이 별도로 확인된 경우에만 연결하며 현재 환경에서는 미검증이다.
