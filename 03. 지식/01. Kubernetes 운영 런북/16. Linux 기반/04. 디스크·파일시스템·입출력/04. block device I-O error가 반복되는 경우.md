# block device I-O error가 반복되는 경우

## 입력값과 빠른 수집

실행 경로는 `운영자 Bash -> 직접 SSH -> 승인된 host -> kernel journal -> 확인된 block device -> sysfs·device graph -> filesystem/mount -> storage provider`다. ProxyJump·ProxyCommand를 사용하지 않으며 bastion이 필요하면 bastion에서 이 절을 새로 시작한다. Kubernetes 이름, `/dev/sdX` 접두사 또는 mapper 이름으로 장치를 추측하지 않는다.

| 구분 | 값 | 계약 |
|---|---|---|
| 최초 입력 | `SSH_TARGET`, `EXPECTED_MACHINE_ID_SHA256` | 승인된 직접 SSH endpoint와 `/etc/machine-id` 파일 SHA-256 |
| 운영자 선택 | `START_RFC3339`, `END_RFC3339`, `DEVICE_PATH` | 사건 전후 UTC 창과 bounded kernel 증거에서 확인한 실제 `/dev` 경로 |
| system-auto | `HOSTNAME_ACTUAL`, `BOOT_ID`, `KNAME`, `MAJOR_MINOR`, `SYSFS_PATH`, `DEVICE_SIZE`, `GRAPH_HASH` | 원격 host·`lsblk`·sysfs에서 등록 |
| 계산값 | `DEVICE_RE`, producer/filter rc, device graph hash | 현재 identity와 같은 evidence window에서만 사용 |

다른 host·시간·device로 바꾸거나 조회가 실패하면 device graph, evidence, normalization을 포함한 모든 downstream 값을 먼저 폐기한다. machine-id 원문은 출력·저장하지 않는다.

### 1. 최초 입력과 host 등록

`SSH_TARGET`은 `user@host` 한 hop만 허용한다. 작업 PC의 shell 변수가 원격에 자동 전달된다고 가정하지 않고 positional argument로 넘긴다.

```bash
unset HOST_READY TIME_READY DEVICE_READY EVIDENCE_READY NORMALIZATION_READY HOSTNAME_ACTUAL BOOT_ID START_RFC3339 END_RFC3339 START_EPOCH END_EPOCH DEVICE_PATH KNAME MAJOR_MINOR DEVICE_TYPE SYSFS_PATH DEVICE_SIZE DEVICE_RO GRAPH_HASH DEVICE_RE EVIDENCE_AT PRODUCER_RC IDENTITY_FILTER_RC ERROR_FILTER_RC; SSH_TARGET='PASTE_SSH_TARGET_HERE'; EXPECTED_MACHINE_ID_SHA256='PASTE_MACHINE_ID_SHA256_HERE'; HOST_READY=false; TIME_READY=false; DEVICE_READY=false; EVIDENCE_READY=false; NORMALIZATION_READY=false; if [ -z "${BASH_VERSION:-}" ] || ! command -v ssh >/dev/null 2>&1 || ! command -v date >/dev/null 2>&1 || ! command -v grep >/dev/null 2>&1 || ! command -v sed >/dev/null 2>&1 || ! [[ "$SSH_TARGET" =~ ^[A-Za-z0-9._-]+@([A-Za-z0-9._-]+|\[[0-9A-Fa-f:]+\])$ ]] || ! [[ "$EXPECTED_MACHINE_ID_SHA256" =~ ^[0-9a-f]{64}$ ]]; then printf '%s\n' '중단: Bash·도구·직접 SSH endpoint·machine-id SHA-256 입력을 확인한다.' >&2; elif OUT="$(ssh -o BatchMode=yes -o ConnectTimeout=10 -o ProxyCommand=none -o ProxyJump=none -- "$SSH_TARGET" 'set -euo pipefail; expected=$1; command -v sha256sum >/dev/null || exit 127; sum=$(sha256sum /etc/machine-id); [ "${sum%% *}" = "$expected" ] || exit 70; printf "%s\n%s\n" "$(hostname --fqdn 2>/dev/null || hostname)" "$(cat /proc/sys/kernel/random/boot_id)"' bash "$EXPECTED_MACHINE_ID_SHA256")"; then mapfile -t HOST_META <<<"$OUT"; if [ "${#HOST_META[@]}" -eq 2 ] && [[ "${HOST_META[1]}" =~ ^[0-9a-fA-F-]{36}$ ]]; then HOSTNAME_ACTUAL=${HOST_META[0]}; BOOT_ID=${HOST_META[1]}; HOST_READY=true; printf 'HOST_READY=true host=%s boot_id=%s direct-hop-only=true\n' "$HOSTNAME_ACTUAL" "$BOOT_ID"; else unset HOSTNAME_ACTUAL BOOT_ID; printf '%s\n' '중단: host metadata 형식 오류' >&2; fi; else unset HOSTNAME_ACTUAL BOOT_ID; printf '%s\n' '중단: SSH 또는 machine identity gate 실패' >&2; fi
```

성공 gate는 `HOST_READY=true`다. 모든 후속 원격 명령은 이 값만 믿지 않고 machine-id hash와 boot ID를 다시 검사한다.

### 2. strict UTC evidence window 등록

```bash
unset START_EPOCH END_EPOCH DEVICE_PATH KNAME MAJOR_MINOR DEVICE_TYPE SYSFS_PATH DEVICE_SIZE DEVICE_RO GRAPH_HASH DEVICE_RE EVIDENCE_AT; TIME_READY=false; DEVICE_READY=false; EVIDENCE_READY=false; NORMALIZATION_READY=false; START_RFC3339='PASTE_START_RFC3339_HERE'; END_RFC3339='PASTE_END_RFC3339_HERE'; if [ "$HOST_READY" != true ] || [[ ! "$START_RFC3339" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] || [[ ! "$END_RFC3339" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]]; then printf '%s\n' '중단: host gate 또는 strict UTC RFC3339 Z 형식 오류' >&2; elif S="$(date -u -d "$START_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" && E="$(date -u -d "$END_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" && [ "$S" = "$START_RFC3339" ] && [ "$E" = "$END_RFC3339" ] && START_EPOCH="$(date -u -d "$S" +%s)" && END_EPOCH="$(date -u -d "$E" +%s)" && [ "$START_EPOCH" -lt "$END_EPOCH" ]; then TIME_READY=true; printf 'TIME_READY=true start=%s end=%s seconds=%s\n' "$S" "$E" "$((END_EPOCH-START_EPOCH))"; else printf '%s\n' '중단: UTC calendar round-trip 실패 또는 start>=end' >&2; fi
```

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | 같은 block identity에 `I/O error`, `Buffer I/O error`, `critical medium error`, timeout·offline이 strict UTC 창에서 반복됨 |
| 적용 | host·boot, KNAME·major:minor·sysfs·size와 device graph를 현재 값으로 연결 가능 |
| 제외 | 오류 없이 latency·queue만 높으면 [[05. disk latency와 I-O queue가 지속적으로 높은 경우]], `ro` 전환이 주증상이면 [[03. filesystem이 read-only로 remount된 경우]], Kubernetes `FailedMount`·`FailedAttachVolume`이 최초 관측이면 해당 Pod·CSI 런북 |

검색 문자열: `I/O error`, `blk_update_request`, `Buffer I/O error`, `critical medium error`, `uncorrectable`, `timed out`, `device offline`, `reset controller`, `read-only`, `multipath`.

## 관측별 진단 경로

| 지금 보이는 것 | 먼저 볼 것 | 그다음 어디를 볼지 | 상세 절 |
|---|---|---|---|
| device 이름 없는 kernel I/O 오류 | bounded journal의 식별자·시각·read/write·sector | 실제 KNAME·major:minor 후보 | [[#1. device 후보를 위한 bounded kernel evidence\|1]] |
| 같은 KNAME·major:minor 오류 반복 | sysfs·size·graph hash | partition·mapper·filesystem·mount | [[#2. block identity와 graph 등록\|2]], [[#3. 현재 device의 결정적 kernel evidence\|3]] |
| read-only·filesystem 오류가 이어짐 | graph의 source·FSTYPE·mount options | filesystem owner | [[#4. filesystem·mount와 provider 경계\|4]] |
| 현재 SMART/provider는 정상 | 관측 시각과 device identity | 과거 kernel 증거와 현재 health 분리 | [[#4. filesystem·mount와 provider 경계\|4]] |

### 1. device 후보를 위한 bounded kernel evidence

아직 장치를 선택하지 않았으므로 이 명령은 오류 후보만 보여 준다. producer 실패와 filter no-match를 분리한다.

```bash
unset RAW MATCH PRODUCER_RC ERROR_FILTER_RC; EVIDENCE_READY=false; NORMALIZATION_READY=false; if [ "$HOST_READY" != true ] || [ "$TIME_READY" != true ]; then printf '%s\n' '중단: current host/time gate가 완전하지 않다.' >&2; elif RAW="$(ssh -o BatchMode=yes -o ConnectTimeout=10 -o ProxyCommand=none -o ProxyJump=none -- "$SSH_TARGET" 'set -euo pipefail; expected=$1; boot=$2; since=$3; until=$4; sum=$(sha256sum /etc/machine-id); [ "${sum%% *}" = "$expected" ] && [ "$(cat /proc/sys/kernel/random/boot_id)" = "$boot" ] || exit 70; s=$(date -u -d "$since" +%Y-%m-%dT%H:%M:%SZ); e=$(date -u -d "$until" +%Y-%m-%dT%H:%M:%SZ); [ "$s" = "$since" ] && [ "$e" = "$until" ] && [ "$(date -u -d "$s" +%s)" -lt "$(date -u -d "$e" +%s)" ] || exit 71; command -v journalctl >/dev/null || exit 127; TZ=UTC sudo -n journalctl -k --since "$since" --until "$until" --no-pager -o short-iso-precise' bash "$EXPECTED_MACHINE_ID_SHA256" "$BOOT_ID" "$START_RFC3339" "$END_RFC3339")"; then PRODUCER_RC=0; MATCH="$(grep -E -i -C 3 -- 'I/O error|blk_update_request|Buffer I/O error|critical medium error|uncorrectable|timed out|device offline|reset controller|read-only|multipath' <<<"$RAW")"; ERROR_FILTER_RC=$?; if [ "$ERROR_FILTER_RC" -eq 0 ]; then printf '%s\n' "$MATCH"; elif [ "$ERROR_FILTER_RC" -eq 1 ]; then printf '%s\n' 'filter 일치 없음: 오류 부재가 아니라 이 window에서 후보를 얻지 못함' >&2; else printf 'filter 실패 rc=%s\n' "$ERROR_FILTER_RC" >&2; fi; printf 'producer_rc=%s filter_rc=%s requested_window=%s/%s\n' "$PRODUCER_RC" "$ERROR_FILTER_RC" "$START_RFC3339" "$END_RFC3339"; else PRODUCER_RC=$?; printf 'journal producer 실패 rc=%s\n' "$PRODUCER_RC" >&2; fi; unset RAW MATCH
```

출력에서 실제 UTC timestamp, KNAME 또는 major:minor, read/write 방향, sector/LBA와 반복 횟수를 본다. 빈 결과는 kernel 정상 증거가 아니다. journal 보존·권한·시간대가 확인되지 않으면 `historical kernel evidence unavailable`로 기록한다. 민감 경로·개인정보가 보이면 표시·저장을 중단하고 시각·장치 식별자·오류 종류만 남긴다.

### 2. block identity와 graph 등록

`DEVICE_PATH`는 위 bounded kernel 행을 `lsblk`·sysfs와 대조해 확인한 block device다. 임의의 첫 후보를 선택하지 않는다.

```bash
unset KNAME MAJOR_MINOR DEVICE_TYPE SYSFS_PATH DEVICE_SIZE DEVICE_RO GRAPH_HASH DEVICE_RE EVIDENCE_AT; DEVICE_READY=false; EVIDENCE_READY=false; NORMALIZATION_READY=false; DEVICE_PATH='PASTE_DEVICE_PATH_HERE'; if [ "$HOST_READY" != true ] || [ "$TIME_READY" != true ] || [[ ! "$DEVICE_PATH" =~ ^/dev/[A-Za-z0-9._/+:-]+$ ]]; then printf '%s\n' '중단: current host/time gate와 확인된 /dev 경로가 필요하다.' >&2; elif OUT="$(ssh -o BatchMode=yes -o ConnectTimeout=10 -o ProxyCommand=none -o ProxyJump=none -- "$SSH_TARGET" 'set -euo pipefail; expected=$1; boot=$2; device=$3; sum=$(sha256sum /etc/machine-id); [ "${sum%% *}" = "$expected" ] && [ "$(cat /proc/sys/kernel/random/boot_id)" = "$boot" ] || exit 70; command -v lsblk >/dev/null && command -v sha256sum >/dev/null || exit 127; [ -b "$device" ] || exit 71; k=$(lsblk -dn -o KNAME -- "$device"); mm=$(lsblk -dn -o MAJ:MIN -- "$device"); type=$(lsblk -dn -o TYPE -- "$device"); sysfs=$(readlink -f "/sys/class/block/$k"); size=$(cat "/sys/class/block/$k/size"); ro=$(cat "/sys/class/block/$k/ro"); graph=$(lsblk -p -n -o NAME,KNAME,TYPE,PKNAME,MAJ:MIN,FSTYPE,RO,SIZE,MOUNTPOINTS -- "$device"); [ -n "$k" ] && [ -n "$mm" ] && [ -n "$sysfs" ] && [ -n "$graph" ] || exit 72; hash=$(printf "%s\n" "$graph" | sha256sum); printf "%s\n%s\n%s\n%s\n%s\n%s\n%s\n" "$k" "$mm" "$type" "$sysfs" "$size" "$ro" "${hash%% *}"' bash "$EXPECTED_MACHINE_ID_SHA256" "$BOOT_ID" "$DEVICE_PATH")"; then mapfile -t DEVICE_META <<<"$OUT"; if [ "${#DEVICE_META[@]}" -eq 7 ] && [[ "${DEVICE_META[1]}" =~ ^[0-9]+:[0-9]+$ ]] && [[ "${DEVICE_META[6]}" =~ ^[0-9a-f]{64}$ ]]; then KNAME=${DEVICE_META[0]}; MAJOR_MINOR=${DEVICE_META[1]}; DEVICE_TYPE=${DEVICE_META[2]}; SYSFS_PATH=${DEVICE_META[3]}; DEVICE_SIZE=${DEVICE_META[4]}; DEVICE_RO=${DEVICE_META[5]}; GRAPH_HASH=${DEVICE_META[6]}; DEVICE_RE="$(printf '%s' "$KNAME" | sed 's/[][\\.^$*+?(){}|]/\\&/g')"; DEVICE_READY=true; printf 'DEVICE_READY=true path=%s kname=%s major:minor=%s type=%s sysfs=%s sectors=%s ro=%s graph_sha256=%s\n' "$DEVICE_PATH" "$KNAME" "$MAJOR_MINOR" "$DEVICE_TYPE" "$SYSFS_PATH" "$DEVICE_SIZE" "$DEVICE_RO" "$GRAPH_HASH"; else unset KNAME MAJOR_MINOR DEVICE_TYPE SYSFS_PATH DEVICE_SIZE DEVICE_RO GRAPH_HASH DEVICE_RE; printf '%s\n' '중단: block identity metadata 형식 오류' >&2; fi; else unset KNAME MAJOR_MINOR DEVICE_TYPE SYSFS_PATH DEVICE_SIZE DEVICE_RO GRAPH_HASH DEVICE_RE; printf '%s\n' '중단: block identity 등록 실패' >&2; fi
```

device graph는 current identity를 원격 경계에서 다시 확인한 뒤 읽는다.

```bash
if [ "$DEVICE_READY" != true ]; then printf '%s\n' '중단: DEVICE_READY가 아니다.' >&2; exit 1; fi; ssh -o BatchMode=yes -o ConnectTimeout=10 -o ProxyCommand=none -o ProxyJump=none -- "$SSH_TARGET" 'set -euo pipefail; expected=$1; boot=$2; device=$3; kname=$4; mm=$5; sysfs=$6; size=$7; graph_hash=$8; sum=$(sha256sum /etc/machine-id); [ "${sum%% *}" = "$expected" ] && [ "$(cat /proc/sys/kernel/random/boot_id)" = "$boot" ] || exit 70; [ -b "$device" ] && [ "$(lsblk -dn -o KNAME -- "$device")" = "$kname" ] && [ "$(lsblk -dn -o MAJ:MIN -- "$device")" = "$mm" ] && [ "$(readlink -f "/sys/class/block/$kname")" = "$sysfs" ] && [ "$(cat "/sys/class/block/$kname/size")" = "$size" ] || exit 71; graph=$(lsblk -p -n -o NAME,KNAME,TYPE,PKNAME,MAJ:MIN,FSTYPE,RO,SIZE,MOUNTPOINTS -- "$device"); hash=$(printf "%s\n" "$graph" | sha256sum); [ "${hash%% *}" = "$graph_hash" ] || exit 72; printf "%s\n" "$graph"; printf "%s\n" "--- direct mounts ---"; findmnt -rn -S "$device" -o TARGET,SOURCE,FSTYPE,OPTIONS || [ "$?" -eq 1 ]' bash "$EXPECTED_MACHINE_ID_SHA256" "$BOOT_ID" "$DEVICE_PATH" "$KNAME" "$MAJOR_MINOR" "$SYSFS_PATH" "$DEVICE_SIZE" "$GRAPH_HASH"
```

빈 direct mount는 오류가 아니라 partition·mapper 아래에 filesystem이 있거나 mount가 없을 수 있다는 뜻이다. `PKNAME`, `TYPE`, major:minor와 `findmnt SOURCE`가 `device -> partition -> mapper -> filesystem -> mount`의 각 관계를 지지해야 한다. graph hash가 바뀌면 기존 evidence를 폐기하고 새 identity로 다시 등록한다.

### 3. 현재 device의 결정적 kernel evidence

선택한 device와 같은 identity를 원격에서 재검증하고 같은 UTC 창의 journal을 다시 읽는다. identity filter와 오류 filter를 별도로 판정한다.

```bash
unset RAW DEVICE_LINES ERROR_LINES PRODUCER_RC IDENTITY_FILTER_RC ERROR_FILTER_RC EVIDENCE_AT; EVIDENCE_READY=false; NORMALIZATION_READY=false; if [ "$DEVICE_READY" != true ] || [ "$TIME_READY" != true ]; then printf '%s\n' '중단: current device/time gate가 완전하지 않다.' >&2; elif RAW="$(ssh -o BatchMode=yes -o ConnectTimeout=10 -o ProxyCommand=none -o ProxyJump=none -- "$SSH_TARGET" 'set -euo pipefail; expected=$1; boot=$2; device=$3; kname=$4; mm=$5; sysfs=$6; size=$7; graph_hash=$8; since=$9; until=${10}; sum=$(sha256sum /etc/machine-id); [ "${sum%% *}" = "$expected" ] && [ "$(cat /proc/sys/kernel/random/boot_id)" = "$boot" ] || exit 70; [ -b "$device" ] && [ "$(lsblk -dn -o KNAME -- "$device")" = "$kname" ] && [ "$(lsblk -dn -o MAJ:MIN -- "$device")" = "$mm" ] && [ "$(readlink -f "/sys/class/block/$kname")" = "$sysfs" ] && [ "$(cat "/sys/class/block/$kname/size")" = "$size" ] || exit 71; graph=$(lsblk -p -n -o NAME,KNAME,TYPE,PKNAME,MAJ:MIN,FSTYPE,RO,SIZE,MOUNTPOINTS -- "$device"); hash=$(printf "%s\n" "$graph" | sha256sum); [ "${hash%% *}" = "$graph_hash" ] || exit 72; s=$(date -u -d "$since" +%Y-%m-%dT%H:%M:%SZ); e=$(date -u -d "$until" +%Y-%m-%dT%H:%M:%SZ); [ "$s" = "$since" ] && [ "$e" = "$until" ] && [ "$(date -u -d "$s" +%s)" -lt "$(date -u -d "$e" +%s)" ] || exit 73; TZ=UTC sudo -n journalctl -k --since "$since" --until "$until" --no-pager -o short-iso-precise' bash "$EXPECTED_MACHINE_ID_SHA256" "$BOOT_ID" "$DEVICE_PATH" "$KNAME" "$MAJOR_MINOR" "$SYSFS_PATH" "$DEVICE_SIZE" "$GRAPH_HASH" "$START_RFC3339" "$END_RFC3339")"; then PRODUCER_RC=0; DEVICE_LINES="$(grep -E -i -C 4 -- "(^|[^[:alnum:]_])${DEVICE_RE}([^[:alnum:]_]|$)|${MAJOR_MINOR}" <<<"$RAW")"; IDENTITY_FILTER_RC=$?; if [ "$IDENTITY_FILTER_RC" -eq 0 ]; then ERROR_LINES="$(grep -E -i -C 3 -- 'I/O error|blk_update_request|Buffer I/O error|critical medium error|uncorrectable|timed out|device offline|reset controller|read-only|multipath' <<<"$DEVICE_LINES")"; ERROR_FILTER_RC=$?; if [ "$ERROR_FILTER_RC" -eq 0 ]; then EVIDENCE_AT="$(date -u '+%Y-%m-%dT%H:%M:%SZ')"; EVIDENCE_READY=true; printf '%s\n' "$ERROR_LINES"; printf 'EVIDENCE_READY=true at=%s producer_rc=0 identity_filter_rc=0 error_filter_rc=0 device=%s graph=%s\n' "$EVIDENCE_AT" "$MAJOR_MINOR" "$GRAPH_HASH"; elif [ "$ERROR_FILTER_RC" -eq 1 ]; then printf '%s\n' 'device 행은 있으나 결정적 오류 filter 일치 없음' >&2; else printf '오류 filter 실패 rc=%s\n' "$ERROR_FILTER_RC" >&2; fi; elif [ "$IDENTITY_FILTER_RC" -eq 1 ]; then printf '%s\n' '현재 device identity와 일치하는 journal 행 없음' >&2; else printf 'identity filter 실패 rc=%s\n' "$IDENTITY_FILTER_RC" >&2; fi; else PRODUCER_RC=$?; printf 'journal/device producer 실패 rc=%s\n' "$PRODUCER_RC" >&2; fi; unset RAW DEVICE_LINES ERROR_LINES
```

`EVIDENCE_READY=true`는 현재 device identity와 결정적 오류 문자열이 같은 bounded 출력에 있다는 뜻이다. sector/LBA·read/write·오류 시각까지 같은 장치에 연결해야 원인을 확정하며, 인접 context의 다른 장치 오류를 섞지 않는다. 현재 SMART 정상, mount 정상 또는 오류가 잠시 멈춘 사실은 과거 I/O 실패와 데이터 무결성을 부정하지 않는다.

### 4. filesystem·mount와 provider 경계

현재 graph 출력에서 filesystem과 mount가 확인되면 [[03. filesystem이 read-only로 remount된 경우]]의 path/mount identity 계약으로 이동한다. `ro`, corruption, journal abort가 같은 시각이면 용량 정리나 재시작으로 닫지 않는다. mount가 없거나 raw device·LVM PV라면 filesystem 명령을 억지로 실행하지 않는다.

SMART는 local block device와 passthrough 지원이 확인된 경우에만 보조 증거로 읽는다. serial·WWN 원문은 보존하지 않는다.

```bash
if [ "$DEVICE_READY" != true ]; then printf '%s\n' '중단: DEVICE_READY가 아니다.' >&2; exit 1; fi; ssh -o BatchMode=yes -o ConnectTimeout=10 -o ProxyCommand=none -o ProxyJump=none -- "$SSH_TARGET" 'set -euo pipefail; expected=$1; boot=$2; device=$3; kname=$4; mm=$5; sysfs=$6; size=$7; graph_hash=$8; sum=$(sha256sum /etc/machine-id); [ "${sum%% *}" = "$expected" ] && [ "$(cat /proc/sys/kernel/random/boot_id)" = "$boot" ] || exit 70; [ -b "$device" ] && [ "$(lsblk -dn -o KNAME -- "$device")" = "$kname" ] && [ "$(lsblk -dn -o MAJ:MIN -- "$device")" = "$mm" ] && [ "$(readlink -f "/sys/class/block/$kname")" = "$sysfs" ] && [ "$(cat "/sys/class/block/$kname/size")" = "$size" ] || exit 71; graph=$(lsblk -p -n -o NAME,KNAME,TYPE,PKNAME,MAJ:MIN,FSTYPE,RO,SIZE,MOUNTPOINTS -- "$device"); hash=$(printf "%s\n" "$graph" | sha256sum); [ "${hash%% *}" = "$graph_hash" ] || exit 72; command -v smartctl >/dev/null || { printf "%s\n" "smartctl unavailable" >&2; exit 127; }; sudo -n smartctl -H -A -- "$device"' bash "$EXPECTED_MACHINE_ID_SHA256" "$BOOT_ID" "$DEVICE_PATH" "$KNAME" "$MAJOR_MINOR" "$SYSFS_PATH" "$DEVICE_SIZE" "$GRAPH_HASH"
```

`smartctl` 미설치, passthrough 미지원과 권한 실패를 `PASSED`로 해석하지 않는다. cloud·SAN·RAID·multipath·hypervisor 상태는 승인된 provider inventory에서 volume/LUN identity와 관측 시각을 현재 KNAME·major:minor·sysfs graph에 연결한다. provider `healthy`는 guest path의 과거 오류를 배제하지 않으며, provider identity를 확인하지 못하면 `미확정`으로 이관한다.

## 복구 전 안전 gate

이 문서는 reset, rescan, detach·force detach, unmount/remount, fsck·repair·format, multipath 변경, 파일 삭제, daemon·kubelet·CSI·runtime 재시작, drain 또는 reboot 명령을 제공하지 않는다. 외부 변경은 실행 직전에 machine-id hash, boot ID, KNAME·major:minor·sysfs·size·graph hash, fresh evidence window를 다시 확인하고 trigger, 승인 ID, maintenance window, 백업·대체 가용성, 데이터 무결성 영향, 멱등성, 중단 조건과 검증된 rollback·보상 절차가 모두 있어야 한다. device나 graph가 교체되면 과거 이름과 READY를 재사용하지 않고 새 identity로 등록한다.

## 정상화 검증

승인된 외부 조치 후 새 strict UTC 창을 등록하고 2절의 device identity·graph와 3절의 kernel evidence를 다시 실행한다. 정상화 순서는 `provider/path -> block identity·graph -> kernel 오류 비재발 -> filesystem/mount -> 실제 service read/write·health check·요청 또는 Job 산출물`이다. 새 창에서 producer가 성공하고 현재 device filter가 유효한 상태로 I/O·timeout·read-only 오류가 재발하지 않으며 실제 기능이 승인 기준을 충족해야 `NORMALIZATION_READY=true`로 기록한다. 빈 journal, SMART `PASSED`, mount `rw` 또는 process 생존 하나만으로 정상화하지 않는다.

## 증거 보존과 환경별 미검증

host·boot, machine-id hash 검증 성공 여부, strict UTC 요청 창과 실제 journal timestamp, producer/identity/error filter rc, device path·KNAME·major:minor·type·sysfs·size·RO·graph hash, bounded 결정적 오류의 read/write·sector, filesystem/mount 관계, SMART/provider 결과의 별도 관측 시각, 실제 기능 결과를 보존한다. machine-id 원문, serial·WWN, 전체 journal, 파일 내용, argv, Secret·token·개인키·개인정보는 저장하지 않는다. 실제 SSH, kernel journal 보존, SMART passthrough, provider와 Kubernetes/CSI/runtime mapping은 환경별 미검증이다.
