# filesystem이 read-only로 remount된 경우

## 입력값과 빠른 수집

실행 경로는 `운영자 Bash -> 직접 SSH -> 대상 host -> 오류 path -> 실제 mount/source -> kernel journal`이다. application의 read-only 설정과 kernel remount를 분리한다. retarget·실패 전에 host, mount/device, 시간과 downstream gate를 무효화한다.

| 구분 | 값 | 계약 |
|---|---|---|
| 최초 입력 | `SSH_TARGET`, `EXPECTED_MACHINE_ID_SHA256` | 승인된 직접 endpoint와 machine-id 파일 hash |
| 운영자 선택 | `AFFECTED_PATH`, strict UTC 창 | 오류와 사건 기록에서 선택 |
| system-auto | `BOOT_ID`, `MOUNT_KEY`, `DEVICE_KEY` | 실제 target/source/FSTYPE/options와 filesystem device |
| 계산값 | 현재 `ro` 여부, bytes/inode, journal 시간 상관 | 같은 identity에서만 판정 |

### 1. host·mount·시간 등록

```bash
unset HOST_READY TARGET_READY TIME_READY DOWNSTREAM_READY HOSTNAME_ACTUAL BOOT_ID AFFECTED_PATH MOUNT_KEY DEVICE_KEY START_RFC3339 END_RFC3339; SSH_TARGET='PASTE_SSH_TARGET_HERE'; EXPECTED_MACHINE_ID_SHA256='PASTE_MACHINE_ID_SHA256_HERE'; HOST_READY=false; if [ -z "${BASH_VERSION:-}" ] || ! command -v ssh >/dev/null 2>&1 || ! command -v date >/dev/null 2>&1 || ! [[ "$SSH_TARGET" =~ ^[A-Za-z0-9._-]+@([A-Za-z0-9._-]+|\[[0-9A-Fa-f:]+\])$ ]] || ! [[ "$EXPECTED_MACHINE_ID_SHA256" =~ ^[0-9a-f]{64}$ ]]; then printf '%s\n' '중단: Bash, ssh, date 또는 최초 입력 오류' >&2; elif OUT="$(ssh -o BatchMode=yes -o ConnectTimeout=10 -o ProxyCommand=none -o ProxyJump=none -- "$SSH_TARGET" 'set -euo pipefail; sum=$(sha256sum /etc/machine-id); [ "${sum%% *}" = "$1" ] || exit 70; printf "%s\n%s\n" "$(hostname --fqdn 2>/dev/null || hostname)" "$(cat /proc/sys/kernel/random/boot_id)"' bash "$EXPECTED_MACHINE_ID_SHA256")"; then mapfile -t H <<<"$OUT"; if [ "${#H[@]}" -eq 2 ] && [ -n "${H[0]}" ] && [[ "${H[1]}" =~ ^[0-9a-fA-F-]{36}$ ]]; then HOSTNAME_ACTUAL=${H[0]}; BOOT_ID=${H[1]}; HOST_READY=true; printf 'HOST_READY=true host=%s boot=%s\n' "$HOSTNAME_ACTUAL" "$BOOT_ID"; else unset HOSTNAME_ACTUAL BOOT_ID; printf '%s\n' '중단: host metadata 형식 오류' >&2; fi; else unset HOSTNAME_ACTUAL BOOT_ID; printf '%s\n' '중단: SSH/machine identity 실패' >&2; fi
```

```bash
unset MOUNT_KEY DEVICE_KEY START_RFC3339 END_RFC3339; TARGET_READY=false; TIME_READY=false; DOWNSTREAM_READY=false; AFFECTED_PATH='PASTE_AFFECTED_PATH_HERE'; if [ "$HOST_READY" != true ] || [ "${AFFECTED_PATH#/}" = "$AFFECTED_PATH" ]; then printf '%s\n' '중단: host/path gate 실패' >&2; elif OUT="$(ssh -o BatchMode=yes -o ConnectTimeout=10 -o ProxyCommand=none -o ProxyJump=none -- "$SSH_TARGET" 'set -euo pipefail; expected=$1; boot=$2; path=$3; sum=$(sha256sum /etc/machine-id); [ "${sum%% *}" = "$expected" ] && [ "$(cat /proc/sys/kernel/random/boot_id)" = "$boot" ] || exit 70; probe=$path; [ -e "$probe" ] || probe=$(dirname -- "$probe"); [ -e "$probe" ] || exit 71; printf "%s\n%s\n" "$(findmnt -T "$probe" -n -o TARGET,SOURCE,FSTYPE,OPTIONS)" "$(stat -Lc "%d" -- "$probe")"' bash "$EXPECTED_MACHINE_ID_SHA256" "$BOOT_ID" "$AFFECTED_PATH")"; then mapfile -t M <<<"$OUT"; MOUNT_KEY=${M[0]}; DEVICE_KEY=${M[1]}; TARGET_READY=true; printf 'TARGET_READY=true mount=%s stat_device=%s\n' "$MOUNT_KEY" "$DEVICE_KEY"; else unset MOUNT_KEY DEVICE_KEY; printf '%s\n' '중단: mount 등록 실패' >&2; fi
```

```bash
TIME_READY=false; DOWNSTREAM_READY=false; START_RFC3339='PASTE_START_RFC3339_HERE'; END_RFC3339='PASTE_END_RFC3339_HERE'; if S=$(date -u -d "$START_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null) && E=$(date -u -d "$END_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null) && [ "$S" = "$START_RFC3339" ] && [ "$E" = "$END_RFC3339" ] && [ "$(date -u -d "$S" +%s)" -lt "$(date -u -d "$E" +%s)" ]; then TIME_READY=true; printf 'TIME_READY=true start=%s end=%s\n' "$S" "$E"; else printf '%s\n' '중단: UTC RFC3339 roundtrip/order 실패' >&2; fi
```

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | 실제 mount options의 `ro` 또는 같은 source·시간의 kernel remount 증거 |
| 적용 | mount/source와 오류 창을 연결 가능 |
| 제외 | host mount가 `rw`이고 application/container 설정만 RO면 workload owner, inode/bytes면 해당 용량 런북 |

검색 문자열: `read-only file system`, `Remounting filesystem read-only`, `I/O error`, `EXT4-fs error`, `XFS`, `BTRFS`, `ro`, `rw`.

## 직접 진단

```bash
if [ "$TARGET_READY" != true ]; then printf '%s\n' '중단: target gate가 아니다.' >&2; exit 1; fi; ssh -o BatchMode=yes -o ConnectTimeout=10 -o ProxyCommand=none -o ProxyJump=none -- "$SSH_TARGET" 'set -euo pipefail; expected=$1; boot=$2; path=$3; mount_key=$4; device_key=$5; sum=$(sha256sum /etc/machine-id); [ "${sum%% *}" = "$expected" ] && [ "$(cat /proc/sys/kernel/random/boot_id)" = "$boot" ] || exit 70; probe=$path; [ -e "$probe" ] || probe=$(dirname -- "$probe"); [ "$(findmnt -T "$probe" -n -o TARGET,SOURCE,FSTYPE,OPTIONS)" = "$mount_key" ] && [ "$(stat -Lc "%d" -- "$probe")" = "$device_key" ] || exit 71; target=$(findmnt -T "$probe" -n -o TARGET); printf "observed_at=%s path=%s mount=%s\n" "$(date -u +%Y-%m-%dT%H:%M:%SZ)" "$path" "$mount_key"; findmnt -T "$probe" -o TARGET,SOURCE,FSTYPE,OPTIONS; df -hT -- "$target"; df -iT -- "$target"' bash "$EXPECTED_MACHINE_ID_SHA256" "$BOOT_ID" "$AFFECTED_PATH" "$MOUNT_KEY" "$DEVICE_KEY"
```

현재 `rw`는 과거 `ro` 전환을 부정하지 않는다. `ro`는 kernel/filesystem/device 원인 후보지만 단독으로 손상 원인을 확정하지 않는다. bytes와 inode 고갈도 분리한다.

## bounded kernel journal

```bash
if [ "$TARGET_READY" != true ] || [ "$TIME_READY" != true ]; then printf '%s\n' '중단: target/time gate가 완전하지 않다.' >&2; exit 1; fi; ssh -o BatchMode=yes -o ConnectTimeout=10 -o ProxyCommand=none -o ProxyJump=none -- "$SSH_TARGET" 'set -euo pipefail; expected=$1; boot=$2; path=$3; mount_key=$4; device_key=$5; since=$6; until=$7; sum=$(sha256sum /etc/machine-id); [ "${sum%% *}" = "$expected" ] && [ "$(cat /proc/sys/kernel/random/boot_id)" = "$boot" ] || exit 70; probe=$path; [ -e "$probe" ] || probe=$(dirname -- "$probe"); [ "$(findmnt -T "$probe" -n -o TARGET,SOURCE,FSTYPE,OPTIONS)" = "$mount_key" ] && [ "$(stat -Lc "%d" -- "$probe")" = "$device_key" ] || exit 71; s=$(date -u -d "$since" +%Y-%m-%dT%H:%M:%SZ); e=$(date -u -d "$until" +%Y-%m-%dT%H:%M:%SZ); [ "$s" = "$since" ] && [ "$e" = "$until" ] && [ "$(date -u -d "$s" +%s)" -lt "$(date -u -d "$e" +%s)" ] || exit 72; set +e; raw=$(TZ=UTC journalctl -k --since "$since" --until "$until" --no-pager -o short-iso-precise); producer_rc=$?; set -e; [ "$producer_rc" -eq 0 ] || { printf "journal producer failed rc=%s\n" "$producer_rc" >&2; exit "$producer_rc"; }; set +e; printf "%s\n" "$raw" | grep -E -i -C 3 -- "read-only|remount|I/O error|filesystem|corrupt|ext4|xfs|btrfs|device"; filter_rc=${PIPESTATUS[1]}; set -e; printf "producer_rc=%s filter_rc=%s requested_window=%s/%s\n" "$producer_rc" "$filter_rc" "$since" "$until"; [ "$filter_rc" -eq 0 ] || [ "$filter_rc" -eq 1 ]' bash "$EXPECTED_MACHINE_ID_SHA256" "$BOOT_ID" "$AFFECTED_PATH" "$MOUNT_KEY" "$DEVICE_KEY" "$START_RFC3339" "$END_RFC3339"
```

source/device와 실제 UTC timestamp가 맞는 행만 직접 증거다. producer rc와 no-match(rc=1)를 분리하고 journal의 실제 첫·마지막 timestamp와 보존 범위를 기록한다. 민감정보는 저장하지 않는다.

## application RO 경계

host mount가 `rw`이고 kernel remount 증거가 없을 때만 application 설정을 본다. Kubernetes/runtime 경로는 Pod UID, container ID, runtime endpoint와 실행 host identity가 모두 확인된 별도 런북에서 수행한다. `readOnlyRootFilesystem`이나 volume `readOnly`는 host remount 증거가 아니며 이 문서에서 broad Kubernetes 조회를 실행하지 않는다.

## 복구 전 안전 gate와 정상화

이 문서는 `remount,rw`, fsck/repair, device reset, reboot, file 삭제, daemon/Pod restart 명령을 제공하지 않는다. 외부 변경은 fresh host/mount/device/evidence gate, trigger, 승인 ID, maintenance window, 백업·snapshot과 대체 가용성, 영향 범위, 멱등성, 중단 조건, 검증된 rollback/보상 절차가 필요하다. repair·remount는 일반적인 즉시 rollback을 가정하지 않으며 재생성된 mount/device/process를 재등록한다.

정상화는 새 UTC 창에서 mount identity/options와 journal을 다시 확인하고 bytes/inode, 새 RO/I/O/corruption, 실제 service write/read·health check·요청 또는 Job 산출물과 재발 창을 검증한다. `rw` 한 번 또는 process 생존만으로 닫지 않는다.

## 증거 보존과 환경별 미검증

host/boot, path, target/source/FSTYPE/options, device identity, strict UTC 창, bytes/inode, journal producer/filter rc·실제 timestamp, 실제 기능 결과를 보존한다. machine-id 원문, 전체 journal/config·환경변수·민감정보는 저장하지 않는다. filesystem repair 절차와 Kubernetes/CSI/runtime mapping은 환경별 미검증이다.
