# filesystem inode가 고갈된 경우

## 입력값과 빠른 수집

실행 경로는 `운영자 Bash -> 직접 SSH -> 대상 host -> 오류 path -> 실제 mount/source`다. path·host가 바뀌거나 실패하면 mount/device/time과 downstream gate를 먼저 무효화한다.

| 구분 | 값 | 계약 |
|---|---|---|
| 최초 입력 | `SSH_TARGET`, `EXPECTED_MACHINE_ID_SHA256` | 승인된 직접 endpoint와 machine-id 파일 hash |
| 운영자 선택 | `AFFECTED_PATH`, `START_RFC3339`, `END_RFC3339` | 오류 메시지와 사건 기록에서 선택 |
| system-auto | `BOOT_ID`, `MOUNT_KEY`, `DEVICE_KEY` | target/source/FSTYPE/options와 filesystem device |
| 계산값 | bytes·inode snapshot, 한 단계 inode 집계 | 같은 identity 안에서만 비교 |

### 1. host·mount·시간 등록

```bash
unset HOST_READY TARGET_READY TIME_READY DOWNSTREAM_READY HOSTNAME_ACTUAL BOOT_ID AFFECTED_PATH MOUNT_KEY DEVICE_KEY START_RFC3339 END_RFC3339; SSH_TARGET='PASTE_SSH_TARGET_HERE'; EXPECTED_MACHINE_ID_SHA256='PASTE_MACHINE_ID_SHA256_HERE'; HOST_READY=false; if [ -z "${BASH_VERSION:-}" ] || ! command -v ssh >/dev/null 2>&1 || ! command -v date >/dev/null 2>&1 || ! [[ "$SSH_TARGET" =~ ^[A-Za-z0-9._-]+@([A-Za-z0-9._-]+|\[[0-9A-Fa-f:]+\])$ ]] || ! [[ "$EXPECTED_MACHINE_ID_SHA256" =~ ^[0-9a-f]{64}$ ]]; then printf '%s\n' '중단: Bash, ssh, date 또는 최초 입력 오류' >&2; elif OUT="$(ssh -o BatchMode=yes -o ConnectTimeout=10 -o ProxyCommand=none -o ProxyJump=none -- "$SSH_TARGET" 'set -euo pipefail; sum=$(sha256sum /etc/machine-id); [ "${sum%% *}" = "$1" ] || exit 70; printf "%s\n%s\n" "$(hostname --fqdn 2>/dev/null || hostname)" "$(cat /proc/sys/kernel/random/boot_id)"' bash "$EXPECTED_MACHINE_ID_SHA256")"; then mapfile -t H <<<"$OUT"; if [ "${#H[@]}" -eq 2 ] && [ -n "${H[0]}" ] && [[ "${H[1]}" =~ ^[0-9a-fA-F-]{36}$ ]]; then HOSTNAME_ACTUAL=${H[0]}; BOOT_ID=${H[1]}; HOST_READY=true; printf 'HOST_READY=true host=%s boot=%s\n' "$HOSTNAME_ACTUAL" "$BOOT_ID"; else unset HOSTNAME_ACTUAL BOOT_ID; printf '%s\n' '중단: host metadata 형식 오류' >&2; fi; else unset HOSTNAME_ACTUAL BOOT_ID; printf '%s\n' '중단: SSH/machine identity 실패' >&2; fi
```

```bash
unset MOUNT_KEY DEVICE_KEY START_RFC3339 END_RFC3339; TARGET_READY=false; TIME_READY=false; DOWNSTREAM_READY=false; AFFECTED_PATH='PASTE_AFFECTED_PATH_HERE'; if [ "$HOST_READY" != true ] || [ "${AFFECTED_PATH#/}" = "$AFFECTED_PATH" ]; then printf '%s\n' '중단: host/path gate 실패' >&2; elif OUT="$(ssh -o BatchMode=yes -o ConnectTimeout=10 -o ProxyCommand=none -o ProxyJump=none -- "$SSH_TARGET" 'set -euo pipefail; expected=$1; boot=$2; path=$3; sum=$(sha256sum /etc/machine-id); [ "${sum%% *}" = "$expected" ] && [ "$(cat /proc/sys/kernel/random/boot_id)" = "$boot" ] || exit 70; probe=$path; [ -e "$probe" ] || probe=$(dirname -- "$probe"); [ -e "$probe" ] || exit 71; printf "%s\n%s\n" "$(findmnt -T "$probe" -n -o TARGET,SOURCE,FSTYPE,OPTIONS)" "$(stat -Lc "%d" -- "$probe")"' bash "$EXPECTED_MACHINE_ID_SHA256" "$BOOT_ID" "$AFFECTED_PATH")"; then mapfile -t M <<<"$OUT"; MOUNT_KEY=${M[0]}; DEVICE_KEY=${M[1]}; TARGET_READY=true; printf 'TARGET_READY=true mount=%s stat_device=%s\n' "$MOUNT_KEY" "$DEVICE_KEY"; else unset MOUNT_KEY DEVICE_KEY; printf '%s\n' '중단: mount 등록 실패' >&2; fi
```

```bash
TIME_READY=false; DOWNSTREAM_READY=false; START_RFC3339='PASTE_START_RFC3339_HERE'; END_RFC3339='PASTE_END_RFC3339_HERE'; if S=$(date -u -d "$START_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null) && E=$(date -u -d "$END_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null) && [ "$S" = "$START_RFC3339" ] && [ "$E" = "$END_RFC3339" ] && [ "$(date -u -d "$S" +%s)" -lt "$(date -u -d "$E" +%s)" ]; then TIME_READY=true; printf 'TIME_READY=true start=%s end=%s\n' "$S" "$E"; else printf '%s\n' '중단: UTC RFC3339 roundtrip/order 실패' >&2; fi
```

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | 같은 mount의 `IFree` 고갈과 파일 생성 실패가 시간상 맞음 |
| 적용 | bytes와 inode를 분리하고 생성 경로를 depth 제한으로 좁힐 수 있음 |
| 제외 | bytes-only는 [[01. filesystem 용량이 가득 차 no space left on device가 발생한 경우]], read-only/I/O는 해당 filesystem/device 런북 |

검색 문자열: `IFree`, `IUse%`, `inodesFree`, `ENOSPC`, `no space left on device`, `read-only`, `I/O error`.

## 관측별 진단 경로

| 지금 보이는 것 | 직접 증거 | 다음 판단 |
|---|---|---|
| `IFree=0`, bytes 여유 | 같은 mount의 `df -hT`·`df -iT` | inode 고갈 확인 |
| bytes와 inode 모두 고갈 | 각각의 현재값·추세 | 두 원인을 분리 |
| `ro`·I/O 오류 | source와 bounded kernel journal | inode 정리 금지, 이관 |
| 현재 정상 | 사건 시각 journal/metrics 보존 | 과거 사건 미확정 |

## 직접 진단

```bash
if [ "$TARGET_READY" != true ]; then printf '%s\n' '중단: target gate가 아니다.' >&2; exit 1; fi; ssh -o BatchMode=yes -o ConnectTimeout=10 -o ProxyCommand=none -o ProxyJump=none -- "$SSH_TARGET" 'set -euo pipefail; expected=$1; boot=$2; path=$3; mount_key=$4; device_key=$5; sum=$(sha256sum /etc/machine-id); [ "${sum%% *}" = "$expected" ] && [ "$(cat /proc/sys/kernel/random/boot_id)" = "$boot" ] || exit 70; probe=$path; [ -e "$probe" ] || probe=$(dirname -- "$probe"); [ "$(findmnt -T "$probe" -n -o TARGET,SOURCE,FSTYPE,OPTIONS)" = "$mount_key" ] && [ "$(stat -Lc "%d" -- "$probe")" = "$device_key" ] || exit 71; target=$(findmnt -T "$probe" -n -o TARGET); printf "observed_at=%s mount=%s\n" "$(date -u +%Y-%m-%dT%H:%M:%SZ)" "$mount_key"; df -hT -- "$target"; df -iT -- "$target"; command -v du >/dev/null 2>&1 || { printf "%s\n" "du unavailable" >&2; exit 72; }; set +e; sudo du -x --inodes -d 1 -- "$target"; producer_rc=$?; set -e; printf "du_rc=%s\n" "$producer_rc"; [ "$producer_rc" -eq 0 ]' bash "$EXPECTED_MACHINE_ID_SHA256" "$BOOT_ID" "$AFFECTED_PATH" "$MOUNT_KEY" "$DEVICE_KEY"
```

한 단계 집계에서 큰 경로가 보여도 owner를 확정하지 않는다. 다음 depth는 그 경로가 같은 mount임을 새로 등록한 뒤 실행한다. `find`, 전체 파일 목록·내용, symbolic link 추적은 하지 않는다.

## bounded journal

```bash
if [ "$TARGET_READY" != true ] || [ "$TIME_READY" != true ]; then printf '%s\n' '중단: target/time gate가 완전하지 않다.' >&2; exit 1; fi; ssh -o BatchMode=yes -o ConnectTimeout=10 -o ProxyCommand=none -o ProxyJump=none -- "$SSH_TARGET" 'set -euo pipefail; expected=$1; boot=$2; path=$3; mount_key=$4; device_key=$5; since=$6; until=$7; sum=$(sha256sum /etc/machine-id); [ "${sum%% *}" = "$expected" ] && [ "$(cat /proc/sys/kernel/random/boot_id)" = "$boot" ] || exit 70; probe=$path; [ -e "$probe" ] || probe=$(dirname -- "$probe"); [ "$(findmnt -T "$probe" -n -o TARGET,SOURCE,FSTYPE,OPTIONS)" = "$mount_key" ] && [ "$(stat -Lc "%d" -- "$probe")" = "$device_key" ] || exit 71; s=$(date -u -d "$since" +%Y-%m-%dT%H:%M:%SZ); e=$(date -u -d "$until" +%Y-%m-%dT%H:%M:%SZ); [ "$s" = "$since" ] && [ "$e" = "$until" ] && [ "$(date -u -d "$s" +%s)" -lt "$(date -u -d "$e" +%s)" ] || exit 72; set +e; raw=$(TZ=UTC journalctl -k --since "$since" --until "$until" --no-pager -o short-iso-precise); producer_rc=$?; set -e; [ "$producer_rc" -eq 0 ] || exit "$producer_rc"; set +e; printf "%s\n" "$raw" | grep -E -i -C 3 -- "no space left on device|ENOSPC|inode|read-only|I/O error|filesystem"; filter_rc=${PIPESTATUS[1]}; set -e; printf "producer_rc=%s filter_rc=%s requested_window=%s/%s\n" "$producer_rc" "$filter_rc" "$since" "$until"; [ "$filter_rc" -eq 0 ] || [ "$filter_rc" -eq 1 ]' bash "$EXPECTED_MACHINE_ID_SHA256" "$BOOT_ID" "$AFFECTED_PATH" "$MOUNT_KEY" "$DEVICE_KEY" "$START_RFC3339" "$END_RFC3339"
```

producer rc와 filter rc=1을 구분한다. journal의 실제 첫·마지막 UTC timestamp가 요청 창을 덮는지 기록한다. 빈 결과는 inode 오류 부재가 아니다. 민감정보가 보이면 저장을 중단한다.

## 복구 전 안전 gate와 정상화

이 문서는 `rm`, truncate, `find -delete`, log/image 정리, remount, fsck, restart, reboot 명령을 제공하지 않는다. 외부 변경은 fresh host/mount/device/evidence gate, trigger, 승인 ID, window, 대체 가용성, 영향 범위, 멱등성, 중단 조건과 검증된 rollback/보상 절차가 필요하다. 삭제는 일반 rollback이 없으며 재생성된 mount/device/process는 재등록한다.

정상화는 새 UTC 창에서 직접 진단과 journal을 반복하고, inode·bytes가 안정되며 새 write/RO/I/O 오류가 없고 실제 서비스의 파일 생성·요청 또는 Job 산출물이 정상인지 확인한다. `IFree` 한 번의 회복만으로 닫지 않는다.

## 증거 보존과 환경별 미검증

host/boot, 오류 path, mount/source/FSTYPE/options, device identity, UTC 창, bytes/inode, bounded inode 집계, journal producer/filter rc·실제 timestamp, 실제 기능 결과를 보존한다. machine-id 원문, 전체 파일 목록·내용·민감정보는 저장하지 않는다. Kubernetes nodefs/imagefs/PVC 연결은 object UID와 endpoint가 확인된 경우에만 수행하며 환경별 미검증이다.
