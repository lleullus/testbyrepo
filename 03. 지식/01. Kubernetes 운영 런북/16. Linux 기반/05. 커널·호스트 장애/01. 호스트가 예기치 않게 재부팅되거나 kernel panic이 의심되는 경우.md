# 호스트가 예기치 않게 재부팅되거나 kernel panic이 의심되는 경우

## 입력값과 빠른 수집

실행 hop은 `승인된 작업 PC/Bash → current Node API identity → 승인된 SSH host의 current machine-id·boot ID → journal boot catalog → incident boot의 bounded kernel journal → pstore·kdump metadata → Kubernetes·application 영향`이다. current boot와 incident boot를 혼합하지 않고 crash dump·pstore 내용은 출력하지 않는다.

| 구분 | 값 | 출처와 gate |
|---|---|---|
| 최초 입력 | `CTX`, `NODE`, `NODE_HOST` | incident와 승인 기록 |
| API 자동값 | Node UID·systemUUID·machineID·current boot ID | current API와 SSH host exact match |
| 계산 후보값 | journal boot ID 목록, pstore/kdump metadata | current host에서 읽기 전용 수집 |
| 운영자 선택값 | `INCIDENT_BOOT_ID`, strict UTC start/end | boot catalog와 최초 장애 시각을 확인한 뒤 선택 |

### 1. current host identity

```bash
TOOLS_READY=false; INPUT_READY=false; HOST_READY=false; INCIDENT_READY=false; EVIDENCE_READY=false
unset NODE_UID SYSTEM_UUID API_MACHINE_ID API_BOOT_ID REMOTE_HOSTNAME REMOTE_MACHINE_ID REMOTE_BOOT_ID INCIDENT_BOOT_ID START_RFC3339 END_RFC3339 START_EPOCH END_EPOCH
CTX='PASTE_REBOOT_CONTEXT_HERE'
NODE='PASTE_REBOOT_NODE_HERE'
NODE_HOST='PASTE_REBOOT_NODE_HOST_HERE'
MISSING=''
for tool in kubectl jq ssh date grep sed awk; do command -v "$tool" >/dev/null 2>&1 || MISSING="$MISSING $tool"; done
if [ -z "${BASH_VERSION:-}" ] || [ -n "$MISSING" ]; then
  printf '중단: Bash 또는 도구 미충족:%s\n' "$MISSING" >&2
elif [[ ! "$NODE_HOST" =~ ^[A-Za-z0-9._:-]+$ ]]; then
  printf '%s\n' '중단: 승인된 SSH host 형식이 아니다.' >&2
elif kubectl --context "$CTX" get node "$NODE" -o name >/dev/null 2>&1; then
  TOOLS_READY=true; INPUT_READY=true
else
  printf '%s\n' '중단: exact-name Node API 조회 실패' >&2
fi
```

```bash
invalidate_reboot() {
  HOST_READY=false; INCIDENT_READY=false; EVIDENCE_READY=false
  unset NODE_UID SYSTEM_UUID API_MACHINE_ID API_BOOT_ID REMOTE_HOSTNAME REMOTE_MACHINE_ID REMOTE_BOOT_ID INCIDENT_BOOT_ID START_EPOCH END_EPOCH
}
refresh_reboot_host() {
  local j r rc rh rm rb
  invalidate_reboot
  [ "$INPUT_READY" = true ] || return 1
  j="$(kubectl --context "$CTX" get node "$NODE" -o json)" || return 1
  NODE_UID="$(jq -er '.metadata.uid' <<<"$j")" || return 1
  SYSTEM_UUID="$(jq -er '.status.nodeInfo.systemUUID' <<<"$j")" || return 1
  API_MACHINE_ID="$(jq -er '.status.nodeInfo.machineID' <<<"$j")" || return 1
  API_BOOT_ID="$(jq -er '.status.nodeInfo.bootID' <<<"$j")" || return 1
  jq -e --arg h "$NODE_HOST" --arg n "$NODE" '(.metadata.name==$n) and (($h==$n) or any(.status.addresses[]?; .address==$h))' <<<"$j" >/dev/null || return 1
  r="$(ssh -o BatchMode=yes -o ConnectTimeout=10 -- "$NODE_HOST" bash -s <<'REMOTE'
set -eu
printf '%s\t%s\t%s\n' "$(hostname -s)" "$(cat /etc/machine-id)" "$(cat /proc/sys/kernel/random/boot_id)"
REMOTE
)"; rc=$?
  [ "$rc" -eq 0 ] || { invalidate_reboot; return 1; }
  IFS=$'\t' read -r rh rm rb <<<"$r"
  jq -e --arg h "$rh" --arg n "$NODE" '($h==$n) or any(.status.addresses[]?; .address==$h)' <<<"$j" >/dev/null && [ "$rm" = "$API_MACHINE_ID" ] && [ "$rb" = "$API_BOOT_ID" ] || { invalidate_reboot; return 1; }
  REMOTE_HOSTNAME="$rh"; REMOTE_MACHINE_ID="$rm"; REMOTE_BOOT_ID="$rb"; HOST_READY=true
  printf 'HOST_READY=true node=%s uid=%s system-uuid=%s machine-id=%s current-boot=%s remote=%s\n' "$NODE" "$NODE_UID" "$SYSTEM_UUID" "$API_MACHINE_ID" "$API_BOOT_ID" "$REMOTE_HOSTNAME"
}
guard_reboot_host() {
  local j r rh rm rb
  [ "$HOST_READY" = true ] || return 1
  j="$(kubectl --context "$CTX" get node "$NODE" -o json)" || { invalidate_reboot; return 1; }
  [ "$(jq -r '.metadata.uid // empty' <<<"$j")" = "$NODE_UID" ] && [ "$(jq -r '.status.nodeInfo.systemUUID // empty' <<<"$j")" = "$SYSTEM_UUID" ] && [ "$(jq -r '.status.nodeInfo.machineID // empty' <<<"$j")" = "$API_MACHINE_ID" ] && [ "$(jq -r '.status.nodeInfo.bootID // empty' <<<"$j")" = "$API_BOOT_ID" ] || { invalidate_reboot; return 1; }
  r="$(ssh -o BatchMode=yes -o ConnectTimeout=10 -- "$NODE_HOST" bash -s <<'REMOTE'
set -eu
printf '%s\t%s\t%s\n' "$(hostname -s)" "$(cat /etc/machine-id)" "$(cat /proc/sys/kernel/random/boot_id)"
REMOTE
)" || { invalidate_reboot; return 1; }
  IFS=$'\t' read -r rh rm rb <<<"$r"
  [ "$rh" = "$REMOTE_HOSTNAME" ] && [ "$rm" = "$REMOTE_MACHINE_ID" ] && [ "$rb" = "$REMOTE_BOOT_ID" ] || { invalidate_reboot; return 1; }
}
refresh_reboot_host
```

### 2. boot catalog와 incident 창 선택

```bash
if guard_reboot_host; then ssh -o BatchMode=yes -o ConnectTimeout=10 -- "$NODE_HOST" bash -s -- "$REMOTE_MACHINE_ID" "$REMOTE_BOOT_ID" <<'REMOTE'
set -eu
[ "$(cat /etc/machine-id)" = "$1" ] || exit 42
[ "$(cat /proc/sys/kernel/random/boot_id)" = "$2" ] || exit 43
command -v journalctl >/dev/null 2>&1 || exit 127
journalctl --list-boots --no-pager
REMOTE
else printf '%s\n' '중단: current host guard 실패' >&2; fi
```

```bash
INCIDENT_BOOT_ID='PASTE_REBOOT_INCIDENT_BOOT_ID_HERE'
START_RFC3339='PASTE_REBOOT_START_RFC3339_HERE'
END_RFC3339='PASTE_REBOOT_END_RFC3339_HERE'
```

```bash
register_incident_boot() {
  local list rc count
  INCIDENT_READY=false; EVIDENCE_READY=false
  unset START_EPOCH END_EPOCH
  guard_reboot_host || return 1
  [[ "$INCIDENT_BOOT_ID" =~ ^[0-9a-f]{32}$ ]] || { printf '%s\n' '중단: incident boot ID 형식 오류' >&2; return 1; }
  [[ "$START_RFC3339" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] && [[ "$END_RFC3339" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] || return 1
  [ "$(date -u -d "$START_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" = "$START_RFC3339" ] && [ "$(date -u -d "$END_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" = "$END_RFC3339" ] || return 1
  START_EPOCH="$(date -u -d "$START_RFC3339" +%s)"; END_EPOCH="$(date -u -d "$END_RFC3339" +%s)"; [ "$START_EPOCH" -lt "$END_EPOCH" ] || return 1
  list="$(ssh -o BatchMode=yes -o ConnectTimeout=10 -- "$NODE_HOST" bash -s -- "$REMOTE_MACHINE_ID" "$REMOTE_BOOT_ID" <<'REMOTE'
set -eu
[ "$(cat /etc/machine-id)" = "$1" ] || exit 42
[ "$(cat /proc/sys/kernel/random/boot_id)" = "$2" ] || exit 43
journalctl --list-boots --no-pager
REMOTE
)"; rc=$?
  [ "$rc" -eq 0 ] || { printf 'boot catalog producer 실패 rc=%s\n' "$rc" >&2; return 1; }
  count="$(awk -v id="$INCIDENT_BOOT_ID" '$2==id{n++} END{print n+0}' <<<"$list")"
  [ "$count" -eq 1 ] || { printf '중단: incident boot ID 후보 수=%s\n' "$count" >&2; return 1; }
  INCIDENT_READY=true
  printf 'INCIDENT_READY=true incident-boot=%s current-boot=%s start=%s end=%s\n' "$INCIDENT_BOOT_ID" "$REMOTE_BOOT_ID" "$START_RFC3339" "$END_RFC3339"
}
register_incident_boot
```

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | Node boot ID 변경, uptime 초기화, reboot 기록 또는 panic/watchdog 흔적이 관측됨 |
| 적용 | current host identity와 incident journal boot ID·UTC 창을 분리해 검증 가능 |
| 제외 | boot ID가 그대로인 hung task·soft lockup은 [[02. kernel hung task·soft lockup이 반복되는 경우]], 계획된 reboot는 변경 기록으로 확인 |

검색 문자열: `Kernel panic`, `panic`, `Oops`, `BUG:`, `watchdog`, `hard LOCKUP`, `soft lockup`, `Out of memory`, `reboot`, `shutdown`, `power`.

## 관측별 진단 경로

| 지금 보이는 것 | 먼저 볼 것 | 그다음 어디를 볼지 | 상세 절 |
|---|---|---|---|
| incident boot에 panic/Oops | 마지막 kernel timestamp·stack signature | pstore/kdump metadata와 kernel owner | [[#incident boot kernel evidence\|kernel evidence]] |
| clean shutdown 뒤 reboot | shutdown initiator·변경 기록·provider event | automation/platform owner | [[#영향·외부 증거 분기\|외부 증거]] |
| journal이 갑자기 끝남 | journal producer·보존·power/provider 시각 | hardware·hypervisor·power owner | [[#영향·외부 증거 분기\|외부 증거]] |
| current Node Ready지만 재발 | 새 boot ID·workload 기능·재발 창 | root cause owner와 교체 판단 | [[#정상화·증거\|정상화]] |

## incident boot kernel evidence

```bash
collect_incident_kernel() {
  local raw rc matched frc re
  EVIDENCE_READY=false
  guard_reboot_host || return 1
  [ "$INCIDENT_READY" = true ] || return 1
  re='Kernel panic|panic|Oops|BUG:|watchdog|hard LOCKUP|soft lockup|Out of memory|Killed process|reboot|shutdown|power'
  raw="$(ssh -o BatchMode=yes -o ConnectTimeout=10 -- "$NODE_HOST" bash -s -- "$REMOTE_MACHINE_ID" "$REMOTE_BOOT_ID" "$INCIDENT_BOOT_ID" "$START_RFC3339" "$END_RFC3339" <<'REMOTE'
set -eu
[ "$(cat /etc/machine-id)" = "$1" ] || exit 42
[ "$(cat /proc/sys/kernel/random/boot_id)" = "$2" ] || exit 43
command -v journalctl >/dev/null 2>&1 || exit 127
sudo -n journalctl -k --utc --boot "$3" --since "$4" --until "$5" -o short-iso-precise --no-pager --lines=1500
REMOTE
)"; rc=$?
  [ "$rc" -eq 0 ] || { printf 'incident journal producer 실패 rc=%s\n' "$rc" >&2; return 1; }
  matched="$(grep -E -i -C 4 -- "$re" <<<"$raw")"; frc=$?
  case "$frc" in
    0) EVIDENCE_READY=true; printf '%s\n' "$matched" | sed -n '1,120p'; printf 'EVIDENCE_READY=true incident-boot=%s\n' "$INCIDENT_BOOT_ID" ;;
    1) printf '%s\n' 'filter 일치 없음; clean shutdown이나 panic 부재로 확정하지 않음' >&2 ;;
    *) printf 'filter 오류 rc=%s\n' "$frc" >&2; return "$frc" ;;
  esac
}
collect_incident_kernel
```

같은 boot의 마지막 kernel timestamp, shutdown sequence 완결 여부, panic/Oops/watchdog/OOM signature를 본다. journal 빈 결과는 rotation·volatile journal·wrong boot·권한·producer 실패 후보이며 정상 증거가 아니다. stack 원문에 주소·tenant 정보가 있으면 최소 signature와 timestamp만 보존한다.

## 영향·외부 증거 분기

**pstore·kdump metadata만 확인**

```bash
if guard_reboot_host; then ssh -o BatchMode=yes -o ConnectTimeout=10 -- "$NODE_HOST" sudo -n bash -s -- "$REMOTE_MACHINE_ID" "$REMOTE_BOOT_ID" <<'REMOTE'
set -eu
[ "$(cat /etc/machine-id)" = "$1" ] || exit 42
[ "$(cat /proc/sys/kernel/random/boot_id)" = "$2" ] || exit 43
printf '%s\n' '=== pstore metadata ==='
count=0
for f in /sys/fs/pstore/*; do [ -e "$f" ] || continue; stat -c 'name=%n size=%s mtime=%y mode=%a' "$f"; count=$((count+1)); [ "$count" -le 50 ] || exit 75; done
[ "$count" -gt 0 ] || printf '%s\n' 'pstore metadata 없음'
printf '%s\n' '=== kdump service property ==='
if command -v systemctl >/dev/null 2>&1; then if ! systemctl show kdump.service --property=LoadState,ActiveState,SubState,Result --no-pager 2>/dev/null; then printf '%s\n' 'kdump service property 조회 실패 또는 unit 없음'; fi; fi
REMOTE
else printf '%s\n' '중단: current host guard 실패' >&2; fi
```

pstore·vmcore 내용, 전체 stack, memory dump를 이 런북에서 출력하거나 복사하지 않는다. provider reboot/power event, BMC/MCE/EDAC, automation audit와 변경 기록은 machine/system UUID와 UTC 시각이 일치하는 승인된 화면/API에서 확인한다. event ID·시각·상태만 보존하고 actor 상세·token은 저장하지 않는다.

**current Kubernetes 영향**

`if guard_reboot_host; then NODE_JSON="$(kubectl --context "$CTX" get node "$NODE" -o json)" && jq -e --arg uid "$NODE_UID" --arg boot "$REMOTE_BOOT_ID" '.metadata.uid==$uid and .status.nodeInfo.bootID==$boot' <<<"$NODE_JSON" >/dev/null && jq -r '"=== current Node ===\nUID: \(.metadata.uid)\nBoot ID: \(.status.nodeInfo.bootID)\n" + ([.status.conditions[] | "\(.type): \(.status) reason=\(.reason) transition=\(.lastTransitionTime)"] | join("\n"))' <<<"$NODE_JSON"; else printf '%s\n' '중단: current host guard 실패' >&2; fi`

`Ready=True`는 이전 boot의 root cause, filesystem·runtime과 실제 workload 기능 정상을 보장하지 않는다. incident 전후 Pod UID·owner·node·containerID, replacement 생성 시각, PDB/quorum 영향은 해당 workload 런북에서 현재 lifecycle로 재등록한다.

## 안전 경계

이 문서는 reboot, sysrq·panic trigger, kexec, watchdog 변경, crash dump 삭제, kernel parameter 변경, module unload, device reset, kubelet/runtime restart, `cordon`·`drain`·Pod delete를 실행하지 않는다. 추가 reboot나 host 교체는 fresh current identity, root-cause evidence, availability·quorum, 승인 window, 중단 조건과 검증 가능한 rollback/replace 계획이 있는 별도 변경으로 이관한다. current boot ID가 바뀌면 기존 admission은 무효다.

## 정상화·증거

정상화는 `provider·hardware 안정 → 새 boot에서 kernel 경고 비재발 → device/filesystem/runtime → Node Ready·Lease → replacement workload identity → 실제 서비스·Job 결과` 순서다. 새 UTC 관찰 창에서 journal producer가 성공하고 warning이 재발하지 않으며, boot ID가 유지되고 실제 요청·read/write·데이터 일관성이 회복돼야 한다. filter no-match만으로 정상화하지 않는다.

Node name·UID·systemUUID·machineID, current/incident boot ID, remote identity, strict UTC 원문·정규화 창, producer/filter rc, 마지막 kernel timestamp와 비민감 signature, pstore/kdump metadata, provider event ID, workload 영향, 승인된 외부 조치와 실제 기능 결과를 보존한다. 전체 journal·dump·pstore 내용, actor 상세, token, credential, private key와 개인정보는 저장하지 않는다.
