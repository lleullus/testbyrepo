# 호스트 시간이 급격히 바뀌거나 동기화되지 않는 경우

## 입력값과 빠른 수집

실행 hop은 `승인된 작업 PC/Bash의 기준 시계 → Kubernetes API`와 `작업 PC/Bash → SSH → Node host namespace → kernel/time service`다. wall clock, monotonic clock, API timestamp와 collector receive time은 서로 다른 축이다.

| 구분 | 값 | 계약 |
|---|---|---|
| 최초 입력 | `NODE`, `SSH_DEST`, `EXPECTED_MACHINE_ID` | 승인 inventory exact match |
| API 확인 자동값 | `NODE_UID`, `SYSTEM_UUID`, `HOST_BOOT_ID` | API·SSH 성공 뒤 등록 |
| 계산 후보값 | `TIME_RE` | time jump/offset 고정 문자열 필터 |
| 운영자 선택값 | `START_UTC`, `END_UTC`, `TIME_UNIT` | canonical UTC 창과 실제 확인한 unit |

### 1. target과 time source 고정

```bash
TARGET_READY=false; WINDOW_READY=false
unset NODE_UID SYSTEM_UUID API_BOOT_ID HOST_BOOT_ID START_UTC END_UTC TIME_UNIT TIME_RE PID PID_START_TICKS MOUNT_ID DEVICE_ID CGROUP_ID NETNS_ID NETWORK_ID ARGV_RE READ_READY JOURNAL_READY FILTER_READY READ_OUT JOURNAL_OUT FILTERED_OUT
SSH_OPTS=(-o BatchMode=yes -o ConnectTimeout=10 -o StrictHostKeyChecking=yes -o LogLevel=ERROR)
canonical_utc() { local value=${1:-}; [[ "$value" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] && [ "$(date -u -d "$value" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" = "$value" ]; }
window_valid() { canonical_utc "${START_UTC:-}" && canonical_utc "${END_UTC:-}" && [[ "$START_UTC" < "$END_UTC" ]]; }
NODE='PASTE_TIME_NODE_HERE'; SSH_DEST='PASTE_TIME_SSH_DEST_HERE'; EXPECTED_MACHINE_ID='PASTE_TIME_MACHINE_ID_HERE'
MISSING=''; for tool in kubectl jq ssh grep date; do command -v "$tool" >/dev/null 2>&1 || MISSING="$MISSING $tool"; done
if [ -z "${BASH_VERSION:-}" ] || [ -n "$MISSING" ] || [[ ! "$SSH_DEST" =~ ^[A-Za-z0-9][A-Za-z0-9._@:-]*$ ]] || [[ ! "$EXPECTED_MACHINE_ID" =~ ^[0-9a-f]{32}$ ]]; then printf '중단: Bash/도구/입력 gate 실패:%s\n' "$MISSING" >&2; else
  J="$(kubectl get node "$NODE" -o json)"; API_RC=$?; [ "$API_RC" -eq 0 ] && NODE_UID="$(jq -r '.metadata.uid // empty' <<<"$J")" && SYSTEM_UUID="$(jq -r '.status.nodeInfo.systemUUID // empty' <<<"$J")" && API_BOOT_ID="$(jq -r '.status.nodeInfo.bootID // empty' <<<"$J")"
  HOST_BOOT_ID="$(ssh "${SSH_OPTS[@]}" -- "$SSH_DEST" sh -s -- "$EXPECTED_MACHINE_ID" <<'REMOTE'
set -eu
[ "$(cat /etc/machine-id)" = "$1" ] || exit 42
cat /proc/sys/kernel/random/boot_id
REMOTE
)"; SSH_RC=$?
  if [ "$API_RC" -eq 0 ] && [ -n "$NODE_UID" ] && [ -n "$SYSTEM_UUID" ] && [ "$API_BOOT_ID" = "$HOST_BOOT_ID" ]; then TIME_RE='clock|time.*changed|offset|step|jump|backward|forward|synchron|source|selected|timeout'; TARGET_READY=true; printf 'TARGET_READY=true node=%s uid=%s systemUUID=%s machine-id=%s boot-id=%s local-reference=%s\n' "$NODE" "$NODE_UID" "$SYSTEM_UUID" "$EXPECTED_MACHINE_ID" "$HOST_BOOT_ID" "$(date -u '+%Y-%m-%dT%H:%M:%SZ')"; else unset NODE_UID SYSTEM_UUID API_BOOT_ID HOST_BOOT_ID TIME_RE; printf '중단: identity producer 실패 api_rc=%s ssh_rc=%s\n' "$API_RC" "$SSH_RC" >&2; fi
fi
unset J
```

먼저 실제 active time service를 승인된 host owner와 확인한다. unit 이름을 추측하지 않는다.

```bash
WINDOW_READY=false; READ_READY=false; JOURNAL_READY=false; FILTER_READY=false
unset START_UTC END_UTC TIME_UNIT READ_OUT JOURNAL_OUT FILTERED_OUT
START_UTC='PASTE_TIME_START_UTC_HERE'; END_UTC='PASTE_TIME_END_UTC_HERE'; TIME_UNIT='PASTE_TIME_UNIT_HERE'
if window_valid && [[ "$TIME_UNIT" =~ ^[A-Za-z0-9_.@-]{1,128}\.service$ ]]; then WINDOW_READY=true; printf 'WINDOW_READY=true start=%s end=%s unit=%s regex=%s\n' "$START_UTC" "$END_UTC" "$TIME_UNIT" "$TIME_RE"; else unset START_UTC END_UTC TIME_UNIT; printf '%s\n' '중단: UTC 창/unit 형식 오류' >&2; fi
```

### 2. fresh read와 journal

```bash
time_read() {
  local mode=${1:-} j rc uid system boot
  READ_READY=false; unset READ_OUT
  [ "$TARGET_READY" = true ] && [ "$WINDOW_READY" = true ] && window_valid && [[ "$TIME_UNIT" =~ ^[A-Za-z0-9_.@-]{1,128}\.service$ ]] || { printf '%s\n' '중단: gate 미충족 또는 선택값 변경' >&2; return 1; }
  j="$(kubectl get node "$NODE" -o json)"; rc=$?; [ "$rc" -eq 0 ] || { TARGET_READY=false; printf 'fresh API 실패 rc=%s\n' "$rc" >&2; return "$rc"; }
  uid="$(jq -r '.metadata.uid // empty' <<<"$j")"; system="$(jq -r '.status.nodeInfo.systemUUID // empty' <<<"$j")"; boot="$(jq -r '.status.nodeInfo.bootID // empty' <<<"$j")"
  [ "$uid" = "$NODE_UID" ] && [ "$system" = "$SYSTEM_UUID" ] && [ "$boot" = "$HOST_BOOT_ID" ] || { TARGET_READY=false; printf '%s\n' '중단: identity/lifecycle 변경' >&2; return 1; }
  READ_OUT="$(ssh "${SSH_OPTS[@]}" -- "$SSH_DEST" sh -s -- "$EXPECTED_MACHINE_ID" "$HOST_BOOT_ID" "$TIME_UNIT" "$mode" <<'REMOTE'
set -eu
[ "$(cat /etc/machine-id)" = "$1" ] || exit 42
[ "$(cat /proc/sys/kernel/random/boot_id)" = "$2" ] || exit 43
unit=$3; mode=$4
case "$mode" in
  clocks) printf 'wall-utc=%s\nepoch=%s\n' "$(date -u '+%Y-%m-%dT%H:%M:%S.%NZ')" "$(date -u '+%s')"; printf 'uptime='; cat /proc/uptime ;;
  service) [ "$(cat /proc/1/comm)" = systemd ] || exit 70; systemctl show "$unit" -p Id -p LoadState -p ActiveState -p SubState -p Result -p ExecMainStartTimestampMonotonic ;;
  timedate) command -v timedatectl >/dev/null 2>&1 || exit 69; timedatectl show -p NTPSynchronized -p Timezone -p LocalRTC ;;
  *) exit 64 ;;
esac
REMOTE
)"; rc=$?
  if [ "$rc" -ne 0 ]; then unset READ_OUT; printf 'remote producer 실패 mode=%s rc=%s\n' "$mode" "$rc" >&2; return "$rc"; fi
  READ_READY=true; printf 'local-received=%s\n%s\n' "$(date -u '+%Y-%m-%dT%H:%M:%S.%NZ')" "$READ_OUT"
}
```

`time_read clocks`

`time_read service`

`time_read timedate`

SSH latency가 포함되므로 local/remote wall 차이를 정밀 offset으로 해석하지 않는다. `/proc/uptime`은 monotonic 계열 경과 후보이지 UTC timestamp가 아니다. service active나 `NTPSynchronized=yes`는 source 정확도·offset·재발 없음을 보장하지 않는다.

```bash
time_journal() {
  local j api_rc producer_rc filter_rc
  JOURNAL_READY=false; FILTER_READY=false; unset JOURNAL_OUT FILTERED_OUT
  [ "$TARGET_READY" = true ] && [ "$WINDOW_READY" = true ] && window_valid && [[ "$TIME_UNIT" =~ ^[A-Za-z0-9_.@-]{1,128}\.service$ ]] || { printf '%s\n' '중단: gate 미충족 또는 선택값 변경' >&2; return 1; }
  j="$(kubectl get node "$NODE" -o json)"; api_rc=$?; [ "$api_rc" -eq 0 ] && [ "$(jq -r '.metadata.uid' <<<"$j")" = "$NODE_UID" ] && [ "$(jq -r '.status.nodeInfo.systemUUID' <<<"$j")" = "$SYSTEM_UUID" ] && [ "$(jq -r '.status.nodeInfo.bootID' <<<"$j")" = "$HOST_BOOT_ID" ] || { TARGET_READY=false; printf 'fresh API 실패/identity 변경 rc=%s\n' "$api_rc" >&2; return 1; }
  JOURNAL_OUT="$(ssh "${SSH_OPTS[@]}" -- "$SSH_DEST" sh -s -- "$EXPECTED_MACHINE_ID" "$HOST_BOOT_ID" "$TIME_UNIT" "$START_UTC" "$END_UTC" <<'REMOTE'
set -eu
[ "$(cat /etc/machine-id)" = "$1" ] || exit 42
[ "$(cat /proc/sys/kernel/random/boot_id)" = "$2" ] || exit 43
exec journalctl -u "$3" --utc --since "$4" --until "$5" -o short-iso-precise --no-pager --lines=1000
REMOTE
)"; producer_rc=$?
  [ "$producer_rc" -eq 0 ] || { unset JOURNAL_OUT; printf 'journal producer 실패 rc=%s\n' "$producer_rc" >&2; return "$producer_rc"; }
  JOURNAL_READY=true; FILTERED_OUT="$(grep -E -i -C 3 -- "$TIME_RE" <<<"$JOURNAL_OUT")"; filter_rc=$?
  case "$filter_rc" in 0) FILTER_READY=true; printf '%s\n' "$FILTERED_OUT";; 1) unset FILTERED_OUT; printf '%s\n' '필터 일치 없음: 시간 정상 아님' >&2;; *) unset JOURNAL_OUT FILTERED_OUT; JOURNAL_READY=false; printf '필터 오류 rc=%s\n' "$filter_rc" >&2; return "$filter_rc";; esac
}
```

`time_journal`

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | offset·step·jump·sync 실패 또는 TLS/Event 시간 불일치가 있음 |
| 적용 | wall/monotonic/source/API 시간을 같은 identity에서 구분 가능 |
| 제외 | 표시 timezone만 다름, 단일 app timestamp 생성 오류, API 전체 장애 |

검색 문자열: `offset`, `step`, `clock jump`, `time went backwards`, `not yet valid`, `renewTime`, `lastHeartbeatTime`.

## 분기

- offset은 확인된 source와 host wall의 차이로만 기록한다. 숫자 단위와 sign을 보존한다.
- step/jump 전후 순서는 원문 UTC와 monotonic marker를 함께 써서 정렬한다. wall time만으로 순서를 재작성하지 않는다.
- `x509`는 certificate `notBefore/notAfter`, host time과 API path를 분리하며 인증서 원문·key를 저장하지 않는다.
- Node UID가 같은 경우에만 heartbeat·Lease·Event 시간을 대조한다. API 실패/Forbidden은 시간 데이터 부재가 아니다.
- provider time injection 외부 조회는 공식 read-only 경로에서 HTTP/API success와 pagination까지 확인한다. 401/403/429/5xx 또는 결과 부재를 정상으로 바꾸지 않는다.

## 변경 경계와 정상화

이 문서는 `date -s`, `clock_settime`, `timedatectl set-time/set-ntp`, service restart, source/config 변경, certificate 교체, reboot·VM migration을 실행하지 않는다. 별도 변경은 fresh identity/evidence, 승인 ID·window, certificate·quorum·Job side effect·availability, idempotence, 중단 조건과 원 source/config rollback 검증이 필요하다. backward step이나 추가 큰 step 위험이 있으면 중단한다.

정상화는 `time_read clocks/service/timedate`와 `time_journal`을 새 재평가 창에서 fresh 실행한다. source·offset·sync, 새 step 부재, TLS/API, Node heartbeat·Lease, workload timeout·Job 결과 순으로 실제 기능을 확인한다. 교체 host/process는 새 machine/boot/PID/start identity를 재등록한다. 한 번의 sync 성공이나 로그 순서 회복은 정상화가 아니다.

보존: identity, 원문 timezone·precision, canonical UTC, wall/monotonic/source/offset·step, producer/filter rc, certificate 요약, Node/Event/workload 영향과 rollback 결과. 전체 로그·credential·private key는 저장하지 않는다.

## 환경별 미검증

NTP 구현체/source, VM time injection, leap/smear 정책, certificate/Event 보존과 실제 Kubernetes 1.26 환경은 미검증이며 실행하지 않았다.
