# kernel module이 load되지 않거나 예상 모듈이 없는 경우

## 입력값과 빠른 수집

실행 hop은 `승인된 작업 PC/Bash → Kubernetes API`와 `작업 PC/Bash → 승인된 SSH 경로 → Node host namespace → kmod/kernel journal`이다. `SSH_DEST`는 단일 argv로 전달하고 host key 검증을 끄거나 `eval`하지 않는다.

| 구분 | 값 | gate |
|---|---|---|
| 최초 입력 | `NODE`, `SSH_DEST`, `EXPECTED_MACHINE_ID` | 승인 inventory의 exact identity |
| API 확인 자동값 | `NODE_UID`, `SYSTEM_UUID`, `API_BOOT_ID`, `KERNEL_RELEASE` | API와 원격 identity가 모두 성공할 때만 등록 |
| 계산 후보값 | `MODULE_RE` | 정확한 module 이름을 ERE escape한 필터 후보 |
| 운영자 선택값 | `MODULE`, `START_UTC`, `END_UTC` | 오류·manifest·inventory에서 확인한 이름과 UTC 창 |

### 1. 대상 고정과 stale 상태 제거

```bash
TARGET_READY=false
SELECTION_READY=false
unset NODE_UID SYSTEM_UUID API_BOOT_ID HOST_BOOT_ID KERNEL_RELEASE MODULE MODULE_RE START_UTC END_UTC PID PID_START_TICKS MOUNT_ID DEVICE_ID CGROUP_ID NETNS_ID NETWORK_ID ARGV_RE READ_OUT JOURNAL_OUT FILTERED_OUT READ_READY JOURNAL_READY FILTER_READY MODULE_JOURNAL_READY
SSH_OPTS=(-o BatchMode=yes -o ConnectTimeout=10 -o StrictHostKeyChecking=yes -o LogLevel=ERROR)
canonical_utc() { local value=${1:-}; [[ "$value" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] && [ "$(date -u -d "$value" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" = "$value" ]; }
window_valid() { canonical_utc "${START_UTC:-}" && canonical_utc "${END_UTC:-}" && [[ "$START_UTC" < "$END_UTC" ]]; }
NODE='PASTE_MODULE_NODE_HERE'
SSH_DEST='PASTE_MODULE_SSH_DEST_HERE'
EXPECTED_MACHINE_ID='PASTE_MODULE_MACHINE_ID_HERE'
MISSING=''; for tool in kubectl jq ssh grep sed date; do command -v "$tool" >/dev/null 2>&1 || MISSING="$MISSING $tool"; done
if [ -z "${BASH_VERSION:-}" ] || [ -n "$MISSING" ] || [[ ! "$SSH_DEST" =~ ^[A-Za-z0-9][A-Za-z0-9._@:-]*$ ]] || [[ ! "$EXPECTED_MACHINE_ID" =~ ^[0-9a-f]{32}$ ]]; then printf '중단: Bash/도구/입력 gate 실패:%s\n' "$MISSING" >&2; else
  NODE_JSON="$(kubectl get node "$NODE" -o json)"; API_RC=$?
  [ "$API_RC" -eq 0 ] && NODE_UID="$(jq -r '.metadata.uid // empty' <<<"$NODE_JSON")" && SYSTEM_UUID="$(jq -r '.status.nodeInfo.systemUUID // empty' <<<"$NODE_JSON")" && API_BOOT_ID="$(jq -r '.status.nodeInfo.bootID // empty' <<<"$NODE_JSON")"
  ID_OUT="$(ssh "${SSH_OPTS[@]}" -- "$SSH_DEST" sh -s -- "$EXPECTED_MACHINE_ID" <<'REMOTE'
set -eu
[ "$(cat /etc/machine-id)" = "$1" ] || exit 42
printf '%s\t%s\n' "$(cat /proc/sys/kernel/random/boot_id)" "$(uname -r)"
REMOTE
)"; SSH_RC=$?
  [ "$SSH_RC" -eq 0 ] && IFS=$'\t' read -r HOST_BOOT_ID KERNEL_RELEASE <<<"$ID_OUT"
  if [ "$API_RC" -eq 0 ] && [ -n "$NODE_UID" ] && [ -n "$SYSTEM_UUID" ] && [ "$HOST_BOOT_ID" = "$API_BOOT_ID" ] && [ -n "$KERNEL_RELEASE" ]; then TARGET_READY=true; printf 'TARGET_READY=true node=%s uid=%s systemUUID=%s machine-id=%s boot-id=%s kernel=%s\n' "$NODE" "$NODE_UID" "$SYSTEM_UUID" "$EXPECTED_MACHINE_ID" "$HOST_BOOT_ID" "$KERNEL_RELEASE"; else unset NODE_UID SYSTEM_UUID API_BOOT_ID HOST_BOOT_ID KERNEL_RELEASE; printf '중단: API/SSH identity 생산 실패 api_rc=%s ssh_rc=%s\n' "$API_RC" "$SSH_RC" >&2; fi
fi
unset NODE_JSON ID_OUT
```

API/SSH/system producer 실패 뒤에는 identity와 모든 downstream gate가 비어 있어야 한다. Kubernetes Node를 사용하지 않는 독립 host라면 이 문서를 억지로 적용하지 말고 host inventory 절차를 사용한다.

### 2. module과 UTC 창 선택

```bash
unset MODULE MODULE_RE START_UTC END_UTC READ_OUT JOURNAL_OUT FILTERED_OUT
SELECTION_READY=false; READ_READY=false; MODULE_JOURNAL_READY=false; FILTER_READY=false
MODULE='PASTE_MODULE_NAME_HERE'
START_UTC='PASTE_MODULE_START_UTC_HERE'
END_UTC='PASTE_MODULE_END_UTC_HERE'
if [[ "$MODULE" =~ ^[A-Za-z0-9_][A-Za-z0-9_.-]{0,127}$ ]] && window_valid; then MODULE_RE="$(printf '%s' "$MODULE" | sed 's/[][\\.^$*+?(){}|]/\\&/g')"; SELECTION_READY=true; printf 'SELECTION_READY=true module=%s regex=%s start=%s end=%s\n' "$MODULE" "$MODULE_RE" "$START_UTC" "$END_UTC"; else unset MODULE MODULE_RE START_UTC END_UTC; printf '%s\n' '중단: module 또는 canonical UTC 창 오류' >&2; fi
```

### 3. 모든 원격 읽기의 fresh gate

```bash
module_read() {
  local mode=${1:-} now_json uid system boot rc
  READ_READY=false; unset READ_OUT
  [ "$TARGET_READY" = true ] && [ "$SELECTION_READY" = true ] && window_valid && [ "$(printf '%s' "$MODULE" | sed 's/[][\\.^$*+?(){}|]/\\&/g')" = "$MODULE_RE" ] || { printf '%s\n' '중단: target/selection gate 미충족 또는 선택값 변경' >&2; return 1; }
  now_json="$(kubectl get node "$NODE" -o json)"; rc=$?
  [ "$rc" -eq 0 ] || { TARGET_READY=false; printf 'fresh API 실패 rc=%s\n' "$rc" >&2; return "$rc"; }
  uid="$(jq -r '.metadata.uid // empty' <<<"$now_json")"; system="$(jq -r '.status.nodeInfo.systemUUID // empty' <<<"$now_json")"; boot="$(jq -r '.status.nodeInfo.bootID // empty' <<<"$now_json")"
  [ "$uid" = "$NODE_UID" ] && [ "$system" = "$SYSTEM_UUID" ] && [ "$boot" = "$HOST_BOOT_ID" ] || { TARGET_READY=false; printf '%s\n' '중단: Node identity/lifecycle 변경' >&2; return 1; }
  READ_OUT="$(ssh "${SSH_OPTS[@]}" -- "$SSH_DEST" sh -s -- "$EXPECTED_MACHINE_ID" "$HOST_BOOT_ID" "$KERNEL_RELEASE" "$MODULE" "$mode" <<'REMOTE'
set -eu
[ "$(cat /etc/machine-id)" = "$1" ] || exit 42
[ "$(cat /proc/sys/kernel/random/boot_id)" = "$2" ] || exit 43
[ "$(uname -r)" = "$3" ] || exit 44
module=$4; mode=$5
case "$mode" in
  metadata) command -v modinfo >/dev/null 2>&1 || exit 69; for field in filename vermagic depends signer sig_id; do value=$(modinfo -k "$3" -F "$field" "$module") || exit $?; printf '%s=%s\n' "$field" "$value"; done ;;
  loaded) command -v lsmod >/dev/null 2>&1 || exit 69; command -v awk >/dev/null 2>&1 || exit 69; out=$(lsmod) || exit $?; awk -v data="$out" -v module="$module" 'BEGIN {n=split(data,row,"\n"); for(i=1;i<=n;i++){line=row[i]; sub(/^ +/,"",line); split(line,field,/ +/); if(i==1 || field[1]==module){print row[i]; if(i>1) found=1}} printf "loaded=%s\n", found ? "true" : "false"}' ;;
  builtin) for f in "/lib/modules/$3/modules.builtin" "/lib/modules/$3/modules.builtin.modinfo"; do if [ -r "$f" ]; then printf -- '--- %s ---\n' "$f"; if result=$(grep -F -- "$module" "$f"); then printf '%s\n' "$result"; else grep_rc=$?; [ "$grep_rc" -eq 1 ] && printf 'builtin-match=none path=%s\n' "$f" || exit "$grep_rc"; fi; fi; done ;;
  secureboot) command -v mokutil >/dev/null 2>&1 || exit 69; mokutil --sb-state ;;
  *) exit 64 ;;
esac
REMOTE
)"; rc=$?
  if [ "$rc" -ne 0 ]; then unset READ_OUT; printf 'remote read 실패 mode=%s rc=%s\n' "$mode" "$rc" >&2; return "$rc"; fi
  READ_READY=true; printf '%s\n' "$READ_OUT"
}
```

`module_read metadata`

`module_read loaded`는 `lsmod` 생산 성공 뒤 header와 exact module 행만 출력하고 `loaded=true|false`를 명시한다. `loaded=false`는 built-in·미로딩·이름 경계를 구분하지 못하므로 metadata와 built-in 결과를 함께 본다.

### 4. bounded kernel journal

```bash
MODULE_JOURNAL_READY=false; FILTER_READY=false; unset JOURNAL_OUT FILTERED_OUT
if [ "$TARGET_READY" = true ] && [ "$SELECTION_READY" = true ] && window_valid && [ "$(printf '%s' "$MODULE" | sed 's/[][\\.^$*+?(){}|]/\\&/g')" = "$MODULE_RE" ]; then
  NOW_JSON="$(kubectl get node "$NODE" -o json)"; API_RC=$?
  if [ "$API_RC" -eq 0 ] && [ "$(jq -r '.metadata.uid' <<<"$NOW_JSON")" = "$NODE_UID" ] && [ "$(jq -r '.status.nodeInfo.systemUUID' <<<"$NOW_JSON")" = "$SYSTEM_UUID" ] && [ "$(jq -r '.status.nodeInfo.bootID' <<<"$NOW_JSON")" = "$HOST_BOOT_ID" ]; then
    JOURNAL_OUT="$(ssh "${SSH_OPTS[@]}" -- "$SSH_DEST" sh -s -- "$EXPECTED_MACHINE_ID" "$HOST_BOOT_ID" "$KERNEL_RELEASE" "$START_UTC" "$END_UTC" <<'REMOTE'
set -eu
[ "$(cat /etc/machine-id)" = "$1" ] || exit 42
[ "$(cat /proc/sys/kernel/random/boot_id)" = "$2" ] || exit 43
[ "$(uname -r)" = "$3" ] || exit 44
exec journalctl -k --utc --since "$4" --until "$5" -o short-iso-precise --no-pager --lines=1000
REMOTE
)"; PRODUCER_RC=$?
    if [ "$PRODUCER_RC" -eq 0 ]; then MODULE_JOURNAL_READY=true; FILTERED_OUT="$(grep -E -i -C 3 -- "$MODULE_RE|unknown symbol|invalid module format|version magic|required key|verification|lockdown|no such device" <<<"$JOURNAL_OUT")"; FILTER_RC=$?; case "$FILTER_RC" in 0) FILTER_READY=true; printf '%s\n' "$FILTERED_OUT";; 1) unset FILTERED_OUT; printf '%s\n' '필터 일치 없음: 정상 아님' >&2;; *) unset FILTERED_OUT JOURNAL_OUT; MODULE_JOURNAL_READY=false; printf '필터 오류 rc=%s\n' "$FILTER_RC" >&2;; esac; else unset JOURNAL_OUT; printf 'journal producer 실패 rc=%s\n' "$PRODUCER_RC" >&2; fi
  else TARGET_READY=false; unset NOW_JSON; printf 'fresh API 실패/identity 변경 rc=%s\n' "$API_RC" >&2; fi
fi
unset NOW_JSON
```

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | 정확한 module identifier와 load 실패·기능 부재 증거가 있음 |
| 적용 | 같은 machine-id·boot ID·kernel release에서 file/built-in/dependency/signature를 구분 가능 |
| 제외 | userspace package, device permission, Pod sysctl, runtime 자체 장애 |

검색 문자열: `Unknown symbol`, `invalid module format`, `version magic`, `Required key not available`, `module verification failed`, `Lockdown`, `No such device`.

## 관측별 진단 경로

| 관측 | 직접 근거 | 다음 행동 |
|---|---|---|
| filename·vermagic 일치 | 현재 release의 file module metadata | dependency·consumer 기능 확인 |
| built-in index exact match | 현재 release의 built-in path | load 명령 없이 consumer 확인 |
| `Unknown symbol` | exact journal과 depends | package/build owner |
| signature·Lockdown | signer·sig_id·journal | security/kernel owner; 우회 금지 |
| metadata·journal 생산 실패 | rc와 도구/권한 | 부재로 해석하지 않고 owner 이관 |

`module_read secureboot`는 journal에 signature·Lockdown 근거가 있고 `mokutil` 경로가 실제 있는 경우에만 사용한다. EFI가 아니거나 도구가 없으면 Secure Boot `미관측`이다.

## 변경 경계와 정상화

이 문서는 `modprobe`, `rmmod`, `insmod`, `depmod`, module 복사·삭제, trust/Secure Boot 우회, service restart와 reboot를 실행하지 않는다. 별도 변경은 fresh identity/evidence, 승인 ID·window, Node 가용성·PDB/quorum, 정확한 package/artifact와 idempotence, 중단 조건, 원 package/config로의 검증 가능한 rollback이 모두 있어야 한다. boot ID나 kernel release가 바뀌면 기존 승인은 무효다.

정상화는 새 boot·replacement module이면 stale 값을 모두 지우고 처음부터 재등록한다. file module은 filename·vermagic·depends·signature, built-in은 index와 kernel identity를 확인한 뒤 실제 device/runtime/CNI/storage consumer 기능, Node Ready·Lease, workload 요청을 fresh gate로 검증한다. `lsmod` 한 행이나 `Ready=True`는 기능 정상화가 아니다. device 교체가 있었다면 새 serial/WWID를 inventory와 plugin/runtime에 재등록하고 실제 I/O까지 확인한다.

보존: Node UID·systemUUID, machine-id·boot ID·kernel release, module 이름 출처, metadata 필드, producer/filter rc, bounded UTC 오류, consumer 영향, 승인·rollback·기능 결과. 전체 config·journal·argv·credential·key는 저장하지 않는다.

## 환경별 미검증

kmod/package layout, built-in index, signature·MOK 정책, runtime/device consumer와 실제 Kubernetes 1.26 동작은 환경별 미검증이며 실행하지 않았다.
