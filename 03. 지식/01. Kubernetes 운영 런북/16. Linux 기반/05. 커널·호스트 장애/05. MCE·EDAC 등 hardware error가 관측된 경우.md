# MCE·EDAC 등 hardware error가 관측된 경우

## 입력값과 빠른 수집

실행 hop은 `승인된 작업 PC/Bash → Kubernetes API`와 `작업 PC/Bash → SSH → Node host namespace → kernel journal`이다. provider/BMC/hypervisor는 별도 외부 evidence source이며 host journal 성공이 그 source의 성공을 보장하지 않는다.

| 구분 | 값 | 계약 |
|---|---|---|
| 최초 입력 | `NODE`, `SSH_DEST`, `EXPECTED_MACHINE_ID` | 승인 inventory의 정확한 host |
| API 확인 자동값 | `NODE_UID`, `SYSTEM_UUID`, `HOST_BOOT_ID` | API·SSH 모두 성공해야 등록 |
| 계산 후보값 | `HARDWARE_RE` | hardware 오류 고정 문자열 필터 |
| 운영자 선택값 | `START_UTC`, `END_UTC`, `EXTERNAL_SOURCE` | canonical UTC 창과 승인된 외부 source 이름 |

### 1. identity와 관측 창 고정

```bash
TARGET_READY=false; WINDOW_READY=false
unset NODE_UID SYSTEM_UUID API_BOOT_ID HOST_BOOT_ID START_UTC END_UTC EXTERNAL_SOURCE HARDWARE_RE PID PID_START_TICKS MOUNT_ID DEVICE_ID CGROUP_ID NETNS_ID NETWORK_ID ARGV_RE JOURNAL_READY FILTER_READY JOURNAL_OUT FILTERED_OUT
SSH_OPTS=(-o BatchMode=yes -o ConnectTimeout=10 -o StrictHostKeyChecking=yes -o LogLevel=ERROR)
canonical_utc() { local value=${1:-}; [[ "$value" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] && [ "$(date -u -d "$value" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" = "$value" ]; }
window_valid() { canonical_utc "${START_UTC:-}" && canonical_utc "${END_UTC:-}" && [[ "$START_UTC" < "$END_UTC" ]]; }
NODE='PASTE_HW_NODE_HERE'; SSH_DEST='PASTE_HW_SSH_DEST_HERE'; EXPECTED_MACHINE_ID='PASTE_HW_MACHINE_ID_HERE'
MISSING=''; for tool in kubectl jq ssh grep date; do command -v "$tool" >/dev/null 2>&1 || MISSING="$MISSING $tool"; done
if [ -z "${BASH_VERSION:-}" ] || [ -n "$MISSING" ] || [[ ! "$SSH_DEST" =~ ^[A-Za-z0-9][A-Za-z0-9._@:-]*$ ]] || [[ ! "$EXPECTED_MACHINE_ID" =~ ^[0-9a-f]{32}$ ]]; then printf '중단: Bash/도구/입력 gate 실패:%s\n' "$MISSING" >&2; else
  J="$(kubectl get node "$NODE" -o json)"; API_RC=$?; [ "$API_RC" -eq 0 ] && NODE_UID="$(jq -r '.metadata.uid // empty' <<<"$J")" && SYSTEM_UUID="$(jq -r '.status.nodeInfo.systemUUID // empty' <<<"$J")" && API_BOOT_ID="$(jq -r '.status.nodeInfo.bootID // empty' <<<"$J")"
  HOST_BOOT_ID="$(ssh "${SSH_OPTS[@]}" -- "$SSH_DEST" sh -s -- "$EXPECTED_MACHINE_ID" <<'REMOTE'
set -eu
[ "$(cat /etc/machine-id)" = "$1" ] || exit 42
cat /proc/sys/kernel/random/boot_id
REMOTE
)"; SSH_RC=$?
  if [ "$API_RC" -eq 0 ] && [ -n "$NODE_UID" ] && [ -n "$SYSTEM_UUID" ] && [ "$API_BOOT_ID" = "$HOST_BOOT_ID" ]; then HARDWARE_RE='mce|machine check|hardware error|edac|corrected|uncorrected|aer|pcie|memory error|i/o error|fatal'; TARGET_READY=true; printf 'TARGET_READY=true node=%s uid=%s systemUUID=%s machine-id=%s boot-id=%s regex=%s\n' "$NODE" "$NODE_UID" "$SYSTEM_UUID" "$EXPECTED_MACHINE_ID" "$HOST_BOOT_ID" "$HARDWARE_RE"; else unset NODE_UID SYSTEM_UUID API_BOOT_ID HOST_BOOT_ID HARDWARE_RE; printf '중단: identity producer 실패 api_rc=%s ssh_rc=%s\n' "$API_RC" "$SSH_RC" >&2; fi
fi
unset J
```

```bash
WINDOW_READY=false; JOURNAL_READY=false; FILTER_READY=false
unset START_UTC END_UTC EXTERNAL_SOURCE JOURNAL_OUT FILTERED_OUT
START_UTC='PASTE_HW_START_UTC_HERE'; END_UTC='PASTE_HW_END_UTC_HERE'; EXTERNAL_SOURCE='PASTE_HW_EXTERNAL_SOURCE_HERE'
if window_valid && [ -n "$EXTERNAL_SOURCE" ]; then WINDOW_READY=true; printf 'WINDOW_READY=true start=%s end=%s external-source=%s\n' "$START_UTC" "$END_UTC" "$EXTERNAL_SOURCE"; else unset START_UTC END_UTC EXTERNAL_SOURCE; printf '%s\n' '중단: UTC 창 또는 외부 source 미지정' >&2; fi
```

### 2. bounded journal, rc 분리

```bash
hardware_journal() {
  local j api_rc uid system boot producer_rc filter_rc
  JOURNAL_READY=false; FILTER_READY=false; unset JOURNAL_OUT FILTERED_OUT
  [ "$TARGET_READY" = true ] && [ "$WINDOW_READY" = true ] && window_valid && [ -n "$EXTERNAL_SOURCE" ] || { printf '%s\n' '중단: gate 미충족 또는 관측 창 변경' >&2; return 1; }
  j="$(kubectl get node "$NODE" -o json)"; api_rc=$?; [ "$api_rc" -eq 0 ] || { TARGET_READY=false; printf 'fresh API 실패 rc=%s\n' "$api_rc" >&2; return "$api_rc"; }
  uid="$(jq -r '.metadata.uid // empty' <<<"$j")"; system="$(jq -r '.status.nodeInfo.systemUUID // empty' <<<"$j")"; boot="$(jq -r '.status.nodeInfo.bootID // empty' <<<"$j")"
  [ "$uid" = "$NODE_UID" ] && [ "$system" = "$SYSTEM_UUID" ] && [ "$boot" = "$HOST_BOOT_ID" ] || { TARGET_READY=false; printf '%s\n' '중단: identity/lifecycle 변경' >&2; return 1; }
  JOURNAL_OUT="$(ssh "${SSH_OPTS[@]}" -- "$SSH_DEST" sh -s -- "$EXPECTED_MACHINE_ID" "$HOST_BOOT_ID" "$START_UTC" "$END_UTC" <<'REMOTE'
set -eu
[ "$(cat /etc/machine-id)" = "$1" ] || exit 42
[ "$(cat /proc/sys/kernel/random/boot_id)" = "$2" ] || exit 43
exec journalctl -k --utc --since "$3" --until "$4" -o short-iso-precise --no-pager --lines=1000
REMOTE
)"; producer_rc=$?
  if [ "$producer_rc" -ne 0 ]; then unset JOURNAL_OUT; printf 'journal producer 실패 rc=%s\n' "$producer_rc" >&2; return "$producer_rc"; fi
  JOURNAL_READY=true
  FILTERED_OUT="$(grep -E -i -C 3 -- "$HARDWARE_RE" <<<"$JOURNAL_OUT")"; filter_rc=$?
  case "$filter_rc" in 0) FILTER_READY=true; printf '%s\n' "$FILTERED_OUT";; 1) unset FILTERED_OUT; printf '%s\n' '필터 일치 없음: hardware 정상 아님' >&2;; *) unset JOURNAL_OUT FILTERED_OUT; JOURNAL_READY=false; printf '필터 오류 rc=%s\n' "$filter_rc" >&2; return "$filter_rc";; esac
}
```

`hardware_journal`

UTC·microsecond 출력 순서를 보존한다. corrected/uncorrected, severity, bank/socket/DIMM/PCI BDF/device ID는 실제 행에 있는 값만 기록한다. identifier가 없으면 장치를 추측하지 않는다.

### 3. Kubernetes 영향 fresh gate

```bash
K8S_READY=false; unset K8S_OUT
if [ "$TARGET_READY" = true ]; then
  K8S_OUT="$(kubectl get node "$NODE" -o json)"; API_RC=$?
  if [ "$API_RC" -eq 0 ] && [ "$(jq -r '.metadata.uid' <<<"$K8S_OUT")" = "$NODE_UID" ] && [ "$(jq -r '.status.nodeInfo.systemUUID' <<<"$K8S_OUT")" = "$SYSTEM_UUID" ] && [ "$(jq -r '.status.nodeInfo.bootID' <<<"$K8S_OUT")" = "$HOST_BOOT_ID" ]; then K8S_READY=true; jq -r '"=== Node ===\nUID: \(.metadata.uid)\nBoot ID: \(.status.nodeInfo.bootID)\n" + ([.status.conditions[] | "\(.type): \(.status) reason=\(.reason) heartbeat=\(.lastHeartbeatTime) transition=\(.lastTransitionTime)"] | join("\n"))' <<<"$K8S_OUT"; else TARGET_READY=false; unset K8S_OUT; printf 'API producer 실패/identity 변경 rc=%s\n' "$API_RC" >&2; fi
fi
```

Node 상태 조회 성공은 hardware·kubelet·runtime·workload 정상을 보장하지 않는다. API 실패나 `Forbidden` 뒤에는 오래된 Node 상태를 사용하지 않는다.

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | MCE·EDAC·AER·hardware error 또는 승인된 provider/BMC event가 있음 |
| 적용 | 같은 machine/boot/UTC에서 kernel, external event, Node/workload 영향을 대조 가능 |
| 제외 | 단일 application 오류, 시간축 불신, 장치 식별 없는 추측 |

검색 문자열: `MCE`, `Machine Check`, `EDAC`, `corrected`, `uncorrected`, `AER`, `Hardware Error`, `fatal`.

## 외부 source 조회 계약

`EXTERNAL_SOURCE`의 공식 UI/API에서 exact machine/system UUID 또는 승인된 provider instance ID, 시작·종료 UTC, pagination 종료까지 완전한 범위를 조회한다. API를 사용한다면 TLS 검증, read-only credential scope, HTTP status, API success field, pagination token을 각각 확인하고 401/403/429/5xx를 “event 없음”으로 바꾸지 않는다. 이 문서는 provider가 정해지지 않아 가짜 명령을 제공하지 않는다. 결과 부재는 정상이나 오류 없음이 아니라 `external evidence 없음/조회 미완료`다.

## 관측별 진단 경로

- uncorrected/fatal 또는 반복 MCE: platform owner에 즉시 이관하고 workload availability를 평가한다.
- corrected 단발: 안전한 계속 운용을 보장하지 않으며 같은 component ID의 재발·증가를 관찰한다.
- AER/I/O와 exact device identity: storage/network owner가 firmware·link·device 경계를 확인한다.
- external event와 guest journal 시간 일치: 상관 증거이며 단독 인과 확정은 아니다.
- 여러 Node 공통: 개별 guest가 아니라 fault domain/provider 경계를 확인한다.

## 변경 경계와 정상화

이 문서는 reboot, reset, VM migration, CPU/memory/device offline, firmware 변경, `cordon`·`drain`, kubelet/runtime restart와 Pod 삭제를 실행하지 않는다. 별도 변경은 fresh identity/evidence, 승인 ID·window, PDB/quorum·대체 capacity·데이터 무결성, idempotence, 중단 조건과 provider가 지원하는 verified rollback을 갖춰야 한다. irreversible hardware replacement는 rollback 불가를 명시하고 교체 계획으로 승인한다.

replacement host/device는 새 machine-id/systemUUID/boot ID와 serial/WWID/BDF를 처음부터 재등록한다. inventory, OS driver, runtime/device plugin, Kubernetes allocatable/Node condition, workload 실제 read/write·network·서비스 요청 순으로 기능을 확인하고 bounded 재평가 창에서 오류 counter와 journal 재발이 없어야 정상화한다. provider health green이나 `Ready=True` 하나만으로 닫지 않는다.

보존: identity, UTC 원문·정규화, kernel/external event ID·severity·component, producer/filter/API rc, Node·Pod/workload 영향, 승인·rollback·기능 검증. 전체 journal, credential, token, private key, 개인정보는 저장하지 않는다.

## 환경별 미검증

MCE/EDAC/AER 해석, BMC/provider API, fault domain, hardware 교체·재등록, 실제 Kubernetes 1.26 환경은 미검증이며 실행하지 않았다.
