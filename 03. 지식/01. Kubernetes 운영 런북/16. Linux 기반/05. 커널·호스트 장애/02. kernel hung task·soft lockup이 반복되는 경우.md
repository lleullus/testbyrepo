# kernel hung task·soft lockup이 반복되는 경우

## 입력값과 빠른 수집

실행 경로는 `승인된 작업 PC/Bash → Kubernetes API`와 `승인된 작업 PC/Bash → SSH → 대상 Node host namespace → kernel journal`이다. SSH의 `127.0.0.1`이나 작업 PC의 PID·mount·network namespace는 대상 host의 것이 아니다. bastion을 거치면 승인된 `ProxyJump` 설정 자체를 별도 hop으로 기록하고 임의 `ssh -J` 값을 추가하지 않는다.

| 구분 | 값 | 계약 |
|---|---|---|
| 최초 입력 | `NODE`, `SSH_DEST`, `EXPECTED_MACHINE_ID` | 승인 기록의 정확한 Node, 안전한 SSH destination, CMDB의 machine-id |
| API 확인 자동값 | `NODE_UID`, `SYSTEM_UUID`, `API_BOOT_ID` | exact-name Node API 성공 때만 등록 |
| 계산 후보값 | `EVIDENCE_RE` | 증상 고정 문자열로 생성하며 원인 확정값이 아님 |
| 운영자 선택값 | `START_UTC`, `END_UTC` | 원문 시각을 포함하는 canonical UTC 창, 시작 `<` 종료 |

각 `PASTE_..._HERE` 문자열은 문서에서 한 번만 나타난다. 재대상화할 때 이전 machine identity, PID/start, mount/device/cgroup/netns/network/time/argv-regex와 모든 downstream gate를 먼저 지운다.

### 1. 실행 위치·도구·대상 고정

```bash
TOOLS_READY=false
TARGET_READY=false
WINDOW_READY=false
unset NODE_UID SYSTEM_UUID API_BOOT_ID HOST_BOOT_ID HOSTNAME_FQDN EVIDENCE_RE START_UTC END_UTC PID PID_START_TICKS MOUNT_ID DEVICE_ID CGROUP_ID NETNS_ID NETWORK_ID ARGV_RE READ_READY JOURNAL_READY FILTER_READY READ_OUT JOURNAL_OUT FILTERED_OUT
SSH_OPTS=(-o BatchMode=yes -o ConnectTimeout=10 -o StrictHostKeyChecking=yes -o LogLevel=ERROR)
canonical_utc() { local value=${1:-}; [[ "$value" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] && [ "$(date -u -d "$value" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" = "$value" ]; }
window_valid() { canonical_utc "${START_UTC:-}" && canonical_utc "${END_UTC:-}" && [[ "$START_UTC" < "$END_UTC" ]]; }
NODE='PASTE_HUNG_NODE_HERE'
SSH_DEST='PASTE_HUNG_SSH_DEST_HERE'
EXPECTED_MACHINE_ID='PASTE_HUNG_MACHINE_ID_HERE'
MISSING=''
for tool in kubectl jq ssh grep date; do command -v "$tool" >/dev/null 2>&1 || MISSING="$MISSING $tool"; done
if [ -z "${BASH_VERSION:-}" ] || [ -n "$MISSING" ]; then
  printf '중단: Bash 또는 도구 미충족:%s\n' "$MISSING" >&2
elif [[ ! "$SSH_DEST" =~ ^[A-Za-z0-9][A-Za-z0-9._@:-]*$ ]] || [[ ! "$EXPECTED_MACHINE_ID" =~ ^[0-9a-f]{32}$ ]]; then
  printf '%s\n' '중단: SSH destination 또는 machine-id 형식 오류' >&2
else
  TOOLS_READY=true
fi
if [ "$TOOLS_READY" = true ]; then
  NODE_JSON="$(kubectl get node "$NODE" -o json)"; API_RC=$?
  if [ "$API_RC" -eq 0 ]; then
    NODE_UID="$(jq -r '.metadata.uid // empty' <<<"$NODE_JSON")"
    SYSTEM_UUID="$(jq -r '.status.nodeInfo.systemUUID // empty' <<<"$NODE_JSON")"
    API_BOOT_ID="$(jq -r '.status.nodeInfo.bootID // empty' <<<"$NODE_JSON")"
  fi
  if [ "$API_RC" -ne 0 ] || [ -z "$NODE_UID" ] || [ -z "$SYSTEM_UUID" ] || [ -z "$API_BOOT_ID" ]; then
    unset NODE_UID SYSTEM_UUID API_BOOT_ID NODE_JSON
    printf '중단: Node API identity 생산 실패 rc=%s\n' "$API_RC" >&2
  else
    IDENTITY_OUT="$(ssh "${SSH_OPTS[@]}" -- "$SSH_DEST" sh -s -- "$EXPECTED_MACHINE_ID" <<'REMOTE'
set -eu
expected=$1
actual=$(cat /etc/machine-id)
[ "$actual" = "$expected" ] || { printf 'machine-id mismatch expected=%s actual=%s\n' "$expected" "$actual" >&2; exit 42; }
printf '%s\t%s\t%s\n' "$actual" "$(cat /proc/sys/kernel/random/boot_id)" "$(hostname --fqdn 2>/dev/null || hostname)"
REMOTE
)"; SSH_RC=$?
    if [ "$SSH_RC" -eq 0 ]; then IFS=$'\t' read -r ACTUAL_MACHINE_ID HOST_BOOT_ID HOSTNAME_FQDN <<<"$IDENTITY_OUT"; fi
    if [ "$SSH_RC" -ne 0 ] || [ "$ACTUAL_MACHINE_ID" != "$EXPECTED_MACHINE_ID" ] || [ "$HOST_BOOT_ID" != "$API_BOOT_ID" ]; then
      unset HOST_BOOT_ID HOSTNAME_FQDN IDENTITY_OUT NODE_UID SYSTEM_UUID API_BOOT_ID
      printf '중단: remote/API identity 불일치 ssh_rc=%s\n' "$SSH_RC" >&2
    else
      EVIDENCE_RE='hung task|blocked for more than|soft lockup|hard lockup|watchdog|rcu.*stall'
      TARGET_READY=true
      printf 'TARGET_READY=true\nNode=%s\nNode UID=%s\nSystem UUID=%s\nMachine ID=%s\nBoot ID=%s\nRemote host=%s\n' "$NODE" "$NODE_UID" "$SYSTEM_UUID" "$EXPECTED_MACHINE_ID" "$HOST_BOOT_ID" "$HOSTNAME_FQDN"
    fi
  fi
fi
unset NODE_JSON IDENTITY_OUT ACTUAL_MACHINE_ID
```

`TARGET_READY=true`는 CMDB machine-id, API Node UID·systemUUID·boot ID와 SSH host의 현재 machine-id·boot ID가 일치한다는 뜻이다. 이것만으로 kernel이나 workload가 정상이라는 뜻은 아니다. `PermissionDenied`·`Forbidden`은 정상 데이터 부재가 아니라 접근 경계 실패다. RBAC을 넓히거나 host key 검증을 끄지 않는다.

### 2. 매 조회용 fresh gate 등록

아래 함수는 호출할 때마다 Node API identity와 원격 machine-id·boot ID를 다시 확인한다. API, SSH 또는 remote command가 실패하면 출력과 gate를 지우며 이전 결과를 재사용하지 않는다. 허용한 읽기 mode 외의 문자열은 원격 shell에서 실행되지 않으므로 `eval`은 필요하지 않다.

```bash
host_read() {
  local mode=${1:-} now_json current_uid current_system current_api_boot rc
  READ_READY=false
  unset READ_OUT
  [ "$TARGET_READY" = true ] || { printf '%s\n' '중단: TARGET_READY가 아니다.' >&2; return 1; }
  now_json="$(kubectl get node "$NODE" -o json)"; rc=$?
  if [ "$rc" -ne 0 ]; then TARGET_READY=false; printf '중단: fresh Node API 실패 rc=%s\n' "$rc" >&2; return "$rc"; fi
  current_uid="$(jq -r '.metadata.uid // empty' <<<"$now_json")"
  current_system="$(jq -r '.status.nodeInfo.systemUUID // empty' <<<"$now_json")"
  current_api_boot="$(jq -r '.status.nodeInfo.bootID // empty' <<<"$now_json")"
  if [ "$current_uid" != "$NODE_UID" ] || [ "$current_system" != "$SYSTEM_UUID" ] || [ "$current_api_boot" != "$HOST_BOOT_ID" ]; then
    printf '%s\n' '중단: Node identity/lifecycle 변경' >&2
    TARGET_READY=false
    return 1
  fi
  READ_OUT="$(ssh "${SSH_OPTS[@]}" -- "$SSH_DEST" sh -s -- "$EXPECTED_MACHINE_ID" "$HOST_BOOT_ID" "$mode" <<'REMOTE'
set -eu
expected_machine=$1
expected_boot=$2
mode=$3
[ "$(cat /etc/machine-id)" = "$expected_machine" ] || exit 42
[ "$(cat /proc/sys/kernel/random/boot_id)" = "$expected_boot" ] || exit 43
case "$mode" in
  identity) printf 'machine-id=%s\nboot-id=%s\nhost=%s\nkernel=%s\nobserved=%s\n' "$(cat /etc/machine-id)" "$(cat /proc/sys/kernel/random/boot_id)" "$(hostname --fqdn 2>/dev/null || hostname)" "$(uname -r)" "$(date -u '+%Y-%m-%dT%H:%M:%SZ')" ;;
  pressure) printf '%s\n' '=== /proc/pressure ==='; for f in /proc/pressure/cpu /proc/pressure/io /proc/pressure/memory; do [ -r "$f" ] && { printf -- '--- %s ---\n' "$f"; cat "$f"; }; done; printf '%s\n' '=== blocked tasks ==='; ps_out=$(ps -eo pid=,ppid=,stat=,lstart=,comm=) || exit $?; awk -v data="$ps_out" 'BEGIN {n=split(data,row,"\n"); found=0; for(i=1;i<=n;i++){line=row[i]; sub(/^ +/,"",line); split(line,field,/ +/); if(field[3] ~ /^D/){print row[i]; found=1}} if(!found) print "blocked-task-match=none"}' ;;
  mounts) findmnt -rn -o TARGET,SOURCE,MAJ:MIN,FSTYPE,OPTIONS ;;
  *) printf 'unsupported read mode=%s\n' "$mode" >&2; exit 64 ;;
esac
REMOTE
)"; rc=$?
  if [ "$rc" -ne 0 ]; then unset READ_OUT; printf '중단: fresh remote read 실패 mode=%s rc=%s\n' "$mode" "$rc" >&2; return "$rc"; fi
  READ_READY=true
  printf '%s\n' "$READ_OUT"
}
```

### 3. UTC 관측 창과 journal gate

```bash
unset START_UTC END_UTC JOURNAL_OUT FILTERED_OUT
WINDOW_READY=false
START_UTC='PASTE_HUNG_START_UTC_HERE'
END_UTC='PASTE_HUNG_END_UTC_HERE'
if window_valid; then
  WINDOW_READY=true
  printf 'WINDOW_READY=true start=%s end=%s regex=%s\n' "$START_UTC" "$END_UTC" "$EVIDENCE_RE"
else
  unset START_UTC END_UTC
  printf '%s\n' '중단: canonical UTC 창 오류' >&2
fi
```

```bash
kernel_journal() {
  local now_json current_uid current_system current_boot producer_rc filter_rc
  JOURNAL_READY=false
  FILTER_READY=false
  unset JOURNAL_OUT FILTERED_OUT
  [ "$TARGET_READY" = true ] && [ "$WINDOW_READY" = true ] && window_valid || { printf '%s\n' '중단: target/time gate 미충족 또는 UTC 값 변경' >&2; return 1; }
  now_json="$(kubectl get node "$NODE" -o json)"; producer_rc=$?
  [ "$producer_rc" -eq 0 ] || { TARGET_READY=false; printf '중단: fresh Node API 실패 rc=%s\n' "$producer_rc" >&2; return "$producer_rc"; }
  current_uid="$(jq -r '.metadata.uid // empty' <<<"$now_json")"; current_system="$(jq -r '.status.nodeInfo.systemUUID // empty' <<<"$now_json")"; current_boot="$(jq -r '.status.nodeInfo.bootID // empty' <<<"$now_json")"
  [ "$current_uid" = "$NODE_UID" ] && [ "$current_system" = "$SYSTEM_UUID" ] && [ "$current_boot" = "$HOST_BOOT_ID" ] || { TARGET_READY=false; printf '%s\n' '중단: journal 전 identity/lifecycle 변경' >&2; return 1; }
  JOURNAL_OUT="$(ssh "${SSH_OPTS[@]}" -- "$SSH_DEST" sh -s -- "$EXPECTED_MACHINE_ID" "$HOST_BOOT_ID" "$START_UTC" "$END_UTC" <<'REMOTE'
set -eu
[ "$(cat /etc/machine-id)" = "$1" ] || exit 42
[ "$(cat /proc/sys/kernel/random/boot_id)" = "$2" ] || exit 43
command -v journalctl >/dev/null 2>&1 || exit 69
exec journalctl -k --utc --since "$3" --until "$4" -o short-iso-precise --no-pager --lines=1000
REMOTE
)"; producer_rc=$?
  if [ "$producer_rc" -ne 0 ]; then unset JOURNAL_OUT; printf 'journal producer 실패 rc=%s\n' "$producer_rc" >&2; return "$producer_rc"; fi
  JOURNAL_READY=true
  FILTERED_OUT="$(grep -E -i -C 3 -- "$EVIDENCE_RE" <<<"$JOURNAL_OUT")"; filter_rc=$?
  case "$filter_rc" in
    0) FILTER_READY=true; printf '%s\n' "$FILTERED_OUT" ;;
    1) unset FILTERED_OUT; printf '%s\n' '필터 일치 없음: 오류 부재나 정상으로 해석하지 않는다.' >&2 ;;
    *) unset FILTERED_OUT JOURNAL_OUT; JOURNAL_READY=false; printf '필터 오류 rc=%s\n' "$filter_rc" >&2; return "$filter_rc" ;;
  esac
}
```

`journalctl` 출력은 UTC·microsecond 형식을 유지하며 명령이 반환한 순서를 보존한다. 다른 source의 시각은 원문 timezone·정밀도와 UTC 정규화값을 함께 기록한다. 빈 journal은 rotation, volatile storage, 권한, wrong boot 또는 수집 실패 후보이며 정상 증거가 아니다.

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | 같은 host boot에서 `hung task`, `blocked for more than`, `soft lockup` 또는 watchdog이 반복됨 |
| 적용 | 정확한 machine-id·boot ID·UTC 창에서 task/PID/CPU와 storage·virtualization·Node 영향을 대조 가능 |
| 제외 | boot ID 변경은 [[01. 호스트가 예기치 않게 재부팅되거나 kernel panic이 의심되는 경우]], Node Ready/Lease 이상은 해당 Node 상태 런북, 단일 Pod 문제는 workload 런북 |

검색 문자열: `hung task`, `blocked for more than`, `soft lockup`, `watchdog`, `rcu stall`, `D state`, `I/O error`, `reset`, `read-only`.

## 관측별 진단 경로

| 지금 보이는 것 | 먼저 볼 것 | 그다음 어디를 볼지 | 상세 절 |
|---|---|---|---|
| 같은 task/PID가 blocked | PID와 start time, D state, stack 주변 행 | device/mount 및 process owner | 1 |
| 같은 CPU에서 lockup | CPU 번호·지속 시간·RCU/watchdog 행 | kernel·virtualization owner | 2 |
| I/O timeout·reset 동반 | exact device token·MAJ:MIN·mount | storage/device owner | 3 |
| Node Ready·Lease 변화 | 같은 Node UID·UTC 시간 | Node 상태 런북 | 4 |

### 1. task lifecycle 고정

`kernel_journal`을 실행한다. PID가 출력에 있을 때만 그 PID를 운영자 선택값으로 등록하고, 현재 process start ticks와 command name을 확인한다. PID 재사용이나 process 종료가 보이면 이전 stack과 현재 process를 합치지 않는다. argv 전체나 환경변수는 읽지 않는다.

`host_read identity`

`host_read pressure`

같은 PID·start ticks가 확인되지 않으면 task 이름만으로 현재 process를 원인으로 지목하지 않는다. D state는 uninterruptible sleep 관측이지 storage 고장 확정이 아니다.

### 2. CPU·watchdog 분기

kernel 결과의 exact UTC, CPU 번호, stuck duration, task/PID와 boot ID를 묶는다. `/proc/pressure`는 현재 압력이며 과거 lockup의 직접 증거가 아니다. RCU, scheduler, driver, vCPU steal 중 하나를 임의 선택하지 않고 kernel stack과 provider event ID를 해당 owner에게 전달한다.

### 3. device·mount 분기

`host_read mounts`

exact journal device token을 `findmnt`의 source·MAJ:MIN과 연결할 수 있을 때만 storage 영향 후보로 기록한다. 현재 mount는 과거 I/O 오류 원인을 보장하지 않는다. device가 교체됐다면 이전 WWID/serial과 새 device identity, 재등록 시각을 storage inventory에서 확인하고 kubelet/runtime/device plugin이 새 device를 다시 발견했으며 실제 workload read/write가 성공한 뒤에만 정상화한다.

### 4. Kubernetes 영향

```bash
NODE_CHECK_READY=false
unset NODE_CHECK_OUT
if [ "$TARGET_READY" = true ]; then
  NODE_CHECK_OUT="$(kubectl get node "$NODE" -o json)"; API_RC=$?
  if [ "$API_RC" -eq 0 ] && [ "$(jq -r '.metadata.uid' <<<"$NODE_CHECK_OUT")" = "$NODE_UID" ] && [ "$(jq -r '.status.nodeInfo.systemUUID' <<<"$NODE_CHECK_OUT")" = "$SYSTEM_UUID" ] && [ "$(jq -r '.status.nodeInfo.bootID' <<<"$NODE_CHECK_OUT")" = "$HOST_BOOT_ID" ]; then
    NODE_CHECK_READY=true
    jq -r '"=== Node ===\nUID: \(.metadata.uid)\nBoot ID: \(.status.nodeInfo.bootID)\n" + ([.status.conditions[] | "\(.type): \(.status) reason=\(.reason) heartbeat=\(.lastHeartbeatTime) transition=\(.lastTransitionTime)"] | join("\n"))' <<<"$NODE_CHECK_OUT"
  else
    unset NODE_CHECK_OUT
    TARGET_READY=false
    printf '중단: Node API 생산 실패 또는 identity 변경 rc=%s\n' "$API_RC" >&2
  fi
fi
```

API 조회 실패·권한 거부·identity 변경 뒤에는 이전 Ready/Lease 값을 사용하지 않는다. `Ready=True`는 kernel task, device와 실제 workload 기능 정상을 보장하지 않는다.

## 복구 전 안전 경계

이 문서는 sysrq, panic trigger, reboot, CPU offline, affinity 변경, module unload, device reset, filesystem remount·fsck, kubelet/runtime restart, `cordon`·`drain`·Pod delete 명령을 제공하지 않는다. 필요하면 별도 변경 절차에서 현재 identity/evidence 재수집, 승인 ID·window, PDB/quorum·대체 capacity, idempotence, 중단 조건과 검증 가능한 rollback을 먼저 확정한다. identity 또는 boot ID가 바뀌면 승인은 무효다.

## 정상화와 증거

정상화 조회도 `host_read`와 `kernel_journal`의 fresh gate를 새 UTC 재평가 창으로 다시 통과한다. 필터 무일치는 journal producer 성공과 보존 범위가 확인된 경우에만 “해당 창에서 재발 미관측”으로 기록한다. 실제 기능 → workload 오류율/지연 → kubelet·runtime → Node Ready·Lease → host pressure → kernel warning 순으로 확인한다. 교체 process나 device는 새 PID/start ticks 또는 device identity를 재등록하고 실제 서비스 요청·Job 결과·read/write가 성공해야 한다.

보존: Node name·UID·systemUUID, machine-id, boot ID, SSH 실행 host/hop, UTC 원문·정규화 창, warning timestamp·task/PID/CPU, 관련 device/mount identity, producer/filter rc, Node·workload 영향, 승인·rollback·기능 검증 결과. 전체 journal, argv, 환경변수, token, Secret, private key와 개인정보는 저장하지 않는다.

## 환경별 미검증

kernel watchdog·hung task 설정, journal 보존, PID와 stack 형식, storage/device identity, virtualization/provider event, SSH hop, workload SLO는 환경별 미검증이다. 실제 host와 Kubernetes 1.26 환경에서는 실행하지 않았다.
