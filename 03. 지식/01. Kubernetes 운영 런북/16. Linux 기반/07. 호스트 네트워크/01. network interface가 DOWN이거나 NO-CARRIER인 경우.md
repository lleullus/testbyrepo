# network interface가 DOWN이거나 NO-CARRIER인 경우

## 입력값과 빠른 수집

이 문서는 Linux host network namespace만 다룬다. 실행 경로는 `작업 PC/Bastion -> SSH -> 승인 host -> /etc/machine-id + host netns -> exact interface ifindex/iflink/MAC -> link/address/route/kernel`이다. 작업 PC 변수를 원격 환경변수로 가정하지 않고 positional argument로 전달한다.

| 종류 | 변수 | 출처 |
|---|---|---|
| 최초 입력 | `SSH_HOST`, `HOST_MACHINE_ID`, `IFACE` | 승인 인벤토리와 실제 `ip` 출력 |
| 시스템 자동값 | host netns inode, ifindex, iflink, MAC, link kind | 원격 Linux |
| 계산 후보 | route 결과의 `dev/src` | destination 선택 뒤 계산하며 확정 전 원인으로 사용하지 않음 |
| 운영자 선택 | `DESTINATION_IP`, UTC evidence window | 사건의 실제 API/service endpoint와 최초 관측 시각 |

interface 이름만으로 physical NIC, bond, bridge, veth, tunnel 또는 CNI를 추측하지 않는다.

**도구·최초 입력·stale 상태 폐기**

`TOOLS_READY=false; MISSING=''; for T in ssh jq date; do command -v "$T" >/dev/null 2>&1 || MISSING="$MISSING $T"; done; [ -n "${BASH_VERSION:-}" ] && [ -z "$MISSING" ] && TOOLS_READY=true; unset INPUT_READY AUTO_READY SELECTION_READY EVIDENCE_READY MUTATION_READY ROLLBACK_READY NORMALIZATION_READY NETNS_INODE IFINDEX IFLINK MAC LINK_KIND DESTINATION_IP START_RFC3339 END_RFC3339; SSH_HOST='PASTE_APPROVED_SSH_HOST_HERE'; HOST_MACHINE_ID='PASTE_REMOTE_MACHINE_ID_HERE'; IFACE='PASTE_INTERFACE_HERE'; INPUT_READY=false; if [ "$TOOLS_READY" = true ] && [ -n "$SSH_HOST" ] && [ -n "$HOST_MACHINE_ID" ] && [ -n "$IFACE" ]; then INPUT_READY=true; printf 'INPUT_READY=true host=%s machineID=%s interface=%s\n' "$SSH_HOST" "$HOST_MACHINE_ID" "$IFACE"; else printf '중단: 도구/입력 실패%s\n' "$MISSING" >&2; fi`

**host/interface identity 자동 등록**

`AUTO_READY=false; SELECTION_READY=false; EVIDENCE_READY=false; MUTATION_READY=false; ROLLBACK_READY=false; NORMALIZATION_READY=false; unset NETNS_INODE IFINDEX IFLINK MAC LINK_KIND; if [ "$INPUT_READY" != true ]; then printf '%s\n' '중단: INPUT_READY가 아니다.' >&2; elif RAW="$(ssh -o BatchMode=yes -- "$SSH_HOST" bash -c 'set -eu; mid=$1; iface=$2; [ "$(cat /etc/machine-id)" = "$mid" ]; command -v ip >/dev/null; command -v jq >/dev/null; printf "netns=%s\n" "$(stat -Lc %i /proc/1/ns/net)"; ip -j -details link show dev "$iface"' bash "$HOST_MACHINE_ID" "$IFACE")"; then NETNS_INODE="${RAW%%$'\n'*}"; NETNS_INODE="${NETNS_INODE#netns=}"; J="${RAW#*$'\n'}"; COUNT="$(jq 'length' <<<"$J")"; if [ "$COUNT" -ne 1 ]; then printf '중단: exact interface 후보 수=%s\n' "$COUNT" >&2; else IFINDEX="$(jq -r '.[0].ifindex' <<<"$J")"; IFLINK="$(jq -r '.[0].link_index // .[0].ifindex' <<<"$J")"; MAC="$(jq -r '.[0].address // "-"' <<<"$J")"; LINK_KIND="$(jq -r '.[0].linkinfo.info_kind // "physical-or-unknown"' <<<"$J")"; AUTO_READY=true; printf 'AUTO_READY=true host=%s netns=%s interface=%s ifindex=%s iflink=%s mac=%s kind=%s\n' "$SSH_HOST" "$NETNS_INODE" "$IFACE" "$IFINDEX" "$IFLINK" "$MAC" "$LINK_KIND"; fi; else printf '%s\n' '중단: SSH/machine-id/interface 조회 실패' >&2; fi`

**모든 host 조회의 direct identity guard**

`fresh_host(){ EVIDENCE_READY=false; MUTATION_READY=false; ROLLBACK_READY=false; NORMALIZATION_READY=false; local j selection_was="${SELECTION_READY:-false}"; SELECTION_READY=false; [ "$AUTO_READY" = true ] || return 1; j="$(ssh -o BatchMode=yes -- "$SSH_HOST" bash -c 'set -eu; mid=$1; netns=$2; iface=$3; idx=$4; iflink=$5; mac=$6; [ "$(cat /etc/machine-id)" = "$mid" ]; [ "$(stat -Lc %i /proc/1/ns/net)" = "$netns" ]; j=$(ip -j -details link show dev "$iface"); [ "$(jq -r '\''if length==1 then .[0].ifindex else empty end'\'' <<<"$j")" = "$idx" ]; [ "$(jq -r '\''if length==1 then (.[0].link_index // .[0].ifindex) else empty end'\'' <<<"$j")" = "$iflink" ]; [ "$(jq -r '\''if length==1 then (.[0].address // "-") else empty end'\'' <<<"$j")" = "$mac" ]; printf "%s" "$j"' bash "$HOST_MACHINE_ID" "$NETNS_INODE" "$IFACE" "$IFINDEX" "$IFLINK" "$MAC")" || { printf '%s\n' '중단: host/netns/interface identity 변경; 자동 등록부터 재실행' >&2; return 1; }; if [ "$(jq 'length' <<<"$j")" -eq 1 ]; then SELECTION_READY="$selection_was"; return 0; else return 1; fi; }`

원격 host에도 `jq`가 필요하다. 없으면 자동 identity guard를 우회하지 말고 승인된 host owner에게 ifindex/iflink/MAC를 같은 machine-id·netns에서 수집하도록 이관한다.

**운영자 선택값 입력**

`DESTINATION_IP='PASTE_INCIDENT_DESTINATION_IP_HERE'; START_RFC3339='PASTE_START_RFC3339_HERE'; END_RFC3339='PASTE_END_RFC3339_HERE'`

**selection·canonical time gate**

`SELECTION_READY=false; EVIDENCE_READY=false; NORMALIZATION_READY=false; canon(){ [[ "$1" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] && [ "$(date -u -d "$1" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" = "$1" ]; }; if ! fresh_host; then printf '%s\n' '중단: current host identity 실패' >&2; elif ! [[ "$DESTINATION_IP" =~ ^([0-9]{1,3}\.){3}[0-9]{1,3}$|^[0-9A-Fa-f:]+$ ]] || ! canon "$START_RFC3339" || ! canon "$END_RFC3339" || [ "$(date -u -d "$START_RFC3339" +%s)" -ge "$(date -u -d "$END_RFC3339" +%s)" ]; then printf '%s\n' '중단: destination 또는 UTC RFC3339 window 형식 실패' >&2; else SELECTION_READY=true; printf 'SELECTION_READY=true destination=%s window=%s..%s\n' "$DESTINATION_IP" "$START_RFC3339" "$END_RFC3339"; fi`

IPv4 regex는 형식 후보만 거르며 각 octet 범위를 확정하지 않는다. 실제 `ip route get` 성공이 destination 유효성 gate다.

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | 승인 host의 exact interface가 `DOWN`, `NO-CARRIER` 또는 carrier 상실로 관측됨 |
| 적용 | host netns와 interface identity를 고정해 link/address/route/kernel을 대조 가능 |
| 제외 | Node condition·Lease가 최초 증상이면 [[04. 노드·런타임/01. 노드 상태·상태 보고/01. Node Ready condition이 False인 경우]], Pod veth/CNI는 [[00. Kubernetes 운영 런북 허브#카테고리|클러스터 네트워크]] |

검색 문자열: `DOWN`, `NO-CARRIER`, `LOWER_UP`, `carrier`, `NETDEV WATCHDOG`, `renamed`, `reset`, `firmware`, `veth`, `bridge`, `bond`, `vxlan`, `tun`.

## 관측별 진단 경로

| 지금 보이는 것 | 먼저 볼 것 | 그다음 어디를 볼지 | 상세 절 |
|---|---|---|---|
| admin/oper state DOWN | flags·operstate·carrier·kind | manager 또는 lower layer | [[#1. link·address snapshot]] |
| NO-CARRIER | physical/virtual kind·master/parent | NIC/switch/hypervisor/virtual owner | [[#1. link·address snapshot]] |
| link UP이나 path 실패 | route get의 dev/src | route/policy owner | [[#2. destination path]] |
| link/driver message 동시 발생 | exact interface·UTC window | kernel/infrastructure owner | [[#3. bounded kernel evidence]] |
| veth/bridge/tunnel | master·peer·namespace | CNI/virtual network | [[#4. 경계와 원인 확정]] |

## 1. link·address snapshot

`if [ "$SELECTION_READY" != true ] || ! fresh_host; then printf '%s\n' '중단: current host selection gate 실패' >&2; elif ssh -o BatchMode=yes -- "$SSH_HOST" bash -c 'set -eu; mid=$1; netns=$2; iface=$3; idx=$4; iflink=$5; mac=$6; [ "$(cat /etc/machine-id)" = "$mid" ]; [ "$(stat -Lc %i /proc/1/ns/net)" = "$netns" ]; j=$(ip -j -details link show dev "$iface"); [ "$(jq -r '\''.[0].ifindex'\'' <<<"$j")" = "$idx" ]; [ "$(jq -r '\''.[0].link_index // .[0].ifindex'\'' <<<"$j")" = "$iflink" ]; [ "$(jq -r '\''.[0].address // "-"'\'' <<<"$j")" = "$mac" ]; ip -details link show dev "$iface"; ip -br address show dev "$iface"; ip route show default' bash "$HOST_MACHINE_ID" "$NETNS_INODE" "$IFACE" "$IFINDEX" "$IFLINK" "$MAC"; then EVIDENCE_READY=true; else RC=$?; printf 'link producer_error rc=%s\n' "$RC" >&2; fi`

볼 것: administrative `UP`, `state`, `LOWER_UP`, `NO-CARRIER`, ifindex/iflink, kind/master/parent, address, default route `dev/src`. `NO-CARRIER`는 lower carrier 부재를 보이지만 cable·switch·hypervisor·driver 중 하나를 단독 확정하지 않는다.

## 2. destination path

`if [ "$SELECTION_READY" != true ] || ! fresh_host; then printf '%s\n' '중단: current host selection gate 실패' >&2; elif ssh -o BatchMode=yes -- "$SSH_HOST" bash -c 'set -eu; mid=$1; netns=$2; iface=$3; idx=$4; destination=$5; [ "$(cat /etc/machine-id)" = "$mid" ]; [ "$(stat -Lc %i /proc/1/ns/net)" = "$netns" ]; [ "$(cat "/sys/class/net/$iface/ifindex")" = "$idx" ]; ip route get "$destination"' bash "$HOST_MACHINE_ID" "$NETNS_INODE" "$IFACE" "$IFINDEX" "$DESTINATION_IP"; then EVIDENCE_READY=true; else RC=$?; printf 'route producer_error rc=%s; invalid destination/no route/identity 실패를 구분\n' "$RC" >&2; fi`

route 결과의 `dev`가 `IFACE`이고 `src`가 승인 주소일 때만 이 interface를 해당 destination path로 연결한다. link 정상은 Pod network, Service, 외부 VIP 또는 application 성공을 보장하지 않는다.

## 3. bounded kernel evidence

`if [ "$SELECTION_READY" != true ] || ! fresh_host; then printf '%s\n' '중단: current host selection gate 실패' >&2; elif ssh -o BatchMode=yes -- "$SSH_HOST" bash -c 'set -eu; mid=$1; netns=$2; iface=$3; idx=$4; since=$5; until=$6; [ "$(cat /etc/machine-id)" = "$mid" ]; [ "$(stat -Lc %i /proc/1/ns/net)" = "$netns" ]; [ "$(cat "/sys/class/net/$iface/ifindex")" = "$idx" ]; f=$(mktemp); m=${f}.match; trap '\''rm -f "$f" "$m"'\'' EXIT; journalctl -k --since "$since" --until "$until" --no-pager >"$f" || exit 2; if grep -F "$iface" "$f" >"$m"; then if grep -E -i "link is down|link becomes ready|carrier|NETDEV WATCHDOG|renamed|timeout|reset|error|firmware|driver" "$m"; then exit 0; else rc=$?; [ "$rc" -eq 1 ] && exit 3; exit "$rc"; fi; else rc=$?; [ "$rc" -eq 1 ] && exit 4; exit "$rc"; fi' bash "$HOST_MACHINE_ID" "$NETNS_INODE" "$IFACE" "$IFINDEX" "$START_RFC3339" "$END_RFC3339"; then printf '%s\n' 'filter_match=true'; else RC=$?; case "$RC" in 2) printf '%s\n' 'producer_error: kernel journal 실패' >&2;; 3) printf '%s\n' 'filter_match=false: interface 행에는 증상 pattern 없음';; 4) printf '%s\n' 'filter_match=false: interface 행 없음';; *) printf 'filter_error rc=%s\n' "$RC" >&2;; esac; fi`

no-match는 오류 부재가 아니라 journal 미보존·다른 message 형식 가능성을 남긴다. provider/switch/hypervisor evidence는 확인된 owner에게 같은 UTC window만 전달하며 CLI나 provider를 추측하지 않는다.

## 4. 경계와 원인 확정

- physical inventory와 ifindex/MAC가 연결되고 carrier loss·driver message가 같은 window면 physical/driver 경로다.
- virtual kind/master/peer가 확인되면 parent/virtual switch owner 경로다.
- route `dev/src`가 다른 interface면 현재 interface를 primary path 장애로 확정하지 않는다.
- veth/bridge/tunnel/CNI evidence면 Pod network로 이관한다.
- interface rename, ifindex/iflink/MAC 변화가 있으면 기존 READY와 evidence를 폐기하고 재등록한다.

## 변경 경계와 정상화

`ip link/addr/route` 변경, manager restart/reload, DHCP renew, ifup/down, kubelet/runtime/CNI restart, cordon/drain, reboot와 provider 변경은 제공하지 않는다. 별도 mutation은 current host/netns/interface tuple, 승인 manager와 원본 config, approval ID·변경 시간, Node/workload/PDB/quorum 영향, 보상 rollback을 명령 자체에서 다시 확인해야 한다.

정상화는 fresh host identity에서 link/carrier/address/route를 다시 확인하고, 같은 UTC 관찰 창에 carrier flap·driver error·route 변동이 없으며, 실제 destination 통신과 제품 기능이 성공해야 한다. 한 번 `UP`이거나 `NO-CARRIER`가 사라진 것만으로 닫지 않는다. Kubernetes Node가 관련되면 Node UID/Ready/Lease/workload를 Node 런북에서 별도 검증한다.

## 증거 경계

보존: 승인 host와 machine-id, host netns inode, interface/ifindex/iflink/MAC/kind, UTC window, 관련 link/address/route 행과 제한된 kernel message. 제외: 전체 journal/provider 응답, credential, token, Secret, 개인정보.
