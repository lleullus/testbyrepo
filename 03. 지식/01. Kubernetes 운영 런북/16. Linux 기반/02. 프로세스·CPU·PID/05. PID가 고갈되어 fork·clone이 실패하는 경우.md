# PID가 고갈되어 fork·clone이 실패하는 경우

## 입력값과 빠른 수집

hop은 `작업 Bash → API server → Node UID/condition`과 `ssh → systemUUID가 일치하는 Linux host → host process/thread limit 또는 검증된 cgroup pids controller → 선택적으로 kubelet service journal`이다. `PIDPressure`, host `pid_max/threads-max`, cgroup `pids.current/max`, systemd `TasksCurrent/TasksMax`, PID namespace는 서로 다른 제한이다.

| 종류 | 변수 | gate |
|---|---|---|
| 최초 입력 | `NODE`, `HOST` | 승인된 exact Node와 SSH endpoint |
| API 확인 자동값 | `NODE_UID`, `NODE_RV`, `NODE_SYSTEM_UUID`, `NODE_INTERNAL_IP` | API 성공 후 원격 UUID 일치 |
| 계산 후보값 | `INSTANCE_RE`, cgroup utilization | escape·분모 검증 전에는 확정하지 않음 |
| 운영자 선택값 | `PID_CGROUP`, `KUBELET_UNIT`, `START_RFC3339`, `END_RFC3339`, `EXPORTER_INSTANCE` | 실제 mount/unit/증거 확인 뒤 각각 한 번 입력 |

```bash
fresh_node() {
  local j u r
  [ "$INPUT_READY" = true ] || return 1
  j="$(kubectl get node "$NODE" -o json)" || return 1
  u="$(jq -r '.metadata.uid // empty' <<<"$j")"; r="$(jq -r '.metadata.resourceVersion // empty' <<<"$j")"
  [ "$u" = "$NODE_UID" ] && [ "$r" = "$NODE_RV" ] || { printf '중단: Node lifecycle 변경 uid=%s rv=%s\n' "$u" "$r" >&2; return 1; }
}
node_read() {
  local op="$1"; shift
  fresh_node || return 1
  ssh -- "$HOST" bash -s -- "$NODE_SYSTEM_UUID" "$op" "$@" <<'REMOTE'
set -o pipefail
expected=$1; op=$2; shift 2
actual=$(tr '[:upper:]' '[:lower:]' </sys/class/dmi/id/product_uuid 2>/dev/null | tr -d '-') || exit 20
expected=$(printf '%s' "$expected" | tr '[:upper:]' '[:lower:]' | tr -d '-')
[ -n "$actual" ] && [ "$actual" = "$expected" ] || exit 21
case "$op" in
  identity) printf 'hostname=%s\nsystem_uuid=%s\n' "$(hostname --fqdn 2>/dev/null || hostname)" "$actual" ;;
  baseline) date -u '+observed-rfc3339=%Y-%m-%dT%H:%M:%SZ'; ps -e -o pid=,ppid=,nlwp=,stat=,comm= --sort=-nlwp | sed -n '1,21p'; printf 'thread_count='; ps -eLf | wc -l; printf 'pid_max='; cat /proc/sys/kernel/pid_max; printf 'threads_max='; cat /proc/sys/kernel/threads-max; findmnt -T /sys/fs/cgroup -o TARGET,FSTYPE,OPTIONS ;;
  cgroup_identity) path=$1; case "$path" in /sys/fs/cgroup/*) ;; *) exit 30 ;; esac; real=$(realpath -e -- "$path") || exit 31; case "$real" in /sys/fs/cgroup/*) ;; *) exit 32 ;; esac; [ -r "$real/pids.current" ] && [ -r "$real/pids.max" ] || exit 33; printf 'cgroup_real=%s\npids_current=' "$real"; cat "$real/pids.current"; printf 'pids_max='; cat "$real/pids.max" ;;
  service_identity) unit=$1; [[ "$unit" =~ ^[A-Za-z0-9_.@-]+\.service$ ]] || exit 40; systemctl show "$unit" -p Id -p LoadState -p FragmentPath -p MainPID -p InvocationID --value | sed -n '1,5p' ;;
  journal_kernel) start=$1; end=$2; journalctl -k --since "$start" --until "$end" --no-pager | grep -E -i -C 3 'fork|clone|pthread_create|resource temporarily unavailable|cannot allocate|too many processes|pid|thread'; status=("${PIPESTATUS[@]}"); [ "${status[0]}" -eq 0 ] || exit "${status[0]}"; [ "${status[1]}" -eq 0 ] || [ "${status[1]}" -eq 1 ] || exit "${status[1]}" ;;
  journal_unit) unit=$1; fragment=$2; mainpid=$3; invocation=$4; start=$5; end=$6; [[ "$unit" =~ ^[A-Za-z0-9_.@-]+\.service$ ]] || exit 40; out=$(systemctl show "$unit" -p FragmentPath -p MainPID -p InvocationID --value) || exit 41; [ "$(printf '%s\n' "$out" | sed -n '1p')" = "$fragment" ] && [ "$(printf '%s\n' "$out" | sed -n '2p')" = "$mainpid" ] && [ "$(printf '%s\n' "$out" | sed -n '3p')" = "$invocation" ] || exit 42; journalctl -u "$unit" --since "$start" --until "$end" --no-pager | grep -E -i -C 3 'pid.available|PIDPressure|pid pressure|fork|clone|evict|failed|resource temporarily unavailable|too many processes'; status=("${PIPESTATUS[@]}"); [ "${status[0]}" -eq 0 ] || exit "${status[0]}"; [ "${status[1]}" -eq 0 ] || [ "${status[1]}" -eq 1 ] || exit "${status[1]}" ;;
  *) exit 22 ;;
esac
REMOTE
}
```

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | `fork`, `clone`, `pthread_create`, `resource temporarily unavailable` 또는 `PIDPressure=True` |
| 적용 | host·cgroup·service·Node 신호를 같은 UTC window에서 분리 가능 |
| 제외 | `EMFILE/ENFILE`은 FD 런북, OOM은 메모리 런북, `Preempted`는 scheduler 런북 |

검색 문자열: `fork`, `clone`, `threads-max`, `pid_max`, `pids.current`, `pids.max`, `PIDPressure`, `pid.available`.

## 직접 진단

`DIAG_READY=false; if [ "$TIME_READY" != true ]; then printf '%s\n' '중단: TIME_READY가 아니다.' >&2; elif B="$(node_read baseline)"; then DIAG_READY=true; printf '%s\n' "$B"; else printf '%s\n' '중단: baseline producer 실패' >&2; fi; unset B`

`if [ "$DIAG_READY" = true ] && [ "$CGROUP_READY" = true ] && C="$(node_read cgroup_identity "$CGROUP_REAL")"; then printf '%s\n' "$C"; else printf '%s\n' '중단: cgroup fresh identity/producer 실패' >&2; fi; unset C`

`if [ "$DIAG_READY" = true ] && K="$(node_read journal_kernel "$START_RFC3339" "$END_RFC3339")"; then if [ -n "$K" ]; then printf '%s\n' "$K"; else printf '%s\n' 'no-match: kernel 필터 결과 없음'; fi; else printf '%s\n' '중단: kernel journal producer/filter 오류' >&2; fi; unset K`

`if [ "$DIAG_READY" = true ] && [ "$SERVICE_READY" = true ] && J="$(node_read journal_unit "$KUBELET_UNIT" "$KUBELET_FRAGMENT" "$KUBELET_MAINPID" "$KUBELET_INVOCATION_ID" "$START_RFC3339" "$END_RFC3339")"; then if [ -n "$J" ]; then printf '%s\n' "$J"; else printf '%s\n' 'no-match: 동일 service identity의 kubelet 필터 결과 없음'; fi; else printf '%s\n' '중단: service replacement 또는 journal producer/filter 오류' >&2; fi; unset J`

host 총량과 전역 limit, cgroup current/max, service journal, Node condition/Event를 별도 근거로 판정한다. `pids.max=max`는 host 여유를 보장하지 않는다. producer 실패·권한 오류, 성공 producer의 no-match, filter 오류를 구분한다. 현재 정상값은 과거 peak 부재를 보장하지 않는다. runtime unit/socket/CRI endpoint는 이 런북에서 사용하지 않으며 kubelet의 runtime endpoint를 추측하지 않는다.

분모 0·metric 없음·label mismatch·target down·datasource/time 오류와 query 오류를 분리한다. `absent==1`은 정상 0이 아니다. exporter identity가 Node UID/systemUUID와 monitoring inventory에서 매핑되지 않으면 쿼리를 증거로 쓰지 않는다.

## 변경 격리와 정상화

limit/sysctl/cgroup 변경, process kill, Pod 삭제, kubelet/runtime restart, reboot를 실행하지 않는다. 별도 변경은 fresh identities, 직접 fork 실패 근거, owner 승인 ID·정확한 RBAC/SSH/audit 주체, window, PDB/quorum·Job side effect·대체 capacity, 멱등성, 중단 조건과 검증된 rollback을 확인한다. 변경/rollback도 직전 identity·evidence를 다시 조회하며 replacement Node/Pod/process/service invocation은 새 관계로 전체 등록한다.

`NORMALIZE_READY=false; if [ "$DIAG_READY" != true ] || [ "$CGROUP_READY" != true ]; then printf '%s\n' '중단: 진단/cgroup gate 실패' >&2; elif V="$(node_read baseline)" && C="$(node_read cgroup_identity "$CGROUP_REAL")"; then NORMALIZE_READY=true; printf '%s\n%s\n' "$V" "$C"; else printf '%s\n' '중단: 정상화 fresh producer 실패' >&2; fi; unset V C`

새 fork·PIDPressure·eviction 오류가 window 동안 멈추고 host/cgroup 여유가 안정되며, 새 Pod UID·owner·Ready·EndpointSlice와 실제 요청/Job 결과가 정상이어야 한다. `PIDPressure=False`나 process 수 한 번 감소만으로 닫지 않는다.

## 증거·환경 한계

Node UID/RV/systemUUID, 원격 identity, service FragmentPath/MainPID/InvocationID, UTC window, process/thread·limits, cgroup real path/current/max, journal producer/no-match/filter 결과, 영향 owner와 기능 검증을 보존한다. argv·전체 process 목록·Secret·token·개인정보는 저장하지 않는다. 실제 인프라 명령은 실행하지 않았고 cgroup 버전, systemd/journal, metrics 보존은 환경별 미검증이다.
