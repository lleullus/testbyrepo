# zombie 프로세스가 계속 증가하는 경우

## 입력값과 빠른 수집

연결 경로는 `작업 Bash → Kubernetes API의 Node identity`와 `같은 host의 ssh → 검증된 Linux host → host PID namespace → zombie PID → PPID → parent의 PID namespace/cgroup → 선택적으로 검증된 workload owner`다. zombie는 이미 종료한 child의 table entry이며 zombie 자체에 signal을 보내는 절차가 아니다.

| 종류 | 변수 | gate |
|---|---|---|
| 최초 입력 | `NODE`, `HOST` | 승인된 exact Node와 SSH endpoint |
| API 확인 자동값 | `NODE_UID`, `NODE_RV`, `NODE_SYSTEM_UUID` | Node API 성공 후 원격 DMI UUID 일치 |
| 계산 후보값 | `INSTANCE_RE`, sample별 parent 분포 | regex escape와 bounded 계산이며 owner 확정값이 아님 |
| 운영자 선택값 | `ZOMBIE_PID`, `PARENT_PID`, `START_RFC3339`, `END_RFC3339`, `EXPORTER_INSTANCE` | 출력 근거를 확인한 뒤 각 입력칸을 한 번 사용 |

### 1. 도구·Node·원격 identity

```bash
fresh_node() {
  local j u r
  [ "$INPUT_READY" = true ] || return 1
  j="$(kubectl get node "$NODE" -o json)" || return 1
  u="$(jq -r '.metadata.uid // empty' <<<"$j")"; r="$(jq -r '.metadata.resourceVersion // empty' <<<"$j")"
  [ "$u" = "$NODE_UID" ] && [ "$r" = "$NODE_RV" ] || { printf '중단: Node lifecycle 변경 uid=%s rv=%s\n' "$u" "$r" >&2; return 1; }
}
node_read() {
  local op="$1"; shift
  fresh_node || return 1
  ssh -- "$HOST" bash -s -- "$NODE_SYSTEM_UUID" "$op" "$@" <<'REMOTE'
set -o pipefail
expected=$1; op=$2; shift 2
actual=$(tr '[:upper:]' '[:lower:]' </sys/class/dmi/id/product_uuid 2>/dev/null | tr -d '-') || exit 20
expected=$(printf '%s' "$expected" | tr '[:upper:]' '[:lower:]' | tr -d '-')
[ -n "$actual" ] && [ "$actual" = "$expected" ] || exit 21
proc_identity() {
  pid=$1; [[ "$pid" =~ ^[1-9][0-9]*$ ]] && [ -r "/proc/$pid/stat" ] || exit 30
  stat=$(cat "/proc/$pid/stat") || exit 31; rest=${stat##*) }; set -- $rest
  printf '%s\t%s\t%s\t%s\t%s\n' "${20}" "$(readlink "/proc/$pid/ns/pid")" "$(sed -n 's/^PPid:[[:space:]]*//p' "/proc/$pid/status")" "$(tr '\n' ';' <"/proc/$pid/cgroup")" "${1}"
}
snapshot() {
  ps -e -o pid=,ppid=,stat=,etimes=,comm= | awk '$3 ~ /^Z/ {count++; parent[$2]++; if (shown < 20) {print "pid=" $1 " ppid=" $2 " stat=" $3 " etimes=" $4 " comm=" $5; shown++}} END {print "zombie_count=" count+0; for (p in parent) print "ppid=" p " count=" parent[p]}'
}
case "$op" in
  identity) printf 'hostname=%s\nsystem_uuid=%s\n' "$(hostname --fqdn 2>/dev/null || hostname)" "$actual" ;;
  snapshot) date -u '+sample-rfc3339=%Y-%m-%dT%H:%M:%SZ'; snapshot; printf 'thread_count='; ps -eLf | wc -l; printf 'pid_max='; cat /proc/sys/kernel/pid_max ;;
  trend) for i in 1 2 3; do date -u '+sample-rfc3339=%Y-%m-%dT%H:%M:%SZ'; snapshot; sleep 10; done ;;
  proc_identity) proc_identity "$1" ;;
  relation) zpid=$1; zstart=$2; zns=$3; ppid=$4; pstart=$5; pns=$6; z=$(proc_identity "$zpid") || exit; p=$(proc_identity "$ppid") || exit; IFS=$'\t' read -r now_zstart now_zns now_ppid now_zcg now_zstate <<<"$z"; IFS=$'\t' read -r now_pstart now_pns now_ppid_parent now_pcg now_pstate <<<"$p"; [ "$now_zstart" = "$zstart" ] && [ "$now_zns" = "$zns" ] && [ "$now_ppid" = "$ppid" ] && [[ "$now_zstate" == Z* ]] || exit 35; [ "$now_pstart" = "$pstart" ] && [ "$now_pns" = "$pns" ] || exit 36; sed -n '/^\(Name\|State\|Pid\|PPid\|NSpid\):/p' "/proc/$zpid/status"; sed -n '/^\(Name\|State\|Pid\|PPid\|NSpid\):/p' "/proc/$ppid/status"; printf 'parent_children='; cat "/proc/$ppid/task/$ppid/children"; printf '\n' ;;
  *) exit 22 ;;
esac
REMOTE
}
```

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | bounded 세 sample에서 zombie count 또는 동일 PPID count가 계속 증가 |
| 적용 | zombie·parent의 start ticks, PID namespace, PPID 관계를 재검증할 수 있음 |
| 제외 | 단일 transient zombie, PIDPressure/fork 실패, parent `D`, runtime 오류는 각각 해당 런북으로 이동 |

검색 문자열: `Z`, `defunct`, `zombie`, `wait`, `SIGCHLD`, `PIDPressure`, `fork`.

`unset START_RFC3339 END_RFC3339 START_EPOCH END_EPOCH; TIME_READY=false; DIAG_READY=false; NORMALIZE_READY=false; START_RFC3339='PASTE_START_RFC3339_HERE'; END_RFC3339='PASTE_END_RFC3339_HERE'; RE='^[0-9]{4}-(0[1-9]|1[0-2])-([0-2][0-9]|3[01])T([01][0-9]|2[0-3]):[0-5][0-9]:[0-5][0-9]Z$'; if [ "$RELATION_READY" != true ] || [[ ! ## 진단과 판정

`DIAG_READY=false; if [ "$TIME_READY" != true ]; then printf '%s\n' '중단: TIME_READY가 아니다.' >&2; elif T="$(node_read trend)"; then DIAG_READY=true; printf '%s\n' "$T"; else printf '%s\n' '중단: trend producer 실패' >&2; fi; unset T`

`if [ "$DIAG_READY" = true ] && R="$(node_read relation "$ZOMBIE_PID" "$ZOMBIE_START_TICKS" "$ZOMBIE_NS" "$PARENT_PID" "$PARENT_START_TICKS" "$PARENT_NS")"; then printf '%s\n' "$R"; else printf '%s\n' '중단: process replacement/PPID relation/producer 실패' >&2; fi; unset R`

count가 연속 증가하고 같은 identity의 parent에 모이면 child reaping/SIGCHLD 경로를 application owner에게 이관한다. PPID 1은 해당 PID namespace에서 해석한다. parent가 `D`면 D-state 런북으로 이동한다. cgroup 문자열이나 `comm`만으로 Pod/container/runtime owner를 확정하지 않으며, Pod status의 exact containerID와 cgroup ID가 일치하는 별도 증거가 있어야 한다. 이 문서는 CRI endpoint/socket을 사용하지 않는다.

producer 실패는 진단 실패, 성공한 producer의 zombie 0은 현재 no-match, `awk` 오류는 filter 오류다. 현재 0은 과거 누적 부재를 보장하지 않는다.

`absent==1`은 0이 아니라 collector·target·label·datasource·시간 범위 문제다. query/API 오류와 no series를 구분하며 metric은 PPID를 알려 주지 않는다.

## 변경 격리와 정상화

zombie/parent `kill`, restart, Pod 삭제, pid_max/sysctl/cgroup 변경, runtime/kubelet restart, reboot를 실행하지 않는다. 별도 변경은 fresh Node·process 관계, 직접 증거, owner 승인 ID·정확한 RBAC/SSH/audit 주체, window, blast radius, PDB/quorum·Job side effect, 멱등성, 중단 조건, 검증 가능한 rollback이 있을 때만 수행한다. replacement PID/Pod는 새 identity·owner 관계를 등록하고 전체 refresh한다.

`NORMALIZE_READY=false; if [ "$DIAG_READY" != true ]; then printf '%s\n' '중단: DIAG_READY가 아니다.' >&2; elif V="$(node_read trend)"; then NORMALIZE_READY=true; printf '%s\n' "$V"; else printf '%s\n' '중단: 정상화 producer/fresh identity 실패' >&2; fi; unset V`

관찰 window에서 새 zombie 생성과 동일 PPID 누적이 멈추고 PID 자원이 안정되며, parent reaping의 owner 증거와 workload 새 UID·Ready·EndpointSlice·실제 기능/Job 결과가 정상이어야 한다. 기존 zombie 하나가 사라지거나 parent가 교체된 것만으로 정상화하지 않는다.

## 증거·한계

Node UID/RV/systemUUID, 원격 identity, canonical UTC window, sample별 count·PPID 분포, zombie/parent start ticks·namespace·관계, 최소 cgroup 식별자, PID 자원, producer/no-match/filter 결과와 기능 검증을 보존한다. argv, exe 원문, 전체 process tree, Secret·token·개인정보는 저장하지 않는다. 실제 인프라 명령은 실행하지 않았고 init/reaping, procps, namespace/runtime mapping, exporter 보존은 환경별 미검증이다.
