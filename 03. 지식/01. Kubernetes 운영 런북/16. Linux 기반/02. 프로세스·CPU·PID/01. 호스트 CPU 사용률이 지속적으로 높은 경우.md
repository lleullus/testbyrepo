# 호스트 CPU 사용률이 지속적으로 높은 경우

## 입력값과 빠른 수집

실행 경로는 `운영자 Bash -> 승인 SSH endpoint -> machine/boot -> /proc/stat·vmstat·PSI -> PID/start ticks·namespace -> cgroup CPU controller -> workload 또는 hypervisor owner`다. current snapshot은 과거 CPU peak의 증거가 아니다.

| 종류 | 값 | 등록 기준 |
|---|---|---|
| 최초 입력 | `SSH_DEST` | 자산 기록의 승인 SSH endpoint |
| host 자동값 | machine/boot, online CPU, clock, cgroup version | fresh 원격 조회 성공 후 등록 |
| 계산 후보값 | 상위 CPU PID, cgroup path, exporter query | snapshot·PID identity·label mapping 검증 전 미확정 |
| 운영자 선택값 | expected machine/boot, UTC 관측 창, `PID_INPUT`, metric instance | 자산·사건·출력 근거를 본 뒤 선택 |

```bash
unset INPUT_READY HOST_READY TIME_READY SAMPLE_READY PROCESS_READY CGROUP_READY QUERY_READY EVIDENCE_READY MUTATION_READY ROLLBACK_READY NORMALIZATION_READY MACHINE_ID BOOT_ID ONLINE_CPUS CGROUP_VERSION START_RFC3339 END_RFC3339 PID_VALUE PID_START PID_COMM PID_CGROUP PID_PIDNS PID_MNTNS PID_NETNS CGROUP_CPU_PATH

printf 'INPUT_READY=%s ssh=%s\n' "$INPUT_READY" "$SSH_DEST"
```

### host·time refresh

refresh는 host/process/cgroup/query/evidence와 변경·rollback·normalization 상태를 먼저 폐기한다. machine/boot가 바뀌거나 조회가 실패하면 과거 sample·PID·cgroup을 재사용하지 않는다.

```bash
refresh_cpu_host() {
  local out s e se ee
  unset HOST_READY TIME_READY SAMPLE_READY PROCESS_READY CGROUP_READY QUERY_READY EVIDENCE_READY MUTATION_READY ROLLBACK_READY NORMALIZATION_READY MACHINE_ID BOOT_ID ONLINE_CPUS CGROUP_VERSION START_RFC3339 END_RFC3339 START_EPOCH END_EPOCH PID_VALUE PID_START PID_COMM PID_CGROUP PID_PIDNS PID_MNTNS PID_NETNS CGROUP_CPU_PATH
  HOST_READY=false; TIME_READY=false; SAMPLE_READY=false; PROCESS_READY=false; CGROUP_READY=false; QUERY_READY=false; EVIDENCE_READY=false; MUTATION_READY=false; ROLLBACK_READY=false; NORMALIZATION_READY=false
  [[ "$INPUT_READY" == true && "$EXPECTED_MACHINE_ID_INPUT" =~ ^[0-9a-fA-F]{32}$ && "$EXPECTED_BOOT_ID_INPUT" =~ ^[0-9a-fA-F]{8}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{12}$ ]] || { printf '%s\n' '중단: input/machine/boot gate 실패' >&2; return 1; }
  [[ "$START_INPUT" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ && "$END_INPUT" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] || return 1
  s=$(date -u -d "$START_INPUT" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null) && e=$(date -u -d "$END_INPUT" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null) && [[ "$s" == "$START_INPUT" && "$e" == "$END_INPUT" ]] || { printf '%s\n' '중단: UTC round-trip 실패' >&2; return 1; }
  se=$(date -u -d "$s" +%s) && ee=$(date -u -d "$e" +%s) && (( se < ee && ee <= $(date -u +%s) && ee - se <= 86400 )) || { printf '%s\n' '중단: start<end/future/24h 범위 실패' >&2; return 1; }
  out=$(ssh -- "$SSH_DEST" bash -s -- "$EXPECTED_MACHINE_ID_INPUT" "$EXPECTED_BOOT_ID_INPUT" <<'REMOTE'
set -eu
expected_machine=$1; expected_boot=$2
test "$(tr -d '\n' </etc/machine-id)" = "$expected_machine"; test "$(tr -d '\n' </proc/sys/kernel/random/boot_id)" = "$expected_boot"
for tool in vmstat ps sed grep mktemp; do command -v "$tool" >/dev/null || { printf 'missing-tool=%s\n' "$tool" >&2; exit 12; }; done
test -r /proc/stat; test -r /proc/loadavg; test -r /proc/pressure/cpu
printf 'machine-id=%s\nboot-id=%s\nonline-cpus=%s\n' "$expected_machine" "$expected_boot" "$(getconf _NPROCESSORS_ONLN)"
if test -f /sys/fs/cgroup/cgroup.controllers; then printf '%s\n' 'cgroup-version=2'; else printf '%s\n' 'cgroup-version=1'; fi
timedatectl show -p Timezone -p NTPSynchronized -p LocalRTC
REMOTE
  ) || { printf '%s\n' 'producer 실패: SSH/host/proc/tool 조회' >&2; return 1; }
  grep -Fxq "machine-id=$EXPECTED_MACHINE_ID_INPUT" <<<"$out" && grep -Fxq "boot-id=$EXPECTED_BOOT_ID_INPUT" <<<"$out" || { printf '%s\n' 'no match: current host identity 불일치' >&2; return 1; }
  MACHINE_ID=$EXPECTED_MACHINE_ID_INPUT; BOOT_ID=$EXPECTED_BOOT_ID_INPUT; ONLINE_CPUS=$(sed -n 's/^online-cpus=//p' <<<"$out"); CGROUP_VERSION=$(sed -n 's/^cgroup-version=//p' <<<"$out"); START_RFC3339=$s; END_RFC3339=$e; START_EPOCH=$se; END_EPOCH=$ee
  [[ "$ONLINE_CPUS" =~ ^[1-9][0-9]*$ && "$CGROUP_VERSION" =~ ^[12]$ ]] || { unset MACHINE_ID BOOT_ID ONLINE_CPUS CGROUP_VERSION START_RFC3339 END_RFC3339 START_EPOCH END_EPOCH; printf '%s\n' 'filter 오류: host 자동값 누락' >&2; return 1; }
  HOST_READY=true; TIME_READY=true
  printf 'HOST_READY=true TIME_READY=true machine=%s boot=%s cpus=%s cgroup=v%s start=%s end=%s\n' "$MACHINE_ID" "$BOOT_ID" "$ONLINE_CPUS" "$CGROUP_VERSION" "$START_RFC3339" "$END_RFC3339"
  printf '%s\n' "$out"
}
```

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | 같은 host에서 CPU busy 또는 `vmstat`의 `us`·`sy`가 관측 창 동안 높게 유지됨 |
| 적용 | host CPU, run queue, iowait, steal, PSI와 확인된 cgroup throttling을 분리해야 함 |
| 제외 | load가 높지만 CPU가 낮으면 [[02. CPU 사용률은 낮지만 load average가 높은 경우]], memory·disk·PID pressure는 해당 전용 런북으로 이동 |

검색 문자열: `vmstat`, `us`, `sy`, `id`, `wa`, `st`, `run queue`, `nr_throttled`, `throttled_usec`, `CPU pressure`, `load average`.

CPU 사용률만으로 특정 process, container, resource limit 또는 host 장애를 확정하지 않는다.

## host bounded sample

먼저 `refresh_cpu_host`를 실행한다. 명령은 remote machine/boot를 직접 재검사하고 각 producer 결과를 분리한다. `vmstat 1 6`의 첫 행은 boot 평균이므로 뒤 5개 interval을 판단에 사용한다.

```bash
SAMPLE_READY=false; if [[ "$HOST_READY" == true && "$TIME_READY" == true ]]; then if ssh -- "$SSH_DEST" bash -s -- "$MACHINE_ID" "$BOOT_ID" <<'REMOTE'
set -u
expected_machine=$1; expected_boot=$2
[[ "$(tr -d '\n' </etc/machine-id)" == "$expected_machine" && "$(tr -d '\n' </proc/sys/kernel/random/boot_id)" == "$expected_boot" ]] || exit 10
printf 'sample-start=%s\n' "$(date -u '+%Y-%m-%dT%H:%M:%SZ')"
vmstat 1 6; vmstat_rc=$?; printf 'vmstat_rc=%s\n' "$vmstat_rc"; (( vmstat_rc == 0 )) || exit 20
cat /proc/loadavg; load_rc=$?; printf 'load_rc=%s\n' "$load_rc"; (( load_rc == 0 )) || exit 21
cat /proc/pressure/cpu; cpu_psi_rc=$?; printf 'cpu_psi_rc=%s\n' "$cpu_psi_rc"; (( cpu_psi_rc == 0 )) || exit 22
if test -r /proc/pressure/io; then cat /proc/pressure/io; io_psi_rc=$?; printf 'io_psi_rc=%s\n' "$io_psi_rc"; (( io_psi_rc == 0 )) || exit 23; else printf '%s\n' 'unsupported: io PSI unavailable'; fi
printf 'sample-end=%s\n' "$(date -u '+%Y-%m-%dT%H:%M:%SZ')"
REMOTE
then SAMPLE_READY=true; else printf '중단: host sample 실패 rc=%s\n' "$?" >&2; fi; else printf '%s\n' '중단: fresh host/time READY가 아니다.' >&2; fi; printf 'SAMPLE_READY=%s\n' "$SAMPLE_READY"
```

## 관측별 진단 경로

| 지금 보이는 것 | 먼저 볼 것 | 그다음 어디를 볼지 | 상세 절 |
|---|---|---|---|
| `us`·`sy`, `r`이 높고 `id`가 낮음 | 5개 interval의 지속성·CPU PSI | process identity·cgroup | [[#상위 process와 identity]] |
| `wa` 또는 `b`·I/O PSI가 높고 `id`가 남음 | exact device await/util | filesystem/storage owner | [[#iowait·steal 경계]] |
| `st`가 높음 | 동일 창의 guest steal과 provider evidence | VM/provider owner | [[#iowait·steal 경계]] |
| host 여유가 있으나 cgroup throttle delta 증가 | PID/cgroup identity와 `cpu.stat` | workload resource owner | [[#cgroup throttling]] |
| load만 높고 CPU가 낮음 | runnable과 blocked task 분리 | load-only 런북 | [[02. CPU 사용률은 낮지만 load average가 높은 경우]] |

### 상위 process와 identity

`SAMPLE_READY=true`이고 host CPU 실행 경쟁이 확인됐을 때만 상위 process 후보를 본다. argv·environment는 출력하지 않는다.

```bash
if [[ "$SAMPLE_READY" == true ]]; then ssh -- "$SSH_DEST" bash -s -- "$MACHINE_ID" "$BOOT_ID" <<'REMOTE'
set -u
expected_machine=$1; expected_boot=$2
[[ "$(tr -d '\n' </etc/machine-id)" == "$expected_machine" && "$(tr -d '\n' </proc/sys/kernel/random/boot_id)" == "$expected_boot" ]] || exit 10
tmp=$(mktemp) || exit 12; trap 'rm -f "$tmp"' EXIT
ps -e -o pid=,ppid=,psr=,pcpu=,stat=,comm= --sort=-pcpu >"$tmp"; producer_rc=$?; printf 'producer_rc=%s\n' "$producer_rc"; (( producer_rc == 0 )) || exit 20
sed -n '1,20p' "$tmp"; filter_rc=$?; printf 'filter_rc=%s\n' "$filter_rc"; (( filter_rc == 0 )) || exit 31
REMOTE
else printf '%s\n' '중단: SAMPLE_READY가 아니다.' >&2; fi
```

`PID`, `PPID`, processor, CPU%, state, comm은 현재 snapshot이며 과거 peak나 workload 소속을 증명하지 않는다. 확인할 PID를 한 번 선택한다.

```bash
PID_INPUT='PASTE_CONFIRMED_HIGH_CPU_PID_HERE'
```

```bash
refresh_cpu_process() {
  local out
  unset PROCESS_READY CGROUP_READY EVIDENCE_READY MUTATION_READY ROLLBACK_READY NORMALIZATION_READY PID_VALUE PID_START PID_COMM PID_CGROUP PID_PIDNS PID_MNTNS PID_NETNS CGROUP_CPU_PATH
  PROCESS_READY=false; CGROUP_READY=false; EVIDENCE_READY=false; MUTATION_READY=false; ROLLBACK_READY=false; NORMALIZATION_READY=false
  [[ "$SAMPLE_READY" == true && "$PID_INPUT" =~ ^[1-9][0-9]*$ ]] || { printf '%s\n' '중단: sample/PID gate 실패' >&2; return 1; }
  out=$(ssh -- "$SSH_DEST" bash -s -- "$MACHINE_ID" "$BOOT_ID" "$PID_INPUT" <<'REMOTE'
set -eu
expected_machine=$1; expected_boot=$2; pid=$3
test "$(tr -d '\n' </etc/machine-id)" = "$expected_machine"; test "$(tr -d '\n' </proc/sys/kernel/random/boot_id)" = "$expected_boot"; test -r "/proc/$pid/stat"; test -r "/proc/$pid/cgroup"
stat=$(cat "/proc/$pid/stat")
rest=${stat##*) }
printf 'pid=%s\nstart=%s\nstate=%s\ncomm=%s\npidns=%s\nmntns=%s\nnetns=%s\n' "$pid" "$(cut -d' ' -f20 <<<"$rest")" "${rest%% *}" "$(cat "/proc/$pid/comm")" "$(readlink "/proc/$pid/ns/pid")" "$(readlink "/proc/$pid/ns/mnt")" "$(readlink "/proc/$pid/ns/net")"
sed 's/^/cgroup=/' "/proc/$pid/cgroup"
REMOTE
  ) || { printf '%s\n' 'producer 실패: current PID identity 조회' >&2; return 1; }
  grep -Fxq "pid=$PID_INPUT" <<<"$out" || { printf '%s\n' 'no match: PID identity 불일치' >&2; return 1; }
  PID_VALUE=$PID_INPUT; PID_START=$(sed -n 's/^start=//p' <<<"$out"); PID_COMM=$(sed -n 's/^comm=//p' <<<"$out"); PID_PIDNS=$(sed -n 's/^pidns=//p' <<<"$out"); PID_MNTNS=$(sed -n 's/^mntns=//p' <<<"$out"); PID_NETNS=$(sed -n 's/^netns=//p' <<<"$out"); PID_CGROUP=$(sed -n 's/^cgroup=//p' <<<"$out")
  [[ "$PID_START" =~ ^[0-9]+$ && -n "$PID_PIDNS" && -n "$PID_MNTNS" && -n "$PID_NETNS" && -n "$PID_CGROUP" ]] || { printf '%s\n' 'filter 오류: process identity 누락' >&2; return 1; }
  PROCESS_READY=true; printf 'PROCESS_READY=true pid=%s start_ticks=%s comm=%s pidns=%s mntns=%s netns=%s\n%s\n' "$PID_VALUE" "$PID_START" "$PID_COMM" "$PID_PIDNS" "$PID_MNTNS" "$PID_NETNS" "$out"
}
```

PID가 재사용될 수 있으므로 모든 후속 process/cgroup 명령은 PID와 start ticks를 같이 검사한다. process가 사라지거나 start ticks가 바뀌면 원인 해소가 아니라 stale evidence 폐기다.

### iowait·steal 경계

`wa`/I/O PSI가 같은 sample에서 높을 때만 `iostat`을 사용한다. 미설치는 원인이 아니다.

```bash
if [[ "$SAMPLE_READY" == true ]]; then ssh -- "$SSH_DEST" bash -s -- "$MACHINE_ID" "$BOOT_ID" <<'REMOTE'
set -u
expected_machine=$1; expected_boot=$2
[[ "$(tr -d '\n' </etc/machine-id)" == "$expected_machine" && "$(tr -d '\n' </proc/sys/kernel/random/boot_id)" == "$expected_boot" ]] || exit 10
if command -v iostat >/dev/null; then iostat -xz 1 3; rc=$?; printf 'iostat_rc=%s\n' "$rc"; exit "$rc"; else printf '%s\n' 'unsupported: iostat unavailable'; exit 40; fi
REMOTE
else printf '%s\n' '중단: SAMPLE_READY가 아니다.' >&2; fi
```

`await`·queue·util이 높은 actual device를 mount namespace의 source/filesystem/major:minor와 연결하기 전에는 disk/PVC 원인으로 확정하지 않는다. `st`는 guest가 실행되지 못한 시간이며 동일 관측 창의 provider 자료 없이 hypervisor 장애를 확정하지 않는다.

### cgroup throttling

먼저 `refresh_cpu_process`를 실행한다. 다음 명령은 current PID/start identity에서 kernel이 보고한 cgroup 경로만 사용한다. 추정한 Pod/container 경로는 금지한다.

```bash
CGROUP_READY=false; if [[ "$PROCESS_READY" == true ]]; then if ssh -- "$SSH_DEST" bash -s -- "$MACHINE_ID" "$BOOT_ID" "$PID_VALUE" "$PID_START" "$CGROUP_VERSION" <<'REMOTE'
set -eu
expected_machine=$1; expected_boot=$2; pid=$3; expected_start=$4; version=$5
test "$(tr -d '\n' </etc/machine-id)" = "$expected_machine"; test "$(tr -d '\n' </proc/sys/kernel/random/boot_id)" = "$expected_boot"; test -r "/proc/$pid/stat"; stat=$(cat "/proc/$pid/stat"); rest=${stat##*) }; test "$(cut -d' ' -f20 <<<"$rest")" = "$expected_start"
if [[ "$version" == 2 ]]; then rel=$(sed -n 's/^0:://p' "/proc/$pid/cgroup"); test -n "$rel"; base="/sys/fs/cgroup$rel"; test -r "$base/cpu.stat"; printf 'cgroup-path=%s\n' "$base"; for i in 1 2 3; do date -u '+sample=%Y-%m-%dT%H:%M:%SZ'; cat "$base/cpu.stat"; test -r "$base/cpu.max" && { printf 'cpu.max='; cat "$base/cpu.max"; }; sleep 1; done; else rels=$(sed -n 's/^[0-9]*:cpu,cpuacct://p; s/^[0-9]*:cpu://p' "/proc/$pid/cgroup"); sed_rc=$?; (( sed_rc == 0 )) || exit 31; rel=${rels%%$'\n'*}; test -n "$rel"; base="/sys/fs/cgroup/cpu$rel"; test -r "$base/cpu.stat"; printf 'cgroup-path=%s\n' "$base"; for i in 1 2 3; do date -u '+sample=%Y-%m-%dT%H:%M:%SZ'; cat "$base/cpu.stat"; test -r "$base/cpu.cfs_quota_us" && { printf 'quota='; cat "$base/cpu.cfs_quota_us"; }; test -r "$base/cpu.cfs_period_us" && { printf 'period='; cat "$base/cpu.cfs_period_us"; }; sleep 1; done; fi
REMOTE
then CGROUP_READY=true; else printf '중단: cgroup identity/sample 실패 rc=%s\n' "$?" >&2; fi; else printf '%s\n' '중단: PROCESS_READY가 아니다.' >&2; fi; printf 'CGROUP_READY=%s\n' "$CGROUP_READY"
```

누적 `nr_throttled`, `throttled_usec`/`throttled_time`은 세 sample 사이 delta로 판단한다. 과거 누적값이 0보다 크다는 이유만으로 현재 throttling을 확정하지 않는다. host CPU가 낮고 이 delta만 증가하면 host saturation으로 확대하지 않는다. process가 container에 속한 것이 확인된 경우에만 workload owner가 current container ID·Pod UID와 cgroup을 연결한다. active kubelet CRI endpoint나 runtime provider를 추측해 `crictl`을 실행하지 않는다.

## Prometheus query 생성

metric이 실제로 있고 exporter `instance`가 현재 machine 자산과 연결될 때만 사용한다. instance를 label browser에서 확인해 한 번 등록한다.

```bash
METRIC_INSTANCE_INPUT='PASTE_CONFIRMED_EXPORTER_INSTANCE_HERE'
QUERY_READY=false
if [[ "$HOST_READY" == true && "$METRIC_INSTANCE_INPUT" =~ ^[A-Za-z0-9_.:-]+$ ]]; then QUERY_READY=true; printf 'QUERY_READY=true instance=%s machine=%s\n' "$METRIC_INSTANCE_INPUT" "$MACHINE_ID"; fi
```

```bash
if [[ "$QUERY_READY" == true ]] && ssh -- "$SSH_DEST" bash -s -- "$MACHINE_ID" "$BOOT_ID" <<'REMOTE'
set -eu
test "$(tr -d '\n' </etc/machine-id)" = "$1"; test "$(tr -d '\n' </proc/sys/kernel/random/boot_id)" = "$2"
REMOTE
then esc=${METRIC_INSTANCE_INPUT//\\/\\\\}; esc=${esc//\"/\\\"}; printf '100*(1-avg by(instance)(rate(node_cpu_seconds_total{instance="%s",mode="idle"}[5m])))\n' "$esc"; printf 'avg by(instance)(rate(node_cpu_seconds_total{instance="%s",mode="steal"}[5m]))*100\n' "$esc"; printf 'node_load1{instance="%s"}/count without(cpu,mode)(node_cpu_seconds_total{instance="%s",mode="idle"})\n' "$esc" "$esc"; else printf '%s\n' '중단: QUERY_READY 또는 current host identity 실패' >&2; fi
```

출력된 완성 PromQL만 UI에 붙여 넣고 조회 시간은 `START_RFC3339..END_RFC3339`로 설정한다. 빈 결과는 정상·0이 아니라 metric 미수집, label/cluster/time 오류 또는 stale series 후보다. PromQL은 process나 cgroup owner를 증명하지 않는다.

## 변경 경계와 정상화

이 문서는 읽기 전용이다. `renice`, `taskset`, `kill`, service restart, sysctl/cgroup quota 변경, workload resource 변경, cordon/drain/reboot를 실행하지 않는다. 별도 변경은 실행 직전 host와 해당 process/cgroup identity를 refresh하고 직접 원인 evidence, 승인 ID·창, 가용 capacity·quorum, 외부 side effect·멱등성, 중단 조건과 rollback 원본을 확인해야 한다. replacement process/cgroup은 새 PID/start ticks/path로 등록한다.

새 canonical 관찰 창에서 refresh와 host sample을 다시 실행한다. 원인 경로에 따라 `us/sy/r`, `wa`·I/O PSI, `st`, cgroup throttle delta가 안정되고 새 pressure/timeout이 없어야 한다. 이어 실제 client 요청·처리량·queue/Job 산출물과 가용성 목표가 유지돼야 한다. 한 번의 낮은 CPU, process 소멸 또는 빈 metric은 정상화가 아니다.
