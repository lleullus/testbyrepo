# 프로세스가 예상하지 않은 signal로 종료된 경우

## 입력값과 빠른 수집

연결 경로는 `작업 PC 또는 bastion의 Bash → kubectl → API server → Node 객체`와 `같은 작업 host의 ssh → 승인된 endpoint → systemUUID가 일치하는 Linux host → systemd unit identity → bounded unit·kernel journal`이다. 종료 후 PID는 사라지거나 재사용될 수 있으므로 PID 숫자, `128+signal`, 현재 `MainPID` 중 하나만으로 과거 종료 주체를 확정하지 않는다.

| 종류 | 변수 | 등록 계약 |
|---|---|---|
| 최초 입력 | `NODE`, `HOST` | 승인된 exact Node 이름과 옵션 형태가 아닌 SSH endpoint |
| API 확인 자동값 | `NODE_UID`, `NODE_RV`, `NODE_SYSTEM_UUID` | Node API 성공 후 원격 DMI UUID와 일치할 때만 등록 |
| 운영자 선택값 | `UNIT`, `INCIDENT_PID`, `START_RFC3339`, `END_RFC3339` | 직접 종료 증거에서 확인한 unit·PID·UTC 사건 창 |
| systemd 자동값 | `UNIT_FRAGMENT`, `UNIT_MAINPID`, `UNIT_INVOCATION_ID` | 현재 unit identity를 등록하며 과거 사건 identity로 간주하지 않음 |
| 정상화 선택값 | `VERIFY_START_RFC3339`, `VERIFY_END_RFC3339` | 조치 이후 재발을 확인할 별도 UTC 관찰 창 |

### 1. Bash·도구·Node identity

`TOOLS_READY=false; MISSING=''; for TOOL in kubectl jq ssh date sed grep; do command -v "$TOOL" >/dev/null 2>&1 || MISSING="$MISSING $TOOL"; done; if [ -n "${BASH_VERSION:-}" ] && [ -z "$MISSING" ]; then TOOLS_READY=true; printf 'TOOLS_READY=true bash=%s\n' "$BASH_VERSION"; else printf '중단: Bash 또는 도구 없음:%s\n' "$MISSING" >&2; fi`

### 2. 매 호출 fresh gate와 제한 원격 함수

`fresh_node`는 후속 API·journal·정상화 직전에 Node UID와 resourceVersion을 다시 확인한다. `node_read`는 허용한 읽기 전용 operation과 positional argument만 원격 Bash에 전달하며 `eval`과 문자열 명령 조립을 사용하지 않는다.

```bash
fresh_node() {
  local j u r
  [ "$INPUT_READY" = true ] || { printf '%s\n' '중단: INPUT_READY가 아니다.' >&2; return 1; }
  j="$(kubectl get node "$NODE" -o json)" || { printf '%s\n' '중단: Node fresh 조회 실패' >&2; return 1; }
  u="$(jq -r '.metadata.uid // empty' <<<"$j")"
  r="$(jq -r '.metadata.resourceVersion // empty' <<<"$j")"
  [ "$u" = "$NODE_UID" ] && [ "$r" = "$NODE_RV" ] || { printf '중단: Node identity/lifecycle 변경 uid=%s rv=%s\n' "$u" "$r" >&2; return 1; }
}
node_read() {
  local op="$1"
  shift
  fresh_node || return 1
  ssh -- "$HOST" bash -s -- "$NODE_SYSTEM_UUID" "$op" "$@" <<'REMOTE'
set -o pipefail
expected=$1
op=$2
shift 2
actual=$(tr '[:upper:]' '[:lower:]' </sys/class/dmi/id/product_uuid 2>/dev/null | tr -d '-') || exit 20
expected=$(printf '%s' "$expected" | tr '[:upper:]' '[:lower:]' | tr -d '-')
[ -n "$actual" ] && [ "$actual" = "$expected" ] || { printf '%s\n' '중단: 원격 host system UUID 불일치' >&2; exit 21; }
unit_identity() {
  unit=$1
  [[ "$unit" =~ ^[A-Za-z0-9_.@-]+\.service$ ]] || exit 30
  data=$(systemctl show "$unit" -p Id -p LoadState -p FragmentPath -p MainPID -p InvocationID -p ActiveState -p SubState -p Result -p ExecMainCode -p ExecMainStatus -p ExecMainExitTimestamp) || exit 31
  id=$(sed -n 's/^Id=//p' <<<"$data")
  load=$(sed -n 's/^LoadState=//p' <<<"$data")
  fragment=$(sed -n 's/^FragmentPath=//p' <<<"$data")
  mainpid=$(sed -n 's/^MainPID=//p' <<<"$data")
  invocation=$(sed -n 's/^InvocationID=//p' <<<"$data")
  [ -n "$invocation" ] || invocation=-
  [ "$id" = "$unit" ] && [ "$load" = loaded ] && [[ "$fragment" = /* ]] && [ -f "$fragment" ] && [ -r "$fragment" ] && [[ "$mainpid" =~ ^[0-9]+$ ]] && { [ "$invocation" = - ] || [[ "$invocation" =~ ^[0-9a-fA-F]{32}$ ]]; } || exit 32
  printf 'Id=%s\nLoadState=%s\nFragmentPath=%s\nMainPID=%s\nInvocationID=%s\n' "$id" "$load" "$fragment" "$mainpid" "$invocation"
  printf '%s\n' "$data" | grep -E '^(ActiveState|SubState|Result|ExecMainCode|ExecMainStatus|ExecMainExitTimestamp)='
}
check_unit() {
  unit=$1; expected_fragment=$2; expected_mainpid=$3; expected_invocation=$4
  data=$(unit_identity "$unit") || exit
  [ "$(sed -n 's/^FragmentPath=//p' <<<"$data")" = "$expected_fragment" ] && [ "$(sed -n 's/^MainPID=//p' <<<"$data")" = "$expected_mainpid" ] && [ "$(sed -n 's/^InvocationID=//p' <<<"$data")" = "$expected_invocation" ] || exit 33
}
case "$op" in
  identity) printf 'hostname=%s\nsystem_uuid=%s\n' "$(hostname --fqdn 2>/dev/null || hostname)" "$actual" ;;
  service_identity) unit_identity "$1" ;;
  pid_snapshot) pid=$1; [[ "$pid" =~ ^[1-9][0-9]*$ ]] || exit 40; if [ ! -r "/proc/$pid/stat" ]; then printf 'pid_present=false pid=%s\n' "$pid"; else stat=$(cat "/proc/$pid/stat") || exit 41; rest=${stat##*) }; set -- $rest; printf 'pid_present=true pid=%s start_ticks=%s state=%s pid_ns=%s ppid=%s\n' "$pid" "${20}" "$1" "$(readlink "/proc/$pid/ns/pid")" "$(sed -n 's/^PPid:[[:space:]]*//p' "/proc/$pid/status")"; ps -p "$pid" -o pid=,ppid=,stat=,lstart=,etimes=,comm=; fi ;;
  unit_journal) unit=$1; fragment=$2; mainpid=$3; invocation=$4; start=$5; end=$6; pid=$7; check_unit "$unit" "$fragment" "$mainpid" "$invocation"; journalctl -u "$unit" --since "$start" --until "$end" --no-pager | grep -E -i -C 3 "(^|[^0-9])${pid}([^0-9]|$)|Main process exited|code=(killed|exited)|status=|signal|Stopping|Stopped|restart|timeout|watchdog|shutdown|fatal|panic|failed"; status=("${PIPESTATUS[@]}"); [ "${status[0]}" -eq 0 ] || exit "${status[0]}"; [ "${status[1]}" -eq 0 ] || [ "${status[1]}" -eq 1 ] || exit "${status[1]}" ;;
  kernel_journal) start=$1; end=$2; pid=$3; journalctl -k --since "$start" --until "$end" --no-pager | grep -E -i -C 3 "oom-kill|out of memory|invoked oom-killer|Killed process[[:space:]]+${pid}([^0-9]|$)|segfault|general protection|watchdog"; status=("${PIPESTATUS[@]}"); [ "${status[0]}" -eq 0 ] || exit "${status[0]}"; [ "${status[1]}" -eq 0 ] || [ "${status[1]}" -eq 1 ] || exit "${status[1]}" ;;
  *) printf '중단: 허용되지 않은 operation=%s\n' "$op" >&2; exit 22 ;;
esac
REMOTE
}
```

원격 identity 조회 전에는 이전 unit·시간·증거·정상화 gate를 폐기한다.

`unset REMOTE_HOSTNAME REMOTE_SYSTEM_UUID UNIT UNIT_FRAGMENT UNIT_MAINPID UNIT_INVOCATION_ID UNIT_ACTIVE_STATE UNIT_SUB_STATE UNIT_RESULT UNIT_EXEC_CODE UNIT_EXEC_STATUS UNIT_EXIT_TIMESTAMP FUNCTION_EVIDENCE_ID; REMOTE_READY=false; SERVICE_READY=false; TIME_READY=false; DIAG_READY=false; VERIFY_TIME_READY=false; NORMALIZATION_EVIDENCE_READY=false; NORMALIZE_READY=false; if O="$(node_read identity)"; then REMOTE_HOSTNAME="$(sed -n 's/^hostname=//p' <<<"$O")"; REMOTE_SYSTEM_UUID="$(sed -n 's/^system_uuid=//p' <<<"$O")"; if [ -n "$REMOTE_HOSTNAME" ] && [ -n "$REMOTE_SYSTEM_UUID" ]; then REMOTE_READY=true; export REMOTE_HOSTNAME REMOTE_SYSTEM_UUID; printf 'REMOTE_READY=true hostname=%s systemUUID=%s\n' "$REMOTE_HOSTNAME" "$REMOTE_SYSTEM_UUID"; else printf '%s\n' '중단: 원격 identity 출력 불완전' >&2; fi; else printf '%s\n' '중단: SSH 또는 원격 identity 검증 실패' >&2; fi; unset O`

### 3. unit·사건 PID 등록

`UNIT`은 실제 systemd service 이름이고 `INCIDENT_PID`는 종료 기록에 나온 PID다. 현재 `MainPID`는 사건 PID와 다를 수 있으며 같더라도 시작 시각 없이 같은 process라고 확정하지 않는다. transient·generated unit처럼 읽을 수 있는 regular `FragmentPath`가 없으면 자동 등록을 중단하고 service manager owner에게 해당 unit의 identity 계약을 요청한다.

```bash
register_service() {
  local data
  unset UNIT_FRAGMENT UNIT_MAINPID UNIT_INVOCATION_ID UNIT_ACTIVE_STATE UNIT_SUB_STATE UNIT_RESULT UNIT_EXEC_CODE UNIT_EXEC_STATUS UNIT_EXIT_TIMESTAMP START_RFC3339 END_RFC3339 START_EPOCH END_EPOCH VERIFY_START_RFC3339 VERIFY_END_RFC3339 VERIFY_START_EPOCH VERIFY_END_EPOCH
  unset FUNCTION_EVIDENCE_ID
  SERVICE_READY=false; TIME_READY=false; DIAG_READY=false; VERIFY_TIME_READY=false; NORMALIZATION_EVIDENCE_READY=false; NORMALIZE_READY=false
  [ "$REMOTE_READY" = true ] || { printf '%s\n' '중단: REMOTE_READY가 아니다.' >&2; return 1; }
  [[ "$UNIT" =~ ^[A-Za-z0-9_.@-]+\.service$ ]] && [[ "$INCIDENT_PID" =~ ^[1-9][0-9]*$ ]] || { printf '%s\n' '중단: UNIT 또는 INCIDENT_PID 형식 오류' >&2; return 1; }
  data="$(node_read service_identity "$UNIT")" || { printf '%s\n' '중단: current service identity 조회 실패' >&2; return 1; }
  UNIT_FRAGMENT="$(sed -n 's/^FragmentPath=//p' <<<"$data")"
  UNIT_MAINPID="$(sed -n 's/^MainPID=//p' <<<"$data")"
  UNIT_INVOCATION_ID="$(sed -n 's/^InvocationID=//p' <<<"$data")"
  UNIT_ACTIVE_STATE="$(sed -n 's/^ActiveState=//p' <<<"$data")"
  UNIT_SUB_STATE="$(sed -n 's/^SubState=//p' <<<"$data")"
  UNIT_RESULT="$(sed -n 's/^Result=//p' <<<"$data")"
  UNIT_EXEC_CODE="$(sed -n 's/^ExecMainCode=//p' <<<"$data")"
  UNIT_EXEC_STATUS="$(sed -n 's/^ExecMainStatus=//p' <<<"$data")"
  UNIT_EXIT_TIMESTAMP="$(sed -n 's/^ExecMainExitTimestamp=//p' <<<"$data")"
  if [ -n "$UNIT_FRAGMENT" ] && [[ "$UNIT_MAINPID" =~ ^[0-9]+$ ]] && { [ "$UNIT_INVOCATION_ID" = - ] || [[ "$UNIT_INVOCATION_ID" =~ ^[0-9a-fA-F]{32}$ ]]; }; then SERVICE_READY=true; export UNIT INCIDENT_PID UNIT_FRAGMENT UNIT_MAINPID UNIT_INVOCATION_ID UNIT_ACTIVE_STATE UNIT_SUB_STATE UNIT_RESULT UNIT_EXEC_CODE UNIT_EXEC_STATUS UNIT_EXIT_TIMESTAMP; printf 'SERVICE_READY=true\nunit=%s\nincident_pid=%s\ncurrent_fragment=%s\ncurrent_mainpid=%s\ncurrent_invocation=%s\ncurrent_state=%s/%s\ncurrent_result=%s exec=%s/%s exit=%s\n' "$UNIT" "$INCIDENT_PID" "$UNIT_FRAGMENT" "$UNIT_MAINPID" "$UNIT_INVOCATION_ID" "$UNIT_ACTIVE_STATE" "$UNIT_SUB_STATE" "$UNIT_RESULT" "$UNIT_EXEC_CODE" "$UNIT_EXEC_STATUS" "$UNIT_EXIT_TIMESTAMP"; else printf '%s\n' '중단: service identity 불완전' >&2; fi
}
```

`UNIT='PASTE_SYSTEMD_UNIT_HERE'; INCIDENT_PID='PASTE_INCIDENT_PID_HERE'; register_service`

service가 재시작되거나 unit 파일이 바뀌면 `register_service`를 다시 실행하고 이후 수집 전체를 새 identity로 반복한다. 이때 과거 사건 PID를 현재 process PID로 바꾸지 않는다.

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | service process가 정상 exit가 아닌 signal 형태로 종료됐고 unit·kernel·변경 기록을 분리해야 하는 경우 |
| 적용 | Node/host identity, exact unit, incident PID와 bounded UTC 사건 창이 있고 systemd·journald를 사용할 수 있는 경우 |
| 제외 | container 종료가 최초 증상이면 Pod UID·owner·container kind/name/current containerID·node를 등록한 뒤 [[00. Kubernetes 운영 런북 허브#카테고리\|워크로드/Pod]]로 이동한다. `OOMKilled`는 [[11. Pod STATUS가 OOMKilled인 경우]], `Evicted`는 [[12. Pod STATUS가 Evicted인 경우]]로 이관한다. |

검색 문자열: `SIGTERM`, `SIGKILL`, `code=killed`, `status=`, `Main process exited`, `oom-kill`, `Killed process`, `Stopping`, `watchdog`, `segfault`.

`ExecMainCode=killed`와 `ExecMainStatus`는 signal 종료 형태를 지지하지만 발신자를 증명하지 않는다. `137`·`143`도 각각 SIGKILL·SIGTERM과 수치가 맞을 뿐 kernel OOM·operator·service manager 중 어느 경로인지 확정하지 않는다.

## 사건 시간 창 등록

UTC `Z` 형식만 허용하고 GNU `date` 결과가 입력과 정확히 round-trip하며 시작이 종료보다 앞설 때만 등록한다.

`unset START_RFC3339 END_RFC3339 START_EPOCH END_EPOCH FUNCTION_EVIDENCE_ID; TIME_READY=false; DIAG_READY=false; VERIFY_TIME_READY=false; NORMALIZATION_EVIDENCE_READY=false; NORMALIZE_READY=false; START_RFC3339='PASTE_START_RFC3339_HERE'; END_RFC3339='PASTE_END_RFC3339_HERE'; RE='^[0-9]{4}-(0[1-9]|1[0-2])-([0-2][0-9]|3[01])T([01][0-9]|2[0-3]):[0-5][0-9]:[0-5][0-9]Z$'; if [ "$SERVICE_READY" != true ] || [[ ! "$START_RFC3339" =~ $RE ]] || [[ ! "$END_RFC3339" =~ $RE ]]; then printf '%s\n' '중단: service 또는 canonical UTC RFC3339 gate 실패' >&2; elif [ "$(date -u -d "$START_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" != "$START_RFC3339" ] || [ "$(date -u -d "$END_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" != "$END_RFC3339" ]; then printf '%s\n' '중단: RFC3339 date round-trip 실패' >&2; else START_EPOCH="$(date -u -d "$START_RFC3339" +%s)"; END_EPOCH="$(date -u -d "$END_RFC3339" +%s)"; if [ "$START_EPOCH" -lt "$END_EPOCH" ]; then TIME_READY=true; export START_RFC3339 END_RFC3339 START_EPOCH END_EPOCH; printf 'TIME_READY=true start=%s end=%s duration_seconds=%s\n' "$START_RFC3339" "$END_RFC3339" "$((END_EPOCH-START_EPOCH))"; else printf '%s\n' '중단: start가 end보다 앞서지 않는다.' >&2; fi; fi; unset RE`

## 관측별 진단 경로

| 지금 보이는 것 | 먼저 볼 것 | 그다음 어디를 볼지 | 상세 절 |
|---|---|---|---|
| `code=killed`, `status=TERM/KILL`만 있음 | 같은 unit·PID·시간의 선행 `Stopping`·timeout·watchdog | manager 또는 승인 변경 기록 | [[#직접 진단과 판정\|직접 진단]] |
| `Killed process INCIDENT_PID`와 OOM 문맥이 일치 | victim PID·시각·cgroup 문맥 | 메모리/OOM owner | [[#직접 진단과 판정\|직접 진단]] |
| `segfault`·`general protection` | PID·시각·실행 식별자와 crash artifact | application/kernel owner | [[#직접 진단과 판정\|직접 진단]] |
| 현재 `/proc/INCIDENT_PID`가 존재 | start ticks·PID namespace | PID reuse 여부, 현재 process와 사건 분리 | [[#직접 진단과 판정\|직접 진단]] |

## 직접 진단과 판정

unit journal 수집은 현재 `FragmentPath/MainPID/InvocationID`가 등록값과 같은지 명령 안에서 다시 검사한다. 이는 수집 중 service replacement를 막는 gate이며, 현재 invocation이 과거 사건 invocation과 같다는 뜻은 아니다.

`DIAG_READY=false; if [ "$TIME_READY" != true ]; then printf '%s\n' '중단: TIME_READY가 아니다.' >&2; elif UJ="$(node_read unit_journal "$UNIT" "$UNIT_FRAGMENT" "$UNIT_MAINPID" "$UNIT_INVOCATION_ID" "$START_RFC3339" "$END_RFC3339" "$INCIDENT_PID")"; then DIAG_READY=true; if [ -n "$UJ" ]; then printf '%s\n' "$UJ"; else printf '%s\n' 'no-match: unit journal producer는 성공했지만 bounded filter 결과가 없음'; fi; else printf '%s\n' '중단: service replacement, journal producer 또는 filter 오류' >&2; fi; unset UJ`

`if [ "$DIAG_READY" != true ]; then printf '%s\n' '중단: DIAG_READY가 아니다.' >&2; elif KJ="$(node_read kernel_journal "$START_RFC3339" "$END_RFC3339" "$INCIDENT_PID")"; then if [ -n "$KJ" ]; then printf '%s\n' "$KJ"; else printf '%s\n' 'no-match: kernel journal producer는 성공했지만 bounded filter 결과가 없음'; fi; else printf '%s\n' '중단: kernel journal producer 또는 filter 오류' >&2; fi; unset KJ`

`if [ "$DIAG_READY" = true ] && PS="$(node_read pid_snapshot "$INCIDENT_PID")"; then printf '%s\n' "$PS"; else printf '%s\n' '중단: current PID snapshot producer 실패' >&2; fi; unset PS`

판정 경계:

- unit journal에서 사건 PID의 `code=killed/status=...`와 종료 시각이 맞으면 signal 종료 형태만 확정한다.
- 종료보다 앞선 동일 unit의 `Stopping`·timeout·watchdog와 승인 변경 ID가 함께 있으면 manager/change 경로를 지지한다. journal만으로 사람·자동화 주체를 식별하지 않는다.
- kernel journal의 같은 시각에 정확한 `Killed process INCIDENT_PID`와 OOM 문맥이 있으면 kernel OOM 경로를 지지한다. 다른 victim PID나 일반 `oom-kill` 행은 대상 원인 확정 근거가 아니다.
- `segfault`는 synchronous crash 후보이며 signal 발신자 경로와 구분한다. coredump 원문·memory dump는 이 런북에서 수집하지 않는다.
- `pid_present=true`여도 사건 종료 뒤 시작한 재사용 PID일 수 있다. 사건 당시 start ticks·namespace 증거가 없으면 현재 process와 연결하지 않는다.
- producer 실패는 진단 실패, 성공 producer의 빈 filter는 no-match, grep 오류는 filter 오류다. no-match는 원인 부재가 아니라 보존·권한·unit·시간 범위 공백일 수 있다.

operator action은 shell history나 broad audit 원문으로 확인하지 않는다. 보안·변경관리 owner에게 사건 창, exact unit, incident PID, 승인 ID 존재 여부와 실행 결과만 요청한다. actor 상세, 전체 argv·환경변수·토큰·개인키를 출력하거나 사건 기록에 저장하지 않는다. Kubernetes API 변경이 관련됐다면 단일 auditID의 timestamp·verb·resource/subresource·namespace/name·requestURI·status와 당시 객체 UID를 별도 Kubernetes 런북에서 확인한다.

## 변경 격리

이 문서는 `kill`, service restart, unit 변경, `sysctl`, cgroup 변경, Pod 삭제, kubelet/runtime restart, `drain`, reboot를 실행하지 않으며 CRI/socket을 사용하지 않는다. 별도 변경은 fresh Node/host/unit identity, 직접 원인 증거, 승인 ID, 정확한 SSH/RBAC 주체, 변경 window, blast radius, PDB/quorum·대체 capacity, 멱등성, 중단 조건과 검증 가능한 rollback이 모두 있는 승인 절차로 이관한다.

변경 또는 rollback 직전에는 target unit의 current fragment·MainPID·InvocationID, 승인 설정/revision, evidence와 availability를 다시 확인한다. process·service invocation·Node·Pod가 교체되면 이전 PID·UID·READY를 재사용하지 않고 `register_service`와 영향 workload의 전체 identity 등록을 다시 수행한다.

## 정상화 검증

사건 창과 별도로 변경 이후 관찰 창을 strict UTC로 등록한다.

## 증거 보존과 환경 한계

Node name·UID·resourceVersion·systemUUID, SSH endpoint와 원격 hostname/system UUID, exact unit과 current FragmentPath/MainPID/InvocationID, incident PID, canonical 사건·검증 창, exit code/status/result, bounded unit·kernel 결정 행, producer/no-match/filter 오류, 변경관리 확인 결과, 새 process/workload identity와 실제 기능 결과를 보존한다. 전체 journal·argv·환경변수·coredump·actor 상세·Secret·token·개인키·개인정보는 저장하지 않는다.

실제 클러스터·Node에는 이 문서 작성 중 접근하거나 명령을 실행하지 않았다. systemd·journald 사용, DMI UUID mapping, journal 보존·권한·시간 동기화, unit 종류, signal sender와 container/runtime mapping은 환경별 미검증이다.
