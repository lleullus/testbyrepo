# CPU 사용률은 낮지만 load average가 높은 경우

## 입력값과 빠른 수집

연결 경로는 `작업 PC 또는 bastion의 Bash → kubectl → API server → Node 객체`와 `같은 작업 host의 ssh client → 승인된 SSH endpoint → 대상 Linux host → /proc·PSI·vmstat`다. `HOST`는 SSH 접속 문자열이고 `NODE`는 Kubernetes Node 이름이다. 둘이 같다고 가정하지 않으며 Node의 `systemUUID`와 원격 DMI UUID가 일치해야 Linux 증거를 등록한다.

| 종류 | 변수 | 출처와 gate |
|---|---|---|
| 최초 입력 | `NODE`, `HOST` | 승인된 Node exact name과 SSH endpoint를 각각 한 번 입력한다. |
| API 확인 자동값 | `NODE_UID`, `NODE_RV`, `NODE_SYSTEM_UUID`, `NODE_INTERNAL_IP` | Node API exact-name 조회가 모두 성공한 뒤에만 등록한다. |
| 계산 후보값 | `INSTANCE_RE`, PromQL | exporter identity를 regex escape해 생성하며 실제 producer·label mapping 확인 전에는 확정하지 않는다. |
| 운영자 선택값 | `START_RFC3339`, `END_RFC3339`, `EXPORTER_INSTANCE` | 장애 증거와 monitoring target을 확인한 뒤 해당 절에서 한 번 입력한다. |

### 1. Bash·도구 확인

`TOOLS_READY=false; MISSING=''; for TOOL in kubectl jq ssh date sed grep; do command -v "$TOOL" >/dev/null 2>&1 || MISSING="$MISSING $TOOL"; done; if [ -n "${BASH_VERSION:-}" ] && [ -z "$MISSING" ]; then TOOLS_READY=true; printf 'TOOLS_READY=true bash=%s\n' "$BASH_VERSION"; else printf '중단: Bash 또는 도구 없음:%s\n' "$MISSING" >&2; fi`

### 2. 최초 입력과 API identity 등록

재등록 전 Node·host·관계·시각·regex와 모든 downstream gate를 비운다. API 실패 시 일부 자동값이나 이전 `READY`가 남지 않는다.

`unset INPUT_READY REMOTE_READY TIME_READY QUERY_READY DIAG_READY NORMALIZE_READY NODE HOST NODE_UID NODE_RV NODE_SYSTEM_UUID NODE_INTERNAL_IP REMOTE_SYSTEM_UUID REMOTE_HOSTNAME START_RFC3339 END_RFC3339 START_EPOCH END_EPOCH EXPORTER_INSTANCE INSTANCE_RE; INPUT_READY=false; REMOTE_READY=false; TIME_READY=false; QUERY_READY=false; DIAG_READY=false; NORMALIZE_READY=false; NODE='PASTE_NODE_HERE'; HOST='PASTE_SSH_HOST_HERE'; if [ "$TOOLS_READY" != true ]; then printf '%s\n' '중단: TOOLS_READY가 아니다.' >&2; elif [ -z "$NODE" ] || [ -z "$HOST" ] || [[ "$HOST" == -* ]]; then printf '%s\n' '중단: NODE/HOST가 비었거나 HOST가 옵션 형태다.' >&2; elif NODE_JSON="$(kubectl get node "$NODE" -o json)"; then NODE_UID_TMP="$(jq -r '.metadata.uid // empty' <<<"$NODE_JSON")"; NODE_RV_TMP="$(jq -r '.metadata.resourceVersion // empty' <<<"$NODE_JSON")"; NODE_SYSTEM_UUID_TMP="$(jq -r '.status.nodeInfo.systemUUID // empty' <<<"$NODE_JSON")"; NODE_INTERNAL_IP_TMP="$(jq -r '[.status.addresses[]? | select(.type=="InternalIP") | .address] | if length==1 then .[0] else empty end' <<<"$NODE_JSON")"; if [ -n "$NODE_UID_TMP" ] && [ -n "$NODE_RV_TMP" ] && [ -n "$NODE_SYSTEM_UUID_TMP" ] && [ -n "$NODE_INTERNAL_IP_TMP" ]; then NODE_UID="$NODE_UID_TMP"; NODE_RV="$NODE_RV_TMP"; NODE_SYSTEM_UUID="$NODE_SYSTEM_UUID_TMP"; NODE_INTERNAL_IP="$NODE_INTERNAL_IP_TMP"; INPUT_READY=true; export NODE HOST NODE_UID NODE_RV NODE_SYSTEM_UUID NODE_INTERNAL_IP; printf 'INPUT_READY=true\nNode=%s\nUID=%s\nresourceVersion=%s\nsystemUUID=%s\nInternalIP=%s\nSSH endpoint=%s\n' "$NODE" "$NODE_UID" "$NODE_RV" "$NODE_SYSTEM_UUID" "$NODE_INTERNAL_IP" "$HOST"; else printf '%s\n' '중단: Node identity 필드가 비었거나 InternalIP가 단일 값이 아니다.' >&2; fi; unset NODE_UID_TMP NODE_RV_TMP NODE_SYSTEM_UUID_TMP NODE_INTERNAL_IP_TMP; else printf '중단: Node exact-name 조회 실패 node=%s\n' "$NODE" >&2; fi; unset NODE_JSON`

### 3. fresh gate와 안전한 원격 operation 등록

`fresh_node`는 모든 후속 API·원격·정상화 조회 직전에 UID와 `resourceVersion`을 다시 읽는다. `resourceVersion` 변경은 stale evidence를 막기 위해 중단하며, 기본 수집부터 전체 refresh 후 재등록한다. 원격 함수는 정해진 operation과 위치 인자만 받고 `eval`, 문자열 command 조립, 원격 shell interpolation을 사용하지 않는다.

```bash
fresh_node() {
  local data uid rv
  [ "$INPUT_READY" = true ] || { printf '%s\n' '중단: INPUT_READY가 아니다.' >&2; return 1; }
  data="$(kubectl get node "$NODE" -o json)" || { printf '%s\n' '중단: Node fresh 조회 실패' >&2; return 1; }
  uid="$(jq -r '.metadata.uid // empty' <<<"$data")"
  rv="$(jq -r '.metadata.resourceVersion // empty' <<<"$data")"
  [ "$uid" = "$NODE_UID" ] && [ "$rv" = "$NODE_RV" ] || { printf '중단: Node identity/lifecycle 변경 uid=%s rv=%s\n' "$uid" "$rv" >&2; return 1; }
}
node_read() {
  local operation="$1"
  shift
  fresh_node || return 1
  ssh -- "$HOST" bash -s -- "$NODE_SYSTEM_UUID" "$operation" "$@" <<'REMOTE'
set -o pipefail
expected_uuid=$1
operation=$2
shift 2
actual_uuid=$(tr '[:upper:]' '[:lower:]' </sys/class/dmi/id/product_uuid 2>/dev/null | tr -d '-') || exit 20
expected_uuid=$(printf '%s' "$expected_uuid" | tr '[:upper:]' '[:lower:]' | tr -d '-')
[ -n "$actual_uuid" ] && [ "$actual_uuid" = "$expected_uuid" ] || { printf '%s\n' '중단: 원격 host system UUID 불일치' >&2; exit 21; }
case "$operation" in
  identity) printf 'remote_hostname=%s\nremote_system_uuid=%s\n' "$(hostname --fqdn 2>/dev/null || hostname)" "$actual_uuid" ;;
  baseline) date -u '+observed-rfc3339=%Y-%m-%dT%H:%M:%SZ'; cat /proc/loadavg; getconf _NPROCESSORS_ONLN; vmstat 1 3; cat /proc/pressure/cpu; cat /proc/pressure/io ;;
  blocked) ps -e -o pid=,ppid=,state=,wchan:32,comm= | grep -E '^[[:space:]]*[0-9]+[[:space:]]+[0-9]+[[:space:]]+D' | sed -n '1,20p'; status=("${PIPESTATUS[@]}"); [ "${status[0]}" -eq 0 ] || exit "${status[0]}"; { [ "${status[1]}" -eq 0 ] || [ "${status[1]}" -eq 1 ]; } || exit "${status[1]}"; [ "${status[2]}" -eq 0 ] || exit "${status[2]}" ;;
  verify) date -u '+verify-rfc3339=%Y-%m-%dT%H:%M:%SZ'; cat /proc/loadavg; vmstat 1 3; cat /proc/pressure/cpu; cat /proc/pressure/io ;;
  *) printf '중단: 허용되지 않은 operation=%s\n' "$operation" >&2; exit 22 ;;
esac
REMOTE
}
```

원격 identity를 등록한다. SSH 실패나 UUID 불일치 시 이전 원격값과 모든 downstream `READY`를 폐기한다.

`unset REMOTE_SYSTEM_UUID REMOTE_HOSTNAME; REMOTE_READY=false; TIME_READY=false; QUERY_READY=false; DIAG_READY=false; NORMALIZE_READY=false; if OUT="$(node_read identity)"; then REMOTE_HOSTNAME="$(sed -n 's/^remote_hostname=//p' <<<"$OUT")"; REMOTE_SYSTEM_UUID="$(sed -n 's/^remote_system_uuid=//p' <<<"$OUT")"; if [ -n "$REMOTE_HOSTNAME" ] && [ -n "$REMOTE_SYSTEM_UUID" ]; then REMOTE_READY=true; export REMOTE_HOSTNAME REMOTE_SYSTEM_UUID; printf 'REMOTE_READY=true\nNode=%s UID=%s\nSSH=%s\nRemote hostname=%s\nRemote system UUID=%s\n' "$NODE" "$NODE_UID" "$HOST" "$REMOTE_HOSTNAME" "$REMOTE_SYSTEM_UUID"; else printf '%s\n' '중단: 원격 identity 출력 불완전' >&2; fi; else printf '%s\n' '중단: SSH 또는 원격 identity 검증 실패' >&2; fi; unset OUT`

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | 같은 관측 창에서 load average가 높지만 `vmstat`의 `id`가 남아 runnable·blocked·steal을 분리해야 하는 경우 |
| 적용 | 검증된 Node UID와 원격 system UUID에서 load, `r/b`, `us/sy/id/wa/st`, CPU/I/O PSI를 수집할 수 있는 경우 |
| 제외 | `us`·`sy`와 `r`이 함께 높으면 [[01. 호스트 CPU 사용률이 지속적으로 높은 경우]], 지속 `D` task는 [[03. 프로세스가 D 상태에서 오래 멈춘 경우]], pressure condition은 전용 Node 런북으로 이동한다. |

검색 문자열: `load average`, `/proc/loadavg`, `r`, `b`, `D`, `wchan`, `wa`, `st`, `CPU pressure`, `I/O pressure`.

## 시간 창 등록

UTC `Z` 형식만 허용하고 GNU `date` parsing 결과가 입력과 정확히 round-trip하며 시작이 종료보다 앞설 때만 등록한다.

`unset START_RFC3339 END_RFC3339 START_EPOCH END_EPOCH; TIME_READY=false; QUERY_READY=false; DIAG_READY=false; NORMALIZE_READY=false; START_RFC3339='PASTE_START_RFC3339_HERE'; END_RFC3339='PASTE_END_RFC3339_HERE'; RFC3339_RE='^[0-9]{4}-(0[1-9]|1[0-2])-([0-2][0-9]|3[01])T([01][0-9]|2[0-3]):[0-5][0-9]:[0-5][0-9]Z$'; if [ "$REMOTE_READY" != true ]; then printf '%s\n' '중단: REMOTE_READY가 아니다.' >&2; elif [[ ! "$START_RFC3339" =~ $RFC3339_RE ]] || [[ ! "$END_RFC3339" =~ $RFC3339_RE ]]; then printf '%s\n' '중단: canonical UTC RFC3339 형식이 아니다.' >&2; elif [ "$(date -u -d "$START_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" != "$START_RFC3339" ] || [ "$(date -u -d "$END_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" != "$END_RFC3339" ]; then printf '%s\n' '중단: RFC3339 date round-trip 실패' >&2; else START_EPOCH="$(date -u -d "$START_RFC3339" +%s)"; END_EPOCH="$(date -u -d "$END_RFC3339" +%s)"; if [ "$START_EPOCH" -lt "$END_EPOCH" ]; then TIME_READY=true; export START_RFC3339 END_RFC3339 START_EPOCH END_EPOCH; printf 'TIME_READY=true start=%s end=%s duration_seconds=%s\n' "$START_RFC3339" "$END_RFC3339" "$((END_EPOCH-START_EPOCH))"; else printf '%s\n' '중단: start가 end보다 앞서지 않는다.' >&2; fi; fi; unset RFC3339_RE`

## 관측별 진단 경로

| 지금 보이는 것 | 판정 | 다음 행동 |
|---|---|---|
| `r`·CPU PSI와 `us/sy`가 높고 `id`가 낮음 | runnable CPU 경쟁 | CPU 포화 런북으로 이동한다. |
| `b`·`wa`·I/O PSI와 D task가 함께 증가 | blocked I/O 후보 | PID/wchan을 보존하고 D-state·filesystem/storage owner로 이동한다. |
| `st`가 높음 | guest 실행 기회 상실 후보 | 같은 시간의 승인된 hypervisor metric을 platform owner에게 요청한다. |
| 현재 sample 정상, 과거 metric만 높음 | 현재 관측으로 과거 peak를 재구성할 수 없음 | producer와 retention을 확인하고 `historical evidence unavailable` 여부를 기록한다. |

## 직접 진단

기본 수집은 매 호출마다 fresh Node와 원격 identity를 검증한다. `node_read baseline`의 producer가 실패하면 진단 실패다. 출력 성공 후 `grep`으로 필요한 행이 없으면 no-match이며 producer 실패와 구분한다.

`DIAG_READY=false; if [ "$TIME_READY" != true ]; then printf '%s\n' '중단: TIME_READY가 아니다.' >&2; elif BASELINE="$(node_read baseline)"; then DIAG_READY=true; printf '%s\n' "$BASELINE"; else printf '%s\n' '중단: baseline producer 실패' >&2; fi`

`if [ "$DIAG_READY" != true ]; then printf '%s\n' '중단: DIAG_READY가 아니다.' >&2; elif BLOCKED="$(node_read blocked)"; then if [ -n "$BLOCKED" ]; then printf '%s\n' "$BLOCKED"; else printf '%s\n' 'no-match: 현재 bounded 목록에 D task가 없음'; fi; else printf '%s\n' '중단: ps producer 또는 filter 실행 오류' >&2; fi`

`D` task가 없다는 현재 결과는 과거 blocked task 부재를 보장하지 않는다. 장치·mount·PVC·CSI 관계는 PID와 실제 path가 확인되기 전에는 만들지 않는다. 이 문서는 `kubectl exec`, Pod 로그, CRI, runtime socket, storage 변경을 사용하지 않는다.

## Prometheus 완성 쿼리

`EXPORTER_INSTANCE`는 monitoring target 화면에서 현재 Node UID/system UUID와 매핑이 확인된 exact label이다. 입력을 정규식에 그대로 붙이지 않고 escape한다.

`unset EXPORTER_INSTANCE INSTANCE_RE; QUERY_READY=false; EXPORTER_INSTANCE='PASTE_NODE_EXPORTER_INSTANCE_HERE'; if [ "$INPUT_READY" != true ] || ! fresh_node; then printf '%s\n' '중단: fresh Node gate 실패' >&2; elif [ -z "$EXPORTER_INSTANCE" ]; then printf '%s\n' '중단: exporter instance가 비었다.' >&2; else INSTANCE_RE="$(printf '%s' "$EXPORTER_INSTANCE" | sed 's/[][\\.^$*+?(){}|]/\\&/g')"; QUERY_READY=true; export EXPORTER_INSTANCE INSTANCE_RE; printf 'QUERY_READY=true node=%s uid=%s instance_re=^%s$\n' "$NODE" "$NODE_UID" "$INSTANCE_RE"; fi`

`if [ "$QUERY_READY" = true ] && fresh_node; then printf 'node_load1{instance=~"^%s$"}\n' "$INSTANCE_RE"; printf '100*(1-avg(rate(node_cpu_seconds_total{instance=~"^%s$",mode="idle"}[5m])))\n' "$INSTANCE_RE"; printf 'absent(node_load1{instance=~"^%s$"})\n' "$INSTANCE_RE"; else printf '%s\n' '중단: QUERY_READY/fresh Node gate 실패' >&2; fi`

첫 두 쿼리가 값이 있고 `absent(...)`가 비면 producer·target·label이 존재한다. 첫 쿼리가 비고 `absent(...)`가 1이면 metric 미수집, target down, label 불일치 또는 조회 datasource/time 범위를 분리한다. query 실행 오류는 no-match로 해석하지 않는다. PromQL 결과만으로 PID·device·원인 또는 변경을 승인하지 않는다.

## 복구 전 안전 gate와 금지 조치

이 문서에는 상태 변경, rollback 또는 CRI 명령이 없다. `kill`, `renice`, `taskset`, `sysctl`, cgroup 변경, unmount, kubelet/runtime restart, Pod 삭제, `cordon`, `drain`, `reboot`를 실행하지 않는다.

별도 변경 절차로 이관하려면 변경 직전에 fresh Node UID/resourceVersion과 원격 system UUID, 직접 원인 증거, 승인 ID·RBAC/SSH 주체·감사 로그 위치, 변경 window, blast radius, PDB/quorum·대체 capacity, 멱등성, 중단 조건과 검증 가능한 rollback을 다시 확인한다. 변경 후에는 replacement Node/Pod/process를 이전 UID/PID의 연속으로 간주하지 않고 새 identity와 owner 관계를 등록한 뒤 전체 수집을 새로 수행한다.

## 정상화 검증

정상화 명령도 fresh gate와 원격 identity를 다시 통과한다.

`NORMALIZE_READY=false; if [ "$DIAG_READY" != true ] || [ "$TIME_READY" != true ]; then printf '%s\n' '중단: 진단·시간 gate가 준비되지 않았다.' >&2; elif VERIFY="$(node_read verify)"; then NORMALIZE_READY=true; printf '%s\n' "$VERIFY"; else printf '%s\n' '중단: 정상화 producer 실패' >&2; fi`

관찰 window 동안 load 방향, `r/b`, `wa/st`, CPU/I/O PSI가 안정되고 새 D task·pressure·kubelet/runtime 오류가 없어야 한다. 이어 영향 workload의 새 UID·owner·Ready/restart, EndpointSlice 관계와 승인된 실제 요청 또는 Job 결과를 fresh API로 확인한다. 한 번의 낮은 load, Node `Ready=True`, Pod `Running`은 기능 정상화를 보장하지 않는다.

## 증거 보존과 완료 보고

Node name·UID·resourceVersion·systemUUID, SSH endpoint와 원격 hostname/system UUID, canonical UTC window, load 1·5·15분, online CPU, `r/b/us/sy/id/wa/st`, CPU/I/O PSI, bounded D PID·PPID·wchan·comm, query와 producer/no-match/filter 오류 분기, owner 이관, 변경 없음, 기능 검증과 재평가 시각을 보존한다. 전체 process 목록·argv·환경변수·Secret·token·개인키·개인정보는 저장하지 않는다.

실제 클러스터·Node·Prometheus에는 이 문서 작성 중 접근하거나 명령을 실행하지 않았다. Linux 배포판, systemd, `vmstat`·PSI 지원, exporter label mapping과 metric 보존은 환경별 미검증이다.
