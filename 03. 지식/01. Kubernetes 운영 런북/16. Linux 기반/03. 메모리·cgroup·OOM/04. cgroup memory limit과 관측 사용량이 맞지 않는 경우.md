# cgroup memory limit과 관측 사용량이 맞지 않는 경우

## 입력값과 빠른 수집

| 구분 | 값 | 출처와 gate |
|---|---|---|
| 최초 입력 | `NS`, `POD`, `APPROVED_HOST`, UTC start/end | 승인된 Kubernetes 대상·SSH host·비교 창 |
| API·시스템 자동값 | Pod UID/RV, controller kind/name/UID, Node UID/machineID, regular container current ID, host·kubelet·runtime lifecycle | API와 실제 node에서 fresh 등록 |
| 계산 후보값 | epoch, escaped label regex, argv regex | roundtrip·bounded 출력 뒤 사용 |
| 운영자 선택값 | regular `CONTAINER_NAME`, Node-host relation ID, metrics provider·source labels relation | 관계가 보존된 후보를 본 뒤 선택한다. CRI endpoint와 cgroup path는 자동 확정한다. |

경로는 `operator Bash/kubectl -> API server -> Pod UID/containerID/node`와 `operator Bash -> SSH approved host -> active kubelet -> exact CRI provider -> container PID/start/cgroup -> cgroup files`다. `kubectl top`·Prometheus·raw cgroup은 서로 다른 source와 시각이므로 동일값으로 가정하지 않는다.

## 변경 분리·정상화·증거

limit/request, cgroup, swap, Pod/runtime/kubelet을 이 문서에서 변경하지 않는다. 외부 변경은 각 항목별 fresh target/evidence/approval/window/quorum/idempotence/rollback gate로 분리한다. replacement는 새 Pod UID/RV/owner/node/containerID/imageID, host boot, active CRI provider, PID start/cgroup path를 완전히 재등록하고 old->new relation을 기록한다.

정상화는 새 sample의 정의·identity가 일치하고 cgroup event·OOM·MemoryPressure·restart가 재발하지 않으며 desired/Ready와 실제 request·read/write·Job 결과가 회복되어야 한다. metric 한 개 일치나 새 Pod `Running`은 충분하지 않다.

보존: API identity/RV/owner, node-host relation, machine/boot/namespaces, active kubelet lifecycle/endpoint 출처, exact runtime provider, container lifecycle/PID start/cgroup, source별 timestamp/definition/query, 승인·rollback·실제 기능. Secret·raw inspect 전체는 저장하지 않는다. infrastructure 명령은 작성 중 실행하지 않았다.
