# cgroup controller가 활성화되지 않거나 제한이 적용되지 않는 경우

## 입력값과 빠른 수집

실행 경로는 `운영자 Bash -> 직접 SSH -> 대상 host -> 확인된 cgroup mount -> parent -> child`다. Kubernetes 선언이나 runtime 이름만으로 cgroup path를 만들지 않는다. 다른 host·parent·child로 바꾸거나 실패하면 mount/dev/inode, PID/start time, netns, argv regex, 시간 창과 downstream gate를 먼저 무효화한다.

| 구분 | 값 | 계약 |
|---|---|---|
| 최초 입력 | `SSH_TARGET`, `EXPECTED_MACHINE_ID_SHA256` | 승인된 직접 SSH endpoint와 machine-id 파일 hash |
| system-auto | `BOOT_ID`, cgroup `FSTYPE`, mount major:minor | 대상 host에서 수집 |
| 운영자 선택 | `PARENT_PATH`, `CHILD_PATH`, `ARGV_REGEX`, `TARGET_PID`, UTC 시간 창 | 실제 hierarchy와 후보를 보고 선택 |
| system-auto | parent·child dev:inode, PID start ticks, netns inode | 후속 명령의 identity gate |
| 계산값 | parent-child containment, controller 교집합 | 출력에서 계산하며 설정 변경은 하지 않음 |

### 1. host와 hierarchy 등록

```bash

[[ "$SSH_TARGET" =~ ^[A-Za-z0-9._-]+@([A-Za-z0-9._-]+|\[[0-9A-Fa-f:]+\])$ ]] || ! [[ "$EXPECTED_MACHINE_ID_SHA256" =~ ^[0-9a-f]{64}$ ]]; then printf '%s\n' '중단: 입력 또는 도구 오류' >&2; elif OUT="$(ssh -o BatchMode=yes -o ConnectTimeout=10 -o ProxyCommand=none -o ProxyJump=none -- "$SSH_TARGET" 'set -euo pipefail; sum=$(sha256sum /etc/machine-id); [ "${sum%% *}" = "$1" ] || exit 70; printf "%s\n%s\n" "$(hostname --fqdn 2>/dev/null || hostname)" "$(cat /proc/sys/kernel/random/boot_id)"' bash "$EXPECTED_MACHINE_ID_SHA256")"; then mapfile -t HOST_META <<<"$OUT"; if [ "${#HOST_META[@]}" -eq 2 ] && [ -n "${HOST_META[0]}" ] && [[ "${HOST_META[1]}" =~ ^[0-9a-fA-F-]{36}$ ]]; then HOSTNAME_ACTUAL=${HOST_META[0]}; BOOT_ID=${HOST_META[1]}; HOST_READY=true; printf 'HOST_READY=true host=%s boot_id=%s\n' "$HOSTNAME_ACTUAL" "$BOOT_ID"; else unset HOSTNAME_ACTUAL BOOT_ID; printf '%s\n' '중단: host metadata 형식 오류' >&2; fi; else unset BOOT_ID HOSTNAME_ACTUAL; printf '%s\n' '중단: SSH/machine identity 실패' >&2; fi

```

### 2. process와 시간 등록

```bash
unset TARGET_PID PID_START_TICKS NETNS_INODE; PROCESS_READY=false; DOWNSTREAM_READY=false; ARGV_REGEX='PASTE_ARGV_REGEX_HERE'; if [ "$HIERARCHY_READY" != true ] || [ -z "$ARGV_REGEX" ] || [[ "$ARGV_REGEX" == *$'\n'* ]]; then printf '%s\n' '중단: hierarchy 또는 regex 오류' >&2; else ssh -o BatchMode=yes -o ConnectTimeout=10 -o ProxyCommand=none -o ProxyJump=none -- "$SSH_TARGET" 'set -euo pipefail; expected=$1; boot=$2; child=$3; ckey=$4; regex=$5; sum=$(sha256sum /etc/machine-id); [ "${sum%% *}" = "$expected" ] && [ "$(cat /proc/sys/kernel/random/boot_id)" = "$boot" ] && [ "$(stat -Lc "%d:%i" -- "$child")" = "$ckey" ] || exit 70; while IFS= read -r pid; do [[ "$pid" =~ ^[0-9]+$ ]] || continue; [ -r "/proc/$pid/stat" ] || continue; argv=$(tr "\0" " " <"/proc/$pid/cmdline"); if printf "%s\n" "$argv" | grep -Eq -- "$regex"; then filter_rc=0; else filter_rc=$?; fi; [ "$filter_rc" -eq 0 ] || { [ "$filter_rc" -eq 1 ] && continue; exit "$filter_rc"; }; printf "pid=%s start_ticks=%s netns=%s argv=%.*s\n" "$pid" "$(cut -d" " -f22 "/proc/$pid/stat")" "$(stat -Lc "%i" "/proc/$pid/ns/net")" 160 "$argv"; done <"$child/cgroup.procs"' bash "$EXPECTED_MACHINE_ID_SHA256" "$BOOT_ID" "$CHILD_PATH" "$CHILD_KEY" "$ARGV_REGEX"; fi
```

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | 선언한 limit과 실제 child interface가 다르거나 controller/subtree/delegation 불일치가 의심됨 |
| 적용 | 같은 mount의 확인된 parent-child와 실제 process를 연결 가능 |
| 제외 | 단순 OOM·CPU throttling이면 해당 OOM 런북 또는 [[07. cgroup CPU throttling이 지속적으로 증가하는 경우]] |

검색 문자열: `cgroup.controllers`, `cgroup.subtree_control`, `cgroup.type`, `memory.max`, `cpu.max`, `Delegate`, `ControlGroup`, `cgroup.procs`.

## 관측별 진단 경로

| 지금 보이는 것 | 직접 증거 | 다음 판단 |
|---|---|---|
| v2 controller available, subtree에 없음 | parent의 두 파일과 child interface | controller 미배포 후보 |
| v1 controller mount가 다름 | mount FSTYPE/options와 child dev:inode | hierarchy 불일치 |
| process가 child에 없음 | PID start/netns/argv와 `cgroup.procs` | 이동·재시작 후 재등록 |
| systemd unit과 path가 다름 | 승인된 unit의 `ControlGroup`·`Delegate` | delegation owner 이관 |

## 직접 진단

```bash
if [ "$HIERARCHY_READY" != true ] || [ "$PROCESS_READY" != true ]; then printf '%s\n' '중단: hierarchy/process gate가 완전하지 않다.' >&2; exit 1; fi; ssh -o BatchMode=yes -o ConnectTimeout=10 -o ProxyCommand=none -o ProxyJump=none -- "$SSH_TARGET" 'set -euo pipefail; expected=$1; boot=$2; parent=$3; pkey=$4; child=$5; ckey=$6; pid=$7; start=$8; netns=$9; regex=${10}; sum=$(sha256sum /etc/machine-id); [ "${sum%% *}" = "$expected" ] && [ "$(cat /proc/sys/kernel/random/boot_id)" = "$boot" ] && [ "$(stat -Lc "%d:%i" -- "$parent")" = "$pkey" ] && [ "$(stat -Lc "%d:%i" -- "$child")" = "$ckey" ] && [ "$(cut -d" " -f22 "/proc/$pid/stat")" = "$start" ] && [ "$(stat -Lc "%i" "/proc/$pid/ns/net")" = "$netns" ] || exit 70; grep -Fxq -- "$pid" "$child/cgroup.procs" || exit 72; argv=$(tr "\0" " " <"/proc/$pid/cmdline"); printf "%s\n" "$argv" | grep -Eq -- "$regex" || exit 73; printf "observed_at=%s mount=%s\n" "$(date -u +%Y-%m-%dT%H:%M:%SZ)" "$(findmnt -T "$child" -n -o MAJ:MIN,TARGET,FSTYPE,OPTIONS)"; if [ -r "$parent/cgroup.controllers" ]; then printf "%s\n" "version=v2"; for file in cgroup.controllers cgroup.subtree_control cgroup.type cgroup.procs; do printf "parent/%s=" "$file"; cat "$parent/$file"; done; for file in cgroup.controllers cgroup.subtree_control cgroup.type cgroup.procs; do [ -r "$child/$file" ] && { printf "child/%s=" "$file"; cat "$child/$file"; }; done; for file in memory.max memory.current memory.events cpu.max cpu.weight cpu.stat; do [ -r "$child/$file" ] && { printf "child/%s=" "$file"; cat "$child/$file"; }; done; else printf "%s\n" "version=v1"; findmnt -T "$child" -n -o TARGET,SOURCE,FSTYPE,OPTIONS; for file in memory.limit_in_bytes memory.usage_in_bytes memory.failcnt cpu.cfs_quota_us cpu.cfs_period_us cpu.stat tasks; do [ -r "$child/$file" ] && { printf "child/%s=" "$file"; cat "$child/$file"; }; done; fi' bash "$EXPECTED_MACHINE_ID_SHA256" "$BOOT_ID" "$PARENT_PATH" "$PARENT_KEY" "$CHILD_PATH" "$CHILD_KEY" "$TARGET_PID" "$PID_START_TICKS" "$NETNS_INODE" "$ARGV_REGEX"
```

v2 `cgroup.controllers`는 사용 가능 controller, parent `cgroup.subtree_control`은 child에 배포한 controller다. 한 파일의 존재만으로 enforcement를 보장하지 않는다. v1은 controller가 연결된 실제 mount와 child path가 같아야 한다. root cgroup 값은 workload 증거가 아니다.

systemd delegation은 systemd 사용과 unit이 확인된 경우에만 본다. unit 이름은 운영자가 서비스 관리자에서 확인하며 이 문서는 추측 명령을 제공하지 않는다. `ControlGroup`, `Delegate`, drop-in의 비민감 필드만 보존하고 unit 원문·환경변수는 저장하지 않는다.

## journal 증거

kernel cgroup 오류가 실제 사건에 있을 때만 실행한다. producer rc와 filter rc를 분리하며 no-match(rc=1)는 오류 부재가 아니다.

```bash
if [ "$HIERARCHY_READY" != true ] || [ "$PROCESS_READY" != true ] || [ "$TIME_READY" != true ]; then printf '%s\n' '중단: identity/time gate가 완전하지 않다.' >&2; exit 1; fi; ssh -o BatchMode=yes -o ConnectTimeout=10 -o ProxyCommand=none -o ProxyJump=none -- "$SSH_TARGET" 'set -euo pipefail; expected=$1; boot=$2; child=$3; ckey=$4; pid=$5; start=$6; netns=$7; regex=$8; since=$9; until=${10}; sum=$(sha256sum /etc/machine-id); [ "${sum%% *}" = "$expected" ] && [ "$(cat /proc/sys/kernel/random/boot_id)" = "$boot" ] && [ "$(stat -Lc "%d:%i" -- "$child")" = "$ckey" ] && [ "$(cut -d" " -f22 "/proc/$pid/stat")" = "$start" ] && [ "$(stat -Lc "%i" "/proc/$pid/ns/net")" = "$netns" ] || exit 70; argv=$(tr "\0" " " <"/proc/$pid/cmdline"); printf "%s\n" "$argv" | grep -Eq -- "$regex" || exit 73; s=$(date -u -d "$since" +%Y-%m-%dT%H:%M:%SZ); e=$(date -u -d "$until" +%Y-%m-%dT%H:%M:%SZ); [ "$s" = "$since" ] && [ "$e" = "$until" ] && [ "$(date -u -d "$s" +%s)" -lt "$(date -u -d "$e" +%s)" ] || exit 74; set +e; raw=$(TZ=UTC journalctl -k --since "$since" --until "$until" --no-pager -o short-iso-precise); producer_rc=$?; set -e; [ "$producer_rc" -eq 0 ] || { printf "journal producer failed rc=%s\n" "$producer_rc" >&2; exit "$producer_rc"; }; set +e; printf "%s\n" "$raw" | grep -E -i -C 3 -- "cgroup|controller|subtree|delegat|memory cgroup|task_memcg|failed"; filter_rc=${PIPESTATUS[1]}; set -e; printf "producer_rc=%s filter_rc=%s window=%s/%s\n" "$producer_rc" "$filter_rc" "$since" "$until"; [ "$filter_rc" -eq 0 ] || [ "$filter_rc" -eq 1 ]' bash "$EXPECTED_MACHINE_ID_SHA256" "$BOOT_ID" "$CHILD_PATH" "$CHILD_KEY" "$TARGET_PID" "$PID_START_TICKS" "$NETNS_INODE" "$ARGV_REGEX" "$START_RFC3339" "$END_RFC3339"
```

출력에 Secret·token·개인키·개인정보가 보이면 즉시 표시·저장을 중단하고 UTC 시각, 오류 유형과 비민감 identity만 기록한다. journal의 첫·마지막 실제 UTC timestamp와 요청 창을 함께 보존한다.

## 복구 전 안전 gate와 정상화

이 문서는 controller enable, subtree write, cgroup 이동, `Delegate=`·limit 변경, daemon reload/restart, Pod 재생성을 실행하지 않는다. 외부 변경은 매 명령 직전에 host/process/mount/cgroup/evidence identity를 재확인하고, 승인 ID·window·가용성·blast radius·멱등성·중단 조건·검증된 rollback/보상 절차가 있어야 한다. 새 process·cgroup이 생기면 반드시 재등록한다.

정상화는 직접 진단과 필요한 journal 명령을 새 UTC 창에서 반복해 controller→subtree→child interface→process membership→limit/event 순으로 확인한다. 실제 서비스의 승인된 health check·요청 또는 batch 결과와 재발 관찰이 통과해야 한다. controller 파일 존재나 Pod `Running`만으로 정상화하지 않는다.

## 증거 보존과 환경별 미검증

host/boot, mount major:minor·FSTYPE, parent/child dev:inode, controller/subtree/type, process PID/start/netns/argv 요약, strict UTC 창, journal producer/filter rc와 실제 timestamp, 실제 기능 결과를 보존한다. machine-id 원문, raw inspect/config, 환경변수와 민감정보는 저장하지 않는다. runtime/CRI/Kubernetes mapping은 실제 endpoint와 container identity 계약이 별도로 확인되지 않아 환경별 미검증이다.
