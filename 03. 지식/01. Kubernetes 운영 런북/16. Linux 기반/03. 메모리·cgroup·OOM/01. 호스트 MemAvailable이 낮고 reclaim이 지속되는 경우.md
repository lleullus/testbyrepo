# 호스트 MemAvailable이 낮고 reclaim이 지속되는 경우

## 입력값과 빠른 수집

이 문서는 Linux host의 memory reclaim을 판정한다. Kubernetes 객체나 특정 container를 원인으로 미리 정하지 않는다.

| 구분 | 값 | 출처와 gate |
|---|---|---|
| 최초 입력 | `APPROVED_HOST`, `START_RFC3339`, `END_RFC3339` | 승인된 SSH 대상과 사건 창. 한 번만 입력한다. |
| API·시스템 자동값 | `HOSTNAME_ACTUAL`, `MACHINE_ID`, `BOOT_ID`, `KERNEL_RELEASE` | 원격 host에서 직접 읽는다. 하나라도 비면 중단한다. |
| 계산 후보값 | `START_EPOCH`, `END_EPOCH`, `MEM_RE` | UTC roundtrip과 정규식 bounded 출력 전에는 사용하지 않는다. |
| 운영자 선택값 | `APPROVED_METRICS_PROVIDER`, `INSTANCE` | 실제 보존 source와 label을 확인한 경우에만 선택한다. |

실행 경로는 `승인된 operator Bash -> SSH -> 승인된 Linux host의 host mount/PID/network namespace -> /proc·journal`이다. Pod shell, chroot, container namespace에서 실행하지 않는다. SSH 대상에는 allowlist된 host 문자만 허용하고, 원격 값은 검증 후 위치 인자로만 전달하며 `eval`을 사용하지 않는다.

**최초 입력·모든 downstream 상태 초기화**

`unset INPUT_READY HOST_READY SNAPSHOT_READY DELTA_READY JOURNAL_READY SELECTION_READY AUTHORIZATION_READY EVIDENCE_READY QUERY_READY MUTATION_READY ROLLBACK_READY NORMALIZATION_READY APPROVED_HOST START_RFC3339 END_RFC3339 START_EPOCH END_EPOCH HOSTNAME_ACTUAL MACHINE_ID BOOT_ID KERNEL_RELEASE MOUNT_ID NETNS_ID APPROVED_METRICS_PROVIDER INSTANCE INSTANCE_RE METRICS_RELATION_ID MEM_RE RFC3339_RE; IFS=$'\t' read -r APPROVED_HOST START_RFC3339 END_RFC3339 <<< $'PASTE_TAB_SEPARATED_HOST_START_END_HERE'; INPUT_READY=false; RFC3339_RE='^[0-9]{4}-(0[1-9]|1[0-2])-([0-2][0-9]|3[01])T([01][0-9]|2[0-3]):[0-5][0-9]:[0-5][0-9]Z$'; if [[ "$APPROVED_HOST" =~ ^[A-Za-z0-9._:-]+$ ]] && [[ "$START_RFC3339" =~ $RFC3339_RE ]] && [[ "$END_RFC3339" =~ $RFC3339_RE ]] && START_CANON="$(date -u -d "$START_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" && END_CANON="$(date -u -d "$END_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" && [ "$START_CANON" = "$START_RFC3339" ] && [ "$END_CANON" = "$END_RFC3339" ]; then START_EPOCH="$(date -u -d "$START_RFC3339" +%s)"; END_EPOCH="$(date -u -d "$END_RFC3339" +%s)"; if [ "$START_EPOCH" -lt "$END_EPOCH" ]; then SSH_OPTS=(-o BatchMode=yes -o ConnectTimeout=10); MEM_RE='^(MemTotal|MemFree|MemAvailable|Buffers|Cached|SReclaimable|SUnreclaim|Shmem|SwapTotal|SwapFree|Dirty|Writeback):'; INPUT_READY=true; printf 'INPUT_READY=true host=%s window=%s/%s MEM_RE=%s\n' "$APPROVED_HOST" "$START_RFC3339" "$END_RFC3339" "$MEM_RE"; fi; fi; if [ "$INPUT_READY" != true ]; then unset APPROVED_HOST START_RFC3339 END_RFC3339 START_EPOCH END_EPOCH MEM_RE SSH_OPTS; printf '%s\n' '중단: host 또는 canonical UTC RFC3339 창이 유효하지 않다.' >&2; fi`

`START_RFC3339`와 `END_RFC3339`는 정확히 `YYYY-MM-DDTHH:MM:SSZ`로 roundtrip되고 `start < end`여야 한다. 다른 timezone, leap normalization, 빈 값은 허용하지 않는다.

**원격 host identity 등록**

```bash
HOST_READY=false; SNAPSHOT_READY=false; DELTA_READY=false; JOURNAL_READY=false; SELECTION_READY=false; AUTHORIZATION_READY=false; EVIDENCE_READY=false; QUERY_READY=false; MUTATION_READY=false; ROLLBACK_READY=false; NORMALIZATION_READY=false; unset HOSTNAME_ACTUAL MACHINE_ID BOOT_ID KERNEL_RELEASE MOUNT_ID NETNS_ID HOST_RECORD APPROVED_METRICS_PROVIDER INSTANCE INSTANCE_RE METRICS_RELATION_ID; if [ "$INPUT_READY" != true ]; then printf '%s\n' '중단: INPUT_READY가 아니다.' >&2; else if HOST_RECORD="$(ssh "${SSH_OPTS[@]}" -- "$APPROVED_HOST" 'set -eu; h=$(hostname -f 2>/dev/null || hostname); m=$(cat /etc/machine-id); b=$(cat /proc/sys/kernel/random/boot_id); k=$(uname -r); mi=$(stat -Lc %i /proc/1/ns/mnt); ni=$(stat -Lc %i /proc/1/ns/net); printf "%s\t%s\t%s\t%s\t%s\t%s\n" "$h" "$m" "$b" "$k" "$mi" "$ni"')" && IFS=$'\t' read -r HOSTNAME_ACTUAL MACHINE_ID BOOT_ID KERNEL_RELEASE MOUNT_ID NETNS_ID <<< "$HOST_RECORD" && [ -n "$HOSTNAME_ACTUAL" ] && [ -n "$KERNEL_RELEASE" ] && [[ "$MACHINE_ID" =~ ^[0-9a-fA-F]{32}$ ]] && [[ "$BOOT_ID" =~ ^[0-9a-fA-F-]{36}$ ]] && [[ "$MOUNT_ID" =~ ^[0-9]+$ ]] && [[ "$NETNS_ID" =~ ^[0-9]+$ ]]; then HOST_READY=true; printf 'HOST_READY=true host=%s machine=%s boot=%s kernel=%s mntns=%s netns=%s\n' "$HOSTNAME_ACTUAL" "$MACHINE_ID" "$BOOT_ID" "$KERNEL_RELEASE" "$MOUNT_ID" "$NETNS_ID"; else unset HOSTNAME_ACTUAL MACHINE_ID BOOT_ID KERNEL_RELEASE MOUNT_ID NETNS_ID HOST_RECORD; printf '%s\n' '중단: SSH 또는 host identity 등록 실패' >&2; fi; fi
```

이후 모든 원격 수집은 machine-id, boot-id, host mount namespace를 새로 대조한다. 재부팅 또는 namespace 불일치는 이전 evidence와의 관계를 끊으므로 이 절부터 다시 등록한다.

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | `MemAvailable` 저하와 reclaim scan·stall이 같은 host·boot·시간창에 지속되는 경우 |
| 적용 | 현재 snapshot과 두 sample의 counter delta, PSI, swap, dirty/writeback을 분리할 수 있는 경우 |
| 제외 | 결정적 global OOM은 [[02. kernel system OOM에 Killed process가 기록된 경우]], 특정 cgroup event는 [[03. container cgroup에 OOM event가 증가한 경우]], swap 지연은 [[05. swap in·out과 지연이 함께 증가하는 경우]]로 이동한다. |

검색 문자열: `MemAvailable`, `pgscan`, `pgsteal`, `allocstall`, `some`, `full`, `pswpin`, `pswpout`, `Dirty`, `Writeback`.

## 관측별 진단 경로

| 지금 보이는 것 | 먼저 볼 것 | 그다음 어디를 볼지 | 상세 절 |
|---|---|---|---|
| `MemAvailable` 저하와 scan 증가 | 같은 boot의 counter delta | reclaim 효율·PSI | [[#1. 현재 snapshot과 counter delta]] |
| scan 대비 steal이 작고 allocstall 증가 | dirty/writeback·slab | I/O 또는 unreclaimable memory | [[#2. reclaim 실패 경계]] |
| swap·PSI가 함께 증가 | swap delta와 stall 창 | swap 지연 런북 | [[#3. 사건 journal과 시계열]] |
| 현재 정상, 과거 alert만 존재 | bounded journal·승인 metrics retention | 증거 공백 또는 과거 사건 | [[#3. 사건 journal과 시계열]] |

## 1. 현재 snapshot과 counter delta

각 명령은 fresh host gate를 직접 수행한다. 빈 필드나 명령 실패는 정상값 0이 아니다.

```bash
SNAPSHOT_READY=false; DELTA_READY=false; EVIDENCE_READY=false; QUERY_READY=false; MUTATION_READY=false; ROLLBACK_READY=false; NORMALIZATION_READY=false; unset APPROVED_METRICS_PROVIDER INSTANCE INSTANCE_RE METRICS_RELATION_ID; if [ "$HOST_READY" != true ]; then printf '%s\n' '중단: HOST_READY가 아니다.' >&2; else ssh "${SSH_OPTS[@]}" -- "$APPROVED_HOST" bash -s -- "$MACHINE_ID" "$BOOT_ID" "$MOUNT_ID" "$MEM_RE" <<'REMOTE'
set -euo pipefail
[ "$(cat /etc/machine-id)" = "$1" ] && [ "$(cat /proc/sys/kernel/random/boot_id)" = "$2" ] && [ "$(stat -Lc %i /proc/1/ns/mnt)" = "$3" ] || exit 40
for key in MemTotal MemAvailable Dirty Writeback; do grep -q "^$key:" /proc/meminfo || exit 41; done
grep -q '^pgscan' /proc/vmstat && grep -q '^pgsteal' /proc/vmstat && grep -q '^allocstall' /proc/vmstat || exit 42
date -u '+observed=%Y-%m-%dT%H:%M:%SZ'
grep -E "$4" /proc/meminfo
grep -E '^(pgscan|pgsteal|allocstall|pswpin|pswpout)' /proc/vmstat
if [ -r /proc/pressure/memory ]; then cat /proc/pressure/memory; else printf '%s\n' 'PSI=unavailable'; fi
REMOTE
rc=$?; if [ "$rc" -eq 0 ]; then SNAPSHOT_READY=true; printf '%s\n' 'SNAPSHOT_READY=true'; else unset SNAPSHOT_READY; SNAPSHOT_READY=false; printf '중단: snapshot 실패 rc=%s\n' "$rc" >&2; fi; fi
```

두 sample은 같은 `MACHINE_ID`·`BOOT_ID`에서 수집한다. 첫 sample 이전의 누적값은 사건 시각으로 해석하지 않는다.

```bash
DELTA_READY=false; if [ "$SNAPSHOT_READY" != true ]; then printf '%s\n' '중단: SNAPSHOT_READY가 아니다.' >&2; else ssh "${SSH_OPTS[@]}" -- "$APPROVED_HOST" bash -s -- "$MACHINE_ID" "$BOOT_ID" "$MOUNT_ID" <<'REMOTE'
set -euo pipefail
[ "$(cat /etc/machine-id)" = "$1" ] && [ "$(cat /proc/sys/kernel/random/boot_id)" = "$2" ] && [ "$(stat -Lc %i /proc/1/ns/mnt)" = "$3" ] || exit 40
for n in 1 2; do grep -q '^pgscan' /proc/vmstat && grep -q '^pgsteal' /proc/vmstat && grep -q '^allocstall' /proc/vmstat || exit 41; date -u '+sample=%Y-%m-%dT%H:%M:%SZ'; grep -E '^(pgscan|pgsteal|allocstall|pswpin|pswpout)' /proc/vmstat; [ "$n" -eq 1 ] && sleep 5; done
REMOTE
rc=$?; if [ "$rc" -eq 0 ]; then DELTA_READY=true; printf '%s\n' 'DELTA_READY=true'; else unset DELTA_READY; DELTA_READY=false; printf '중단: delta 수집 실패 rc=%s\n' "$rc" >&2; fi; fi
```

성공 gate는 두 timestamp와 동일 counter key가 모두 존재하는 것이다. `pgscan`과 `pgsteal` delta가 함께 양수면 reclaim 진행, scan만 크고 `allocstall`도 증가하면 직접 reclaim·효율 저하 후보이다. 5초 표본은 장기 지속을 보장하지 않는다.

## 2. reclaim 실패 경계

`Dirty`·`Writeback` 증가가 있으면 backing filesystem I/O와 같은 창을 대조한다. `SUnreclaim` 증가는 kernel memory 후보지만 leak을 단독 확정하지 않는다. `MemAvailable` 저하, 낮은 steal/scan 비율, allocstall 또는 PSI가 같은 boot·창에 연결되어야 pressure evidence가 된다. `/proc` field 부재는 `unavailable`이며 0이 아니다.

## 3. 사건 journal과 시계열

journal은 먼저 파일로 완전 수집 성공을 확인한 뒤 filter한다. 이렇게 producer인 `journalctl` 실패와 filter의 no-match를 분리한다.

```bash
JOURNAL_READY=false; if [ "$HOST_READY" != true ] || [ "$START_EPOCH" -ge "$END_EPOCH" ]; then printf '%s\n' '중단: host/time gate 실패' >&2; else ssh "${SSH_OPTS[@]}" -- "$APPROVED_HOST" bash -s -- "$MACHINE_ID" "$BOOT_ID" "$MOUNT_ID" "$START_RFC3339" "$END_RFC3339" <<'REMOTE'
set -euo pipefail
[ "$(cat /etc/machine-id)" = "$1" ] && [ "$(cat /proc/sys/kernel/random/boot_id)" = "$2" ] && [ "$(stat -Lc %i /proc/1/ns/mnt)" = "$3" ] || exit 40
tmp=$(mktemp); trap 'rm -f "$tmp"' EXIT
journalctl -k --since "$4" --until "$5" --utc --no-pager >"$tmp"
if grep -E -i -C 3 'oom-kill|out of memory|page allocation failure|direct reclaim|kswapd|writeback' "$tmp"; then :; else grc=$?; [ "$grc" -eq 1 ] || exit "$grc"; printf '%s\n' 'FILTER_MATCH=none; 원문 수집 성공, 해당 문자열 없음'; tail -n 50 "$tmp"; fi
REMOTE
rc=$?; if [ "$rc" -eq 0 ]; then JOURNAL_READY=true; printf '%s\n' 'JOURNAL_READY=true'; else unset JOURNAL_READY; JOURNAL_READY=false; printf '중단: journal 수집 실패 rc=%s\n' "$rc" >&2; fi; fi
```

no-match는 OOM·reclaim 부재의 성공이 아니다. 시간창, boot, journal retention과 producer 성공만 확인한다. 토큰·개인정보·키가 보이면 저장을 중단하고 시각·오류 유형만 비식별화한다.

Prometheus를 사용할 때만 실제 provider와 이 host를 가리키는 `instance` label을 운영자가 선택한다. 이름을 추측하거나 빈 결과를 0으로 바꾸지 않는다.

`QUERY_READY=false; MUTATION_READY=false; ROLLBACK_READY=false; NORMALIZATION_READY=false; unset APPROVED_METRICS_PROVIDER INSTANCE INSTANCE_RE METRICS_RELATION_ID; read -r -p '승인 metrics provider: ' APPROVED_METRICS_PROVIDER; read -r -p '이 host의 exact instance label: ' INSTANCE; read -r -p 'instance와 current machine-id의 승인 relation ID: ' METRICS_RELATION_ID; if [ "$HOST_READY" = true ] && [ "$SNAPSHOT_READY" = true ] && [ -n "$APPROVED_METRICS_PROVIDER" ] && [[ "$INSTANCE" =~ ^[A-Za-z0-9._:/-]+$ ]] && [ -n "$METRICS_RELATION_ID" ]; then INSTANCE_RE="$(printf '%s' "$INSTANCE" | sed 's/[][\\.^$*+?(){}|]/\\&/g')"; QUERY_READY=true; printf 'QUERY_READY=true provider=%s machine=%s relation=%s INSTANCE_RE=^%s$\n' "$APPROVED_METRICS_PROVIDER" "$MACHINE_ID" "$METRICS_RELATION_ID" "$INSTANCE_RE"; else unset APPROVED_METRICS_PROVIDER INSTANCE INSTANCE_RE METRICS_RELATION_ID; printf '%s\n' '중단: current host snapshot/provider/instance relation이 준비되지 않았다.' >&2; fi`

`if [ "$HOST_READY" = true ] && [ "$SNAPSHOT_READY" = true ] && [ "$QUERY_READY" = true ] && [ -n "$METRICS_RELATION_ID" ]; then printf '100*node_memory_MemAvailable_bytes{instance=~"^%s$"}/node_memory_MemTotal_bytes{instance=~"^%s$"}\nrate(node_vmstat_pgscan_kswapd{instance=~"^%s$"}[5m])+rate(node_vmstat_pgscan_direct{instance=~"^%s$"}[5m])\nrate(node_pressure_memory_stalled_seconds_total{instance=~"^%s$"}[5m])\n' "$INSTANCE_RE" "$INSTANCE_RE" "$INSTANCE_RE" "$INSTANCE_RE" "$INSTANCE_RE"; else printf '%s\n' '중단: current HOST/SNAPSHOT/QUERY READY가 아니다.' >&2; fi`

쿼리 parser 성공, non-empty series, label의 host 관계, scrape timestamp가 모두 필요하다. metric 부재·collector 비활성·label 불일치·retention 밖·권한/API 실패를 각각 분리한다.

## 변경 분리와 정상화

이 문서의 명령은 읽기 전용이다. `drop_caches`, swap·sysctl·cgroup 변경, process kill, restart, reboot를 실행하지 않는다. 별도 변경은 매 시도마다 fresh host identity, 직접 evidence, 승인 ID, UTC 변경 window, workload quorum·대체 capacity, idempotence, 중단 조건과 구체적 rollback을 다시 확인한다. 서로 다른 변경을 한 승인으로 묶지 않는다.

재부팅·process/container 교체가 발생하면 이전 `BOOT_ID`, PID start, cgroup path·counter를 폐기하고 새 identity를 완전히 등록한 뒤 old->new `RELATION_ID`와 변경 근거를 남긴다. 수치 하락만으로 복구하지 않는다. 새 bounded 창에서 reclaim·allocstall·PSI·swap·dirty/writeback이 악화되지 않고 실제 영향 서비스의 지연·요청·데이터 작업이 회복되어야 한다.

## 증거와 완료 보고

host name·machine-id·boot-id·kernel·mount/net namespace inode, canonical UTC 창, meminfo, 두 sample의 vmstat delta, PSI, journal producer/filter 상태, provider·query·scrape 시각, 변경 승인과 실제 기능 결과를 보존한다. 전체 `/proc`, 전체 journal, Secret·token·개인정보는 저장하지 않는다.

환경별 미검증: kernel counter, PSI, journal retention, SSH trust, metrics provider와 label. 문서 작성 중 infrastructure 명령은 실행하지 않았다.
