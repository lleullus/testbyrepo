# kernel system OOM에 Killed process가 기록된 경우

## 입력값과 빠른 수집

| 구분 | 값 | 출처와 gate |
|---|---|---|
| 최초 입력 | `APPROVED_HOST`, `START_RFC3339`, `END_RFC3339` | 승인된 SSH host와 사건 창 |
| 시스템 자동값 | `MACHINE_ID`, `BOOT_ID`, `KERNEL_RELEASE`, host mount/net namespace inode | 실제 원격 host에서 등록 |
| 계산 후보값 | UTC epoch, `OOM_RE` | canonical roundtrip·bounded 출력 뒤 사용 |
| 운영자 선택값 | `VICTIM_PID`, 승인 metrics provider·`INSTANCE` | journal의 정확한 victim 행 또는 실제 provider를 본 뒤 선택 |

경로는 `operator Bash -> SSH -> 승인 Linux host의 host namespaces -> kernel journal -> 필요 시 현재 /proc/PID`다. `Killed process`의 PID는 이미 재사용됐거나 사라졌을 수 있다. 현재 PID의 start tick·executable·cgroup이 사건 victim과 같다는 관계가 입증되지 않으면 현재 process 정보를 과거 victim에 붙이지 않는다.

`unset INPUT_READY HOST_READY JOURNAL_READY SELECTION_READY AUTHORIZATION_READY EVIDENCE_READY VICTIM_READY QUERY_READY MUTATION_READY ROLLBACK_READY NORMALIZATION_READY APPROVED_HOST START_RFC3339 END_RFC3339 START_EPOCH END_EPOCH HOSTNAME_ACTUAL MACHINE_ID BOOT_ID KERNEL_RELEASE MOUNT_ID NETNS_ID OOM_EVENT_RFC3339 OOM_EVENT_EPOCH VICTIM_PID APPROVED_METRICS_PROVIDER INSTANCE INSTANCE_RE METRICS_RELATION_ID OOM_RE RFC3339_RE; IFS=$'\t' read -r APPROVED_HOST START_RFC3339 END_RFC3339 <<< $'PASTE_TAB_SEPARATED_HOST_START_END_HERE'; INPUT_READY=false; RFC3339_RE='^[0-9]{4}-(0[1-9]|1[0-2])-([0-2][0-9]|3[01])T([01][0-9]|2[0-3]):[0-5][0-9]:[0-5][0-9]Z$'; if [[ "$APPROVED_HOST" =~ ^[A-Za-z0-9._:-]+$ ]] && [[ "$START_RFC3339" =~ $RFC3339_RE ]] && [[ "$END_RFC3339" =~ $RFC3339_RE ]] && SC="$(date -u -d "$START_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" && EC="$(date -u -d "$END_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" && [ "$SC" = "$START_RFC3339" ] && [ "$EC" = "$END_RFC3339" ]; then START_EPOCH="$(date -u -d "$START_RFC3339" +%s)"; END_EPOCH="$(date -u -d "$END_RFC3339" +%s)"; if [ "$START_EPOCH" -lt "$END_EPOCH" ]; then SSH_OPTS=(-o BatchMode=yes -o ConnectTimeout=10); OOM_RE='oom-kill|out of memory|killed process|invoked oom-killer|constraint=|task_memcg|memory cgroup'; INPUT_READY=true; printf 'INPUT_READY=true host=%s window=%s/%s OOM_RE=%s\n' "$APPROVED_HOST" "$START_RFC3339" "$END_RFC3339" "$OOM_RE"; fi; fi; if [ "$INPUT_READY" != true ]; then unset APPROVED_HOST START_RFC3339 END_RFC3339 START_EPOCH END_EPOCH OOM_RE SSH_OPTS; printf '%s\n' '중단: 입력 또는 canonical UTC 창 오류' >&2; fi`

```bash
HOST_READY=false; JOURNAL_READY=false; SELECTION_READY=false; AUTHORIZATION_READY=false; EVIDENCE_READY=false; VICTIM_READY=false; QUERY_READY=false; MUTATION_READY=false; ROLLBACK_READY=false; NORMALIZATION_READY=false; unset HOSTNAME_ACTUAL MACHINE_ID BOOT_ID KERNEL_RELEASE MOUNT_ID NETNS_ID REC OOM_EVENT_RFC3339 OOM_EVENT_EPOCH VICTIM_PID APPROVED_METRICS_PROVIDER INSTANCE INSTANCE_RE METRICS_RELATION_ID; if [ "$INPUT_READY" != true ]; then printf '%s\n' '중단: INPUT_READY가 아니다.' >&2; else if REC="$(ssh "${SSH_OPTS[@]}" -- "$APPROVED_HOST" 'set -eu; printf "%s\t%s\t%s\t%s\t%s\t%s\n" "$(hostname -f 2>/dev/null || hostname)" "$(cat /etc/machine-id)" "$(cat /proc/sys/kernel/random/boot_id)" "$(uname -r)" "$(stat -Lc %i /proc/1/ns/mnt)" "$(stat -Lc %i /proc/1/ns/net)"')" && IFS=$'\t' read -r HOSTNAME_ACTUAL MACHINE_ID BOOT_ID KERNEL_RELEASE MOUNT_ID NETNS_ID <<< "$REC" && [ -n "$HOSTNAME_ACTUAL" ] && [ -n "$KERNEL_RELEASE" ] && [[ "$MACHINE_ID" =~ ^[0-9a-fA-F]{32}$ ]] && [[ "$BOOT_ID" =~ ^[0-9a-fA-F-]{36}$ ]] && [[ "$MOUNT_ID" =~ ^[0-9]+$ ]] && [[ "$NETNS_ID" =~ ^[0-9]+$ ]]; then HOST_READY=true; printf 'HOST_READY=true host=%s machine=%s boot=%s kernel=%s mntns=%s netns=%s\n' "$HOSTNAME_ACTUAL" "$MACHINE_ID" "$BOOT_ID" "$KERNEL_RELEASE" "$MOUNT_ID" "$NETNS_ID"; else unset HOSTNAME_ACTUAL MACHINE_ID BOOT_ID KERNEL_RELEASE MOUNT_ID NETNS_ID REC; printf '%s\n' '중단: host identity 실패' >&2; fi; fi
```

모든 SSH 명령은 strict allowlist 대상과 고정 script를 사용한다. 전달값은 검증된 hex·UUID·정수·canonical UTC뿐이며 `eval`, 동적 remote command, shell interpolation을 사용하지 않는다.

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | 같은 boot의 kernel journal에 OOM context와 `Killed process`가 직접 존재 |
| 적용 | constraint·victim PID/name·`task_memcg`·시각 관계를 bounded 창에서 판정 가능 |
| 제외 | `CONSTRAINT_MEMCG`가 직접 확인되면 [[03. container cgroup에 OOM event가 증가한 경우]]로 이동 |

검색 문자열: `CONSTRAINT_NONE`, `CONSTRAINT_MEMCG`, `Killed process`, `task_memcg`, `oom_score_adj`, `Memory cgroup out of memory`.

## 관측별 진단 경로

| 지금 보이는 것 | 먼저 볼 것 | 다음 판단 | 상세 절 |
|---|---|---|---|
| `CONSTRAINT_NONE` + victim | 같은 사건의 allocation·memory 문맥 | global OOM 확인 후보 | [[#1. bounded kernel evidence]] |
| `CONSTRAINT_MEMCG` | 정확한 `task_memcg`와 cgroup event | memcg 런북 이관 | [[#2. constraint와 victim lifecycle]] |
| victim 행만 존재 | 앞선 producer 원문·보존 범위 | 원인 미확정 | [[#1. bounded kernel evidence]] |
| 현재 같은 PID가 존재 | start tick·exe·cgroup | 과거와 별 identity | [[#2. constraint와 victim lifecycle]] |

## 1. bounded kernel evidence

```bash
JOURNAL_READY=false; EVIDENCE_READY=false; VICTIM_READY=false; QUERY_READY=false; MUTATION_READY=false; ROLLBACK_READY=false; NORMALIZATION_READY=false; unset OOM_EVENT_RFC3339 OOM_EVENT_EPOCH VICTIM_PID APPROVED_METRICS_PROVIDER INSTANCE INSTANCE_RE METRICS_RELATION_ID; if [ "$HOST_READY" != true ] || [ "$START_EPOCH" -ge "$END_EPOCH" ]; then printf '%s\n' '중단: host/time gate 실패' >&2; else JOUT="$(ssh "${SSH_OPTS[@]}" -- "$APPROVED_HOST" bash -s -- "$MACHINE_ID" "$BOOT_ID" "$MOUNT_ID" "$START_RFC3339" "$END_RFC3339" "$OOM_RE" <<'REMOTE'
set -euo pipefail
[ "$(cat /etc/machine-id)" = "$1" ] && [ "$(cat /proc/sys/kernel/random/boot_id)" = "$2" ] && [ "$(stat -Lc %i /proc/1/ns/mnt)" = "$3" ] || exit 40
tmp=$(mktemp); trap 'rm -f "$tmp"' EXIT
journalctl -k --since "$4" --until "$5" --utc --no-pager >"$tmp"
if grep -E -i -C 5 "$6" "$tmp"; then printf '%s\n' 'FILTER_MATCH=found'; else grc=$?; [ "$grc" -eq 1 ] || exit "$grc"; printf '%s\n' 'FILTER_MATCH=none; producer 성공, OOM 문자열 없음'; tail -n 50 "$tmp"; fi
REMOTE
 )"; rc=$?; if [ "$rc" -eq 0 ]; then printf '%s\n' "$JOUT"; JOURNAL_READY=true; if [[ "$JOUT" == *'FILTER_MATCH=found'* ]]; then EVIDENCE_READY=true; fi; printf 'JOURNAL_READY=true EVIDENCE_READY=%s\n' "$EVIDENCE_READY"; else unset JOUT OOM_EVENT_RFC3339 OOM_EVENT_EPOCH VICTIM_PID; VICTIM_READY=false; EVIDENCE_READY=false; JOURNAL_READY=false; printf '중단: journal 실패 rc=%s\n' "$rc" >&2; fi; fi
```

`journalctl` 성공과 grep match를 분리했다. no-match·빈 journal은 OOM 부재가 아니다. boot mismatch, retention, forwarding, clock 기준을 확인한다. 민감정보가 보이면 원문 저장을 중단하고 결정적 시각·constraint·비식별 victim만 남긴다.

## 2. constraint와 victim lifecycle

`CONSTRAINT_NONE`과 같은 사건의 `Killed process`가 있으면 global OOM을 지지한다. victim이 container cgroup에 있어도 global OOM이 선택할 수 있다. `CONSTRAINT_MEMCG` 또는 `Memory cgroup out of memory`와 같은 시각·경로가 있으면 memcg 경로다. 두 사건이 한 창에 공존하면 행별 timestamp로 별도 사건 관계를 만든다.

현재 PID를 조사할 때만 journal의 정확한 사건 시각과 victim 숫자를 입력한다. 사건 시각은 입력 창 안의 canonical UTC여야 하며, filter no-match에서는 선택 gate가 열리지 않는다.

`SELECTION_READY=false; VICTIM_READY=false; QUERY_READY=false; MUTATION_READY=false; ROLLBACK_READY=false; NORMALIZATION_READY=false; unset OOM_EVENT_RFC3339 OOM_EVENT_EPOCH VICTIM_PID; read -r -p 'journal의 exact OOM event UTC RFC3339: ' OOM_EVENT_RFC3339; read -r -p '같은 event의 exact victim PID(현재 생존 확인 시만): ' VICTIM_PID; if [ "$HOST_READY" = true ] && [ "$JOURNAL_READY" = true ] && [ "$EVIDENCE_READY" = true ] && [[ "$OOM_EVENT_RFC3339" =~ $RFC3339_RE ]] && [ "$(date -u -d "$OOM_EVENT_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" = "$OOM_EVENT_RFC3339" ] && OOM_EVENT_EPOCH="$(date -u -d "$OOM_EVENT_RFC3339" +%s)" && [ "$OOM_EVENT_EPOCH" -ge "$START_EPOCH" ] && [ "$OOM_EVENT_EPOCH" -le "$END_EPOCH" ] && [[ "$VICTIM_PID" =~ ^[1-9][0-9]*$ ]]; then SELECTION_READY=true; VICTIM_READY=true; printf 'SELECTION_READY=true VICTIM_READY=true event=%s pid=%s\n' "$OOM_EVENT_RFC3339" "$VICTIM_PID"; else unset OOM_EVENT_RFC3339 OOM_EVENT_EPOCH VICTIM_PID; printf '%s\n' '중단: current journal evidence, event time 또는 PID gate 오류' >&2; fi`

```bash
if [ "$HOST_READY" != true ] || [ "$JOURNAL_READY" != true ] || [ "$EVIDENCE_READY" != true ] || [ "$SELECTION_READY" != true ] || [ "$VICTIM_READY" != true ]; then printf '%s\n' '중단: current host/journal/evidence/selection/victim gate가 아니다.' >&2; else ssh "${SSH_OPTS[@]}" -- "$APPROVED_HOST" bash -s -- "$MACHINE_ID" "$BOOT_ID" "$MOUNT_ID" "$VICTIM_PID" <<'REMOTE'
set -euo pipefail
[ "$(cat /etc/machine-id)" = "$1" ] && [ "$(cat /proc/sys/kernel/random/boot_id)" = "$2" ] && [ "$(stat -Lc %i /proc/1/ns/mnt)" = "$3" ] || exit 40
pid=$4
if [ ! -r "/proc/$pid/stat" ]; then printf 'pid=%s current=absent\n' "$pid"; exit 3; fi
start=$(cut -d ' ' -f 22 "/proc/$pid/stat")
exe=$(readlink "/proc/$pid/exe")
sed -n '1,20p' "/proc/$pid/cgroup"
REMOTE
rc=$?; if [ "$rc" -ne 0 ]; then unset VICTIM_PID PID_START PID_EXE CGROUP_PATH RELATION_ID; VICTIM_READY=false; printf '중단: 현재 PID identity를 사건 victim과 연결할 수 없음 rc=%s\n' "$rc" >&2; fi; fi
```

현재 PID가 존재해도 journal에 PID start가 없으면 동일 process를 증명하지 못한다. 사건 후 재부팅은 `BOOT_ID`가 달라 관계가 끊긴다. executable name 일치도 충분하지 않다.

## 안전한 시계열 쿼리

`QUERY_READY=false; MUTATION_READY=false; ROLLBACK_READY=false; NORMALIZATION_READY=false; unset APPROVED_METRICS_PROVIDER INSTANCE INSTANCE_RE METRICS_RELATION_ID; read -r -p '승인 metrics provider: ' APPROVED_METRICS_PROVIDER; read -r -p 'exact instance label: ' INSTANCE; read -r -p 'instance와 current machine-id의 승인 relation ID: ' METRICS_RELATION_ID; if [ "$HOST_READY" = true ] && [ "$JOURNAL_READY" = true ] && [ -n "$APPROVED_METRICS_PROVIDER" ] && [[ "$INSTANCE" =~ ^[A-Za-z0-9._:/-]+$ ]] && [ -n "$METRICS_RELATION_ID" ]; then INSTANCE_RE="$(printf '%s' "$INSTANCE" | sed 's/[][\\.^$*+?(){}|]/\\&/g')"; QUERY_READY=true; printf 'QUERY_READY=true provider=%s machine=%s relation=%s INSTANCE_RE=^%s$\n' "$APPROVED_METRICS_PROVIDER" "$MACHINE_ID" "$METRICS_RELATION_ID" "$INSTANCE_RE"; else unset APPROVED_METRICS_PROVIDER INSTANCE INSTANCE_RE METRICS_RELATION_ID; printf '%s\n' '중단: current host/journal/provider/instance relation 미확정' >&2; fi`

`if [ "$HOST_READY" = true ] && [ "$JOURNAL_READY" = true ] && [ "$QUERY_READY" = true ] && [ -n "$METRICS_RELATION_ID" ]; then printf 'increase(node_vmstat_oom_kill{instance=~"^%s$"}[%ss])\nmin_over_time(node_memory_MemAvailable_bytes{instance=~"^%s$"}[%ss])\nrate(node_pressure_memory_stalled_seconds_total{instance=~"^%s$"}[5m])\n' "$INSTANCE_RE" "$((END_EPOCH-START_EPOCH))" "$INSTANCE_RE" "$((END_EPOCH-START_EPOCH))" "$INSTANCE_RE"; else printf '%s\n' '중단: current HOST/JOURNAL/QUERY READY가 아니다.' >&2; fi`

provider parser/API 성공, non-empty series, exact instance-to-machine 관계와 scrape timestamp가 필요하다. metric은 victim·constraint를 제공하지 않으므로 kernel evidence를 대체하지 않는다.

## 변경 분리·정상화·증거

이 문서는 읽기 전용이다. `drop_caches`, kill, limit·swap 변경, restart, reboot를 제공하지 않는다. 별도 변경마다 fresh machine/boot/target identity, 직접 evidence, 승인 ID, canonical UTC window, quorum·대체 capacity, idempotence, 중단과 rollback을 독립적으로 확인한다. 변경을 묶지 않는다.

교체·재부팅 후에는 새 machine/boot, PID start, cgroup/mount namespace를 완전히 재등록하고 old->new 관계를 승인 기록으로 연결한다. 새 OOM 행이 없는 것만으로 정상화하지 않는다. memory/PSI 안정, 영향 프로세스의 실제 요청·데이터 기능, 재발 관찰 창이 모두 필요하다.

보존: host identity, kernel release, UTC 창, journal producer/filter status, constraint·victim·task_memcg, 현재 PID identity의 한계, provider/query timestamp, 변경·rollback·기능 검증. 환경별 미검증은 kernel log 형식, retention, metrics source다. infrastructure 명령은 문서 작성 중 실행하지 않았다.
