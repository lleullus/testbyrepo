# 호스트에서 systemd service가 inactive·failed인 경우

## 입력값과 빠른 수집

| 구분 | 값 | 출처와 gate |
|---|---|---|
| 최초 입력 | `INPUT_NODE`, `INPUT_UNIT` | 사건 기록의 exact Node와 systemd unit 이름 |
| API/host 확인 자동값 | `NODE_UID`, `NODE_RV`, `NODE_MACHINE_ID`, `UNIT_ID`, `UNIT_FRAGMENT`, `MAIN_PID`, `MAIN_PID_START`, `INVOCATION_ID` | current Node API와 승인 host의 active systemd |
| 계산 후보값 | `UNIT_RE`, `ARGV_RE` | unit literal regex escape, bounded 출력 전 미확정 |
| 운영자 선택값 | `APPROVED_HOST`, `START_RFC3339`, `END_RFC3339` | node inventory와 장애 전후 UTC 창 |

경로는 `작업 PC/bastion -> 승인 SSH endpoint -> 실제 host identity -> PID 1 systemd -> exact unit -> ExecStart process -> host dependency/equipment`다. Kubernetes 영향은 별도 `kubectl -> API server -> Node UID -> Pod UID/owner` 경로로 본다. container, kubelet 또는 runtime unit이면 이 일반 service 런북에서 CRI endpoint를 추측하지 않고 전용 런북으로 이관한다.

### Node·unit refresh

refresh는 current IDs/RV/owners/container IDs/node·approved host/relations/time 파생값/argv-regex와 selection 이후 gate를 먼저 폐기한다. 입력 host는 `INPUT_APPROVED_HOST`로 보존하지 않으므로 selection을 다시 통과해야 하며, 실패 시 stale host도 남지 않는다.

```bash
refresh_unit() {
  local selected_host=${APPROVED_HOST:-} n remote uid rv machine remote_machine re
  unset AUTO_READY CANDIDATE_READY AUTH_READY EVIDENCE_READY MUTATION_READY ROLLBACK_READY NORMALIZATION_READY NODE_UID NODE_RV NODE_MACHINE_ID UNIT_ID UNIT_FRAGMENT MAIN_PID MAIN_PID_START INVOCATION_ID CURRENT_NODE APPROVED_HOST CONTAINER_IDS RELATIONS ARGV_RE UNIT_RE
  AUTO_READY=false
  CANDIDATE_READY=false
  [ "$INPUT_READY" = true ] && [ "$SELECTION_READY" = true ] && [ -n "$selected_host" ] || { printf '%s\n' '중단: 입력·selection이 fresh하지 않다.' >&2; return 1; }
  n=$(kubectl get node "$INPUT_NODE" -o json) || { printf '%s\n' 'producer 실패: Node API 조회 실패' >&2; return 1; }
  uid=$(jq -r '.metadata.uid // empty' <<<"$n")
  rv=$(jq -r '.metadata.resourceVersion // empty' <<<"$n")
  machine=$(jq -r '.status.nodeInfo.machineID // empty' <<<"$n")
  [ -n "$uid" ] && [ -n "$rv" ] && [[ "$machine" =~ ^[A-Fa-f0-9]{32}$ ]] || { printf '%s\n' 'filter 오류: Node/machine identity 누락' >&2; return 1; }
  remote=$(ssh -- "$selected_host" bash -s -- "$INPUT_NODE" "$INPUT_UNIT" "$machine" <<'REMOTE'
set -eu
expected_node=$1
unit=$2
expected_machine_id=$3
test "$(ps -p 1 -o comm= | tr -d ' ')" = systemd
command -v systemctl >/dev/null
command -v journalctl >/dev/null
remote_host=$(hostname -f 2>/dev/null || hostname)
actual_machine_id=$(tr -d '\n' </etc/machine-id)
[ "$actual_machine_id" = "$expected_machine_id" ]
props=$(systemctl show -- "$unit" -p Id -p LoadState -p ActiveState -p SubState -p Result -p MainPID -p InvocationID -p FragmentPath -p ExecMainCode -p ExecMainStatus)
main_pid=$(printf '%s\n' "$props" | sed -n 's/^MainPID=//p')
pid_start='-'
case $main_pid in ''|0) ;; *[!0-9]*) exit 1;; *) pid_start=$(sed -n 's/^[^)]*) \([^ ]* \)\{19\}\([^ ]*\).*/\2/p' "/proc/$main_pid/stat"); [ -n "$pid_start" ];; esac
printf 'remote-host=%s\nmachine-id=%s\nmain-pid-start=%s\nexpected-node=%s\n%s\n' "$remote_host" "$actual_machine_id" "$pid_start" "$expected_node" "$props"
REMOTE
) || { printf '%s\n' 'producer 실패: SSH/systemd/unit 조회 실패' >&2; return 1; }
  if grep -Fxq "Id=$INPUT_UNIT" <<<"$remote"; then
    :
  else
    grep_rc=$?
    if [ "$grep_rc" -eq 1 ]; then printf '%s\n' 'no match: exact unit identity 불일치' >&2; else printf 'filter 오류: unit identity grep 실패 rc=%s\n' "$grep_rc" >&2; fi
    return 1
  fi
  remote_machine=$(sed -n 's/^machine-id=//p' <<<"$remote")
  [ "$remote_machine" = "$machine" ] || { printf '%s\n' '중단: Node와 원격 /etc/machine-id 불일치' >&2; return 1; }
  re=$(printf '%s' "$INPUT_UNIT" | sed 's/[][\\.^$*+?(){}|]/\\&/g') || return 1
  NODE_UID=$uid
  NODE_RV=$rv
  NODE_MACHINE_ID=$machine
  CURRENT_NODE=$INPUT_NODE
  APPROVED_HOST=$selected_host
  UNIT_ID=$INPUT_UNIT
  UNIT_FRAGMENT=$(sed -n 's/^FragmentPath=//p' <<<"$remote")
  MAIN_PID=$(sed -n 's/^MainPID=//p' <<<"$remote")
  MAIN_PID_START=$(sed -n 's/^main-pid-start=//p' <<<"$remote")
  INVOCATION_ID=$(sed -n 's/^InvocationID=//p' <<<"$remote")
  UNIT_RE="^${re}$"
  ARGV_RE=$UNIT_RE
  RELATIONS="node:$NODE_UID@rv:$NODE_RV/machine:$NODE_MACHINE_ID->host:$APPROVED_HOST->unit:$UNIT_ID@invocation:${INVOCATION_ID:--}/pid:${MAIN_PID:-0}/start:${MAIN_PID_START:--}"
  AUTO_READY=true
  CANDIDATE_READY=true
  AUTH_READY=true
  printf 'AUTO_READY=true relation=%s regex=%s\n%s\n' "$RELATIONS" "$UNIT_RE" "$remote"
}
```

`refresh_unit`

SSH host와 unit은 allowlist 후 remote script positional argument로만 전달하며 `eval`하지 않는다. Node API의 machineID와 원격 `/etc/machine-id`가 exact match한 경우에만 `AUTH_READY=true`가 된다. hostname·address·providerID inventory도 함께 대조하며 불일치하면 host 명령을 더 실행하지 않는다.

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | exact unit의 `ActiveState=inactive/failed` 또는 `SubState=dead/failed`가 current invocation에서 관측된 경우 |
| 적용 | unit identity, invocation/MainPID, bounded journal과 host 영향이 연결되는 경우 |
| 제외 | dependency/start-limit/timeout은 각각 전용 systemd 런북, kubelet·runtime은 node/runtime 런북, Pod 자체 원인은 Pod 런북으로 이동 |

검색 문자열: `inactive`, `failed`, `Main process exited`, `Result=exit-code`, `permission denied`, `no such file`, `address already in use`, `no space left`, `oom-kill`, `start-limit`.

## 최초 확인과 journal

```bash
if [ "$AUTO_READY" != true ] || [ "$AUTH_READY" != true ]; then
  printf '%s\n' '중단: fresh unit/remote identity auth가 아니다.' >&2
elif ! CURRENT_NODE_JSON=$(kubectl get node "$CURRENT_NODE" -o json); then
  printf '%s\n' 'producer 실패: current Node 재조회 실패' >&2
elif [ "$(jq -r '.metadata.uid // empty' <<<"$CURRENT_NODE_JSON")" != "$NODE_UID" ] || [ "$(jq -r '.metadata.resourceVersion // empty' <<<"$CURRENT_NODE_JSON")" != "$NODE_RV" ] || [ "$(jq -r '.status.nodeInfo.machineID // empty' <<<"$CURRENT_NODE_JSON")" != "$NODE_MACHINE_ID" ]; then
  printf '%s\n' '중단: Node UID/resourceVersion/machineID가 바뀌었으므로 refresh_unit을 다시 실행한다.' >&2
elif ! ssh -- "$APPROVED_HOST" bash -s -- "$UNIT_ID" "$START_RFC3339" "$END_RFC3339" "$NODE_MACHINE_ID" "${INVOCATION_ID:--}" "${MAIN_PID:-0}" "${MAIN_PID_START:--}" <<'REMOTE'
set -eu
unit=$1
start=$2
end=$3
expected_machine_id=$4
expected_invocation=$5
expected_pid=$6
expected_pid_start=$7
actual_machine_id=$(tr -d '\n' </etc/machine-id)
[ "$actual_machine_id" = "$expected_machine_id" ]
props=$(systemctl show -- "$unit" -p Id -p LoadState -p ActiveState -p SubState -p Result -p MainPID -p InvocationID -p NRestarts -p ExecMainCode -p ExecMainStatus -p FragmentPath -p DropInPaths)
current_id=$(printf '%s\n' "$props" | sed -n 's/^Id=//p')
current_invocation=$(printf '%s\n' "$props" | sed -n 's/^InvocationID=//p')
current_pid=$(printf '%s\n' "$props" | sed -n 's/^MainPID=//p')
[ "$current_id" = "$unit" ]
[ "${current_invocation:--}" = "$expected_invocation" ]
[ "${current_pid:-0}" = "$expected_pid" ]
if [ "$current_pid" != 0 ]; then
  current_pid_start=$(sed -n 's/^[^)]*) \([^ ]* \)\{19\}\([^ ]*\).*/\2/p' "/proc/$current_pid/stat")
  [ "$current_pid_start" = "$expected_pid_start" ]
fi
printf '%s\n' "$props"
journal_file=$(mktemp)
trap 'rm -f "$journal_file"' EXIT
if ! journalctl -u "$unit" --since "$start" --until "$end" --no-pager -n 200 >"$journal_file"; then
  printf '%s\n' 'producer 실패: journal 조회 실패' >&2
  exit 1
elif [ ! -s "$journal_file" ]; then
  printf '%s\n' 'no match: 지정 시간 창에 journal 행이 없음'
else
  while IFS= read -r line; do printf '%s\n' "$line"; done <"$journal_file"
fi
REMOTE
then
  printf '%s\n' 'producer 실패 또는 current host/unit/process identity 불일치' >&2
fi
unset CURRENT_NODE_JSON
```

journal 원문에 환경·주소·token·개인정보가 보이면 저장을 중단하고 invocation ID, 시각과 결정적 오류만 비식별화한다. journal 명령 non-zero는 producer failure, 성공하지만 행 없음은 no match/retention 후보, 후속 `grep`의 exit 2는 filter error다. grep exit 1은 패턴 no match이며 오류 부재가 아니다. `ActiveState=inactive`는 crash를 단독 증명하지 않는다.

## 관측별 진단 경로

| 지금 보이는 것 | 먼저 볼 것 | 그다음 어디를 볼지 | 상세 절 |
|---|---|---|---|
| failed/non-zero status | 같은 InvocationID의 최초 오류 | ExecStart/dependency/path | [[#1. unit·host 경계]] |
| permission/path/socket/mount | FragmentPath와 실제 resource identity | filesystem/LSM/network owner | [[#1. unit·host 경계]] |
| OOM/no-space/I/O | 같은 UTC 창의 kernel·resource | Linux/storage equipment owner | [[#1. unit·host 경계]] |
| start/restart 필요 | fresh identity·승인·rollback | 별도 mutation | [[#2. 변경과 정상화]] |

### 1. unit·host 경계

`LoadState=not-found`는 unit 이름/배포 no match다. dependency 실패는 dependency 전용 런북, 반복 전환/NRestarts 증가는 start-limit 런북, timeout은 timeout 런북으로 넘긴다. path/socket/port는 journal에 실제 값이 있을 때만 `stat`, `namei`, `findmnt`, `ss`의 좁은 읽기 조회를 owner가 수행한다. 임의 `kill`, chmod, remount, fsck와 장비 조작을 하지 않는다. current `free/df`가 과거 OOM/no-space를 단독 증명하지 않는다.

Kubernetes Pod 영향은 exact Node field selector로 UID/owner/Ready만 조회한다. `kubectl auth can-i list pods --all-namespaces`의 yes와 실제 요청을 모두 확인하며 Forbidden과 empty를 구분한다. Secret/env/전체 Pod YAML과 cluster audit 원문은 수집하지 않는다. service가 kubelet/runtime이거나 container lifecycle 오류면 이 문서를 끝내고 전용 런북에서 active kubelet CRI endpoint와 exact container provider/id 관계를 새로 등록한다.

### 2. 변경과 정상화

start/restart/reset-failed/daemon-reload/enable, unit 수정, reboot는 진단과 분리한다. mutation 직전 `refresh_unit`으로 Node UID/RV, remote identity, exact unit·InvocationID/MainPID를 다시 확인하고 evidence ID, 승인 ID, 실행 window, service owner, workload/PDB/quorum, 장비 dependency와 영향 범위를 기록한다. start/restart 재실행의 멱등성, 외부 Job/message/API side effect와 중복 보상 방법을 확인한다. rollback은 이전 unit/drop-in/config artifact와 service 중단 복구 절차를 가리켜야 한다.

새 실패, NRestarts 증가, Node/Pod Ready 저하, quorum·실제 기능 악화가 stop 조건이다. 변경 후 이전 InvocationID/MainPID/container relation을 폐기하고 새 identity와 process relation을 refresh로 재등록한다.

정상화는 `unit Load/Active/SubState -> 새 InvocationID/MainPID 안정 -> bounded journal 오류 부재 -> host resource/dependency -> Node/Pod desired/Ready -> 실제 service 요청·Job 산출물`과 재발 관찰을 통과해야 한다. active 한 번이나 exit 0 한 번으로 닫지 않는다.

## 메트릭 사용 경계

`node_systemd_unit_state`의 `instance`가 Kubernetes Node name이나 machineID와 같다는 표준 계약은 없다. 따라서 이 문서는 범용 PromQL을 제공하지 않는다. exporter target과 `NODE_MACHINE_ID`의 exact mapping 및 systemd collector의 unit allowlist가 확인된 환경에서만 monitoring owner가 완성 query를 만들며, metric 부재를 unit active로 해석하지 않는다. metric은 InvocationID, MainPID start와 실제 기능도 증명하지 않는다.

## 증거·근거와 미검증

canonical UTC 창, Node UID/RV, approved host/remote identity, exact unit·fragment·InvocationID/MainPID, 비민감 종료/journal/resource 증거, 승인·rollback·replacement relation과 실제 기능만 보존한다. 전체 argv/env/journal, token, credential, 개인정보는 보존하지 않는다.
