# systemd service가 반복 재시작되고 start-limit에 도달한 경우

## 입력값과 빠른 수집

실행 경로는 `운영자 Bash -> 승인된 SSH endpoint -> /etc/machine-id와 boot ID -> PID 1 systemd -> exact service -> InvocationID와 PID/start ticks -> dependency`다. start-limit은 반복 기동을 막은 결과이지 최초 원인이 아니다.

| 종류 | 값 | 등록 기준 |
|---|---|---|
| 최초 입력 | `SSH_DEST`, `UNIT` | 승인된 SSH 목적지와 exact `.service` 이름 |
| host 자동값 | `MACHINE_ID`, `BOOT_ID`, `UNIT_ID`, `INVOCATION_ID`, `MAIN_PID`, `PID_START`, `UNIT_FRAGMENT` | refresh의 원격 exact 조회가 모두 성공한 뒤 등록 |
| 계산 후보값 | `UNIT_RE` | unit literal을 escape한 정규식, bounded 출력 전 미확정 |
| 운영자 선택값 | `EXPECTED_MACHINE_ID_INPUT`, `EXPECTED_BOOT_ID_INPUT`, `START_INPUT`, `END_INPUT` | 자산·boot 목록과 사건 기록에서 선택, refresh마다 canonical 검증 |

작업 PC 또는 bastion의 같은 Bash에서 실행한다. 로컬 변수가 SSH에 전달된다고 가정하지 않고 모든 원격 값은 positional argument로 전달한다. `eval`은 사용하지 않는다.

```bash
unset INPUT_READY TARGET_READY TIME_READY EVIDENCE_READY MUTATION_READY ROLLBACK_READY NORMALIZATION_READY MACHINE_ID BOOT_ID UNIT_ID INVOCATION_ID MAIN_PID PID_START UNIT_FRAGMENT UNIT_RE START_RFC3339 END_RFC3339 START_EPOCH END_EPOCH
SSH_DEST='PASTE_APPROVED_SSH_DEST_HERE'
UNIT='PASTE_EXACT_SERVICE_UNIT_HERE'
INPUT_READY=false
if [[ "$SSH_DEST" =~ ^[A-Za-z0-9][A-Za-z0-9._-]*(@[A-Za-z0-9][A-Za-z0-9._-]*)?$ && "$UNIT" =~ ^[A-Za-z0-9_.@:-]+\.service$ ]] && command -v ssh >/dev/null && command -v date >/dev/null && command -v sed >/dev/null && command -v grep >/dev/null; then INPUT_READY=true; fi
printf 'INPUT_READY=%s ssh=%s unit=%s\n' "$INPUT_READY" "$SSH_DEST" "$UNIT"
```

먼저 접속 후보의 identity만 읽고 자산 기록 및 사건의 boot와 대조한다.

```bash
if [[ "$INPUT_READY" == true ]]; then ssh -- "$SSH_DEST" bash -s <<'REMOTE'
set -eu
test -r /etc/machine-id
test -r /proc/sys/kernel/random/boot_id
pid1=$(ps -p 1 -o comm=); pid1=${pid1//[[:space:]]/}; test "$pid1" = systemd
printf 'host=%s\nmachine-id=%s\nboot-id=%s\n' "$(hostname -f 2>/dev/null || hostname)" "$(tr -d '\n' </etc/machine-id)" "$(tr -d '\n' </proc/sys/kernel/random/boot_id)"
journalctl --list-boots --no-pager
REMOTE
else printf '%s\n' '중단: INPUT_READY가 아니다.' >&2; fi
```

```bash
EXPECTED_MACHINE_ID_INPUT='PASTE_VERIFIED_MACHINE_ID_HERE'
EXPECTED_BOOT_ID_INPUT='PASTE_VERIFIED_BOOT_ID_HERE'
START_INPUT='PASTE_FIRST_CYCLE_START_UTC_RFC3339_HERE'
END_INPUT='PASTE_LAST_CYCLE_END_UTC_RFC3339_HERE'
```

### fresh target 등록

아래 함수는 호출할 때마다 identity, 시간, evidence, 변경·rollback·정상화 상태를 먼저 폐기한다. 조회가 부분 실패하면 과거 READY와 PID가 남지 않는다.

```bash
refresh_restart_target() {
  local out s e se ee re
  unset TARGET_READY TIME_READY EVIDENCE_READY MUTATION_READY ROLLBACK_READY NORMALIZATION_READY MACHINE_ID BOOT_ID UNIT_ID INVOCATION_ID MAIN_PID PID_START UNIT_FRAGMENT UNIT_RE START_RFC3339 END_RFC3339 START_EPOCH END_EPOCH
  TARGET_READY=false; TIME_READY=false; EVIDENCE_READY=false; MUTATION_READY=false; ROLLBACK_READY=false; NORMALIZATION_READY=false
  [[ "$INPUT_READY" == true ]] || { printf '%s\n' '중단: INPUT_READY가 아니다.' >&2; return 1; }
  [[ "$EXPECTED_MACHINE_ID_INPUT" =~ ^[0-9a-fA-F]{32}$ && "$EXPECTED_BOOT_ID_INPUT" =~ ^[0-9a-fA-F]{8}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{12}$ ]] || { printf '%s\n' '중단: machine/boot 선택값 형식 오류' >&2; return 1; }
  [[ "$START_INPUT" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ && "$END_INPUT" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] || { printf '%s\n' '중단: UTC RFC3339 형식 오류' >&2; return 1; }
  s=$(date -u -d "$START_INPUT" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null) && e=$(date -u -d "$END_INPUT" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null) && [[ "$s" == "$START_INPUT" && "$e" == "$END_INPUT" ]] || { printf '%s\n' '중단: UTC round-trip 실패' >&2; return 1; }
  se=$(date -u -d "$s" +%s) && ee=$(date -u -d "$e" +%s) && (( se < ee && ee <= $(date -u +%s) && ee - se <= 86400 )) || { printf '%s\n' '중단: start<end/future/24h 범위 실패' >&2; return 1; }
  out=$(ssh -- "$SSH_DEST" bash -s -- "$EXPECTED_MACHINE_ID_INPUT" "$EXPECTED_BOOT_ID_INPUT" "$UNIT" <<'REMOTE'
set -eu
expected_machine=$1; expected_boot=$2; unit=$3
test "$(tr -d '\n' </etc/machine-id)" = "$expected_machine"
test "$(tr -d '\n' </proc/sys/kernel/random/boot_id)" = "$expected_boot"
pid1=$(ps -p 1 -o comm=); pid1=${pid1//[[:space:]]/}; test "$pid1" = systemd
props=$(systemctl show -p Id -p LoadState -p ActiveState -p SubState -p Result -p NRestarts -p Restart -p RestartUSec -p StartLimitIntervalUSec -p StartLimitBurst -p ExecMainCode -p ExecMainStatus -p MainPID -p InvocationID -p FragmentPath -p DropInPaths -- "$unit")
printf 'machine-id=%s\nboot-id=%s\n%s\n' "$expected_machine" "$expected_boot" "$props"
pid=$(systemctl show --value -p MainPID -- "$unit")
if [[ "$pid" =~ ^[1-9][0-9]*$ && -r "/proc/$pid/stat" ]]; then stat=$(cat "/proc/$pid/stat"); rest=${stat##*) }; printf 'pid-start=%s\npid-ns=%s\nmnt-ns=%s\nnet-ns=%s\n' "$(cut -d' ' -f20 <<<"$rest")" "$(readlink "/proc/$pid/ns/pid")" "$(readlink "/proc/$pid/ns/mnt")" "$(readlink "/proc/$pid/ns/net")"; fi
REMOTE
  ) || { printf '%s\n' 'producer 실패: SSH/host/systemd 조회' >&2; return 1; }
  grep -Fxq "machine-id=$EXPECTED_MACHINE_ID_INPUT" <<<"$out" && grep -Fxq "boot-id=$EXPECTED_BOOT_ID_INPUT" <<<"$out" && grep -Fxq "Id=$UNIT" <<<"$out" || { printf '%s\n' 'no match: current identity 불일치' >&2; return 1; }
  MACHINE_ID=$EXPECTED_MACHINE_ID_INPUT; BOOT_ID=$EXPECTED_BOOT_ID_INPUT; UNIT_ID=$UNIT
  INVOCATION_ID=$(sed -n 's/^InvocationID=//p' <<<"$out"); MAIN_PID=$(sed -n 's/^MainPID=//p' <<<"$out"); PID_START=$(sed -n 's/^pid-start=//p' <<<"$out"); UNIT_FRAGMENT=$(sed -n 's/^FragmentPath=//p' <<<"$out")
  re=$(sed 's/[][\\.^$*+?(){}|]/\\&/g' <<<"$UNIT_ID") || return 1
  UNIT_RE="^${re}$"; START_RFC3339=$s; END_RFC3339=$e; START_EPOCH=$se; END_EPOCH=$ee
  TARGET_READY=true; TIME_READY=true
  printf 'TARGET_READY=true TIME_READY=true machine=%s boot=%s unit=%s invocation=%s pid=%s start_ticks=%s regex=%s\n' "$MACHINE_ID" "$BOOT_ID" "$UNIT_ID" "${INVOCATION_ID:--}" "${MAIN_PID:-0}" "${PID_START:--}" "$UNIT_RE"
  printf '%s\n' "$out"
}
```

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | 같은 machine·boot·unit에서 둘 이상의 start/exit cycle, `NRestarts` 증가 또는 `Result=start-limit-hit`가 보임 |
| 적용 | cycle별 UTC 시각, 최초 오류, exit와 restart scheduling을 한 창에서 복원 가능 |
| 제외 | 단일 실패는 [[01. 호스트에서 systemd service가 inactive·failed인 경우]], dependency는 [[03. systemd unit dependency 실패로 service가 시작되지 않는 경우]], timeout은 [[04. systemd service 시작·종료가 timeout에서 멈춘 경우]] |

검색 문자열: `Start request repeated too quickly`, `start-limit-hit`, `Scheduled restart job`, `Main process exited`, `Failed with result`.

## cycle 증거

먼저 `refresh_restart_target`을 실행한다. 다음 명령은 current machine·boot·unit을 원격 경계에서 다시 확인하고 producer와 filter 종료 상태를 분리한다.

```bash
EVIDENCE_READY=false; if [[ "$TARGET_READY" == true && "$TIME_READY" == true ]]; then if ssh -- "$SSH_DEST" bash -s -- "$MACHINE_ID" "$BOOT_ID" "$UNIT_ID" "$INVOCATION_ID" "$MAIN_PID" "$PID_START" "$START_RFC3339" "$END_RFC3339" <<'REMOTE'
set -u
expected_machine=$1; expected_boot=$2; unit=$3; expected_invocation=$4; expected_pid=$5; expected_pid_start=$6; start=$7; end=$8
[[ "$(tr -d '\n' </etc/machine-id)" == "$expected_machine" && "$(tr -d '\n' </proc/sys/kernel/random/boot_id)" == "$expected_boot" ]] || exit 10
[[ "$(systemctl show --value -p Id -- "$unit")" == "$unit" ]] || exit 11
[[ "$(systemctl show --value -p InvocationID -- "$unit")" == "$expected_invocation" && "$(systemctl show --value -p MainPID -- "$unit")" == "$expected_pid" ]] || exit 12
if [[ "$expected_pid" =~ ^[1-9][0-9]*$ ]]; then stat=$(cat "/proc/$expected_pid/stat") || exit 13; rest=${stat##*) }; [[ "$(cut -d' ' -f20 <<<"$rest")" == "$expected_pid_start" ]] || exit 14; fi
tmp=$(mktemp) || exit 12; trap 'rm -f "$tmp"' EXIT
journalctl --utc --boot="$expected_boot" -u "$unit" --since "$start" --until "$end" --no-pager -o short-iso-precise >"$tmp"; producer_rc=$?
printf 'producer_rc=%s\n' "$producer_rc"; (( producer_rc == 0 )) || exit 20
grep -E -i -C 2 'starting|started|scheduled restart job|main process exited|failed with result|start request repeated too quickly|start-limit|status=|dependency|permission denied|address already in use|oom|no space|i/o error|timeout' "$tmp"; filter_rc=$?
printf 'filter_rc=%s\n' "$filter_rc"
case $filter_rc in 0) exit 0;; 1) printf '%s\n' 'no match: 범위에 cycle 문자열 없음' >&2; exit 30;; *) printf '%s\n' 'filter 오류' >&2; exit 31;; esac
REMOTE
then EVIDENCE_READY=true; else printf '중단: evidence 수집 실패 rc=%s\n' "$?" >&2; fi; else printf '%s\n' '중단: fresh TARGET_READY/TIME_READY가 아니다.' >&2; fi; printf 'EVIDENCE_READY=%s\n' "$EVIDENCE_READY"
```

성공 gate는 같은 boot/unit에서 최소 두 cycle의 `start -> 최초 오류 -> exit -> scheduled restart` 순서 또는 선행 오류와 `start-limit-hit`가 함께 보이는 것이다. 필터 무결과는 오류 부재가 아니라 unit·boot·시간·보존 범위 미확정이다.

## 원인 확정과 변경 경계

start-limit 행만으로 원인을 확정하지 않는다. cycle마다 같은 최초 오류와 exit가 반복되거나 dependency/resource/kernel 직접 증거가 PID/start identity와 연결돼야 한다. PID가 바뀌거나 `/proc/$PID/stat` 조회가 실패하면 이전 process·namespace·cgroup evidence를 폐기하고 refresh한다. argv·environment·credential은 출력하지 않는다.

진단 중 `reset-failed`, `start`, `restart`, policy 완화, unit 편집과 `kill`을 실행하지 않는다. 별도 변경은 실행 직전 refresh를 다시 통과하고 current InvocationID/PID/start ticks, 원인 수정 evidence, 승인 ID, 변경 창, 가용성·quorum, 외부 API/Job side effect와 멱등성, 한 번만 실행할 명령, 중단 기준과 원본 rollback을 확인해야 `MUTATION_READY=true`다. rollback도 current unit identity와 승인된 원본을 재확인해야 `ROLLBACK_READY=true`다.

변경 후 기존 InvocationID/PID를 재사용하지 않는다. 모든 READY를 폐기하고 새 process를 refresh한다. 새 실패, restart 증가, 실제 기능 악화가 중단 조건이다.

## 정상화

새 canonical UTC 관찰 창을 `START_INPUT`, `END_INPUT`에 넣고 refresh와 cycle 증거를 다시 실행한다. 새 InvocationID/PID/start ticks가 안정되고 `NRestarts`가 증가하지 않으며 최초 오류와 start-limit이 재발하지 않아야 한다. dependency/resource가 정상이고 실제 client 요청·queue 처리·Job 산출물과 가용성 목표가 관찰 창 동안 유지될 때만 `NORMALIZATION_READY=true`로 기록한다. `active` 한 번, start-limit 표시 소거 또는 빈 filter는 정상화가 아니다.

## 증거와 미검증

machine/boot/unit, fragment/drop-in, InvocationID, PID/start ticks·namespace, restart policy, canonical UTC, producer/filter status, cycle별 최초 오류·exit, 승인·rollback과 실제 기능 결과만 보존한다. 전체 journal, argv/environment, token·credential·개인정보는 저장하지 않는다.
