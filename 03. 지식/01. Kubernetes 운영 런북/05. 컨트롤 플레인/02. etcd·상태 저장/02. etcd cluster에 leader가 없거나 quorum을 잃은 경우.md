# etcd cluster에 leader가 없거나 quorum을 잃은 경우

## 입력값과 빠른 수집

실행 hop은 `승인된 작업 host의 Bash -> Kubernetes API static Pod mirror -> 현재 node와 일치하는 SSH host -> 확인된 etcd client endpoint -> 전체 member/peer`다. static Pod가 아닌 systemd·managed control plane이면 확인되지 않은 Pod, host, unit, endpoint를 만들지 않고 owner의 동등한 읽기 전용 경로로 이관한다.

| 종류 | 값 | gate |
|---|---|---|
| 최초 입력 | `NS`, `ETCD_POD` | 승인 inventory의 exact static Pod name |
| API 확인 자동값 | UID, RV, owner, node/systemUUID, containerID, creation time | Pod·Node API와 lifecycle 관계가 모두 성공할 때만 등록 |
| 계산 후보값 | etcd container, endpoint 목록, TLS/data-dir, `ARGV_RE` | argv strict extraction과 regex escape 뒤에도 후보로 취급 |
| 운영자 선택값 | SSH host, exact endpoint, UTC 창, Prometheus job, 승인 window | 현재 출력과 inventory를 대조한 뒤 선택 |

재등록 전 UID/RV/owner/containerID/node/host/member 관계/time/argv regex와 모든 downstream `READY`를 폐기한다. API 실패 후 이전 값을 사용하지 않는다.

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | 여러 endpoint health 실패, 응답 member 모두 `IS LEADER=false`, `no leader`, 정상 응답 voting member가 과반 미만 |
| 적용 | 승인된 전체 member ID/peer URL과 endpoint health/status를 같은 UTC 창에서 확인 가능 |
| 제외 | 한 endpoint만 실패하고 leader·과반이 유지되면 [[01. etcd endpoint health가 실패하거나 member가 Unhealthy인 경우]]. WAL/backend 지연·NOSPACE·CORRUPT는 각 문서로 이동 |

검색 문자열: `no leader`, `quorum`, `unhealthy cluster`, `lost the leader`, `rafthttp`, `election`, `heartbeat`, `failed to reach the peer URL`.

`IS LEADER=false`인 follower 하나는 정상일 수 있다. Kubernetes Pod 수나 `member list` 행 수만으로 quorum을 계산하지 않는다. 실제 응답하는 **voting member** 수와 승인된 cluster membership에서 `floor(voters/2)+1`을 대조한다.

## 보안·권한·runtime 경계

`fresh_target && kubectl auth can-i get pods -n "$NS" && kubectl auth can-i get pods/log -n "$NS" && kubectl auth can-i get nodes`

RBAC `Forbidden`, TLS read 실패, SSH 실패는 quorum 상실 증거가 아니다. 권한을 확대하거나 `--insecure-skip-tls-verify`를 쓰지 않는다. private key·Secret·token·audit body를 출력하지 않는다. Audit은 API storage timeout의 시각/verb/objectRef/response code만 승인된 경로에서 본다.

CRI는 이 consensus 문서의 직접 경로가 아니다. container lifecycle 오류가 직접 보일 때만 runtime 런북으로 이관하며, 그곳에서 활성 kubelet runtime endpoint 단일 추출, exact match, runtime socket owner/type/permission을 확인한다. 기본 socket 추측은 금지한다.

`ETCD_READY=false; if [ "$HOST_READY" = true ] && fresh_remote; then ssh -T -- "$HOST" 'set -eu; e=$1; ca=$2; crt=$3; key=$4; command -v etcdctl >/dev/null; sudo -- test -r "$ca"; sudo -- test -r "$crt"; sudo -- test -r "$key"; sudo -- env ETCDCTL_API=3 etcdctl version' sh "$ENDPOINT" "$CA_FILE" "$CERT_FILE" "$KEY_FILE"; RC=$?; if [ "$RC" -eq 0 ]; then ETCD_READY=true; else printf '중단: preflight rc=%s\n' "$RC" >&2; fi; fi`

`if [ "$ETCD_READY" = true ] && fresh_remote; then ssh -T -- "$HOST" 'set -eu; e=$1; ca=$2; crt=$3; key=$4; sudo -- env ETCDCTL_API=3 etcdctl --endpoints="$e" --cacert="$ca" --cert="$crt" --key="$key" endpoint health --cluster' sh "$ENDPOINT" "$CA_FILE" "$CERT_FILE" "$KEY_FILE"; fi`

`if [ "$ETCD_READY" = true ] && fresh_remote; then ssh -T -- "$HOST" 'set -eu; e=$1; ca=$2; crt=$3; key=$4; sudo -- env ETCDCTL_API=3 etcdctl --endpoints="$e" --cacert="$ca" --cert="$crt" --key="$key" endpoint status --cluster -w table; sudo -- env ETCDCTL_API=3 etcdctl --endpoints="$e" --cacert="$ca" --cert="$crt" --key="$key" member list -w table; sudo -- env ETCDCTL_API=3 etcdctl --endpoints="$e" --cacert="$ca" --cert="$crt" --key="$key" alarm list' sh "$ENDPOINT" "$CA_FILE" "$CERT_FILE" "$KEY_FILE"; fi`

모든 의도 endpoint의 응답, member ID/name/peer/client URL, learner 여부, leader, raft term/index/applied를 연결한다. 명령 rc 실패나 빈 출력은 정상 member가 아니다. `NOSPACE`·`CORRUPT`가 있으면 해당 런북으로 이동하되 leader/quorum은 별도 상태로 기록한다. endpoint 목록이 승인 inventory와 다르면 계산을 중단한다.

## canonical UTC 로그 창

`START_RFC3339='PASTE_START_UTC_RFC3339_HERE'; END_RFC3339='PASTE_END_UTC_RFC3339_HERE'; TIME_READY=false; R='^[0-9]{4}-(0[1-9]|1[0-2])-([0-2][0-9]|3[01])T([01][0-9]|2[0-3]):[0-5][0-9]:[0-5][0-9]Z$'; if [[ "$START_RFC3339" =~ $R ]] && [[ "$END_RFC3339" =~ $R ]]; then S="$(date -u -d "$START_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)"; SRC=$?; E="$(date -u -d "$END_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)"; ERC=$?; SE="$(date -u -d "$START_RFC3339" +%s 2>/dev/null)"; EE="$(date -u -d "$END_RFC3339" +%s 2>/dev/null)"; if [ "$SRC" -eq 0 ] && [ "$ERC" -eq 0 ] && [ "$S" = "$START_RFC3339" ] && [ "$E" = "$END_RFC3339" ] && [ "$SE" -lt "$EE" ]; then TIME_READY=true; export START_RFC3339 END_RFC3339; else printf '%s\n' '중단: UTC round-trip/start<end 실패' >&2; fi; else printf '%s\n' '중단: canonical UTC RFC3339 아님' >&2; fi`

`if [ "$TIME_READY" = true ] && fresh_target; then RAW="$(mktemp)"; WIN="$(mktemp)"; kubectl logs "$ETCD_POD" -n "$NS" -c "$ETCD_CONTAINER" --timestamps --since-time="$START_RFC3339" >"$RAW"; PRODUCER_RC=$?; if [ "$PRODUCER_RC" -eq 0 ]; then awk -v start="$START_RFC3339" -v end="$END_RFC3339" '$1>=start && $1<=end' "$RAW" >"$WIN"; WINDOW_RC=$?; if [ "$WINDOW_RC" -eq 0 ]; then grep -E -i -C 3 'no leader|lost the leader|leader changed|election|quorum|rafthttp|peer|heartbeat|timeout|unhealthy' "$WIN"; FILTER_RC=$?; printf 'producer_rc=%s window_rc=%s filter_rc=%s evidence=%s..%s\n' "$PRODUCER_RC" "$WINDOW_RC" "$FILTER_RC" "$START_RFC3339" "$END_RFC3339"; else printf '중단: window filter rc=%s\n' "$WINDOW_RC" >&2; fi; else printf '중단: log producer rc=%s\n' "$PRODUCER_RC" >&2; fi; rm -f "$RAW" "$WIN"; fi`

producer rc, window rc, filter rc를 각각 기록한다. filter rc `1`은 일치 없음이며 원인 부재가 아니다. 로그의 member ID/peer URL과 status가 같은 identity·창에서 맞아야 한다.

## 실행 가능한 Prometheus 쿼리

`[ "$ETCD_READY" = true ] && fresh_remote && [ "$QUERY_READY" = true ] && printf 'sum(etcd_server_is_leader{job=~"^%s$",instance=~"^%s$"})\n' "$JOB_RE" "$INSTANCE_RE"`

`[ "$ETCD_READY" = true ] && fresh_remote && [ "$QUERY_READY" = true ] && printf 'sum by(instance)(increase(etcd_server_leader_changes_seen_total{job=~"^%s$",instance=~"^%s$"}[15m])) > 0\n' "$JOB_RE" "$INSTANCE_RE"`

`[ "$ETCD_READY" = true ] && fresh_remote && [ "$QUERY_READY" = true ] && printf 'sum by(instance)(increase(etcd_server_heartbeat_send_failures_total{job=~"^%s$",instance=~"^%s$"}[15m])) > 0\n' "$JOB_RE" "$INSTANCE_RE"`

Prometheus HTTP status, `status=success`, non-empty data를 분리 검증한다. 빈 결과는 성공이 아니다. metric의 instance를 member ID/endpoint와 연결하지 못하면 quorum 증거로 채택하지 않는다.

## 상태 변경·replacement·정상화

이 문서는 restart, member remove/add, force-new-cluster, restore, data-dir 변경, alarm mutation 명령을 제공하지 않는다. 별도 변경은 **각 mutation 직전** fresh target/evidence, 승인 ID와 window, 현재 voting membership·leader·quorum, 검증된 snapshot source identity, 멱등성, 중단 조건과 실제 검증된 rollback/DR 절차를 다시 확인한다. quorum을 잃은 상태에서 직렬 작업이라는 이유만으로 안전하다고 보지 않는다.

controller replacement가 있는 경로는 selector+원 owner UID+controller UID+변경 이후 creationTimestamp+단일 후보를 모두 만족해야 한다. static Pod mirror/member replacement에는 selector를 억지 적용하지 않고 member ID/peer URL과 exact mirror identity를 사용한다. replacement 후 모든 identity·관계·time·regex·`READY`를 폐기하고 전체 재등록한다.

정상화는 승인 membership과 모든 endpoint health, 정확히 한 leader, 과반 voting member 응답, 진행하는 raft index, 안정된 peer/heartbeat, alarm 없음, API server readyz와 실제 승인 read/write 기능을 같은 관찰 창에서 확인한다. 쓰기 probe는 업무 멱등성과 정리/rollback이 승인된 기존 표면만 사용한다. Pod Running·leader 한 번·빈 metric은 정상화가 아니다.
