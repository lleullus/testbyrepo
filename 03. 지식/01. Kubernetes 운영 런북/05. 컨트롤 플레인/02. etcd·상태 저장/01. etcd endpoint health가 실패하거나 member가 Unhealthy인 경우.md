# etcd endpoint health가 실패하거나 member가 Unhealthy인 경우

## 입력값과 빠른 수집

이 절의 Kubernetes 명령은 승인된 작업 PC/bastion의 같은 Bash에서, etcdctl·filesystem 명령은 현재 Pod가 배치된 node와 일치함을 검증한 SSH host에서 실행한다. hop은 `작업 host -> Kubernetes API의 static Pod mirror -> 확인된 node/SSH host -> etcd client endpoint -> member/peer`다. managed control plane 또는 systemd 전용 배포이면 확인되지 않은 Pod·endpoint·unit을 추측하지 말고 제공자/etcd owner의 동등한 read-only 경로로 이관한다.

| 종류 | 값 | 등록 계약 |
|---|---|---|
| 최초 입력 | `NS`, `ETCD_POD` | 승인 inventory의 static Pod exact name. 한 번만 입력한다. |
| API 확인 자동값 | Pod UID/RV·owner·node·systemUUID·containerID·argv 관계 | 모든 API 호출과 단일 관계 검사가 성공할 때만 등록한다. |
| 계산 후보값 | container, endpoint, TLS path, data-dir, `ARGV_RE` | Pod argv에서 strict extraction하며 복수 endpoint는 자동 선택하지 않는다. |
| 운영자 선택값 | `HOST`, endpoint, UTC 증거 창, Prometheus job | 출력과 승인 inventory를 대조한 뒤 해당 gate에서만 선택한다. |

재등록 전 또는 API 실패 시 UID, RV, owner, containerID, node, host, endpoint/member 관계, 시간, argv 정규식과 모든 downstream `READY`를 폐기한다. stale 값으로 etcdctl·SSH·로그·metric 명령을 실행하지 않는다.

**Bash·필수 도구 확인**

TLS path는 경로만 보며 내용을 출력하지 않는다. endpoint가 여러 개면 실제 host에서 listen하는 client URL을 inventory와 대조해 한 개를 선택한다.

**SSH host·endpoint 선택과 remote identity 확인**

`HOST='PASTE_APPROVED_SSH_HOST_HERE'; ENDPOINT='PASTE_EXACT_CLIENT_ENDPOINT_HERE'; HOST_READY=false; if [ "$TARGET_READY" != true ]; then printf '%s\n' '중단: TARGET_READY가 아니다.' >&2; elif ! [[ "$HOST" =~ ^[A-Za-z0-9._:-]+$ ]]; then printf '%s\n' '중단: HOST 형식이 안전하지 않음' >&2; elif ! printf '%s\n' "${ENDPOINT_CANDIDATES[@]}" | grep -Fxq -- "$ENDPOINT"; then printf '%s\n' '중단: endpoint가 argv 후보와 exact match하지 않음' >&2; else REMOTE_UUID="$(ssh -T -- "$HOST" 'tr "[:upper:]" "[:lower:]" </sys/class/dmi/id/product_uuid' 2>/dev/null)"; SSH_RC=$?; if [ "$SSH_RC" -eq 0 ] && [ "$REMOTE_UUID" = "$NODE_SYSTEM_UUID" ]; then HOST_READY=true; export HOST ENDPOINT; printf 'HOST_READY=true host=%s remoteUUID=%s node=%s endpoint=%s\n' "$HOST" "$REMOTE_UUID" "$NODE" "$ENDPOINT"; else printf '중단: remote identity 불일치 ssh_rc=%s remote=%s expected=%s\n' "$SSH_RC" "${REMOTE_UUID:--}" "$NODE_SYSTEM_UUID" >&2; fi; fi`

Node API의 `machineID`와 원격 `/etc/machine-id`를 별도로 exact match한다. DMI UUID 확인 성공만으로 node 전용 명령을 실행하지 않는다.

`MACHINE_READY=false; NODE_MACHINE_ID=''; NODE_NOW="$(kubectl get node "$NODE" -o json)"; NODE_MACHINE_RC=$?; if [ "$NODE_MACHINE_RC" -eq 0 ]; then NODE_MACHINE_ID="$(jq -r '.status.nodeInfo.machineID // empty' <<<"$NODE_NOW")"; JQ_RC=$?; else JQ_RC=1; fi; if [ "$HOST_READY" = true ] && [ "$NODE_MACHINE_RC" -eq 0 ] && [ "$JQ_RC" -eq 0 ] && [ -n "$NODE_MACHINE_ID" ]; then REMOTE_MACHINE_ID="$(ssh -T -- "$HOST" 'set -eu; test -r /etc/machine-id; tr -d "\n" </etc/machine-id' 2>/dev/null)"; SSH_RC=$?; if [ "$SSH_RC" -eq 0 ] && [ "$REMOTE_MACHINE_ID" = "$NODE_MACHINE_ID" ]; then MACHINE_READY=true; export NODE_MACHINE_ID REMOTE_MACHINE_ID; printf 'MACHINE_READY=true nodeUID=%s machineID=%s\n' "$NODE_UID" "$NODE_MACHINE_ID"; else HOST_READY=false; printf '%s\n' '중단: /etc/machine-id와 Node machineID 불일치' >&2; fi; else HOST_READY=false; printf '%s\n' '중단: Node machineID 조회 실패' >&2; fi`

`invalidate_etcd(){ unset TARGET_READY HOST_READY ETCD_READY TIME_READY QUERY_READY HOST REMOTE_UUID ENDPOINT START_RFC3339 END_RFC3339 START_EPOCH END_EPOCH JOB JOB_RE; TARGET_READY=false; }; fresh_etcd(){ local p n uid rv node nid nuuid cid canon sha; p="$(kubectl get pod "$ETCD_POD" -n "$NS" -o json)" && node="$(jq -r '.spec.nodeName // empty' <<<"$p")" && n="$(kubectl get node "$node" -o json)" || { invalidate_etcd; printf '%s\n' '중단: fresh Pod/Node API 실패' >&2; return 1; }; uid="$(jq -r '.metadata.uid' <<<"$p")"; rv="$(jq -r '.metadata.resourceVersion' <<<"$p")"; nid="$(jq -r '.metadata.uid' <<<"$n")"; nuuid="$(jq -r '.status.nodeInfo.systemUUID|ascii_downcase' <<<"$n")"; cid="$(jq -r --arg c "$ETCD_CONTAINER" '.status.containerStatuses[]?|select(.name==$c)|.containerID // empty' <<<"$p")"; canon="$(jq -r --arg c "$ETCD_CONTAINER" '.spec.containers[]|select(.name==$c)|[.command[]?,.args[]?]|join(" ")' <<<"$p")"; sha="$(printf '%s' "$canon" | sha256sum | jq -Rr 'split(" ")[0]')"; if [ "$uid" = "$POD_UID" ] && [ "$rv" = "$POD_RV" ] && [ "$node" = "$NODE" ] && [ "$nid" = "$NODE_UID" ] && [ "$nuuid" = "$NODE_SYSTEM_UUID" ] && [ "$cid" = "$CONTAINER_ID" ] && [ "$sha" = "$ARGV_SHA" ] && [[ "$canon" =~ $ARGV_RE ]]; then return 0; fi; invalidate_etcd; printf '%s\n' '중단: Pod/node/container/argv lifecycle 변경, 전체 재등록 필요' >&2; return 1; }`

`fresh_remote(){ local r rc mid; [ "$MACHINE_READY" = true ] || return 1; fresh_etcd || return 1; mid="$(kubectl get node "$NODE" -o json | jq -r '.status.nodeInfo.machineID // empty')" || { HOST_READY=false; MACHINE_READY=false; return 1; }; r="$(ssh -T -- "$HOST" 'set -eu; test -r /etc/machine-id; tr -d "\n" </etc/machine-id' 2>/dev/null)"; rc=$?; if [ "$rc" -eq 0 ] && [ "$mid" = "$NODE_MACHINE_ID" ] && [ "$r" = "$NODE_MACHINE_ID" ]; then return 0; fi; HOST_READY=false; MACHINE_READY=false; printf '%s\n' '중단: fresh /etc/machine-id identity 실패' >&2; return 1; }`

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | `endpoint health` 실패, member unhealthy/unstarted, API server의 `etcdserver: request timed out`·storage timeout |
| 적용 | current Pod/node/container argv와 승인 endpoint/member identity를 같은 창에서 연결할 수 있음 |
| 제외 | leader/quorum 상실은 [[02. etcd cluster에 leader가 없거나 quorum을 잃은 경우]], WAL/backend 지연은 [[03. etcd 요청·WAL fsync·backend commit 지연이 증가한 경우]], alarm은 NOSPACE/CORRUPT 런북으로 이동 |

검색 문자열: `endpoint health`, `unhealthy`, `failed to commit proposal`, `connection refused`, `context deadline exceeded`, `x509`, `wal`, `NOSPACE`, `CORRUPT`.

## 권한·보안·runtime 경계

`fresh_etcd && kubectl auth can-i get pods -n "$NS" && kubectl auth can-i get pods/log -n "$NS" && kubectl auth can-i get nodes`

`Forbidden`은 etcd 장애가 아니다. RBAC를 넓히지 않고 owner에게 이관한다. 원격 명령은 검증된 `$HOST`에 고정 script와 positional argument로 전달하며 `eval`, 동적 remote script, agent forwarding을 사용하지 않는다. CA/cert/key는 확인된 path의 존재·readability만 검사하고 파일·Secret·token을 출력하지 않는다. Audit은 승인된 reader가 API server storage timeout의 시각·verb·objectRef·response code만 보며 body는 수집하지 않는다.

이 문서는 CRI를 직접 호출하지 않는다. endpoint health는 etcd client API 경로다. container lifecycle 오류로 CRI 분기가 필요하면 kubelet의 현재 argv/config에서 활성 runtime endpoint를 **정확히 하나** 추출하고, 입력 endpoint와 exact match하며, socket owner/type/permission을 확인하는 runtime 런북으로 이관한다. 기본 socket 추측이나 복수 후보 첫 선택은 금지한다.

## 관측별 진단 경로

| 관측 | 직접 gate | 다음 경계 |
|---|---|---|
| 한 endpoint만 실패 | 전체 endpoint health/status와 member ID | 해당 listener·TLS·node |
| 여러 endpoint 실패 | leader·정상 응답 voting member 수 | quorum 런북 |
| `NOSPACE`/`CORRUPT` | alarm member ID | 각 alarm 런북 |
| etcd healthy, readyz 실패 | API server storage/admission 경로 | API server owner |

## etcd read-only 직접 확인

각 실행은 fresh Pod와 remote identity를 다시 확인한다. 원격 script는 인자를 `eval`하지 않는다.

`ETCD_READY=false; if [ "$HOST_READY" = true ] && fresh_remote; then ssh -T -- "$HOST" 'set -eu; endpoint=$1; ca=$2; cert=$3; key=$4; command -v etcdctl >/dev/null; sudo -- test -r "$ca"; sudo -- test -r "$cert"; sudo -- test -r "$key"; sudo -- env ETCDCTL_API=3 etcdctl version' sh "$ENDPOINT" "$CA_FILE" "$CERT_FILE" "$KEY_FILE"; RC=$?; if [ "$RC" -eq 0 ]; then ETCD_READY=true; printf '%s\n' 'ETCD_READY=true'; else printf '중단: remote preflight rc=%s\n' "$RC" >&2; fi; fi`

`if [ "$ETCD_READY" = true ] && fresh_remote; then ssh -T -- "$HOST" 'set -eu; endpoint=$1; ca=$2; cert=$3; key=$4; sudo -- env ETCDCTL_API=3 etcdctl --endpoints="$endpoint" --cacert="$ca" --cert="$cert" --key="$key" endpoint health --cluster' sh "$ENDPOINT" "$CA_FILE" "$CERT_FILE" "$KEY_FILE"; fi`

`if [ "$ETCD_READY" = true ] && fresh_remote; then ssh -T -- "$HOST" 'set -eu; endpoint=$1; ca=$2; cert=$3; key=$4; sudo -- env ETCDCTL_API=3 etcdctl --endpoints="$endpoint" --cacert="$ca" --cert="$cert" --key="$key" endpoint status --cluster -w table' sh "$ENDPOINT" "$CA_FILE" "$CERT_FILE" "$KEY_FILE"; fi`

`if [ "$ETCD_READY" = true ] && fresh_remote; then ssh -T -- "$HOST" 'set -eu; endpoint=$1; ca=$2; cert=$3; key=$4; sudo -- env ETCDCTL_API=3 etcdctl --endpoints="$endpoint" --cacert="$ca" --cert="$cert" --key="$key" member list -w table; sudo -- env ETCDCTL_API=3 etcdctl --endpoints="$endpoint" --cacert="$ca" --cert="$cert" --key="$key" alarm list' sh "$ENDPOINT" "$CA_FILE" "$CERT_FILE" "$KEY_FILE"; fi`

endpoint별 `ID`, `IS LEADER`, `RAFT TERM/INDEX/APPLIED`, DB size와 오류를 member list의 ID/name/peer/client URL에 연결한다. 명령 실패·빈 table은 healthy가 아니다. TLS/권한 실패, listener 실패, member 실패를 분리한다. `--cluster` 결과의 의도 endpoint가 inventory와 다르면 자동으로 신뢰하지 않는다.

`fresh_etcd && kubectl get --raw='/readyz?verbose'`

API 실패 시 이전 readyz를 사용하지 않는다. etcd health와 readyz는 같은 UTC 창이어야 하며 한쪽 성공이 다른 쪽 성공을 보장하지 않는다.

## UTC 증거 창과 producer/filter rc

`START_RFC3339='PASTE_START_UTC_RFC3339_HERE'; END_RFC3339='PASTE_END_UTC_RFC3339_HERE'; TIME_READY=false; RFC3339_RE='^[0-9]{4}-(0[1-9]|1[0-2])-([0-2][0-9]|3[01])T([01][0-9]|2[0-3]):[0-5][0-9]:[0-5][0-9]Z$'; if [[ "$START_RFC3339" =~ $RFC3339_RE ]] && [[ "$END_RFC3339" =~ $RFC3339_RE ]]; then S="$(date -u -d "$START_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)"; SRC=$?; E="$(date -u -d "$END_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)"; ERC=$?; START_EPOCH="$(date -u -d "$START_RFC3339" +%s 2>/dev/null)"; END_EPOCH="$(date -u -d "$END_RFC3339" +%s 2>/dev/null)"; if [ "$SRC" -eq 0 ] && [ "$ERC" -eq 0 ] && [ "$S" = "$START_RFC3339" ] && [ "$E" = "$END_RFC3339" ] && [ "$START_EPOCH" -lt "$END_EPOCH" ]; then TIME_READY=true; export START_RFC3339 END_RFC3339; printf 'TIME_READY=true window=%s..%s\n' "$START_RFC3339" "$END_RFC3339"; else printf '%s\n' '중단: UTC round-trip/start<end 실패' >&2; fi; else printf '%s\n' '중단: canonical UTC RFC3339 형식 아님' >&2; fi`

`if [ "$TIME_READY" = true ] && fresh_etcd; then RAW="$(mktemp)"; WIN="$(mktemp)"; kubectl logs "$ETCD_POD" -n "$NS" -c "$ETCD_CONTAINER" --timestamps --since-time="$START_RFC3339" >"$RAW"; PRODUCER_RC=$?; if [ "$PRODUCER_RC" -eq 0 ]; then awk -v end="$END_RFC3339" '$1<=end' "$RAW" >"$WIN"; WINDOW_RC=$?; if [ "$WINDOW_RC" -eq 0 ]; then grep -E -i -C 3 'unhealthy|failed to commit|leader|peer|timeout|connection refused|x509|wal|corrupt|no space|panic|error' "$WIN"; FILTER_RC=$?; printf 'producer_rc=%s window_rc=%s filter_rc=%s evidence=%s..%s\n' "$PRODUCER_RC" "$WINDOW_RC" "$FILTER_RC" "$START_RFC3339" "$END_RFC3339"; fi; else printf '중단: log producer rc=%s\n' "$PRODUCER_RC" >&2; fi; rm -f "$RAW" "$WIN"; fi`

filter rc `1`은 일치 없음이지 오류 부재가 아니다. rc `>1`은 filter 실패다. Secret·token·인증서 원문이 보이면 보존을 중단한다.

## 실행 가능한 Prometheus 쿼리

`JOB='PASTE_PROMETHEUS_ETCD_JOB_HERE'; INSTANCE='PASTE_PROMETHEUS_INSTANCE_FOR_SELECTED_ENDPOINT_HERE'; QUERY_READY=false; if [ "$ETCD_READY" = true ] && fresh_remote && [ -n "$JOB" ] && [ -n "$INSTANCE" ] && [[ "$JOB" != *$'\n'* ]] && [[ "$INSTANCE" != *$'\n'* ]]; then JOB_RE="$(printf '%s' "$JOB" | sed 's/[][\\.^$*+?(){}|]/\\&/g')"; INSTANCE_RE="$(printf '%s' "$INSTANCE" | sed 's/[][\\.^$*+?(){}|]/\\&/g')"; QUERY_READY=true; export JOB_RE INSTANCE_RE; printf 'QUERY_READY=true job=^%s$ instance=^%s$ endpoint=%s\n' "$JOB_RE" "$INSTANCE_RE" "$ENDPOINT"; else printf '%s\n' '중단: 현재 endpoint와 대조한 Prometheus target label 미등록' >&2; fi`

`[ "$ETCD_READY" = true ] && fresh_remote && [ "$QUERY_READY" = true ] && printf 'up{job=~"^%s$",instance=~"^%s$"} == 0\n' "$JOB_RE" "$INSTANCE_RE"`

`[ "$ETCD_READY" = true ] && fresh_remote && [ "$QUERY_READY" = true ] && printf 'etcd_server_has_leader{job=~"^%s$",instance=~"^%s$"} == 0\n' "$JOB_RE" "$INSTANCE_RE"`

출력된 쿼리만 승인된 UI/API에 사용한다. HTTP success, Prometheus `status=success`, non-empty data를 각각 확인한다. 빈 결과는 정상/0이 아니라 미수집·label/시간/cluster 오류·권한/API 실패 후보다. metric은 endpoint/member identity를 대신하지 않는다.

## 변경 분리·replacement·정상화

이 문서는 restart, Pod 삭제, member remove/add, data-dir 조작, alarm mutation, defrag/restore를 실행하지 않는다. 별도 변경은 매 명령 직전에 fresh target/evidence, 승인 ID·유효 window, 현재 leader와 voting quorum, 검증된 backup, 멱등성, 중단 조건, 실제 수행해 검증된 rollback 절차를 다시 확인한다.

controller가 replacement를 만드는 종류의 변경이면 확인된 selector, 원 owner UID, controller UID, creationTimestamp가 변경 이후인 후보를 조회해 **정확히 하나**일 때만 선택한다. static Pod mirror 또는 member replacement에는 이 selector 계약을 억지 적용하지 않고 승인 inventory의 member ID/peer URL과 mirror Pod exact identity를 사용한다. 어느 경로든 replacement 뒤 UID/RV·owner·containerID·node/host·member 관계·시간·argv regex와 모든 `READY`를 폐기하고 전체 재등록한다.

정상화는 모든 의도 endpoint health -> member ID/URL·정확히 한 leader·raft 진행 -> alarm 없음 -> current Pod/node/container -> API server readyz -> 승인된 실제 read-only Kubernetes 기능 순서로 확인한다. 관찰 창 동안 같은 오류·leader churn·restart가 재발하지 않아야 한다. endpoint 하나, Pod `Running`, readyz 한 번, 빈 metric만으로 정상화하지 않는다.
