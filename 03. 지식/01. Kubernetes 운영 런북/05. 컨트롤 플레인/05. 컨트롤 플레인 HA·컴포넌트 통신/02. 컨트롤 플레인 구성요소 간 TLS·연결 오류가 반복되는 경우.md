# 컨트롤 플레인 구성요소 간 TLS·연결 오류가 반복되는 경우

## 입력값과 빠른 수집

이 런북의 연결 경로는 `작업 PC → API server → source Pod` 또는 `작업 PC → SSH → source node의 process → destination DNS·route → destination listener → TLS peer`다. managed control plane은 provider가 확인한 source·destination role, backend identity와 같은 UTC 창을 제공할 때만 같은 판정표를 사용하며 Pod·node·unit을 추측하지 않는다.

| 종류 | 변수 | 출처와 중단 조건 |
|---|---|---|
| 최초 입력 | `SOURCE_MODE`, `SOURCE_ROLE`, `NS`, `SOURCE_POD`, `NODE` | inventory와 장애 화면. `pod` 또는 `systemd`; 해당 mode의 exact target이 없으면 중단 |
| API 확인 자동값 | `SOURCE_UID`, `SOURCE_RV`, `SOURCE_CONTAINER`, `SOURCE_CONTAINER_ID`, `NODE_UID`, `NODE_MACHINE_ID`, `OWNER_REL` | exact-name API 응답. UID, current containerID 또는 owner 관계가 바뀌면 전 단계 폐기 |
| 계산 후보값 | `ENDPOINT_ID`, `DEST_IP` | source 오류·승인된 redacted config에서 계산한 후보. 실제 destination과 대조 전 미확정 |
| 운영자 선택값 | `DEST_ROLE`, `DEST_HOST`, `DEST_PORT`, `SERVER_NAME`, UTC 창, SSH host·unit | 같은 오류 행과 inventory에서 선택. 임의 기본값 금지 |

**Bash와 로컬 도구 확인:** `TOOLS_READY=false; MISSING=''; for T in kubectl jq date grep openssl ssh; do command -v "$T" >/dev/null 2>&1 || MISSING="$MISSING $T"; done; if [ -n "$MISSING" ]; then printf '중단: 없는 도구=%s\n' "$MISSING" >&2; elif [ -z "${BASH_VERSION:-}" ]; then printf '%s\n' '중단: Bash에서 실행한다.' >&2; else TOOLS_READY=true; printf 'TOOLS_READY=true bash=%s\n' "$BASH_VERSION"; fi`

**최초 입력과 모든 이전 파생 상태 폐기:** `unset INPUT_READY AUTO_READY WINDOW_READY REMOTE_READY SOURCE_UID SOURCE_RV SOURCE_CONTAINER SOURCE_CONTAINER_ID NODE_UID NODE_MACHINE_ID OWNER_REL DEST_ROLE DEST_HOST DEST_PORT SERVER_NAME ENDPOINT_ID DEST_IP START_RFC3339 END_RFC3339 EVIDENCE_RFC3339 START_EPOCH END_EPOCH EVIDENCE_EPOCH SSH_TARGET EXPECTED_REMOTE_HOST SOURCE_UNIT DEST_UNIT SOURCE_JSON NODE_JSON; SOURCE_MODE='PASTE_SOURCE_MODE_HERE'; SOURCE_ROLE='PASTE_SOURCE_ROLE_HERE'; NS='PASTE_NAMESPACE_OR_EMPTY_HERE'; SOURCE_POD='PASTE_SOURCE_POD_OR_EMPTY_HERE'; NODE='PASTE_NODE_OR_EMPTY_HERE'; INPUT_READY=false; AUTO_READY=false; WINDOW_READY=false; REMOTE_READY=false; if [ "$TOOLS_READY" != true ]; then printf '%s\n' '중단: 도구 gate 실패' >&2; elif [ "$SOURCE_MODE" = pod ] && [ -n "$SOURCE_ROLE" ] && [ -n "$NS" ] && [ -n "$SOURCE_POD" ]; then INPUT_READY=true; elif [ "$SOURCE_MODE" = systemd ] && [ -n "$SOURCE_ROLE" ] && [ -n "$NODE" ]; then INPUT_READY=true; else printf '%s\n' '중단: mode별 필수 입력 불완전' >&2; fi`

**현재 source 자동 등록:** `AUTO_READY=false; unset SOURCE_UID SOURCE_RV SOURCE_CONTAINER SOURCE_CONTAINER_ID NODE_UID NODE_MACHINE_ID OWNER_REL SOURCE_JSON NODE_JSON; if [ "$INPUT_READY" != true ]; then printf '%s\n' '중단: INPUT_READY=false' >&2; elif [ "$SOURCE_MODE" = pod ]; then J=$(kubectl get pod "$SOURCE_POD" -n "$NS" -o json) && U=$(jq -er '.metadata.uid' <<<"$J") && R=$(jq -er '.metadata.resourceVersion' <<<"$J") && N=$(jq -er '.spec.nodeName | select(length>0)' <<<"$J") && C=$(jq -er --arg role "$SOURCE_ROLE" '[.spec.containers[].name | select(.==$role)] | if length==1 then .[0] else error("source container exact match required") end' <<<"$J") && CID=$(jq -er --arg role "$SOURCE_ROLE" '[.status.containerStatuses[]?|select(.name==$role)|.containerID|select(length>0)]|if length==1 then .[0] else error("current containerID required") end' <<<"$J") && O=$(jq -er '[.metadata.ownerReferences[]? | select(.controller==true) | [.kind,.name,.uid]|join("/")] | if length==0 then "none" elif length==1 then .[0] else error("ambiguous controller owner") end' <<<"$J") && NJ=$(kubectl get node "$N" -o json) && NU=$(jq -er '.metadata.uid' <<<"$NJ") && NM=$(jq -er '.status.nodeInfo.machineID|select(length>0)' <<<"$NJ") || { unset J U R N C CID O NJ NU NM; printf '%s\n' '중단: exact source 수집 실패' >&2; }; if [ -n "${NM:-}" ]; then SOURCE_JSON=$J; SOURCE_UID=$U; SOURCE_RV=$R; NODE=$N; SOURCE_CONTAINER=$C; SOURCE_CONTAINER_ID=$CID; OWNER_REL=$O; NODE_JSON=$NJ; NODE_UID=$NU; NODE_MACHINE_ID=$NM; AUTO_READY=true; fi; else NJ=$(kubectl get node "$NODE" -o json) && NU=$(jq -er '.metadata.uid' <<<"$NJ") && NM=$(jq -er '.status.nodeInfo.machineID|select(length>0)' <<<"$NJ") || { unset NJ NU NM; printf '%s\n' '중단: exact node 수집 실패' >&2; }; if [ -n "${NM:-}" ]; then NODE_JSON=$NJ; NODE_UID=$NU; NODE_MACHINE_ID=$NM; OWNER_REL=systemd; AUTO_READY=true; fi; fi; unset J U R N C CID O NJ NU NM; [ "$AUTO_READY" = true ] && printf 'AUTO_READY=true mode=%s source=%s uid=%s rv=%s container_id=%s node=%s node_uid=%s machine_id=%s owner=%s container=%s\n' "$SOURCE_MODE" "$SOURCE_ROLE" "${SOURCE_UID:-none}" "${SOURCE_RV:-none}" "${SOURCE_CONTAINER_ID:-none}" "$NODE" "$NODE_UID" "$NODE_MACHINE_ID" "$OWNER_REL" "${SOURCE_CONTAINER:-none}"`

**direct latest gate 등록:** `refresh_source(){ local j u r n c cid o nj nu nm; AUTO_READY=false; if [ "$SOURCE_MODE" = pod ]; then j=$(kubectl get pod "$SOURCE_POD" -n "$NS" -o json) || return 1; u=$(jq -er '.metadata.uid' <<<"$j") || return 1; [ "$u" = "$SOURCE_UID" ] || { printf '%s\n' '중단: source Pod lifecycle 변경' >&2; return 1; }; n=$(jq -er '.spec.nodeName | select(length>0)' <<<"$j") || return 1; c=$(jq -er --arg role "$SOURCE_ROLE" '[.spec.containers[].name|select(.==$role)]|if length==1 then .[0] else error("container relation changed") end' <<<"$j") || return 1; cid=$(jq -er --arg role "$SOURCE_ROLE" '[.status.containerStatuses[]?|select(.name==$role)|.containerID|select(length>0)]|if length==1 then .[0] else error("current containerID changed") end' <<<"$j") || return 1; o=$(jq -er '[.metadata.ownerReferences[]?|select(.controller==true)|[.kind,.name,.uid]|join("/")]|if length==0 then "none" elif length==1 then .[0] else error("owner changed") end' <<<"$j") || return 1; [ "$n" = "$NODE" ] && [ "$c" = "$SOURCE_CONTAINER" ] && [ "$cid" = "$SOURCE_CONTAINER_ID" ] && [ "$o" = "$OWNER_REL" ] || { printf '%s\n' '중단: node/containerID/owner relation 변경' >&2; return 1; }; r=$(jq -er '.metadata.resourceVersion' <<<"$j") || return 1; SOURCE_JSON=$j; SOURCE_RV=$r; fi; nj=$(kubectl get node "$NODE" -o json) || return 1; nu=$(jq -er '.metadata.uid' <<<"$nj") || return 1; nm=$(jq -er '.status.nodeInfo.machineID|select(length>0)' <<<"$nj") || return 1; [ "$nu" = "$NODE_UID" ] && [ "$nm" = "$NODE_MACHINE_ID" ] || { printf '%s\n' '중단: node lifecycle/machineID 변경' >&2; return 1; }; NODE_JSON=$nj; AUTO_READY=true; }`

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | 같은 source→destination에서 `x509`, `TLS handshake timeout`, `connection refused/reset`이 반복됨 |
| 적용 | source identity, destination role·endpoint와 UTC 오류 행을 같은 연결로 묶을 수 있음 |
| 제외 | 인증서 발급·갱신은 [[15. 클러스터 수명주기/01. 인증서/01. 클러스터 인증서가 만료됐거나 갱신 결과가 반영되지 않는 경우]], API 인증·RBAC는 [[12. 보안/01. API 접근·권한]], 일반 route·firewall은 [[06. 클러스터 네트워크]]로 이관 |

검색 문자열: `certificate has expired or is not yet valid`, `certificate signed by unknown authority`, `certificate is valid for`, `TLS handshake timeout`, `connection refused`, `connection reset by peer`, `dial tcp`.

## 최초 확인과 시간 gate

**현재 source 상태:** `refresh_source || exit $?; if [ "$SOURCE_MODE" = pod ]; then jq -r '"=== source ===\nUID: \(.metadata.uid)\nRV: \(.metadata.resourceVersion)\nNode: \(.spec.nodeName)\nCreated: \(.metadata.creationTimestamp)\n" + (.status.containerStatuses[]|"Container: \(.name) ready=\(.ready) restart=\(.restartCount) id=\(.containerID // "none")")' <<<"$SOURCE_JSON"; else jq -r '"=== source node ===\nNode: \(.metadata.name)\nUID: \(.metadata.uid)\nReady: \([.status.conditions[]|select(.type=="Ready")][0].status)\nRuntime: \(.status.nodeInfo.containerRuntimeVersion)"' <<<"$NODE_JSON"; fi`

`Running`·`Ready`는 해당 destination의 TLS 성공을 보장하지 않는다. current containerID는 등록값과 매 명령의 최신 API 값이 일치할 때만 같은 source 증거로 사용한다.

**오류에서 endpoint와 엄격한 UTC 창 선택:** `unset WINDOW_READY START_EPOCH END_EPOCH EVIDENCE_EPOCH; DEST_ROLE='PASTE_DESTINATION_ROLE_HERE'; DEST_HOST='PASTE_DESTINATION_HOST_HERE'; DEST_PORT='PASTE_DESTINATION_PORT_HERE'; SERVER_NAME='PASTE_TLS_SERVER_NAME_HERE'; START_RFC3339='PASTE_START_RFC3339_HERE'; END_RFC3339='PASTE_END_RFC3339_HERE'; EVIDENCE_RFC3339='PASTE_EVIDENCE_RFC3339_HERE'; WINDOW_READY=false; RFC3339_RE='^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$'; if [[ ! "$DEST_PORT" =~ ^[1-9][0-9]{0,4}$ ]] || [ "$DEST_PORT" -gt 65535 ] || [ -z "$DEST_ROLE" ] || [ -z "$DEST_HOST" ] || [ -z "$SERVER_NAME" ] || [[ ! "$START_RFC3339" =~ $RFC3339_RE ]] || [[ ! "$END_RFC3339" =~ $RFC3339_RE ]] || [[ ! "$EVIDENCE_RFC3339" =~ $RFC3339_RE ]]; then printf '%s\n' '중단: destination 또는 RFC3339 선택값 불완전' >&2; else START_EPOCH=$(date -u -d "$START_RFC3339" +%s 2>/dev/null) && END_EPOCH=$(date -u -d "$END_RFC3339" +%s 2>/dev/null) && EVIDENCE_EPOCH=$(date -u -d "$EVIDENCE_RFC3339" +%s 2>/dev/null) || true; if [ -n "${START_EPOCH:-}" ] && [ "$(date -u -d "@$START_EPOCH" '+%Y-%m-%dT%H:%M:%SZ')" = "$START_RFC3339" ] && [ "$(date -u -d "@$END_EPOCH" '+%Y-%m-%dT%H:%M:%SZ')" = "$END_RFC3339" ] && [ "$(date -u -d "@$EVIDENCE_EPOCH" '+%Y-%m-%dT%H:%M:%SZ')" = "$EVIDENCE_RFC3339" ] && [ "$START_EPOCH" -lt "$END_EPOCH" ] && [ "$START_EPOCH" -le "$EVIDENCE_EPOCH" ] && [ "$EVIDENCE_EPOCH" -lt "$END_EPOCH" ]; then ENDPOINT_ID="$DEST_ROLE@$DEST_HOST:$DEST_PORT"; WINDOW_READY=true; printf 'WINDOW_READY=true endpoint=%s evidence=%s\n' "$ENDPOINT_ID" "$EVIDENCE_RFC3339"; else printf '%s\n' '중단: canonical UTC RFC3339 또는 start<=evidence<end 위반' >&2; unset START_EPOCH END_EPOCH EVIDENCE_EPOCH ENDPOINT_ID; fi; fi`

**Pod source 로그와 pipeline RC 분리:** `refresh_source || exit $?; [ "$SOURCE_MODE" = pod ] && [ "$WINDOW_READY" = true ] || { printf '%s\n' '중단: Pod mode 또는 시간 gate 불충족' >&2; exit 1; }; RAW=$(kubectl logs "$SOURCE_POD" -n "$NS" -c "$SOURCE_CONTAINER" --timestamps --since-time="$START_RFC3339" --tail=300 2>&1); RC=$?; if [ "$RC" -ne 0 ]; then printf '수집 실패 rc=%s: %s\n' "$RC" "$RAW" >&2; elif MATCH=$(grep -E -i -C 3 'x509|certificate|tls|handshake|connection refused|connection reset|dial tcp|timeout' <<<"$RAW"); then printf '%s\n' "$MATCH"; else printf '%s\n' '필터 불일치: 오류 없음이 아님'; tail -n 50 <<<"$RAW"; fi; unset RAW MATCH RC`

로그 endpoint가 선택한 `ENDPOINT_ID`와 다르거나 오류 시각이 창 밖이면 중단한다. `unknown authority`는 trust/chain 후보, SAN 오류는 접속 이름 후보, refused는 route 도달 뒤 listener 부재·거부 후보, timeout은 route·listener·부하 후보이며 단독 원인 확정이 아니다.

## 관측별 진단 경로

| 지금 보이는 것 | 먼저 볼 것 | 그다음 어디를 볼지 | 상세 절 |
|---|---|---|---|
| expired/not yet valid | 양 끝 UTC와 public cert `notBefore/notAfter` | 시간 owner → 인증서 owner | [[#1. source node와 destination hop]] |
| unknown authority/SAN mismatch | source CA 참조와 peer public chain/SAN | config owner → 인증서 owner | [[#2. TLS metadata와 config]] |
| timeout/refused/reset | source DNS·route, destination listener·journal | network 또는 destination owner | [[#1. source node와 destination hop]] |

### 1. source node와 destination hop

SSH는 작업 PC에서 실행한다. `SSH_TARGET`은 접속 문자열, `EXPECTED_REMOTE_HOST`는 inventory의 원격 `hostname -f`, unit은 실제 service manager 결과다. Kubernetes Node 이름과 hostname이 다르면 승인된 inventory 관계가 없을 때 중단한다.

**SSH·unit 선택 및 안전 전달 helper:** `unset REMOTE_READY SSH_TARGET EXPECTED_REMOTE_HOST SOURCE_UNIT DEST_UNIT; SSH_TARGET='PASTE_SSH_TARGET_HERE'; EXPECTED_REMOTE_HOST='PASTE_EXPECTED_REMOTE_HOST_HERE'; SOURCE_UNIT='PASTE_SOURCE_UNIT_HERE'; DEST_UNIT='PASTE_DESTINATION_UNIT_OR_EMPTY_HERE'; run_remote(){ local script=$1 arg q cmd='bash -s --'; shift; for arg in "$@"; do printf -v q '%q' "$arg"; cmd+=" $q"; done; ssh -- "$SSH_TARGET" "$cmd" <<<"$script"; }; if [ -n "$SSH_TARGET" ] && [ -n "$EXPECTED_REMOTE_HOST" ] && [ -n "$SOURCE_UNIT" ]; then REMOTE_READY=true; else REMOTE_READY=false; printf '%s\n' '중단: SSH 선택값 불완전' >&2; fi`

**원격 identity·source unit·DNS·route:** `refresh_source || exit $?; [ "$REMOTE_READY" = true ] && [ "$WINDOW_READY" = true ] || exit 1; run_remote 'set -o pipefail; expected=$1; expected_mid=$2; unit=$3; host=$4; port=$5; actual=$(hostname -f 2>/dev/null || hostname) || exit 20; actual_mid=$(cat /etc/machine-id) || exit 21; [ "$actual" = "$expected" ] && [ "$actual_mid" = "$expected_mid" ] || { printf "remote identity mismatch expected=%s/%s actual=%s/%s\n" "$expected" "$expected_mid" "$actual" "$actual_mid" >&2; exit 22; }; active=$(systemctl is-active "$unit" 2>&1); rc=$?; [ "$rc" -eq 0 ] && [ "$active" = active ] || { printf "source unit inactive rc=%s state=%s\n" "$rc" "$active" >&2; exit 23; }; systemctl show "$unit" -p MainPID -p ExecMainStartTimestampMonotonic --no-pager || exit 24; getent ahosts "$host" || exit 25; ip=$(getent ahostsv4 "$host" | { read -r first rest; printf "%s" "$first"; }) || exit 26; [ -n "$ip" ] || exit 27; ip route get "$ip" || exit 28; printf "destination=%s:%s\n" "$host" "$port"' "$EXPECTED_REMOTE_HOST" "$NODE_MACHINE_ID" "$SOURCE_UNIT" "$DEST_HOST" "$DEST_PORT"`

`is-active` 실패, DNS 실패, route 실패는 서로 다른 hop이다. 빈 주소를 정상으로 보지 않는다. destination이 다른 host면 그 host의 별도 승인된 SSH identity로 listener·unit을 확인하고 source host의 `ss` 결과로 대신하지 않는다.

**source journal과 RC 분리:** `refresh_source || exit $?; [ "$REMOTE_READY" = true ] && [ "$WINDOW_READY" = true ] || exit 1; run_remote 'expected=$1; expected_mid=$2; unit=$3; start=$4; end=$5; role=$6; actual=$(hostname -f 2>/dev/null || hostname) || exit 20; actual_mid=$(cat /etc/machine-id) || exit 21; [ "$actual" = "$expected" ] && [ "$actual_mid" = "$expected_mid" ] || exit 22; raw=$(sudo journalctl -u "$unit" --since "$start" --until "$end" --no-pager -n 500 2>&1); rc=$?; if [ "$rc" -ne 0 ]; then printf "journal 수집 실패 rc=%s: %s\n" "$rc" "$raw" >&2; exit "$rc"; elif match=$(grep -E -i -C 3 "$role|x509|certificate|tls|handshake|refused|reset|dial tcp|timeout" <<<"$raw"); then printf "%s\n" "$match"; else printf "%s\n" "필터 불일치: 오류 없음이 아님"; tail -n 50 <<<"$raw"; fi' "$EXPECTED_REMOTE_HOST" "$NODE_MACHINE_ID" "$SOURCE_UNIT" "$START_RFC3339" "$END_RFC3339" "$DEST_ROLE"`

### 2. TLS metadata와 config

인증서 private key, bearer token, kubeconfig 원문, Secret data, raw PEM은 출력·저장하지 않는다. public CA bundle 경로는 승인된 redacted config에서 확인하고, 경로를 문서 변수로 보존하지 않는다. 인증서·endpoint 조회 권한이 없으면 권한 부재와 요청 주체를 기록해 owner에게 이관한다. `kubectl auth can-i=yes`는 실제 요청 성공을 보장하지 않으며 audit log는 audit가 활성화되고 승인된 reader·시간·objectRef/URI가 있을 때만 담당자에게 요청한다.

**source host에서 peer public metadata 확인:** `refresh_source || exit $?; [ "$REMOTE_READY" = true ] && [ "$WINDOW_READY" = true ] || exit 1; run_remote 'expected=$1; expected_mid=$2; host=$3; port=$4; name=$5; actual=$(hostname -f 2>/dev/null || hostname) || exit 20; actual_mid=$(cat /etc/machine-id) || exit 21; [ "$actual" = "$expected" ] && [ "$actual_mid" = "$expected_mid" ] || exit 22; raw=$(timeout 10 openssl s_client -connect "$host:$port" -servername "$name" -showcerts </dev/null 2>&1); rc=$?; if [ "$rc" -ne 0 ]; then printf "TLS 수집 실패 rc=%s: %s\n" "$rc" "$raw" >&2; exit "$rc"; fi; cert=$(openssl x509 -noout -subject -issuer -serial -dates -ext subjectAltName <<<"$raw" 2>&1); rc=$?; [ "$rc" -eq 0 ] && [ -n "$cert" ] || { printf "certificate parse 실패 rc=%s\n" "$rc" >&2; exit 26; }; printf "%s\n" "$cert"' "$EXPECTED_REMOTE_HOST" "$NODE_MACHINE_ID" "$DEST_HOST" "$DEST_PORT" "$SERVER_NAME"`

성공은 해당 source host에서 한 peer가 public certificate를 제공했다는 뜻뿐이다. CA 검증 성공은 source component가 실제 사용하는 CA bundle로 별도 확인해야 하며, `-k`, `insecure-skip-tls-verify`, endpoint IP 치환으로 우회하지 않는다. `notBefore/notAfter`는 `EVIDENCE_RFC3339`와 비교하고 SAN은 실제 `SERVER_NAME`과 비교한다.

## 변경 전 gate와 정상화

이 문서는 restart, 인증서·CA 교체, config edit, route/firewall 변경 명령을 제공하지 않는다. 변경 owner는 실행 직전에 다음을 모두 새로 확인해야 한다.

1. fresh source UID/RV·node UID 또는 systemd node identity, 동일 `ENDPOINT_ID`, 같은 UTC 증거 창과 직접 오류가 유지된다.
2. 변경 대상 원본·owner·승인 ID·실행 창·HA peer·etcd quorum과 한 번에 변경할 instance 수가 확정됐다.
3. 작업이 재실행돼도 안전한지 또는 중복 실행을 막을 idempotency key/change ID가 있다.
4. 검증된 rollback 원본·명령·담당자와 rollback trigger가 있으며 사전 복원 검증 결과가 있다.
5. replacement가 생기면 새 Pod UID/process start, node, source→destination relation, CA/SAN을 재등록한다. 이전 RV·UID·READY·시간·endpoint 파생값은 폐기한다.

정상화는 `destination 기능 → TLS 검증 → listener → route/DNS → source 요청 → control-plane 기능` 역순으로 확인한다. 같은 오류가 관찰 창 동안 재발하지 않고 HA peer·quorum이 유지되며, API read/write, controller 조정 또는 scheduler binding처럼 해당 source의 실제 기능이 정상이어야 한다. `Running`, TCP 연결, handshake 한 번, `/readyz` 한 번만으로 닫지 않는다. 실패하면 추가 instance 변경을 중단하고 rollback한다.

## 증거와 환경별 미검증

보존: source mode/role, Pod UID·RV·container 또는 node UID·remote hostname·unit, 마스킹한 endpoint role, UTC 창과 오류 행, DNS·route·listener hop 결과, public cert subject/issuer/serial/dates/SAN, 승인·rollback·기능 검증. 저장 금지: 실제 private endpoint가 민감한 환경의 원문, credential, token, private key, kubeconfig, raw PEM, 전체 journal.

배포 방식, provider backend, unit/config 경로, CA 배포, audit 활성화·보존, HA topology는 환경별 미검증이다.
