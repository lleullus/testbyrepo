# 특정 control-plane node 또는 API endpoint에서만 요청이 실패하는 경우

## 입력값과 빠른 수집

이 런북은 같은 요청이 다른 API endpoint에서는 성공하지만 승인된 한 backend endpoint에서만 실패할 때 사용한다. 연결 경로는 `작업 PC/bastion Bash → DNS·route·TLS → TARGET_API_SERVER → target host listener → 현재 kube-apiserver process/container → API handler → etcd`다. `127.0.0.1`을 사용하지 않으며, 작업 PC 변수는 SSH에 자동 전달된다고 가정하지 않는다.

| 입력 종류 | 변수 | 출처와 gate |
|---|---|---|
| 최초 입력 | `NS`, `API_POD` | 승인된 kube-apiserver namespace와 exact Pod 이름 |
| API 확인 자동값 | `API_UID`, `API_RV`, `NODE`, `NODE_UID`, `MACHINE_ID`, `OWNER_REL`, container 관계 | 현재 Pod·Node API가 모두 성공할 때만 등록 |
| 계산 후보값 | `API_POD_RE`, `TARGET_API_SERVER` | literal 이름 escape와 승인 host·port로 계산하고 bounded 출력 |
| 운영자 선택값 | `API_CONTAINER`, endpoint host·port·backend IP, UTC 창·증거 시각, SSH destination | Pod 출력, LB/backend inventory와 결정적 오류에서 선택 |

### 1. 실행 위치·도구·최초 입력

모든 로컬 명령은 승인된 kubeconfig를 가진 같은 Bash에서 실행한다. endpoint 비교는 현재 context가 아니라 아래에서 등록한 exact target URL에 `--server`를 명시한다. token, client key, kubeconfig 원문과 response body 전체는 출력·보존하지 않는다.

**Bash·도구 확인**

`TOOLS_READY=false; MISSING=''; if [ -z "${BASH_VERSION:-}" ]; then printf '%s\n' '중단: Bash가 아니다.' >&2; else for T in kubectl jq grep sed date mktemp ssh awk; do command -v "$T" >/dev/null 2>&1 || MISSING="$MISSING $T"; done; if [ -z "$MISSING" ]; then TOOLS_READY=true; printf 'TOOLS_READY=true bash=%s\n' "$BASH_VERSION"; else printf '중단: 없는 도구=%s\n' "$MISSING" >&2; fi; fi`

**최초 입력과 모든 downstream 상태 폐기**

`unset INPUT_READY AUTO_READY SELECTION_READY TIME_READY ENDPOINT_READY LOG_READY HOST_READY PROCESS_READY RBAC_READY PROM_READY MUTATE_READY ROLLBACK_READY NORMALIZE_READY API_UID API_RV NODE NODE_UID MACHINE_ID OWNER_REL CONTAINER_REL API_CONTAINER CONTAINER_ID ARGV_RE API_POD_RE ENDPOINT_HOST ENDPOINT_PORT EXPECTED_BACKEND_IP TARGET_API_SERVER START_RFC3339 END_RFC3339 EVIDENCE_RFC3339 START_EPOCH END_EPOCH EVIDENCE_EPOCH SSH_HOST EXPECTED_MACHINE_ID PROM_JOB; NS='PASTE_APISERVER_NAMESPACE_HERE'; API_POD='PASTE_APISERVER_POD_HERE'; INPUT_READY=false; if [ "$TOOLS_READY" != true ] || [ -z "$NS" ] || [ -z "$API_POD" ]; then printf '%s\n' '중단: 도구와 최초 입력을 확인한다.' >&2; elif J="$(kubectl get pod "$API_POD" -n "$NS" -o json)" && jq -e --arg n "$API_POD" --arg ns "$NS" '.metadata.name==$n and .metadata.namespace==$ns' <<<"$J" >/dev/null; then INPUT_READY=true; export NS API_POD; printf 'INPUT_READY=true namespace=%s pod=%s\n' "$NS" "$API_POD"; else printf '%s\n' '중단: exact API Pod 조회 실패. 이전 상태는 모두 무효다.' >&2; fi`

### 2. 현재 Pod·Node identity 자동 등록

다음 명령은 Pod와 Node 조회 중 하나라도 실패하거나 현재 containerID가 없으면 부분값을 남기지 않는다. static Pod는 controller owner가 없을 수 있어 `static-or-unowned`로 명시하지만, owner가 있으면 kind/name/UID를 모두 보존한다.

**자동값 등록·관계 출력**

`unset AUTO_READY SELECTION_READY TIME_READY ENDPOINT_READY LOG_READY HOST_READY PROCESS_READY RBAC_READY PROM_READY MUTATE_READY ROLLBACK_READY NORMALIZE_READY API_UID API_RV NODE NODE_UID MACHINE_ID OWNER_REL CONTAINER_REL API_POD_RE; AUTO_READY=false; if [ "$INPUT_READY" != true ]; then printf '%s\n' '중단: INPUT_READY가 아니다.' >&2; elif PJ="$(kubectl get pod "$API_POD" -n "$NS" -o json)" && jq -e '(.metadata.uid|length>0) and (.metadata.resourceVersion|length>0) and (.spec.nodeName|length>0) and ([.status.containerStatuses[]?|select((.containerID//"")|length>0)]|length>0)' <<<"$PJ" >/dev/null && NODE_TMP="$(jq -r '.spec.nodeName' <<<"$PJ")" && NJ="$(kubectl get node "$NODE_TMP" -o json)" && jq -e '(.metadata.uid|length>0) and (.status.nodeInfo.machineID|length>0)' <<<"$NJ" >/dev/null; then API_UID="$(jq -r '.metadata.uid' <<<"$PJ")"; API_RV="$(jq -r '.metadata.resourceVersion' <<<"$PJ")"; NODE="$NODE_TMP"; NODE_UID="$(jq -r '.metadata.uid' <<<"$NJ")"; MACHINE_ID="$(jq -r '.status.nodeInfo.machineID' <<<"$NJ")"; OWNER_REL="$(jq -r '[.metadata.ownerReferences[]?|(.kind+"/"+.name+"/"+.uid)]|join(",")' <<<"$PJ")"; [ -n "$OWNER_REL" ] || OWNER_REL='static-or-unowned'; CONTAINER_REL="$(jq -r '([.status.initContainerStatuses[]?|("init/"+.name+"="+(.containerID//"-")+" ready="+(.ready|tostring))] + [.status.containerStatuses[]?|("regular/"+.name+"="+(.containerID//"-")+" ready="+(.ready|tostring)+" restart="+(.restartCount|tostring))])|join("; ")' <<<"$PJ")"; API_POD_RE="$(printf '%s' "$API_POD"|sed 's/[][\\.^$*+?(){}|]/\\&/g')"; AUTO_READY=true; export API_UID API_RV NODE NODE_UID MACHINE_ID OWNER_REL CONTAINER_REL API_POD_RE; printf 'AUTO_READY=true\nPod UID/RV: %s/%s\nNode UID: %s/%s\nMachine ID: %s\nOwner: %s\nContainer 관계: %s\nPod regex: ^%s$\n' "$API_UID" "$API_RV" "$NODE" "$NODE_UID" "$MACHINE_ID" "$OWNER_REL" "$CONTAINER_REL" "$API_POD_RE"; else printf '%s\n' '중단: Pod→Node identity 또는 container 관계 수집 실패. 자동값은 무효다.' >&2; fi`

Pod가 교체되거나 Pod UID·owner·node·containerID 또는 Node UID·machineID가 달라지면 이 절부터 다시 실행한다. `Running`, Node `Ready`, API Pod readiness는 선택한 endpoint의 DNS·TLS·listener·API write 성공을 각각 보장하지 않는다.

### 3. endpoint·container·시간·host 선택

`ENDPOINT_HOST`는 승인된 backend DNS 이름 또는 인증서 SAN에 포함된 host, `EXPECTED_BACKEND_IP`는 그 endpoint가 이 Node에 연결된다는 LB/backend inventory의 IP다. 여러 backend를 반환하는 공용 VIP를 넣으면 특정 Node를 고립할 수 없으므로 중단한다.

**운영자 선택값 입력**

`API_CONTAINER='PASTE_APISERVER_CONTAINER_HERE'; ENDPOINT_HOST='PASTE_TARGET_API_ENDPOINT_HOST_HERE'; ENDPOINT_PORT='PASTE_TARGET_API_ENDPOINT_PORT_HERE'; EXPECTED_BACKEND_IP='PASTE_EXPECTED_BACKEND_IP_HERE'; START_RFC3339='PASTE_API_ENDPOINT_START_UTC_HERE'; END_RFC3339='PASTE_API_ENDPOINT_END_UTC_HERE'; EVIDENCE_RFC3339='PASTE_API_ENDPOINT_EVIDENCE_UTC_HERE'; SSH_HOST='PASTE_API_ENDPOINT_SSH_DESTINATION_HERE'; EXPECTED_MACHINE_ID='PASTE_API_ENDPOINT_EXPECTED_MACHINE_ID_HERE'; PROM_JOB='PASTE_APISERVER_PROMETHEUS_JOB_HERE'`

**선택값과 canonical UTC 창 검증**

`SELECTION_READY=false; TIME_READY=false; unset ENDPOINT_READY LOG_READY HOST_READY PROCESS_READY RBAC_READY PROM_READY MUTATE_READY ROLLBACK_READY NORMALIZE_READY CONTAINER_ID ARGV_RE TARGET_API_SERVER START_EPOCH END_EPOCH EVIDENCE_EPOCH; if [ "$AUTO_READY" != true ]; then printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; elif PJ="$(kubectl get pod "$API_POD" -n "$NS" -o json)" && [ "$(jq -r '.metadata.uid' <<<"$PJ")" = "$API_UID" ] && [ "$(jq -r '.metadata.resourceVersion' <<<"$PJ")" = "$API_RV" ] && [ "$(jq -r '.spec.nodeName' <<<"$PJ")" = "$NODE" ] && jq -e --arg c "$API_CONTAINER" 'any(.spec.containers[]?;.name==$c)' <<<"$PJ" >/dev/null && [[ "$ENDPOINT_HOST" =~ ^[A-Za-z0-9.-]+$ ]] && [[ "$ENDPOINT_PORT" =~ ^[0-9]+$ ]] && [ "$ENDPOINT_PORT" -ge 1 ] && [ "$ENDPOINT_PORT" -le 65535 ] && [ -n "$EXPECTED_BACKEND_IP" ]; then CONTAINER_ID="$(jq -r --arg c "$API_CONTAINER" '.status.containerStatuses[]?|select(.name==$c)|.containerID//empty' <<<"$PJ")"; ARGV="$(jq -r --arg c "$API_CONTAINER" '.spec.containers[]|select(.name==$c)|([.command[]?,.args[]?]|join(" "))' <<<"$PJ")"; ARGV_RE="$(printf '%s' "$ARGV"|sed 's/[][\\.^$*+?(){}|]/\\&/g')"; TARGET_API_SERVER="https://$ENDPOINT_HOST:$ENDPOINT_PORT"; [ -n "$CONTAINER_ID" ] && [ -n "$ARGV_RE" ] && SELECTION_READY=true; fi; if [ "$SELECTION_READY" = true ] && [[ "$START_RFC3339" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] && [[ "$END_RFC3339" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] && [[ "$EVIDENCE_RFC3339" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]]; then START_EPOCH="$(date -u -d "$START_RFC3339" '+%s' 2>/dev/null)" && END_EPOCH="$(date -u -d "$END_RFC3339" '+%s' 2>/dev/null)" && EVIDENCE_EPOCH="$(date -u -d "$EVIDENCE_RFC3339" '+%s' 2>/dev/null)" && [ "$(date -u -d "@$START_EPOCH" '+%Y-%m-%dT%H:%M:%SZ')" = "$START_RFC3339" ] && [ "$(date -u -d "@$END_EPOCH" '+%Y-%m-%dT%H:%M:%SZ')" = "$END_RFC3339" ] && [ "$(date -u -d "@$EVIDENCE_EPOCH" '+%Y-%m-%dT%H:%M:%SZ')" = "$EVIDENCE_RFC3339" ] && [ "$START_EPOCH" -lt "$END_EPOCH" ] && [ "$START_EPOCH" -le "$EVIDENCE_EPOCH" ] && [ "$EVIDENCE_EPOCH" -lt "$END_EPOCH" ] && TIME_READY=true; fi; printf 'SELECTION_READY=%s TIME_READY=%s endpoint=%s backend=%s container=%s containerID=%s argv-regex-bytes=%s\n' "$SELECTION_READY" "$TIME_READY" "${TARGET_API_SERVER:--}" "$EXPECTED_BACKEND_IP" "$API_CONTAINER" "${CONTAINER_ID:--}" "${#ARGV_RE}"`

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | 동일 verb/resource가 다른 endpoint에서는 성공하고 이 endpoint에서만 timeout·TLS·5xx·readyz 실패가 반복됨 |
| 적용 | exact API Pod·Node·container와 backend endpoint 관계, 실패 시각을 같은 UTC 창에서 대조 가능 |
| 제외 | 모든 endpoint가 실패하면 [[01. kube-apiserver health endpoint가 실패하거나 API endpoint에 연결할 수 없는 경우]], TLS 오류가 source·destination 전반에 공통이면 [[02. 컨트롤 플레인 구성요소 간 TLS·연결 오류가 반복되는 경우]]로 이동 |

검색 문자열: `connection refused`, `i/o timeout`, `TLS handshake timeout`, `x509`, `EOF`, `connection reset by peer`, `readyz`, `etcd`, `HTTP 500`, `HTTP 503`.

## 관측별 진단 경로

| 지금 보이는 것 | 먼저 볼 것 | 그다음 어디를 볼지 | 상세 절 |
|---|---|---|---|
| direct endpoint에서 TCP·TLS 실패 | endpoint host·backend IP와 host listener | DNS·route·LB 또는 target process | [[#1. direct API endpoint와 application gate]] |
| readyz 5xx·check 실패 | 현재 container log와 실패 check | API handler·etcd dependency | [[#2. kube-apiserver 로그와 증거 창]] |
| 한 host listener/process만 비정상 | machine-id·local IP·PID start | process/runtime·manifest owner | [[#3. 원격 host·listener·process identity]] |

### 1. direct API endpoint와 application gate

**현재 identity를 다시 확인한 direct readyz 요청**

`ENDPOINT_READY=false; unset LOG_READY HOST_READY PROCESS_READY RBAC_READY PROM_READY MUTATE_READY ROLLBACK_READY NORMALIZE_READY; BODY="$(mktemp)" || exit 1; ERR="$(mktemp)" || { rm -f "$BODY"; exit 1; }; if [ "$SELECTION_READY" != true ] || [ "$TIME_READY" != true ]; then printf '%s\n' '중단: selection/time gate 실패.' >&2; elif PJ="$(kubectl get pod "$API_POD" -n "$NS" -o json)" && NJ="$(kubectl get node "$NODE" -o json)" && [ "$(jq -r '.metadata.uid' <<<"$PJ")" = "$API_UID" ] && [ "$(jq -r '.metadata.uid' <<<"$NJ")" = "$NODE_UID" ] && [ "$(jq -r --arg c "$API_CONTAINER" '.status.containerStatuses[]?|select(.name==$c)|.containerID' <<<"$PJ")" = "$CONTAINER_ID" ]; then kubectl --request-timeout=10s --server="$TARGET_API_SERVER" get --raw='/readyz?verbose' >"$BODY" 2>"$ERR"; RC=$?; if [ "$RC" -ne 0 ]; then printf 'endpoint-producer-failure rc=%s endpoint=%s error=' "$RC" "$TARGET_API_SERVER" >&2; sed -n '1p' "$ERR" >&2; elif grep -Fq '[-]' "$BODY"; then printf 'application-failure endpoint=%s failed-checks=%s\n' "$TARGET_API_SERVER" "$(grep -Fc '[-]' "$BODY")" >&2; elif grep -Eq '(^ok$|\[\+\].*ok)' "$BODY"; then ENDPOINT_READY=true; printf 'ENDPOINT_READY=true endpoint=%s uid=%s node_uid=%s checks=%s\n' "$TARGET_API_SERVER" "$API_UID" "$NODE_UID" "$(grep -Ec '^\[\+\]' "$BODY")"; else GRC=$?; if [ "$GRC" -eq 1 ]; then printf '%s\n' 'endpoint-filter=no-match; 빈 응답을 정상으로 해석하지 않는다.' >&2; else printf 'endpoint-filter-error rc=%s\n' "$GRC" >&2; fi; fi; else printf '%s\n' '중단: current Pod/Node/container identity가 바뀌었다.' >&2; fi; rm -f "$BODY" "$ERR"`

producer 실패는 DNS·route·TCP·TLS·인증·HTTP 오류를 뜻할 수 있으며 readyz 실패와 같지 않다. `401/403`은 transport 이후의 인증·인가, `5xx`는 handler/dependency, filter no-match는 예상 application payload 부재다. 다른 endpoint의 성공은 이 target의 성공을 보장하지 않는다. `--server`는 endpoint만 바꾸며 현재 kubeconfig credential·CA 정책을 사용하므로 인증서 검증을 끄지 않는다.

### 2. kube-apiserver 로그와 증거 창

로그는 producer 성공 뒤 UTC end 이전 행만 별도 filter하고, 증상 filter의 match/no-match/error를 구분한다.

**bounded log 분류**

`LOG_READY=false; unset HOST_READY PROCESS_READY RBAC_READY PROM_READY MUTATE_READY ROLLBACK_READY NORMALIZE_READY; RAW="$(mktemp)" || exit 1; WINDOW="$(mktemp)" || { rm -f "$RAW"; exit 1; }; if [ "$SELECTION_READY" != true ] || [ "$TIME_READY" != true ]; then printf '%s\n' '중단: selection/time gate 실패.' >&2; elif PJ="$(kubectl get pod "$API_POD" -n "$NS" -o json)" && [ "$(jq -r '.metadata.uid' <<<"$PJ")" = "$API_UID" ] && [ "$(jq -r --arg c "$API_CONTAINER" '.status.containerStatuses[]?|select(.name==$c)|.containerID' <<<"$PJ")" = "$CONTAINER_ID" ]; then if kubectl logs "$API_POD" -n "$NS" -c "$API_CONTAINER" --timestamps --since-time="$START_RFC3339" --tail=600 >"$RAW"; then if awk -v end="$END_RFC3339" '{ts=$1; sub(/\.[0-9]+Z$/,"Z",ts); if (ts<=end) print}' "$RAW" >"$WINDOW"; then grep -Eic 'readyz|etcd|timeout|deadline|refused|reset|EOF|x509|tls|429|5[0-9][0-9]|panic|fatal' "$WINDOW" >/dev/null; FRC=$?; case "$FRC" in 0) LOG_READY=true; printf 'LOG_READY=true filter=matched count=%s window=%s..%s\n' "$(grep -Eic 'readyz|etcd|timeout|deadline|refused|reset|EOF|x509|tls|429|5[0-9][0-9]|panic|fatal' "$WINDOW")" "$START_RFC3339" "$END_RFC3339";; 1) LOG_READY=true; printf '%s\n' 'LOG_READY=true filter=no-match; 오류 부재나 endpoint 정상 증거가 아니다.';; *) printf 'log-filter-error rc=%s\n' "$FRC" >&2;; esac; else printf '%s\n' 'time-window-filter-error' >&2; fi; else RC=$?; printf 'log-producer-failure rc=%s\n' "$RC" >&2; fi; else printf '%s\n' '중단: current Pod/container identity 불일치.' >&2; fi; rm -f "$RAW" "$WINDOW"`

결정적 로그 timestamp가 `[START_RFC3339, END_RFC3339)` 밖이거나 다른 endpoint·peer를 가리키면 같은 사건으로 연결하지 않는다. `etcd` check 실패는 이 API instance의 etcd client 경로 후보이며 etcd quorum 상실을 단독 확정하지 않는다. raw 로그·request body·authorization header는 보존하지 않는다.

### 3. 원격 host·listener·process identity

이 분기는 self-managed control plane에서 endpoint backend IP가 현재 Node의 local IP라는 inventory가 있을 때만 사용한다. SSH는 작업 PC에서 실행하고 값은 positional argument로 전달한다. 원격 경계에서 `/etc/machine-id`, local IP, exact listener port, socket owner PID와 process start time을 다시 확인한다.

**SSH host·listener·process 검증**

`HOST_READY=false; PROCESS_READY=false; unset RBAC_READY PROM_READY MUTATE_READY ROLLBACK_READY NORMALIZE_READY; if [ "$SELECTION_READY" != true ] || [ "$TIME_READY" != true ] || [ "$EXPECTED_MACHINE_ID" != "$MACHINE_ID" ]; then printf '%s\n' '중단: current selection/time 또는 API machineID 관계 미확정.' >&2; elif PJ="$(kubectl get pod "$API_POD" -n "$NS" -o json)" && NJ="$(kubectl get node "$NODE" -o json)" && [ "$(jq -r '.metadata.uid' <<<"$PJ")" = "$API_UID" ] && [ "$(jq -r '.metadata.uid' <<<"$NJ")" = "$NODE_UID" ]; then ssh -- "$SSH_HOST" bash -c 'expected=$1; ip=$2; port=$3; actual=$(cat /etc/machine-id 2>/dev/null) || exit 40; [ "$actual" = "$expected" ] || exit 41; addr=$(ip -o addr show 2>&1); arc=$?; [ "$arc" -eq 0 ] || exit 42; grep -F " $ip/" <<<"$addr" >/dev/null; grc=$?; [ "$grc" -eq 0 ] || exit 43; listeners=$(ss -ltnpH 2>&1); src=$?; [ "$src" -eq 0 ] || exit 44; line=$(grep -E "[[:space:]]([^[:space:]]+:)?$port[[:space:]]" <<<"$listeners"); grc=$?; [ "$grc" -eq 0 ] || exit 45; [ "$(wc -l <<<"$line")" -eq 1 ] || exit 46; pid=$(sed -n "s/.*pid=\([0-9][0-9]*\).*/\1/p" <<<"$line"); [ -n "$pid" ] && [ -r "/proc/$pid/stat" ] || exit 47; comm=$(cat "/proc/$pid/comm") || exit 48; start_ticks=$(cut -d" " -f22 "/proc/$pid/stat") || exit 49; lstart=$(ps -p "$pid" -o lstart=) || exit 50; printf "HOST_READY=true PROCESS_READY=true machine_id=%s ip=%s port=%s pid=%s comm=%s start_ticks=%s lstart=%s\n" "$actual" "$ip" "$port" "$pid" "$comm" "$start_ticks" "$lstart"' bash "$EXPECTED_MACHINE_ID" "$EXPECTED_BACKEND_IP" "$ENDPOINT_PORT"; RC=$?; if [ "$RC" -eq 0 ]; then HOST_READY=true; PROCESS_READY=true; else printf 'host/listener/process 검증 실패 rc=%s\n' "$RC" >&2; fi; else printf '%s\n' '중단: current Pod/Node identity 불일치.' >&2; fi`

listener 부재, IP 관계 불일치와 SSH 실패는 서로 다른 hop이다. `ss` 성공이나 PID 존재만으로 그 process가 현재 Pod containerID에 해당한다고 확정하지 않는다. container/runtime 연계가 필요하면 active kubelet endpoint와 socket provider를 검증하는 [[07. runtime 상태와 Pod container ID가 일치하지 않는 경우]]로 이동하며 기본 CRI socket을 추측하거나 먼저 `crictl`을 실행하지 않는다. managed control plane은 provider backend ID·health-check·drain 상태를 같은 UTC 창으로 받아 이 분기를 대체한다.

### 4. RBAC·audit와 Prometheus 경계

`Forbidden`은 audit에서 단일 `auditID`, timestamp, user, verb, resource/subresource, namespace/name, requestURI, response code가 이 incident 창과 current lifecycle 대상에 일치할 때만 authorization 문제로 분류한다. `/readyz`는 non-resource URL이므로 workload resource RBAC와 섞지 않는다. request/response body, token, client certificate private key와 상세 actor 개인정보는 출력·보존하지 않는다.

Prometheus target inventory에서 `job`, `namespace`, `pod` label이 현재 API Pod를 가리킨다고 확인한 경우만 다음 완성 query를 생성한다.

**현재 identity용 PromQL 생성**

`PROM_READY=false; unset MUTATE_READY ROLLBACK_READY NORMALIZE_READY; if [ "$AUTO_READY" != true ] || [ -z "$PROM_JOB" ]; then printf '%s\n' '중단: component/job gate 실패.' >&2; elif PJ_NOW="$(kubectl get pod "$API_POD" -n "$NS" -o json)" && [ "$(jq -r '.metadata.uid' <<<"$PJ_NOW")" = "$API_UID" ]; then J="${PROM_JOB//\\/\\\\}"; J="${J//\"/\\\"}"; N="${NS//\\/\\\\}"; N="${N//\"/\\\"}"; P="${API_POD//\\/\\\\}"; P="${P//\"/\\\"}"; printf 'up{job="%s",namespace="%s",pod="%s"}\nchanges(process_start_time_seconds{job="%s",namespace="%s",pod="%s"}[15m])\nsum by(code)(rate(apiserver_request_total{job="%s",namespace="%s",pod="%s",code=~"429|5.."}[5m]))\nhistogram_quantile(0.99,sum by(le)(rate(apiserver_request_duration_seconds_bucket{job="%s",namespace="%s",pod="%s"}[5m])))\n' "$J" "$N" "$P" "$J" "$N" "$P" "$J" "$N" "$P" "$J" "$N" "$P"; PROM_READY=true; else printf '%s\n' '중단: current API Pod UID 불일치.' >&2; fi`

query empty는 정상이나 0이 아니다. target 부재, scrape/TLS/RBAC 실패, time range·label 불일치와 metric 미지원을 구분한다. regular kube-apiserver container target만 사용하며 init/sidecar metric을 현재 process로 결합하지 않는다.

## 변경 gate와 정상화

이 문서는 restart, static Pod manifest·LB member·route·certificate·etcd membership 변경 명령을 제공하지 않는다. 별도 변경 절차는 실행 직전에 current Pod UID·RV·owner·node·containerID, Node UID·machineID, endpoint/backend/listener/PID start, 직접 오류와 evidence 시각, 승인 ID·실행자·창, 남은 API endpoint와 etcd quorum/capacity, tenant 영향, 멱등성, 중단 조건 및 실행 가능한 rollback을 다시 수집해 `MUTATE_READY`를 새로 만들어야 한다. rollback도 target revision/config/backend membership과 새 증거를 재검증한 독립 `ROLLBACK_READY`가 필요하다.

변경 시작 전 모든 stale READY를 폐기한다. 교체 후 기존 Pod 이름이나 UID를 재사용하지 않고 node·selector·static Pod mirror relation, owner kind/name/UID, creation time과 단일 후보를 대조해 새 Pod UID·RV·containerID, Node UID·machineID, endpoint/backend/listener/PID start를 처음부터 등록한다.

정상화는 `실제 API read/write → readyz dependency → TLS → listener/process → backend health·route → 다른 HA endpoint와 결과 일치` 순서로 확인한다. 승인된 관찰 창 동안 같은 오류·process restart·backend flap이 없고 controller 조정과 scheduler binding 같은 실제 control-plane 기능이 수렴해야 `NORMALIZE_READY=true`다. TCP 연결, HTTP 200, readyz 한 번 또는 Pod `Running`만으로 닫지 않는다. 실패하면 추가 instance 변경을 중단하고 rollback trigger를 적용한다.

## 증거와 환경별 미검증

보존: UTC 창·evidence 시각, Pod UID·RV·owner·node·containerID, Node UID·machineID, endpoint role과 backend IP, DNS/TLS/HTTP application 결과, listener PID·start, 분류 count, 단일 audit tuple, Prometheus target identity, 승인·rollback·replacement·실제 기능 결과. 저장 금지: kubeconfig·token·private key·Secret, 전체 argv/config, raw log/audit/request/response body와 개인정보.

실제 HA topology, LB backend relation, endpoint TLS·인증, static Pod/runtime 배포, host 접근, audit, etcd와 Prometheus label/metric은 환경별 미검증이다. 승인된 Kubernetes 1.26 클러스터나 SSH 환경에서 명령과 상태 변경은 실행하지 않았다.
