# API 요청에 429 Too Many Requests가 반환되는 경우

## 입력값과 빠른 수집

실행 hop은 `원 client → client rate limiter → DNS/TLS/VIP 또는 gateway → kube-apiserver → API Priority and Fairness(APF) 분류·queue/reject → handler`다. `client-side throttling`은 HTTP 응답 전 client 대기이고, gateway 429와 kube-apiserver APF 429도 서로 다른 사건이다.

| 종류 | 변수 | 출처와 gate |
|---|---|---|
| 최초 입력 | `REQ_METHOD`, `REQ_PATH`, `ORIGINAL_STATUS` | 원 transcript의 method, redacted path와 status |
| 로컬 자동값 | `API_URL`, `COLLECTED_UTC`, `READ_ONLY`, `PATH_RE` | minified kubeconfig server, 현재 UTC와 계산값 |
| API 자동값 | `APISERVER_UIDS`, `APISERVER_RVS`, `APISERVER_NODES` | component selector가 실제 후보를 반환할 때만 |
| 운영자 선택값 | `START_UTC`, `END_UTC`, `LOCAL_PORT`, `PROM_JOB` | 원 429보다 앞선 UTC 창, 미사용 local port와 실제 scrape job |
| 응답 자동값 | `FLOW_UID`, `PL_UID`, `RETRY_AFTER` | 승인된 GET/HEAD 응답 header에서만 등록 |
| APF 선택값 | `FLOW_NAME`, `PL_NAME` | header UID를 승인된 mapping으로 확인한 exact object 이름 |

### 1. 실행 위치·도구·최초 입력

Kubernetes 명령과 local proxy/curl은 승인된 작업 PC 또는 bastion의 같은 Bash에서 실행한다. `127.0.0.1`은 이 작업 host의 loopback이며 Pod·API server 주소가 아니다.

`TOOLS_READY=false; MISSING=''; [ -n "${BASH_VERSION:-}" ] || MISSING=' bash'; for T in kubectl jq curl date sed grep mktemp; do command -v "$T" >/dev/null 2>&1 || MISSING="$MISSING $T"; done; if [ -z "$MISSING" ]; then TOOLS_READY=true; printf 'TOOLS_READY=true bash=%s\n' "$BASH_VERSION"; else printf '중단: 없는 도구=%s\n' "$MISSING" >&2; fi`

`if [ -n "${PROXY_PID:-}" ] && kill -0 "$PROXY_PID" 2>/dev/null; then kill "$PROXY_PID" 2>/dev/null; wait "$PROXY_PID" 2>/dev/null || true; fi; unset INPUT_READY LOCAL_READY API_READY TIME_READY PROXY_CONFIG_READY PROXY_READY RESPONSE_READY APF_HEADER_READY APF_READY LOG_READY PROM_READY EVIDENCE_READY MUTATION_READY ROLLBACK_READY NORMALIZATION_READY DOWNSTREAM_READY API_URL COLLECTED_UTC READ_ONLY PATH_RE APISERVER_UIDS APISERVER_RVS APISERVER_NODES START_UTC END_UTC START_EPOCH END_EPOCH LOCAL_PORT LOCAL_PROXY_URL PROXY_PID PROXY_LOG PROM_JOB JOB_RE FLOW_UID PL_UID RETRY_AFTER FLOW_NAME PL_NAME FLOW_RV PL_RV APISERVER_POD APISERVER_UID APISERVER_RV APISERVER_CONTAINER CONTAINER_ID POD_NODE AUDIT_ID; REQ_METHOD='PASTE_ORIGINAL_HTTP_METHOD_HERE'; REQ_PATH='PASTE_REDACTED_API_PATH_HERE'; ORIGINAL_STATUS='PASTE_ORIGINAL_429_STATUS_HERE'; INPUT_READY=false; LOCAL_READY=false; if [ "$TOOLS_READY" = true ] && [[ "$REQ_METHOD" =~ ^(GET|HEAD|POST|PUT|PATCH|DELETE)$ ]] && [[ "$REQ_PATH" =~ ^/[^[:space:]]*$ ]] && [ "$ORIGINAL_STATUS" = 429 ] && [[ "$REQ_PATH" != *'?'* ]]; then INPUT_READY=true; fi; if [ "$INPUT_READY" = true ] && API_URL_TMP="$(kubectl config view --minify -o json | jq -er '.clusters|if length==1 then .[0].cluster.server else error("cluster count") end')" && NOW_TMP="$(date -u '+%Y-%m-%dT%H:%M:%SZ')"; then API_URL="$API_URL_TMP"; COLLECTED_UTC="$NOW_TMP"; READ_ONLY=false; [[ "$REQ_METHOD" =~ ^(GET|HEAD)$ ]] && READ_ONLY=true; PATH_RE="$(printf '%s' "$REQ_PATH" | sed 's/[][\\.^$*+?(){}|]/\\&/g')"; LOCAL_READY=true; export REQ_METHOD REQ_PATH ORIGINAL_STATUS API_URL COLLECTED_UTC READ_ONLY PATH_RE; printf 'LOCAL_READY=true host=%s endpoint=%s method=%s path=%s status=%s READ_ONLY=%s PATH_RE=%s collected=%s\n' "$(hostname)" "$API_URL" "$REQ_METHOD" "$REQ_PATH" "$ORIGINAL_STATUS" "$READ_ONLY" "$PATH_RE" "$COLLECTED_UTC"; else printf '%s\n' '중단: 입력/local 자동 수집 실패; query·token·개인정보가 없는 redacted path만 사용한다.' >&2; fi`

write body와 credential은 입력·저장·재전송하지 않는다. POST·PUT·PATCH·DELETE 사건은 원 transcript·audit·server evidence로만 조사한다.

### 2. API 후보 자동 수집

재조회 전에는 identity/resourceVersion, owner/container/node, 시간, header/APF/log/evidence/mutation/rollback/normalization READY와 모든 파생값을 먼저 폐기한다. 실패한 조회 뒤 과거 후보를 사용하지 않는다.

`unset API_READY TIME_READY PROXY_CONFIG_READY PROXY_READY RESPONSE_READY APF_HEADER_READY APF_READY LOG_READY PROM_READY EVIDENCE_READY MUTATION_READY ROLLBACK_READY NORMALIZATION_READY DOWNSTREAM_READY APISERVER_UIDS APISERVER_RVS APISERVER_NODES START_UTC END_UTC START_EPOCH END_EPOCH LOCAL_PORT LOCAL_PROXY_URL PROXY_PID PROXY_LOG PROM_JOB JOB_RE FLOW_UID PL_UID RETRY_AFTER FLOW_NAME PL_NAME FLOW_RV PL_RV APISERVER_POD APISERVER_UID APISERVER_RV APISERVER_CONTAINER CONTAINER_ID POD_NODE AUDIT_ID; API_READY=false; if [ "$LOCAL_READY" != true ]; then printf '%s\n' '중단: LOCAL_READY가 아니다.' >&2; elif PODS_JSON="$(kubectl get pods -n kube-system -l component=kube-apiserver -o json)" && COUNT="$(jq -er '.items|length' <<<"$PODS_JSON")" && [ "$COUNT" -ge 1 ]; then APISERVER_UIDS="$(jq -r '[.items[].metadata.uid]|join(",")' <<<"$PODS_JSON")"; APISERVER_RVS="$(jq -r '[.items[].metadata.resourceVersion]|join(",")' <<<"$PODS_JSON")"; APISERVER_NODES="$(jq -r '[.items[].spec.nodeName]|join(",")' <<<"$PODS_JSON")"; jq -r '.items[]|"=== kube-apiserver 후보 ===\nPod: \(.metadata.name)\nUID: \(.metadata.uid)\nRV: \(.metadata.resourceVersion)\nNode: \(.spec.nodeName)\nContainer/현재 ID: \([.status.containerStatuses[]?|"\(.name)=\(.containerID//"-")"]|join(";"))"' <<<"$PODS_JSON"; API_READY=true; export APISERVER_UIDS APISERVER_RVS APISERVER_NODES; printf 'API_READY=true candidates=%s\n' "$COUNT"; else printf '%s\n' 'API 후보 조회 실패 또는 0건: managed/selector/권한/API 상태를 분리하고 stale 값은 폐기됨' >&2; fi`

selector 결과는 설치 방식별 후보이며 첫 항목을 자동 선택하지 않는다. managed control plane이나 label이 다른 환경은 provider가 같은 UTC 창의 backend identity를 제공해야 한다.

### 3. 엄격한 UTC 창·proxy·Prometheus 선택값

`START_UTC='PASTE_START_UTC_RFC3339_HERE'; END_UTC='PASTE_END_UTC_RFC3339_HERE'; LOCAL_PORT='PASTE_UNUSED_LOCAL_PROXY_PORT_HERE'; PROM_JOB='PASTE_PROMETHEUS_JOB_LABEL_HERE'`

`TIME_READY=false; PROXY_CONFIG_READY=false; PROM_READY=false; unset START_EPOCH END_EPOCH LOCAL_PROXY_URL JOB_RE PROXY_READY RESPONSE_READY APF_HEADER_READY APF_READY LOG_READY EVIDENCE_READY MUTATION_READY ROLLBACK_READY NORMALIZATION_READY DOWNSTREAM_READY FLOW_UID PL_UID RETRY_AFTER FLOW_NAME PL_NAME FLOW_RV PL_RV; if [[ "$START_UTC" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] && [[ "$END_UTC" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] && START_ROUND="$(date -u -d "$START_UTC" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" && END_ROUND="$(date -u -d "$END_UTC" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" && [ "$START_ROUND" = "$START_UTC" ] && [ "$END_ROUND" = "$END_UTC" ]; then START_EPOCH="$(date -u -d "$START_UTC" +%s)"; END_EPOCH="$(date -u -d "$END_UTC" +%s)"; [ "$START_EPOCH" -lt "$END_EPOCH" ] && TIME_READY=true; fi; if [[ "$LOCAL_PORT" =~ ^[0-9]+$ ]] && (( LOCAL_PORT >= 1024 && LOCAL_PORT <= 65535 )); then LOCAL_PROXY_URL="http://127.0.0.1:$LOCAL_PORT$REQ_PATH"; PROXY_CONFIG_READY=true; fi; if [ -n "$PROM_JOB" ]; then JOB_RE="$(printf '%s' "$PROM_JOB" | sed 's/\\/\\\\/g; s/"/\\"/g')"; PROM_READY=true; fi; export START_UTC END_UTC LOCAL_PORT PROM_JOB JOB_RE; printf 'TIME_READY=%s PROXY_CONFIG_READY=%s PROM_READY=%s start=%s end=%s local_url=%s JOB_RE=%s\n' "$TIME_READY" "$PROXY_CONFIG_READY" "$PROM_READY" "$START_UTC" "$END_UTC" "${LOCAL_PROXY_URL:--}" "${JOB_RE:--}"`

`TIME_READY=true`는 canonical UTC와 `start < end`를 뜻한다. start는 최초 429 전에 있어야 하고 end는 조사 상한이어야 한다. 현재 수집 시각으로 사건 시작을 대체하지 않는다.

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | 원 response에서 HTTP 429가 확인됐거나 승인된 GET/HEAD 재현이 429를 반환함 |
| 적용 | response source, APF UID·object, client/gateway 경계와 같은 UTC 창의 지표·로그를 연결할 수 있음 |
| 제외 | HTTP 429 없이 지연만 있으면 [[03. API 요청 지연이 증가하거나 timeout이 발생하는 경우]], 500/503이면 [[02. API 요청에 500·503 오류가 반환되는 경우]], transport 실패면 [[01. kube-apiserver health endpoint가 실패하거나 API endpoint에 연결할 수 없는 경우]] |

검색 문자열: `429 Too Many Requests`, `Retry-After`, `X-Kubernetes-PF-FlowSchema-UID`, `X-Kubernetes-PF-PriorityLevel-UID`, `queue-full`, `client-side throttling`, `apiserver_flowcontrol_rejected_requests_total`.

## 최초 확인: 승인된 read-only proxy cycle

원 transcript에 status와 APF header가 있으면 재현하지 않고 그 증거를 사용한다. 없으면 GET/HEAD만 아래 cycle로 1회 확인한다.

`if [ "$READ_ONLY" != true ] || [ "$TIME_READY" != true ] || [ "$PROXY_CONFIG_READY" != true ]; then printf '%s\n' '중단: read-only/time/proxy-config gate가 아니다.' >&2; elif [ -n "${PROXY_PID:-}" ] && kill -0 "$PROXY_PID" 2>/dev/null; then printf '중단: 이전 proxy가 살아 있음 pid=%s\n' "$PROXY_PID" >&2; else unset PROXY_PID PROXY_LOG FLOW_UID PL_UID RETRY_AFTER; PROXY_READY=false; RESPONSE_READY=false; APF_HEADER_READY=false; EVIDENCE_READY=false; PROXY_LOG="$(mktemp)" || exit 1; kubectl proxy --port="$LOCAL_PORT" --api-prefix=/ --accept-hosts='^localhost$,^127\.0\.0\.1$' --reject-methods='POST,PUT,PATCH,DELETE' >"$PROXY_LOG" 2>&1 & PROXY_PID=$!; for WAIT in 1 2 3 4 5; do if grep -Fq "Starting to serve on 127.0.0.1:$LOCAL_PORT" "$PROXY_LOG"; then PROXY_READY=true; break; fi; kill -0 "$PROXY_PID" 2>/dev/null || break; sleep 1; done; printf 'PROXY_READY=%s pid=%s\n' "$PROXY_READY" "$PROXY_PID"; fi`

`if [ "$PROXY_READY" != true ]; then printf '%s\n' '중단: PROXY_READY가 아니다.' >&2; else HEADER_FILE="$(mktemp)" || exit 1; CODE="$(curl -sS -X "$REQ_METHOD" -D "$HEADER_FILE" -o /dev/null -w '%{http_code}' --max-time 20 "$LOCAL_PROXY_URL")"; CURL_RC=$?; FLOW_UID_TMP=''; PL_UID_TMP=''; RETRY_TMP=''; while IFS=: read -r KEY VALUE; do VALUE="${VALUE#$' '}"; VALUE="${VALUE%$'\r'}"; case "${KEY,,}" in x-kubernetes-pf-flowschema-uid) FLOW_UID_TMP="$VALUE";; x-kubernetes-pf-prioritylevel-uid) PL_UID_TMP="$VALUE";; retry-after) RETRY_TMP="$VALUE";; esac; done <"$HEADER_FILE"; if grep -E -i '^(HTTP/|Retry-After:|X-Kubernetes-PF-FlowSchema-UID:|X-Kubernetes-PF-PriorityLevel-UID:)' "$HEADER_FILE"; then FILTER_RC=0; else FILTER_RC=$?; fi; if [ "$CURL_RC" -eq 0 ] && [ "$CODE" = 429 ]; then RESPONSE_READY=true; RETRY_AFTER="$RETRY_TMP"; fi; if [ "$RESPONSE_READY" = true ] && [ -n "$FLOW_UID_TMP" ] && [ -n "$PL_UID_TMP" ]; then FLOW_UID="$FLOW_UID_TMP"; PL_UID="$PL_UID_TMP"; APF_HEADER_READY=true; EVIDENCE_READY=true; export FLOW_UID PL_UID RETRY_AFTER; fi; printf 'curl_rc=%s http=%s filter_rc=%s RESPONSE_READY=%s APF_HEADER_READY=%s flow_uid=%s priority_uid=%s retry_after=%s\n' "$CURL_RC" "${CODE:-000}" "$FILTER_RC" "$RESPONSE_READY" "$APF_HEADER_READY" "${FLOW_UID:--}" "${PL_UID:--}" "${RETRY_AFTER:--}"; rm -f "$HEADER_FILE"; fi`

producer인 curl, HTTP status와 header filter rc를 별도로 판정한다. filter rc 1은 필요한 header가 없다는 뜻이고 2 이상은 filter 오류다. 429인데 APF UID가 없으면 gateway/provider 경로를 우선하며, APF header가 있다는 사실만으로 object rule match까지 보장하지 않는다.

`if [ -n "${PROXY_PID:-}" ] && kill -0 "$PROXY_PID" 2>/dev/null; then kill "$PROXY_PID" 2>/dev/null; wait "$PROXY_PID" 2>/dev/null || true; fi; if [ -n "${PROXY_PID:-}" ] && kill -0 "$PROXY_PID" 2>/dev/null; then printf '중단: proxy 종료 실패 pid=%s\n' "$PROXY_PID" >&2; else rm -f "${PROXY_LOG:-}"; unset PROXY_PID PROXY_LOG LOCAL_PROXY_URL; PROXY_READY=false; printf '%s\n' 'proxy 종료; tunnel READY 무효화, response evidence identity는 유지'; fi`

## 관측별 진단 경로

| 지금 보이는 것 | 직접 증거 | 다음 경계 |
|---|---|---|
| 429와 두 APF UID header | exact FlowSchema/PriorityLevel UID·RV와 matching rule | APF queue/reject |
| external만 429, local read는 정상 | `Server`·`Via`·quota evidence | gateway/provider owner |
| `client-side throttling`만 있음 | 실제 HTTP status 없음 | client QPS/Burst·fan-out owner |
| APF reject `queue-full` 증가 | 같은 flow/priority/time | 호출량과 APF policy owner |
| APF reject가 없고 dependency 오류 | 단일 auditID·같은 request | 해당 admission/audit/storage owner |

## APF identity·RBAC·request match

원 transcript나 위 cycle의 UID를 승인된 APF object 이름에 매핑한다. 이름을 추측하거나 목록 첫 항목을 고르지 않는다.

`FLOW_NAME='PASTE_CONFIRMED_FLOWSCHEMA_NAME_HERE'; PL_NAME='PASTE_CONFIRMED_PRIORITYLEVEL_NAME_HERE'`

`APF_READY=false; unset FLOW_RV PL_RV LOG_READY MUTATION_READY ROLLBACK_READY NORMALIZATION_READY DOWNSTREAM_READY; if [ "$APF_HEADER_READY" != true ] || [ "$TIME_READY" != true ]; then printf '%s\n' '중단: current APF header/time gate가 아니다.' >&2; elif [ "$(kubectl auth can-i get flowschemas.flowcontrol.apiserver.k8s.io)" != yes ] || [ "$(kubectl auth can-i get prioritylevelconfigurations.flowcontrol.apiserver.k8s.io)" != yes ]; then printf '%s\n' '중단: 현재 subject의 exact get 권한 없음; RBAC 확대 금지' >&2; elif FLOW_JSON="$(kubectl get flowschema "$FLOW_NAME" -o json)" && PL_JSON="$(kubectl get prioritylevelconfiguration "$PL_NAME" -o json)" && [ "$(jq -r '.metadata.uid' <<<"$FLOW_JSON")" = "$FLOW_UID" ] && [ "$(jq -r '.metadata.uid' <<<"$PL_JSON")" = "$PL_UID" ] && [ "$(jq -r '.spec.priorityLevelConfiguration.name' <<<"$FLOW_JSON")" = "$PL_NAME" ]; then FLOW_RV="$(jq -r '.metadata.resourceVersion' <<<"$FLOW_JSON")"; PL_RV="$(jq -r '.metadata.resourceVersion' <<<"$PL_JSON")"; APF_READY=true; jq -r '"=== FlowSchema ===\n이름: \(.metadata.name)\nUID: \(.metadata.uid)\nRV: \(.metadata.resourceVersion)\n우선순위: \(.spec.matchingPrecedence)\nPriorityLevel: \(.spec.priorityLevelConfiguration.name)\nSubjects: \([.spec.rules[]?.subjects[]?|(.kind+":"+(.name//.group.name//.serviceAccount.name//"-"))]|unique|join(","))\nResource rules: \([.spec.rules[]?.resourceRules[]?|"verbs="+(.verbs|join("|"))+" groups="+(.apiGroups|join("|"))+" resources="+(.resources|join("|"))+" namespaces="+(.namespaces|join("|"))]|join("; "))"' <<<"$FLOW_JSON"; jq -r '"=== PriorityLevel ===\n이름: \(.metadata.name)\nUID: \(.metadata.uid)\nRV: \(.metadata.resourceVersion)\nType: \(.spec.type)\nShares: \(.spec.limited.nominalConcurrencyShares//"-")\nResponse: \(.spec.limited.limitResponse.type//"-")\nQueues: \(.spec.limited.limitResponse.queuing.queues//"-")\nQueue length: \(.spec.limited.limitResponse.queuing.queueLengthLimit//"-")"' <<<"$PL_JSON"; else printf '%s\n' '중단: header UID↔current APF object/name relation 실패' >&2; fi`

`auth can-i=yes`는 원 subject나 요청 match를 보장하지 않는다. 원 audit/transcript의 subject, verb, API group, resource/subresource, namespace와 FlowSchema rule이 모두 일치해야 `EVIDENCE_READY=true`를 유지한다. `limitResponse=Reject` 또는 같은 priority level의 `reason=queue-full` 증가가 함께 있어야 APF reject 원인으로 확정한다.

## API server log와 current container gate

managed control plane은 아래 Pod 명령을 실행하지 않고 provider에게 동일 필드·UTC 창·단일 auditID를 요청한다.

`APISERVER_POD='PASTE_EXACT_APISERVER_POD_HERE'; APISERVER_CONTAINER='PASTE_EXACT_APISERVER_CONTAINER_HERE'`

`LOG_READY=false; unset APISERVER_UID APISERVER_RV CONTAINER_ID POD_NODE MUTATION_READY ROLLBACK_READY NORMALIZATION_READY DOWNSTREAM_READY; if [ "$API_READY" != true ] || [ "$TIME_READY" != true ]; then printf '%s\n' '중단: API/time gate가 아니다.' >&2; elif AP_JSON="$(kubectl get pod "$APISERVER_POD" -n kube-system -o json)" && APISERVER_UID_TMP="$(jq -er '.metadata.uid' <<<"$AP_JSON")" && APISERVER_RV_TMP="$(jq -er '.metadata.resourceVersion' <<<"$AP_JSON")" && POD_NODE_TMP="$(jq -er '.spec.nodeName' <<<"$AP_JSON")" && CONTAINER_ID_TMP="$(jq -er --arg c "$APISERVER_CONTAINER" '[.status.containerStatuses[]?|select(.name==$c)|.containerID]|if length==1 and .[0]!="" then .[0] else error("current containerID") end' <<<"$AP_JSON")"; then APISERVER_UID="$APISERVER_UID_TMP"; APISERVER_RV="$APISERVER_RV_TMP"; POD_NODE="$POD_NODE_TMP"; CONTAINER_ID="$CONTAINER_ID_TMP"; LOG_READY=true; export APISERVER_POD APISERVER_UID APISERVER_RV APISERVER_CONTAINER CONTAINER_ID POD_NODE; printf 'LOG_READY=true pod=%s uid=%s rv=%s node=%s container=%s current_id=%s\n' "$APISERVER_POD" "$APISERVER_UID" "$APISERVER_RV" "$POD_NODE" "$APISERVER_CONTAINER" "$CONTAINER_ID"; else printf '%s\n' '중단: current Pod/container identity 실패' >&2; fi`

`if [ "$LOG_READY" != true ]; then printf '%s\n' '중단: LOG_READY가 아니다.' >&2; elif CURRENT_JSON="$(kubectl get pod "$APISERVER_POD" -n kube-system -o json)" && [ "$(jq -r '.metadata.uid' <<<"$CURRENT_JSON")" = "$APISERVER_UID" ] && [ "$(jq -r '.metadata.resourceVersion' <<<"$CURRENT_JSON")" = "$APISERVER_RV" ] && [ "$(jq -r --arg c "$APISERVER_CONTAINER" '.status.containerStatuses[]?|select(.name==$c)|.containerID' <<<"$CURRENT_JSON")" = "$CONTAINER_ID" ]; then TMP="$(mktemp)" || exit 1; if kubectl logs "$APISERVER_POD" -n kube-system -c "$APISERVER_CONTAINER" --timestamps --since-time="$START_UTC" --tail=400 >"$TMP"; then PRODUCER_RC=0; else PRODUCER_RC=$?; fi; if [ "$PRODUCER_RC" -eq 0 ]; then if grep -E -i -C 3 "$PATH_RE|flowcontrol|queue-full|429|client-side throttling|failed calling webhook|Failed to write audit event|etcdserver: request timed out|context deadline exceeded" "$TMP"; then FILTER_RC=0; else FILTER_RC=$?; fi; else FILTER_RC=125; fi; printf 'producer_rc=%s filter_rc=%s pod_uid=%s current_container_id=%s\n' "$PRODUCER_RC" "$FILTER_RC" "$APISERVER_UID" "$CONTAINER_ID"; rm -f "$TMP"; [ "$PRODUCER_RC" -eq 0 ] && [ "$FILTER_RC" -le 1 ]; else LOG_READY=false; printf '%s\n' '중단: Pod UID/RV/current containerID 변경; stale LOG_READY 폐기 후 재등록' >&2; fi`

filter rc 1은 무일치이지 오류 부재가 아니다. audit를 사용할 때는 승인된 owner가 **단일 auditID**의 timestamp, verb, resource/subresource, namespace/name, redacted requestURI, response status와 현재 lifecycle UID 관계만 공개한다. actor 상세, source IP, token과 request/response body는 redaction한다.

## Prometheus 완성 query

아래 생성 명령의 출력만 Prometheus/Grafana에 붙인다. metric과 label이 실제로 없거나 결과가 비면 0/정상으로 해석하지 않는다.

`if [ "$PROM_READY" = true ] && [ "$TIME_READY" = true ]; then printf 'sum by(instance,verb,resource,subresource) (rate(apiserver_request_total{job="%s",code="429"}[5m])) > 0\n' "$JOB_RE"; printf 'sum by(instance,flow_schema,priority_level,reason) (rate(apiserver_flowcontrol_rejected_requests_total{job="%s"}[5m])) > 0\n' "$JOB_RE"; printf 'sum by(instance,flow_schema,priority_level) (apiserver_flowcontrol_current_inqueue_requests{job="%s"})\n' "$JOB_RE"; printf 'sum by(instance,flow_schema,priority_level) (apiserver_flowcontrol_current_executing_requests{job="%s"})\n' "$JOB_RE"; else printf '%s\n' '중단: PROM_READY/TIME_READY가 아니다.' >&2; fi`

APF UID header, exact object rule과 같은 시간의 reject reason을 연결하지 않고 metric만으로 정책 변경을 승인하지 않는다. 빈 결과는 target 미수집, job/label 불일치, metric 미지원, 조회 창·권한·Prometheus API 실패로 분리한다.

## 상태 변경·rollback 경계

이 문서의 실행 명령은 읽기 전용이다. APF patch, API server 재시작, client QPS/Burst 일괄 상향, 폭주 workload scale, retry 폭증, gateway quota 우회, admission/audit 비활성화를 실행하지 않는다.

별도 변경은 fresh FlowSchema/PriorityLevel UID·RV, current kube-apiserver Pod UID/RV/containerID 또는 provider backend identity, 원 subject·verb·resource/subresource·namespace match, 같은 UTC evidence, 승인 ID·작업 창, 다른 priority level과 control-plane availability/quorum, 요청 idempotence·side effect, 승인 manifest revision과 rollback target을 **변경 명령 자체에서** 다시 확인해야 한다. 하나라도 바뀌면 `MUTATION_READY=false`다. rollback도 fresh identity와 실제 적용 revision을 확인한 `ROLLBACK_READY=true` 없이는 실행하지 않는다.

API server Pod/container 또는 APF object가 교체·재생성되면 이름을 재사용하지 않는다. 기존 자동값과 모든 downstream READY를 폐기하고 selector, current UID/RV, creation time, Pod→Node→current containerID와 APF UID relation을 처음부터 다시 등록한다.

## 정상화 검증

정상화는 같은 실행 host·승인된 method/path에서 response source가 확인된 정상 status로 돌아오고, 대상 FlowSchema/PriorityLevel reject 증가와 queue 포화가 멈추며, 다른 priority level·control-plane client가 악화되지 않고 실제 API 기능이 승인된 관찰 창 동안 성공할 때만 선언한다. gateway 원인이면 같은 external route의 quota/backend도 확인하고, client 원인이면 client 대기와 server response를 분리한다.

단일 2xx, `/readyz`, queue 한 번 감소는 정상화 근거가 아니다. 새 kube-apiserver가 생겼다면 새 UID/containerID로 재등록한 뒤 restart 안정과 실제 기능까지 확인한다.

## 증거와 미검증

method/redacted path, 원 429와 UTC, 실행 host·endpoint, curl/status/filter rc, `Retry-After`, APF header UID와 current object UID/RV·rule match, kube-apiserver Pod/Node/current container identity, 제한된 metric·log·단일 auditID, 승인/rollback과 실제 기능 결과만 보존한다. Authorization, token, Secret, private key, body, actor 상세와 전체 audit/log/metrics는 저장하지 않는다.

Kubernetes 1.26 APF API와 metric을 기준으로 했다. external gateway/provider, component label, audit source, Prometheus labels와 실제 정책은 환경 미검증이다.
