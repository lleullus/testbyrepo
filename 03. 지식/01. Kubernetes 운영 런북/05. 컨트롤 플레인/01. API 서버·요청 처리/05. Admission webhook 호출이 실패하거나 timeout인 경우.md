# Admission webhook 호출이 실패하거나 timeout인 경우

## 입력값과 빠른 수집

이 문서는 승인된 작업 PC 또는 bastion의 **같은 Bash**에서 실행한다. 실행 경로는 `작업 host의 kubectl -> API server -> admission configuration -> Service/URL -> EndpointSlice -> 현재 backend Pod UID/container -> webhook listener`다. 작업 host의 성공은 API server에서 backend까지의 성공을 보장하지 않는다.

| 종류 | 값 | 출처와 유효성 gate |
|---|---|---|
| 최초 입력 | `CONFIG_KIND`, `CONFIG`, `WEBHOOK` | 실제 API 오류에 나온 webhook과 승인된 configuration exact name. 한 번만 입력한다. |
| API 확인 자동값 | `CONFIG_UID`, `CONFIG_RV`, `CONFIG_OWNER`, `MODE`, Service·Pod identity | exact-name API 조회가 모두 성공하고 관계가 하나로 확정될 때만 등록한다. |
| 계산 후보값 | `WEBHOOK_RE`, EndpointSlice/Pod 후보 | 이름을 escape해 만들며 후보 수와 targetRef 관계를 확인하기 전에는 대상이 아니다. |
| 운영자 선택값 | 증거 창, 대표 요청, 변경 승인·관찰 창 | 직접 오류와 현재 identity를 본 뒤 해당 절에서만 정한다. |

`PASTE_..._HERE` 문자열은 각각 아래 입력 명령에 한 번만 있다. API 실패, 이름 재사용 또는 재등록 전에는 UID, resourceVersion, owner, Pod UID, containerID, node, Service/EndpointSlice/Pod 관계, 시간, 정규식과 모든 downstream `READY`를 폐기한다.

**Bash·도구 확인**

`TOOLS_READY=false; MISSING=''; for T in kubectl jq grep sed date mktemp awk; do command -v "$T" >/dev/null 2>&1 || MISSING="$MISSING $T"; done; if [ -n "${BASH_VERSION:-}" ] && [ -z "$MISSING" ]; then TOOLS_READY=true; printf 'TOOLS_READY=true bash=%s\n' "$BASH_VERSION"; else printf '중단: Bash 또는 도구 없음:%s\n' "$MISSING" >&2; fi`

**최초 입력·이전 상태 폐기**

`unset INPUT_READY AUTO_READY BACKEND_READY TIME_READY QUERY_READY CONFIG_UID CONFIG_RV CONFIG_OWNER MODE SERVICE_NS SERVICE_NAME SERVICE_UID SERVICE_RV SERVICE_PORT SERVICE_PATH ES_NAME ES_UID ES_RV POD POD_UID POD_RV POD_OWNER CONTROLLER_UID CONTAINER CONTAINER_ID NODE HOST WEBHOOK_RE START_RFC3339 END_RFC3339 START_EPOCH END_EPOCH; CONFIG_KIND='PASTE_VALIDATING_OR_MUTATING_KIND_HERE'; CONFIG='PASTE_CONFIGURATION_NAME_HERE'; WEBHOOK='PASTE_WEBHOOK_NAME_HERE'; INPUT_READY=false; if [ "$TOOLS_READY" != true ]; then printf '%s\n' '중단: TOOLS_READY가 아니다.' >&2; elif [ "$CONFIG_KIND" != validatingwebhookconfiguration ] && [ "$CONFIG_KIND" != mutatingwebhookconfiguration ]; then printf '%s\n' '중단: CONFIG_KIND가 허용값이 아니다.' >&2; elif JSON="$(kubectl get "$CONFIG_KIND" "$CONFIG" -o json)"; then COUNT="$(jq -r --arg w "$WEBHOOK" '[.webhooks[]? | select(.name==$w)]|length' <<<"$JSON")"; if [ "$COUNT" = 1 ]; then INPUT_READY=true; export CONFIG_KIND CONFIG WEBHOOK; printf 'INPUT_READY=true kind=%s config=%s webhook=%s\n' "$CONFIG_KIND" "$CONFIG" "$WEBHOOK"; else printf '중단: webhook exact match count=%s\n' "$COUNT" >&2; fi; else printf '%s\n' '중단: configuration API 실패, 이전 값 사용 금지' >&2; fi`

**현재 configuration과 client 경로 등록**

`unset AUTO_READY BACKEND_READY TIME_READY QUERY_READY CONFIG_UID CONFIG_RV CONFIG_OWNER MODE SERVICE_NS SERVICE_NAME SERVICE_UID SERVICE_RV SERVICE_PORT SERVICE_PATH ES_NAME ES_UID ES_RV POD POD_UID POD_RV POD_OWNER CONTROLLER_UID CONTAINER CONTAINER_ID NODE HOST WEBHOOK_RE; AUTO_READY=false; if [ "$INPUT_READY" != true ]; then printf '%s\n' '중단: INPUT_READY가 아니다.' >&2; elif JSON="$(kubectl get "$CONFIG_KIND" "$CONFIG" -o json)"; then COUNT="$(jq -r --arg w "$WEBHOOK" '[.webhooks[]? | select(.name==$w)]|length' <<<"$JSON")"; CONFIG_UID_TMP="$(jq -r '.metadata.uid // empty' <<<"$JSON")"; CONFIG_RV_TMP="$(jq -r '.metadata.resourceVersion // empty' <<<"$JSON")"; if [ "$COUNT" != 1 ] || [ -z "$CONFIG_UID_TMP" ] || [ -z "$CONFIG_RV_TMP" ]; then printf '%s\n' '중단: identity 또는 webhook 단일 일치 실패' >&2; else CONFIG_UID="$CONFIG_UID_TMP"; CONFIG_RV="$CONFIG_RV_TMP"; CONFIG_OWNER="$(jq -r '[.metadata.ownerReferences[]? | "\(.kind)/\(.name)#\(.uid)"]|join(",")' <<<"$JSON")"; SERVICE_NS="$(jq -r --arg w "$WEBHOOK" '.webhooks[]|select(.name==$w)|.clientConfig.service.namespace // empty' <<<"$JSON")"; SERVICE_NAME="$(jq -r --arg w "$WEBHOOK" '.webhooks[]|select(.name==$w)|.clientConfig.service.name // empty' <<<"$JSON")"; SERVICE_PORT="$(jq -r --arg w "$WEBHOOK" '.webhooks[]|select(.name==$w)|.clientConfig.service.port // 443' <<<"$JSON")"; SERVICE_PATH="$(jq -r --arg w "$WEBHOOK" '.webhooks[]|select(.name==$w)|.clientConfig.service.path // empty' <<<"$JSON")"; URL_SET="$(jq -r --arg w "$WEBHOOK" '.webhooks[]|select(.name==$w)|has("clientConfig") and (.clientConfig.url!=null)' <<<"$JSON")"; if [ -n "$SERVICE_NS" ] && [ -n "$SERVICE_NAME" ] && [ "$URL_SET" = false ]; then MODE=service; elif [ -z "$SERVICE_NS" ] && [ -z "$SERVICE_NAME" ] && [ "$URL_SET" = true ]; then MODE=url; else printf '%s\n' '중단: service/url clientConfig 관계가 단일하지 않음' >&2; MODE=''; fi; if [ -n "$MODE" ]; then WEBHOOK_RE="$(printf '%s' "$WEBHOOK" | sed 's/[][\\.^$*+?(){}|]/\\&/g')"; AUTO_READY=true; export CONFIG_UID CONFIG_RV CONFIG_OWNER MODE SERVICE_NS SERVICE_NAME SERVICE_PORT SERVICE_PATH WEBHOOK_RE; printf 'AUTO_READY=true\nConfiguration: %s uid=%s rv=%s owner=%s\nWebhook: %s regex=%s\nClient mode: %s\nService relation: %s/%s port=%s path=%s\n' "$CONFIG" "$CONFIG_UID" "$CONFIG_RV" "${CONFIG_OWNER:--}" "$WEBHOOK" "$WEBHOOK_RE" "$MODE" "${SERVICE_NS:--}" "${SERVICE_NAME:--}" "$SERVICE_PORT" "${SERVICE_PATH:--}"; fi; fi; else printf '%s\n' '중단: 등록 API 실패, stale 값 폐기됨' >&2; fi`

다음 fresh gate는 API를 직접 다시 읽어 UID·resourceVersion·webhook 단일 관계를 대조한다. 실패하면 downstream 값을 폐기하므로 같은 이름의 재생성 객체나 변경 전 설정을 계속 사용하지 않는다.

**fresh gate 함수 등록**

`invalidate_webhook(){ unset AUTO_READY BACKEND_READY TIME_READY QUERY_READY SERVICE_UID SERVICE_RV ES_NAME ES_UID ES_RV POD POD_UID POD_RV POD_OWNER CONTROLLER_UID CONTAINER CONTAINER_ID NODE HOST START_RFC3339 END_RFC3339 START_EPOCH END_EPOCH; AUTO_READY=false; }; fresh_webhook(){ local j uid rv count mode; j="$(kubectl get "$CONFIG_KIND" "$CONFIG" -o json)" || { invalidate_webhook; printf '%s\n' '중단: fresh API 실패' >&2; return 1; }; uid="$(jq -r '.metadata.uid // empty' <<<"$j")"; rv="$(jq -r '.metadata.resourceVersion // empty' <<<"$j")"; count="$(jq -r --arg w "$WEBHOOK" '[.webhooks[]? | select(.name==$w)]|length' <<<"$j")"; mode="$(jq -r --arg w "$WEBHOOK" '.webhooks[]|select(.name==$w)|if .clientConfig.service then "service" elif .clientConfig.url then "url" else "invalid" end' <<<"$j")"; if [ "$uid" = "$CONFIG_UID" ] && [ "$rv" = "$CONFIG_RV" ] && [ "$count" = 1 ] && [ "$mode" = "$MODE" ]; then return 0; fi; invalidate_webhook; printf '중단: configuration identity/lifecycle 변경 uid=%s rv=%s mode=%s, 전체 재등록 필요\n' "$uid" "$rv" "$mode" >&2; return 1; }`

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | API response·Event·API server 로그에 `failed calling webhook`, `context deadline exceeded`, `no endpoints available for service`, `x509`, `connection refused`가 직접 보임 |
| 적용 | 오류의 webhook 이름과 현재 configuration UID/RV, operation/resource/namespace, client 경로를 같은 UTC 증거 창에 연결할 수 있음 |
| 제외 | APF `429`, etcd storage timeout, 일반 인증·인가, API server 자체 장애는 해당 런북으로 이동. `failurePolicy=Ignore`나 configuration 삭제로 숨기지 않음 |

검색 문자열: `failed calling webhook`, `context deadline exceeded`, `no endpoints available for service`, `certificate signed by unknown authority`, `x509`, `connection refused`, `i/o timeout`.

## 최초 확인과 RBAC 경계

`fresh_webhook && kubectl auth can-i get "$CONFIG_KIND"`

Service mode에서만 현재 namespace의 정확한 read·log 권한을 확인한다. `yes`는 같은 주체·context·verb·resource의 허용만 뜻하며 실제 요청 성공을 보장하지 않는다.

`fresh_webhook && [ "$MODE" = service ] && kubectl auth can-i get services -n "$SERVICE_NS" && kubectl auth can-i get endpointslices.discovery.k8s.io -n "$SERVICE_NS" && kubectl auth can-i get pods -n "$SERVICE_NS" && kubectl auth can-i get pods/log -n "$SERVICE_NS"`

`Forbidden`이면 RBAC를 확대하지 않는다. Secret은 Pod spec에 참조된 **이름과 mount 관계만** 확인하고 `secrets` data, token, `caBundle`, private key를 출력하지 않는다. Audit은 승인된 audit reader가 `requestReceivedTimestamp`, `verb`, `objectRef`, `responseStatus`, webhook 관련 annotation의 존재만 같은 창에서 대조하며 request/response body와 token을 수집하지 않는다.

## 관측별 진단 경로

| 지금 보이는 것 | 먼저 볼 것 | 다음 경계 |
|---|---|---|
| `no endpoints available` | Service UID/RV와 EndpointSlice service-name/targetRef | selector·Pod readiness |
| timeout·refused | ready target Pod UID/containerID/node와 listener | API server->Service->Pod network/process |
| `x509` | Service DNS 또는 URL host, Secret 참조, SAN·유효기간 owner 증거 | TLS 발급·rotation·trust owner |
| backend Ready인데 호출 실패 | 같은 창의 API server 직접 로그와 representative request | API server network/TLS/admission |

### 1. Service·EndpointSlice·현재 backend identity

URL mode이면 URL 원문·credential을 출력하지 않고 API server 실행 위치에서의 DNS/LB/TLS 증거를 URL owner에게 요청한다. Service mode이면 다음 등록을 수행한다.

`unset PORT_READY SERVICE_PORT_NAME SERVICE_TARGET_PORT ENDPOINT_PORT; PORT_READY=false`

`unset BACKEND_READY SERVICE_UID SERVICE_RV ES_NAME ES_UID ES_RV POD POD_UID POD_RV POD_OWNER CONTROLLER_UID CONTAINER CONTAINER_ID NODE; BACKEND_READY=false; if fresh_webhook && [ "$MODE" = service ]; then SVC_JSON="$(kubectl get service "$SERVICE_NAME" -n "$SERVICE_NS" -o json)" && ES_JSON="$(kubectl get endpointslice -n "$SERVICE_NS" -l "kubernetes.io/service-name=$SERVICE_NAME" -o json)" || { printf '%s\n' '중단: Service/EndpointSlice API 실패' >&2; exit 1; }; SERVICE_UID="$(jq -r '.metadata.uid // empty' <<<"$SVC_JSON")"; SERVICE_RV="$(jq -r '.metadata.resourceVersion // empty' <<<"$SVC_JSON")"; mapfile -t READY_REFS < <(jq -r '[.items[] as $s | $s.endpoints[]? | select(.conditions.ready==true and .targetRef.kind=="Pod") | [$s.metadata.name,$s.metadata.uid,$s.metadata.resourceVersion,.targetRef.name,.targetRef.uid]] | unique | .[] | @tsv' <<<"$ES_JSON"); if [ -z "$SERVICE_UID" ] || [ "${#READY_REFS[@]}" -ne 1 ]; then printf '중단: Service identity 없음 또는 ready Pod target 단일 아님 count=%s\n' "${#READY_REFS[@]}" >&2; else IFS=$'\t' read -r ES_NAME ES_UID ES_RV POD POD_UID_REF <<<"${READY_REFS[0]}"; POD_JSON="$(kubectl get pod "$POD" -n "$SERVICE_NS" -o json)" || exit 1; POD_UID="$(jq -r '.metadata.uid // empty' <<<"$POD_JSON")"; POD_RV="$(jq -r '.metadata.resourceVersion // empty' <<<"$POD_JSON")"; NODE="$(jq -r '.spec.nodeName // empty' <<<"$POD_JSON")"; POD_OWNER="$(jq -r '[.metadata.ownerReferences[]? | "\(.kind)/\(.name)#\(.uid)"]|join(",")' <<<"$POD_JSON")"; CONTROLLER_UID="$(jq -r '[.metadata.ownerReferences[]?|select(.controller==true)][0].uid // empty' <<<"$POD_JSON")"; mapfile -t LIVE < <(jq -r '.status.containerStatuses[]?|select(.state.running!=null)|[.name,.containerID]|@tsv' <<<"$POD_JSON"); if [ "$POD_UID" != "$POD_UID_REF" ] || [ -z "$NODE" ] || [ "${#LIVE[@]}" -lt 1 ]; then printf '%s\n' '중단: targetRef UID 또는 running container 관계 불일치' >&2; else IFS=$'\t' read -r CONTAINER CONTAINER_ID <<<"${LIVE[0]}"; BACKEND_READY=true; export SERVICE_UID SERVICE_RV ES_NAME ES_UID ES_RV POD POD_UID POD_RV POD_OWNER CONTROLLER_UID CONTAINER CONTAINER_ID NODE; printf 'BACKEND_READY=true\nService: %s/%s uid=%s rv=%s\nEndpointSlice: %s uid=%s rv=%s\nPod: %s uid=%s rv=%s node=%s owner=%s controllerUID=%s\nContainer candidate: %s id=%s\n' "$SERVICE_NS" "$SERVICE_NAME" "$SERVICE_UID" "$SERVICE_RV" "$ES_NAME" "$ES_UID" "$ES_RV" "$POD" "$POD_UID" "$POD_RV" "$NODE" "${POD_OWNER:--}" "${CONTROLLER_UID:--}" "$CONTAINER" "$CONTAINER_ID"; fi; fi; fi`

running container가 여러 개면 첫 항목은 후보일 뿐이다. Pod spec의 container-port, readiness probe와 args 관계를 보고 webhook container를 정한 뒤 exact-name 존재를 fresh API로 검증한다. Endpoint `ready=true`와 `containerPort`는 listener·TLS·application 성공을 보장하지 않는다.

`fresh_backend(){ local s e p suid srv euid erv puid prv node cid; fresh_webhook || return 1; s="$(kubectl get service "$SERVICE_NAME" -n "$SERVICE_NS" -o json)" && e="$(kubectl get endpointslice "$ES_NAME" -n "$SERVICE_NS" -o json)" && p="$(kubectl get pod "$POD" -n "$SERVICE_NS" -o json)" || { BACKEND_READY=false; printf '%s\n' '중단: backend fresh API 실패' >&2; return 1; }; suid="$(jq -r '.metadata.uid' <<<"$s")"; srv="$(jq -r '.metadata.resourceVersion' <<<"$s")"; euid="$(jq -r '.metadata.uid' <<<"$e")"; erv="$(jq -r '.metadata.resourceVersion' <<<"$e")"; puid="$(jq -r '.metadata.uid' <<<"$p")"; prv="$(jq -r '.metadata.resourceVersion' <<<"$p")"; node="$(jq -r '.spec.nodeName // empty' <<<"$p")"; cid="$(jq -r --arg c "$CONTAINER" '.status.containerStatuses[]?|select(.name==$c)|.containerID // empty' <<<"$p")"; if [ "$suid" = "$SERVICE_UID" ] && [ "$srv" = "$SERVICE_RV" ] && [ "$euid" = "$ES_UID" ] && [ "$erv" = "$ES_RV" ] && [ "$puid" = "$POD_UID" ] && [ "$prv" = "$POD_RV" ] && [ "$node" = "$NODE" ] && [ "$cid" = "$CONTAINER_ID" ] && jq -e --arg p "$POD" --arg u "$POD_UID" 'any(.endpoints[]?; .conditions.ready==true and .targetRef.name==$p and .targetRef.uid==$u)' <<<"$e" >/dev/null; then return 0; fi; BACKEND_READY=false; printf '%s\n' '중단: backend identity/lifecycle 변경, 전체 재등록 필요' >&2; return 1; }`

running container가 여러 개인 경우 아래에서 webhook listener를 소유한 **regular container exact name**을 한 번 선택한다. Service port, `targetPort`, 선택 container의 named/numeric port와 현재 EndpointSlice port가 하나의 경로로 일치해야 로그와 listener 조사를 시작할 수 있다.

`CONTAINER='PASTE_WEBHOOK_CONTAINER_HERE'; PORT_READY=false; unset SERVICE_PORT_NAME SERVICE_TARGET_PORT ENDPOINT_PORT; if [ "$BACKEND_READY" != true ] || ! fresh_backend; then printf '%s\n' '중단: fresh backend gate 실패' >&2; elif SVC_NOW="$(kubectl get service "$SERVICE_NAME" -n "$SERVICE_NS" -o json)" && ES_NOW="$(kubectl get endpointslice "$ES_NAME" -n "$SERVICE_NS" -o json)" && POD_NOW="$(kubectl get pod "$POD" -n "$SERVICE_NS" -o json)"; then SP_COUNT="$(jq -r --argjson p "$SERVICE_PORT" '[.spec.ports[]?|select(.port==$p and (.protocol // "TCP")=="TCP")]|length' <<<"$SVC_NOW")"; CID_NOW="$(jq -r --arg c "$CONTAINER" '[.status.containerStatuses[]?|select(.name==$c and .state.running!=null)][0].containerID // empty' <<<"$POD_NOW")"; if [ "$SP_COUNT" != 1 ] || [ -z "$CID_NOW" ]; then printf '중단: Service port 단일 관계 또는 running container 불일치 count=%s container=%s\n' "$SP_COUNT" "$CONTAINER" >&2; else SERVICE_PORT_NAME="$(jq -r --argjson p "$SERVICE_PORT" '.spec.ports[]|select(.port==$p and (.protocol // "TCP")=="TCP")|.name // empty' <<<"$SVC_NOW")"; SERVICE_TARGET_PORT="$(jq -r --argjson p "$SERVICE_PORT" '.spec.ports[]|select(.port==$p and (.protocol // "TCP")=="TCP")|.targetPort // .port|tostring' <<<"$SVC_NOW")"; if [[ "$SERVICE_TARGET_PORT" =~ ^[0-9]+$ ]]; then RESOLVED_PORT="$SERVICE_TARGET_PORT"; else RESOLVED_PORT="$(jq -r --arg c "$CONTAINER" --arg n "$SERVICE_TARGET_PORT" '[.spec.containers[]|select(.name==$c)|.ports[]?|select(.name==$n and (.protocol // "TCP")=="TCP")][0].containerPort // empty' <<<"$POD_NOW")"; fi; if [ -z "$RESOLVED_PORT" ]; then printf '%s\n' '중단: targetPort를 선택 container에서 해석하지 못함' >&2; elif [ -n "$SERVICE_PORT_NAME" ]; then EP_COUNT="$(jq -r --arg n "$SERVICE_PORT_NAME" --argjson p "$RESOLVED_PORT" '[.ports[]?|select(.name==$n and .port==$p and (.protocol // "TCP")=="TCP")]|length' <<<"$ES_NOW")"; else EP_COUNT="$(jq -r --argjson p "$RESOLVED_PORT" '[.ports[]?|select(.port==$p and (.protocol // "TCP")=="TCP")]|length' <<<"$ES_NOW")"; fi; if [ "${EP_COUNT:-0}" = 1 ]; then CONTAINER_ID="$CID_NOW"; ENDPOINT_PORT="$RESOLVED_PORT"; PORT_READY=true; export CONTAINER CONTAINER_ID SERVICE_PORT_NAME SERVICE_TARGET_PORT ENDPOINT_PORT; printf 'PORT_READY=true service=%s:%s targetPort=%s endpointSlice=%s:%s pod=%s#%s container=regular/%s#%s\n' "$SERVICE_NAME" "$SERVICE_PORT" "$SERVICE_TARGET_PORT" "$ES_NAME" "$ENDPOINT_PORT" "$POD" "$POD_UID" "$CONTAINER" "$CONTAINER_ID"; else printf '중단: EndpointSlice port 단일 관계 실패 count=%s resolved=%s\n' "${EP_COUNT:-0}" "${RESOLVED_PORT:--}" >&2; fi; fi; else printf '%s\n' '중단: Service/EndpointSlice/Pod fresh API 실패' >&2; fi`

`fresh_service_path(){ local s e p cid resolved count; [ "$PORT_READY" = true ] || return 1; fresh_backend || { PORT_READY=false; return 1; }; s="$(kubectl get service "$SERVICE_NAME" -n "$SERVICE_NS" -o json)" && e="$(kubectl get endpointslice "$ES_NAME" -n "$SERVICE_NS" -o json)" && p="$(kubectl get pod "$POD" -n "$SERVICE_NS" -o json)" || { PORT_READY=false; return 1; }; cid="$(jq -r --arg c "$CONTAINER" '[.status.containerStatuses[]?|select(.name==$c and .state.running!=null)][0].containerID // empty' <<<"$p")"; if [[ "$SERVICE_TARGET_PORT" =~ ^[0-9]+$ ]]; then resolved="$SERVICE_TARGET_PORT"; else resolved="$(jq -r --arg c "$CONTAINER" --arg n "$SERVICE_TARGET_PORT" '[.spec.containers[]|select(.name==$c)|.ports[]?|select(.name==$n and (.protocol // "TCP")=="TCP")][0].containerPort // empty' <<<"$p")"; fi; if [ -n "$SERVICE_PORT_NAME" ]; then count="$(jq -r --arg n "$SERVICE_PORT_NAME" --argjson p "$ENDPOINT_PORT" '[.ports[]?|select(.name==$n and .port==$p and (.protocol // "TCP")=="TCP")]|length' <<<"$e")"; else count="$(jq -r --argjson p "$ENDPOINT_PORT" '[.ports[]?|select(.port==$p and (.protocol // "TCP")=="TCP")]|length' <<<"$e")"; fi; if [ "$cid" = "$CONTAINER_ID" ] && [ "$resolved" = "$ENDPOINT_PORT" ] && [ "$count" = 1 ]; then return 0; fi; PORT_READY=false; printf '%s\n' '중단: containerID 또는 Service/EndpointSlice port 관계 변경, 재등록 필요' >&2; return 1; }`

### 2. canonical UTC 증거 창과 로그

`START_RFC3339='PASTE_START_UTC_RFC3339_HERE'; END_RFC3339='PASTE_END_UTC_RFC3339_HERE'; TIME_READY=false; RFC3339_RE='^[0-9]{4}-(0[1-9]|1[0-2])-([0-2][0-9]|3[01])T([01][0-9]|2[0-3]):[0-5][0-9]:[0-5][0-9]Z$'; if [[ "$START_RFC3339" =~ $RFC3339_RE ]] && [[ "$END_RFC3339" =~ $RFC3339_RE ]]; then SROUND="$(date -u -d "$START_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)"; SRC=$?; EROUND="$(date -u -d "$END_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)"; ERC=$?; START_EPOCH="$(date -u -d "$START_RFC3339" +%s 2>/dev/null)"; END_EPOCH="$(date -u -d "$END_RFC3339" +%s 2>/dev/null)"; if [ "$SRC" -eq 0 ] && [ "$ERC" -eq 0 ] && [ "$SROUND" = "$START_RFC3339" ] && [ "$EROUND" = "$END_RFC3339" ] && [ "$START_EPOCH" -lt "$END_EPOCH" ]; then TIME_READY=true; export START_RFC3339 END_RFC3339; printf 'TIME_READY=true window=%s..%s\n' "$START_RFC3339" "$END_RFC3339"; else printf '%s\n' '중단: UTC round-trip 또는 start<end 실패' >&2; fi; else printf '%s\n' '중단: canonical UTC RFC3339 형식 아님' >&2; fi`

Pod 로그는 producer와 filter의 rc를 분리한다. filter rc `1`은 일치 없음이며 오류 없음이 아니다. rc `>1`은 필터 자체 실패다.

`if [ "$TIME_READY" != true ] || [ "$PORT_READY" != true ] || ! fresh_service_path; then printf '%s\n' '중단: fresh service-path/time gate 실패' >&2; else RAW="$(mktemp)"; WIN="$(mktemp)"; kubectl logs "$POD" -n "$SERVICE_NS" -c "$CONTAINER" --timestamps --since-time="$START_RFC3339" >"$RAW"; PRODUCER_RC=$?; if [ "$PRODUCER_RC" -eq 0 ]; then awk -v end="$END_RFC3339" '$1<=end' "$RAW" >"$WIN"; WINDOW_RC=$?; if [ "$WINDOW_RC" -eq 0 ]; then grep -E -i -C 3 'listen|ready|tls|x509|certificate|handshake|timeout|refused|reset|error|panic' "$WIN"; FILTER_RC=$?; printf 'producer_rc=%s window_rc=%s filter_rc=%s evidence_window=%s..%s\n' "$PRODUCER_RC" "$WINDOW_RC" "$FILTER_RC" "$START_RFC3339" "$END_RFC3339"; fi; else printf '중단: log producer rc=%s\n' "$PRODUCER_RC" >&2; fi; rm -f "$RAW" "$WIN"; fi`

출력은 `END_RFC3339` 이후 행을 증거로 채택하지 않는다. Kubernetes 1.26의 `kubectl logs`에는 종료 시각 옵션이 없으므로 timestamp가 창 안인지 확인한다. 민감정보가 보이면 출력·저장을 중단하고 시각·오류 유형만 남긴다.

## Prometheus 쿼리 생성

실제 Prometheus에 해당 metric과 `name` label이 수집되는 환경에서만 사용한다. 정규식은 등록된 exact webhook 이름에서 escape해 생성됐다.

`fresh_webhook && printf 'histogram_quantile(0.99,sum by(le,name,operation,type)(rate(apiserver_admission_webhook_admission_duration_seconds_bucket{name=~"^%s$"}[5m])))\n' "$WEBHOOK_RE"`

`fresh_webhook && printf 'sum by(name,operation,type)(rate(apiserver_admission_webhook_admission_duration_seconds_count{name=~"^%s$"}[5m]))\n' "$WEBHOOK_RE"`

출력된 완성 쿼리만 승인된 Prometheus/Grafana에 붙여 넣는다. 빈 결과는 성공이 아니라 metric 미수집, label 불일치, 조회 cluster/시간 범위 오류, 권한/API 실패 후보다. query API의 HTTP status와 Prometheus `status=success`, non-empty data를 각각 확인하기 전에는 정상으로 판정하지 않는다.

## 상태 변경 분리와 정상화

이 문서는 `failurePolicy` 변경, configuration 삭제, selector 수정, Pod 삭제·rollout, 인증서 교체 명령을 제공하지 않는다. 별도 변경은 매 실행 직전에 fresh target/evidence, 승인 ID와 유효 window, 영향 범위와 quorum 성격의 backend 가용성, 요청 멱등성, 중단 기준을 다시 확인한다. rollback은 원래 configuration UID/RV의 승인된 선언 원본과 실제 복원 검증이 있어야 하며 “되돌릴 수 있음”이라는 설명만으로 통과하지 않는다.

controller가 backend를 교체한 경우 이름의 유사성으로 선택하지 않는다. 확인된 selector로 조회한 뒤 owner UID, controller UID, creationTimestamp가 변경 이후이고 후보가 정확히 하나인 경우에만 replacement로 선택한다. 그 뒤 기존 UID/RV·containerID·node·관계·시간·정규식과 모든 `READY`를 폐기하고 처음부터 재등록한다. 후보가 0개 또는 2개 이상이면 자동 선택하지 않는다.

정상화는 fresh configuration -> fresh Service/EndpointSlice/Pod identity -> listener/TLS -> 같은 증거 창의 API server 호출 -> 승인된 representative admission 요청 순서로 확인한다. representative CREATE/UPDATE는 실제 제품 경로를 우선하며, server dry-run은 webhook `sideEffects`와 조직 정책이 허용하고 요청의 외부 부작용·멱등성이 확인된 경우에만 사용한다. 같은 오류가 관찰 창에서 재발하지 않고 의도한 allow/deny/mutation 결과와 실제 API 기능이 정상이어야 한다. `Running`, Endpoint `ready`, HTTP 200 또는 빈 metric만으로 정상화하지 않는다.
