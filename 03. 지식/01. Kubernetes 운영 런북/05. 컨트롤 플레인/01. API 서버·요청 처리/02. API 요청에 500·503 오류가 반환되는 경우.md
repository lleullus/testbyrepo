# API 요청에 500·503 오류가 반환되는 경우

## 입력값과 빠른 수집

실행 경로는 `원 client → DNS/TLS/VIP/LB → kube-apiserver instance → API handler → admission 또는 aggregation 또는 etcd storage`다. HTTP 500/503은 어느 HTTP hop이 응답했다는 증거이지 생성 주체나 원인을 단독 확정하지 않는다.

| 종류 | 변수 | 출처와 gate |
|---|---|---|
| 최초 입력 | `REQ_METHOD`, `REQ_PATH`, `ORIGINAL_STATUS` | 원 transcript의 비식별화 method/path/status |
| 로컬 자동값 | `API_URL`, `COLLECTED_UTC` | kubeconfig server와 현재 UTC |
| API 자동값 | `APISERVER_UIDS`, `APISERVER_RVS`, `APISERVER_NODES` | API가 응답할 때 component 후보에서 수집 |
| 계산값 | `PATH_RE`, `JOB_RE`, `READ_ONLY` | log regex escape, PromQL label escape, GET/HEAD 여부 |
| 운영자 선택값 | `START_UTC`, `END_UTC`, `PROM_JOB`, 분기별 exact `APISERVICE` 또는 `WEBHOOK_CONFIG` | 원 실패보다 앞선 창과 직접 response를 근거로 선택 |

### 1. 도구·최초 입력·자동값

`TOOLS_READY=false; MISSING=''; [ -n "${BASH_VERSION:-}" ] || MISSING=' bash'; for T in kubectl jq date sed grep mktemp; do command -v "$T" >/dev/null 2>&1 || MISSING="$MISSING $T"; done; if [ -z "$MISSING" ]; then TOOLS_READY=true; printf 'TOOLS_READY=true bash=%s\n' "$BASH_VERSION"; else printf '중단: 없는 도구=%s\n' "$MISSING" >&2; fi`

`unset INPUT_READY LOCAL_READY API_READY TIME_READY REQUEST_READY HEALTH_READY BRANCH_READY RELATION_READY SERVICE_READY LOG_READY METRIC_READY CHANGE_READY DOWNSTREAM_READY API_URL COLLECTED_UTC APISERVER_UIDS APISERVER_RVS APISERVER_NODES APISERVER_POD APISERVER_UID APISERVER_RV POD_NODE OWNER_KIND OWNER_UID CONTAINER_IDS CONTAINER_ID NODE_UID NODE_RV HOST_ID HOST_RELATION START_UTC END_UTC START_EPOCH END_EPOCH PATH_RE JOB_RE READ_ONLY APISERVICE APISERVICE_UID APISERVICE_RV SERVICE_NS SERVICE_NAME SERVICE_UID SERVICE_RV ENDPOINTSLICE_UIDS WEBHOOK_CONFIG WEBHOOK_UID WEBHOOK_RV PROM_JOB ARGV_RE CRI_ENDPOINT RUNTIME_UNIT; REQ_METHOD='PASTE_ORIGINAL_HTTP_METHOD_HERE'; REQ_PATH='PASTE_REDACTED_API_PATH_HERE'; ORIGINAL_STATUS='PASTE_500_OR_503_HERE'; INPUT_READY=false; LOCAL_READY=false; if [ "$TOOLS_READY" = true ] && [[ "$REQ_METHOD" =~ ^(GET|HEAD|POST|PUT|PATCH|DELETE)$ ]] && [[ "$REQ_PATH" =~ ^/ ]] && [[ "$ORIGINAL_STATUS" =~ ^(500|503)$ ]]; then INPUT_READY=true; fi; if [ "$INPUT_READY" = true ] && API_URL_TMP="$(kubectl config view --minify -o json | jq -er '.clusters|if length==1 then .[0].cluster.server else error("cluster count") end')" && NOW_TMP="$(date -u '+%Y-%m-%dT%H:%M:%SZ')"; then API_URL="$API_URL_TMP"; COLLECTED_UTC="$NOW_TMP"; PATH_RE="$(printf '%s' "$REQ_PATH" | sed 's/[][\\.^$*+?(){}|]/\\&/g')"; READ_ONLY=false; [[ "$REQ_METHOD" =~ ^(GET|HEAD)$ ]] && READ_ONLY=true; LOCAL_READY=true; export REQ_METHOD REQ_PATH ORIGINAL_STATUS API_URL COLLECTED_UTC PATH_RE READ_ONLY; printf 'LOCAL_READY=true method=%s path=%s status=%s collected=%s READ_ONLY=%s PATH_RE=%s\n' "$REQ_METHOD" "$REQ_PATH" "$ORIGINAL_STATUS" "$COLLECTED_UTC" "$READ_ONLY" "$PATH_RE"; else printf '%s\n' '중단: 입력 또는 local 자동 수집 실패' >&2; fi`

request path에 token·개인정보·secret query가 있으면 중단하고 redaction한 path만 사용한다. write body는 저장하거나 재전송하지 않는다.

### 2. API identity와 시간 창

재조회 전에 identity/RV/owner/containerID/node/host/relation/time/argv-regex와 모든 downstream READY를 폐기한다. 실패 뒤 stale component/service 값을 재사용하지 않는다.

`unset API_READY TIME_READY REQUEST_READY HEALTH_READY BRANCH_READY RELATION_READY SERVICE_READY LOG_READY METRIC_READY CHANGE_READY DOWNSTREAM_READY APISERVER_UIDS APISERVER_RVS APISERVER_NODES APISERVER_POD APISERVER_UID APISERVER_RV POD_NODE OWNER_KIND OWNER_UID CONTAINER_IDS CONTAINER_ID NODE_UID NODE_RV HOST_ID HOST_RELATION START_UTC END_UTC START_EPOCH END_EPOCH JOB_RE APISERVICE APISERVICE_UID APISERVICE_RV SERVICE_NS SERVICE_NAME SERVICE_UID SERVICE_RV ENDPOINTSLICE_UIDS WEBHOOK_CONFIG WEBHOOK_UID WEBHOOK_RV PROM_JOB ARGV_RE CRI_ENDPOINT RUNTIME_UNIT; API_READY=false; if [ "$LOCAL_READY" != true ]; then printf '%s\n' '중단: LOCAL_READY가 아니다.' >&2; elif PODS_JSON="$(kubectl get pods -n kube-system -l component=kube-apiserver -o json)"; then APISERVER_UIDS="$(jq -r '[.items[].metadata.uid]|join(",")' <<<"$PODS_JSON")"; APISERVER_RVS="$(jq -r '[.items[].metadata.resourceVersion]|join(",")' <<<"$PODS_JSON")"; APISERVER_NODES="$(jq -r '[.items[].spec.nodeName]|join(",")' <<<"$PODS_JSON")"; jq -r '.items[]|"=== kube-apiserver candidate ===\nPod: \(.metadata.name)\nUID: \(.metadata.uid)\nRV: \(.metadata.resourceVersion)\nNode: \(.spec.nodeName)\nReady: \([.status.containerStatuses[]?.ready]|join(","))\nContainer/ID: \([.status.containerStatuses[]?|"\(.name)=\(.containerID//"-")"]|join(";"))"' <<<"$PODS_JSON"; API_READY=true; export APISERVER_UIDS APISERVER_RVS APISERVER_NODES; printf 'API_READY=true candidates=%s\n' "$(jq '.items|length' <<<"$PODS_JSON")"; else printf '%s\n' 'API component 조회 실패: managed/selector/권한/API 상태를 분리하고 stale 값 폐기됨' >&2; fi`

`if [ "$API_READY" = true ] && [ "$(jq '.items|length' <<<"$PODS_JSON")" -lt 1 ]; then API_READY=false; unset APISERVER_UIDS APISERVER_RVS APISERVER_NODES; printf '%s\n' '중단: kube-apiserver 후보 0건; selector/managed 환경을 분리' >&2; fi`

`START_UTC='PASTE_START_UTC_RFC3339_HERE'; END_UTC='PASTE_END_UTC_RFC3339_HERE'; PROM_JOB='PASTE_PROMETHEUS_JOB_LABEL_HERE'`

`TIME_READY=false; unset START_EPOCH END_EPOCH JOB_RE LOG_READY METRIC_READY DOWNSTREAM_READY; if [[ "$START_UTC" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] && [[ "$END_UTC" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] && [ "$(date -u -d "$START_UTC" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" = "$START_UTC" ] && [ "$(date -u -d "$END_UTC" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" = "$END_UTC" ]; then START_EPOCH="$(date -u -d "$START_UTC" +%s)"; END_EPOCH="$(date -u -d "$END_UTC" +%s)"; [ "$START_EPOCH" -lt "$END_EPOCH" ] && TIME_READY=true; fi; JOB_RE="$(printf '%s' "$PROM_JOB" | sed 's/\\/\\\\/g; s/"/\\"/g')"; export START_UTC END_UTC PROM_JOB JOB_RE; printf 'TIME_READY=%s start=%s end=%s JOB_RE=%s\n' "$TIME_READY" "$START_UTC" "$END_UTC" "$JOB_RE"`

`PROM_READY=false; [ "$TIME_READY" = true ] && [ -n "$PROM_JOB" ] && PROM_READY=true; printf 'PROM_READY=%s\n' "$PROM_READY"`

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | 원 요청의 HTTP status가 500 또는 503이고 method/path/UTC가 있음 |
| 적용 | 응답 source와 core/aggregation/admission/storage/process 경계를 read-only로 분리 가능 |
| 제외 | HTTP status 없는 transport 실패는 [[01. kube-apiserver health endpoint가 실패하거나 API endpoint에 연결할 수 없는 경우]], 429는 [[04. API 요청에 429 Too Many Requests가 반환되는 경우]] |

검색 문자열: `Internal Server Error`, `Service Unavailable`, `FailedDiscoveryCheck`, `no endpoints available`, `failed calling webhook`, `etcdserver: request timed out`, `context deadline exceeded`.

## 최초 확인

원 요청이 GET/HEAD이고 재조회가 승인된 경우만 1회 실행한다. write는 절대 재생하지 않는다.

`REQUEST_READY=false; if [ "$LOCAL_READY" != true ] || [ "$READ_ONLY" != true ]; then printf '%s\n' '중단: 승인 가능한 read-only 원 요청이 아니다.' >&2; elif BODY="$(kubectl get --raw="$REQ_PATH")"; then REQUEST_READY=true; printf 'REQUEST_READY=true bytes=%s; body는 출력·저장하지 않음\n' "${#BODY}"; unset BODY; else RC=$?; printf 'request_rc=%s; stderr/status를 원 transcript와 분리 기록\n' "$RC" >&2; fi`

`HEALTH_READY=false; if [ "$LOCAL_READY" != true ]; then printf '%s\n' '중단: LOCAL_READY가 아니다.' >&2; elif LIVE="$(kubectl get --raw='/livez?verbose')" && READY="$(kubectl get --raw='/readyz?verbose')"; then printf '%s\n%s\n' "$LIVE" "$READY"; if ! grep -Fq '[-]' <<<"$LIVE" && ! grep -Fq '[-]' <<<"$READY"; then HEALTH_READY=true; fi; printf 'HEALTH_READY=%s\n' "$HEALTH_READY"; else printf '%s\n' 'health 조회 실패: 연결/RBAC/status를 원 5xx와 분리' >&2; fi`

`HEALTH_READY=true`는 특정 path 성공을 보장하지 않는다. 한 path 5xx를 cluster 전체로 확대하지 않는다.

## 관측별 진단 경로

| 지금 보이는 것 | 직접 증거 | 다음 경계 |
|---|---|---|
| built-in API의 5xx | response/log의 storage·panic·webhook 문자열 | admission/storage/process |
| aggregated group의 503 | APIService Available reason | Service→EndpointSlice→extension backend |
| write와 `failed calling webhook` | webhook name/rule/service | webhook backend/TLS/network |
| `[-]etcd` 또는 storage timeout | 같은 UTC의 API log | actual etcd client path·quorum owner |
| 특정 VIP/backend만 5xx | read-only 동일 path와 backend identity | LB/control-plane instance |

## 분기별 read-only gate

### 1. Aggregated API

`APISERVICE='PASTE_EXACT_APISERVICE_NAME_HERE'`

`SERVICE_READY=false; unset APISERVICE_UID APISERVICE_RV SERVICE_NS SERVICE_NAME SERVICE_UID SERVICE_RV ENDPOINTSLICE_UIDS DOWNSTREAM_READY; if [ "$LOCAL_READY" != true ] || [ -z "$APISERVICE" ]; then printf '%s\n' '중단: APIService exact name이 없다.' >&2; elif AS_JSON="$(kubectl get apiservice "$APISERVICE" -o json)" && AS_UID_TMP="$(jq -er '.metadata.uid' <<<"$AS_JSON")" && AS_RV_TMP="$(jq -er '.metadata.resourceVersion' <<<"$AS_JSON")" && NS_TMP="$(jq -er '.spec.service.namespace' <<<"$AS_JSON")" && SVC_TMP="$(jq -er '.spec.service.name' <<<"$AS_JSON")" && SVC_JSON="$(kubectl get service "$SVC_TMP" -n "$NS_TMP" -o json)" && SVC_UID_TMP="$(jq -er '.metadata.uid' <<<"$SVC_JSON")" && SVC_RV_TMP="$(jq -er '.metadata.resourceVersion' <<<"$SVC_JSON")" && EPS_JSON="$(kubectl get endpointslices -n "$NS_TMP" -l "kubernetes.io/service-name=$SVC_TMP" -o json)"; then APISERVICE_UID="$AS_UID_TMP"; APISERVICE_RV="$AS_RV_TMP"; SERVICE_NS="$NS_TMP"; SERVICE_NAME="$SVC_TMP"; SERVICE_UID="$SVC_UID_TMP"; SERVICE_RV="$SVC_RV_TMP"; ENDPOINTSLICE_UIDS="$(jq -r '[.items[].metadata.uid]|join(",")' <<<"$EPS_JSON")"; SERVICE_READY=true; jq -r '"APIService UID: \(.metadata.uid)\nRV: \(.metadata.resourceVersion)\nAvailable: \([.status.conditions[]|select(.type=="Available")|.status][0]//"-")\nReason: \([.status.conditions[]|select(.type=="Available")|.reason][0]//"-")\nService: \(.spec.service.namespace)/\(.spec.service.name)"' <<<"$AS_JSON"; jq -r '.items[]|"EndpointSlice: \(.metadata.name) UID=\(.metadata.uid) RV=\(.metadata.resourceVersion) ready=\([.endpoints[]?.conditions.ready]|join(",")) ports=\([.ports[]?|"\(.name//"-"):\(.port)"]|join(","))"' <<<"$EPS_JSON"; else printf '%s\n' '중단: APIService→Service→EndpointSlice relation 실패, stale 값 폐기됨' >&2; fi`

Ready endpoint는 listener·TLS·extension API 기능을 보장하지 않는다. Service selector/port, EndpointSlice targetRef UID와 backend Pod UID/container/port 관계를 owner가 확인한다. CA bundle 원문이나 `insecureSkipTLSVerify` 변경은 금지한다.

### 2. Admission webhook

`WEBHOOK_CONFIG='PASTE_EXACT_WEBHOOK_CONFIGURATION_HERE'`

`RELATION_READY=false; unset WEBHOOK_UID WEBHOOK_RV SERVICE_NS SERVICE_NAME SERVICE_UID SERVICE_RV ENDPOINTSLICE_UIDS DOWNSTREAM_READY; if [ "$REQ_METHOD" = GET ] || [ "$REQ_METHOD" = HEAD ]; then printf '%s\n' '중단: read 요청을 admission webhook 원인으로 분류하지 않는다.' >&2; elif WH_JSON="$(kubectl get validatingwebhookconfiguration "$WEBHOOK_CONFIG" -o json)" && WH_UID_TMP="$(jq -er '.metadata.uid' <<<"$WH_JSON")" && WH_RV_TMP="$(jq -er '.metadata.resourceVersion' <<<"$WH_JSON")"; then WEBHOOK_UID="$WH_UID_TMP"; WEBHOOK_RV="$WH_RV_TMP"; jq -r '.webhooks[]|"name=\(.name) failurePolicy=\(.failurePolicy) timeout=\(.timeoutSeconds) service=\(.clientConfig.service.namespace//"-")/\(.clientConfig.service.name//"-") path=\(.clientConfig.service.path//"-") urlConfigured=\(.clientConfig.url!=null) operations=\([.rules[]?.operations[]?]|unique|join(",")) resources=\([.rules[]?.resources[]?]|unique|join(","))"' <<<"$WH_JSON"; RELATION_READY=true; else printf '%s\n' 'validating kind 조회 실패: 실제 kind가 Mutating이면 resource type만 바꿔 exact 조회' >&2; fi`

response/log의 webhook name과 config의 rule·operation·resource가 원 요청과 정확히 맞아야 한다. URL, CA bundle, Secret을 출력하지 않는다. `failurePolicy=Ignore`, timeout 증가, webhook 삭제는 보안 경계를 약화하므로 일반 복구가 아니다.

### 3. API server log와 pipeline rc

`APISERVER_POD='PASTE_EXACT_APISERVER_POD_HERE'; APISERVER_CONTAINER='PASTE_EXACT_APISERVER_CONTAINER_HERE'`

`LOG_READY=false; unset APISERVER_UID APISERVER_RV POD_NODE CONTAINER_IDS CONTAINER_ID DOWNSTREAM_READY; if [ "$API_READY" != true ] || [ "$TIME_READY" != true ]; then printf '%s\n' '중단: API/time gate가 아니다.' >&2; elif AP_JSON="$(kubectl get pod "$APISERVER_POD" -n kube-system -o json)" && CONTAINER_ID_TMP="$(jq -er --arg c "$APISERVER_CONTAINER" '[.status.containerStatuses[]?|select(.name==$c)|.containerID]|if length==1 and .[0]!="" then .[0] else error("current containerID") end' <<<"$AP_JSON")"; then APISERVER_UID="$(jq -r '.metadata.uid' <<<"$AP_JSON")"; APISERVER_RV="$(jq -r '.metadata.resourceVersion' <<<"$AP_JSON")"; POD_NODE="$(jq -r '.spec.nodeName' <<<"$AP_JSON")"; CONTAINER_ID="$CONTAINER_ID_TMP"; LOG_READY=true; export APISERVER_UID APISERVER_RV POD_NODE APISERVER_CONTAINER CONTAINER_ID; printf 'LOG_READY=true pod=%s uid=%s rv=%s node=%s container=%s current_id=%s\n' "$APISERVER_POD" "$APISERVER_UID" "$APISERVER_RV" "$POD_NODE" "$APISERVER_CONTAINER" "$CONTAINER_ID"; else printf '%s\n' '중단: Pod/container current identity 실패' >&2; fi`

`if [ "$LOG_READY" != true ]; then printf '%s\n' '중단: LOG_READY가 아니다.' >&2; elif CURRENT_AP_JSON="$(kubectl get pod "$APISERVER_POD" -n kube-system -o json)" && [ "$(jq -r '.metadata.uid' <<<"$CURRENT_AP_JSON")" = "$APISERVER_UID" ] && [ "$(jq -r '.metadata.resourceVersion' <<<"$CURRENT_AP_JSON")" = "$APISERVER_RV" ] && [ "$(jq -r --arg c "$APISERVER_CONTAINER" '.status.containerStatuses[]?|select(.name==$c)|.containerID' <<<"$CURRENT_AP_JSON")" = "$CONTAINER_ID" ]; then TMP="$(mktemp)" || exit 1; if kubectl logs "$APISERVER_POD" -n kube-system -c "$APISERVER_CONTAINER" --timestamps --since-time="$START_UTC" --tail=400 >"$TMP"; then PRODUCER_RC=0; else PRODUCER_RC=$?; fi; if [ "$PRODUCER_RC" -eq 0 ]; then if grep -E -i -C 3 "$PATH_RE|etcdserver: request timed out|failed calling webhook|no endpoints available|context deadline exceeded|panic|fatal|500|503" "$TMP"; then FILTER_RC=0; else FILTER_RC=$?; fi; else FILTER_RC=125; fi; printf 'producer_rc=%s filter_rc=%s pod_uid=%s current_container_id=%s\n' "$PRODUCER_RC" "$FILTER_RC" "$APISERVER_UID" "$CONTAINER_ID"; rm -f "$TMP"; [ "$PRODUCER_RC" -eq 0 ] && [ "$FILTER_RC" -le 1 ]; else LOG_READY=false; printf '%s\n' '중단: Pod UID/RV/current containerID 변경; 재등록 필요' >&2; fi`

producer rc와 filter rc를 분리한다. filter rc 1은 오류 부재가 아니라 선택한 Pod UID/시간/regex에서 무일치다. managed control plane은 같은 필드·UTC 범위를 provider에게 요청한다. audit는 audit ID, verb, redacted URI, objectRef UID, responseStatus, stage timestamps만 최소 공개하고 subject·sourceIP·body는 redaction한다.

audit 상관은 원 transcript에서 확인한 단일 `auditID`만 사용한다. timestamp, verb, resource/subresource, namespace/name, redacted requestURI, status와 현재 lifecycle UID가 모두 맞지 않으면 해당 audit 행을 이 5xx의 증거로 연결하지 않는다.

## 상태 변경 경계

진단은 read-only다. write 재시도, APIService/webhook/TLS 완화, kube-apiserver·etcd restart, LB backend 제거를 실행하지 않는다. 변경에는 fresh object UID/RV와 backend Pod/container identity, response/audit/log relation, 대상·영향, approval/window/quorum, idempotence·외부 side effect, rollback target/source revision과 중단 조건이 필요하다. rollback 직전 fresh target/evidence를 재확인하고 replacement는 새 UID/containerID로 재등록한다.

## 정상화 검증

원 GET/HEAD가 승인되면 같은 method/path를 1회 확인한다. write는 승인된 idempotent synthetic 또는 실제 client 결과만 사용한다. 동일 500/503 중단, health, APIService/webhook Service→EndpointSlice→backend, etcd/provider 경계, 새 API server Pod/container 안정과 실제 API 기능이 관찰 창 동안 모두 정상이어야 한다.

## Prometheus 빠른 관측

`if [ "$TIME_READY" = true ] && [ "$PROM_READY" = true ]; then printf 'sum by(instance,code,verb,resource,subresource) (rate(apiserver_request_total{job="%s",code=~"500|503"}[5m])) > 0\n' "$JOB_RE"; printf 'sum by(instance,request_kind) (apiserver_current_inflight_requests{job="%s"})\n' "$JOB_RE"; printf 'sum by(instance,flow_schema,priority_level,reason) (rate(apiserver_flowcontrol_rejected_requests_total{job="%s"}[5m])) > 0\n' "$JOB_RE"; else printf '%s\n' '중단: current TIME_READY/PROM_READY가 아니다.' >&2; fi`

빈 결과는 0/정상이 아니다. metric 미수집, label/schema 불일치, 시간 범위, Prometheus 권한/API 실패를 분리한다. APF reject가 없어도 aggregation/admission/storage/LB 원인은 배제되지 않는다.

## 증거와 미검증

method/redacted path/status/UTC, endpoint, API server Pod/Node/container UID·RV relation, APIService/webhook/Service/EndpointSlice UID·RV, producer/filter rc, 최소 RBAC/audit 필드, 승인/rollback과 실제 기능을 보존한다. body·token·CA bundle·Secret·private key·전체 log/metrics는 저장하지 않는다.

Kubernetes 1.26 aggregation, admission, APF와 health endpoint를 기준으로 했다. LB/provider, selector, CRI/runtime, etcd, audit와 metric labels는 환경 미검증이다.
