# 여러 controller의 조정이 동시에 진행되지 않는 경우

## 입력값과 빠른 수집

이 런북은 서로 다른 세 resource kind의 조정 정체가 같은 시간 창에 직접 확인된 경우만 사용한다. 경로는 `작업 PC/bastion Bash → API server → controller-manager Pod/leader/API client/workqueue → 세 resource의 status → 실제 기능`이다.

| 입력 종류 | 변수 | 출처와 gate |
|---|---|---|
| 최초 입력 | controller-manager `NS`·`POD`, 영향 `RNS`와 Deployment·StatefulSet·DaemonSet exact name | 네 exact-name API 조회가 모두 성공해야 한다. |
| API 확인 자동값 | component와 세 resource의 UID·RV·generation·owner/node/container 관계 | 한 호출이라도 실패하면 전부 무효화한다. |
| 계산 후보값 | `POD_RE`, 세 resource regex, `ARGV_RE` | literal 이름을 regex escape한 bounded 값이다. |
| 운영자 선택값 | component container, client subject, UTC 창, metrics job, host/unit | 자동 출력·audit·inventory 확인 뒤 선택한다. |

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | 세 kind의 generation/status가 같은 canonical UTC 창에서 함께 진행하지 않고 단일 workload 원인으로 설명되지 않는 경우 |
| 적용 | component identity → leader → API list/watch·RBAC → workqueue → 각 resource status 관계를 대조할 수 있는 경우 |
| 제외 | 한 kind/한 workload만 멈추거나 `FailedScheduling`, PVC, image, spec 오류가 직접 원인이면 해당 workload 런북으로 이동 |

검색 문자열: `observedGeneration`, `Failed to list`, `Failed to watch`, `forbidden`, `workqueue`, `leader election`, `failed to renew lease`, `context deadline exceeded`.

## 관측별 진단 경로

| 지금 보이는 것 | 먼저 볼 것 | 그다음 어디를 볼지 | 상세 절 |
|---|---|---|---|
| 세 kind status가 함께 정지 | current UID/RV/generation/status | component·leader·API | [[#1. 세 resource의 동시성 증거]] |
| list/watch·Forbidden | exact resource와 audit subject | RBAC·API server | [[#2. component 로그와 RBAC]] |
| process/leader/API는 정상, 여러 queue 증가 | 실제 queue name과 rate | controller handler/dependency | [[#3. workqueue와 정상화 경계]] |

### 1. 세 resource의 동시성 증거

`RESOURCE_READY=false; unset EVENT_READY LOG_READY RBAC_READY METRIC_READY NORMALIZE_READY; if [ "$AUTO_READY" != true ] || [ "$TIME_READY" != true ]; then printf '%s\n' '중단: auto/time gate 실패.' >&2; elif DJ="$(kubectl get deployment "$DEP" -n "$RNS" -o json)" && SJ="$(kubectl get statefulset "$STS" -n "$RNS" -o json)" && XJ="$(kubectl get daemonset "$DS" -n "$RNS" -o json)" && [ "$(jq -r '.metadata.uid' <<<"$DJ")" = "$DEP_UID" ] && [ "$(jq -r '.metadata.uid' <<<"$SJ")" = "$STS_UID" ] && [ "$(jq -r '.metadata.uid' <<<"$XJ")" = "$DS_UID" ]; then RESOURCE_READY=true; printf 'RESOURCE_READY=true observed=%s\n' "$(date -u '+%Y-%m-%dT%H:%M:%SZ')"; jq -r '"Deployment UID=\(.metadata.uid) RV=\(.metadata.resourceVersion) generation=\(.metadata.generation) observed=\(.status.observedGeneration//"-") desired=\(.spec.replicas//0) ready=\(.status.readyReplicas//0)"' <<<"$DJ"; jq -r '"StatefulSet UID=\(.metadata.uid) RV=\(.metadata.resourceVersion) generation=\(.metadata.generation) observed=\(.status.observedGeneration//"-") currentRevision=\(.status.currentRevision//"-") updateRevision=\(.status.updateRevision//"-") ready=\(.status.readyReplicas//0)"' <<<"$SJ"; jq -r '"DaemonSet UID=\(.metadata.uid) RV=\(.metadata.resourceVersion) generation=\(.metadata.generation) observed=\(.status.observedGeneration//"-") desired=\(.status.desiredNumberScheduled//0) updated=\(.status.updatedNumberScheduled//0) ready=\(.status.numberReady//0)"' <<<"$XJ"; else printf '%s\n' '중단: resource 교체 또는 API 실패. 이전 관계는 무효다.' >&2; fi`

세 UID가 유지되고 모두 `generation > observedGeneration`이거나 controller별 status가 같은 창에서 정지해야 공통 경로로 진행한다. RV 변화 자체는 조정 성공이 아니다.

`EVENT_READY=false; unset NORMALIZE_READY; if [ "$RESOURCE_READY" != true ]; then printf '%s\n' '중단: RESOURCE_READY가 아니다.' >&2; else EVENT_READY=true; for SPEC in "Deployment:$DEP:$DEP_UID" "StatefulSet:$STS:$STS_UID" "DaemonSet:$DS:$DS_UID"; do IFS=: read -r K N U <<<"$SPEC"; EJ="$(kubectl get events -n "$RNS" --field-selector "involvedObject.kind=$K,involvedObject.name=$N,involvedObject.uid=$U" -o json)" || { printf 'event-producer-failure kind=%s name=%s\n' "$K" "$N" >&2; EVENT_READY=false; break; }; jq -r --arg k "$K" --arg n "$N" '"Event 관계: \($k)/\($n) count=\(.items|length)",(.items[]?|"time=\(.eventTime//.lastTimestamp//.metadata.creationTimestamp) type=\(.type) reason=\(.reason) count=\(.count//1)")' <<<"$EJ" || { printf '%s\n' 'event-filter-error' >&2; EVENT_READY=false; break; }; done; printf 'EVENT_READY=%s\n' "$EVENT_READY"; fi`

Event가 0개인 것은 오류 없음이 아니라 미기록·TTL·권한·시간 범위 후보를 포함한다. message 원문은 민감정보 가능성이 있어 이 명령에서 출력하지 않는다.

### 2. component 로그와 RBAC

`LOG_READY=false; unset RBAC_READY NORMALIZE_READY; TMP=''; if [ "$SELECTION_READY" != true ] || [ "$TIME_READY" != true ]; then printf '%s\n' '중단: log gate 실패.' >&2; elif PJ="$(kubectl get pod "$POD" -n "$NS" -o json)" && [ "$(jq -r '.metadata.uid' <<<"$PJ")" = "$POD_UID" ] && [ "$(jq -r --arg c "$CONTAINER" '.status.containerStatuses[]?|select(.name==$c)|.containerID' <<<"$PJ")" = "$CONTAINER_ID" ]; then LOG_READY=true; TMP="$(mktemp)" || exit 1; if kubectl logs "$POD" -n "$NS" -c "$CONTAINER" --timestamps --since-time="$START_RFC3339" --tail=500 >"$TMP"; then grep -Eic 'Failed to list|Failed to watch|forbidden|unauthorized|workqueue|leader|timeout|deadline|reflector' "$TMP" >/dev/null; FRC=$?; case "$FRC" in 0) printf 'LOG_READY=true filter=matched count=%s\n' "$(grep -Eic 'Failed to list|Failed to watch|forbidden|unauthorized|workqueue|leader|timeout|deadline|reflector' "$TMP")";; 1) printf '%s\n' 'LOG_READY=true filter=no-match; API 정상 증거가 아니다.';; *) printf 'filter-error rc=%s\n' "$FRC" >&2; LOG_READY=false;; esac; else printf 'log-producer-failure rc=%s\n' "$?" >&2; LOG_READY=false; fi; rm -f "$TMP"; else printf '%s\n' '중단: component identity가 바뀌었다.' >&2; fi`

로그·audit에서 실제 실패 resource와 `CLIENT_SUBJECT`가 확인된 경우에만 아래를 실행한다. 세 resource를 무조건 component 권한 실패로 가정하지 않는다.

`RBAC_READY=false; unset NORMALIZE_READY; if [ "$LOG_READY" != true ] || [ -z "$CLIENT_SUBJECT" ]; then printf '%s\n' '중단: log/subject gate 실패.' >&2; else RBAC_READY=true; for RESOURCE in deployments.apps statefulsets.apps daemonsets.apps; do for VERB in list watch; do RESULT="$(kubectl auth can-i "$VERB" "$RESOURCE" --all-namespaces --as="$CLIENT_SUBJECT" 2>&1)"; RC=$?; printf 'subject=%s verb=%s resource=%s namespace=all result=%s rc=%s\n' "$CLIENT_SUBJECT" "$VERB" "$RESOURCE" "$RESULT" "$RC"; if [ "$RC" -ne 0 ] || [ "$RESULT" != yes ]; then RBAC_READY=false; fi; done; done; fi; printf 'RBAC_READY=%s\n' "$RBAC_READY"`

`yes`는 impersonation RBAC만 보장한다. 같은 창의 audit `user.username`, verb, apiGroup/resource/namespace, response code와 component 로그가 일치해야 한다. auditID와 metadata만 보존하고 body·token·Secret은 출력하지 않는다. API timeout/5xx면 API server·etcd owner로 단방향 이관하며 scheduler/plugin으로 되돌리지 않는다.

systemd 경로는 확인된 경우에만 SSH positional arguments와 machine-id를 사용한다.

`HOST_READY=false; unset NORMALIZE_READY; if [ "$TIME_READY" != true ]; then printf '%s\n' '중단: TIME_READY가 아니다.' >&2; else ssh -- "$SSH_HOST" bash -c 'expected=$1; unit=$2; start=$3; end=$4; [ "$(cat /etc/machine-id 2>/dev/null)" = "$expected" ] || exit 41; out=$(journalctl -u "$unit" --since "$start" --until "$end" --no-pager -n 500); prc=$?; [ "$prc" -eq 0 ] || { printf "journal-producer-failure rc=%s\n" "$prc" >&2; exit 42; }; grep -Eic "Failed to list|Failed to watch|forbidden|workqueue|leader|timeout|deadline" <<<"$out" >/dev/null; frc=$?; case "$frc" in 0) printf "HOST_READY=true filter=matched count=%s\n" "$(grep -Eic "Failed to list|Failed to watch|forbidden|workqueue|leader|timeout|deadline" <<<"$out")";; 1) printf "%s\n" "HOST_READY=true filter=no-match";; *) exit 43;; esac' bash "$EXPECTED_MACHINE_ID" "$UNIT" "$START_RFC3339" "$END_RFC3339"; RC=$?; [ "$RC" -eq 0 ] && HOST_READY=true || printf 'SSH/journal 실패 rc=%s\n' "$RC" >&2; fi`

### 3. workqueue와 정상화 경계

workqueue metric은 실제 1.26 build와 scrape target에서 노출된 이름·label만 사용한다. query 생성값을 직접 수정하지 않는다.

`METRIC_READY=false; unset NORMALIZE_READY; if [ "$RESOURCE_READY" != true ] || [ -z "$PROM_JOB" ]; then printf '%s\n' '중단: resource/job gate 실패.' >&2; elif PJ_NOW="$(kubectl get pod "$POD" -n "$NS" -o json)" && [ "$(jq -r '.metadata.uid' <<<"$PJ_NOW")" = "$POD_UID" ]; then PJ="${PROM_JOB//\\/\\\\}"; PJ="${PJ//\"/\\\"}"; PN="${POD//\\/\\\\}"; PN="${PN//\"/\\\"}"; NN="${NS//\\/\\\\}"; NN="${NN//\"/\\\"}"; printf 'max by(instance,name)(workqueue_depth{job="%s",namespace="%s",pod="%s"})\nmax by(instance,name)(workqueue_unfinished_work_seconds{job="%s",namespace="%s",pod="%s"})\nhistogram_quantile(0.99,sum by(le,instance,name)(rate(workqueue_queue_duration_seconds_bucket{job="%s",namespace="%s",pod="%s"}[5m])))\n' "$PJ" "$NN" "$PN" "$PJ" "$NN" "$PN" "$PJ" "$NN" "$PN"; METRIC_READY=true; else printf '%s\n' '중단: current component UID 불일치.' >&2; fi`

빈 결과는 queue=0이 아니다. unsupported metric, scrape/TLS/RBAC 실패, label/time range 불일치와 target 부재를 구분한다. 여러 queue의 증가가 같은 창의 세 resource 정체·component 로그와 맞아야 공통 controller 처리 경계다. queue name만으로 Kubernetes 객체를 확정하지 않는다.

## 변경 gate와 정상화

읽기 전용 진단과 변경을 분리한다. restart, Lease 조작, workload patch, RBAC/config 변경 전에는 current component와 세 resource UID/RV, leader/API/queue 직접 증거, 승인 ID·주체·창, HA quorum/capacity, tenant 영향, 멱등성, 중단 기준과 rollback을 기록한다. 실행·rollback 직전 각각 fresh identity/evidence를 재수집해 별도 READY를 만들어야 한다.

변경 후 모든 READY와 identity를 폐기하고 새 component 및 교체된 resource UID를 다시 등록한다. `component → leader → API list/watch → queue → 세 resource generation/status → Deployment endpoint/요청, StatefulSet quorum·기능, DaemonSet 의도 node Ready`를 역순으로 관찰 창 동안 확인해야 `NORMALIZE_READY=true`다. status 갱신이나 queue 감소 하나만으로 정상화하지 않는다.

## 증거와 미검증

canonical UTC 창, component UID·RV·owner·node·containerID, 세 resource UID·RV·generation/status, Event relation, 정확한 audit/RBAC tuple, queue metric과 process 원점, 승인·rollback·새 identity·기능 결과만 보존한다. raw log/audit/config, credential, Secret과 개인정보는 보존하지 않는다.

배포 방식, leader Lease, metric schema, queue 정상 범위, host/unit, audit와 managed control plane은 환경별 미검증이다. 실제 인프라 실행과 상태 변경은 수행하지 않았다.
