# kube-controller-manager health 확인이 실패하거나 프로세스가 비정상인 경우

## 입력값과 빠른 수집

실행 경로는 `작업 PC 또는 bastion의 Bash → kubectl → API server → 현재 controller-manager Pod`, host 분기는 `작업 PC 또는 bastion → SSH → 확인된 control-plane host → systemd/kubelet → CRI socket`이다. 각 명령은 같은 Bash에서 실행한다. SSH의 `127.0.0.1`은 원격 host loopback이며 작업 PC loopback이 아니다.

| 입력 종류 | 변수 | 출처와 gate |
|---|---|---|
| 최초 입력 | `NS`, `POD` | 승인된 namespace와 정확한 Pod 이름. exact-name API 조회가 성공해야 한다. |
| API 확인 자동값 | `POD_UID`, `POD_RV`, `NODE`, `OWNER_REL`, `CONTAINER_REL` | 현재 Pod JSON에서만 등록한다. UID·resourceVersion·node·owner·containerID 관계가 하나라도 비면 중단한다. |
| 계산 후보값 | `POD_RE`, `ARGV_RE` | 이름과 확인된 argv를 정규식 escape한 값. bounded 출력 전에는 사용하지 않는다. |
| 운영자 선택값 | `CONTAINER`, `START_RFC3339`, `END_RFC3339`, `HEALTH_URL`, host 접근값 | 자동 출력에서 고르고 선택 직후 검증한다. |

`PASTE_..._HERE` 문자열은 각각 아래에서 한 번만 사용한다.

**Bash와 도구 확인**

`TOOLS_READY=false; MISSING=''; if [ -z "${BASH_VERSION:-}" ]; then printf '%s\n' '중단: Bash가 아니다.' >&2; else for T in kubectl jq curl grep sed date mktemp ssh; do command -v "$T" >/dev/null 2>&1 || MISSING="$MISSING $T"; done; if [ -z "$MISSING" ]; then TOOLS_READY=true; printf 'TOOLS_READY=true bash=%s\n' "$BASH_VERSION"; else printf '중단: 없는 도구=%s\n' "$MISSING" >&2; fi; fi`

**최초 입력과 모든 파생 상태 무효화**

`unset INPUT_READY AUTO_READY SELECTION_READY TIME_READY HEALTH_READY LOG_READY HOST_READY CRI_READY NORMALIZE_READY POD_UID POD_RV NODE OWNER_REL CONTAINER_REL CONTAINER_ID POD_RE ARGV_RE CONTAINER START_RFC3339 END_RFC3339 START_EPOCH END_EPOCH HEALTH_URL SSH_HOST EXPECTED_MACHINE_ID UNIT PROM_JOB; NS='PASTE_CONTROLLER_NAMESPACE_HERE'; POD='PASTE_CONTROLLER_POD_HERE'; INPUT_READY=false; if [ "$TOOLS_READY" != true ] || [ -z "$NS" ] || [ -z "$POD" ]; then printf '%s\n' '중단: 도구와 최초 입력을 확인한다.' >&2; elif J="$(kubectl get pod "$POD" -n "$NS" -o json)" && jq -e --arg n "$POD" --arg ns "$NS" '.metadata.name==$n and .metadata.namespace==$ns' <<<"$J" >/dev/null; then INPUT_READY=true; export NS POD; printf 'INPUT_READY=true namespace=%s pod=%s\n' "$NS" "$POD"; else printf '%s\n' '중단: exact-name Pod 조회 실패. 이전 값은 모두 무효다.' >&2; fi`

**현재 identity·관계 자동 등록**

`unset AUTO_READY SELECTION_READY TIME_READY HEALTH_READY LOG_READY HOST_READY CRI_READY NORMALIZE_READY POD_UID POD_RV NODE OWNER_REL CONTAINER_REL CONTAINER_ID POD_RE ARGV_RE; AUTO_READY=false; if [ "$INPUT_READY" != true ]; then printf '%s\n' '중단: INPUT_READY가 아니다.' >&2; elif J="$(kubectl get pod "$POD" -n "$NS" -o json)" && jq -e --arg n "$POD" '.metadata.name==$n and (.metadata.uid|length>0) and (.metadata.resourceVersion|length>0) and (.spec.nodeName|length>0) and ([.spec.containers[]?.name]|length>0)' <<<"$J" >/dev/null; then POD_UID="$(jq -r '.metadata.uid' <<<"$J")"; POD_RV="$(jq -r '.metadata.resourceVersion' <<<"$J")"; NODE="$(jq -r '.spec.nodeName' <<<"$J")"; OWNER_REL="$(jq -r '[.metadata.ownerReferences[]?|(.kind+"/"+.name+"/"+.uid)]|join(",")' <<<"$J")"; CONTAINER_REL="$(jq -r '[.spec.containers[] as $c|(.status.containerStatuses[]?|select(.name==$c.name)|($c.name+"="+(.containerID//"-")+" ready="+(.ready|tostring)+" restart="+(.restartCount|tostring)))]|join("; ")' <<<"$J")"; POD_RE="$(printf '%s' "$POD"|sed 's/[][\\.^$*+?(){}|]/\\&/g')"; [ -n "$OWNER_REL" ] || OWNER_REL='static-or-unowned'; AUTO_READY=true; export POD_UID POD_RV NODE OWNER_REL CONTAINER_REL POD_RE; printf 'AUTO_READY=true\nPod UID: %s\nresourceVersion: %s\nNode: %s\nOwner 관계: %s\nContainer 관계: %s\nPOD_RE: ^%s$\n' "$POD_UID" "$POD_RV" "$NODE" "$OWNER_REL" "$CONTAINER_REL" "$POD_RE"; else printf '%s\n' '중단: 현재 identity 또는 관계 수집 실패. 자동값은 무효다.' >&2; fi`

Pod가 교체되거나 node·owner·containerID가 달라지면 이 절부터 다시 등록한다. `Running`과 readiness probe 성공은 controller 조정 기능을 보장하지 않는다.

**운영자 선택과 시간 검증**

`CONTAINER='PASTE_CONTROLLER_CONTAINER_HERE'; START_RFC3339='PASTE_CONTROLLER_START_UTC_HERE'; END_RFC3339='PASTE_CONTROLLER_END_UTC_HERE'; HEALTH_URL='PASTE_APPROVED_HEALTH_URL_HERE'; SSH_HOST='PASTE_APPROVED_SSH_DESTINATION_HERE'; EXPECTED_MACHINE_ID='PASTE_EXPECTED_MACHINE_ID_HERE'; UNIT='PASTE_CONFIRMED_CONTROLLER_UNIT_HERE'; PROM_JOB='PASTE_CONTROLLER_PROMETHEUS_JOB_HERE'`

`SELECTION_READY=false; TIME_READY=false; unset HEALTH_READY LOG_READY HOST_READY CRI_READY NORMALIZE_READY CONTAINER_ID ARGV_RE; if [ "$AUTO_READY" != true ]; then printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; elif J="$(kubectl get pod "$POD" -n "$NS" -o json)" && [ "$(jq -r '.metadata.uid' <<<"$J")" = "$POD_UID" ] && [ "$(jq -r '.metadata.resourceVersion' <<<"$J")" = "$POD_RV" ] && jq -e --arg c "$CONTAINER" 'any(.spec.containers[]?;.name==$c)' <<<"$J" >/dev/null; then CONTAINER_ID="$(jq -r --arg c "$CONTAINER" '.status.containerStatuses[]?|select(.name==$c)|.containerID//empty' <<<"$J")"; ARGV="$(jq -r --arg c "$CONTAINER" '.spec.containers[]|select(.name==$c)|([.command[]?,.args[]?]|join(" "))' <<<"$J")"; ARGV_RE="$(printf '%s' "$ARGV"|sed 's/[][\\.^$*+?(){}|]/\\&/g')"; if [ -z "$CONTAINER_ID" ] || [ -z "$ARGV_RE" ]; then printf '%s\n' '중단: containerID 또는 argv 관계가 비었다.' >&2; else SELECTION_READY=true; printf 'SELECTION_READY=true container=%s containerID=%s argv-regex-bytes=%s\n' "$CONTAINER" "$CONTAINER_ID" "${#ARGV_RE}"; fi; else printf '%s\n' '중단: Pod 교체 또는 container 불일치.' >&2; fi; if [ "$SELECTION_READY" = true ] && [[ "$START_RFC3339" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] && [[ "$END_RFC3339" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]]; then S="$(date -u -d "$START_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" && E="$(date -u -d "$END_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" && START_EPOCH="$(date -u -d "$START_RFC3339" '+%s' 2>/dev/null)" && END_EPOCH="$(date -u -d "$END_RFC3339" '+%s' 2>/dev/null)" && [ "$S" = "$START_RFC3339" ] && [ "$E" = "$END_RFC3339" ] && [ "$START_EPOCH" -lt "$END_EPOCH" ] && TIME_READY=true; fi; printf 'TIME_READY=%s start=%s end=%s\n' "$TIME_READY" "$START_RFC3339" "$END_RFC3339"`

시간은 초 단위 canonical UTC RFC3339 roundtrip을 통과하고 `start < end`여야 한다. Event·log·audit 시각이 이 창 밖이면 같은 사건의 증거로 연결하지 않는다.

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | 확인된 controller-manager health가 non-2xx이거나 현재 process/container가 종료·재시작하고 같은 시간에 controller 오류가 있는 경우 |
| 적용 | Pod UID·RV·owner·node·containerID와 endpoint/process lifecycle을 같은 창에서 대조할 수 있는 경우 |
| 제외 | Lease acquire/renew가 직접 원인이면 [[02. kube-controller-manager leader election이 반복 실패하는 경우]], 여러 controller만 정체되면 [[03. 여러 controller의 조정이 동시에 진행되지 않는 경우]]로 이동 |

검색 문자열: `healthz`, `livez`, `readyz`, `panic`, `OOMKilled`, `connection refused`, `x509`, `Unauthorized`, `Forbidden`, `failed to acquire lease`.

## 관측별 진단 경로

| 지금 보이는 것 | 먼저 볼 것 | 그다음 어디를 볼지 | 상세 절 |
|---|---|---|---|
| health non-2xx·TLS·timeout | 현재 UID와 승인 URL, HTTP status | listener·TLS·API dependency | [[#1. health와 API 경계]] |
| restart·LastState·containerID 변화 | lifecycle와 node, bounded log | kubelet·CRI·resource | [[#2. lifecycle·로그·CRI]] |
| `Forbidden`·`Unauthorized` | 실제 component subject와 audit resource | RBAC·credential owner | [[#3. RBAC·audit]] |

### 1. health와 API 경계

`HEALTH_URL`은 manifest/argv 또는 승인 inventory에서 확인한 URL이어야 한다. CA는 승인된 `CURL_CA_BUNDLE` 환경변수로 제공하며 token·client key를 명령행에 넣지 않고 `-k`를 쓰지 않는다.

`HEALTH_READY=false; unset NORMALIZE_READY; if [ "$SELECTION_READY" != true ] || [ "$TIME_READY" != true ]; then printf '%s\n' '중단: 선택·시간 gate 실패.' >&2; elif J="$(kubectl get pod "$POD" -n "$NS" -o json)" && [ "$(jq -r '.metadata.uid' <<<"$J")" = "$POD_UID" ] && [ "$(jq -r '.metadata.resourceVersion' <<<"$J")" = "$POD_RV" ] && [ "$(jq -r '.spec.nodeName' <<<"$J")" = "$NODE" ]; then BODY="$(mktemp)" || exit 1; CODE="$(curl -sS --max-time 10 -o "$BODY" -w '%{http_code}' "$HEALTH_URL")"; RC=$?; if [ "$RC" -eq 0 ] && [ "$CODE" -ge 200 ] 2>/dev/null && [ "$CODE" -lt 300 ] 2>/dev/null; then HEALTH_READY=true; printf 'HEALTH_READY=true http=%s bytes=%s uid=%s\n' "$CODE" "$(wc -c <"$BODY")" "$POD_UID"; else printf 'health 실패 curl_rc=%s http=%s uid=%s\n' "$RC" "${CODE:-000}" "$POD_UID" >&2; fi; rm -f "$BODY"; else printf '%s\n' '중단: 현재 Pod identity/관계가 등록값과 다르다.' >&2; fi`

HTTP 성공은 해당 probe hop만 보장한다. `401/403`은 transport 이후 인증·인가, `404`는 path, `5xx`는 handler/dependency, `000`은 TCP·TLS 경계다. body는 민감정보 가능성이 있어 저장·출력하지 않는다. 별도로 `kubectl get --raw='/readyz?verbose'`를 실행할 때도 이는 operator의 API 경로이며 component client의 성공을 대신하지 않는다.

### 2. lifecycle·로그·CRI

현재 lifecycle과 로그 producer/filter를 분리한다. 필터는 raw 행 대신 분류별 count만 출력한다.

`LOG_READY=false; unset NORMALIZE_READY; TMP=''; if [ "$SELECTION_READY" != true ] || [ "$TIME_READY" != true ]; then printf '%s\n' '중단: log gate 실패.' >&2; elif J="$(kubectl get pod "$POD" -n "$NS" -o json)" && [ "$(jq -r '.metadata.uid' <<<"$J")" = "$POD_UID" ] && [ "$(jq -r '.spec.nodeName' <<<"$J")" = "$NODE" ] && [ "$(jq -r --arg c "$CONTAINER" '.status.containerStatuses[]?|select(.name==$c)|.containerID' <<<"$J")" = "$CONTAINER_ID" ]; then LOG_READY=true; TMP="$(mktemp)" || exit 1; if kubectl logs "$POD" -n "$NS" -c "$CONTAINER" --timestamps --since-time="$START_RFC3339" --tail=400 >"$TMP"; then grep -Eic 'health|readyz|livez|unauthorized|forbidden|x509|timeout|refused|panic|oom|fatal|leader' "$TMP" >/dev/null; FRC=$?; if [ "$FRC" -eq 0 ]; then printf 'LOG_READY=true filter=matched count=%s\n' "$(grep -Eic 'health|readyz|livez|unauthorized|forbidden|x509|timeout|refused|panic|oom|fatal|leader' "$TMP")"; elif [ "$FRC" -eq 1 ]; then printf '%s\n' 'LOG_READY=true filter=no-match; 오류 부재가 아니며 bounded raw 검토는 승인된 보안 경로로 이관한다.'; else printf 'filter-error rc=%s\n' "$FRC" >&2; LOG_READY=false; fi; else printf 'log-producer-failure rc=%s\n' "$?" >&2; LOG_READY=false; fi; rm -f "$TMP"; else printf '%s\n' '중단: UID/node/containerID가 바뀌었다.' >&2; fi`

Pod lifecycle이 runtime 경계를 가리킬 때만 아래 host 분기를 사용한다. SSH 값은 승인 inventory의 단일 host와 machine-id여야 한다. 인수는 positional parameter로 전달하며 `eval`하지 않는다. 활성 kubelet argv에서 **정확히 하나**의 CRI endpoint를 얻고, Pod status의 provider/containerID와 socket listener provider 관계를 확인한 뒤 `crictl`을 사용한다.

이 문서 안의 `CRI_READY`나 endpoint 후보는 사용하지 않는다. container lifecycle 오류가 직접 확인된 경우에만 [[04. RunPodSandbox가 runtime·OCI 오류로 실패하는 경우]] 또는 [[07. runtime 상태와 Pod container ID가 일치하지 않는 경우]]에서 current Pod/Node/containerID, 원격 machine-id, active kubelet argv 또는 엄격히 검증한 config의 exact endpoint, runtime MainPID와 socket provider를 전부 새로 등록한다. 그 런북의 direct current guard를 통과한 CRI 요약만 controller-manager 증거에 연결한다.

socket listener 문자열이 containerID provider와 설명 가능한 관계인지 운영자가 확인하지 못하면 `CRI_READY` 출력만으로 원인을 확정하지 않는다. kubelet argv에 endpoint가 0개 또는 여러 개면 검증된 단일 kubelet 구성 원본을 owner에게 요청하고 기본 socket을 추측하지 않는다.

### 3. RBAC·audit

`Forbidden`은 로그의 정확한 verb·API group·resource·namespace와 audit의 `user.username`이 확인된 경우에만 RBAC로 분류한다. operator ServiceAccount를 component subject로 가정하지 않는다. impersonation 권한이 승인됐을 때만 `kubectl auth can-i`를 사용하며 `yes`는 실제 credential/network 성공을 보장하지 않는다. audit는 확인된 audit source에서 `auditID`, stage timestamp, user, verb, objectRef, response code만 보존하고 request/response body, token, Secret은 출력하지 않는다.

## 변경 gate와 정상화

진단 명령은 읽기 전용이다. restart, manifest/RBAC/certificate 변경은 일반 명령으로 제공하지 않는다. 별도 변경 절차에는 현재 UID·RV·owner/node/containerID, 원인 증거 시각, 승인 ID·실행 주체·변경 창, HA quorum/남은 leader·API capacity, 멱등성, 단일 대상, 중단 조건과 실행 가능한 rollback을 모두 기록한다. 하나라도 없으면 변경하지 않는다.

변경 후 기존 identity와 모든 `..._READY`를 폐기하고 입력 절부터 새 Pod/process를 등록한다. `NORMALIZE_READY`는 새 UID·owner·node·containerID, health 성공, 같은 오류/restart 부재, leader/API 정상과 실제 controller 대상의 기능 수렴을 관찰 창 전체에서 확인한 뒤에만 `true`로 기록한다. 새 process 시작이나 HTTP 200 한 번은 정상화가 아니다.

## Prometheus 빠른 관측

job label을 Prometheus target inventory에서 확인한 경우에만 query를 생성한다. label escape 후 생성된 출력만 UI에 붙여 넣는다.

`if [ "$AUTO_READY" != true ] || [ -z "$PROM_JOB" ]; then printf '%s\n' '중단: current component identity 또는 Prometheus job 미확정.' >&2; elif J="$(kubectl get pod "$POD" -n "$NS" -o json)" && [ "$(jq -r '.metadata.uid' <<<"$J")" = "$POD_UID" ]; then PJ="${PROM_JOB//\\/\\\\}"; PJ="${PJ//\"/\\\"}"; PN="${POD//\\/\\\\}"; PN="${PN//\"/\\\"}"; NN="${NS//\\/\\\\}"; NN="${NN//\"/\\\"}"; printf 'up{job="%s",namespace="%s",pod="%s"}\nchanges(process_start_time_seconds{job="%s",namespace="%s",pod="%s"}[15m])\nsum by(instance,code)(rate(rest_client_requests_total{job="%s",namespace="%s",pod="%s",code=~"401|403|5.."}[5m]))\n' "$PJ" "$NN" "$PN" "$PJ" "$NN" "$PN" "$PJ" "$NN" "$PN"; else printf '%s\n' '중단: current component UID 불일치.' >&2; fi`

metric 또는 label이 Kubernetes 1.26 배포 build에서 노출되지 않거나 query가 빈 결과면 `0`이나 정상으로 해석하지 않는다. target 부재, scrape/TLS/RBAC 실패, retention/time range, label 불일치와 unsupported metric을 먼저 구분한다.

## 증거와 미검증

UTC 창, Pod UID·RV·owner·node·containerID, process/health/CRI provider 관계, 분류 count, 정확한 RBAC subject·verb·resource·namespace·auditID, 승인·변경·rollback·새 identity·기능 검증만 보존한다. 내부 credential, 전체 argv/config, raw log/audit body, Secret·token·private key·개인정보는 보존하지 않는다.

Kubernetes 1.26의 실제 배포 방식, endpoint/TLS, systemd unit, SSH host, kubelet argv, CRI socket/provider, audit와 Prometheus metric은 환경별 미검증이다. 실제 인프라 명령과 상태 변경은 이 문서 개정 중 수행하지 않았다.
