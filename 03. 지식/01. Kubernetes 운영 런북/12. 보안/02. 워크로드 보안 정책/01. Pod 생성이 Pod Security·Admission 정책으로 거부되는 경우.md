# Pod 생성이 Pod Security·Admission 정책으로 거부되는 경우

## 입력값과 빠른 수집

연결 경로는 `승인된 작업 host의 kubectl -> API server authentication·authorization -> Pod Security Admission 또는 exact webhook -> 거부 response·audit`다. 생성이 거부되면 Pod UID·containerID·node·runtime·storage identity는 아직 없을 수 있다. 이 경우 값을 발명하지 않고 `not-created`로 기록한다.

| 종류 | 변수 | 출처와 의미 |
|---|---|---|
| 최초 입력 | `NS`, `REQUEST_KIND`, `REQUEST_NAME` | 원래 요청의 namespace·kind·name |
| API 자동값 | namespace UID/RV, 조건부 target UID/RV/generation/owner/template digest | exact API 조회가 모두 성공한 뒤 등록 |
| 계산 후보값 | request key, policy branch, manifest digest | audit·API 결과와 대조 전에는 미확정 |
| 운영자 선택값 | UTC 창, 단일 `AUDIT_ID`, redacted audit file, 조건부 webhook configuration | 원래 response와 승인 evidence에서 선택 |

각 `PASTE_..._HERE` 입력칸은 문서에서 한 번만 사용한다. 명령은 kubectl context가 승인된 같은 작업 host와 같은 Bash에서 실행한다.

### 원자적 request refresh

refresh는 namespace·target·owner·template과 시간·audit·webhook·evidence·dry-run·change·rollback·normalization 상태를 먼저 폐기한다. target 조회가 성공했지만 결과가 비어 있을 때만 `not-created`를 등록한다. 권한·API 실패를 object 부재로 해석하지 않는다.

`refresh_admission(){ local nj tj vals spec; unset AUTO_READY TIME_READY AUDIT_READY WEBHOOK_READY EVIDENCE_READY DRYRUN_READY CHANGE_READY ROLLBACK_READY NORMAL_READY NS_UID NS_RV TARGET_STATE TARGET_UID TARGET_RV TARGET_GENERATION OWNER_KIND OWNER_NAME OWNER_UID TEMPLATE_DIGEST REQUEST_KEY OBSERVED_AT START_RFC3339 END_RFC3339 AUDIT_ID AUDIT_RECORD_PATH POLICY_BRANCH WEBHOOK_KIND WEBHOOK_NAME WEBHOOK_ENTRY WEBHOOK_UID WEBHOOK_RV SERVICE_NS SERVICE_NAME SERVICE_UID SERVICE_RV SERVICE_PORT TARGET_PORT ENDPOINT_HASH APPROVED_MANIFEST APPROVED_DIGEST; AUTO_READY=false; TIME_READY=false; AUDIT_READY=false; WEBHOOK_READY=false; EVIDENCE_READY=false; DRYRUN_READY=false; CHANGE_READY=false; ROLLBACK_READY=false; NORMAL_READY=false; [ "$INPUT_READY" = true ] || { printf '%s\n' '중단: INPUT_READY가 아니다.' >&2; return 1; }; nj="$(kubectl get namespace "$NS" -o json)" || { printf '%s\n' '중단: Namespace refresh 실패' >&2; return 1; }; vals="$(jq -er '[.metadata.uid,.metadata.resourceVersion] | @tsv' <<<"$nj")" || return 1; IFS=$'\t' read -r NS_UID NS_RV <<<"$vals"; tj="$(kubectl get "$REQUEST_KIND" "$REQUEST_NAME" -n "$NS" --ignore-not-found -o json)" || { printf '%s\n' '중단: target API 실패' >&2; return 1; }; if [ -z "$tj" ]; then TARGET_STATE='not-created'; TARGET_UID='-'; TARGET_RV='-'; TARGET_GENERATION='-'; OWNER_KIND='-'; OWNER_NAME='-'; OWNER_UID='-'; TEMPLATE_DIGEST='-'; else vals="$(jq -er '[.metadata.uid,.metadata.resourceVersion,(.metadata.generation // 0 | tostring),([.metadata.ownerReferences[]? | select(.controller==true)][0].kind // "-"),([.metadata.ownerReferences[]? | select(.controller==true)][0].name // "-"),([.metadata.ownerReferences[]? | select(.controller==true)][0].uid // "-")] | @tsv' <<<"$tj")" || return 1; IFS=$'\t' read -r TARGET_UID TARGET_RV TARGET_GENERATION OWNER_KIND OWNER_NAME OWNER_UID <<<"$vals"; if [ "$REQUEST_KIND" = pod ]; then spec="$(jq -cS '.spec' <<<"$tj")"; elif [ "$REQUEST_KIND" = cronjob ]; then spec="$(jq -cS '.spec.jobTemplate.spec.template.spec' <<<"$tj")"; else spec="$(jq -cS '.spec.template.spec' <<<"$tj")"; fi; TEMPLATE_DIGEST="$(printf '%s' "$spec" | sha256sum | cut -d' ' -f1)" || return 1; TARGET_STATE='exists'; fi; REQUEST_KEY="$NS|$REQUEST_KIND|$REQUEST_NAME"; OBSERVED_AT="$(date -u '+%Y-%m-%dT%H:%M:%SZ')" || return 1; AUTO_READY=true; export NS_UID NS_RV TARGET_STATE TARGET_UID TARGET_RV TARGET_GENERATION OWNER_KIND OWNER_NAME OWNER_UID TEMPLATE_DIGEST REQUEST_KEY OBSERVED_AT; printf 'AUTO_READY=true request=%s namespaceUID=%s namespaceRV=%s targetState=%s targetUID=%s targetRV=%s generation=%s owner=%s/%s ownerUID=%s templateDigest=%s observed=%s\n' "$REQUEST_KEY" "$NS_UID" "$NS_RV" "$TARGET_STATE" "$TARGET_UID" "$TARGET_RV" "$TARGET_GENERATION" "$OWNER_KIND" "$OWNER_NAME" "$OWNER_UID" "$TEMPLATE_DIGEST" "$OBSERVED_AT"; }; refresh_admission`

**모든 후속 명령이 호출하는 current guard**

`current_admission(){ local nj tj spec digest generation; [ "$AUTO_READY" = true ] || return 1; nj="$(kubectl get namespace "$NS" -o json)" || return 1; jq -e --arg uid "$NS_UID" --arg rv "$NS_RV" '.metadata.uid==$uid and .metadata.resourceVersion==$rv' <<<"$nj" >/dev/null || return 1; tj="$(kubectl get "$REQUEST_KIND" "$REQUEST_NAME" -n "$NS" --ignore-not-found -o json)" || return 1; if [ "$TARGET_STATE" = not-created ]; then [ -z "$tj" ]; else [ -n "$tj" ] || return 1; jq -e --arg uid "$TARGET_UID" --arg rv "$TARGET_RV" --arg ok "$OWNER_KIND" --arg on "$OWNER_NAME" --arg ou "$OWNER_UID" '.metadata.uid==$uid and .metadata.resourceVersion==$rv and (([$ok,$on,$ou]|all(.=="-")) or any(.metadata.ownerReferences[]?; .controller==true and .kind==$ok and .name==$on and .uid==$ou))' <<<"$tj" >/dev/null || return 1; generation="$(jq -r '(.metadata.generation // 0)|tostring' <<<"$tj")" || return 1; if [ "$REQUEST_KIND" = pod ]; then spec="$(jq -cS '.spec' <<<"$tj")"; elif [ "$REQUEST_KIND" = cronjob ]; then spec="$(jq -cS '.spec.jobTemplate.spec.template.spec' <<<"$tj")"; else spec="$(jq -cS '.spec.template.spec' <<<"$tj")"; fi; digest="$(printf '%s' "$spec" | sha256sum | cut -d' ' -f1)" || return 1; [ "$generation" = "$TARGET_GENERATION" ] && [ "$digest" = "$TEMPLATE_DIGEST" ]; fi; }`

`current_admission` 실패 시 이름이 같은 재생성 object에 과거 response를 연결하지 않고 `refresh_admission`부터 다시 실행한다.

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | exact 요청의 audit/response에 `violates PodSecurity` 또는 `admission webhook ... denied the request`가 있음 |
| 적용 | namespace·request identity, 단일 auditID, effective PSA label 또는 exact webhook/service relation을 연결 가능 |
| 제외 | HTTP 401은 [[01. API 서버 인증이 실패하거나 Unauthorized가 반환되는 경우]], `User ... cannot create` 403은 [[02. Kubernetes API 요청이 Forbidden으로 거부되는 경우]], object 생성 뒤 runtime 실패는 해당 Pod 런북 |

검색 문자열: `violates PodSecurity`, `restricted`, `baseline`, `admission webhook`, `denied the request`, `allowPrivilegeEscalation`, `runAsNonRoot`, `seccompProfile`, `capabilities`, `hostNetwork`.

## canonical 시간과 단일 auditID

`START_RFC3339='PASTE_START_RFC3339_HERE'; END_RFC3339='PASTE_END_RFC3339_HERE'; TIME_READY=false; AUDIT_READY=false; EVIDENCE_READY=false; RFC3339_RE='^[0-9]{4}-(0[1-9]|1[0-2])-([0-2][0-9]|3[01])T([01][0-9]|2[0-3]):[0-5][0-9]:[0-5][0-9]Z$'; if ! [[ "$START_RFC3339" =~ $RFC3339_RE ]] || ! [[ "$END_RFC3339" =~ $RFC3339_RE ]]; then printf '%s\n' '중단: canonical UTC RFC3339 형식 오류' >&2; elif [ "$(date -u -d "$START_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" != "$START_RFC3339" ] || [ "$(date -u -d "$END_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" != "$END_RFC3339" ]; then printf '%s\n' '중단: date round-trip 실패' >&2; elif [ "$(date -u -d "$START_RFC3339" +%s)" -ge "$(date -u -d "$END_RFC3339" +%s)" ]; then printf '%s\n' '중단: START가 END보다 빠르지 않다.' >&2; elif ! current_admission; then AUTO_READY=false; printf '%s\n' '중단: current request identity 변경' >&2; else TIME_READY=true; export START_RFC3339 END_RFC3339; printf 'TIME_READY=true start=%s end=%s observed=%s\n' "$START_RFC3339" "$END_RFC3339" "$OBSERVED_AT"; fi`

audit owner에게 request/response body와 actor 상세를 제거한 완결 stage JSON 한 건을 받는다. 필요한 필드는 `auditID`, timestamp, verb, requestURI, objectRef, responseStatus code/reason/message와 annotation의 policy 식별자뿐이다.

`AUDIT_ID='PASTE_EXACT_AUDIT_ID_HERE'; AUDIT_RECORD_PATH='PASTE_REDACTED_AUDIT_RECORD_PATH_HERE'; AUDIT_READY=false; EVIDENCE_READY=false; if [ "$TIME_READY" != true ] || ! current_admission; then AUTO_READY=false; printf '%s\n' '중단: 현재 TIME/request identity가 아니다.' >&2; elif ! [[ "$AUDIT_ID" =~ ^[A-Za-z0-9-]+$ ]] || [ ! -f "$AUDIT_RECORD_PATH" ] || [ ! -r "$AUDIT_RECORD_PATH" ]; then printf '%s\n' '중단: auditID 또는 redacted regular file 오류' >&2; elif AUDIT_TSV="$(jq -ser --arg id "$AUDIT_ID" --arg ns "$NS" --arg kind "$REQUEST_KIND" --arg name "$REQUEST_NAME" 'def resource_for_kind: if $kind=="pod" then "pods" elif $kind=="deployment" then "deployments" elif $kind=="statefulset" then "statefulsets" elif $kind=="daemonset" then "daemonsets" elif $kind=="job" then "jobs" else "cronjobs" end; if length==1 and .[0].auditID==$id and (.[0].stage=="ResponseComplete" or .[0].stage=="Panic") and (. [0].verb=="create" or .[0].verb=="update" or .[0].verb=="patch") and .[0].objectRef.namespace==$ns and .[0].objectRef.resource==resource_for_kind and (. [0].objectRef.name // $name)==$name and (.[0].responseStatus.code==400 or .[0].responseStatus.code==403) and ((.[0].responseStatus.message // "")|test("violates PodSecurity|admission webhook.*denied the request")) then .[0] | [.auditID,.requestReceivedTimestamp,.stage,.verb,.objectRef.resource,(.objectRef.name // $name),(.responseStatus.code|tostring),((.responseStatus.message // "")|if test("violates PodSecurity") then "PodSecurity" else "Webhook" end)] | @tsv else error("audit mismatch") end' "$AUDIT_RECORD_PATH")"; then IFS=$'\t' read -r AID ATS ASTAGE AVERB ARESOURCE ANAME ACODE POLICY_BRANCH <<<"$AUDIT_TSV"; ATS_CANON="$(date -u -d "$ATS" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)"; if [ -z "$ATS_CANON" ] || [ "$(date -u -d "$ATS_CANON" +%s)" -lt "$(date -u -d "$START_RFC3339" +%s)" ] || [ "$(date -u -d "$ATS_CANON" +%s)" -gt "$(date -u -d "$END_RFC3339" +%s)" ]; then printf '%s\n' '중단: audit timestamp가 evidence window 밖임' >&2; else AUDIT_READY=true; EVIDENCE_READY=true; export AUDIT_ID AUDIT_RECORD_PATH POLICY_BRANCH; printf 'AUDIT_READY=true auditID=%s timestamp=%s stage=%s verb=%s resource=%s name=%s status=%s branch=%s\n' "$AID" "$ATS_CANON" "$ASTAGE" "$AVERB" "$ARESOURCE" "$ANAME" "$ACODE" "$POLICY_BRANCH"; fi; else printf '%s\n' '중단: 단일 auditID와 request/policy identity 불일치' >&2; fi`

audit가 여러 stage를 담아 두 건 이상이면 완결 stage 한 건만 redaction해 다시 요청한다. 다른 auditID, namespace, resource 또는 이름의 message를 합치지 않는다.

## 관측별 진단 경로

| 지금 보이는 것 | 먼저 볼 것 | 다음 owner | 상세 절 |
|---|---|---|---|
| `PodSecurity` branch | namespace UID/RV와 enforce/warn/audit label, exact version | workload·security owner | [[#1. Pod Security Admission]] |
| `Webhook` branch | exact webhook entry→configuration UID/RV→Service/EndpointSlice | admission·service owner | [[#2. admission webhook]] |
| object가 생성됨 | 새 UID·owner·creation과 runtime state | workload/runtime owner | [[#3. dry-run과 변경 경계]] |

### 1. Pod Security Admission

`if [ "$AUDIT_READY" != true ] || [ "$POLICY_BRANCH" != PodSecurity ] || ! current_admission; then AUTO_READY=false; EVIDENCE_READY=false; printf '%s\n' '중단: current PodSecurity evidence가 아니다.' >&2; elif NJ="$(kubectl get namespace "$NS" -o json)"; then if jq -c '{namespace:.metadata.name,uid:.metadata.uid,rv:.metadata.resourceVersion,podSecurityLabels:(.metadata.labels|with_entries(select(.key|startswith("pod-security.kubernetes.io/"))))}' <<<"$NJ"; then EVIDENCE_READY=true; else EVIDENCE_READY=false; printf '%s\n' '중단: namespace policy filter 실패' >&2; fi; else EVIDENCE_READY=false; printf '%s\n' '중단: namespace policy producer 실패' >&2; fi`

`enforce` label과 version은 namespace 선언일 뿐 AdmissionConfiguration default·exemption 전체를 보장하지 않는다. audit의 exact violation field와 승인 manifest의 Pod spec을 대조한다. `privileged`, host namespace, capability 추가 또는 version 하향을 일반 해결책으로 사용하지 않는다.

### 2. admission webhook

response에서 확인한 exact entry와 configuration만 입력한다. Kubernetes 1.26의 `ValidatingAdmissionPolicy`는 alpha이며 feature gate가 확인되지 않으면 이 문서에서 사용하지 않는다.

`WEBHOOK_KIND='PASTE_VALIDATING_OR_MUTATING_CONFIGURATION_HERE'; WEBHOOK_NAME='PASTE_WEBHOOK_CONFIGURATION_NAME_HERE'; WEBHOOK_ENTRY='PASTE_EXACT_WEBHOOK_ENTRY_HERE'; WEBHOOK_READY=false; if [ "$AUDIT_READY" != true ] || [ "$POLICY_BRANCH" != Webhook ] || ! current_admission; then AUTO_READY=false; printf '%s\n' '중단: current webhook evidence가 아니다.' >&2; elif [ "$WEBHOOK_KIND" != validatingwebhookconfiguration ] && [ "$WEBHOOK_KIND" != mutatingwebhookconfiguration ]; then printf '%s\n' '중단: webhook configuration kind 오류' >&2; elif WJ="$(kubectl get "$WEBHOOK_KIND" "$WEBHOOK_NAME" -o json)" && VALS="$(jq -er --arg entry "$WEBHOOK_ENTRY" '[.metadata.uid,.metadata.resourceVersion,([.webhooks[] | select(.name==$entry)] | length | tostring),([.webhooks[] | select(.name==$entry)][0].clientConfig.service.namespace // "-"),([.webhooks[] | select(.name==$entry)][0].clientConfig.service.name // "-"),([.webhooks[] | select(.name==$entry)][0].clientConfig.service.port // 443 | tostring)] | @tsv' <<<"$WJ")"; then IFS=$'\t' read -r WEBHOOK_UID WEBHOOK_RV ENTRY_COUNT SERVICE_NS SERVICE_NAME SERVICE_PORT <<<"$VALS"; if [ "$ENTRY_COUNT" -ne 1 ] || [ "$SERVICE_NS" = - ] || [ "$SERVICE_NAME" = - ]; then printf '%s\n' '중단: exact webhook entry 또는 Service relation 없음' >&2; elif SJ="$(kubectl get service "$SERVICE_NAME" -n "$SERVICE_NS" -o json)" && ESJ="$(kubectl get endpointslice -n "$SERVICE_NS" -l "kubernetes.io/service-name=$SERVICE_NAME" -o json)"; then SERVICE_UID="$(jq -er '.metadata.uid' <<<"$SJ")"; SERVICE_RV="$(jq -er '.metadata.resourceVersion' <<<"$SJ")"; TARGET_PORT="$(jq -er --argjson p "$SERVICE_PORT" '[.spec.ports[] | select(.port==$p)][0].targetPort | tostring' <<<"$SJ")"; ENDPOINT_HASH="$(jq -cS '[.items[] | {uid:.metadata.uid,rv:.metadata.resourceVersion,ports:.ports,endpoints:[.endpoints[]? | {ready:(.conditions.ready // null),targetKind:(.targetRef.kind // "-"),targetName:(.targetRef.name // "-"),targetUID:(.targetRef.uid // "-")}]}] | sort_by(.uid)' <<<"$ESJ" | sha256sum | cut -d' ' -f1)"; WEBHOOK_READY=true; export WEBHOOK_KIND WEBHOOK_NAME WEBHOOK_ENTRY WEBHOOK_UID WEBHOOK_RV SERVICE_NS SERVICE_NAME SERVICE_UID SERVICE_RV SERVICE_PORT TARGET_PORT ENDPOINT_HASH; printf 'WEBHOOK_READY=true config=%s/%s uid=%s rv=%s entry=%s service=%s/%s serviceUID=%s serviceRV=%s servicePort=%s targetPort=%s endpointHash=%s\n' "$WEBHOOK_KIND" "$WEBHOOK_NAME" "$WEBHOOK_UID" "$WEBHOOK_RV" "$WEBHOOK_ENTRY" "$SERVICE_NS" "$SERVICE_NAME" "$SERVICE_UID" "$SERVICE_RV" "$SERVICE_PORT" "$TARGET_PORT" "$ENDPOINT_HASH"; else printf '%s\n' '중단: webhook Service·EndpointSlice 조회 실패' >&2; fi; else printf '%s\n' '중단: webhook configuration 조회 실패' >&2; fi`

`current_webhook(){ local w s e h; [ "$WEBHOOK_READY" = true ] && current_admission || return 1; w="$(kubectl get "$WEBHOOK_KIND" "$WEBHOOK_NAME" -o json)" || return 1; s="$(kubectl get service "$SERVICE_NAME" -n "$SERVICE_NS" -o json)" || return 1; e="$(kubectl get endpointslice -n "$SERVICE_NS" -l "kubernetes.io/service-name=$SERVICE_NAME" -o json)" || return 1; jq -e --arg uid "$WEBHOOK_UID" --arg rv "$WEBHOOK_RV" --arg entry "$WEBHOOK_ENTRY" '.metadata.uid==$uid and .metadata.resourceVersion==$rv and ([.webhooks[] | select(.name==$entry)]|length)==1' <<<"$w" >/dev/null && jq -e --arg uid "$SERVICE_UID" --arg rv "$SERVICE_RV" '.metadata.uid==$uid and .metadata.resourceVersion==$rv' <<<"$s" >/dev/null || return 1; h="$(jq -cS '[.items[] | {uid:.metadata.uid,rv:.metadata.resourceVersion,ports:.ports,endpoints:[.endpoints[]? | {ready:(.conditions.ready // null),targetKind:(.targetRef.kind // "-"),targetName:(.targetRef.name // "-"),targetUID:(.targetRef.uid // "-")}]}] | sort_by(.uid)' <<<"$e" | sha256sum | cut -d' ' -f1)"; [ "$h" = "$ENDPOINT_HASH" ]; }`

`current_webhook_v2(){ local w s e h current_target; [ "$WEBHOOK_READY" = true ] && current_admission || return 1; w="$(kubectl get "$WEBHOOK_KIND" "$WEBHOOK_NAME" -o json)" || return 1; s="$(kubectl get service "$SERVICE_NAME" -n "$SERVICE_NS" -o json)" || return 1; e="$(kubectl get endpointslice -n "$SERVICE_NS" -l "kubernetes.io/service-name=$SERVICE_NAME" -o json)" || return 1; jq -e --arg uid "$WEBHOOK_UID" --arg rv "$WEBHOOK_RV" --arg entry "$WEBHOOK_ENTRY" --arg sns "$SERVICE_NS" --arg sn "$SERVICE_NAME" --argjson sp "$SERVICE_PORT" '.metadata.uid==$uid and .metadata.resourceVersion==$rv and ([.webhooks[] | select(.name==$entry and .clientConfig.service.namespace==$sns and .clientConfig.service.name==$sn and (.clientConfig.service.port // 443)==$sp)]|length)==1' <<<"$w" >/dev/null || return 1; jq -e --arg uid "$SERVICE_UID" --arg rv "$SERVICE_RV" '.metadata.uid==$uid and .metadata.resourceVersion==$rv' <<<"$s" >/dev/null || return 1; current_target="$(jq -er --argjson p "$SERVICE_PORT" '[.spec.ports[] | select(.port==$p)][0].targetPort|tostring' <<<"$s")" || return 1; [ "$current_target" = "$TARGET_PORT" ] || return 1; h="$(jq -cS '[.items[] | {uid:.metadata.uid,rv:.metadata.resourceVersion,ports:.ports,endpoints:[.endpoints[]? | {ready:(.conditions.ready // null),targetKind:(.targetRef.kind // "-"),targetName:(.targetRef.name // "-"),targetUID:(.targetRef.uid // "-")}]}] | sort_by(.uid)' <<<"$e" | sha256sum | cut -d' ' -f1)" || return 1; [ "$h" = "$ENDPOINT_HASH" ]; }; current_webhook(){ current_webhook_v2; }`

`WEBHOOK_READY=true`는 configuration→Service→EndpointSlice 선언 관계만 확인한다. backend TLS, listener, policy 판단과 admission 성공은 보장하지 않는다. URL 방식 webhook이면 내부 URL을 출력하지 않고 admission owner에게 exact auditID와 configuration UID/RV를 이관한다.

### 3. dry-run과 변경 경계

승인된 manifest만 server-side dry-run한다. 이 요청도 admission을 호출하므로 audit와 target identity가 현재여야 한다. 파일 내용이나 Secret 값을 출력하지 않는다.

`APPROVED_MANIFEST='PASTE_APPROVED_WORKLOAD_MANIFEST_PATH_HERE'; APPROVED_DIGEST='PASTE_APPROVED_SHA256_HERE'; DRYRUN_READY=false; if [ "$AUDIT_READY" != true ] || ! current_admission; then AUTO_READY=false; printf '%s\n' '중단: current audit/request identity가 아니다.' >&2; elif [ "$POLICY_BRANCH" = Webhook ] && ! current_webhook; then WEBHOOK_READY=false; printf '%s\n' '중단: current webhook relation이 아니다.' >&2; elif [ ! -f "$APPROVED_MANIFEST" ] || [ ! -r "$APPROVED_MANIFEST" ] || ! [[ "$APPROVED_DIGEST" =~ ^[a-f0-9]{64}$ ]]; then printf '%s\n' '중단: approved regular file/digest 오류' >&2; elif ACTUAL_DIGEST="$(sha256sum "$APPROVED_MANIFEST" | cut -d' ' -f1)" && [ "$ACTUAL_DIGEST" = "$APPROVED_DIGEST" ] && kubectl apply --dry-run=server -n "$NS" -f "$APPROVED_MANIFEST" >/dev/null; then DRYRUN_READY=true; printf 'DRYRUN_READY=true manifestDigest=%s request=%s\n' "$ACTUAL_DIGEST" "$REQUEST_KEY"; else DRYRUN_READY=false; printf '%s\n' '중단: digest 불일치 또는 server-side dry-run 거부' >&2; fi`

이 문서는 실제 `apply`, namespace label 완화, webhook 삭제·우회와 rollback 명령을 제공하지 않는다. mutation은 배포 시스템이 fresh request UID/RV·template digest, 단일 audit evidence, 승인 ID·주체·창, 가용성, 멱등성, 승인 digest와 이전 revision/digest를 직전에 재검증할 때만 수행한다.

## replacement 재등록과 정상화

외부 배포 뒤에는 이전 이름·UID와 모든 `READY`를 폐기하고 `refresh_admission`부터 실행한다. target이 controller이면 current selector·revision·creation time으로 새 Pod 후보를 조회하고, 후보가 하나로 결정되지 않으면 임의 선택하지 않는다. 새 Pod는 이름뿐 아니라 UID, controller owner kind/name/UID, current containerID와 node를 해당 workload 런북에서 다시 등록한다.

정상화는 `policy/admission 판단 -> object 생성의 새 UID·generation -> controller revision·selector -> 새 Pod owner/UID -> Ready -> Service endpoint -> 실제 기능 -> 승인 관찰 창의 동일 audit 거부 미재발` 순으로 확인한다. dry-run 성공, object 생성, Pod `Running`, webhook endpoint ready 또는 metric 감소만으로 닫지 않는다. rollback도 fresh 이전 revision/digest와 새 object identity를 등록한 뒤 같은 역순 검증을 반복한다.

## 증거와 Kubernetes 1.26 경계

보존 대상은 UTC 창, request key, namespace·target·webhook configuration·Service UID/RV, template/manifest digest, 단일 auditID의 redacted status, 승인·rollback과 실제 기능 결과다. actor 상세, request/response body, Secret·token·private key·caBundle·내부 endpoint 주소와 전체 audit 파일은 저장하지 않는다.

- [Kubernetes v1.26 Pod Security Admission](https://v1-26.docs.kubernetes.io/docs/concepts/security/pod-security-admission/)
- [Kubernetes v1.26 Dynamic admission control](https://v1-26.docs.kubernetes.io/docs/reference/access-authn-authz/extensible-admission-controllers/)
- AdmissionConfiguration default/exemption, webhook backend/TLS와 audit backend는 실제 환경 미검증이다.
