# API 서버 인증이 실패하거나 Unauthorized가 반환되는 경우

## 입력값과 빠른 수집

연결 경로는 `승인된 작업 host의 kubectl -> kubeconfig의 cluster/user mechanism -> TLS -> API server service -> authenticator·외부 identity provider -> authorization`이다. HTTP `401`은 authorization/RBAC보다 앞선 인증 경계이며, `/version` 성공은 익명 접근일 수 있어 현재 credential의 인증 성공을 보장하지 않는다.

| 종류 | 변수 | 출처 |
|---|---|---|
| 최초 입력 | `REQUEST_PATH` | query string이 없고 body를 만들지 않는 비민감 GET API path |
| API·client 자동값 | `CLUSTER_NAME`, `USER_NAME`, `EXEC_COMMAND`, `AUTH_PROVIDER`, `CLIENT_CERT_PATH`, `CONFIG_FINGERPRINT` | minified kubeconfig의 비밀값 없는 필드 |
| 계산 후보값 | `PATH_RE`, `AUDIT_RE` | audit filter용 escape 결과, 확인 전 확정 아님 |
| 운영자 선택값 | UTC 시작·종료, `AUDIT_HOST`, `APISERVER_UNIT`, 조건부 metric resource | 승인 inventory와 redacted audit 위치 확인 뒤 선택 |

Kubernetes object UID/RV, owner, containerID, node/runtime, storage identity는 이 API 인증 요청에는 적용되지 않는다. 대신 request path, kubeconfig mechanism fingerprint, API server host/service, auditID와 인증 subject lifecycle을 exact identity로 쓴다.

**원자적 client identity refresh**

`refresh_auth(){ local cfg vals material; unset AUTO_READY TIME_READY AUDIT_HOST_READY EVIDENCE_READY CHANGE_READY NORMAL_READY CLUSTER_NAME USER_NAME EXEC_COMMAND AUTH_PROVIDER CLIENT_CERT_PATH CONFIG_FINGERPRINT PATH_RE AUDIT_RE OBSERVED_AT START_RFC3339 END_RFC3339 AUDIT_HOST AUDIT_HOST_ID APISERVER_UNIT SUBJECT AUDIT_ID; AUTO_READY=false; TIME_READY=false; AUDIT_HOST_READY=false; EVIDENCE_READY=false; CHANGE_READY=false; NORMAL_READY=false; [ "$INPUT_READY" = true ] || { printf '%s\n' '중단: INPUT_READY가 아니다.' >&2; return 1; }; cfg="$(kubectl config view --minify -o json)" || { printf '%s\n' '중단: minified kubeconfig 조회 실패' >&2; return 1; }; vals="$(jq -er '[.contexts[0].context.cluster,.contexts[0].context.user,(.users[0].user.exec.command // "-"),(.users[0].user["auth-provider"].name // "-"),(.users[0].user["client-certificate"] // "-")] | if any(.[]; .==null or .=="") then error("client identity incomplete") else @tsv end' <<<"$cfg")" || { printf '%s\n' '중단: client identity 불완전' >&2; return 1; }; IFS=$'\t' read -r CLUSTER_NAME USER_NAME EXEC_COMMAND AUTH_PROVIDER CLIENT_CERT_PATH <<<"$vals"; material="$CLUSTER_NAME|$USER_NAME|$EXEC_COMMAND|$AUTH_PROVIDER|$CLIENT_CERT_PATH"; CONFIG_FINGERPRINT="$(printf '%s' "$material" | sha256sum | cut -d' ' -f1)" || return 1; PATH_RE="$(printf '%s' "$REQUEST_PATH" | sed 's/[][\\.^$*+?(){}|]/\\&/g')"; AUDIT_RE="$PATH_RE|401|Unauthorized|authentication|invalid bearer|client certificate|oidc|webhook"; OBSERVED_AT="$(date -u '+%Y-%m-%dT%H:%M:%SZ')" || return 1; AUTO_READY=true; export CLUSTER_NAME USER_NAME EXEC_COMMAND AUTH_PROVIDER CLIENT_CERT_PATH CONFIG_FINGERPRINT PATH_RE AUDIT_RE OBSERVED_AT; printf 'AUTO_READY=true cluster=%s configuredUser=%s exec=%s authProvider=%s clientCertPath=%s fingerprint=%s observed=%s\n' "$CLUSTER_NAME" "$USER_NAME" "$EXEC_COMMAND" "$AUTH_PROVIDER" "$CLIENT_CERT_PATH" "$CONFIG_FINGERPRINT" "$OBSERVED_AT"; }; refresh_auth`

refresh는 request identity, UID/RV·owner/container/node/runtime 자리에 해당하는 client·API·audit 관계, host, time, argv regex와 모든 downstream `READY`를 먼저 지운다. 실패한 호출은 stale `true`를 보존하지 않는다. exec args/env, token, inline certificate data와 private key는 읽지 않는다.

**현재 client identity guard**

`current_auth(){ local cfg vals fp; [ "$AUTO_READY" = true ] || return 1; cfg="$(kubectl config view --minify -o json)" || return 1; vals="$(jq -er '[.contexts[0].context.cluster,.contexts[0].context.user,(.users[0].user.exec.command // "-"),(.users[0].user["auth-provider"].name // "-"),(.users[0].user["client-certificate"] // "-")] | @tsv' <<<"$cfg")" || return 1; fp="$(printf '%s' "${vals//$'\t'/|}" | sha256sum | cut -d' ' -f1)" || return 1; [ "$fp" = "$CONFIG_FINGERPRINT" ]; }`

cluster·user 표시 이름이 같아도 server endpoint, CA 또는 credential mechanism이 바뀔 수 있다. 다음 보강 refresh는 secret 값을 읽지 않고 이 관계를 별도 fingerprint로 등록하며 모든 downstream 상태를 먼저 폐기한다.

`unset ENDPOINT_READY ENDPOINT_FINGERPRINT SERVER_URL CA_PATH INSECURE_TLS AUTH_MECHANISM_COUNT; ENDPOINT_READY=false; TIME_READY=false; AUDIT_HOST_READY=false; EVIDENCE_READY=false; CHANGE_READY=false; NORMAL_READY=false; if [ "$AUTO_READY" != true ]; then printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; elif CFG="$(kubectl config view --minify -o json)" && VALS="$(jq -er '[.clusters[0].cluster.server,(.clusters[0].cluster["certificate-authority"] // "inline-or-system"),(.clusters[0].cluster["insecure-skip-tls-verify"] // false | tostring),([.users[0].user | [has("token"),has("tokenFile"),has("client-certificate"),has("client-certificate-data"),has("exec"),has("auth-provider")][] | select(.)] | length | tostring)] | @tsv' <<<"$CFG")"; then IFS=$'\t' read -r SERVER_URL CA_PATH INSECURE_TLS AUTH_MECHANISM_COUNT <<<"$VALS"; if [ "$AUTH_MECHANISM_COUNT" -ne 1 ] || [ "$INSECURE_TLS" = true ]; then printf '중단: credential mechanism 수 또는 TLS 검증 설정이 승인 기준이 아님 mechanisms=%s insecure=%s\n' "$AUTH_MECHANISM_COUNT" "$INSECURE_TLS" >&2; else ENDPOINT_FINGERPRINT="$(printf '%s' "$CLUSTER_NAME|$USER_NAME|$SERVER_URL|$CA_PATH|$INSECURE_TLS|$EXEC_COMMAND|$AUTH_PROVIDER|$CLIENT_CERT_PATH" | sha256sum | cut -d' ' -f1)"; ENDPOINT_READY=true; export SERVER_URL CA_PATH INSECURE_TLS AUTH_MECHANISM_COUNT ENDPOINT_FINGERPRINT; printf 'ENDPOINT_READY=true server=%s ca=%s mechanismCount=%s fingerprint=%s\n' "$SERVER_URL" "$CA_PATH" "$AUTH_MECHANISM_COUNT" "$ENDPOINT_FINGERPRINT"; fi; else printf '%s\n' '중단: endpoint/auth mechanism 등록 실패' >&2; fi`

`current_auth_full(){ local cfg vals fp; [ "$AUTO_READY" = true ] && [ "$ENDPOINT_READY" = true ] || return 1; cfg="$(kubectl config view --minify -o json)" || return 1; vals="$(jq -er '[.contexts[0].context.cluster,.contexts[0].context.user,.clusters[0].cluster.server,(.clusters[0].cluster["certificate-authority"] // "inline-or-system"),(.clusters[0].cluster["insecure-skip-tls-verify"] // false | tostring),(.users[0].user.exec.command // "-"),(.users[0].user["auth-provider"].name // "-"),(.users[0].user["client-certificate"] // "-")] | @tsv' <<<"$cfg")" || return 1; fp="$(printf '%s' "${vals//$'\t'/|}" | sha256sum | cut -d' ' -f1)" || return 1; [ "$fp" = "$ENDPOINT_FINGERPRINT" ]; }; current_auth(){ current_auth_full; }`

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | `Unauthorized`, HTTP `401`, `You must be logged in`, invalid/expired credential 또는 client certificate 인증 오류 |
| 적용 | TLS·endpoint와 credential authentication을 분리하고 exact path·UTC·auditID·redacted authenticator 판정을 연결 가능 |
| 제외 | 인증된 subject의 `403`은 [[02. Kubernetes API 요청이 Forbidden으로 거부되는 경우]], admission 거부는 [[01. Pod 생성이 Pod Security·Admission 정책으로 거부되는 경우]] |

검색 문자열: `Unauthorized`, `HTTP 401`, `invalid bearer token`, `token is expired`, `client certificate`, `exec plugin`, `oidc`, `authentication webhook`.

## 읽기 전용 인증 확인

**API endpoint probe**

`if [ "$AUTO_READY" != true ] || ! current_auth; then AUTO_READY=false; EVIDENCE_READY=false; printf '%s\n' '중단: 현재 client identity가 아니다.' >&2; elif kubectl get --raw='/version'; then printf '%s\n' 'endpoint probe 성공: 현재 credential 인증 성공을 단독 보장하지 않음'; else printf '%s\n' 'endpoint/TLS/auth stderr를 redacted 상태로 분류' >&2; fi`

**원래 비민감 GET 재확인**

`if [ "$AUTO_READY" != true ] || ! current_auth; then AUTO_READY=false; EVIDENCE_READY=false; printf '%s\n' '중단: 현재 client identity가 아니다.' >&2; elif kubectl get --raw="$REQUEST_PATH" >/dev/null; then EVIDENCE_READY=true; printf 'request_status=success path=%s\n' "$REQUEST_PATH"; else RC=$?; EVIDENCE_READY=false; printf 'request_status=failed rc=%s path=%s\n' "$RC" "$REQUEST_PATH" >&2; fi`

응답 body는 저장하지 않는다. `401`이면 인증 경로, `403`이면 인증 후 정확한 RBAC 경로, TLS/timeout이면 API endpoint 경로다. 실패한 요청 뒤 `EVIDENCE_READY=true`를 유지하지 않는다.

client certificate **경로**가 실제 파일이고 오류가 x509 client identity를 지목할 때만 공개 metadata를 확인한다.

`if [ "$AUTO_READY" != true ] || ! current_auth; then AUTO_READY=false; printf '%s\n' '중단: 현재 client identity가 아니다.' >&2; elif [ "$CLIENT_CERT_PATH" = '-' ] || [ ! -r "$CLIENT_CERT_PATH" ]; then printf '%s\n' 'client certificate file 분기 아님'; elif command -v openssl >/dev/null 2>&1; then openssl x509 -in "$CLIENT_CERT_PATH" -noout -subject -issuer -dates -serial; else printf '%s\n' '중단: openssl 없음, 인증서 owner에게 공개 metadata 요청' >&2; fi`

inline `client-certificate-data`를 decode하지 않는다. exec plugin을 수동 실행하거나 stdout·token을 덤프하지 않는다. `kubectl` stderr의 비민감 종료 유형만 기록한다.

## UTC와 audit

`START_RFC3339='PASTE_START_RFC3339_HERE'; END_RFC3339='PASTE_END_RFC3339_HERE'; TIME_READY=false; RFC3339_RE='^[0-9]{4}-(0[1-9]|1[0-2])-([0-2][0-9]|3[01])T([01][0-9]|2[0-3]):[0-5][0-9]:[0-5][0-9]Z$'; if ! [[ "$START_RFC3339" =~ $RFC3339_RE ]] || ! [[ "$END_RFC3339" =~ $RFC3339_RE ]]; then printf '%s\n' '중단: canonical UTC RFC3339 형식 오류' >&2; elif [ "$(date -u -d "$START_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" != "$START_RFC3339" ] || [ "$(date -u -d "$END_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" != "$END_RFC3339" ]; then printf '%s\n' '중단: date round-trip 실패' >&2; elif [ "$(date -u -d "$START_RFC3339" +%s)" -ge "$(date -u -d "$END_RFC3339" +%s)" ]; then printf '%s\n' '중단: 시간 순서 오류' >&2; elif ! current_auth; then AUTO_READY=false; printf '%s\n' '중단: client identity 변경' >&2; else TIME_READY=true; export START_RFC3339 END_RFC3339; printf 'TIME_READY=true start=%s end=%s observed=%s\n' "$START_RFC3339" "$END_RFC3339" "$OBSERVED_AT"; fi`

audit backend와 API server가 systemd host에 있다는 사실이 승인 inventory로 확인된 경우에만 host/unit을 등록한다.

`AUDIT_HOST='PASTE_APPROVED_API_SERVER_HOST_HERE'; APISERVER_UNIT='PASTE_API_SERVER_UNIT_HERE'; AUDIT_HOST_READY=false; if [ "$TIME_READY" != true ] || ! current_auth; then AUTO_READY=false; printf '%s\n' '중단: 현재 TIME/client identity가 아니다.' >&2; elif ! [[ "$AUDIT_HOST" =~ ^[A-Za-z0-9._-]+$ ]] || ! [[ "$APISERVER_UNIT" =~ ^[A-Za-z0-9_.@-]+\.service$ ]]; then printf '%s\n' '중단: host/unit 형식 오류' >&2; else AUDIT_HOST_ID="$(ssh -- "$AUDIT_HOST" 'hostname --fqdn 2>/dev/null || hostname')" && ACTIVE="$(ssh -- "$AUDIT_HOST" 'systemctl is-active "$1"' sh "$APISERVER_UNIT")"; SSH_RC=$?; if [ "$SSH_RC" -eq 0 ] && [ "$ACTIVE" = active ] && [ -n "$AUDIT_HOST_ID" ]; then AUDIT_HOST_READY=true; export AUDIT_HOST AUDIT_HOST_ID APISERVER_UNIT; printf 'AUDIT_HOST_READY=true cluster=%s sshHost=%s linuxHost=%s service=%s\n' "$CLUSTER_NAME" "$AUDIT_HOST" "$AUDIT_HOST_ID" "$APISERVER_UNIT"; else printf '중단: API server host/service 확인 실패 rc=%s\n' "$SSH_RC" >&2; fi; fi`

`AUDIT_HOST_MACHINE_ID=''; if [ "$AUDIT_HOST_READY" != true ] || ! current_auth; then AUTO_READY=false; AUDIT_HOST_READY=false; printf '%s\n' '중단: current audit host/client identity가 아니다.' >&2; elif AUDIT_HOST_MACHINE_ID="$(ssh -- "$AUDIT_HOST" 'cat /etc/machine-id')" && [ -n "$AUDIT_HOST_MACHINE_ID" ]; then export AUDIT_HOST_MACHINE_ID; printf 'AUDIT_HOST_IDENTITY_READY=true linuxHost=%s machineID=%s\n' "$AUDIT_HOST_ID" "$AUDIT_HOST_MACHINE_ID"; else AUDIT_HOST_READY=false; printf '%s\n' '중단: remote machine identity 조회 실패' >&2; fi`

`current_auth_host(){ local remote; current_auth_full && [ "$AUDIT_HOST_READY" = true ] && [ -n "$AUDIT_HOST_MACHINE_ID" ] || return 1; remote="$(ssh -- "$AUDIT_HOST" 'set -eu; expected=$1; unit=$2; [ "$(cat /etc/machine-id)" = "$expected" ]; [ "$(systemctl is-active "$unit")" = active; printf ok' sh "$AUDIT_HOST_MACHINE_ID" "$APISERVER_UNIT")" || return 1; [ "$remote" = ok ]; }; current_auth(){ current_auth_host; }`

**redacted 인증 로그 pipeline**

`if [ "$AUDIT_HOST_READY" != true ] || [ "$TIME_READY" != true ] || ! current_auth; then AUTO_READY=false; EVIDENCE_READY=false; printf '%s\n' '중단: 현재 audit host/time/client identity가 아니다.' >&2; else ssh -- "$AUDIT_HOST" 'sudo journalctl -u "$1" --since "$2" --until "$3" --no-pager' sh "$APISERVER_UNIT" "$START_RFC3339" "$END_RFC3339" | grep -E -i -C 3 -- "$AUDIT_RE"; PS=("${PIPESTATUS[@]}"); printf 'pipeline ssh=%s grep=%s\n' "${PS[0]}" "${PS[1]}"; if [ "${PS[0]}" -ne 0 ]; then EVIDENCE_READY=false; elif [ "${PS[1]}" -eq 0 ]; then EVIDENCE_READY=true; elif [ "${PS[1]}" -eq 1 ]; then EVIDENCE_READY=false; printf '%s\n' '결과 없음: 인증 성공이 아니며 audit backend·보존·시간을 재확인' >&2; else EVIDENCE_READY=false; fi; fi`

static Pod·외부 audit backend이면 unit을 추측하지 않고 owner의 exact query를 사용한다. 필요한 audit 필드는 `auditID`, `stage`, `requestReceivedTimestamp`, `verb`, redacted `requestURI`, `user.username/groups`의 최소 표현, `responseStatus.code/reason`이다. `401`에서는 subject가 없을 수 있다. token, Authorization header, certificate data, source IP, cookie와 request/response body를 저장하지 않는다.

systemd journal 검색은 authenticator 오류 위치를 찾는 보조 단계다. 실제 401 증거는 승인된 audit JSON line 파일에서 단일 `auditID`의 완결 stage를 exact 조회한다. 파일 전체와 actor 상세는 출력하지 않는다.

`AUDIT_ID='PASTE_EXACT_AUDIT_ID_HERE'; AUDIT_LOG_PATH='PASTE_APPROVED_AUDIT_JSONL_PATH_HERE'; AUDIT_READY=false; EVIDENCE_READY=false; if [ "$AUDIT_HOST_READY" != true ] || [ "$TIME_READY" != true ] || ! current_auth; then AUTO_READY=false; printf '%s\n' '중단: 현재 audit host/time/client identity가 아니다.' >&2; elif ! [[ "$AUDIT_ID" =~ ^[A-Za-z0-9-]+$ ]] || ! [[ "$AUDIT_LOG_PATH" =~ ^/[-A-Za-z0-9._/]+$ ]]; then printf '%s\n' '중단: auditID 또는 절대경로 형식 오류' >&2; else AUDIT_JSON="$(ssh -- "$AUDIT_HOST" 'set -eu; path=$1; id=$2; sudo test -f "$path" -a -r "$path"; sudo jq -c --arg id "$id" '\''select(.auditID==$id and (.stage=="ResponseComplete" or .stage=="Panic"))'\'' "$path"' sh "$AUDIT_LOG_PATH" "$AUDIT_ID")"; SSH_RC=$?; if [ "$SSH_RC" -ne 0 ]; then printf '중단: audit producer 실패 ssh=%s\n' "$SSH_RC" >&2; elif ! AUDIT_SUMMARY="$(jq -ser --arg id "$AUDIT_ID" --arg path "$REQUEST_PATH" 'if length==1 and .[0].auditID==$id and .[0].verb=="get" and .[0].requestURI==$path and (.[0].responseStatus.code==401) and (.[0].requestReceivedTimestamp|type=="string") then .[0] | [.auditID,.requestReceivedTimestamp,.stage,.verb,.requestURI,(.responseStatus.code|tostring),(.responseStatus.reason // "-")] | @tsv else error("audit identity mismatch") end' <<<"$AUDIT_JSON")"; then printf '%s\n' '중단: 완결 audit record가 정확히 한 건이 아니거나 요청 identity 불일치' >&2; else IFS=$'\t' read -r AID ATS ASTAGE AVERB AURI ACODE AREASON <<<"$AUDIT_SUMMARY"; ATS_CANON="$(date -u -d "$ATS" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)"; if [ -z "$ATS_CANON" ] || [ "$(date -u -d "$ATS_CANON" +%s)" -lt "$(date -u -d "$START_RFC3339" +%s)" ] || [ "$(date -u -d "$ATS_CANON" +%s)" -gt "$(date -u -d "$END_RFC3339" +%s)" ]; then printf '%s\n' '중단: audit timestamp가 증거 창 밖임' >&2; else AUDIT_READY=true; EVIDENCE_READY=true; export AUDIT_ID AUDIT_LOG_PATH; printf 'AUDIT_READY=true auditID=%s timestamp=%s stage=%s verb=%s requestURI=%s status=%s reason=%s\n' "$AID" "$ATS_CANON" "$ASTAGE" "$AVERB" "$AURI" "$ACODE" "$AREASON"; fi; fi; fi`

Event·object relation은 인증 이전 401 요청에는 생성되지 않으며 object lifecycle UID도 적용할 수 없다. 이 경우 `not-applicable: authentication rejected before object authorization`으로 기록한다. audit `RequestReceived -> ResponseComplete/Panic` 순서와 client UTC를 연결하고, 같은 auditID가 없으면 서로 다른 요청을 합치지 않는다.

## 변경·rollback·정상화

위 명령은 읽기 전용이다. kubeconfig, token, client certificate, exec plugin, API server auth flag와 IdP를 이 문서에서 변경하지 않는다.

별도 변경의 `CHANGE_READY=true`에는 fresh client/API/audit identity, 직접적인 401·authenticator 증거, credential·control-plane·IdP owner와 영향 사용자 승인, 변경 창·HA quorum, credential 발급/rotation의 idempotence와 revocation 순서, 승인된 이전 config fingerprint와 검증된 rollback이 모두 필요하다. replacement credential·API server·host가 생기면 관계를 재등록하고 모든 `READY`를 폐기한다.

정상화는 `IdP/authenticator -> API server audit의 authenticated subject -> 동일한 비민감 GET -> 정확한 RBAC 판정 -> 실제 자동화·서비스 기능` 순으로 확인한다. 새 subject가 기대 subject와 exact match하고 승인된 관찰 창에 401이 재발하지 않아야 한다. `/version` 200, metric 감소 또는 다른 subject의 성공만으로 닫지 않는다. rollback 뒤에도 이전 identity와 기능을 실제 재검증한다.
