# NetworkPolicy 적용 결과가 의도한 통신 허용·차단과 다른 경우

## 입력값과 빠른 수집

연결 경로는 `source container network namespace -> CNI policy dataplane -> destination Pod 또는 Service -> EndpointSlice backend port -> destination listener -> application`이다. `connection refused`는 listener·port 후보이고 timeout은 policy·route·backend 지연 후보다. 어느 하나도 NetworkPolicy를 단독 확정하지 않는다.

| 종류 | 변수 | 출처와 의미 |
|---|---|---|
| 최초 입력 | `NS`, `POD` | 정책 결과가 문제인 exact Pod |
| API 자동값 | Pod/owner/containerID/node·namespace UID/RV, 전체 policy set hash | API 호출이 모두 성공한 뒤 등록 |
| 계산 후보값 | selector match 후보, direction, Service/Endpoint relation | current labels·spec에서 계산 |
| 운영자 선택값 | exact policy, ingress/egress, peer Pod, protocol/port, UTC 창, test container | 실제 통신 관측과 승인 의도에서 선택 |

Pod IP, Service IP, 내부 DNS와 packet 원문은 출력·증거에 저장하지 않는다. 각 `PASTE_..._HERE` 입력칸은 아래에서 한 번만 사용한다.

Pod·owner/containerID/node, namespace label 또는 어느 policy spec/RV라도 달라지면 과거 selector·test 결과를 폐기하고 refresh한다.

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | 특정 current Pod에서 승인 의도와 다른 허용·차단이 같은 방향·protocol·port로 재현됨 |
| 적용 | target·peer·namespace labels, 모든 selecting policy의 합집합, 선택 policy UID/RV와 실제 기능을 연결 가능 |
| 제외 | `hostNetwork`, CNI 미지원, mesh·host firewall 또는 node dataplane 문제는 구현 owner에게 이관 |

검색 문자열: `NetworkPolicy`, `podSelector`, `namespaceSelector`, `policyTypes`, `ingress`, `egress`, `endPort`, `timeout`, `connection refused`.

## policy 선택 후보와 exact 등록

다음 명령은 current Pod label에 selector가 맞는 policy만 출력한다. producer 성공, selector match 없음과 jq 오류를 분리한다.

`if ! current_network_target; then AUTO_READY=false; EVIDENCE_READY=false; printf '%s\n' '중단: current target identity가 아니다.' >&2; else PJ="$(kubectl get pod "$POD" -n "$NS" -o json)" && POLJ="$(kubectl get networkpolicy -n "$NS" -o json)"; API_RC=$?; if [ "$API_RC" -ne 0 ]; then printf '중단: Pod/NetworkPolicy producer 실패 rc=%s\n' "$API_RC" >&2; elif ! jq -er --argjson labels "$(jq -c '.metadata.labels // {}' <<<"$PJ")" 'def matches($l): all((.matchLabels // {})|to_entries[]; $l[.key]==.value) and all(.matchExpressions[]?; if .operator=="In" then ($l[.key] as $v | $v!=null and any(.values[]; .==$v)) elif .operator=="NotIn" then ($l[.key] as $v | $v==null or all(.values[]; .!=$v)) elif .operator=="Exists" then $l[.key]!=null elif .operator=="DoesNotExist" then $l[.key]==null else false end); [.items[] | select(.spec.podSelector|matches($labels)) | {name:.metadata.name,uid:.metadata.uid,rv:.metadata.resourceVersion,generation:.metadata.generation,policyTypes:(.spec.policyTypes // []),ingressRules:(.spec.ingress // []|length),egressRules:(.spec.egress // []|length)}] | if length==0 then error("no selecting policy") else .[] end' <<<"$POLJ"; then printf '%s\n' '선택 policy 없음 또는 selector 계산 오류: jq stderr를 구분해 확인' >&2; fi; fi`

여러 policy가 같은 방향으로 target을 선택하면 허용 규칙은 합집합이다. 한 policy만 보고 차단을 확정하지 않는다.

`POLICY='PASTE_EXACT_NETWORKPOLICY_HERE'; DIRECTION='PASTE_INGRESS_OR_EGRESS_HERE'; POLICY_READY=false; PEER_READY=false; SERVICE_READY=false; TIME_READY=false; TEST_READY=false; EVIDENCE_READY=false; if ! current_network_target; then AUTO_READY=false; printf '%s\n' '중단: current target identity가 아니다.' >&2; elif [ "$DIRECTION" != ingress ] && [ "$DIRECTION" != egress ]; then printf '%s\n' '중단: direction은 ingress 또는 egress' >&2; elif PJ="$(kubectl get networkpolicy "$POLICY" -n "$NS" -o json)" && VALS="$(jq -er '[.metadata.uid,.metadata.resourceVersion,(.metadata.generation|tostring)] | @tsv' <<<"$PJ")"; then IFS=$'\t' read -r POLICY_UID POLICY_RV POLICY_GENERATION <<<"$VALS"; POLICY_SPEC_HASH="$(jq -cS '.spec' <<<"$PJ" | sha256sum | cut -d' ' -f1)"; POLICY_READY=true; export POLICY DIRECTION POLICY_UID POLICY_RV POLICY_GENERATION POLICY_SPEC_HASH; printf 'POLICY_READY=true policy=%s uid=%s rv=%s generation=%s direction=%s specHash=%s\n' "$POLICY" "$POLICY_UID" "$POLICY_RV" "$POLICY_GENERATION" "$DIRECTION" "$POLICY_SPEC_HASH"; else printf '%s\n' '중단: exact policy 조회 실패' >&2; fi`

`current_policy(){ local p h; [ "$POLICY_READY" = true ] && current_network_target || return 1; p="$(kubectl get networkpolicy "$POLICY" -n "$NS" -o json)" || return 1; jq -e --arg uid "$POLICY_UID" --arg rv "$POLICY_RV" '.metadata.uid==$uid and .metadata.resourceVersion==$rv' <<<"$p" >/dev/null || return 1; h="$(jq -cS '.spec' <<<"$p" | sha256sum | cut -d' ' -f1)" || return 1; [ "$h" = "$POLICY_SPEC_HASH" ]; }`

## peer·port·시간 등록

ingress면 peer는 source, egress면 peer는 destination이다. peer가 외부 `ipBlock`이면 주소를 이 문서에 입력하지 않고 policy/CNI owner에게 CIDR·except 대조를 요청한다.

## 조건부 Service·EndpointSlice 관계

Service를 통과하지 않는 직접 Pod 통신이면 `SERVICE_NAME=-`로 입력한다. Service 경로면 실제 destination namespace와 이름을 등록한다.

`SERVICE_NS='PASTE_SERVICE_NAMESPACE_OR_DASH_HERE'; SERVICE_NAME='PASTE_SERVICE_NAME_OR_DASH_HERE'; SERVICE_READY=false; if [ "$TIME_READY" != true ] || ! current_peer; then AUTO_READY=false; printf '%s\n' '중단: current time/peer identity가 아니다.' >&2; elif [ "$SERVICE_NAME" = - ] && [ "$SERVICE_NS" = - ]; then SERVICE_READY=true; SERVICE_UID='not-applicable'; SERVICE_RV='not-applicable'; SERVICE_PORT='not-applicable'; TARGET_PORT="$PORT"; ENDPOINT_HASH='not-applicable'; printf 'SERVICE_READY=true relation=direct-pod targetPort=%s\n' "$TARGET_PORT"; elif ! [[ "$SERVICE_NS" =~ ^[-a-z0-9.]+$ ]] || ! [[ "$SERVICE_NAME" =~ ^[-a-z0-9.]+$ ]]; then printf '%s\n' '중단: Service identity 형식 오류' >&2; elif SJ="$(kubectl get service "$SERVICE_NAME" -n "$SERVICE_NS" -o json)" && ES="$(kubectl get endpointslice -n "$SERVICE_NS" -l "kubernetes.io/service-name=$SERVICE_NAME" -o json)"; then DEST_UID="$POD_UID"; [ "$DIRECTION" = egress ] && DEST_UID="$PEER_UID"; VALS="$(jq -er --argjson p "$PORT" '[.metadata.uid,.metadata.resourceVersion,([.spec.ports[] | select(.port==$p)] | length | tostring),([.spec.ports[] | select(.port==$p)][0].port | tostring),([.spec.ports[] | select(.port==$p)][0].targetPort | tostring)] | @tsv' <<<"$SJ")" && IFS=$'\t' read -r SERVICE_UID SERVICE_RV SERVICE_PORT_COUNT SERVICE_PORT TARGET_PORT <<<"$VALS"; ENDPOINT_MATCHES="$(jq -r --arg uid "$DEST_UID" '[.items[].endpoints[]? | select(.targetRef.kind=="Pod" and .targetRef.uid==$uid)] | length' <<<"$ES")"; if [ "$SERVICE_PORT_COUNT" -ne 1 ] || [ "$ENDPOINT_MATCHES" -lt 1 ]; then printf '중단: exact Service port 또는 destination endpoint relation 없음 portMatches=%s endpointMatches=%s\n' "$SERVICE_PORT_COUNT" "$ENDPOINT_MATCHES" >&2; else ENDPOINT_HASH="$(jq -cS '[.items[] | {uid:.metadata.uid,rv:.metadata.resourceVersion,ports:.ports,endpoints:[.endpoints[]? | {ready:(.conditions.ready // null),targetKind:(.targetRef.kind // "-"),targetName:(.targetRef.name // "-"),targetUID:(.targetRef.uid // "-")}]}] | sort_by(.uid)' <<<"$ES" | sha256sum | cut -d' ' -f1)"; SERVICE_READY=true; export SERVICE_NS SERVICE_NAME SERVICE_UID SERVICE_RV SERVICE_PORT TARGET_PORT ENDPOINT_HASH; printf 'SERVICE_READY=true service=%s/%s uid=%s rv=%s servicePort=%s targetPort=%s destinationUID=%s endpointHash=%s\n' "$SERVICE_NS" "$SERVICE_NAME" "$SERVICE_UID" "$SERVICE_RV" "$SERVICE_PORT" "$TARGET_PORT" "$DEST_UID" "$ENDPOINT_HASH"; fi; else printf '%s\n' '중단: Service·EndpointSlice API 실패' >&2; fi`

`current_network_path(){ local s e h dest matches target; [ "$SERVICE_READY" = true ] && current_peer_base || return 1; [ "$SERVICE_NAME" = - ] && [ "$SERVICE_NS" = - ] && [ "$ENDPOINT_HASH" = not-applicable ] && return 0; s="$(kubectl get service "$SERVICE_NAME" -n "$SERVICE_NS" -o json)" || return 1; e="$(kubectl get endpointslice -n "$SERVICE_NS" -l "kubernetes.io/service-name=$SERVICE_NAME" -o json)" || return 1; jq -e --arg uid "$SERVICE_UID" --arg rv "$SERVICE_RV" '.metadata.uid==$uid and .metadata.resourceVersion==$rv' <<<"$s" >/dev/null || return 1; target="$(jq -er --argjson p "$SERVICE_PORT" '[.spec.ports[] | select(.port==$p)][0].targetPort|tostring' <<<"$s")" || return 1; [ "$target" = "$TARGET_PORT" ] || return 1; dest="$POD_UID"; [ "$DIRECTION" = egress ] && dest="$PEER_UID"; matches="$(jq -r --arg uid "$dest" '[.items[].endpoints[]? | select(.targetRef.kind=="Pod" and .targetRef.uid==$uid)]|length' <<<"$e")" || return 1; [ "$matches" -gt 0 ] || return 1; h="$(jq -cS '[.items[] | {uid:.metadata.uid,rv:.metadata.resourceVersion,ports:.ports,endpoints:[.endpoints[]? | {ready:(.conditions.ready // null),targetKind:(.targetRef.kind // "-"),targetName:(.targetRef.name // "-"),targetUID:(.targetRef.uid // "-")}]}] | sort_by(.uid)' <<<"$e" | sha256sum | cut -d' ' -f1)" || return 1; [ "$h" = "$ENDPOINT_HASH" ]; }; current_peer(){ current_network_path; }`

named `targetPort`이면 Pod container port name과 실제 listener를 별도로 확인한다. EndpointSlice ready, Service selector 또는 NetworkPolicy port 선언은 process listener와 application 성공을 보장하지 않는다.

## 선언 대조와 제한된 재현

`if [ "$SERVICE_READY" != true ] || ! current_peer; then AUTO_READY=false; EVIDENCE_READY=false; printf '%s\n' '중단: current Service/peer/policy identity가 아니다.' >&2; elif NPJ="$(kubectl get networkpolicy "$POLICY" -n "$NS" -o json)"; then if jq -c --arg d "$DIRECTION" --arg protocol "$PROTOCOL" --arg port "$PORT" '{name:.metadata.name,uid:.metadata.uid,rv:.metadata.resourceVersion,generation:.metadata.generation,podSelector:.spec.podSelector,policyTypes:(.spec.policyTypes // []),direction:$d,rules:(if $d=="ingress" then .spec.ingress else .spec.egress end),testedProtocol:$protocol,testedPort:$port}' <<<"$NPJ"; then EVIDENCE_READY=true; else EVIDENCE_READY=false; printf '%s\n' '중단: policy filter 실패' >&2; fi; else EVIDENCE_READY=false; printf '%s\n' '중단: policy producer 실패' >&2; fi`

같은 방향으로 target을 선택하는 **모든** policy의 peer 합집합을 target/peer namespace labels와 대조한다. `namespaceSelector`와 `podSelector`가 같은 peer에 있으면 AND, 별도 peer면 OR다. 빈 peer는 전체, 빈 rule 목록은 해당 방향 전체 차단 후보이며 `policyTypes` 생략 시 Kubernetes 1.26 기본 규칙을 적용한다.

TCP 재현만 이 문서에서 제공한다. UDP/SCTP와 application protocol은 workload owner의 승인된 기능 검증을 사용한다. ingress의 source container는 peer, egress의 source container는 target에 있어야 한다.

`SOURCE_CONTAINER='PASTE_SOURCE_CONTAINER_HERE'; TEST_HOST='PASTE_APPROVED_TEST_HOST_HERE'; TEST_READY=false; if [ "$TIME_READY" != true ] || [ "$SERVICE_READY" != true ] || ! current_peer; then AUTO_READY=false; EVIDENCE_READY=false; printf '%s\n' '중단: current test identity가 아니다.' >&2; elif [ "$PROTOCOL" != TCP ] || ! [[ "$SOURCE_CONTAINER" =~ ^[-a-z0-9.]+$ ]] || ! [[ "$TEST_HOST" =~ ^[-A-Za-z0-9.]+$ ]]; then printf '%s\n' '중단: 이 명령은 승인된 TCP host와 container만 지원' >&2; else run_network_test(){ local src_ns src_pod spj test_rc; src_ns="$NS"; src_pod="$POD"; [ "$DIRECTION" = ingress ] && src_ns="$PEER_NS" && src_pod="$PEER_POD"; spj="$(kubectl get pod "$src_pod" -n "$src_ns" -o json)" || { printf '%s\n' '중단: source Pod refresh 실패' >&2; return 1; }; SOURCE_CONTAINER_ID="$(jq -er --arg c "$SOURCE_CONTAINER" '[.status.containerStatuses[]? | select(.name==$c)][0].containerID' <<<"$spj")" || { printf '%s\n' '중단: current regular containerID 없음' >&2; return 1; }; if kubectl exec "$src_pod" -n "$src_ns" -c "$SOURCE_CONTAINER" -- nc -vz -w 5 "$TEST_HOST" "$PORT"; then test_rc=0; else test_rc=$?; fi; if ! current_peer; then AUTO_READY=false; POLICY_READY=false; PEER_READY=false; printf '%s\n' '중단: test 뒤 identity 변경, 결과 폐기' >&2; return 1; fi; TEST_READY=true; export SOURCE_CONTAINER SOURCE_CONTAINER_ID; printf 'TEST_READY=true rc=%s direction=%s source=%s/%s sourceContainer=%s sourceContainerID=%s protocol=%s port=%s testedAt=%s\n' "$test_rc" "$DIRECTION" "$src_ns" "$src_pod" "$SOURCE_CONTAINER" "$SOURCE_CONTAINER_ID" "$PROTOCOL" "$PORT" "$(date -u '+%Y-%m-%dT%H:%M:%SZ')"; }; run_network_test; fi`

`rc=0`은 TCP connect 범위만 확인한다. `rc!=0`은 정책 차단을 단독 증명하지 않으며 `nc` 부재, DNS, route, listener, mesh와 CNI를 구분한다. 허용 검증은 application 고유 성공이 필요하고, 차단 검증은 승인된 음성 검증과 destination listener 정상 증거가 함께 있어야 한다.

## 변경·rollback·정상화

정책 삭제와 allow-all은 일반 복구가 아니다. 승인 manifest는 읽기 전용 server-side dry-run까지만 이 문서에서 확인한다.

`APPROVED_MANIFEST='PASTE_APPROVED_POLICY_MANIFEST_PATH_HERE'; APPROVED_DIGEST='PASTE_APPROVED_POLICY_SHA256_HERE'; DRYRUN_READY=false; if [ "$TEST_READY" != true ] || ! current_peer || ! current_policy; then AUTO_READY=false; POLICY_READY=false; PEER_READY=false; printf '%s\n' '중단: current evidence/policy identity가 아니다.' >&2; elif [ ! -f "$APPROVED_MANIFEST" ] || [ ! -r "$APPROVED_MANIFEST" ] || ! [[ "$APPROVED_DIGEST" =~ ^[a-f0-9]{64}$ ]]; then printf '%s\n' '중단: approved regular file/digest 오류' >&2; elif ACTUAL_DIGEST="$(sha256sum "$APPROVED_MANIFEST" | cut -d' ' -f1)" && [ "$ACTUAL_DIGEST" = "$APPROVED_DIGEST" ] && kubectl apply --dry-run=server -n "$NS" -f "$APPROVED_MANIFEST" >/dev/null; then DRYRUN_READY=true; printf 'DRYRUN_READY=true policyUID=%s policyRV=%s manifestDigest=%s\n' "$POLICY_UID" "$POLICY_RV" "$ACTUAL_DIGEST"; else printf '%s\n' '중단: digest 불일치 또는 dry-run 실패' >&2; fi`

실제 mutation은 배포 시스템이 fresh policy UID/RV/spec hash, target·peer·namespace UID/RV, Service/Endpoint relation, test evidence, 승인 ID·주체·창, 영향 consumer, 멱등성, 이전 manifest digest와 rollback을 직전에 재검증할 때만 수행한다. 이 문서는 `apply`·삭제·rollback 명령을 제공하지 않는다.

외부 변경 뒤 같은 이름의 policy나 Pod를 재사용하지 않는다. 모든 `READY`를 폐기하고 `refresh_networkpolicy`부터 실행해 policy set, target·peer UID/owner/containerID/node, Service·EndpointSlice를 재등록한다. replacement 후보는 current selector·owner UID·creation time으로 하나만 선택하며 복수 후보면 중단한다.

정상화는 `승인 policy spec -> selector·peer 합집합 -> namespace labels -> Service/Endpoint backend port -> destination listener -> 허용 application 기능과 차단 음성 검증 -> 여러 node에서 승인 관찰 창의 재발 없음` 순으로 확인한다. policy YAML 일치, `nc` 한 번 성공/실패, Endpoint ready, Pod Running 또는 metric 소멸만으로 닫지 않는다. 선언은 일치하지만 결과가 다르면 target·peer node UID, policy UID/RV, CNI 미확정 상태와 test 시각만 보존해 CNI/dataplane owner에게 이관한다.

## 증거와 Kubernetes 1.26 경계

보존 대상은 UTC 창, Pod·owner·namespace·Node·policy·Service UID/RV, containerID, selector·policyTypes·peer·protocol/port의 비민감 요약, endpoint target UID relation, pipeline/exec status, 승인 digest와 실제 기능 결과다. Pod/Service IP, 내부 DNS, packet 원문, Secret·token·private key와 전체 CNI 로그는 저장하지 않는다.

- [Kubernetes v1.26 Network Policies](https://v1-26.docs.kubernetes.io/docs/concepts/services-networking/network-policies/)
- CNI 종류·NetworkPolicy 지원, dataplane, mesh, node firewall와 application test는 실제 환경 미검증이다.
