# 使用 kubectl CLI 启用用户

> [!summary] 摘要
> 这是一个基于 KubeSphere Web UI、通过 Bastion 服务器绕行使用 kubectl CLI 的流程。按创建 Bastion 账户 → 申请 CyberArk 权限 → 从 ConfigMap 提取 config → 修改 Cluster VIP → 应用这 6 个步骤进行。

---

## 1. 概述

由于该流程基于 KubeSphere Web UI，kubectl CLI 默认不受支持，因此这是一种绕行解决方案。Kube config 每年需要更新 1 次。

各 Cluster 的 Bastion 服务器提供 Kubectl CLI 服务。

---

## 2. 事前请求流程

需要向 T-DKS 团队请求创建 Bastion 账户并开放防火墙。Bastion 账户名与 AD 账户名相同。

收到 DKS 运营团队的账户创建通知后，还需要单独请求 **CyberArk 权限**，以访问 Bastion 服务器。

### 请求表单格式

| 项目 | 内容 |
|------|------|
| **DKS kubectl application** | Remarks |
| **User information** | |
| - Requestor Name | 申请人姓名 |
| - User account | Global AD 账户 |
| **DKS information** | |
| - Cluster | 目标 Cluster（例如：dev-apps-pa01-xas） |
| - Project | 目标 Project |

---

## 3. 配置流程

### 流程

1. **连接 Bastion 服务器（Admin）**

   Admin 需要在 Bastion 服务器上创建账户，并设置用于 CLI 访问的 `.kube/config`。

2. **创建用户 config（ConfigMap）**

   ConfigMap: `kubeconfig-[User global AD account]`

   ```bash
   # 작업 디렉토리 생성
   mkdir [G-AD user account] && cd [G-AD user account]

   # ConfigMap 확인
   kubectl get -n kubesphere-controls-system configmaps | grep [G-AD user account]

   # Config 파일 생성
   kubectl describe configmaps -n kubesphere-controls-system kubeconfig-[AD 계정] > config
   ```

3. **修改 config 文件**

   ```bash
   vi config
   ```

   **修改事项**：

   | 更改项目 | 示例 |
   |-----------|------|
   | `server` | `https://109.156.25.57:6443` → Cluster VIP-A（例如：`https://10.166.202.239:6443`） |
   | `name` (clusters) | `local` → Cluster Name（例如：`prd-apps-pa01-xas`） |
   | `cluster` (contexts) | `local` → Cluster Name |
   | `name` (contexts) | `[AD 계정]@local` → `[AD 계정]@ClusterName` |
   | `current-context` | `[AD 계정]@local` → `[AD 계정]@ClusterName` |

   **要删除的部分**：
   - `#Name:`, `#Namespace:`, `#Labels:`, `#Annotations:`, `#Data`, `#===`, `#config:`, `#BinaryData`, `#Events:` 等所有注释行

4. **在 Bastion 服务器上创建用户账户**

   ```bash
   sudo useradd [G-AD user account]
   sudo passwd [G-AD user account]
   # OS Account: [G-AD user account] (AD 계정과 동일)
   # Password: abc135!!! (초기 비밀번호)
   ```

5. **移动 config 文件并设置权限**

   ```bash
   # .kube 디렉토리 생성
   sudo mkdir /home/[G-AD user account]/.kube

   # config 복사
   sudo cp config /home/[G-AD user account]/.kube/config

   # 소유권 변경
   sudo chown -R [G-AD user account]:[G-AD user account] /home/[G-AD user account]/.kube

   # 권한 확인
   sudo ls /home/[G-AD user account]/.kube -al
   # config 파일 권한: -rw------- (600)
   ```

6. **应用 config 并确认权限**

   ```bash
   # 사용자 계정으로 전환
   su [G-AD user account]

   # config 확인
   cat ~/.kube/config

   # current-context 확인
   kubectl config current-context
   # 예: [G-AD user account]@prd-apps-pa01-xas

   # kubectl 접근 테스트
   kubectl get all -n hello-kubesphere
   ```
