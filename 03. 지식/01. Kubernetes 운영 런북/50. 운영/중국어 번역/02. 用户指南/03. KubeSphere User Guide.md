## 3. 权限管理

在 Namespace(Project) 中授予用户部署权限。

| 角色 | 说明 |
|------|------|
| **Admin** | 管理项目内所有资源及成员 |
| **Operator** | 管理除用户/角色以外的项目资源 |
| **Viewer** | 仅查看项目内所有资源 |

### 授予 Operator 权限的流程

1. 使用项目管理员（project-admin）账户登录
2. **Projects** → 选择项目 → **Project Settings** → **Project Members**
3. 点击 **+User** → 添加成员账户
4. 在角色中选择 **Operator** → OK

## 4. 部署 PVC (UI)

### 4-1. 创建 PVC

1. KubeSphere Dashboard → **Storage** → **Volumes** → **Create**

### 4-2. 基本信息

| 项目 | 输入 | 备注 |
|------|------|------|
| Name | `<pvc-name>` | 必填 |
| Alias | — | 可选 |
| Description | — | 可选 |

### 4-3. 设置 PVC 选项

| 项目 | 选择 | 备注 |
|------|------|------|
| Storage Class | `taylor-netapp-qtree-nfs-sc-delete` | NAS |
| Access Mode | RWX | — |
| Volume Capacity | 输入容量 | — |

### 4-4. 创建

**Advanced Settings** → **Create**

---

## 5. 部署镜像 Secret (UI)

1. 点击 **Configuration** → **Secrets** → **Create**
2. 在 **Basic Information** 中输入 Secret Name → Next
3. 在 **Data Settings** 中设置 Secret 选项
4. **Type**：选择 Image registry information
5. **Registry Address**：输入镜像仓库地址
6. **Username**：输入镜像仓库账户
7. **Password**：输入镜像仓库密码
8. 点击 **Create**

---

|------|------|------|
| Name | `<deployment-name>` | 必填 |
| Alias | — | 可选 |
| Description | — | 可选 |

### 6-3. 设置选项

| 项目 | 输入 | 备注 |
|------|------|------|
| Pod Replicas | 输入副本数 | — |
| Container Image | 输入镜像名称 | — |

### 6-4. 挂载 PVC

1. 选择 **Volume Settings** → **Mount Volume** → **Existing Volume**

## 9. 基于 YAML 的部署

### 9-1. PVC YAML

1. KubeSphere Dashboard → **Storage** → **Volumes** → **Create** → **Edit YAML**

```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  namespace: wwjung-project
  name: harbor-yaml-nginx-test
spec:
  accessModes:
    - ReadWriteOnce
  resources:
    requests:
      storage: 10Gi
  storageClassName: powerflexos-ext4-sc-450t-sp16
  volumeMode: Filesystem
```

### 9-2. Deployment YAML

1. KubeSphere Dashboard → 选择项目 → **Application Workloads** → **Workloads** → **Deployments** → **Create** → **Edit YAML**

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  namespace: wwjung-project
  name: harbor-yaml-nginx-test
  labels:
    app: harbor-yaml-nginx-test
spec:
  replicas: 1
  selector:
    matchLabels:
      app: harbor-yaml-nginx-test
  template:
    metadata:
      labels:
        app: harbor-yaml-nginx-test
    spec:
      containers:
        - image: dcr.cloud.samsungds.net/dspaas-testrepo/nginx:latest
          imagePullPolicy: IfNotPresent
          name: container-uocn20
          ports:
            - containerPort: 80
              name: http-test
              protocol: TCP
          volumeMounts:
            - mountPath: /data
              name: harbor-yaml-nginx-test
      serviceAccount: default
      volumes:
        - name: harbor-yaml-nginx-test
          persistentVolumeClaim:
            claimName: harbor-yaml-nginx-test
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxUnavailable: 25%
      maxSurge: 25%
```

### 9-3. Service YAML

1. KubeSphere Dashboard → 选择项目 → **Application Workloads** → **Services** → **Create** → **Specify Workload** → **Edit YAML**

```yaml
apiVersion: v1
kind: Service
metadata:
  namespace: wwjung-project
  name: harbor-yaml-nginx-test
  labels:
    app: harbor-yaml-nginx-test
spec:
  sessionAffinity: None
  ports:
    - name: http-test
      port: 80
      protocol: TCP
      targetPort: 80
  selector:
    app: harbor-yaml-nginx-test
```

### 9-4. Route YAML

1. KubeSphere Dashboard → 选择项目 → **Application Workloads** → **Routes** → **Create** → **Edit YAML**

```yaml
apiVersion: extensions/v1beta1
kind: Ingress
metadata:
  namespace: wwjung-project
  name: harbor-yaml-nginx-test
spec:
  rules:
    - host: "harbor-yaml-nginx-test.apps.ksp-member.cloud.samsungds.net"
      http:
        paths:
          - pathType: ImplementationSpecific
            path: /
            backend:
              serviceName: harbor-yaml-nginx-test
              servicePort: 80
```

## 10. 设置 Autoscaling

1. 选择项目 → **Application Workloads** → **Workloads** → 选择 Deployment
2. 点击 **More** → **Edit Autoscaling**
3. 设置选项后点击 **OK**

| 项目 | 说明 |
|------|------|
| Target CPU Usage (%) | 实际使用量相对于请求量的平均 CPU 使用率（百分比） |
| Target Memory Usage (MiB) | 实际使用量相对于请求量的平均内存使用率 |
| Minimum Replicas | 最小 Pod 数量 |
| Maximum Replicas | 最大 Pod 数量 |

## 11. 使用 Kubectl CLI

各 Cluster 的 Bastion 服务器提供 Kubectl CLI 服务。

- 需要向 T-DKS 团队申请创建 Bastion 账户（与 AD 账户名相同）
- 收到账户创建通知后，还需要另外申请 **CyberArk 权限**

详细流程请参考 [[50. 운영/중국어 번역/03. 运营流程/KubeSphere/06. Enable users using kubectl CLI|使用 kubectl CLI 启用用户]]。
