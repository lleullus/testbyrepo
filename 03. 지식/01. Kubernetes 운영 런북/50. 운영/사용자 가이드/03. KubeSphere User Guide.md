## 3. 권한 관리

Namespace(Project)에서 사용자에게 배포 권한을 부여한다.

| 역할 | 설명 |
|------|------|
| **Admin** | 프로젝트 내 모든 리소스 및 멤버 관리 |
| **Operator** | 사용자/역할을 제외한 프로젝트 리소스 관리 |
| **Viewer** | 프로젝트 내 모든 리소스 조회 전용 |

### Operator 권한 부여 절차

1. 프로젝트-admin 계정으로 로그인
2. **Projects** → 프로젝트 선택 → **Project Settings** → **Project Members**
3. **+User** 클릭 → 멤버 계정 추가
4. 역할에서 **Operator** 선택 → OK

## 5. Image Secret 배포 (UI)

1. **Configuration** → **Secrets** → **Create** 클릭
2. **Basic Information**에서 Secret Name 입력 → Next
3. **Data Settings**에서 Secret 옵션 설정
4. **Type**: Image registry information 선택
5. **Registry Address**: 저장소 주소 입력
6. **Username**: 저장소 계정 입력
7. **Password**: 저장소 비밀번호 입력
8. **Create** 클릭

## 9. YAML 기반 배포

### 9-1. PVC YAML

1. KubeSphere Dashboard → **Storage** → **Volumes** → **Create** → **Edit YAML**

```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  namespace: wwjung-project
  name: harbor-yaml-nginx-test
spec:
  accessModes:
    - ReadWriteOnce
  resources:
    requests:
      storage: 10Gi
  storageClassName: powerflexos-ext4-sc-450t-sp16
  volumeMode: Filesystem
```

### 9-2. Deployment YAML

1. KubeSphere Dashboard → 프로젝트 선택 → **Application Workloads** → **Workloads** → **Deployments** → **Create** → **Edit YAML**

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  namespace: wwjung-project
  name: harbor-yaml-nginx-test
  labels:
    app: harbor-yaml-nginx-test
spec:
  replicas: 1
  selector:
    matchLabels:
      app: harbor-yaml-nginx-test
  template:
    metadata:
      labels:
        app: harbor-yaml-nginx-test
    spec:
      containers:
        - image: dcr.cloud.samsungds.net/dspaas-testrepo/nginx:latest
          imagePullPolicy: IfNotPresent
          name: container-uocn20
          ports:
            - containerPort: 80
              name: http-test
              protocol: TCP
          volumeMounts:
            - mountPath: /data
              name: harbor-yaml-nginx-test
      serviceAccount: default
      volumes:
        - name: harbor-yaml-nginx-test
          persistentVolumeClaim:
            claimName: harbor-yaml-nginx-test
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxUnavailable: 25%
      maxSurge: 25%
```

### 9-3. Service YAML

1. KubeSphere Dashboard → 프로젝트 선택 → **Application Workloads** → **Services** → **Create** → **Specify Workload** → **Edit YAML**

```yaml
apiVersion: v1
kind: Service
metadata:
  namespace: wwjung-project
  name: harbor-yaml-nginx-test
  labels:
    app: harbor-yaml-nginx-test
spec:
  sessionAffinity: None
  ports:
    - name: http-test
      port: 80
      protocol: TCP
      targetPort: 80
  selector:
    app: harbor-yaml-nginx-test
```

### 9-4. Route YAML

1. KubeSphere Dashboard → 프로젝트 선택 → **Application Workloads** → **Routes** → **Create** → **Edit YAML**

```yaml
apiVersion: extensions/v1beta1
kind: Ingress
metadata:
  namespace: wwjung-project
  name: harbor-yaml-nginx-test
spec:
  rules:
    - host: "harbor-yaml-nginx-test.apps.ksp-member.cloud.samsungds.net"
      http:
        paths:
          - pathType: ImplementationSpecific
            path: /
            backend:
              serviceName: harbor-yaml-nginx-test
              servicePort: 80
```

## 10. Autoscaling 설정

1. 프로젝트 선택 → **Application Workloads** → **Workloads** → Deployment 선택
2. **More** → **Edit Autoscaling** 클릭
3. 옵션 설정 후 **OK** 클릭

| 항목 | 설명 |
|------|------|
| Target CPU Usage (%) | 실제 사용량 대비 요청 대비 평균 CPU 사용률 (퍼센트) |
| Target Memory Usage (MiB) | 실제 사용량 대비 요청 대비 평균 메모리 사용률 |
| Minimum Replicas | 최소 Pod 수 |
| Maximum Replicas | 최대 Pod 수 |

## 11. Kubectl CLI 사용

각 Cluster의 Bastion 서버에서 Kubectl CLI 서비스를 제공한다.

- T-DKS팀에 Bastion 계정 생성 요청 필요 (AD 계정명과 동일)
