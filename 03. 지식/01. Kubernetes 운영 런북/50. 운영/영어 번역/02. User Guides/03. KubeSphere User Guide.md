## 3. Managing Permissions

Grant users deployment permissions in the Namespace (Project).

| Role | Description |
|------|------|
| **Admin** | Manages all resources and members in the project |
| **Operator** | Manages project resources but cannot manage users or roles |
| **Viewer** | Read-only access to all resources in the project |

### Procedure for Granting Operator Permissions

1. Log in with the project-admin account.
2. **Projects** -> Select the project -> **Project Settings** -> **Project Members**
3. Click **+User** -> Add the member account.
4. Select **Operator** as the role -> OK

## 5. Deploying an Image Secret (UI)

1. Click **Configuration** -> **Secrets** -> **Create**.
2. Enter the Secret Name in **Basic Information** -> Next.
3. Configure the Secret options in **Data Settings**.
4. **Type**: Select Image registry information.
5. **Registry Address**: Enter the registry address.
6. **Username**: Enter the registry account.
7. **Password**: Enter the registry password.
8. Click **Create**.

## 9. YAML-Based Deployment

### 9-1. PVC YAML

1. KubeSphere Dashboard -> **Storage** -> **Volumes** -> **Create** -> **Edit YAML**

```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  namespace: wwjung-project
  name: harbor-yaml-nginx-test
spec:
  accessModes:
    - ReadWriteOnce
  resources:
    requests:
      storage: 10Gi
  storageClassName: powerflexos-ext4-sc-450t-sp16
  volumeMode: Filesystem
```

### 9-2. Deployment YAML

1. KubeSphere Dashboard -> Select the project -> **Application Workloads** -> **Workloads** -> **Deployments** -> **Create** -> **Edit YAML**

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  namespace: wwjung-project
  name: harbor-yaml-nginx-test
  labels:
    app: harbor-yaml-nginx-test
spec:
  replicas: 1
  selector:
    matchLabels:
      app: harbor-yaml-nginx-test
  template:
    metadata:
      labels:
        app: harbor-yaml-nginx-test
    spec:
      containers:
        - image: dcr.cloud.samsungds.net/dspaas-testrepo/nginx:latest
          imagePullPolicy: IfNotPresent
          name: container-uocn20
          ports:
            - containerPort: 80
              name: http-test
              protocol: TCP
          volumeMounts:
            - mountPath: /data
              name: harbor-yaml-nginx-test
      serviceAccount: default
      volumes:
        - name: harbor-yaml-nginx-test
          persistentVolumeClaim:
            claimName: harbor-yaml-nginx-test
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxUnavailable: 25%
      maxSurge: 25%
```

### 9-3. Service YAML

1. KubeSphere Dashboard -> Select the project -> **Application Workloads** -> **Services** -> **Create** -> **Specify Workload** -> **Edit YAML**

```yaml
apiVersion: v1
kind: Service
metadata:
  namespace: wwjung-project
  name: harbor-yaml-nginx-test
  labels:
    app: harbor-yaml-nginx-test
spec:
  sessionAffinity: None
  ports:
    - name: http-test
      port: 80
      protocol: TCP
      targetPort: 80
  selector:
    app: harbor-yaml-nginx-test
```

### 9-4. Route YAML

1. KubeSphere Dashboard -> Select the project -> **Application Workloads** -> **Routes** -> **Create** -> **Edit YAML**

```yaml
apiVersion: extensions/v1beta1
kind: Ingress
metadata:
  namespace: wwjung-project
  name: harbor-yaml-nginx-test
spec:
  rules:
    - host: "harbor-yaml-nginx-test.apps.ksp-member.cloud.samsungds.net"
      http:
        paths:
          - pathType: ImplementationSpecific
            path: /
            backend:
              serviceName: harbor-yaml-nginx-test
              servicePort: 80
```

## 10. Configuring Autoscaling

1. Select the project -> **Application Workloads** -> **Workloads** -> Select the Deployment.
2. Click **More** -> **Edit Autoscaling**.
3. Configure the options -> Click **OK**.

| Item | Description |
|------|------|
| Target CPU Usage (%) | Average CPU usage as a percentage of the requested amount, based on actual usage |
| Target Memory Usage (MiB) | Average memory usage relative to the requested amount, based on actual usage |
| Minimum Replicas | Minimum number of Pods |
| Maximum Replicas | Maximum number of Pods |

## 11. Using the Kubectl CLI

The Kubectl CLI service is provided on the Bastion server for each Cluster.

- Request a Bastion account from the T-DKS team (same as the AD account name).
- After receiving notification that the Bastion account has been created, request **CyberArk permissions** separately.

For detailed procedures, see [[50. 운영/영어 번역/03. Operations Procedures/KubeSphere/06. Enable users using kubectl CLI|Enable users using kubectl CLI]].
