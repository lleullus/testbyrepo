# Enable users to use kubectl CLI

> [!summary] Summary
> Using kubectl CLI through the KubeSphere Web UI requires a Bastion server workaround. The process consists of six steps: creating a Bastion account → obtaining CyberArk permissions → extracting the config from the ConfigMap → modifying the Cluster VIP → applying the configuration.

---

## 1. Overview

Because KubeSphere is operated through the Web UI, kubectl CLI is not supported by default and requires this workaround. The kubeconfig must be renewed annually.

Each cluster has a Bastion server that provides kubectl CLI access.

---

## 2. Prerequisite request procedure

Request the T-DKS team to create a Bastion account and open the firewall. The Bastion account name must be the same as the AD account name.

After receiving notification from the DKS operations team that the account has been created, separately request **CyberArk permissions** to access the Bastion server.

### Request form template

| Item | Details |
|------|---------|
| **DKS kubectl application** | Remarks |
| **User information** | |
| - Requestor Name | Requestor's name |
| - User account | Global AD account |
| **DKS information** | |
| - Cluster | Target Cluster (e.g., dev-apps-pa01-xas) |
| - Project | Target Project |

## 3. Configuration procedure

### Procedure

1. **Connect to the Bastion server (Admin)**

   The Admin must create the account on the Bastion server and configure `.kube/config` for CLI access.

2. **Create the user config (ConfigMap)**

   ConfigMap: `kubeconfig-[User global AD account]`

   ```bash
   # 작업 디렉토리 생성
   mkdir [G-AD user account] && cd [G-AD user account]

   # ConfigMap 확인
   kubectl get -n kubesphere-controls-system configmaps | grep [G-AD user account]

   # Config 파일 생성
   kubectl describe configmaps -n kubesphere-controls-system kubeconfig-[AD 계정] > config
   ```

3. **Modify the config file**

   ```bash
   vi config
   ```

   **Changes**:

   | Change item | Example |
   |-------------|---------|
   | `server` | `https://109.156.25.57:6443` → Cluster VIP-A (e.g., `https://10.166.202.239:6443`) |
   | `name` (clusters) | `local` → Cluster Name (e.g., `prd-apps-pa01-xas`) |
   | `cluster` (contexts) | `local` → Cluster Name |
    | `name` (contexts) | `[AD account]@local` → `[AD account]@ClusterName` |
    | `current-context` | `[AD account]@local` → `[AD account]@ClusterName` |

   **Sections to remove**:
   - All comment lines, including `#Name:`, `#Namespace:`, `#Labels:`, `#Annotations:`, `#Data`, `#===`, `#config:`, `#BinaryData`, and `#Events:`

4. **Create the user account on the Bastion server**

   ```bash
   sudo useradd [G-AD user account]
   sudo passwd [G-AD user account]
   # OS Account: [G-AD user account] (AD 계정과 동일)
   # Password: abc135!!! (초기 비밀번호)
   ```

5. **Move the config file and set permissions**

   ```bash
   # .kube 디렉토리 생성
   sudo mkdir /home/[G-AD user account]/.kube

   # config 복사
   sudo cp config /home/[G-AD user account]/.kube/config

   # 소유권 변경
   sudo chown -R [G-AD user account]:[G-AD user account] /home/[G-AD user account]/.kube

   # 권한 확인
   sudo ls /home/[G-AD user account]/.kube -al
   # config 파일 권한: -rw------- (600)
   ```

6. **Apply the config and verify permissions**

   ```bash
   # 사용자 계정으로 전환
   su [G-AD user account]

   # config 확인
   cat ~/.kube/config

   # current-context 확인
   kubectl config current-context
   # 예: [G-AD user account]@prd-apps-pa01-xas

   # kubectl 접근 테스트
   kubectl get all -n hello-kubesphere
   ```
