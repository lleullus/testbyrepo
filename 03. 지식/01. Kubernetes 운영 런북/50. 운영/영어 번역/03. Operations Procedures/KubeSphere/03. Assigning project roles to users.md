# Assigning project roles to users

> [!summary] Summary
> This procedure assigns roles at the Project level to members invited to the Workspace. Select one of project-admin, project-operator, or project-viewer based on the information in the user's request.

---

## Inviting Project members

**Only members invited to the Workspace can be designated as project-admin.** Therefore, you must first invite the user to the Workspace by following the procedure in 02. Inviting a new member.

### Procedure

1. Click **Projects** in the left navigation panel
2. Click the **Project name** whose user permissions you want to change
3. Click **Project Settings > Project Members > Invite**
4. **Invite the user**
   - Assign a Role based on the Permission field (Admin/User) in the user's request form (see the `[!note]` permission mapping below)
5. Click **OK**

---

## Role assignment criteria

| Role | Permissions | Request form Permission |
|------|-------------|-------------------------|
| **project-admin** | Project administrator — can create/modify/delete resources, change settings, and invite members | - |
| **project-operator** | General user — can create/modify/delete resources but cannot change settings | Admin |
| **project-viewer** | Read-only — can view resources only and cannot make changes | User |

---

> [!note] Permission mapping reference
> Users who request "Admin" permission in the request form are assigned the `project-operator` role, while users who request "User" permission are assigned the `project-viewer` role.
