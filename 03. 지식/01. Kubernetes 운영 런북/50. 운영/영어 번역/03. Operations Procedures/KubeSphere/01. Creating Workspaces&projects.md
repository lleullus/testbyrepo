# Creating Workspaces and Projects

> [!summary] Summary
> Creating a KubeSphere project consists of four steps: submitting a request → confirming login → creating a Workspace → creating a Project. Under DKS policy, each Workspace corresponds to exactly one Project.

---

## 1. Submit a Request

The system administrator receives the user's request to use the KubeSphere Project.

In KubeSphere, a **Project** represents a Kubernetes **Namespace**. Therefore, users must submit a request for DKS Namespace service access through a KubeSphere Project.

## 2. Confirm Login History

KubeSphere requires the user's access history when approving an account. Therefore, before creating the Project, confirm that the user has accessed the KubeSphere web dashboard at least once.

### Procedure

1. Log in to the KubeSphere web console (Host Cluster) with an Admin account
2. Click **Workbench > Users** in the top navigation bar → go to the user management page
3. Check the target user's login history
4. If there is no login history, ask the user to access KubeSphere on the web first

---

## 3. Create a Workspace

A Workspace is the logical unit of a Project. It is used to control access to resources within a team and share resources.

Under DKS policy, **each Workspace corresponds to exactly one Project**. Therefore, create one Project under each Workspace.

### Procedure

1. Click **Workspace > Create**
2. On the **Basic Information** page:
   - **Name**: `ws-[cluster]-[project]-[suffix]`
     - Use lowercase for all characters
     - Example: `ws-prd-apps-pa01-xas-myapp-prd`
   - **Administrator**: Select `admin(DKS)` from the drop-down list
   - **Description**: Enter requester information (AD account, department, request date, etc.)
3. On the **Cluster Settings** page:
   - Confirm the Project name and assign the Cluster
   - `prd` suffix → `prd-apps-pa01-xas` (production)
   - `dev` suffix → `dev-apps-pa01-xas` (development)

    #### Cluster Information

    | Namespace suffix | Purpose      | Cluster name          | Ingress domain                              |
    | -------------- | --------- | ---------------- | ----------------------------------------- |
    | OOO-prd        | Production | prd-apps-pa01-xas | *.xaprdpa01.apps.dks.samsungds.net        |
    | OOO-dev        | Development | dev-apps-pa01-xas | *.xadevpa01.apps.dks.samsungds.net        |

    > [!note] Permission Mapping Reference
   > If the request form specifies the "admin" permission, the `project-operator` role is assigned in KubeSphere. If it specifies the "user" permission, the `project-viewer` role is assigned.

4. Click **Create**

---

## 4. Create a Project

A KubeSphere Project is equivalent to a Kubernetes Namespace and provides virtual isolation for resources.

### Procedure

1. In the Workspace, click **Projects > Create**
2. Enter the Project name and click **OK**
   - You can add an alias (Alias) and a description (Description)
3. Click the created Project in the **Projects** list → check the details
