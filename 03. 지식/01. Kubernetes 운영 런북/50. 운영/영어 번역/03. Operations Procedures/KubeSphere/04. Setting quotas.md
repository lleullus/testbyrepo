# Setting quotas

> [!summary] Summary
> Set three types of quotas: Workspace Quotas (CPU/Memory), Project Quotas (CPU/Memory), and Storage Resource Quota. Because each Workspace corresponds to exactly one Project in the DKS environment, set Workspace Quota and Project Quota to the same values.

> [!note] Request Form Integration
> Set quota values according to the **DKS Information** fields (CPU, Memory, and Storage) in the user's submitted request form. Refer to [[50. 운영/영어 번역/03. Operations Procedures/KubeSphere/01. Creating Workspaces&projects|01. Creating Workspaces and Projects]] for the request form sample.

---

## 1. Workspace Quotas (CPU/Memory)

Workspace Quotas control the total resource usage of all Projects within a Workspace.

Because each Workspace corresponds to exactly one Project in the DKS environment, set Workspace Quota and Project Quota to the same values.

Workspace Quotas include **Requests** and **Limits** for CPU and Memory.

- **Requests**: Guarantee and reserve the resources required by Projects within the Workspace.
- **Limits**: Prevent all Projects within the Workspace from exceeding a specified resource usage value.

### Procedure

1. Click **Workbench > Workspaces**
2. Select the **Workspace** for which quotas will be configured
3. Click **Workspace Settings > Workspace Quotas > Edit Quotas**
4. **Configure Quotas**
   - Default: Neither Requests nor Limits is configured
   - Move the slider or enter a number directly
   - **CPU Limit**: The application's CPU core value
   - **CPU Request**: The application's CPU core value
   - **Memory Limit**: The application's memory value
   - **Memory Request**: The application's memory value
5. Click **OK**

---

## 2. Project Quotas (CPU/Memory)

KubeSphere uses Kubernetes Requests and Limits to control resource (CPU and Memory) usage within a Project. In Kubernetes, these are called **ResourceQuotas**.

- **Requests**: Guarantee and reserve the resources required by the Project.
- **Limits**: Prevent the Project from using resources beyond a specified value.

### Procedure

1. Check Quotas on the **Project Overview** page
   - A newly created Project has no Quotas configured
   - Click **Edit Quotas** to configure them
2. **Configure Quotas**
   - Default: Neither Requests nor Limits is configured
   - Move the slider or enter a number directly
   - **CPU Limit**: The application's CPU core value
   - **CPU Request**: The application's CPU core value
   - **Memory Limit**: The application's memory value
   - **Memory Request**: The application's memory value
3. Click **OK**
4. Check all resource Quotas in **Project Settings > Basic Info**

## 3. Storage Resource Quota

Limit the total storage resources that can be requested in a Namespace (= Project). Storage consumption can also be limited by StorageClass.

### Procedure

1. **Check the current StorageClass status**

   ```bash
   $ kubectl get sc
   ```

   | NAME | PROVISIONER | RECLAIMPOLICY | VOLUMEBINDINGMODE | ALLOWVOLUMEEXPANSION | AGE |
   |------|-------------|---------------|-------------------|----------------------|-----|
   | xa-netapp-nfs-sc | csi.trident.netapp.io | Delete | Immediate | true | 27d |
   | powerflexos-xfs-sc-300t-sp04 | csi-vxflexos.dellemc.com | Delete | Immediate | true | 83d |

   **Quota configuration is required for every StorageClass in the cluster.**

> StorageClasses have not yet been preconfigured in the Xi'an environment. Check the actual `kubectl get sc` result, then change and use the SC names accordingly.

2. **Create a YAML file**

   ```yaml
   # storagequota.yaml
   ---
   apiVersion: v1
   kind: ResourceQuota
   metadata:
     name: (project name)-storage-quota
     namespace: (project name)
   spec:
     hard:
       # 개별 StorageClass별 할당량
       xa-netapp-nfs-sc.storageclass.storage.k8s.io/requests.storage: 10Gi
       powerflexos-xfs-sc-300t-sp04.storageclass.storage.k8s.io/requests.storage: 5Gi
       # 모든 StorageClass의 총합
       requests.storage: 15Gi
   ```

   #### Field Descriptions

   | Field | Description |
   |------|------|
   | `metadata.name` | `(project name)-storage-quota` |
   | `metadata.namespace` | Project name |
   | `requests.storage` | Total storage that can be requested in the Namespace. Setting this value to `100Gi` prevents total requested storage from exceeding `100Gi`. |
   | `<storage-class-name>.storageclass.storage.k8s.io/requests.storage` | Total storage requests for the corresponding StorageClass |

   **Example**: When allocating `xa-netapp-nfs-sc` and `powerflexos-xfs-sc-300t-sp04` separately:

   ```yaml
   spec:
     hard:
       xa-netapp-nfs-sc.storageclass.storage.k8s.io/requests.storage: 50Gi
       powerflexos-xfs-sc-300t-sp04.storageclass.storage.k8s.io/requests.storage: 50Gi
       requests.storage: 100Gi
   ```

   - `requests.storage`: The total storage request across all PersistentVolumeClaims cannot exceed this value
   - `<storage-class-name>.storageclass.storage.k8s.io/requests.storage`: The total PVC request for the corresponding StorageClass cannot exceed this value

3. **Apply the ResourceQuota**

   ```bash
   $ kubectl create -f storagequota.yaml
   resourcequota/(project name)-storage-quota created
   ```
