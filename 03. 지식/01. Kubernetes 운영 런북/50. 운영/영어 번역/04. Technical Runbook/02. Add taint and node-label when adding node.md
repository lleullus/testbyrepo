## 1. Taints & Tolerations Concept

### Components

Taints and tolerations consist of three components: Key, Value, and Effect.

- **Taints** (node property) — configured so that a node rejects specific Pods
- **Tolerations** (Pod property) — allows a Pod to be scheduled on a node with a taint

Example: `key1=value1:NoSchedule` — a Pod without a matching toleration cannot be scheduled on a node with a taint whose `key1` is `value1`.

### Three Effects

| Effect | Behavior |
|--------|------|
| `PreferNoSchedule` | Avoid scheduling Pods if possible (preferred, but not strict) |
| `NoSchedule` | Pods without a matching toleration cannot be scheduled |
| `NoExecute` | Pods without a matching toleration are evicted immediately |

## 5. Deploy nodeSelector & Toleration

### 5-1. nodeSelector

Add `nodeSelector` to the Pod spec to match the labels of the target node:

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: checker-podselector-test3
spec:
  replicas: 1
  selector:
    matchLabels:
      app: checker3
  template:
    metadata:
      labels:
        app: checker3
    spec:
      containers:
        - name: checker
          image: xa.dcr.dks.samsungds.net/dspaas-testrepo/checker:v5
          command: ['s', '-c', 'sleep 365d']
      nodeSelector:
        kubernetes.io/os: linux
        team: dscmp
        node-type: worker
```

### 5-2. tolerations

Allow Pod scheduling on a node with a taint:

```yaml
spec:
  tolerations:
    - key: team
      value: dscmp
      effect: NoSchedule
```
