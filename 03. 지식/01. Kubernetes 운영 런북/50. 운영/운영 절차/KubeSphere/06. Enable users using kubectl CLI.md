# Enable users using kubectl CLI

> [!summary] 요약
> Kubesphere Web UI 기반 kubectl CLI 사용은 Bastion 서버 우회 절차이다. Bastion 계정 생성 → CyberArk 권한 → ConfigMap에서 config 추출 → Cluster VIP 수정 → 적용의 6단계로 진행된다.

---

## 1. 개요

Kubesphere Web UI 기반이므로 kubectl CLI는 기본 지원되지 않는 우회 솔루션이다. Kube config는 연 1회 갱신해야 한다.

각 Cluster별 Bastion 서버에서 Kubectl CLI 서비스를 제공한다.

---

## 2. 사전 요청 절차

T-DKS 팀에 Bastion 계정 생성 및 방화벽 개방을 요청해야 한다. Bastion 계정명은 AD 계정명과 동일하다.

DKS 운영팀으로부터 계정 생성 통보를 받으면, Bastion 서버 접근을 위해 **CyberArk 권한**을 별도로 요청해야 한다.

### 요청 폼 양식

| 항목 | 내용 |
|------|------|
| **DKS kubectl application** | Remarks |
| **User information** | |
| - Requestor Name | 신청자 이름 |
| - User account | Global AD 계정 |
| **DKS information** | |
| - Cluster | 대상 Cluster (예: dev-apps-pa01-xas) |
| - Project | 대상 Project |

---

## 3. 설정 절차

### 절차

1. **Bastion 서버 연결 (Admin)**

   Admin이 Bastion 서버에 계정을 생성하고, CLI 접근을 위한 `.kube/config`를 설정해야 한다.

2. **사용자 config 생성 (ConfigMap)**

   ConfigMap: `kubeconfig-[User global AD account]`

   ```bash
   # 작업 디렉토리 생성
   mkdir [G-AD user account] && cd [G-AD user account]

   # ConfigMap 확인
   kubectl get -n kubesphere-controls-system configmaps | grep [G-AD user account]

   # Config 파일 생성
   kubectl describe configmaps -n kubesphere-controls-system kubeconfig-[AD 계정] > config
   ```

3. **config 파일 수정**

   ```bash
   vi config
   ```

   **수정 사항**:

   | 변경 항목 | 예시 |
   |-----------|------|
   | `server` | `https://109.156.25.57:6443` → Cluster VIP-A (예: `https://10.166.202.239:6443`) |
   | `name` (clusters) | `local` → Cluster Name (예: `prd-apps-pa01-xas`) |
   | `cluster` (contexts) | `local` → Cluster Name |
   | `name` (contexts) | `[AD 계정]@local` → `[AD 계정]@ClusterName` |
   | `current-context` | `[AD 계정]@local` → `[AD 계정]@ClusterName` |

   **제거할 섹션**:
   - `#Name:`, `#Namespace:`, `#Labels:`, `#Annotations:`, `#Data`, `#===`, `#config:`, `#BinaryData`, `#Events:` 등 모든 주석 라인

4. **Bastion 서버에 사용자 계정 생성**

   ```bash
   sudo useradd [G-AD user account]
   sudo passwd [G-AD user account]
   # OS Account: [G-AD user account] (AD 계정과 동일)
   # Password: abc135!!! (초기 비밀번호)
   ```

5. **config 파일 이동 및 권한 설정**

   ```bash
   # .kube 디렉토리 생성
   sudo mkdir /home/[G-AD user account]/.kube

   # config 복사
   sudo cp config /home/[G-AD user account]/.kube/config

   # 소유권 변경
   sudo chown -R [G-AD user account]:[G-AD user account] /home/[G-AD user account]/.kube

   # 권한 확인
   sudo ls /home/[G-AD user account]/.kube -al
   # config 파일 권한: -rw------- (600)
   ```

6. **config 적용 및 권한 확인**

   ```bash
   # 사용자 계정으로 전환
   su [G-AD user account]

   # config 확인
   cat ~/.kube/config

   # current-context 확인
   kubectl config current-context
   # 예: [G-AD user account]@prd-apps-pa01-xas

   # kubectl 접근 테스트
   kubectl get all -n hello-kubesphere
   ```
