# 여러 Node에서 동일한 registry pull 실패가 발생하는 경우

## 입력값과 빠른 수집

연결 경로는 `승인된 작업 host의 kubectl -> API server -> Pod·Node 객체`, `승인된 작업 host -> SSH host -> kubelet -> active CRI endpoint -> runtime -> registry service`다. 한 hop의 성공은 다음 hop의 성공을 보장하지 않는다. 이 문서는 storage 변경을 하지 않으며 imagefs 문제가 직접 보이면 [[04. Node imagefs 용량 부족·image garbage collection이 실패한 경우]]로 이동한다.

| 종류 | 변수 | 출처와 의미 |
|---|---|---|
| 최초 입력 | `NS`, `SELECTOR` | 확인된 namespace와 workload selector |
| API 자동값 | `POD_UID`, `POD_RV`, `OWNER_*`, `CONTAINER_ID`, `NODE`, `NODE_UID`, `NODE_RV`, `RUNTIME_VERSION`, `IMAGE` | exact Pod·container·Node API에서 현재 Bash에 등록 |
| 계산 후보값 | `IMAGE_RE`, `JOURNAL_RE`, `POD_RE`, `CONTAINER_RE`, `ENDPOINT_ARG_RE` | 로그·PromQL·argv exact-match용 escape 결과이며 bounded 출력 뒤 사용 |
| 운영자 선택값 | `REP_POD`, `CONTAINER`, `REGISTRY_HOST`, `START_RFC3339`, `END_RFC3339`, `NODE_HOST`, `KUBELET_UNIT`, `RUNTIME_UNIT`, `CRI_ENDPOINT` | 후보 출력, 변경 기록과 승인된 node inventory를 보고 선택 |

`PASTE_..._HERE` 문자열은 각각 아래에서 한 번만 나온다. 같은 Bash와 같은 작업 host를 유지한다.

**Bash와 도구 확인**

`TOOLS_READY=false; MISSING=''; if [ -z "${BASH_VERSION:-}" ]; then printf '%s\n' '중단: Bash에서 실행한다.' >&2; else for T in kubectl jq sed grep date ssh curl; do command -v "$T" >/dev/null 2>&1 || MISSING="$MISSING $T"; done; if [ -z "$MISSING" ]; then TOOLS_READY=true; printf 'TOOLS_READY=true bash=%s\n' "$BASH_VERSION"; else printf '중단: 없는 도구=%s\n' "$MISSING" >&2; fi; fi`

**최초 입력과 전체 lifecycle 초기화**

`unset INPUT_READY AUTO_READY TIME_READY HOST_READY CRI_READY EVIDENCE_READY CHANGE_READY NORMAL_READY POD_UID POD_RV OWNER_KIND OWNER_NAME OWNER_UID CONTAINER_ID NODE NODE_UID NODE_RV NODE_HOST HOST_ID RUNTIME_VERSION RUNTIME_PROVIDER IMAGE IMAGE_RE JOURNAL_RE POD_RE CONTAINER_RE ENDPOINT_ARG_RE OBSERVED_AT START_RFC3339 END_RFC3339 REGISTRY_HOST REP_POD CONTAINER KUBELET_UNIT RUNTIME_UNIT CRI_ENDPOINT; INPUT_READY=false; AUTO_READY=false; TIME_READY=false; HOST_READY=false; CRI_READY=false; EVIDENCE_READY=false; CHANGE_READY=false; NORMAL_READY=false; NS='PASTE_NAMESPACE_HERE'; SELECTOR='PASTE_WORKLOAD_SELECTOR_HERE'; if [ "$TOOLS_READY" != true ]; then printf '%s\n' '중단: TOOLS_READY가 아니다.' >&2; elif [ -z "$NS" ] || [ -z "$SELECTOR" ]; then printf '%s\n' '중단: 최초 입력이 비었다.' >&2; elif kubectl get pods -n "$NS" -l "$SELECTOR" -o name >/dev/null; then INPUT_READY=true; export NS SELECTOR; printf 'INPUT_READY=true NS=%s SELECTOR=%s\n' "$NS" "$SELECTOR"; else printf '%s\n' '중단: namespace·selector 조회 실패' >&2; fi`

실패한 호출은 어떤 `READY`도 `true`로 남기지 않는다. 다음 refresh는 UID·RV·owner·containerID·node·host·runtime·service 관계·시각·argv regex와 모든 downstream `READY`를 먼저 지운다.

**현재 후보 출력**

`if [ "$INPUT_READY" != true ]; then printf '%s\n' '중단: INPUT_READY가 아니다.' >&2; elif DATA="$(kubectl get pods -n "$NS" -l "$SELECTOR" -o json)"; then jq -r '.items[] | "\n=== Pod: \(.metadata.name) ===\nUID: \(.metadata.uid)\nRV: \(.metadata.resourceVersion)\nOwner: \([.metadata.ownerReferences[]? | select(.controller==true) | "\(.kind)/\(.name) uid=\(.uid)"] | join(","))\nNode: \(.spec.nodeName // "-")\n생성: \(.metadata.creationTimestamp)\nContainer/Image/ID/Reason: \([.spec.containers[] as $c | ($c.name) as $n | (.status.containerStatuses[]? | select(.name==$n)) as $s | "\($n) image=\($c.image) id=\($s.containerID // "-") reason=\($s.state.waiting.reason // "-") message=\($s.state.waiting.message // "-")"] | join("; "))"' <<<"$DATA"; else printf '%s\n' '중단: Pod API 조회 실패' >&2; fi`

여러 Node에서 **동일한 image와 최초 오류 suffix**가 확인된 뒤 대표 Pod와 container, image에서 확인한 registry host를 선택한다.

`REP_POD='PASTE_REPRESENTATIVE_POD_HERE'; CONTAINER='PASTE_CONTAINER_HERE'; REGISTRY_HOST='PASTE_REGISTRY_HOST_HERE'`

**원자적 identity refresh 함수 등록 및 실행**

`refresh_registry(){ local pj nj vals; unset AUTO_READY TIME_READY HOST_READY CRI_READY EVIDENCE_READY CHANGE_READY NORMAL_READY POD_UID POD_RV OWNER_KIND OWNER_NAME OWNER_UID CONTAINER_ID NODE NODE_UID NODE_RV NODE_HOST HOST_ID RUNTIME_VERSION RUNTIME_PROVIDER IMAGE IMAGE_RE JOURNAL_RE POD_RE CONTAINER_RE ENDPOINT_ARG_RE OBSERVED_AT START_RFC3339 END_RFC3339 KUBELET_UNIT RUNTIME_UNIT CRI_ENDPOINT; AUTO_READY=false; TIME_READY=false; HOST_READY=false; CRI_READY=false; EVIDENCE_READY=false; CHANGE_READY=false; NORMAL_READY=false; [ "$INPUT_READY" = true ] || { printf '%s\n' '중단: INPUT_READY가 아니다.' >&2; return 1; }; pj="$(kubectl get pod "$REP_POD" -n "$NS" -o json)" || { printf '%s\n' '중단: Pod refresh 실패' >&2; return 1; }; vals="$(jq -er --arg c "$CONTAINER" '[.metadata.uid,.metadata.resourceVersion,([.metadata.ownerReferences[]? | select(.controller==true)][0].kind // "-"),([.metadata.ownerReferences[]? | select(.controller==true)][0].name // "-"),([.metadata.ownerReferences[]? | select(.controller==true)][0].uid // "-"),([.status.containerStatuses[]? | select(.name==$c)][0].containerID // "-"),.spec.nodeName,([.spec.containers[] | select(.name==$c)][0].image),.metadata.creationTimestamp] | if any(.[]; .==null or .=="") then error("identity incomplete") else @tsv end' <<<"$pj")" || { printf '%s\n' '중단: Pod·container identity 불완전' >&2; return 1; }; IFS=$'\t' read -r POD_UID POD_RV OWNER_KIND OWNER_NAME OWNER_UID CONTAINER_ID NODE IMAGE POD_CREATED <<<"$vals"; nj="$(kubectl get node "$NODE" -o json)" || { printf '%s\n' '중단: Node refresh 실패' >&2; return 1; }; vals="$(jq -er '[.metadata.uid,.metadata.resourceVersion,.status.nodeInfo.containerRuntimeVersion,.status.nodeInfo.operatingSystem,.status.nodeInfo.osImage] | if any(.[]; .==null or .=="") then error("node identity incomplete") else @tsv end' <<<"$nj")" || { printf '%s\n' '중단: Node identity 불완전' >&2; return 1; }; IFS=$'\t' read -r NODE_UID NODE_RV RUNTIME_VERSION NODE_OS NODE_OS_IMAGE <<<"$vals"; RUNTIME_PROVIDER="${RUNTIME_VERSION%%:*}"; IMAGE_RE="$(printf '%s' "$IMAGE" | sed 's/[][\\.^$*+?(){}|]/\\&/g')"; JOURNAL_RE="$POD_UID|$IMAGE_RE|pull|resolve|unauthorized|denied|401|403|429|x509|timeout|no such host"; POD_RE="$(printf '%s' "$REP_POD" | sed 's/[][\\.^$*+?(){}|]/\\&/g')"; CONTAINER_RE="$(printf '%s' "$CONTAINER" | sed 's/[][\\.^$*+?(){}|]/\\&/g')"; OBSERVED_AT="$(date -u '+%Y-%m-%dT%H:%M:%SZ')" || return 1; AUTO_READY=true; export POD_UID POD_RV OWNER_KIND OWNER_NAME OWNER_UID CONTAINER_ID NODE NODE_UID NODE_RV RUNTIME_VERSION RUNTIME_PROVIDER IMAGE IMAGE_RE JOURNAL_RE POD_RE CONTAINER_RE OBSERVED_AT; printf 'AUTO_READY=true\nPod=%s uid=%s rv=%s owner=%s/%s ownerUID=%s\nContainer=%s containerID=%s image=%s\nNode=%s uid=%s rv=%s runtime=%s provider=%s OS=%s image=%s\nRegistry service=%s storage=not-applicable observed=%s\nJOURNAL_RE=%s\n' "$REP_POD" "$POD_UID" "$POD_RV" "$OWNER_KIND" "$OWNER_NAME" "$OWNER_UID" "$CONTAINER" "$CONTAINER_ID" "$IMAGE" "$NODE" "$NODE_UID" "$NODE_RV" "$RUNTIME_VERSION" "$RUNTIME_PROVIDER" "$NODE_OS" "$NODE_OS_IMAGE" "$REGISTRY_HOST" "$OBSERVED_AT" "$JOURNAL_RE"; }; refresh_registry`

**모든 후속 명령이 호출하는 현재 identity guard**

`current_registry(){ local p n; [ "$AUTO_READY" = true ] || return 1; p="$(kubectl get pod "$REP_POD" -n "$NS" -o json)" || return 1; n="$(kubectl get node "$NODE" -o json)" || return 1; jq -e --arg uid "$POD_UID" --arg rv "$POD_RV" --arg node "$NODE" --arg c "$CONTAINER" --arg image "$IMAGE" '.metadata.uid==$uid and .metadata.resourceVersion==$rv and .spec.nodeName==$node and any(.spec.containers[]?; .name==$c and .image==$image)' <<<"$p" >/dev/null && jq -e --arg uid "$NODE_UID" --arg rv "$NODE_RV" '.metadata.uid==$uid and .metadata.resourceVersion==$rv' <<<"$n" >/dev/null; }`

owner·현재 containerID와 Node machine identity도 같은 lifecycle에 묶는다. `refresh_registry` 직후 아래 등록을 통과해야 하며, 이 명령은 이전 machine identity와 downstream 상태를 먼저 폐기한다.

`unset API_ID_READY NODE_MACHINE_ID; API_ID_READY=false; TIME_READY=false; HOST_READY=false; CRI_READY=false; EVIDENCE_READY=false; CHANGE_READY=false; NORMAL_READY=false; if [ "$AUTO_READY" != true ]; then printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; elif NODE_MACHINE_ID="$(kubectl get node "$NODE" -o jsonpath='{.status.nodeInfo.machineID}')" && [ -n "$NODE_MACHINE_ID" ]; then API_ID_READY=true; export NODE_MACHINE_ID; printf 'API_ID_READY=true node=%s nodeUID=%s machineID=%s\n' "$NODE" "$NODE_UID" "$NODE_MACHINE_ID"; else printf '%s\n' '중단: Node machineID 등록 실패' >&2; fi`

`current_registry_api(){ local p n; [ "$AUTO_READY" = true ] && [ "$API_ID_READY" = true ] || return 1; p="$(kubectl get pod "$REP_POD" -n "$NS" -o json)" || return 1; n="$(kubectl get node "$NODE" -o json)" || return 1; jq -e --arg uid "$POD_UID" --arg rv "$POD_RV" --arg ok "$OWNER_KIND" --arg on "$OWNER_NAME" --arg ou "$OWNER_UID" --arg node "$NODE" --arg c "$CONTAINER" --arg cid "$CONTAINER_ID" --arg image "$IMAGE" '.metadata.uid==$uid and .metadata.resourceVersion==$rv and .spec.nodeName==$node and any(.metadata.ownerReferences[]?; .controller==true and .kind==$ok and .name==$on and .uid==$ou) and any(.spec.containers[]?; .name==$c and .image==$image) and (([.status.containerStatuses[]? | select(.name==$c)][0].containerID // "-")==$cid)' <<<"$p" >/dev/null && jq -e --arg uid "$NODE_UID" --arg rv "$NODE_RV" --arg mid "$NODE_MACHINE_ID" '.metadata.uid==$uid and .metadata.resourceVersion==$rv and .status.nodeInfo.machineID==$mid' <<<"$n" >/dev/null; }; current_registry(){ current_registry_api; }`

`if [ "$API_ID_READY" = true ]; then API_ID_OBSERVED_AT="$OBSERVED_AT"; export API_ID_OBSERVED_AT; fi; current_registry_api_v2(){ [ "${API_ID_OBSERVED_AT:-}" = "$OBSERVED_AT" ] && current_registry_api; }; current_registry(){ current_registry_api_v2; }`

RV가 달라지거나 호출이 실패하면 stale `true`를 유지하지 말고 `refresh_registry`부터 다시 수행한다.

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | 서로 다른 Node의 현재 Pod UID에서 같은 image와 `unauthorized`, `denied`, `429`, `x509`, timeout 등 같은 최초 pull 오류가 관측됨 |
| 적용 | Pod→owner→container image→Node→active kubelet CRI endpoint→runtime provider→registry service 관계를 같은 시간 창으로 연결할 수 있음 |
| 제외 | 단일 Pod 설정은 [[07. Pod STATUS가 ImagePullBackOff·ErrImagePull인 경우]], pause image는 [[02. pause image를 가져오지 못해 Pod sandbox 생성이 실패하는 경우]], imagefs는 storage 런북으로 이동 |

검색 문자열: `Failed to pull image`, `ImagePullBackOff`, `unauthorized`, `denied`, `429`, `x509`, `no such host`, `context deadline exceeded`, `mirror`, `upstream`.

## 시간·Event 관계

운영자 입력 시각은 canonical UTC RFC3339 초 단위여야 하며 `START < END`, Pod 생성 시각과 Event·journal 시각의 순서를 대조한다.

`START_RFC3339='PASTE_START_RFC3339_HERE'; END_RFC3339='PASTE_END_RFC3339_HERE'; TIME_READY=false; RFC3339_RE='^[0-9]{4}-(0[1-9]|1[0-2])-([0-2][0-9]|3[01])T([01][0-9]|2[0-3]):[0-5][0-9]:[0-5][0-9]Z$'; if ! [[ "$START_RFC3339" =~ $RFC3339_RE ]] || ! [[ "$END_RFC3339" =~ $RFC3339_RE ]]; then printf '%s\n' '중단: canonical UTC RFC3339 형식이 아니다.' >&2; elif [ "$(date -u -d "$START_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" != "$START_RFC3339" ] || [ "$(date -u -d "$END_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" != "$END_RFC3339" ]; then printf '%s\n' '중단: date round-trip 실패' >&2; elif [ "$(date -u -d "$START_RFC3339" +%s)" -ge "$(date -u -d "$END_RFC3339" +%s)" ]; then printf '%s\n' '중단: START가 END보다 빠르지 않다.' >&2; elif ! current_registry; then AUTO_READY=false; printf '%s\n' '중단: 현재 identity가 달라졌다. refresh한다.' >&2; else TIME_READY=true; export START_RFC3339 END_RFC3339; printf 'TIME_READY=true start=%s end=%s podCreated=%s observed=%s\n' "$START_RFC3339" "$END_RFC3339" "$POD_CREATED" "$OBSERVED_AT"; fi`

**UID 제한 Event**

`if [ "$TIME_READY" != true ] || ! current_registry; then AUTO_READY=false; EVIDENCE_READY=false; printf '%s\n' '중단: 현재 TIME/AUTO identity가 아니다.' >&2; elif kubectl get events -n "$NS" --field-selector "involvedObject.kind=Pod,involvedObject.name=$REP_POD,involvedObject.uid=$POD_UID" --sort-by=.metadata.creationTimestamp -o custom-columns='EVENT-UID:.metadata.uid,OBJECT-UID:.involvedObject.uid,CREATED:.metadata.creationTimestamp,FIRST:.firstTimestamp,LAST:.lastTimestamp,EVENT-TIME:.eventTime,SERIES-LAST:.series.lastObservedTime,REASON:.reason,MESSAGE:.message'; then EVIDENCE_READY=true; else EVIDENCE_READY=false; printf '%s\n' '중단: Event API 실패. 빈 Event와 혼동하지 않는다.' >&2; fi`

Event가 비면 오류 부재가 아니다. Event TTL·권한·재생성 여부를 확인하고, API 실패면 `EVIDENCE_READY=false`다. Event·object 생성·journal의 timestamp를 UTC로 정렬해 최초 pull 실패가 Pod UID와 image에 속하는지 확인한다.

## Node·CRI·registry hop

승인 inventory에서 API의 `$NODE`에 대응하는 SSH host와 실제 unit, kubelet의 active endpoint를 고른다. host 문자열·unit·socket은 shell metacharacter를 허용하지 않는다.

`NODE_HOST='PASTE_APPROVED_NODE_HOST_HERE'; KUBELET_UNIT='PASTE_KUBELET_UNIT_HERE'; RUNTIME_UNIT='PASTE_RUNTIME_UNIT_HERE'; CRI_ENDPOINT='PASTE_CRI_ENDPOINT_HERE'; HOST_READY=false; CRI_READY=false; if [ "$TIME_READY" != true ] || ! current_registry; then AUTO_READY=false; printf '%s\n' '중단: 현재 identity가 아니다.' >&2; elif ! [[ "$NODE_HOST" =~ ^[A-Za-z0-9._-]+$ ]] || ! [[ "$KUBELET_UNIT" =~ ^[A-Za-z0-9_.@-]+\.service$ ]] || ! [[ "$RUNTIME_UNIT" =~ ^[A-Za-z0-9_.@-]+\.service$ ]] || ! [[ "$CRI_ENDPOINT" =~ ^unix:///[-A-Za-z0-9._/]+\.sock$ ]]; then printf '%s\n' '중단: host·unit·CRI endpoint 형식이 안전하지 않다.' >&2; else HOST_ID="$(ssh -- "$NODE_HOST" 'hostname --fqdn 2>/dev/null || hostname')" && ACTIVE="$(ssh -- "$NODE_HOST" 'systemctl is-active "$1" "$2"' sh "$KUBELET_UNIT" "$RUNTIME_UNIT")"; SSH_RC=$?; if [ "$SSH_RC" -ne 0 ] || [ -z "$HOST_ID" ] || [ "$ACTIVE" != $'active\nactive' ]; then printf '중단: SSH host 또는 unit 확인 실패 rc=%s host=%s active=%q\n' "$SSH_RC" "${HOST_ID:--}" "$ACTIVE" >&2; else ENDPOINT_ESC="$(printf '%s' "$CRI_ENDPOINT" | sed 's/[][\\.^$*+?(){}|]/\\&/g')"; ENDPOINT_ARG_RE="(^|[[:space:];])--container-runtime-endpoint=${ENDPOINT_ESC}([[:space:];]|$)"; HOST_READY=true; export NODE_HOST HOST_ID KUBELET_UNIT RUNTIME_UNIT CRI_ENDPOINT ENDPOINT_ARG_RE; printf 'HOST_READY=true apiNode=%s sshHost=%s linuxHost=%s kubelet=%s runtimeUnit=%s endpoint=%s\n' "$NODE" "$NODE_HOST" "$HOST_ID" "$KUBELET_UNIT" "$RUNTIME_UNIT" "$CRI_ENDPOINT"; fi; fi`

`HOST_READY=true`는 SSH host와 Linux service가 active라는 뜻일 뿐 kubelet이 선택한 CRI와 provider 일치는 아직 보장하지 않는다.

**active kubelet endpoint와 runtime provider exact relation**

`if [ "$HOST_READY" != true ] || ! current_registry; then AUTO_READY=false; CRI_READY=false; printf '%s\n' '중단: 현재 HOST/AUTO identity가 아니다.' >&2; else CRI_JSON="$(ssh -- "$NODE_HOST" 'set -eu; unit=$1; endpoint=$2; arg_re=$3; exec_start=$(systemctl show "$unit" -p ExecStart --value); count=$(printf "%s\n" "$exec_start" | grep -Eoc -- "$arg_re"); [ "$count" -eq 1 ]; sudo crictl --runtime-endpoint "$endpoint" version -o json' sh "$KUBELET_UNIT" "$CRI_ENDPOINT" "$ENDPOINT_ARG_RE")"; SSH_RC=$?; if [ "$SSH_RC" -ne 0 ]; then CRI_READY=false; printf '중단: active kubelet endpoint exact match 또는 CRI version 실패 rc=%s\n' "$SSH_RC" >&2; elif CRI_NAME="$(jq -er '.runtimeName' <<<"$CRI_JSON")" && CRI_VERSION="$(jq -er '.runtimeVersion' <<<"$CRI_JSON")" && [ "$CRI_NAME" = "$RUNTIME_PROVIDER" ]; then CRI_READY=true; export CRI_NAME CRI_VERSION; printf 'CRI_READY=true endpoint=%s apiProvider=%s criProvider=%s criVersion=%s\n' "$CRI_ENDPOINT" "$RUNTIME_PROVIDER" "$CRI_NAME" "$CRI_VERSION"; else CRI_READY=false; printf '중단: Node provider와 CRI provider 관계 불일치 api=%s cri=%s\n' "$RUNTIME_PROVIDER" "${CRI_NAME:--}" >&2; fi; fi`

`CRI_READY=true`만으로 선택 unit이 socket provider라는 뜻은 아니다. 다음 명령은 원격 `/etc/machine-id`, runtime unit MainPID와 Unix socket inode owner를 함께 검증한다. 원격 경계에는 positional argument만 전달한다.

`HOST_IDENTITY_READY=false; RUNTIME_SOCKET_READY=false; EVIDENCE_READY=false; CHANGE_READY=false; NORMAL_READY=false; if [ "$CRI_READY" != true ] || ! current_registry_api; then AUTO_READY=false; CRI_READY=false; printf '%s\n' '중단: 현재 CRI/API identity가 아니다.' >&2; else REL="$(ssh -- "$NODE_HOST" 'set -eu; expected_mid=$1; unit=$2; endpoint=$3; actual_mid=$(cat /etc/machine-id); [ "$actual_mid" = "$expected_mid" ]; socket=${endpoint#unix://}; [ -S "$socket" ]; pid=$(systemctl show "$unit" -p MainPID --value); [ "$pid" -gt 1 ]; inode=$(stat -Lc %i "$socket"); sudo sh -c '\''for fd in /proc/$1/fd/*; do [ "$(readlink "$fd" 2>/dev/null)" = "socket:[$2]" ] && exit 0; done; exit 1'\'' sh "$pid" "$inode"; printf "machineID=%s mainPID=%s socket=%s inode=%s\n" "$actual_mid" "$pid" "$socket" "$inode"' sh "$NODE_MACHINE_ID" "$RUNTIME_UNIT" "$CRI_ENDPOINT")"; SSH_RC=$?; if [ "$SSH_RC" -eq 0 ]; then HOST_IDENTITY_READY=true; RUNTIME_SOCKET_READY=true; export HOST_IDENTITY_READY RUNTIME_SOCKET_READY; printf 'HOST_IDENTITY_READY=true RUNTIME_SOCKET_READY=true %s\n' "$REL"; else CRI_READY=false; printf '중단: remote machineID 또는 runtime socket owner 관계 실패 rc=%s\n' "$SSH_RC" >&2; fi; fi`

`current_registry_host(){ local out cri name; [ "$CRI_READY" = true ] && [ "$HOST_IDENTITY_READY" = true ] && [ "$RUNTIME_SOCKET_READY" = true ] && current_registry_api_v2 || return 1; out="$(ssh -- "$NODE_HOST" 'set -eu; expected_mid=$1; kubelet=$2; runtime=$3; endpoint=$4; arg_re=$5; [ "$(cat /etc/machine-id)" = "$expected_mid" ]; [ "$(systemctl is-active "$kubelet")" = active ]; [ "$(systemctl is-active "$runtime")" = active ]; exec_start=$(systemctl show "$kubelet" -p ExecStart --value); [ "$(printf "%s\n" "$exec_start" | grep -Eoc -- "$arg_re")" -eq 1 ]; socket=${endpoint#unix://}; [ -S "$socket" ]; pid=$(systemctl show "$runtime" -p MainPID --value); [ "$pid" -gt 1 ]; inode=$(stat -Lc %i "$socket"); sudo sh -c '\''for fd in /proc/$1/fd/*; do [ "$(readlink "$fd" 2>/dev/null)" = "socket:[$2]" ] && exit 0; done; exit 1'\'' sh "$pid" "$inode"; sudo crictl --runtime-endpoint "$endpoint" version -o json' sh "$NODE_MACHINE_ID" "$KUBELET_UNIT" "$RUNTIME_UNIT" "$CRI_ENDPOINT" "$ENDPOINT_ARG_RE")" || return 1; name="$(jq -er '.runtimeName' <<<"$out")" || return 1; [ "$name" = "$RUNTIME_PROVIDER" ]; }; current_registry(){ current_registry_host; }`

이후 journal·registry·CRI 증거 명령은 `CRI_READY=true`, `HOST_IDENTITY_READY=true`, `RUNTIME_SOCKET_READY=true`가 모두 현재인 경우에만 실행한다. host 재부팅, runtime 재시작, socket inode 변경 또는 Pod·Node RV 변경 시 세 상태와 모든 downstream `READY`를 폐기하고 이 절을 다시 등록한다.

**kubelet와 runtime journal, pipeline status 분리**

`if [ "$CRI_READY" != true ] || [ "$TIME_READY" != true ] || ! current_registry; then AUTO_READY=false; EVIDENCE_READY=false; printf '%s\n' '중단: 현재 CRI/TIME/AUTO identity가 아니다.' >&2; else ssh -- "$NODE_HOST" 'sudo journalctl -u "$1" --since "$2" --until "$3" --no-pager' sh "$KUBELET_UNIT" "$START_RFC3339" "$END_RFC3339" | grep -E -i -C 3 -- "$JOURNAL_RE"; PS=("${PIPESTATUS[@]}"); printf 'pipeline ssh=%s grep=%s\n' "${PS[0]}" "${PS[1]}"; if [ "${PS[0]}" -ne 0 ]; then EVIDENCE_READY=false; printf '%s\n' '중단: 원격 journal 호출 실패' >&2; elif [ "${PS[1]}" -eq 0 ]; then EVIDENCE_READY=true; elif [ "${PS[1]}" -eq 1 ]; then EVIDENCE_READY=false; printf '%s\n' '필터 결과 없음: 오류 부재가 아니며 시간·unit·보존 범위를 재확인한다.' >&2; else EVIDENCE_READY=false; printf '%s\n' '중단: grep 실패' >&2; fi; fi`

`if [ "$CRI_READY" != true ] || [ "$TIME_READY" != true ] || ! current_registry; then AUTO_READY=false; EVIDENCE_READY=false; printf '%s\n' '중단: 현재 CRI/TIME/AUTO identity가 아니다.' >&2; else ssh -- "$NODE_HOST" 'sudo journalctl -u "$1" --since "$2" --until "$3" --no-pager' sh "$RUNTIME_UNIT" "$START_RFC3339" "$END_RFC3339" | grep -E -i -C 3 -- "$JOURNAL_RE"; PS=("${PIPESTATUS[@]}"); printf 'pipeline ssh=%s grep=%s\n' "${PS[0]}" "${PS[1]}"; if [ "${PS[0]}" -ne 0 ]; then EVIDENCE_READY=false; elif [ "${PS[1]}" -eq 0 ]; then EVIDENCE_READY=true; elif [ "${PS[1]}" -eq 1 ]; then EVIDENCE_READY=false; printf '%s\n' '필터 결과 없음: 수집 실패·보존 범위·다른 unit을 구분한다.' >&2; else EVIDENCE_READY=false; fi; fi`

**Node에서 registry 공개 endpoint 확인**

`if [ "$CRI_READY" != true ] || ! current_registry; then AUTO_READY=false; printf '%s\n' '중단: 현재 CRI/AUTO identity가 아니다.' >&2; elif ! [[ "$REGISTRY_HOST" =~ ^[A-Za-z0-9.-]+(:[0-9]{1,5})?$ ]]; then printf '%s\n' '중단: registry host 형식이 안전하지 않다.' >&2; else ssh -- "$NODE_HOST" 'curl -sS -o /dev/null -w "http_code=%{http_code}\n" --max-time 10 "https://$1/v2/"' sh "$REGISTRY_HOST"; SSH_RC=$?; printf 'registry_probe_ssh=%s node=%s registry=%s\n' "$SSH_RC" "$NODE" "$REGISTRY_HOST"; [ "$SSH_RC" -eq 0 ] || printf '%s\n' 'probe 실패는 metric 부재나 repository 권한 거부와 동일하지 않다.' >&2; fi`

`200`은 공개 endpoint 응답, `401`은 인증 필요, `403`은 정책 거부, `429`는 rate limit 후보다. 어느 것도 repository manifest나 credential 유효성을 단독 증명하지 않는다. Secret data, token, `WWW-Authenticate` 원문, 인증서 개인키, 내부 주소와 전체 journal은 출력·저장하지 않는다.

## 관측별 진단 경로

| 지금 보이는 것 | 먼저 볼 것 | 다음 owner |
|---|---|---|
| 여러 Node의 같은 image에서 `401/403` | Pod가 참조한 Secret **이름·type·ServiceAccount 관계**와 registry audit의 redacted subject/repository | workload·registry IAM owner |
| `429` | 응답 시각, `Retry-After`의 비민감 값, Node·namespace 범위 | registry quota·mirror owner |
| `manifest unknown` | exact tag/digest와 mirror/upstream 동기화 | image release·registry owner |
| 한 Node만 DNS·x509·timeout | Node host·CA·proxy·시간과 같은 endpoint의 비교 Node | node owner |
| 여러 Node의 같은 오류 | kubelet→exact CRI→runtime→registry 관계와 provider audit | platform·registry owner |

## Prometheus 보조 관측

현재 identity를 포함한 완성 query만 생성한다.

`if [ "$AUTO_READY" != true ] || ! current_registry; then AUTO_READY=false; printf '%s\n' '중단: 현재 identity가 아니다.' >&2; else printf 'sum by(namespace,pod,uid,container,node,reason)(kube_pod_container_status_waiting_reason{namespace="%s",pod=~"^%s$",container=~"^%s$",reason=~"ImagePullBackOff|ErrImagePull"} * on(namespace,pod,uid) group_left(node) kube_pod_info{namespace="%s",pod=~"^%s$",uid="%s"})\n' "$NS" "$POD_RE" "$CONTAINER_RE" "$NS" "$POD_RE" "$POD_UID"; fi`

query 결과가 비면 `정상/0`이 아니다. 먼저 `kube_pod_info{namespace=...,pod=...,uid=...}`의 현재 UID series 존재, kube-state-metrics target `up`, 조회 cluster·time range, label schema를 순서대로 확인한다. metric·label 부재면 Event와 exact CRI journal을 1차 근거로 사용한다. query가 있어도 auth·manifest·TLS 원인은 확정하지 않는다.

## 변경과 정상화

위 절은 전부 읽기 전용이다. credential, runtime config, mirror, quota, image reference 변경과 runtime restart는 이 문서에서 실행하지 않는다. 외부 provider별 명령은 발명하지 않는다.

변경 창에서만 별도 `CHANGE_READY=true`를 기록하며 다음이 모두 필요하다.

1. fresh `refresh_registry` 뒤 같은 Pod·owner·container image·Node·active CRI·runtime provider·registry service 관계가 유지된다.
2. Event, 두 journal pipeline status, registry 또는 audit의 redacted 직접 증거가 같은 UTC 창에 있다.
3. workload, node/runtime, registry owner의 승인 ID·실행 주체·변경 창·quorum/HA 최소 가용 조건이 있다.
4. 재시도·credential rotation·quota/mirror 변경의 idempotence와 중복 pull 영향이 확인됐다.
5. 승인된 이전 설정 digest와 실제 rollback 절차가 있으며 rollback도 fresh identity와 별도 승인으로 검증한다.
6. Pod·Node가 교체되면 모든 `READY`를 폐기하고 새 UID/RV, owner, containerID, node, endpoint, provider, service 관계를 재등록한다.

정상화는 `registry provider 상태·audit -> Node DNS/TLS -> exact CRI pull -> kubelet Warning 중단 -> 새 Pod UID와 owner 관계 -> 모든 replica Ready -> 실제 서비스 요청` 순으로 확인한다. 비교 Node와 승인된 관찰 창에서 같은 오류가 재발하지 않고 실제 요청이 성공해야 `NORMAL_READY=true`다. 한 번의 `/v2/` 응답, pull 성공, Pod `Running` 또는 metric 소멸만으로 정상화하지 않는다.

보존할 것은 UTC 시각, Pod·owner·Node·runtime·registry의 비민감 identity, image tag/digest, pipeline status, redacted 오류, 승인·rollback·실제 기능 결과다. Secret 원문, token, credential, 개인키, 개인정보, 내부 주소와 전체 로그는 보존하지 않는다.
