# kubectl top 또는 리소스 Metrics API 결과를 조회할 수 없는 경우

## 입력값과 빠른 수집

명령은 승인된 작업 PC 또는 bastion의 같은 Bash에서 실행한다. 연결 경로는 `kubectl -> API server aggregation layer -> APIService/v1beta1.metrics.k8s.io -> Service port -> EndpointSlice port와 adapter Pod -> 리소스 메트릭 응답`이다. APIService `Available=True`, Service 존재, endpoint 준비와 Metrics API data 반환은 서로 다른 gate다.

| 구분 | 값 | 출처와 gate |
|---|---|---|
| 최초 입력 | `NS`, `POD` | 실제 `kubectl top pod` 실패를 재현한 namespace와 exact Pod 이름 |
| API 확인 자동값 | 대상 Pod UID/RV, APIService UID/RV, Service UID/RV·port, EndpointSlice·adapter 후보 | 모든 API 호출과 관계 검증 성공 뒤 등록 |
| 계산 후보값 | `POD_RE` | Pod 이름을 regex escape한 값이며 완성 PromQL에만 사용 |
| 운영자 선택값 | `ADAPTER_POD`, `ADAPTER_CONTAINER`, UTC 증거 창 | endpoint 후보 출력과 container 상태를 보고 선택 |

**Bash·도구 확인**

`TOOLS_READY=false; MISSING=''; if [ -z "${BASH_VERSION:-}" ]; then printf '%s\n' '중단: Bash에서 실행한다.' >&2; else for T in kubectl jq date sed grep mktemp; do command -v "$T" >/dev/null 2>&1 || MISSING="$MISSING $T"; done; if [ -z "$MISSING" ]; then TOOLS_READY=true; printf 'TOOLS_READY=true bash=%s\n' "$BASH_VERSION"; else printf '중단: 없는 도구=%s\n' "$MISSING" >&2; fi; fi`

### API 자동 수집과 Service·Endpoint 관계

재실행할 때 자동값, 선택값, 시간·증거·query·정상화 gate를 먼저 모두 폐기한다. APIService의 Service 참조가 없거나 Service port가 유일하게 결정되지 않으면 local adapter나 다른 배포 형태를 추측하지 않는다.

### 1. APIService와 endpoint 관계

`if [ "$AUTO_READY" != true ] || ! metrics_current; then printf '%s\n' '중단: 최신 AUTO_READY가 필요하다.' >&2; else kubectl get apiservice v1beta1.metrics.k8s.io -o json | jq -r '"name=\(.metadata.name) uid=\(.metadata.uid) rv=\(.metadata.resourceVersion)",(.status.conditions[]? | "type=\(.type) status=\(.status) reason=\(.reason // "-") lastTransition=\(.lastTransitionTime // "-") message=\(.message // "-")")'; fi`

`FailedDiscoveryCheck`는 aggregation layer가 adapter API discovery 응답을 유효하게 받지 못한 범위다. `MissingEndpoints`는 Service에 사용 가능한 endpoint가 없다는 범위다. 둘 다 TLS, listener, adapter process 또는 메트릭 내용의 단일 원인을 확정하지 않는다.

### 2. raw API와 RBAC

`RBAC_READY=false; if [ "$AUTO_READY" != true ] || ! metrics_current; then printf '%s\n' '중단: 최신 identity 필요' >&2; elif A="$(kubectl auth can-i get pods.metrics.k8s.io -n "$NS")" && B="$(kubectl auth can-i get nodes.metrics.k8s.io)"; then RBAC_READY=true; printf 'RBAC_READY=true subject=current-kubeconfig verb=get pod_metrics=%s node_metrics=%s namespace=%s\n' "$A" "$B" "$NS"; else printf '%s\n' '중단: auth can-i 자체 실패' >&2; fi`

`yes`는 현재 kubeconfig subject·verb·resource·namespace에만 해당하며 실제 API 성공을 보장하지 않는다. 권한을 확대하지 않는다. audit이 필요하면 단일 auditID의 `timestamp`, `user.username`, `verb=get`, `objectRef.apiGroup=metrics.k8s.io`, `resource=pods|nodes`, namespace/name, requestURI와 status code만 redacted evidence로 요청한다.

`RAW_READY=false; if [ "$AUTO_READY" != true ] || ! metrics_current; then printf '%s\n' '중단: 최신 API 경로 identity 필요' >&2; elif TMP="$(mktemp)"; then if kubectl get --raw "/apis/metrics.k8s.io/v1beta1/namespaces/$NS/pods/$POD" >"$TMP"; then if jq -e --arg n "$POD" '.kind=="PodMetrics" and .metadata.name==$n and (.timestamp|type=="string") and (.containers|type=="array")' "$TMP" >/dev/null; then RAW_READY=true; jq -r '"RAW_READY=true name=\(.metadata.name) timestamp=\(.timestamp) window=\(.window) containers=\([.containers[].name]|join(","))"' "$TMP"; else printf '%s\n' '중단: HTTP/API는 반환됐지만 기대 PodMetrics schema가 아님' >&2; fi; else printf 'raw API producer_rc=%s\n' "$?" >&2; fi; rm -f "$TMP"; else printf '%s\n' '중단: 임시 파일 생성 실패' >&2; fi`

`if [ "$RAW_READY" = true ] && metrics_current >/dev/null; then TMP="$(mktemp)" || RAW_READY=false; if [ "$RAW_READY" = true ] && kubectl get --raw "/apis/metrics.k8s.io/v1beta1/namespaces/$NS/pods/$POD" >"$TMP"; then METRIC_TIMESTAMP="$(jq -r '.timestamp // empty' "$TMP")"; POD_CREATED="$(kubectl get pod "$POD" -n "$NS" -o jsonpath='{.metadata.creationTimestamp}' 2>/dev/null)"; if [[ "$METRIC_TIMESTAMP" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] && METRIC_EPOCH="$(date -u -d "$METRIC_TIMESTAMP" +%s 2>/dev/null)" && CREATED_EPOCH="$(date -u -d "$POD_CREATED" +%s 2>/dev/null)" && [ "$(date -u -d "$METRIC_TIMESTAMP" '+%Y-%m-%dT%H:%M:%SZ')" = "$METRIC_TIMESTAMP" ] && [ "$METRIC_EPOCH" -ge "$CREATED_EPOCH" ]; then printf 'RAW_TIME_READY=true timestamp=%s pod_created=%s\n' "$METRIC_TIMESTAMP" "$POD_CREATED"; else RAW_READY=false; unset TOP_READY QUERY_READY NORMAL_READY; printf '%s\n' '중단: metric timestamp canonical/lifecycle 관계 실패' >&2; fi; else RAW_READY=false; unset TOP_READY QUERY_READY NORMAL_READY; printf '%s\n' '중단: timestamp 재조회 실패' >&2; fi; rm -f "${TMP:-}"; fi`

raw API가 반환한 `metadata.name`은 요청한 현재 Pod 이름과 같아야 한다. Resource Metrics API에는 Pod UID가 없으므로 같은 이름의 재생성 Pod를 구분하지 못한다. 현재 Pod UID·생성 시각과 metric `timestamp/window`의 시간 관계를 함께 기록한다.

### 3. adapter Pod와 bounded log

**strict UTC 증거 창 입력**

`START_RFC3339='PASTE_EVIDENCE_START_UTC_HERE'; END_RFC3339='PASTE_EVIDENCE_END_UTC_HERE'`

`unset TIME_READY LOG_READY START_EPOCH END_EPOCH; TIME_READY=false; if [[ "$START_RFC3339" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ && "$END_RFC3339" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] && START_EPOCH="$(date -u -d "$START_RFC3339" +%s 2>/dev/null)" && END_EPOCH="$(date -u -d "$END_RFC3339" +%s 2>/dev/null)" && [ "$(date -u -d "$START_RFC3339" '+%Y-%m-%dT%H:%M:%SZ')" = "$START_RFC3339" ] && [ "$(date -u -d "$END_RFC3339" '+%Y-%m-%dT%H:%M:%SZ')" = "$END_RFC3339" ] && [ "$START_EPOCH" -lt "$END_EPOCH" ]; then TIME_READY=true; printf 'TIME_READY=true start=%s end=%s\n' "$START_RFC3339" "$END_RFC3339"; else printf '%s\n' '중단: canonical UTC RFC3339 round-trip/order 실패' >&2; fi`

`LOG_READY=false; TMP=''; if [ "$ADAPTER_READY" != true ] || [ "$TIME_READY" != true ] || ! metrics_current; then printf '%s\n' '중단: 최신 adapter identity와 시간 창 필요' >&2; elif TMP="$(mktemp)"; then if kubectl logs "$ADAPTER_POD" -n "$SERVICE_NS" -c "$ADAPTER_CONTAINER" --timestamps --since-time="$START_RFC3339" --tail=400 >"$TMP"; then PRODUCER_RC=0; else PRODUCER_RC=$?; fi; if [ "$PRODUCER_RC" -ne 0 ]; then printf 'producer_rc=%s filter_rc=not-run\n' "$PRODUCER_RC" >&2; elif grep -E -i -C 3 'metrics|scrape|kubelet|timeout|refused|x509|unauthorized|forbidden|failed|error' "$TMP"; then LOG_READY=true; printf 'producer_rc=0 filter_rc=0 match=true\n'; else FILTER_RC=$?; if [ "$FILTER_RC" -eq 1 ]; then LOG_READY=true; printf 'producer_rc=0 filter_rc=1 match=false (오류 없음 아님)\n'; else printf 'producer_rc=0 filter_rc=%s filter_error=true\n' "$FILTER_RC" >&2; fi; fi; rm -f "$TMP"; else printf '%s\n' '중단: 임시 파일 생성 실패' >&2; fi`

adapter log의 kubelet timeout·TLS·authorization 오류는 adapter→kubelet 수집 경계 후보일 뿐 node resource 정상/비정상을 확정하지 않는다. filter no-match는 로그 producer 성공만 뜻한다.

### 4. 정상화와 비보장

`TOP_READY=false; if [ "$RAW_READY" != true ] || ! metrics_current; then printf '%s\n' '중단: 같은 lifecycle의 최신 RAW_READY 필요' >&2; elif kubectl top pod "$POD" -n "$NS" --containers; then TOP_READY=true; printf 'TOP_READY=true pod_uid=%s current_rv=%s\n' "$TARGET_UID" "$CURRENT_TARGET_RV"; else printf '%s\n' 'kubectl top 실패: raw API 성공과 client 출력 경계를 분리한다.' >&2; fi`

정상화는 `adapter가 현재 node·Pod를 수집 -> EndpointSlice와 Service port 관계 유지 -> APIService Available=True -> 현재 PodMetrics timestamp/window 갱신 -> kubectl top 출력 -> 실제 workload·node 관측 기능` 순서로 확인한다. 한 번의 `Available=True`, raw API HTTP 성공, `kubectl top` 한 행은 freshness와 모든 node 수집을 보장하지 않는다. 최소 두 수집 주기 동안 timestamp가 전진하고 같은 오류·누락이 재발하지 않아야 한다.

이 런북은 상태 변경 명령을 제공하지 않는다. APIService·Service selector/port, adapter flags·TLS, RBAC, rollout을 임의 변경하지 않는다. 확인된 owner UID·revision, 승인 ID·변경 창·가용성·rollback 선언 원본이 있는 별도 변경 절차에서만 수정하고 변경 뒤 모든 identity를 첫 단계부터 재등록한다.

## Prometheus 빠른 관측

KSM에 현재 Pod UID label이 실제로 존재할 때만 완성 query를 생성한다. Resource Metrics API의 값과 Prometheus 값은 수집 경로·시각·window가 다를 수 있다.

`QUERY_READY=false; if [ "$AUTO_READY" != true ] || ! metrics_current; then printf '%s\n' '중단: 최신 identity 필요' >&2; elif [ -n "$POD_RE" ]; then QUERY_READY=true; printf 'kube_pod_info{namespace="%s",pod=~"^%s$",uid="%s"}\n' "$NS" "$POD_RE" "$TARGET_UID"; printf 'time()-timestamp(kube_pod_info{namespace="%s",pod=~"^%s$",uid="%s"})\n' "$NS" "$POD_RE" "$TARGET_UID"; fi`

빈 결과는 Pod 부재나 정상 상태가 아니다. KSM metric/UID label 미지원, scrape 실패, 범위·retention·query 오류를 APIService 경로와 분리한다.

## 증거와 근거

대상 Pod UID/RV·생성 시각, APIService UID/RV·condition, Service UID/RV·port/targetPort, EndpointSlice UID·port·targetRef UID, adapter Pod UID/RV·owner UID·container kind/name/current containerID·node, UTC 창, producer/filter rc, exact RBAC, PodMetrics timestamp/window와 재발 관찰을 보존한다. metric 원문 전체, token·인증서 개인키·audit actor 상세는 보존하지 않는다.
