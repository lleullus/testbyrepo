# Prometheus 수집 대상의 메트릭이 누락되는 경우

## 입력값과 빠른 수집

명령은 승인된 작업 PC 또는 bastion의 같은 Bash에서 실행한다. 연결 경로는 `Kubernetes 대상 identity -> 실제 discovery 선언 -> Service port·EndpointSlice 또는 Pod port -> Prometheus target -> scrape HTTP -> exposition -> metric relabel -> TSDB series -> query`다. target 존재, `health=up`, exposition의 metric 존재, TSDB sample 저장과 query 결과는 서로 다른 gate다.

| 구분 | 값 | 출처와 gate |
|---|---|---|
| 최초 입력 | `NS`, `TARGET_KIND`, `TARGET_NAME` | 승인된 `service` 또는 `pod` exact 대상 |
| API 확인 자동값 | target UID/RV, selector·port, backend Pod UID/RV·owner·containerID | 현재 API와 EndpointSlice relation 검증 뒤 등록 |
| 계산 후보값 | escaped PromQL string | metric·job·instance 선택과 문법 검증 뒤 생성 |
| 운영자 선택값 | backend Pod/container/remote port, Prometheus URL, discovery UID label, metric·job·instance, UTC query 창 | 관계 출력과 승인된 Prometheus target UI에서 선택 |

Secret·token·client key, 전체 Prometheus config, raw scrape URL과 metric 원문 전체를 출력·저장하지 않는다. 인증은 승인된 기존 curl 환경을 사용하며 URL에 credential을 넣거나 TLS 검증을 끄지 않는다.

**Bash·도구 확인**

`TOOLS_READY=false; MISSING=''; if [ -z "${BASH_VERSION:-}" ]; then printf '%s\n' '중단: Bash에서 실행한다.' >&2; else for T in kubectl jq curl date sed grep mktemp; do command -v "$T" >/dev/null 2>&1 || MISSING="$MISSING $T"; done; if [ -z "$MISSING" ]; then TOOLS_READY=true; printf 'TOOLS_READY=true bash=%s\n' "$BASH_VERSION"; else printf '중단: 없는 도구=%s\n' "$MISSING" >&2; fi; fi`

### API 자동값과 discovery 후보 출력

Service와 Pod schema를 섞지 않는다. Service면 Service port와 EndpointSlice targetRef를, Pod면 container-port 대응을 별도로 출력한다.

`unset AUTO_READY BACKEND_READY PROM_INPUT_READY TARGET_API_READY TIME_READY QUERY_READY SERIES_READY LOG_READY NORMAL_READY TARGET_JSON TARGET_UID TARGET_RV TARGET_RE SERVICE_PORT_NAME SERVICE_PORT TARGET_PORT ENDPOINT_PORT BACKEND_POD BACKEND_UID BACKEND_RV BACKEND_OWNER_KIND BACKEND_OWNER_NAME BACKEND_OWNER_UID APP_CONTAINER APP_CONTAINER_ID BACKEND_NODE REMOTE_PORT PROMQL; AUTO_READY=false; if [ "$INPUT_READY" != true ]; then printf '%s\n' '중단: INPUT_READY가 아니다.' >&2; elif J="$(kubectl get "$TARGET_KIND" "$TARGET_NAME" -n "$NS" -o json)" && U="$(jq -r '.metadata.uid // empty' <<<"$J")" && R="$(jq -r '.metadata.resourceVersion // empty' <<<"$J")" && [ -n "$U" ] && [ -n "$R" ]; then TARGET_JSON="$J"; TARGET_UID="$U"; TARGET_RV="$R"; TARGET_RE="$(printf '%s' "$TARGET_NAME" | sed 's/[][\\.^$*+?(){}|]/\\&/g')"; if [ "$TARGET_KIND" = service ]; then printf '=== Service ===\nname=%s uid=%s rv=%s\nselector=%s\n' "$TARGET_NAME" "$TARGET_UID" "$TARGET_RV" "$(jq -c '.spec.selector // {}' <<<"$J")"; jq -r '.spec.ports[]? | "port name=\(.name // "-") service=\(.port) targetPort=\(.targetPort) protocol=\(.protocol // "TCP")"' <<<"$J"; if E="$(kubectl get endpointslice -n "$NS" -l "kubernetes.io/service-name=$TARGET_NAME" -o json)"; then jq -r '.items[] | "=== EndpointSlice: \(.metadata.name) ===\nuid=\(.metadata.uid) rv=\(.metadata.resourceVersion)",(.ports[]? | "port name=\(.name // "-") value=\(.port) protocol=\(.protocol // "TCP")"),(.endpoints[]? | "endpoint ready=\(.conditions.ready // "unknown") serving=\(.conditions.serving // "unknown") target=\(.targetRef.kind // "-")/\(.targetRef.namespace // "-")/\(.targetRef.name // "-") uid=\(.targetRef.uid // "-") node=\(.nodeName // "-")")' <<<"$E"; AUTO_READY=true; else printf '%s\n' '중단: EndpointSlice 조회 실패' >&2; fi; else printf '=== Pod ===\nname=%s uid=%s rv=%s node=%s phase=%s\n' "$TARGET_NAME" "$TARGET_UID" "$TARGET_RV" "$(jq -r '.spec.nodeName // "-"' <<<"$J")" "$(jq -r '.status.phase // "-"' <<<"$J")"; jq -r '.spec.initContainers[]? | "init container=\(.name) ports="+([.ports[]? | "\(.name // "-"):\(.containerPort)"]|join(",")),.spec.containers[]? | "regular container=\(.name) ports="+([.ports[]? | "\(.name // "-"):\(.containerPort)"]|join(","))' <<<"$J"; AUTO_READY=true; fi; if [ "$AUTO_READY" = true ]; then export TARGET_UID TARGET_RV TARGET_RE; printf 'AUTO_READY=true target_uid=%s target_rv=%s observed=%s\n' "$TARGET_UID" "$TARGET_RV" "$(date -u '+%Y-%m-%dT%H:%M:%SZ')"; fi; else printf '%s\n' '중단: target 자동 수집 실패' >&2; fi`

Service selector가 비었거나 endpoint가 없으면 target 누락을 Prometheus 단독 문제로 확정하지 않는다. EndpointSlice의 `ready=true`는 실제 listener와 HTTP exposition을 보장하지 않는다.

**현재 target/backend identity helper**

`target_current(){ local tj bj eu; CURRENT_TARGET_UID=''; CURRENT_TARGET_RV=''; CURRENT_BACKEND_UID=''; CURRENT_BACKEND_RV=''; CURRENT_BACKEND_OWNER_UID=''; CURRENT_CONTAINER_ID=''; tj="$(kubectl get "$TARGET_KIND" "$TARGET_NAME" -n "$NS" -o json 2>/dev/null)" || { unset AUTO_READY BACKEND_READY PROM_INPUT_READY TARGET_API_READY TIME_READY QUERY_READY SERIES_READY LOG_READY NORMAL_READY; printf '%s\n' '중단: target 재조회 실패, downstream 무효' >&2; return 1; }; CURRENT_TARGET_UID="$(jq -r '.metadata.uid // empty' <<<"$tj")"; CURRENT_TARGET_RV="$(jq -r '.metadata.resourceVersion // empty' <<<"$tj")"; if [ "$AUTO_READY" != true ] || [ "$CURRENT_TARGET_UID" != "$TARGET_UID" ] || [ -z "$CURRENT_TARGET_RV" ]; then unset AUTO_READY BACKEND_READY PROM_INPUT_READY TARGET_API_READY TIME_READY QUERY_READY SERIES_READY LOG_READY NORMAL_READY; printf '%s\n' '중단: target lifecycle 변경, 전체 재수집' >&2; return 1; fi; if [ "$BACKEND_READY" = true ]; then bj="$(kubectl get pod "$BACKEND_POD" -n "$NS" -o json 2>/dev/null)" || { unset BACKEND_READY PROM_INPUT_READY TARGET_API_READY TIME_READY QUERY_READY SERIES_READY LOG_READY NORMAL_READY; printf '%s\n' '중단: backend Pod 재조회 실패' >&2; return 1; }; CURRENT_BACKEND_UID="$(jq -r '.metadata.uid // empty' <<<"$bj")"; CURRENT_BACKEND_RV="$(jq -r '.metadata.resourceVersion // empty' <<<"$bj")"; CURRENT_BACKEND_OWNER_UID="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)] | if length==1 then .[0].uid else empty end' <<<"$bj")"; CURRENT_CONTAINER_ID="$(jq -r --arg c "$APP_CONTAINER" '[.status.containerStatuses[]? | select(.name==$c)] | if length==1 then .[0].containerID // empty else empty end' <<<"$bj")"; if [ "$TARGET_KIND" = service ]; then eu="$(kubectl get endpointslice -n "$NS" -l "kubernetes.io/service-name=$TARGET_NAME" -o json 2>/dev/null | jq -r --arg uid "$BACKEND_UID" --arg pn "$SERVICE_PORT_NAME" --argjson ep "$ENDPOINT_PORT" '[.items[] | .ports[]? as $p | select($p.name==$pn and $p.port==$ep) | .endpoints[]? | select(.targetRef.kind=="Pod" and .targetRef.uid==$uid)] | length')"; else eu=1; fi; if [ "$CURRENT_BACKEND_UID" != "$BACKEND_UID" ] || [ "$CURRENT_BACKEND_OWNER_UID" != "$BACKEND_OWNER_UID" ] || [ "$CURRENT_CONTAINER_ID" != "$APP_CONTAINER_ID" ] || [ -z "$CURRENT_BACKEND_RV" ] || [ "$eu" -lt 1 ]; then unset BACKEND_READY PROM_INPUT_READY TARGET_API_READY TIME_READY QUERY_READY SERIES_READY LOG_READY NORMAL_READY; printf '%s\n' '중단: backend owner/container/endpoint lifecycle 변경, 다시 선택' >&2; return 1; fi; fi; printf 'CURRENT=true target_uid=%s target_rv=%s backend_uid=%s backend_rv=%s container_id=%s\n' "$CURRENT_TARGET_UID" "$CURRENT_TARGET_RV" "${CURRENT_BACKEND_UID:--}" "${CURRENT_BACKEND_RV:--}" "${CURRENT_CONTAINER_ID:--}"; }`

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | 승인된 scrape 대상이 targets API에서 사라졌거나 down이고, 또는 target은 up인데 기대 metric series가 없음 |
| 적용 | Kubernetes current UID에서 Prometheus discovered target·scrape·series/query까지 연결 가능 |
| 제외 | `kubectl top`·`metrics.k8s.io`는 [[01. kubectl top 또는 리소스 Metrics API 결과를 조회할 수 없는 경우]], PVC 사용률 편차는 [[03. Prometheus StatefulSet replica별 PVC 사용률이 다른 경우]] |

검색 문자열: `health=down`, `lastError`, `context deadline exceeded`, `connection refused`, `no such host`, `x509`, `server returned HTTP status 404`, `relabel`, `sample out of order`, `WAL`, `series`.

## 관측별 진단 경로

| 지금 보이는 것 | 먼저 볼 것 | 다음 경계 | 상세 절 |
|---|---|---|---|
| targets API에 current Pod UID가 없음 | discovery UID label·selector | ServiceMonitor/PodMonitor/static discovery owner | [[#1. backend와 target identity]] |
| target은 있으나 `health=down` | lastError 유형·lastScrape | listener·path·scheme·TLS·network | [[#2. Prometheus target API]] |
| target `up`, 기대 metric 없음 | exposition·scraped/post-relabel sample | instrumentation·metric relabel | [[#3. app log와 scrape 경계]] |
| target·exposition 정상, query 비어 있음 | exact job/instance·UTC range | TSDB·retention·query | [[#4. 완성 query와 저장 경계]] |

### 1. backend와 target identity

관계 출력에서 현재 endpoint Pod와 regular app container, 실제 remote listener 후보를 선택한다. Service 대상이면 이름 있는 Service port와 같은 이름·port의 EndpointSlice를 검증한다. Pod 대상이면 `SERVICE_PORT_NAME=-`를 사용한다.

`BACKEND_POD='PASTE_BACKEND_POD_HERE'; APP_CONTAINER='PASTE_APP_CONTAINER_HERE'; SERVICE_PORT_NAME='PASTE_SERVICE_PORT_NAME_OR_DASH_HERE'; REMOTE_PORT='PASTE_REMOTE_PORT_HERE'`

`unset BACKEND_READY PROM_INPUT_READY TARGET_API_READY TIME_READY QUERY_READY SERIES_READY LOG_READY NORMAL_READY SERVICE_PORT TARGET_PORT ENDPOINT_PORT BACKEND_UID BACKEND_RV BACKEND_OWNER_KIND BACKEND_OWNER_NAME BACKEND_OWNER_UID APP_CONTAINER_ID BACKEND_NODE; BACKEND_READY=false; if [ "$AUTO_READY" != true ] || ! [[ "$REMOTE_PORT" =~ ^[0-9]+$ ]] || (( REMOTE_PORT < 1 || REMOTE_PORT > 65535 )); then printf '%s\n' '중단: AUTO_READY 또는 remote port 오류' >&2; elif BJ="$(kubectl get pod "$BACKEND_POD" -n "$NS" -o json)" && BU="$(jq -r '.metadata.uid // empty' <<<"$BJ")" && BR="$(jq -r '.metadata.resourceVersion // empty' <<<"$BJ")" && CID="$(jq -r --arg c "$APP_CONTAINER" '[.status.containerStatuses[]? | select(.name==$c)] | if length==1 then .[0].containerID // empty else empty end' <<<"$BJ")" && DECLARED="$(jq -r --arg c "$APP_CONTAINER" --argjson p "$REMOTE_PORT" '[.spec.containers[]? | select(.name==$c) | .ports[]? | select(.containerPort==$p)] | length' <<<"$BJ")" && [ -n "$BU" ] && [ -n "$BR" ] && [ -n "$CID" ] && [ "$DECLARED" -ge 1 ]; then if [ "$TARGET_KIND" = pod ]; then if [ "$BACKEND_POD" != "$TARGET_NAME" ] || [ "$BU" != "$TARGET_UID" ] || [ "$SERVICE_PORT_NAME" != - ]; then printf '%s\n' '중단: Pod target과 backend identity 불일치' >&2; else REL_OK=true; ENDPOINT_PORT="$REMOTE_PORT"; fi; else PC="$(jq -r --arg n "$SERVICE_PORT_NAME" '[.spec.ports[]? | select(.name==$n)] | length' <<<"$TARGET_JSON")"; SERVICE_PORT="$(jq -r --arg n "$SERVICE_PORT_NAME" '.spec.ports[]? | select(.name==$n) | .port' <<<"$TARGET_JSON")"; TARGET_PORT="$(jq -r --arg n "$SERVICE_PORT_NAME" '.spec.ports[]? | select(.name==$n) | .targetPort | tostring' <<<"$TARGET_JSON")"; EP="$(kubectl get endpointslice -n "$NS" -l "kubernetes.io/service-name=$TARGET_NAME" -o json)"; EC="$(jq -r --arg uid "$BU" --arg n "$SERVICE_PORT_NAME" --argjson p "$REMOTE_PORT" '[.items[] | .ports[]? as $port | select($port.name==$n and $port.port==$p) | .endpoints[]? | select(.targetRef.kind=="Pod" and .targetRef.uid==$uid)] | length' <<<"$EP")"; if [ "$PC" != 1 ] || [ "$EC" -lt 1 ]; then printf '%s\n' '중단: Service port/EndpointSlice/backend UID 관계 실패' >&2; else REL_OK=true; ENDPOINT_PORT="$REMOTE_PORT"; fi; fi; if [ "${REL_OK:-false}" = true ]; then BACKEND_UID="$BU"; BACKEND_RV="$BR"; BACKEND_OWNER_KIND="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)] | if length==1 then .[0].kind else empty end' <<<"$BJ")"; BACKEND_OWNER_NAME="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)] | if length==1 then .[0].name else empty end' <<<"$BJ")"; BACKEND_OWNER_UID="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)] | if length==1 then .[0].uid else empty end' <<<"$BJ")"; APP_CONTAINER_ID="$CID"; BACKEND_NODE="$(jq -r '.spec.nodeName // empty' <<<"$BJ")"; BACKEND_READY=true; export BACKEND_POD BACKEND_UID BACKEND_RV BACKEND_OWNER_KIND BACKEND_OWNER_NAME BACKEND_OWNER_UID APP_CONTAINER APP_CONTAINER_ID BACKEND_NODE REMOTE_PORT SERVICE_PORT_NAME SERVICE_PORT TARGET_PORT ENDPOINT_PORT; printf 'BACKEND_READY=true pod=%s uid=%s rv=%s owner=%s/%s owner_uid=%s container=%s id=%s node=%s service_port=%s target_port=%s endpoint_port=%s\n' "$BACKEND_POD" "$BACKEND_UID" "$BACKEND_RV" "${BACKEND_OWNER_KIND:--}" "${BACKEND_OWNER_NAME:--}" "${BACKEND_OWNER_UID:--}" "$APP_CONTAINER" "$APP_CONTAINER_ID" "$BACKEND_NODE" "${SERVICE_PORT:--}" "${TARGET_PORT:--}" "$ENDPOINT_PORT"; fi; else printf '%s\n' '중단: backend Pod/container/declared port 조회 실패' >&2; fi`

`containerPort`와 EndpointSlice ready는 실제 process listener·HTTP path·scheme을 보장하지 않는다. discovery owner가 ServiceMonitor·PodMonitor인지 확인할 때는 먼저 `kubectl api-resources --api-group=monitoring.coreos.com -o name`으로 CRD 존재를 확인하고, 현재 target UID와 selector relation이 없는 CRD를 임의로 생성·수정하지 않는다.

### 2. Prometheus target API

승인된 query endpoint와 실제 discovered label 중 Kubernetes Pod UID를 담는 label 이름을 입력한다. Kubernetes SD가 아닌 static/file discovery라 UID label이 없으면 current lifecycle 연결을 보장할 수 없으므로 이 명령을 사용하지 않고 discovery owner의 redacted mapping evidence를 요청한다.

`PROM_URL='PASTE_APPROVED_PROMETHEUS_BASE_URL_HERE'; DISCOVERY_UID_LABEL='PASTE_DISCOVERED_POD_UID_LABEL_HERE'`

`PROM_INPUT_READY=false; if [ "$BACKEND_READY" != true ] || ! target_current; then printf '%s\n' '중단: 최신 backend identity 필요' >&2; elif ! [[ "$PROM_URL" =~ ^https?://[^[:space:]]+$ ]] || [[ "$PROM_URL" == *'@'* ]] || ! [[ "$DISCOVERY_UID_LABEL" =~ ^[A-Za-z_][A-Za-z0-9_]*$ ]]; then printf '%s\n' '중단: URL 또는 discovered label 이름 오류; credential 포함 금지' >&2; else PROM_URL="${PROM_URL%/}"; PROM_INPUT_READY=true; export PROM_URL DISCOVERY_UID_LABEL; printf 'PROM_INPUT_READY=true url=%s uid_label=%s backend_uid=%s\n' "$PROM_URL" "$DISCOVERY_UID_LABEL" "$BACKEND_UID"; fi`

`prom_get(){ local path="$1" body code rc; shift; [ "$PROM_INPUT_READY" = true ] && target_current >/dev/null || { printf '%s\n' '중단: 최신 PROM_INPUT_READY가 아니다.' >&2; return 1; }; body="$(mktemp)" || return 1; code="$(curl -G -sS --max-time 15 -o "$body" -w '%{http_code}' "$@" "$PROM_URL$path")"; rc=$?; if [ "$rc" -ne 0 ]; then printf 'curl 실패 path=%s rc=%s\n' "$path" "$rc" >&2; elif [ "$code" != 200 ]; then printf 'HTTP 실패 path=%s code=%s\n' "$path" "$code" >&2; rc=1; elif ! jq -e '.status=="success" and has("data")' "$body" >/dev/null; then jq -c '{status,errorType,error}' "$body" >&2; rc=1; else cat "$body"; rc=0; fi; rm -f "$body"; return "$rc"; }`

`TARGET_API_READY=false; if [ "$PROM_INPUT_READY" != true ] || ! target_current; then printf '%s\n' '중단: 최신 Prometheus/backend identity 필요' >&2; elif BODY="$(prom_get '/api/v1/targets' --data-urlencode 'state=any')"; then COUNT="$(jq -r --arg k "$DISCOVERY_UID_LABEL" --arg uid "$BACKEND_UID" '[.data.activeTargets[]? | select(.discoveredLabels[$k]==$uid)] | length' <<<"$BODY")"; if [ "$COUNT" -eq 1 ]; then TARGET_API_READY=true; jq -r --arg k "$DISCOVERY_UID_LABEL" --arg uid "$BACKEND_UID" '.data.activeTargets[] | select(.discoveredLabels[$k]==$uid) | "TARGET_API_READY=true health=\(.health) lastScrape=\(.lastScrape) lastError=\(if .lastError=="" then "-" else (.lastError|gsub("[^: ]+://[^ ]+";"REDACTED_URL")) end) job=\(.labels.job // "-") instance=\(.labels.instance // "-") scrape_url_present=\(.scrapeUrl!=null and .scrapeUrl!="")"' <<<"$BODY"; else printf '중단: current backend UID target count=%s\n' "$COUNT" >&2; fi; else printf '%s\n' '중단: targets API transport/HTTP/API 실패' >&2; fi`

`COUNT=0`이면 selector·namespaceSelector·relabel keep/drop·config reload 경계다. `health=down`의 `connection refused`, timeout, DNS, `404`, x509, 401/403은 각각 listener, network, path, TLS, auth 후보이며 단일 원인을 확정하지 않는다. raw `scrapeUrl`과 credential은 저장하지 않는다.

### 3. app log와 scrape 경계

**strict UTC 증거 창**

`START_RFC3339='PASTE_EVIDENCE_START_UTC_HERE'; END_RFC3339='PASTE_EVIDENCE_END_UTC_HERE'; STEP='PASTE_QUERY_STEP_HERE'`

`unset TIME_READY LOG_READY QUERY_READY SERIES_READY START_EPOCH END_EPOCH; TIME_READY=false; if [[ "$START_RFC3339" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ && "$END_RFC3339" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ && "$STEP" =~ ^[1-9][0-9]*(ms|s|m|h)$ ]] && START_EPOCH="$(date -u -d "$START_RFC3339" +%s 2>/dev/null)" && END_EPOCH="$(date -u -d "$END_RFC3339" +%s 2>/dev/null)" && [ "$(date -u -d "$START_RFC3339" '+%Y-%m-%dT%H:%M:%SZ')" = "$START_RFC3339" ] && [ "$(date -u -d "$END_RFC3339" '+%Y-%m-%dT%H:%M:%SZ')" = "$END_RFC3339" ] && [ "$START_EPOCH" -lt "$END_EPOCH" ]; then TIME_READY=true; printf 'TIME_READY=true start=%s end=%s step=%s\n' "$START_RFC3339" "$END_RFC3339" "$STEP"; else printf '%s\n' '중단: canonical UTC RFC3339/order/step 실패' >&2; fi`

`LOG_READY=false; TMP=''; if [ "$BACKEND_READY" != true ] || [ "$TIME_READY" != true ] || ! target_current; then printf '%s\n' '중단: 최신 backend identity와 시간 창 필요' >&2; elif TMP="$(mktemp)"; then if kubectl logs "$BACKEND_POD" -n "$NS" -c "$APP_CONTAINER" --timestamps --since-time="$START_RFC3339" --tail=300 >"$TMP"; then PRODUCER_RC=0; else PRODUCER_RC=$?; fi; if [ "$PRODUCER_RC" -ne 0 ]; then printf 'producer_rc=%s filter_rc=not-run\n' "$PRODUCER_RC" >&2; elif grep -E -i -C 3 'metrics|prometheus|exposition|collector|listen|bind|timeout|failed|error' "$TMP"; then LOG_READY=true; printf 'producer_rc=0 filter_rc=0 match=true\n'; else FILTER_RC=$?; if [ "$FILTER_RC" -eq 1 ]; then LOG_READY=true; printf 'producer_rc=0 filter_rc=1 match=false (정상 증거 아님)\n'; else printf 'producer_rc=0 filter_rc=%s filter_error=true\n' "$FILTER_RC" >&2; fi; fi; rm -f "$TMP"; else printf '%s\n' '중단: 임시 파일 생성 실패' >&2; fi`

target `up`은 마지막 scrape의 HTTP·parse 성공 범위이며 기대 metric 이름·label이나 post-relabel sample 존재를 보장하지 않는다. `scrape_samples_scraped`와 `scrape_samples_post_metric_relabeling` 차이는 같은 current target label과 시간에서 비교한다.

### 4. 완성 query와 저장 경계

targets API의 current UID 대상에서 확인한 exported `job`, `instance`와 기대 metric 이름을 입력한다. metric 이름과 label 값은 사용자가 PromQL 본문을 직접 편집하지 않고 완성 query로 생성한다.

`METRIC_NAME='PASTE_EXPECTED_METRIC_NAME_HERE'; QUERY_JOB='PASTE_EXPORTED_JOB_HERE'; QUERY_INSTANCE='PASTE_EXPORTED_INSTANCE_HERE'`

`unset QUERY_READY SERIES_READY PROMQL; QUERY_READY=false; if [ "$TARGET_API_READY" != true ] || [ "$TIME_READY" != true ] || ! target_current; then printf '%s\n' '중단: current target API와 시간 창 필요' >&2; elif ! [[ "$METRIC_NAME" =~ ^[a-zA-Z_:][a-zA-Z0-9_:]*$ ]] || [ -z "$QUERY_JOB" ] || [ -z "$QUERY_INSTANCE" ]; then printf '%s\n' '중단: metric/job/instance 선택 오류' >&2; elif TBODY="$(prom_get '/api/v1/targets' --data-urlencode 'state=any')" && MATCH_COUNT="$(jq -r --arg k "$DISCOVERY_UID_LABEL" --arg uid "$BACKEND_UID" --arg j "$QUERY_JOB" --arg i "$QUERY_INSTANCE" '[.data.activeTargets[]? | select(.discoveredLabels[$k]==$uid and .labels.job==$j and .labels.instance==$i)] | length' <<<"$TBODY")" && [ "$MATCH_COUNT" -eq 1 ]; then PROMQL="$(jq -nr --arg m "$METRIC_NAME" --arg j "$QUERY_JOB" --arg i "$QUERY_INSTANCE" '$m+"{job="+($j|@json)+",instance="+($i|@json)+"}"')"; QUERY_READY=true; export METRIC_NAME QUERY_JOB QUERY_INSTANCE PROMQL; printf 'QUERY_READY=true backend_uid=%s promql=%s\n' "$BACKEND_UID" "$PROMQL"; printf 'up query: up{job=%s,instance=%s}\n' "$(jq -Rn --arg v "$QUERY_JOB" '$v|@json')" "$(jq -Rn --arg v "$QUERY_INSTANCE" '$v|@json')"; printf 'scraped query: scrape_samples_scraped{job=%s,instance=%s}\n' "$(jq -Rn --arg v "$QUERY_JOB" '$v|@json')" "$(jq -Rn --arg v "$QUERY_INSTANCE" '$v|@json')"; printf 'post-relabel query: scrape_samples_post_metric_relabeling{job=%s,instance=%s}\n' "$(jq -Rn --arg v "$QUERY_JOB" '$v|@json')" "$(jq -Rn --arg v "$QUERY_INSTANCE" '$v|@json')"; else printf '중단: current backend UID와 exported job/instance exact target count=%s\n' "${MATCH_COUNT:-unknown}" >&2; fi`

`SERIES_READY=false; if [ "$QUERY_READY" != true ] || ! target_current; then printf '%s\n' '중단: 최신 QUERY_READY 필요' >&2; elif BODY="$(prom_get '/api/v1/query_range' --data-urlencode "query=$PROMQL" --data-urlencode "start=$START_RFC3339" --data-urlencode "end=$END_RFC3339" --data-urlencode "step=$STEP")"; then SERIES_COUNT="$(jq -r '.data.result | length' <<<"$BODY")"; SAMPLE_COUNT="$(jq -r '[.data.result[]?.values[]?] | length' <<<"$BODY")"; SERIES_READY=true; printf 'SERIES_READY=true series=%s samples=%s result_type=%s\n' "$SERIES_COUNT" "$SAMPLE_COUNT" "$(jq -r '.data.resultType' <<<"$BODY")"; else printf '%s\n' 'query transport/HTTP/API 실패' >&2; fi`

빈 result는 성공이나 0이 아니다. current target UID mapping, metric exposition, metric relabel, exact exported labels, query UTC 범위, retention, TSDB/WAL과 remote storage를 순서대로 분리한다.

## 상태 변경 경계와 정상화

이 런북은 상태 변경 명령을 제공하지 않는다. Service selector/port, Pod label, ServiceMonitor·PodMonitor, scrape path/scheme/TLS/auth, relabel rule, application instrumentation, Prometheus reload/rollout을 임의 변경하지 않는다. 확인된 discovery owner kind/name/UID·revision, 승인 ID·창·가용성·멱등성·rollback 선언 원본이 있는 별도 절차에서만 변경한다. 교체된 Service·Pod·monitor·Prometheus replica는 이름을 재사용하지 말고 새 UID·owner·selector·EndpointSlice·target mapping을 첫 단계부터 재등록한다.

정상화는 `current application metric 생성 -> 실제 scrape sample -> post-relabel sample -> TSDB current/range query -> dashboard·alert -> 실제 서비스 기능` 순서로 확인한다. targets API `up`, 한 sample, query HTTP 200은 단독 정상화가 아니다. 최소 여러 scrape/evaluation 주기 동안 lastScrape가 전진하고 lastError·series gap·query 오류가 재발하지 않아야 한다. 과거 누락 sample 복구 가능성은 현재 pipeline 회복과 별도로 기록한다.

## 증거와 근거

target kind/name/UID/RV, Service port/targetPort·EndpointSlice UID/port/targetRef UID, backend Pod UID/RV·owner UID·regular container/current containerID·node, discovery 방식·current UID label, redacted target health/lastScrape/error 유형, UTC 창, producer/filter rc, metric·exported label 이름, query API status와 series/sample count를 보존한다. credential·전체 config·raw URL·metric 값 원문은 보존하지 않는다.
