# 중앙 로그에서 대상 Pod·노드 로그를 찾을 수 없는 경우

## 입력값과 빠른 수집

Kubernetes 명령은 승인된 작업 PC 또는 bastion의 같은 Bash에서 실행한다. node journal 분기는 `작업 PC -> SSH -> API가 지정한 node -> /etc/machine-id -> 확인된 collector unit`의 별도 hop이다. 중앙 경로는 `current Pod/container 또는 node identity -> node source -> collector input -> parse/drop -> queue/transport -> store/index -> bounded query`다. 한 hop의 성공은 다음 hop을 보장하지 않는다.

| 구분 | 값 | 출처와 gate |
|---|---|---|
| 최초 입력 | `TARGET_KIND`, `NS`, `TARGET_NAME` | `pod`이면 namespace와 Pod, `node`이면 `NS=-`와 Node exact name |
| API 확인 자동값 | target UID/RV, owner UID, node UID/machineID/providerID | 현재 Kubernetes API 응답 |
| 계산 후보값 | UTC epoch, escaped LogQL selector, SSH argv | canonical time·label·remote identity 검증 전 미확정 |
| 운영자 선택값 | container kind/name, UTC 증거 창, 승인 SSH host·collector unit, 중앙 query 구현·URL·실제 label 이름 | API·inventory·중앙 schema를 확인하고 선택 |

로그 본문, Secret·token·private key, 개인정보와 내부 credential은 출력·증거에 저장하지 않는다. `kubectl logs`와 중앙 API의 성공 여부·count·timestamp·비민감 오류 유형만 기록한다.

**Bash·도구 확인**

### API 자동 수집

자동 수집 재실행 전에 container·node·시간·SSH·중앙 query·정상화 상태를 모두 지운다. Pod 이름이나 Node 이름만으로 과거 로그를 현재 객체에 연결하지 않는다.

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | 중앙 검색에서 current Pod UID·container 또는 Node UID·시간 범위의 로그가 없거나 다른 lifecycle 로그만 보임 |
| 적용 | source 생성 여부와 collector→store/index→query count를 같은 identity·UTC 창으로 연결 가능 |
| 제외 | `kubectl logs` 자체가 실패하면 [[27. Pod 로그를 가져올 수 없는 경우]], 애플리케이션 오류 내용은 로그 확보 뒤 해당 workload 런북으로 이동 |

검색 문자열: `pod_uid`, `container_id`, `node`, `input`, `parse`, `drop`, `buffer`, `backpressure`, `retry`, `429`, `index`, `retention`, `query timeout`.

## 관측별 진단 경로

| 지금 보이는 것 | 먼저 볼 것 | 다음 경계 | 상세 절 |
|---|---|---|---|
| `kubectl logs`에는 count가 있고 중앙은 0 | current containerID·UTC 창 | node collector input | [[#1. source 생성과 시간 창]] |
| 같은 node의 여러 Pod가 함께 누락 | node machine identity·collector journal | queue·transport | [[#2. node collector hop]] |
| input/forward count는 있고 query만 0 | parse/drop·store/index count | field·tenant·retention | [[#3. 중앙 query]] |
| 특정 시간만 누락 | event/receive/index timestamp | clock·parser·flush·retention | [[#4. 판정과 정상화]] |

### 1. source 생성과 시간 창

Pod 대상은 container kind/name을 선택한다. Node 대상은 두 값에 `-`를 사용한다.

`CONTAINER='PASTE_CONTAINER_OR_DASH_HERE'; CONTAINER_KIND='PASTE_REGULAR_INIT_OR_DASH_HERE'`

`unset SELECTION_READY TIME_READY SOURCE_READY NODE_READY REMOTE_READY CENTRAL_INPUT_READY QUERY_READY CENTRAL_READY NORMAL_READY CONTAINER_ID CONTAINER_STARTED; SELECTION_READY=false; if [ "$AUTO_READY" != true ]; then printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; elif [ "$TARGET_KIND" = node ]; then if [ "$CONTAINER" = - ] && [ "$CONTAINER_KIND" = - ]; then CONTAINER_ID=''; CONTAINER_STARTED=''; SELECTION_READY=true; printf 'SELECTION_READY=true node-only\n'; else printf '%s\n' '중단: Node 대상 container 값은 -' >&2; fi; elif { [ "$CONTAINER_KIND" != regular ] && [ "$CONTAINER_KIND" != init ]; }; then printf '%s\n' '중단: container kind는 regular 또는 init' >&2; else C="$(jq -c --arg c "$CONTAINER" --arg k "$CONTAINER_KIND" 'if $k=="regular" then [.status.containerStatuses[]? | select(.name==$c)] else [.status.initContainerStatuses[]? | select(.name==$c)] end | if length==1 then .[0] else empty end' <<<"$TARGET_JSON")"; CONTAINER_ID="$(jq -r '.containerID // empty' <<<"$C")"; CONTAINER_STARTED="$(jq -r '.state.running.startedAt // .state.terminated.startedAt // empty' <<<"$C")"; if [ -n "$C" ] && [ -n "$CONTAINER_ID" ]; then SELECTION_READY=true; export CONTAINER CONTAINER_KIND CONTAINER_ID CONTAINER_STARTED; printf 'SELECTION_READY=true container=%s kind=%s id=%s started=%s\n' "$CONTAINER" "$CONTAINER_KIND" "$CONTAINER_ID" "${CONTAINER_STARTED:--}"; else unset CONTAINER_ID CONTAINER_STARTED; printf '%s\n' '중단: current container instance 없음' >&2; fi; fi`

**strict UTC 증거 창**

`START_RFC3339='PASTE_EVIDENCE_START_UTC_HERE'; END_RFC3339='PASTE_EVIDENCE_END_UTC_HERE'`

`unset TIME_READY SOURCE_READY NODE_READY REMOTE_READY CENTRAL_INPUT_READY QUERY_READY CENTRAL_READY NORMAL_READY START_EPOCH END_EPOCH; TIME_READY=false; if [[ "$START_RFC3339" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ && "$END_RFC3339" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] && START_EPOCH="$(date -u -d "$START_RFC3339" +%s 2>/dev/null)" && END_EPOCH="$(date -u -d "$END_RFC3339" +%s 2>/dev/null)" && [ "$(date -u -d "$START_RFC3339" '+%Y-%m-%dT%H:%M:%SZ')" = "$START_RFC3339" ] && [ "$(date -u -d "$END_RFC3339" '+%Y-%m-%dT%H:%M:%SZ')" = "$END_RFC3339" ] && [ "$START_EPOCH" -lt "$END_EPOCH" ]; then TIME_READY=true; printf 'TIME_READY=true start=%s end=%s\n' "$START_RFC3339" "$END_RFC3339"; else printf '%s\n' '중단: canonical UTC RFC3339 round-trip/order 실패' >&2; fi`

`if [ "$TIME_READY" = true ] && [ "$TARGET_KIND" = pod ]; then CREATED="$(jq -r '.metadata.creationTimestamp // empty' <<<"$TARGET_JSON")"; CREATED_EPOCH="$(date -u -d "$CREATED" +%s 2>/dev/null)" || CREATED_EPOCH=''; STARTED_EPOCH="$(date -u -d "$CONTAINER_STARTED" +%s 2>/dev/null)" || STARTED_EPOCH=''; if [ -z "$CREATED_EPOCH" ] || [ -z "$STARTED_EPOCH" ] || [ "$END_EPOCH" -lt "$CREATED_EPOCH" ] || [ "$END_EPOCH" -lt "$STARTED_EPOCH" ]; then TIME_READY=false; unset SOURCE_READY NODE_READY REMOTE_READY CENTRAL_INPUT_READY QUERY_READY CENTRAL_READY NORMAL_READY; printf '%s\n' '중단: evidence window가 current Pod/container lifecycle과 겹치지 않음' >&2; else printf 'TIME_LIFECYCLE_READY=true pod_created=%s container_started=%s\n' "$CREATED" "$CONTAINER_STARTED"; fi; fi`

`SOURCE_READY=false; if [ "$TARGET_KIND" != pod ] || [ "$SELECTION_READY" != true ] || [ "$TIME_READY" != true ] || ! log_target_current; then printf '%s\n' '중단: current Pod/container/time gate 필요' >&2; elif TMP="$(mktemp)"; then if kubectl logs "$TARGET_NAME" -n "$NS" -c "$CONTAINER" --timestamps --since-time="$START_RFC3339" --tail=500 >"$TMP"; then PRODUCER_RC=0; else PRODUCER_RC=$?; fi; if [ "$PRODUCER_RC" -ne 0 ]; then printf 'SOURCE_READY=false producer_rc=%s\n' "$PRODUCER_RC" >&2; else LINE_COUNT="$(wc -l <"$TMP")"; FIRST_TS="$(sed -n '1{s/ .*//;p;}' "$TMP")"; LAST_TS="$(sed -n '${s/ .*//;p;}' "$TMP")"; SOURCE_READY=true; printf 'SOURCE_READY=true producer_rc=0 lines=%s first_ts=%s last_ts=%s pod_uid=%s container_id=%s\n' "$LINE_COUNT" "${FIRST_TS:--}" "${LAST_TS:--}" "$TARGET_UID" "$CONTAINER_ID"; fi; rm -f "$TMP"; else printf '%s\n' '중단: 임시 파일 생성 실패' >&2; fi`

`lines=0`은 producer 성공과 해당 bounded 결과가 비었다는 뜻이며 application이 로그를 생성하지 않았거나 retention·rotation·container 선택이 다른 후보를 구분하지 못한다. 로그 원문을 중앙 검색어로 복사하지 않는다.

`RBAC_READY=false; if [ "$TARGET_KIND" != pod ] || ! log_target_current; then printf '%s\n' '중단: current Pod identity 필요' >&2; elif A="$(kubectl auth can-i get pods/log -n "$NS")"; then RBAC_READY=true; printf 'RBAC_READY=true subject=current-kubeconfig verb=get resource=pods/log namespace=%s result=%s\n' "$NS" "$A"; else printf '%s\n' '중단: auth can-i 조회 실패' >&2; fi`

`yes`는 현재 subject·namespace·subresource에만 해당한다. 권한 확대나 impersonation을 하지 않는다. audit이 필요하면 단일 auditID의 `verb=get`, `resource=pods`, `subresource=log`, namespace/name, requestURI, status와 current Pod UID 시간 관계만 redacted 요청한다.

### 2. node collector hop

Pod source가 존재하지만 같은 node에서 중앙 누락되거나 Node 로그 자체가 누락된 경우에만 사용한다. 승인 inventory의 SSH host와 실제 systemd collector unit을 입력한다. 작업 PC 변수를 원격 shell이 자동으로 안다고 가정하지 않는다.

`REMOTE_HOST='PASTE_APPROVED_NODE_SSH_HOST_HERE'; COLLECTOR_UNIT='PASTE_CONFIRMED_COLLECTOR_UNIT_HERE'`

`unset NODE_READY REMOTE_READY CENTRAL_INPUT_READY QUERY_READY CENTRAL_READY NORMAL_READY SSH_ARGS; NODE_READY=false; if [ "$AUTO_READY" != true ] || [ "$TIME_READY" != true ] || ! log_target_current; then printf '%s\n' '중단: current target/node/time gate 필요' >&2; elif N="$(kubectl get node "$NODE" -o json)" && [ "$(jq -r '.metadata.uid // empty' <<<"$N")" = "$NODE_UID" ] && [ "$(jq -r '.status.nodeInfo.machineID // empty' <<<"$N")" = "$NODE_MACHINE_ID" ] && [ "$(jq -r '.spec.providerID // empty' <<<"$N")" = "$NODE_PROVIDER_ID" ] && jq -e --arg h "$REMOTE_HOST" '[.metadata.name,.status.addresses[]?.address] | any(.==$h)' <<<"$N" >/dev/null && [ -n "$COLLECTOR_UNIT" ] && [[ "$COLLECTOR_UNIT" != *[[:space:]]* ]]; then SSH_ARGS=(ssh -- "$REMOTE_HOST"); NODE_READY=true; printf 'NODE_READY=true node=%s uid=%s rv=%s machine=%s provider=%s remote=%s unit=%s\n' "$NODE" "$NODE_UID" "$(jq -r '.metadata.resourceVersion' <<<"$N")" "$NODE_MACHINE_ID" "${NODE_PROVIDER_ID:--}" "$REMOTE_HOST" "$COLLECTOR_UNIT"; else unset SSH_ARGS; printf '%s\n' '중단: node UID/machine/provider/SSH/unit relation 실패' >&2; fi`

`REMOTE_READY=false; if [ "$NODE_READY" != true ] || [ "$TIME_READY" != true ] || ! log_target_current; then printf '%s\n' '중단: 최신 node/target/time gate 필요' >&2; elif "${SSH_ARGS[@]}" bash -s -- "$NODE_MACHINE_ID" "$COLLECTOR_UNIT" "$START_RFC3339" "$END_RFC3339" "$TARGET_UID" <<'REMOTE'
set -u
expected_machine="$1"; unit="$2"; start="$3"; end="$4"; target_uid="$5"
actual_machine="$(cat /etc/machine-id 2>/dev/null)" || exit 10
[ "$actual_machine" = "$expected_machine" ] || { printf '%s\n' '중단: remote machine identity mismatch' >&2; exit 11; }
command -v journalctl >/dev/null 2>&1 || exit 12
tmp="$(mktemp)" || exit 13
if sudo -n journalctl -u "$unit" --since "$start" --until "$end" --utc --no-pager >"$tmp"; then producer_rc=0; else producer_rc=$?; fi
if [ "$producer_rc" -eq 0 ]; then
  if grep -E -i -C 3 -- "$target_uid|input|tail|parse|drop|buffer|queue|retry|backpressure|timeout|429|failed|error" "$tmp"; then filter_rc=0; else filter_rc=$?; fi
else
  filter_rc=not-run
fi
rm -f "$tmp"
printf 'remote_machine_verified=true producer_rc=%s filter_rc=%s\n' "$producer_rc" "$filter_rc"
[ "$producer_rc" -eq 0 ] && { [ "$filter_rc" = 0 ] || [ "$filter_rc" = 1 ]; }
REMOTE
then REMOTE_READY=true; printf 'REMOTE_READY=true node_uid=%s machine=%s\n' "$NODE_UID" "$NODE_MACHINE_ID"; else unset SSH_ARGS; NODE_READY=false; printf '%s\n' '원격 collector journal 실패: machine/producer/filter rc를 분리한다.' >&2; fi`

`filter_rc=1`은 journal producer 성공·일치 없음이며 collector 정상이나 target input 성공이 아니다. node 전용 도구는 이 SSH 분기에서만 요구한다. unit·runtime·로그 파일 경로를 추측하지 않는다.

### 3. 중앙 query

중앙 구현이 Loki이고 current identity label이 실제 schema에 존재할 때만 아래 query를 사용한다. 다른 구현이면 `CENTRAL_KIND=other`로 등록하고 이 문서가 query 문법을 발명하지 않는다. storage owner에게 동일 UID·container/node·UTC 창의 redacted count query와 단계별 count를 요청한다.

`CENTRAL_KIND='PASTE_LOKI_OR_OTHER_HERE'; CENTRAL_URL='PASTE_APPROVED_CENTRAL_BASE_URL_HERE'; UID_LABEL='PASTE_UID_LABEL_OR_DASH_HERE'; NAMESPACE_LABEL='PASTE_NAMESPACE_LABEL_OR_DASH_HERE'; CONTAINER_LABEL='PASTE_CONTAINER_LABEL_OR_DASH_HERE'; NODE_LABEL='PASTE_NODE_LABEL_HERE'`

`unset CENTRAL_INPUT_READY QUERY_READY CENTRAL_READY NORMAL_READY LOGQL; CENTRAL_INPUT_READY=false; if [ "$AUTO_READY" != true ] || [ "$TIME_READY" != true ] || ! log_target_current; then printf '%s\n' '중단: current identity와 time gate 필요' >&2; elif [ "$CENTRAL_KIND" = other ]; then CENTRAL_INPUT_READY=true; printf '%s\n' 'CENTRAL_INPUT_READY=true kind=other; 구현 owner의 redacted bounded query로 이관'; elif [ "$CENTRAL_KIND" != loki ] || ! [[ "$CENTRAL_URL" =~ ^https?://[^[:space:]]+$ ]] || [[ "$CENTRAL_URL" == *'@'* ]] || ! [[ "$NODE_LABEL" =~ ^[A-Za-z_][A-Za-z0-9_]*$ ]]; then printf '%s\n' '중단: loki|other, URL 또는 label 이름 오류' >&2; elif [ "$TARGET_KIND" = pod ] && { ! [[ "$UID_LABEL" =~ ^[A-Za-z_][A-Za-z0-9_]*$ ]] || ! [[ "$NAMESPACE_LABEL" =~ ^[A-Za-z_][A-Za-z0-9_]*$ ]] || ! [[ "$CONTAINER_LABEL" =~ ^[A-Za-z_][A-Za-z0-9_]*$ ]]; }; then printf '%s\n' '중단: Pod identity label 이름 오류' >&2; elif [ "$TARGET_KIND" = node ] && { [ "$UID_LABEL" != - ] || [ "$NAMESPACE_LABEL" != - ] || [ "$CONTAINER_LABEL" != - ]; }; then printf '%s\n' '중단: Node 대상 Pod label은 -' >&2; else CENTRAL_URL="${CENTRAL_URL%/}"; CENTRAL_INPUT_READY=true; export CENTRAL_KIND CENTRAL_URL UID_LABEL NAMESPACE_LABEL CONTAINER_LABEL NODE_LABEL; printf 'CENTRAL_INPUT_READY=true kind=loki url=%s\n' "$CENTRAL_URL"; fi`

`QUERY_READY=false; if [ "$CENTRAL_INPUT_READY" != true ] || [ "$CENTRAL_KIND" != loki ] || ! log_target_current; then printf '%s\n' '중단: 최신 Loki/current identity 필요' >&2; elif [ "$TARGET_KIND" = pod ]; then LOGQL="$(jq -nr --arg ul "$UID_LABEL" --arg uid "$TARGET_UID" --arg nl "$NAMESPACE_LABEL" --arg ns "$NS" --arg cl "$CONTAINER_LABEL" --arg c "$CONTAINER" --arg nol "$NODE_LABEL" --arg node "$NODE" '"{"+$ul+"="+($uid|@json)+","+$nl+"="+($ns|@json)+","+$cl+"="+($c|@json)+","+$nol+"="+($node|@json)+"}"')"; QUERY_READY=true; printf 'QUERY_READY=true logql=%s\n' "$LOGQL"; else LOGQL="$(jq -nr --arg l "$NODE_LABEL" --arg v "$NODE" '"{"+$l+"="+($v|@json)+"}"')"; QUERY_READY=true; printf 'QUERY_READY=true logql=%s\n' "$LOGQL"; fi`

`CENTRAL_READY=false; if [ "$QUERY_READY" != true ] || ! log_target_current; then printf '%s\n' '중단: 최신 QUERY_READY 필요' >&2; elif BODY="$(mktemp)"; then CODE="$(curl -G -sS --max-time 20 -o "$BODY" -w '%{http_code}' --data-urlencode "query=$LOGQL" --data-urlencode "start=${START_EPOCH}000000000" --data-urlencode "end=${END_EPOCH}000000000" --data-urlencode 'limit=100' "$CENTRAL_URL/loki/api/v1/query_range")"; CURL_RC=$?; if [ "$CURL_RC" -ne 0 ]; then printf 'curl_rc=%s HTTP=000\n' "$CURL_RC" >&2; elif [ "$CODE" != 200 ]; then printf 'curl_rc=0 HTTP=%s\n' "$CODE" >&2; elif ! jq -e '.status=="success" and .data.resultType=="streams" and (.data.result|type=="array")' "$BODY" >/dev/null; then printf '%s\n' 'HTTP 성공이나 Loki API success/schema 실패' >&2; else STREAMS="$(jq -r '.data.result|length' "$BODY")"; ENTRIES="$(jq -r '[.data.result[]?.values[]?]|length' "$BODY")"; CENTRAL_READY=true; printf 'CENTRAL_READY=true streams=%s entries=%s current_uid=%s window=%s..%s\n' "$STREAMS" "$ENTRIES" "$TARGET_UID" "$START_RFC3339" "$END_RFC3339"; fi; rm -f "$BODY"; else printf '%s\n' '중단: 임시 파일 생성 실패' >&2; fi`

HTTP 200과 `status=success` 뒤에도 `entries=0`은 정상화가 아니다. label 미보존·enrichment 실패, tenant/index 범위, parser/drop, ingest 지연, retention과 실제 로그 미생성을 분리한다. Loki response의 `.values[][1]` 로그 본문은 출력·저장하지 않는다.

중앙 pipeline owner에게 같은 identity·창으로 다음 count와 첫 비민감 오류 시각을 요청한다.

```text
source_count -> input_count -> parsed_count -> forwarded_count -> stored_count -> indexed_count -> query_count
```

- `source>0, input=0`: node tail/source permission·collector input 경계
- `input>parsed`: timestamp/multiline parser 또는 drop rule
- `parsed>forwarded`: queue·backpressure·destination transport·429/TLS
- `forwarded>stored/indexed`: backend ingest·quota·shard·index 지연
- `indexed>query`: label/tenant/time/retention query 경계

### 4. 판정과 정상화

이 런북은 상태 변경 명령을 제공하지 않는다. collector restart, queue flush/drop, buffer 삭제, parser/routing 변경, 재전송, index 재생성, retention 변경을 진단에 섞지 않는다. 재전송은 event ID·idempotency·순서·중복 영향이 확인되지 않으면 실행하지 않는다. 별도 변경 절차에는 current collector owner UID/revision, node identity, 승인 창, 보존 가능한 queue, 영향 tenant, rollback과 중단 조건이 필요하다.

교체된 Pod·node·collector는 같은 이름을 재사용하지 않는다. 새 Pod UID·owner·containerID·node 또는 새 Node UID·machineID부터 전체 자동값, SSH와 query selector를 다시 등록한다.

정상화는 `새 source event 생성 -> collector input/parse -> queue/forward -> store/index -> current UID·container/node query -> 실제 운영 검색면` 순서다. 각 count가 같은 새 UTC 창에서 증가하고 허용 지연 안에 수렴하며 retry/backpressure/drop·query 오류가 여러 flush 주기 동안 재발하지 않아야 한다. query 한 건, collector Ready, journal no-match는 단독 정상화가 아니다. 과거 로그가 retention·drop으로 손실됐으면 현재 pipeline 회복과 복구 불가 범위를 분리 기록한다. 로그 접근 회복은 애플리케이션 정상화를 보장하지 않으므로 실제 제품 기능은 서비스 owner가 별도로 검증한다.

## 증거와 근거
