# ConfigMap·Secret의 참조 이름·key·값이 기대와 다른 경우

## 입력값과 빠른 수집

이 런북은 **작업 PC 또는 bastion의 같은 Bash**에서 실행한다. 실행 경로는 `kubectl → API server → 현재 Pod spec → 같은 namespace의 ConfigMap·Secret metadata`다. 객체 존재는 key·값의 정확성이나 새 Pod 주입 성공을 보장하지 않는다. Secret `.data`·`stringData`, ConfigMap 값, token·인증서·개인키는 출력하거나 증거에 저장하지 않는다.

| 구분 | 값 | 출처와 gate |
|---|---|---|
| 최초 입력 | `NS`, `POD` | 승인된 namespace와 exact Pod 이름. exact-name 조회 성공 전에는 사용하지 않는다. |
| API 확인 자동값 | `POD_UID`, `POD_RV`, `NODE`, `OWNER_KIND`, `OWNER_NAME`, `OWNER_UID`, `OBSERVED_AT` | 현재 Pod JSON과 controller owner reference에서 등록한다. |
| 계산 후보값 | `REF_RESOURCE`, `REF_RE`, `POD_RE` | 선택 kind와 이름으로 계산하되 현재 참조·객체 identity 대조 전에는 확정하지 않는다. |
| 운영자 선택값 | `REF_KIND`, `REF_NAME`, `REF_KEY` | 자동 출력에서 실제 참조를 선택한다. key 없는 `envFrom`은 `REF_KEY=-`를 사용한다. |

### API 자동값과 관계 출력

자동 수집을 다시 실행할 때마다 identity·resourceVersion·owner·node·관계·시간·regex와 모든 downstream gate를 먼저 지운다. 실패해도 부분값을 남기지 않는다.

`unset AUTO_READY REF_READY OBJECT_READY RBAC_READY QUERY_READY CHANGE_READY APPLY_READY ROLLBACK_READY NORMAL_READY POD_JSON POD_UID POD_RV NODE OWNER_KIND OWNER_NAME OWNER_UID OBSERVED_AT REF_RESOURCE REF_RE POD_RE OBJECT_UID OBJECT_RV OBJECT_TYPE OBJECT_IMMUTABLE; AUTO_READY=false; if [ "$INPUT_READY" != true ]; then printf '%s\n' '중단: INPUT_READY가 아니다.' >&2; elif POD_JSON_TMP="$(kubectl get pod "$POD" -n "$NS" -o json)" && POD_UID_TMP="$(jq -r '.metadata.uid // empty' <<<"$POD_JSON_TMP")" && POD_RV_TMP="$(jq -r '.metadata.resourceVersion // empty' <<<"$POD_JSON_TMP")" && OBSERVED_TMP="$(date -u '+%Y-%m-%dT%H:%M:%SZ')" && [ -n "$POD_UID_TMP" ] && [ -n "$POD_RV_TMP" ]; then POD_JSON="$POD_JSON_TMP"; POD_UID="$POD_UID_TMP"; POD_RV="$POD_RV_TMP"; NODE="$(jq -r '.spec.nodeName // "-"' <<<"$POD_JSON")"; OWNER_KIND="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)] | if length==1 then .[0].uid else empty end' <<<"$POD_JSON")"; OBSERVED_AT="$OBSERVED_TMP"; AUTO_READY=true; export POD_UID POD_RV NODE OWNER_KIND OWNER_NAME OWNER_UID OBSERVED_AT; printf 'AUTO_READY=true pod_uid=%s pod_rv=%s node=%s owner=%s/%s owner_uid=%s observed=%s\n' "$POD_UID" "$POD_RV" "$NODE" "${OWNER_KIND:--}" "${OWNER_NAME:--}" "${OWNER_UID:--}" "$OBSERVED_AT"; jq -r '.spec.initContainers[]?,.spec.containers[]? | "=== Container: \(.name) ===", ([.env[]? | if .valueFrom.configMapKeyRef then "env \(.name) -> ConfigMap/\(.valueFrom.configMapKeyRef.name):\(.valueFrom.configMapKeyRef.key) optional=\(.valueFrom.configMapKeyRef.optional // false)" elif .valueFrom.secretKeyRef then "env \(.name) -> Secret/\(.valueFrom.secretKeyRef.name):\(.valueFrom.secretKeyRef.key) optional=\(.valueFrom.secretKeyRef.optional // false)" else empty end][]), ([.envFrom[]? | if .configMapRef then "envFrom -> ConfigMap/\(.configMapRef.name) prefix=\(.prefix // "") optional=\(.configMapRef.optional // false)" elif .secretRef then "envFrom -> Secret/\(.secretRef.name) prefix=\(.prefix // "") optional=\(.secretRef.optional // false)" else empty end][])' <<<"$POD_JSON"; jq -r '.spec.volumes[]? | if .configMap then "=== Volume: \(.name) ===\nConfigMap/\(.configMap.name) items="+([.configMap.items[]? | "\(.key):\(.path)"]|join(",")) elif .secret then "=== Volume: \(.name) ===\nSecret/\(.secret.secretName) items="+([.secret.items[]? | "\(.key):\(.path)"]|join(",")) elif .projected then "=== Volume: \(.name) ===\nprojected="+([.projected.sources[]? | if .configMap then "ConfigMap/\(.configMap.name)" elif .secret then "Secret/\(.secret.name)" else "other" end]|join(",")) else empty end' <<<"$POD_JSON"; else unset POD_JSON POD_UID POD_RV NODE OWNER_KIND OWNER_NAME OWNER_UID OBSERVED_AT; printf '%s\n' '중단: Pod 자동 수집 실패, 모든 파생값 무효' >&2; fi`

`AUTO_READY=true`여도 owner가 비어 있으면 standalone Pod다. owner가 하나가 아니거나 controller relation이 없으면 임의 owner를 선택하지 않는다.

**현재 Pod identity helper**

`refresh_pod(){ CURRENT_POD_UID=''; CURRENT_POD_RV=''; CURRENT_OWNER_UID=''; CURRENT_POD_JSON="$(kubectl get pod "$POD" -n "$NS" -o json 2>/dev/null)" || { unset AUTO_READY REF_READY OBJECT_READY RBAC_READY QUERY_READY CHANGE_READY APPLY_READY ROLLBACK_READY NORMAL_READY POD_UID POD_RV NODE OWNER_KIND OWNER_NAME OWNER_UID OBSERVED_AT REF_RESOURCE REF_RE POD_RE OBJECT_UID OBJECT_RV OBJECT_TYPE OBJECT_IMMUTABLE; printf '%s\n' '중단: Pod 재조회 실패, 파생값과 downstream gate 무효' >&2; return 1; }; CURRENT_POD_UID="$(jq -r '.metadata.uid // empty' <<<"$CURRENT_POD_JSON")"; CURRENT_POD_RV="$(jq -r '.metadata.resourceVersion // empty' <<<"$CURRENT_POD_JSON")"; CURRENT_OWNER_UID="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)] | if length==1 then .[0].uid else empty end' <<<"$CURRENT_POD_JSON")"; if [ "$AUTO_READY" = true ] && [ "$CURRENT_POD_UID" = "$POD_UID" ] && { [ -z "$OWNER_UID" ] || [ "$CURRENT_OWNER_UID" = "$OWNER_UID" ]; }; then printf 'POD_CURRENT=true uid=%s rv=%s owner_uid=%s\n' "$CURRENT_POD_UID" "$CURRENT_POD_RV" "${CURRENT_OWNER_UID:--}"; return 0; fi; unset AUTO_READY REF_READY OBJECT_READY RBAC_READY QUERY_READY CHANGE_READY APPLY_READY ROLLBACK_READY NORMAL_READY POD_UID POD_RV NODE OWNER_KIND OWNER_NAME OWNER_UID OBSERVED_AT REF_RESOURCE REF_RE POD_RE OBJECT_UID OBJECT_RV OBJECT_TYPE OBJECT_IMMUTABLE; printf '%s\n' '중단: Pod UID/owner lifecycle 변경, 전체 재수집 필요' >&2; return 1; }`

object 선택 뒤에는 helper가 object UID/RV도 함께 현재값으로 재검사하도록 다음 정의로 갱신한다. standalone Pod에 새 owner가 붙은 경우도 lifecycle 변경으로 취급한다.

`refresh_pod(){ CURRENT_POD_UID=''; CURRENT_POD_RV=''; CURRENT_OWNER_UID=''; CURRENT_OBJECT_UID=''; CURRENT_OBJECT_RV=''; CURRENT_POD_JSON="$(kubectl get pod "$POD" -n "$NS" -o json 2>/dev/null)" || { unset AUTO_READY REF_READY OBJECT_READY RBAC_READY QUERY_READY CHANGE_READY APPLY_READY ROLLBACK_READY NORMAL_READY; printf '%s\n' '중단: Pod 재조회 실패, downstream 무효' >&2; return 1; }; CURRENT_POD_UID="$(jq -r '.metadata.uid // empty' <<<"$CURRENT_POD_JSON")"; CURRENT_POD_RV="$(jq -r '.metadata.resourceVersion // empty' <<<"$CURRENT_POD_JSON")"; CURRENT_OWNER_UID="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)] | if length==1 then .[0].uid else empty end' <<<"$CURRENT_POD_JSON")"; if [ "$AUTO_READY" != true ] || [ "$CURRENT_POD_UID" != "$POD_UID" ] || [ -z "$CURRENT_POD_RV" ] || { [ -z "$OWNER_UID" ] && [ -n "$CURRENT_OWNER_UID" ]; } || { [ -n "$OWNER_UID" ] && [ "$CURRENT_OWNER_UID" != "$OWNER_UID" ]; }; then unset AUTO_READY REF_READY OBJECT_READY RBAC_READY QUERY_READY CHANGE_READY APPLY_READY ROLLBACK_READY NORMAL_READY; printf '%s\n' '중단: Pod/owner lifecycle 변경, 전체 재수집' >&2; return 1; fi; if [ "$OBJECT_READY" = true ]; then CURRENT_OBJECT_UID="$(kubectl get "$REF_RESOURCE" "$REF_NAME" -n "$NS" -o jsonpath='{.metadata.uid}' 2>/dev/null)" && CURRENT_OBJECT_RV="$(kubectl get "$REF_RESOURCE" "$REF_NAME" -n "$NS" -o jsonpath='{.metadata.resourceVersion}' 2>/dev/null)" || { unset OBJECT_READY RBAC_READY QUERY_READY CHANGE_READY APPLY_READY ROLLBACK_READY NORMAL_READY; printf '%s\n' '중단: object 재조회 실패' >&2; return 1; }; if [ "$CURRENT_OBJECT_UID" != "$OBJECT_UID" ] || [ "$CURRENT_OBJECT_RV" != "$OBJECT_RV" ]; then unset OBJECT_READY RBAC_READY QUERY_READY CHANGE_READY APPLY_READY ROLLBACK_READY NORMAL_READY; printf '%s\n' '중단: object UID/RV 변경, relation부터 재수집' >&2; return 1; fi; fi; printf 'POD_CURRENT=true uid=%s rv=%s owner_uid=%s object_uid=%s object_rv=%s\n' "$CURRENT_POD_UID" "$CURRENT_POD_RV" "${CURRENT_OWNER_UID:--}" "${CURRENT_OBJECT_UID:--}" "${CURRENT_OBJECT_RV:--}"; }`

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | live Pod의 ConfigMap·Secret 이름, key, optional, prefix, items/path 또는 객체 metadata가 승인 원본과 다른 경우 |
| 적용 | 현재 Pod UID와 정확한 참조 relation을 확인하고 값 없이 객체 UID·resourceVersion·key 집합을 대조할 수 있는 경우 |
| 제외 | 객체가 없어 시작하지 못하면 [[26. Pod가 ConfigMap·Secret을 찾지 못하는 경우]], 실제 주입은 [[01. 환경 변수·설정 볼륨에 기대한 값이 주입되지 않는 경우]], 변경 전파는 [[01. ConfigMap·Secret 변경 후 워크로드가 이전 설정을 계속 사용하는 경우]]로 이동 |

검색 문자열: `configMapKeyRef`, `secretKeyRef`, `envFrom`, `projected`, `items`, `optional`, `CreateContainerConfigError`, `NotFound`, `Immutable`.

## 관측별 진단 경로

| 지금 보이는 것 | 먼저 볼 것 | 다음 경계 | 상세 절 |
|---|---|---|---|
| 이름·key·optional 불일치 | 현재 Pod의 exact relation | 객체 metadata·key 집합 | [[#1. 참조 선택과 객체 identity]] |
| `Forbidden` | 현재 주체의 정확한 resource/name 권한 | RBAC owner·audit | [[#2. RBAC와 audit 정확성]] |
| Pod와 owner template 불일치 | controller UID·revision | 승인 선언·생성 경로 | [[#3. owner와 변경 경계]] |
| 값이 다르다고 신고됨 | 승인된 비민감 fingerprint·기능 | object owner·실제 주입 | [[#3. owner와 변경 경계]] |

### 1. 참조 선택과 객체 identity

**관계 선택값 등록**

`REF_KIND='PASTE_CONFIGMAP_OR_SECRET_HERE'; REF_NAME='PASTE_REFERENCED_OBJECT_HERE'; REF_KEY='PASTE_REFERENCED_KEY_OR_DASH_HERE'`

**선택 relation·객체 자동 등록**

`unset REF_READY OBJECT_READY RBAC_READY QUERY_READY CHANGE_READY APPLY_READY ROLLBACK_READY NORMAL_READY REF_RESOURCE REF_RE POD_RE OBJECT_UID OBJECT_RV OBJECT_TYPE OBJECT_IMMUTABLE; REF_READY=false; OBJECT_READY=false; if ! refresh_pod; then :; elif [ "$REF_KIND" = ConfigMap ]; then REF_RESOURCE=configmap; elif [ "$REF_KIND" = Secret ]; then REF_RESOURCE=secret; else printf '%s\n' '중단: REF_KIND는 ConfigMap 또는 Secret' >&2; fi; if [ -n "${REF_RESOURCE:-}" ]; then REL_COUNT="$(jq -r --arg k "$REF_KIND" --arg n "$REF_NAME" --arg key "$REF_KEY" '[.spec.initContainers[]?,.spec.containers[]? | (.env[]? | select((($k=="ConfigMap" and .valueFrom.configMapKeyRef.name==$n and ($key=="-" or .valueFrom.configMapKeyRef.key==$key)) or ($k=="Secret" and .valueFrom.secretKeyRef.name==$n and ($key=="-" or .valueFrom.secretKeyRef.key==$key)))), (.envFrom[]? | select($key=="-" and (($k=="ConfigMap" and .configMapRef.name==$n) or ($k=="Secret" and .secretRef.name==$n))))] | length' <<<"$CURRENT_POD_JSON")"; VOL_COUNT="$(jq -r --arg k "$REF_KIND" --arg n "$REF_NAME" --arg key "$REF_KEY" '[.spec.volumes[]? | select((($k=="ConfigMap" and .configMap.name==$n) or ($k=="Secret" and .secret.secretName==$n)) and ($key=="-" or any((.configMap.items[]?,.secret.items[]?); .key==$key)))] | length' <<<"$CURRENT_POD_JSON")"; if [ "$REL_COUNT" -eq 0 ] && [ "$VOL_COUNT" -eq 0 ]; then printf '%s\n' '중단: 현재 Pod에 exact 참조 relation 없음' >&2; elif CURRENT_OBJECT_JSON="$(kubectl get "$REF_RESOURCE" "$REF_NAME" -n "$NS" -o json)" && OBJECT_UID_TMP="$(jq -r '.metadata.uid // empty' <<<"$CURRENT_OBJECT_JSON")" && OBJECT_RV_TMP="$(jq -r '.metadata.resourceVersion // empty' <<<"$CURRENT_OBJECT_JSON")" && [ -n "$OBJECT_UID_TMP" ] && [ -n "$OBJECT_RV_TMP" ]; then if [ "$REF_KEY" != - ] && ! jq -e --arg key "$REF_KEY" '((.data // {}) + (.binaryData // {})) | has($key)' <<<"$CURRENT_OBJECT_JSON" >/dev/null; then printf '%s\n' '중단: 객체에 선택 key 없음' >&2; else OBJECT_UID="$OBJECT_UID_TMP"; OBJECT_RV="$OBJECT_RV_TMP"; OBJECT_TYPE="$(jq -r '.type // "ConfigMap"' <<<"$CURRENT_OBJECT_JSON")"; OBJECT_IMMUTABLE="$(jq -r '.immutable // false' <<<"$CURRENT_OBJECT_JSON")"; REF_RE="$(printf '%s' "$REF_NAME" | sed 's/[][\\.^$*+?(){}|]/\\&/g')"; POD_RE="$(printf '%s' "$POD" | sed 's/[][\\.^$*+?(){}|]/\\&/g')"; REF_READY=true; OBJECT_READY=true; printf 'REF_READY=true OBJECT_READY=true relation_count=%s volume_count=%s object=%s/%s uid=%s rv=%s type=%s immutable=%s\n' "$REL_COUNT" "$VOL_COUNT" "$REF_RESOURCE" "$REF_NAME" "$OBJECT_UID" "$OBJECT_RV" "$OBJECT_TYPE" "$OBJECT_IMMUTABLE"; jq -r '"key names: "+((((.data // {}) + (.binaryData // {}))|keys|sort)|join(","))' <<<"$CURRENT_OBJECT_JSON"; fi; else unset REF_RESOURCE REF_RE POD_RE OBJECT_UID OBJECT_RV OBJECT_TYPE OBJECT_IMMUTABLE; printf '%s\n' '중단: 객체 조회/identity 등록 실패' >&2; fi; fi`

Secret의 key **이름만** 표시된다. `optional=true`는 값의 유효성이나 애플리케이션의 빈 값 허용을 보장하지 않는다. 객체 `NotFound`는 26번, key 불일치는 승인 원본 관리 경로로 이동한다.

### 2. RBAC와 audit 정확성

**현재 identity와 exact resource/name 권한 확인**

`RBAC_READY=false; if [ "$OBJECT_READY" != true ] || ! refresh_pod; then printf '%s\n' '중단: 최신 OBJECT_READY가 필요하다.' >&2; elif GET_AUTH="$(kubectl auth can-i get "$REF_RESOURCE/$REF_NAME" -n "$NS")" && POD_AUTH="$(kubectl auth can-i get "pods/$POD" -n "$NS")"; then RBAC_READY=true; printf 'RBAC_READY=true subject=current-kubectl pod=%s object=%s\n' "$POD_AUTH" "$GET_AUTH"; else printf '%s\n' '중단: auth can-i 조회 실패' >&2; fi`

`yes`는 현재 kubeconfig 주체·namespace·verb·resource/name에만 해당한다. Secret 값 열람 권한 확대, cluster-admin 부여, impersonation은 하지 않는다. audit owner에게 요청할 exact 조건은 `verb=get`, `objectRef.resource=configmaps|secrets`, `namespace=NS`, `name=REF_NAME`, `responseStatus.code`, `user.username`, `stageTimestamp`다. audit record 없음은 요청 부재·audit 비활성·수집 지연을 구분하지 못한다. audit 원문과 Secret response body는 저장하지 않는다.

### 3. owner와 변경 경계

controller owner가 있으면 UID를 exact-name 재조회로 확인한다. ReplicaSet이 직접 owner면 상위 Deployment를 별도로 확인하기 전 rollout 대상으로 사용하지 않는다.

`if [ "$REF_READY" != true ] || ! refresh_pod; then printf '%s\n' '중단: 최신 REF_READY가 필요하다.' >&2; elif [ -z "$OWNER_KIND" ]; then printf '%s\n' 'standalone Pod: 승인 manifest와 대조'; elif OWNER_JSON="$(kubectl get "$OWNER_KIND" "$OWNER_NAME" -n "$NS" -o json)" && [ "$(jq -r '.metadata.uid' <<<"$OWNER_JSON")" = "$OWNER_UID" ]; then printf 'OWNER_CURRENT=true kind=%s name=%s uid=%s generation=%s\n' "$OWNER_KIND" "$OWNER_NAME" "$OWNER_UID" "$(jq -r '.metadata.generation // "-"' <<<"$OWNER_JSON")"; else unset REF_READY OBJECT_READY RBAC_READY QUERY_READY CHANGE_READY APPLY_READY ROLLBACK_READY NORMAL_READY; printf '%s\n' '중단: controller UID 변경 또는 조회 실패' >&2; fi`

live Pod만 다르면 생성 revision·admission·상위 controller를 조사한다. owner도 다르면 승인 선언을 수정 대상으로 삼는다. 값 차이는 Secret/ConfigMap 원문 대신 승인된 비민감 fingerprint, schema 검사와 실제 기능 결과로 확정한다.

## 제한적 변경과 rollback

진단 중 객체 생성·덮어쓰기, live Pod patch/delete, Secret 출력은 금지한다. 변경은 relation-select replacement를 우선한다. 공유 객체를 직접 바꾸는 것보다 새 versioned 객체를 만들고 **확인된 owner의 해당 참조만** 교체한 뒤, 모든 consumer를 재수집하는 방식이다. full refresh가 필요한 env·`subPath`는 새 Pod identity를 검증한다.

**변경 입력**

`APPROVAL_ID='PASTE_APPROVAL_ID_HERE'; CHANGE_START='PASTE_CHANGE_START_UTC_HERE'; CHANGE_END='PASTE_CHANGE_END_UTC_HERE'; APPROVED_MANIFEST='PASTE_APPROVED_MANIFEST_PATH_HERE'; ROLLBACK_MANIFEST='PASTE_ROLLBACK_MANIFEST_PATH_HERE'; IDEMPOTENCE_EVIDENCE='PASTE_IDEMPOTENCE_EVIDENCE_HERE'; QUORUM_EVIDENCE='PASTE_QUORUM_EVIDENCE_OR_NA_HERE'; CHANGE_INPUT_READY=true`

**fresh identity·승인 창 gate**

`unset CHANGE_READY APPLY_READY ROLLBACK_READY NORMAL_READY; CHANGE_READY=false; CHANGE_START_EPOCH=''; CHANGE_END_EPOCH=''; if [ "$CHANGE_INPUT_READY" != true ] || [ "$OBJECT_READY" != true ] || ! refresh_pod; then printf '%s\n' '중단: fresh Pod/object relation이 필요하다.' >&2; elif ! [[ "$CHANGE_START" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ && "$CHANGE_END" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]]; then printf '%s\n' '중단: 변경 창은 canonical UTC RFC3339' >&2; elif CHANGE_START_EPOCH="$(date -u -d "$CHANGE_START" +%s 2>/dev/null)" && CHANGE_END_EPOCH="$(date -u -d "$CHANGE_END" +%s 2>/dev/null)" && [ "$(date -u -d "$CHANGE_START" '+%Y-%m-%dT%H:%M:%SZ')" = "$CHANGE_START" ] && [ "$(date -u -d "$CHANGE_END" '+%Y-%m-%dT%H:%M:%SZ')" = "$CHANGE_END" ] && [ "$CHANGE_START_EPOCH" -lt "$CHANGE_END_EPOCH" ] && NOW_EPOCH="$(date -u +%s)" && [ "$NOW_EPOCH" -ge "$CHANGE_START_EPOCH" ] && [ "$NOW_EPOCH" -le "$CHANGE_END_EPOCH" ] && [ -n "$APPROVAL_ID" ] && [ -r "$APPROVED_MANIFEST" ] && [ -r "$ROLLBACK_MANIFEST" ] && [ -n "$IDEMPOTENCE_EVIDENCE" ] && [ -n "$QUORUM_EVIDENCE" ]; then CURRENT_OBJECT_UID="$(kubectl get "$REF_RESOURCE" "$REF_NAME" -n "$NS" -o jsonpath='{.metadata.uid}' 2>/dev/null)"; CURRENT_OBJECT_RV="$(kubectl get "$REF_RESOURCE" "$REF_NAME" -n "$NS" -o jsonpath='{.metadata.resourceVersion}' 2>/dev/null)"; if [ "$CURRENT_OBJECT_UID" = "$OBJECT_UID" ] && [ "$CURRENT_OBJECT_RV" = "$OBJECT_RV" ]; then CHANGE_READY=true; printf 'CHANGE_READY=true approval=%s window=%s..%s pod_uid=%s object_uid=%s object_rv=%s idempotence=%s quorum=%s\n' "$APPROVAL_ID" "$CHANGE_START" "$CHANGE_END" "$POD_UID" "$OBJECT_UID" "$OBJECT_RV" "$IDEMPOTENCE_EVIDENCE" "$QUORUM_EVIDENCE"; else printf '%s\n' '중단: object UID/RV 변경, 전체 재수집 필요' >&2; fi; else printf '%s\n' '중단: 승인·창·manifest·멱등성·quorum gate 실패' >&2; fi`

**승인 manifest 적용**

이 런북은 범용 manifest를 실행하는 mutation 명령을 제공하지 않는다. 문서만으로는 manifest가 현재 owner UID의 정확한 reference 하나만 바꾸는지, 새 versioned object와 rollback revision이 무엇인지, 다른 consumer를 건드리지 않는지 검증할 수 없기 때문이다. 별도 승인 절차에서 manifest 대상 kind/namespace/name, current owner UID·generation·revision, current object UID/RV, 새 object UID, selector, 가용성, 멱등성과 승인 창을 **적용 명령 자체가 다시 검사**해야 한다.

Ready 감소, 새 `NotFound`·`CreateContainerConfigError`, restart·오류율 증가, quorum 저하, 다른 consumer 영향 또는 민감값 노출 시 즉시 중단한다.

**검증 실패 시 승인 rollback**

rollback도 이 문서에서 실행하지 않는다. 별도 절차의 rollback 명령은 실제 적용된 owner revision·새 object UID·현재 relation·승인 창·rollback 선언 원본을 직접 재검사해야 한다. 적용 또는 rollback 뒤에는 성공 문자열을 gate로 재사용하지 않고 이 문서 첫 입력부터 새 Pod/owner/object identity를 수집한다.

적용과 rollback 뒤에는 이 문서 첫 입력부터 다시 실행한다. 이전 Pod UID·object UID/RV·owner·regex·gate를 재사용하지 않는다.

## 정상화 검증

정상화 순서는 `실제 기능 → 새 Pod 주입 → Pod→객체 relation → 객체 UID/RV·key → owner template → controller availability`다. 새 Pod UID에서 승인된 이름·key·optional·prefix·items/path가 일치하고, 객체 metadata와 비민감 schema가 맞으며, 원하는 Ready 수·실제 요청이 성공해야 한다. 승인 관찰 창 동안 같은 Event, restart, 오류율이 증가하지 않아야 한다. `Running`, 객체 존재, `auth can-i=yes`, apply 성공 한 번은 정상화가 아니다.

## Prometheus 빠른 관측

KSM metric·label이 실제로 존재할 때만 완성 쿼리를 생성한다. query 결과가 비면 객체 부재·metric 미수집·label 불일치·시간 범위·query 실패를 분리한다.

`QUERY_READY=false; if [ "$OBJECT_READY" != true ] || ! refresh_pod; then printf '%s\n' '중단: 최신 OBJECT_READY가 필요하다.' >&2; elif [ -n "$REF_RE" ] && [ -n "$POD_RE" ]; then QUERY_READY=true; if [ "$REF_KIND" = ConfigMap ]; then printf 'kube_configmap_info{namespace="%s",configmap=~"^%s$"}\n' "$NS" "$REF_RE"; else printf 'kube_secret_info{namespace="%s",secret=~"^%s$"}\n' "$NS" "$REF_RE"; fi; printf 'sum by(namespace,pod,uid,container,reason)(kube_pod_container_status_waiting_reason{namespace="%s",pod=~"^%s$",reason="CreateContainerConfigError"}==1)\n' "$NS" "$POD_RE"; else printf '%s\n' '중단: escaped regex 없음' >&2; fi`

## 증거와 근거

관측 UTC, Pod UID/RV·node·controller UID, exact relation, 객체 UID/RV/type/immutable와 key 이름, exact RBAC 결과, redacted audit status, 승인·창·manifest 식별자·rollback·기능·재발 관찰을 보존한다. Secret/ConfigMap 값과 전체 YAML·audit/log 원문은 보존하지 않는다.
