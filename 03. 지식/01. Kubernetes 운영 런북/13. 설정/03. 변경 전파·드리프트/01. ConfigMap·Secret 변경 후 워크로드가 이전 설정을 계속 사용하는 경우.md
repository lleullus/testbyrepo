# ConfigMap·Secret 변경 후 워크로드가 이전 설정을 계속 사용하는 경우

## 입력값과 빠른 수집

kubectl은 승인된 작업 PC 또는 bastion의 같은 Bash에서 실행한다. node journal은 별도 SSH hop이며 작업 PC gate가 원격에 전달된다고 가정하지 않는다. 경로는 `object UID/RV → Pod reference → kubelet projection 또는 env snapshot → container instance → application reload → 기능`이다. Secret/ConfigMap 값과 파일 원문은 출력하지 않는다.

| 구분 | 값 | 출처와 gate |
|---|---|---|
| 최초 입력 | `NS`, `POD` | exact Pod 조회 성공 |
| API 확인 자동값 | Pod UID/RV, controller UID, node UID/machineID/providerID, object UID/RV | 현재 API 응답과 exact relation |
| 계산 후보값 | 이름 regex, UTC epoch, SSH argv 배열 | escape·round-trip·remote identity 검증 전 미확정 |
| 운영자 선택값 | container, object kind/name, 전달 방식, path, UTC 증거 창, 승인 SSH host | relation 출력·inventory를 보고 선택 |

|---|---|
| 사용 | 객체 변경 뒤 env, 일반 volume, projected volume, `subPath` 또는 앱 동작이 이전 상태인 경우 |

검색 문자열: `resourceVersion`, `immutable`, `subPath`, `projected`, `envFrom`, `reload`, `SIGHUP`, `stale configuration`.

### 1. 전달 방식과 object relation

`CONTAINER='PASTE_CONTAINER_HERE'; OBJECT_KIND='PASTE_CONFIGMAP_OR_SECRET_HERE'; OBJECT_NAME='PASTE_OBJECT_NAME_HERE'; DELIVERY='PASTE_ENV_VOLUME_OR_SUBPATH_HERE'; FILE_PATH='PASTE_FILE_PATH_OR_DASH_HERE'`

`unset RELATION_READY TIME_READY NODE_READY REMOTE_READY LOG_READY CHANGE_READY APPLY_READY ROLLBACK_READY NORMAL_READY QUERY_READY OBJECT_RESOURCE OBJECT_UID OBJECT_RV CONTAINER_ID OBJECT_RE POD_RE CONTAINER_RE; RELATION_READY=false; if [ "$AUTO_READY" != true ] || { [ "$OBJECT_KIND" != ConfigMap ] && [ "$OBJECT_KIND" != Secret ]; } || { [ "$DELIVERY" != env ] && [ "$DELIVERY" != volume ] && [ "$DELIVERY" != subPath ]; }; then printf '%s\n' '중단: 선택값 오류' >&2; elif [ "$OBJECT_KIND" = ConfigMap ]; then OBJECT_RESOURCE=configmap; else OBJECT_RESOURCE=secret; fi; if [ -n "${OBJECT_RESOURCE:-}" ]; then REL="$(jq -r --arg c "$CONTAINER" --arg k "$OBJECT_KIND" --arg n "$OBJECT_NAME" --arg d "$DELIVERY" '[.spec.initContainers[]?,.spec.containers[]? | select(.name==$c) | if $d=="env" then (.env[]?,.envFrom[]?) | select(($k=="ConfigMap" and (.valueFrom.configMapKeyRef.name==$n or .configMapRef.name==$n)) or ($k=="Secret" and (.valueFrom.secretKeyRef.name==$n or .secretRef.name==$n))) else .volumeMounts[]? as $m | $m | select(($d=="volume" and (.subPath // "")=="") or ($d=="subPath" and (.subPath // "")!="")) end] | length' <<<"$POD_JSON")"; STATUS="$(jq -c --arg c "$CONTAINER" '[.status.initContainerStatuses[]?,.status.containerStatuses[]? | select(.name==$c)] | if length==1 then .[0] else empty end' <<<"$POD_JSON")"; if [ "$REL" -lt 1 ] || [ -z "$STATUS" ]; then printf '%s\n' '중단: exact container/delivery relation 없음' >&2; elif O="$(kubectl get "$OBJECT_RESOURCE" "$OBJECT_NAME" -n "$NS" -o json)" && OU="$(jq -r '.metadata.uid // empty' <<<"$O")" && ORV="$(jq -r '.metadata.resourceVersion // empty' <<<"$O")" && [ -n "$OU" ] && [ -n "$ORV" ]; then OBJECT_UID="$OU"; OBJECT_RV="$ORV"; CONTAINER_ID="$(jq -r '.containerID // empty' <<<"$STATUS")"; OBJECT_RE="$(printf '%s' "$OBJECT_NAME" | sed 's/[][\\.^$*+?(){}|]/\\&/g')"; POD_RE="$(printf '%s' "$POD" | sed 's/[][\\.^$*+?(){}|]/\\&/g')"; CONTAINER_RE="$(printf '%s' "$CONTAINER" | sed 's/[][\\.^$*+?(){}|]/\\&/g')"; if [ -n "$CONTAINER_ID" ]; then RELATION_READY=true; printf 'RELATION_READY=true delivery=%s object=%s/%s uid=%s rv=%s container=%s id=%s\n' "$DELIVERY" "$OBJECT_RESOURCE" "$OBJECT_NAME" "$OBJECT_UID" "$OBJECT_RV" "$CONTAINER" "$CONTAINER_ID"; else printf '%s\n' '중단: current container ID 없음' >&2; fi; else unset OBJECT_UID OBJECT_RV CONTAINER_ID OBJECT_RE POD_RE CONTAINER_RE; printf '%s\n' '중단: object identity 조회 실패' >&2; fi; fi`

volume·`subPath` 선택은 mount 존재만으로 끝내지 않고 mount name→volume→직접 또는 projected source object까지 다시 검증한다.

`if [ "$RELATION_READY" = true ] && [ "$DELIVERY" != env ]; then EXACT_REL="$(jq -r --arg c "$CONTAINER" --arg k "$OBJECT_KIND" --arg n "$OBJECT_NAME" --arg d "$DELIVERY" '([.spec.initContainers[]?,.spec.containers[]? | select(.name==$c) | .volumeMounts[]? | select(($d=="volume" and (.subPath // "")=="") or ($d=="subPath" and (.subPath // "")!="")) | .name]) as $mounted | [.spec.volumes[]? | select(.name as $vn | $mounted | index($vn)) | select(if $k=="ConfigMap" then ((.configMap.name // "")==$n or any(.projected.sources[]?; (.configMap.name // "")==$n)) else ((.secret.secretName // "")==$n or any(.projected.sources[]?; (.secret.name // "")==$n)) end)] | length' <<<"$POD_JSON")"; if [ "$EXACT_REL" -lt 1 ]; then RELATION_READY=false; unset TIME_READY NODE_READY REMOTE_READY LOG_READY CHANGE_READY APPLY_READY ROLLBACK_READY NORMAL_READY QUERY_READY OBJECT_UID OBJECT_RV CONTAINER_ID OBJECT_RE POD_RE CONTAINER_RE; printf '%s\n' '중단: mount→volume→object exact relation 없음' >&2; else printf 'RELATION_EXACT_READY=true delivery=%s object=%s/%s\n' "$DELIVERY" "$OBJECT_KIND" "$OBJECT_NAME"; fi; fi`

relation 등록 이후 모든 downstream 명령이 object UID/RV도 직접 재검사하도록 helper를 다시 등록한다.

`refresh_current(){ CURRENT_READY=false; CURRENT_JSON="$(kubectl get pod "$POD" -n "$NS" -o json 2>/dev/null)" || { unset AUTO_READY RELATION_READY TIME_READY NODE_READY REMOTE_READY LOG_READY CHANGE_READY APPLY_READY ROLLBACK_READY NORMAL_READY QUERY_READY; printf '%s\n' '중단: Pod 재조회 실패, downstream 무효' >&2; return 1; }; CURRENT_UID="$(jq -r '.metadata.uid // empty' <<<"$CURRENT_JSON")"; CURRENT_RV="$(jq -r '.metadata.resourceVersion // empty' <<<"$CURRENT_JSON")"; CURRENT_OWNER_UID="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)] | if length==1 then .[0].uid else empty end' <<<"$CURRENT_JSON")"; CURRENT_CONTAINER_ID="$(jq -r --arg c "${CONTAINER:-}" '[.status.initContainerStatuses[]?,.status.containerStatuses[]? | select(.name==$c)] | if length==1 then .[0].containerID // empty else empty end' <<<"$CURRENT_JSON")"; if [ "$AUTO_READY" != true ] || [ "$CURRENT_UID" != "$POD_UID" ] || [ -z "$CURRENT_RV" ] || { [ -z "$OWNER_UID" ] && [ -n "$CURRENT_OWNER_UID" ]; } || { [ -n "$OWNER_UID" ] && [ "$CURRENT_OWNER_UID" != "$OWNER_UID" ]; } || { [ "$RELATION_READY" = true ] && [ "$CURRENT_CONTAINER_ID" != "$CONTAINER_ID" ]; }; then unset AUTO_READY RELATION_READY TIME_READY NODE_READY REMOTE_READY LOG_READY CHANGE_READY APPLY_READY ROLLBACK_READY NORMAL_READY QUERY_READY; printf '%s\n' '중단: Pod/owner/container lifecycle 변경, 전체 재수집' >&2; return 1; fi; if [ "$RELATION_READY" = true ]; then CURRENT_OBJECT_UID="$(kubectl get "$OBJECT_RESOURCE" "$OBJECT_NAME" -n "$NS" -o jsonpath='{.metadata.uid}' 2>/dev/null)" && CURRENT_OBJECT_RV="$(kubectl get "$OBJECT_RESOURCE" "$OBJECT_NAME" -n "$NS" -o jsonpath='{.metadata.resourceVersion}' 2>/dev/null)" || { unset RELATION_READY TIME_READY NODE_READY REMOTE_READY LOG_READY CHANGE_READY APPLY_READY ROLLBACK_READY NORMAL_READY QUERY_READY; printf '%s\n' '중단: object 재조회 실패' >&2; return 1; }; if [ "$CURRENT_OBJECT_UID" != "$OBJECT_UID" ] || [ "$CURRENT_OBJECT_RV" != "$OBJECT_RV" ]; then unset RELATION_READY TIME_READY NODE_READY REMOTE_READY LOG_READY CHANGE_READY APPLY_READY ROLLBACK_READY NORMAL_READY QUERY_READY; printf '%s\n' '중단: object UID/RV 변경, relation부터 재수집' >&2; return 1; fi; fi; CURRENT_READY=true; printf 'CURRENT_READY=true pod_uid=%s pod_rv=%s owner_uid=%s container_id=%s object_uid=%s object_rv=%s\n' "$CURRENT_UID" "$CURRENT_RV" "${CURRENT_OWNER_UID:--}" "${CURRENT_CONTAINER_ID:--}" "${CURRENT_OBJECT_UID:--}" "${CURRENT_OBJECT_RV:--}"; }`

- `env`: Pod/container 생성 시 snapshot이며 object RV 변경만으로 갱신되지 않는다.
- `volume`: kubelet projection 후 앱이 다시 읽어야 한다. 변경 직후 즉시 갱신을 보장하지 않는다.
- `subPath`: 이후 projection 갱신을 받지 않으므로 승인된 새 Pod가 필요하다.

### 2. node projection hop

일반 volume이고 projection 지연·실패 증거가 있을 때만 연다. 실행 hop은 `작업 PC → SSH transport → API가 지정한 node → 실제 machineID → kubelet unit journal`이다. node Ready는 projection 성공을 보장하지 않는다.

`START_RFC3339='PASTE_EVIDENCE_START_UTC_HERE'; END_RFC3339='PASTE_EVIDENCE_END_UTC_HERE'; REMOTE_HOST='PASTE_APPROVED_NODE_SSH_HOST_HERE'; KUBELET_UNIT='PASTE_CONFIRMED_KUBELET_UNIT_HERE'`

`unset TIME_READY NODE_READY REMOTE_READY LOG_READY CHANGE_READY APPLY_READY ROLLBACK_READY NORMAL_READY START_EPOCH END_EPOCH SSH_ARGS; TIME_READY=false; if [[ "$START_RFC3339" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ && "$END_RFC3339" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] && START_EPOCH="$(date -u -d "$START_RFC3339" +%s 2>/dev/null)" && END_EPOCH="$(date -u -d "$END_RFC3339" +%s 2>/dev/null)" && [ "$(date -u -d "$START_RFC3339" '+%Y-%m-%dT%H:%M:%SZ')" = "$START_RFC3339" ] && [ "$(date -u -d "$END_RFC3339" '+%Y-%m-%dT%H:%M:%SZ')" = "$END_RFC3339" ] && [ "$START_EPOCH" -lt "$END_EPOCH" ]; then TIME_READY=true; printf 'TIME_READY=true start=%s end=%s\n' "$START_RFC3339" "$END_RFC3339"; else printf '%s\n' '중단: strict UTC RFC3339 round-trip/order 실패' >&2; fi`

`NODE_READY=false; if [ "$RELATION_READY" != true ] || [ "$DELIVERY" != volume ] || [ "$TIME_READY" != true ] || ! refresh_current; then printf '%s\n' '중단: current volume/time relation 필요' >&2; elif N="$(kubectl get node "$NODE" -o json)" && CURRENT_NODE_UID="$(jq -r '.metadata.uid // empty' <<<"$N")" && CURRENT_MACHINE_ID="$(jq -r '.status.nodeInfo.machineID // empty' <<<"$N")" && CURRENT_PROVIDER_ID="$(jq -r '.spec.providerID // empty' <<<"$N")" && [ "$CURRENT_NODE_UID" = "$NODE_UID" ] && [ "$CURRENT_MACHINE_ID" = "$NODE_MACHINE_ID" ] && [ "$CURRENT_PROVIDER_ID" = "$NODE_PROVIDER_ID" ] && jq -e --arg h "$REMOTE_HOST" '[.metadata.name,.status.addresses[]?.address] | any(.==$h)' <<<"$N" >/dev/null; then SSH_ARGS=(ssh -- "$REMOTE_HOST"); NODE_READY=true; printf 'NODE_READY=true node=%s uid=%s machine=%s provider=%s remote=%s\n' "$NODE" "$NODE_UID" "$NODE_MACHINE_ID" "${NODE_PROVIDER_ID:--}" "$REMOTE_HOST"; else unset SSH_ARGS REMOTE_HOST; printf '%s\n' '중단: node UID/machine/provider/SSH relation 불일치' >&2; fi`

원격 명령은 `eval`하지 않고 배열과 positional argument로 전달한다. 원격에서 `/etc/machine-id`를 API machineID와 다시 비교한다.

`REMOTE_READY=false; if [ "$NODE_READY" != true ] || [ "$TIME_READY" != true ] || ! refresh_current; then printf '%s\n' '중단: 최신 node/Pod/time gate 필요' >&2; elif "${SSH_ARGS[@]}" bash -s -- "$NODE_MACHINE_ID" "$KUBELET_UNIT" "$START_RFC3339" "$END_RFC3339" "$POD_UID" "$OBJECT_NAME" <<'REMOTE'
set -u
expected_machine="$1"; unit="$2"; start="$3"; end="$4"; pod_uid="$5"; object="$6"
actual_machine="$(cat /etc/machine-id 2>/dev/null)" || exit 10
[ "$actual_machine" = "$expected_machine" ] || { printf '중단: remote machine identity mismatch\n' >&2; exit 11; }
command -v journalctl >/dev/null 2>&1 || exit 12
sudo -n journalctl -u "$unit" --since "$start" --until "$end" --utc --no-pager | grep -E -i -C 3 -- "$pod_uid|$object|projected|configmap|secret|volume|sync|failed|forbidden|timeout"
producer_rc="${PIPESTATUS[0]}"; filter_rc="${PIPESTATUS[1]}"
printf 'remote_machine_verified=true producer_rc=%s filter_rc=%s\n' "$producer_rc" "$filter_rc"
[ "$producer_rc" -eq 0 ] && { [ "$filter_rc" -eq 0 ] || [ "$filter_rc" -eq 1 ]; }
REMOTE
then REMOTE_READY=true; printf 'REMOTE_READY=true\n'; else unset SSH_ARGS; NODE_READY=false; printf '%s\n' '원격 journal 실패: machine/producer/filter rc를 구분한다.' >&2; fi`

`filter_rc=1`은 일치 없음이며 projection 성공이 아니다. producer 실패와 섞지 않는다. 다른 node·unit·시간을 임의로 넓히지 않는다.

### 3. application reload와 기능

`LOG_READY=false; TMP=''; if [ "$RELATION_READY" != true ] || [ "$TIME_READY" != true ] || ! refresh_current; then printf '%s\n' '중단: current relation/time 필요' >&2; elif TMP="$(mktemp)"; then if kubectl logs "$POD" -n "$NS" -c "$CONTAINER" --timestamps --since-time="$START_RFC3339" --tail=300 >"$TMP"; then PRC=0; else PRC=$?; fi; if [ "$PRC" -ne 0 ]; then printf 'producer_rc=%s filter_rc=not-run\n' "$PRC" >&2; elif grep -E -i -C 3 'reload|reloaded|config|watch|SIGHUP|parse|failed|error' "$TMP"; then FRC=0; LOG_READY=true; printf 'producer_rc=0 filter_rc=0 match=true\n'; else FRC=$?; if [ "$FRC" -eq 1 ]; then LOG_READY=true; printf 'producer_rc=0 filter_rc=1 match=false\n'; else printf 'producer_rc=0 filter_rc=%s filter_error=true\n' "$FRC" >&2; fi; fi; rm -f "$TMP"; fi`

`configuration reloaded`는 새 설정의 실제 사용을 보장하지 않는다. 승인된 비민감 config version/schema와 실제 요청 결과를 object RV·container start와 같은 증거 창에서 확인한다.

### 4. 제한적 변경과 rollback

변경은 env/`subPath` full refresh 또는 확인된 reload 선언만 다룬다. 공유 객체 덮어쓰기보다 versioned object로 relation-select replacement를 우선하고 모든 consumer를 다시 수집한다. Job/CronJob은 외부 side effect·중복·멱등성을 확인하지 않으면 재실행하지 않는다. StatefulSet은 quorum·leader·ordinal을 승인한다.

`APPROVAL_ID='PASTE_APPROVAL_ID_HERE'; CHANGE_START='PASTE_CHANGE_START_UTC_HERE'; CHANGE_END='PASTE_CHANGE_END_UTC_HERE'; APPROVED_MANIFEST='PASTE_APPROVED_OWNER_MANIFEST_HERE'; ROLLBACK_MANIFEST='PASTE_ROLLBACK_OWNER_MANIFEST_HERE'; IDEMPOTENCE_EVIDENCE='PASTE_IDEMPOTENCE_EVIDENCE_HERE'; QUORUM_EVIDENCE='PASTE_QUORUM_EVIDENCE_OR_NA_HERE'; CHANGE_INPUT_READY=true`

`unset CHANGE_READY APPLY_READY ROLLBACK_READY NORMAL_READY; CHANGE_READY=false; if [ "$CHANGE_INPUT_READY" != true ] || [ "$RELATION_READY" != true ] || ! refresh_current; then printf '%s\n' '중단: fresh relation 필요' >&2; elif [[ "$CHANGE_START" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ && "$CHANGE_END" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] && CS="$(date -u -d "$CHANGE_START" +%s 2>/dev/null)" && CE="$(date -u -d "$CHANGE_END" +%s 2>/dev/null)" && [ "$(date -u -d "$CHANGE_START" '+%Y-%m-%dT%H:%M:%SZ')" = "$CHANGE_START" ] && [ "$(date -u -d "$CHANGE_END" '+%Y-%m-%dT%H:%M:%SZ')" = "$CHANGE_END" ] && [ "$CS" -lt "$CE" ] && NOW="$(date -u +%s)" && [ "$NOW" -ge "$CS" ] && [ "$NOW" -le "$CE" ] && [ -n "$APPROVAL_ID" ] && [ -r "$APPROVED_MANIFEST" ] && [ -r "$ROLLBACK_MANIFEST" ] && [ -n "$IDEMPOTENCE_EVIDENCE" ] && [ -n "$QUORUM_EVIDENCE" ] && CU="$(kubectl get "$OBJECT_RESOURCE" "$OBJECT_NAME" -n "$NS" -o jsonpath='{.metadata.uid}' 2>/dev/null)" && CR="$(kubectl get "$OBJECT_RESOURCE" "$OBJECT_NAME" -n "$NS" -o jsonpath='{.metadata.resourceVersion}' 2>/dev/null)" && [ "$CU" = "$OBJECT_UID" ] && [ "$CR" = "$OBJECT_RV" ]; then CHANGE_READY=true; printf 'CHANGE_READY=true approval=%s object_uid=%s rv=%s\n' "$APPROVAL_ID" "$OBJECT_UID" "$OBJECT_RV"; else printf '%s\n' '중단: fresh identity/승인 창/rollback/멱등성/quorum 실패' >&2; fi`

이 런북은 범용 owner manifest를 실행하지 않는다. 별도 승인 mutation 절차는 current owner UID·generation·revision, object UID/RV, template relation, selector, image digest, 가용성·quorum, 승인 창, 멱등성과 rollback 원본을 적용 명령 자체에서 다시 검사해야 한다. 적용 뒤에는 selector·owner UID·creationTimestamp로 새 Pod 후보를 다시 찾고 단일 replacement relation을 검증한다.

rollback 명령도 제공하지 않는다. 별도 절차는 실제 적용 revision과 새 Pod UID/containerID, current owner UID, 승인 창과 rollback revision을 직접 검사하고 rollback 뒤 모든 consumer의 relation·기능·재발을 새 identity로 검증한다.

Ready 감소, 새 Warning/restart, quorum 저하, 오류율·지연 증가, 다른 consumer 영향 또는 민감값 노출 시 중단한다.

## 정상화·PromQL

정상화는 `실제 기능 → app reload/version → 새 container ID → projection/env snapshot → object UID/RV → owner desired/Ready` 역순이다. 승인 관찰 창 동안 stale 설정·restart·Warning·기능 오류가 재발하지 않아야 한다. 과거 손실과 현재 pipeline 회복을 분리해 기록한다.

`QUERY_READY=false; if [ "$RELATION_READY" != true ] || ! refresh_current; then printf '%s\n' '중단: 최신 relation 필요' >&2; elif [ -n "$POD_RE" ] && [ -n "$CONTAINER_RE" ]; then QUERY_READY=true; printf 'time()-kube_pod_created{namespace="%s",pod=~"^%s$",uid="%s"}\n' "$NS" "$POD_RE" "$POD_UID"; printf 'kube_pod_container_status_ready{namespace="%s",pod=~"^%s$",uid="%s",container=~"^%s$"}==1\n' "$NS" "$POD_RE" "$POD_UID" "$CONTAINER_RE"; printf 'sum by(namespace,pod,uid,container)(increase(kube_pod_container_status_restarts_total{namespace="%s",pod=~"^%s$",uid="%s",container=~"^%s$"}[15m]))\n' "$NS" "$POD_RE" "$POD_UID" "$CONTAINER_RE"; fi`

빈 결과는 성공이 아니다. metric/label 부재, scrape 실패, query 범위와 retention을 분리한다.
