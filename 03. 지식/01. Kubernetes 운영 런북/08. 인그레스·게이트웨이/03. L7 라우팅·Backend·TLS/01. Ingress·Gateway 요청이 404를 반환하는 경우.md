# Ingress·Gateway 요청이 404를 반환하는 경우

## 입력값과 빠른 수집

실행 경로는 `승인된 작업 PC 또는 bastion의 같은 Bash → kubectl/API server → Ingress 또는 Gateway·HTTPRoute → Service → EndpointSlice → backend Pod/container`다. 실제 요청 경로는 `같은 실행 host의 curl → DNS/VIP → controller listener → host/path match → Service port → EndpointSlice port → backend listener/application`이다. `404`는 transport가 HTTP 응답까지 도달했다는 뜻이지만 controller의 미매칭 응답인지 backend application 응답인지는 단독으로 증명하지 않는다.

| 입력 종류 | 변수 | 출처와 gate |
|---|---|---|
| 최초 입력 | `NS`, `KIND`, `NAME`, `ROUTE` | exact namespace, `ingress` 또는 `gateway`, 객체 이름, Gateway일 때 HTTPRoute 이름이다. Ingress면 `ROUTE=-`를 사용한다. |
| API 확인 자동값 | 대상·Route `UID/RV/generation/owner/created`, class, rule/listener/parent/backend, Service `UID/RV/port/targetPort` | 모든 필수 API가 성공한 뒤에만 등록한다. |
| 계산 후보값 | `TARGET_RE`, `PATH_RE`, 표준 Ingress match 후보 | regex escape와 API rule 계산 결과다. `ImplementationSpecific`은 자동 확정하지 않는다. |
| 운영자 선택값 | `REQ_HOST`, `REQ_PATH`, `CHECK_URL`, `BACKEND_POD`, `BACKEND_CONTAINER`, `START_RFC3339`, `END_RFC3339` | 승인된 비민감 GET, EndpointSlice target, 실제 증거 창에서 선택한다. |

Gateway API는 Kubernetes 1.26 내장 API가 아니다. discovery·CRD served version·설치 controller 계약이 확인되지 않으면 Ingress와 같은 condition 의미를 적용하지 않는다.

### 2. 자동값 재수집

재수집 전에 UID/RV/owner/containerID/node, Service·EndpointSlice 관계, 시간·regex·request, authorization·evidence·mutation·rollback·normalization 상태를 모두 폐기한다. 조회가 일부만 성공해도 이전 값은 유효하지 않다.

### 3. 승인 요청과 backend 관계 등록

`REQ_HOST='PASTE_404_APPROVED_HOST_HERE'; REQ_PATH='PASTE_404_APPROVED_PATH_HERE'; CHECK_URL='PASTE_404_APPROVED_HTTPS_URL_HERE'`

`SELECTION_READY=false; REQUEST_READY=false; unset PATH_RE; fresh_route || exit 1; URL_REST="${CHECK_URL#https://}"; URL_AUTH="${URL_REST%%/*}"; URL_HOST="${URL_AUTH%%:*}"; URL_PATH="/${URL_REST#*/}"; if [ -z "$REQ_HOST" ] || [[ "$REQ_HOST" == *$'\n'* ]] || [[ ! "$REQ_PATH" =~ ^/ ]] || [ "$URL_REST" = "$CHECK_URL" ] || [ "$URL_AUTH" = "$URL_REST" ] || [ "$URL_HOST" != "$REQ_HOST" ] || { [ "$URL_PATH" != "$REQ_PATH" ] && [[ "$URL_PATH" != "$REQ_PATH"\?* ]]; }; then printf '%s\n' '중단: 승인 host/path/https URL authority 또는 형식 오류.' >&2; else PATH_RE="$(printf '%s' "$REQ_PATH"|sed 's/[][\\.^$*+?(){}|]/\\&/g')"; SELECTION_READY=true; REQUEST_READY=true; export REQ_HOST REQ_PATH CHECK_URL PATH_RE; printf 'SELECTION_READY=true REQUEST_READY=true host=%s path=%s path_regex=^%s$\n' "$REQ_HOST" "$REQ_PATH" "$PATH_RE"; fi`

Ingress는 `Exact`·`Prefix`의 표준 match만 자동 계산한다. `ImplementationSpecific`, wildcard host, rewrite 또는 regex annotation이 필요한 경우 자동 선택하지 않고 [[08. 인그레스·게이트웨이/01. Ingress·Gateway 객체/02. Ingress host·path 규칙이 기대한 backend를 선택하지 않는 경우]]로 이동한다. Gateway는 현재 HTTPRoute가 같은 namespace의 현재 Gateway를 parent로 참조하고 단일 Service backend를 갖는 범위만 자동 등록한다.

`unset RELATION_READY SERVICE SERVICE_UID SERVICE_RV SERVICE_PORT_NAME SERVICE_PORT_NUMBER TARGET_PORT; RELATION_READY=false; fresh_route || exit 1; [ "$SELECTION_READY" = true ] || exit 1; if [ "$KIND" = ingress ]; then BEST="$(jq -c --arg h "$REQ_HOST" --arg p "$REQ_PATH" '[.[]|select(.host==$h)|select(.pathType=="Exact" or .pathType=="Prefix")|select((.pathType=="Exact" and .path==$p) or (.pathType=="Prefix" and (.path=="/" or .path==$p or (.path as $base|$p|startswith($base+"/")))))]|sort_by(.path|length,if .pathType=="Exact" then 1 else 0 end)|last//empty' <<<"$TARGET_RULES")"; **EndpointSlice owner·port·Pod 후보 등록**

`ENDPOINT_READY=false; fresh_route || exit 1; [ "$RELATION_READY" = true ] || exit 1; SJSON="$(kubectl get service "$SERVICE" -n "$NS" -o json)" || exit 1; [ "$(jq -r '.metadata.uid' <<<"$SJSON")/$(jq -r '.metadata.resourceVersion' <<<"$SJSON")" = "$SERVICE_UID/$SERVICE_RV" ] || { printf '%s\n' '중단: Service UID/RV 변경, 관계 재등록.' >&2; exit 1; }; SLICE_FILE="$(mktemp)" || exit 1; if kubectl get endpointslice -n "$NS" -l "kubernetes.io/service-name=$SERVICE" -o json >"$SLICE_FILE"; then if [ -n "$SERVICE_PORT_NAME" ]; then PORT_OK="$(jq --arg su "$SERVICE_UID" --arg pn "$SERVICE_PORT_NAME" '[.items[]|select(any(.metadata.ownerReferences[]?;.kind=="Service" and .uid==$su))|.ports[]?|select((.name//"")==$pn)]|length' "$SLICE_FILE")"; elif [[ "$TARGET_PORT" =~ ^[0-9]+$ ]]; then PORT_OK="$(jq --arg su "$SERVICE_UID" --argjson tp "$TARGET_PORT" '[.items[]|select(any(.metadata.ownerReferences[]?;.kind=="Service" and .uid==$su))|.ports[]?|select(.port==$tp)]|length' "$SLICE_FILE")"; else PORT_OK=0; fi; if [ "$PORT_OK" -gt 0 ] && OUT="$(jq -r --arg su "$SERVICE_UID" '[.items[]|select(any(.metadata.ownerReferences[]?;.kind=="Service" and .uid==$su))] as $s|$s[]|"=== EndpointSlice ===\n이름/UID: \(.metadata.name)/\(.metadata.uid)\nowner: \([.metadata.ownerReferences[]?|"\(.kind)/\(.name)/\(.uid)"]|join(","))\nports: \([.ports[]?|"\(.name//"-"):\(.port//0)"]|join(","))\nPod/UID/node/ready: \([.endpoints[]?|"\(.targetRef.kind//"-")/\(.targetRef.name//"-")/\(.targetRef.uid//"-")/\(.nodeName//"-")/\(.conditions.ready//false)"]|join(";"))"' "$SLICE_FILE")" && [ -n "$OUT" ]; then ENDPOINT_READY=true; printf '%s\nENDPOINT_READY=true\n' "$OUT"; else printf '%s\n' 'NO_MATCH: current Service UID 소유 slice·port 관계가 없음. named targetPort와 unnamed Service port는 Pod mapping 확인 전 자동 확정하지 않음.' >&2; fi; else printf '%s\n' 'PRODUCER_ERROR: EndpointSlice API 실패.' >&2; fi; rm -f "$SLICE_FILE"`

### 4. backend Pod/container와 시간 선택

EndpointSlice 출력에서 실제 요청 후보 Pod와 regular container를 고른다. `ready=true`와 선언 port는 실제 process listener 또는 application 정상 증거가 아니다.

`BACKEND_POD='PASTE_404_BACKEND_POD_HERE'; BACKEND_CONTAINER='PASTE_404_BACKEND_CONTAINER_HERE'`

`unset BACKEND_READY BACKEND_POD_UID BACKEND_POD_RV BACKEND_OWNER BACKEND_NODE BACKEND_CONTAINER_ID RUNTIME_PROVIDER; BACKEND_READY=false; fresh_route || exit 1; [ "$ENDPOINT_READY" = true ] || exit 1; then BACKEND_READY=true; export BACKEND_POD BACKEND_CONTAINER BACKEND_POD_UID BACKEND_POD_RV BACKEND_OWNER BACKEND_NODE BACKEND_CONTAINER_ID RUNTIME_PROVIDER; printf 'BACKEND_READY=true Service=%s/%s -> Pod=%s/%s owner=%s -> regular-container=%s current-id=%s -> node=%s runtime-provider=%s\n' "$SERVICE" "$SERVICE_UID" "$BACKEND_POD" "$BACKEND_POD_UID" "$BACKEND_OWNER" "$BACKEND_CONTAINER" "$BACKEND_CONTAINER_ID" "$BACKEND_NODE" "$RUNTIME_PROVIDER"; else printf '%s\n' '중단: Pod owner/node/current containerID 불완전.' >&2; fi; else printf '%s\n' '중단: EndpointSlice targetRef UID 또는 regular container 관계 불일치.' >&2; fi; rm -f "$SLICE_FILE"`

`fresh_backend(){ BACKEND_FRESH_READY=false; fresh_route || return 1; [ "$BACKEND_READY" = true ] && [ "$RELATION_READY" = true ] || return 1; local sj pj su sr pu pn pc sf; sj="$(kubectl get service "$SERVICE" -n "$NS" -o json)" || return 1; su="$(jq -r '.metadata.uid//empty' <<<"$sj")"; sr="$(jq -r '.metadata.resourceVersion//empty' <<<"$sj")"; [ "$su/$sr" = "$SERVICE_UID/$SERVICE_RV" ] || return 1; pj="$(kubectl get pod "$BACKEND_POD" -n "$NS" -o json)" || return 1; pu="$(jq -r '.metadata.uid//empty' <<<"$pj")"; pn="$(jq -r '.spec.nodeName//empty' <<<"$pj")"; pc="$(jq -r --arg c "$BACKEND_CONTAINER" '[.status.containerStatuses[]?|select(.name==$c)|.containerID][0]//empty' <<<"$pj")"; [ "$pu/$pn/$pc" = "$BACKEND_POD_UID/$BACKEND_NODE/$BACKEND_CONTAINER_ID" ] || { printf '%s\n' '중단: backend Pod UID/node/current containerID 변경.' >&2; return 1; }; sf="$(mktemp)" || return 1; if kubectl get endpointslice -n "$NS" -l "kubernetes.io/service-name=$SERVICE" -o json >"$sf" && jq -e --arg su "$SERVICE_UID" --arg pu "$BACKEND_POD_UID" 'any(.items[];any(.metadata.ownerReferences[]?;.kind=="Service" and .uid==$su) and any(.endpoints[]?;.targetRef.uid==$pu))' "$sf" >/dev/null; then BACKEND_FRESH_READY=true; else printf '%s\n' '중단: current EndpointSlice→Pod UID 관계 불일치.' >&2; fi; rm -f "$sf"; [ "$BACKEND_FRESH_READY" = true ]; }`

`START_RFC3339='PASTE_404_EVIDENCE_START_UTC_HERE'; END_RFC3339='PASTE_404_EVIDENCE_END_UTC_HERE'`

`TIME_READY=false; unset START_EPOCH END_EPOCH; RX='^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$'; if [[ "$START_RFC3339" =~ $RX ]] && [[ "$END_RFC3339" =~ $RX ]] && [ "$(date -u -d "$START_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" = "$START_RFC3339" ] && [ "$(date -u -d "$END_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" = "$END_RFC3339" ]; then START_EPOCH="$(date -u -d "$START_RFC3339" +%s)"; END_EPOCH="$(date -u -d "$END_RFC3339" +%s)"; TARGET_CREATED_EPOCH="$(date -u -d "$TARGET_CREATED" +%s 2>/dev/null)"; ROUTE_CREATED_EPOCH="$TARGET_CREATED_EPOCH"; [ "$KIND" = ingress ] || ROUTE_CREATED_EPOCH="$(date -u -d "$ROUTE_CREATED" +%s 2>/dev/null)"; if [ "$START_EPOCH" -lt "$END_EPOCH" ] && [ "$TARGET_CREATED_EPOCH" -le "$END_EPOCH" ] && [ "$ROUTE_CREATED_EPOCH" -le "$END_EPOCH" ] && [ "$END_EPOCH" -le "$(date -u +%s)" ]; then TIME_READY=true; export START_RFC3339 END_RFC3339 START_EPOCH END_EPOCH; printf 'TIME_READY=true evidence=%s..%s target-created=%s route-created=%s\n' "$START_RFC3339" "$END_RFC3339" "$TARGET_CREATED" "${ROUTE_CREATED:--}"; else printf '%s\n' '중단: start<end, 객체 lifecycle, end<=현재 UTC 조건 실패.' >&2; fi; else printf '%s\n' '중단: canonical UTC RFC3339 regex/date roundtrip 실패.' >&2; fi`

**승인된 실제 GET의 transport·HTTP 분리**

`fresh_route || exit 1; [ "$REQUEST_READY" = true ] || exit 1; CODE="$(curl -sS -o /dev/null -w '%{http_code}' --connect-timeout 5 --max-time 10 "$CHECK_URL")"; RC=$?; if [ "$RC" -ne 0 ]; then printf 'PRODUCER_ERROR: curl transport/TLS rc=%s\n' "$RC" >&2; elif [[ ! "$CODE" =~ ^[0-9]{3}$ ]]; then printf 'FILTER_ERROR: HTTP code=%s\n' "$CODE" >&2; elif [ "$CODE" = 000 ]; then printf '%s\n' 'transport 실패 HTTP 000' >&2; else printf 'HTTP=%s observed=%s target-uid=%s\n' "$CODE" "$(date -u '+%Y-%m-%dT%H:%M:%SZ')" "$TARGET_UID"; fi`

요청 body, cookie, token, Authorization header와 불필요한 내부 주소는 출력·저장하지 않는다. HTTP `200`도 기대 backend나 핵심 기능을 단독 보장하지 않는다.

### 1. class·attachment·running config 경계

Ingress는 현재 `ingressClassName`, legacy annotation과 exact IngressClass `spec.controller`를 확인한다. Gateway API는 설치 CRD version에 실제 존재하는 GatewayClass·listener·HTTPRoute parent condition과 `observedGeneration`만 사용한다. status success는 running data-plane revision 또는 backend 전달을 보장하지 않는다.

`fresh_route || exit 1; if [ "$KIND" = ingress ]; then [ -n "$TARGET_CLASS" ] || { printf '%s\n' '중단: 명시 IngressClass 없음. default를 자동 선택하지 않음.' >&2; exit 1; }; kubectl get ingressclass "$TARGET_CLASS" -o custom-columns='NAME:.metadata.name,UID:.metadata.uid,RV:.metadata.resourceVersion,CONTROLLER:.spec.controller,DEFAULT:.metadata.annotations.ingressclass\.kubernetes\.io/is-default-class'; else kubectl get gatewayclasses.gateway.networking.k8s.io "$TARGET_CLASS" -o custom-columns='NAME:.metadata.name,UID:.metadata.uid,RV:.metadata.resourceVersion,CONTROLLER:.spec.controllerName' || exit 1; if GJ="$(kubectl get gateways.gateway.networking.k8s.io "$NAME" -n "$NS" -o json)" && RJ="$(kubectl get httproutes.gateway.networking.k8s.io "$ROUTE" -n "$NS" -o json)"; then jq -r '.status.conditions[]?,.status.listeners[]?.conditions[]?|"condition=\(.type)/\(.status) observed=\(.observedGeneration//"-") reason=\(.reason//"-")"' <<<"$GJ" && jq -r '.status.parents[]?|"parent=\(.parentRef.name)/\(.parentRef.sectionName//"-") controller=\(.controllerName)",(.conditions[]?|"condition=\(.type)/\(.status) observed=\(.observedGeneration//"-") reason=\(.reason//"-")")' <<<"$RJ" || printf '%s\n' 'FILTER_ERROR: Gateway/Route condition JSON 파싱 실패.' >&2; else printf '%s\n' 'PRODUCER_ERROR: Gateway/Route API 실패.' >&2; fi; fi`

condition의 `observedGeneration`이 저장한 generation과 다르거나 controller generated artifact/running revision이 미확정이면 [[08. 인그레스·게이트웨이/02. Controller/01. Ingress·Gateway controller가 리소스 변경을 반영하지 않는 경우]]와 [[08. 인그레스·게이트웨이/02. Controller/02. ### 2. host/path match와 Service 관계

`RELATION_READY=true`는 표준 Ingress match 또는 exact Gateway parent와 단일 Service backend, Service port까지 증명한다. `ENDPOINT_READY=true`는 현재 Service UID가 소유한 EndpointSlice에 관련 port가 있다는 뜻이다. endpoint `ready=true`는 backend listener와 application route 성공을 보장하지 않는다.

Service·EndpointSlice relation이 끊기면 [[06. 클러스터 네트워크/02. Service·EndpointSlice/03. Service port·targetPort로 backend에 연결되지 않는 경우]]로 이동한다. current targetRef Pod UID를 확인하지 않은 주소, 이름만 같은 재생성 Pod, 다른 Service UID의 slice를 증거에 섞지 않는다.

### 3. backend application 404 판별

backend 로그는 current regular containerID와 검증된 UTC 창에만 연결한다. 로그 producer와 end-time filter, regex match를 각각 분리한다.

`LOG_READY=false; fresh_backend || exit 1; [ "$TIME_READY" = true ] || exit 1; PR="$(printf '%s' "$REQ_PATH"|sed 's/[][\\.^$*+?(){}|]/\\&/g')"; LOG_RE="$PR|404|not found|route"; LOG_READY=true; printf 'LOG_READY=true regex=%s pod=%s uid=%s container-id=%s window=%s..%s\n' "$LOG_RE" "$BACKEND_POD" "$BACKEND_POD_UID" "$BACKEND_CONTAINER_ID" "$START_RFC3339" "$END_RFC3339"`

`fresh_backend || exit 1; [ "$LOG_READY" = true ] || exit 1; LOG_FILE="$(mktemp)" || exit 1; WINDOW_FILE="$(mktemp)" || { rm -f "$LOG_FILE"; exit 1; }; if kubectl logs "$BACKEND_POD" -n "$NS" -c "$BACKEND_CONTAINER" --timestamps --since-time="$START_RFC3339" --tail=500 >"$LOG_FILE"; then if awk -v e="$END_RFC3339" 'substr($0,1,19)<=substr(e,1,19)' "$LOG_FILE" >"$WINDOW_FILE"; then if grep -E -i -C 3 "$LOG_RE" "$WINDOW_FILE"; then printf '%s\n' 'FILTER_MATCH=true'; else GRC=$?; if [ "$GRC" -eq 1 ]; then printf '%s\n' 'NO_MATCH: producer 성공, 검증된 시간 창에 일치 로그 없음.' >&2; else printf 'FILTER_ERROR: grep rc=%s\n' "$GRC" >&2; fi; fi; else printf '%s\n' 'FILTER_ERROR: end-time 필터 실패.' >&2; fi; else printf '%s\n' 'PRODUCER_ERROR: kubectl logs 실패.' >&2; fi; rm -f "$LOG_FILE" "$WINDOW_FILE"`

같은 Pod UID·containerID에서 승인 요청 시각과 path의 404가 확인되면 application route/base-path 후보로 이관한다. no-match는 application 404 부재가 아니라 로그 미수집·형식·sampling·다른 backend 처리 후보를 남긴다. 민감한 header/body/query가 보이면 출력을 중단하고 시각·status·비민감 path만 기록한다.

### 4. 외부 listener와 404 생성 계층

객체·Service·backend 관계가 current인데 backend 수신 증거가 없으면 controller running config, 실제 listener/VIP/DNS가 다른 경로를 선택했는지 확인한다. [[09. 외부 트래픽/01. LoadBalancer·VIP/02. VIP·External IP가 할당됐지만 외부에서 연결되지 않는 경우]]와 [[09. 외부 트래픽/03. 라우팅·방화벽·Egress/01. 외부 인입 트래픽이 route·NAT·방화벽 구간에서 차단되는 경우]]로 current routing UID, host/path, 요청 UTC, 제한된 status만 전달한다.

SSH나 CRI가 필요해도 이 문서에서 기본 socket을 추측하지 않는다. 승인 node를 positional argument로 전달하고 원격 `/etc/machine-id`를 현재 Node UID/providerID 또는 승인 host inventory와 대조한다. CRI는 active kubelet endpoint와 socket provider PID 관계가 exact 검증된 node 런북에서만 사용한다.

## RBAC·audit·변경 경계

RBAC은 실제 주체에 대해 필요한 `get` verb와 `ingresses`, 설치된 `gateways`·`httproutes`, `services`, `endpointslices`, `pods`, `pods/log` subresource를 namespace·이름별로 확인한다. `kubectl auth can-i=yes`는 승인이나 실제 요청 성공을 뜻하지 않는다. audit가 필요하면 단일 auditID의 timestamp, verb, resource/subresource, namespace/name, requestURI, status와 current lifecycle UID 관계만 audit owner가 확인하며 actor 상세·token·원문을 이 문서에 저장하지 않는다.

이 문서는 mutation 명령을 제공하지 않는다. 별도 변경 절차는 실행 직전에 fresh routing/Route/Service/EndpointSlice/Pod UID·RV·owner·containerID, 직접 원인 evidence, 승인 ID와 window, 영향 host/path·tenant, controller quorum/가용 replica, 멱등성 key, 승인 원본, 중단 조건, current UID/revision에 결합한 rollback target을 명령 자체에서 재검증해야 한다. 교체 객체가 생기면 이름을 재사용하지 말고 selector·owner·creation time으로 단일 새 후보를 다시 선택해 모든 자동값과 READY를 재등록한다.

## 정상화와 증거

정상화는 `application 핵심 기능 → backend current container의 기대 응답 → EndpointSlice target UID/port → Service UID/RV/port → controller running revision·listener → host/path match와 condition → current routing/Route UID/RV` 순서로 역검증한다. 승인된 GET의 기대 status가 동등한 관찰 창 동안 유지되고 새 404·5xx·TLS 오류·Warning·reconcile 실패가 반복되지 않아야 한다. 404가 한 번 사라지거나 Pod가 Running인 것으로 닫지 않는다.

보존: UTC 창, routing/Route/Service/EndpointSlice/Pod UID·RV·owner, containerID/node, class/listener/host/path/port 관계, 비식별화 condition·Event·결정 로그, 승인·rollback·실제 기능 결과. 보존 금지: Secret data, token, private key, cookie, request/response body, 전체 로그, 불필요한 내부 주소와 audit actor 상세.
