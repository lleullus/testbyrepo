# Ingress·Gateway TLS handshake·인증서·redirect가 실패하는 경우

## 입력값과 빠른 수집

실행 host는 승인된 작업 PC 또는 bastion의 같은 Bash다. 연결 hop은 `client DNS/route → 공개 address:port → listener → TLS ClientHello SNI → certificate 선택·chain·trust → HTTP host/path → redirect Location → route/backend`다. TCP 성공, TLS handshake, 인증서 검증, HTTP status와 redirect 의미를 분리한다.

| lifecycle | 값 | 계약 |
|---|---|---|
| 최초 입력 | `CONTEXT`, `NS`, `ROUTE_KIND`, `ROUTE_NAME`, `TEST_HOST`, `TEST_PATH`, 기대 HTTP/HTTPS status·Location | exact route와 승인된 공개 host/path 및 정상 동작이다. |
| API 자동값 | route `UID/RV/generation`, listener/host/certificate reference 관계 | 전체 API 성공 뒤에만 등록한다. |
| 계산 후보 | `ROUTE_RE`, canonical UTC, endpoint 후보 | 검증 전에는 확정하지 않는다. |
| 운영자 선택값 | `PUBLIC_ENDPOINT`, `SNI`, `SECRET_NS`, `SECRET_NAME`, controller identity, 시간 | API 출력·인증서 owner·inventory를 확인한 뒤 고른다. |

`reset_tls_state; CONTEXT='PASTE_CONTEXT_HERE'; NS='PASTE_NAMESPACE_HERE'; ROUTE_KIND='PASTE_INGRESS_OR_GATEWAY_HERE'; ROUTE_NAME='PASTE_ROUTE_NAME_HERE'; TEST_HOST='PASTE_APPROVED_HOST_HERE'; TEST_PATH='PASTE_APPROVED_PATH_HERE'; EXPECTED_HTTP_STATUS='PASTE_EXPECTED_HTTP_STATUS_HERE'; EXPECTED_HTTPS_STATUS='PASTE_EXPECTED_HTTPS_STATUS_HERE'; EXPECTED_HTTP_LOCATION='PASTE_EXPECTED_HTTP_LOCATION_OR_NONE_HERE'; EXPECTED_HTTPS_LOCATION='PASTE_EXPECTED_HTTPS_LOCATION_OR_NONE_HERE'; INPUT_READY=false; if [ "$TOOLS_READY" != true ]; then printf '%s\n' '중단: TOOLS_READY가 아니다.' >&2; elif [ "$ROUTE_KIND" != ingress ] && [ "$ROUTE_KIND" != gateway ]; then printf '%s\n' '중단: ROUTE_KIND는 ingress 또는 gateway다.' >&2; elif [ -z "$CONTEXT" ] || [ -z "$NS" ] || [ -z "$ROUTE_NAME" ] || [ -z "$TEST_HOST" ] || [ -z "$TEST_PATH" ] || ! [[ "$EXPECTED_HTTP_STATUS" =~ ^[1-5][0-9][0-9]$ ]] || ! 재수집은 `reset_tls_state`로 UID·RV·owner·containerID·node·host·listener/certificate relation·time·argv/regex와 downstream gate를 전부 먼저 폐기한다. 각 `PASTE_..._HERE`는 한 번만 나타난다.

`reset_tls_state; if [ "$INPUT_READY" != true ]; then printf '%s\n' '중단: INPUT_READY가 아니다.' >&2; elif J="$(kubectl --context "$CONTEXT" get "$ROUTE_KIND" "$ROUTE_NAME" -n "$NS" -o json)" && U="$(jq -r '.metadata.uid // empty' <<<"$J")" && R="$(jq -r '.metadata.resourceVersion // empty' <<<"$J")" && [ -n "$U" ] && [ -n "$R" ]; then ROUTE_JSON="$J"; ROUTE_UID="$U"; ROUTE_RV="$R"; ROUTE_GENERATION="$(jq -r '.metadata.generation // 0' <<<"$J")"; ROUTE_OWNER="$(jq -r '[.metadata.ownerReferences[]? | "\(.kind)/\(.name)/\(.uid)"]|join(",")' <<<"$J")"; ROUTE_HOST="$(jq -r 'if .kind=="Ingress" then [.spec.tls[]?.hosts[]?]|join(",") else [.spec.listeners[]?.hostname]|join(",") end' <<<"$J")"; LISTENER_RELATION="$(jq -r 'if .kind=="Ingress" then [.spec.tls[]? | "hosts=\(.hosts|join(\",\")) secret=\(.secretName)"]|join("; ") else [.spec.listeners[]? | "listener=\(.name) host=\(.hostname // \"*\") port=\(.port) protocol=\(.protocol) refs=\([.tls.certificateRefs[]?.name]|join(\",\"))"]|join("; ") end' <<<"$J")"; ROUTE_RE="^$(printf '%s' "$ROUTE_NAME" | sed 's/[][\\.^$*+?(){}|]/\\&/g')$"; OBSERVED_AT="$(date -u '+%Y-%m-%dT%H:%M:%SZ')"; AUTO_READY=true; printf '=== TLS route ===\nUID: %s\nRV: %s\nGeneration: %s\nHost: %s\nListener/certificate 관계: %s\n관측 UTC: %s\nAUTO_READY=true\n' "$ROUTE_UID" "$ROUTE_RV" "$ROUTE_GENERATION" "$ROUTE_HOST" "$LISTENER_RELATION" "$OBSERVED_AT"; else reset_tls_state; printf '%s\n' '중단: route API/identity 실패; stale 값 없음' >&2; fi`

`tls_route_fresh(){ local j u r g; AUTO_LATEST_READY=false; j="$(kubectl --context "$CONTEXT" get "$ROUTE_KIND" "$ROUTE_NAME" -n "$NS" -o json)" || { reset_tls_state; return 1; }; u="$(jq -r '.metadata.uid // empty' <<<"$j")"; r="$(jq -r '.metadata.resourceVersion // empty' <<<"$j")"; g="$(jq -r '.metadata.generation // 0' <<<"$j")"; if [ "$u" = "$ROUTE_UID" ] && [ "$g" = "$ROUTE_GENERATION" ] && [ -n "$r" ]; then ROUTE_JSON="$j"; ROUTE_RV="$r"; AUTO_LATEST_READY=true; printf 'AUTO_LATEST_READY=true uid=%s rv=%s generation=%s\n' "$u" "$r" "$g"; return 0; else reset_tls_state; return 1; fi; }`

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | 승인된 SNI/host에서 handshake, hostname/trust/validity 또는 HTTP→HTTPS redirect가 실패한다. |
| 적용 | 공개 endpoint와 route UID/listener/certificate reference를 같은 UTC 관측으로 연결한다. |
| 제외 | handshake 뒤 `502/503`은 [[02. Ingress·Gateway 요청이 502·503을 반환하는 경우]], VIP까지 미도달은 [[09. 외부 트래픽/01. LoadBalancer·VIP/02. VIP·External IP가 할당됐지만 외부에서 연결되지 않는 경우]]다. |

검색 문자열: `handshake`, `x509`, `unknown authority`, `hostname`, `expired`, `not yet valid`, `certificateRef`, `SNI`, `Location`, `redirect loop`.

## 공개 endpoint와 certificate metadata

`PUBLIC_ENDPOINT='PASTE_PUBLIC_HOST_PORT_HERE'; SNI='PASTE_APPROVED_SNI_HERE'`

`SELECTION_READY=false; TLS_TRANSPORT_READY=false; CERT_READY=false; REDIRECT_READY=false; LOG_READY=false; NORMAL_READY=false; if [ "$AUTO_READY" != true ] || ! tls_route_fresh; then printf '%s\n' '중단: latest route gate 실패' >&2; elif [[ "$PUBLIC_ENDPOINT" =~ ^[A-Za-z0-9.-]+:[0-9]{1,5}$ ]] && [[ "$SNI" =~ ^[A-Za-z0-9.-]+$ ]]; then SELECTION_READY=true; export PUBLIC_ENDPOINT SNI; printf 'SELECTION_READY=true endpoint=%s sni=%s execution_host=%s\n' "$PUBLIC_ENDPOINT" "$SNI" "$(hostname)"; else printf '%s\n' '중단: 승인된 공개 host:port/SNI 형식 오류' >&2; fi`

`TLS_TRANSPORT_READY=false; CERT_READY=false; REDIRECT_READY=false; NORMAL_READY=false; TLS_RC=not-run; X509_RC=not-run; TMP="$(mktemp)" || exit 1; if [ "$SELECTION_READY" != true ] || ! tls_route_fresh; then printf '%s\n' '중단: latest route/selection gate 실패' >&2; elif timeout 10 openssl s_client -connect "$PUBLIC_ENDPOINT" -servername "$SNI" -verify_hostname "$SNI" -verify_return_error </dev/null >"$TMP" 2>&1; then TLS_RC=0; TLS_TRANSPORT_READY=true; if openssl x509 -in "$TMP" -noout -subject -issuer -serial -dates -ext subjectAltName; then X509_RC=0; CERT_READY=true; else X509_RC=$?; fi; else TLS_RC=$?; fi; printf 'tls_rc=%s x509_rc=%s certificate_ready=%s observed=%s\n' "$TLS_RC" "$X509_RC" "$CERT_READY" "$(date -u '+%Y-%m-%dT%H:%M:%SZ')"; rm -f "$TMP"`

TLS producer와 x509 parser status를 분리한다. handshake 실패 출력을 x509에 넘겨 나온 빈 값은 certificate 부재 증거가 아니다. `-k`, `-verify 0` 또는 trust 검증 비활성화는 사용하지 않는다. subject/issuer/serial/validity/SAN metadata만 보고 certificate body·chain·private key는 저장하지 않는다. OpenSSL trust store와 실제 client trust store가 다를 수 있으므로 같은 host의 `curl` 결과와 별도로 대조한다.

## Secret reference metadata

`SECRET_NS='PASTE_SECRET_NAMESPACE_HERE'; SECRET_NAME='PASTE_TLS_SECRET_NAME_HERE'`

`SECRET_READY=false; SECRET_LATEST_READY=false; LOG_READY=false; NORMAL_READY=false; unset SECRET_UID SECRET_RV CERT_RELATION; if [ "$AUTO_READY" != true ] || ! tls_route_fresh; then printf '%s\n' '중단: latest route gate 실패' >&2; elif ! jq -e --arg ns "$SECRET_NS" --arg n "$SECRET_NAME" --arg route_ns "$NS" 'if .kind=="Ingress" then $ns==$route_ns and any(.spec.tls[]?; .secretName==$n) else any(.spec.listeners[]?.tls.certificateRefs[]?; .name==$n and ((.namespace // $route_ns)==$ns) and ((.group // "")=="") and ((.kind // "Secret")=="Secret")) end' <<<"$ROUTE_JSON" >/dev/null; then printf '%s\n' '중단: 현재 listener의 certificateRef와 선택 Secret 불일치' >&2; elif META="$(kubectl --context "$CONTEXT" get secret "$SECRET_NAME" -n "$SECRET_NS" -o jsonpath='{.metadata.uid}{"\t"}{.metadata.resourceVersion}{"\t"}{.type}{"\t"}{.metadata.creationTimestamp}')" && IFS=$'\t' read -r SU SR ST SC <<<"$META" && [ -n "$SU" ] && [ -n "$SR" ]; then SECRET_UID="$SU"; SECRET_RV="$SR"; CERT_RELATION="$ROUTE_UID->$SECRET_NS/$SECRET_NAME/$SECRET_UID"; SECRET_READY=true; printf '=== Secret metadata ===\n이름: %s\nNamespace: %s\nUID: %s\nRV: %s\nType: %s\n생성: %s\nSECRET_READY=true relation=%s\n' "$SECRET_NAME" "$SECRET_NS" "$SECRET_UID" "$SECRET_RV" "$ST" "$SC" "$CERT_RELATION"; unset META SU SR ST SC; else unset SECRET_UID SECRET_RV CERT_RELATION; printf '%s\n' '중단: Secret metadata exact 조회 실패' >&2; fi`

`tls_secret_fresh(){ local m u; SECRET_LATEST_READY=false; m="$(kubectl --context "$CONTEXT" get secret "$SECRET_NAME" -n "$SECRET_NS" -o jsonpath='{.metadata.uid}{"\n"}{.metadata.resourceVersion}{"\n"}{.type}')" || { SECRET_READY=false; return 1; }; u="${m%%$'\n'*}"; if [ "$u" = "$SECRET_UID" ] && [ -n "$u" ]; then SECRET_RV="$(printf '%s\n' "$m" | sed -n '2p')"; SECRET_LATEST_READY=true; return 0; else SECRET_READY=false; unset SECRET_UID SECRET_RV CERT_RELATION; return 1; fi; }`

Ingress `secretName`과 Gateway `certificateRefs`의 group/kind/name/namespace 규칙을 실제 served Gateway API와 ReferenceGrant condition으로 대조한다. `.data`, `tls.crt`, `tls.key`, base64 decode, `get secret -o yaml`은 실행하지 않는다. Secret metadata 일치는 controller load·key pair·chain 정상의 증거가 아니다.

## redirect status와 Location 분리

`REDIRECT_READY=false; NORMAL_READY=false; HTTP_OK=false; HTTPS_OK=false; if [ "$SELECTION_READY" != true ] || [ "$TLS_TRANSPORT_READY" != true ] || [ "$CERT_READY" != true ] || ! tls_route_fresh; then printf '%s\n' '중단: latest route/selection/TLS/certificate gate 실패' >&2; else for SCHEME in http https; do H="$(mktemp)" || exit 1; CODE="$(curl -sS --connect-timeout 5 --max-time 10 -D "$H" -o /dev/null -w '%{http_code}' "$SCHEME://$TEST_HOST$TEST_PATH")"; RC=$?; LOCATION=''; if grep -i '^location:' "$H" >"$H.location"; then FILTER_RC=0; LOCATION="$(sed -n '1{s/^[Ll]ocation:[[:space:]]*//;s/\r$//;p;}' "$H.location")"; else FILTER_RC=$?; fi; EXPECTED_CODE="$EXPECTED_HTTPS_STATUS"; EXPECTED_LOCATION="$EXPECTED_HTTPS_LOCATION"; if [ "$SCHEME" = http ]; then EXPECTED_CODE="$EXPECTED_HTTP_STATUS"; EXPECTED_LOCATION="$EXPECTED_HTTP_LOCATION"; fi; LOCATION_OK=false; if [ "$EXPECTED_LOCATION" = NONE ] && [ -z "$LOCATION" ]; then LOCATION_OK=true; elif [ "$LOCATION" = "$EXPECTED_LOCATION" ]; then LOCATION_OK=true; fi; if [ "$RC" -eq 0 ] && [ "$CODE" = "$EXPECTED_CODE" ] && [ "$LOCATION_OK" = true ]; then [ "$SCHEME" = http ] && HTTP_OK=true || HTTPS_OK=true; fi; printf 'scheme=%s transport_rc=%s http_status=%s expected_status=%s location_match=%s filter_rc=%s observed=%s\n' "$SCHEME" "$RC" "${CODE:-000}" "$EXPECTED_CODE" "$LOCATION_OK" "$FILTER_RC" "$(date -u '+%Y-%m-%dT%H:%M:%SZ')"; rm -f "$H" "$H.location"; done; [ "$HTTP_OK" = true ] && [ "$HTTPS_OK" = true ] && REDIRECT_READY=true; fi`

`-L`로 자동 추적하지 않는다. HTTP transport 성공·status 301/302/307/308·Location scheme/host/path는 별도다. Location에 query/token/개인정보가 있으면 저장하지 않고 scheme·host·path만 기록한다. 최대 5개 승인 hop을 개별 요청해 URL 반복을 확인한다.

## controller 로그, RBAC와 strict UTC

`CTRL_NS='PASTE_CONTROLLER_NAMESPACE_HERE'; CTRL_POD='PASTE_CONTROLLER_POD_HERE'; CTRL_CONTAINER='PASTE_CONTROLLER_CONTAINER_HERE'; START_RFC3339='PASTE_START_RFC3339_HERE'; END_RFC3339='PASTE_END_RFC3339_HERE'`

`TIME_READY=false; if [[ "$START_RFC3339" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] && [[ "$END_RFC3339" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] && S_E="$(date -u -d "$START_RFC3339" +%s 2>/dev/null)" && E_E="$(date -u -d "$END_RFC3339" +%s 2>/dev/null)" && [ "$(date -u -d "$START_RFC3339" '+%Y-%m-%dT%H:%M:%SZ')" = "$START_RFC3339" ] && [ "$(date -u -d "$END_RFC3339" '+%Y-%m-%dT%H:%M:%SZ')" = "$END_RFC3339" ] && [ "$S_E" -lt "$E_E" ]; then TIME_READY=true; printf 'TIME_READY=true start=%s end=%s\n' "$START_RFC3339" "$END_RFC3339"; else printf '%s\n' '중단: canonical UTC 또는 순서 오류' >&2; fi`

`CTRL_READY=false; if [ "$TIME_READY" != true ] || ! tls_route_fresh; then printf '%s\n' '중단: time/latest route gate 실패' >&2; elif C="$(kubectl --context "$CONTEXT" get pod "$CTRL_POD" -n "$CTRL_NS" -o json)" && CU="$(jq -r '.metadata.uid // empty' <<<"$C")" && CI="$(jq -r --arg c "$CTRL_CONTAINER" '[.status.containerStatuses[]? | select(.name==$c and .state.running!=null)|.containerID][0] // empty' <<<"$C")" && [ -n "$CU" ] && [ -n "$CI" ]; then CTRL_UID="$CU"; CTRL_RV="$(jq -r '.metadata.resourceVersion' <<<"$C")"; CTRL_OWNER="$(jq -r '[.metadata.ownerReferences[]?|"\(.kind)/\(.name)/\(.uid)"]|join(",")' <<<"$C")"; CTRL_NODE="$(jq -r '.spec.nodeName' <<<"$C")"; CTRL_CONTAINER_ID="$CI"; CTRL_READY=true; printf 'CTRL_READY=true uid=%s container_id=%s node=%s owner=%s\n' "$CTRL_UID" "$CTRL_CONTAINER_ID" "$CTRL_NODE" "$CTRL_OWNER"; else printf '%s\n' '중단: controller running identity 실패' >&2; fi`

`ctrl_tls_fresh(){ local j; CTRL_LATEST_READY=false; j="$(kubectl --context "$CONTEXT" get pod "$CTRL_POD" -n "$CTRL_NS" -o json)" || return 1; jq -e --arg u "$CTRL_UID" --arg c "$CTRL_CONTAINER" --arg i "$CTRL_CONTAINER_ID" '.metadata.uid==$u and .metadata.deletionTimestamp==null and any(.status.containerStatuses[]?;.name==$c and .state.running!=null and .containerID==$i)' <<<"$j" >/dev/null || { CTRL_READY=false; LOG_READY=false; unset CTRL_UID CTRL_RV CTRL_OWNER CTRL_NODE CTRL_CONTAINER_ID; return 1; }; CTRL_LATEST_READY=true; }`

`LOG_READY=false; if [ "$CTRL_READY" != true ] || [ "$SECRET_READY" != true ] || [ "$TIME_READY" != true ] || ! tls_route_fresh || ! tls_secret_fresh || ! ctrl_tls_fresh; then printf '%s\n' '중단: latest route/Secret/controller/time gate 실패' >&2; elif AUTH="$(kubectl --context "$CONTEXT" auth can-i get pods "$CTRL_POD" --subresource=log -n "$CTRL_NS" 2>&1)" && [ "$AUTH" = yes ]; then T="$(mktemp)" || exit 1; W="$(mktemp)" || { rm -f "$T"; exit 1; }; kubectl --context "$CONTEXT" logs "$CTRL_POD" -n "$CTRL_NS" -c "$CTRL_CONTAINER" --timestamps --since-time="$START_RFC3339" --tail=300 >"$T"; P_RC=$?; if [ "$P_RC" -eq 0 ]; then awk -v end="$END_RFC3339" 'substr($1,1,19) "Z" <= end' "$T" >"$W"; W_RC=$?; else W_RC=not-run; fi; if [ "$P_RC" -eq 0 ] && [ "$W_RC" -eq 0 ]; then grep -E -i -C 3 "$ROUTE_UID|$SECRET_UID|certificate|tls|handshake|sni|redirect|location|x509" "$W"; F_RC=$?; printf 'producer_rc=%s window_rc=%s filter_rc=%s\n' "$P_RC" "$W_RC" "$F_RC"; [ "$F_RC" -le 1 ] && LOG_READY=true; else printf 'producer_rc=%s window_rc=%s filter_rc=not-run\n' "$P_RC" "$W_RC" >&2; fi; rm -f "$T" "$W"; else printf '중단: exact pods/log RBAC=%s\n' "${AUTH:--}" >&2; fi`

`filter_rc=1`은 오류 없음이 아니다. subject·`get pods/log`·namespace·Pod UID·response status·UTC 시각을 audit owner에게 확인한다. cluster-admin 부여나 TLS 검증 우회는 하지 않는다.

## 판정·변경·정상화

- handshake 전 timeout/refused는 VIP/listener 경계이며 certificate 원인으로 확정하지 않는다.
- handshake 성공 뒤 SAN/validity/trust 불일치는 certificate/client trust owner 경계다.
- SNI별 metadata가 다르면 listener hostname/certificate selection을 확인한다.
- TLS가 성공하고 redirect만 잘못되면 route filter와 application redirect를 분리한다.
- HTTPS 뒤 502/503은 2번 런북으로 이동한다.

이 문서에는 mutation 명령을 두지 않는다. 별도 변경은 fresh route/Secret/controller identity, 직접 증거, 승인 ID, window, replica/PDB/quorum, certificate 교체 멱등성·client 영향, rollback certificate/revision과 즉시 중단 조건을 충족한 승인 경로에서만 수행한다. Secret 직접 편집·삭제, controller 무조건 restart, `-k`, redirect 무조건 추가는 금지한다.

변경 후 `reset_tls_state`로 모든 파생값을 폐기하고 route·listener·Secret·controller를 완전히 재등록한다. replacement UID나 containerID가 달라지면 이전 증거를 사용하지 않는다. 실제 정상화는 같은 승인 SNI/host/path에서 TLS 검증, 기대 certificate metadata, HTTP→HTTPS Location, HTTPS status, route/backend 핵심 기능과 관찰 창의 재발 부재를 확인한다.

`NORMAL_READY=false; if [ "$SELECTION_READY" != true ] || [ "$TLS_TRANSPORT_READY" != true ] || [ "$CERT_READY" != true ] || [ "$REDIRECT_READY" != true ] || [ "$SECRET_READY" != true ] || ! tls_route_fresh || ! tls_secret_fresh; then printf '%s\n' '중단: 변경 후 전체 재등록·selection·TLS·certificate·Secret·기대 redirect latest gate 필요' >&2; else NORMAL_READY=true; printf 'NORMAL_READY=true route_uid=%s route_rv=%s secret_uid=%s observed=%s\n' "$ROUTE_UID" "$ROUTE_RV" "$SECRET_UID" "$(date -u '+%Y-%m-%dT%H:%M:%SZ')"; fi`

## Prometheus 빠른 관측

`QUERY_READY=false; if [ "$AUTO_READY" != true ] || ! tls_route_fresh; then printf '%s\n' '중단: latest route gate 실패' >&2; else QUERY_READY=true; printf 'kube_ingress_tls{namespace="%s",ingress=~"%s",tls_host="%s"}\nnginx_ingress_controller_config_last_reload_successful==0\n' "$NS" "$ROUTE_RE" "$TEST_HOST"; fi`

metric·labels가 실제 노출될 때만 사용한다. 빈 결과는 정상이나 0이 아니며 metric 미수집, label 불일치, 조회 시간 범위, Prometheus transport/HTTP/API 오류를 구분한다. certificate body·chain·SNI 선택·client trust·redirect loop는 이 metric으로 확정하지 않는다.

## 증거와 1.26 경계

UTC 시각, route UID/RV/generation, listener/host/certificateRef 관계, Secret metadata UID/type, 공개 endpoint·SNI, TLS/x509 rc, 제한된 certificate metadata, HTTP status·비민감 Location, controller UID/containerID와 producer/filter rc, 승인 기록만 보존한다. Secret data·certificate body·private key·token·cookie·개인정보는 보존하지 않는다. Gateway API와 controller/certificate manager 구현은 환경별 미검증이며 실제 인프라에서 실행하지 않았다.
