# Ingress·Gateway controller가 리소스 변경을 반영하지 않는 경우

## 입력값과 빠른 수집

실행 경로는 `승인된 작업 PC/bastion의 같은 Bash → kubectl → API server → 대상 Ingress/Gateway → controller workload → owner chain → controller Pod/container/node`다. 반영 경로는 `API watch → reconcile queue/leader → generated artifact → data-plane apply → listener/route → Service/backend`다. 이 문서는 node SSH·Linux·CRI를 직접 실행하지 않는다. 이관 시 SSH argument는 positional parameter로 전달하고 원격 hostname/machine-id를 현재 node UID/providerID와 재검증하며 `eval`을 사용하지 않는다.

| 입력 종류 | 변수 | 출처와 gate |
|---|---|---|
| 최초 입력 | `CTRL_NS`, `CTRL_KIND`, `CTRL_NAME`, `TARGET_NS`, `TARGET_KIND`, `TARGET_NAME` | 설치 기록으로 확인한 exact workload와 대상 객체다. kind allowlist를 통과해야 한다. |
| API 확인 자동값 | controller/target `UID/RV/generation`, selector, replicas, Pod owner/container/image/containerID/node, target class/condition | 필수 API가 모두 성공한 뒤만 등록한다. |
| 계산 후보값 | `SELECTOR`, `TARGET_RE`, `LOG_RE`, `PROM_QUERY` | API selector와 escaped regex 후보이며 출력 검증 전에는 확정하지 않는다. |
| 운영자 선택값 | `CTRL_POD`, `CTRL_CONTAINER`, `START_RFC3339`, `END_RFC3339`, `PROM_JOB`, `CHECK_URL`, `CHECK_HOST` | 자동 후보에서 선택하고 exact identity·시간·기능 gate를 통과한다. |

### 3. Pod/container 관계 선택

`CTRL_POD='PASTE_RECONCILE_CONTROLLER_POD_HERE'; CTRL_CONTAINER='PASTE_RECONCILE_CONTROLLER_CONTAINER_HERE'`

`unset SELECTION_READY CTRL_POD_UID CTRL_POD_RV CTRL_OWNER CTRL_NODE CTRL_CONTAINER_ID CTRL_IMAGE RUNTIME_PROVIDER; SELECTION_READY=false; fresh_pair || exit 1; if PJ="$(kubectl get pod "$CTRL_POD" -n "$CTRL_NS" -o json)" && jq -e --arg c "$CTRL_CONTAINER" 'any(.spec.containers[]?;.name==$c)' <<<"$PJ" >/dev/null; then CTRL_POD_UID="$(jq -r '.metadata.uid' <<<"$PJ")"; CTRL_POD_RV="$(jq -r '.metadata.resourceVersion' <<<"$PJ")"; CTRL_OWNER="$(jq -r '[.metadata.ownerReferences[]?|"\(.kind)/\(.name)/\(.uid)"]|join(",")' <<<"$PJ")"; CTRL_NODE="$(jq -r '.spec.nodeName//empty' <<<"$PJ")"; CTRL_CONTAINER_ID="$(jq -r --arg c "$CTRL_CONTAINER" '[.status.containerStatuses[]?|select(.name==$c)|.containerID][0]//empty' <<<"$PJ")"; CTRL_IMAGE="$(jq -r --arg c "$CTRL_CONTAINER" '.spec.containers[]|select(.name==$c)|.image' <<<"$PJ")"; RUNTIME_PROVIDER="${CTRL_CONTAINER_ID%%://*}"; if [ -n "$CTRL_POD_UID" ] && [ -n "$CTRL_OWNER" ] && [ -n "$CTRL_NODE" ] && [ -n "$CTRL_CONTAINER_ID" ] && [[ "$CTRL_CONTAINER_ID" == *://* ]]; then SELECTION_READY=true; export CTRL_POD CTRL_CONTAINER CTRL_POD_UID CTRL_POD_RV CTRL_OWNER CTRL_NODE CTRL_CONTAINER_ID CTRL_IMAGE RUNTIME_PROVIDER; printf 'SELECTION_READY=true workload=%s/%s -> Pod=%s/%s owner=%s -> container=%s id=%s runtime-provider=%s -> node=%s\n' "$CTRL_NAME" "$CTRL_UID" "$CTRL_POD" "$CTRL_POD_UID" "$CTRL_OWNER" "$CTRL_CONTAINER" "$CTRL_CONTAINER_ID" "$RUNTIME_PROVIDER" "$CTRL_NODE"; else printf '%s\n' '중단: owner/containerID/node 관계 불완전.' >&2; fi; else printf '%s\n' '중단: Pod API 실패 또는 container exact match 없음.' >&2; fi`

**controller owner chain과 current container gate**

`RELATION_READY=false; fresh_pair || exit 1; [ "$SELECTION_READY" = true ] || exit 1; PJ="$(kubectl get pod "$CTRL_POD" -n "$CTRL_NS" -o json)" || exit 1; OWNER_COUNT="$(jq '[.metadata.ownerReferences[]?|select(.controller==true)]|length' <<<"$PJ")"; [ "$OWNER_COUNT" -eq 1 ] || { printf '%s\n' '중단: controller owner가 정확히 하나가 아님.' >&2; exit 1; }; OK=false; if [ "$CTRL_KIND" = deployment ]; then RS_NAME="$(jq -r '.metadata.ownerReferences[]|select(.controller==true and .kind=="ReplicaSet")|.name//empty' <<<"$PJ")"; RS_UID="$(jq -r '.metadata.ownerReferences[]|select(.controller==true and .kind=="ReplicaSet")|.uid//empty' <<<"$PJ")"; if [ -n "$RS_NAME" ] && RSJ="$(kubectl get replicaset "$RS_NAME" -n "$CTRL_NS" -o json)" && [ "$(jq -r '.metadata.uid' <<<"$RSJ")" = "$RS_UID" ] && jq -e --arg n "$CTRL_NAME" --arg u "$CTRL_UID" 'any(.metadata.ownerReferences[]?;.controller==true and .kind=="Deployment" and .name==$n and .uid==$u)' <<<"$RSJ" >/dev/null; then OK=true; fi; else EXPECTED_KIND="$(case "$CTRL_KIND" in daemonset) printf 'DaemonSet';; statefulset) printf 'StatefulSet';; esac)"; if jq -e --arg k "$EXPECTED_KIND" --arg n "$CTRL_NAME" --arg u "$CTRL_UID" 'any(.metadata.ownerReferences[]?;.controller==true and .kind==$k and .name==$n and .uid==$u)' <<<"$PJ" >/dev/null; then OK=true; fi; fi; if [ "$OK" = true ]; then RELATION_READY=true; printf 'RELATION_READY=true controller=%s/%s -> pod=%s/%s owner=%s\n' "$CTRL_NAME" "$CTRL_UID" "$CTRL_POD" "$CTRL_POD_UID" "$CTRL_OWNER"; else printf '%s\n' '중단: Pod owner chain이 current controller UID와 불일치.' >&2; fi`

`fresh_controller_pod(){ POD_FRESH_READY=false; fresh_pair || return 1; [ "$SELECTION_READY" = true ] && [ "$RELATION_READY" = true ] || return 1; local pj pu pn pc; pj="$(kubectl get pod "$CTRL_POD" -n "$CTRL_NS" -o json)" || return 1; pu="$(jq -r '.metadata.uid//empty' <<<"$pj")"; pn="$(jq -r '.spec.nodeName//empty' <<<"$pj")"; pc="$(jq -r --arg c "$CTRL_CONTAINER" '[.status.containerStatuses[]?|select(.name==$c)|.containerID][0]//empty' <<<"$pj")"; [ "$pu/$pn/$pc" = "$CTRL_POD_UID/$CTRL_NODE/$CTRL_CONTAINER_ID" ] || { printf '%s\n' '중단: Pod UID/node/current containerID 변경, selection 재등록 필요.' >&2; return 1; }; POD_FRESH_READY=true; }`

selector에 포함된 Pod라는 사실만으로 workload 소유를 확정하지 않는다. owner UID를 workload의 실제 owner chain과 대조한다. containerID prefix는 runtime provider 관계의 한 증거일 뿐 CRI endpoint가 아니다. CRI 명령은 현재 node의 active kubelet config에서 endpoint가 exact 확인되고 그 endpoint provider가 `$RUNTIME_PROVIDER`와 맞을 때만 node/runtime 런북에서 실행한다.

## 진입 판단과 분기

검색 문자열: `generation`, `resourceVersion`, `observedGeneration`, `watch`, `reconcile`, `forbidden`, `leader`, `queue`, `rejected`, `stale`.

| 관측 | 먼저 확인 | 다음 계층 |
|---|---|---|
| target generation 미관측 | current UID/RV/generation, class/watch 범위, exact RBAC | API watch/RBAC |
| condition 실패 | observedGeneration/reason와 UID 제한 Event | 입력 참조/reconcile |
| 한 Pod만 처리 | Pod UID/start/containerID와 실제 Lease holder | leader/replica |
| reconcile 성공, artifact stale | documented revision/checksum과 target generation | [[02. Ingress·Gateway status와 실제 data plane 설정이 일치하지 않는 경우]] |
| artifact 최신, 기능 실패 | listener→Service→EndpointSlice→backend | L7/Service |

`fresh_pair || exit 1; if TJ="$(kubectl get "$TARGET_KIND" "$TARGET_NAME" -n "$TARGET_NS" -o json)"; then jq -r '"UID/RV/gen=\(.metadata.uid)/\(.metadata.resourceVersion)/\(.metadata.generation)",(.status.conditions[]?|"condition=\(.type)/\(.status) observed=\(.observedGeneration//"-") reason=\(.reason//"-") message=\(.message//""|gsub("[[:cntrl:]]";" ")|.[0:300])")' <<<"$TJ" || printf '%s\n' 'FILTER_ERROR: target status JSON 파싱 실패.' >&2; else printf '%s\n' 'PRODUCER_ERROR: target API 실패.' >&2; fi`

`resourceVersion`은 불투명 값이며 숫자 revision으로 비교하지 않는다. condition success는 generated config·data plane apply를 보장하지 않는다.

## 시간·Event·로그

`START_RFC3339='PASTE_RECONCILE_LOG_START_UTC_HERE'; END_RFC3339='PASTE_RECONCILE_LOG_END_UTC_HERE'`

`TIME_READY=false; RX='^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$'; if [[ "$START_RFC3339" =~ $RX ]] && [[ "$END_RFC3339" =~ $RX ]] && [ "$(date -u -d "$START_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" = "$START_RFC3339" ] && [ "$(date -u -d "$END_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" = "$END_RFC3339" ]; then START_EPOCH="$(date -u -d "$START_RFC3339" +%s)"; END_EPOCH="$(date -u -d "$END_RFC3339" +%s)"; TE="$(date -u -d "$TARGET_CREATED" +%s)"; if [ "$START_EPOCH" -lt "$END_EPOCH" ] && [ "$TE" -le "$END_EPOCH" ] && [ "$END_EPOCH" -le "$(date -u +%s)" ]; then TIME_READY=true; export START_RFC3339 END_RFC3339 START_EPOCH END_EPOCH; printf 'TIME_READY=true %s..%s target-created=%s\n' "$START_RFC3339" "$END_RFC3339" "$TARGET_CREATED"; else printf '%s\n' '중단: 시간/evidence lifecycle 불일치.' >&2; fi; else printf '%s\n' '중단: canonical UTC RFC3339 regex/date roundtrip 실패.' >&2; fi`

`fresh_pair || exit 1; [ "$TIME_READY" = true ] || exit 1; EVENT_FILE="$(mktemp)" || exit 1; if kubectl get events -n "$TARGET_NS" --field-selector "involvedObject.name=$TARGET_NAME,involvedObject.uid=$TARGET_UID" -o json >"$EVENT_FILE"; then if FILTERED="$(jq -r --arg s "$START_RFC3339" --arg e "$END_RFC3339" '.items[]|(.eventTime//.lastTimestamp//.metadata.creationTimestamp) as $t|select($t >= $s and $t <= $e)|"\($t) \(.type) \(.reason) \(.message|gsub("[[:cntrl:]]";" ")|.[0:300])"' "$EVENT_FILE")"; then if [ -n "$FILTERED" ]; then printf '%s\n' "$FILTERED"; else printf '%s\n' 'NO_MATCH: Event API 성공, UID·시간 창 일치 없음.' >&2; fi; else printf '%s\n' 'FILTER_ERROR: Event JSON/시간 필터 실패.' >&2; fi; else printf '%s\n' 'PRODUCER_ERROR: Event API 실패.' >&2; fi; rm -f "$EVENT_FILE"`

**로그 regex 생성·producer 수집·filter 분리**

`LOG_READY=false; fresh_pair || exit 1; [ "$SELECTION_READY" = true ] && [ "$TIME_READY" = true ] || { printf '%s\n' '중단: selection/time gate 실패.' >&2; exit 1; }; TN="$(printf '%s' "$TARGET_NAME"|sed 's/[][\\.^$*+?(){}|]/\\&/g')"; TU="$(printf '%s' "$TARGET_UID"|sed 's/[][\\.^$*+?(){}|]/\\&/g')"; LOG_RE="$TN|$TU|reconcil|watch|forbidden|denied|generation|queue|leader|rejected|stale|error|failed"; LOG_READY=true; printf 'LOG_READY=true regex=%s\n' "$LOG_RE"`

`fresh_controller_pod || exit 1; [ "$LOG_READY" = true ] || exit 1; LOG_FILE="$(mktemp)" || exit 1; WINDOW_FILE="$(mktemp)" || { rm -f "$LOG_FILE"; exit 1; }; if kubectl logs "$CTRL_POD" -n "$CTRL_NS" -c "$CTRL_CONTAINER" --timestamps --since-time="$START_RFC3339" --tail=500 >"$LOG_FILE"; then if awk -v e="$END_RFC3339" 'substr($0,1,19)<=substr(e,1,19)' "$LOG_FILE" >"$WINDOW_FILE"; then if grep -E -i -C 3 "$LOG_RE" "$WINDOW_FILE"; then printf '%s\n' 'FILTER_MATCH=true'; else GRC=$?; if [ "$GRC" -eq 1 ]; then printf '%s\n' 'NO_MATCH: 로그 producer 성공, 검증된 시간 창에 필터 일치 없음.' >&2; else printf 'FILTER_ERROR rc=%s\n' "$GRC" >&2; fi; fi; else printf '%s\n' 'FILTER_ERROR: 로그 end-time 필터 실패.' >&2; fi; else printf '%s\n' 'PRODUCER_ERROR: kubectl logs 실패.' >&2; fi; rm -f "$LOG_FILE" "$WINDOW_FILE"`

`kubectl logs`에는 end-time 옵션이 없으므로 출력 timestamp가 `$END_RFC3339` 이후면 증거에서 제외한다. 구현체 로그 timestamp가 canonical UTC가 아니면 자동 비교하지 않고 owner에게 검증된 범위를 요청한다. Secret·token·cookie·개인정보가 보이면 저장을 중단한다. exact RBAC는 `pods/log` subresource, target kind, events, leases에 대해 verb/namespace별로 확인하고 audit owner에게 UID·UTC 창을 전달한다.

## 변경 경계와 정상화

읽기 전용과 mutation을 분리한다. restart/rollout/scale/reload/patch/delete는 일반 진단 명령이 아니다. 별도 변경 절차는 실행 직전에 fresh target/controller/Pod/artifact identity, 직접 증거, 승인 ID, window, 영향 route/tenant, quorum·ready replica, 멱등성 key, 승인 원본, 중단 기준, 현재 UID/RV에 결합된 rollback target을 검증해야 한다. 교체 Pod나 artifact는 owner/containerID/node/revision/service 관계를 재등록하고 모든 READY gate를 폐기한다.

정상화는 `실제 핵심 기능 → backend/listener → data-plane revision/checksum → generated artifact → reconcile/leader → target generation/condition → current UID/RV` 순으로 역검증하며 동등한 관찰 창에서 새 error·retry·Warning이 없어야 한다. 재시작 성공이나 Pod Running, condition 한 개, HTTP 한 번으로 닫지 않는다.

보존: 대상/controller/workload/Pod UID·RV, generation, owner/containerID/node/runtime-provider 관계, verified UTC 창, Event·로그의 비식별화 결정 행, revision/checksum, exact RBAC/audit 요청, 승인·rollback·기능 결과. Secret data, token, private key, config 원문, 전체 로그는 저장하지 않는다.
