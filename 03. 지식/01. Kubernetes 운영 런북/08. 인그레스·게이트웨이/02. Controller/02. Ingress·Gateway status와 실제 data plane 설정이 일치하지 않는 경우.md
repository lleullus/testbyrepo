# Ingress·Gateway status와 실제 data plane 설정이 일치하지 않는 경우

## 입력값과 빠른 수집

실행 경로는 `승인된 작업 PC/bastion의 같은 Bash → API server의 대상 객체/status → controller workload/Pod → 문서화된 generated artifact metadata → 문서화된 data-plane revision → listener/backend → 실제 기능`이다. status 성공은 data-plane apply 성공이 아니다. 이 문서는 구현체 admin/config dump, SSH, Linux, CRI를 발명하지 않는다. 이관 시 SSH 값은 positional argument로 전달하고 원격 hostname/machine-id를 현재 node identity와 재검증하며 `eval`을 금지한다.

| 입력 종류 | 변수 | 출처와 gate |
|---|---|---|
| 최초 입력 | `NS`, `KIND`, `NAME`, `CTRL_NS`, `CTRL_KIND`, `CTRL_NAME` | exact 대상과 설치 기록의 controller workload다. kind allowlist를 통과한다. |
| API 확인 자동값 | 대상/controller UID·RV·generation·condition, selector, Pod owner/containerID/node, artifact UID·RV | 모든 필수 API 성공 후만 등록한다. |
| 계산 후보값 | `TARGET_RE`, `SELECTOR`, `LOG_RE`, `PROM_QUERY` | API selector 및 escaped query/regex다. |
| 운영자 선택값 | `CTRL_POD`, `CTRL_CONTAINER`, `ART_NS`, `ART_KIND`, `ART_NAME`, `REV_KEY`, `SUM_KEY`, 시간 창·job·URL/Host | 구현체 문서와 후보 출력으로 선택하고 exact 조회한다. |

## 진입 판단과 분기

검색 문자열: `Accepted`, `Programmed`, `observedGeneration`, `generation`, `resourceVersion`, `revision`, `checksum`, `stale`, `applied`, `NACK`.

| 관측 | 성공이 보장하는 범위 | 다음 행동 |
|---|---|---|
| condition observedGeneration이 과거 | status가 current spec을 아직 보지 않음 | controller watch/reconcile 런북 |
| status current, artifact revision 과거 | status 게시와 artifact 생성 불일치 | controller owner |
| artifact current, replica별 apply 표식 불일치 | 생성 성공, 전파/apply 실패 후보 | data-plane owner |
| revision 일치, 실제 404/5xx/TLS | metadata 일치만 확인 | L7/Service/backend owner |

`fresh_pair || exit 1; if TJ="$(kubectl get "$KIND" "$NAME" -n "$NS" -o json)"; then jq -r '"UID/RV/gen=\(.metadata.uid)/\(.metadata.resourceVersion)/\(.metadata.generation)",(.status.conditions[]?|"condition=\(.type)/\(.status) observed=\(.observedGeneration//"-") reason=\(.reason//"-")")' <<<"$TJ" || printf '%s\n' 'FILTER_ERROR: target status JSON 파싱 실패.' >&2; else printf '%s\n' 'PRODUCER_ERROR: target API 실패.' >&2; fi`

Ingress status address와 Gateway `Programmed=True`는 실제 proxy running config revision이 아니다. 구현체가 read-only running revision을 문서화하지 않으면 config dump/admin 명령을 추측하지 않고 미확정으로 이관한다.

## 시간·Event·로그

`START_RFC3339='PASTE_DATAPLANE_LOG_START_UTC_HERE'; END_RFC3339='PASTE_DATAPLANE_LOG_END_UTC_HERE'`

`TIME_READY=false; RX='^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$'; if [[ "$START_RFC3339" =~ $RX ]] && [[ "$END_RFC3339" =~ $RX ]] && [ "$(date -u -d "$START_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" = "$START_RFC3339" ] && [ "$(date -u -d "$END_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" = "$END_RFC3339" ]; then START_EPOCH="$(date -u -d "$START_RFC3339" +%s)"; END_EPOCH="$(date -u -d "$END_RFC3339" +%s)"; TE="$(date -u -d "$TARGET_CREATED" +%s)"; if [ "$START_EPOCH" -lt "$END_EPOCH" ] && [ "$TE" -le "$END_EPOCH" ] && [ "$END_EPOCH" -le "$(date -u +%s)" ]; then TIME_READY=true; export START_RFC3339 END_RFC3339 START_EPOCH END_EPOCH; printf 'TIME_READY=true %s..%s target-created=%s\n' "$START_RFC3339" "$END_RFC3339" "$TARGET_CREATED"; else printf '%s\n' '중단: time/evidence lifecycle 불일치.' >&2; fi; else printf '%s\n' '중단: canonical UTC RFC3339 regex/date roundtrip 실패.' >&2; fi`

`LOG_READY=false; fresh_pair || exit 1; [ "$SELECTION_READY" = true ] && [ "$ARTIFACT_READY" = true ] && [ "$TIME_READY" = true ] || exit 1; NR="$(printf '%s' "$NAME"|sed 's/[][\\.^$*+?(){}|]/\\&/g')"; UR="$(printf '%s' "$TARGET_UID"|sed 's/[][\\.^$*+?(){}|]/\\&/g')"; RR="$(printf '%s' "$REVISION"|sed 's/[][\\.^$*+?(){}|]/\\&/g')"; LOG_RE="$NR|$UR|$RR|generation|revision|checksum|applied|stale|reconcil|NACK|error|failed"; LOG_READY=true; printf 'LOG_READY=true regex=%s\n' "$LOG_RE"`

`fresh_artifact || exit 1; [ "$LOG_READY" = true ] || exit 1; LOG_FILE="$(mktemp)" || exit 1; WINDOW_FILE="$(mktemp)" || { rm -f "$LOG_FILE"; exit 1; }; if kubectl logs "$CTRL_POD" -n "$CTRL_NS" -c "$CTRL_CONTAINER" --timestamps --since-time="$START_RFC3339" --tail=500 >"$LOG_FILE"; then if awk -v e="$END_RFC3339" 'substr($0,1,19)<=substr(e,1,19)' "$LOG_FILE" >"$WINDOW_FILE"; then if grep -E -i -C 3 "$LOG_RE" "$WINDOW_FILE"; then printf '%s\n' 'FILTER_MATCH=true'; else GRC=$?; [ "$GRC" -eq 1 ] && printf '%s\n' 'NO_MATCH: producer 성공, 검증된 시간 창에 필터 일치 없음.' >&2 || printf 'FILTER_ERROR rc=%s\n' "$GRC" >&2; fi; else printf '%s\n' 'FILTER_ERROR: 로그 end-time 필터 실패.' >&2; fi; else printf '%s\n' 'PRODUCER_ERROR: kubectl logs 실패.' >&2; fi; rm -f "$LOG_FILE" "$WINDOW_FILE"`

end 이후 timestamp는 증거에서 제외한다. producer/API 실패, no match, filter error를 분리하고 빈 결과를 성공으로 보지 않는다. exact RBAC는 target, controller workload, Pod, `pods/log`, artifact metadata, Event/Lease별로 확인한다. audit 요청에는 exact UID·verb·resource·namespace·UTC 창만 전달한다.

## 변경 경계·정상화

읽기 전용과 mutation을 분리한다. 별도 변경은 fresh target/controller/Pod/artifact/data-plane relation, 직접 증거, 승인 ID, window, tenant 영향, quorum/ready replica, 멱등성 key, 승인 원본, 중단 조건, 현재 UID/RV에 결합된 rollback target을 실행 직전에 검증한다. data plane을 직접 편집하지 않는다. 교체 객체·Pod는 owner/containerID/node/revision/Service 관계와 READY gate를 전부 재등록한다.

정상화는 `핵심 기능 → listener/backend → 모든 relevant data-plane replica revision → artifact revision/checksum → controller reconcile → current status observedGeneration → target UID/RV` 순으로 역검증하고 동등한 관찰 창에서 stale/NACK/Warning 재발이 없어야 한다. status, checksum 또는 HTTP 한 번만으로 닫지 않는다.

보존: exact UID/RV/generation, owner/containerID/node/runtime-provider, verified UTC, metadata revision/checksum, 비식별화 Event/log, exact RBAC/audit, 승인·rollback·기능 결과. Secret data/config 원문, token, cookie, private key, 전체 로그는 저장하지 않는다.
