# Ingress가 controller에 선택되지 않거나 ADDRESS가 갱신되지 않는 경우

## 입력값과 빠른 수집

실행 경로는 `승인된 작업 PC 또는 bastion의 같은 Bash → kubectl → API server → Ingress·IngressClass`다. 실제 기능 확인은 `같은 실행 host의 curl → DNS/VIP → controller listener → Service → EndpointSlice → backend`이며 한 hop의 성공은 다음 hop의 성공을 보장하지 않는다. 이 문서는 node·kubelet·CRI·Linux 또는 SSH 진단을 실행하지 않는다. 후속 이관에서 SSH가 필요하면 대상 host를 positional argument로 전달하고 원격 `hostname`과 machine-id를 승인된 node identity와 다시 대조하며 `eval`을 사용하지 않는다.

| 입력 종류 | 변수 | 출처와 gate |
|---|---|---|
| 최초 입력 | `NS`, `ING` | 운영자가 namespace와 exact Ingress 이름을 한 번 입력하고 exact-name API 조회를 통과한다. |
| API 확인 자동값 | `ING_UID`, `ING_RV`, `ING_GEN`, `ING_CLASS`, `LEGACY_CLASS`, `ING_OWNER`, `ING_CREATED`, `ADDRESS` | 현재 Ingress JSON에서만 등록한다. API 실패 시 모두 비운다. |
| 계산 후보값 | `ING_RE`, `PROM_QUERY` | 이름을 regex/PromQL 문자열로 escape한 후보이며 출력 확인 전 확정하지 않는다. |
| 운영자 선택값 | `START_RFC3339`, `END_RFC3339`, `PROM_JOB`, `CHECK_URL`, `CHECK_HOST` | 증거 창·실제 Prometheus job·승인된 비민감 GET 대상이다. 별도 검증 후 사용한다. |

### 1. 실행 위치·도구·최초 입력

**도구 확인**

`TOOLS_READY=false; MISSING=''; for T in kubectl jq sed grep date curl mktemp; do command -v "$T" >/dev/null 2>&1 || MISSING="$MISSING $T"; done; if [ -n "${BASH_VERSION:-}" ] && [ -z "$MISSING" ]; then TOOLS_READY=true; printf 'TOOLS_READY=true bash=%s host=%s\n' "$BASH_VERSION" "$(hostname)"; else printf '중단: Bash 또는 도구 누락:%s\n' "$MISSING" >&2; fi`

**최초 입력과 전체 lifecycle 초기화**

`unset INPUT_READY AUTO_READY TIME_READY QUERY_READY REQUEST_READY FRESH_READY ING_UID ING_RV ING_GEN ING_CLASS LEGACY_CLASS ING_OWNER ING_CREATED ADDRESS ING_RE PROM_QUERY START_RFC3339 END_RFC3339 START_EPOCH END_EPOCH PROM_JOB CHECK_URL CHECK_HOST CLASS_UID CLASS_RV CLASS_CONTROLLER CLASS_DEFAULT EVENT_FILE LOG_FILE POD_UID NODE CONTAINER CONTAINER_ID CRI_ENDPOINT RUNTIME_PROVIDER SERVICE_UID ENDPOINTSLICE_UID HOST_ID RELATION_READY APPROVAL_ID CHANGE_WINDOW QUORUM_OK IDEMPOTENCE_KEY ROLLBACK_TARGET; NS='PASTE_INGRESS_NAMESPACE_HERE'; ING='PASTE_INGRESS_NAME_HERE'; INPUT_READY=false; if [ "$TOOLS_READY" != true ]; then printf '%s\n' '중단: TOOLS_READY가 아니다.' >&2; elif [ -z "$NS" ] || [ -z "$ING" ]; then printf '%s\n' '중단: 최초 입력이 비었다.' >&2; elif kubectl get ingress "$ING" -n "$NS" >/dev/null 2>&1; then INPUT_READY=true; export NS ING; printf 'INPUT_READY=true namespace=%s ingress=%s\n' "$NS" "$ING"; else printf '중단: exact Ingress 조회 실패 namespace=%s ingress=%s\n' "$NS" "$ING" >&2; fi`

`INPUT_READY=true`가 아니면 namespace·이름·현재 주체의 `get ingresses.networking.k8s.io` 권한을 확인하고 중단한다.

### 2. 자동값 재수집

재수집 때는 모든 downstream identity·resourceVersion·owner·containerID·node·host·관계·시간·argv/regex와 READY gate를 먼저 지운다. 필수 API가 하나라도 실패하면 과거 값은 유효하지 않다.

**현재 identity 등록**

`unset AUTO_READY TIME_READY QUERY_READY REQUEST_READY FRESH_READY ING_UID ING_RV ING_GEN ING_CLASS LEGACY_CLASS ING_OWNER ING_CREATED ADDRESS ING_RE PROM_QUERY START_RFC3339 END_RFC3339 START_EPOCH END_EPOCH PROM_JOB CHECK_URL CHECK_HOST CLASS_UID CLASS_RV CLASS_CONTROLLER CLASS_DEFAULT EVENT_FILE POD_UID NODE CONTAINER CONTAINER_ID CRI_ENDPOINT RUNTIME_PROVIDER SERVICE_UID ENDPOINTSLICE_UID HOST_ID RELATION_READY; AUTO_READY=false; if [ "$INPUT_READY" != true ]; then printf '%s\n' '중단: INPUT_READY가 아니다.' >&2; elif J="$(kubectl get ingress "$ING" -n "$NS" -o json)"; then U="$(jq -r '.metadata.uid // empty' <<<"$J")"; R="$(jq -r '.metadata.resourceVersion // empty' <<<"$J")"; G="$(jq -r '.metadata.generation // empty' <<<"$J")"; C="$(jq -r '.spec.ingressClassName // empty' <<<"$J")"; L="$(jq -r '.metadata.annotations["kubernetes.io/ingress.class"] // empty' <<<"$J")"; O="$(jq -r '[.metadata.ownerReferences[]? | "\(.kind)/\(.name)/\(.uid)"] | join(",")' <<<"$J")"; T="$(jq -r '.metadata.creationTimestamp // empty' <<<"$J")"; A="$(jq -r '[.status.loadBalancer.ingress[]? | (.ip // .hostname // empty)] | join(",")' <<<"$J")"; if [ -n "$U" ] && [ -n "$R" ] && [ -n "$G" ] && [ -n "$T" ]; then ING_UID="$U"; ING_RV="$R"; ING_GEN="$G"; ING_CLASS="$C"; LEGACY_CLASS="$L"; ING_OWNER="$O"; ING_CREATED="$T"; ADDRESS="$A"; ING_RE="$(printf '%s' "$ING" | sed 's/[][\\.^$*+?(){}|]/\\&/g')"; AUTO_READY=true; export ING_UID ING_RV ING_GEN ING_CLASS LEGACY_CLASS ING_OWNER ING_CREATED ADDRESS ING_RE; printf 'AUTO_READY=true\nIngress: %s\nUID: %s\nresourceVersion/generation: %s/%s\nclass/legacy: %s/%s\nowner(kind/name/uid): %s\nADDRESS: %s\n생성 시각: %s\nregex 후보: ^%s$\n' "$ING" "$ING_UID" "$ING_RV" "$ING_GEN" "${ING_CLASS:--}" "${LEGACY_CLASS:--}" "${ING_OWNER:--}" "${ADDRESS:--}" "$ING_CREATED" "$ING_RE"; else printf '%s\n' '중단: 현재 identity 필드가 불완전하다.' >&2; fi; else printf '%s\n' '중단: Ingress API 실패, 이전 자동값은 폐기됨.' >&2; fi`

현재 owner가 비어 있는 것은 허용되지만 owner가 있다는 뜻으로 보충하지 않는다. 다음 helper는 모든 후속 Kubernetes 명령 직전에 UID와 resourceVersion을 재검증한다.

**fresh identity gate 등록**

`fresh_ing(){ FRESH_READY=false; [ "$AUTO_READY" = true ] || { printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; return 1; }; local j u r; j="$(kubectl get ingress "$ING" -n "$NS" -o json)" || { printf '%s\n' '중단: fresh Ingress API 실패.' >&2; return 1; }; u="$(jq -r '.metadata.uid // empty' <<<"$j")"; r="$(jq -r '.metadata.resourceVersion // empty' <<<"$j")"; [ "$u" = "$ING_UID" ] && [ "$r" = "$ING_RV" ] || { printf '중단: identity/RV 변경 old=%s/%s new=%s/%s, 재수집 필요\n' "$ING_UID" "$ING_RV" "$u" "$r" >&2; return 1; }; FRESH_READY=true; }`

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | 기대 controller가 Ingress를 선택하지 않거나 `status.loadBalancer.ingress`가 비었거나 stale인 경우 |
| 적용 | 현재 UID/RV의 class·legacy annotation·IngressClass controller·Event와 status를 같은 시간 창에서 비교할 수 있는 경우 |
| 제외 | host/path는 [[02. Ingress host·path 규칙이 기대한 backend를 선택하지 않는 경우]], Gateway API는 [[03. Gateway·HTTPRoute가 Accepted·Programmed되지 않거나 연결되지 않는 경우]], 실제 404는 [[08. 인그레스·게이트웨이/03. L7 라우팅·Backend·TLS/01. Ingress·Gateway 요청이 404를 반환하는 경우]]로 이동한다. |

검색 문자열: `ingressClassName`, `kubernetes.io/ingress.class`, `IngressClass`, `spec.controller`, `status.loadBalancer`, `ADDRESS`, `forbidden`.

## 읽기 전용 진단

**현재 Ingress 상태**

`fresh_ing || exit 1; kubectl get ingress "$ING" -n "$NS" -o custom-columns='NAME:.metadata.name,UID:.metadata.uid,RV:.metadata.resourceVersion,GENERATION:.metadata.generation,CLASS:.spec.ingressClassName,ADDRESS-IP:.status.loadBalancer.ingress[*].ip,ADDRESS-HOST:.status.loadBalancer.ingress[*].hostname,CREATED:.metadata.creationTimestamp'`

성공 gate는 저장한 UID/RV와 출력이 같다는 것이다. ADDRESS가 비어 있어도 명령 성공일 뿐 정상은 아니다.

**IngressClass 관계 등록**

`unset CLASS_UID CLASS_RV CLASS_CONTROLLER CLASS_DEFAULT RELATION_READY; RELATION_READY=false; fresh_ing || exit 1; if [ -z "$ING_CLASS" ]; then printf '%s\n' '중단: 명시 class 없음. default 후보를 자동 선택하지 않는다.' >&2; elif CJSON="$(kubectl get ingressclass "$ING_CLASS" -o json)"; then CLASS_UID="$(jq -r '.metadata.uid // empty' <<<"$CJSON")"; CLASS_RV="$(jq -r '.metadata.resourceVersion // empty' <<<"$CJSON")"; CLASS_CONTROLLER="$(jq -r '.spec.controller // empty' <<<"$CJSON")"; CLASS_DEFAULT="$(jq -r '.metadata.annotations["ingressclass.kubernetes.io/is-default-class"] // "false"' <<<"$CJSON")"; if [ -n "$CLASS_UID" ] && [ -n "$CLASS_RV" ] && [ -n "$CLASS_CONTROLLER" ]; then RELATION_READY=true; export CLASS_UID CLASS_RV CLASS_CONTROLLER CLASS_DEFAULT; printf 'RELATION_READY=true ingress=%s/%s -> class=%s/%s -> controller=%s default=%s\n' "$ING" "$ING_UID" "$ING_CLASS" "$CLASS_UID" "$CLASS_CONTROLLER" "$CLASS_DEFAULT"; else printf '%s\n' '중단: IngressClass identity/controller 불완전.' >&2; fi; else printf '%s\n' '중단: IngressClass API 실패.' >&2; fi`

`RELATION_READY=true`는 선언된 선택 관계만 증명한다. controller workload가 실제로 watch/reconcile하거나 status를 썼다는 증거는 아니다. 명시 class가 없으면 `fresh_ing` 후 `kubectl get ingressclass`로 default 후보를 사람이 확인하되 정확히 하나라는 설치 계약 없이는 선택하지 않는다.

### 시간 창과 Event

**운영자 시간 입력**

`START_RFC3339='PASTE_INGRESS_EVENT_START_UTC_HERE'; END_RFC3339='PASTE_INGRESS_EVENT_END_UTC_HERE'`

**UTC RFC3339 검증**

`TIME_READY=false; unset START_EPOCH END_EPOCH; RX='^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$'; if [[ "$START_RFC3339" =~ $RX ]] && [[ "$END_RFC3339" =~ $RX ]] && [ "$(date -u -d "$START_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" = "$START_RFC3339" ] && [ "$(date -u -d "$END_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" = "$END_RFC3339" ]; then START_EPOCH="$(date -u -d "$START_RFC3339" +%s)"; END_EPOCH="$(date -u -d "$END_RFC3339" +%s)"; CREATED_EPOCH="$(date -u -d "$ING_CREATED" +%s 2>/dev/null)"; if [ "$START_EPOCH" -lt "$END_EPOCH" ] && [ -n "$CREATED_EPOCH" ] && [ "$CREATED_EPOCH" -le "$END_EPOCH" ] && [ "$END_EPOCH" -le "$(date -u +%s)" ]; then TIME_READY=true; export START_RFC3339 END_RFC3339 START_EPOCH END_EPOCH; printf 'TIME_READY=true start=%s end=%s evidence-created=%s\n' "$START_RFC3339" "$END_RFC3339" "$ING_CREATED"; else printf '%s\n' '중단: start<end, 객체 생성 시각<=end, end<=현재 UTC를 만족하지 않음.' >&2; fi; else printf '%s\n' '중단: canonical UTC RFC3339 roundtrip 실패.' >&2; fi`

**UID와 시간으로 제한한 Event**

`fresh_ing || exit 1; [ "$TIME_READY" = true ] || { printf '%s\n' '중단: TIME_READY가 아니다.' >&2; exit 1; }; EVENT_FILE="$(mktemp)" || exit 1; if kubectl get events -n "$NS" --field-selector "involvedObject.kind=Ingress,involvedObject.name=$ING,involvedObject.uid=$ING_UID" -o json >"$EVENT_FILE"; then if FILTERED="$(jq -r --arg s "$START_RFC3339" --arg e "$END_RFC3339" '.items[] | (.eventTime // .lastTimestamp // .metadata.creationTimestamp) as $t | select($t >= $s and $t <= $e) | "\($t) \(.type) \(.reason) \(.message|gsub("[[:cntrl:]]";" ")|.[0:300])"' "$EVENT_FILE")"; then if [ -n "$FILTERED" ]; then printf '%s\n' "$FILTERED"; else printf '%s\n' 'NO_MATCH: Event API 성공, 검증된 시간 창에 일치 항목 없음.' >&2; fi; else printf '%s\n' 'FILTER_ERROR: Event JSON 파싱 또는 시간 필터 실패.' >&2; fi; else printf '%s\n' 'PRODUCER_ERROR: Event API 조회 실패.' >&2; fi; rm -f "$EVENT_FILE"`

여기서 `kubectl` 실패는 producer/API 실패, `jq` nonzero는 parser/filter 오류, `NO_MATCH`는 성공한 수집에 일치 Event가 없음이다. 셋을 정상·오류 없음으로 합치지 않는다. `Forbidden`이면 현재 주체에 대해 `kubectl auth can-i get events -n "$NS"`와 `kubectl auth can-i get ingresses.networking.k8s.io -n "$NS"`를 각각 확인한다. audit가 필요하면 audit owner에게 정확한 verb/resource/namespace/name/UID와 검증된 UTC 창을 전달하며 audit 원문·token을 이 문서에서 수집하지 않는다.

## Prometheus 보조 관측

구현체 exporter의 실제 job을 확인한 뒤에만 사용한다. 빈 결과는 성공이 아니다.

`PROM_JOB='PASTE_INGRESS_PROMETHEUS_JOB_HERE'; QUERY_READY=false; if ! fresh_ing; then printf '%s\n' '중단: current Ingress identity가 아니다.' >&2; elif [ -z "$PROM_JOB" ] || [[ "$PROM_JOB" == *$'\n'* ]]; then printf '%s\n' '중단: PROM_JOB이 유효하지 않음.' >&2; else PJ="${PROM_JOB//\\/\\\\}"; PJ="${PJ//\"/\\\"}"; NQ="${NS//\\/\\\\}"; NQ="${NQ//\"/\\\"}"; IQ="${ING//\\/\\\\}"; IQ="${IQ//\"/\\\"}"; PROM_QUERY="sum(rate(nginx_ingress_controller_requests{job=\"$PJ\",namespace=\"$NQ\",ingress=\"$IQ\"}[5m])) by (status)"; QUERY_READY=true; export PROM_QUERY; printf 'QUERY_READY=true PromQL=%s\n' "$PROM_QUERY"; fi`

이 metric과 `namespace`·`ingress` label을 실제 exporter가 노출하는 경우에만 생성된 한 줄을 Prometheus/Grafana에 붙여 넣는다. query API의 HTTP status, JSON, `.status=="success"`, non-empty `.data.result`를 차례로 확인하며 빈 결과를 0이나 정상으로 해석하지 않는다.

## 승인된 실제 기능 확인

`CHECK_URL='PASTE_INGRESS_APPROVED_HTTPS_URL_HERE'; CHECK_HOST='PASTE_INGRESS_APPROVED_HOST_HERE'; REQUEST_READY=false; if [ "$AUTO_READY" != true ] || [[ ! "$CHECK_URL" =~ ^https://[^/?#]+/ ]] || [ -z "$CHECK_HOST" ] || [ "${CHECK_URL#https://}" = "$CHECK_URL" ] || [ "${CHECK_URL#https://}" = "${CHECK_URL#https://$CHECK_HOST}" ]; then printf '%s\n' '중단: 승인된 https URL/Host 관계를 확인한다.' >&2; else REQUEST_READY=true; export CHECK_URL CHECK_HOST; printf 'REQUEST_READY=true host=%s\n' "$CHECK_HOST"; fi`

`fresh_ing || exit 1; [ "$REQUEST_READY" = true ] || { printf '%s\n' '중단: REQUEST_READY가 아니다.' >&2; exit 1; }; CODE="$(curl -sS -o /dev/null -w '%{http_code}' --connect-timeout 5 --max-time 10 -H "Host: $CHECK_HOST" "$CHECK_URL")"; RC=$?; if [ "$RC" -ne 0 ]; then printf 'transport/TLS 실패 rc=%s\n' "$RC" >&2; elif [[ ! "$CODE" =~ ^[0-9]{3}$ ]]; then printf 'filter 오류 code=%s\n' "$CODE" >&2; elif [ "$CODE" = 000 ]; then printf '%s\n' 'transport 실패 HTTP 000' >&2; else printf 'HTTP=%s observed=%s\n' "$CODE" "$(date -u '+%Y-%m-%dT%H:%M:%SZ')"; fi`

`2xx`도 기대 backend·핵심 기능과 status writer를 단독 증명하지 않는다. body, 전체 header, token, cookie, Secret, 내부 주소는 저장하지 않는다.

## 관측별 진단 경로

| 지금 보이는 것 | 먼저 볼 것 | 다음 owner |
|---|---|---|
| class 없음·불일치 | 현재 UID/RV의 spec/legacy와 exact IngressClass controller | 객체/class owner |
| class 관계 정상, ADDRESS 비어 있음 | UID 제한 Event와 controller status-update RBAC/reconcile | [[08. 인그레스·게이트웨이/02. Controller/01. Ingress·Gateway controller가 리소스 변경을 반영하지 않는 경우]] |
| ADDRESS stale·불일치 | status와 승인된 VIP/DNS identity 및 갱신 시각 | 외부 LB/VIP owner |
| ADDRESS 정상, 실제 요청 실패 | 요청 hop, route, Service·EndpointSlice·backend | L7/Service owner |

## 변경 절차 경계

읽기 전용 진단과 mutation을 섞지 않는다. 이 문서는 `patch`, `apply`, `delete`, restart/reload 명령을 제공하지 않는다. 별도 변경 절차는 실행 직전에 fresh UID/RV, 직접 원인 증거, 승인 ID, 변경 window, 영향받는 tenant/route, HA quorum 또는 가용 replica, 멱등성 key, 승인된 원본, 중단 기준과 **현재 UID/RV에 결합된 rollback target**을 모두 재검증해야 한다. 교체 객체가 생기면 새 UID/RV와 Ingress→IngressClass→controller→Service→EndpointSlice→backend 관계를 전부 재등록하며 과거 READY gate를 재사용하지 않는다.

정확한 RBAC gate는 계획한 verb별 `kubectl auth can-i` 결과와 실제 요청 결과를 함께 보존한다. `can-i=yes`는 승인이나 요청 성공을 뜻하지 않는다. 변경 window 종료, quorum 저하, 새 5xx·다른 route 영향 또는 rollback target 불일치 시 추가 mutation을 중단한다.

## 정상화와 증거

정상화는 역순으로 확인한다: 승인된 핵심 기능 → 실제 HTTP 결과 → backend/Service/EndpointSlice → controller running relation → status ADDRESS → 현재 Ingress UID/RV와 class 관계. 증상이 발생했던 관찰 창과 동등한 창에서 새 Warning·status-update 실패·기능 오류가 반복되지 않아야 한다. ADDRESS만 채워지거나 HTTP 한 번이 성공한 것으로 닫지 않는다.

보존: UTC 창, Ingress UID/RV/generation, owner, class/legacy, IngressClass UID/RV/controller, 비식별화 Event reason, status 주소, 승인 ID·변경·rollback·기능 결과. 보존 금지: Secret data, token, 인증서 개인키, cookie, request body, 전체 로그와 불필요한 내부 주소.
