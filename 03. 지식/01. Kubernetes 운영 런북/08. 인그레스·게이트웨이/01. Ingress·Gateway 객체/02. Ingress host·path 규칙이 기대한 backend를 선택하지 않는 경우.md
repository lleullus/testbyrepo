# Ingress host·path 규칙이 기대한 backend를 선택하지 않는 경우

## 입력값과 빠른 수집

실행 경로는 `승인된 작업 PC 또는 bastion의 같은 Bash → kubectl → API server → Ingress → Service → EndpointSlice → Pod UID/container/node`다. 기능 경로는 `같은 host의 curl → DNS/VIP → controller listener → host/path match → Service port → endpoint port → backend listener/application`이다. 이 문서에서는 SSH·node Linux·CRI를 실행하지 않는다. 이관 후 SSH가 필요하면 인자를 positional argument로 안전하게 넘기고 원격 `hostname`·machine-id를 승인된 node와 재대조하며 `eval`을 금지한다.

| 입력 종류 | 변수 | 출처와 유효성 gate |
|---|---|---|
| 최초 입력 | `NS`, `ING` | 운영자가 exact namespace/name을 한 번 입력하고 Ingress API 조회를 통과한다. |
| API 확인 자동값 | `ING_UID`, `ING_RV`, `ING_GEN`, `ING_CLASS`, `ING_OWNER`, `ING_CREATED`, `RULES_JSON` | 현재 Ingress JSON에서만 등록한다. |
| 계산 후보값 | `ING_RE`, `HOST_RE`, `PROM_QUERY` | regex·PromQL escape 결과이며 bounded 출력 뒤 사용한다. |
| 운영자 선택값 | `REQ_HOST`, `REQ_PATH`, `START_RFC3339`, `END_RFC3339`, `PROM_JOB`, `CHECK_URL` | 승인된 실제 요청과 증거 창에서 선택하고 검증한다. |

### 2. 자동값 재수집과 fresh gate

**재수집**

`unset AUTO_READY SELECTION_READY TIME_READY RELATION_READY QUERY_READY REQUEST_READY FRESH_READY ING_UID ING_RV ING_GEN ING_CLASS ING_OWNER ING_CREATED RULES_JSON ING_RE HOST_RE PROM_QUERY REQ_HOST REQ_PATH START_RFC3339 END_RFC3339 START_EPOCH END_EPOCH PROM_JOB CHECK_URL SERVICE SERVICE_UID SERVICE_RV SERVICE_PORT_NAME SERVICE_PORT_NUMBER TARGET_PORT ENDPOINTSLICE_UID BACKEND_POD BACKEND_POD_UID BACKEND_NODE BACKEND_CONTAINER BACKEND_CONTAINER_ID OWNER_UID NODE HOST_ID CRI_ENDPOINT RUNTIME_PROVIDER ARGV_RE; AUTO_READY=false; if [ "$INPUT_READY" != true ]; then printf '%s\n' '중단: INPUT_READY가 아니다.' >&2; elif J="$(kubectl get ingress "$ING" -n "$NS" -o json)"; then U="$(jq -r '.metadata.uid // empty' <<<"$J")"; R="$(jq -r '.metadata.resourceVersion // empty' <<<"$J")"; G="$(jq -r '.metadata.generation // empty' <<<"$J")"; T="$(jq -r '.metadata.creationTimestamp // empty' <<<"$J")"; if [ -n "$U" ] && [ -n "$R" ] && [ -n "$G" ] && [ -n "$T" ]; then ING_UID="$U"; ING_RV="$R"; ING_GEN="$G"; ING_CLASS="$(jq -r '.spec.ingressClassName // empty' <<<"$J")"; ING_OWNER="$(jq -r '[.metadata.ownerReferences[]? | "\(.kind)/\(.name)/\(.uid)"]|join(",")' <<<"$J")"; ING_CREATED="$T"; RULES_JSON="$(jq -c '[.spec.rules[]? as $r | $r.http.paths[]? | {host:($r.host//""),path:(.path//""),pathType:(.pathType//""),service:(.backend.service.name//""),portName:(.backend.service.port.name//""),portNumber:(.backend.service.port.number//null)}]' <<<"$J")"; ING_RE="$(printf '%s' "$ING" | sed 's/[][\\.^$*+?(){}|]/\\&/g')"; AUTO_READY=true; export ING_UID ING_RV ING_GEN ING_CLASS ING_OWNER ING_CREATED RULES_JSON ING_RE; jq -r 'if length==0 then "규칙 없음" else .[] | "=== 규칙 ===\nhost: \(.host)\npath/pathType: \(.path) / \(.pathType)\nService port: \(.service) / \(.portName // "")\(.portNumber // "")" end' <<<"$RULES_JSON"; printf 'AUTO_READY=true UID=%s RV=%s generation=%s class=%s owner=%s created=%s regex=^%s$\n' "$ING_UID" "$ING_RV" "$ING_GEN" "${ING_CLASS:--}" "${ING_OWNER:--}" "$ING_CREATED" "$ING_RE"; else printf '%s\n' '중단: identity 필드 불완전.' >&2; fi; else printf '%s\n' '중단: API 실패, 모든 downstream 값 폐기.' >&2; fi`

자동 출력이 `규칙 없음`이면 default backend를 별도 확인하고 host/path 규칙이 있다고 가정하지 않는다.

`fresh_ing(){ FRESH_READY=false; [ "$AUTO_READY" = true ] || return 1; local j u r; j="$(kubectl get ingress "$ING" -n "$NS" -o json)" || { printf '%s\n' '중단: fresh API 실패.' >&2; return 1; }; u="$(jq -r '.metadata.uid // empty' <<<"$j")"; r="$(jq -r '.metadata.resourceVersion // empty' <<<"$j")"; [ "$u" = "$ING_UID" ] && [ "$r" = "$ING_RV" ] || { printf '중단: Ingress UID/RV 변경 %s/%s -> %s/%s, 재수집 필요\n' "$ING_UID" "$ING_RV" "$u" "$r" >&2; return 1; }; FRESH_READY=true; }`

### 3. 실제 요청 선택과 Service 관계

`REQ_HOST='PASTE_RULE_APPROVED_HOST_HERE'; REQ_PATH='PASTE_RULE_APPROVED_PATH_HERE'`

`SELECTION_READY=false; unset HOST_RE SERVICE SERVICE_PORT_NAME SERVICE_PORT_NUMBER; if [ "$AUTO_READY" != true ] || [ -z "$REQ_HOST" ] || [[ "$REQ_HOST" == *$'\n'* ]] || [[ ! "$REQ_PATH" =~ ^/ ]]; then printf '%s\n' '중단: host/path 선택값 형식 오류.' >&2; elif MATCHES="$(jq -c --arg h "$REQ_HOST" --arg p "$REQ_PATH" '[.[] | select(.host==$h or .host=="") | select((.pathType=="Exact" and .path==$p) or (.pathType=="Prefix" and (.path=="/" or $p==.path or (.path as $base|$p|startswith($base+"/")))) or .pathType=="ImplementationSpecific")]' <<<"$RULES_JSON")" && [ "$(jq 'length' <<<"$MATCHES")" -gt 0 ]; then HOST_RE="$(printf '%s' "$REQ_HOST" | sed 's/[][\\.^$*+?(){}|]/\\&/g')"; SELECTION_READY=true; export REQ_HOST REQ_PATH HOST_RE; printf 'SELECTION_READY=true host=%s path=%s host_regex=^%s$\n' "$REQ_HOST" "$REQ_PATH" "$HOST_RE"; jq -r '.[]|"candidate service=\(.service) port=\(.portName // "")\(.portNumber // "") path=\(.path) type=\(.pathType)"' <<<"$MATCHES"; else printf '%s\n' 'NO_MATCH: producer/API는 성공했지만 일치 규칙 없음.' >&2; fi`

`ImplementationSpecific` 후보는 controller 계약 전에는 match 확정이 아니다. 복수 후보면 Kubernetes longest path·Exact 우선 규칙을 대조하되 controller별 merge/rewrite를 추측하지 않는다.

`unset RELATION_READY SERVICE SERVICE_UID SERVICE_RV SERVICE_PORT_NAME SERVICE_PORT_NUMBER TARGET_PORT; RELATION_READY=false; fresh_ing || exit 1; [ "$SELECTION_READY" = true ] || { printf '%s\n' '중단: SELECTION_READY가 아니다.' >&2; exit 1; }; BEST="$(jq -c --arg h "$REQ_HOST" --arg p "$REQ_PATH" '[.[] | select(.host==$h or .host=="") | select(.pathType!="ImplementationSpecific") | select((.pathType=="Exact" and .path==$p) or (.pathType=="Prefix" and (.path=="/" or $p==.path or (.path as $base|$p|startswith($base+"/")))))] | sort_by(.path|length,if .pathType=="Exact" then 1 else 0 end) | last // empty' <<<"$RULES_JSON")"; [ -n "$BEST" ] || { printf '%s\n' '중단: 표준 pathType에서 단일 계산 후보 없음.' >&2; exit 1; }; SERVICE="$(jq -r '.service' <<<"$BEST")"; SERVICE_PORT_NAME="$(jq -r '.portName // empty' <<<"$BEST")"; SERVICE_PORT_NUMBER="$(jq -r '.portNumber // empty' <<<"$BEST")"; if SJSON="$(kubectl get service "$SERVICE" -n "$NS" -o json)"; then SERVICE_UID="$(jq -r '.metadata.uid // empty' <<<"$SJSON")"; SERVICE_RV="$(jq -r '.metadata.resourceVersion // empty' <<<"$SJSON")"; PORTS="$(jq -c --arg n "$SERVICE_PORT_NAME" --arg p "$SERVICE_PORT_NUMBER" '[.spec.ports[] | select(($n!="" and .name==$n) or ($p!="" and (.port|tostring)==$p))]' <<<"$SJSON")"; if [ "$(jq 'length' <<<"$PORTS")" -eq 1 ]; then TARGET_PORT="$(jq -r '.[0].targetPort' <<<"$PORTS")"; RELATION_READY=true; export SERVICE SERVICE_UID SERVICE_RV SERVICE_PORT_NAME SERVICE_PORT_NUMBER TARGET_PORT; printf 'RELATION_READY=true Ingress=%s/%s -> host=%s path=%s -> Service=%s/%s port=%s%s -> targetPort=%s\n' "$ING" "$ING_UID" "$REQ_HOST" "$REQ_PATH" "$SERVICE" "$SERVICE_UID" "$SERVICE_PORT_NAME" "$SERVICE_PORT_NUMBER" "$TARGET_PORT"; else printf '%s\n' '중단: Service port exact match가 하나가 아님.' >&2; fi; else printf '%s\n' '중단: Service API 실패.' >&2; fi`

**EndpointSlice·Pod 관계 확인**

`fresh_ing || exit 1; [ "$RELATION_READY" = true ] || { printf '%s\n' '중단: RELATION_READY가 아니다.' >&2; exit 1; }; SJSON="$(kubectl get service "$SERVICE" -n "$NS" -o json)" || exit 1; [ "$(jq -r '.metadata.uid' <<<"$SJSON")/$(jq -r '.metadata.resourceVersion' <<<"$SJSON")" = "$SERVICE_UID/$SERVICE_RV" ] || { printf '%s\n' '중단: Service UID/RV 변경, 관계 재등록 필요.' >&2; exit 1; }; SLICE_FILE="$(mktemp)" || exit 1; if kubectl get endpointslice -n "$NS" -l "kubernetes.io/service-name=$SERVICE" -o json >"$SLICE_FILE"; then if [ -n "$SERVICE_PORT_NAME" ]; then PORT_OK="$(jq --arg su "$SERVICE_UID" --arg pn "$SERVICE_PORT_NAME" '[.items[]|select(any(.metadata.ownerReferences[]?;.kind=="Service" and .uid==$su))|.ports[]?|select((.name//"")==$pn)]|length' "$SLICE_FILE")"; elif [[ "$TARGET_PORT" =~ ^[0-9]+$ ]]; then PORT_OK="$(jq --arg su "$SERVICE_UID" --argjson tp "$TARGET_PORT" '[.items[]|select(any(.metadata.ownerReferences[]?;.kind=="Service" and .uid==$su))|.ports[]?|select(.port==$tp)]|length' "$SLICE_FILE")"; else PORT_OK=0; fi; if [ "$PORT_OK" -gt 0 ] && OUT="$(jq -r --arg su "$SERVICE_UID" '[.items[]|select(any(.metadata.ownerReferences[]?;.kind=="Service" and .uid==$su))] as $owned|$owned[]|"=== EndpointSlice ===\n이름/UID: \(.metadata.name)/\(.metadata.uid)\nService owner: \([.metadata.ownerReferences[]?|"\(.kind)/\(.name)/\(.uid)"]|join(","))\nport: \([.ports[]?|"\(.name//"-"):\(.port//0)"]|join(","))\nendpoint Pod/UID/node/ready: \([.endpoints[]?|"\(.targetRef.name//"-")/\(.targetRef.uid//"-")/\(.nodeName//"-")/\(.conditions.ready//false)"]|join(";"))"' "$SLICE_FILE")" && [ -n "$OUT" ]; then printf '%s\n' "$OUT"; else printf '%s\n' 'NO_MATCH: current Service UID 소유 EndpointSlice와 port 관계 없음.' >&2; fi; else printf '%s\n' 'PRODUCER_ERROR: EndpointSlice API 실패.' >&2; fi; rm -f "$SLICE_FILE"`

EndpointSlice owner·targetRef UID·node와 Service UID 관계가 불명확하면 ready 주소를 backend로 확정하지 않는다. container·containerID·실제 listener는 선택된 Pod를 exact 조회한 뒤에만 확인하며 선언된 targetPort는 listener 보장이 아니다. runtime/CRI 진단이 필요하면 validated active kubelet endpoint의 exact socket과 runtime provider 관계가 확인된 node 런북으로 이관한다. 기본 socket을 추측하지 않는다.

## 시간·Event·로그 계약

`START_RFC3339='PASTE_RULE_EVIDENCE_START_UTC_HERE'; END_RFC3339='PASTE_RULE_EVIDENCE_END_UTC_HERE'`

`TIME_READY=false; RX='^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$'; if [[ "$START_RFC3339" =~ $RX ]] && [[ "$END_RFC3339" =~ $RX ]] && [ "$(date -u -d "$START_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" = "$START_RFC3339" ] && [ "$(date -u -d "$END_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" = "$END_RFC3339" ]; then START_EPOCH="$(date -u -d "$START_RFC3339" +%s)"; END_EPOCH="$(date -u -d "$END_RFC3339" +%s)"; CREATED_EPOCH="$(date -u -d "$ING_CREATED" +%s 2>/dev/null)"; if [ "$START_EPOCH" -lt "$END_EPOCH" ] && [ "$CREATED_EPOCH" -le "$END_EPOCH" ] && [ "$END_EPOCH" -le "$(date -u +%s)" ]; then TIME_READY=true; export START_RFC3339 END_RFC3339 START_EPOCH END_EPOCH; printf 'TIME_READY=true evidence=%s..%s object-created=%s\n' "$START_RFC3339" "$END_RFC3339" "$ING_CREATED"; else printf '%s\n' '중단: 시간 순서 또는 evidence lifecycle 불일치.' >&2; fi; else printf '%s\n' '중단: canonical UTC RFC3339 regex/date roundtrip 실패.' >&2; fi`

`fresh_ing || exit 1; [ "$TIME_READY" = true ] || { printf '%s\n' '중단: TIME_READY가 아니다.' >&2; exit 1; }; EVENT_FILE="$(mktemp)" || exit 1; if kubectl get events -n "$NS" --field-selector "involvedObject.kind=Ingress,involvedObject.name=$ING,involvedObject.uid=$ING_UID" -o json >"$EVENT_FILE"; then if FILTERED="$(jq -r --arg s "$START_RFC3339" --arg e "$END_RFC3339" '.items[]|(.eventTime//.lastTimestamp//.metadata.creationTimestamp) as $t|select($t >= $s and $t <= $e)|"\($t) \(.type) \(.reason) \(.message|gsub("[[:cntrl:]]";" ")|.[0:300])"' "$EVENT_FILE")"; then if [ -n "$FILTERED" ]; then printf '%s\n' "$FILTERED"; else printf '%s\n' 'NO_MATCH: Event API 성공, 시간 창 일치 없음.' >&2; fi; else printf '%s\n' 'FILTER_ERROR: Event JSON/시간 필터 실패.' >&2; fi; else printf '%s\n' 'PRODUCER_ERROR: Event API 실패.' >&2; fi; rm -f "$EVENT_FILE"`

producer/API 실패, 성공 후 `NO_MATCH`, jq/filter 오류를 각각 기록한다. filter 없음은 오류 없음이 아니다. 로그는 controller/backend Pod UID·container·node와 이 시간 창이 재검증된 분기에서만 임시 파일에 먼저 수집하여 producer exit를 확인한 후 별도 `grep`을 실행한다. 민감한 header/body/query·token·cookie가 보이면 중단한다.

metric/label이 실제 exporter에 없으면 0으로 만들지 않는다. query API는 HTTP·JSON·`status=success`·non-empty result를 각각 gate로 확인한다.

`CHECK_URL='PASTE_RULE_APPROVED_HTTPS_URL_HERE'; REQUEST_READY=false; if [ "$SELECTION_READY" != true ] || [[ "$CHECK_URL" != "https://$REQ_HOST"* ]] || [[ "$CHECK_URL" != *"$REQ_PATH"* ]]; then printf '%s\n' '중단: URL과 승인 host/path 관계 불일치.' >&2; else REQUEST_READY=true; export CHECK_URL; printf 'REQUEST_READY=true\n'; fi`

`fresh_ing || exit 1; [ "$REQUEST_READY" = true ] || { printf '%s\n' '중단: REQUEST_READY가 아니다.' >&2; exit 1; }; CODE="$(curl -sS -o /dev/null -w '%{http_code}' --connect-timeout 5 --max-time 10 -H "Host: $REQ_HOST" "$CHECK_URL")"; RC=$?; if [ "$RC" -ne 0 ]; then printf 'producer transport/TLS 실패 rc=%s\n' "$RC" >&2; elif [[ ! "$CODE" =~ ^[0-9]{3}$ ]]; then printf 'filter 오류 code=%s\n' "$CODE" >&2; elif [ "$CODE" = 000 ]; then printf '%s\n' 'HTTP 000은 application 결과가 아님.' >&2; else printf 'HTTP=%s observed=%s\n' "$CODE" "$(date -u '+%Y-%m-%dT%H:%M:%SZ')"; fi`

## 변경 경계와 정상화

읽기 전용과 mutation을 분리한다. 별도 변경 절차는 실행 직전 fresh Ingress/Service/EndpointSlice/Pod UID·RV, 직접 증거, 승인 ID, window, tenant 영향, quorum/가용 replica, 멱등성 key, 승인된 원본, 중단 조건과 현재 대상에 결합된 rollback target을 검증해야 한다. 교체 Pod·Service·Ingress가 생기면 owner/containerID/node/Service/EndpointSlice 관계와 READY gate를 모두 재등록한다. `can-i=yes`는 승인·실제 요청 성공을 뜻하지 않으며 정확한 verb/resource/subresource와 audit 시각·UID를 기록한다.

정상화는 `application 핵심 기능 → backend 수신/응답 → EndpointSlice ready target UID → Service port → controller running match → 현재 Ingress host/path/class/UID` 순으로 역검증하고 동등한 관찰 창에서 재발이 없어야 한다. HTTP 한 번의 2xx나 객체 rule 일치만으로 닫지 않는다.

보존: UTC 창, Ingress/Service/EndpointSlice/Pod UID와 RV, owner/container/node 관계, host/path/pathType, port 관계, 비식별화 Event·status, 승인·rollback·실제 기능 결과. Secret, token, cookie, private key, request body, 전체 로그는 보존하지 않는다.
