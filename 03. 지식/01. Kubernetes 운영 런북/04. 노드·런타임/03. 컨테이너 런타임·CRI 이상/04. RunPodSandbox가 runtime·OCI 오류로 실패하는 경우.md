# RunPodSandbox가 runtime·OCI 오류로 실패하는 경우

## 입력값과 빠른 수집

hop은 `작업 PC/kubectl → API의 현재 Pod UID → Pod.spec.nodeName → SSH host → active kubelet → exact CRI socket/provider → Pod sandbox → OCI runtime → Linux cgroup·namespace·filesystem·LSM`이다. CNI ADD/IPAM과 pause image pull은 인접하지만 별도 lifecycle 단계다.

| 구분 | 값 | 처리 |
|---|---|---|
| 최초 입력 | `NS`, `POD`, `SSH_HOST` | 승인된 대표 Pod와 SSH 목적지 |
| API 자동값 | Pod UID/RV, owner UID, node/Node UID/RV/Hostname, runtimeVersion, spec/container relation | 모든 API가 성공할 때만 등록 |
| 계산 후보 | runtime kind, escaped regex, socket path | strict 검증 전 미확정 |
| 운영자 선택 | kubelet/runtime unit, exact endpoint, canonical UTC 창, 조건부 CNI Pod/container | 직접 증거 확인 후 선택 |

**도구·입력과 stale 폐기**

`TOOLS_READY=false; M=''; [ -n "${BASH_VERSION:-}" ] || M="$M bash"; for T in kubectl jq ssh date grep mktemp; do command -v "$T" >/dev/null 2>&1 || M="$M $T"; done; [ -z "$M" ] && TOOLS_READY=true || printf '중단: 없는 도구=%s\n' "$M" >&2; unset INPUT_READY API_READY HOST_READY TIME_READY ENDPOINT_READY SANDBOX_READY CNI_READY EVIDENCE_READY NORMAL_READY POD_UID POD_RV OWNER_KIND OWNER_NAME OWNER_UID NODE_NAME NODE_UID NODE_RV EXPECTED_HOSTNAME RUNTIME_VERSION RUNTIME_KIND CONTAINER_RELATION KUBELET_UNIT RUNTIME_UNIT CRI_ENDPOINT CRI_SOCKET SANDBOX_ID START_RFC3339 END_RFC3339 EVIDENCE_RFC3339 CNI_NS CNI_POD CNI_CONTAINER SELECTOR REVISION SPEC_HASH IMAGE_DIGEST CONTAINER_ID RELATION_ID ARGV_RE; NS='PASTE_NAMESPACE_HERE'; POD='PASTE_POD_NAME_HERE'; SSH_HOST='PASTE_SSH_HOST_HERE'; INPUT_READY=false; if [ "$TOOLS_READY" = true ] && [ -n "$NS" ] && [ -n "$POD" ] && [ -n "$SSH_HOST" ]; then INPUT_READY=true; printf 'INPUT_READY=true\n'; else printf '%s\n' '중단: 입력 실패' >&2; fi`

**API 자동 수집·관계 출력**

`unset API_READY HOST_READY TIME_READY ENDPOINT_READY SANDBOX_READY CNI_READY EVIDENCE_READY NORMAL_READY POD_UID POD_RV OWNER_KIND OWNER_NAME OWNER_UID NODE_NAME NODE_UID NODE_RV EXPECTED_HOSTNAME RUNTIME_VERSION RUNTIME_KIND CONTAINER_RELATION CRI_SOCKET SANDBOX_ID CONTAINER_ID RELATION_ID ARGV_RE; then POD_UID="$PU"; POD_RV="$PR"; OWNER_UID="$OU"; OWNER_KIND="$OK"; OWNER_NAME="$ON"; NODE_NAME="$PN"; NODE_UID="$NU"; NODE_RV="$NR"; EXPECTED_HOSTNAME="$H"; RUNTIME_VERSION="$V"; RUNTIME_KIND="${V%%:*}"; CONTAINER_RELATION="$(jq -c '[.spec.initContainers[]?,.spec.containers[]?|{name,image,command,args,securityContext}]' <<<"$P")"; API_READY=true; export NS POD SSH_HOST POD_UID POD_RV OWNER_KIND OWNER_NAME OWNER_UID NODE_NAME NODE_UID NODE_RV EXPECTED_HOSTNAME RUNTIME_VERSION RUNTIME_KIND; printf 'API_READY=true\nPod=%s/%s UID=%s RV=%s\nOwner=%s/%s UID=%s\nNode=%s UID=%s RV=%s Hostname=%s Runtime=%s\nContainer spec relation:\n' "$NS" "$POD" "$POD_UID" "$POD_RV" "$OWNER_KIND" "$OWNER_NAME" "$OWNER_UID" "$NODE_NAME" "$NODE_UID" "$NODE_RV" "$EXPECTED_HOSTNAME" "$RUNTIME_VERSION"; jq -r '.[]|"  \(.name) image=\(.image) command=\(.command) args=\(.args)"' <<<"$CONTAINER_RELATION"; else printf '%s\n' '중단: API 또는 단일 owner/node relation 실패; 부분값 폐기' >&2; fi`

standalone Pod 또는 owner chain이 둘 이상이면 owner를 자동 추측하지 않는다. workload owner가 relation을 승인한 뒤 별도 절차를 사용한다. command/args에는 민감정보가 있을 수 있어 화면에서만 확인하고 원문을 저장하지 않는다.

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | 현재 Pod UID의 `RunPodSandbox` 뒤 OCI/shim/cgroup/namespace 오류가 있고 CNI/IPAM 또는 pause image 실패가 선행하지 않음 |
| 적용 | kubelet CRI 요청 이후 sandbox 생성 단계 |
| 제외 | CNI/IPAM은 네트워크 런북, image/x509/unauthorized는 registry 런북, runtime service crash는 [[03. 컨테이너 runtime 서비스가 반복 종료·재시작되는 경우]] |

검색 문자열: `RunPodSandbox`, `failed to create shim task`, `OCI runtime create failed`, `CNI ADD failed`, `failed to allocate IP`, `pause image`, `cgroup`, `namespace`, `avc: denied`.

## endpoint·시간 준비

**선택값과 UTC round-trip**

`unset HOST_READY TIME_READY ENDPOINT_READY SANDBOX_READY CNI_READY EVIDENCE_READY NORMAL_READY CRI_SOCKET SANDBOX_ID ARGV_RE; KUBELET_UNIT='PASTE_KUBELET_UNIT_HERE'; RUNTIME_UNIT='PASTE_RUNTIME_UNIT_HERE'; CRI_ENDPOINT='PASTE_CRI_ENDPOINT_HERE'; START_RFC3339='PASTE_START_RFC3339_HERE'; END_RFC3339='PASTE_END_RFC3339_HERE'; EVIDENCE_RFC3339='PASTE_EVIDENCE_RFC3339_HERE'; HOST_READY=false; TIME_READY=false; if [ "$API_READY" = true ] && [[ "$KUBELET_UNIT" =~ ^[A-Za-z0-9_.@:-]+\.service$ ]] && [[ "$RUNTIME_UNIT" =~ ^[A-Za-z0-9_.@:-]+\.service$ ]] && [[ "$CRI_ENDPOINT" == unix:///* ]]; then HOST_READY=true; S="$(date -u -d "$START_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)"; E="$(date -u -d "$END_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)"; X="$(date -u -d "$EVIDENCE_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)"; SE="$(date -u -d "$START_RFC3339" +%s 2>/dev/null)"; EE="$(date -u -d "$END_RFC3339" +%s 2>/dev/null)"; XE="$(date -u -d "$EVIDENCE_RFC3339" +%s 2>/dev/null)"; [ "$S" = "$START_RFC3339" ] && [ "$E" = "$END_RFC3339" ] && [ "$X" = "$EVIDENCE_RFC3339" ] && [ "$SE" -lt "$EE" ] && [ "$SE" -le "$XE" ] && [ "$XE" -le "$EE" ] && TIME_READY=true; fi; [ "$HOST_READY" = true ] && [ "$TIME_READY" = true ] && printf 'HOST_READY=true TIME_READY=true\n' || { HOST_READY=false; TIME_READY=false; printf '%s\n' '중단: 선택값/UTC 관계 실패' >&2; }`

`MACHINE_READY=false; NODE_NOW="$(kubectl get node "$NODE_NAME" -o json)"; API_RC=$?; if [ "$HOST_READY" = true ] && [ "$API_RC" -eq 0 ] && [ "$(jq -r '.metadata.uid // empty' <<<"$NODE_NOW")" = "$NODE_UID" ] && NODE_MACHINE_ID="$(jq -er '.status.nodeInfo.machineID|select(length>0)' <<<"$NODE_NOW")" && REMOTE_MACHINE_ID="$(ssh -- "$SSH_HOST" 'test -r /etc/machine-id && tr -d "\n" </etc/machine-id')" && [ "$REMOTE_MACHINE_ID" = "$NODE_MACHINE_ID" ]; then MACHINE_READY=true; printf 'MACHINE_READY=true nodeUID=%s machineID=%s\n' "$NODE_UID" "$NODE_MACHINE_ID"; else HOST_READY=false; unset NODE_MACHINE_ID REMOTE_MACHINE_ID; printf '%s\n' '중단: current Node UID/machineID와 원격 /etc/machine-id 불일치' >&2; fi`

**remote identity, active kubelet 단일 endpoint, runtime provider**

`if [ "$HOST_READY" != true ] || [ "$MACHINE_READY" != true ] || [ "$TIME_READY" != true ]; then printf '%s\n' '중단: host/machine/time gate가 아니다.' >&2; else ENDPOINT_READY=false; if ssh -- "$SSH_HOST" bash -s -- "$EXPECTED_HOSTNAME" "$KUBELET_UNIT" "$RUNTIME_UNIT" "$CRI_ENDPOINT" "$RUNTIME_KIND" <<'REMOTE'

## lifecycle 분기

**UID 제한 Event 한 번 수집**

`if [ "$API_READY" != true ] || [ "$TIME_READY" != true ]; then printf '%s\n' '중단: API_READY/TIME_READY가 아니다.' >&2; else kubectl get events -n "$NS" --field-selector "involvedObject.kind=Pod,involvedObject.name=$POD,involvedObject.uid=$POD_UID" --sort-by=.metadata.creationTimestamp -o custom-columns='CREATED:.metadata.creationTimestamp,EVENT-TIME:.eventTime,SERIES-LAST:.series.lastObservedTime,REASON:.reason,COUNT:.count,MESSAGE:.message'; fi`

Event time이 canonical evidence 창 안인지 확인한다. Event aggregate count는 모든 발생 시각을 보존하지 않으므로 최초/마지막 시각이 불명확하면 journal로 확정한다.

**kubelet/runtime journal**

`if [ "$ENDPOINT_READY" != true ]; then printf '%s\n' '중단: ENDPOINT_READY가 아니다.' >&2; else EVIDENCE_READY=false; if ssh -- "$SSH_HOST" bash -s -- "$EXPECTED_HOSTNAME" "$KUBELET_UNIT" "$RUNTIME_UNIT" "$POD_UID" "$START_RFC3339" "$END_RFC3339" <<'REMOTE'
host=$1; ku=$2; ru=$3; uid=$4; start=$5; end=$6; [ "$(hostname)" = "$host" ] || exit 40; for unit in "$ku" "$ru"; do tmp=$(mktemp); sudo journalctl -u "$unit" --since "$start" --until "$end" --output=short-iso --no-pager >"$tmp"; p=$?; [ "$p" -eq 0 ] || { rm -f "$tmp"; exit 41; }; grep -E -i -C 3 "$uid|RunPodSandbox|CNI|IPAM|pause image|pull|shim|OCI|cgroup|namespace|permission denied|no space|read-only|I/O error|apparmor|avc: denied" "$tmp"; f=$?; rm -f "$tmp"; case "$f" in 0) ;; 1) printf '필터 일치 없음 unit=%s\n' "$unit" ;; *) exit 42 ;; esac; done
REMOTE
then EVIDENCE_READY=true; printf 'EVIDENCE_READY=true evidence=%s\n' "$EVIDENCE_RFC3339"; else printf '%s\n' '중단: journal producer/filter 실패' >&2; fi; fi`

판정은 timestamp 순서로 한다. CNI ADD/IPAM 실패 또는 pause image pull이 먼저면 runtime/OCI 원인으로 확정하지 않는다. CNI 성공 뒤 shim/OCI 오류면 runtime 경로다. cgroup/filesystem/LSM 직접 오류는 Linux owner에게 넘기며 보안 정책·mount를 완화하지 않는다.

**현재 Pod UID의 sandbox exact match**

`if [ "$ENDPOINT_READY" != true ] || [ "$EVIDENCE_READY" != true ]; then printf '%s\n' '중단: endpoint/evidence gate가 아니다.' >&2; else unset SANDBOX_ID; SANDBOX_READY=false; if RESULT="$(ssh -- "$SSH_HOST" bash -s -- "$EXPECTED_HOSTNAME" "$CRI_ENDPOINT" "$NS" "$POD" "$POD_UID" <<'REMOTE'
host=$1; ep=$2; ns=$3; pod=$4; uid=$5; [ "$(hostname)" = "$host" ] || exit 50; command -v crictl >/dev/null 2>&1 || exit 51; ids=(); while IFS= read -r id; do [ -n "$id" ] && ids+=("$id"); done < <(sudo crictl --runtime-endpoint="$ep" pods --name "$pod" --namespace "$ns" -q); matches=(); for id in "${ids[@]}"; do got=$(sudo crictl --runtime-endpoint="$ep" inspectp "$id" | jq -r '.status.metadata.uid // empty') || exit 52; [ "$got" = "$uid" ] && matches+=("$id"); done; [ "${#matches[@]}" -eq 1 ] || { printf '중단: UID exact sandbox count=%s\n' "${#matches[@]}" >&2; exit 53; }; printf '%s\n' "${matches[0]}"
REMOTE
)"; then SANDBOX_ID="$RESULT"; SANDBOX_READY=true; export SANDBOX_ID; printf 'SANDBOX_READY=true sandbox=%s pod-uid=%s\n' "$SANDBOX_ID" "$POD_UID"; else printf '%s\n' 'sandbox 없음/복수/CRI 실패; stale ID 사용 금지' >&2; fi; fi`

sandbox가 아직 생성되지 않아 0개인 것은 유효한 실패 결과일 수 있다. 이름만 일치하거나 이전 UID의 sandbox는 채택하지 않는다. inspect 원문 대신 UID, state, runtime handler, createdAt과 오류 suffix만 기록한다.

## 변경·정상화 계약

runtime restart, sandbox 강제 제거, Pod 반복 삭제, CNI/IPAM·pause image 변경, cgroup/LSM 완화를 제공하지 않는다. 변경 직전 fresh Pod/Node/owner UID·RV, selector·revision·spec hash·image digest, endpoint/provider, sandbox/containerID, 증거, 승인·window, PDB/quorum, RWO storage, Job/외부 side effect 멱등성, rollback을 재검증한다. stale이면 중단한다.

정상화 재수집은 모든 READY와 sandbox ID를 먼저 폐기한다. 새 Pod라면 UID·owner·node·revision·digest·containerID·sandbox를 재등록하고 sandbox→image→create→start→Ready, owner desired/Ready, EndpointSlice 등록, 실제 요청·핵심 기능 또는 Job 산출물·중복 없음을 확인한다. `Running`이나 sandbox ID 하나는 정상화가 아니다.

## Prometheus 빠른 관측

`if [ "$API_READY" != true ]; then printf '%s\n' '중단: API_READY가 아니다.' >&2; else PROM_LABEL='PASTE_PROM_LABEL_HERE'; PROM_VALUE='PASTE_PROM_VALUE_HERE'; if [[ "$PROM_LABEL" =~ ^[A-Za-z_][A-Za-z0-9_]*$ ]]; then Q="$(jq -Rn --arg v "$PROM_VALUE" '$v')"; NQ="$(jq -Rn --arg v "$NODE_NAME" '$v')"; printf 'sum(rate(kubelet_runtime_operations_errors_total{%s=%s,operation_type="run_podsandbox"}[5m]))\n' "$PROM_LABEL" "$Q"; printf 'histogram_quantile(0.99,sum by(le)(rate(kubelet_runtime_operations_duration_seconds_bucket{%s=%s,operation_type="run_podsandbox"}[5m])))\n' "$PROM_LABEL" "$Q"; printf 'sum by(namespace,pod,uid)(kube_pod_container_status_waiting_reason{reason="ContainerCreating"} * on(namespace,pod,uid) group_left(node) kube_pod_info{node=%s})\n' "$NQ"; else printf '%s\n' '중단: label 이름 오류' >&2; fi; fi`

operation_type 실제 값은 label browser로 확인한다. query가 비면 metric 미노출, scrape/label/range 실패와 실제 0을 구분한다. ContainerCreating은 CNI/image/mount도 포함하므로 OCI 원인 확정값이 아니다.

## 증거·미검증

Pod/owner/node/runtime/service/sandbox/container relation, UTC 순서, endpoint/provider, producer/filter rc, CNI/image/OCI/Linux 분기, 승인과 기능 검증을 보존한다. Secret·token·개인키·전체 inspect/config/journal/argv는 저장하지 않는다. CNI, runtime, OCI, systemd, SSH, cgroup/filesystem/LSM, metric은 환경별 미검증이다.
