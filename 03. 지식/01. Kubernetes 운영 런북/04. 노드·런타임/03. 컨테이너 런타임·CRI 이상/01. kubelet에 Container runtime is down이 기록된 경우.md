# kubelet에 Container runtime is down이 기록된 경우

## 입력값과 빠른 수집

연결 경로는 `승인된 작업 PC/Bash → Kubernetes API → Node 객체`와 `작업 PC → SSH → 그 Node의 host namespace → active kubelet → 단일 CRI Unix socket → runtime service`다. API의 Node 이름과 SSH 주소, Linux hostname은 서로 다른 identity다. 모든 명령은 같은 Bash에서 실행하며 `eval`을 사용하지 않는다.

| 구분 | 값 | 계약 |
|---|---|---|
| 최초 입력 | `NODE_NAME`, `SSH_HOST` | 승인된 Node 이름과 SSH 목적지 |
| API 자동값 | `NODE_UID`, `NODE_RV`, `EXPECTED_HOSTNAME`, `RUNTIME_VERSION` | exact-name Node 조회가 모두 성공할 때만 등록 |
| 계산 후보 | `RUNTIME_KIND`, `CRI_SOCKET` | runtimeVersion scheme과 검증된 `unix://` endpoint에서 계산하지만 검증 전 미확정 |
| 운영자 선택 | `KUBELET_UNIT`, `RUNTIME_UNIT`, `CRI_ENDPOINT`, UTC 증거 창 | host 출력과 장애 증거를 본 뒤 선택 |

각 `PASTE_..._HERE` 토큰은 문서에서 한 번만 나온다.

**Bash·도구 확인**

`TOOLS_READY=false; MISSING=''; [ -n "${BASH_VERSION:-}" ] || MISSING="$MISSING bash"; for T in kubectl jq ssh date grep mktemp; do command -v "$T" >/dev/null 2>&1 || MISSING="$MISSING $T"; done; if [ -z "$MISSING" ]; then TOOLS_READY=true; printf 'TOOLS_READY=true\n'; else printf '중단: 없는 도구=%s\n' "$MISSING" >&2; fi`

**최초 입력과 전체 stale 상태 폐기**

`unset INPUT_READY API_READY HOST_READY TIME_READY ENDPOINT_READY CRI_READY EVIDENCE_READY NORMAL_READY NODE_UID NODE_RV EXPECTED_HOSTNAME RUNTIME_VERSION RUNTIME_KIND KUBELET_UNIT RUNTIME_UNIT CRI_ENDPOINT CRI_SOCKET START_RFC3339 END_RFC3339 EVIDENCE_RFC3339 START_EPOCH END_EPOCH EVIDENCE_EPOCH OWNER_UID SELECTOR REVISION SPEC_HASH IMAGE_DIGEST CONTAINER_ID RELATION_ID ARGV_RE; NODE_NAME='PASTE_NODE_NAME_HERE'; SSH_HOST='PASTE_SSH_HOST_HERE'; INPUT_READY=false; if [ "$TOOLS_READY" = true ] && [ -n "$NODE_NAME" ] && [ -n "$SSH_HOST" ]; then INPUT_READY=true; printf 'INPUT_READY=true node=%s ssh-host=%s\n' "$NODE_NAME" "$SSH_HOST"; else printf '%s\n' '중단: 도구와 최초 입력을 확인한다.' >&2; fi`

**API 자동값 수집**

`unset API_READY HOST_READY TIME_READY ENDPOINT_READY CRI_READY EVIDENCE_READY NORMAL_READY NODE_UID NODE_RV EXPECTED_HOSTNAME RUNTIME_VERSION RUNTIME_KIND CRI_SOCKET CONTAINER_ID RELATION_ID ARGV_RE; API_READY=false; if [ "$INPUT_READY" != true ]; then printf '%s\n' '중단: INPUT_READY가 아니다.' >&2; elif NODE_JSON="$(kubectl get node "$NODE_NAME" -o json)" && NODE_UID_TMP="$(jq -er '.metadata.uid|select(length>0)' <<<"$NODE_JSON")" && NODE_RV_TMP="$(jq -er '.metadata.resourceVersion|select(length>0)' <<<"$NODE_JSON")" && HOST_TMP="$(jq -er '[.status.addresses[]?|select(.type=="Hostname")|.address]|unique|if length==1 then .[0] else error("Hostname must be unique") end' <<<"$NODE_JSON")" && RUNTIME_TMP="$(jq -er '.status.nodeInfo.containerRuntimeVersion|select(length>0)' <<<"$NODE_JSON")"; then NODE_UID="$NODE_UID_TMP"; NODE_RV="$NODE_RV_TMP"; EXPECTED_HOSTNAME="$HOST_TMP"; RUNTIME_VERSION="$RUNTIME_TMP"; RUNTIME_KIND="${RUNTIME_VERSION%%:*}"; API_READY=true; export NODE_NAME SSH_HOST NODE_UID NODE_RV EXPECTED_HOSTNAME RUNTIME_VERSION RUNTIME_KIND; printf 'API_READY=true\nNode=%s\nUID=%s\nRV=%s\nLinux Hostname=%s\nRuntime=%s\n관측=%s\n' "$NODE_NAME" "$NODE_UID" "$NODE_RV" "$EXPECTED_HOSTNAME" "$RUNTIME_VERSION" "$(date -u '+%Y-%m-%dT%H:%M:%SZ')"; else printf '%s\n' '중단: Node API 조회 또는 필수 identity 수집 실패; 파생값은 폐기됨' >&2; fi`

`API_READY=true`가 아니면 RBAC·context·exact name을 확인한다. `kubectl auth can-i get nodes`는 현재 주체의 일반 권한 preflight일 뿐 위 exact 요청의 성공, 동일 context 또는 audit 기록 존재를 보장하지 않는다. 감사 증거는 승인된 audit backend에서 request URI, authenticated user/groups, verb, response code, `auditID`만 최소 수집하고 token·인증서 개인키·Secret 원문은 저장하지 않는다.

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | 현재 Node UID에서 kubelet의 `container runtime is down` 또는 CRI `RuntimeReady=false`가 확인됨 |
| 적용 | 여러 Pod lifecycle과 Node 상태에 공통인 kubelet→CRI→runtime 경로 |
| 제외 | endpoint refused/timeout이 직접 증거면 [[02. CRI endpoint 연결이 거부되거나 timeout인 경우]], 한 Pod의 sandbox/create/start 문제면 해당 Pod·runtime 런북 |

검색 문자열: `container runtime is down`, `RuntimeReady=false`, `PLEG is not healthy`, `rpc error`, `connection refused`, `context deadline exceeded`.

## host·시간·CRI 준비

host 명령 전에 현재 Node identity를 다시 확인하고, SSH 원격에서는 positional argument로 전달한 API Hostname을 `hostname`과 재대조한다. `SSH_HOST`는 명령 문자열 안에 삽입하지 않는다.

**active unit 후보 확인**

`if [ "$API_READY" != true ]; then printf '%s\n' '중단: API_READY가 아니다.' >&2; else ssh -- "$SSH_HOST" bash -s -- "$EXPECTED_HOSTNAME" <<'REMOTE'
expected=$1
actual=$(hostname)
[ "$actual" = "$expected" ] || { printf '중단: 원격 host 불일치 expected=%s actual=%s\n' "$expected" "$actual" >&2; exit 10; }
systemctl list-units --type=service --state=active --no-legend --no-pager | grep -E '(^|[[:space:]])(kubelet|containerd|crio|cri-o|cri-docker|cri-dockerd)[^[:space:]]*\.service([[:space:]]|$)'
producer_rc=${PIPESTATUS[0]}; filter_rc=${PIPESTATUS[1]}
[ "$producer_rc" -eq 0 ] || { printf '중단: systemctl producer rc=%s\n' "$producer_rc" >&2; exit 11; }
case "$filter_rc" in 0) ;; 1) printf '%s\n' '중단: active unit 후보 없음' >&2; exit 12 ;; *) printf '중단: grep filter rc=%s\n' "$filter_rc" >&2; exit 13 ;; esac
REMOTE
fi`

출력에서 active kubelet 하나와 `RUNTIME_KIND`에 맞는 runtime service 하나만 선택한다.

**선택값·canonical UTC 창 검증**

`unset HOST_READY TIME_READY ENDPOINT_READY CRI_READY EVIDENCE_READY NORMAL_READY CRI_SOCKET ARGV_RE; KUBELET_UNIT='PASTE_KUBELET_UNIT_HERE'; RUNTIME_UNIT='PASTE_RUNTIME_UNIT_HERE'; CRI_ENDPOINT='PASTE_CRI_ENDPOINT_HERE'; START_RFC3339='PASTE_START_RFC3339_HERE'; END_RFC3339='PASTE_END_RFC3339_HERE'; EVIDENCE_RFC3339='PASTE_EVIDENCE_RFC3339_HERE'; HOST_READY=false; TIME_READY=false; if [ "$API_READY" != true ]; then printf '%s\n' '중단: API_READY가 아니다.' >&2; elif [[ "$KUBELET_UNIT" =~ ^[A-Za-z0-9_.@:-]+\.service$ ]] && [[ "$RUNTIME_UNIT" =~ ^[A-Za-z0-9_.@:-]+\.service$ ]] && [[ "$CRI_ENDPOINT" == unix:///* ]]; then HOST_READY=true; START_CANON="$(date -u -d "$START_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" && END_CANON="$(date -u -d "$END_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" && EVIDENCE_CANON="$(date -u -d "$EVIDENCE_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" && START_EPOCH="$(date -u -d "$START_RFC3339" +%s)" && END_EPOCH="$(date -u -d "$END_RFC3339" +%s)" && EVIDENCE_EPOCH="$(date -u -d "$EVIDENCE_RFC3339" +%s)" && [ "$START_CANON" = "$START_RFC3339" ] && [ "$END_CANON" = "$END_RFC3339" ] && [ "$EVIDENCE_CANON" = "$EVIDENCE_RFC3339" ] && [ "$START_EPOCH" -lt "$END_EPOCH" ] && [ "$START_EPOCH" -le "$EVIDENCE_EPOCH" ] && [ "$EVIDENCE_EPOCH" -le "$END_EPOCH" ] && TIME_READY=true; fi; if [ "$HOST_READY" = true ] && [ "$TIME_READY" = true ]; then printf 'HOST_READY=true TIME_READY=true start=%s evidence=%s end=%s\n' "$START_RFC3339" "$EVIDENCE_RFC3339" "$END_RFC3339"; else HOST_READY=false; TIME_READY=false; printf '%s\n' '중단: unit, unix endpoint 또는 canonical UTC start<end/evidence 관계 불일치' >&2; fi`

`MACHINE_READY=false; NODE_NOW="$(kubectl get node "$NODE_NAME" -o json)"; API_RC=$?; if [ "$HOST_READY" = true ] && [ "$API_RC" -eq 0 ] && [ "$(jq -r '.metadata.uid // empty' <<<"$NODE_NOW")" = "$NODE_UID" ] && NODE_MACHINE_ID="$(jq -er '.status.nodeInfo.machineID|select(length>0)' <<<"$NODE_NOW")" && REMOTE_MACHINE_ID="$(ssh -- "$SSH_HOST" 'test -r /etc/machine-id && tr -d "\n" </etc/machine-id')" && [ "$REMOTE_MACHINE_ID" = "$NODE_MACHINE_ID" ]; then MACHINE_READY=true; printf 'MACHINE_READY=true nodeUID=%s machineID=%s\n' "$NODE_UID" "$NODE_MACHINE_ID"; else HOST_READY=false; unset NODE_MACHINE_ID REMOTE_MACHINE_ID; printf '%s\n' '중단: current Node UID/machineID와 원격 /etc/machine-id 불일치' >&2; fi`

**active kubelet endpoint·runtime socket provider 엄격 검증**

`if [ "$HOST_READY" != true ] || [ "$MACHINE_READY" != true ] || [ "$TIME_READY" != true ]; then printf '%s\n' '중단: HOST_READY/MACHINE_READY/TIME_READY가 아니다.' >&2; else ENDPOINT_READY=false; if ssh -- "$SSH_HOST" bash -s -- "$EXPECTED_HOSTNAME" "$KUBELET_UNIT" "$RUNTIME_UNIT" "$CRI_ENDPOINT" "$RUNTIME_KIND" <<'REMOTE'
expected_host=$1; kubelet_unit=$2; runtime_unit=$3; selected_endpoint=$4; runtime_kind=$5
[ "$(hostname)" = "$expected_host" ] || exit 20
[ "$(systemctl is-active "$kubelet_unit")" = active ] || { printf '%s\n' '중단: 선택 kubelet이 active가 아님' >&2; exit 21; }
kpid=$(systemctl show "$kubelet_unit" -p MainPID --value); [ "$kpid" -gt 1 ] 2>/dev/null || exit 22
mapfile -d '' -t argv < "/proc/$kpid/cmdline" || exit 23
endpoints=(); config=''
for arg in "${argv[@]}"; do case "$arg" in --container-runtime-endpoint=*) endpoints+=("${arg#*=}");; --config=*) config=${arg#*=};; esac; done
if [ -n "$config" ]; then [ -r "$config" ] || exit 24; while IFS= read -r value; do endpoints+=("$value"); done < <(sed -n 's/^[[:space:]]*containerRuntimeEndpoint:[[:space:]]*["'"']\{0,1\}\([^"'"'[:space:]]*\)["'"']\{0,1\}[[:space:]]*$/\1/p' "$config"); fi
mapfile -t unique < <(printf '%s\n' "${endpoints[@]}" | sed '/^$/d' | sort -u)
[ "${#unique[@]}" -eq 1 ] && [ "${unique[0]}" = "$selected_endpoint" ] || { printf '중단: active kubelet endpoint 단일/exact 검증 실패 count=%s\n' "${#unique[@]}" >&2; exit 25; }
socket=${selected_endpoint#unix://}; [ "$socket" != "$selected_endpoint" ] && [ -S "$socket" ] || exit 26
[ "$(systemctl is-active "$runtime_unit")" = active ] || exit 27
rpid=$(systemctl show "$runtime_unit" -p MainPID --value); [ "$rpid" -gt 1 ] 2>/dev/null || exit 28
tmp=$(mktemp); trap 'rm -f "$tmp"' EXIT
sudo ss -xlpn >"$tmp"; producer_rc=$?; [ "$producer_rc" -eq 0 ] || { printf '중단: ss producer rc=%s\n' "$producer_rc" >&2; exit 29; }
grep -F -- "$socket" "$tmp" | grep -F -- "pid=$rpid,"; filter_rc=${PIPESTATUS[0]}; provider_rc=${PIPESTATUS[1]}
[ "$filter_rc" -eq 0 ] && [ "$provider_rc" -eq 0 ] || { printf '중단: socket/provider 불일치 filter=%s provider=%s\n' "$filter_rc" "$provider_rc" >&2; exit 30; }
case "$runtime_kind" in containerd|cri-o|docker) ;; *) printf '중단: 미지원 runtime scheme=%s\n' "$runtime_kind" >&2; exit 31 ;; esac
printf 'endpoint=%s socket=%s kubelet-pid=%s runtime-unit=%s runtime-pid=%s\n' "$selected_endpoint" "$socket" "$kpid" "$runtime_unit" "$rpid"
REMOTE
then CRI_SOCKET="${CRI_ENDPOINT#unix://}"; ENDPOINT_READY=true; export KUBELET_UNIT RUNTIME_UNIT CRI_ENDPOINT CRI_SOCKET START_RFC3339 END_RFC3339 EVIDENCE_RFC3339; printf 'ENDPOINT_READY=true socket=%s\n' "$CRI_SOCKET"; else unset CRI_SOCKET; printf '%s\n' '중단: 원격 identity·active kubelet·endpoint·provider 검증 실패' >&2; fi; fi`

## 진단 분기

**같은 증거 창의 kubelet/runtime journal**

`if [ "$ENDPOINT_READY" != true ]; then printf '%s\n' '중단: ENDPOINT_READY가 아니다.' >&2; else EVIDENCE_READY=false; if ssh -- "$SSH_HOST" bash -s -- "$EXPECTED_HOSTNAME" "$KUBELET_UNIT" "$RUNTIME_UNIT" "$START_RFC3339" "$END_RFC3339" <<'REMOTE'
expected=$1; ku=$2; ru=$3; start=$4; end=$5
[ "$(hostname)" = "$expected" ] || exit 40
for unit in "$ku" "$ru"; do tmp=$(mktemp); sudo journalctl -u "$unit" --since "$start" --until "$end" --output=short-iso --no-pager >"$tmp"; producer_rc=$?; if [ "$producer_rc" -ne 0 ]; then rm -f "$tmp"; printf '중단: journal producer unit=%s rc=%s\n' "$unit" "$producer_rc" >&2; exit 41; fi; grep -E -i -C 3 'container runtime is down|RuntimeReady|PLEG|rpc error|refused|deadline|timeout|panic|fatal|oom|no space|read-only|I/O error' "$tmp"; filter_rc=$?; rm -f "$tmp"; case "$filter_rc" in 0) ;; 1) printf '필터 일치 없음 unit=%s; 오류 부재로 해석 금지\n' "$unit" ;; *) exit 42 ;; esac; done
REMOTE
then EVIDENCE_READY=true; printf 'EVIDENCE_READY=true node-uid=%s evidence=%s\n' "$NODE_UID" "$EVIDENCE_RFC3339"; else printf '%s\n' '중단: journal 수집 실패' >&2; fi; fi`

- runtime service inactive/crash가 증거 시각보다 먼저면 [[03. 컨테이너 runtime 서비스가 반복 종료·재시작되는 경우]]로 이동한다.
- refused/timeout이면 [[02. CRI endpoint 연결이 거부되거나 timeout인 경우]]로 이동한다.
- service·socket은 정상이지만 PLEG/status 갱신만 실패하면 kubelet 상태 보고 계층으로 이관한다.
- OOM·no-space·read-only·I/O가 같은 시각이면 Linux memory/storage owner로 이관한다. 상관 시각이 없으면 원인으로 확정하지 않는다.

**검증된 endpoint의 CRI 상태**

`if [ "$ENDPOINT_READY" != true ] || [ "$EVIDENCE_READY" != true ]; then printf '%s\n' '중단: ENDPOINT_READY/EVIDENCE_READY가 아니다.' >&2; else CRI_READY=false; if ssh -- "$SSH_HOST" bash -s -- "$EXPECTED_HOSTNAME" "$CRI_ENDPOINT" <<'REMOTE'
expected=$1; endpoint=$2
[ "$(hostname)" = "$expected" ] || exit 50
command -v crictl >/dev/null 2>&1 || { printf '%s\n' '중단: crictl 없음' >&2; exit 51; }
sudo crictl --runtime-endpoint="$endpoint" info | jq -e '.status.conditions|any(.type=="RuntimeReady" and .status==true)' >/dev/null
REMOTE
then CRI_READY=true; printf 'CRI_READY=true endpoint=%s\n' "$CRI_ENDPOINT"; else printf '%s\n' 'CRI 조회 실패 또는 RuntimeReady!=true; endpoint 연결 실패와 condition false를 원격 오류로 구분한다.' >&2; fi; fi`

`crictl info` 성공은 해당 CRI endpoint의 RuntimeReady만 보장한다. kubelet status sync, sandbox/image/container lifecycle, 기존 containerID, workload Ready와 서비스 기능은 보장하지 않는다. 출력은 condition과 비민감 오류만 기록한다.

## 복구 gate와 정상화

이 문서는 restart·socket 권한 변경·endpoint 변경·reboot·cordon/drain·Pod 삭제 명령을 제공하지 않는다. 별도 변경은 실행 직전에 fresh Node UID/RV, workload owner UID·selector·revision·spec hash·image digest, 영향 containerID, endpoint/provider identity, 증거, 승인 ID, 변경 창, PDB/quorum, Job·외부 호출 멱등성, rollback trigger를 다시 등록해야 한다. 하나라도 바뀌면 승인을 폐기한다. rollback은 승인된 이전 spec/digest로만 수행하고, 교체 Pod는 새 UID·owner relation으로 재등록한다.

정상화 재수집 전 위 API 수집 명령을 다시 실행해 모든 downstream READY를 폐기한다. 이후 새 identity로 endpoint gate와 증거 창을 다시 통과하고 다음을 모두 확인한다.

- 같은 endpoint의 `RuntimeReady=true`가 관찰 창 동안 유지되고 새 runtime down/timeout journal이 없다.
- Node `Ready=True`, Lease와 RV가 갱신되며 pressure가 해소됐다.
- replacement가 있으면 새 Pod UID·owner·revision·digest·containerID·node 관계를 재등록했다.
- sandbox→image→create→start→Ready lifecycle과 owner desired/Ready가 수렴했다.
- EndpointSlice 등록 후 실제 요청, 핵심 기능 또는 Job 산출물·중복 없음까지 정상이다.

## Prometheus 빠른 관측

Prometheus label 이름·값은 실제 series label browser에서 선택한다. label 값은 JSON quoting으로 PromQL 문자열 escape하며 쿼리 안을 직접 수정하지 않는다.

`if [ "$API_READY" != true ]; then printf '%s\n' '중단: API_READY가 아니다.' >&2; else PROM_LABEL='PASTE_PROM_LABEL_HERE'; PROM_VALUE='PASTE_PROM_VALUE_HERE'; if [[ "$PROM_LABEL" =~ ^[a-zA-Z_][a-zA-Z0-9_]*$ ]]; then PROM_VALUE_Q="$(jq -Rn --arg v "$PROM_VALUE" '$v')"; printf 'sum by(operation_type)(rate(kubelet_runtime_operations_errors_total{%s=%s}[5m]))\n' "$PROM_LABEL" "$PROM_VALUE_Q"; printf 'kube_node_status_condition{node=%s,condition="Ready",status=~"false|unknown"} == 1\n' "$(jq -Rn --arg v "$NODE_NAME" '$v')"; else printf '%s\n' '중단: Prometheus label 이름이 유효하지 않다.' >&2; fi; fi`

첫 query가 비면 metric 미노출, scrape 실패, label 불일치, 시간 범위 오류를 `up`과 label browser로 구분한다. 두 번째만 비면 Node Ready 이상 series가 없는 후보지만 kube-state-metrics 수집 성공을 별도 확인한다. metric empty를 0이나 정상으로 기록하지 않는다.

## 증거와 미검증

Node UID/RV·Hostname·runtimeVersion, 원격 hostname, active unit/MainPID, kubelet argv/config의 단일 endpoint, socket provider, canonical UTC 창, producer/filter rc, 결정적 journal과 CRI condition, 승인·변경·기능 검증을 보존한다. 전체 argv/config/journal, Secret·token·개인키·개인정보는 저장하지 않는다.

Kubernetes 1.26의 Node·kubelet config·CRI API를 기준으로 한다. SSH 주소, systemd unit, runtime 구현체, socket, Linux 배포판, journald 보존, metric·label은 환경별 미검증이다.
