# 컨테이너 runtime 서비스가 반복 종료·재시작되는 경우

## 입력값과 빠른 수집

실행 hop은 `작업 PC/Bash → Kubernetes API`와 `작업 PC → SSH → 정확한 Node host → systemd runtime unit/process → CRI socket`이다. API Node, SSH destination, Linux hostname, systemd unit과 process lifecycle identity를 분리한다.

| 구분 | 값 | 출처 |
|---|---|---|
| 최초 입력 | `NODE_NAME`, `SSH_HOST` | 승인된 대상 |
| API 자동값 | Node `UID/RV`, Hostname, runtimeVersion, 영향 Pod UID·owner·containerID | exact API 응답 |
| 계산 후보 | runtime kind, socket path, journal regex | 검증 전 미확정 |
| 운영자 선택 | active kubelet/runtime unit, exact endpoint, UTC start/evidence/end | host·최초 crash 증거 |

**도구·입력·stale 폐기**

`TOOLS_READY=false; M=''; [ -n "${BASH_VERSION:-}" ] || M="$M bash"; for T in kubectl jq ssh date grep mktemp; do command -v "$T" >/dev/null 2>&1 || M="$M $T"; done; [ -z "$M" ] && TOOLS_READY=true || printf '중단: 없는 도구=%s\n' "$M" >&2; unset INPUT_READY API_READY HOST_READY TIME_READY SERVICE_READY ENDPOINT_READY CRI_READY EVIDENCE_READY NORMAL_READY NODE_UID NODE_RV EXPECTED_HOSTNAME RUNTIME_VERSION RUNTIME_KIND POD_RELATIONS KUBELET_UNIT RUNTIME_UNIT CRI_ENDPOINT CRI_SOCKET START_RFC3339 END_RFC3339 EVIDENCE_RFC3339 OWNER_UID SELECTOR REVISION SPEC_HASH IMAGE_DIGEST CONTAINER_ID RELATION_ID ARGV_RE; NODE_NAME='PASTE_NODE_NAME_HERE'; SSH_HOST='PASTE_SSH_HOST_HERE'; INPUT_READY=false; if [ "$TOOLS_READY" = true ] && [ -n "$NODE_NAME" ] && [ -n "$SSH_HOST" ]; then INPUT_READY=true; printf 'INPUT_READY=true\n'; else printf '%s\n' '중단: 입력 실패' >&2; fi`

**API identity와 영향 범위 자동 수집**

`unset API_READY HOST_READY TIME_READY SERVICE_READY ENDPOINT_READY CRI_READY EVIDENCE_READY NORMAL_READY NODE_UID NODE_RV EXPECTED_HOSTNAME RUNTIME_VERSION RUNTIME_KIND POD_RELATIONS CONTAINER_ID RELATION_ID ARGV_RE; API_READY=false; if [ "$INPUT_READY" != true ]; then printf '%s\n' '중단: INPUT_READY가 아니다.' >&2; elif N="$(kubectl get node "$NODE_NAME" -o json)" && P="$(kubectl get pods -A --field-selector "spec.nodeName=$NODE_NAME" -o json)" && U="$(jq -er '.metadata.uid' <<<"$N")" && R="$(jq -er '.metadata.resourceVersion' <<<"$N")" && H="$(jq -er '[.status.addresses[]?|select(.type=="Hostname")|.address]|unique|if length==1 then .[0] else error("hostname") end' <<<"$N")" && V="$(jq -er '.status.nodeInfo.containerRuntimeVersion|select(length>0)' <<<"$N")"; then NODE_UID="$U"; NODE_RV="$R"; EXPECTED_HOSTNAME="$H"; RUNTIME_VERSION="$V"; RUNTIME_KIND="${V%%:*}"; POD_RELATIONS="$(jq -c '[.items[]|{namespace:.metadata.namespace,pod:.metadata.name,uid:.metadata.uid,rv:.metadata.resourceVersion,owner:[.metadata.ownerReferences[]?|{kind,name,uid}],node:.spec.nodeName,containers:[.status.containerStatuses[]?|{name,containerID,ready,restartCount}]}]' <<<"$P")"; API_READY=true; export NODE_NAME SSH_HOST NODE_UID NODE_RV EXPECTED_HOSTNAME RUNTIME_VERSION RUNTIME_KIND; printf 'API_READY=true\nNode=%s UID=%s RV=%s Hostname=%s Runtime=%s\n' "$NODE_NAME" "$NODE_UID" "$NODE_RV" "$EXPECTED_HOSTNAME" "$RUNTIME_VERSION"; jq -r '.[]|"=== \(.namespace)/\(.pod) ===\nUID: \(.uid) RV: \(.rv) Node: \(.node)\nOwner: \(.owner|map("\(.kind)/\(.name)/\(.uid)")|join(","))\nContainer relation: \(.containers|map("\(.name)=\(.containerID // "-") ready=\(.ready) restarts=\(.restartCount)")|join("; "))"' <<<"$POD_RELATIONS"; else printf '%s\n' '중단: API producer 실패; 부분 identity 폐기' >&2; fi`

Pod 목록 성공과 빈 영향 범위는 다르다. 빈 목록은 현재 배치 Pod 없음이며 runtime crash 부재가 아니다. RBAC preflight와 실제 API 성공을 구분하고, audit에는 subject·verb·URI·code·auditID만 남긴다.

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | 같은 runtime unit의 `NRestarts`/MainPID/activation timestamp가 반복 변경되고 journal crash가 연결됨 |
| 적용 | runtime service lifecycle이 Pod 오류보다 선행함 |
| 제외 | service가 안정적이고 sandbox만 실패하면 [[04. RunPodSandbox가 runtime·OCI 오류로 실패하는 경우]], create/start만 실패하면 [[05. 같은 Node에서 container create·start와 shim 오류가 반복되는 경우]] |

검색 문자열: `Main process exited`, `Failed with result`, `panic`, `fatal`, `oom-kill`, `no space left`, `plugin`, `permission denied`.

## host·service·시간 gate

**active unit 후보**

`if [ "$API_READY" != true ]; then printf '%s\n' '중단: API_READY가 아니다.' >&2; else ssh -- "$SSH_HOST" bash -s -- "$EXPECTED_HOSTNAME" <<'REMOTE'
host=$1; [ "$(hostname)" = "$host" ] || exit 10; tmp=$(mktemp); trap 'rm -f "$tmp"' EXIT; systemctl list-units --type=service --state=active --no-legend --no-pager >"$tmp"; producer_rc=$?; [ "$producer_rc" -eq 0 ] || exit 11; grep -E '(^|[[:space:]])(kubelet|containerd|crio|cri-o|cri-docker|cri-dockerd)[^[:space:]]*\.service([[:space:]]|$)' "$tmp"; filter_rc=$?; case "$filter_rc" in 0) ;; 1) exit 12 ;; *) exit 13 ;; esac
REMOTE
fi`

**선택값·UTC 검증**

`unset HOST_READY TIME_READY SERVICE_READY ENDPOINT_READY CRI_READY EVIDENCE_READY NORMAL_READY CRI_SOCKET ARGV_RE; KUBELET_UNIT='PASTE_KUBELET_UNIT_HERE'; RUNTIME_UNIT='PASTE_RUNTIME_UNIT_HERE'; CRI_ENDPOINT='PASTE_CRI_ENDPOINT_HERE'; START_RFC3339='PASTE_START_RFC3339_HERE'; END_RFC3339='PASTE_END_RFC3339_HERE'; EVIDENCE_RFC3339='PASTE_EVIDENCE_RFC3339_HERE'; HOST_READY=false; TIME_READY=false; if [ "$API_READY" = true ] && [[ "$KUBELET_UNIT" =~ ^[A-Za-z0-9_.@:-]+\.service$ ]] && [[ "$RUNTIME_UNIT" =~ ^[A-Za-z0-9_.@:-]+\.service$ ]] && [[ "$CRI_ENDPOINT" == unix:///* ]]; then HOST_READY=true; S="$(date -u -d "$START_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)"; E="$(date -u -d "$END_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)"; X="$(date -u -d "$EVIDENCE_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)"; SE="$(date -u -d "$START_RFC3339" +%s 2>/dev/null)"; EE="$(date -u -d "$END_RFC3339" +%s 2>/dev/null)"; XE="$(date -u -d "$EVIDENCE_RFC3339" +%s 2>/dev/null)"; [ "$S" = "$START_RFC3339" ] && [ "$E" = "$END_RFC3339" ] && [ "$X" = "$EVIDENCE_RFC3339" ] && [ "$SE" -lt "$EE" ] && [ "$SE" -le "$XE" ] && [ "$XE" -le "$EE" ] && TIME_READY=true; fi; [ "$HOST_READY" = true ] && [ "$TIME_READY" = true ] && printf 'HOST_READY=true TIME_READY=true\n' || { HOST_READY=false; TIME_READY=false; printf '%s\n' '중단: 선택/시간 검증 실패' >&2; }`

`MACHINE_READY=false; NODE_NOW="$(kubectl get node "$NODE_NAME" -o json)"; API_RC=$?; if [ "$HOST_READY" = true ] && [ "$API_RC" -eq 0 ] && [ "$(jq -r '.metadata.uid // empty' <<<"$NODE_NOW")" = "$NODE_UID" ] && NODE_MACHINE_ID="$(jq -er '.status.nodeInfo.machineID|select(length>0)' <<<"$NODE_NOW")" && REMOTE_MACHINE_ID="$(ssh -- "$SSH_HOST" 'test -r /etc/machine-id && tr -d "\n" </etc/machine-id')" && [ "$REMOTE_MACHINE_ID" = "$NODE_MACHINE_ID" ]; then MACHINE_READY=true; printf 'MACHINE_READY=true nodeUID=%s machineID=%s\n' "$NODE_UID" "$NODE_MACHINE_ID"; else HOST_READY=false; unset NODE_MACHINE_ID REMOTE_MACHINE_ID; printf '%s\n' '중단: current Node UID/machineID와 원격 /etc/machine-id 불일치' >&2; fi`

**service lifecycle과 active kubelet endpoint/provider 검증**

`if [ "$HOST_READY" != true ] || [ "$MACHINE_READY" != true ] || [ "$TIME_READY" != true ]; then printf '%s\n' '중단: host/machine/time gate가 아니다.' >&2; else SERVICE_READY=false; ENDPOINT_READY=false; if ssh -- "$SSH_HOST" bash -s -- "$EXPECTED_HOSTNAME" "$KUBELET_UNIT" "$RUNTIME_UNIT" "$CRI_ENDPOINT" "$RUNTIME_KIND" <<'REMOTE'
host=$1; ku=$2; ru=$3; ep=$4; kind=$5; [ "$(hostname)" = "$host" ] || exit 20; [ "$(systemctl is-active "$ku")" = active ] || exit 21
kpid=$(systemctl show "$ku" -p MainPID --value); [ "$kpid" -gt 1 ] 2>/dev/null || exit 22; mapfile -d '' -t argv < "/proc/$kpid/cmdline" || exit 23
vals=(); cfg=''; for a in "${argv[@]}"; do case "$a" in --container-runtime-endpoint=*) vals+=("${a#*=}");; --config=*) cfg=${a#*=};; esac; done; if [ -n "$cfg" ]; then [ -r "$cfg" ] || exit 24; while IFS= read -r v; do vals+=("$v"); done < <(sed -n 's/^[[:space:]]*containerRuntimeEndpoint:[[:space:]]*["'"']\{0,1\}\([^"'"'[:space:]]*\)["'"']\{0,1\}[[:space:]]*$/\1/p' "$cfg"); fi; mapfile -t uniq < <(printf '%s\n' "${vals[@]}" | sed '/^$/d' | sort -u); [ "${#uniq[@]}" -eq 1 ] && [ "${uniq[0]}" = "$ep" ] || exit 25
socket=${ep#unix://}; [ "$socket" != "$ep" ] && [ -S "$socket" ] || exit 26; [ "$(systemctl is-active "$ru")" = active ] || exit 27; rpid=$(systemctl show "$ru" -p MainPID --value); [ "$rpid" -gt 1 ] 2>/dev/null || exit 28
systemctl show "$ru" -p Id -p ActiveState -p SubState -p MainPID -p NRestarts -p ExecMainCode -p ExecMainStatus -p ExecMainStartTimestamp -p ActiveEnterTimestamp -p InactiveEnterTimestamp --no-pager
tmp=$(mktemp); trap 'rm -f "$tmp"' EXIT; sudo ss -xlpn >"$tmp"; prc=$?; [ "$prc" -eq 0 ] || exit 29; grep -F -- "$socket" "$tmp" | grep -F -- "pid=$rpid,"; src=${PIPESTATUS[0]}; rrc=${PIPESTATUS[1]}; [ "$src" -eq 0 ] && [ "$rrc" -eq 0 ] || exit 30; case "$kind" in containerd|cri-o|docker) ;; *) exit 31 ;; esac
REMOTE
then CRI_SOCKET="${CRI_ENDPOINT#unix://}"; SERVICE_READY=true; ENDPOINT_READY=true; export KUBELET_UNIT RUNTIME_UNIT CRI_ENDPOINT CRI_SOCKET START_RFC3339 END_RFC3339 EVIDENCE_RFC3339; printf 'SERVICE_READY=true ENDPOINT_READY=true\n'; else unset CRI_SOCKET; printf '%s\n' '중단: service/endpoint/provider gate 실패' >&2; fi; fi`

`NRestarts`는 현재 activation의 systemd counter이며 재부팅·unit reload 경계를 함께 기록한다. MainPID와 start/active/inactive timestamp가 바뀌지 않으면 반복 종료를 확정하지 않는다.

## crash 원인 분기

`if [ "$SERVICE_READY" != true ] || [ "$ENDPOINT_READY" != true ]; then printf '%s\n' '중단: service/endpoint gate가 아니다.' >&2; else EVIDENCE_READY=false; if ssh -- "$SSH_HOST" bash -s -- "$EXPECTED_HOSTNAME" "$RUNTIME_UNIT" "$KUBELET_UNIT" "$START_RFC3339" "$END_RFC3339" <<'REMOTE'
host=$1; ru=$2; ku=$3; start=$4; end=$5; [ "$(hostname)" = "$host" ] || exit 40
for unit in "$ru" "$ku"; do tmp=$(mktemp); sudo journalctl -u "$unit" --since "$start" --until "$end" --output=short-iso --no-pager >"$tmp"; producer_rc=$?; if [ "$producer_rc" -ne 0 ]; then rm -f "$tmp"; exit 41; fi; grep -E -i -C 3 'Main process exited|Failed with result|panic|fatal|oom-kill|no space|read-only|I/O error|config|plugin|permission denied|socket|RunPodSandbox|connection refused' "$tmp"; filter_rc=$?; rm -f "$tmp"; case "$filter_rc" in 0) ;; 1) printf '필터 일치 없음 unit=%s\n' "$unit" ;; *) exit 42 ;; esac; done
REMOTE
then EVIDENCE_READY=true; printf 'EVIDENCE_READY=true evidence=%s\n' "$EVIDENCE_RFC3339"; else printf '%s\n' '중단: journal producer/filter 실패' >&2; fi; fi`

- crash/exit가 kubelet CRI 오류보다 먼저면 runtime service lifecycle 원인이다.
- kernel OOM, full inode/filesystem, read-only/I/O가 같은 시각이면 Linux owner로 이관한다. `fsck`, remount, cgroup/LSM 완화는 하지 않는다.
- config/plugin 오류는 `FragmentPath`·`DropInPaths`와 승인된 diff/digest만 비교한다. credential이 포함될 수 있는 전체 ExecStart/config는 저장하지 않는다.
- CNI/IPAM 또는 image pull이 먼저면 각각 network/registry 경로다.

**검증된 endpoint CRI 상태**

`if [ "$ENDPOINT_READY" != true ] || [ "$EVIDENCE_READY" != true ]; then printf '%s\n' '중단: endpoint/evidence gate가 아니다.' >&2; else CRI_READY=false; if ssh -- "$SSH_HOST" bash -s -- "$EXPECTED_HOSTNAME" "$CRI_ENDPOINT" <<'REMOTE'
host=$1; ep=$2; [ "$(hostname)" = "$host" ] || exit 50; command -v crictl >/dev/null 2>&1 || exit 51; sudo crictl --runtime-endpoint="$ep" info | jq -e '.status.conditions|any(.type=="RuntimeReady" and .status==true)' >/dev/null
REMOTE
then CRI_READY=true; printf 'CRI_READY=true\n'; else printf '%s\n' 'CRI 실패/RuntimeReady false; stderr와 condition을 구분한다.' >&2; fi; fi`

## 변경·정상화 계약

원인 미확정 restart/stop, socket 삭제, `crictl rm`, kill, reboot, drain, 보안 완화를 금지한다. 변경 직전 fresh Node UID/RV, 영향 owner UID·selector·revision·spec hash·image digest·containerID, unit/MainPID/NRestarts, endpoint/provider, 직접 증거, 승인·window, PDB/quorum, Job/외부 호출 멱등성, rollback을 다시 대조한다. stale approval은 폐기한다. replacement는 새 UID·relation으로 등록한다.

정상화 재수집은 먼저 모든 READY를 폐기한다. 새 identity로 runtime MainPID/NRestarts/activation 안정, 동일 endpoint RuntimeReady, 새 crash·sandbox Warning 부재, Node Ready/Lease, sandbox→image→create→start→Ready, owner desired/Ready, EndpointSlice·실제 요청 또는 Job 산출물·중복 없음을 확인한다.

## Prometheus 빠른 관측

`if [ "$API_READY" != true ]; then printf '%s\n' '중단: API_READY가 아니다.' >&2; else PROM_LABEL='PASTE_PROM_LABEL_HERE'; PROM_VALUE='PASTE_PROM_VALUE_HERE'; if [[ "$PROM_LABEL" =~ ^[A-Za-z_][A-Za-z0-9_]*$ ]]; then Q="$(jq -Rn --arg v "$PROM_VALUE" '$v')"; printf 'changes(process_start_time_seconds{%s=%s}[30m])\n' "$PROM_LABEL" "$Q"; printf 'min_over_time(up{%s=%s}[30m])\n' "$PROM_LABEL" "$Q"; printf 'sum by(operation_type)(increase(kubelet_runtime_operations_errors_total{%s=%s}[30m]))\n' "$PROM_LABEL" "$Q"; else printf '%s\n' '중단: label 이름 오류' >&2; fi; fi`

runtime exporter의 process metric이 실제 runtime service를 가리킬 때만 첫 query를 사용한다. 빈 결과는 exporter/metric 부재, label mismatch, scrape gap, 범위 오류로 분기하고 0으로 대체하지 않는다. systemd lifecycle과 journal이 확정 근거다.

## 증거·미검증

Node/Pod/controller/container identity와 relation, host/unit/process lifecycle, endpoint/provider, UTC 창, producer/filter rc, crash 원인, 승인·기능 검증을 보존한다. Secret·token·개인키·전체 argv/config/journal은 보존하지 않는다. runtime·systemd·SSH·filesystem/cgroup/LSM·metric은 환경별 미검증이다.
