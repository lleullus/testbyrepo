# container stop·remove와 sandbox 정리가 완료되지 않는 경우

## 입력값과 빠른 수집

실행 hop은 `작업 PC/bastion → 삭제 중인 현재 Pod UID·owner → 현재 Node UID/machineID → 원격 machine-id → active kubelet exact CRI endpoint → runtime provider PID → current containerID·sandbox UID → shim/mount/network namespace`다. API `NotFound`, CRI `NotFound`, 새 Pod 생성 중 하나만으로 old process·mount·sandbox가 정리됐다고 판단하지 않는다.

| 종류 | 값 | gate |
|---|---|---|
| 최초 입력 | namespace, 삭제 대상 Pod | deletion lifecycle의 exact object |
| API 자동값 | Pod UID/RV/deletion/owner/node, regular container/current ID, Node UID/machineID | 모든 relation 성공 후 등록 |
| 계산 후보 | container ID suffix, owner selector, CRI socket | exact relation 전 미확정 |
| 운영자 선택값 | container, SSH host, units, endpoint, canonical UTC 창 | API 후보·CMDB·active kubelet·사건 시각 확인 후 선택 |

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | deletion/finalizer/preStop/volume 경계를 확인한 뒤 같은 ID의 `StopContainer`, `RemoveContainer`, `RemovePodSandbox` timeout이 남음 |
| 적용 | current API identity와 CRI container/sandbox, shim/mount 증거를 같은 창에 연결 가능 |
| 제외 | API deletion·finalizer·PDB·volume·node unreachable은 [[15. Pod가 Terminating에서 멈춘 경우]], create/start 실패는 [[05. 같은 Node에서 container create·start와 shim 오류가 반복되는 경우]] |

검색 문자열: `StopContainer`, `RemoveContainer`, `RemovePodSandbox`, `context deadline exceeded`, `task still running`, `shim`, `network namespace`, `device or resource busy`.

## 관측별 진단 경로

| 지금 보이는 것 | 직접 증거 | 다음 경계 | 상세 절 |
|---|---|---|---|
| finalizer/preStop/volume가 먼저 실패 | deletionTimestamp·Event UID | Kubernetes deletion | [[15. Pod가 Terminating에서 멈춘 경우]] |
| stop/remove RPC timeout | current container ID·journal | CRI container | [[#bounded journal·CRI relation]] |
| sandbox teardown timeout | sandbox metadata UID·CNI 문자열 | runtime/CNI/netns | [[#bounded journal·CRI relation]] |
| API/CRI `NotFound` | old shim/mount/netns와 owner replacement | 정상화 | [[#replacement 재등록·정상화]] |


`filter_rc=1`은 오류 부재가 아니다. CRI `NotFound`는 producer 실패와 분리하고 old shim PID start time, mount ID/source, network namespace가 남지 않았다는 host 증거 전에는 정리 성공으로 해석하지 않는다.

## 변경 경계

이 문서는 force delete, runtime/kubelet restart, `crictl stop/rm/stopp/rmp`, shim kill, namespace·mount 수동 제거를 제공하지 않는다. 별도 변경은 fresh Pod/owner/controller/Node UID, machineID, endpoint/provider, exact container/sandbox, evidence, approval ID/window, PDB/quorum·RWO volume, Job·외부 side effect 멱등성, rollback 원본을 명령 직전에 검증해야 한다. 강제 삭제는 process·mount·sandbox 종료의 rollback이 아니다.

## replacement 재등록·정상화

외부 승인 변경이 시작된 canonical UTC 시각을 한 번 입력한다. 변경 실행 명령은 이 문서에 없다.

```bash
CHANGE_RFC3339='PASTE_APPROVED_CHANGE_RFC3339_HERE'
REPLACEMENT_READY=false
if [ "$CONTROLLER_UID" != '-' ] && [ -n "$SELECTOR" ] && [[ "$CHANGE_RFC3339" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] && [ "$(date -u -d "$CHANGE_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" = "$CHANGE_RFC3339" ]; then
  CHANGE_EPOCH="$(date -u -d "$CHANGE_RFC3339" +%s)"
  C="$(kubectl get "$CONTROLLER_KIND" "$CONTROLLER_NAME" -n "$NS" -o json)" || exit 1
  [ "$(jq -r '.metadata.uid' <<<"$C")" = "$CONTROLLER_UID" ] || exit 1
  LIST="$(kubectl get pods -n "$NS" -l "$SELECTOR" -o json)" || exit 1
  mapfile -t CANDIDATES < <(jq -r --arg old "$POD_UID" --argjson t "$CHANGE_EPOCH" '.items[]|select(.metadata.uid!=$old and .metadata.deletionTimestamp==null and (.metadata.creationTimestamp|fromdateiso8601)>=$t)|[.metadata.name,.metadata.uid,.metadata.resourceVersion,.spec.nodeName]|@tsv' <<<"$LIST")
  if [ "${#CANDIDATES[@]}" -eq 1 ]; then
    IFS=$'\t' read -r NEW_POD NEW_POD_UID NEW_POD_RV NEW_NODE <<<"${CANDIDATES[0]}"
    NJ="$(kubectl get pod "$NEW_POD" -n "$NS" -o json)" || exit 1
    DIRECT_KIND="$(jq -er '[.metadata.ownerReferences[]|select(.controller==true)][0].kind' <<<"$NJ")" || exit 1
    DIRECT_NAME="$(jq -er '[.metadata.ownerReferences[]|select(.controller==true)][0].name' <<<"$NJ")" || exit 1
    DIRECT_UID="$(jq -er '[.metadata.ownerReferences[]|select(.controller==true)][0].uid' <<<"$NJ")" || exit 1
    OWNER_CHAIN_READY=false
    if [ "$DIRECT_UID" = "$CONTROLLER_UID" ] && [ "$DIRECT_KIND" = "$CONTROLLER_KIND" ] && [ "$DIRECT_NAME" = "$CONTROLLER_NAME" ]; then
      OWNER_CHAIN_READY=true
    elif [ "$DIRECT_KIND" = ReplicaSet ]; then
      RS="$(kubectl get replicaset "$DIRECT_NAME" -n "$NS" -o json)" || exit 1
      if [ "$(jq -r '.metadata.uid' <<<"$RS")" = "$DIRECT_UID" ] && [ "$(jq -r '[.metadata.ownerReferences[]?|select(.controller==true)][0].uid // empty' <<<"$RS")" = "$CONTROLLER_UID" ]; then OWNER_CHAIN_READY=true; fi
    fi
    NEW_CONTAINER_ID="$(jq -r --arg c "$CONTAINER" '.status.containerStatuses[]?|select(.name==$c)|.containerID // empty' <<<"$NJ")"
    if [ "$OWNER_CHAIN_READY" = true ] && [ -n "$NEW_CONTAINER_ID" ] && [ "$(jq -r '.metadata.uid' <<<"$NJ")" = "$NEW_POD_UID" ] && [ "$(jq -r '.metadata.resourceVersion' <<<"$NJ")" = "$NEW_POD_RV" ] && [ "$(jq -r '.spec.nodeName' <<<"$NJ")" = "$NEW_NODE" ]; then REPLACEMENT_READY=true; printf 'REPLACEMENT_READY=true pod=%s uid=%s rv=%s node=%s owner=%s/%s[%s] id=%s\n' "$NEW_POD" "$NEW_POD_UID" "$NEW_POD_RV" "$NEW_NODE" "$DIRECT_KIND" "$DIRECT_NAME" "$DIRECT_UID" "$NEW_CONTAINER_ID"; fi
  else
    printf '중단: replacement candidate count=%s\n' "${#CANDIDATES[@]}" >&2
  fi
fi

NORMALIZATION_READY=false
fresh_replacement(){
  local j c dk dn du rs
  [ "$REPLACEMENT_READY" = true ] || return 1
  c="$(kubectl get "$CONTROLLER_KIND" "$CONTROLLER_NAME" -n "$NS" -o json)" || return 1
  [ "$(jq -r '.metadata.uid' <<<"$c")" = "$CONTROLLER_UID" ] || return 1
  j="$(kubectl get pod "$NEW_POD" -n "$NS" -o json)" || return 1
  [ "$(jq -r '.metadata.uid' <<<"$j")" = "$NEW_POD_UID" ] && [ "$(jq -r '.metadata.resourceVersion' <<<"$j")" = "$NEW_POD_RV" ] && [ "$(jq -r '.spec.nodeName' <<<"$j")" = "$NEW_NODE" ] && [ "$(jq -r --arg c "$CONTAINER" '.status.containerStatuses[]?|select(.name==$c)|.containerID // empty' <<<"$j")" = "$NEW_CONTAINER_ID" ] || return 1
  dk="$(jq -er '[.metadata.ownerReferences[]|select(.controller==true)][0].kind' <<<"$j")"; dn="$(jq -er '[.metadata.ownerReferences[]|select(.controller==true)][0].name' <<<"$j")"; du="$(jq -er '[.metadata.ownerReferences[]|select(.controller==true)][0].uid' <<<"$j")" || return 1
  if [ "$du" = "$CONTROLLER_UID" ] && [ "$dk" = "$CONTROLLER_KIND" ] && [ "$dn" = "$CONTROLLER_NAME" ]; then return 0; fi
  [ "$dk" = ReplicaSet ] || return 1; rs="$(kubectl get replicaset "$dn" -n "$NS" -o json)" || return 1; [ "$(jq -r '.metadata.uid' <<<"$rs")" = "$du" ] && [ "$(jq -r '[.metadata.ownerReferences[]?|select(.controller==true)][0].uid // empty' <<<"$rs")" = "$CONTROLLER_UID" ]
}
if fresh_replacement; then J="$(kubectl get pod "$NEW_POD" -n "$NS" -o json)" || exit 1; if jq -e '.status.containerStatuses|length>0 and all(.[];.ready==true and (.containerID|length>0))' <<<"$J" >/dev/null; then NORMALIZATION_READY=true; fi; fi
printf 'NORMALIZATION_READY=%s\n' "$NORMALIZATION_READY"
```

후보는 selector만으로 확정하지 않는다. ReplicaSet/StatefulSet/DaemonSet owner chain이 current controller UID와 맞는지 API에서 대조해야 하며 단일 후보가 아니면 `REPLACEMENT_READY=false`를 유지한다. 실제 정상화에는 old API object 부재, old container/sandbox 종료 또는 부재, shim/task·mount/netns 잔류 없음, kubelet sync, controller desired/Ready, 새 Pod CRI exact relation, EndpointSlice·실제 요청, Job 결과·중복 없음과 재발 관찰이 모두 필요하다.

## Prometheus 빠른 관측

```bash
if fresh_target; then NODE_JSON="$(jq -Rn --arg v "$NODE" '$v')"; printf 'sum by(operation_type)(rate(kubelet_runtime_operations_errors_total{node=%s,operation_type=~"stop_container|remove_container|stop_podsandbox|remove_podsandbox"}[5m]))\n' "$NODE_JSON"; else printf '%s\n' '중단: fresh target 실패' >&2; fi
```

실제 metric label과 operation type이 없으면 빈 결과를 성공으로 보지 않고 Event·journal·CRI로 이관한다.

## 증거·미검증

삭제 시각, Pod/owner/controller/Node UID·RV, machineID, container/sandbox ID, canonical 창, producer/filter rc, endpoint/provider PID, old process·mount/netns, replacement relation과 기능 검증만 보존한다. 전체 inspect/journal/argv, Secret·token·private key는 저장하지 않는다. runtime, systemd, SSH, CNI, storage, metric은 환경별 미검증이다.
