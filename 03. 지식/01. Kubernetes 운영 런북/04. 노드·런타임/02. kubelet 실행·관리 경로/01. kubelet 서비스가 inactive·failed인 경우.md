# kubelet 서비스가 inactive·failed인 경우

## 입력값과 빠른 수집

실행 hop은 `승인된 작업 PC의 Bash → SSH host key 검증 → 대상 Linux host → systemd kubelet unit`과 `작업 PC의 kubectl → API server → Node·Lease·Pod`다. SSH host와 Kubernetes Node의 관계는 자동으로 추측하지 않고 원격 hostname·machine-id·boot-id를 확인한 운영자가 한 번 승인한다. `eval`, 비밀번호 인자, host key 검증 해제는 사용하지 않는다.

| 입력 종류 | 이 문서의 값 | 등록 방식 | 유효성 gate |
|---|---|---|---|
| 최초 입력 | `NODE`, `SSH_TARGET` | 운영자가 정확한 Node 이름과 승인된 SSH 목적지를 한 번 입력 | exact-name Node 조회와 SSH 목적지 allowlist |
| API 확인 자동값 | `NODE_UID`, `NODE_RV`, `NODE_MACHINE_ID`, `LEASE_UID`, `LEASE_RV`, `RUNTIME_PROVIDER`, `NODE_ADDRESS`, Pod owner 범위 | Kubernetes API에서 매 guard마다 갱신 | Node UID·machineID와 Lease UID·holder exact match |
| 계산 후보값 | `KUBELET_UNIT`, `NODE_RE` | 원격 unit 목록과 escaped Node 이름에서 계산 | 후보가 정확히 하나이고 unit 이름 allowlist 통과 |
| 운영자 선택값 | `START_RFC3339`, `END_RFC3339`, host↔Node 승인, 변경 승인 | 직접 오류보다 앞선 UTC 증거 창과 승인 기록 | canonical round-trip, `start < end`, host identity 재검증 |

`PASTE_..._HERE` 문자열은 각각 한 번만 나온다. 이후 값은 같은 Bash에서 재사용한다.

**도구 확인**

`TOOLS_READY=false; MISSING=''; for T in kubectl jq ssh date awk grep sed mktemp; do command -v "$T" >/dev/null 2>&1 || MISSING="$MISSING $T"; done; if [ -n "${BASH_VERSION:-}" ] && [ -z "$MISSING" ]; then TOOLS_READY=true; printf 'TOOLS_READY=true\n'; else printf '중단: Bash 또는 도구 부족:%s\n' "$MISSING" >&2; fi`

"$SSH_TARGET" =~ ^[A-Za-z0-9_.@:-]+$ ]] || [[ "$SSH_TARGET" == -* ]]; then printf '%s\n' '중단: Node 또는 SSH 목적지 형식 오류' >&2; elif NODE_JSON="$(kubectl get node "$NODE" -o json)" && LEASE_JSON="$(kubectl get lease "$NODE" -n kube-node-lease -o json)" && [ "$(jq -r '.metadata.name' <<<"$NODE_JSON")" = "$NODE" ] && [ "$(jq -r '.spec.holderIdentity // empty' <<<"$LEASE_JSON")" = "$NODE" ]; then NODE_UID="$(jq -er '.metadata.uid' <<<"$NODE_JSON")" && NODE_MACHINE_ID="$(jq -er '.status.nodeInfo.machineID' <<<"$NODE_JSON")" && LEASE_UID="$(jq -er '.metadata.uid' <<<"$LEASE_JSON")" && INPUT_READY=true; SSH_OPTS=(-o BatchMode=yes -o StrictHostKeyChecking=yes -o ConnectTimeout=10); printf 'INPUT_READY=true node=%s uid=%s machineID=%s ssh=%s\n' "$NODE" "$NODE_UID" "$NODE_MACHINE_ID" "$SSH_TARGET"; else printf '%s\n' '중단: exact-name Node/Lease 조회 실패' >&2; fi`

**UTC 증거 창 입력과 canonical 검증**

`unset WINDOW_READY START_RFC3339 END_RFC3339; WINDOW_READY=false; API_READY=false; HOST_READY=false; UNIT_READY=false; EVIDENCE_READY=false; CRI_READY=false; MUTATION_READY=false; NORMAL_READY=false; START_RFC3339='PASTE_START_UTC_RFC3339_HERE'; END_RFC3339='PASTE_END_UTC_RFC3339_HERE'; START_CANON="$(date -u -d "$START_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)"; START_RC=$?; END_CANON="$(date -u -d "$END_RFC3339" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)"; END_RC=$?; if [ "$INPUT_READY" = true ] && [[ "$START_RFC3339" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] && [[ "$END_RFC3339" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] && [ "$START_RC" -eq 0 ] && [ "$END_RC" -eq 0 ] && [ "$START_CANON" = "$START_RFC3339" ] && [ "$END_CANON" = "$END_RFC3339" ] && [[ "$START_RFC3339" < "$END_RFC3339" ]]; then WINDOW_READY=true; printf 'WINDOW_READY=true start=%s end=%s\n' "$START_RFC3339" "$END_RFC3339"; else printf '%s\n' '중단: canonical UTC RFC3339 또는 start<end 실패' >&2; fi`

다음 guard는 매 조회 전에 Node·Lease를 새로 읽는다. 조회 실패 시 `API_READY=false`인 채로 끝나며 이전 resourceVersion이나 downstream READY를 사용하지 않는다.

`invalidate_current(){ API_READY=false; HOST_READY=false; UNIT_READY=false; EVIDENCE_READY=false; CRI_READY=false; MUTATION_READY=false; NORMAL_READY=false; }; api_guard(){ API_READY=false; local n l uid machine holder lease_uid; [ "$INPUT_READY" = true ] && [ "$WINDOW_READY" = true ] || { invalidate_current; printf '%s\n' '중단: 입력/시간 gate 실패' >&2; return 1; }; n="$(kubectl get node "$NODE" -o json)" && l="$(kubectl get lease "$NODE" -n kube-node-lease -o json)" || { invalidate_current; return 1; }; uid="$(jq -r '.metadata.uid' <<<"$n")"; machine="$(jq -r '.status.nodeInfo.machineID' <<<"$n")"; lease_uid="$(jq -r '.metadata.uid' <<<"$l")"; holder="$(jq -r '.spec.holderIdentity // empty' <<<"$l")"; [ "$uid" = "$NODE_UID" ] && [ "$machine" = "$NODE_MACHINE_ID" ] && [ "$lease_uid" = "$LEASE_UID" ] && [ "$holder" = "$NODE" ] || { invalidate_current; printf '%s\n' '중단: Node/Lease current identity 변경' >&2; return 1; }; NODE_RV="$(jq -r '.metadata.resourceVersion' <<<"$n")"; LEASE_RV="$(jq -r '.metadata.resourceVersion' <<<"$l")"; RUNTIME_PROVIDER="$(jq -r '.status.nodeInfo.containerRuntimeVersion|split("://")[0]' <<<"$n")"; NODE_ADDRESS="$(jq -r '[.status.addresses[]?|select(.type=="InternalIP")|.address]|if length==1 then .[0] else empty end' <<<"$n")"; [ -n "$NODE_RV" ] && [ -n "$LEASE_RV" ] && [ -n "$RUNTIME_PROVIDER" ] || { invalidate_current; return 1; }; API_READY=true; }`

**현재 API identity와 blast radius 수집**

`api_guard || exit; PODS_JSON="$(kubectl get pods -A --field-selector "spec.nodeName=$NODE" -o json)"; POD_RC=$?; if [ "$POD_RC" -eq 0 ]; then jq -r --arg node "$NODE" '"=== Node ===\n이름: \($node)\n" + (.items|sort_by(.metadata.namespace,.metadata.name)|map("=== Pod ===\nnamespace/name: \(.metadata.namespace)/\(.metadata.name)\nUID: \(.metadata.uid)\nowner: \([.metadata.ownerReferences[]?|"\(.kind)/\(.name)/\(.uid)"]|join(","))\nphase/ready: \(.status.phase)/\([.status.containerStatuses[]?.ready]|join(","))\ncontainerID: \([.status.containerStatuses[]?|"\(.name)=\(.containerID // "-")"]|join(";"))")|join("\n"))' <<<"$PODS_JSON"; else printf '중단: Pod producer rc=%s\n' "$POD_RC" >&2; fi`

Pod UID·owner UID·containerID·Node 관계는 이 출력의 현재 lifecycle에만 유효하다. 재생성·재수집 전 모두 폐기한다. Secret, token, annotation 원문은 수집하지 않는다.

### 원격 Linux identity와 unit 확정

**원격 identity 등록**

`api_guard || exit; REMOTE_ID="$(ssh "${SSH_OPTS[@]}" -- "$SSH_TARGET" 'printf "hostname=%s machine_id=%s boot_id=%s\n" "$(hostname -f 2>/dev/null || hostname)" "$(cat /etc/machine-id 2>/dev/null)" "$(cat /proc/sys/kernel/random/boot_id 2>/dev/null)"')"; SSH_RC=$?; printf '%s\n' "$REMOTE_ID"; read -r -p '이 host가 대상 Node이면 Node 이름을 다시 입력: ' HOST_CONFIRM; if [ "$SSH_RC" -eq 0 ] && [ "$HOST_CONFIRM" = "$NODE" ] && [[ "$REMOTE_ID" =~ ^hostname=[^[:space:]]+[[:space:]]machine_id=[0-9a-fA-F-]+[[:space:]]boot_id=[0-9a-fA-F-]+$ ]] && [[ "$REMOTE_ID" == *"machine_id=$NODE_MACHINE_ID "* ]]; then HOST_IDENTITY="$REMOTE_ID"; HOST_READY=true; printf 'HOST_READY=true node=%s machineID=%s address=%s\n' "$NODE" "$NODE_MACHINE_ID" "${NODE_ADDRESS:--}"; else HOST_READY=false; printf '%s\n' '중단: 원격 /etc/machine-id와 Node identity 관계 미승인' >&2; fi`

`host_guard(){ HOST_READY=false; api_guard || return 1; local now rc; now="$(ssh "${SSH_OPTS[@]}" -- "$SSH_TARGET" 'printf "hostname=%s machine_id=%s boot_id=%s\n" "$(hostname -f 2>/dev/null || hostname)" "$(cat /etc/machine-id 2>/dev/null)" "$(cat /proc/sys/kernel/random/boot_id 2>/dev/null)"')"; rc=$?; [ "$rc" -eq 0 ] && [ "$now" = "$HOST_IDENTITY" ] && [[ "$now" == *"machine_id=$NODE_MACHINE_ID "* ]] || { invalidate_current; printf '%s\n' '중단: 원격 host identity 변경/조회 실패' >&2; return 1; }; HOST_READY=true; }`

**실제 kubelet unit 후보 확정**

`host_guard || exit; UNIT_OUTPUT="$(ssh "${SSH_OPTS[@]}" -- "$SSH_TARGET" systemctl list-unit-files --type=service --no-legend)"; PRODUCER_RC=$?; UNIT_CANDIDATES=(); if [ "$PRODUCER_RC" -eq 0 ]; then UNIT_MATCHES="$(grep -E '^kubelet[A-Za-z0-9_.@-]*\.service[[:space:]]' <<<"$UNIT_OUTPUT")"; FILTER_RC=$?; [ "$FILTER_RC" -eq 0 ] && mapfile -t UNIT_CANDIDATES < <(awk '{print $1}' <<<"$UNIT_MATCHES"); else FILTER_RC=99; fi; if [ "$PRODUCER_RC" -eq 0 ] && [ "$FILTER_RC" -eq 0 ] && [ "${#UNIT_CANDIDATES[@]}" -eq 1 ] && [[ "${UNIT_CANDIDATES[0]}" =~ ^kubelet[A-Za-z0-9_.@-]*\.service$ ]]; then KUBELET_UNIT="${UNIT_CANDIDATES[0]}"; UNIT_READY=true; printf 'UNIT_READY=true unit=%s\n' "$KUBELET_UNIT"; else printf '중단: unit producer_rc=%s filter_rc=%s candidates=%s\n' "$PRODUCER_RC" "$FILTER_RC" "${#UNIT_CANDIDATES[@]}" >&2; fi; unit_guard(){ UNIT_READY=false; host_guard || return 1; local state; state="$(ssh "${SSH_OPTS[@]}" -- "$SSH_TARGET" systemctl show "$KUBELET_UNIT" -p Id -p LoadState)" || { invalidate_current; return 1; }; [ "$(sed -n 's/^Id=//p' <<<"$state")" = "$KUBELET_UNIT" ] && [ "$(sed -n 's/^LoadState=//p' <<<"$state")" = loaded ] || { invalidate_current; return 1; }; UNIT_READY=true; }`

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | 확인된 host의 실제 kubelet unit이 `inactive`, `failed`, `dead`이고 같은 증거 창에 start 실패 또는 종료 결과가 있음 |
| 적용 | Node UID·Lease·Pod owner 범위와 Linux host identity·unit·UTC 창이 모두 READY |
| 제외 | unit이 active인데 반복 restart면 [[02. kubelet이 반복 재시작되는 경우]], API status/Lease 오류가 주 증거면 [[03. kubelet이 Node 상태·Lease를 갱신하지 못하는 경우]], PLEG가 주 증거면 [[04. kubelet 로그에 PLEG is not healthy가 기록된 경우]] |

검색 문자열: `inactive`, `failed`, `dead`, `Main process exited`, `failed to load`, `x509`, `cgroup`, `container runtime is down`, `failed to register node`.

## 관측별 진단 경로

| 지금 보이는 것 | 먼저 볼 것 | 다음 경로 |
|---|---|---|
| `Result=exit-code`, config parser 오류 | 실제 `ExecStart`의 config 인자와 파일 metadata | 승인된 kubelet config owner |
| `x509`, expired, not yet valid | 인증서 metadata와 host UTC | 인증서·시간 owner |
| cgroup/container manager 오류 | host cgroup mount와 runtime provider | Linux/runtime owner |
| CRI socket·runtime down | kubelet active endpoint와 provider unit/socket | CRI 런북 |
| API timeout/refused/register 실패 | kubelet endpoint, host route, TLS | API/network owner |

**unit 상태와 argv 수집**

`unit_guard || exit; UNIT_STATE="$(ssh "${SSH_OPTS[@]}" -- "$SSH_TARGET" systemctl show "$KUBELET_UNIT" -p Id -p LoadState -p ActiveState -p SubState -p Result -p ExecMainCode -p ExecMainStatus -p NRestarts -p ExecMainStartTimestamp -p ExecMainExitTimestamp -p ExecStart)"; PRODUCER_RC=$?; if [ "$PRODUCER_RC" -eq 0 ] && grep -Eq '^ActiveState=(inactive|failed)$' <<<"$UNIT_STATE"; then FILTER_RC=0; EVIDENCE_READY=true; printf '%s\n' "$UNIT_STATE" | sed -E 's/(token|password|secret)=[^ ;]+/\1=REDACTED/Ig'; else FILTER_RC=$?; EVIDENCE_READY=false; printf '중단: producer_rc=%s inactive_filter_rc=%s\n' "$PRODUCER_RC" "$FILTER_RC" >&2; fi`

`ExecStart`는 argv 경로 확인에만 쓰며 credential처럼 보이는 값은 저장하지 않는다. unit state만으로 config·인증서·CRI 원인을 확정하지 않는다.

**bounded kubelet journal**

`unit_guard || exit; TMP="$(mktemp)" || exit 1; ssh "${SSH_OPTS[@]}" -- "$SSH_TARGET" sudo journalctl -u "$KUBELET_UNIT" --since "$START_RFC3339" --until "$END_RFC3339" --no-pager >"$TMP"; PRODUCER_RC=$?; if [ "$PRODUCER_RC" -eq 0 ]; then grep -E -i -C 3 'main process exited|failed|failure|config|unknown field|certificate|x509|cgroup|container manager|runtime|cri|socket|register node|update node status|timeout|refused|no route' "$TMP"; FILTER_RC=$?; else FILTER_RC=99; fi; rm -f "$TMP"; printf 'producer_rc=%s filter_rc=%s\n' "$PRODUCER_RC" "$FILTER_RC"; [ "$PRODUCER_RC" -eq 0 ] || exit 1; [ "$FILTER_RC" -eq 0 ] || printf '%s\n' '필터 무결과: 오류 없음이 아니며 전체 로그를 저장하지 말고 owner에게 bounded 원문 확인 요청' >&2`

producer 실패와 필터 무결과를 분리한다. 최초 비정상 exit와 바로 앞 오류가 config·certificate·cgroup·CRI·API 중 어느 분기를 여는지 결정한다.

### CRI 분기

kubelet이 inactive·failed이면 실행 중인 kubelet의 active `ExecStart`에서 endpoint를 확정할 수 없다. 이 문서에서는 기본 socket 추측이나 stale argv로 `crictl`을 실행하지 않는다. CRI 직접 오류가 확인되면 [[04. 노드·런타임/03. 컨테이너 런타임·CRI 이상/02. CRI endpoint 연결이 거부되거나 timeout인 경우]]로 이동해, strict fallback config 또는 다시 active가 된 kubelet의 endpoint와 runtime MainPID/socket owner 관계를 매 명령에서 재검증한다.

## Prometheus 빠른 관측

`api_guard || exit; printf 'kube_node_status_condition{node="%s",condition="Ready",status=~"false|unknown"} == 1\n' "$NODE"; printf 'time()-kube_lease_renew_time{namespace="kube-node-lease",lease="%s"}\n' "$NODE"`

출력된 PromQL을 승인된 Prometheus/Grafana에 실행한다. 빈 vector는 정상 또는 0이 아니라 metric 미수집·label 불일치·범위 오류로 실패 처리한다. `up=0`도 kubelet inactive를 단독 확정하지 않으며 systemd exit와 journal이 기준이다.

## 제한적 복구와 정상화

상태 변경 전 fresh `api_guard`, `host_guard`, unit identity, 직접 evidence, 승인 ID·변경 창, workload owner/PDB/quorum/Job 멱등성, 대체 capacity를 다시 확인한다. 하나라도 unknown이면 start하지 않는다. start는 재실행 멱등성을 보장하지 않으며 이미 실행 중인 container, volume, Job 외부 side effect를 고치지 않는다.

**승인 gate와 한 번의 start**

`MUTATION_READY=false; unit_guard || exit; CURRENT_STATE="$(ssh "${SSH_OPTS[@]}" -- "$SSH_TARGET" systemctl show "$KUBELET_UNIT" -p Id -p ActiveState -p SubState -p Result -p ExecMainStatus)" || exit 1; if ! grep -Eq '^ActiveState=(inactive|failed)$' <<<"$CURRENT_STATE"; then printf '%s\n' '중단: fresh inactive/failed evidence가 없음' >&2; exit 1; fi; EVIDENCE_READY=true; PODS_NOW="$(kubectl get pods -A --field-selector "spec.nodeName=$NODE" -o json)" || exit 1; jq -r '.items[]|"\(.metadata.namespace)/\(.metadata.name) uid=\(.metadata.uid) owner=\([.metadata.ownerReferences[]?|"\(.kind)/\(.name)/\(.uid)"]|join(","))"' <<<"$PODS_NOW"; read -r -p '승인 ID: ' APPROVAL_ID; read -r -p '승인된 UTC 변경 창 설명: ' CHANGE_WINDOW; read -r -p '위 current owner의 PDB/quorum/Job 멱등성/대체 capacity 확인 후 Node 이름 입력: ' SAFETY_CONFIRM; if [ -n "$APPROVAL_ID" ] && [ -n "$CHANGE_WINDOW" ] && [ "$SAFETY_CONFIRM" = "$NODE" ]; then MUTATION_READY=true; fi; [ "$MUTATION_READY" = true ] || { printf '%s\n' '중단: 변경 gate 실패' >&2; exit 1; }; ssh "${SSH_OPTS[@]}" -- "$SSH_TARGET" sudo systemctl start "$KUBELET_UNIT"; MUTATION_RC=$?; printf 'mutation_rc=%s approval=%s node_uid=%s node_rv=%s\n' "$MUTATION_RC" "$APPROVAL_ID" "$NODE_UID" "$NODE_RV"; [ "$MUTATION_RC" -eq 0 ] || exit 1`

restart 반복은 rollback이 아니다. config/unit/certificate 교정이 있었다면 승인된 구성 관리 시스템의 이전 revision으로만 되돌리고, 수동 overwrite·`reset-failed`·권한 완화는 금지한다. 검증 실패 시 추가 start/restart를 중단하고 원인 owner에게 rollback을 요청한다.

**교체·재등록과 실제 기능 정상화**

`FUNCTION_EVIDENCE_REF='PASTE_APPROVED_FUNCTION_EVIDENCE_HERE'; NORMAL_READY=false; unit_guard || exit; ACTIVE_1="$(ssh "${SSH_OPTS[@]}" -- "$SSH_TARGET" systemctl is-active "$KUBELET_UNIT")" || exit 1; LEASE_1="$(kubectl get lease "$NODE" -n kube-node-lease -o jsonpath='{.spec.renewTime}')" || exit 1; sleep 60; unit_guard || exit; ACTIVE_2="$(ssh "${SSH_OPTS[@]}" -- "$SSH_TARGET" systemctl is-active "$KUBELET_UNIT")" || exit 1; LEASE_2="$(kubectl get lease "$NODE" -n kube-node-lease -o jsonpath='{.spec.renewTime}')" || exit 1; NODE_NOW="$(kubectl get node "$NODE" -o json)" || exit 1; PODS_NOW="$(kubectl get pods -A --field-selector "spec.nodeName=$NODE" -o json)" || exit 1; if [ "$ACTIVE_1" = active ] && [ "$ACTIVE_2" = active ] && [[ "$LEASE_1" < "$LEASE_2" ]] && [ -n "$FUNCTION_EVIDENCE_REF" ] && jq -e 'any(.status.conditions[]; .type=="Ready" and .status=="True")' <<<"$NODE_NOW" >/dev/null && jq -e 'all(.items[]; ([.status.containerStatuses[]?.ready]|all))' <<<"$PODS_NOW" >/dev/null; then NORMAL_READY=true; printf 'NORMAL_READY=true node=%s uid=%s lease=%s function=%s\n' "$NODE" "$NODE_UID" "$LEASE_2" "$FUNCTION_EVIDENCE_REF"; else printf '%s\n' '중단: process/Lease/Ready/Pod/실제 기능 검증 실패' >&2; fi`

`NORMAL_READY=true` 뒤에도 owner desired/Ready, EndpointSlice의 현재 Pod UID 대응, 새 Warning·restart 부재와 승인된 실제 요청·queue·Job 산출물을 관찰 창 동안 확인한다. 교체 Node는 새 UID·host identity·runtime·owner 관계를 처음부터 재등록해야 한다.

## 증거·보안 경계

보존: Node/Lease resourceVersion, Node UID, host identity, unit/argv의 비민감 경로, bounded UTC 창, producer/filter rc, 직접 오류, runtime provider/socket 관계, workload owner·quorum·승인·검증 결과. RBAC은 Node/Lease/Pod read와 필요한 logs/exec subresource를 최소화한다. Secret, token, private key, 전체 kubeconfig, 전체 audit/journal, 개인정보는 출력·저장하지 않는다. audit은 승인된 담당자가 request URI·subject·response code·stageTimestamp만 bounded 창에서 대조한다.
