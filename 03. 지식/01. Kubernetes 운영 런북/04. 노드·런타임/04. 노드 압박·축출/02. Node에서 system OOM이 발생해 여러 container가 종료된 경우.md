# Node에서 system OOM이 발생해 여러 container가 종료된 경우

## 입력값과 빠른 수집

실행 hop은 `승인된 작업 PC/Bastion → Kubernetes API → 승인된 SSH host → kernel/kubelet → 필요할 때만 확인된 CRI·cgroup`이다. 같은 Bash를 유지하고 `eval`은 사용하지 않는다.

| 종류 | 값 | 확정 방법 |
|---|---|---|
| 최초 입력 | `NODE` | 승인된 Node exact name |
| API 확인 자동값 | `NODE_UID`, `NODE_RV`, runtime provider, 영향 Pod UID/owner/container ID | 매 단계 API에서 재조회 |
| 계산 후보값 | escaped ID regex, 사건 시간창 | exact ID·canonical 시각 검증 전 미확정 |
| 운영자 선택값 | `START_RFC3339`, `END_RFC3339`, `SSH_HOST`, 실제 unit/cgroup path | kernel 사건·CMDB·runtime 근거로 선택 |

`TOOLS_READY=false; MISSING=''; for T in kubectl jq grep sed date ssh; do command -v "$T" >/dev/null 2>&1 || MISSING="$MISSING $T"; done; if [ -z "${BASH_VERSION:-}" ] || [ -n "$MISSING" ]; then printf '중단: Bash/도구 gate 실패%s\n' "$MISSING" >&2; elif kubectl auth whoami >/dev/null 2>&1 && kubectl auth can-i get nodes | grep -Fxq yes && kubectl auth can-i list pods --all-namespaces | grep -Fxq yes; then TOOLS_READY=true; kubectl auth whoami; else printf '%s\n' '중단: 현재 주체 또는 RBAC 실패' >&2; fi`

`unset INPUT_READY AUTO_READY HOST_READY TIME_READY KUBELET_READY CRI_READY EVIDENCE_READY MUTATION_READY REPLACEMENT_READY NORMALIZATION_READY DOWNSTREAM_READY NODE_UID NODE_RV OWNER_KIND OWNER_NAME OWNER_UID POD_UID CONTAINER_ID RAW_CONTAINER_ID RUNTIME_VERSION RUNTIME_PROVIDER SSH_HOST HOST_IDENTITY KUBELET_UNIT RUNTIME_UNIT CRI_ENDPOINT CRI_SOCKET START_RFC3339 END_RFC3339 START_EPOCH END_EPOCH START_CANON END_CANON ARGV_RE; SSH_ARGS=(); NODE='PASTE_NODE_HERE'; INPUT_READY=false; if [ "$TOOLS_READY" = true ] && J="$(kubectl get node "$NODE" -o json)" && [ "$(jq -r '.metadata.name' <<<"$J")" = "$NODE" ]; then INPUT_READY=true; printf 'INPUT_READY=true node=%s\n' "$NODE"; else printf '%s\n' '중단: Node exact-name 조회 실패' >&2; fi`

`unset AUTO_READY HOST_READY TIME_READY KUBELET_READY CRI_READY EVIDENCE_READY MUTATION_READY REPLACEMENT_READY NORMALIZATION_READY NODE_UID NODE_RV RUNTIME_VERSION RUNTIME_PROVIDER SSH_HOST HOST_IDENTITY KUBELET_UNIT RUNTIME_UNIT CRI_ENDPOINT CRI_SOCKET START_RFC3339 END_RFC3339 START_EPOCH END_EPOCH START_CANON END_CANON ARGV_RE DOWNSTREAM_READY; SSH_ARGS=(); AUTO_READY=false; if [ "$INPUT_READY" = true ] && J="$(kubectl get node "$NODE" -o json)"; then NODE_UID="$(jq -r '.metadata.uid // empty' <<<"$J")"; NODE_RV="$(jq -r '.metadata.resourceVersion // empty' <<<"$J")"; RUNTIME_VERSION="$(jq -r '.status.nodeInfo.containerRuntimeVersion // empty' <<<"$J")"; case "$RUNTIME_VERSION" in containerd://*) RUNTIME_PROVIDER=containerd;; cri-o://*) RUNTIME_PROVIDER=cri-o;; *) RUNTIME_PROVIDER='';; esac; if [ -n "$NODE_UID" ] && [ -n "$NODE_RV" ] && [ -n "$RUNTIME_PROVIDER" ]; then AUTO_READY=true; jq -r '"Node/UID/RV: \(.metadata.name) \(.metadata.uid) \(.metadata.resourceVersion)\nRuntime: \(.status.nodeInfo.containerRuntimeVersion)\n" + ([.status.conditions[] | "\(.type)=\(.status) reason=\(.reason) transition=\(.lastTransitionTime)"]|join("\n"))' <<<"$J"; else printf '%s\n' '중단: identity/runtime provider 등록 실패' >&2; fi; else printf '%s\n' '중단: fresh Node API 실패' >&2; fi`

`fresh_node(){ local j; unset CURRENT_NODE_RV; j="$(kubectl get node "$NODE" -o json)" || return 1; [ "$(jq -r '.metadata.uid' <<<"$j")" = "$NODE_UID" ] || return 1; CURRENT_NODE_RV="$(jq -r '.metadata.resourceVersion // empty' <<<"$j")"; [ -n "$CURRENT_NODE_RV" ]; }`

모든 재등록 전에 UID/RV/owner/containerID/node/host/relation/time/argv-regex와 downstream `READY`를 unset/false로 만든다. 실패한 부분 등록은 폐기한다.

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | kernel global OOM 행과 여러 process/container 종료가 같은 사건 창에 있음 |
| 적용 | Node/Pod UID, 종료 시각, kernel constraint/victim, kubelet eviction과 cgroup 경계를 대조 가능 |
| 제외 | 단일 memcg OOM, kubelet eviction, Disk/PID pressure는 해당 런북으로 이관 |

검색 문자열: `Out of memory`, `oom-kill`, `Killed process`, `invoked oom-killer`, `CONSTRAINT_NONE`, `CONSTRAINT_MEMCG`, `task_memcg`, `must evict`.

## 영향 대상 자동 수집

`fresh_node && kubectl get pods -A --field-selector "spec.nodeName=$NODE" -o json | jq -r '.items[] | "\n=== \(.metadata.namespace)/\(.metadata.name) ===\nUID: \(.metadata.uid)\nOwner: \(.metadata.ownerReferences[0].kind // "-")/\(.metadata.ownerReferences[0].name // "-") UID=\(.metadata.ownerReferences[0].uid // "-")\nPhase: \(.status.phase)\n" + ([.status.containerStatuses[]? | "Container: \(.name) ID=\(.containerID // "-") restart=\(.restartCount) last=\(.lastState.terminated.reason // "-") exit=\(.lastState.terminated.exitCode // "-") finished=\(.lastState.terminated.finishedAt // "-")"]|join("\n"))'`

API 호출 실패와 빈 목록을 분리한다. 서로 다른 owner의 Pod UID와 container 종료가 같은 좁은 창에 모여야 node 공통 사건 후보이며, `OOMKilled` 문자열만으로 system OOM을 확정하지 않는다.

## 시간·host gate

`START_RFC3339='PASTE_START_RFC3339_HERE'; END_RFC3339='PASTE_END_RFC3339_HERE'; unset TIME_READY KUBELET_READY CRI_READY EVIDENCE_READY START_EPOCH END_EPOCH START_CANON END_CANON DOWNSTREAM_READY; TIME_READY=false; if [[ "$START_RFC3339" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] && [[ "$END_RFC3339" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] && START_EPOCH="$(date -u -d "$START_RFC3339" +%s 2>/dev/null)" && END_EPOCH="$(date -u -d "$END_RFC3339" +%s 2>/dev/null)"; then START_CANON="$(date -u -d "@$START_EPOCH" '+%Y-%m-%dT%H:%M:%SZ')"; END_CANON="$(date -u -d "@$END_EPOCH" '+%Y-%m-%dT%H:%M:%SZ')"; if [ "$START_RFC3339" = "$START_CANON" ] && [ "$END_RFC3339" = "$END_CANON" ] && [ "$START_EPOCH" -lt "$END_EPOCH" ]; then TIME_READY=true; printf 'TIME_READY=true %s < %s\n' "$START_CANON" "$END_CANON"; else printf '%s\n' '중단: canonical round-trip/start<end 실패' >&2; fi; else printf '%s\n' '중단: strict UTC RFC3339 regex/parse 실패' >&2; fi`

`SSH_HOST='PASTE_APPROVED_SSH_HOST_HERE'; unset HOST_READY KUBELET_READY CRI_READY EVIDENCE_READY HOST_IDENTITY DOWNSTREAM_READY; SSH_ARGS=(); HOST_READY=false; if fresh_node && [[ "$SSH_HOST" =~ ^[A-Za-z0-9_.@:-]+$ ]] && [[ "$SSH_HOST" != -* ]]; then SSH_ARGS=(-o BatchMode=yes -o StrictHostKeyChecking=yes -o ClearAllForwardings=yes -o ConnectTimeout=10 "$SSH_HOST"); REMOTE_ID="$(ssh "${SSH_ARGS[@]}" -- 'printf "hostname=%s machine_id=%s boot_id=%s\n" "$(hostname -f 2>/dev/null || hostname)" "$(cat /etc/machine-id 2>/dev/null)" "$(cat /proc/sys/kernel/random/boot_id 2>/dev/null)"')"; SSH_RC=$?; printf '%s\n' "$REMOTE_ID"; read -r -p 'CMDB에서 이 host가 대상 Node임을 확인했으면 Node 이름 입력: ' HOST_CONFIRM; if [ "$SSH_RC" -eq 0 ] && [ "$HOST_CONFIRM" = "$NODE" ] && [[ "$REMOTE_ID" =~ ^hostname=[^[:space:]]+[[:space:]]machine_id=[0-9a-fA-F-]+[[:space:]]boot_id=[0-9a-fA-F-]+$ ]]; then HOST_IDENTITY="$REMOTE_ID"; HOST_READY=true; printf 'HOST_READY=true host=%s node=%s uid=%s rv=%s\n' "$SSH_HOST" "$NODE" "$NODE_UID" "$CURRENT_NODE_RV"; else printf '%s\n' '중단: 원격 host identity/CMDB 승인 실패' >&2; fi; else printf '%s\n' '중단: fresh Node/SSH host 형식 실패' >&2; fi`

`host_guard(){ local now; HOST_READY=false; fresh_node || return 1; now="$(ssh "${SSH_ARGS[@]}" -- 'printf "hostname=%s machine_id=%s boot_id=%s\n" "$(hostname -f 2>/dev/null || hostname)" "$(cat /etc/machine-id 2>/dev/null)" "$(cat /proc/sys/kernel/random/boot_id 2>/dev/null)"')" || return 1; [ "$now" = "$HOST_IDENTITY" ] || return 1; HOST_READY=true; }`

모든 node 명령은 작업 PC에서 `host_guard`를 직접 호출하고 검증된 값만 SSH positional argument로 전달한다. 작업 PC 변수가 원격 shell에 자동 전달된다고 가정하지 않는다.

## 관측별 진단 경로

| 지금 보이는 것 | 먼저 볼 것 | 그다음 어디를 볼지 | 상세 절 |
|---|---|---|---|
| `CONSTRAINT_NONE`과 다중 victim | 같은 창의 Pod finishedAt | system OOM 영향·서비스 | [[#kernel·kubelet 직접 증거]] |
| `CONSTRAINT_MEMCG`·`task_memcg` | exact container/cgroup 관계 | Pod OOM 런북 | [[#CRI·cgroup 조건부 경계]] |
| `must evict`·`memory.available` | Evicted Pod UID·threshold source | eviction 런북 | [[#kernel·kubelet 직접 증거]] |
| 증거가 비거나 충돌 | producer/filter RC·clock | 원인 미확정 | [[#kernel·kubelet 직접 증거]] |

## kernel·kubelet 직접 증거

`host_guard || exit 1; [ "$TIME_READY" = true ] || exit 1; TMP="$(mktemp)" || exit 1; ssh "${SSH_ARGS[@]}" -- sudo journalctl -k --since "$START_CANON" --until "$END_CANON" --no-pager >"$TMP"; PRODUCER_RC=$?; if [ "$PRODUCER_RC" -eq 0 ]; then grep -E -i -C 4 'oom-kill|out of memory|invoked oom-killer|killed process|task_memcg|memory cgroup|constraint' "$TMP"; FILTER_RC=$?; else FILTER_RC=99; fi; rm -f "$TMP"; printf 'producer_rc=%s filter_rc=%s\n' "$PRODUCER_RC" "$FILTER_RC"; [ "$PRODUCER_RC" -eq 0 ] && { [ "$FILTER_RC" -eq 0 ] || [ "$FILTER_RC" -eq 1 ]; }`

`unset KUBELET_READY KUBELET_UNIT EVIDENCE_READY DOWNSTREAM_READY; KUBELET_READY=false; host_guard || exit 1; UNIT_OUTPUT="$(ssh "${SSH_ARGS[@]}" -- systemctl list-units --type=service --all --no-legend)"; PRODUCER_RC=$?; if [ "$PRODUCER_RC" -eq 0 ]; then mapfile -t KU < <(grep -E '(^|[[:space:]])kubelet\.service([[:space:]]|$)' <<<"$UNIT_OUTPUT" | sed -E 's/^[[:space:]]*([^[:space:]]+).*/\1/'); FILTER_RC=$?; else FILTER_RC=99; fi; if [ "$PRODUCER_RC" -eq 0 ] && [ "$FILTER_RC" -eq 0 ] && [ "${#KU[@]}" -eq 1 ] && ssh "${SSH_ARGS[@]}" -- sudo systemctl is-active --quiet "${KU[0]}"; then KUBELET_UNIT="${KU[0]}"; KUBELET_READY=true; printf 'KUBELET_READY=true unit=%s\n' "$KUBELET_UNIT"; else printf '중단: kubelet producer=%s filter=%s candidates=%s\n' "$PRODUCER_RC" "$FILTER_RC" "${#KU[@]}" >&2; fi`

`host_guard || exit 1; [ "$KUBELET_READY" = true ] && [ "$TIME_READY" = true ] || exit 1; TMP="$(mktemp)" || exit 1; ssh "${SSH_ARGS[@]}" -- sudo journalctl -u "$KUBELET_UNIT" --since "$START_CANON" --until "$END_CANON" --no-pager >"$TMP"; PRODUCER_RC=$?; if [ "$PRODUCER_RC" -eq 0 ]; then grep -E -i -C 3 'eviction manager|must evict|eviction threshold|memory\.available|MemoryPressure|Evicted|oom|killed' "$TMP"; FILTER_RC=$?; else FILTER_RC=99; fi; rm -f "$TMP"; printf 'producer_rc=%s filter_rc=%s\n' "$PRODUCER_RC" "$FILTER_RC"; [ "$PRODUCER_RC" -eq 0 ] && { [ "$FILTER_RC" -eq 0 ] || [ "$FILTER_RC" -eq 1 ]; }`

`host_guard || exit 1; printf '%s\n' '=== current snapshot; 사건 peak 아님 ==='; ssh "${SSH_ARGS[@]}" -- free -h; host_guard || exit 1; ssh "${SSH_ARGS[@]}" -- grep -E '^(MemAvailable|SwapFree|SwapTotal|Dirty|Slab):' /proc/meminfo`

producer/filter RC를 따로 기록한다. `filter_rc=1`은 증거 없음이지 정상 아님이다. kernel timestamp, kubelet timestamp, API finishedAt은 canonical UTC의 `start <= evidence <= end` 관계로 대조하며 clock sync가 미확정이면 인과를 확정하지 않는다.

`CONSTRAINT_NONE`이 실제 출력되고 여러 victim/Pod 종료와 맞으며 kubelet eviction 근거가 없을 때 system OOM 가능성이 높다. `CONSTRAINT_MEMCG` 또는 단일 cgroup이면 system OOM으로 기록하지 않는다.

## CRI·cgroup 조건부 경계

특정 victim과 container 관계가 필요할 때만 현재 API Pod UID/container ID, kubelet의 active CRI endpoint exact-one 추출, socket listener와 runtime provider exact match를 [[07. runtime 상태와 Pod container ID가 일치하지 않는 경우]] 절차로 새로 확인한다. 기본 socket·unit·cgroup path를 추측하지 않는다.

API raw ID scheme을 provider와 exact match해 한 번만 제거하고, CRI inspect의 exact ID·Pod UID·container name·sandbox ID가 모두 맞은 뒤에만 runtime이 제공한 container 전용 cgroup path를 읽는다. `/sys/fs/cgroup` root는 대상 container 증거가 아니다.

이 문서의 shell에 남아 있을 수 있는 외부 `CRI_READY` 값은 신뢰하지 않는다. [[07. runtime 상태와 Pod container ID가 일치하지 않는 경우]]에서 current Pod·Node·containerID, 원격 machine-id, active kubelet endpoint와 runtime MainPID/socket provider를 새로 등록하고 exact inspect relation이 성공한 출력만 이 절의 증거로 가져온다.

cgroup v2/v1은 실제 mount와 runtime 연결을 확인한 경우에만 해당 파일을 읽는다. counter 원점과 event 시각이 없으면 누적값을 사건 증거로 단정하지 않는다.

## 보안·변경·정상화

`kubectl auth can-i`는 실제 동일 요청 성공을 보장하지 않는다. node proxy/Pod logs가 필요하면 정확한 subresource RBAC을 fresh 확인한다. audit은 승인된 backend에서 사건 ID·주체·verb/resource·response만 요청한다. Secret/token/key, args/env, 전체 journal은 저장하지 않는다.

이 문서는 mutation 명령을 제공하지 않는다. drop_caches, swap 변경, kill, 파일/image 삭제, limit 변경, Pod 삭제, restart/reboot/cordon/drain은 금지한다. 별도 변경은 fresh evidence, 승인 ID, window, PDB/quorum, 대체 capacity, idempotence·외부 write, rollback 또는 비가역 중단 계획을 모두 요구한다.

이 문서 안에서는 `MUTATION_READY=false`를 유지한다. 별도 변경 절차가 실제 명령을 제공할 때 그 명령 자체가 fresh Node UID/RV·host identity·evidence window·승인 ID·PDB/quorum·대체 capacity·멱등성·rollback 또는 비가역 중단 조건을 다시 검사해야 한다.

replacement는 owner UID로 후보를 다시 조회하고 새 Pod UID/RV/node/container ID를 재등록한다. 후보 0/복수 또는 Ready 전에는 downstream을 실행하지 않는다.

`NORMALIZATION_READY=false; if fresh_node && J="$(kubectl get node "$NODE" -o json)" && [ "$(jq -r '[.status.conditions[]|select(.type=="MemoryPressure")|.status][0]' <<<"$J")" = False ]; then NORMALIZATION_READY=true; printf 'NORMALIZATION_READY=true node_uid=%s rv=%s\n' "$NODE_UID" "$CURRENT_NODE_RV"; else printf '%s\n' '중단: Node condition fresh gate 실패' >&2; fi`

정상화는 관찰 window의 새 kernel OOM·kubelet eviction 부재, same-node replacement 새 UID의 Ready/restart 안정, owner desired=Ready, EndpointSlice `ready=true`, 실제 서비스 요청 또는 Job 산출물까지 확인해야 한다. 한 항목 실패 시 추가 변경을 중단한다.

## Prometheus 빠른 관측

`fresh_node || exit 1; NODE_RE="$(printf '%s' "$NODE" | sed 's/[][\\.^$*+?(){}|]/\\&/g')"; printf 'increase(node_vmstat_oom_kill{nodename=~"^%s$"}[15m])\n' "$NODE_RE"; printf 'sum by(node)(increase(container_oom_events_total{node=~"^%s$",container!=""}[15m]))\n' "$NODE_RE"`

완성 쿼리 출력만 UI에 붙이고 metric/label 미존재, 권한/API 실패, 조회 범위 오류를 빈 정상값과 구분한다.

## 증거·환경 미검증

Node UID/RV, Pod UID/owner/container ID, canonical 시간 관계, remote host/machine-id, producer/filter RC, kernel/kubelet 결정적 행, 조건부 CRI/cgroup exact 관계, 승인·replacement·정상화를 보존한다. cgroup layout, kernel journal, kubelet threshold, CRI endpoint, SSH/NTP/audit/metrics는 환경별 미검증이다. 실제 인프라에는 실행하지 않았다.
