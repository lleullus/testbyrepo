# Node PIDPressure가 True인 경우

## 입력값과 빠른 수집

이 문서의 Kubernetes 명령은 승인된 작업 PC 또는 bastion의 **같은 Bash**에서 실행한다. 호스트 명령은 뒤에서 확인한 Node에 대해 local console 또는 승인된 SSH 한 hop으로만 실행한다.

| 종류 | 변수 | 출처와 gate |
|---|---|---|
| 최초 입력 | `NODE` | 운영자가 Node exact name을 한 번 입력한다. |
| API 자동값 | `NODE_UID`, `NODE_RV`, `NODE_INTERNAL_IP`, `NODE_MACHINE_ID`, `RUNTIME_VERSION` | 같은 Node API 응답에서 원자적으로 등록한다. |
| 계산값 | `NODE_PROM`, `ARGV_RE` | PromQL 문자열 escape와 증상 전용 argv/log 정규식이며 bounded 출력 후 사용한다. |
| 운영자 선택값 | `HOST_MODE`, `SSH_TARGET`, `EXPECTED_HOST`, `EXPECTED_MACHINE_ID`, `START_UTC`, `END_UTC` | 승인된 inventory와 최초 신호 시각을 확인한 뒤 입력한다. |
| 분기 자동값 | `KUBELET_PID`, `KUBELET_ARGV`, `CRI_ENDPOINT`, `RUNTIME_UNIT`, `CONTAINER_ID`, `OWNER_UID` | 현재 host·process·API/CRI exact relation을 통과한 경우에만 유효하다. |

### 1. 실행 위치·도구·최초 입력

`TOOLS_READY=false; MISSING=''; [ -n "${BASH_VERSION:-}" ] || MISSING=' bash'; for T in kubectl jq date sed grep mktemp; do command -v "$T" >/dev/null 2>&1 || MISSING="$MISSING $T"; done; if [ -z "$MISSING" ]; then TOOLS_READY=true; printf 'TOOLS_READY=true bash=%s\n' "$BASH_VERSION"; else printf '중단: 없는 도구=%s\n' "$MISSING" >&2; fi`

`unset INPUT_READY API_READY HOST_READY TIME_READY KUBELET_READY CRI_READY RELATION_READY EVIDENCE_READY DOWNSTREAM_READY NODE_UID NODE_RV NODE_INTERNAL_IP RUNTIME_VERSION NODE_PROM ARGV_RE SSH_TARGET EXPECTED_HOST START_UTC END_UTC KUBELET_PID KUBELET_ARGV CRI_ENDPOINT RUNTIME_UNIT CONTAINER_ID OWNER_UID OWNER_KIND OWNER_NAME POD_UID POD_RV POD_NODE HOST_ID HOST_RELATION START_EPOCH END_EPOCH; NODE='PASTE_NODE_EXACT_NAME_HERE'; INPUT_READY=false; if [ "$TOOLS_READY" = true ] && [ -n "$NODE" ] && kubectl get node "$NODE" >/dev/null 2>&1; then INPUT_READY=true; export NODE; printf 'INPUT_READY=true node=%s\n' "$NODE"; else printf '%s\n' '중단: 도구·권한·Node exact name을 확인한다.' >&2; fi`

`unset NODE_MACHINE_READY NODE_MACHINE_ID EXPECTED_MACHINE_ID HOST_RELATION_READY; NODE_MACHINE_READY=false`

각 `PASTE_..._HERE` 문자열은 문서 전체에서 한 번만 나온다. 새 shell, 재조회 또는 대상 변경 시 이 절부터 다시 실행한다.

### 2. API 자동 수집

재조회 전에 identity, resourceVersion, owner/container/node/host relation, 시간, argv 정규식과 모든 downstream READY를 먼저 폐기한다. API 호출 실패 시 이전 값은 복구하지 않는다.

`unset API_READY HOST_READY TIME_READY KUBELET_READY CRI_READY RELATION_READY EVIDENCE_READY DOWNSTREAM_READY NODE_UID NODE_RV NODE_INTERNAL_IP RUNTIME_VERSION NODE_PROM ARGV_RE SSH_TARGET EXPECTED_HOST START_UTC END_UTC KUBELET_PID KUBELET_ARGV CRI_ENDPOINT RUNTIME_UNIT CONTAINER_ID OWNER_UID OWNER_KIND OWNER_NAME POD_UID POD_RV POD_NODE HOST_ID HOST_RELATION START_EPOCH END_EPOCH; API_READY=false; if [ "$INPUT_READY" != true ]; then printf '%s\n' '중단: INPUT_READY가 아니다.' >&2; elif NODE_JSON="$(kubectl get node "$NODE" -o json)" && NODE_UID_TMP="$(jq -er '.metadata.uid' <<<"$NODE_JSON")" && NODE_RV_TMP="$(jq -er '.metadata.resourceVersion' <<<"$NODE_JSON")" && NODE_IP_TMP="$(jq -er '[.status.addresses[]|select(.type=="InternalIP")|.address]|if length==1 then .[0] else error("InternalIP count") end' <<<"$NODE_JSON")" && RUNTIME_TMP="$(jq -er '.status.nodeInfo.containerRuntimeVersion' <<<"$NODE_JSON")"; then NODE_UID="$NODE_UID_TMP"; NODE_RV="$NODE_RV_TMP"; NODE_INTERNAL_IP="$NODE_IP_TMP"; RUNTIME_VERSION="$RUNTIME_TMP"; NODE_PROM="$(printf '%s' "$NODE" | sed 's/\\/\\\\/g; s/"/\\"/g')"; ARGV_RE='(^|[[:space:]])(--config|--container-runtime-endpoint)(=|[[:space:]])'; API_READY=true; export NODE_UID NODE_RV NODE_INTERNAL_IP RUNTIME_VERSION NODE_PROM ARGV_RE; jq -r '"=== Node ===\n이름: \(.metadata.name)\nUID: \(.metadata.uid)\nresourceVersion: \(.metadata.resourceVersion)\nReady: \([.status.conditions[]|select(.type=="Ready")|.status][0] // "-")\nPIDPressure: \([.status.conditions[]|select(.type=="PIDPressure")|.status][0] // "-")\nPIDPressure 전환: \([.status.conditions[]|select(.type=="PIDPressure")|.lastTransitionTime][0] // "-")\nInternalIP 수: \([.status.addresses[]|select(.type=="InternalIP")]|length)\nRuntime: \(.status.nodeInfo.containerRuntimeVersion)"' <<<"$NODE_JSON"; printf 'API_READY=true NODE_PROM=%s ARGV_RE=%s\n' "$NODE_PROM" "$ARGV_RE"; else printf '%s\n' '중단: Node API/필수 identity 조회 실패, stale 값 폐기됨' >&2; fi`

`unset NODE_MACHINE_READY NODE_MACHINE_ID HOST_RELATION_READY; NODE_MACHINE_READY=false; if [ "$API_READY" = true ] && CURRENT_NODE_JSON="$(kubectl get node "$NODE" -o json)" && [ "$(jq -r '.metadata.uid' <<<"$CURRENT_NODE_JSON")" = "$NODE_UID" ] && [ "$(jq -r '.metadata.resourceVersion' <<<"$CURRENT_NODE_JSON")" = "$NODE_RV" ] && NODE_MACHINE_ID_TMP="$(jq -er '.status.nodeInfo.machineID|select(length>0)' <<<"$CURRENT_NODE_JSON")"; then NODE_MACHINE_ID="$NODE_MACHINE_ID_TMP"; NODE_MACHINE_READY=true; export NODE_MACHINE_ID; printf 'NODE_MACHINE_READY=true machineID=%s\n' "$NODE_MACHINE_ID"; else API_READY=false; printf '%s\n' '중단: current Node UID/RV/machineID 조회 실패; downstream 폐기' >&2; fi`

`API_READY=true`이고 UID·resourceVersion·InternalIP가 하나씩 있어야 한다. `containerRuntimeVersion`은 provider 문자열일 뿐 unit·socket 증거가 아니다.

### 3. host와 UTC 관측 창 선택

`HOST_MODE='PASTE_LOCAL_OR_SSH_HERE'; SSH_TARGET='PASTE_APPROVED_SSH_TARGET_OR_DASH_HERE'; EXPECTED_HOST='PASTE_EXPECTED_REMOTE_HOSTNAME_HERE'; EXPECTED_MACHINE_ID='PASTE_EXPECTED_MACHINE_ID_HERE'; START_UTC='PASTE_START_UTC_RFC3339_HERE'; END_UTC='PASTE_END_UTC_RFC3339_HERE'`

`HOST_READY=false; TIME_READY=false; unset HOST_ID HOST_RELATION START_EPOCH END_EPOCH KUBELET_READY CRI_READY RELATION_READY EVIDENCE_READY DOWNSTREAM_READY; if [ "$API_READY" != true ]; then printf '%s\n' '중단: API_READY가 아니다.' >&2; elif [ "$HOST_MODE" != local ] && [ "$HOST_MODE" != ssh ]; then printf '%s\n' '중단: HOST_MODE은 local 또는 ssh다.' >&2; elif [ "$HOST_MODE" = ssh ] && { [ -z "$SSH_TARGET" ] || [ -z "$EXPECTED_HOST" ]; }; then printf '%s\n' '중단: 승인된 SSH target과 expected hostname이 필요하다.' >&2; else HOST_READY=true; fi; if ! [[ "$START_UTC" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] || ! [[ "$END_UTC" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]]; then printf '%s\n' '중단: UTC RFC3339 초 단위 형식이 아니다.' >&2; elif START_ROUND="$(date -u -d "$START_UTC" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" && END_ROUND="$(date -u -d "$END_UTC" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" && [ "$START_ROUND" = "$START_UTC" ] && [ "$END_ROUND" = "$END_UTC" ]; then START_EPOCH="$(date -u -d "$START_UTC" +%s)"; END_EPOCH="$(date -u -d "$END_UTC" +%s)"; if [ "$START_EPOCH" -lt "$END_EPOCH" ]; then TIME_READY=true; export START_UTC END_UTC; else printf '%s\n' '중단: start는 end보다 빨라야 한다.' >&2; fi; else printf '%s\n' '중단: date UTC round-trip 실패' >&2; fi; printf 'HOST_READY=%s TIME_READY=%s start=%s end=%s\n' "$HOST_READY" "$TIME_READY" "$START_UTC" "$END_UTC"`

`HOST_RELATION_READY=false; if [ "$HOST_READY" != true ] || [ "$NODE_MACHINE_READY" != true ] || [ -z "$EXPECTED_MACHINE_ID" ] || [ "$EXPECTED_MACHINE_ID" != "$NODE_MACHINE_ID" ]; then HOST_READY=false; printf '%s\n' '중단: inventory expected machineID와 current Node machineID가 일치하지 않는다.' >&2; elif [ "$HOST_MODE" = local ]; then ACTUAL_HOST="$(hostname -f 2>/dev/null || hostname)"; ACTUAL_MACHINE_ID="$(cat /etc/machine-id 2>/dev/null)"; if [ "$ACTUAL_MACHINE_ID" = "$EXPECTED_MACHINE_ID" ]; then HOST_RELATION_READY=true; else HOST_READY=false; fi; printf 'local-host=%s machineID=%s HOST_RELATION_READY=%s\n' "$ACTUAL_HOST" "$ACTUAL_MACHINE_ID" "$HOST_RELATION_READY"; elif REMOTE_ID="$(ssh -- "$SSH_TARGET" bash -c 'actual=$(hostname -f 2>/dev/null || hostname); machine=$(cat /etc/machine-id) || exit 1; [ "$actual" = "$1" ] && [ "$machine" = "$2" ] || exit 1; printf "%s %s" "$actual" "$machine"' _ "$EXPECTED_HOST" "$EXPECTED_MACHINE_ID")"; then HOST_RELATION_READY=true; printf 'remote-identity=%s HOST_RELATION_READY=true\n' "$REMOTE_ID"; else HOST_READY=false; printf '%s\n' '중단: remote hostname/machine-id identity 불일치' >&2; fi`

SSH hop은 `작업 PC → 승인된 SSH target → Node host → kubelet process → active CRI endpoint → container/cgroup`이다. `ssh "$SSH_TARGET" "문자열"`, `eval`, 중첩 shell interpolation을 사용하지 않는다. 아래 방식처럼 고정 script와 positional argument만 전달한다.

`if [ "$HOST_READY" != true ] || [ "$HOST_MODE" != ssh ]; then printf '%s\n' '중단: ssh host gate가 아니다.' >&2; else ssh -- "$SSH_TARGET" bash -s -- "$EXPECTED_HOST" <<'REMOTE'
set -u
expected=$1
actual=$(hostname -f 2>/dev/null || hostname)
printf 'remote-host=%s expected=%s\n' "$actual" "$expected"
[ "$actual" = "$expected" ] || { printf '%s\n' '중단: remote identity 불일치' >&2; exit 1; }
REMOTE
fi`

remote identity 성공과 승인 inventory의 `NODE_UID ↔ InternalIP ↔ EXPECTED_HOST` 관계를 사건 기록에서 대조한 뒤에만 `HOST_RELATION=approved`로 기록한다. hostname 일치만으로 Kubernetes Node 관계를 확정하지 않는다.

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | 같은 Node UID에서 `PIDPressure=True`, `NodeHasPIDPressure` 또는 kubelet `pid.available` 부족이 관측됨 |
| 적용 | Node identity·시간 창과 host/kubelet/CRI/Linux 증거를 연결할 수 있음 |
| 제외 | `MemoryPressure`·`DiskPressure`만 있으면 해당 전용 런북, `Preempted`면 scheduler 경로, 단일 Pod OOM이면 OOMKilled 런북 |

검색 문자열: `PIDPressure`, `NodeHasPIDPressure`, `pid.available`, `EvictionThresholdMet`, `resource temporarily unavailable`, `fork`, `pids.current`, `pids.max`.

## 최초 확인

`if [ "$API_READY" = true ]; then kubectl get node "$NODE" -o custom-columns='NODE:.metadata.name,UID:.metadata.uid,RV:.metadata.resourceVersion,READY:.status.conditions[?(@.type=="Ready")].status,PID-PRESSURE:.status.conditions[?(@.type=="PIDPressure")].status,PID-TRANSITION:.status.conditions[?(@.type=="PIDPressure")].lastTransitionTime,RUNTIME:.status.nodeInfo.containerRuntimeVersion'; else printf '%s\n' '중단: API_READY가 아니다.' >&2; fi`

`if [ "$API_READY" = true ]; then kubectl get pods -A --field-selector "spec.nodeName=$NODE" -o custom-columns='NAMESPACE:.metadata.namespace,POD:.metadata.name,UID:.metadata.uid,RV:.metadata.resourceVersion,PHASE:.status.phase,REASON:.status.reason,OWNER-KIND:.metadata.ownerReferences[0].kind,OWNER-UID:.metadata.ownerReferences[0].uid,READY:.status.containerStatuses[*].ready,CONTAINER-ID:.status.containerStatuses[*].containerID'; else printf '%s\n' '중단: API_READY가 아니다.' >&2; fi`

현재 목록은 이미 삭제된 Evicted Pod를 복원하지 않는다. UID·owner UID·containerID·Node UID가 같은 관측 창에 있을 때만 workload와 runtime 증거를 연결한다.

## 읽기 전용 진단

### 1. kubelet과 Linux PID 신호

local console이면 같은 script body를 local Bash에서 실행한다. SSH이면 아래 고정 script를 사용한다. `systemctl` unit은 provider가 확인한 실제 kubelet unit만 positional argument로 전달한다.

`KUBELET_UNIT='PASTE_CONFIRMED_KUBELET_UNIT_HERE'`

`if [ "$HOST_READY" != true ] || [ "$TIME_READY" != true ] || [ "$HOST_MODE" != ssh ]; then printf '%s\n' '중단: host/time/ssh gate가 아니다.' >&2; else ssh -- "$SSH_TARGET" bash -s -- "$EXPECTED_HOST" "$KUBELET_UNIT" "$START_UTC" "$END_UTC" <<'REMOTE'
set -u
expected=$1
unit=$2
start=$3
end=$4
actual=$(hostname -f 2>/dev/null || hostname)
[ "$actual" = "$expected" ] || { printf '%s\n' '중단: remote identity 불일치' >&2; exit 1; }
pid=$(systemctl show "$unit" -p MainPID --value) || exit 1
[[ "$pid" =~ ^[1-9][0-9]*$ ]] || { printf '%s\n' '중단: active kubelet MainPID 없음' >&2; exit 1; }
printf 'host=%s unit=%s kubelet-pid=%s\n' "$actual" "$unit" "$pid"
tr '\0' '\n' <"/proc/$pid/cmdline"
printf '%s\n' '=== pid totals ==='
ps_tmp=$(mktemp) || exit 1
if ps -e --no-headers >"$ps_tmp"; then ps_rc=0; else ps_rc=$?; fi
if [ "$ps_rc" -ne 0 ]; then rm -f "$ps_tmp"; exit "$ps_rc"; fi
printf 'processes=%s\n' "$(wc -l <"$ps_tmp")"
if ps -eLf --no-headers >"$ps_tmp"; then thread_rc=0; else thread_rc=$?; fi
if [ "$thread_rc" -ne 0 ]; then rm -f "$ps_tmp"; exit "$thread_rc"; fi
printf 'threads=%s\n' "$(wc -l <"$ps_tmp")"
rm -f "$ps_tmp"
cat /proc/sys/kernel/pid_max
tmp=$(mktemp) || exit 1
if sudo journalctl -u "$unit" --since "$start" --until "$end" --no-pager >"$tmp"; then producer_rc=0; else producer_rc=$?; fi
if [ "$producer_rc" -ne 0 ]; then rm -f "$tmp"; printf '중단: journal producer rc=%s\n' "$producer_rc" >&2; exit "$producer_rc"; fi
if grep -E -i -C 3 'pid\.available|PIDPressure|EvictionThresholdMet|resource temporarily unavailable|fork|too many processes|failed to create|failed to stop' "$tmp"; then filter_rc=0; else filter_rc=$?; fi
printf 'journal_producer_rc=%s filter_rc=%s\n' "$producer_rc" "$filter_rc"
if [ "$filter_rc" -eq 1 ]; then printf '%s\n' '필터 무일치: 오류 없음으로 해석하지 말고 같은 창의 bounded journal을 owner에게 요청한다.'; fi
rm -f "$tmp"
REMOTE
fi`

producer rc가 0이고 filter rc가 0일 때만 결정적 행을 사용한다. filter rc 1은 무일치, 2 이상은 filter 오류다. 현재 process/thread 수는 과거 peak를 증명하지 않는다.

### 2. active CRI와 workload relation

active kubelet의 `/proc/$KUBELET_PID/cmdline`과 실제 `--config` source에서 runtime endpoint를 확인한다. endpoint가 둘 이상이거나 socket 추측만 가능하면 중단한다. `containerRuntimeVersion` 문자열로 `/run/containerd/containerd.sock` 등을 만들지 않는다.

`CRI_ENDPOINT='PASTE_EXACT_ACTIVE_CRI_ENDPOINT_HERE'; RUNTIME_UNIT='PASTE_CONFIRMED_RUNTIME_UNIT_HERE'; CONTAINER_ID='PASTE_EXACT_CONTAINER_ID_HERE'`

`CRI_READY=false; if [ "$HOST_READY" != true ] || [ "$TIME_READY" != true ]; then printf '%s\n' '중단: host/time gate가 아니다.' >&2; elif [ -z "$CRI_ENDPOINT" ] || ! [[ "$CRI_ENDPOINT" =~ ^unix:///[^[:space:]]+$ ]]; then printf '%s\n' '중단: active kubelet에서 확인한 unix CRI endpoint가 아니다.' >&2; elif [ -z "$CONTAINER_ID" ] || ! [[ "$CONTAINER_ID" =~ ^[a-f0-9]{12,64}$ ]]; then printf '%s\n' '중단: exact container ID 형식이 아니다.' >&2; else CRI_READY=true; printf 'CRI_READY=true endpoint=%s runtime-unit=%s container-id=%s\n' "$CRI_ENDPOINT" "$RUNTIME_UNIT" "$CONTAINER_ID"; fi`

`if [ "$CRI_READY" != true ] || [ "$HOST_RELATION_READY" != true ] || [ "$HOST_MODE" != ssh ] || ! CURRENT_NODE_JSON="$(kubectl get node "$NODE" -o json)" || [ "$(jq -r '.metadata.uid' <<<"$CURRENT_NODE_JSON")" != "$NODE_UID" ] || [ "$(jq -r '.metadata.resourceVersion' <<<"$CURRENT_NODE_JSON")" != "$NODE_RV" ]; then printf '%s\n' '중단: current CRI/host/Node gate가 아니다.' >&2; else ssh -- "$SSH_TARGET" bash -s -- "$EXPECTED_HOST" "$EXPECTED_MACHINE_ID" "$KUBELET_UNIT" "$CRI_ENDPOINT" "$RUNTIME_UNIT" "$CONTAINER_ID" <<'REMOTE'
set -u
expected=$1
expected_machine=$2
kubelet_unit=$3
endpoint=$4
runtime_unit=$5
cid=$6
actual=$(hostname -f 2>/dev/null || hostname)
[ "$actual" = "$expected" ] && [ "$(cat /etc/machine-id)" = "$expected_machine" ] || exit 1
command -v crictl >/dev/null 2>&1 || { printf '%s\n' '중단: crictl 없음' >&2; exit 1; }
kpid=$(systemctl show "$kubelet_unit" -p MainPID --value) || exit 1
rpid=$(systemctl show "$runtime_unit" -p MainPID --value) || exit 1
[[ "$kpid" =~ ^[1-9][0-9]*$ ]] && [[ "$rpid" =~ ^[1-9][0-9]*$ ]] || { printf '%s\n' '중단: active kubelet/runtime PID 없음' >&2; exit 1; }
mapfile -d '' -t argv <"/proc/$kpid/cmdline"
active=''
config=''
for ((i=0;i<${#argv[@]};i++)); do case "${argv[$i]}" in --container-runtime-endpoint=*) active=${argv[$i]#*=};; --container-runtime-endpoint) ((i++)); active=${argv[$i]:-};; --config=*) config=${argv[$i]#*=};; --config) ((i++)); config=${argv[$i]:-};; esac; done
if [ -z "$active" ]; then [[ "$config" = /* && -f "$config" && -r "$config" ]] || { printf '%s\n' '중단: kubelet config가 absolute readable regular file이 아님' >&2; exit 1; }; ep_tmp=$(mktemp) || exit 1; if grep -E '^[[:space:]]*containerRuntimeEndpoint:[[:space:]]*[^[:space:]].*$' "$config" >"$ep_tmp"; then ep_rc=0; else ep_rc=$?; fi; if [ "$ep_rc" -ne 0 ]; then rm -f "$ep_tmp"; printf '중단: endpoint filter rc=%s\n' "$ep_rc" >&2; exit "$ep_rc"; fi; mapfile -t ep_lines <"$ep_tmp"; rm -f "$ep_tmp"; [ "${#ep_lines[@]}" -eq 1 ] || { printf '%s\n' '중단: containerRuntimeEndpoint key가 정확히 하나가 아님' >&2; exit 1; }; active=${ep_lines[0]#*:}; active=${active# }; active=${active%$'\r'}; active=${active#\"}; active=${active%\"}; fi
[[ "$active" =~ ^unix:///[^[:space:]]+$ ]] && [ "$active" = "$endpoint" ] || { printf '중단: selected endpoint가 active kubelet endpoint와 다름 active=%s selected=%s\n' "$active" "$endpoint" >&2; exit 1; }
socket=${endpoint#unix://}
[ -S "$socket" ] || { printf '%s\n' '중단: CRI socket이 socket이 아님' >&2; exit 1; }
sock_tmp=$(mktemp) || exit 1
if sudo ss -xlpn >"$sock_tmp"; then ss_rc=0; else ss_rc=$?; fi
if [ "$ss_rc" -ne 0 ]; then rm -f "$sock_tmp"; exit "$ss_rc"; fi
provider_rc=1
while IFS= read -r socket_line; do if [[ "$socket_line" == *"$socket"* && "$socket_line" == *"pid=$rpid,"* ]]; then provider_rc=0; break; fi; done <"$sock_tmp"
rm -f "$sock_tmp"
[ "$provider_rc" -eq 0 ] || { printf '중단: runtime unit PID가 socket provider가 아님 pid=%s socket=%s filter_rc=%s\n' "$rpid" "$socket" "$provider_rc" >&2; exit 1; }
sudo crictl --runtime-endpoint "$endpoint" info >/dev/null || { printf '%s\n' '중단: active endpoint 검증 실패' >&2; exit 1; }
sudo crictl --runtime-endpoint "$endpoint" inspect "$cid"
REMOTE
fi`

inspect에서 exact container ID, Pod sandbox metadata UID, container name과 state를 API의 `containerID`, Pod UID·owner UID와 대조한다. 일치하지 않으면 stale/reused ID로 간주해 폐기한다. raw inspect에는 env·mount가 포함될 수 있으므로 저장하지 말고 identity/state/cgroup path만 기록한다. cgroup `pids.current`·`pids.max`는 이 exact relation이 성립한 경우에만 node/Linux owner가 읽는다.

## 상태 변경 경계

이 문서의 명령은 읽기 전용이다. process kill, `pid_max`·cgroup 변경, Pod 삭제, kubelet/runtime restart, eviction threshold 변경, cordon/drain을 실행하지 않는다.

변경은 fresh Node UID/RV, active kubelet PID/argv·CRI endpoint, exact owner/container relation, UTC 증거 창, 영향 owner와 quorum/PDB/Job side effect, 승인 ID·작업 창·2인 확인, idempotence, 중단 조건과 rollback target을 모두 확보한 별도 절차에서만 한다. rollback 직전에도 Node UID/RV와 변경 대상 source revision을 재조회한다. 교체 Node/Pod/container가 생기면 이전 identity·READY를 폐기하고 새 UID/containerID를 처음부터 등록한다.

## 정상화 검증

`NORMALIZATION_READY=false; if [ "$API_READY" = true ] && CURRENT_NODE_JSON="$(kubectl get node "$NODE" -o json)" && [ "$(jq -r '.metadata.uid' <<<"$CURRENT_NODE_JSON")" = "$NODE_UID" ] && [ "$(jq -r '.status.nodeInfo.machineID' <<<"$CURRENT_NODE_JSON")" = "$NODE_MACHINE_ID" ]; then jq -r '"NODE=\(.metadata.name) UID=\(.metadata.uid) RV=\(.metadata.resourceVersion) READY=\([.status.conditions[]|select(.type=="Ready")|.status][0]) PID-PRESSURE=\([.status.conditions[]|select(.type=="PIDPressure")|.status][0]) TRANSITION=\([.status.conditions[]|select(.type=="PIDPressure")|.lastTransitionTime][0])"' <<<"$CURRENT_NODE_JSON"; NORMALIZATION_READY=true; else printf '%s\n' '중단: current Node UID/machineID normalization gate 실패' >&2; fi`

정상화는 새 `pid.available`/eviction 경고가 승인된 관찰 창 동안 없고, Linux PID·thread와 exact cgroup이 안정되며, replacement가 재-Evicted되지 않고, owner desired/Ready와 실제 Service 요청 또는 Job 산출물이 정상일 때만 선언한다. `PIDPressure=False`, Pod `Running`, process 수 한 번 감소는 단독 근거가 아니다.

## Prometheus 빠른 관측

metric/label 존재를 먼저 확인하고 아래 생성 명령의 출력만 Prometheus/Grafana에 붙인다.

`if [ "$API_READY" = true ]; then printf 'kube_node_status_condition{node="%s",condition="PIDPressure",status="true"} == 1\n' "$NODE_PROM"; printf 'sum by(node) (kube_pod_status_reason{node="%s",reason="Evicted"} == 1)\n' "$NODE_PROM"; else printf '%s\n' '중단: API_READY가 아니다.' >&2; fi`

두 번째 metric에 `node` label이 없는 환경에서는 query가 비거나 잘못된 결과가 될 수 있으므로 kube-state-metrics의 실제 labels를 확인해 `kube_pod_info`와 UID 기준 join을 설계한다. 빈 결과는 0이나 정상으로 해석하지 않고 metric 미수집, label 불일치, retention 범위, Prometheus 권한/API 실패를 분리한다.

## 증거와 미검증

Node UID/RV, UTC 창, condition transition, host relation, kubelet PID/argv/config source, exact CRI endpoint·runtime provider, Pod/owner UID와 containerID relation, producer/filter rc, 결정적 로그, 변경 승인과 실제 기능 결과만 보존한다. Secret·token·전체 argv 환경·raw CRI inspect·전체 process/journal은 저장하지 않는다.

Kubernetes 1.26의 Node-pressure eviction과 Node condition을 기준으로 했다. 배포판별 kubelet unit/config, SSH inventory, CRI endpoint·runtime unit, cgroup version, metrics label은 환경 미검증이다.
