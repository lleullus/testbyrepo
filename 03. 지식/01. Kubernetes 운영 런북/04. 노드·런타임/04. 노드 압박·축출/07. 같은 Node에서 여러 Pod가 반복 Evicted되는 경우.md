# 같은 Node에서 여러 Pod가 반복 Evicted되는 경우

## 입력값과 빠른 수집

이 문서는 같은 Node UID와 UTC 관측 창에서 둘 이상의 Pod UID가 Evicted되거나 replacement가 다시 Evicted되는 사건을 다룬다. API 명령은 승인된 작업 PC/bastion의 같은 Bash에서, host 명령은 확인된 Node에 대한 승인된 한 hop에서만 실행한다.

| 종류 | 변수 | 출처와 gate |
|---|---|---|
| 최초 입력 | `NODE` | Node exact name을 한 번 입력한다. |
| API 자동값 | `NODE_UID`, `NODE_RV`, `NODE_INTERNAL_IP`, `NODE_MACHINE_ID`, `RUNTIME_VERSION` | exact Node 응답에서 원자적으로 등록한다. |
| 계산값 | `NODE_PROM`, `EVENT_FIELD`, `ARGV_RE` | PromQL escape, representative UID Event selector, kubelet argv 식별식이다. |
| 운영자 선택값 | `REP_NS`, `REP_POD`, `START_UTC`, `END_UTC`, `SSH_TARGET`, `EXPECTED_HOST`, `EXPECTED_MACHINE_ID` | 현재 목록과 승인 inventory를 본 뒤 선택한다. |
| 선택 후 API 자동값 | `REP_UID`, `REP_RV`, `REP_NODE`, `OWNER_KIND`, `OWNER_NAME`, `OWNER_UID`, `CONTAINER_IDS` | representative Pod exact 조회가 Node UID 관계를 통과할 때만 등록한다. |

### 2. API 자동 수집과 영향 목록

재조회 전에는 identity/RV/owner/containerID/node/host/relation/time/argv-regex와 모든 downstream READY를 완전히 폐기한다. 실패한 재조회 뒤 이전 값을 사용하지 않는다.

`unset API_READY SELECTION_READY TIME_READY HOST_READY KUBELET_READY CRI_READY RELATION_READY EVENT_READY OWNER_READY IMPACT_READY DOWNSTREAM_READY NODE_UID NODE_RV NODE_INTERNAL_IP RUNTIME_VERSION NODE_PROM EVENT_FIELD ARGV_RE REP_NS REP_POD REP_UID REP_RV REP_NODE OWNER_KIND OWNER_NAME OWNER_UID CONTAINER_IDS SSH_TARGET EXPECTED_HOST HOST_ID HOST_RELATION START_UTC END_UTC START_EPOCH END_EPOCH KUBELET_PID KUBELET_ARGV CRI_ENDPOINT RUNTIME_UNIT CONTAINER_ID; API_READY=false; if [ "$INPUT_READY" != true ]; then printf '%s\n' '중단: INPUT_READY가 아니다.' >&2; elif NODE_JSON="$(kubectl get node "$NODE" -o json)" && NODE_UID_TMP="$(jq -er '.metadata.uid' <<<"$NODE_JSON")" && NODE_RV_TMP="$(jq -er '.metadata.resourceVersion' <<<"$NODE_JSON")" && NODE_IP_TMP="$(jq -er '[.status.addresses[]|select(.type=="InternalIP")|.address]|if length==1 then .[0] else error("InternalIP count") end' <<<"$NODE_JSON")" && RUNTIME_TMP="$(jq -er '.status.nodeInfo.containerRuntimeVersion' <<<"$NODE_JSON")"; then NODE_UID="$NODE_UID_TMP"; NODE_RV="$NODE_RV_TMP"; NODE_INTERNAL_IP="$NODE_IP_TMP"; RUNTIME_VERSION="$RUNTIME_TMP"; NODE_PROM="$(printf '%s' "$NODE" | sed 's/\\/\\\\/g; s/"/\\"/g')"; ARGV_RE='(^|[[:space:]])(--config|--container-runtime-endpoint)(=|[[:space:]])'; API_READY=true; export NODE_UID NODE_RV NODE_INTERNAL_IP RUNTIME_VERSION NODE_PROM ARGV_RE; jq -r '"=== Node ===\n이름: \(.metadata.name)\nUID: \(.metadata.uid)\nRV: \(.metadata.resourceVersion)\nReady: \([.status.conditions[]|select(.type=="Ready")|.status][0] // "-")\nMemoryPressure: \([.status.conditions[]|select(.type=="MemoryPressure")|.status][0] // "-")\nDiskPressure: \([.status.conditions[]|select(.type=="DiskPressure")|.status][0] // "-")\nPIDPressure: \([.status.conditions[]|select(.type=="PIDPressure")|.status][0] // "-")\nRuntime: \(.status.nodeInfo.containerRuntimeVersion)"' <<<"$NODE_JSON"; printf 'API_READY=true NODE_PROM=%s ARGV_RE=%s\n' "$NODE_PROM" "$ARGV_RE"; else printf '%s\n' '중단: Node API/identity 실패, stale 값 폐기됨' >&2; fi`

`if [ "$API_READY" = true ]; then kubectl get pods -A --field-selector "spec.nodeName=$NODE" -o custom-columns='NAMESPACE:.metadata.namespace,POD:.metadata.name,UID:.metadata.uid,RV:.metadata.resourceVersion,CREATED:.metadata.creationTimestamp,PHASE:.status.phase,REASON:.status.reason,MESSAGE:.status.message,OWNER-KIND:.metadata.ownerReferences[0].kind,OWNER-NAME:.metadata.ownerReferences[0].name,OWNER-UID:.metadata.ownerReferences[0].uid,READY:.status.containerStatuses[*].ready,CONTAINER-ID:.status.containerStatuses[*].containerID'; else printf '%s\n' '중단: API_READY가 아니다.' >&2; fi`

이 broad query는 같은 Node의 현재 blast radius를 한 번 확인하기 위한 것이다. 삭제된 Pod와 retention 밖 Event는 포함하지 않는다. `Failed`, `Preempted`, `OOMKilled`를 Evicted로 합산하지 않는다.

### 3. representative와 엄격한 UTC 창

`REP_NS='PASTE_REPRESENTATIVE_NAMESPACE_HERE'; REP_POD='PASTE_REPRESENTATIVE_POD_HERE'; START_UTC='PASTE_START_UTC_RFC3339_HERE'; END_UTC='PASTE_END_UTC_RFC3339_HERE'; SSH_TARGET='PASTE_APPROVED_SSH_TARGET_HERE'; EXPECTED_HOST='PASTE_EXPECTED_REMOTE_HOSTNAME_HERE'; EXPECTED_MACHINE_ID='PASTE_EXPECTED_MACHINE_ID_HERE'`

`SELECTION_READY=false; TIME_READY=false; HOST_READY=false; unset REP_UID REP_RV REP_NODE OWNER_KIND OWNER_NAME OWNER_UID CONTAINER_IDS EVENT_FIELD START_EPOCH END_EPOCH HOST_ID HOST_RELATION EVENT_READY OWNER_READY IMPACT_READY DOWNSTREAM_READY; if [ "$API_READY" != true ]; then printf '%s\n' '중단: API_READY가 아니다.' >&2; elif REP_JSON="$(kubectl get pod "$REP_POD" -n "$REP_NS" -o json)" && REP_UID_TMP="$(jq -er '.metadata.uid' <<<"$REP_JSON")" && REP_RV_TMP="$(jq -er '.metadata.resourceVersion' <<<"$REP_JSON")" && REP_NODE_TMP="$(jq -er '.spec.nodeName' <<<"$REP_JSON")" && [ "$REP_NODE_TMP" = "$NODE" ] && [ "$(jq -r '.status.reason // empty' <<<"$REP_JSON")" = Evicted ]; then REP_UID="$REP_UID_TMP"; REP_RV="$REP_RV_TMP"; REP_NODE="$REP_NODE_TMP"; OWNER_KIND="$(jq -r '.metadata.ownerReferences[0].kind // empty' <<<"$REP_JSON")"; OWNER_NAME="$(jq -r '.metadata.ownerReferences[0].name // empty' <<<"$REP_JSON")"; OWNER_UID="$(jq -r '.metadata.ownerReferences[0].uid // empty' <<<"$REP_JSON")"; CONTAINER_IDS="$(jq -r '[.status.containerStatuses[]?.containerID]|join(",")' <<<"$REP_JSON")"; EVENT_FIELD="involvedObject.kind=Pod,involvedObject.name=$REP_POD,involvedObject.uid=$REP_UID"; SELECTION_READY=true; export REP_NS REP_POD REP_UID REP_RV REP_NODE OWNER_KIND OWNER_NAME OWNER_UID CONTAINER_IDS EVENT_FIELD; else printf '%s\n' '중단: representative exact identity/Node/Evicted 관계 실패' >&2; fi; if [[ "$START_UTC" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] && [[ "$END_UTC" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] && [ "$(date -u -d "$START_UTC" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" = "$START_UTC" ] && [ "$(date -u -d "$END_UTC" '+%Y-%m-%dT%H:%M:%SZ' 2>/dev/null)" = "$END_UTC" ]; then START_EPOCH="$(date -u -d "$START_UTC" +%s)"; END_EPOCH="$(date -u -d "$END_UTC" +%s)"; if [ "$START_EPOCH" -lt "$END_EPOCH" ]; then TIME_READY=true; export START_UTC END_UTC; fi; fi; if [ -n "$SSH_TARGET" ] && [ -n "$EXPECTED_HOST" ]; then HOST_READY=true; fi; printf 'SELECTION_READY=%s TIME_READY=%s HOST_READY=%s pod=%s uid=%s owner=%s/%s owner_uid=%s\n' "$SELECTION_READY" "$TIME_READY" "$HOST_READY" "$REP_POD" "${REP_UID:--}" "${OWNER_KIND:--}" "${OWNER_NAME:--}" "${OWNER_UID:--}"`

`TIME_READY=true`가 아니면 journal·metrics·Event 시간 상관을 시작하지 않는다. start는 최초 Evicted보다 앞서야 하고 end는 조사 상한이어야 한다.

`HOST_RELATION_READY=false; NODE_MACHINE_ID=''; if [ "$API_READY" != true ] || [ "$HOST_READY" != true ] || [ -z "$EXPECTED_MACHINE_ID" ]; then HOST_READY=false; printf '%s\n' '중단: API/host/expected machineID gate가 아니다.' >&2; elif CURRENT_NODE_JSON="$(kubectl get node "$NODE" -o json)" && [ "$(jq -r '.metadata.uid' <<<"$CURRENT_NODE_JSON")" = "$NODE_UID" ] && NODE_MACHINE_ID_TMP="$(jq -er '.status.nodeInfo.machineID|select(length>0)' <<<"$CURRENT_NODE_JSON")" && [ "$NODE_MACHINE_ID_TMP" = "$EXPECTED_MACHINE_ID" ] && REMOTE_ID="$(ssh -- "$SSH_TARGET" bash -c 'actual=$(hostname -f 2>/dev/null || hostname); machine=$(cat /etc/machine-id) || exit 1; [ "$actual" = "$1" ] && [ "$machine" = "$2" ] || exit 1; printf "%s %s" "$actual" "$machine"' _ "$EXPECTED_HOST" "$EXPECTED_MACHINE_ID")"; then NODE_MACHINE_ID="$NODE_MACHINE_ID_TMP"; HOST_RELATION_READY=true; export NODE_MACHINE_ID; printf 'HOST_RELATION_READY=true remote=%s node_uid=%s\n' "$REMOTE_ID" "$NODE_UID"; else HOST_READY=false; printf '%s\n' '중단: Node UID/machineID/remote host relation 실패' >&2; fi`

## 읽기 전용 진단

### 1. pressure signal과 host 증거

실행 hop은 `작업 PC → SSH target → expected Node host → active kubelet → pressure signal → Pod UID`다. hostname은 Node relation의 필요조건일 뿐 충분조건이 아니므로 승인 inventory의 Node UID/InternalIP/host 관계도 확인한다.

`KUBELET_UNIT='PASTE_CONFIRMED_KUBELET_UNIT_HERE'`

`if [ "$HOST_RELATION_READY" != true ] || [ "$TIME_READY" != true ] || ! CURRENT_REP_JSON="$(kubectl get pod "$REP_POD" -n "$REP_NS" -o json)" || [ "$(jq -r '.metadata.uid' <<<"$CURRENT_REP_JSON")" != "$REP_UID" ] || [ "$(jq -r '.metadata.resourceVersion' <<<"$CURRENT_REP_JSON")" != "$REP_RV" ]; then printf '%s\n' '중단: current host/time/representative gate가 아니다.' >&2; else ssh -- "$SSH_TARGET" bash -s -- "$EXPECTED_HOST" "$EXPECTED_MACHINE_ID" "$KUBELET_UNIT" "$START_UTC" "$END_UTC" "$REP_UID" <<'REMOTE'
set -u
expected=$1
expected_machine=$2
unit=$3
start=$4
end=$5
pod_uid=$6
actual=$(hostname -f 2>/dev/null || hostname)
[ "$actual" = "$expected" ] && [ "$(cat /etc/machine-id)" = "$expected_machine" ] || { printf '%s\n' '중단: remote identity 불일치' >&2; exit 1; }
pid=$(systemctl show "$unit" -p MainPID --value) || exit 1
[[ "$pid" =~ ^[1-9][0-9]*$ ]] || { printf '%s\n' '중단: active kubelet PID 없음' >&2; exit 1; }
printf 'host=%s kubelet-pid=%s pod-uid=%s\n' "$actual" "$pid" "$pod_uid"
tr '\0' '\n' <"/proc/$pid/cmdline"
tmp=$(mktemp) || exit 1
if sudo journalctl -u "$unit" --since "$start" --until "$end" --no-pager >"$tmp"; then producer_rc=0; else producer_rc=$?; fi
if [ "$producer_rc" -ne 0 ]; then rm -f "$tmp"; printf '중단: journal producer rc=%s\n' "$producer_rc" >&2; exit "$producer_rc"; fi
if grep -E -i -C 3 "${pod_uid}|EvictionThresholdMet|must evict|memory\.available|nodefs\.available|imagefs\.available|inodesFree|pid\.available|DiskPressure|MemoryPressure|PIDPressure" "$tmp"; then filter_rc=0; else filter_rc=$?; fi
printf 'producer_rc=%s filter_rc=%s\n' "$producer_rc" "$filter_rc"
[ "$filter_rc" -le 1 ] || { rm -f "$tmp"; exit "$filter_rc"; }
rm -f "$tmp"
REMOTE
fi`

producer와 filter rc를 따로 기록한다. filter rc 1은 오류 없음이 아니라 선택한 UID/문자열이 bounded 창에서 없다는 뜻이다. signal family가 둘 이상이면 임의로 하나를 선택하지 않는다. runtime/CRI를 확인해야 할 때는 active kubelet argv 또는 확인된 config의 **정확한** endpoint 하나만 사용하며 provider 문자열로 socket을 추측하지 않는다.

### 2. owner와 replacement lifecycle

owner UID가 비어 있으면 owner를 이름으로 추측하지 않는다. ReplicaSet이면 상위 Deployment를 한 단계 더 exact UID로 확인한다. StatefulSet은 ordinal/PVC/quorum, Job은 completion/외부 side effect, DaemonSet/Deployment는 desired/Ready와 Service endpoint를 각각 확인한다.

`OWNER_READY=false; if [ "$SELECTION_READY" != true ] || [ -z "$OWNER_KIND" ] || [ -z "$OWNER_NAME" ] || [ -z "$OWNER_UID" ]; then printf '%s\n' '중단: exact owner relation이 없다.' >&2; elif CURRENT_REP_JSON="$(kubectl get pod "$REP_POD" -n "$REP_NS" -o json)" && [ "$(jq -r '.metadata.uid' <<<"$CURRENT_REP_JSON")" = "$REP_UID" ] && OWNER_JSON="$(kubectl get "$OWNER_KIND" "$OWNER_NAME" -n "$REP_NS" -o json)" && [ "$(jq -r '.metadata.uid' <<<"$OWNER_JSON")" = "$OWNER_UID" ]; then OWNER_READY=true; jq -r '"KIND=\(.kind) NAME=\(.metadata.name) UID=\(.metadata.uid) RV=\(.metadata.resourceVersion) REPLICAS=\(.spec.replicas//"-") READY=\(.status.readyReplicas//"-") AVAILABLE=\(.status.availableReplicas//"-") ACTIVE=\(.status.active//"-") SUCCEEDED=\(.status.succeeded//"-") FAILED=\(.status.failed//"-")"' <<<"$OWNER_JSON"; else printf '%s\n' '중단: current representative→owner UID relation 실패' >&2; fi`

`if [ "$OWNER_READY" = true ] && CURRENT_OWNER_JSON="$(kubectl get "$OWNER_KIND" "$OWNER_NAME" -n "$REP_NS" -o json)" && [ "$(jq -r '.metadata.uid' <<<"$CURRENT_OWNER_JSON")" = "$OWNER_UID" ]; then POD_LIST_JSON="$(kubectl get pods -n "$REP_NS" -o json)" || exit 1; jq -r --arg uid "$OWNER_UID" '.items[]|select(any(.metadata.ownerReferences[]?;.uid==$uid))|[.metadata.name,.metadata.uid,.metadata.resourceVersion,.metadata.creationTimestamp,.spec.nodeName,.status.phase,(.status.reason//"-"),([.status.containerStatuses[]?.ready]|join(",")),([.status.containerStatuses[]?.containerID]|join(","))]|@tsv' <<<"$POD_LIST_JSON"; else printf '%s\n' '중단: current OWNER_READY/UID gate가 아니다.' >&2; fi`

replacement는 owner UID가 같고 새 Pod UID가 생성된 경우다. 이름 유사성만으로 chain을 만들지 않는다. 새 UID·node·containerID가 나타나면 이전 READY와 relation을 폐기하고 fresh 조회로 재등록한다. Service가 있는 workload는 selector→EndpointSlice ready endpoint→실제 read-only request까지 확인한다.

### 3. Event와 증거 한계

대표 UID Event는 한 번만 조회한다.

`EVENT_READY=false; if [ "$SELECTION_READY" = true ] && [ "$TIME_READY" = true ] && CURRENT_REP_JSON="$(kubectl get pod "$REP_POD" -n "$REP_NS" -o json)" && [ "$(jq -r '.metadata.uid' <<<"$CURRENT_REP_JSON")" = "$REP_UID" ] && EVENTS_JSON="$(kubectl get events -n "$REP_NS" --field-selector "$EVENT_FIELD" -o json)"; then MATCHES="$(jq --argjson start "$START_EPOCH" --argjson end "$END_EPOCH" '[.items[]|. as $e|(.eventTime//.series.lastObservedTime//.lastTimestamp//.metadata.creationTimestamp) as $t|select(($t|fromdateiso8601) >= $start and ($t|fromdateiso8601) <= $end)]|length' <<<"$EVENTS_JSON")"; jq -r --argjson start "$START_EPOCH" --argjson end "$END_EPOCH" '.items[]|. as $e|(.eventTime//.series.lastObservedTime//.lastTimestamp//.metadata.creationTimestamp) as $t|select(($t|fromdateiso8601) >= $start and ($t|fromdateiso8601) <= $end)|[$t,.type,.reason,(.count//1),.message]|@tsv' <<<"$EVENTS_JSON"; if [ "$MATCHES" -gt 0 ]; then EVENT_READY=true; fi; printf 'EVENT_READY=%s matches=%s pod_uid=%s\n' "$EVENT_READY" "$MATCHES" "$REP_UID"; else printf '%s\n' '중단: current selection/time/Event producer 실패' >&2; fi`

Event가 비면 과거 eviction이 없었다는 뜻이 아니다. 대상 없음, UID 교체, Event TTL, 권한/API 실패를 분리한다. audit를 사용할 경우 승인된 audit owner가 `verb`, objectRef namespace/name/UID, responseStatus, requestReceivedTimestamp/stageTimestamp만 최소 공개하고 user·source IP·request/response body·token은 redaction한다.

## 상태 변경 경계

이 문서에서는 Pod delete/restart/rollout, Job 재실행, request/limit 변경, kubelet/runtime restart, log/image 삭제, threshold/sysctl 변경, cordon/drain을 실행하지 않는다.

별도 변경은 fresh Node/Pod/owner UID·RV, pressure와 UTC 증거 relation, 대체 capacity, PDB, StatefulSet quorum/PVC, Job idempotence·외부 중복, 실제 Service 영향, 승인자·작업 창·quorum, 명시적 rollback target과 중단 조건을 모두 갖춰야 한다. rollback 직전 target UID/RV를 다시 확인한다. replacement가 생기면 새 identity를 등록하고 실제 기능이 복구될 때까지 완료로 보지 않는다.

## 정상화 검증

`NORMALIZATION_READY=false; if [ "$API_READY" = true ] && CURRENT_NODE_JSON="$(kubectl get node "$NODE" -o json)" && [ "$(jq -r '.metadata.uid' <<<"$CURRENT_NODE_JSON")" = "$NODE_UID" ] && [ "$(jq -r '.status.nodeInfo.machineID' <<<"$CURRENT_NODE_JSON")" = "$NODE_MACHINE_ID" ]; then jq -r '"NODE=\(.metadata.name) UID=\(.metadata.uid) RV=\(.metadata.resourceVersion) READY=\([.status.conditions[]|select(.type=="Ready")|.status][0]) MEMORY=\([.status.conditions[]|select(.type=="MemoryPressure")|.status][0]) DISK=\([.status.conditions[]|select(.type=="DiskPressure")|.status][0]) PID=\([.status.conditions[]|select(.type=="PIDPressure")|.status][0])"' <<<"$CURRENT_NODE_JSON"; NORMALIZATION_READY=true; else printf '%s\n' '중단: current Node UID/machineID normalization gate 실패' >&2; fi`

정상화에는 원인 signal과 kubelet eviction 행 중단, 새 Evicted UID 중단, replacement 재-Evicted 중단, owner desired/Ready·quorum·Job 결과 안정, EndpointSlice와 실제 핵심 요청 성공이 모두 필요하다. Evicted 객체 삭제나 Pod `Running`만으로 닫지 않는다.

## Prometheus 빠른 관측

`if [ "$API_READY" = true ]; then printf 'count by(node) ((kube_pod_status_reason{reason="Evicted"} == 1) * on(namespace,pod,uid) group_left(node) kube_pod_info{node="%s"})\n' "$NODE_PROM"; printf 'kube_node_status_condition{node="%s",condition=~"MemoryPressure|DiskPressure|PIDPressure",status="true"} == 1\n' "$NODE_PROM"; else printf '%s\n' '중단: API_READY가 아니다.' >&2; fi`

`uid` label이나 metric이 실제로 없으면 query를 수정하기 전에 kube-state-metrics schema를 확인한다. 빈 결과는 0/정상이 아니라 metric 미수집, 삭제된 Pod, label mismatch, retention, query 범위, 권한/API 실패 중 하나다.

## 증거와 미검증

Node/Pod/owner UID·RV, replacement chain, UTC 창, pressure signal, host/kubelet argv, exact CRI provider relation, producer/filter rc, 최소 Event/audit 필드, quorum·PDB·Job side effect와 실제 기능 결과를 보존한다. Secret·token·전체 audit/journal·raw CRI inspect는 저장하지 않는다.

Kubernetes 1.26 Node-pressure eviction과 Pod lifecycle을 기준으로 했다. kubelet unit/config, SSH inventory, CRI endpoint/runtime, Event/audit retention, metrics labels는 환경 미검증이다.
