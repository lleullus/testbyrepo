# Node Ready condition이 False인 경우

## 입력값과 빠른 수집

실행 hop은 `작업 PC/Bash → Kubernetes API → Node·Lease·해당 Node의 Pod`와 조건부 `작업 PC → SSH endpoint → 승인된 Linux host → kubelet journal`이다. API의 `Ready=False`, Lease 갱신, host process와 runtime 상태는 서로 다른 증거다.

| 구분 | 값 | 출처·유효성 |
|---|---|---|
| 최초 입력 | `NODE` | incident의 exact Node 이름 |
| API 확인 자동값 | Node UID/RV/providerID/machineID, Ready·pressure conditions, Lease UID/RV/renewTime | Node와 Lease API 모두 성공하고 `Ready=False`인 경우 |
| 계산 후보값 | `NODE_RE`, `NODE_LABEL` | 이름을 regex와 PromQL label용으로 escape |
| 운영자 선택값 | `SSH_HOST`, `REMOTE_HOSTNAME`, `KUBELET_UNIT`, `START_RFC3339`, `END_RFC3339` | 승인된 CMDB/host mapping, 확인된 active unit, 장애 evidence 창 |

### 1. 도구와 최초 입력

`TOOLS_READY=false; MISSING=''; [ -n "${BASH_VERSION:-}" ] || MISSING="$MISSING bash"; for T in kubectl jq sed date ssh mktemp grep; do command -v "$T" >/dev/null 2>&1 || MISSING="$MISSING $T"; done; if [ -z "$MISSING" ]; then TOOLS_READY=true; printf 'TOOLS_READY=true\n'; else printf '중단: 없는 도구=%s\n' "$MISSING" >&2; fi`

`unset INPUT_READY AUTO_READY PODS_READY TIME_READY HOST_READY QUERY_READY NODE_UID NODE_RV PROVIDER_ID READY_REASON READY_MESSAGE READY_HEARTBEAT READY_TRANSITION LEASE_UID LEASE_RV LEASE_RENEW NODE_RE NODE_LABEL SSH_HOST REMOTE_HOSTNAME KUBELET_UNIT START_RFC3339 END_RFC3339 CONTAINER_ID CRI_ENDPOINT RUNTIME_UNIT ARGV_RE; NODE='PASTE_NODE_HERE'; INPUT_READY=false; if [ "$TOOLS_READY" = true ] && [ -n "$NODE" ]; then INPUT_READY=true; export NODE; printf 'INPUT_READY=true node=%s\n' "$NODE"; else printf '%s\n' '중단: 도구 또는 NODE 입력 실패' >&2; fi`

재등록 시작 전 Node/Lease/Pod owner identity와 resourceVersion, containerID, 실행 node·host 관계, 시간, argv/regex, CRI/runtime 값 및 모든 downstream `READY`를 무효화한다. API 실패 시 이전 값을 출력·사용하지 않는다.

### 2. 현재 Node·Lease 자동 등록

`unset AUTO_READY PODS_READY TIME_READY HOST_READY QUERY_READY NODE_UID NODE_RV PROVIDER_ID READY_REASON READY_MESSAGE READY_HEARTBEAT READY_TRANSITION LEASE_UID LEASE_RV LEASE_RENEW NODE_RE NODE_LABEL SSH_HOST REMOTE_HOSTNAME KUBELET_UNIT START_RFC3339 END_RFC3339 CONTAINER_ID CRI_ENDPOINT RUNTIME_UNIT ARGV_RE; AUTO_READY=false; if [ "$INPUT_READY" != true ]; then printf '%s\n' '중단: INPUT_READY가 아니다.' >&2; elif NODE_JSON="$(kubectl get node "$NODE" -o json)" && LEASE_JSON="$(kubectl get lease "$NODE" -n kube-node-lease -o json)"; then NODE_UID="$(jq -er '.metadata.uid' <<<"$NODE_JSON")" && NODE_RV="$(jq -er '.metadata.resourceVersion' <<<"$NODE_JSON")" && PROVIDER_ID="$(jq -r '.spec.providerID // empty' <<<"$NODE_JSON")" && READY_STATUS="$(jq -er '[.status.conditions[]? | select(.type=="Ready")][0].status' <<<"$NODE_JSON")" && [ "$READY_STATUS" = False ] && READY_REASON="$(jq -r '[.status.conditions[]? | select(.type=="Ready")][0].reason // "-"' <<<"$NODE_JSON")" && READY_MESSAGE="$(jq -r '[.status.conditions[]? | select(.type=="Ready")][0].message // "-"' <<<"$NODE_JSON")" && READY_HEARTBEAT="$(jq -er '[.status.conditions[]? | select(.type=="Ready")][0].lastHeartbeatTime' <<<"$NODE_JSON")" && READY_TRANSITION="$(jq -er '[.status.conditions[]? | select(.type=="Ready")][0].lastTransitionTime' <<<"$NODE_JSON")" && LEASE_UID="$(jq -er '.metadata.uid' <<<"$LEASE_JSON")" && LEASE_RV="$(jq -er '.metadata.resourceVersion' <<<"$LEASE_JSON")" && LEASE_RENEW="$(jq -er '.spec.renewTime' <<<"$LEASE_JSON")" && [ "$(jq -r '.spec.holderIdentity' <<<"$LEASE_JSON")" = "$NODE" ] && NODE_RE="$(printf '%s' "$NODE" | sed 's/[][\\.^$*+?(){}|]/\\&/g')" && NODE_LABEL="$(printf '%s' "$NODE" | sed 's/\\/\\\\/g;s/"/\\"/g')" && AUTO_READY=true && export NODE_UID NODE_RV PROVIDER_ID READY_STATUS READY_REASON READY_MESSAGE READY_HEARTBEAT READY_TRANSITION LEASE_UID LEASE_RV LEASE_RENEW NODE_RE NODE_LABEL; if [ "$AUTO_READY" = true ]; then jq -r '"=== Node ===\n이름: \(.metadata.name)\nUID/RV: \(.metadata.uid) / \(.metadata.resourceVersion)\nRuntime 식별자: \(.status.nodeInfo.containerRuntimeVersion // "-")\n" + ([.status.conditions[] | "\(.type): \(.status) reason=\(.reason // "-") heartbeat=\(.lastHeartbeatTime // "-") transition=\(.lastTransitionTime // "-") message=\(.message // "-")"] | join("\n"))' <<<"$NODE_JSON"; printf '=== Lease ===\nUID/RV/renew: %s / %s / %s\nAUTO_READY=true\n' "$LEASE_UID" "$LEASE_RV" "$LEASE_RENEW"; else printf '%s\n' '중단: Ready=False identity gate 실패' >&2; fi; else printf '%s\n' '중단: Node/Lease API producer 실패; stale 값 사용 금지' >&2; fi`

Node `containerRuntimeVersion`은 구현체 힌트일 뿐 active unit·socket·endpoint를 확정하지 않는다. Lease UID는 Node UID와 다른 객체 identity다.

현재 Node identity를 쓰는 각 API·SSH·query 명령은 먼저 다음 guard를 호출한다. API 조회 실패, UID 변경, `Ready=False` 해소 또는 Node `machineID` 누락 시 과거 READY와 host 관계를 모두 폐기한다.

`node_guard(){ API_CURRENT_READY=false; HOST_READY=false; QUERY_READY=false; unset CURRENT_NODE_RV CURRENT_LEASE_RV NODE_MACHINE_ID; local n l uid status mid; [ "$AUTO_READY" = true ] || return 1; n="$(kubectl get node "$NODE" -o json)" && l="$(kubectl get lease "$NODE" -n kube-node-lease -o json)" || return 1; uid="$(jq -er '.metadata.uid' <<<"$n")" || return 1; status="$(jq -er '[.status.conditions[]? | select(.type=="Ready")][0].status' <<<"$n")" || return 1; mid="$(jq -er '.status.nodeInfo.machineID' <<<"$n")" || return 1; [ "$uid" = "$NODE_UID" ] && [ "$status" = False ] && [ "$(jq -er '.metadata.uid' <<<"$l")" = "$LEASE_UID" ] && [ "$(jq -er '.spec.holderIdentity' <<<"$l")" = "$NODE" ] && [[ "$mid" =~ ^[0-9A-Fa-f-]+$ ]] || return 1; CURRENT_NODE_RV="$(jq -er '.metadata.resourceVersion' <<<"$n")" && CURRENT_LEASE_RV="$(jq -er '.metadata.resourceVersion' <<<"$l")" || return 1; NODE_MACHINE_ID="$(tr '[:upper:]' '[:lower:]' <<<"${mid//-/}")"; API_CURRENT_READY=true; export CURRENT_NODE_RV CURRENT_LEASE_RV NODE_MACHINE_ID; }`

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | 현재 UID의 Node가 `Ready=False`를 보고하고 Lease·condition을 읽을 수 있음 |
| 적용 | kubelet 보고, pressure, runtime/CNI, 영향 Pod 범위를 분리해야 함 |
| 제외 | `Ready=Unknown`과 Lease 정체는 [[02. Node Ready condition이 Unknown이고 Lease 갱신이 중단된 경우]], 새 Node 가입 실패는 스케줄링/프로비저닝 런북 |

검색 문자열: `KubeletNotReady`, `container runtime is down`, `PLEG is not healthy`, `MemoryPressure`, `DiskPressure`, `PIDPressure`, `NetworkUnavailable`, `FailedCreatePodSandBox`.

## 관측별 진단 경로

| Ready/condition 직접 증거 | 다음 확인 | 이관 |
|---|---|---|
| Lease 최신, kubelet status 오류 | 같은 창의 kubelet journal·API readyz | kubelet/API network |
| pressure=True | Node 범위 Pod와 Linux resource evidence | 노드 압박/Linux |
| runtime/PLEG message | 현재 runtime identity와 전용 CRI 절차 | runtime/CRI |
| NetworkUnavailable/CNI | 여러 Pod의 sandbox 공통성 | CNI/network |

### API와 영향 Pod

`if ! node_guard; then printf '%s\n' '중단: current Node identity/Ready gate 실패' >&2; elif kubectl get --raw='/readyz?verbose'; then printf '%s\n' 'API_READY=true (kubelet의 API write 성공은 보장하지 않음)'; else printf '%s\n' 'producer 오류: API readyz 실패; Node 원인 해석 중단' >&2; fi`

`if ! node_guard; then printf '%s\n' '중단: current Node identity/Ready gate 실패' >&2; else PODS_READY=false; if PODS_JSON="$(kubectl get pods -A --field-selector "spec.nodeName=$NODE" -o json)"; then PODS_READY=true; jq -r '.items[] | "=== Pod: \(.metadata.namespace)/\(.metadata.name) ===\nUID/RV: \(.metadata.uid) / \(.metadata.resourceVersion)\nOwner: \([.metadata.ownerReferences[]? | "\(.kind)/\(.name) uid=\(.uid)"] | join(","))\nPhase/Ready: \(.status.phase // "-") / \([.status.containerStatuses[]? | "\(.name)=\(.ready) restart=\(.restartCount) containerID=\((.containerID // "-")|split("://")|last)"] | join("; "))"' <<<"$PODS_JSON"; else printf '%s\n' 'producer 오류: Pod API 실패' >&2; fi; fi`

Pod 출력은 현재 nodeName·UID/RV·owner·container lifecycle 관계를 보존한다. container ID는 비민감 suffix만 incident 정책에 따라 기록하고, Secret·환경값·전체 Pod YAML은 수집하지 않는다. 한 Pod만 실패하면 Node 공통 원인으로 확정하지 않는다.

## 조건부 host journal

`SSH_HOST='PASTE_APPROVED_SSH_HOST_HERE'; REMOTE_HOSTNAME='PASTE_REMOTE_HOSTNAME_HERE'; KUBELET_UNIT='PASTE_CONFIRMED_KUBELET_UNIT_HERE'; START_RFC3339='PASTE_START_RFC3339_HERE'; END_RFC3339='PASTE_END_RFC3339_HERE'; TIME_READY=false; HOST_READY=false; if [ "$AUTO_READY" != true ]; then printf '%s\n' '중단: AUTO_READY가 아니다.' >&2; elif [[ ! "$START_RFC3339" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] || [[ ! "$END_RFC3339" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]]; then printf '%s\n' '중단: UTC RFC3339 형식 오류' >&2; elif S="$(date -u -d "$START_RFC3339" +%s)" && E="$(date -u -d "$END_RFC3339" +%s)" && T="$(date -u -d "$READY_TRANSITION" +%s)" && [ "$(date -u -d "@$S" +%Y-%m-%dT%H:%M:%SZ)" = "$START_RFC3339" ] && [ "$(date -u -d "@$E" +%Y-%m-%dT%H:%M:%SZ)" = "$END_RFC3339" ] && [ "$S" -lt "$E" ] && [ "$S" -le "$T" ] && [ "$T" -le "$E" ] && [[ "$KUBELET_UNIT" =~ ^[A-Za-z0-9_.@-]+\.service$ ]]; then TIME_READY=true; export SSH_HOST REMOTE_HOSTNAME KUBELET_UNIT START_RFC3339 END_RFC3339; printf 'TIME_READY=true transition=%s window=%s..%s\n' "$READY_TRANSITION" "$START_RFC3339" "$END_RFC3339"; else printf '%s\n' '중단: date round-trip/start<end/evidence 또는 unit 형식 실패' >&2; fi`

```bash
if ! node_guard || [ "$TIME_READY" != true ]; then printf '%s\n' '중단: current Node identity와 TIME_READY가 필요하다.' >&2; else HOST_READY=false; if ssh -- "$SSH_HOST" bash -s -- "$REMOTE_HOSTNAME" "$NODE_MACHINE_ID" "$KUBELET_UNIT" "$START_RFC3339" "$END_RFC3339" <<'REMOTE'
set -o nounset
expected=$1
expected_machine=$2
unit=$3
start=$4
end=$5
actual=$(hostname -f 2>/dev/null || hostname)
[ "$actual" = "$expected" ] || { printf '중단: host identity 불일치 expected=%s actual=%s\n' "$expected" "$actual" >&2; exit 30; }
[ -f /etc/machine-id ] && [ -r /etc/machine-id ] || { printf '%s\n' '중단: regular readable /etc/machine-id가 없음' >&2; exit 31; }
actual_machine=$(tr -d '-' </etc/machine-id | tr '[:upper:]' '[:lower:]') || exit 31
[ -n "$actual_machine" ] && [ "$actual_machine" = "$expected_machine" ] || { printf '%s\n' '중단: Node machineID와 원격 /etc/machine-id 불일치' >&2; exit 32; }
[ "$(ps -p 1 -o comm=)" = systemd ] || { printf '%s\n' '중단: systemd host가 아님' >&2; exit 33; }
systemctl show "$unit" -p Id -p LoadState -p ActiveState -p SubState -p ExecMainStartTimestamp -p NRestarts --no-pager || exit 34
tmp=$(mktemp) || exit 35
trap 'rm -f "$tmp"' EXIT
if ! journalctl -u "$unit" --since "$start" --until "$end" --no-pager >"$tmp"; then printf '%s\n' 'producer 오류: journalctl 실패' >&2; exit 36; fi
if grep -E -i -C 3 'node status|lease|KubeletNotReady|PLEG|runtime|pressure|evict|cni|network|timeout|refused|x509|unauthorized|forbidden|oom|read-only|I/O error' "$tmp"; then exit 0; else rc=$?; [ "$rc" -eq 1 ] && { printf '%s\n' 'filter no-match: 오류 부재로 해석 금지' >&2; exit 37; }; printf 'filter 오류: grep rc=%s\n' "$rc" >&2; exit 38; fi
REMOTE
then HOST_READY=true; printf 'HOST_READY=true host=%s unit=%s\n' "$REMOTE_HOSTNAME" "$KUBELET_UNIT"; else printf '%s\n' '중단: remote identity/service/pipeline gate 실패' >&2; fi; fi
```

SSH 값은 옵션과 분리된 positional argument로 전달하며 원격에서 재해석하지 않는다. `eval`, host key 검증 우회, process 전체 argv 저장은 금지한다. no-match와 producer/filter 오류를 별도로 기록한다.

runtime/CRI 분기는 [[04. 노드·런타임/03. 컨테이너 런타임·CRI 이상/02. CRI endpoint 연결이 거부되거나 timeout인 경우]]를 사용한다. active kubelet ExecStart/config의 argv 정규식에서 endpoint 후보가 정확히 하나이고, runtime service가 제공하는 socket과 exact match하며, 원격 host identity와 socket provider를 확인한 뒤에만 `crictl`을 실행한다. endpoint 추측, 여러 후보 중 첫 값 선택, stale container ID inspect는 금지한다.

## Prometheus 쿼리

`if ! node_guard; then printf '%s\n' '중단: current Node identity/Ready gate 실패' >&2; else QUERY_READY=true; printf 'kube_node_status_condition{node="%s",condition="Ready",status="false"} == 1\n' "$NODE_LABEL"; printf 'kube_node_status_condition{node="%s",condition=~"MemoryPressure|DiskPressure|PIDPressure|NetworkUnavailable",status="true"} == 1\n' "$NODE_LABEL"; fi`

완성 출력만 현재 cluster·관측 창에서 사용한다. 빈 결과는 metric 미수집·label/시간 범위 오류와 query/API 실패를 나누며 정상으로 해석하지 않는다. metric에는 Node UID가 없을 수 있어 현재 API identity를 대체하지 않는다.

## 변경 경계와 정상화

이 런북은 restart, cordon/drain, reboot, Node/Pod delete 명령을 제공하지 않는다. 별도 mutation은 실행 직전에 fresh Node UID/RV, Lease UID/RV, Pod owner·selector, kubelet/runtime config revision·image digest, evidence 창, 변경 승인·window, PDB·quorum·capacity, 멱등성과 rollback을 직접 gate한다. API/host identity가 바뀌거나 조회가 실패하면 중단한다.

변경 후 Node나 Pod가 교체되면 새 UID/RV·owner·node/containerID 관계를 처음부터 재등록한다. 정상화는 `host 원인 해소 → kubelet/runtime/CNI → Lease 연속 갱신 → Ready=True·pressure 해소 → workload desired/Ready → Endpoint·실제 요청/Job 산출물` 역순과 재발 관찰 창으로 확인한다. rollback도 동일하게 검증한다.

RBAC은 `nodes`, `leases`, 승인된 Node 범위 `pods`의 읽기에 제한한다. audit는 별도 권한·정책의 owner가 Node UID와 시간 창으로 조회하며 credential, Secret, 인증서 개인키, 개인정보와 전체 journal을 저장하지 않는다.
