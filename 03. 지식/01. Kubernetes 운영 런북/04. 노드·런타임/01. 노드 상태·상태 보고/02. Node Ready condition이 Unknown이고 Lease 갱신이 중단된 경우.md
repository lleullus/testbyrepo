# Node Ready condition이 Unknown이고 Lease 갱신이 중단된 경우

## 입력값과 빠른 수집

`Unknown`은 API에 저장된 상태가 불확실하다는 뜻이다. 실행 경로 `작업 PC → API server → Node/Lease`와 `작업 PC → 승인된 SSH host → kubelet/host`를 분리하며, API 실패·SSH 실패·stale Lease 중 하나로 host 손실을 확정하지 않는다.

| 구분 | 값 | 출처·gate |
|---|---|---|
| 최초 입력 | `NODE` | incident의 exact Node 이름 |
| API 확인 자동값 | Node UID/RV/machineID, Unknown heartbeat/transition, Lease UID/RV/renewTime, 수집 시각 | Node·Lease API 모두 성공하고 holder/identity가 맞음 |
| 계산 후보값 | `T0_EPOCH`, `T1_EPOCH`, `T2_EPOCH`, `NODE_RE`, `NODE_LABEL` | UTC round-trip 뒤 시간 순서 확인; 고정 stale 임계치 아님 |
| 운영자 선택값 | SSH host/원격 hostname/kubelet unit, `START_RFC3339`, `END_RFC3339` | 독립 host mapping과 승인된 evidence 창 |

`unset INPUT_READY AUTO_READY API_READY TIME_READY HOST_READY QUERY_READY NODE_UID NODE_RV READY_REASON READY_MESSAGE READY_HEARTBEAT READY_TRANSITION LEASE_UID LEASE_RV LEASE_RENEW T0_EPOCH T1_EPOCH T2_EPOCH COLLECTED_AT NODE_RE NODE_LABEL SSH_HOST REMOTE_HOSTNAME KUBELET_UNIT START_RFC3339 END_RFC3339 OWNER_UID CONTAINER_ID CRI_ENDPOINT RUNTIME_UNIT ARGV_RE; NODE='PASTE_NODE_HERE'; INPUT_READY=false; if [ "$TOOLS_READY" = true ] && [ -n "$NODE" ]; then INPUT_READY=true; export NODE; printf 'INPUT_READY=true node=%s\n' "$NODE"; else printf '%s\n' '중단: 입력 또는 도구 gate 실패' >&2; fi`

재등록 전에 object/controller/container/node/runtime/service/Linux host identity와 resourceVersion, owner/containerID/host 관계, 시간·argv/regex 및 모든 downstream `READY`를 무효화한다. producer 실패 뒤 stale 값으로 partition 또는 host 손실을 판단하지 않는다.

### 2. Unknown·Lease 시간축 자동 등록

`unset AUTO_READY API_READY TIME_READY HOST_READY QUERY_READY NODE_UID NODE_RV READY_REASON READY_MESSAGE READY_HEARTBEAT READY_TRANSITION LEASE_UID LEASE_RV LEASE_RENEW T0_EPOCH T1_EPOCH T2_EPOCH COLLECTED_AT NODE_RE NODE_LABEL SSH_HOST REMOTE_HOSTNAME KUBELET_UNIT START_RFC3339 END_RFC3339 OWNER_UID CONTAINER_ID CRI_ENDPOINT RUNTIME_UNIT ARGV_RE; AUTO_READY=false; if [ "$INPUT_READY" != true ]; then printf '%s\n' '중단: INPUT_READY가 아니다.' >&2; elif NODE_JSON="$(kubectl get node "$NODE" -o json)" && LEASE_JSON="$(kubectl get lease "$NODE" -n kube-node-lease -o json)" && COLLECTED_AT="$(date -u +%Y-%m-%dT%H:%M:%SZ)"; then NODE_UID="$(jq -er '.metadata.uid' <<<"$NODE_JSON")" && NODE_RV="$(jq -er '.metadata.resourceVersion' <<<"$NODE_JSON")" && READY_STATUS="$(jq -er '[.status.conditions[]? | select(.type=="Ready")][0].status' <<<"$NODE_JSON")" && [ "$READY_STATUS" = Unknown ] && READY_REASON="$(jq -r '[.status.conditions[]? | select(.type=="Ready")][0].reason // "-"' <<<"$NODE_JSON")" && READY_MESSAGE="$(jq -r '[.status.conditions[]? | select(.type=="Ready")][0].message // "-"' <<<"$NODE_JSON")" && READY_HEARTBEAT="$(jq -er '[.status.conditions[]? | select(.type=="Ready")][0].lastHeartbeatTime' <<<"$NODE_JSON")" && READY_TRANSITION="$(jq -er '[.status.conditions[]? | select(.type=="Ready")][0].lastTransitionTime' <<<"$NODE_JSON")" && LEASE_UID="$(jq -er '.metadata.uid' <<<"$LEASE_JSON")" && LEASE_RV="$(jq -er '.metadata.resourceVersion' <<<"$LEASE_JSON")" && LEASE_RENEW="$(jq -er '.spec.renewTime' <<<"$LEASE_JSON")" && [ "$(jq -r '.spec.holderIdentity' <<<"$LEASE_JSON")" = "$NODE" ] && T0_EPOCH="$(date -u -d "$READY_HEARTBEAT" +%s)" && T1_EPOCH="$(date -u -d "$LEASE_RENEW" +%s)" && T2_EPOCH="$(date -u -d "$COLLECTED_AT" +%s)" && [ "$T0_EPOCH" -le "$T2_EPOCH" ] && [ "$T1_EPOCH" -le "$T2_EPOCH" ] && NODE_RE="$(printf '%s' "$NODE" | sed 's/[][\\.^$*+?(){}|]/\\&/g')" && NODE_LABEL="$(printf '%s' "$NODE" | sed 's/\\/\\\\/g;s/"/\\"/g')" && AUTO_READY=true && export NODE_UID NODE_RV READY_STATUS READY_REASON READY_MESSAGE READY_HEARTBEAT READY_TRANSITION LEASE_UID LEASE_RV LEASE_RENEW T0_EPOCH T1_EPOCH T2_EPOCH COLLECTED_AT NODE_RE NODE_LABEL; if [ "$AUTO_READY" = true ]; then printf 'AUTO_READY=true\nNode UID/RV: %s / %s\nReady: %s reason=%s\nHeartbeat T0: %s\nTransition: %s\nLease UID/RV: %s / %s\nLease T1: %s\nCollection T2: %s\nT2-T0=%ss T2-T1=%ss\n' "$NODE_UID" "$NODE_RV" "$READY_STATUS" "$READY_REASON" "$READY_HEARTBEAT" "$READY_TRANSITION" "$LEASE_UID" "$LEASE_RV" "$LEASE_RENEW" "$COLLECTED_AT" "$((T2_EPOCH-T0_EPOCH))" "$((T2_EPOCH-T1_EPOCH))"; else printf '%s\n' '중단: Unknown/Lease identity 또는 시간 gate 실패' >&2; fi; else printf '%s\n' '중단: Node/Lease API producer 실패; stale 값 금지' >&2; fi`

경과 초는 관측값이며 환경의 node-monitor grace period를 대신하지 않는다. Node UID와 Lease UID는 서로 다른 identity다.

`node_guard(){ API_CURRENT_READY=false; HOST_READY=false; QUERY_READY=false; unset CURRENT_NODE_RV CURRENT_LEASE_RV NODE_MACHINE_ID; local n l uid status mid holder; [ "$AUTO_READY" = true ] || return 1; n="$(kubectl get node "$NODE" -o json)" || return 1; l="$(kubectl get lease "$NODE" -n kube-node-lease -o json)" || return 1; uid="$(jq -er '.metadata.uid' <<<"$n")" || return 1; status="$(jq -er '[.status.conditions[]? | select(.type=="Ready")][0].status' <<<"$n")" || return 1; mid="$(jq -er '.status.nodeInfo.machineID' <<<"$n")" || return 1; holder="$(jq -er '.spec.holderIdentity' <<<"$l")" || return 1; [ "$uid" = "$NODE_UID" ] && [ "$status" = Unknown ] && [ "$(jq -er '.metadata.uid' <<<"$l")" = "$LEASE_UID" ] && [ "$holder" = "$NODE" ] && [[ "$mid" =~ ^[0-9A-Fa-f-]+$ ]] || return 1; CURRENT_NODE_RV="$(jq -er '.metadata.resourceVersion' <<<"$n")" && CURRENT_LEASE_RV="$(jq -er '.metadata.resourceVersion' <<<"$l")" || return 1; NODE_MACHINE_ID="$(tr '[:upper:]' '[:lower:]' <<<"${mid//-/}")"; API_CURRENT_READY=true; export CURRENT_NODE_RV CURRENT_LEASE_RV NODE_MACHINE_ID; }`

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | current Node가 `Ready=Unknown`이고 Lease renewTime이 incident의 마지막 정상 이후 진행하지 않음 |
| 적용 | API 관측 장애, node↔control-plane partition, kubelet 중단, VM/host 손실을 시간축으로 분리 |
| 제외 | kubelet이 계속 `Ready=False`를 보고하면 [[01. Node Ready condition이 False인 경우]], 개별 Pod Unknown은 해당 Pod 런북 |

검색 문자열: `NodeStatusUnknown`, `kubelet stopped posting`, `renewTime`, `context deadline exceeded`, `connection refused`, `x509`, `unreachable`.

## 관측별 진단 경로

| 현재 관측 | 성공이 보장하는 범위 | 다음 분기 |
|---|---|---|
| 다른 Node와 readyz도 실패 | 작업 PC의 API 관측 경로 문제 | API/control plane·RBAC |
| API 정상, 대상 UID/Lease만 stale | 저장 객체와 대상 heartbeat의 분리 | kubelet/network/host |
| SSH host 도달, kubelet inactive | 승인된 host의 service 상태 | kubelet 실행·Linux/runtime |
| SSH와 독립 console 모두 실패 | host/network 후보 | platform의 독립 증거 필요 |

### API 관측 gate

`if ! node_guard; then printf '%s\n' '중단: current Node/Lease identity gate 실패' >&2; else API_READY=false; if READYZ="$(kubectl get --raw='/readyz?verbose')" && NODES_JSON="$(kubectl get nodes -o json)"; then API_READY=true; printf 'API_READY=true node_count=%s current_uid=%s\n' "$(jq '.items|length' <<<"$NODES_JSON")" "$NODE_UID"; printf '%s\n' "$READYZ"; else printf '%s\n' 'producer 오류: readyz 또는 nodes API 실패; Node 손실로 해석 금지' >&2; fi; fi`

`API_READY=true`는 작업 PC→API read 경로만 확인한다. kubelet의 write, host 생존, Lease 갱신은 보장하지 않는다. 401/403은 정확한 주체의 `nodes get/list`, `leases get` RBAC 경계로, timeout/5xx는 API/network 경계로 이관한다.

## 조건부 host/kubelet 확인

`SSH_HOST='PASTE_APPROVED_SSH_HOST_HERE'; REMOTE_HOSTNAME='PASTE_REMOTE_HOSTNAME_HERE'; KUBELET_UNIT='PASTE_CONFIRMED_KUBELET_UNIT_HERE'; START_RFC3339='PASTE_START_RFC3339_HERE'; END_RFC3339='PASTE_END_RFC3339_HERE'; TIME_READY=false; HOST_READY=false; if [ "$AUTO_READY" != true ] || [ "$API_READY" != true ]; then printf '%s\n' '중단: AUTO_READY와 API_READY가 필요하다.' >&2; elif [[ ! "$START_RFC3339" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] || [[ ! "$END_RFC3339" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]]; then printf '%s\n' '중단: UTC RFC3339 형식 오류' >&2; elif S="$(date -u -d "$START_RFC3339" +%s)" && E="$(date -u -d "$END_RFC3339" +%s)" && [ "$(date -u -d "@$S" +%Y-%m-%dT%H:%M:%SZ)" = "$START_RFC3339" ] && [ "$(date -u -d "@$E" +%Y-%m-%dT%H:%M:%SZ)" = "$END_RFC3339" ] && [ "$S" -lt "$E" ] && [ "$S" -le "$T0_EPOCH" ] && [ "$T0_EPOCH" -le "$E" ] && [ "$S" -le "$T1_EPOCH" ] && [ "$T1_EPOCH" -le "$E" ] && [[ "$KUBELET_UNIT" =~ ^[A-Za-z0-9_.@-]+\.service$ ]]; then TIME_READY=true; export SSH_HOST REMOTE_HOSTNAME KUBELET_UNIT START_RFC3339 END_RFC3339; printf 'TIME_READY=true window includes T0/T1\n'; else printf '%s\n' '중단: round-trip/start<end/T0-T1 관계 또는 unit 형식 실패' >&2; fi`

```bash
if ! node_guard || [ "$API_READY" != true ] || [ "$TIME_READY" != true ]; then printf '%s\n' '중단: current identity/API/시간 gate가 필요하다.' >&2; else HOST_READY=false; if ssh -- "$SSH_HOST" bash -s -- "$REMOTE_HOSTNAME" "$NODE_MACHINE_ID" "$KUBELET_UNIT" "$START_RFC3339" "$END_RFC3339" <<'REMOTE'
set -o nounset
expected=$1
expected_machine=$2
unit=$3
start=$4
end=$5
actual=$(hostname -f 2>/dev/null || hostname)
[ "$actual" = "$expected" ] || { printf '중단: remote identity 불일치 expected=%s actual=%s\n' "$expected" "$actual" >&2; exit 40; }
[ -f /etc/machine-id ] && [ -r /etc/machine-id ] || { printf '%s\n' '중단: regular readable /etc/machine-id가 없음' >&2; exit 41; }
actual_machine=$(tr -d '-' </etc/machine-id | tr '[:upper:]' '[:lower:]') || exit 41
[ -n "$actual_machine" ] && [ "$actual_machine" = "$expected_machine" ] || { printf '%s\n' '중단: Node machineID와 원격 /etc/machine-id 불일치' >&2; exit 42; }
[ "$(ps -p 1 -o comm=)" = systemd ] || exit 43
systemctl show "$unit" -p Id -p LoadState -p ActiveState -p SubState -p ExecMainStartTimestamp -p NRestarts --no-pager || exit 44
tmp=$(mktemp) || exit 45
trap 'rm -f "$tmp"' EXIT
if ! journalctl -u "$unit" --since "$start" --until "$end" --no-pager >"$tmp"; then printf '%s\n' 'producer 오류: journalctl 실패' >&2; exit 46; fi
if grep -E -i -C 3 'lease|node status|heartbeat|timeout|context deadline exceeded|connection refused|x509|unauthorized|forbidden|stopped|panic|oom|read-only|I/O error|runtime|PLEG' "$tmp"; then exit 0; else rc=$?; [ "$rc" -eq 1 ] && { printf '%s\n' 'filter no-match: kubelet 정상 증거가 아님' >&2; exit 47; }; printf 'filter 오류: grep rc=%s\n' "$rc" >&2; exit 48; fi
REMOTE
then HOST_READY=true; printf 'HOST_READY=true host=%s\n' "$REMOTE_HOSTNAME"; else printf '%s\n' '중단: SSH/identity/service/pipeline 실패' >&2; fi; fi
```

SSH failure는 host 손실을 증명하지 않는다. endpoint는 옵션 뒤 positional argument로 전달하고 원격에서 `$1..$5`로만 사용한다. `eval`, host key 검증 우회, argv/credential 원문 수집은 금지한다. filter no-match, filter 오류, journal producer 오류를 구분한다.

runtime 확인이 필요하면 전용 CRI 런북으로 이관한다. active kubelet config/ExecStart에서 단일 endpoint를 엄격 추출하고 runtime socket provider와 exact match한 뒤에만 `crictl`을 사용한다. stale containerID 또는 기본 socket 추측은 금지한다.

## Prometheus 쿼리

`if ! node_guard || [ "$API_READY" != true ]; then printf '%s\n' '중단: current identity/API gate가 필요하다.' >&2; else QUERY_READY=true; printf 'kube_node_status_condition{node="%s",condition="Ready",status="unknown"} == 1\n' "$NODE_LABEL"; printf 'time()-kube_lease_renew_time{namespace="kube-node-lease",lease="%s"}\n' "$NODE_LABEL"; fi`

현재 cluster와 동일 UTC 창에서 출력 완성본만 사용한다. metric 빈 결과는 미수집·label/시간 범위 문제이고 API/query 실패와 분리한다. `up=0`이나 Lease metric만으로 kubelet process/host 손실을 확정하지 않는다.

## stale identity·변경·정상화

Node 이름이 다시 보여도 UID/RV가 바뀌면 replacement다. old Node의 Pod owner·containerID·외부 write와 replacement workload를 분리한다. StatefulSet/quorum/Job은 중복 process·write 가능성을 업무 owner가 확인하기 전 삭제·재실행하지 않는다.

이 문서는 delete, force delete, restart, reboot, cordon/drain 명령을 제공하지 않는다. 별도 mutation은 fresh Node/Lease UID·RV, Pod owner/selector/spec, host identity, config revision·digest, 독립 host/VM evidence, 승인·window, PDB/quorum, 멱등성·fencing, rollback을 직접 gate한다. API가 다시 실패하거나 old/new identity가 불명확하면 중단한다.

정상화는 `API read/watch → intended Node UID → heartbeat와 Lease 연속 진행 → kubelet/host/network 원인 해소 → workload Ready/Endpoint → 실제 요청·queue·Job 산출물과 중복 없음` 순으로 확인한다. replacement 관계를 재등록하고 rollback도 같은 관찰 창을 통과한다.

Secret·token·인증서 개인키·개인정보·전체 journal은 저장하지 않는다. audit는 별도 권한과 보존 정책이 확인된 owner가 Node UID와 UTC 창으로 제한해 조회한다.
