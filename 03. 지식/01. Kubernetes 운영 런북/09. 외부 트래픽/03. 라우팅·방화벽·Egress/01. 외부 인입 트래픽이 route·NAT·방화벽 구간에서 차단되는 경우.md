# 외부 인입 트래픽이 route·NAT·방화벽 구간에서 차단되는 경우

## 입력값과 빠른 수집

연결 hop은 `승인된 외부 client → DNS → edge route/NAT/firewall → Service port → EndpointSlice port → 현재 backend Pod`다. Kubernetes 명령은 승인된 작업 PC의 같은 Bash에서, edge 명령은 승인된 SSH host에서 실행한다. 작업 PC 변수를 SSH가 상속한다고 가정하지 않는다.

| 종류 | 변수 | 등록 기준 |
|---|---|---|
| 최초 입력 | `CONTEXT`, `NS`, `SERVICE`, `PUBLIC_HOST`, `PUBLIC_PORT` | 승인된 exact 대상 |
| API 자동값 | Service UID·RV, port 후보, EndpointSlice와 backend 후보 | 모든 API 조회가 성공한 뒤 한 번에 등록 |
| 계산 후보 | exact-match PromQL label 값 | current identity 확인 뒤 생성 |
| 운영자 선택값 | Service port/protocol, backend, UTC 창, 5-tuple, SSH host/interface | 후보·inventory·동일 연결 증거에서 선택 |

**실행 위치·도구 확인:** `TOOLS_READY=false; MISSING=''; for T in kubectl jq sed date ssh; do command -v "$T" >/dev/null 2>&1 || MISSING="$MISSING $T"; done; if [ -z "${BASH_VERSION:-}" ]; then printf '%s\n' '중단: Bash에서 실행한다.' >&2; elif [ -n "$MISSING" ]; then printf '중단: 없는 도구=%s\n' "$MISSING" >&2; else TOOLS_READY=true; printf 'TOOLS_READY=true bash=%s\n' "$BASH_VERSION"; fi`

**최초 입력·이전 상태 전체 폐기:** `unset INPUT_READY AUTO_READY SELECTION_READY WINDOW_READY REMOTE_READY EVIDENCE_READY QUERY_READY SERVICE_UID SERVICE_RV SERVICE_PORT SERVICE_PROTOCOL TARGET_PORT BACKEND_POD BACKEND_UID BACKEND_RV BACKEND_IP BACKEND_NODE START_RFC3339 END_RFC3339 EVIDENCE_RFC3339 START_EPOCH END_EPOCH EVIDENCE_EPOCH SSH_TARGET EXPECTED_REMOTE_HOST EXPECTED_REMOTE_MACHINE_ID REMOTE_INTERFACE SOURCE_IP DEST_IP SVC_JSON EPS_JSON; CONTEXT='PASTE_CONTEXT_HERE'; NS='PASTE_NAMESPACE_HERE'; SERVICE='PASTE_SERVICE_HERE'; PUBLIC_HOST='PASTE_PUBLIC_HOST_HERE'; PUBLIC_PORT='PASTE_PUBLIC_PORT_HERE'; INPUT_READY=false; AUTO_READY=false; SELECTION_READY=false; WINDOW_READY=false; REMOTE_READY=false; EVIDENCE_READY=false; QUERY_READY=false; if [ "$TOOLS_READY" != true ]; then printf '%s\n' '중단: TOOLS_READY=false' >&2; elif [ -z "$CONTEXT" ] || [ -z "$NS" ] || [ -z "$SERVICE" ] || [ -z "$PUBLIC_HOST" ] || [[ ! "$PUBLIC_PORT" =~ ^[1-9][0-9]{0,4}$ ]] || (( PUBLIC_PORT > 65535 )); then printf '%s\n' '중단: 최초 입력 형식 오류' >&2; elif kubectl --context "$CONTEXT" get service "$SERVICE" -n "$NS" >/dev/null 2>&1; then INPUT_READY=true; export CONTEXT NS SERVICE PUBLIC_HOST PUBLIC_PORT; printf 'INPUT_READY=true context=%s namespace=%s service=%s public=%s:%s\n' "$CONTEXT" "$NS" "$SERVICE" "$PUBLIC_HOST" "$PUBLIC_PORT"; else printf '%s\n' '중단: exact Service 조회 실패' >&2; fi`

**하위 상태 폐기 함수:** `invalidate_ingress(){ unset AUTO_READY SELECTION_READY BACKEND_OWNER_READY WINDOW_READY REMOTE_READY EVIDENCE_READY QUERY_READY SERVICE_UID SERVICE_RV SERVICE_PORT SERVICE_PROTOCOL TARGET_PORT BACKEND_UID BACKEND_RV BACKEND_IP BACKEND_NODE BACKEND_OWNER_KIND BACKEND_OWNER_NAME BACKEND_OWNER_UID START_EPOCH END_EPOCH EVIDENCE_EPOCH SVC_JSON EPS_JSON; AUTO_READY=false; SELECTION_READY=false; BACKEND_OWNER_READY=false; WINDOW_READY=false; REMOTE_READY=false; EVIDENCE_READY=false; QUERY_READY=false; }`

**Service·EndpointSlice 자동 수집:** `invalidate_ingress; if [ "$INPUT_READY" != true ]; then printf '%s\n' '중단: INPUT_READY=false' >&2; elif SJ="$(kubectl --context "$CONTEXT" get service "$SERVICE" -n "$NS" -o json)" && EJ="$(kubectl --context "$CONTEXT" get endpointslice -n "$NS" -l "kubernetes.io/service-name=$SERVICE" -o json)" && SU="$(jq -er '.metadata.uid' <<<"$SJ")" && SR="$(jq -er '.metadata.resourceVersion' <<<"$SJ")"; then SVC_JSON="$SJ"; EPS_JSON="$EJ"; SERVICE_UID="$SU"; SERVICE_RV="$SR"; AUTO_READY=true; export SERVICE_UID SERVICE_RV; jq -r '"=== Service ===\n이름: \(.metadata.name)\nUID: \(.metadata.uid)\nRV: \(.metadata.resourceVersion)", (.spec.ports[]? | "Port 후보: name=\(.name // \"-\") protocol=\(.protocol) service=\(.port) target=\(.targetPort)")' <<<"$SVC_JSON"; jq -r '"=== EndpointSlice ===", (.items[]? | "Slice: \(.metadata.name) UID=\(.metadata.uid) RV=\(.metadata.resourceVersion)", (.ports[]? | "  Port: name=\(.name // \"-\") protocol=\(.protocol) endpoint=\(.port)"), (.endpoints[]? | "  Backend: \(.targetRef.name // \"-\") UID=\(.targetRef.uid // \"-\") node=\(.nodeName // \"-\") address=\(.addresses|join(\",\")) ready=\(.conditions.ready // false) terminating=\(.conditions.terminating // false)"))' <<<"$EPS_JSON"; printf 'AUTO_READY=true service_uid=%s rv=%s\n' "$SERVICE_UID" "$SERVICE_RV"; else invalidate_ingress; printf '%s\n' '중단: Service·EndpointSlice 수집 실패, 하위 상태 폐기' >&2; fi; unset SJ EJ SU SR`

EndpointSlice가 비었거나 ready backend가 없으면 외부 방화벽 차단으로 해석하지 않고 Service·EndpointSlice 런북으로 이관한다. 복수 backend를 임의 선택하지 않는다.

**선택값 입력:** `SERVICE_PORT='PASTE_SERVICE_PORT_HERE'; SERVICE_PROTOCOL='PASTE_TCP_UDP_OR_SCTP_HERE'; BACKEND_POD='PASTE_READY_BACKEND_POD_HERE'; START_RFC3339='PASTE_START_UTC_RFC3339_HERE'; END_RFC3339='PASTE_END_UTC_RFC3339_HERE'; EVIDENCE_RFC3339='PASTE_EVIDENCE_UTC_RFC3339_HERE'; SSH_TARGET='PASTE_APPROVED_SSH_TARGET_HERE'; EXPECTED_REMOTE_HOST='PASTE_EXPECTED_REMOTE_HOSTNAME_HERE'; EXPECTED_REMOTE_MACHINE_ID='PASTE_EXPECTED_REMOTE_MACHINE_ID_HERE'; REMOTE_INTERFACE='PASTE_REMOTE_INTERFACE_HERE'; SOURCE_IP='PASTE_OBSERVED_SOURCE_IP_HERE'; DEST_IP='PASTE_OBSERVED_DESTINATION_IP_HERE'`

**port·backend·UTC·원격 승인 검증:** `SELECTION_READY=false; WINDOW_READY=false; REMOTE_READY=false; EVIDENCE_READY=false; unset TARGET_PORT BACKEND_UID BACKEND_RV BACKEND_IP BACKEND_NODE START_EPOCH END_EPOCH EVIDENCE_EPOCH; if [ "$AUTO_READY" != true ]; then printf '%s\n' '중단: AUTO_READY=false' >&2; elif [[ ! .targetRef.kind=="Pod" and .targetRef.name==$n and .targetRef.uid==$u and (.addresses|index($ip))!=null and .conditions.ready==true and (.conditions.terminating // false)==false)' <<<"$EPS_JSON" >/dev/null; then TARGET_PORT="$(jq -r '.targetPort' <<<"$SP")"; BACKEND_UID="$BU"; BACKEND_RV="$BR"; BACKEND_IP="$BI"; BACKEND_NODE="$BN"; START_EPOCH="$(date -u -d "$START_RFC3339" +%s 2>/dev/null)" || START_EPOCH=''; END_EPOCH="$(date -u -d "$END_RFC3339" +%s 2>/dev/null)" || END_EPOCH=''; EVIDENCE_EPOCH="$(date -u -d "$EVIDENCE_RFC3339" +%s 2>/dev/null)" || EVIDENCE_EPOCH=''; if [[ "$START_RFC3339" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] && [[ "$END_RFC3339" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] && [[ "$EVIDENCE_RFC3339" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] && [ -n "$START_EPOCH" ] && [ -n "$END_EPOCH" ] && [ -n "$EVIDENCE_EPOCH" ] && [ "$(date -u -d "@$START_EPOCH" '+%Y-%m-%dT%H:%M:%SZ')" = "$START_RFC3339" ] && [ "$(date -u -d "@$END_EPOCH" '+%Y-%m-%dT%H:%M:%SZ')" = "$END_RFC3339" ] && [ "$(date -u -d "@$EVIDENCE_EPOCH" '+%Y-%m-%dT%H:%M:%SZ')" = "$EVIDENCE_RFC3339" ] && (( START_EPOCH < END_EPOCH && START_EPOCH <= EVIDENCE_EPOCH && EVIDENCE_EPOCH <= END_EPOCH )); then SELECTION_READY=true; WINDOW_READY=true; EVIDENCE_READY=true; if [ -n "$SSH_TARGET" ] && [ -n "$EXPECTED_REMOTE_HOST" ] && [ -n "$EXPECTED_REMOTE_MACHINE_ID" ] && [ -n "$REMOTE_INTERFACE" ] && [ -n "$SOURCE_IP" ] && [ -n "$DEST_IP" ]; else printf '%s\n' '중단: UTC canonical·순서·evidence 창 오류' >&2; fi; else printf '%s\n' '중단: Service→EndpointSlice port→backend 관계 검증 실패' >&2; fi; unset SP BP BU BR BI BN`

**backend owner 등록:** `BACKEND_OWNER_READY=false; unset BACKEND_OWNER_KIND BACKEND_OWNER_NAME BACKEND_OWNER_UID; if [ "$SELECTION_READY" != true ]; then printf '%s\n' '중단: SELECTION_READY=false' >&2; elif BP="$(kubectl --context "$CONTEXT" get pod "$BACKEND_POD" -n "$NS" -o json)" && [ "$(jq -r '.metadata.uid' <<<"$BP")" = "$BACKEND_UID" ]; then BACKEND_OWNER_KIND="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)][0].kind // "None"' <<<"$BP")"; BACKEND_OWNER_NAME="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)][0].name // "None"' <<<"$BP")"; BACKEND_OWNER_UID="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)][0].uid // "None"' <<<"$BP")"; if [ "$BACKEND_OWNER_KIND" = None ] || [ "$(kubectl --context "$CONTEXT" get "$BACKEND_OWNER_KIND" "$BACKEND_OWNER_NAME" -n "$NS" -o jsonpath='{.metadata.uid}' 2>/dev/null)" = "$BACKEND_OWNER_UID" ]; then BACKEND_OWNER_READY=true; export BACKEND_OWNER_KIND BACKEND_OWNER_NAME BACKEND_OWNER_UID; printf 'BACKEND_OWNER_READY=true owner=%s/%s/%s\n' "$BACKEND_OWNER_KIND" "$BACKEND_OWNER_NAME" "$BACKEND_OWNER_UID"; else printf '%s\n' '중단: current backend owner UID 불일치' >&2; fi; else printf '%s\n' '중단: backend UID 재검증 실패' >&2; fi; unset BP`

| select(.protocol==$sp.protocol and ((($sp.targetPort|type)=="number" and .port==$sp.targetPort) or (($sp.targetPort|type)=="string" and .name==$sp.targetPort)))]|length)>0 and any(.items[].endpoints[]?; .targetRef.name==$n and .targetRef.uid==$u and (.addresses|index($ip))!=null and .conditions.ready==true and (.conditions.terminating // false)==false)' <<<"$ej" >/dev/null; then invalidate_ingress; printf '%s\n' '중단: current port/backend/owner relation 변경, 처음부터 재등록' >&2; return 1; fi; if [ "$BACKEND_OWNER_KIND" != None ]; then co="$(kubectl --context "$CONTEXT" get "$BACKEND_OWNER_KIND" "$BACKEND_OWNER_NAME" -n "$NS" -o jsonpath='{.metadata.uid}' 2>/dev/null)" || { invalidate_ingress; return 1; }; [ "$co" = "$BACKEND_OWNER_UID" ] || { invalidate_ingress; return 1; }; fi; SVC_JSON="$sj"; EPS_JSON="$ej"; SERVICE_RV="$(jq -r '.metadata.resourceVersion' <<<"$sj")"; BACKEND_RV="$(jq -r '.metadata.resourceVersion' <<<"$bp")"; AUTO_READY=true; SELECTION_READY=true; BACKEND_OWNER_READY=true; return 0; }`

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | 승인된 public host·port에서 timeout, refused, reset이 UTC 창에 재현됨 |
| 적용 | 동일 5-tuple을 edge와 현재 Service→EndpointSlice→Pod 관계에 연결 가능 |
| 제외 | L7 404·502·503·TLS는 [[08. 인그레스·게이트웨이/03. L7 라우팅·Backend·TLS/02. Ingress·Gateway 요청이 502·503을 반환하는 경우]], endpoint 부재는 [[06. 클러스터 네트워크/02. Service·EndpointSlice/01. Service에 EndpointSlice endpoint가 생성되지 않는 경우]] |

검색 문자열: `timeout`, `connection refused`, `connection reset`, `SYN`, `SYN-ACK`, `DNAT`, `DROP`, `REJECT`, `no route to host`.

## 관측별 진단 경로

| 지금 보이는 것 | 먼저 볼 것 | 그다음 어디를 볼지 | 상세 절 |
|---|---|---|---|
| port/backend identity 변경 | Service UID·port와 targetRef UID | 전체 재등록 | [[#1. Kubernetes 경계|1]] |
| public만 timeout | edge DNS·route | NAT·firewall | [[#2. 원격 identity와 route|2]] |
| SYN만 관측 | 같은 5-tuple의 양방향 header | rule·return path | [[#3. packet·정책 증거|3]] |
| RST/refused | 실제 listener와 기능 | listener owner | [[#4. listener와 기능|4]] |

### 1. Kubernetes 경계

**실행:** `refresh_ingress && kubectl --context "$CONTEXT" get service "$SERVICE" -n "$NS" -o custom-columns='NAME:.metadata.name,UID:.metadata.uid,RV:.metadata.resourceVersion,TYPE:.spec.type,PORTS:.spec.ports[*].port,TARGET-PORTS:.spec.ports[*].targetPort,PROTOCOLS:.spec.ports[*].protocol,EXTERNAL-POLICY:.spec.externalTrafficPolicy' && kubectl --context "$CONTEXT" get endpointslice -n "$NS" -l "kubernetes.io/service-name=$SERVICE" -o custom-columns='NAME:.metadata.name,UID:.metadata.uid,RV:.metadata.resourceVersion,PORTS:.ports[*].port,PROTOCOLS:.ports[*].protocol,ADDRESSES:.endpoints[*].addresses,READY:.endpoints[*].conditions.ready,TERMINATING:.endpoints[*].conditions.terminating,TARGET-UIDS:.endpoints[*].targetRef.uid'`

두 producer 중 하나라도 실패하면 성공으로 보지 않는다. 이 성공은 Kubernetes API 관계만 보장하며 edge NAT·firewall과 backend application listener는 보장하지 않는다.

### 2. 원격 identity와 route

SSH 인수는 positional argument와 `%q`로 전달하고 원격 `/etc/machine-id`를 inventory 값과 재대조한다.

**원격 실행 함수 등록:** `run_remote(){ local script="$1" arg q cmd='bash -s --'; shift; for arg in "$@"; do printf -v q '%q' "$arg"; cmd+=" $q"; done; ssh -- "$SSH_TARGET" "$cmd" <<<"$script"; }`

**실행:** `refresh_ingress && [ "$REMOTE_READY" = true ] && [ "$WINDOW_READY" = true ] && run_remote 'set -o pipefail; expected_host=$1; expected_machine=$2; host=$3; ip=$4; actual_host=$(hostname -f 2>/dev/null || hostname) || exit 20; actual_machine=$(tr -d "\n" </etc/machine-id) || exit 21; [ "$actual_host" = "$expected_host" ] && [ "$actual_machine" = "$expected_machine" ] || { printf "identity mismatch host=%s machine=%s\n" "$actual_host" "$actual_machine" >&2; exit 22; }; dns=$(getent ahosts "$host" 2>&1); producer_rc=$?; if [ "$producer_rc" -ne 0 ]; then printf "DNS producer 실패 rc=%s %s\n" "$producer_rc" "$dns" >&2; exit 23; elif [ -z "$dns" ]; then printf "%s\n" "DNS empty" >&2; exit 24; fi; printf "%s\n" "$dns"; ip route get "$ip"' "$EXPECTED_REMOTE_HOST" "$EXPECTED_REMOTE_MACHINE_ID" "$PUBLIC_HOST" "$DEST_IP"`

DNS producer 실패, 성공한 빈 answer와 route 실패를 분리한다. 성공은 이 원격 host의 forward route만 보장한다.

### 3. packet·정책 증거

현재 시각이 승인 창 안일 때만 payload 없는 header 20개를 수집한다.

**실행:** `refresh_ingress && [ "$REMOTE_READY" = true ] && [ "$WINDOW_READY" = true ] && [ "$EVIDENCE_READY" = true ] && [ "$SERVICE_PROTOCOL" = TCP ] && NOW_EPOCH="$(date -u +%s)" && (( START_EPOCH <= NOW_EPOCH && NOW_EPOCH <= END_EPOCH )) && run_remote 'expected_host=$1; expected_machine=$2; iface=$3; src=$4; dst=$5; port=$6; [ "$(hostname -f 2>/dev/null || hostname)" = "$expected_host" ] || exit 20; [ "$(tr -d "\n" </etc/machine-id)" = "$expected_machine" ] || exit 21; command -v tcpdump >/dev/null 2>&1 || exit 127; sudo timeout 30 tcpdump -ni "$iface" -nn -tttt -q -c 20 "host $src and host $dst and tcp port $port"' "$EXPECTED_REMOTE_HOST" "$EXPECTED_REMOTE_MACHINE_ID" "$REMOTE_INTERFACE" "$SOURCE_IP" "$DEST_IP" "$PUBLIC_PORT"`

exit 127·권한 실패는 packet 부재가 아니다. SYN 없음은 관측점 전단, SYN만은 downstream 또는 return path, 3-way handshake는 이 관측점의 TCP hop만 확인한다. firewall owner에게 같은 UTC 창·5-tuple의 rule ID, zone, allow/drop/reject와 hit를 요청한다.

### 4. listener와 기능

destination listener가 SSH host와 같다는 inventory 관계가 있을 때만 실행한다.

**실행:** `refresh_ingress && [ "$REMOTE_READY" = true ] && run_remote 'expected_host=$1; expected_machine=$2; port=$3; [ "$(hostname -f 2>/dev/null || hostname)" = "$expected_host" ] || exit 20; [ "$(tr -d "\n" </etc/machine-id)" = "$expected_machine" ] || exit 21; command -v ss >/dev/null 2>&1 || exit 127; out=$(ss -ltn "sport = :$port" 2>&1); rc=$?; [ "$rc" -eq 0 ] || { printf "%s\n" "$out" >&2; exit "$rc"; }; [ -n "$out" ] || { printf "%s\n" "LISTEN empty" >&2; exit 2; }; printf "%s\n" "$out"' "$EXPECTED_REMOTE_HOST" "$EXPECTED_REMOTE_MACHINE_ID" "$PUBLIC_PORT"`

LISTEN은 TLS·HTTP·backend 기능을 보장하지 않는다. 실제 기능은 owner가 승인한 비민감 endpoint의 기대 status와 application data로 별도 확인한다.

## 변경 경계·정상화·증거

이 문서는 route, NAT, firewall, Service, EndpointSlice, listener 변경 명령을 제공하지 않는다. 별도 변경은 fresh UID·port/backend relation, 동일 5-tuple·UTC 증거, owner·승인 ID·실행 창, HA 영향, 멱등성, 중단 조건과 실제 rollback 절차가 모두 확인된 경우에만 수행한다. replacement가 생기면 이전 READY를 폐기하고 새 UID·RV·node·address를 처음부터 재등록한다.

**정상화 API gate:** `refresh_ingress && kubectl --context "$CONTEXT" get endpointslice -n "$NS" -l "kubernetes.io/service-name=$SERVICE" -o custom-columns='NAME:.metadata.name,UID:.metadata.uid,RV:.metadata.resourceVersion,PORTS:.ports[*].port,READY:.endpoints[*].conditions.ready,TERMINATING:.endpoints[*].conditions.terminating,ADDRESSES:.endpoints[*].addresses,TARGET-UIDS:.endpoints[*].targetRef.uid'`

정상화는 `application 기능 → listener → firewall allow → NAT translation → 양방향 packet → public DNS·route → Service port → EndpointSlice port → current backend` 순서다. 같은 관찰 창의 새 timeout/reset/drop이 없고 승인된 외부 client의 실제 기능이 정상이어야 한다. 실패하면 추가 변경을 중단하고 승인 절차의 rollback을 수행한다.

**완성 PromQL 생성:** `QUERY_READY=false; if ! refresh_ingress; then printf '%s\n' '중단: fresh gate 실패' >&2; else NS_Q="$(printf '%s' "$NS" | sed 's/\\/\\\\/g; s/"/\\"/g')"; SERVICE_Q="$(printf '%s' "$SERVICE" | sed 's/\\/\\\\/g; s/"/\\"/g')"; QUERY_READY=true; printf 'kube_endpoint_address_available{namespace="%s",endpoint="%s"}\n' "$NS_Q" "$SERVICE_Q"; printf 'kube_endpoint_address_not_ready{namespace="%s",endpoint="%s"}\n' "$NS_Q" "$SERVICE_Q"; fi`

빈 vector는 정상이나 0이 아니다. metric 미지원, label 불일치, 권한·query API 실패와 조회 시간 범위를 분리한다. 보존 항목은 UTC 창, Service/EndpointSlice/backend UID·RV, port 관계, redacted 5-tuple, remote hostname·machine-id, route, packet header summary, rule ID·decision, listener와 기능 결과다. token, private key, payload, raw capture는 저장하지 않는다. 실제 Kubernetes·SSH·firewall·Prometheus 환경은 미검증이다.
