# 비대칭 경로·SNAT·반환 경로 문제로 연결이 간헐적으로 실패하는 경우

## 입력값과 빠른 수집

성공과 실패를 서로 다른 connection tuple로 보존한다. 연결 hop은 `current container → Pod route → current node → SNAT/egress gateway → stateful firewall → upstream → return path`다. 이 문서의 socket·conntrack·packet 명령은 TCP에만 적용한다.

| 종류 | 변수 | 등록 기준 |
|---|---|---|
| 최초 입력 | context, namespace, Pod, destination host·port | exact Pod 조회 성공 |
| API 자동값 | Pod UID·RV·owner, current containerID, Node UID·machineID | API 전체 성공 뒤 등록 |
| 계산 후보 | DNS address set, PromQL | current identity에 연결한 뒤 사용 |
| 운영자 선택값 | regular container, 성공·실패 tuple·UTC 시각, node SSH/interface | 실제 connection evidence·inventory에서 선택 |

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | 같은 current Pod와 destination에서 성공·실패 TCP 흐름이 교차함 |
| 적용 | 두 tuple의 시각·address·source port를 node/edge에서 구분 가능 |
| 제외 | 지속 실패는 [[02. Pod에서 외부 API·DB·인터넷으로 연결할 수 없는 경우]], DNS 오류는 [[07. DNS/01. Pod DNS/01. Pod의 DNS 질의가 timeout·SERVFAIL로 실패하는 경우]] |

검색 문자열: `SYN-SENT`, `SYN-ACK`, `UNREPLIED`, `ESTABLISHED`, `RST`, `martian`, `asymmetric`, `SNAT`, `DROP`, `i/o timeout`.

## 관측별 진단 경로

| 지금 보이는 것 | 먼저 볼 것 | 그다음 어디를 볼지 | 상세 절 |
|---|---|---|---|
| destination IP별 성공률 차이 | 두 DNS address와 route | upstream별 listener | [[#1. route·socket 비교|1]] |
| SNAT source별 차이 | 두 conntrack tuple | NAT pool·allowlist | [[#2. node tuple 비교|2]] |
| edge SYN-ACK가 Pod에 없음 | 양방향 packet header | reverse route·stateful rule | [[#2. node tuple 비교|2]] |
| handshake 뒤 reset | application 시각·listener | protocol owner | [[#3. log·기능|3]] |

### 1. route·socket 비교

**실행:** `refresh_asym && [ "$OBSERVATION_READY" = true ] && kubectl --context "$CONTEXT" auth can-i create pods/exec -n "$NS" --quiet && kubectl --context "$CONTEXT" exec "$POD" -n "$NS" -c "$CONTAINER" -- sh -c 'command -v ip >/dev/null 2>&1 || exit 127; printf "%s\n" "=== success destination ==="; ip route get "$1" || exit 20; printf "%s\n" "=== failure destination ==="; ip route get "$2"' sh "$SUCCESS_DEST_IP" "$FAILURE_DEST_IP"`

route source/device 차이는 CNI·node route 후보지만 NAT와 return path를 보장하지 않는다. 실제 socket이 이미 끝났다면 현재 `ss` 출력으로 과거 tuple을 재구성하지 않는다.

### 2. node tuple 비교

**SSH 함수 등록:** `run_node(){ local script="$1" arg q cmd='bash -s --'; shift; for arg in "$@"; do printf -v q '%q' "$arg"; cmd+=" $q"; done; ssh -- "$SSH_TARGET" "$cmd" <<<"$script"; }`

**bounded packet 실행:** `refresh_asym && [ "$REMOTE_READY" = true ] && [ "$OBSERVATION_READY" = true ] && NOW_EPOCH="$(date -u +%s)" && (( START_EPOCH <= NOW_EPOCH && NOW_EPOCH <= END_EPOCH )) && run_node 'expected_host=$1; expected_machine=$2; iface=$3; ssrc=$4; sport=$5; sdst=$6; fsrc=$7; fport=$8; fdst=$9; dport=${10}; [ "$(hostname -f 2>/dev/null || hostname)" = "$expected_host" ] || exit 20; [ "$(tr -d "\n" </etc/machine-id)" = "$expected_machine" ] || exit 21; command -v tcpdump >/dev/null 2>&1 || exit 127; sudo timeout 40 tcpdump -ni "$iface" -nn -tttt -q -c 40 "(src host $ssrc and src port $sport and dst host $sdst and dst port $dport) or (src host $sdst and src port $dport and dst host $ssrc and dst port $sport) or (src host $fsrc and src port $fport and dst host $fdst and dst port $dport) or (src host $fdst and src port $dport and dst host $fsrc and dst port $fport)"' "$EXPECTED_NODE_HOST" "$NODE_MACHINE_ID" "$NODE_INTERFACE" "$SUCCESS_SOURCE_IP" "$SUCCESS_SOURCE_PORT" "$SUCCESS_DEST_IP" "$FAILURE_SOURCE_IP" "$FAILURE_SOURCE_PORT" "$FAILURE_DEST_IP" "$DEST_PORT"`

**conntrack producer/filter 분리:** `refresh_asym && [ "$REMOTE_READY" = true ] && [ "$OBSERVATION_READY" = true ] && run_node 'expected_host=$1; expected_machine=$2; ssrc=$3; sport=$4; sdst=$5; fsrc=$6; fport=$7; fdst=$8; dport=$9; [ "$(hostname -f 2>/dev/null || hostname)" = "$expected_host" ] || exit 20; [ "$(tr -d "\n" </etc/machine-id)" = "$expected_machine" ] || exit 21; command -v conntrack >/dev/null 2>&1 || exit 127; tmp=$(mktemp) || exit 30; if ! sudo conntrack -L -p tcp >"$tmp" 2>&1; then printf "%s\n" "conntrack producer 실패" >&2; rm -f "$tmp"; exit 4; fi; matched=false; while IFS= read -r line; do if { [[ "$line" == *"src=$ssrc"* ]] && [[ "$line" == *"sport=$sport"* ]] && [[ "$line" == *"dst=$sdst"* ]] && [[ "$line" == *"dport=$dport"* ]]; } || { [[ "$line" == *"src=$fsrc"* ]] && [[ "$line" == *"sport=$fport"* ]] && [[ "$line" == *"dst=$fdst"* ]] && [[ "$line" == *"dport=$dport"* ]]; }; then printf "%s\n" "$line"; matched=true; fi; done <"$tmp"; rm -f "$tmp"; [ "$matched" = true ] || { printf "%s\n" "filter no-match: entry expiry와 tuple 불일치를 구분" >&2; exit 2; }' "$EXPECTED_NODE_HOST" "$NODE_MACHINE_ID" "$SUCCESS_SOURCE_IP" "$SUCCESS_SOURCE_PORT" "$SUCCESS_DEST_IP" "$FAILURE_SOURCE_IP" "$FAILURE_SOURCE_PORT" "$FAILURE_DEST_IP" "$DEST_PORT"`

성공 tuple은 ESTABLISHED이고 실패 tuple만 UNREPLIED면 NAT pool·allowlist·return path 후보가 강해진다. no-match는 entry 만료일 수 있다. capture·conntrack 성공도 외부 application 기능은 보장하지 않는다.

### 3. log·기능

**bounded producer/time/filter 실행:** `if ! refresh_asym || [ "$WINDOW_READY" != true ] || ! kubectl --context "$CONTEXT" auth can-i get pods/log -n "$NS" --quiet; then printf '%s\n' '중단: fresh identity/window/RBAC gate 실패' >&2; else RAW="$(mktemp)"; CUT="$(mktemp)"; if kubectl --context "$CONTEXT" logs "$POD" -n "$NS" -c "$CONTAINER" --timestamps --since-time="$START_RFC3339" --tail=400 >"$RAW"; then if awk -v end="$END_RFC3339" '$1 <= end' "$RAW" >"$CUT"; then if grep -E -i -C 3 'timeout|refused|reset|unreachable|no route|connect|handshake|tls|broken pipe' "$CUT"; then :; elif [ "$?" -eq 1 ]; then printf '%s\n' 'filter no-match: 오류 부재가 아님' >&2; else printf '%s\n' 'regex filter 오류' >&2; fi; else printf '%s\n' '시간 filter 오류' >&2; fi; else printf '%s\n' 'log producer 실패' >&2; fi; rm -f "$RAW" "$CUT"; fi`

두 시각을 tuple과 연결한다. dependency owner는 destination IP별 listener·allowlist·실제 read-only 기능을 확인한다. TCP handshake 한 번은 TLS·API·DB 기능을 보장하지 않는다.

## 변경 경계·정상화·PromQL

conntrack 삭제/flush, source IP 고정, route/NAT/firewall/sysctl/Pod 변경 명령은 제공하지 않는다. 별도 변경은 fresh identity, 두 tuple의 직접 증거, owner·승인 ID, 영향·멱등성·중단·rollback이 필요하다. replacement Pod는 owner kind/name/UID·selector·creation time으로 다시 선택하고 이전 READY를 폐기한다.

**정상화 identity gate:** `refresh_asym && kubectl --context "$CONTEXT" get pod "$POD" -n "$NS" -o custom-columns='NAME:.metadata.name,UID:.metadata.uid,RV:.metadata.resourceVersion,NODE:.spec.nodeName,POD-IP:.status.podIP,READY:.status.containerStatuses[*].ready,RESTARTS:.status.containerStatuses[*].restartCount,CONTAINER-IDS:.status.containerStatuses[*].containerID'`

정상화는 `실제 기능 → upstream listener → stateful allow → return packet → conntrack·SNAT → node route → Pod route → current container` 순서다. 승인된 재발 관찰 창에서 IP·source·node 어느 분기에도 실패가 없어야 한다.

**완성 PromQL 생성:** `QUERY_READY=false; if ! refresh_asym; then printf '%s\n' '중단: fresh gate 실패' >&2; else NS_Q="$(printf '%s' "$NS" | sed 's/\\/\\\\/g; s/"/\\"/g')"; POD_Q="$(printf '%s' "$POD" | sed 's/\\/\\\\/g; s/"/\\"/g')"; QUERY_READY=true; printf 'sum by (pod) (rate(container_network_transmit_errors_total{namespace="%s",pod="%s"}[5m]))\n' "$NS_Q" "$POD_Q"; printf 'rate(node_netstat_Tcp_RetransSegs[5m]) / clamp_min(rate(node_netstat_Tcp_OutSegs[5m]), 1)\n'; printf 'node_nf_conntrack_entries / node_nf_conntrack_entries_limit\n'; fi`

metric 미지원·empty vector·label·권한·query API 실패와 시간 범위를 분리한다. 보존 항목은 current Pod/owner/containerID/node UID·machineID, 두 canonical 시각·tuple, route, conntrack state, packet header summary, rule·listener·기능 결과다. payload·credential·token·private key는 저장하지 않는다. 실제 인프라와 Prometheus는 미검증이다.
