# Pod에서 외부 API·DB·인터넷으로 연결할 수 없는 경우

## 입력값과 빠른 수집

연결 hop은 `현재 container network namespace → Pod route → node/CNI → SNAT·egress gateway → firewall → 외부 listener → application`이다. Kubernetes 명령은 승인된 작업 PC의 같은 Bash에서 실행하고, node 명령은 선택된 Pod가 현재 배치된 node로 SSH한 뒤 machine identity를 다시 검증한다.

| 종류 | 변수 | 등록 기준 |
|---|---|---|
| 최초 입력 | `CONTEXT`, `NS`, `POD`, `DEST_HOST`, `DEST_PORT` | exact Pod 조회 성공 |
| API 자동값 | Pod UID·RV·owner·node·IP, Node UID·machineID, container 후보 | 모든 API 조회 성공 뒤 등록 |
| 계산 후보 | DNS address, 완성 PromQL | current container에서 관측하고 선택 전 미확정 |
| 운영자 선택값 | regular container·protocol, 실제 destination IP, UTC 창, node SSH/interface·SNAT source | 후보와 동일 연결 증거에서 선택 |

API path, query, credential, token과 DB 접속 문자열은 입력·출력·증거에 남기지 않는다.

**실행 위치·도구 확인:** `TOOLS_READY=false; MISSING=''; for T in kubectl jq sed date ssh mktemp grep awk; do command -v "$T" >/dev/null 2>&1 || MISSING="$MISSING $T"; done; if [ -z "${BASH_VERSION:-}" ]; then printf '%s\n' '중단: Bash에서 실행한다.' >&2; elif [ -n "$MISSING" ]; then printf '중단: 없는 도구=%s\n' "$MISSING" >&2; else TOOLS_READY=true; printf 'TOOLS_READY=true bash=%s\n' "$BASH_VERSION"; fi`

**하위 상태 폐기 함수:** `invalidate_egress(){ unset AUTO_READY SELECTION_READY WINDOW_READY EVIDENCE_READY REMOTE_READY LOG_READY QUERY_READY POD_UID POD_RV POD_IP NODE NODE_UID NODE_MACHINE_ID OWNER_KIND OWNER_NAME OWNER_UID CONTAINER_ID DEST_IP START_EPOCH END_EPOCH EVIDENCE_EPOCH POD_JSON NODE_JSON; AUTO_READY=false; SELECTION_READY=false; WINDOW_READY=false; EVIDENCE_READY=false; REMOTE_READY=false; LOG_READY=false; QUERY_READY=false; }`

**Pod·owner·Node·container 자동 수집:** `invalidate_egress; if [ "$INPUT_READY" != true ]; then printf '%s\n' '중단: INPUT_READY=false' >&2; elif PJ="$(kubectl --context "$CONTEXT" get pod "$POD" -n "$NS" -o json)" && PU="$(jq -er '.metadata.uid' <<<"$PJ")" && PR="$(jq -er '.metadata.resourceVersion' <<<"$PJ")" && PN="$(jq -er '.spec.nodeName | select(length>0)' <<<"$PJ")" && PI="$(jq -er '.status.podIP | select(length>0)' <<<"$PJ")" && NJ="$(kubectl --context "$CONTEXT" get node "$PN" -o json)" && NU="$(jq -er '.metadata.uid' <<<"$NJ")" && NM="$(jq -er '.status.nodeInfo.machineID | select(length>0)' <<<"$NJ")"; then POD_JSON="$PJ"; NODE_JSON="$NJ"; POD_UID="$PU"; POD_RV="$PR"; POD_IP="$PI"; NODE="$PN"; NODE_UID="$NU"; NODE_MACHINE_ID="$NM"; OWNER_KIND="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)][0].kind // "None"' <<<"$PJ")"; OWNER_NAME="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)][0].name // "None"' <<<"$PJ")"; OWNER_UID="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)][0].uid // "None"' <<<"$PJ")"; AUTO_READY=true; export POD_UID POD_IP NODE NODE_UID NODE_MACHINE_ID OWNER_KIND OWNER_NAME OWNER_UID; printf 'AUTO_READY=true pod=%s uid=%s rv=%s ip=%s node=%s node_uid=%s machine_id=%s owner=%s/%s owner_uid=%s\n' "$POD" "$POD_UID" "$POD_RV" "$POD_IP" "$NODE" "$NODE_UID" "$NODE_MACHINE_ID" "$OWNER_KIND" "$OWNER_NAME" "$OWNER_UID"; jq -r '(.spec.containers[] | .name) as $c | (.status.containerStatuses[]? | select(.name==$c)) | "Regular container 후보: \($c) currentID=\(.containerID // \"-\") running=\(.state.running != null) ready=\(.ready)"' <<<"$POD_JSON"; jq -r '(.spec.initContainers[]? | .name) as $c | (.status.initContainerStatuses[]? | select(.name==$c)) | "Init container(선택 제외): \($c) currentID=\(.containerID // \"-\")"' <<<"$POD_JSON"; else invalidate_egress; printf '%s\n' '중단: Pod·Node 자동 수집 실패, 하위 상태 폐기' >&2; fi; unset PJ PU PR PN PI NJ NU NM`

**regular container·protocol 선택:** `CONTAINER='PASTE_RUNNING_REGULAR_CONTAINER_HERE'; PROTOCOL='PASTE_TCP_UDP_OR_SCTP_HERE'`

**선택 검증:** `SELECTION_READY=false; unset CONTAINER_ID; if [ "$AUTO_READY" != true ]; then printf '%s\n' '중단: AUTO_READY=false' >&2; elif [ "$PROTOCOL" != TCP ] && [ "$PROTOCOL" != UDP ] && [ "$PROTOCOL" != SCTP ]; then printf '%s\n' '중단: protocol 형식 오류' >&2; elif CID="$(jq -er --arg c "$CONTAINER" '[.status.containerStatuses[]? | select(.name==$c and .state.running != null) | .containerID] | if length==1 and .[0]!="" then .[0] else error("regular running container relation") end' <<<"$POD_JSON")"; then CONTAINER_ID="$CID"; SELECTION_READY=true; export CONTAINER PROTOCOL CONTAINER_ID; printf 'SELECTION_READY=true container=%s currentID=%s protocol=%s\n' "$CONTAINER" "$CONTAINER_ID" "$PROTOCOL"; else printf '%s\n' '중단: current regular running container를 하나로 확인하지 못함' >&2; fi; unset CID`

**모든 exec·log·node 조회가 직접 호출할 current gate:** `refresh_egress(){ local pj nj pu pn pi nu nm cid okind oname ouid current_owner; AUTO_READY=false; SELECTION_READY=false; pj="$(kubectl --context "$CONTEXT" get pod "$POD" -n "$NS" -o json)" || { invalidate_egress; return 1; }; nj="$(kubectl --context "$CONTEXT" get node "$NODE" -o json)" || { invalidate_egress; return 1; }; pu="$(jq -r '.metadata.uid' <<<"$pj")"; pn="$(jq -r '.spec.nodeName // empty' <<<"$pj")"; pi="$(jq -r '.status.podIP // empty' <<<"$pj")"; nu="$(jq -r '.metadata.uid' <<<"$nj")"; nm="$(jq -r '.status.nodeInfo.machineID // empty' <<<"$nj")"; cid="$(jq -r --arg c "$CONTAINER" '[.status.containerStatuses[]? | select(.name==$c and .state.running != null) | .containerID] | if length==1 then .[0] else empty end' <<<"$pj")"; okind="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)][0].kind // "None"' <<<"$pj")"; oname="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)][0].name // "None"' <<<"$pj")"; ouid="$(jq -r '[.metadata.ownerReferences[]? | select(.controller==true)][0].uid // "None"' <<<"$pj")"; if [ "$pu" != "$POD_UID" ] || [ "$pn" != "$NODE" ] || [ "$pi" != "$POD_IP" ] || [ "$nu" != "$NODE_UID" ] || [ "$nm" != "$NODE_MACHINE_ID" ] || [ "$cid" != "$CONTAINER_ID" ] || [ "$okind/$oname/$ouid" != "$OWNER_KIND/$OWNER_NAME/$OWNER_UID" ]; then invalidate_egress; printf '%s\n' '중단: Pod/container/node/owner lifecycle 변경, 처음부터 재등록' >&2; return 1; fi; if [ "$OWNER_KIND" != None ]; then current_owner="$(kubectl --context "$CONTEXT" get "$OWNER_KIND" "$OWNER_NAME" -n "$NS" -o jsonpath='{.metadata.uid}' 2>/dev/null)" || { invalidate_egress; return 1; }; [ "$current_owner" = "$OWNER_UID" ] || { invalidate_egress; printf '%s\n' '중단: current owner UID 변경' >&2; return 1; }; fi; POD_JSON="$pj"; NODE_JSON="$nj"; POD_RV="$(jq -r '.metadata.resourceVersion' <<<"$pj")"; AUTO_READY=true; SELECTION_READY=true; return 0; }`

### DNS 후보 수집

**실행:** `refresh_egress && kubectl --context "$CONTEXT" auth can-i create pods/exec -n "$NS" --quiet && kubectl --context "$CONTEXT" exec "$POD" -n "$NS" -c "$CONTAINER" -- sh -c 'host=$1; if command -v getent >/dev/null 2>&1; then getent ahosts "$host"; elif command -v nslookup >/dev/null 2>&1; then nslookup "$host"; elif command -v dig >/dev/null 2>&1; then dig +short "$host"; else exit 127; fi' sh "$DEST_HOST"`

exit 127은 도구 부재다. producer non-zero, 성공한 빈 answer와 정상 address set을 구분한다. 여러 주소가 있으면 실제 실패 연결이 사용한 주소를 임의로 첫 번째에서 고르지 않는다.

**evidence·UTC·node 관측값 입력:** `DEST_IP='PASTE_ACTUAL_DESTINATION_IP_HERE'; START_RFC3339='PASTE_START_UTC_RFC3339_HERE'; END_RFC3339='PASTE_END_UTC_RFC3339_HERE'; EVIDENCE_RFC3339='PASTE_EVIDENCE_UTC_RFC3339_HERE'; SSH_TARGET='PASTE_APPROVED_NODE_SSH_TARGET_HERE'; EXPECTED_NODE_HOST='PASTE_EXPECTED_NODE_HOSTNAME_HERE'; NODE_INTERFACE='PASTE_NODE_EGRESS_INTERFACE_HERE'; SNAT_SOURCE='PASTE_OBSERVED_SNAT_SOURCE_IP_HERE'`

**canonical time·원격 node gate:** `WINDOW_READY=false; EVIDENCE_READY=false; REMOTE_READY=false; unset START_EPOCH END_EPOCH EVIDENCE_EPOCH; if [ "$SELECTION_READY" != true ] || [ -z "$DEST_IP" ]; then printf '%s\n' '중단: selection 또는 destination IP 없음' >&2; else START_EPOCH="$(date -u -d "$START_RFC3339" +%s 2>/dev/null)" || START_EPOCH=''; END_EPOCH="$(date -u -d "$END_RFC3339" +%s 2>/dev/null)" || END_EPOCH=''; EVIDENCE_EPOCH="$(date -u -d "$EVIDENCE_RFC3339" +%s 2>/dev/null)" || EVIDENCE_EPOCH=''; if [[ "$START_RFC3339" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] && [[ "$END_RFC3339" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] && [[ "$EVIDENCE_RFC3339" =~ ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$ ]] && [ -n "$START_EPOCH" ] && [ -n "$END_EPOCH" ] && [ -n "$EVIDENCE_EPOCH" ] && [ "$(date -u -d "@$START_EPOCH" '+%Y-%m-%dT%H:%M:%SZ')" = "$START_RFC3339" ] && [ "$(date -u -d "@$END_EPOCH" '+%Y-%m-%dT%H:%M:%SZ')" = "$END_RFC3339" ] && [ "$(date -u -d "@$EVIDENCE_EPOCH" '+%Y-%m-%dT%H:%M:%SZ')" = "$EVIDENCE_RFC3339" ] && (( START_EPOCH < END_EPOCH && START_EPOCH <= EVIDENCE_EPOCH && EVIDENCE_EPOCH <= END_EPOCH )); then WINDOW_READY=true; EVIDENCE_READY=true; if [ -n "$SSH_TARGET" ] && [ -n "$EXPECTED_NODE_HOST" ] && [ -n "$NODE_INTERFACE" ] && [ -n "$SNAT_SOURCE" ]; then REMOTE_READY=true; fi; export DEST_IP START_RFC3339 END_RFC3339 EVIDENCE_RFC3339; printf 'WINDOW_READY=true start=%s end=%s evidence=%s\nREMOTE_READY=%s node=%s node_uid=%s machine_id=%s\n' "$START_RFC3339" "$END_RFC3339" "$EVIDENCE_RFC3339" "$REMOTE_READY" "$NODE" "$NODE_UID" "$NODE_MACHINE_ID"; else printf '%s\n' '중단: UTC canonical·순서·evidence 창 오류' >&2; fi; fi`

## 진입 판단

| 구분 | 판단 기준 |
|---|---|
| 사용 | current Pod/container에서 외부 destination의 timeout, refused, reset, no route가 관측됨 |
| 적용 | 동일 destination IP·UTC 창의 Pod route, node SNAT, firewall, listener를 연결 가능 |
| 제외 | DNS는 [[07. DNS/01. Pod DNS/01. Pod의 DNS 질의가 timeout·SERVFAIL로 실패하는 경우]], NetworkPolicy는 [[12. 보안/03. NetworkPolicy/01. NetworkPolicy 적용 결과가 의도한 통신 허용·차단과 다른 경우]], 간헐 실패는 [[03. 비대칭 경로·SNAT·반환 경로 문제로 연결이 간헐적으로 실패하는 경우]] |

검색 문자열: `no such host`, `SERVFAIL`, `i/o timeout`, `connection refused`, `connection reset`, `no route to host`, `SNAT`, `DROP`, `SYN-ACK`.

## 관측별 진단 경로

| 지금 보이는 것 | 먼저 볼 것 | 그다음 어디를 볼지 | 상세 절 |
|---|---|---|---|
| DNS 주소 없음 | current container resolver 결과 | DNS owner | [[#DNS 후보 수집|DNS]] |
| route는 있으나 SYN-SENT | Pod source·node SNAT | firewall·return path | [[#1. Pod route·socket|1]], [[#2. node SNAT·packet|2]] |
| refused/RST | 외부 listener | dependency owner | [[#3. listener·기능|3]] |
| application 오류 시각 불명확 | bounded log producer/filter | 같은 UTC packet 증거 | [[#4. application log|4]] |

### 1. Pod route·socket

**route 실행:** `refresh_egress && [ "$WINDOW_READY" = true ] && kubectl --context "$CONTEXT" auth can-i create pods/exec -n "$NS" --quiet && kubectl --context "$CONTEXT" exec "$POD" -n "$NS" -c "$CONTAINER" -- sh -c 'command -v ip >/dev/null 2>&1 || exit 127; ip route get "$1"' sh "$DEST_IP"`

**socket 실행:** `refresh_egress && [ "$WINDOW_READY" = true ] && [ "$PROTOCOL" = TCP ] && kubectl --context "$CONTEXT" auth can-i create pods/exec -n "$NS" --quiet && kubectl --context "$CONTEXT" exec "$POD" -n "$NS" -c "$CONTAINER" -- sh -c 'command -v ss >/dev/null 2>&1 || exit 127; ss -tan "dst $1:$2"' sh "$DEST_IP" "$DEST_PORT"`

route 성공은 upstream NAT/firewall을 보장하지 않는다. TCP가 아니면 `ss -tan`으로 판단하지 않는다. 빈 socket 출력은 producer 성공 뒤 현재 matching socket이 없다는 뜻이며 연결 성공이 아니다.

### 2. node SNAT·packet

**SSH 함수 등록:** `run_node(){ local script="$1" arg q cmd='bash -s --'; shift; for arg in "$@"; do printf -v q '%q' "$arg"; cmd+=" $q"; done; ssh -- "$SSH_TARGET" "$cmd" <<<"$script"; }`

**node identity·route 실행:** `refresh_egress && [ "$REMOTE_READY" = true ] && run_node 'expected_host=$1; expected_machine=$2; dst=$3; [ "$(hostname -f 2>/dev/null || hostname)" = "$expected_host" ] || exit 20; [ "$(tr -d "\n" </etc/machine-id)" = "$expected_machine" ] || exit 21; ip route get "$dst"' "$EXPECTED_NODE_HOST" "$NODE_MACHINE_ID" "$DEST_IP"`

**bounded packet 실행:** `refresh_egress && [ "$REMOTE_READY" = true ] && [ "$EVIDENCE_READY" = true ] && [ "$PROTOCOL" = TCP ] && NOW_EPOCH="$(date -u +%s)" && (( START_EPOCH <= NOW_EPOCH && NOW_EPOCH <= END_EPOCH )) && run_node 'expected_host=$1; expected_machine=$2; iface=$3; pod_ip=$4; nat_ip=$5; dst=$6; port=$7; [ "$(hostname -f 2>/dev/null || hostname)" = "$expected_host" ] || exit 20; [ "$(tr -d "\n" </etc/machine-id)" = "$expected_machine" ] || exit 21; command -v tcpdump >/dev/null 2>&1 || exit 127; sudo timeout 30 tcpdump -ni "$iface" -nn -tttt -q -c 20 "(host $pod_ip or host $nat_ip) and host $dst and tcp port $port"' "$EXPECTED_NODE_HOST" "$NODE_MACHINE_ID" "$NODE_INTERFACE" "$POD_IP" "$SNAT_SOURCE" "$DEST_IP" "$DEST_PORT"`

도구·권한 실패를 packet 부재로 해석하지 않는다. pre-SNAT SYN은 있고 post-SNAT가 없으면 node/CNI/NAT, SYN은 나가고 SYN-ACK가 없으면 firewall/listener/return path 후보다. firewall owner에게 동일 UTC 창과 redacted tuple의 rule ID·decision을 요청한다.

### 3. listener·기능

외부 host shell과 승인된 비민감 health 절차는 dependency owner가 실행한다. LISTEN·TCP connect는 TLS, DB 인증, API response를 보장하지 않는다. HTTP는 status와 기대 application data를 분리하고 TLS 검증을 끄지 않는다. 이 문서는 URL·credential·SQL을 발명하지 않는다.

### 4. application log

**producer/time/filter 분리 실행:** `LOG_READY=false; if ! refresh_egress || [ "$WINDOW_READY" != true ] || ! kubectl --context "$CONTEXT" auth can-i get pods/log -n "$NS" --quiet; then printf '%s\n' '중단: fresh identity/window/RBAC gate 실패' >&2; else RAW="$(mktemp)"; CUT="$(mktemp)"; if kubectl --context "$CONTEXT" logs "$POD" -n "$NS" -c "$CONTAINER" --timestamps --since-time="$START_RFC3339" --tail=300 >"$RAW"; then if awk -v end="$END_RFC3339" '$1 <= end' "$RAW" >"$CUT"; then if grep -E -i -C 3 'timeout|refused|reset|no route|no such host|unreachable|tls|handshake|connect' "$CUT"; then LOG_READY=true; elif [ "$?" -eq 1 ]; then printf '%s\n' 'filter no-match: 오류 부재가 아님' >&2; else printf '%s\n' 'regex filter 오류' >&2; fi; else printf '%s\n' '시간 filter 오류' >&2; fi; else printf '%s\n' 'kubectl logs producer 실패' >&2; fi; rm -f "$RAW" "$CUT"; fi`

filter match를 packet·route와 같은 시각에 연결한다. no-match와 producer 실패를 섞지 않는다. 민감정보가 보이면 출력·저장을 중단한다.

## 변경 경계·정상화·PromQL

이 문서는 NetworkPolicy, route, NAT, firewall, security group, conntrack, sysctl, Pod를 변경하는 명령을 제공하지 않는다. 별도 변경은 current Pod/owner/containerID/node identity, 동일 tuple·UTC evidence, owner·승인 ID, 영향·멱등성·중단 조건·검증된 rollback이 필요하다. Pod replacement가 생기면 이전 이름·UID·READY를 재사용하지 않고 owner UID·selector·creation time으로 단일 새 대상을 재등록한다.

**정상화 identity gate:** `refresh_egress && kubectl --context "$CONTEXT" get pod "$POD" -n "$NS" -o custom-columns='NAME:.metadata.name,UID:.metadata.uid,RV:.metadata.resourceVersion,PHASE:.status.phase,NODE:.spec.nodeName,POD-IP:.status.podIP,READY:.status.containerStatuses[*].ready,RESTARTS:.status.containerStatuses[*].restartCount,CONTAINER-IDS:.status.containerStatuses[*].containerID'`

정상화는 `application read-only 기능 → listener → firewall allow → return packet → SNAT → node route → Pod route → current container` 순서다. 같은 관찰 창에 오류·SYN-SENT·drop이 재발하지 않아야 하며 TCP connect나 Pod Ready만으로 닫지 않는다.

**완성 PromQL 생성:** `QUERY_READY=false; if ! refresh_egress; then printf '%s\n' '중단: fresh gate 실패' >&2; else NS_Q="$(printf '%s' "$NS" | sed 's/\\/\\\\/g; s/"/\\"/g')"; POD_Q="$(printf '%s' "$POD" | sed 's/\\/\\\\/g; s/"/\\"/g')"; NODE_Q="$(printf '%s' "$NODE" | sed 's/\\/\\\\/g; s/"/\\"/g')"; QUERY_READY=true; printf 'kube_pod_status_ready{namespace="%s",pod="%s",condition="true"} == 1\n' "$NS_Q" "$POD_Q"; printf 'sum by (pod) (rate(container_network_transmit_errors_total{namespace="%s",pod="%s"}[5m]))\n' "$NS_Q" "$POD_Q"; printf 'sum by (instance,device) (rate(node_network_transmit_drop_total{node="%s"}[5m]) + rate(node_network_transmit_errs_total{node="%s"}[5m]))\n' "$NODE_Q" "$NODE_Q"; fi`

metric·label 미지원, query API 오류, 권한 실패, empty vector와 시간 범위를 분리한다. 보존 항목은 Pod/owner/containerID/node UID·machineID, UTC 창, destination address, route, SNAT source, packet summary, rule decision과 실제 기능 결과다. payload·token·private key·DB 문자열은 저장하지 않는다. 실제 Kubernetes·SSH·CNI·firewall·외부 provider·Prometheus 환경은 미검증이다.
