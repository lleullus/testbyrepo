# externalTrafficPolicy 때문에 트래픽이 실패하거나 source IP가 보존되지 않는 경우

## 입력값과 빠른 수집

kubectl은 작업 PC/bastion, node 관측은 승인된 원격 node, source 관측은 승인된 external probe와 backend access metric에서 수행한다. hop은 `client source → edge NAT/firewall → VIP/listener/health → node address:nodePort → externalTrafficPolicy Local/Cluster → local 또는 cross-node endpoint → L7 proxy → backend가 관측한 source`다. client IP, proxy protocol/X-Forwarded-For와 packet source를 혼동하지 않는다.

| lifecycle | 값 | 계약 |
|---|---|---|
| 최초 입력 | context·namespace·Service | exact Service다. |
| API 자동값 | Service UID/RV/policy, nodePort/healthCheckNodePort, EndpointSlice targetRef UID/node | 원자 등록한다. |
| 계산 후보 | Service/node regex, locality 집계, UTC | 실제 source evidence 전에는 원인이 아니다. |
| 운영자 선택값 | failed/working node, approved source, observation point, provider health identity, SSH host | 분기 직전에 고른다. |

backend source는 승인된 access metric/log의 source 필드만 사용하고 payload·header·개인정보는 저장하지 않는다. `Cluster`는 source 보존을 보장하지 않는다. `Local`도 edge/L7 proxy가 source를 바꿀 수 있다. X-Forwarded-For/PROXY protocol은 packet source와 별도이며 신뢰 proxy 목록이 확인된 경우만 해석한다.

Local이면 failed/working node의 Ready와 serving endpoint를 대조한다. 해당 node serving endpoint 부재는 locality 설명이지만 provider가 그 node를 member로 사용했는지는 health evidence가 필요하다. Cluster이면 cross-node forwarding/NAT와 return path를 확인한다.

`healthCheckNodePort`가 Service에 있어도 provider가 실제로 사용한다는 증거가 아니다. 같은 resource/health ID의 probe source·port/path·backend membership·UTC 결과를 owner read-only 절차로 대조한다. provider ID 관계가 없으면 CLI/API를 실행하지 않는다.

## 안전한 원격 node 관측

원격 인수는 positional argument로 전달하고 `eval`을 사용하지 않는다. remote hostname/machineID를 API node와 대조한 뒤에만 제한된 socket/route 정보를 읽는다.

`REMOTE_READY=false; if [ "$NODE_READY" != true ] || ! etp_fresh || ! etp_relation_fresh || ! etp_node_fresh; then printf '%s\n' '중단: latest Service/relation/nodes gate 실패' >&2; elif ssh -- "$NODE_HOST" bash -s -- "$FAILED_NODE" "$NODE_MACHINE_ID" "$NODE_PORT" "$POLICY" <<< 'set -u; expected_node="$1"; expected_machine="$2"; node_port="$3"; policy="$4"; actual_host="$(hostname)"; actual_machine="$(cat /etc/machine-id)"; [ "$actual_machine" = "$expected_machine" ] || { printf "중단: remote machine mismatch expected_node=%s host=%s machine=%s\n" "$expected_node" "$actual_host" "$actual_machine" >&2; exit 1; }; ss -ltn "sport = :$node_port"; ss_rc=$?; printf "REMOTE_READY=true expected_node=%s host=%s machine=%s policy=%s ss_rc=%s\n" "$expected_node" "$actual_host" "$actual_machine" "$policy" "$ss_rc"'; then REMOTE_READY=true; else printf '%s\n' '중단: remote preflight/read 실패' >&2; fi`

socket 부재는 iptables/ipvs/nft data plane 부재를 의미하지 않는다. proxy mode가 확인된 뒤 owner가 승인한 한 경로만 읽는다. CRI/kubelet endpoint·container runtime은 source NAT/locality 판정에 필요하지 않으므로 `crictl`을 실행하지 않는다. route/NAT/firewall은 translation·rule ID·SYN/SYN-ACK·return path UTC만 요청한다.

## 판정·변경·정상화

- Local + member node local serving endpoint 없음 + provider health 실패가 같은 시각이면 locality/health 경계다.
- Cluster + backend source가 node/proxy 주소로 변환되면 정책상 가능한 SNAT 후보지만 실제 proxy/provider evidence가 필요하다.
- policy/locality가 맞는데 transport가 실패하면 일반 NodePort/VIP/route 경계로 이동한다.
- source IP 요구는 보안·rate-limit·audit 영향과 L7 trusted proxy 계약을 함께 평가한다.

이 문서에는 mutation 명령을 두지 않는다. `externalTrafficPolicy`, endpoint 배치, provider health, firewall/NAT 변경은 fresh Service/node/provider identity, 직접 evidence, 승인 ID/window, PDB/quorum·capacity·source-dependent consumer 영향, 멱등성, rollback과 중단 조건을 갖춘 owner 경로에서만 한다. 즉시 patch, node label 변경, health 완화, endpoint 강제 이동은 금지한다.

변경 뒤 `reset_etp_state`부터 전체 재등록한다. replacement UID/policy/node면 이전 source·health 증거를 폐기한다. 실제 정상화는 Local이면 intended member마다 serving endpoint·health·연결·source, Cluster면 cross-node 연결·의도한 source 형태·return path, 그리고 L7 실제 기능과 관찰 창 재발 부재를 확인한다.
