# 저장된 대화 세션 이어가기

Status: approved
Owner: user01

## Problem

Oracle Browser 호출자는 후속 질문을 요청할 때 현재 OpenCode 대화가 사용한 어느 Oracle 세션과 ChatGPT 대화를 이어야 하는지 직접 찾아 지정해야 하며, 다른 슬롯이나 새 ChatGPT 대화로 잘못 제출되지 않았는지 일관되게 확인하기 어렵다. 현재 대화의 최근 상담을 안전하게 선택하고 같은 브라우저 정체성과 ChatGPT conversation에서 계속했다는 증거가 필요하다.

## Desired Outcome

현재 OpenCode 대화에서 팔로우업 의도를 밝히면 가장 최근의 재개 가능한 Oracle Browser 세션이 기본 부모로 선택되고, 후속 질문과 응답이 부모의 원 슬롯·로그인 프로필에서 같은 ChatGPT conversation에 추가된다. 각 후속 실행은 부모와 연결된 새 Oracle 자식 세션으로 남아 다음 팔로우업과 사후 확인에 사용된다.

## Requirements

- 세션 ID가 없는 팔로우업 요청은 현재 OpenCode 대화가 만든 Oracle Browser 세션 중 가장 최근의 재개 가능한 세션을 기본 부모로 선택한다.
- 사용자가 세션 ID를 명시하면 해당 세션을 기본 자동 선택보다 우선한다.
- 명시된 세션이 재개 자격을 충족하지 않으면 다른 세션으로 대체하지 않고 이유를 보여 주며 실패한다.
- 재개 가능한 세션은 실행이 끝났고 안정적인 ChatGPT 대화 식별 정보와 관리되는 원 슬롯·로그인 프로필을 확인할 수 있는 브라우저 세션이어야 한다.
- 정상 완료, 오류 또는 취소 상태는 그 자체로 재개 자격을 결정하지 않으며, 종료 여부와 대화·원 슬롯 복구 가능성을 기준으로 판단한다.
- 세션의 보관 여부는 그 자체로 재개 후보에서 제외하는 이유가 아니다.
- 실행 중인 세션과 ChatGPT 대화 식별 정보 또는 관리되는 원 슬롯을 확인할 수 없는 세션은 자동 부모 후보에서 제외한다.
- 자동 선택할 재개 가능 세션이 없으면 새 ChatGPT 대화를 만들지 않고 후보가 없는 이유와 명시 세션 지정 방법을 보여 주며 실패한다.
- 후속 요청은 부모 세션의 원 슬롯·로그인 프로필에 자동 고정하고 다른 슬롯으로 대체하지 않는다.
- 원 슬롯이 점유 중이면 자동 만료 없이 해당 슬롯만 기다리며 호출자가 대기 요청을 취소할 수 있어야 한다.
- 원 슬롯이 미준비 또는 사용 불가 상태이면 다른 슬롯으로 전환하거나 계속 기다리지 않고 복구 안내와 함께 실패한다.
- 후속 질문은 부모와 같은 ChatGPT conversation에 제출되어야 하며 새 ChatGPT 대화를 만들지 않는다.
- 각 후속 실행은 새 Oracle 자식 세션 ID를 만들고 선택된 부모 세션과의 관계를 남긴다.
- 다음 암시적 팔로우업은 현재 OpenCode 대화가 만든 최신 재개 가능한 자식 세션을 선택해 같은 대화 chain을 계속한다.
- 자식 세션에는 부모 선택 방식, 부모·자식 세션 ID, 원 슬롯, 부모와 동일한 conversation ID/URL, 후속 프롬프트 제출 결과와 응답 완료 상태를 남긴다.
- 저장된 lineage 증거와 후속 응답은 기존 세션 조회 흐름에서 다시 확인할 수 있어야 한다.
- 일반 새 Oracle 요청과 슬롯 준비·상태·점유, 기존 세션 조회의 이 범위 밖 관찰 가능한 동작은 변경하지 않는다.

## Non-Goals

- 모든 첨부를 단일 ZIP으로 묶거나 첨부 용량 정책을 변경하지 않는다.
- API 엔진 응답을 이어가지 않는다.
- 저장된 Oracle 세션과 무관한 임의 ChatGPT URL을 재개하지 않는다.
- 최초 호출 안에서 미리 정한 여러 후속 질문을 자동 제출하지 않는다.
- 원 슬롯을 사용할 수 없을 때 다른 로그인 프로필의 슬롯으로 대체하지 않는다.
- 재개 가능한 부모가 없을 때 일반 새 대화로 자동 전환하지 않는다.

## Implementation Constraints

- 대상은 현재 OpenCode 대화가 소유한 로컬 Oracle Browser 세션과 사용자가 명시한 로컬 Oracle Browser 세션이다.
- 후속 요청은 부모 세션의 관리되는 원 슬롯·로그인 프로필과 같은 ChatGPT conversation을 사용해야 한다.
- 각 후속 실행은 부모 기록을 덮어쓰지 않고 별도의 자식 세션과 lineage 증거를 남겨야 한다.
- 원 슬롯 점유 대기는 자동 만료되지 않아야 하며 호출자 취소를 허용해야 한다.

## Verification Expectations

- 현재 OpenCode 대화가 여러 Oracle Browser 세션을 만든 대표 흐름에서 세션 ID 없는 팔로우업이 가장 최근의 재개 가능한 세션을 부모로 선택하는지 확인한다.
- 세션 ID를 명시한 팔로우업이 자동 후보보다 해당 세션을 우선하고, 명시 세션이 부적격하면 다른 세션으로 대체하지 않는지 확인한다.
- 완료·오류·취소 및 보관 여부가 다른 종료 세션에서 대화 식별 정보와 원 슬롯이 복구 가능하면 후보가 되고, 실행 중이거나 복구 정보가 없으면 제외되는지 확인한다.
- 재개 가능한 부모가 없는 요청이 새 ChatGPT 대화를 만들거나 프롬프트를 제출하지 않고 이유와 명시 지정 방법을 보여 주는지 확인한다.
- 원 슬롯이 점유 중인 요청이 다른 빈 슬롯을 사용하지 않고 기다리며, 슬롯 해제 후 원 슬롯에서 실행되고 대기 중 취소할 수 있는지 확인한다.
- 원 슬롯이 미준비 또는 사용 불가이면 다른 슬롯으로 전환하거나 계속 기다리지 않고 복구 안내와 함께 실패하는지 확인한다.
- 성공한 실제 Oracle Browser 팔로우업에서 부모와 자식의 conversation ID/URL이 같고 후속 질문과 응답이 기존 ChatGPT conversation에 추가되며 새 대화가 만들어지지 않는지 확인한다.
- 자식 세션을 다시 읽어 선택 방식, 부모·자식 세션 ID, 원 슬롯, 동일 conversation ID/URL, 프롬프트 제출 결과, 응답 완료 상태와 후속 응답을 확인할 수 있어야 한다.
- 연속 팔로우업에서 다음 요청이 최신 재개 가능한 자식 세션을 부모로 선택하고 동일한 ChatGPT conversation chain을 유지하는지 확인한다.
- 일반 새 Oracle 요청과 슬롯 준비·상태·점유 및 기존 세션 조회의 범위 밖 관찰 가능한 결과가 유지되는지 확인한다.
