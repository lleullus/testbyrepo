# Oracle Browser Managed Slots

Status: approved
Owner: user
Scope: 운영자가 명시적으로 관리하는 Oracle Browser 슬롯의 식별, 준비 상태, 실행 적격성, 자동 배정 및 followup 원 슬롯 연속성

## Research

- 현재 관리 슬롯 집합은 `1, 2, 3, 4, 5`이며 슬롯 ID 허용, 상태 조회, 프로필, 포트, workspace mapping 및 followup 원점 검증의 기준으로 사용된다.
- 슬롯 10의 파생 기본 endpoint는 `127.0.0.1:19231`이고 프로필은 `slot-10`이다.
- 상태, 잠금, 로그 및 프로필 경로는 슬롯 ID별로 분리되므로 슬롯 10은 기존 슬롯 1~5와 별도 운영 경계를 가진다.
- 실행 적격성은 별도 capability 정책으로 결정된다. 현재 정책을 그대로 두면 슬롯 집합에 10을 추가해도 `run`, 자동 `submit`, `followup`은 슬롯 10을 실행 대상으로 인정하지 않는다.
- 로그인 확인은 요청 시작에 필요한 ChatGPT 로그인 상태만 확인하며 계정 신원, 구독, 모델 권한 또는 workspace 접근 권한을 증명하지 않는다.

## Behavior Model

- 관리 슬롯의 식별 집합은 `1, 2, 3, 4, 5, 10`이다. 슬롯 `6, 7, 8, 9` 및 그 밖의 ID는 관리 슬롯이 아니다.
- 슬롯 10은 기존 슬롯 1~5의 상태, 프로필, 점유 및 실행 결과를 변경하지 않는 독립 슬롯이다.
- 슬롯 10의 기본 endpoint는 `127.0.0.1:19231`이고 기본 프로필은 `slot-10`이다.
- 운영자는 슬롯 10을 독립적으로 준비하고 상태를 조회할 수 있다. 준비 성공은 전용 CDP endpoint, ChatGPT 로그인 및 비점유가 확인된 상태를 뜻한다.
- 슬롯 10에는 동시에 Oracle 작업 하나만 점유할 수 있고, 중복 request ID 탐지는 기존 관리 슬롯과 같은 경계를 적용한다.
- 슬롯 10에서 생성된 managed session의 followup은 슬롯 10만 사용한다. 점유 시 그 슬롯만 기다리고, 사용할 수 없으면 다른 슬롯으로 전환하지 않고 복구 가능한 실패를 반환한다.
- 슬롯 10의 계정 로그인, 구독, 모델 권한 및 workspace 접근 적합성은 운영자가 관리한다.
- 슬롯 10은 슬롯 1~2와 같은 reasoning capability를 가진다.
- 기존 슬롯의 상대적 우선순위는 보존하며 슬롯 10은 각 호환 후보 목록의 마지막에 배치한다.
- 기본/standard/medium 후보 순서는 `1, 2, 3, 4, 5, 10`이다.
- light/instant/low 및 heavy/extra-high/pro 후보 순서는 `1, 2, 10`이다.
- extended/high 후보 순서는 `3, 4, 5, 1, 2, 10`이다.

## Counterexample Stress Test

- 구현이 `1..10` 연속 범위를 허용하면 슬롯 6~9가 의도치 않게 준비·실행·workspace mapping 대상이 된다. 허용 집합은 비연속적인 `1, 2, 3, 4, 5, 10`으로 고정한다.
- 슬롯 ID만 추가하고 capability 정책을 유지하면 상태에는 나타나지만 실제 `run`, `submit`, `followup`에는 사용할 수 없는 슬롯이 된다. 승인된 capability 정책을 모든 실행 경로에 일관되게 적용해야 한다.
- 자동 배정에는 포함하지만 followup 호환성에는 포함하지 않는 구현은 슬롯 10에서 시작한 세션을 이어갈 수 없게 한다. 같은 capability 판단이 초기 실행과 followup에 적용되어야 한다.
- followup이 슬롯 10 장애 시 다른 슬롯으로 이동하면 프로필 및 대화 원점이 달라진다. 다른 슬롯 fallback은 금지한다.
- 로그인 성공을 특정 계정 또는 모델 권한의 증거로 취급하면 실제 요청에서 권한 차이가 드러날 수 있다. 준비 상태와 capability 운영 배정은 별도 의미로 유지한다.
- 슬롯 10 준비 실패가 기존 슬롯 상태를 변경하면 독립 슬롯 계약을 위반한다. 실패와 복구는 슬롯 10에 국한한다.

## Product Decision Return

None

## Conclusion

슬롯 10은 기존 슬롯 1~5를 그대로 보존하면서 추가되는 하나의 비연속 관리 슬롯이다. 슬롯 6~9는 계속 거부되며, 슬롯 10은 독립 준비·상태·단일 점유·중복 방지·원 슬롯 followup 경계를 기존 관리 슬롯과 동일하게 제공한다. 슬롯 10은 슬롯 1~2와 같은 reasoning capability를 가지며, 기존 슬롯의 상대적 우선순위를 바꾸지 않도록 각 호환 후보 목록의 마지막에 배치한다.
