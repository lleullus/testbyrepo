## Current System Model

### Runtime Structure

```text
Thinking effort picker
├─ Simple view: Power slider
│  └─ Instant | Medium | High | Extra High | Pro
└─ Advanced view: model/version selector
   └─ Latest | GPT-5.6 Sol | GPT-5.5
```

The final browser model is selected by the conjunction of the version track and Power position. Current `Latest + Pro` resolves to `gpt-6-pro` and displays `6 Pro`.

### Entry And Execution Flow

```text
Stock model token + --browser-thinking-time pro
→ browser desiredModel label + reasoningIntent=pro
→ select and verify model/version row
→ select and verify Power=Pro
→ close picker and verify combined identity
→ submit prompt
→ persist modelSelection + reasoningSelection
```

Wrapper `run` validates one explicit slot, `submit` allocates from compatible candidates, and `followup` remains on the parent origin slot. For accepted Pro combinations the slot boundary is `(1,2,10)`.

### Ownership Boundaries

- ChatGPT live UI owns current option availability and selected state.
- Stock Oracle owns browser selection, pre-submit verification and browser evidence.
- Managed wrapper owns slot eligibility, allocation and conversation-origin continuity.
- No one layer's readback substitutes for the other two.

## Inferences

### Inference 1 — Latest must remain dynamic

Statement: A durable user choice named Latest should mean “the current Latest row at invocation time,” while readback records its resolved display/model identity. Mapping it permanently to GPT-6 would become stale when ChatGPT advances Latest.
Supported By: Finding 2, Finding 3
Plausible Alternative: Expose only fixed model versions and omit Latest. This contradicts the current three-choice user requirement.
Evidence Needed To Disprove: User explicitly rejects dynamic Latest and requests only a fixed GPT-6 Pro target.
Planning Relevance Candidate: PLANNING_CONSTRAINT_CANDIDATE

### Inference 2 — Verification must bind row and Power together

Statement: The minimal truthful success condition is conjunction, not either signal alone: requested model/version row is checked and resolved, Power is Pro, model identity remains continuous, then prompt submission is allowed.
Supported By: Finding 1, Finding 4, Finding 5, Finding 7
Plausible Alternative: Closed pill text alone could encode both. Current code only recognizes `6 Pro`, and exact explicit-version text was not observed, so a sole hard-coded pill matcher is not a stable contract.
Evidence Needed To Disprove: A current, stable browser contract proving one canonical closed-pill semantic for all three choices and exact parse rules.
Planning Relevance Candidate: PRODUCT_DEPENDENCY_CANDIDATE

## Alternate, Legacy And Bypass Paths

- Legacy `Pro Extended` and `Thinking 5.5` labels remain in matchers and tests, but they are not the current three visible model/version rows.
