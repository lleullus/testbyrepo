## Current System Model

### Entry And Execution Flow

1. Commander의 `--browser-thinking-time` parser가 일반 4단계 alias를 `ThinkingTimeLevel`로, 문자열 `pro`만 별도 값으로 반환한다.
2. `buildBrowserConfig()`는 일반 단계는 `thinkingTime`, `pro`는 `reasoningIntent: "pro"`로 분기한다.
3. `resolveBrowserConfig()`는 일반 단계도 `instant | medium | high | extra-high` intent로 변환하여 최종 `BrowserReasoningIntent` 하나를 만든다.
4. `src/browser/index.ts`는 각 제출 전 `ensureBrowserReasoning()`을 호출하고 `verified`가 아니면 prompt를 제출하지 않는다.
5. strict controller는 `LEVEL_RANK = instant, medium, high, extra-high, pro`인 top-level slider/dropdown을 조작한다. `pro`는 slider maximum 및 `6 Pro` elevation으로만 판정된다.
6. selection evidence는 requested/resolved intent, available levels, status, model identity, managed slot을 session metadata에 기록하지만 intent union이 단일 `pro`라 세 내부 강도는 보존할 수 없다.

### State, Data And Lifecycle Ownership

- wrapper `StateStore/SlotService`: slot 준비·점유·PID·port/profile 상태.
- wrapper `JobRunner/AutoAllocator`: argv capability 검증과 slot order.
- stock browser controller: 실제 ChatGPT reasoning control 선택과 prompt-before-selection gate.
- stock session metadata: 실제 selection evidence와 누적 turn attempts.
- wrapper followup namespace: caller context, parent-child relation, originating slot과 completion/readback; reasoning detail은 stock metadata를 재해석하거나 복제하지 않음.

### Configuration And Extension Boundaries

- user/project config의 `thinkingTime`은 일반 4단계 타입/normalizer만 허용하여 `pro`조차 config 경로에서 소실된다.
- MCP `browserThinkingTime` strict enum은 `pro`를 허용하지 않고, `chatgpt-pro-heavy` preset만 별도 내부 flag로 단일 `reasoningIntent: "pro"`를 만든다.
- followup은 CLI에서 현재 명시한 reasoning만 적용하며, 생략하면 저장 config의 `thinkingTime`/`reasoningIntent`를 제거한다.
- wrapper는 unknown/duplicate/empty reasoning token을 claim/queue 전에 거절하고 알려진 token은 child argv에 그대로 전달한다.

### Observable Results And Readbacks

- 입력 수용: CLI parse 성공 또는 explicit error.
- slot route: wrapper compatible tuple/rejection 및 lifecycle JSONL.
- UI selection: strict controller의 positive selected state, numeric position, owner/control continuity 및 model identity.
- durable readback: stock `meta.json`의 `reasoningSelection`/`reasoningSelections`; wrapper authoritative readback은 원 슬롯·conversation·submission/completion을 보강한다.

## Inferences

### Inference 1 — 필요한 product contract는 3개 이름 추가가 아니라 end-to-end identity 보존이다

Statement: parser에 세 token만 추가해도 selector와 metadata가 모두 `pro`로 합치면 사용자가 어느 강도를 요청·실행했는지 알 수 없다. 요청 식별자, UI target, selected-state readback, session evidence가 같은 세부 강도를 가리켜야 제품 약속이 성립한다.
Supported By: Finding 1, Finding 2, Finding 3, Finding 6
Plausible Alternative: 세 token을 모두 현재 `pro` maximum으로 aliasing하는 방법은 입력 수용은 늘리지만 세 강도 개별 선택이라는 결과를 제공하지 못한다.
Evidence Needed To Disprove: ChatGPT가 세 입력을 받지 않고도 외부의 다른 authoritative API에서 선택 강도를 결정·증명한다는 현재 제품 경로.
Planning Relevance Candidate: PLANNING_CONSTRAINT_CANDIDATE

### Inference 2 — 세 강도는 routing capability와 selection identity를 분리해야 한다

Statement: 동일 Pro 계정 capability를 요구하는 세 강도라면 wrapper route class는 공유할 수 있지만 selection identity는 공유할 수 없다. route equality는 UI 강도 equality의 증거가 아니다.
Supported By: Finding 3, Finding 4, Finding 5
Plausible Alternative: 세 강도별 entitlement가 다르면 wrapper capability 모델도 더 세분화되어야 한다.
Evidence Needed To Disprove: 세 강도별 슬롯 entitlement에 차이가 있다는 current account readback.

- User/project config: 일반 `thinkingTime`만 보존; `pro` 및 세부 강도는 소실/불가.
- MCP direct: strict enum에 `pro`와 세부 강도가 없음.
- MCP preset: `chatgpt-pro-heavy` 하나가 내부 single `pro` intent를 주입; 이름과 실제 legacy mapping도 혼합됨.
- Followup: 명시값만 재적용하고 미지정 시 current UI를 유지; 부모의 stored intent를 current selected-state 증거로 재사용하지 않음.
