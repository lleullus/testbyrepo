## Current System Model

2. runner.py의 compatible_slots가 argv에서 --model/--models와 --browser-thinking-time을 파싱하여 호환 슬롯 목록을 산출한다.
3. 슬롯이 확정되면 _validated_oracle_command가 필수 플래그(--engine browser, --browser-model-strategy current, --remote-chrome 127.0.0.1:<port>)를 주입한다.

### Finding 2 — Lifecycle & Followup Model-Agnostic Isolation

Classification: FACT
Statement: Wrapper의 슬롯 상태(service.py), 큐 파일(allocator.py), 부모 세션 검증(followup.py)은 모두 모델 및 추론 강도 필드를 보관하거나 비교하지 않는다. followup.py는 원 슬롯과 endpoint, 대화 ID의 일치만 검사하며 부모-자식 간 모델 불일치(예: 부모 gpt-6-pro, 자식 gpt-5.6-sol)를 허용한다. 단, _eligible_parent가 originating_slot dict의 완전 일치(==)를 검사하므로 이 dict에 모델 필드를 추가하면 이전 부모 세션들이 모두 거절된다.
Primary Evidence: A3
Counterevidence Checked: 실제 합성 세션 메타데이터 프로브 결과, 부모 gpt-6-pro와 자식 gpt-5.6-sol 간의 followup 기록 및 검증이 ok: true로 통과함.

### Finding 4 — Account Plan Cardinality Disparity (Pro vs Plus)

Classification: FACT
Statement: Pro 계정(슬롯 1, 2, 10)은 슬라이더가 5단계(max=4)를 지원하여 Pro 선택이 가능한 반면, Plus 계정(슬롯 3, 5는 max=2, 슬롯 4는 max=3)은 최대 단계가 High에 불과하다. 따라서 Pro 추론 요청을 Plus 슬롯(3, 4, 5)에 라우팅하면 DOM 레벨에서 Pro 선택이 불가능하여 실행이 실패한다.

### Finding 6 — Radix Slider Keyboard Event Ineffectiveness

Classification: FACT
Statement: Stock Oracle의 thinkingTime.ts(dispatchArrow)는 role="menuitem" (Power 컨테이너)에 synthetic KeyboardEvent를 발생시키지만, 실제 ChatGPT의 슬라이더 thumb 및 트랙은 포인터 이벤트 핸들러(onPointerDown, onPointerMove)에 바인딩되어 있어 키보드 이벤트로 슬라이더 값이 변경되지 않는다. 반면 CDP 레벨의 Input.dispatchMouseEvent는 실제 thumb에 도달하여 정상적으로 단계를 조작할 수 있다.
Primary Evidence: A4, A6
Counterevidence Checked: 라이브 브라우저에서 synthetic KeyboardEvent 디스패치 시 isTrusted: false로 값 변화 없음, CDP Input.dispatchMouseEvent로 좌표 클릭 시 aria-valuenow가 3에서 4로 즉시 갱신됨.
Boundary / Limitation: DOM 좌표 기반 클릭은 뷰포트 크기 및 스크롤 위치에 민감할 수 있으므로, interactionNode의 실제 bounding rect를 실시간 계산해야 함.
Planning Relevance Candidate: CURRENT_STATE
Freshness Sensitivity: RUNTIME_STATE

### Finding 7 — Strict Reasoning Fingerprint Role Mismatch Bug

Classification: FACT
