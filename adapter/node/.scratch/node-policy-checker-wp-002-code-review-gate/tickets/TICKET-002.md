## Goal

작성된 Node/TypeScript 변경이 확정 규칙과 근거 기반 AI 의미 판정을 모두 통과한 경우에만 코드 및 리뷰 품질 완료로 인정되게 한다.

## Acceptance Criteria

- 최종 Gate는 b-1~b-3, c-1~c-5, d-1~d-3 전체를 실행하고 판정한다.
- 빈 catch, 조용한 에러 삼킴, 무의미한 fallback과 호출부에 반복된 방어 처리를 판정한다.
- 3단계 이상의 중첩에서 필요성이 근거로 확인되지 않은 경우 차단한다.
- 함수 및 파일 크기, complexity, max-depth에 안전 기본 상한을 적용한다.
- 기존 코드를 대체해야 하는 변경에서 의미 중복, 남은 죽은 코드와 주석 처리 코드를 판정한다.
- 숨은 결합, 암묵 계약, 초기화 순서 의존, 전역 상태 공유와 side effect로 연결된 모듈을 판정한다.
- re-export가 WP-001에서 고정한 경계 및 SSOT와 일치하는지 판정한다.
- fan-in 및 fan-out이 안전 상한을 넘어 한 책임에 과도하게 집중되는지 판정한다.
- TypeScript strict 상태를 요구하고 `as any`와 `as unknown as`를 허용하지 않는다.
- 타입이 없는 JavaScript에서는 암묵 계약을 드러내는 JSDoc 의무를 판정한다.
- 순환 의존성과 WP-001에서 고정한 경계 위반을 차단한다.
- 수치형 품질 상한은 검사기 안전 기본값을 적용하고 저장소의 기존 규칙이 더 엄격할 때만 강화한다.
- 현재 코드 분포, 변경된 코드 또는 더 느슨한 설정으로 상한과 고정 정책을 다시 해석해 위반을 합법화하지 않는다.
- 이번 변경이 건드린 모듈과 의존 영향 범위의 기존 위반은 최종 완료를 차단한다.
- 이번 변경과 무관한 영역의 기존 위반은 보고하지만 이번 변경의 완료를 차단하지 않는다.
- 확정 가능한 항목은 기계 판정하고 의도와 의미가 필요한 항목은 근거가 연결된 AI 판정을 사용한다.
- AI `FAIL`은 정확한 코드 위치, 위반 규칙과 반증 조건을 모두 포함한다.
- AI 근거가 부족하거나 판정이 충돌하면 `PASS` 또는 확정 위반으로 정규화하지 않고 `INCONCLUSIVE`로 처리한다.
- 모든 판정은 WP-001에서 고정한 정책, 변경 전 상태와 영향 범위에 묶인다.
- 결과는 `PASS`, `FAIL`, `INCONCLUSIVE`를 구분한다.
- 필수 확정 검사 또는 AI 검사 하나라도 실행하거나 판정하지 못하면 `INCONCLUSIVE`로 완료를 차단한다.
- 판정 전후 대상 제품 소스는 동일하다.

## Scope

- Node/TypeScript 변경의 b-1~b-3, c-1~c-5, d-1~d-3 전체 코드 및 리뷰 품질 판정
- 확정 규칙과 근거 기반 AI 의미 판정의 결합
- 변경 영향 범위의 선행 위반 차단과 무관한 선행 위반 보고
- 고정 정책 및 안전 상한에 묶인 `PASS`, `FAIL`, `INCONCLUSIVE` 최종 verdict

## Non-Goals

- 변경 전 프로젝트 진단, 정책 고정, 재사용 탐색과 제품 코드 쓰기 허용은 이 Ticket의 범위가 아니다.
- 테스트 실행, 변이 검사, 생성 edge case와 side effect 증명은 이 Ticket의 범위가 아니다.
- 판정 결과에 따른 LLM 자동 수정과 재검사 lifecycle은 이 Ticket의 범위가 아니다.
- CI 결과 소비, 배포 승인과 제품 기능 코드 수정은 이 Ticket의 범위가 아니다.
- Node/TypeScript 이외 언어는 이 Ticket의 범위가 아니다.

## Verification

- b-1~b-3, c-1~c-5, d-1~d-3 각각의 명확한 통과 및 위반 사례가 최종 Gate에서 판정되는지 확인한다.
- 안전 기본 상한과 저장소의 더 엄격한 규칙이 각각 적용되고 느슨한 규칙은 기본 상한을 약화하지 않는지 확인한다.
- 변경 영향 범위 안의 선행 위반은 차단되고 무관한 영역의 선행 위반은 보고만 되는지 확인한다.
- AI `FAIL`이 정확한 위치, 규칙, 반증 조건을 포함하며 하나라도 없거나 판정이 충돌할 때 `INCONCLUSIVE`가 되는지 확인한다.
- 필수 확정 검사 또는 AI 검사 능력이 없거나 실행되지 않은 경우 최종 `PASS`가 아닌 `INCONCLUSIVE`가 되는지 확인한다.
- 변경 코드나 느슨한 설정으로 고정 정책과 상한을 다시 해석해 통과하지 못하는지 확인한다.
- 판정 전후 대상 제품 소스가 동일한지 확인한다.
