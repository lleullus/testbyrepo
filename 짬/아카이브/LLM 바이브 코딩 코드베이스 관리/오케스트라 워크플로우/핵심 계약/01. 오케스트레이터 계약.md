> [!summary] 핵심 계약
> 오케스트레이터가 태스크를 MVP 단위로 분할한다. 구현 서브에이전트와 검증 서브에이전트가 한 팀이다. 모든 MVP가 완료된 후 오케스트레이터가 직접 최종 검수한다.

## 3가지 기본 원칙

1. **MVP 단위 분할**: 하나의 MVP는 독립적으로 구현 가능한 최소 단위
2. **순차 실행**: MVP는 순차적으로 실행되며, 이전 MVP 결과가 다음 MVP의 입력이 될 수 있음
3. **분기 판정 권한**: 오케스트레이터만 Step 3 분기 판정을 내릴 수 있음

## 팀 역할

| 역할 | 책임 | 비고 |
|------|------|------|
| **Orchestrator** (본인) | MVP 분할, 작업 할당, 분기 판정, 최종 검수, DDD-Lumin Scope Packet/Lumin evidence 관리 | 항상 한 명 |
| **Implementation Subagent** | MVP 범위 내 구현 → R1-R12 적용 → 완료 보고 | subagent로 호출 |
| **Verification Subagent(s)** | 검증 계획 → 범위/품질/증거 확인 → 통과/수정 | 단일 또는 다중 |

> [!warning] DDD-Lumin 대상 시
> 구현/검증 서브에이전트는 Lumin을 직접 실행하거나, Lumin evidence를 새로 생성/갱신/대체할 수 없다. 필요시 **blocked 보고** 후 오케스트레이터가 처리한다.

## DDD-Lumin Gate

Lumin은 authority가 아니다. DDD가 scope/authority/SSOT/boundary/completion을 결정하고, Lumin은 repo evidence 수집 도구로만 동작한다.

### 분류 체계

| 분류 | 의미 |
|------|------|
| **non_target** | 구현 영향 없음 (문서/주석/포맷). DDD-Lumin evidence 불필요 |
| **minimal** | low-risk, domain behavior 불변, 새 covered artifact/type/helper/shape 없음. 조건부 evidence |
| **strict** | 새 type/helper/shape/DTO/API, file create/move/delete, cross-boundary import, public surface 변경. pre-write required |

> [!note] DDD-Lumin 판정 안전 기준
> 코드 구현, 파일 생성/이동/삭제, 타입/shape/API/helper 변경, import/export 변경, 테스트 harness 변경 중 하나라도 있으면 **우선 DDD-Lumin 대상으로 간주하고 Phase 0 classification을 수행**한다.

## Hard Rules

1. **File Boundary**: `allowed_files` 밖으로 쓰지 않는다. 밖이 필요하면 blocked 보고.
2. **Subagent Session Freshness**: 수정 재할당 시 반드시 새로운 clean subagent session.
3. **Evidence Ownership**: 서브에이전트는 Lumin 실행/evidence 생성 금지. blocked 보고만.
4. **MVP 분할 독점**: MVP 분할/재분할 권한은 Orchestrator만 가짐.
5. **Non-target 경량 패킷**: non_target/minimal MVP도 경량 할당 패킷 필요.
