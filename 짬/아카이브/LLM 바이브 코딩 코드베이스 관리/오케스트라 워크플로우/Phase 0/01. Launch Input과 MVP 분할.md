> [!summary] Phase 0 목적
> 주어진 태스크를 분석하여 독립적으로 구현 가능한 **MVP 단위**로 분할하고, 각 MVP의 DDD-Lumin classification을 수행한다.

## Launch Input (7개 필드)

오케스트레이터는 Phase 0 진입 전에 다음 7개 필드를 확인한다. 대화 컨텍스트에 있는 값은 자동 채우고, 누락된 필드만 사용자에게 질문한다.

| # | 필드 | 설명 |
|---|------|------|
| 1 | **작업 목표 / 요청 내용** | 무엇을 할 것인가 |
| 2 | **구현 모델** | 구현 서브에이전트 모델 지정 |
| 3 | **검증 모델** | 검증 서브에이전트 모델 지정 |
| 4 | **검증 전략** | single / blind double / split-lens / adversarial / quorum |
| 5 | **대상 범위** | 대상 모듈/파일/디렉토리 |
| 6 | **제외 범위** | 건드리지 말아야 할 파일/모듈 |
| 7 | **Phase 0 분석 방식** | `normal` (직접 분석) 또는 `oracle-browser` (Oracle Browser 분석) |

> [!warning] Launch Input 누락 금지
> 7개 필드 중 하나라도 누락되면 Phase 0을 시작할 수 없다. 사용자에게 누락 필드를 요청해야 한다.

## MVP 분할 기준

각 MVP는 다음을 명시한다:

```yaml
MVP1:
  goal: ""
  scope: ""
  files_or_paths: []
  prerequisites: []  # 선행 MVP ID

  ddd:
    packet: minimal | strict
    reason: ""
    covered_artifacts:
      creates_or_changes: true | false
    boundary_impact:
      import_boundary_change: true | false
      public_surface_change: true | false
      state_or_persistence_change: true | false
      domain_behavior_change: true | false

  lumin:
    baseline_full_required: true | false
    prewrite_required: true | false
    postwrite_required: true | false
```

### strict 필수 조건

하나라도 해당하면 `strict`:

- 새 type/helper/shape/schema/DTO/API/event/contract
- covered artifact 생성/변경
- 구현 파일 create/move/rename/delete
- cross-boundary import
- public surface/barrel/re-export
- state/persistence/mutation 의미 변경
- domain behavior 변경
- 새 shared/common/utils/lib/helpers/types home

### minimal 허용 조건 (모두 참)

- low-risk
- no domain behavior change
- no new covered artifact
- no helper/type/shape/schema/DTO/API/event/contract change
- no import or boundary direction change
- no public surface/barrel/re-export change
- no state/persistence/mutation meaning change

> [!tip] 빠른 분류 참조
> - 문서/주석/포맷 → `non_target`
> - 로컬 리팩터 (import/export/domain 불변) → `minimal` 가능
> - 새 helper/type/shape → `strict`, pre-write required
> - 파일 create/move/delete → `strict`, pre-write required
> - public export 변경 → `strict`, pre-write required
> - cross-boundary import → `strict`, pre-write required

## Oracle Browser Role (분석)

Phase 0 분석 방식이 `oracle-browser`로 선택된 경우, 오케스트레이터는 Oracle Browser role에 분석을 의뢰할 수 있다.

- **도구**: `oracle-plus --engine browser --browser-model-strategy ignore --wait`
- **입력**: 태스크 요구사항 + 관련 소스 파일 (압축 가능)
- **출력**: MVP 분할 제안 (advisory, 최종 결정권은 오케스트레이터)

> Oracle Browser의 결과는 **advisory**다. 최종 MVP 분할 결정권은 항상 오케스트레이터에게 있다.
