> [!summary] Phase 2 목적
> 모든 MVP가 통과 상태로 완료된 후, 오케스트레이터가 직접 전체 결과를 통합 검수하고 최종 완료를 선언한다.

## 검수 절차

```text
1. MVPs Done 확인
   → 모든 MVP가 Step 3에서 "통과" 상태인가?
   → blocked/미완료 MVP가 있으면 완료 불가

2. Verification Bundle 최종 검토
   → 각 MVP의 검증 결과 취합
   → accepted findings / rejected findings with reasons
   → ambiguous findings (재확인 필요)

3. DDD-Lumin Evidence 취합
   → Scope Packet 상태 (각 MVP별)
   → Lumin pre-write/post-write 결과
   → 허용 중복 allowlist 기록

4. 누락/모순/범위 이탈 검사
   → 전체 변경이 원래 Phase 0 범위 내인가
   → 의도하지 않은 public surface 변경이 있는가
   → evidence chain이 끊긴 MVP가 있는가

5. 최종 판정
   → 통과: 전체 작업 완료 선언
   → 재할당: 특정 MVP만 재실행 (clean session)
   → 사용자 문의: 해결 불가능한 blocker
```

## 검수 체크리스트

### MVP 수준

- [ ] 모든 MVP가 Step 3 통과 상태
- [ ] 각 MVP의 verification bundle에 accepted/rejected findings 명시
- [ ] DDD-Lumin 대상 MVP의 Scope Packet이 evidence와 일치
- [ ] post-write blocker가 통과 상태로 넘어오지 않았는가
- [ ] R1-R12 Rule Map이 모든 구현 파일에 적용되었는가

### 통합 수준

- [ ] Phase 0 MVP 분할이 실제 변경 범위와 일치
- [ ] 의도하지 않은 경계 위반(module boundary, public surface) 없음
- [ ] 모든 새 covered artifact가 기록됨
- [ ] 허용 중복에 reason/owner/expiry가 기록됨
- [ ] evidence chain이 완전함 (Scope Packet → pre-write → 구현 → post-write → 검증)
