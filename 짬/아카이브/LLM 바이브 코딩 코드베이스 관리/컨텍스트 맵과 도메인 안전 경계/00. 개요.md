> [!summary] 요약
> LLM이 10만 줄 이상 코드베이스에서 "어디를 읽고, 어디를 건드리고, 어디를 건드리면 안 되는지"를 구조적으로 판단할 수 있게 하는 지식 계층이다. 구조 지식(컨텍스트 맵, 모듈 경계)과 행동 제약(도메인 언어, 불변식, 고위험 변경)의 두 축으로 구성된다.

## 이 영역이 담당하는 질문

구조 지식 축:
- 어떤 컨텍스트가 존재하는가
- 컨텍스트 간 의존 방향과 통신 방식은 무엇인가
- 각 레이어의 책임 경계는 어디인가

행동 제약 축:
- 어떤 도메인 규칙을 어겨서는 안 되는가
- 각 불변식은 누가 소유하고, 어떤 테스트가 강제하는가
- 어떤 변경은 자동으로 고위험으로 승격되는가

## 개념 지도

`리포지토리 탐색과 안전 경계.md`가 두 축의 규격을 하나의 파일에 담고 있다. 아래는 해당 파일 내 섹션의 논리적 그룹화이다.

| 논리적 그룹 | 파일 내 섹션 | 답변하는 질문 |
|-------------|-------------|---------------|
| 구조 지식 | 컨텍스트 맵, 모듈 경계 | 어떤 구조가 있고, 어떻게 연결되는가 |
| 행동 제약 | 도메인 언어, 불변식, 고위험 변경, 작업 라우팅 | 어떤 규칙을 지켜야 하고, 어길 때 무엇이 깨지는가 |
| 실행 전략 | 위키 컨텍스트 인덱스 전략 | 구조 지식을 LLM에게 어떻게 전달할 것인가 |
| 설계 판단 | DDD-lite 도메인 안전 계층 | DDD 패턴 중 무엇을 흡수하고, 무엇을 배제할 것인가 |

## 주요 문서

### 구조와 제약의 규격

- [[리포지토리 탐색과 안전 경계]] — 컨텍스트 맵, 모듈 경계, 도메인 언어, 불변식, 고위험 변경, 작업 라우팅의 실질적 규격을 담고 있는 핵심 개념 노트이다. 변경 요청을 받을 때 먼저 읽어야 할 문서이다.

### 실행 전략

- [[옵시디언 위키 컨텍스트 인덱스 전략]] — Obsidian 위키를 LLM의 외부 작업기억으로 운영하는 전략이다. "전체 코드베이스를 기억하게 하는 것"을 포기하고, 기능별로 필요한 구조 정보만 인덱스로 연결하는 방법을 정의한다. Oracle Browser 인사이트와 실패 모드 분석 포함.

### 설계 판단

- [[DDD-lite 도메인 안전 계층|DDD 영감 도메인 안전 계층/DDD-lite 도메인 안전 계층]] — 별도 폴더로 유지하는 이유는 이 문서가 DDD 방법론의 흡수/배제 판단 기준을 담고 있어, 다른 영역에서 독립적으로 참조하기 때문이다. Oracle Browser 3턴 토의의 최종 결론으로, "실행 가능한 결과가 없는 DDD 산출물은 만들지 않는다"는 원칙을 중심으로 한다.

## 새 자료가 들어올 때

- 컨텍스트 맵, 모듈 경계, 의존성 규칙과 관련되면 → 구조 지식
- 도메인 규칙, 불변식, 용어 정의, 변경 위험도와 관련되면 → 행동 제약
- 위키 운영, 인덱싱, 컨텍스트 전달 방법과 관련되면 → 실행 전략
- DDD 패턴 도입/배제 판단과 관련되면 → 설계 판단
- 분류가 불명확하면 → [[리포지토리 탐색과 안전 경계]]의 관련 섹션에 먼저 통합 시도하고, 재사용 가능성이 명확해지면 별도 노트로 분리
