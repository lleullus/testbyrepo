> [!summary] 요약
> 10만 줄 이상 코드베이스를 LLM + 바이브 코딩으로 관리할 때 먼저 갖춰야 할 "검증 가능한 개발 시스템"을 설계하고 문서화하는 프로젝트이다. 핵심 전제는 "LLM이 코드를 바꿔도, 인간이 다 읽지 않고도 틀렸다고 말해주는 장치를 먼저 만들어야 한다"는 것이다. 현재 결론은 **LLM에게 많이 맡기는 용기보다, LLM이 틀릴 수밖에 없다는 전제 위에 세운 검증 시스템**이 먼저라는 것이다.

## 프로젝트 개요

| 항목 | 내용 |
|------|------|
| 상태 | **설계 중** |
| 기술적 복잡도 | **High** |
| 현재 결론 | AGENTS.md + 자동 검증 명령 + 핵심 도메인 테스트 20개를 0순위로 구축 |

프로젝트의 핵심은 LLM 코딩 환경에서 "프롬프트 잘 쓰기"가 아니라 **코드베이스 자체가 LLM에게 길을 알려주고, 잘못 가면 자동으로 멈춰 세우는 구조**를 만드는 것이다.

## 배경

LLM 코딩의 병목은 "코드를 못 짠다"가 아니라 **틀렸을 때 그럴듯하게 틀린다**는 점이다. Anthropic의 Claude Code, OpenAI Codex, GitHub Copilot, Google Jules 등 주요 에이전트 문서가 공통으로 강조하는 것은 "실행 가능한 검증 수단"이다. 테스트, 빌드, 스크린샷 비교처럼 pass/fail을 내는 체크가 있어야 에이전트가 스스로 반복 수정할 수 있다.

10만 줄 이상에서는 인간 리뷰가 모든 의미를 추적할 수 없다. LLM은 더더욱 전체 의미망을 안정적으로 들고 있지 못하다. 결국 테스트, 타입, 린트, 빌드, 스키마 검증, 계약 테스트, 스냅샷 테스트, 마이그레이션 검증이 코드베이스의 면역계가 된다.
