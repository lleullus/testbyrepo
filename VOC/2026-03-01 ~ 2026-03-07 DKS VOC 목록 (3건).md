**DKS 운영(dksmgmt.sec)/Cloud Solution그룹(AI센터)** · [게시됨] · 등록일: 2026-03-04 11:34:16
> 안녕하세요. DKS 운영팀 입니다.
> 문의주신 oom 이슈에 대해 적용해 보실 수 있는 방안 2가지를 설명드리겠습니다.
> 
> 1. **jvm 파라미터 추가**
> oom은 Heap Memory 부족으로 인하여 발생하므로 Heap Memory 영역의 최대 크기를 늘려주어 부족한 Heap Memory를 확보합니다.
> 기본 Heap Memory 크기는 할당된 메모리의 25%가 할당됩니다.
> 그래서 메모리를 6GB로 늘려주어도 1.5GB의 Heap Memory를 가지게 됩니다.
> 기본 25% Heap Memory 크기는 아래와 같이 jvm 파라미터를 사용하여 최대 크기를 늘려줄 수 있습니다.
> 다만, 적용시 어플리케이션의 적정한 크기를 테스트하여 적절하게 조절하시어 적용하시기 바랍니다.
> `-XX:MaxRAMPercentage=75.0`
> 
> 2. **Replica 수 증가**
> Replica 수를 증가시켜 요청에 대한 하나의 Pod가 아닌 다수의 Pod에 부하 분산하여 처리 될 수 있도록 합니다.
> `Deployment > spec.replicas=2`
> Service와 연결된 다수의 Pod는 round robin 방식으로 트래픽이 순차 분산되어 하나의 Pod에서 처리되는 트래픽을 줄여 Memory 사용량을 줄일 수 있습니다.
> 
> 위 내용 참고하시어 문제 해결에 도움되시길 바랍니다.
> 감사합니다.
