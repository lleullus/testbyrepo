## Outcome

현재 소스는 페이지 평가마다 새 128-bit `resume` 값을 만들고, 서버는 알려지지 않은 유효 ID를 신규 세션 요청과 구분하지 않은 채 새 셸을 생성하며, 활성 세션에 같은 ID로 접속하면 기존 연결을 확인 없이 분리한다. 브라우저 복구는 WebSocket `close` 이벤트에만 의존하고 60초 뒤의 수동 경로는 터미널 키보드 Enter만 구독한다. 이 때문에 새로고침의 동일 작업 복귀, 반단절 감지, 모바일 원터치 복구, 중복 탭의 기존 소유자 보호, 만료·종료·확인 불가 상태의 정직한 분기가 성립하지 않는다.

이 Scope는 승인된 Transition Baseline `r2-2026-09-15`의 `BLOCK-001`을 하나의 `HARD_ATOMIC` 제품 경계로 전달한다. 동일 탭의 식별자가 탭 수명 동안 유지되고, 적격 재진입만 같은 서버 세션과 프로세스에 결속되며, 신규 생성은 명시적 신규 요청에서만 일어난다. 서버가 활성 소유자, 복구 가능, 만료·종료, 대상 불명 상태를 구분하여 알려 주고, 활성 소유권을 확인 없이 탈취하지 않는다. 화면 복귀와 liveness 실패는 한 세대의 단일 복구 흐름으로 수렴하며, 60초 자동 시도 뒤 오버레이 탭과 툴바 Enter 모두 복구를 시작하되 PTY 입력을 만들지 않는다. 연결, 인계, 화면 복원, 입력 준비는 각각 사실에 맞는 상태로 드러난다.

포함 범위는 Thesis NB1·NB5·NB6·NB10, I1·I4·I5·I6, SC-1·SC-2·SC-4와 Baseline B1-E1~B1-E6, 적용 G1~G3·G5·G8 및 P1~P7이다. 이를 위해 필요한 최소 서버 세션 상태·소유권 계약과 클라이언트 복구 상태 전이가 포함된다. 현재 9시간 grace, 비차단 PTY drain, foreground resize, 기존 툴바와 정상 실시간 입력은 회귀시키지 않는다.

BLOCK-002의 완결된 Takeover 선택 UI, 한글 IME·포커스·뷰포트·수정자 정책과 BLOCK-003의 최신-tail 절사, 종료 결과 보존, 자원 회수·수용 상한·운영 감독 cutover는 제외한다. 이 Scope는 그 미완성 결과를 성공으로 표시하지 않는다. 운영 포트 7683의 daemon 재시작이나 기존 OMP 세션 종료는 이 Scope의 기본 실행 수단이 아니며, 격리된 실제 ttyd/PTY/브라우저 경계에서 먼저 판독한다.

## Acceptance

### 동일 탭 복귀와 명시적 신규 생성

격리된 실제 ttyd 인스턴스에서 사용자가 셸 작업 표식을 만들고 탭을 새로고침하거나 같은 탭 상태를 복원하면, 탭 식별자와 서버 세션 진단 ID, 루트 PID·시작 시각 및 작업 표식이 유지되고 추가 셸은 생성되지 않는다. 새 독립 탭의 명시적 신규 세션 요청만 별도 셸을 만든다. 저장소가 차단되거나 값이 사라진 경우에는 연속성 불가를 표시하며 기존 세션 복구로 위장하지 않는다. 출력 상한 이내의 지원 셸/OMP 화면이 복귀하고, PID 생존만으로 화면 복원을 선언하지 않는다.

### 상태 진실성과 소유권 보호

서버가 확정한 만료·종료는 그 상태로, 서버 재기동 등으로 원인을 확정할 수 없는 ID는 확인 불가로 표시한다. 사용자가 신규 세션을 명시적으로 선택하기 전 스폰 횟수와 PTY 입력은 모두 0이다. 같은 탭 식별자로 기존 활성 연결과 경쟁하는 두 번째 연결은 기존 입력·resize 소유자를 빼앗지 않고 충돌 상태로 멈춘다. 정상 재진입은 확인된 인계 또는 이전 연결의 분리 뒤에만 이루어지며, 지연된 이전 세대 이벤트가 현재 소유권을 바꾸거나 새 연결을 닫지 않는다.

### 화면 복귀와 반단절 liveness

실제 브라우저에서 2분 비가시 상태 뒤 복귀, 앱 전환에 해당하는 visibility 전이, 제어된 네트워크 단절·회복 및 겉보기 `OPEN` 반단절을 각각 발생시키면, 현재 연결의 liveness 실패가 판독되고 죽은 연결만 단일 복구 경로로 교체된다. 정상 생존 소켓은 복제되지 않는다. visibility, 수동 조작, 타이머와 지연된 토큰·소켓 결과가 겹쳐도 동시에 진행되는 유효 연결 시도와 입력 소유자는 각각 하나이며, 반복 복구 뒤 리스너·소켓·타이머가 누적되지 않는다.

### 날조 입력 없는 수동 복구

60초 자동 시도 한도가 실제로 끝난 뒤 하드웨어 키보드나 새로고침 없이 오버레이 탭과 툴바 Enter 각각이 재연결을 시작한다. 빠른 연속 탭, `pointerdown` 뒤 연결 완료, 오버레이 제거 뒤 `click`, visibility 복귀와 동시 탭을 포함하여 복구 제스처에 귀속되는 PTY 수신은 정확히 0 byte이다. 복구 완료와 입력 준비가 별도로 확인된 뒤 사용자가 새로 수행한 명령 입력만 정확히 한 번 전달된다. 전달 여부가 불명인 이전 입력은 자동 재전송되지 않는다.

### 복원 진실성과 보존

WebSocket 연결, 세션 인계, 백로그 처리, 화면 복원 및 입력 준비가 구분되어 표시된다. 기존 terminal normal/alternate buffer를 지우는 복구 reset이나 복귀를 돕기 위한 Enter·ESC·Ctrl+L 주입이 없다. 재개 불가, 복원 한계, 출력 오버플로 및 종료 결과 보존의 아직 미완성인 경계는 정직하게 남고 신규 깨끗한 셸로 감춰지지 않는다. 기존 9시간 grace, PTY 연속 drain, foreground resize와 정상 연결 상태의 툴바/터미널 입력은 유지된다.

### 통합 대상과 Block 출구

위 관찰은 동일한 소스 리비전에서 빌드한 호환 서버·서빙 번들과 하나의 격리 실행에 귀속되고, storage 네임스페이스, 연결 세대, 스폰 수, PTY 입출력 수 및 세션/PID readback을 함께 남긴다. 시험 연결·타이머·프로세스는 정리되고 운영 7683과 기존 OMP 세션은 변경되지 않는다. 실제 Android Chrome 또는 외부 `/terminal`에서 요구되는 관찰을 수행할 수 없다면 해당 경계를 통과한 것으로 대체하지 않고 정확한 환경 한계를 남긴다. B1-E1~B1-E6의 모든 관찰과 적용 불변식이 같은 안정된 대상에서 성립해야 `BLOCK-001` Exit와 다음 Block의 Safe Continuation이 가능하다.
