## Outcome

선행 이정표인 `BLOCK-001`(세션 연속성 및 생존성 복구)과 `BLOCK-002`(모바일 터치·키보드·모디파이어 및 Takeover 완결)는 각각 독립 검증 및 Coverage를 통과하고 `Status: done`으로 기록되었다. 현재 소스와 빌드 대상(`build/ttyd`, `html/dist/inline.html`)에는 탭 식별자 유지, 명시적 create/resume 구분, 살아 있는 소유자 보호, 세대 격리, 복구 제스처 PTY 0바이트 차단, 터치 본체 입력 포커스/blur 분리, 한글 IME 조합 및 커밋 전용 Enter/ESC, 360/390 CSS px 12개 툴바 요소(34~36 CSS px), 단일 뷰포트 기하 수렴(`interactive-widget=resizes-content`), 명시적 Takeover 및 displaced 상태 처리가 구축되어 있다. 이들 선행 계약과 현재 보호 대상인 운영 포트 7683(PID 202, crontab `@reboot` 기동, live OMP 세션)의 동작은 보존 대상이다.

반면 현재 백엔드 출력 및 프로세스 거버넌스에는 중대한 결손이 남아 있다.
1. `src/protocol.c`에 `SESSION_BACKLOG_MAX (8 * 1024 * 1024)`가 정의되어 있으나, 버퍼 한도 초과 시 최신 8 MiB tail을 순환 보존하는 대신 버퍼 전체를 `free`하고 `needs_redraw = true`로 설정하여 모든 누적 출력을 폐기하는 구형 "전체 폐기 후 redraw" 경로가 잔존한다. 또한 출력 절사 여부를 정직하게 안내하는 링버퍼 거버넌스가 결여되어 있다.
2. `process_exit_cb`는 루트 프로세스 종료 시 즉시 tombstone을 남기고 `session_release`를 호출하여 세션을 파기한다. 단절 중 백그라운드 작업이 종료되었을 때 종료 코드와 최종 8 MiB 출력을 9시간 동안 보존하여 사용자가 재접속 시 열람할 수 있도록 하는 `EXITED_RETAINED` 상태와 1시간 재열람 경로가 구현되어 있지 않다.
3. 프로세스 회수(`pty_kill`)는 `uv_kill(-process->pid, sig)`에 머물러 있어, OMP 하위 작업이나 별도 프로세스 그룹/세션을 형성한 워커 트리 전체를 유한 에스컬레이션(`SIGHUP` → 유한 대기 → `SIGKILL`)으로 확실하게 수거(reap)하지 못하며, 회수 완료 여부를 판정하는 `PURGED` 및 회수 실패 추적 상태인 `TERMINATING` 구분이 부재하다.
4. 호스트 전체 동시 세션 수, 결과 보존 세션 수, 총 메모리 및 프로세스에 대한 수용 상한(Admission Limits)이 없어, 상한 도달 시 신규 생성을 정직하게 거절(503/거절 응답)하지 못하고 기존 9시간 보호 세션의 침묵 퇴출이나 자원 고갈 위험에 노출되어 있다.
5. 현재 운영 서비스는 crontab `@reboot`으로 구동 중이며, 일관된 배포 식별자를 갖춘 `systemd` 사용자 서비스 unit 및 로그 보존·회전을 보장하는 `logrotate` 정책이 설정되어 있지 않다.
6. `CUSTOMIZATION.md`에는 BLOCK-001/002 내용만 반영되어 있고, BLOCK-003의 8 MiB 순환 tail 및 절사 고지, `EXITED_RETAINED` 결과 보존, 워커 회수, 수용 상한, `systemd` 사용자 서비스/`logrotate` 운영 지침과 WSL 전제 등이 누락되어 있다.

이 Scope는 승인된 Transition Baseline `r2-2026-09-15`의 `BLOCK-003` 전체를 하나의 분할 불가능한 `HARD_ATOMIC` 제품 경계로 전달한다.
- 유한 비차단 출력 배출: 단절 및 지연 렌더링 상황에서 10 MiB 대량 출력이 발생해도 파이프 블로킹으로 프로세스가 멈추지 않고 완주하며, 최신 8,388,608 bytes(8 MiB) 순환 tail과 끝 표식을 메모리에 보존하고, 재접속 시 절사 안내를 정직하게 표시한다.
- 포그라운드 TUI 레이아웃 동기화: 동일 크기 재접속, 화면 회전, 키보드/폰트 변경 시 `TIOCGPGRP`로 식별된 포그라운드 프로세스에 SIGWINCH와 갱신된 rows/cols를 전달하여 파괴적 reset(Full RIS)이나 날조 입력(Enter/Ctrl+L) 없이 정상 화면을 동기화한다.
- 종료 결과 보존(`EXITED_RETAINED`): 단절 중 프로세스가 종료되어도 9시간 유예 기간 동안 종료 코드/신호와 최종 8 MiB 출력을 보존하며, 1시간 뒤 재접속 시 추가 셸 생성(0회) 및 PTY 입력 누설(0 byte) 없이 완료 결과를 안전하게 열람한다. 결과 열람은 원래 기한을 갱신하지 않는다.
- 32,400초(9시간) 수명주기 경계: 서버 단일 판정으로 32,400초 만료를 엄격히 집행하며, 만료 시 보존 자료를 완전 회수(`PURGED`)한다.
- 소유 프로세스 트리 유한 회수: 명시적 종료 및 만료 시 세션에 귀속된 모든 워커 프로세스 트리에 유한 에스컬레이션(`SIGHUP` → 대기 → `SIGKILL`)을 적용하여 고아 프로세스 없이 완전 수거하고 `PURGED`로 전환한다. 회수 실패 시 `TERMINATING`으로 진실하게 추적한다.
- 자원 계상 및 정직한 수용 상한: 동시 실행 세션, 결과 보존 세션, 리소스 상한을 계상하고 초과 시 신규 생성을 정직하게 거절하며, 기존 세션 재접속 슬롯과 구분한다.
- 실제 운영 감독 체계 구축: 지정 바이너리, 외부 웹 번들, 세션 런처를 단일 식별자로 감독하는 `systemd` 사용자 서비스와 유한 크기·세대를 관리하는 `logrotate` 설정을 완성하고, `/terminal`, `/terminal/token`, `/terminal/ws`의 정상 양방향 통신을 실제 Android 환경에서 확인한다.
- 운영 문서 최신화: `CUSTOMIZATION.md`에 설치, 기동/중단, 업데이트, 롤백, 수용 거절, 절사 및 결과 보존 의미, WSL 환경 전제, 안전 중단 절차를 실측값과 일치하도록 갱신한다.
- 14대 반례 차단 및 전구간 회귀 검증: Thesis §6의 14개 거짓 성공 반례를 모두 차단하고 SC-1~SC-8 성공 기준과 BLOCK-001/002의 기전달 기능을 동일 최종 실행물에서 회귀 검증한다.

## Acceptance

### 유한 출력 배출과 최신 8 MiB Tail 보존·절사 고지 (B3-E1, SC-6)

단절 및 느린 렌더링/흐름 제어 조건에서 10 MiB 대량 출력을 생성하는 승인된 fixture를 실행한다.
1. 호스트 자식 프로세스가 출력 파이프 백프레셔로 인해 정지하거나 데드락에 빠지지 않고 정상 종료(`exit 0`)까지 지속 배출을 완주한다.
2. 메모리 버퍼는 상한을 초과하여 무한 증식하거나 전체가 버려지지 않고, 최신의 정확한 8,388,608 bytes(8 MiB) tail과 최종 끝 표식을 결속 보존한다.
3. 폐기된 바이트 수와 절사(Truncation) 플래그가 서버 상태에 정확히 기록되며, 클라이언트 재연결 시 화면에 "이전 출력이 절사됨" 안내가 명시적으로 표시된다.
4. 다회 오버플로 및 UTF-8 멀티바이트/ANSI 제어 시퀀스 경계에서도 메모리 누수나 크래시가 없으며 무한 보조 큐가 발생하지 않는다.
5. 출판된 raw tail의 원시 바이트와 클라이언트 표시용 가공이 분리 처리되어 파서 한계로 인한 표시 제한이 있더라도 원시 tail 보존 진실성이 훼손되지 않는다.
Authoritative Readback: 자식 프로세스 exit code(0), PTY 총 배출 바이트(10 MiB 초과), 서버 링버퍼 보존 바이트(8,388,608 bytes), 서버 절사 플래그 및 클라이언트 UI Truncation 고지 확인.

### 포그라운드 TUI 레이아웃 동기화 및 비파괴 재그리기 (B3-E2)

동일 크기 재접속, 브라우저 크기 변경, 화면 회전, 가상 키보드 호출 및 폰트 크기 변경 시:
1. 서버는 `TIOCGPGRP` 시스템 콜로 실제 포그라운드 프로세스 그룹을 식별하고, 해당 포그라운드 프로세스(OMP, vim, less 등)에 SIGWINCH 시그널과 갱신된 rows/cols를 전달한다.
2. 동일 뷰포트 크기로 재접속하는 경우에도 TUI 화면이 깨지거나 공백으로 남지 않고 포그라운드 애플리케이션의 현재 화면이 정상 렌더링된다.
3. xterm normal/alternate screen 버퍼, 커서 위치, application cursor mode가 현재 작업 상태와 정확히 일치한다.
4. 재연결 과정에서 화면을 강제로 백지화하는 파괴적 `terminal.reset()`(Full RIS) 호출이 전면 배제되며, 가짜 Enter, ESC, Ctrl+L 등의 날조 입력을 전혀 주입하지 않는다.
5. 새 xterm 인스턴스로의 페이지 재로드와 기존 xterm 인스턴스의 소켓 재연결이 각각 별도로 검증된다.
Authoritative Readback: `TIOCGPGRP` 반환 PGID, 포그라운드 프로세스 SIGWINCH 수신 로그, xterm 화면 내 TUI 렌더링 무결성 및 날조 입력 0 byte 판독.

### 단절 중 종료 결과 보존과 EXITED_RETAINED 1시간 재열람 (B3-E3, SC-7)

모바일 단절 중 루트 프로세스가 정상(`exit 0`) 또는 비정상(종료 신호 또는 non-zero exit code) 종료되는 경우:
1. 서버는 세션을 즉시 파기하지 않고 `EXITED_RETAINED` 상태로 전이시키며, 종료 상태 코드, 종료 신호, 최종 8 MiB tail, 절사 여부 및 원래의 9시간 만료 기한을 세션 테이블에 유지한다.
2. 루트 프로세스의 exit 통지와 마지막 PTY read 사이의 경합 상황에서도 최종 출력 끝 표식을 유실하지 않고 온전히 버퍼에 수거한다.
3. SC-7에 따라 단절 중 1분 만에 완료된 백그라운드 작업을 실제 1시간 뒤 재접속하여 열람할 때, 세션이 살아 있어 동일한 종료 코드와 최종 실행 결과를 확인할 수 있다.
4. 결과 재열람 과정에서 새 루트 셸 스폰 횟수는 정확히 0회이며, 세션에 전달되는 PTY 입력 바이트는 정확히 0 byte이다.
5. 결과 재열람은 세션의 원래 9시간 기한을 새로 시작(연장)하지 않고 기존 기한을 유지한다.
Authoritative Readback: 세션 진단 상태 `EXITED_RETAINED`, 저장된 exit code/signal, 1시간 경과 후 재접속 화면의 결과 출력 일치, 추가 spawn count = 0, PTY write bytes = 0.

### 32,400초 수명주기 경계와 만료 단일 판정 (B3-E4)

단절 시점부터 시작되는 32,400초(9시간) reconnect grace 기한 관리:
1. 단절 시점부터 32,400초 카운트다운이 정확히 동작하며, 기한 이전 재접속, 기한 경계, 기한 초과 분기가 결정적으로 동작한다.
2. 실패한 재연결 시도, 거절된 contender 충돌 등은 32,400초 만료 기한을 연장하지 않는다.
3. 유효 세션의 적격 Takeover/재연결과 만료 시점이 경합하는 경우 서버의 단일 원자 판정으로 처리되어, 이미 만료된 세션이 활성으로 둔갑하거나 취소된 이전 타이머가 새 소유자를 오종료시키지 않는다.
4. 32,400초가 만료되면 `EXITED_RETAINED` 결과 버퍼와 세션 메타데이터를 포함한 보존 자료가 완전히 메모리에서 제거(`PURGED`)된다.
5. 실제 9시간 장기 관찰 증거와 환경 통제하의 단축/가상 시간 검증 증거가 명확히 구분되어 기록된다.
Authoritative Readback: 서버 단절 타임스탬프, 만료 타이머 등록/취소 로그, 기한 전후 상태 전이, 메모리 버퍼 해제(`PURGED`) 확인.

### 소유 프로세스 트리 유한 회수와 수명주기 진실성 (B3-E5)

명시적 세션 종료 요청 또는 32,400초 유예 만료 발생 시:
1. 서버는 세션 루트 PID뿐만 아니라, 다른 job-control 그룹이나 세션을 형성한 OMP 하위 작업 및 모든 워커 프로세스 트리 전체에 `SIGHUP`을 전송한다.
2. 확정된 유한 대기 시간(grace period) 경과 후에도 종료되지 않고 잔존하는 모든 하위 프로세스에 `SIGKILL`을 에스컬레이션 적용한다.
3. 자식 프로세스 reaping(`waitpid`), PTY master FD, 내부 소켓 핸들, 타이머, 출력 버퍼가 남김없이 회수된 후에만 세션 상태가 `PURGED`로 확정된다.
4. 정해진 회수 관찰 한도 내에 프로세스나 FD가 완전히 정리되지 않는 경우, 상태를 거짓으로 `PURGED` 처리하지 않고 `TERMINATING` 상태와 실패 진단을 명확히 유지한다.
5. 해당 세션과 무관한 호스트의 다른 프로세스, 별도 서비스 및 사용자 작업 파일은 일체 영향을 받지 않고 안전하게 보존된다.
Authoritative Readback: 프로세스 테이블(`/proc`) 스캔을 통한 하위 PGID/워커 전원 소멸 확인, 열린 FD 누수 없음, 서버 상태 `PURGED` 전환 확인.

### 자원 계상과 정직한 수용 상한 방어 (B3-E6)

호스트 보호를 위한 세션 및 자원 상한 거버넌스:
1. 활성 실행 세션 수, detached 세션 수, 결과 보존(`EXITED_RETAINED`) 세션 수 및 총 프로세스/메모리 자원을 정확히 계상한다.
2. 설정된 수용 상한의 직전, 경계, 초과 상태 및 동시 신규 생성 경쟁 상황을 검증한다.
3. 상한 도달 시 신규 세션 생성 요청은 즉시 명시적이고 정직한 수용 거절(HTTP 503 또는 프로토콜 거절 메시지)을 반환하며, 추가 루트 셸을 스폰하거나 백그라운드 보호 세션을 침묵 퇴출(Silent Eviction)하지 않는다.
4. 이미 존재하는 유효 세션에 대한 재접속 및 결과 열람은 새로운 실행 세션 슬롯을 소비하지 않고 정상 처리된다.
5. 거절된 요청의 반복 재시도가 새로운 좀비 세션이나 고아 프로세스를 누적시키지 않으며, 진단 로그 및 생명주기 기록 저장소가 무제한 팽창하지 않는다.
Authoritative Readback: 세션 테이블 카운터, 상한 도달 시 거절 응답 코드, 프로세스 스폰 0회 확인, 기존 9시간 보호 세션의 완전 보존 확인.

### systemd 사용자 서비스 기반 단일 리스너 운영 감독 (B3-E7)

4. 외부 경로에 임의의 신규 인증 장벽을 추가하지 않으며 기존 라우트의 노출 범위를 안전하게 유지한다.
Authoritative Readback: `systemctl --user status` 출력, 프로세스 인자 및 포트 바인딩 확인, Android 실기기에서의 `/terminal` 및 `/terminal/ws` 통신 확인.
