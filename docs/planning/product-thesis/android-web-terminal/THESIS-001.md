## 1. Product Promise (제품 약속)

### 1.1 해결하고자 하는 구체적 결손 (The Concrete Shortfall)

안드로이드 스마트폰의 웹 브라우저를 통해 원격 리눅스 호스트의 개발 셸과 대화형 AI 코딩 에이전트(OMP)를 운영할 때, 기존 순정 웹 터미널은 다음과 같은 실전적 결손으로 인해 실제 사용이 불가능하다:

1. **가상 키보드와 뷰포트의 파괴적 충돌**:
   - 페이지 로드 시 터미널이 입력을 자동 가로채 가상 키보드가 불필요하게 팝업되어 화면 전체를 가린다.
   - 안드로이드 크롬 108+의 기본 뷰포트 정책(`resizes-visual`)으로 인해, 타이핑을 위해 키보드가 올라오면 레이아웃 뷰포트는 축소되지 않은 채 키보드가 하단 터미널 프롬프트와 툴바 위를 덮어버려 자신이 무엇을 입력하고 있는지 볼 수 없는 맹목 상태가 된다.
   - 스마트폰 소프트웨어 키보드에는 터미널 제어에 필수적인 특수 키(TAB, 4방향키, ESC, CTRL 등)가 전무하여 셸 완성, 히스토리 탐색, 작업 취소가 차단된다.
2. **모바일 절전/네트워크 전환 시의 세션 파괴 및 수동 재연결 소프트 락(Soft Lock)**:
   - 스마트폰 화면 잠금, 백그라운드 앱 전환, Wi-Fi ↔ LTE/5G 통신망 전환 등으로 인해 소켓 연결이 빈번히 단절된다.
   - 기존 시스템은 단 30초~수분의 짧은 단절만으로도 셸 프로세스를 강제 종료하여 장시간 실행 중이던 에이전트 작업과 빌드를 파괴한다.
   - 일시적 통신 장애로 60초간 자동 재연결이 실패하여 수동 재연결 오버레이("Press ⏎ to Reconnect")가 뜨면, 화면 터치와 툴바 Enter 입력이 모두 차단되는 소프트 락이 발생하여 브라우저 새로고침(F5) 외에는 복구할 수 없는 반복 마찰을 유발한다.
3. **세션 수명주기 불일치와 새로고침 시 영구 고아 프로세스 적체**:
   - 호스트가 9시간의 Reconnect Grace를 제공하더라도, 프론트엔드가 페이지 새로고침이나 재진입 시 매번 임의의 신규 `resumeId`를 발급하면 이전 세션으로 복귀하지 못하고 무조건 새로운 빈 셸(Fresh Session)이 생성된다.
   - 복구 불가능한 이전 셸 세션들과 OMP 에이전트 하위 프로세스들이 9시간 동안 호스트에 누적되어 메모리와 프로세스 테이블을 고갈시킨다.
4. **단절 상태 PTY 파이프 블로킹 및 대량 출력 시 프로세스 정지**:
   - 모바일이 슬립 상태인 동안 에이전트나 컴파일러가 대량의 출력을 발생시키면 커널 PTY 버퍼(기본 4KB~64KB)가 포화되어 호스트 프로세스 자체가 I/O 블록 상태에 빠져 완주되지 못하고 멈춰 선다.

### 1.2 사용자에게 제공하는 불변의 가치 (Durable Utility)

> **"호스트와 터미널 서비스가 구동 중인 상태에서, 안드로이드 스마트폰 브라우저를 통해 원격 개발 셸과 OMP 에이전트에 접속하여, 화면을 끄거나 통신이 단절되더라도 작업 세션을 9시간 동안 유지하며, 최신 8 MiB 범위 내의 출력을 보존하고, 가상 키보드 가림 없는 단일 행 컴팩트 모바일 툴바로 프롬프트를 눈으로 확인하며 터미널 작업을 매끄럽게 지속한다."**

- **작업 연속성의 온전한 보장**: 화면을 덮고 장시간 이동 후 다시 브라우저 탭을 열어도, 9시간 유예 기간 내라면 실행 중이던 에이전트 대화와 터미널 세션으로 즉시 복귀한다.
- **비차단 백그라운드 완주**: 모바일 화면이 꺼져 있어도 호스트 프로세스는 출력 버퍼 포화로 멈추지 않고 끝까지 작업을 완주하며, 최신 8 MiB 이내의 출력 백로그를 유지한다.
- **모바일 완결적 입력 및 가상 키보드 공존**: 하드웨어 키보드가 없는 스마트폰에서도 단일 행 컴팩트 툴바를 통해 특수 키 입력을 완결하며, 키보드가 팝업되어도 뷰포트가 실제 축소되어 프롬프트와 툴바가 키보드 상단에 온전히 노출된다.

## 2. Core Completion Loop (핵심 인과 루프)

> **[브라우저 접속] $\rightarrow$ [탭 세션 식별 및 단일 소유권 확정] $\rightarrow$ [출력 백로그 리플레이 및 TUI 뷰포트 동기화] $\rightarrow$ [모바일 툴바/IME 입력] $\rightarrow$ [슬립/단절 및 8 MiB 비차단 드레인] $\rightarrow$ [화면 복귀 시 능동/원터치 재연결] $\rightarrow$ [결과 보존 및 거버넌스 종료]**

```text
[Step 1. 브라우저 접속 및 엔드포인트 연결]
  │
  ├─ Tailscale Funnel 엔드포인트(/terminal)를 통해 진입하여 정적 웹 번들 로드 및 웹소켓 세션 채널 개설.
  │  (누락 시: 원격에서 터미널 접속 경로가 차단됨)
  │
[Step 2. 탭 수명주기 결합 세션 식별 및 소유권 조정]
  │
  ├─ sessionStorage 내 resumeId 확인. 최초 진입 시 신규 128-bit ID 발급 및 탭 격리 보존.
  ├─ 호스트 세션 목록 조회:
  │    ├─ 동일 탭 재접속/새로고침: 이전 연결 인계(Takeover), 9시간 타이머 취소.
  │    ├─ 탭 복제(Duplicate Tab)로 인한 충돌: 기존 활성 클라이언트 보호, 신규 탭에 "세션 중복" 안내 및 분기 선택 제공.
  │    └─ 세션 만료/기존 셸 종료: 침묵하는 새 셸 생성을 금지하고 "세션 종료됨" 명시 고지 후 신규 세션 개시.
  │  (누락 시: 새로고침마다 신규 셸이 스폰되어 고아 프로세스가 누적되거나 탭 간 세션 탈취 핑퐁 발생)
  │
[Step 3. 출력 백로그 리플레이 및 포그라운드 TUI 레이아웃 복원]
  │
  ├─ 단절 중 누적된 최신 출력(최대 8 MiB)을 클라이언트로 재생.
  ├─ 현재 모바일 화면 크기를 현재 실행 중인 포그라운드 프로세스 그룹(TIOCGPGRP)에 SIGWINCH로 전달하여 화면 동기화.
  │  (누락 시: TUI 화면이 깨진 채 복구되지 않거나 단절 중 발생한 출력 확인 불가)
  │
[Step 4. 모바일 터치, 툴바, IME 입력 운용]
  │
  ├─ 페이지 로드: xterm 자동 포커스 방지 (가상 키보드 팝업 차단).
  ├─ 터미널 본체 탭: xterm 포커스 획득 및 가상 키보드 호출 (interactive-widget 기반 뷰포트 실제 압축).
  ├─ 툴바 버튼 터치: 타이핑 중에는 키보드를 불필요하게 닫지 않고 특수 키 전달, Shift/CTRL 원샷 모디파이어 제어.
  ├─ 한글 IME 조합: 조합 완료 시에만 단 1회 전송 보장, 조합 중 ESC 누름 시 로컬 조합 취소.
  │  (누락 시: 버튼 누를 때마다 키보드가 닫히고, 프롬프트가 키보드에 가려지며, 한글 입력 시 중복 전송 발생)
  │
[Step 5. 화면 잠금 / 네트워크 단절 및 비차단 완주]
  │
  ├─ 클라이언트 단절 즉시 호스트는 9시간(32,400초) Reconnect Grace 카운트다운 시작.
  ├─ 호스트 프로세스 출력을 8 MiB 유한 링버퍼로 연속 드레인하여 커널 PTY 파이프 블로킹 방지. 8 MiB 초과분은 헤드 드롭.
  │  (누락 시: 모바일 슬립 중 OMP 에이전트의 대용량 코드 생성 작업이 I/O 버퍼 포화로 멈춤)
  │
[Step 6. 화면 복귀 및 무결 재연결 (No Invented Input)]
  │
  ├─ visibilitychange 및 소켓 liveness 점검: 화면 켜짐 감지 즉시 단일 비행(Single-flight) 능동 재연결 시도.
  ├─ 60초 초과로 수동 오버레이 표시 시: 툴바 ↵ 터치 또는 화면 탭으로 즉시 재연결 실행.
  ├─ [중요] 재연결 제스처는 순수 로컬 이벤트로 소비되며, PTY 셸로 어떠한 Enter나 키 입력도 누설 방출되지 않음.
  │  (누락 시: 화면을 켜도 끊긴 채 방치되거나, 재연결을 누른 터치가 에이전트에 원치 않는 명령 제출로 오발송)
  │
[Step 7. 백그라운드 완료 결과 보존 및 거버넌스 회수]
  │
  ├─ 단절 중 루트 프로세스가 정상 완료(exit 0 등)되어도 즉시 세션을 지우지 않고 9시간 동안 종료 코드와 최종 출력을 보존.
  └─ 9시간 유예 만료 또는 명시적 세션 종료 시, 프로세스 그룹 전체를 유한 에스컬레이션 정책으로 확실히 회수.
```

## 3. Necessary Behaviors (필수 동작 요건)

1. **[NB1] 탭 수명주기 결합 세션 영속성 및 정직한 상태 분기 (Session Continuity)**:
   - 클라이언트는 세션 식별자를 탭 수명(`sessionStorage`)과 결합하여 관리해야 하며, 브라우저 새로고침이나 일시적 탭 닫힘 복원 시 동일한 세션 식별자를 재사용하여 기존 세션으로 복귀해야 한다.
   - 복구 대상 세션이 이미 종료되었거나 9시간이 만료된 경우, 사용자를 속이고 조용히 새 셸을 열어주는 침묵 성공을 엄격히 금지하며, **"세션 만료/종료"** 상태를 명확히 고지하고 사용자의 명시적 선택을 통해 신규 세션을 개시해야 한다.
   - *누락 시*: 새로고침 한 번에 작업 문맥이 날아가고 호스트에 불필요한 백그라운드 프로세스가 누적된다.
2. **[NB2] 8 MiB 유한 비차단 출력 보존 및 절사 고지 (Bounded Continuous Drain)**:
   - 클라이언트 접속이 단절되어 있더라도 호스트 프로세스가 표준 출력을 생성할 때 파이프가 차단되지 않고 지속적으로 배출되어야 하며, 최신 8 MiB(`8,388,608 bytes`) 범위의 출력이 메모리에 보존되어야 한다.
   - 8 MiB를 초과하는 대량 출력 발생 시에는 가장 오래된 출력을 버리고 최신 출력을 유지하되, 클라이언트 재연결 시 **"이전 출력이 절사됨"**을 사용자에게 정직하게 표시해야 한다.
   - *누락 시*: 모바일 슬립 중 대용량 빌드나 에이전트 작업이 I/O Deadlock에 빠져 멈추거나, 데이터가 잘렸음에도 완전한 복원인 것처럼 오인하게 만든다.
3. **[NB3] 포그라운드 TUI 레이아웃 즉시 동기화 (Foreground Resize Synchronization)**:
   - 세션 재접속 또는 모바일 화면 회전 시, 단순 셸 리더뿐만 아니라 현재 포그라운드에서 실행 중인 대화형 TUI 프로그램(OMP, vim, less 등)에 `TIOCGPGRP` 기반으로 SIGWINCH 시그널을 전달하여 현재 뷰포트 크기로 화면을 다시 그려야 한다.
   - 동일 크기로 재접속하는 경우에도 TUI 화면이 누락 없이 갱신될 수 있도록 동기화 경로를 보장해야 한다.
   - *누락 시*: 재접속 후 터미널 글자가 겹치거나 깨진 상태로 멈추어 작업을 이어갈 수 없다.
4. **[NB4] 가상 키보드 소유권과 툴바 포커스 분리 (Focus-Keyboard Isolation)**:
   - 페이지 진입 시에는 가상 키보드가 열리지 않아야 한다.
   - 사용자가 텍스트 입력을 위해 터미널 본체를 직접 터치했을 때만 가상 키보드가 팝업되어야 한다.
   - 타이핑 도중 툴바의 특수 키(TAB, 방향키 등)를 터치할 때는 사용자의 입력 흐름을 깨지 않도록 키보드를 강제로 닫지 않고 유지해야 하며, 툴바 터치로 인해 입력 포커스가 엉뚱한 곳으로 튀지 않아야 한다.
   - *누락 시*: 방향키나 TAB을 누를 때마다 화면 절반을 가리는 가상 키보드가 덜컹거리며 닫히고 다시 열리는 극심한 마찰이 발생한다.
5. **[NB5] 소프트 락 없는 원터치 수동 재연결 (Accessible Manual Reconnect)**:
   - 자동 재연결 시도가 만료되어 "Press ⏎ to Reconnect" 화면이 표시된 상태에서도, 툴바의 Enter 버튼이나 화면 오버레이 터치 입력을 차단하지 않고 정상 수신하여 즉시 재연결 루틴을 시작해야 한다.
   - *누락 시*: 하드웨어 키보드가 없는 모바일 환경에서 화면이 먹통이 되어 강제로 브라우저 새로고침을 할 수밖에 없다.
6. **[NB6] 소켓 반단절 감지 및 화면 활성화 능동 재연결 (Liveness-aware Auto-reconnect)**:
   - 스마트폰 잠금 해제나 앱 복귀(`visibilitychange`)를 감지하여 즉시 재연결을 시도해야 한다.
   - 소켓 상태가 겉으로는 `OPEN`으로 보이지만 실제 데이터가 흐르지 않는 모바일 특유의 반단절(Half-open) 상태를 핑/퐁 하트비트 주기를 통해 감지하고 즉시 연결 복구 절차로 진입해야 한다.
   - *누락 시*: 화면을 켠 후에도 소켓이 먹통인 채 방치되어 사용자가 멍하니 대기하게 된다.
7. **[NB7] 원샷 모디파이어 상태의 결정적 해제 (Deterministic Modifier Cleanup)**:
   - `Shift`와 `CTRL`은 다음 1회 입력에만 영향을 주는 상호 배타적 원샷 토글이어야 한다.
   - 모디파이어를 켠 상태에서 `ESC`를 누르면 Shift와 CTRL이 모두 즉시 해제되어야 한다.
   - 텍스트 붙여넣기(Paste), 한글 조합 시작, 특수 제어 이벤트 발생 시 pending된 모디파이어는 즉시 안전하게 초기화되어야 한다.
   - *누락 시*: 취소 의도로 ESC를 누른 뒤 일반 알파벳(예: `c`)을 터치했을 때 의도치 않게 강제 종료 시그널(Ctrl+C)이 전송되어 실행 중인 작업이 날아간다.
8. **[NB8] 안드로이드 가상 키보드 반응형 뷰포트 압축 (Keyboard Content Resizing)**:
   - `interactive-widget=resizes-content` 메타 속성을 적용하여, Android Chrome 108+ 환경에서 가상 키보드가 활성화될 때 레이아웃 뷰포트가 실제 축소되어 터미널 줄 수가 재계산되고 툴바가 키보드 바로 위에 안착해야 한다.
   - 390px 미만 소형 화면이나 노치/곡면 Safe Area 환경에서도 툴바 버튼이 잘리지 않도록 안전한 최소 너비 및 패딩 규칙을 제공해야 한다.
   - *누락 시*: 키보드가 터미널 하단 프롬프트와 툴바를 완전히 덮어버려 입력 중인 내용을 확인할 수 없다.
9. **[NB9] 인위적 화면 리셋 가드레일 전면 금지 (No Destructive Reset Guardrails)**:
   - 재연결 시 화면을 깨끗하게 비우는 강제 `terminal.reset()`(Full RIS) 호출을 전면 금지하며, xterm alternate screen 버퍼와 상태를 있는 그대로 보존해야 한다.
   - *누락 시*: 세션 재개 시 화면이 백지로 지워지거나 TUI 편집기 상태가 파괴된다.
10. **[NB10] 입력 의도 보존 및 날조 입력 방지 (Input Intent Preservation)**:
    - 모든 사용자 액션은 로컬 인터페이스 제어, 연결 복구 제스처, IME 조합 텍스트, 터미널 명령 입력으로 명확히 구분되어야 한다.
    - 재연결을 위해 수행한 화면 터치나 툴바 Enter 조작은 **순수하게 연결 재개 이벤트로만 소비되어야 하며, PTY 터미널로 어떠한 개행 문자나 제어 바이트도 누설 방출(Invented Input)되어서는 안 된다.**
    - 네트워크 단절 중 발생하여 전달 여부가 불확실한 이전 입력은 클라이언트가 임의로 자동 재전송하지 않아야 한다.
    - *누락 시*: 끊긴 화면을 살리려고 탭한 행위가 에이전트에게 그대로 Enter로 입력되어 잘못된 프롬프트가 실행되거나 파괴적 작업이 무단 승인된다.
11. **[NB11] 프로세스 수명주기 거버넌스 및 백그라운드 결과 보존 (Governed Lifecycle & Result Readback)**:
    - 모바일 단절 중 호스트의 루트 프로세스가 정상 또는 비정상 종료되더라도, 9시간 유예 기간 동안은 **종료 상태 코드와 최종 8 MiB 출력을 보존**하여 사용자가 복귀 시 완료 결과를 확인할 수 있어야 한다.
    - 9시간 유예 만료 또는 명시적 세션 종료 시에는 프로세스 그룹 전체를 유한 에스컬레이션 정책(`SIGHUP` $\rightarrow$ 대기 $\rightarrow$ `SIGKILL`)으로 확실히 수거(Reap)하여 고아 프로세스를 남기지 않아야 한다.
    - 호스트 전체 동시 세션 수 및 총 리소스 사용량에 대한 수용 상한(Admission Limits)을 두어 서비스 안정성을 방어해야 한다.
    - *누락 시*: 백그라운드 작업이 끝났는데 결과를 볼 수 없거나, 반대로 만료된 세션이 좀비/고아 프로세스로 남아 서버를 다운시킨다.

## 4. Behavior and UI Policy (동작 및 인터랙션 정책)

### 4.1 390px 단일 행 컴팩트 하단 툴바 레이아웃 규격

- **화면 제약 및 너비 기준**: 390 CSS px(현대 표준 세로 폭)에서 가로 스크롤 없이 단일 행(12개 요소)으로 모든 특수 조작을 수용한다.
- **버튼별 규격 및 배열 (좌측 $\rightarrow$ 우측)**:
  1. `TAB` (33px): 탭 완성. Shift 활성 시 `Shift+Tab` (`\x1b[Z`) 전송.
  2. `Shift` (30px): 탭 및 방향키 전용 원샷 모디파이어 토글.
  3. `◀` / `▲` / `▼` / `▶` (각 29px): 커서 이동 및 셸 히스토리 탐색 (xterm `applicationCursorKeysMode` 자동 반영).
  4. `↵` (Enter, 32px): 명령 실행 및 모디파이어 해제. 수동 재연결 화면에서는 오직 재연결 명령으로만 소비됨.
  5. `ESC` (33px): `\x1b` 전송. Shift 및 CTRL armed 상태 모두 즉시 해제.
  6. `CTRL` (40px): 다음 1회 입력에 대한 Ctrl 조합 생성 원샷 토글.
  7. `A-` / `A+` (각 29px): 폰트 크기 동적 조절 (8px ~ 32px).
  8. `⛶` (29px): 브라우저 전체화면 전환.
- **물리적 여백 및 터치 타깃 방어**:
  - 버튼 높이는 **34~36px**로 확대하여 세로 터치 안정성을 확보한다.
  - `touch-action: manipulation`을 강제하여 모바일 브라우저의 더블탭 확대 지연(300ms)을 제거한다.
  - 360px 이하 초소형 기기나 Safe Area가 넓은 기기에서는 버튼 패딩을 축소하거나 최소 폰트 크기를 유지하며 버튼이 화면 밖으로 잘리지 않도록 flex 축소 규칙을 적용한다.

### 4.2 터치, 포커스 및 가상 키보드 상호작용 규칙

| 사용자 동작 | 터미널 입력 포커스 | 가상 키보드 상태 | 활성 모디파이어 (Shift/CTRL) |
| :--- | :--- | :--- | :--- |
| **페이지 진입** | 해제 (Blur) | 닫힘 유지 | 모두 해제 |
| **터미널 본체 직접 탭** | 획득 (Focus) | **열림 (팝업)** | Shift 해제, CTRL 유지 |
| **타이핑 중 툴바 버튼 터치** | 포커스 보존/유지 | **열림 유지 (닫힘 방지)** | 해당 버튼 동작 수행 후 모디파이어 전이 |
| **비입력 상태 툴바 터치** | 해제 (Blur) | 닫힘 유지 | 해당 버튼 동작 수행 |
| **가상 키보드로 문자 입력** | 유지 (Focus) | 열림 유지 | CTRL 1회 적용 후 즉시 자동 해제 |
| **수동 재연결 오버레이 탭** | 해제 (Blur) | 닫힘 유지 | 모두 해제 후 재연결 시퀀스 실행 (PTY 누설 없음) |

### 4.3 모바일 한글 IME 조합 및 특수 입력 정책

- **조합 완료 보장**: 한글 입력 중 발생하는 `compositionstart`, `compositionupdate`, `compositionend` 이벤트를 정상 추적하여, 글자 조합이 완료된 시점에만 PTY로 1회 전송되어야 한다. 조합 도중 문자가 중복 전송되거나 깨지지 않아야 한다.
- **조합 중 Enter / ESC**: 한글 글자를 조합하는 도중 누른 Enter는 글자 조합을 확정(Commit)하는 용도로만 소비되어야 하며, 터미널 명령을 즉시 제출(Submit)해서는 안 된다. 조합 중 누른 ESC는 진행 중인 조합 텍스트를 로컬에서 취소한다.
- **텍스트 붙여넣기(Paste)**: 붙여넣은 텍스트는 1글자짜리라도 CTRL 모디파이어의 대상으로 삼지 않고 순수 텍스트로 처리하며, 붙여넣기 직전 무장된 모디파이어는 모두 안전하게 해제한다.

### 4.4 탭 복제(Duplicate Tab) 및 다중 소유권 조정 정책

- **단일 소유자 원칙**: 하나의 셸 세션은 동일 시점에 오직 하나의 활성 클라이언트 탭에 의해서만 조작되어야 한다.
- **탭 복제 감지**: 사용자가 브라우저에서 '탭 복제(Duplicate Tab)'를 실행하여 동일한 `sessionStorage`를 가진 두 번째 탭이 열릴 경우:
  - 기존 탭이 여전히 활성 통신 중이라면, 새 탭이 기존 탭을 무단으로 강제 탈취(Steal)하지 않는다.
  - 새 탭 화면에는 **"세션이 이미 다른 탭에서 사용 중입니다"** 안내를 표시하고, 사용자가 명시적으로 **[이 화면으로 가져오기 (Take Over)]**를 누를 때만 기존 탭을 분리하고 연결을 인계한다.
  - 인계당한 기존 탭은 **"세션이 다른 탭으로 이동되었습니다"** 상태를 표시하고 자동 재연결 시도를 영구 중단하여 탭 간 핑퐁 경쟁을 원천 차단한다.

### 4.5 세션 수명주기 상태 전이 규격

```text
[INIT] ──(연결 및 신규 생성)──> [ACTIVE] ──(소켓 단절)──> [DETACHED_GRACE] ──(9시간 만료)──> [TERMINATING]
                                   │                               │                               │
                                   │(동일 탭 인계 Takeover)          │(9시간 내 재연결)             ▼
                                   ▼                               ▼                        [PURGED]
                              [REATTACHED] <───────────────────────┘
                                   │
                                   └──> [ACTIVE] (백로그 재생 + SIGWINCH)
                                   
[DETACHED_GRACE] ──(루트 프로세스 종료)──> [EXITED_RETAINED] ──(재연결)──> [ACTIVE (종료 결과 표시)]
```

- **ACTIVE**: 정상 연결, 실시간 입출력 처리.
- **DETACHED_GRACE**: 단절 후 9시간 카운트다운 가동, 프로세스는 계속 실행되며 출력은 8 MiB 링버퍼에 비차단 누적.
- **REATTACHED**: 재연결 성공 시 9시간 타이머 취소, 8 MiB 백로그 재생, 포그라운드 TUI 레이아웃 동기화.
- **EXITED_RETAINED**: 단절 중 프로세스가 종료되었으나 9시간 이내인 상태. 종료 코드와 최종 출력을 유지하여 복귀한 사용자에게 결과를 열람시킴.
- **TERMINATING**: 9시간 만료 또는 명시적 종료. 프로세스 그룹 에스컬레이션 회수 진행.
- **PURGED**: 프로세스 수거 완료, 세션 테이블 및 메모리 버퍼 완전 반환.

## 5. Truth and Causal Invariants (진실 및 인과 불변식)

1. **[I1] 세션 단일 귀속 불변식 (Session Identity Invariant)**:
   - 동일 탭에서 새로고침 또는 재방문 시, 9시간 유예가 끝나지 않은 세션은 결코 신규 셸로 분기되지 않고 단 하나의 살아있는 세션으로 100% 인계 복귀되어야 한다.
2. **[I2] 유한 비차단 드레인 불변식 (Bounded Continuous Drain Invariant)**:
   - 클라이언트 단절 상태에서 출력이 아무리 쏟아져도 호스트 프로세스는 파이프 블로킹으로 멈추지 않고 완주되어야 하며, 세션당 보존되는 출력 메모리는 정확히 8 MiB(`8,388,608 bytes`)를 초과하지 않는다. 초과분 발생 시 절사 사실이 클라이언트에 기록되어야 한다.
3. **[I3] 모디파이어 배타·정리 불변식 (Modifier Clean Invariant)**:
   - Shift와 CTRL은 동시에 켜질 수 없으며, 1회 키 전송, ESC 취소, 붙여넣기, IME 조합 시작 시 상태 머신은 반드시 중립(`false`)으로 환원되어야 한다.
4. **[I4] 소프트 락 배제 불변식 (No Soft-Lock Invariant)**:
   - 네트워크 단절 및 오류 오버레이 노출 상태에서도 사용자의 재연결 관련 입력 접점(Enter 버튼, 화면 탭)은 결코 비활성화되거나 차단되지 않아야 한다.
5. **[I5] 복원 진실성 불변식 (Restoration Truth Invariant)**:
   - 하위 계층의 이벤트(웹소켓 연결 성공)가 상위 계층의 성공(화면 복원, 입력 준비 완료, 작업 성공)을 자동으로 증명하지 않는다. 소켓 연결, 세션 인계, 화면 재렌더링, 입력 가능 상태는 각각 독립적으로 성립하고 검증되어야 한다.
6. **[I6] 날조 입력 배제 불변식 (No Invented Input Invariant)**:
   - 재연결 제스처(탭, ↵ 터치)나 브라우저 수명주기 이벤트는 어떠한 경우에도 PTY 터미널 입력으로 날조되어 방출되지 않는다. 연결 재시도는 이전 명령어나 프롬프트의 재전송을 수반하지 않는다.
7. **[I7] 책임 있는 수명주기 불변식 (Accounted Lifecycle Invariant)**:
   - 호스트의 모든 세션은 활성(ACTIVE), 결과 보존(EXITED_RETAINED), 회수 중(TERMINATING) 상태 중 하나로 명확히 추적 관리되며, 회수 확인 없는 단순 시그널 발송만으로 자원 정리를 완료된 것으로 간주하지 않는다.

## 6. Plausible False Successes & Counterexamples (그럴듯한 거짓 성공 및 반례 검증)

| 겉보기 성공 (Plausible False Success) | 은폐된 실제 결손 (Hidden Failure) | 필수 반증 및 진실 판독 기준 (Readback) |
| :--- | :--- | :--- |
| **"새로고침 후 터미널이 깨끗하게 떴다"** | 이전 세션을 복원한 것이 아니라 새 셸을 연 것이며, 이전 작업은 고아로 방치됨. | 동일 세션 ID 유지 확인 및 이전 작업 화면/히스토리 복원 입증. |
| **"동일한 PID가 유지되고 있다"** | 프로세스는 살아있으나 클라이언트 xterm 화면 버퍼가 완전히 깨지거나 비어있음. | 프로세스 PID 생존과 함께 클라이언트 화면 TUI 레이아웃 및 텍스트 복원 입증. |
| **"8 MiB 초과 출력을 뿜고 프로세스가 끝났다"** | 프로세스는 끝났으나 출력 백로그 초과분이 통째로 날아가 최종 결과 확인 불가. | 최신 8 MiB 백로그 유지 및 화면에 출력 절사(Truncation) 안내 표기 확인. |
| **"WebSocket OPEN 상태가 되었다"** | 소켓만 열렸을 뿐 세션 인계 핸드셰이크가 완료되지 않아 입력을 못 받음. | 소켓 연결과 별개로 세션 인계 완료 및 입력 가능 상태(Input Ready) 표기 확인. |
| **"화면을 켰을 때 visibility 리스너가 돌았다"** | 모바일 네트워크 반단절(Half-open) 상태라 실제 패킷 송수신이 불가능함. | 핑/퐁 Liveness 검증 완료 및 실제 데이터 송수신 재개 확인. |
| **"재연결 탭 한 번으로 연결이 복구되었다"** | 탭 제스처가 PTY로 그대로 흘러들어가 OMP 에이전트에 원치 않는 Enter가 제출됨. | 재연결 수행 시 PTY로 방출된 바이트 수가 정확히 0바이트임을 검증. |
| **"동일 세션에 두 번째 탭이 바로 붙었다"** | 두 탭이 세션 소유권을 놓고 무한 핑퐁 탈취전을 벌여 화면이 깜빡임. | 중복 탭 진입 시 기존 탭 보호 및 명시적 Takeover 확인 절차 작동 검증. |
| **"재연결 시 resize 시스템 콜이 성공했다"** | 터미널 크기가 이전과 동일하여 포그라운드 TUI가 화면을 다시 그리지 않고 깨져있음. | 시스템 콜 성공 여부가 아닌 포그라운드 TUI 애플리케이션의 실제 재렌더링 화면 검증. |
| **"가상 키보드가 정상적으로 닫혔다"** | 키보드가 닫히면서 작성 중이던 한글 조합 글자가 깨지거나 누락됨. | 한글 조합 완료(Commit) 텍스트가 정확히 1회 터미널에 반영되었는지 검증. |
| **"CTRL 버튼이 영문 글자와 잘 동작했다"** | 텍스트 붙여넣기나 특수 문자 입력 후 CTRL armed 상태가 남아 다음 키를 망침. | 붙여넣기 및 취소 후 일반 문자 입력 시 SIGINT 미발생 검증. |
| **"9시간 만료 후 로그에 kill이 찍혔다"** | 서브프로세스나 워커들이 수거되지 않고 백그라운드에 남아있음. | 프로세스 테이블 검사를 통해 세션 하위 프로세스 그룹의 완전 소멸 검증. |
| **"단일 행 툴바가 390px 화면에 딱 맞게 들어갔다"** | Safe Area가 있는 노치 기기나 360px 기기에서는 양 끝 버튼이 잘려 누를 수 없음. | 360px 및 노치 디스플레이 환경에서 12개 버튼의 온전한 터치 가능성 검증. |
| **"Tailscale HTTPS로 페이지가 잘 열린다"** | 정적 페이지만 로드되고 WebSocket(/terminal/ws) 경로 프록시 설정이 어긋나 연결 실패가 반복됨. | 정적 페이지 로드와 별개로 /terminal/ws 웹소켓의 정상 양방향 통신 검증. |
| **"단절 중 에이전트 프로세스가 살아있다"** | 에이전트가 정상 작업 중인 것이 아니라 사용자 입력을 기다리며 대기 중인 상태임. | 프로세스 생존 여부와 에이전트의 실제 작업 진행/대기 상태를 분리 인지. |

## 7. Success Criteria & Observable Readback (성공 기준 및 관찰 검증)

| 성공 기준 | 검증 상황 및 입력 | 기대되는 관찰 가능한 결과 | 권위 있는 판독처 (Authoritative Readback) |
| :--- | :--- | :--- | :--- |
| **SC-1 (새로고침 세션 복귀)** | 모바일 접속 후 작업 중 탭 새로고침 실행 | 신규 셸이 아닌 기존 세션으로 100% 인계 복귀하며 이전 화면 버퍼 복원 | 브라우저 `sessionStorage` ID 유지 및 백엔드 `attached to existing process` 로그 |
| **SC-2 (날조 없는 원터치 재연결)** | 수동 재연결 오버레이 표시 시 ↵ 터치 또는 화면 탭 | 셸/에이전트에 Enter 입력 누설 없이 즉시 소켓 재연결 및 입력 준비 완료 | PTY 수신 바이트(0 byte) 및 웹소켓 상태 `ACTIVE` 전환 |
| **SC-3 (ESC 모디파이어 완결)** | 툴바 CTRL 터치 후 ESC 터치 취소, 이후 'c' 입력 | 프로세스 종료(SIGINT) 없이 일반 문자 'c'가 입력창에 타이핑됨 | 터미널 입력 데이터 모니터링 |
| **SC-4 (화면 복귀 자동 Liveness 연결)** | 화면 끄고 2분 대기 후 스마트폰 켜기 | 수동 조작 없이 포그라운드 복귀 감지만으로 웹소켓 정상 통신 재개 | `visibilitychange` 이벤트 및 핑/퐁 하트비트 정상 수신 로그 |
| **SC-5 (키보드 뷰포트 압축)** | 안드로이드에서 화면 탭하여 가상 키보드 호출 | 뷰포트가 실제 축소되어 프롬프트 라인과 하단 툴바가 키보드 상단에 노출됨 | 레이아웃 뷰포트 높이 축소 및 xterm 렌더링 영역 일치 확인 |
| **SC-6 (슬립 중 비차단 완주 및 절사 고지)** | 모바일 슬립 중 10 MiB 대량 출력 발생 | 파이프 블로킹 없이 프로세스 완주(`exit 0`), 재접속 시 최신 출력 및 절사 안내 표기 | 프로세스 정상 종료 코드 및 터미널 화면 내 Truncation 플래그 |
| **SC-7 (단절 중 완료 결과 보존)** | 모바일 단절 중 백그라운드 작업이 1분 만에 완료됨 | 1시간 뒤 재접속 시 세션이 사라지지 않고 최종 종료 코드 및 결과 출력 열람 가능 | 세션 상태 `EXITED_RETAINED` 및 최종 출력 버퍼 렌더링 |
| **SC-8 (탭 복제 소유권 충돌 방어)** | 동일 세션 ID를 가진 탭을 브라우저에서 복제 | 기존 탭 연결 유지, 복제된 탭에 명시적 Takeover 확인 UI 노출 | 양 탭의 WebSocket 연결 상태 및 인계 이벤트 로그 |
