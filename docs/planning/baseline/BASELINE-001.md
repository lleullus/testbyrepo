- **P5 — 실행물과 상태 전환 결합:** 새 프런트와 서버의 세션/소유권/결과 상태 계약을 호환 상태로 함께 준비한 뒤 해당 기능을 활성화한다. 실제 서빙 방식이 외부 `index.html`인지 내장 번들인지 관찰하고 다른 파일을 고쳤다는 이유로 배포 성공을 선언하지 않는다. 실행 중인 구 프로세스가 디스크상의 새 바이너리로 바뀌었다고 가정하지 않는다. 기존 세션을 이관할 수 없는 교체는 승인된 유지보수 경계를 필요로 한다.
- **P6 — 결과와 미확정 효과의 인계:** Block 경계에서 실제 증거 경로·해시·환경·세션 진단 ID·연결 세대·PID/시작 시각·출력 위치/절사·기한·회수 상태·운영 감독 소유자를 인계한다. 입력 전달 여부 불명, 미완료 reap, 실행 중 배포/재시작 또는 소유자 불명 작업을 “문제 없음”으로 바꾸지 않는다. 새 실행물에 영향을 받는 선행 SC를 재검증하고 한정된 표본/모의 시험과 실기기·장시간 실측을 구별한다.
- **P7 — 매개변수와 운영 전제의 출처:** `32,400초`, `8,388,608 bytes`, 자동 재시도 `60초`, 기준 폭 `390/360 CSS px`, 버튼 높이 `34~36 CSS px`, 폰트 `8~32px`는 결속된 값이다. heartbeat 주기/응답 제한시간/시도 제한, 복원 대기 한도, SIGHUP 후 대기와 회수 관찰 한도, 세션/총 메모리·프로세스 상한, 로그 크기·세대·보존 기간은 관련 Scope 진입 시 유한한 실제 값과 설정 출처·검증 경계를 확정한다. 값을 정하지 않은 “적절한 제한”으로 Exit를 선언하지 않는다. WSL의 사용자 관리자·로그 회전 실행 주체·로그아웃 후 감독 전제는 실측하며, linger·시스템 설정·권한 상승이 필요하면 현재 운영자 권한을 별도로 확인한다.

## Transition Blocks

아래 Block은 큰 전환 이정표와 측정 조건이다. 미래 Scope, 구현 패치 순서 또는 자동 실행 작업을 사전 승인하지 않는다. Entry/Exit의 판독은 실제로 접근 가능한 환경에서 현재 Scope 책임자와 지정 검증자가 수행하고, 수행하지 못한 항목은 미관찰로 기록한다.

### Block `BLOCK-001` — 프런트엔드 세션 연속성·생존성 복구·소프트 락 제거

- **ID:** `BLOCK-001`
- **Name:** 동일 세션으로 돌아오고 복구 조작이 명령 입력이 되지 않는 재연결 경계 확립
- **Meaning Contribution:** D-01·D-02·D-04를 해소하여 R1의 재진입/상태 분기와 R2를 성립시킨다. NB1·NB5·NB6·NB10의 핵심 인과 루프를 실제 서버와 연결한다. 출력 오버플로·종료 결과 장기 보존의 완료는 BLOCK-003에 남기되, 이를 미구현 상태에서 성공으로 표시하지 않는다.
- **Order / Dependencies:** 첫 전환 이정표이다. 현행 서버의 실제 세션 조회·인계·새 세션 생성 조건을 전제 검사하며 필요하면 이 Block에서 최소 서버 계약도 변경한다. 유효 ID가 없거나 대상이 사라진 경우 서버가 자동 스폰하는데 프런트 문구만 바꾸는 상태는 허용하지 않는다. 활성 복제 탭을 서버가 먼저 차단하는 최소 소유권 보호는 이 Block의 경계이고, 명시적 Takeover의 완결된 모바일 UI는 BLOCK-002의 경계이다.
- **Entry:** 현재 Scope 책임자가 P1의 소스·실행물·작업 트리 및 D-01·D-02·D-04의 재현 여부를 읽고 실제 원인/이미 반영된 수정을 구분한다. 운영자는 기존 세션과 분리 기한·사용 중 OMP 작업을 식별한다. 검증자는 별도 fixture와 실기기 접근, 실제 `/terminal` 경로의 기동 방식, 해당 변경의 현재 실행 권한을 확인한다.
  - 새 세션 요청과 재개 요청의 서버 구분, 기존 소유자/연결 세대 판독, grace 설정, 토큰·WebSocket 경로와 오류 응답, 백그라운드 후 남은 소켓 상태를 확인한다. 장기 grace와 foreground 신호가 “선행 확인됨”이라는 보고만으로 검사를 생략하지 않는다.
  - 저장소 접근 거부/값 소실, 재개 대상 없음, 서버 재기동 후 알 수 없는 ID, 살아 있는 기존 소유자, 지연된 토큰/연결 결과의 분기를 승인된 Scope에 결속한다. heartbeat/응답 제한·복귀 시도 한도와 새 연결 활성화 조건을 P7에 따라 확정한다. 운영 교체가 필요하면 기존 세션에 대한 영향을 먼저 승인받는다.
- **Exit:** 안정된 동일 대상에서 다음 조건이 모두 관찰된다.
  - **B1-E1:** 적격 세션의 새로고침과 저장소가 유지된 탭 복원에서 같은 ID·서버 세션·PID/시작 시각·작업 문맥으로 복귀하고 추가 셸이 생성되지 않는다. 새 독립 탭은 별개 신규 요청이다. 저장소 소실/차단 시 연속성 불가를 명시하고 복구로 위장하지 않는다. 운영 데이터가 아닌 fixture로 스폰 전후 개수와 작업 표식을 판독한다. SC-1의 세션 근거와 출력 상한 이내 지원 화면 복원을 함께 확인한다.
  - **B1-E2:** 서버가 확정한 만료/종료는 그 상태로, 원인 불명은 확인 불가로 표시하며 사용자 신규 생성 선택 전에는 스폰이 `0회`이다. 입력 가능 상태가 확정되지 않은 화면에서 명령 입력을 흘리지 않는다. 같은 저장값의 경쟁 연결은 기존 입력/resize 소유자를 빼앗지 않고 충돌 상태로 멈춘다. 정상 재진입은 확인된 handoff 또는 구 연결 분리 뒤 복귀하며 복제 탭을 임의로 새로고침이라 간주하지 않는다.
  - **B1-E3:** SC-4의 실제 2분 화면 잠금/복귀, 앱 전환, 제어된 통신망 변경과 소켓이 `OPEN`으로 남은 반단절에서 liveness 실패/회복을 판독한다. 정상 생존 소켓을 불필요하게 복제하지 않고 죽은 연결만 단일 복구 경로로 교체한다. visibility·수동 탭·타이머·지연 응답이 겹쳐도 동시에 유효한 연결 시도/소유자는 하나이며 구 세대 close가 새 연결을 끊지 않는다.
  - **B1-E4:** 60초 자동 시도 소진 뒤 오버레이 탭과 툴바 ↵ 각각이 하드웨어 키보드나 새로고침 없이 복구를 시작한다. 빠른 연속 탭, pointerdown 뒤 연결 완료, 오버레이 제거 뒤 click, 화면 복귀와 동시 탭을 포함하여 복구에 귀속되는 PTY 수신은 정확히 `0 byte`이다. 복귀 완료 후 별도의 실제 명령 입력만 1회 전달된다. SC-2는 바이트 판독과 입력 준비 상태를 함께 증거로 갖는다.
  - **B1-E5:** 연결 직전 입력, 전달 여부 불명 입력, 서버가 먼저 종료된 입력을 자동 재전송하지 않는다. 현재 연결/인계/복원/입력 준비와 불가 상태를 구별해 표시한다. 기존 터미널의 alternate/normal 상태를 지우는 복구 reset이 없고, 새 페이지의 화면 복원 한계는 PID 생존으로 덮지 않는다. backlog 상한 이내의 지원 셸/OMP 재진입을 검증하고 오버플로·종료 결과 보존의 남은 책임을 인계한다.
  - **B1-E6:** 위 관찰의 소스·서빙 번들·서버 프로토콜 조합, storage 네임스페이스, 연결 세대와 스폰/PTY 카운터가 같은 시험에 귀속된다. 승인된 배포가 없는 격리 환경 Exit는 그 범위를 명시하며 운영 완료라고 하지 않는다. 신규 리스너/소켓/타이머가 반복 복구 횟수에 따라 누적되지 않음을 정한 반복 시험 범위에서 확인한다.
- **Invariants:** G1~G3·G5·G8과 P1~P7이 직접 적용된다. G4·G6·G7의 기존 실행/출력·입력·기한 의미를 회귀시키지 않는다. 아직 보수하지 않은 출력 오버플로/결과 보존 경로는 적용 범위와 남은 Exit를 명시하며 R4~R6의 완료로 인정하지 않는다.
- **Continuation:** B1-E1~B1-E6 근거, 호환 서버/클라이언트 리비전, 세션 상태 분기·인계 제한, 비밀값을 제거한 진단 ID, 미전달/불명 입력 여부, 기존/시험 세션 소유·기한, 남은 모바일/출력/결과 요구를 인계한다. 시험 연결·타이머는 정리되거나 확인된 감독자 아래 있고 운영 세션은 계속 추적되어야 한다. Safe Continuation과 BLOCK-002 Entry를 새로 확인한 후 사용자가 다음 진행을 허가해야 한다. 자동 계속하지 않는다.
- **Abort:** 중복 스폰, 무단 인계, 복구 제스처의 PTY 누설, 구 세대가 새 연결을 닫음, 만료를 새 셸로 감춤, 기존 작업의 영향 불명 또는 원본/프로토콜 불일치가 발생하면 변경 소유자는 후보 경로의 신규 접속/자동 복구/입력 활성화를 억제하고 시험을 중단한다. 운영자 승인 없이 기존 daemon을 재시작하거나 실제 OMP를 종료하지 않는다. 중단 후 스폰된 시험 세션 목록·입력 관찰·현재 연결 소유권·남은 프로세스·기한을 읽고 정상 기존 서비스 보존 또는 명시적 유지보수 상태를 판독한다. 누설된 입력의 효과는 자동 취소/재실행하지 않는다.
- **Insufficient for Exit:** `sessionStorage` 키 존재, 프런트 코드 수정만의 상태 안내, 콘솔의 `Reconnected`, WebSocket `OPEN`, visibility 이벤트 1회, 데스크톱 Enter 성공, 서버를 우회한 모의 복구, PID만 유지, 새 셸의 깨끗한 화면, 강제 새로고침을 요구하는 오버레이, 자동 복제 탭 탈취, 연결 복구와 함께 한 바이트라도 흘리는 ↵.

### Block `BLOCK-002` — 모바일 터치·키보드·모디파이어 상호작용 완결

- **ID:** `BLOCK-002`
- **Name:** 한글 입력과 12개 툴바 조작을 보존하는 화면·포커스 정책 및 명시적 탭 인계 경험
- **Meaning Contribution:** D-03·O-01을 해소하고 R3 및 R1의 복제 탭 선택 경험을 완성한다. NB4·NB7·NB8, Thesis §4.1~4.4를 실제 Android/IME 동작으로 성립시키되 BLOCK-001의 NB10 입력 경계를 그대로 유지한다.
- **Order / Dependencies:** BLOCK-001의 측정된 Exit와 세션/복구/단일 소유권 계약이 선행한다. 기존 소유자 차단 없이 Takeover 버튼만 추가하거나 키보드 처리를 바꾸면서 복구 ↵가 PTY로 새는 상태는 허용하지 않는다. 뷰포트의 희망 크기는 현행 foreground 경로로 전달하되 NB3 전체의 동일 크기·오버플로 후 화면 복원 판독은 BLOCK-003에서 완결한다.
- **Entry:** Scope 책임자와 검증자가 B1-E1~B1-E6의 적용 리비전을 확인하고 현재 실기기의 Android·Chrome·IME/키보드 버전, CSS 폭·배율·Safe Area·세로/가로·전체화면 상태, OMP 버전과 사용 keymap을 기록한다. 운영 번들의 viewport meta, 포커스/blur 경로, composition과 paste 경로, modifier 상태의 단일 원천을 판독한다.
  - 390/360 CSS px·34~36px·8~32px 정책, 한글 조합 Enter/ESC, 키보드가 열린/닫힌 상태의 툴바, 자동 복귀 후 조작을 구분한 전이표를 해당 Scope 근거로 결속한다. 직접 탭·스크롤·선택·링크 동작을 동일한 타이핑 의도로 처리하지 않는다. 시험 IME와 안전한 PTY 관찰 fixture 및 실기기 접근이 없으면 해당 Exit 검증 권한/능력이 준비되지 않은 것이다.
  - 키보드/브라우저 chrome/회전/전체화면/폰트 변화에서 사용할 단일 기하 계산 경로와 지원 최소 폭의 처리 방식을 확정한다. viewport를 두 번 차감하거나 숨겨진 0 크기를 서버 크기로 보내지 않을 조건을 판독한다. 복제 탭의 Takeover 요청·취소·이전 탭 displaced 상태는 서버 소유권 응답과 결합한다.
- **Exit:** 안정된 동일 대상에서 다음 조건이 모두 관찰된다.
  - **B2-E1:** 최초 진입·자동 재연결은 키보드를 열지 않고, 사용자의 본체 직접 탭으로 입력을 시작한다. 키보드가 열린 채 TAB·방향키를 누르면 닫힘/재열림 없이 입력 흐름을 유지하고, 닫힌 상태의 툴바 조작은 키보드를 열지 않는다. 읽기 위한 스크롤·선택과 실제 입력 탭을 구분하며 연결 복구 탭은 여전히 PTY `0 byte`이다.
  - **B2-E2:** Shift/CTRL 동시 활성화가 불가능하고 1회 유효 조작 뒤 중립이 된다. CTRL → ESC → `c`는 제어문자 `0x03`이 아니라 일반 `c`이고 의도하지 않은 SIGINT가 없다. Shift+TAB·Shift+방향키, application cursor mode의 일반 방향키, 모디파이어 재토글, Enter/ESC, A-/A+/전체화면, 페이지 숨김/단절/인계의 전이를 관찰한다. CTRL 후 본체 타이핑 탭은 Thesis §4.2대로 CTRL을 유지하되 붙여넣기·조합 시작·연결 소유권 상실은 남은 arm을 제거한다. 한 글자 paste도 Ctrl 조합으로 변환하지 않는다.
  - **B2-E3:** 실제 한글 IME의 음절 조립·수정·후보 선택·조합 중 backspace·한영 전환·붙여넣기에서 최종 확정 텍스트가 정확히 한 번 반영된다. 조합 중 Enter는 확정만 하고 셸/OMP 제출을 발생시키지 않으며, 조합 중 ESC는 양 모디파이어와 로컬 미확정 조합을 취소하고 원격 Escape를 보내지 않는다. 뒤늦은 compositionend/input, 툴바 접촉·화면 회전·단절이 끼어도 중복 문자/명령/이전 세션 입력을 만들지 않는다. 정상 터미널 입력 경로와 별도 composition 처리기를 중복 연결한 시험 성공은 인정하지 않는다.
  - **B2-E4:** 실제 서빙 문서에 `interactive-widget=resizes-content`가 적용되고 키보드/후보창을 열면 레이아웃과 xterm 유효 rows/cols가 수렴하여 현재 프롬프트와 툴바 전체가 보인다. 키보드 닫기·주소창 변화·회전·전체화면 진입/해제·폰트 8~32px에서 중복 축소·빈 영역·무한 resize가 없다. 단절 중에는 최신 유효 크기를 보유하고 재연결 시 그 크기를 적용하며, 숨김/0 크기를 마지막 정상 크기로 덮지 않는다. SC-5의 높이 판독과 실제 화면을 함께 확인한다.
  - **B2-E5:** 390 CSS px에서 Thesis 배열의 12개 요소가 가로 스크롤 없이 단일 행으로 보이고 각 실제 hit 영역의 높이가 34~36 CSS px이다. 360 CSS px·Safe Area·확대된 텍스트에서 양끝을 포함한 버튼이 잘리거나 서로 겹쳐 오작동하지 않는다. 측정한 bounding/hit 영역과 실제 터치를 함께 검증한다. 지원 범위를 넘는 폭에서는 기능을 몰래 숨기지 않고 한계를 드러내며 새로운 레이아웃 의미가 필요하면 원본 결정을 받는다.
  - **B2-E6:** 살아 있는 원본 탭과 같은 storage를 가진 복제 탭에서 원본 연결/입력/크기가 유지되고 신규 탭에 “세션이 이미 다른 탭에서 사용 중입니다”와 명시적 Takeover 선택이 보인다. 취소는 아무 세션도 종료/생성하지 않는다. Takeover 확정 뒤 정확히 한 소유자가 입력·resize를 수행하고 이전 탭은 displaced 안내 뒤 visibility·online·타이머가 발생해도 자동 재획득하지 않는다. 양 탭 동시 선택/지연 응답에서도 실제 서버 소유자와 양쪽 표시가 일치한다. 독립 새 탭의 신규 세션과 복제 충돌을 구별한다. SC-8은 양 탭과 서버 사건을 함께 판독한다.
  - **B2-E7:** 해당 OMP 버전/keymap에서 하드웨어 키보드 없이 프롬프트 편집·한글/여러 줄 입력·줄바꿈과 제출 구분·필수 선택지 탐색·의도한 취소·이전 출력 열람을 수행한다. 제공된 조작으로 필수 작업이 불가능하면 임의 키를 추정해 보내지 않고 의미 결손으로 남긴다. 실제 지원 OMP 화면과 시험 입력 판독을 함께 갖추고 SC-1~SC-5·SC-8의 영향 경로를 회귀 확인한다.
- **Invariants:** G1~G3·G5·G6·G8과 P1~P7이 직접 적용된다. G4·G7의 드레인·기한·결과 귀속을 회귀시키지 않는다. 포커스가 유지되었다는 사실만으로 IME 무결성을, CSS 높이만으로 터치 가능성을, 팝업 문구만으로 소유권 보호를 증명하지 않는다.
- **Continuation:** 실기기/IME/OMP/keymap 식별, 관찰 폭·배율·Safe Area·키보드 상태, 입력 바이트/조합 제출 수, 전이표, viewport 크기/rows·cols, 양 탭 인계 기록과 동일 빌드의 선행 회귀 증거를 인계한다. 이벤트 리스너/복구 타이머·활성 소유권이 정돈되고 종료하지 않은 실제 작업은 감독자·기한과 함께 유지한다. Safe Continuation과 BLOCK-003 Entry 및 현재 사용자 계속 권한이 모두 성립할 때만 다음 Scope를 선택한다.
- **Abort:** IME 중복/누락/의도하지 않은 제출, ESC 이후 제어문자 누설, 복제 탭 무단 인계/핑퐁, 키보드가 프롬프트·필수 버튼을 가림, resize가 정상 TUI 상태를 파괴하면 변경 소유자는 위험 입력/인계 경로의 신규 활성화와 시험을 멈춘다. 운영자는 기존 작업을 보존한 읽기/단절 상태 또는 검증된 호환 경로를 선택한다. 후보 번들만 되돌릴 수 있는지 서버 계약을 먼저 확인하며 브라우저 전체 저장소 삭제·운영 daemon 재시작으로 안전 상태를 가장하지 않는다. 마지막 유효 소유권·입력 불명 범위·화면/PTY 상태를 판독한다.
- **Insufficient for Exit:** viewport meta 문자열, 데스크톱 에뮬레이션만의 화면, ASCII 단일 키 성공, 한글 완성 문자열을 paste한 시험만의 IME 지원 주장, keyboard blur 성공, 390px 스크린샷만의 버튼 접근성, 34px CSS 선언만의 hit 영역 판독, 프로토콜에 연결되지 않은 Takeover 모달, 실제 OMP keymap을 확인하지 않은 단축키 추정.

### Block `BLOCK-003` — 백엔드 출력 거버넌스·종료 결과 보존·운영 감독

- **ID:** `BLOCK-003`
- **Name:** 유한 출력·종료 결과·소유 프로세스 회수와 실제 서비스 감독을 결합한 전체 루프 완성
- **Meaning Contribution:** R4~R8을 완결하고 R1~R3의 선행 결과를 최종 실행물에서 보존한다. NB2·NB3·NB9·NB11의 출력·화면·결과·자원 의미와 `systemd` 사용자 서비스/`logrotate`/운영 문서를 같은 운영 대상으로 성립시킨다.
- **Order / Dependencies:** BLOCK-001·BLOCK-002의 측정된 Exit가 선행한다. 최소 소유권/상태 계약은 이미 존재해야 하며, 이 Block은 링버퍼·결과 보존·회수·수용 정책을 정직하게 소비하는 서버/클라이언트 결합을 완성한다. 서비스 감독을 먼저 켜서 불완전한 종료/스폰 경로를 자동 재실행하지 않는다. 실제 운영 cutover는 별도 현재 권한과 유지보수 경계를 필요로 한다.
- **Entry:** Scope 책임자가 선행 Exit의 소스/실행물 정합성을 다시 읽고, 현행 출력 append/소비/오버플로, PTY 연속 drain, 루트 exit/EOF와 최종 읽기 순서, 세션 expiry/인계, kill/reap, foreground resize, 세션 수용 판정을 실제 코드·격리 런타임에서 판독한다. 선행 스냅샷의 “전체 폐기 후 redraw” 경로가 남았는지와 이미 수정되었는지를 구분한다.
  - 운영자는 실행 중/분리 중 세션과 완료 결과, 루트 PID·시작 시각·PTY·foreground PGID·세션 소유 워커 범위를 읽는다. 다른 job-control 그룹·세션을 만든 OMP 하위 작업도 소유 범위에 포함할 방법을 확정하고, 별도 감독되는 공유 작업의 제외 여부는 명시적 운영 결정으로 남긴다. 루트 PID 그룹 하나가 모든 하위 작업이라는 가정은 허용하지 않는다.
  - P7의 수용 상한과 메모리/프로세스 계상 대상, 결과 보존 용량, 대기/회수 한도, 로그 크기·세대·보존 기간·회전 주체를 실제 유한 값으로 결속한다. 결과 재열람의 읽기 전용 의미, 원래 deadline과 purge, 입출력/종료 경쟁의 판정 순서를 확정한다. 신규 수용의 정적 검사와 실제 생성 사이 경쟁도 검증 대상이다.
  - `/home/user01/.local/bin/ttyd`, `/home/user01/.local/share/webterm/index.html`, `/home/user01/.local/share/webterm/session.sh`의 내용/권한/기동 참조, 실제 7683 리스너, 사용자 `systemd` 관리자 가용성과 기존 감독자, 로그 저장 대상 및 `logrotate` 실행 가능성을 판독한다. 중복 daemon·충돌 unit·무제한 restart를 방지할 현재 감독 경계와 로그아웃/WSL 전제를 확정한다. 운영 재시작이 세션을 보존하지 못하면 사용자 작업 종료/결과 회수 또는 명시적 손실 수용 없이는 교체하지 않는다.
- **Exit:** 안정된 최종 대상에서 다음 조건이 모두 관찰된다.
  - **B3-E1:** 단절 및 느린 렌더/flow-control 상황에서 승인된 10 MiB fixture가 연결 출력 대기 때문에 정지하지 않고 정한 정상 결과로 끝난다. 최신 `8,388,608 bytes` tail과 끝 표식, 폐기량/절사 여부가 원 출력과 일치하며 재접속 화면에 절사 안내가 보인다. 여러 차례 오버플로와 UTF-8/제어 시퀀스 경계를 포함해 보존량이 상한을 넘지 않고 무한 보조 큐가 없다. 파서 경계 처리로 표시에서 제외된 부분이 있으면 원시 tail 보존과 표시 제한을 구분해 고지한다. SC-6은 `exit 0` 하나가 아니라 결과·tail·고지를 함께 판독한다.
  - **B3-E2:** 동일 크기 재접속·화면 회전·키보드/폰트 변경에서 실제 `TIOCGPGRP`로 식별한 foreground TUI에 갱신된 rows/cols와 재그리기가 도달한다. OMP와 지원 편집기/페이저의 normal/alternate 화면, 커서·application cursor mode가 현재 작업과 맞고 강제 reset/Full RIS·가짜 Enter/Ctrl+L 주입이 없다. 재로드의 새 xterm과 기존 xterm 재연결을 따로 검증한다. 신호 전송 성공이나 절사 경고만으로 화면 복원 성공을 대체하지 않는다.
  - **B3-E3:** 단절 중 루트가 정상/비정상 종료하면 exit code 또는 종료 신호·최종 tail·절사·원래 deadline이 `EXITED_RETAINED`에 남는다. 루트 exit 통지와 마지막 PTY read가 경합해도 읽기로 확보되어야 할 끝 표식을 유실하지 않으며, 소유 워커가 남으면 종료/회수 미완료가 추적된다. SC-7대로 단절 후 1분 내 루트가 끝난 fixture를 실제 1시간 뒤 열어 같은 결과를 읽고 새 루트 스폰 `0회`·PTY 입력 `0 byte`를 확인한다. 결과 재열람은 원래 기한을 새로 시작하지 않는다.
  - **B3-E4:** 서버 관찰 분리 시점부터 `32,400초` 구성과 기한 전/경계/기한 후의 분기를 검증한다. 실패한 재시도·복제 충돌은 기한을 연장하지 않고, 살아 있는 세션의 적격 인계와 만료가 경쟁해도 서버의 단일 판정으로 처리된다. 만료가 먼저 확정된 대상을 살아 있는 세션으로 인계하거나 취소된 옛 타이머가 새 소유자를 종료하지 않는다. 종료 결과의 만료는 실제 보존 자료 purge로 이어진다. 실제 9시간 관찰과 제어된 단축/가상 시간 시험의 증거를 구분한다.
  - **B3-E5:** 승인된 fixture의 명시적 종료와 만료에서 소유 범위에 SIGHUP을 보내고 확정한 유한 대기 뒤 남은 범위에 SIGKILL을 적용한다. 실제 소유 프로세스/워커·자식 reaping·PTY/FD/타이머·출력 버퍼가 회수된 뒤 `PURGED`로 바뀐다. 그룹을 달리한 워커, SIGHUP 비종료 및 회수 실패 경로를 포함한다. 정한 관찰 한도에서 비워지지 않으면 `TERMINATING`과 실패 진단을 유지하고 성공으로 기록하지 않는다. 관련 없는 다른 세션/서비스와 작업 파일은 보존된다.
  - **B3-E6:** 설정된 실행 세션·보존 결과·전체 자원 상한의 바로 아래/경계/초과와 동시 신규 생성 경쟁을 검증한다. detached 세션도 계상하고 결과 보존으로 전이한 뒤의 계상 변경이 실제 메모리/프로세스와 맞는다. 상한 시 신규 요청은 명시적으로 거절되고 추가 루트 스폰/침묵 기존 세션 퇴출이 없다. 기존 세션 재접속은 새 실행 슬롯을 소비하지 않으며, 수용 거절이 재시도마다 새 세션을 만드는 경로가 없다. 생명주기 기록·진단 로그 등 별도 저장도 무제한 누적되지 않는다.
  - **B3-E7:** 운영자 승인 범위에서 실제 `systemd` 사용자 서비스가 지정 바이너리·외부 웹 번들·런처·유효 grace/수용 설정으로 단일 7683 리스너를 감독한다. 실제 unit/프로세스/서빙 문서가 같은 배포 식별자에 귀속되며, `/terminal` 정적 페이지뿐 아니라 token 응답과 `/terminal/ws`의 정상 양방향 통신을 실제 Android에서 확인한다. 외부 인증을 추가하지 않고 기존 라우트의 외부 노출 범위도 임의로 변경하지 않는다.
  - **B3-E8:** 승인된 안전 경계에서 사용자 서비스의 기동·정상 중단·예기치 않은 종료 후 감독 정책과 재시작 제한을 관찰한다. 서비스를 중단했을 때 운영/시험 세션에 미치는 실제 효과를 읽고 재시작 후 구 ID를 새 셸로 위장하지 않는다. ## Safe Continuation

Safe Continuation Predicate:
- 현재 Block의 모든 Exit가 안정된 동일 대상에서 관찰되고 적용 불변식의 위반이 없으며, 후보 변경·시험·연결/입력·회수·배포의 효과가 종료되었거나 실제 소유자와 유한 상태를 갖는 정상 감독 아래 있다. 추적 중인 합법적 운영 세션은 종료할 필요가 없지만 소유권·기한·출력/결과 상태와 감독자가 확인되어야 한다. 미확정 비멱등 입력·소유자 불명 프로세스·중간 cutover가 없고 다음 Entry에 필요한 원본/실행물/증거가 보존되어야 인계 가능한 경계이다. 그 경계 성립과 별개로 다음 Block 시작은 현재 사용자 승인 없이는 허용되지 않는다.

Required handoff facts and readbacks:
- 실제 Block ID와 Bn-Em별 판독, 적용 Scope/계획/독립 검증 기록의 실제 경로·해시, 소스 전체 커밋 및 미커밋 변경, 바이너리·번들·런처·설정 식별자, 관찰 시각/시간대와 실제 기기·Chrome·IME·OMP/keymap·네트워크 시험 조건. 존재하지 않는 증거 파일을 만들어 참조하지 않는다.
- 서버 인스턴스·비밀값을 제거한 세션 진단 ID·소유 연결 세대·PID/시작 시각·PTY/foreground PGID·소유 워커 범위, 현재 상태·원래 deadline·출력/절사·종료 코드·회수 상태. 원시 resumeId나 사용자 입력 내용을 handoff 문서의 편의상 복사하지 않는다.
- 진행 중 연결/타이머/토큰 조회·IME·불확실한 입력·재시작·kill/reap의 정리 또는 감독 판독. 읽기 전용 결과와 실제 입력 가능한 세션을 구분한다. 결과가 불명인 명령을 재실행하거나 이미 종료된 작업을 복구했다고 표시하지 않는다.
- 실제 운영 감독자·unit·포트·프로토콜 호환·서빙 문서·로그 대상/회전·수용 설정, 변경 전후 보존된 작업과 fixture 정리 결과. 유지보수 상태라면 재개 권한과 제한도 인계한다.
- 남은 Goal/R1~R8, 선행/후속 SC와 14개 반례 Coverage, 적용 G/P 제약, 미관찰 실기기/시간 경계, 원본 정합화 대상. 다음 Entry에서 다시 읽을 정확한 원본 리비전·현재 해시와 현재 구현 상태를 제공한다.

Successor authority:
- 현재 사용자 지시에 따라 이 요청의 Main은 `BLOCK-001` → `BLOCK-002` → `BLOCK-003`을 순차 진행할 수 있다. 후속 Block은 선행 Block의 독립 검증·Coverage·완료 기록과 Safe Continuation이 실제로 성립한 경우에만 시작한다. 이 승인은 관계없는 배포·세션 종료·권한 상승이나 이 요청 밖의 후속 실행을 허가하지 않는다.

관찰된 위험이 없다는 사실은 Safe Continuation의 증명이 아니다. 조건 또는 필수 readback이 미상이면 안전한 인계로 기록하지 않는다. 안전한 경계가 성립해도 이 계약의 `no`를 자동 계속 허가로 바꾸지 않는다.

## Safe Abort

Trigger:
- 무단 세션 인계/중복 스폰, 복구·IME·로컬 조작의 PTY 입력 누설, 불확실한 입력 자동 재전송, 화면/종료 결과/절사의 허위 표시, 원래 기한 위반, 추적에서 사라진 소유 워커, 보호 중 세션 침묵 퇴출 또는 상한을 넘는 프로세스/메모리/로그가 관찰된다.
- 실제 실행물/프로토콜/서빙 경로 불일치, 승인되지 않은 daemon 교체·서비스 제어·권한 상승, 회수 대상 소유권 불명, 입력/kill/재시작 효과 불명, 원본 충돌 또는 필수 readback 부재 때문에 다음 변경을 안전하게 선택할 수 없다.
- 정상적인 통신 장애, 명시된 출력 절사, 수용 거절, 사용자 결정을 기다리는 OMP, 아직 재접속하지 않은 grace 세션 자체는 전체 서비스 종료 사유가 아니다. 해당 상태를 진실하게 표시하고 원래 보호/감독을 유지하며 Block 완료와 구분한다.

Authorized safe target state:
- **후보 변경 격리:** 새 후보 배포/위험 입력/자동 인계/신규 생성 시험이 멈추고 기존 정상 실행물과 사용자 작업이 계속 추적되는 상태. 이미 진행 중인 명령이나 실제 결과를 되돌렸다고 주장하지 않으며, 불확실한 범위는 마지막 확인 상태와 함께 남긴다.
- **확인된 감독 유지:** 기존 활성/분리 세션은 드레인·소유권·기한·결과 보존이 유지되는 확인된 감독자 아래 둔다. 시험 프로세스는 승인된 자기 소유 범위만 유한하게 종료/회수하고 판독한다. 자원 위험 때문에 일반 운영 유지가 불가능하면 운영자가 승인한 신규 접속 억제/유지보수 상태로 전환하되 합법적 세션을 무차별 종료하지 않는다.
- **되돌림의 한계:** 이전 호환 실행물과 설정이 실제로 보존되고 현재 세션 상태와 호환됨이 판독된 때에만 그 범위의 되돌림을 선택한다. 메모리 세션·유실 출력·이미 제출된 OMP 명령·종료된 프로세스는 파일 복사나 서비스 재시작만으로 복구되지 않는다. 세션 연속성을 보존할 수 없는 중단은 작업/결과 영향과 사용자 승인 없이는 무손실 rollback으로 표시하지 않는다.

Owner and action boundary:
- 변경 소유자는 현재 Scope에서 자신에게 허용된 후보 경로와 시험 작업만 억제·정리한다. 실제 운영 daemon·Funnel 설정·사용자 서비스·세션 소유 범위에 대한 파괴적 조치는 운영자/현재 Main의 구체적 권한 확인을 필요로 한다. 중단 요청 자체가 새로운 권한을 만들지 않는다.
- 중단을 이유로 전체 `sessionStorage`/결과 버퍼/작업 파일 삭제, 관계없는 프로세스 종료, 기본 경로 변경, 자동 관리자 권한 사용, 인증 범위 재설계 또는 다음 Block 시작을 하지 않는다. 새 의미 결정은 Thesis 소유자, 방법 변경은 현재 계획/검토 경계, 선택 Scope 변경은 Scope 수립 경계로 반환한다.
- 이미 누설된 입력 또는 수거 신호가 있다면 재입력·재시도·추가 kill을 즉시 안전한 것으로 간주하지 않는다. 해당 세션의 실제 효과와 소유 범위를 먼저 판독하고 허용된 조치만 수행한다.

Authoritative readback:
- 실제 리스너/daemon·unit 주 PID·바이너리/서빙 번들 식별, 현재 세션/연결 소유권·출력 위치/절사·결과/기한, 소유 워커·PTY/FD·타이머·회수 상태와 총 자원 계상을 읽는다. 중단 명령의 성공 반환 또는 kill 로그만으로 대상 종료를 증명하지 않는다.
- 복구/IME 입력 사고는 승인된 관찰 범위에서 마지막 확정 PTY 입력·OMP/셸 상태·작업 결과를 읽고, 제출/실행 여부를 모르면 해당 행위를 미확정으로 유지한다. 운영 로그·시험 증거·원본/작업 파일이 보존되고 신규 위험 효과가 억제되었는지 확인한다.
- 안전 목표 전체를 입증하지 못하면 `Safe Abort 미완료`와 남은 연결/프로세스/입력·결과 위험, 책임자, 마지막 확인 시각을 보고한다. 읽을 수 없는 상태를 비어 있음·종료 완료·안전함으로 대체하지 않는다.

## Atomic Boundary

`HARD_ATOMIC`은 분할 불가능한 전환을 한 Scope 안에 유지한다. 내부 기술 단위는 독립적으로 완료된 제품 Scope가 아니며 중간 인계를 허용하지 않는다. 안전하고 지속 가능한 경계가 독립적으로 관찰될 때만 분리한다.

- 세 Block 전체를 하나의 `HARD_ATOMIC`으로 묶지 않는다. BLOCK-001의 정직한 세션 복귀/입력 차단, BLOCK-002의 완결된 모바일 상호작용은 각각 실제 감독과 독립 Exit가 확인되면 별도 경계이다. 한 Block 안에서도 비활성 준비 작업 또는 독립적으로 안전한 결과는 여러 Scope가 될 수 있으나 미완성 활성 경로를 완료로 넘기지 않는다.
- **세션 복귀 활성화 — HARD_ATOMIC:** `resumeId` 유지, 서버의 재개/신규 생성 구분, 단일 소유권 응답, 현재 연결 세대, 입력 준비 및 복구 제스처 PTY 차단을 결합하는 cutover는 한 Scope 안에서 끝낸다. 프런트만 새 ID를 재사용하도록 운영 노출하고 서버의 무조건 인계/신규 스폰 금지는 다음 Scope로 넘기지 않는다. 증명된 호환 서버 준비는 활성화 전 별도 작업일 수 있다.
- **모바일 입력·인계 활성화 — HARD_ATOMIC:** pointer/포커스·composition·paste·modifier·↵ 복구 경로와 이를 소비하는 입력 라우팅은 서로 모순 없는 상태로 함께 활성화한다. Takeover UI·서버 소유권 전환·기존 탭 displaced 억제도 한 원자 경계이다. CSS-only 준비처럼 입력 효과가 없는 변경은 독립적으로 안전함이 입증될 때 분리 가능하다.
- **출력·결과·회수 상태 전환 — HARD_ATOMIC:** 최신 tail/절사 판정, exit/최종 PTY read, `EXITED_RETAINED`/deadline/읽기 전용 결과, 자원 계상·유한 회수와 이를 읽는 클라이언트 상태 표시는 호환 단위로 활성화한다. 서버가 결과를 보존하는데 클라이언트는 새 셸을 만들거나, registry에서 먼저 지운 뒤 후속 Scope가 reap하는 상태를 인계하지 않는다. 내부 자료구조 준비와 영향 없는 진단 추가는 활성 상태와 분리될 때만 별도 경계이다.
- **운영 감독 cutover — HARD_ATOMIC:** 호환 바이너리·실제 서빙 번들·런처·사용자 unit/환경·로그 대상과 회전 설정·7683 소유권·외부 `/terminal` 검증·기존 세션 영향 처리를 한 유지보수 Scope 안에서 결속한다. daemon 중복 기동, 디스크 파일만 교체된 구 프로세스, 잘못된 번들 또는 결과 손실 미확인 상태를 중간 완료로 넘기지 않는다. 시스템 파일·권한 상승이 필요한 설정은 별도 현재 권한 없이는 수행하지 않는다.
- 위 원자 경계는 네트워크 입력·파일 교체·프로세스 종료가 하나의 분산 트랜잭션처럼 rollback된다는 주장이 아니다. 중간 실패의 실제 효과는 Safe Abort로 수습한다. 실제 상태에서 추가 불가분 결합이 드러나면 Scope 선택과 승인에 반영하며, 구현 편의를 위해 Thesis를 낮추거나 세 Block의 순차 경계를 자동 병합하지 않는다.
